# WorldOS 언어·나라별 배포판

## VirtualBox로 실행

국가 폴더에서 아래 명령 하나로 해당 판의 커널·POSIX·셸을 빌드하고, 전용 디스크와 가상 머신을 준비하여 VirtualBox 창을 엽니다.

```sh
cd ~/worldos/나라/KOR
make vbox
```

249개 국가판과 46개 문자판에 동일하게 적용됩니다. 예를 들어 `나라/JPN`, `나라/USA`, `문자판/JPN/ja_Hira`, `문자판/IND/ta_Taml`에서도 `make vbox`를 사용합니다. 저장됨(`saved`)·일시 정지(`paused`) 상태에서는 재빌드 없이 기존 실행을 재개하며, 이미 실행 중이면 재시작하지 않습니다. `make vbox-status`로 상태와 로그 경로를 확인합니다.

현재 컴퓨터의 기존 부팅 디스크를 **복제해서** 사용하며 원본은 변경하지 않습니다. 다른 컴퓨터의 준비 사항, 원본 디스크 경로 지정, 보존 정책과 검증 범위는 [VirtualBox 실행 안내](명명/VirtualBox-실행.md)를 참고하세요.

## 나라별 원문·관리 파일 경로

한국어로 고정돼 있던 `소스`, `이름대응표.tsv`, `파일대응표.tsv`와 POSIX·셸의 관리 파일 이름을 각 판의 언어별 명명안으로 이동했다. 중국어 간체판은 `나라/CHN/源代码/名称对应表.tsv`, 번체판은 `문자판/CHN/zh_Hant/原始碼/名稱對照表.tsv`, 한국어판은 `나라/KOR/원문/이름대응표.tsv`를 사용한다. 각 판의 `layout.json`이 도구에 실제 경로를 알려 주며, 한국어 이름의 연결 경로를 따로 남기지 않는다.

295개 판 모두 새 경로 체계를 사용하지만, 현지어 관리 이름을 제안한 판은 173개(영어판 포함)이고 122개는 영문 임시 이름과 검토 대기 표시를 사용한다. [명명 근거·경로·백업·검증 안내](명명/관리경로-현지화.md), [판별 경로와 검토 상태](관리경로-현지화.tsv)를 참고한다. 상위 국가·문자판 폴더에서 쓰는 `make source`, `make source-iso`, `make posix`, `make shell`, `make vbox`는 그대로다.

## 현지어 POSIX 함수모음

각 국가·문자판에 `posix-KOR`, `posix-JPN`, `posix-USA` 등 국가 코드 기준 독립 POSIX 소스 폴더가 있다. 문자열·메모리·문자 분류·정수 변환·정렬/검색 함수를 추가하여 공개 함수는 107개다. 한국어 `읽기`·`쓰기`, 일본어 `読む`·`書く`, 두 가나판과 중국어 두 문자판의 소스를 빌드 시 표준 C 연결 이름으로 변환한다. 기존 셸도 같은 판의 새 함수모음을 사용한다. 내부 호출은 `__syscall6`·`__syscall_result`, 라이브러리는 `libposix.a`라는 OS 중립 이름을 쓴다. POSIX 전체 구현과 모든 언어 완역은 아직 미완료다.

```sh
make posix COUNTRY=KOR
make posix COUNTRY=JPN
make script-posix VARIANT=IND/ta_Taml
make verify-posix-builds
```

모든 판의 구현과 모든 언어의 완역은 다르다. 함수·변수별 미번역과 보존 이름도 공개하며, 세부 범위·직접 응용 코드 빌드·실행 시험·접두어 설명은 [POSIX 현지어 구현](명명/POSIX-현지어-구현.md), 판별 경로와 적용 개수는 [POSIX 목록](POSIX-목록.tsv)을 참고한다.

사용자 영역의 선언 경로·자료형·구조체 필드·상수·오류 코드도 현지어 이름에 포함한다. 예를 들어 KOR의 `선언/netinet/in.h`는 이제 `선언/상호연결망/주소.h`이며, `sin_port`는 `통신창구번호`다. 동일한 대응을 셸의 POSIX 사용 코드에도 적용했다. 추가 233개 항목 중 전부 대응한 판은 82개, 통신 선언 30개를 대응한 판은 88개, 새 용어 제안이 없는 판은 125개다. 전부 대응한 82개에는 영어의 약어를 풀어 쓴 64개 판도 포함된다. [선언 이름·호환 방식·검증 범위](명명/POSIX-선언-현지화.md), [판별 미완료 개수](POSIX-선언-현지화.tsv)를 참고한다.

## 운영체제 안에서 실행하는 명령해석기

249개 국가판과 46개 문자판에 각각 독립적인 사용자 영역 셸 소스와 빌드 셸 틀을 추가했습니다. `help`, `echo`, `pwd`, `cd`, `cat`, `stat`, `pid`, `uname`, `run`, `udp`, `source`, `exit`와 등록된 현지어 별칭을 처리합니다. 같은 판의 POSIX 함수모음으로 빌드하며, 다른 국가의 소스를 참조하지 않습니다.

```sh
make shell COUNTRY=KOR
make script-shell VARIANT=IND/ta_Taml
make script-shell VARIANT=JPN/ja_Hira
make verify-shells
make test-shells
```

이 작업의 새 명명 제안은 26개 언어·문자 용어집을 바탕으로 합니다. **295개 판의 셸 구현과 모든 언어의 완역은 서로 다릅니다.** 미번역 언어, 실제 실행 검증, 새 시험 디스크 사용법은 [명령해석기 구현 현황](명명/명령해석기-구현현황.md)에 명시했습니다. 기존 커널에는 셸 실행에 필요한 `fork → exec` 주소 변환 갱신, `/` 자판 처리, 정렬 메모리 할당의 공간 계산을 수정했습니다.

## 추가된 언어·문자별 독립 소스

`문자판/`에 인도 지정어 22개를 포함한 46개의 빌드 가능한 초기 문자판을 추가했습니다. 일본어 히라가나·가타카나, 중국어 간체·번체와 일부 다른 복수 문자를 별도 소스로 제공합니다. **전체 이름의 완역이나 전 세계 모든 문자의 구현 완료는 아닙니다.** [정확한 범위·미완료 항목·실행 검증](명명/문자판-구현현황.md)을 참고하세요.

```sh
make script-kernel VARIANT=IND/ta_Taml
make script-iso VARIANT=JPN/ja_Hira
make script-iso VARIANT=CHN/zh_Hant
```

인도 문자 등의 결합 기호를 보존하기 위해, 새 소스는 빌드 단계에서만 표준 Go 식별자로 대응하는 원문 식별자 방언을 사용합니다. 기존 국가판과 언어 배포 설정은 그대로 유지됩니다.

이 디렉터리는 ISO 639-3 언어 및 ISO 3166-1 국가별 부팅 ISO를 만드는 배포 계층입니다. 각 국가의 원문 폴더는 생성 시점의 engos 기능을 완전히 복제하며, 생성 후에는 engos·공용 소스·다른 국가 폴더 없이 자체 빌드됩니다. 폴더 이름은 위 관리 경로 표에서 확인합니다.

## 카탈로그와 폴더

- `언어/<alpha3>/`: ISO 639-3 레코드별 폴더와 `locale.conf`
- `나라/<ALPHA3>/`: ISO 3166-1 레코드별 폴더와 `country.conf`
- `나라/<ALPHA3>/<현지어 원문 폴더>/`: 해당 국가 대표 공용어로 명명한 독립 커널 소스
- `공통/`: 모든 판이 공유하는 ISO 빌드 규칙
- `언어-카탈로그.tsv`, `나라-카탈로그.tsv`: 전체 색인
- `나라-소스-언어선택.tsv`: 국가별 대표 언어·원어 이름·식별자 표기 방식

ISO 639-3에는 현존 언어뿐 아니라 고대어, 역사어, 인공어, 거시언어 및 특수 코드도 포함됩니다. “세계의 모든 언어”라는 경계가 학술적으로 하나로 고정되지 않기 때문에 이 프로젝트에서는 설치된 `iso-codes`의 ISO 639-3 전체를 명시적 기준으로 사용합니다.

## 사용법

```sh
make catalog                         # 시스템 iso-codes에서 폴더 재생성
make verify                          # 누락과 색인 수 검증
make iso-language LANGUAGE=kor       # 한국어 언어판 ISO
make iso-language LANGUAGE=eng       # 영어 언어판 ISO
make iso-country COUNTRY=KOR         # 대한민국 국가판 ISO
make country-sources                 # 249개 국가 독립 소스 재생성
make verify-country-sources          # 파일·대응표·소스 개수 검사
make verify-country-builds           # 249개 독립 커널 전체 빌드
make refine-country-names            # 현재 소스의 기능 중심 이름 개정
make verify-country-names            # 명명 대응·내용 해시 검사
make test-country-names              # 변환기 회귀 시험
```

개별 폴더에서도 `make iso`를 실행할 수 있습니다. 결과는 그 폴더의 `build/` 아래에 생성됩니다. ISO에는 해당 `locale.conf` 또는 `country.conf`가 GRUB 모듈로 포함됩니다.

국가별 독립 소스는 다음처럼 빌드합니다.

```sh
make -C 나라/KOR source       # 한국 대표 언어 소스에서 커널 생성
make -C 나라/KOR source-iso   # 같은 독립 소스에서 ISO 생성
make -C 나라/JPN source       # 일본어 식별자·파일 소스
make -C 나라/IND source       # 인도 대표 언어 의미 기반 식별자 소스
```

대표 언어는 CLDR에서 `official` 또는 `de_facto_official`인 언어 중 인구 비율이 가장 높은 언어를 선택하며, 공용어 표시가 없는 지역은 가장 높은 인구 비율 언어를 사용합니다.

최초 생성기의 단어별 번역 위에 현재 기능·어원·전체 구절에 따른 명명 개정 단계를 추가했습니다. 예를 들어 목록의 `PushBack`은 되돌리기가 아니라 끝에 추가하기이며, 일본어는 `末尾に追加`, 독일어는 `am Listenende anfügen`으로 표현합니다. 전체 구절의 어순을 유지하며 언어명 토큰과 이름 해시는 사용하지 않습니다. 한국어판의 현재 대응은 `이름대응표.tsv`, 경로는 `파일대응표.tsv`, 새 표현과 검토 상태는 `새명명-용어.tsv`에 있으며, 다른 판의 파일명은 각 원문 폴더의 `layout.json`에서 대응합니다. [현재 명명 정책](명명/정책.md)을 참고하세요.

`port`, `register`, `route`처럼 문맥에 따라 뜻이 달라지는 말은 전역 일대일 치환을 하지 않습니다. 먼저 `PIC command I/O port`, `UDP source port number`처럼 전체 개념을 정규화한 뒤 번역합니다. 검토한 개념 대응과 한국어 권장 표기는 [`용어-의미-검토.md`](용어-의미-검토.md)에 정리되어 있습니다.

각 국가 소스에는 커널·어셈블리·링커·빌드 스크립트뿐 아니라 직렬 로그 진단 도구와 POSIX C 헤더/libc 래퍼 테스트 소스가 들어 있습니다. 국가 루트 Makefile도 `공통/`을 include하지 않습니다.

## 현재 한계

86종의 대표 언어 모두를 완전히 재번역한 것은 아닙니다. 현재 새 전체 표현 제안은 22개 언어·문자 변형에 있으며, 그 언어들에서도 미검토 식별자가 남아 있습니다. 국가별 `명명검토대기.tsv`에 미완료 항목을 공개합니다. 7,847개 언어 폴더는 번역된 독립 커널이 아니라 배포 설정입니다. [국가별 적용 현황](명명-적용현황.tsv)과 [개정 검증 기록](명명/검증결과.md)을 구분해 확인하세요.

언어 카탈로그의 완전성과 번역 어휘의 완전성은 서로 다릅니다. 생성기는 설치된 gettext 카탈로그의 번역과 검토한 운영체제 핵심 용어를 우선 사용합니다. 대응되는 고유어가 없을 때는 카탈로그나 명시적 검토 목록으로 통용성이 확인된 기술 차용어만 허용합니다. 영어 철자를 한 글자씩 읽어 조립한 새 독음은 만들지 않습니다. 검토되지 않은 단어는 거짓 현지어로 위장하지 않고 원문으로 남겨 보완 대상으로 기록합니다. Go/POSIX ABI, 컴파일러 키워드·내장 함수, CPU 레지스터와 국제 표준 약어는 호환을 위해 유지됩니다.

engos 현행 커널의 POSIX IPv4 UDP 로컬 통신 계층도 공유합니다. `socket`, `bind`, `connect`, `send`, `sendto`, `recv`, `recvfrom`, 주소 조회 및 `shutdown`을 사용자 ELF에서 사용할 수 있습니다. 이 계층은 현재 게스트 내부 데이터그램 통신용이며, 외부 PCnet NIC 연결과 TCP는 아직 완료되지 않았습니다.
