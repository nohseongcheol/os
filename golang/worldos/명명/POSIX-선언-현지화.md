# 사용자 영역 선언·자료형·필드의 현지화

2026-09-11 개정. 기존 295개 독립 POSIX 패키지와 같은 판의 사용자 영역 셸에 적용한다. 함수만 번역하고 선언·상수·필드를 영어로 남기던 범위를 확장했다. 언어별 제안은 프로젝트의 새 명명안이며, 공식 표준 번역이나 원어민 감수를 마친 용어라고 주장하지 않는다.

이후 [관리 경로 개정](관리경로-현지화.md)에서 원문 폴더와 대응표 파일명도 현지화했다. 아래 한국어 예시의 POSIX 선언 경로는 유지되지만, 다른 언어판의 대응표 이름은 각 폴더의 `layout.json`으로 확인한다. 이 문서의 시험 기록은 선언 확장 당시의 기록이며 현재 경로·관리 해시 검증은 관리 경로 개정의 별도 결과를 참고한다.

## 한국어에서 달라진 이름

경로는 `나라/KOR/posix-KOR/` 기준이다.

| 표준 이름·이전 경로 | 현재 한국어 이름·경로 | 현재 역할 |
| --- | --- | --- |
| `선언/netinet/in.h` | `선언/상호연결망/주소.h` | IPv4 주소·통신창구 번호·끝점 주소 선언 |
| `arpa/inet.h` | `통신주소/여덟자리묶음순서.h` | 이 구현에 있는 16·32 이진 자리 값의 순서 변환 선언 |
| `sys/types.h` | `체계/자료형.h` | 사용자 영역의 공통 자료형 |
| `in_addr_t` | `상호연결망주소값형` | 32 이진 자리 주소값 |
| `in_port_t` | `통신창구번호형` | 16 이진 자리 전송 계층 번호 |
| `sockaddr_in` | `상호연결망끝점주소` | 주소 계열·창구 번호·IPv4 주소를 묶은 구조체 |
| `sin_port` / `sin_addr` / `s_addr` | `통신창구번호` / `연결망주소내용` / `주소값` | 번호·주소 구조체·그 안의 값 구분 |
| `sin_zero` | `주소맞춤채움` | 구조체 배치를 맞추는 여덟 자리 묶음 8개 |
| `INADDR_ANY` / `INADDR_LOOPBACK` | `모든지역주소` / `자기되돌림주소` | 바인딩용 지역 주소 선택과 자기 되돌림 주소 구분 |
| `st_ctime` | `마지막상태변경시각` | 자료철 상태가 마지막으로 바뀐 시각 |
| `STDOUT_FILENO` | `표준출력번호` | 표준 출력의 열린 자료 서술번호 |

자료형, 구조체 필드, 매크로, 오류 코드, 정수 한계, 시험 보조 이름을 합해 233개 항목을 추가했다. 헤더 보호 이름은 현지어 경로에서, 실제 체계 호출 상수는 현지어 호출 역할에서 유도한다. 선언과 정의·호출을 함께 바꾸며, 같은 판의 셸 본문·대기 프로그램·시험 프로그램도 동일한 공개 POSIX 대응을 사용한다.

## 어원보다 먼저 확인하는 현재 기능

- `Internet`의 연결된 망이라는 개념을 `상호연결망`으로 제안한다. 기관 이름이나 글자 독음보다 서로 연결된 통신망의 주소 체계를 드러내려는 선택이다. IPv4가 상호 연결된 망에서 주소 지정·자료 전달을 다루는 기능은 [RFC 791](https://www.rfc-editor.org/info/rfc791/)을 근거로 한다. 보편적·공식 한국어 권장어라는 뜻은 아니다.
- `port`는 여기서 CPU 입출력 단자나 물리 연결구가 아니라 통신 상대를 구분하는 전송 계층 번호이므로 `통신창구번호`다. `UDP`도 무형의 힘 같은 비유가 아닌 독립된 자료전문 전달 기능으로 풀었다. [RFC 768의 창구 번호와 자료전문 정의](https://www.rfc-editor.org/info/rfc768/).
- `arpa` 같은 역사적 기관 약어를 현재 파일 기능으로 오인하지 않는다. 이 패키지의 `arpa/inet.h`는 순서 변환 네 함수를 선언하므로 한국어 파일을 `여덟자리묶음순서.h`로 명명했다. 현재 파일에 없는 문자열 주소 변환 기능까지 구현했다고 표시하지 않는다.
- `st_ctime`의 `c`를 creation으로 풀지 않는다. 명세상의 마지막 상태 변경 시각을 반영했다. [The Open Group의 stat 선언](https://pubs.opengroup.org/onlinepubs/007904875/basedefs/sys/stat.h.html).
- `htons`·`htonl`의 역사적 short/long 구분은 이 인터페이스가 다루는 16·32 이진 자리로 풀었다. 일반 C의 `long`이 언제나 64비트라는 식의 뜻을 부여하지 않는다. `sizeof`, 정수 값, 부호, 정렬, 주소 순서는 바꾸지 않는다.
- 한국어 어순을 다른 언어에 강요하지 않는다. 일본어 히라가나·가타카나는 각 문자판의 실제 단어 표기로, 중국어 간체·번체는 각 판의 글자와 용어 대응으로 구분한다. 새로운 영어 독음을 조립하는 자동 대체는 없다.

이 명명 변경은 IPv6, TCP, 외부 통신, 전체 POSIX 기능을 추가한 작업이 아니다. 기존 공개 함수는 107개이며 이전부터 있던 커널 기능 제한은 그대로다.

## 언어별 적용 범위와 미완료 항목

[판별 집계](../POSIX-선언-현지화.tsv)는 실행 성공과 번역 범위를 별개로 기록한다.

| 추가 233개 항목의 대응 | 판 수 | 범위 |
| --- | ---: | --- |
| 233개 대응 | 82 | 한국어 2, 일본어·문자판 4, 중국어·문자판 12, 영어 64 |
| 통신 선언 30개 대응 | 88 | 독일어·프랑스어·스페인어·포르투갈어·러시아어·아랍어·힌디어·타밀어 계열 |
| 새 선언 용어 제안 없음 | 125 | 기존 번역은 유지하고 새 미번역은 명시 |

총 170개 판에 새 선언 이름이 있으며, 판별 적용 수를 합하면 21,746개다. 영어판은 약어를 기능 중심 영어로 풀었고, 이미 영어인 일반 이름은 그 판의 원문으로 분류한다. 위 82개 판은 실제 C 식별자 검사에서도 미번역 표시가 0개지만, C 문법·기계어 진입점·컴파일러 내장 이름은 의도적으로 유지한다. 이것은 어휘의 자연스러움에 대한 원어민 검수 통과를 뜻하지 않는다.

**인도 22개 지정어 전체와 모든 나라 언어의 완역은 아직 완료되지 않았다.** 새 선언 용어 제안이 부족한 판은 `pending-language-review`로 남긴다. 검증되지 않은 단어를 기계적으로 붙여 완료로 세지 않는다. 7,847개 언어 카탈로그가 모두 별도 구현·번역됐다는 뜻도 아니다.

각 패키지에 다음 자료가 있다.

- `파일대응.tsv`: 표준 컴파일 경로와 현지어 원문 경로.
- `이름대응.tsv`: 공개 함수·변수·자료형·필드·상수의 대응과 제안 상태.
- `선언용어근거.tsv`: 이번 233개 항목의 현재 역할과 현지어 이름.
- `보존식별자.tsv`: 실제 남은 C 식별자와 보존 이유. include 경로·문자열·주석·정수 접미사는 C 변수로 잘못 세지 않는다.
- 셸의 `사용자영역선언대응.tsv`: 같은 판의 POSIX 인터페이스에 맞춘 대응.

용어 원본은 [`tools/posix_declaration_terms.py`](../tools/posix_declaration_terms.py)다. 이름 충돌과 역변환 가능성을 검사하고, 기존 소스의 식별자를 모두 예약해 새 번역어가 다른 기존 이름을 가로채지 않도록 한다.

## 호환과 사용법

```sh
cd ~/worldos/나라/KOR
make posix
make shell
```

현지어 원문은 일반 GCC에 바로 전달하는 표준 C가 아니라, 결합부호를 포함한 각 문자 체계를 받는 C 방언이다. `posix_build.py`가 식별자와 정확한 include 경로를 표준 C로 변환한 뒤 빌드한다. 구조체 배치·함수 연결 이름·오류 번호·호출 번호는 원래와 같다. 문자열과 주석은 치환하지 않는다.

새 응용 코드는 해당 판의 이름과 선언 경로를 사용하고 아래처럼 변환·연결한다.

```sh
cd ~/worldos/나라/KOR/posix-KOR
python3 posix_build.py compile --source /경로/사용자.c --output /경로/새실행파일
```

출력은 기존 파일을 덮어쓰지 않는 새 경로여야 한다. 과거 현지어 이름과 include 경로는 `posix.json`의 `name_aliases`·`include_aliases`로 함께 인식한다. 옛 실제 헤더 파일을 원래 자리에 복제해 두는 방식은 아니다. 표준 영어 include도 그대로 사용할 수 있다.

`build/include/netinet/in.h`처럼 **build 아래에 생기는 영어 파일은 컴파일러용 산출물**이다. 현지어 소스가 다시 영어로 되돌아간 것이 아니다. `.h`·`.c` 확장자, Makefile, JSON 설정, 빌드 도구 파일명, 어셈블리 진입점 등 도구 계약은 유지한다. 사용자가 지정한 OS 중립 이름 `__syscall6`와 `__syscall_result`도 유지한다. 셸의 `idle.c`·`probe.c` 같은 보조 빌드 경로는 유지하고 그 안의 POSIX 사용 이름은 변경했다.

이번 대상은 독립 `posix-<국가코드>`와 실제로 그것을 사용하는 셸이다. 각 나라 `소스/` 아래에 출처로 남아 있는 예전 내장 POSIX 사본, 커널 자체, 진단 출력 문자열까지 이번에 모두 번역한 것은 아니다.

## 백업과 재생성

```sh
cd ~/worldos
python3 tools/install_posix.py --refresh --rename
python3 tools/install_shells.py --refresh
```

기존 감사 해시와 다른 사용자 수정은 덮어쓰지 않는다. POSIX 원문·설정은 `/tmp/worldos-posix-refresh-backup-*`, 셸 생성 파일·설정은 `/tmp/worldos-shell-refresh-backup-*`에 보관한 후 갱신한다. 이전 선언 경로의 생성 파일은 백업으로 이동했으며 복구할 수 있다. 사용자 추가 파일과 기존 build 폴더는 유지한다. 경로 이동 실패 시 원본을 복원하는 시험도 포함한다. 이번 기록의 백업 경로는 `build-verification/posix-declarations/install*.log`와 `shell-install*.log`에 있다. `/tmp`는 장기 보관 장소가 아니므로 필요한 백업은 별도로 보관해야 한다.

VirtualBox VM 설정·저장 상태·기존 부팅 디스크는 이 작업에서 변경하지 않는다. 실행 시험은 원본 디스크를 복제한 임시 시험 디스크에서만 수행한다.

## 검증 기록

현재 개정의 검사 결과는 `build-verification/posix-declarations/`에 이전 기능 확장 결과와 분리해 둔다. 선언 변환 시험에는 9개 언어·문자 설정의 i386 주소 구조체 크기와 필드 위치, 프로토콜 값, 시각 필드 위치 검사가 포함된다. 모든 현지어 원문을 표준 C로 되돌렸을 때 원래 컴파일 입력과 바이트 단위로 동일한지도 검사한다.

```sh
python3 -m unittest discover -s tools -p 'test_*.py'
python3 tools/verify_posix.py --build --jobs 4 \
  --report-dir build-verification/posix-declarations
python3 tools/verify_shells.py --build
make verify-vbox
```

실제 게스트 실행의 판·항목·결과와 원본 디스크 해시는 이 디렉터리의 시험 결과표에 남긴다. 이전 부팅 시험에 통과했다는 사실만으로 이번 실행 검증을 대신하지 않는다.

검증 완료 범위:

- 295개 POSIX 판 빌드·감사 통과, 원문 파일 12,390개의 표준 입력 역변환 일치.
- 295개 셸 판의 본체·대기·시험 실행파일 빌드 통과.
- 단위시험 107개 통과. 주소 구조체 크기·필드 위치 검사는 9개 언어·문자 설정에서 수행했다.
- KOR, USA, 일본어 두 가나판, 중국어 간체·번체, 힌디어 데바나가리, 타밀어의 8종 POSIX 회귀시험 총 64건 통과.
- 위 8개 판에 일반 일본어·프랑스어·독일어·아랍어를 더한 12개 판의 실제 셸 부팅·명령·실행 전환·통신 시험 통과.
- VirtualBox 실행 진입 설정 295개 검사 통과. VirtualBox 자체를 새로 부팅한 시험은 아니다.
- 한국어 통신 응용 코드를 새 이름과 백업의 이전 이름으로 각각 `compile`한 두 실행파일의 SHA-256 일치.
- 현재 295개 `posix-native-probe`도 앞선 함수 확장 때의 실행파일 해시와 동일하다. 다만 이번에 295개 판을 모두 재부팅한 것은 아니며 실제 새 부팅 범위는 위 8개·12개 판이다.

첫 샌드박스 시도는 QEMU 임시 스냅샷의 읽기 전용 파일체계 오류로 게스트가 시작되지 않았다. 그 실패 기록은 결과 디렉터리 루트에 보존했고, 승인된 환경의 실제 실행 결과는 `guest-execution/`에 분리했다. 실제 실행 64건·12건은 최초 실행에서 모두 통과했으며, 두 시험의 원본 디스크 전후 SHA-256도 동일하다.

최종 용어 보정 후 인도 3개 판은 `build-selected.tsv`로 다시 빌드했다. [`delivery-summary.json`](../build-verification/posix-declarations/delivery-summary.json)은 전체 `build-all.tsv`에 이 새 증거를 우선 적용하고, 현재 각 패키지의 입력·산출물 해시까지 다시 검사한 결과다. 재대조 명령은 다음과 같다.

```sh
python3 tools/summarize_posix_declarations.py
```
