# 나라·문자판의 원문 폴더와 관리 파일 이름

2026-09-11. 한국어로 고정돼 있던 원문 폴더, 식별자·파일 대응표, 용어 근거, 명명 검증, 문자판 구축 도구와 POSIX·셸의 관리 파일 이름을 이동했다. 기존 249개 국가판과 46개 문자판이 대상이다. **언어별 새 명명안을 적용한 범위와 전체 판에 경로 체계를 적용한 범위는 다르다.**

## 현재 경로

| 판 | 원문 폴더 | 이름 또는 식별자 대응표 |
| --- | --- | --- |
| 한국어 KOR | `나라/KOR/원문` | `이름대응표.tsv` |
| 중국어 간체 CHN | `나라/CHN/源代码` | `名称对应表.tsv` |
| 중국어 번체 | `문자판/CHN/zh_Hant/原始碼` | `識別字對映.tsv` |
| 일본어 JPN | `나라/JPN/原始記述` | `名前対応表.tsv` |
| 일본어 히라가나 | `문자판/JPN/ja_Hira/げんしきじゅつ` | `しきべつしたいおう.tsv` |
| 일본어 가타카나 | `문자판/JPN/ja_Kana/ゲンシキジュツ` | `シキベツシタイオウ.tsv` |
| 영어 USA | `나라/USA/source` | `name-correspondence.tsv` |
| 프랑스어 FRA | `나라/FRA/code-source` | `correspondance-des-noms.tsv` |
| 독일어 DEU | `나라/DEU/Quelltext` | `Namenszuordnung.tsv` |

문자판은 원래 국가판의 `이름대응표.tsv` 대신 `식별자대응.tsv`를 관리하므로 그 역할에 맞는 이름을 쓴다. 국가 번체판 `나라/TWN/原始碼`의 이름 대응표는 `名稱對照表.tsv`다.

중국어 간체 국가판의 주요 변경 예:

| 이전 | 현재 | 역할 |
| --- | --- | --- |
| `소스` | `源代码` | 컴파일할 프로그램 원문 |
| `이름대응표.tsv` | `名称对应表.tsv` | 원래 이름과 현지 이름의 대응 |
| `파일대응표.tsv` | `文件对应表.tsv` | 원래 파일 경로와 현재 경로의 대응 |
| `용어사전.tsv` | `术语词表.tsv` | 사용한 용어 목록 |
| `용어근거.tsv` | `术语依据.tsv` | 용어를 선택한 근거 |
| `명명검토대기.tsv` | `待审命名.tsv` | 아직 검토가 필요한 이름 |
| `명명검증.json` | `命名核验.json` | 이름 정책과 파일 해시를 검사하는 기록 |
| POSIX의 `기능범위.tsv` | `功能范围.tsv` | 실제 제공 기능과 제한 |
| 셸의 `명령대응.tsv` | `命令对应.tsv` | 기본 명령과 현지어 명령의 대응 |

단순한 겉보기 별칭이 아니다. 실제 폴더와 파일을 이동했고, 이전 한국어 이름의 복제본이나 심볼릭 링크를 활성 소스에 남기지 않았다. 이미 자연스러운 한국어 관리 이름은 유지했으며, 외래어 `소스`는 KOR·PRK에서 `원문`으로 바꿨다.

## 이름 선택 원칙

어원은 뜻을 이해하는 단서로 삼되 현재 기능을 먼저 확인한다. `source`를 물리적인 샘이나 자원으로 직역하지 않고, 실행파일을 만드는 프로그램 원문이라는 역할로 구분했다. 간체의 `源代码`는 GNU 중국어 개발 문서에도 쓰이는 표현이다. [GNU 개발 자료의 사용례](https://www.gnu.org/software/devel.zh-cn.html). 독일어 `Quelltext` 역시 원문을 가리키는 기존 기술 용어의 사용례가 있다. [GNU 선언 독일어판](https://www.gnu.org/gnu/manifesto.de.html).

`mapping`은 지리적인 지도 제작이 아니라 원래 이름과 새 이름의 대응 관계를 담는 파일이므로 대응표·대조표 역할로 명명했다. `audit`은 재무 감사가 아니라 이 프로젝트가 수행하는 이름·내용 해시 검사이므로 그 기능을 드러내도록 했다. 물려받은 문서는 새 판의 원문과 혼동하지 않도록 계승 자료 폴더에 두었다.

새 제안 전체가 공식 표준어이거나 역사적 어원을 학술적으로 확정한 번역이라는 뜻은 아니다. 원어민 감수도 완료되지 않았다. 언어마다 전체 구절을 따로 지정했으며, 알파벳을 새 독음으로 조립하는 자동 번역은 사용하지 않는다. 가타카나판은 대응하는 일본어 히라가나 제안을 가타카나 문자로 옮긴 별도 이름을 사용한다.

## 적용 범위와 남은 작업

관리 역할 25종을 정의했고 실제 존재하는 파일에 적용했다. 최초 이동에서는 원문 폴더를 포함한 6,002개 경로가 바뀌었다. [판별 경로·검토 상태](../관리경로-현지화.tsv), [명명안 원본](../tools/layout_terms.py)을 함께 확인할 수 있다.

- 173개 판: 현지어 명명안 적용. 영어판 64개도 해당 언어의 의미 기반 이름을 사용하므로 포함한다.
- 122개 판: 이번 관리 이름의 현지어 명명안이 아직 없다. 한국어 고정 이름을 영문 임시 관리 이름으로 바꾸고 `pending-language-review`로 명시했다. 현지어 번역 완료로 세지 않는다.
- 인도의 22개 지정어 전체를 포함한 모든 언어의 완역은 미완료다. 이번 새 관리 이름은 힌디어·타밀어에 제안이 있으며, 다른 지정어의 부족한 항목을 힌디어로 대신 채우지 않았다.

공통 프로젝트 색인인 `나라`, `문자판`, `명명`은 각 판의 언어 폴더가 아니므로 유지한다. 국가 코드, `posix-<국가코드>`, `Makefile`, Go 도구의 `src`, 산출물의 `build`, 파일 확장자, 실행 진입 설정과 `layout.json` 같은 도구 식별 경로도 유지한다. 파일 형식·C/Go 문법·기계어 연결 규약을 번역한 작업이 아니다.

대응표의 본문·설명 문서 전체를 새 언어로 번역한 것도 아니다. 특히 계승 자료의 내용과 과거 시험 결과는 역사적 기록으로 보존했다. 사용자 추가 파일과 기존 build 산출물은 유지한다. VM 설정·저장 상태·가상 디스크 파일을 옮기거나 재부팅하지 않았다.

## 빌드와 경로 찾기

상위 폴더의 명령은 그대로 쓸 수 있다.

```sh
cd ~/worldos/나라/CHN
make source       # 源代码에서 커널 구축
make source-iso   # 같은 원문에서 부팅 ISO 구축
make posix
make shell
make vbox         # 기존 독립 VirtualBox 실행 흐름
```

직접 원문을 보려면 `cd ~/worldos/나라/CHN/源代码`를 사용한다. 문자판도 상위 폴더의 `make source`, `make source-iso`를 제공한다.

```sh
cd ~/worldos
make script-kernel VARIANT=JPN/ja_Hira
make script-iso VARIANT=CHN/zh_Hant
make verify-layout
```

각 판의 `layout.json`에는 원문 폴더, 원문·POSIX·셸 폴더의 `layout.json`에는 관리 파일의 역할별 실제 경로가 있다. 예전 이름을 아는 도구는 `native_source.local_path`로 현재 경로를 찾는다. 이는 파일체계에 옛 경로를 다시 만드는 기능이 아니다. VirtualBox 실행기는 `vbox-entry.json`의 `kernel_directory`로 같은 폴더를 찾으며, 다른 판이나 공용 원문에 의존하지 않는다.

POSIX·셸 생성기의 갱신도 현지어 관리 파일 이름을 사용하도록 반영했다. `make localize-layout`은 감사 해시를 먼저 검사하고 이름·참조만 갱신한다. `make country-sources` 같은 원본 재생성은 현지화된 판에서 거부한다. 사용자가 편집한 원문을 지우거나 `소스` 폴더를 다시 생성하지 않도록 하기 위한 제한이다.

## 백업과 검증

최초 이동의 원본은 `/tmp/worldos-layout-backup-avnx9jq3/<판>/`에 있다. 각 판의 `migration.json`은 이전·현재 원문 폴더와 정확한 파일 이동을 기록한다. 백업에는 이동 전 커널·POSIX·셸 원문과 관리 파일, 상위 Makefile·실행기가 포함되며, build 산출물과 가상 디스크는 복제하지 않았다. 활성 폴더에서 사라진 옛 관리 파일은 이 백업에서 복구할 수 있다. `/tmp`는 장기 보관 장소가 아니므로 필요한 백업은 따로 보관해야 한다.

충돌 대상이 이미 있거나 감사 해시와 다른 사용자 수정이 있으면 덮어쓰지 않고 멈춘다. 게시 중 오류가 발생하면 해당 판의 원래 파일과 경로를 복원하며, 실패 산출물도 백업 안에 남긴다. 이후 안내문 갱신의 셸 백업 경로는 `build-verification/layout/shell-refresh.log`에 기록했다.

검증 기록은 `build-verification/layout/`에 있다. `layout-check.log`는 295개 판의 재검사와 재적용 시 변경 없음, `kernel-audit.log`는 국가·문자판의 원문·대응·컴파일 입력 검사와 VirtualBox 진입 경로 검사다. 실행 시험은 원본 디스크의 임시 사본에서만 수행한다. 실제 재빌드·부팅한 판과 결과는 별도 결과표에 명시하며 전체 295개 커널을 재부팅했다고 표시하지 않는다.

완료한 검증:

- 295개 판 경로·명명 감사 및 재적용 시 변경 없음.
- 단위시험 115개 통과. 경로 충돌 거부, 사용자 추가 파일 보존, 게시 실패 시 복원, 문자판 컴파일 입력 유지, 새 VirtualBox 커널 경로 사용을 포함한다.
- 295개 POSIX와 295개 셸 본체·대기·시험 프로그램 재빌드 통과.
- 대표 13개 판의 상위 Makefile부터 커널·부팅 ISO까지 강제 재빌드 통과.
- 9개 판의 POSIX 실행시험 72건과 13개 판의 셸 부팅·명령·통신 실행시험 통과.
- 백업과 대조한 커널 및 함께 보관된 사용자 영역 프로그램 파일 27,730개의 내용 동일.
- 원본 시험 디스크의 시험 전후 SHA-256 동일. 실행 중이던 VirtualBox VM에는 조작 명령을 보내지 않았다.

[`delivery-summary.json`](../build-verification/layout/delivery-summary.json)은 현재 소스·빌드·시험 실행파일·ISO 해시까지 다시 대조한 결과다. 대표 판의 정확한 목록은 `kernel-builds.tsv`와 `guest-execution/`의 결과표에 있다. 새 검증은 모두 최초 실행에서 통과했으며 실패 기록을 성공으로 덮어쓴 재시도는 없다.

```sh
python3 tools/summarize_layout.py --backup /tmp/worldos-layout-backup-avnx9jq3
```

이 명령은 이번 이동 직전 백업을 필요로 한다. 과거 POSIX 선언 확장의 검증 요약은 당시 파일 이름·관리 해시에 대한 기록이며, 현재 경로 개정 검증은 이 문서의 별도 요약을 기준으로 한다.
