# WorldOS 명령해석기 구현과 명명 범위

## 구현 범위

대상은 `나라/`의 독립 국가·지역판 249개와 `문자판/`의 독립 문자판 46개, 합계 295개입니다. 각 판에 사용자 영역에서 실행하는 C 명령해석기, 현지어 빌드 셸 틀, 이름 대응표, 예제 명령파일을 추가했습니다. 일본어 혼합문자·히라가나·가타카나, 중국어 간체·번체, 인도 지정어 22개의 기본 문자판과 추가 문자판 7개에도 실행 코드를 제공합니다.

다만 **실행 가능한 코드가 있다는 뜻이지 모든 이름을 그 언어로 완역했다는 뜻은 아닙니다.** 이번 셸 용어 제안은 26개 언어·문자 용어집에서 출발하며, 파생 표기까지 32개 언어·문자 코드의 193개 판에 적용됩니다. 이 판들은 새 셸의 내부 C 이름 68개와 빌드 셸 이름 8개에 기능 중심 표현을 갖습니다. 나머지 102개 판은 영어 임시 이름을 유지하며 번역 대기로 기록합니다. `und` 지역은 영어 이름을 제공해도 현지어 번역으로 계산하지 않습니다.

인도 문자판 중 새 셸 이름의 제안이 있는 것은 현재 벵골어·힌디어·타밀어·우르두어입니다. 나머지 지정어에 힌디어를 복사하거나 문자만 바꿔 완역으로 표시하지 않습니다. 기존 커널·도구·모든 디렉터리의 재명명과 전 언어 원어민 감수 역시 완료되지 않았습니다. 7,847개 `언어/` 폴더는 계속 배포 설정이며, 독립 번역 셸 7,847개로 세지 않습니다.

정확한 판별 상태는 [명령해석기 목록](../명령해석기-목록.tsv)의 `native_proposals`, `pending_identifiers`, `linguistic_review`에 있습니다. 모든 새 용어는 `project-proposal`, 언어 감수는 `incomplete`입니다.

## 이름을 정한 기준

영문 철자 독음이나 어근의 무조건적인 일대일 치환 대신 실제 구현의 역할을 먼저 읽었습니다. 역사적 명칭은 배경으로 참고하되 현재 하지 않는 기능을 이름에 넣지 않았습니다. 한 국가가 하나의 언어 철학만을 갖는다고 가정하지 않으며, 지역별 표현 차이와 새 조어의 자연스러움은 추가 감수 대상입니다.

| 원래 이름 | 현재 기능에 따른 한국어 제안 | 구별한 의미 |
| --- | --- | --- |
| shell | 명령해석기 | 사용자의 명령을 해석하는 역할이며 물체의 껍데기가 아님 |
| `text_length` | `문자열_여덟자리묶음_길이` | UTF-8 문자·자소 개수가 아니라 바이트 수 |
| `command_cat` | `자료철_내용_표시` | 이 구현은 한 파일을 표시하며 여러 파일 이어붙이기는 하지 않음 |
| `command_source` | `명령자료철_해석` | 소스코드 생성이 아니라 현재 해석기에서 명령파일 처리 |
| `command_run` | `실행자료철_가동` | 자식 실행과정을 만든 뒤 ELF 실행파일을 실행 |
| `command_udp` | `자료전문_되돌림_시험` | 게스트 내부 데이터그램 왕복 시험이며 외부 인터넷 접속이 아님 |
| `receive_socket` | `수신_통신끝점` | 물리적 구멍이 아니라 통신이 시작·끝나는 논리적 지점 |
| `overflow` | `잘못된_입력줄` | 길이 초과뿐 아니라 NUL이 든 이진 입력도 거부하는 상태 |

`자료철`, `여덟자리묶음`은 프로젝트의 새 번역어 제안이며 공식 표준어라고 주장하지 않습니다. 앞말은 자료를 묶어 다룬다는 비유, 뒷말은 이 운영체제의 바이트가 여덟 이진 자리라는 현재 구현을 표현합니다. 모든 시대의 byte 정의를 여덟 자리라고 단정하는 어원 설명은 아닙니다.

셸을 명령해석기라는 현재 역할로 다루는 근거는 [GNU의 셸 설명](https://www.gnu.org/software/bash/manual/html_node/What-is-a-shell_003f.html)입니다. 명칭의 역사와 command interpreter라는 대안은 [Bell Labs의 1978년 Unix shell 논문 소개](https://www.nokia.com/bell-labs/publications-and-media/publications/unix-time-sharing-system-the-unix-shell/)에서 확인할 수 있습니다. 이 자료들이 각 언어의 이번 조어를 인증하는 것은 아닙니다.

## 제공되는 파일과 빌드 방식

예를 들어 한국판은 `나라/KOR/명령해석기/`에 있습니다. 다른 판의 정확한 폴더는 각 국가·문자판 루트의 `shell-entry.json`으로 찾을 수 있습니다.

- 현지어 이름의 `.c`: 함수·지역변수·내부 자료형·상수의 원문 식별자 소스
- `shell_locale.h`: 현지어 내부 배열 이름과 명령 별칭
- 현지어 이름의 `.sh.in`: 빌드 함수와 경로 변수의 현지어 원문 틀
- 현지어 이름의 `.commands`: 그 판의 명령 별칭으로 작성한 UTF-8 예제
- `이름대응.tsv`, `셸이름대응.tsv`, `명령대응.tsv`: 컴파일 대응명·원문 이름·번역 상태
- `shell.json`: 대응 정보와 생성 파일의 검증 해시
- `build/worldos-shell`: 실제 게스트용 32비트 i386 ELF
- `build/worldos-idle`, `build/worldos-shell-probe`: 시험용 대기 프로그램과 실행·인수 전달 검사 프로그램

원문 식별자에 결합 문자가 포함될 수 있으므로 C는 빌드용 임시 복제에서만 컴파일 대응명으로 변환합니다. 표준 GCC가 모든 원문 문자를 직접 받아들인다는 뜻은 아닙니다. `.sh.in`의 `@{현지어식별자}`도 명시적인 틀 문법이며 Bash에서 직접 실행할 수 없습니다. 빌드 시 표준 셸 변수로 바꾼 후 `sh -n`을 검사합니다. 원문 이름은 원래 파일에 보존되고, 원문 편집은 다음 빌드에 반영됩니다.

일본어 가나판은 자동 변환 결과를 그대로 확정하지 않았습니다. `命令解釈器 → めいれいかいしゃくき`, `引数列 → ひきすうれつ`, `原文書 → げんぶんしょ` 등의 복합어 읽기를 명시적으로 보정했습니다. 셸 폴더도 `めいれいかいしゃくき`와 `メイレイカイシャクキ`로 바꾸었으며, 이전 생성본과 빌드 산출물은 각각 `/tmp/worldos-shell-rename-backup-p1rvhmc6`, `/tmp/worldos-shell-rename-backup-kvvo3lgc`에 백업했습니다. 옛 이름의 생성 파일은 새 폴더에서 정리했지만 백업으로 복원할 수 있습니다. 두 판 모두 다시 빌드한 실행파일의 SHA-256이 변경 전과 일치했습니다.

`main`, C/POSIX 함수·구조체 인터페이스, CPU 명령, 빌드 도구 옵션과 일부 관리용 파일명은 호환을 위해 유지합니다. 검사 도구의 Python 코드와 기존 커널의 모든 호스트 셸 스크립트를 이번에 완역한 것은 아닙니다. 영어 도움말·진단 문구도 남아 있습니다.

기본 설치는 기존 셸을 덮어쓰지 않고 검사합니다. 제안 용어집을 수정한 뒤 `python3 tools/install_shells.py --refresh`를 실행하면 생성 당시 해시와 일치하는 파일만 갱신합니다. 사용자가 편집한 생성 파일이 있으면 중단하므로 먼저 변경 내용을 검토·통합해야 합니다. 원문 빌드 자체는 편집을 허용하지만 `verify`는 기준 해시와 달라진 사실을 보고합니다.

폴더명까지 바꾸는 검토된 개정에는 추가로 `--rename`이 필요합니다. 대상 폴더가 비어 있거나 기존 파일을 덮어쓰는 방식으로 처리하지 않으며, 새 경로가 없어야 합니다. 기존 생성 파일과 Makefile을 검사하고 전체 백업 후 이동하며, 사용자 메모·빌드 파일은 보존합니다.

## 지원 기능과 한계

12개 명령 `help echo pwd cd cat stat pid uname run udp source exit`와 대응표의 현지어 별칭을 받습니다. 작은따옴표·큰따옴표·인접한 인수 조각·역슬래시·빈 인수·단어 경계의 주석을 처리합니다. 잘못된 따옴표, 인수 초과, 너무 긴 줄, NUL 입력은 앞부분도 실행하지 않고 거부합니다.

최대 한 줄은 511바이트, 명령 이름을 포함한 인수는 15개, 명령파일 중첩은 4단계입니다. UDP 시험 메시지는 최대 95바이트이며 넘으면 UTF-8을 중간에서 자르지 않고 거부합니다. UDP는 게스트 내부 되돌림 시험입니다.

이는 POSIX `sh` 전체 구현이 아닙니다. 변수 확장, 파이프, 재지정, 조건문, 반복문, 작업 제어, 실행 경로 검색은 없습니다. 외부 프로그램은 `run /실행파일`로 호출합니다. `exit`에 종료 코드 인수를 지정하는 기능도 없습니다.

UTF-8 명령파일과 직렬 로그의 문자열 보존을 시험합니다. VGA 글꼴·조합형 문자 렌더링·각국어 입력기까지 구현한 것은 아니며, 기존 자판은 제한된 ASCII 입력을 제공합니다. 백스페이스도 자소 묶음 전체가 아니라 UTF-8 코드포인트 하나를 지웁니다. 기존 커널의 시연 작업들이 출력하는 `A/B/C/taskD1` 등이 화면·로그에 섞일 수 있습니다.

## 새 디스크로 실행하기

셸을 빌드하는 것과 기존 사용자 프로그램 디스크에 설치하는 것은 별개입니다. 셸 ELF만 만든 상태에서 ISO를 부팅하면 기존 디스크의 `USER1`이 실행됩니다. 아래 명령은 기존 VDI를 읽기만 하고 **새 VDI**를 만들어 `USER1`에 셸, `USER2`·`USER3`에 대기 프로그램, `SHEXEC`에 시험 실행파일, `COMMANDS`에 현지어 예제를 넣습니다. 출력 파일이 이미 있으면 덮어쓰지 않고 중단합니다.

```sh
cd /home/user/worldos
make shell COUNTRY=KOR
make shell-disk SHELL_EDITION=KOR \
  TEST_DISK='/home/user/VirtualBox VMs/eng operating system/NewVirtualDisk1-fixed-20260908.vdi' \
  SHELL_DISK=build/worldos-KOR-shell.vdi
```

문자판은 `SHELL_EDITION=IND/ta_Taml`처럼 선택합니다. 같은 판의 원문 폴더 아래 `build/kernel.iso`와 생성된 새 VDI를 사용해야 합니다. 원문 폴더는 이제 각 판의 `layout.json`에서 확인하며 [관리 경로 표](../관리경로-현지화.tsv)에도 나옵니다. 이 커널의 시험 배치는 CD가 IDE 두 번째 채널의 첫 장치(`ide.1,unit=0`), 사용자 디스크가 첫 번째 채널의 두 번째 장치(`ide.0,unit=1`)입니다. 기존 VirtualBox 등록 정보나 원본 디스크를 이 도구가 변경하지는 않습니다.

부팅 뒤 `help` 또는 `source /commands`로 확인합니다. 다른 UTF-8 명령파일은 `tools/shell_disk.py --command-file <경로>`로 새 디스크의 `/COMMANDS` 자리에 설치할 수 있습니다.

이번 작업에서 `build/worldos-KOR-shell.vdi`를 실제로 생성했습니다. 이미 있는 파일을 재생성하려면 기존 것을 덮어쓰지 말고 다른 새 출력 이름을 지정하세요.

## 커널에 함께 필요한 세 수정

`run`의 실제 `fork → exec → waitpid` 시험에서 페이지 복사 후 이전 주소 변환이 남아 잘못된 명령을 실행하는 오류를 발견했습니다. 페이지 테이블을 새 물리 프레임으로 바꾼 뒤 `reloadCR3()`를 호출하여 가상 주소로 쓰기 전에 주소 변환을 갱신했습니다.

또 시스템 호출의 자판 직접 읽기 보조 경로에서 스캔코드 `0x35`가 `-`로 잘못 대응되어 있었습니다. 이를 `/`로 고쳤습니다. 별도 자판 드라이버의 이미 올바른 대응은 변경하지 않았습니다.

타밀 문자판에서는 위 두 수정을 적용한 후에도 외부 프로그램 실행 뒤 종료 문구가 `WORLDOS-SHELL:EX`에서 끊겼습니다. 시험용 게스트 메모리를 확인한 결과, 종료 문구의 마지막 네 바이트가 다음 메모리 조각을 가리키는 포인터로 덮여 있었습니다. 정렬 할당기가 요청 크기만 보고 빈 조각을 선택한 뒤 정렬 여백을 추가하여, 조각 경계를 넘고 남은 크기를 음수처럼 감싸게 하는 결함이었습니다. 이제 **요청 크기와 앞쪽 정렬 여백이 모두 들어가는 조각만 선택**하며, 정확히 맞는 공간도 사용하고 크기 넘침을 거부합니다. 수정 후 동일한 타밀어 전체 셸 시험이 통과했습니다.

`tools/fix_shell_kernel_paths.py`가 295개 판의 해당 Go 파일 세 개씩만 수정하고, 원래 이름을 유지하며, 검증 해시와 변경 전후 감사를 갱신했습니다. 새 셸 설치기 자체는 커널 소스를 수정하지 않습니다. 변경 전 백업은 각 소스 감사 파일의 `functional_fixes`에 기록되어 있습니다. 최초 두 수정은 `/tmp/worldos-shell-kernel-backup-nazrtakv/USA`와 `/tmp/worldos-shell-kernel-backup-yo_so85m/`, 정렬 할당 수정은 `/tmp/worldos-shell-kernel-backup-kd5e2a5z/IND/ta_Taml`와 `/tmp/worldos-shell-kernel-backup-exazs4uu/`에 있습니다. 임시 폴더이므로 장기 보관용 백업은 아닙니다. `engos`·`koros4` 원본 소스는 수정하지 않았습니다.

`make country-sources`는 기존의 강제 재생성 명령입니다. 수정한 소스를 보존하려면 실행하지 마세요. 향후 원본으로부터 의도적으로 재생성할 때는 명명 개정과 이 세 커널 수정을 다시 적용하고 셸 연결·빌드·부팅을 재검사해야 합니다. 현재 빌드와 셸 설치에는 재생성이 필요하지 않습니다.

## 검증 기록

최종 수정본은 295개 판 모두 셸·시험 ELF 빌드와 실제 셸 부팅 검사를 통과했습니다. 검사 기록의 셸 ELF·커널 ELF 해시가 현재 파일과 295개 모두 일치함도 확인했습니다. 한국판·영어판·타밀 문자판의 기존 POSIX 시험은 각 6개, 합계 18개를 다시 통과했습니다. 원본 VDI의 SHA-256은 변경되지 않았습니다.

빌드, 원문 변환, 부팅 결과를 별개로 기록합니다. 최종 결과는 아래 기계 판독 기록을 기준으로 확인하세요.

- [셸 소스·ELF 빌드 검사](../build-verification/shell-build-status.tsv)
- [실제 셸 부팅·현지어 명령·실행·UDP 검사](../build-verification/shell-boot-status.tsv)
- [원본 VDI의 변경 전후 SHA-256](../build-verification/shell-source-disk-check.json)

실제 부팅 시험은 판마다 전용 임시 디스크를 사용하며, 현지어 별칭·한글/힌디어/타밀어 UTF-8 내용·인수 인용·파일 읽기·`fork+exec+waitpid`·UDP·명령파일 중첩·잘못된 입력 거부·셸 종료를 확인합니다. ELF와 커널 해시도 결과에 기록합니다. 단위 시험은 명명 변환기와 셸 파서, 실제 32비트 정렬 할당 코드, 가나 읽기와 안전한 폴더명 변경 등을 합쳐 59개를 통과했습니다. 32비트 Go 실행을 차단하는 격리 환경에서는 해당 회귀 시험에 실행 허용이 필요합니다. 기존 국가판 249개와 문자판 46개의 소스 해시·역변환 검사도 통과했습니다.

```sh
make verify-shell-builds
make test-shells
python3 -m unittest discover -s tools -p 'test_*.py'
make verify-all-shell-boots \
  TEST_DISK='/home/user/VirtualBox VMs/eng operating system/NewVirtualDisk1-fixed-20260908.vdi'
```
