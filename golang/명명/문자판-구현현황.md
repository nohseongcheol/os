# 언어·문자별 소스 구현 현황

2026-09-10. **46개의 독립적으로 빌드되는 초기 문자판을 추가했다. 완역은 아니다.**
기존 `나라/*/소스` 249개는 변경하지 않았다. 원문 파일과 빌드용 대응표를 각 문자판에 복제했으며, 다른 국가판 소스를 빌드 중에 참조하지 않는다.

`기본`은 프로젝트의 생성 순서를 뜻하며 유일한 정자법이라는 선언이 아니다. 마니푸리어는 메이테이 문자와 벵골 문자를 둘 다 별도 소스로 제공한다. CLDR 자료의 primary/secondary 분류만으로 역사적·현대적 사용이나 사회적 우열을 단정하지 않는다.

## 번역 완성도와 남은 작업

- 인도판 신규 식별자 제안은 프로필당 **2~16개**다. 주 파일·일부 폴더 이름도 해당 문자로 제안했다. 나머지 약 1,700개 식별자는 미번역으로 명시한다. 영어 철자 대소문자 복원도 `changed_identifiers`에 포함되므로 그 수치를 번역 개수로 읽으면 안 된다.
- 기본안은 읽기·쓰기·초기화·크기·주소 참조, 자료가 있는 언어의 메모리 할당·해제 등이다. 의미 역할을 잃는 `메모리 관리자 → 메모리` 같은 형식 이름 치환은 적용하지 않았다.
- 신규 구절은 **프로젝트 번역 제안**이다. 정부 용어집에 실린 공인 번역이나 원어민 감수 완료를 뜻하지 않는다. 카슈미르어 등 추가 정자법과 보도어·도그리어·콩카니어·마니푸리어·산탈리어의 세부 표기는 특히 검토가 필요하다. 다른 언어의 빈칸을 힌디어로 채우지 않았다.
- 일본어 히라가나·가타카나판은 일본어 표현에서 읽기를 얻었다. 미번역 영어를 가나로 독음해서 번역으로 집계하지 않는다. 복합어의 음독·훈독은 문맥별 검토 대상이다. 이번 두 가나판의 식별자 대응표에는 한자가 남아 있지 않지만, 영어 미번역 부분·기술 약어·형식 접두부는 남아 있다.
- 중국어판은 기존 간체·번체 이름 대응을 이용한다. 기존의 부자연스러운 단어 조합까지 전부 교정한 것은 아니다. 세르비아어·보스니아어의 문자 변환도 의미 감수와 구분한다.
- 확실한 어원 자료가 없는 제안에 역사적 어원 설명을 만들어 붙이지 않았다. 전체 함수의 현재 동작과 각 언어의 자연스러운 어순·정자법·어원을 대조하는 검토가 남아 있다.

각 소스의 `식별자대응.tsv`에 `project-proposal`, `pending-translation`, `reading-needs-review`, `existing-unreviewed`, `compatibility` 상태를 기록한다. 모든 판의 `linguistic_review`는 `incomplete`다.

전체 색인은 [문자판-목록.tsv](../문자판-목록.tsv), 복수 문자 범위는 [문자판-범위점검.tsv](../문자판-범위점검.tsv), 미구현 후보는 [문자판-미구현.tsv](../문자판-미구현.tsv)에 있다. 범위 점검은 기존 국가판의 선택 언어와 인도 22개 언어를 대상으로 한다. 전 세계 모든 소수언어의 모든 문자까지 조사 완료했다는 뜻은 아니다.

413개 국가·언어·문자 후보 중 신규 소스 46개, 기존 문자 사용이 확인된 국가 소스 135개, 별도 구현이 없는 후보 232개다. 마지막 수에는 룬 문자·속기·역사적 문자도 포함된다. 아제르바이잔어·우즈베크어의 추가 문자, 산탈리어의 라틴·오디아 문자, 산스크리트어의 그란타·샤라다·싯담 등은 아직 구현하지 않았다. **요청한 전 세계 모든 복수 문자 및 모든 이름의 자연스러운 완역은 미완료다.**

## 빌드 방식과 사용법

원문은 `문자판/<국가>/<언어_문자>/<현지어 원문 폴더>/`에 있다. 2026-09-11부터 고정 이름 `소스` 대신 각 판의 `layout.json`이 지정하는 경로를 사용한다. [현재 관리 경로](관리경로-현지화.md)를 참고한다.

```sh
cd /home/user/worldos
make script-kernel VARIANT=IND/ta_Taml
make script-iso VARIANT=JPN/ja_Hira
make script-iso VARIANT=CHN/zh_Hant
make -C 문자판/IND/mni_Mtei/source userland
make test-script-variants
make verify-script-variants
python3 tools/verify_script_variants.py --build
```

결과는 각 소스의 `build/kernel.bin`, `build/kernel.iso`, `build/userland/`에 생성한다. 각 소스 폴더에서 바로 `make kernel` 또는 `make iso`도 가능하다. `문자판`은 기존 `언어/<ISO639-3>/` 배포 설정 폴더와 다르다. 후자의 7,847개 설정을 번역된 독립 소스로 집계하지 않는다.

많은 인도 문자에서 모음·받침·결합 기호는 글자의 필수 구성이다. 이를 삭제하거나 임의 로마자로 바꾸지 않는다. 다만 [표준 Go 식별자 규칙](https://go.dev/ref/spec#Identifiers)은 Unicode 문자·십진 숫자만 허용하고 다수의 결합 기호를 받지 못하므로, 이 소스는 **WorldOS 원문 식별자 방언**으로 명시했다.

빌드할 때 각 판에 포함된 문자판 구축 도구가 현재 원문을 읽어 임시 디렉터리에서 컴파일 대응명으로 복원한다. 중국어 간체판에서는 `文字构建.py`와 `文字映射.json`이며, 원래 이름 `문자빌드.py`·`문자대응.json`과의 대응은 원문 폴더의 `layout.json`에 있다. Go 키워드, 숫자·문자열·주석, C 공개 ABI와 기계 명령은 의미 번역하지 않는다. 번역 전 소스 전체를 숨겨 두고 그것을 대신 컴파일하는 방식이 아니다. 실행파일의 심볼과 일부 진단은 컴파일 대응명으로 표시되므로 대응표로 추적한다.

기존 파일의 코드 편집은 매 빌드에 반영한다. 새 파일·새 식별자·경로 변경은 대응표에도 등록해야 한다. 미등록 새 소스 파일은 조용히 무시하지 않고 오류로 알린다. 미등록 결합문자 식별자는 표준 Go 컴파일 오류로 검출한다. `make verify`는 생성 당시 해시를 확인하는 감사 명령이므로 의도적으로 코드를 수정한 뒤에는 해시 검토·갱신 전까지 실패할 수 있다.

`T`, `V`, 숫자 꼬리, `Makefile`, `src`, `build`, 파일 확장자와 공개 호출 규약은 형식·도구 호환성을 위해 남긴다. 국가판에서 물려받은 언어 설명·이전 사전·이전 안내서는 계승 자료 폴더(간체판 `继承资料`, 번체판 `承襲資料`)에 보관한다. 해당 자료는 새 문자판의 번역 근거가 아니며 본문은 역사적 자료로 유지했다. 화면 문구·글꼴·입력기·문자 조합 엔진 전체를 현지화한 작업도 아니다. 아래 검증은 문자판을 처음 추가했던 시점의 기록이며, 이후 경로 이동 검증은 별도 관리 경로 문서에 있다.

## 검증 결과

- 기존 국가 소스 249개 해시·대응 검사: 통과, 기존 소스 변경 없음.
- 새 46개 판 × 104개 파일: 원문 → 컴파일 대응명 복원 후 기존 구현과 바이트 단위 일치.
- 각 판의 Go 원문 43개에 식별자 처리를 적용, 빌드 보조 Go 도구 1개는 외부 라이브러리 호환 때문에 별도 보존.
- 커널·ISO 빌드: 46/46 통과.
- POSIX C 헤더·라이브러리 검사 및 실행 시험 프로그램 빌드: 46/46 통과.
- 실제 QEMU 기본 POSIX 실행: 46/46 통과.
- 타밀 문자판, 일본어 히라가나판, 중국 간체 국가의 번체판: 각각 기본·힙·fork·exec·표준입력·socket 6종 통과. 기본 시험 중복을 제외한 실행 결과는 총 **61/61 통과**.
- 새 문자 처리 회귀 시험 16개, 기존 명명 시험 14개: 통과.

빌드 결과는 [script-variant-status.tsv](../build-verification/script-variant-status.tsv), 실제 실행 결과는 [script-boot-status.tsv](../build-verification/script-boot-status.tsv)에 있다. 직렬 로그와 빌드 로그도 `build-verification/`에 보존한다. QEMU 실행에는 원본 디스크를 읽어서 만든 임시 복제와 스냅샷을 사용했으며 원본 가상 디스크는 수정하지 않았다.

이 검증은 커널 빌드 대상과 위 실행 시험에 대한 것이다. 기존 코드의 미사용 gate/phymem/text_mode 패키지 문제를 이번 명명 작업에서 고쳤거나 모든 선택 패키지까지 컴파일했다고 주장하지 않는다.

## 자료와 재현

- 언어 목록: 위 인도 내무부 제8부속서 자료.
- 문자 후보: [Unicode CLDR release-48 자료](https://github.com/unicode-org/cldr/blob/release-48/tools/cldr-code/src/main/resources/org/unicode/cldr/util/data/language_script.tsv). 로컬 사본 `cldr48-language-script.tsv`, 배포 고지 `UNICODE-LICENSE.txt`.
- 일본어 읽기: 생성 시에만 pykakasi 2.0.8 사용. [공식 API 설명](https://pykakasi.readthedocs.io/en/latest/api.html). 생성 의존성은 `/tmp/worldos-variants-resources/python`에 있으며 운영체제 빌드에는 필요 없다.
- 신규 표현: `tools/variant_terms.py`의 명시적 제안. 일부 설치 gettext 자료를 조사했지만, 전체 제안이 그 자료에서 확인됐다는 뜻은 아니다.

```sh
python3 tools/fetch_variant_resources.py /tmp/worldos-variants-resources
python3 tools/generate_script_variants.py
python3 tools/catalog_script_coverage.py
```

생성기는 기존 국가 소스를 덮어쓰지 않는다. 이미 존재하는 문자판은 내용 해시를 검사하며, 사용자가 수정한 소스나 빌드 처리기를 재생성으로 덮어쓰지 않는다.
