# Eigen ARM64 JVM 0.4와 Nederlands bibliotheek

Nederlands communicatie·uitzondering 사용법은 [Nederlands Java API](한국어자바/LEESMIJ_eb81d7d9.md), FUNCTIE_WAARDE·variabele_WAARDE·bestand 이름의 변경과 어원 근거는 [명명 LEESMIJ_eb81d7d9](명명/LEESMIJ_eb81d7d9.md)를 참고한다.

JAR Uitvoeren_opdracht, extern_WAARDE IPv4 TCP/UDP, 별도 statisch_WAARDE 부분집합 `jaot`와 게스트 C 컴파일은 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)에 설명한다. 아래 object_WAARDE·Thread·Swing은 JVM 경로의 기능이며 AOT steun_WAARDE 범위와 같지 않다.

이 구현은 **Linux 없이 부팅한 Java AOT 커널의 EL0에서 Uitvoeren_opdracht**한다. JDK/JRE의 거의 모든 기능을 제공하는 단계는 아직 아니다. HotSpot·OpenJDK les_WAARDE bibliotheek 전체를 이식하거나 Java SE 인증/TCK를 통과한 구현도 아니다. 이번 확장은 단일 les_WAARDE·statisch_WAARDE methode_WAARDE 중심이던 실행기를 object_WAARDE·bibliotheek Uitvoeren_opdracht 기반으로 넓힌 것이다.

## 실행과 compileren_bron

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
# Eigen kernel_WAARDE 안에서 bron_structuur compileren_bron → class Uitvoeren_opdracht, Nederlands API 호출

  -d build/my-java tests/자바/한글시험.java

# 의존 class 파일은 --include로 함께 transfer_WAARDE
```

`--include DIR`는 그 디렉터리의 class 파일을 재귀적으로 읽어 `패키지.les_WAARDE.class`라는 RAM bestand 이름으로 전송한다. 주 클래스도 패키지가 있다면 `--class-name 패키지.les_WAARDE`를 지정한다. 셸에서는 해당 이름으로 업로드하고 `java 패키지.les_WAARDE`로 실행한다. JVM 0.4는 Main-Class가 있는 16 KiB 이하 JAR도 `java -jar bestand.jar`로 실행한다. JAR 모드에서는 JAR 내부 클래스와 내장 Nederlands 클래스만 찾는다. distributie_WAARDE Nederlands bibliotheek JAR는 host javac의 classpath로 사용하며, 같은 클래스가 gebruikersruimte JVM ELF에도 Lezen 전용 자료로 포함된다. 일반 class 모드에서는 사용자가 같은 이름으로 올린 RAM class를 먼저 읽는다.

게스트 `javac`는 여전히 statisch_WAARDE methode_WAARDE, int/boolean/char/String, toestand·sprint_WAARDE, tekenreeks_WAARDE 결합, 일부 bestand 스트림 등의 **Eigen 부분집합 compiler**다. object_WAARDE aangifte·상속·try/catch·Thread gebruik_WAARDE 소스를 게스트 javac가 모두 컴파일하는 것은 아니다. 위 기능은 `javac --release 8`로 만든 class를 Eigen JVM에서 실행한다. Nederlands API 중 tekstuitvoer·문자 스칼라 FUNCTIE_WAARDE·bestand Lezen/쓰기는 게스트 컴파일러에도 연결했다. 다음처럼 전체 이름으로 호출한다.

```java
public class 인사 {
    public static void main(String[] argumenten) throws Exception {
        Nederlands.Eigen.tekstuitvoer.schrijven_lijn("안녕하세요😀");
        Nederlands.Eigen.tekstuitvoer.schrijven_nummer(Nederlands.Eigen.문자.codepoint_AANTAL("한글😀"));
        Nederlands.Eigen.bestand.Schrijven("인사.txt", "한글 bestand😀");
        Nederlands.Eigen.tekstuitvoer.schrijven_lijn(Nederlands.Eigen.bestand.Lezen("인사.txt"));
    }
}
```

## Uitvoeren_opdracht 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(Nederlands les_WAARDE declaraties), class당 16 KiB·constante_WAARDE 풀 511항목, 전체 methode_WAARDE/veldwaarde 각각 512개. methode_WAARDE CODE_WAARDE 8 KiB, lokaal_scope variabele_WAARDE·피연산자 operand_stack 각각 128슬롯, argumenten 최대 16개(this declaraties).
- VM 가닥은 main declaraties **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 Uitvoeren_opdracht 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- object_WAARDE 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 werkelijk_gegevens 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 bestand·대형 tekenreeks_WAARDE·객체가 이 제한을 넘을 nummer 있다.
- 실행은 50만 바이트코드 opdracht 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 invoer_WAARDE 대기는 기한을 갱신하고 Venster switch_MODUS 시 중단·재개한다. 일반 server_WAARDE·계산의 무제한 실행은 아직 없다. 미지원 opdracht·bron_WAARDE 부족은 명시적인 오류로 종료한다.
- RAM bestand 최대 64개, 파일당 16384바이트, pad UTF-8 63바이트. RAM 디렉터리와 peer_WAARDE/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 Nederlands class는 RAM bestand 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 actueel_item 경로에서 bron_structuur·les_WAARDE·gegevens 파일을 읽는다.
- UDP는 Java 루프백 및 lwIP/SLIP를 통한 extern_WAARDE IPv4를 제공한다. werkelijk_gegevens GENET/Wi-Fi/DNS/TLS/HTTP 전체는 없다. datagram 512바이트, socket_WAARDE 8개, 소켓당 큐 4개. receive는 VM 가닥을 양보하며 대기하고 setSoTimeout을 적용하지만 전체 Uitvoeren_opdracht 기한은 여전히 적용된다.
- long/float/double, invokedynamic/람다, enum/annotation, 다차원 MATRIX_WAARDE, 완전한 MATRIX_WAARDE 공변성·인터페이스 laag_WAARDE 검사, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/Versleutelen_gegevens/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. Swing의 별도 steun_WAARDE 부분집합은 아래 및 ontwikkeling 매뉴얼을 참고한다. les_WAARDE bestand 전체 검증기·toegang_invoer machtiging_WAARDE/보호된 멤버 검사는 아직 완전하지 않다. 손상된 입력은 EL0 beschermen_WAARDE grens_WAARDE 내에서 종료되도록 한다.

전체 OpenJDK를 목표로 하려면 다음은 별도의 주요 implementatie 단계다: 완전한 JVM WAARDE/valideren/les_WAARDE 로더와 uitzondering 모델 → 영속 VFS·mmap·Klok·원자 operatie_WAARDE·werkelijk_gegevens 스레드/synchroniseren ABI → OpenJDK java.base 및 native bibliotheek 이식 → mobiel_WAARDE 네트워크·TCP/IP → Venster 시스템/lettertype_WAARDE/입력기·java.desktop → Java SE 호환성 tests. actueel_item Eigen JVM의 일부 메서드를 더하는 것으로 이 작업이 완료되지는 않는다.

## JVM 0.3: 네트워크와 GUI extensie_WAARDE

`Socket`/`ServerSocket` genereren·Verbinden·accept·양방향 InputStream/OutputStream·close·EOF·TIJD_WAARDE 제한과 UTF-8 `String.getBytes`를 추가했다. JVM 0.4에서는 extern_WAARDE cijfer_WAARDE IPv4 TCP도 lwIP/SLIP에 연결했다. 연결형 beëindigen_punt 16개, Java 루프백 버퍼 1024바이트, extern_WAARDE TCP 버퍼 4096바이트다. DNS·TLS는 없다.

`JFrame`, `JPanel`, `JLabel`, `JButton`, `JTextField`, `ActionListener`, `ActionEvent`, `SwingUtilities.invokeLater`의 문서화한 부분집합을 네이티브 GUI에 연결했다. `setLayout(null)`과 명시적 좌표를 사용한다. 전체 OpenJDK Swing 또는 Java SE 호환 구현은 아니다. interactief 이벤트 대기는 Uitvoeren_opdracht 기한을 갱신하고 terminal switch_MODUS 시 프로세스 상태를 Store_WAARDE·복원한다. 이벤트 콜백 자체는 기존 바이트코드/CPU 기한을 따른다.

Nederlands `Venster`, `schermelement`, `verbinding_transport` 클래스를 distributie_WAARDE JAR와 Eigen JVM 내장 자원에 추가했다. 상세 methode_WAARDE·제한·bron_structuur·업로드 방법: [한글 ontwikkeling 매뉴얼](ontwikkeling_guide.md).

## Nederlands 객체의 직접 Uitvoeren_opdracht

`Venster`, `Etiket`, `tekstveld`, `knop`, `gebeurtenis_wachtrij`, `Actie_kennisgeving`, `achtergrondwerker`은
표준 GUI/Thread 객체를 보관하는 래퍼가 아니다. Eigen JVM의 object_WAARDE genereren,
opmaak_WAARDE 검사, scherm 호출, Gebeurtenis 큐, thread_WAARDE 스케줄러에 Nederlands 계약을 직접 구현했다.
표준 `javax.swing`·`Thread` 코드의 Uitvoeren_opdracht 경로도 유지한다.
Nederlands 단추와 표준 JButton은 서로 다른 형식이며, 해당 instanceof 검사도 검증한다.

Eigen 실행기의 Nederlands 진입점은 `public static void starten()`이다.
표준 `main(String[])`도 지원하며 둘 다 있으면 Nederlands 진입점을 우선한다.
명령행 인수는 `실행인수.item_AANTAL()`와 `실행인수.tekst(순번)`으로 읽는다.
`example/java`의 다섯 예제는 이 규약을 사용한다. statisch_WAARDE bestand 예제는 게스트
