# بومی ARM64 JVM 0.4와 فارسی کتابخانه

فارسی 통신·استثنا 사용법은 [فارسی Java API](한국어자바/مرا_بخوان_eb81d7d9.md), عملکرد_مقدار·변수·پرونده 이름의 변경과 어원 근거는 [명명 مرا_بخوان_eb81d7d9](명명/مرا_بخوان_eb81d7d9.md)를 참고한다.

JAR اجرا_فرمان, 외부 IPv4 TCP/UDP, 별도 ایستا_مقدار 부분집합 `jaot`와 게스트 C 컴파일은 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)에 설명한다. 아래 شئ_مقدار·Thread·Swing은 JVM 경로의 기능이며 AOT پشتیبان_مقدار 범위와 같지 않다.

이 구현은 **Linux 없이 부팅한 Java AOT 커널의 EL0에서 اجرا_فرمان**한다. JDK/JRE의 거의 모든 기능을 제공하는 단계는 아직 아니다. HotSpot·OpenJDK کلاس_مقدار کتابخانه 전체를 이식하거나 Java SE 인증/TCK를 통과한 구현도 아니다. 이번 확장은 단일 کلاس_مقدار·ایستا_مقدار روش_مقدار 중심이던 실행기를 شئ_مقدار·کتابخانه اجرا_فرمان 기반으로 넓힌 것이다.

## 실행과 ساختن_منبع

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
# بومی هسته_مقدار 안에서 منبع_درخت ساختن_منبع → class اجرا_فرمان, فارسی API 호출
python3 ابزارها/اجرا_فایل.py 시험/자바/한글소스.java

# شئ_مقدار·استثنا 등은 میزبان JDK로 Java 8 class를 만든 후 بومی 커널에서 اجرا_فرمان
mkdir -p build/my-java
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/my-java 시험/자바/한글시험.java
python3 ابزارها/اجرا_فایل.py build/my-java/한글시험.class

# 의존 class 파일은 --include로 함께 انتقال_مقدار_630ba093
javac --release 8 -encoding UTF-8 -d build/my-java 시험/자바/객체시험.java
python3 ابزارها/اجرا_فایل.py build/my-java/객체시험.class \
  --include build/my-java/زمینه_مقدار_0764f371.class --include build/my-java/شعبه_مقدار.class \
  --include build/my-java/계산가능.class

make test-jvm
```

`--include DIR`는 그 디렉터리의 class 파일을 재귀적으로 읽어 `패키지.کلاس_مقدار.class`라는 RAM پرونده 이름으로 전송한다. 주 클래스도 패키지가 있다면 `--class-name 패키지.کلاس_مقدار`를 지정한다. 셸에서는 해당 이름으로 업로드하고 `java 패키지.کلاس_مقدار`로 실행한다. JVM 0.4는 Main-Class가 있는 16 KiB 이하 JAR도 `java -jar پرونده.jar`로 실행한다. JAR 모드에서는 JAR 내부 클래스와 내장 فارسی 클래스만 찾는다. 배포 فارسی کتابخانه JAR는 میزبان javac의 classpath로 사용하며, 같은 클래스가 کاربر JVM ELF에도 خواندن 전용 자료로 포함된다. 일반 class 모드에서는 사용자가 같은 이름으로 올린 RAM class를 먼저 읽는다.

게스트 `javac`는 여전히 ایستا_مقدار روش_مقدار, int/boolean/char/String, شرط·تکرار_مقدار, رشته_مقدار_6ca8363c 결합, 일부 پرونده 스트림 등의 **بومی 부분집합 컴파일러**다. شئ_مقدار اعلامیه·상속·try/catch·Thread 사용 소스를 게스트 javac가 모두 컴파일하는 것은 아니다. 위 기능은 `javac --release 8`로 만든 class를 بومی JVM에서 실행한다. فارسی API 중 خروجی·문자 스칼라 عملکرد_مقدار·پرونده خواندن/쓰기는 게스트 컴파일러에도 연결했다. 다음처럼 전체 이름으로 호출한다.

```java
public class 인사 {
    public static void main(String[] نشانوندها) throws Exception {
        فارسی.بومی.خروجی.نوشتن_خط("안녕하세요😀");
        فارسی.بومی.خروجی.수쓰기(فارسی.بومی.문자.코드포인트수("한글😀"));
        فارسی.بومی.پرونده.نوشتن("인사.txt", "한글 پرونده😀");
        فارسی.بومی.خروجی.نوشتن_خط(فارسی.بومی.پرونده.خواندن("인사.txt"));
    }
}
```

## فارسی API

독립 패키지 **`فارسی.بومی`**를 사용한다. Linux판 `فارسی.자바`가 요구하는 NIO/Swing/HTTP API를 بومی 커널에서 실행할 수 있다고 혼동하지 않도록 패키지를 나눴다. 이 라이브러리는 کلاس_مقدار نام·روش_مقدار·نشانوندها·فیلد_مقدار·پرونده 이름에 한국어를 사용한다. 표준 Java کلاس_مقدار 이름은 호환성을 위해 보존한다.

| کلاس_مقدار | 공개 기능 | 이름의 의미 |
|---|---|---|
| خروجی | نوشتن, نوشتن_خط, 수쓰기 | خروجی(出力): 내용을 바깥으로 내보냄 |
| 문자 | طول_مقدار, 같음, جای_گذاری_متن, برش_مقدار, تفسیر_عدد_صحیح/نوشتن_عدد_صحیح_مقدار, 코드포인트수, 부호화/رمزگشایی_داده_ها | 문자(文字), رمزگذاری_مقدار(符號): 글의 단위와 그 값을 바이트로 나타내는 فیلتر_مقدار |
| پرونده | خواندن/نوشتن(String نام), 바이트읽기/نوشتن_بایت_مقدار | 널리 쓰는 کاربر 용어를 보존; RAM 자료의 نام |
| ورودی_لیست | 더하기, خواندن, تغییر_مکان_مقدار, پاک_کردن_ورودی, اندازه, فناوری_اطلاعات_خالی_مقدار, پاک_کردن_مطالب | ورودی_لیست(目錄): 순서가 있는 ورودی_مقدار 모음 |
| لغت_نامه | 넣기, کشف_ورودی, 있는가, پاک_کردن_ورودی, اندازه, پاک_کردن_مطالب | لغت_نامه(辭典): 찾는 말인 열쇠에 값을 대응 |
| 작업 | اجرا_2(실행할일), 기다리기(작업가닥), تعلیق_کار, 살아있는가 | 작업 رشته_مقدار: 한 برنامه_f5044b9b 안의 اجرا_فرمان جریان_مقدار |
| 통신 | باز_کردن, ارسال, 받기, پایان_مهلت_زمانی, بستن | 통신(通信), 전문(電文), تبدیل_مقدار: داده_ها 교환·메시지·포트의 역할 |
| 화면 | 사각형, پاک_کردن_ورودی | 화면(畫面): واقعی_داده_ها 그림을 표시하는 면 |
| هسته_مقدار | 밀리초, 사각형 | بومی JVM의 고정 native اتصال; 일반 JNI는 아님 |

이 명명은 현재 기능을 설명하는 용어 선택이다. 기존 한국어에 없던 역사적 어원을 만들어 주장하지 않는다. فایل_نام_متن·식별자는 UTF-8 소스로 보관한다. `문자.رمزگشایی_داده_ها`는 잘못된 UTF-8에 IllegalArgumentException을 던지며, `부호화`는 짝이 없는 서로게이트를 `?`로 바꾼다. `پرونده.خواندن`는 엄격한 UTF-8 복호화를 적용한다. 화면 색은 `빨강 | (초록 << 8) | (파랑 << 16)` 형식이다.

## اجرا_فرمان 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(فارسی کلاس_مقدار 포함), class당 16 KiB·ثابت_مقدار 풀 511항목, 전체 روش_مقدار/فیلد_مقدار 각각 512개. روش_مقدار کد_مقدار 8 KiB, محلی_محدوده 변수·피연산자 스택 각각 128슬롯, نشانوندها 최대 16개(this 포함).
- VM 가닥은 main 포함 **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 اجرا_فرمان 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- شئ_مقدار 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 واقعی_داده_ها 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 پرونده·대형 رشته_مقدار_6ca8363c·객체가 이 제한을 넘을 수 있다.
- 실행은 50만 바이트코드 فرمان 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 입력 대기는 기한을 갱신하고 پنجره جابجایی_حالت 시 중단·재개한다. 일반 سرور_مقدار·계산의 무제한 실행은 아직 없다. 미지원 فرمان·منبع_مقدار 부족은 명시적인 오류로 종료한다.
- RAM پرونده 최대 64개, 파일당 16384바이트, مسیر UTF-8 63바이트. RAM 디렉터리와 مشابه_مقدار/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 فارسی class는 RAM پرونده 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 현재 경로에서 منبع_درخت·کلاس_مقدار·داده_ها 파일을 읽는다.
- UDP는 Java 루프백 및 lwIP/SLIP를 통한 외부 IPv4를 제공한다. واقعی_داده_ها GENET/Wi-Fi/DNS/TLS/HTTP 전체는 없다. 전문 512바이트, 소켓 8개, 소켓당 큐 4개. receive는 VM 가닥을 양보하며 대기하고 setSoTimeout을 적용하지만 전체 اجرا_فرمان 기한은 여전히 적용된다.
- long/float/double, invokedynamic/람다, enum/annotation, 다차원 آرايه_مقدار, 완전한 آرايه_مقدار 공변성·인터페이스 لایه_مقدار 검사, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/رمزگذاری_داده_ها/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. Swing의 별도 پشتیبان_مقدار 부분집합은 아래 및 개발 매뉴얼을 참고한다. کلاس_مقدار پرونده 전체 검증기·دسترسی_ورودی مجوز_مقدار/보호된 멤버 검사는 아직 완전하지 않다. 손상된 입력은 EL0 حفاظت_کردن_مقدار 경계 내에서 종료되도록 한다.

전체 OpenJDK를 목표로 하려면 다음은 별도의 주요 구현 단계다: 완전한 JVM مقدار/ارزیابی_کردن/کلاس_مقدار 로더와 استثنا 모델 → 영속 VFS·mmap·ساعت·원자 عملیات_مقدار·واقعی_داده_ها 스레드/همگام_سازی ABI → OpenJDK java.base 및 native کتابخانه 이식 → دستگاه_مقدار 네트워크·TCP/IP → پنجره 시스템/قلم_مقدار/입력기·java.desktop → Java SE 호환성 시험. 현재 بومی JVM의 일부 메서드를 더하는 것으로 이 작업이 완료되지는 않는다.

## ارزیابی_کردن

`ابزارها/자바가상기계시험.py`는 같은 Java 8 class 파일의 출력을 میزبان OpenJDK `-Xverify:all`과 QEMU raspi4b بومی 커널에서 비교한다. شئ_مقدار/상속/인터페이스·switch·آرايه_مقدار, استثنا/finally, 컬렉션/GC, Thread/잠금, فارسی UTF-8/پرونده/컬렉션, واقعی_داده_ها UDP 루프백/زمان_مقدار 초과, 게스트 한글 منبع_درخت ساختن_منبع, آرايه_مقدار تایپ_کردن_مقدار/کپی_مقدار/پرونده 경계·한글 패키지의 9개 비교 시험과 잘못된 class 버전/잘린 پرونده رد_کردن_مقدار 시험을 실행한다. UDP نمایش_دادن_جذر 실행에는 میزبان 루프백 소켓 권한이 필요하다.

`ابزارها/부팅시험.py`는 هسته_مقدار حفاظت_کردن_مقدار/회귀 시험과 별도로 فارسی Java 화면 API가 واقعی_داده_ها 픽셀을 그렸는지도 QMP 화면 캡처로 검사한다. 보고서는 `build/verification/jvm/report.json`, `build/verification/report.json`이며 시험한 kernel8.img의 SHA-256을 기록한다. واقعی_داده_ها Pi4 하드웨어 부팅 시험과 전체 JDK 호환성 시험 결과는 아니다.


## JVM 0.3: 네트워크와 GUI تمدید_مقدار

`Socket`/`ServerSocket` ایجاد·اتصال·accept·양방향 InputStream/OutputStream·close·EOF·زمان_مقدار 제한과 UTF-8 `String.getBytes`를 추가했다. JVM 0.4에서는 외부 رقم_مقدار IPv4 TCP도 lwIP/SLIP에 연결했다. 연결형 پایان_دادن_نقطه 16개, Java 루프백 버퍼 1024바이트, 외부 TCP 버퍼 4096바이트다. DNS·TLS는 없다.

`JFrame`, `JPanel`, `JLabel`, `JButton`, `JTextField`, `ActionListener`, `ActionEvent`, `SwingUtilities.invokeLater`의 문서화한 부분집합을 네이티브 GUI에 연결했다. `setLayout(null)`과 명시적 좌표를 사용한다. 전체 OpenJDK Swing 또는 Java SE 호환 구현은 아니다. محاوره_ای 이벤트 대기는 اجرا_فرمان 기한을 갱신하고 پایانه جابجایی_حالت 시 프로세스 상태를 ذخیره_مقدار·복원한다. 이벤트 콜백 자체는 기존 바이트코드/CPU 기한을 따른다.

فارسی `پنجره`, `ویجت`, `연결통신` 클래스를 배포 JAR와 بومی JVM 내장 자원에 추가했다. 상세 روش_مقدار·제한·منبع_درخت·업로드 방법: [한글 개발 매뉴얼](개발안내.md).

## فارسی 객체의 직접 اجرا_فرمان

`پنجره`, `برچسب`, `متن_فیلد`, `دکمه`, `رویداد_صف`, `동작알림`, `작업가닥`은
표준 GUI/Thread 객체를 보관하는 래퍼가 아니다. بومی JVM의 شئ_مقدار ایجاد,
قالب_مقدار 검사, 화면 호출, رویداد 큐, رشته_مقدار 스케줄러에 فارسی 계약을 직접 구현했다.
표준 `javax.swing`·`Thread` 코드의 اجرا_فرمان 경로도 유지한다.
فارسی 단추와 표준 JButton은 서로 다른 형식이며, 해당 instanceof 검사도 검증한다.

بومی 실행기의 فارسی 진입점은 `public static void اجرا_2()`이다.
표준 `main(String[])`도 지원하며 둘 다 있으면 فارسی 진입점을 우선한다.
명령행 인수는 `실행인수.개수()`와 `실행인수.متن(순번)`으로 읽는다.
`example/java`의 다섯 예제는 이 규약을 사용한다. ایستا_مقدار پرونده 예제는 게스트
javac로도 컴파일하며, GUI/رشته_مقدار 소스는 میزبان `javac --release 8`을 사용한다.
직접 GUI/رشته_مقدار API는 بومی JVM 전용이다. 기존 OpenJDK 비교 시험과 별도로
فارسی 가닥의 اجرا_فرمان·منتظر_ماندن_مقدار·중복 اجرا_2 رد_کردن_مقدار, GUI رویداد 출처·فهرست·콜백을 검사한다.
전체 JDK 번역이나 모든 API의 jaot 지원을 뜻하지 않는다.

روش_مقدار 이름은 바이트코드에서도 유지된다. 이름과 참조를 같이 수정하면
فارسی 클래스도 실행되지만, رشته_مقدار_6ca8363c 리터럴·표준 کتابخانه 재정의·native
اتصال·진입점은 각각 컴파일러와 실행기의 계약을 맞춰야 한다.
[상세 계약과 예제](한국어자바/مرا_بخوان_eb81d7d9.md)를 참고한다.

## پایانه 부분 تازه_کردن

انتقال_مقدار·اندازه 변경은 새 پنجره 영역과 이전 자리에서 드러난 띠만 합성한다.
1920×32 پیکسل(240 KiB)의 임시 그림에서 배경·겹친 پنجره·نویسه_مقدار·GUI를 먼저
완성하고, 현재 نمایش_مقدار 메모리와 비교하여 달라진 화소만 기록한다.
32줄보다 큰 영역은 여러 띠로 처리하므로 전체 프레임을 원자적으로
교체하거나 수직 동기에 맞추는 방식은 아니다. 전체 배경을 먼저 지우는
중간 화면은 표시하지 않는다. 좌표가 같으면 다시 그리지 않는다.

`make test-redraw`는 واقعی_داده_ها C 그리기 코드를 호스트의 حافظه_داده_ها 화면에 연결해
انتقال_مقدار 80회·اندازه تغییر_مقدار 40회·겹친 پنجره 4개를 전체 합성 결과와 پیکسل 단위로 대조한다.
영역 밖 کاربر نقاشی_مقدار, 동일 پیکسل 무기록, اشاره_گر 밑그림, واقعی_داده_ها 화면 خط 간격을
검사한다. 이 시험의 시간은 میزبان CPU 측정이며 Pi 4/QEMU 속도로 해석하지 않는다.
`make test-resize`는 QEMU/VNC의 640×480 및 1920×1080에서 왼쪽 모서리 کشیدن_مقدار,
한글 입력·vi 미저장 محتوا_مقدار·독립 پنجره 크기를 검사한다.
