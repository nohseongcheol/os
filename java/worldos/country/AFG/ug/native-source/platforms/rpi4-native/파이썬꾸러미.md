# 자체 커널의 Python توپلام قاچىلاش_قىممىتى

자체 ARM64 커널의 `python`은 **MicroPython 1.24.1 پۈتۈن_سان نۇسخا_سىستېما**다.
`pip`와 `python -m pip`는 이 환경을 위한 제한형 مەنبە_دەرەخ قاچىلاش_قىممىتى 명령이다.
PyPA pip 전체나 CPython을 이식한 것은 아니다.

호스트에서 실행한다.

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
python3 قوراللار/ئىجرا_قىلىش_بۇيرۇق.py --desktop --network --pip
```

게스트 셸에서 설치하고 사용한다.

```text
pip install micropython-bisect==3.3.3
pip list
python -c 'from bisect import insort as 순서대로넣기; قىممىتى=[1,5]; 순서대로넣기(قىممىتى,3); print(قىممىتى)'
python -m pip list
pip uninstall micropython-bisect
```

정상 ئىجرا_قىلىش_بۇيرۇق 결과는 `[1, 3, 5]`다. 예시 배포 파일은
[PyPI의 micropython-bisect 3.3.3](https://pypi.org/project/micropython-bisect/3.3.3/)이며
SHA-256은 `b8d09d0bb4b2add706078dfa3f306e22fad1f4b5340b87d13f2c852507d720c8`이다.
`bisect`는 قاچىلاش_قىممىتى 전 내장되어 있지 않다. 내려받은 `.py`를 자체 커널의 EL0
MicroPython이 import하여 실행한다.

## قاچىلاش_قىممىتى 경로와 역할

호스트의 [꾸러미중계.py](قوراللار/꾸러미중계.py)는 PyPI HTTPS 다운로드, 인증서 دەلىللىمەك,
배포 ھۆججەت SHA-256 검증과 ئارخىپ_قىممىتى 해제를 맡는다. 호스트에서 `setup.py`나 내려받은
Python 코드를 실행하지 않는다. باقار pip 설치도 필요 없다.
중계는 `127.0.0.1:8027`에만 열리며 게스트는 QEMU NAT의 `10.0.2.2:8027`로 연결한다.
게스트 자체에 DNS·TLS·PyPI ئارخىپ_قىممىتى تارقىتىش_بوشلۇق 기능을 추가했다는 뜻은 아니다.

게스트의 [توپلام.py](파이썬연결/ئامبار/توپلام.py)는 TCP로 받은 파일의 SHA-256과
يول·چوڭلۇقى·문법을 검사한 ئارقىغا_قىممىتى `/lib`에 설치하고 `/lib/.pip.json`에 목록을 기록한다.
`/lib`와 ئىجرا_قىلىش_بۇيرۇق قوليازما_قىممىتى 폴더를 بۆلەك_قىممىتى_6d2d8bf4 검색 경로에 추가했으므로 작업 폴더가 달라도
설치한 모듈을 import할 수 있다. 패키지 폴더와 باراۋەرلىك_قىممىتى import도 지원한다.

قاچىلاش_قىممىتى 도중 공간 부족 등 오류가 발생하면 새 파일과 폴더를 지우고 기존 목록을
복원한다. 이미 있는 ئىشلەتكۈچى 파일을 덮어쓰지 않는다. 동일 버전 재설치 요청은
ھۆججەت 지문을 확인하고 유지한다. 다른 버전은 چىقىرىۋەتمەك_كىرگۈزۈش 후 설치한다. چىقىرىۋەتمەك_كىرگۈزۈش 시 사용자가
수정한 파일이 발견되면 보존하고 오류를 알린다. 빈 패키지 폴더는 남을 수 있다.

**`/lib`도 RAM 파일이다. 재부팅하면 설치한 패키지가 사라진다.**
باقار `build/pip-cache`에는 배포 파일과 출처·지문이 남으므로 كېيىنكى_تۈر 부팅에서 다시
설치할 수 있다. 버전을 지정하면 같은 배포 파일을 재사용한다.

```sh
# باقار: 인터넷이 있을 때 배포 파일만 تەييارلىماق
python3 قوراللار/꾸러미중계.py --fetch micropython-bisect==3.3.3
# كېيىنكى_تۈر ئىجرا_قىلىش_بۇيرۇق: PyPI ئۇلا 없이 캐시 사용
python3 قوراللار/ئىجرا_قىلىش_بۇيرۇق.py --network --pip --pip-offline
```

다른 포트는 باقار `--pip-port 8028`, 게스트
`pip install micropython-bisect==3.3.3 --port 8028`로 맞춘다.
باقار 중계는 `python3 قوراللار/꾸러미중계.py --port 8027`로 별도 실행할 수도 있다.
QEMU를 종료하거나 중계 실행을 끝내면 이 서비스도 닫힌다.

## قوللاش_قىممىتى كەسمە

- 의존성 없는 순수 Python wheel(`*-none-any.whl`, `Root-Is-Purelib: true`).
- 구형 `micropython-*` مەنبە_دەرەخ 배포형의 `.py`와 `PKG-INFO`.
- 꾸러미당 مەنبە_دەرەخ 16개, 합계 64 KiB, 파일당 16 KiB, 절대 يول UTF-8 63바이트 이하.
  전체 RAM ھۆججەت 64개·مۇندەرىجە_قىممىتى 16개의 남은 공간과 Python 힙 256 KiB 한도도 적용된다.
- `install`, `list`, `uninstall`, `--help`, `--version`.
- SHA-256, JSON, ساقلىغۇچ_مەلۇمات `io.StringIO`/`BytesIO`를 실행기에 추가했다.
  일반 ھۆججەت ئوبيېكت_قىممىتى `open()`은 미지원이며 `한국어.파일읽기/يازماق_ھۆججەت` 또는
  `jkoros.read/write`를 사용한다.

C كېڭەيتمە_قىممىتى·플랫폼 전용 wheel, 일반 sdist نۇسخا_سىستېما, 자동 의존성 해결, extras, VCS/임의 URL,
NumPy 같은 CPython 전용 패키지는 지원하지 않는다. 순수 Python 패키지도
MicroPython의 문법·표준 بۆلەك_قىممىتى_6d2d8bf4·پۈتۈن_سان 전용 환경과 맞아야 실제로 실행할 수 있다.
قاچىلاش_قىممىتى 시 문법을 검사하지만 모든 ئىجرا_قىلىش_بۇيرۇق 경로의 호환성을 증명하지는 않는다.
ھەقىقىي_مەلۇمات Raspberry Pi 4의 LAN을 통한 설치는 검증하지 않았으며 현재 중계는 QEMU용이다.

MicroPython 자체의 패키지 체계와 CPython pip의 차이는
[MicroPython 패키지 문서](https://docs.micropython.org/en/v1.24.0/reference/packages.html),
wheel 형식은 [PyPA 배포 فورمات_قىممىتى ئۆلچەملىك_SD](https://packaging.python.org/en/latest/specifications/binary-distribution-format/)을 참고한다.

```sh
make test-pip
```

دەلىللەش 기록은 `build/verification/pip/report.json`과 `serial.log`에 저장한다.
ھەقىقىي_مەلۇمات PyPI توپلام 시험과 별도로 시험용 wheel로 패키지 مۇندەرىجە_قىممىتى, 구문 خاتالىق,
공간 부족 되돌림을 확인한다.
