# användarutrymme 호출 gräns_värde

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `dator/operativsystem_Samtal.s`에서 EAX(INDEX), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 argument)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. kärna_värde 실패는 음수 fel INDEX, C bibliotek 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 användarutrymme område_värde_0e9a97ab 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C data 주소는 byte_värde 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java filnamn 흐름의 어셈블리 경계가 별도 byte_värde 버퍼를 마련하여 같은 호출을 사용한다.

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 Adress 두 칸이다. få_värde 주소가 NULL이면 peer_värde Adress 기록을 생략한다. sockaddr_in은 16바이트이며 Adress 체계는 enhet_värde byte_värde SEKVENS_värde, 접속번호와 IP 주소는 네트워크 byte_värde 차례다. 축소된 Adress 버퍼에도 들어가는 앞부분을 쓰고 전체 Adress Storlek 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 Utgång_app, 2·3은 기존 argument 조회다. aktuellt_objekt 커널의 argument 목록이 köra_kommando 이름을 제외하므로 C 진입기는 argv[0]에 고정 sträng_värde `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX Process_värde ABI와 다른 점이다.

표준 헤더의 heltal Storlek, 플래그 värde, stat fältvärde 순서는 `källfil/deklarationer/`에 정의한다. 동적 Anslut·다중 Process_värde·스레드가 추가되면 fel INDEX 저장과 resurs_värde 수명, 호출 경계도 함께 검토해야 한다.
