# 자체 ARM64 përdorues zbatoj_komandë ABI v1

이 ABI는 `platforms/rpi4-native`의 제한된 freestanding zbatoj_komandë 환경이다. Linux AArch64 ABI나 POSIX 전체 구현이 아니다. **OpenJDK/JRE, CPython, libc, libstdc++는 아직 이식되지 않았다.**

ELF 로더는 Kartelë 확장자 대신 aktual_të_dhëna ELF 헤더를 검사한다. 아래 자체 ABI와 별도로 `run --linux FILE`에 제한된 Linux ARM64 statik_VALUE zbatoj_komandë Kartelë 경로를 추가했다. 두 시스템 호출 번호표를 혼합하지 않는다. [ELF·Linux ABI 매뉴얼](실행파일규약.md).

## ELF와 zbatoj_komandë 수명

- ELF64 little endian, ET_EXEC, EM_AARCH64, 버전 1, e_flags=0.
- program_f5044b9b 헤더 최대 16개. PT_LOAD는 Leximi 가능, 4 KiB drejtvendos_VALUE, 페이지 간 ndërthurje_VALUE 없음, filesz≤memsz, ndërtoj_IMAGE email fragment 안이어야 한다. W+X는 거부한다.
- 진입점은 Kartelë 내용이 있는 zbatoj_komandë 세그먼트 안의 4바이트 drejtvendos_VALUE 주소다.
- PT_NOTE에 Emër `JKOROS\0`(namesz=7), type=1, descsz=4, 버전 1의 little endian uint32가 필요하다. SDK의 `start.o`가 넣는다.
- PT_DYNAMIC/PT_INTERP/PT_TLS 등은 거부한다. 동적 재배치·공유 bibliotekë·TLS 로더가 없다.
- 커널에 포함한 ELF 묶음을 검증하고 별도 përdorues 메모리에 복사한 PAS_VALUE EL0로 진입한다. 커널에 함수로 statik_VALUE 링크해 호출하는 이전 `cpp_test`와 다르다.
- 내장 프로그램은 `demo.elf`, `fault.elf`의 8개 mbroj_VALUE 시험 MODE_VALUE, `network.elf`, 자체 Java Mjete, MicroPython이다. 셸의 `load`/`run FILE`로 RAM의 16KiB 이하 ELF도 같은 vlerësoj 경로로 실행한다.
- `_start`가 `user_start`를 호출하고 `.init_array` → `nis_përdorues_program(int)` → `.fini_array` 순서로 실행한 PAS_VALUE exit 호출을 수행한다. 인수는 호출 15로 읽으며 표준 argc/argv/envp 스택 배치는 없다.
- 한 번에 한 përdorues 프로그램이 CPU에서 실행된다. 네 터미널에 각 하나씩 ndërvepruese 프로그램을 일시 정지해 보관할 수 있다. 정상 dal_program·përjashtim·Ora_VALUE_4692cef5 초과 시 커널에 복귀하고 열린 Kartelë/소켓을 닫으며 përdorues 페이지 권한을 제거한다.
- statik_VALUE 생성자와 자동 객체의 RAII 소멸자를 시험했다. `__cxa_atexit`, 표준 C++ përjashtim/RTTI/STL, 일반적인 전역 objekt_VALUE dal_program 등록은 제공하지 않는다.

## 주소와 mbroj_VALUE

| 가상 email fragment | 용도 |
|---|---|
| 0x02000000–0x02bfffff | ELF ndërtoj_IMAGE, 최대 12 MiB |
| 0x02c00000–0x02ecffff | brk 힙, 최대 2880 KiB |
| 0x02ed0000–0x02efffff | 미매핑 구간/스택 아래 mbroj_VALUE 구간 |
| 0x02f00000–0x02ffffff | 1 MiB përdorues 스택 |

자체 JVM의 klasë_VALUE·objekt_VALUE 자료를 수용하도록 përdorues 창을 16 MiB로 확장했다. program_f5044b9b 헤더의 Lejoj_VALUE fragment, 페이지 leje_VALUE 검사, SDK 링커 skript_VALUE 및 mbroj_VALUE 시험이 같은 배치를 사용한다. 기존에 brk Ekzekuto 주소를 상수로 가정한 프로그램은 새 SDK로 다시 빌드한다. 일반 프로그램은 호출 8로 현재 brk를 조회한다.

zbatoj_komandë 코드는 EL0 Leximi/실행만, të_dhëna·힙·스택은 EL0 Leximi/쓰기만 허용한다. 나머지 bërthamë_VALUE RAM·pajisje_VALUE MMIO에는 EL0 권한을 주지 않는다. 이번 W^X 보장은 **përdorues 페이지에 대한 것**이다. kernel identity map의 전체 leje_VALUE 분할이나 다중 프로세스 email 공간 전환을 구현했다고 의미하지 않는다.

커널은 `-mgeneral-regs-only`로 빌드한다. përdorues C/C++는 FP/SIMD를 허용하고, përdorues futje_p_VALUE 시 vektor_VALUE 레지스터와 FPCR/FPSR를 초기화한다. bërthamë_VALUE 복귀용 callee-saved FP 상태를 보관한다. syscall/IRQ의 C 처리부는 FP 레지스터를 사용하지 않는다. 향후 여러 përdorues 스레드를 전환할 때에는 각 스레드의 전체 FP Konteksti_VALUE 보존을 별도로 구현해야 한다.

GIC-400의 물리 타이머 IRQ로 약 2초의 zbatoj_komandë 기한을 적용한다. SVC 없는 무한 반복도 종료한다. 시스템 호출 Ekzekuto 시 기한을 검사하지만 EL1 Proces_VALUE_futje 중에는 IRQ를 마스킹하므로 긴 출력/그리기 호출의 종료는 지연될 수 있다. 이것은 program_f5044b9b zbatoj_komandë 기한이며 일반 선점 스케줄러가 아니다.

미지원 호출은 -ENOSYS이다. 모든 përdorues 포인터와 해당 페이지의 Leximi/Shkrimi 권한을 확인한다. 파일은 3…18의 프로세스별 서술자를 bërthamë_VALUE 서술자로 변환한다. 0은 현재 셸의 표준 입력(UART 또는 리다이렉션/파이프), 1은 표준 출력(UART/GUI 또는 리다이렉션/파이프), 2는 UART/GUI 진단 출력이다. UART에 읽을 자료가 없으면 -EAGAIN, Kartelë/파이프 입력 끝이면 read가 0을 반환한다. 출력은 Kartelë/파이프에서 LF를 그대로 유지하고 UART에서만 CRLF로 표시한다. 파이프는 16 KiB 순차 버퍼이며 프로세스 간 동시 파이프/PTY는 아니다. read/write 요청은 65536바이트 이하이며, RAM 파일은 최대 64개, 각각 16384바이트다. Kartelë 경로는 현재 pasues 경로에 대한 homolog_VALUE POZICIONI 또는 `/`로 시작하는 절대 경로이며 UTF-8 63바이트까지다. 디렉터리 gjeneroj·빈 direktori_VALUE heq_futje·종류 조회는 호출 18로도 제공한다. 현재 POZICIONI 변경은 pasues 내장 cd가 담당한다. 그래픽 요청은 호출 22로 조회한 aktual_të_dhëna 화면 Madhësi 안의 직사각형만 허용한다. 프레임버퍼 email 자체는 사용자에게 노출하지 않는다.

힙의 페이지 mësim_VALUE 축소·재확장에서 다시 노출하는 페이지는 0으로 만든다. 같은 페이지 안에서 brk만 줄였다 늘리는 경우에는 해당 페이지 내용이 남을 수 있다. malloc/free나 mmap/mprotect의 구현은 아니다.

인수는 최대 8개·각 255바이트다. 잘못된 번호는 -EINVAL, 작은 버퍼는 -ENAMETOOLONG, Shkrimi 불가능한 포인터는 -EFAULT다. `run FILE [ARGS]`는 파일명을 Argumente 0으로 포함한다. `javac`/`java`/`python`은 instruksion_VALUE 자체를 제외한 토큰을 전달한다. 인수는 bërthamë_VALUE 보관 자료를 përdorues 버퍼로 복사하며 bërthamë_VALUE 포인터를 반환하지 않는다.

## UDP 루프백의 계약

바깥 IPv4는 lwIP/SLIP로 확장했다. 기존 fd/구조체/tregues 검사 규약을 유지하며 0.0.0.0 또는 10.0.2.15에 bind한 끝점을 바깥 통신에 연결한다. 127.0.0.1에 명시적으로 bind한 UDP는 루프백에 한정한다. 외부 TCP connect는 비차단 -EINPROGRESS(-115)를 반환할 수 있으므로 같은 주소로 재시도하여 완료를 확인한다. [zbatoj_komandë/제한](파일전송과번역.md).

`Internet_Familja`, `전문통신`, transferim_protokoll 0/`전문전송규약`을 허용한다. `struct 인터넷통신주소`는 16바이트이며 주소갈래는 pajisje_VALUE SEQUENCE_VALUE, 접속번호와 adresë_në_internet.주소값은 rrjet_VALUE 차례다. 호환용 pk_sockaddr_in도 같은 배치지만 독립 자료형이다. 한국어 함수는 직접 SVC를 호출하는 aktual_të_dhëna 함수이며 표준 이름으로 치환하는 매크로가 아니다. pritës Linux 헤더를 섞지 않는다.

- 목적지는 127.0.0.1만 Lejoj_VALUE. bind는 0.0.0.0 또는 127.0.0.1, port=0이면 49152…65535에서 빈 창구를 고른다.
- 미바인드 소켓의 첫 전송은 임시 창구를 바인드한다. 같은 창구의 중복 bind는 EADDRINUSE.
- 최대 8개 소켓, 각 큐 4개, 전문은 0…512바이트. 빈 전문도 소비된다.
- 수신 버퍼가 작으면 복사할 부분만 반환하고 전문의 나머지는 버린다. peer email/창구를 반환한다.
- flags는 현재 0만 Mbështetje_VALUE. 비차단 수신의 빈 큐 및 dërgoj_VALUE objektiv 큐 포화는 EAGAIN이다.
- objektiv portë_VALUE 없음은 ECONNREFUSED, 512바이트 초과는 EMSGSIZE, 루프백에 명시적으로 바인드한 UDP의 외부 IP는 ENETUNREACH, UDP 소켓에 잘못된 규약을 지정하면 EPROTONOSUPPORT. SOCK_STREAM은 별도 연결형 루프백에서 제공한다.
- 외부 IPv4 TCP/UDP 헤더·체크섬·재전송은 lwIP가 처리한다. aktual_të_dhëna GENET/Wi-Fi NIC, poll/select, setsockopt는 아직 없다. 연결형 루프백의 connect/listen/accept는 아래 shtesë_VALUE ABI로 제공한다.

## 여러 터미널의 përdorues Konteksti_VALUE

ndërvepruese tty/GUI 대기를 명시적으로 시작한 프로그램은 입력 대기에서 약 2초 기한을 갱신한다. Prit_VALUE 없이 무한 반복하면 타이머로 종료한다. 파이프/리다이렉션/복합 Komanda/스크립트에서 ndërvepruese 시작은 -ENOTSUP로 거부한다. vi와 Swing의 이벤트 루프가 이 API를 사용한다.

다른 창으로 전환하면 Tjetër_njësi Prit_VALUE SVC에서 EL0 문맥을 저장하고 해당 SVC를 재실행할 위치에서 재개한다. x0…x30, SP/PC/PSTATE, v0…v31, FPCR/FPSR, 매핑·힙·zbatoj_komandë Argumente·Kartelë/소켓 소유권을 보관한다. 스냅샷은 bërthamë_VALUE 전용 물리 email 0x04000000…0x07ffffff(네 hapësirë_për_tekst_VALUE ×16 MiB)에 저장한다. 현재 Aktiv EL0 email 창은 종전 0x02000000…0x02ffffff를 사용한다. 스냅샷 저장소는 EL0에서 접근할 수 없다. fork/exec/wait, SMP 또는 일반 선점형 프로세스 스케줄러의 구현은 아니다.

SVC 40은 소유한 연결형 소켓의 homolog_VALUE 포트 번호를 반환한다(자체 JVM용 numër_i_plotë pyetja_VALUE).

연결형 루프백 fd는 40…55, UDP fd는 32…39다. dal_program/Terminali X 닫기에서 해당 프로그램의 Kartelë·소켓을 회수한다. 연결형 읽기의 të_dhëna 없음은 -EAGAIN, 상대가 닫고 버퍼도 비면 0, 상대가 닫힌 PAS_VALUE 쓰기는 -EPIPE다. 쓰기는 짧게 완료될 수 있다. 큐 용량은 끝점마다 1024바이트이고 한 시스템 호출은 최대 512바이트를 옮긴다. 부모 리스너를 닫으면 아직 accept하지 않은 연결도 회수한다. 외부 연결은 lwIP TCP를 사용하며 외부 수신 버퍼는 4096바이트다. aktual_të_dhëna GENET NIC 드라이버는 없다.

협력 Prit_VALUE(17)는 일반 선점형 sleep/scheduler 구현이 아니다. 호출마다 최대 100 ms 동안 통신을 처리하고 përdorues zbatoj_komandë 기한을 갱신한다. grupoj 설치기의 비차단 TCP 대기에 사용한다.
