# propi ARM64 JVM 0.4와 Català biblioteca

Català 통신·excepció 사용법은 [Català Java API](한국어자바/LLEGIU_ME_eb81d7d9.md), FUNCIÓ_VALOR·변수·Fitxer 이름의 변경과 어원 근거는 [명명 LLEGIU_ME_eb81d7d9](명명/LLEGIU_ME_eb81d7d9.md)를 참고한다.

JAR Executa_ordre, extern_VALOR IPv4 TCP/UDP, 별도 estàtic_VALOR 부분집합 `jaot`와 게스트 C 컴파일은 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)에 설명한다. 아래 objecte_VALOR·Thread·Swing은 JVM 경로의 기능이며 AOT suport_VALOR 범위와 같지 않다.

이 구현은 **Linux 없이 부팅한 Java AOT 커널의 EL0에서 Executa_ordre**한다. JDK/JRE의 거의 모든 기능을 제공하는 단계는 아직 아니다. HotSpot·OpenJDK Classe_VALOR biblioteca 전체를 이식하거나 Java SE 인증/TCK를 통과한 구현도 아니다. 이번 확장은 단일 Classe_VALOR·estàtic_VALOR 메서드 중심이던 실행기를 objecte_VALOR·biblioteca Executa_ordre 기반으로 넓힌 것이다.

## 실행과 generar_font

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
# propi nucli_VALOR 안에서 font_arbre generar_font → class Executa_ordre, Català API 호출
python3 Eines/Executa_arxiu.py 시험/자바/한글소스.java

# objecte_VALOR·excepció 등은 allotjar JDK로 Java 8 class를 만든 후 propi 커널에서 Executa_ordre
mkdir -p build/my-java
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/my-java 시험/자바/한글시험.java
python3 Eines/Executa_arxiu.py build/my-java/한글시험.class

# 의존 class 파일은 --include로 함께 transferir_VALOR
javac --release 8 -encoding UTF-8 -d build/my-java 시험/자바/객체시험.java
python3 Eines/Executa_arxiu.py build/my-java/객체시험.class \
  --include build/my-java/Fons_VALOR.class --include build/my-java/branca_VALOR.class \
  --include build/my-java/계산가능.class

make test-jvm
```

`--include DIR`는 그 디렉터리의 class 파일을 재귀적으로 읽어 `패키지.Classe_VALOR.class`라는 RAM Fitxer 이름으로 전송한다. 주 클래스도 패키지가 있다면 `--class-name 패키지.Classe_VALOR`를 지정한다. 셸에서는 해당 이름으로 업로드하고 `java 패키지.Classe_VALOR`로 실행한다. JVM 0.4는 Main-Class가 있는 16 KiB 이하 JAR도 `java -jar Fitxer.jar`로 실행한다. JAR 모드에서는 JAR 내부 클래스와 내장 Català 클래스만 찾는다. 배포 Català biblioteca JAR는 allotjar javac의 classpath로 사용하며, 같은 클래스가 usuari JVM ELF에도 Lectura 전용 자료로 포함된다. 일반 class 모드에서는 사용자가 같은 이름으로 올린 RAM class를 먼저 읽는다.

게스트 `javac`는 여전히 estàtic_VALOR 메서드, int/boolean/char/String, condició·esprint_VALOR, cadena_VALOR 결합, 일부 Fitxer 스트림 등의 **propi 부분집합 컴파일러**다. objecte_VALOR declaració·상속·try/catch·Thread ús_VALOR 소스를 게스트 javac가 모두 컴파일하는 것은 아니다. 위 기능은 `javac --release 8`로 만든 class를 propi JVM에서 실행한다. Català API 중 Sortida·문자 스칼라 FUNCIÓ_VALOR·Fitxer Lectura/쓰기는 게스트 컴파일러에도 연결했다. 다음처럼 전체 이름으로 호출한다.

```java
public class 인사 {
    public static void main(String[] 인수) throws Exception {
        Català.propi.Sortida.escriure_línia("안녕하세요😀");
        Català.propi.Sortida.수쓰기(Català.propi.문자.codi_de_caràcter_COMPT("한글😀"));
        Català.propi.Fitxer.Escriptura("인사.txt", "한글 Fitxer😀");
        Català.propi.Sortida.escriure_línia(Català.propi.Fitxer.Lectura("인사.txt"));
    }
}
```

## Català API

독립 패키지 **`Català.propi`**를 사용한다. Linux판 `Català.자바`가 요구하는 NIO/Swing/HTTP API를 propi 커널에서 실행할 수 있다고 혼동하지 않도록 패키지를 나눴다. 이 라이브러리는 Classe_VALOR Nom·메서드·인수·camp_VALOR·Fitxer 이름에 한국어를 사용한다. 표준 Java Classe_VALOR 이름은 호환성을 위해 보존한다.

| Classe_VALOR | 공개 기능 | 이름의 의미 |
|---|---|---|
| Sortida | Escriptura, escriure_línia, 수쓰기 | Sortida(出力): 내용을 바깥으로 내보냄 |
| 문자 | durada_VALOR, 같음, enganxar_SMS, tallar_VALOR, 정수읽기/정수쓰기, codi_de_caràcter_COMPT, 부호화/desencriptar_dades | 문자(文字), codificació_VALOR(符號): 글의 단위와 그 값을 바이트로 나타내는 regla_VALOR |
| Fitxer | Lectura/Escriptura(String Nom), tancar_byte_VALOR/escriure_byte_VALOR | 널리 쓰는 usuari 용어를 보존; RAM 자료의 Nom |
| introducció_Llista | 더하기, Lectura, REEMPLAÇA_VALOR, esborrar_introducció, Mida, 비었는가, eliminar_Índex | introducció_Llista(目錄): 순서가 있는 introducció_VALOR 모음 |

## Executa_ordre 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(Català Classe_VALOR 포함), class당 16 KiB·상수 풀 511항목, 전체 메서드/camp_VALOR 각각 512개. 메서드 CODI_VALOR 8 KiB, local_Àmbit 변수·피연산자 스택 각각 128슬롯, 인수 최대 16개(this 포함).
- VM 가닥은 main 포함 **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 Executa_ordre 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- objecte_VALOR 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 real_dades 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 Fitxer·대형 cadena_VALOR·객체가 이 제한을 넘을 수 있다.
- 실행은 50만 바이트코드 Ordre 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 입력 대기는 기한을 갱신하고 Finestra canvi_MODA 시 중단·재개한다. 일반 servidor_VALOR·계산의 무제한 실행은 아직 없다. 미지원 Ordre·recurs_VALOR 부족은 명시적인 오류로 종료한다.
- RAM Fitxer 최대 64개, 파일당 16384바이트, Camí UTF-8 63바이트. RAM 디렉터리와 homòleg_VALOR/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 Català class는 RAM Fitxer 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 현재 경로에서 font_arbre·Classe_VALOR·dades 파일을 읽는다.
- UDP는 Java 루프백 및 lwIP/SLIP를 통한 extern_VALOR IPv4를 제공한다. real_dades GENET/Wi-Fi/DNS/TLS/HTTP 전체는 없다. 전문 512바이트, 소켓 8개, 소켓당 큐 4개. receive는 VM 가닥을 양보하며 대기하고 setSoTimeout을 적용하지만 전체 Executa_ordre 기한은 여전히 적용된다.
- long/float/double, invokedynamic/람다, enum/annotation, 다차원 MATRIU_VALOR, 완전한 MATRIU_VALOR 공변성·인터페이스 capa_VALOR 검사, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/xifrar_dades/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. Swing의 별도 suport_VALOR 부분집합은 아래 및 개발 매뉴얼을 참고한다. Classe_VALOR Fitxer 전체 검증기·accés_introducció permís_VALOR/보호된 멤버 검사는 아직 완전하지 않다. 손상된 입력은 EL0 protegir_VALOR 경계 내에서 종료되도록 한다.

전체 OpenJDK를 목표로 하려면 다음은 별도의 주요 구현 단계다: 완전한 JVM VALOR/validar/Classe_VALOR 로더와 excepció 모델 → 영속 VFS·mmap·Rellotge·원자 cirurgia_VALOR·real_dades 스레드/sincronitzar ABI → OpenJDK java.base 및 native biblioteca 이식 → dispositiu_VALOR 네트워크·TCP/IP → Finestra 시스템/tipus_de_lletra_VALOR/입력기·java.desktop → Java SE 호환성 시험. 현재 propi JVM의 일부 메서드를 더하는 것으로 이 작업이 완료되지는 않는다.

## JVM 0.3: 네트워크와 GUI extensió_VALOR

`Socket`/`ServerSocket` generar·Connecta·accept·양방향 InputStream/OutputStream·close·EOF·Hora_VALOR 제한과 UTF-8 `String.getBytes`를 추가했다. JVM 0.4에서는 extern_VALOR dígit_VALOR IPv4 TCP도 lwIP/SLIP에 연결했다. 연결형 finalitzar_p 16개, Java 루프백 버퍼 1024바이트, extern_VALOR TCP 버퍼 4096바이트다. DNS·TLS는 없다.

`JFrame`, `JPanel`, `JLabel`, `JButton`, `JTextField`, `ActionListener`, `ActionEvent`, `SwingUtilities.invokeLater`의 문서화한 부분집합을 네이티브 GUI에 연결했다. `setLayout(null)`과 명시적 좌표를 사용한다. 전체 OpenJDK Swing 또는 Java SE 호환 구현은 아니다. interactiu 이벤트 대기는 Executa_ordre 기한을 갱신하고 Terminal canvi_MODA 시 프로세스 상태를 Store_VALOR·복원한다. 이벤트 콜백 자체는 기존 바이트코드/CPU 기한을 따른다.

Català `Finestra`, `giny`, `연결통신` 클래스를 배포 JAR와 propi JVM 내장 자원에 추가했다. 상세 메서드·제한·font_arbre·업로드 방법: [한글 개발 매뉴얼](개발안내.md).

## Català 객체의 직접 Executa_ordre

`Finestra`, `Etiqueta`, `SMS_camp`, `Botó`, `incidència_cua`, `동작알림`, `작업가닥`은
표준 GUI/Thread 객체를 보관하는 래퍼가 아니다. propi JVM의 objecte_VALOR generar,
format_VALOR 검사, 화면 호출, Esdeveniment 큐, fil_VALOR 스케줄러에 Català 계약을 직접 구현했다.
표준 `javax.swing`·`Thread` 코드의 Executa_ordre 경로도 유지한다.
Català 단추와 표준 JButton은 서로 다른 형식이며, 해당 instanceof 검사도 검증한다.

propi 실행기의 Català 진입점은 `public static void Executa_2()`이다.
표준 `main(String[])`도 지원하며 둘 다 있으면 Català 진입점을 우선한다.
명령행 인수는 `실행인수.element_COMPT()`와 `실행인수.SMS(순번)`으로 읽는다.
`example/java`의 다섯 예제는 이 규약을 사용한다. estàtic_VALOR Fitxer 예제는 게스트
javac로도 컴파일하며, GUI/fil_VALOR 소스는 allotjar `javac --release 8`을 사용한다.
직접 GUI/fil_VALOR API는 propi JVM 전용이다. 기존 OpenJDK 비교 시험과 별도로
