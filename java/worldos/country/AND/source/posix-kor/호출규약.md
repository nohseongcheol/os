# usuari 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `màquina/sistema_operatiu_Trucades.s`에서 EAX(INDEX), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 인수)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. nucli_VALOR 실패는 음수 s_ha_produït_un_error INDEX, C biblioteca 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 usuari 영역 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C dades 주소는 byte_VALOR 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java Fitxer 흐름의 어셈블리 경계가 별도 byte_VALOR 버퍼를 마련하여 같은 호출을 사용한다.

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 Adreça 두 칸이다. rebre_VALOR 주소가 NULL이면 homòleg_VALOR Adreça 기록을 생략한다. sockaddr_in은 16바이트이며 Adreça 체계는 dispositiu_VALOR byte_VALOR SEQÜÈNCIA_VALOR, 접속번호와 IP 주소는 네트워크 byte_VALOR 차례다. 축소된 Adreça 버퍼에도 들어가는 앞부분을 쓰고 전체 Adreça Mida 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 Surt_programa, 2·3은 기존 인수 조회다. 현재 커널의 인수 목록이 Executa_ordre 이름을 제외하므로 C 진입기는 argv[0]에 고정 cadena_VALOR `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX Procés_VALOR ABI와 다른 점이다.

표준 헤더의 정수 Mida, 플래그 VALOR, stat camp_VALOR 순서는 `FONT/포함/`에 정의한다. 동적 Connecta·다중 Procés_VALOR·스레드가 추가되면 s_ha_produït_un_error INDEX 저장과 recurs_VALOR 수명, 호출 경계도 함께 검토해야 한다.
