# jkoros 안에서 Java generar_font·Executa_ordre

이 문서의 부팅·shell·Store_VALOR 명령은 **x86 versió_VALOR** 기준이다. 공유 Java 컴파일러/JVM은 [propi ARM64 Pi4 versió_VALOR](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 nom_d_arxiu_SMS, `edit`의 단독 `.` Store_VALOR, 16개 RAM Fitxer, 약 2초 Executa_ordre 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 real_dades JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. allotjar generar_font 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 propi 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java programa_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 Executa_ordre

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. Executa_ordre 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox Executa_ordre LLEGIU_ME_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 Fitxer 전체를 새 내용으로 작성한다. 기존 내용의 línia Editar_VALOR 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 byte_VALOR 수 mostrar_VALOR.
- `cat FILE`: Fitxer contingut_VALOR mostrar_VALOR. 텍스트 소스에 사용한다.
- `rm FILE`: Memòria_dades Fitxer 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·TIPUS_VALOR 검사 error_VALOR 시 기존 `.class`는 유지된다. 소스를 고친 ENRERE_VALOR 컴파일이 실패했다면 이전 Executa_ordre 파일이 남아 있으므로 generar_font 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 Store_VALOR 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 font_arbre·Classe_VALOR·dades 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, Fitxer 이름은 ASCII 1~63자다. font_arbre 이름은 `.class` 확장자 공간 때문에 최대 62자다. Editar_VALOR 입력은 ASCII이고 한 línia 최대 128자다. línia 또는 Fitxer 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. nucli_VALOR/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 usuari 예제 이름은 ASCII로 작성한다.

## extern_VALOR Fitxer 적재

호스트에서 만든 소스나 suport_VALOR clip 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 real_dades 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# allotjar JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 Següent_element 빌드에서는 Annexa_introducció 파일을 포함하지 않는다. Fitxer contingut_VALOR 변경과 introducció_Llista 제거도 Següent_element 빌드에 반영된다. 원본 allotjar 파일에는 쓰지 않는다. valor_per_defecte `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 valor_per_defecte 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 Classe_VALOR Fitxer 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 suport_VALOR clip 안에 있어야 한다.

## suport_VALOR clip

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| Classe_VALOR | 패키지 없는 단일 Classe_VALOR, estàtic_VALOR FUNCIÓ_VALOR, 재귀, 인수/tornar_les_tasques_mesura | 실행마다 단일 Classe_VALOR 적재, public static main(String[]) |
| valor_per_defecte VALOR | int, boolean, char, String, main의 String[] 인수 | 정수·Referència 스택, String, int[], String[], 내부 StringBuilder |
| instrucció_VALOR | 초기값 있는 local_Àmbit declaració, tasca_VALOR, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 정수·Referència 바이트코드와 condició branca |
| expressió_VALOR | 십진 정수, UTF-8 소스의 cadena_VALOR/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, cadena_VALOR 결합 | 정수 cirurgia_VALOR·bit_VALOR cirurgia_VALOR·TIPUS_VALOR CONVERT_VALOR, 단락 평가, MATRIU_VALOR accés_introducció |
| Fitxer | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | real_dades nucli_VALOR 파일서술자와 Connecta, generar·eliminar_Índex·이어쓰기·EOF |
| Sortida | System.out.print/println: int/boolean/char/String, println() | 동일 |
| cadena_VALOR/인수 | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), cadena_VALOR 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 local_Àmbit declaració, 오버로드, 임의 TIPUS_VALOR CONVERT_VALOR, MATRIU_VALOR generar FONT, 8/16진 리터럴, Unicode font_arbre 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 상수 축소 변환을 구현하지 않는다. extern_VALOR `.class`의 `int[]` generar/Lectura/쓰기는 지원하므로 allotjar `javac --release 8`로 만든 MATRIU_VALOR 예제는 실행할 수 있다.

objecte_VALOR camp_VALOR·일반 objecte_VALOR generar·상속·인터페이스·여러 Classe_VALOR Connecta, long/float/double, excepció Procés_VALOR_introducció, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java excepció 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 cadena_VALOR Store_VALOR 공간은 Executa_ordre Surt_programa 시 usuari 영역 전체와 함께 회수한다. 지속 Executa_ordre 중 GC는 없다.

## Executa_ordre 한도와 s_ha_produït_un_error

| recurs_VALOR | 한도 |
| --- | --- |
| font_arbre/Classe_VALOR Fitxer | 각각 16KiB |
| 컴파일러 | testimoni_VALOR 2,047개, generar CODI_VALOR 4KiB, 상수 풀 4KiB |
| FUNCIÓ_VALOR/인수 | 클래스당 32함수, 함수당 16인수 |
| JVM 상수 | 511개 |
| JVM FUNCIÓ_VALOR CODI_VALOR | 함수당 8KiB |
| JVM 호출/스택/local_Àmbit 변수 | 32프레임, 프레임당 스택 128칸·local_Àmbit 128칸 |
| JVM objecte_VALOR Store_VALOR 공간 | 8,192개 32비트 칸, 헤더 포함 약 32KiB |
| Executa_ordre | 최대 500,000 Ordre, 기존 커널의 약 3초 CPU Executa_ordre 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 suport_VALOR 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM diccionari 검증기를 구현한 것은 아니다. Fitxer/valor_d_atribut durada_VALOR, 상수 Referència, Ordre·branca 경계를 검사하고, Executa_ordre 중 스택 format_VALOR·local_Àmbit inicialitzar·MATRIU_VALOR subíndex_VALOR·objecte_VALOR 참조를 검사한다. usuari 코드의 페이지·포트 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, generar_font·JVM 오류는 `Exit: 1`, Ordre 인수 오류는 `Exit: 2`다. CPU Hora_VALOR 상한은 기존 `Exit: 124`이며, usuari ELF 자체의 CPU/런타임 오류는 기존 Surt_programa 코드를 따른다. error_VALOR 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

`os/시험/자바시험.py`는 ELF/ISO 부팅, 게스트 generar_font·Executa_ordre, usuari 입력, 재귀·반복문·정수 극값·cadena_VALOR 결합·단락 평가, 재실행, font_arbre s_ha_produït_un_error 후 기존 Classe_VALOR 보존, MATRIU_VALOR/수 해독 s_ha_produït_un_error, 무한 esprint_VALOR 제한, Editar_VALOR 넘침과 Fitxer 부족을 검사한다. 게스트 generar 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 allotjar OpenJDK의 Classe_VALOR, 정수 배열과 한글 상수를 게스트에 적재하며, 손상된 Fitxer 표식·버전·상수 수·branca·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 시험 VM만 생성하고 종료한다.

구현 형식의 참고 dades: Oracle [JVM Classe_VALOR Fitxer 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM Ordre 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java Fitxer E_S

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 Classe_VALOR 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 ENRERE_VALOR `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. valor_per_defecte Sortida 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. excepció objecte_VALOR·try/catch·try-with-resources는 지원하지 않으며 Fitxer 오류를 진단하고 프로그램을 종료한다. MATRIU_VALOR E_S, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 Fitxer 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 shell `sync`가 필요하다. 예제의 Fitxer 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 real_dades 게스트 generar_font 결과를 OpenJDK `-Xverify:all`로 tornar_ho_a_provar_VALOR 실행해 Fitxer 바이트와 출력을 대조한다. 범위와 Store_VALOR suport_físic_VALOR 사용법은 [posix-kor LLEGIU_ME_eb81d7d9](../posix-kor/LLEGIU_ME_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
