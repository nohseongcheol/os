# 셸에서 실행하는 کاربر 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 مرا_بخوان_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 اجرا_فرمان

میزبان پایانه 1:

```sh
cd /home/user/jkoros
python3 os/ابزارها/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 외부 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

میزبان پایانه 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 واقعی_داده_ها CPU مجوز_مقدار `ring 3`, نشانوندها خروجی.
- `netcheck`: تبدیل_مقدار 중복, 잘못된 دستگیره_مقدار/اشاره_گر/طول_مقدار, 비차단 받기와 زمان_مقدار 초과 تأیید_صحت.
- `udp`: IPv4 آدرس·مقصد_مقدار تبدیل_مقدار·한 کلمات_مقدار 메시지를 받아 UDP로 보내고 같은 응답을 تأیید_صحت. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: میزبان `10.0.2.2`의 اختصاص_مقدار 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 حلقه_مقدار 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 현재 주소는 게스트 `10.0.2.15/24`, دروازه_مقدار `10.0.2.2`로 고정돼 있다. QEMU کاربر 네트워크의 میزبان دسترسی_ورودی 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 برنامه_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java برنامه_f5044b9b 추가

`예제/내프로그램.java`를 بعدی_مورد 형식으로 만든다. 진입점은 نشانوندها 없는 `static int` 또는 `static void` 함수다. 인수는 کاربر API로 조회한다.

```java
public final class 내프로그램 {
    public static int اجرا_2() {
        کاربر.نوشتن("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/کاربر/برنامه_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := کاربر/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.اجرا_2
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `کاربر/اعلامیه/کاربر.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 اجرا_فرمان 중인 VM에는 ساخت_سیستم 결과가 자동 반영되지 않는다. برنامه_f5044b9b 이름은 현재 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java کلاس_مقدار·عملکرد_مقدار·변수에는 한국어를 쓴다. 최대 32개 برنامه_f5044b9b, 한 اجرا_فرمان 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.اجرا_2 \
    -o os/build/apps/hello.elf os/کاربر/اعلامیه/کاربر.java os/کاربر/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 میزبان 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 پشتیبان_مقدار کلیپ 안에서 실행한다. `.jar`와 일반 Linux اجرا_فرمان 파일은 지원하지 않는다.

## کاربر 네트워크 API

선언은 `اعلامیه/کاربر.java`에 있다. `ارسال_داده_ها`/`자료받기`의 `int[]` مورد_عنصر 한 개는 بایت_مقدار 하나(0~255)를 나타낸다. 한 데이터그램의 최대 داده_ها 길이는 1,024바이트다.

```java
int دستگیره_مقدار = کاربر.ایجاد_شبکه(0); // 0: 임시 محلی_محدوده UDP تبدیل_مقدار 자동 مورد_انتخابی_مقدار
int[] داده_ها = new int[32];
داده_ها[0] = 'H'; داده_ها[1] = 'i';
int 보낸길이 = کاربر.ارسال_داده_ها(دستگیره_مقدار, 0x0a000202, 9000, داده_ها, 2);
int 받은길이 = کاربر.자료받기(دستگیره_مقدار, داده_ها, 1500);
کاربر.بستن_شبکه(دستگیره_مقدار);
```

واقعی_داده_ها 프로그램에서는 باز_کردن·ارسال·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 منتظر_ماندن_مقدار 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 추가 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | دستگیره_مقدار·فرآیند_مقدار_ورودی طول_مقدار·성공 등 해당 함수의 سنجش |
| -5 | دستگاه_مقدار ارسال_مقدار عدم_موفقیت_مقدار |
| -9 | 잘못되었거나 닫힌 통신 دستگیره_مقدار |
| -11 | 비차단 받기에서 도착한 داده_ها 없음 |
| -14 | کاربر اشاره_گر/آرايه_مقدار کلیپ خطا |
| -19 | پشتیبان_مقدار NIC 없음 |
| -22 | تبدیل_مقدار/منتظر_ماندن_مقدار زمان_مقدار/نشانوندها مقدار خطا |
| -24 | 열린 شبکه_تبدیل 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | داده_ها 또는 수신 آرايه_مقدار اندازه 문제 |
| -98 | محلی_محدوده تبدیل_مقدار فهرست 중복 |
| -101 | 지원하지 않는 مقصد_مقدار آدرس |
| -110 | ARP·دستگاه_مقدار·수신 زمان_مقدار 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 رمزگذاری_مقدار 있는 Java `int`의 بیت_مقدار 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## اجرا_فرمان 경계와 시스템 호출

```text
واسط run → JKAP에서 ELF ارزیابی_کردن·적재 → ring 3 کاربر برنامه_f5044b9b
                                 ↓ int 0x80
                      اشاره_گر 검사 → Java هسته_مقدار API → RTL8139/UDP
                                 ↓ خروج_برنامه·استثنا·زمان_مقدار 초과
                                واسط 복귀
```

시스템 호출 레지스터는 `EAX=فهرست`, `EBX,ECX,EDX,ESI,EDI=نشانوندها`, `EAX=سنجش`다. Java 호출 스택 ABI는 컴파일러가 کاربر 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| فهرست | 호출 |
| --- | --- |
| 0 | خروج_برنامه(وضعیت_مقدار کد_مقدار) — اجرا_2/خطا 런타임에서 사용 |
| 1 | رشته_مقدار_6ca8363c نوشتن |
| 2 / 3 | نشانوندها 개수 / نشانوندها رشته_مقدار_6ca8363c آدرس |
| 10 | UDP باز_کردن |
| 11 | UDP ارسال(دستگیره_مقدار, IP, مقصد_مقدار تبدیل_مقدار, آرايه_مقدار آدرس, طول_مقدار) |
| 12 | UDP 받기(دستگیره_مقدار, آرايه_مقدار آدرس, 제한 밀리초) |
| 13 | UDP بستن |
| 14 | محلی_محدوده IP آدرس |
| 15 / 16 | 마지막 مشابه_مقدار IP / UDP تبدیل_مقدار |
| 20 | RAM پرونده خواندن(نام int[] آدرس, خروجی int[] آدرس) |
| 21 | RAM پرونده نوشتن(نام int[] آدرس, 입력 int[] آدرس, بایت_مقدار طول_مقدار) |
| 22 | UTF-16 کد_مقدار درس_مقدار 문자 خروجی(0~65535) |

پرونده API는 `کاربر.파일읽기(int[] نام, int[] داده_ها)`와 `کاربر.نوشتن_فایل(int[] نام, int[] داده_ها, int طول_مقدار)`다. 이름은 ASCII کد_مقدار آرايه_مقدار(최대 64칸, 0 خروج_برنامه 또는 آرايه_مقدار 끝), داده_ها مورد_عنصر 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 پرونده 없음 `-2`, اشاره_گر خطا `-14`, نام/طول_مقدار خطا `-22`, پرونده شکاف_مقدار 부족 `-28`, اندازه 초과 `-90`을 반환한다. 쓰기는 ارزیابی_کردن 후 پرونده 전체를 대체한다. `کاربر.نوشتن_نویسه_مقدار(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 کاربر 모드에서 CS의 하위 비트를 직접 읽으므로 واقعی_داده_ها اجرا_فرمان 권한을 확인한다. هسته_مقدار 포트 접근용 `دستگاه_مقدار` native 함수는 کاربر هدف 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 اجرا_فرمان, 파이프, 프로세스 간 통신은 없다. اجرا_فرمان 파일은 커널의 خواندن 전용 JKAP 묶음에서 적재한다. داده_ها 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- کاربر 가상 آدرس `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. اجرا_فرمان 영상은 جلو_مقدار 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. هسته_مقدار identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB کاربر 영역을 비우고 پرونده 구역을 복사해 BSS·آرايه_مقدار 영역을 초기화한다. کاربر GC는 없지만 خروج_برنامه 후 بعدی_مورد اجرا_فرمان 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 نقل_قول/이스케이프 파싱은 없다.
- کاربر 페이지의 کد_مقدار/داده_ها 분리 خواندن 전용 تنظیمات, NX, 스택 guard, ASLR은 아직 없다. 커널과 کاربر حافظه_داده_ها·포트 مجوز_مقدار 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 اجرا_فرمان 상한을 두며 زمان_مقدار 초과는 `Exit: 124`다. کاربر CPU 예외는 `128 + استثنا فهرست`(페이지 خطا 142, 특권 위반 141), Java آرايه_مقدار/계산 오류는 101~105다. هسته_مقدار 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, ایستا_مقدار IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP مجموع_مقابله_ای 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- کاربر اجرا_فرمان·네트워크·حفاظت_کردن_مقدار 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 اجرا_فرمان·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## ارزیابی_کردن 근거

`make test`는 컴파일러 14개 시험, Java 패킷 شرط 2,201개 검사, 기존 واسط ELF/ISO 부팅 시험, کاربر ELF/واقعی_داده_ها UDP/حفاظت_کردن_مقدار 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 طول_مقدار·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 فرمان·무한 تکرار_مقدار 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
