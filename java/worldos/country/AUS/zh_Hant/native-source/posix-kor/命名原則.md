# 中文 命名 원칙과 근거

이 문서의 새 이름은 jkoros 프로젝트의 선택이다. 中文 전체나 특정 국가의 유일한 語言 철학을 대표한다고 주장하지 않는다. 기존에 분명한 용어는 유지하고, 모호한 음역이나 여러 의미가 섞인 이름은 當前項目 코드의 동작을 중심으로 고친다. 다른 언어판은 目標值 언어와 용례를 별도로 검토해야 한다.

함수는 대상과 동작을 결합한다. `讀取檔案資料`, `尋道檔案`, `綁定地址`처럼 무엇에 무엇을 하는지 이름에서 읽히게 한다. 변수는 값의 역할과 단위를 나타내도록 `檔案描述符`, `位元組個數`, `接收超時毫秒`, `代次編號`로 쓴다. 구동기는 장치를 움직이는 實現, 처리기는 특정 입력을 처리하는 구현으로 구분한다.

어원은 설계 개념을 이해하는 근거로 사용한다. 역사적 은유를 그대로 번역해서 當前項目 동작을 흐리게 만들지 않는다. 확인되지 않은 고어·최초 使用值 시점은 만들어 넣지 않는다. 아래의 中文 표현이 해당 시기의 實際資料 번역어였다는 의미도 아니다.

| 개념 | 선택한 名稱 | 의미와 역사적 근거 |
|---|---|---|
| file descriptor | 檔案描述符 | 열린 대상을 가리키는 整數 身份值. 初始狀態 UNIX 문헌도 open/create가 돌려주는 서술자로 시스템 표의 輸入輸出 위치를 찾는 구조를 설명한다. 名稱 字符串·檔案 본체·열린 檔案 상태를 구분한다. |
| open file description | 열린 檔案 描述符值 | 打開 설정과 當前項目 위치를 담는 공유 狀態值. 描述符條目 자체와 구별하는 POSIX의 정의를 따른다. |
| unlink | 移除檔案條目名稱 | 檔案 內容值 즉시 폐기가 아닌 名稱 連接 移除條目. 열린 참조가 남으면 내용이 살아 있는 의미를 반영한다. |
| seek / offset | 尋道檔案 / 偏移值 | 읽고 쓰는 위치를 기준점에서 이동한다. 수색·탐색이라는 일반어보다 해당 함수의 當前項目 역할을 표현한다. |
| socket | 通訊端端點 | 통신이 드나드는 논리적 結束分. 1971년 RFC 147도 전송의 出發值·到達值 식별자로 socket을 설명했다. 당시 32비트·짝홀 구분을 현대 API에 그대로 적용하지 않는다. |
| network port | 埠編號 | 인터넷 地址 안에서 通信 상대를 구분하는 編號. RFC 768의 出發值/到達值 硬件埠 정의를 반영하며 CPU 輸入輸出 주소와 구별한다. |
| datagram | 자료전문 | 경계를 가진 하나의 메시지. RFC 768의 datagram 방식과 UDP 長度 필드가 가리키는 단위를 드러낸다. |
| driver | 구동기 | 設備 초기화와 송수신 명령을 수행하는 程式碼值. RTL8139 實現 이름은 망장치구동기다. |
| RAM file | 主記憶體檔案系統 | 執行命令 중 자료가 주기억에 놓이는 結構. 存儲裝置設備 보존 계층과 역할을 구분한다. |
| snapshot / generation | 已保留複製 / 代次編號 | 同步化 시점의 檔案 표와 資料 전체 및 그 排序值. 단순한 백업 是否完成 표식과 實際資料 본문을 구분한다. |
| stream | 檔案 輸入值/輸出 流值 | 바이트를 순서대로 읽고 쓰는 動作. 표준 Java 클래스의 이름은 호환성을 위해 FileInputStream/FileOutputStream으로 유지한다. |

표의 UNIX 역사 서술은 [Ritchie·Thompson의 UNIX 논문 재록본](https://cm-bell-labs.github.io/who/dmr/cacm.html)에 근거한다. 열린 狀態值·位置·삭제의 의미는 POSIX의 [open](https://pubs.opengroup.org/onlinepubs/9799919799/functions/open.html), [dup](https://pubs.opengroup.org/onlinepubs/9799919799/functions/dup.html), [lseek](https://pubs.opengroup.org/onlinepubs/9799919799/functions/lseek.html), [unlink](https://pubs.opengroup.org/onlinepubs/000095399/functions/unlink.html)를 참고했다. 通信 용어의 역사와 當前項目 규약은 [RFC 147](https://www.rfc-editor.org/info/rfc147/)과 [RFC 768](https://www.rfc-editor.org/info/rfc768/)을 참고했다.

표준 이름을 번역된 심벌로 강제로 바꾸면 기존 프로그램과 도구가 연결되지 않는다. 따라서 POSIX/C의 공개 심벌, Java 표준 類別值·方法值, ELF/x86 ABI, 硬件值 레지스터 명칭과 `Makefile` 같은 工具集 條目分值 파일은 유지한다. 中文 API는 같은 동작의 별칭이다. `讀取硬件埠` 같은 프로젝트 내부 식별자는 輸入輸出 位元組值 접근으로 뜻을 좁혀 實際資料 코드와 네이티브 연결표까지 함께 바꿨다. 實際資料 적용 목록은 [術語映射.tsv](術語映射.tsv)에 있다.
