# 자체 ARM64 kánẹ́ẹ̀lì_iye: FTP, C, JAR와 AOT ṣiṣẹ́_àṣẹ

대상은 **Linux를 적재하지 않는 Raspberry Pi 4용 Java AOT kánẹ́ẹ̀lì_iye**이다. CPU·ohun_èlò_iye 경계는 C/어셈블리, Fáìlì 체계와 셸은 Java이며, 이번 TCP/IP 스택은 C로 작성된 lwIP 2.2.0을 이식했다. 게스트 TinyCC와 `jaot`도 EL0에서 실행한다. 호스트에 컴파일을 요청하거나 olùpèsè JVM으로 대신 실행하지 않는다.

## 먼저 알아둘 àtìlẹ́yìn_iye 경계

| 요청 | 이번 구현 | 남은 ní_ṣókí |
|---|---|---|
| JAR를 ṣiṣẹ́_àṣẹ 파일처럼 ṣiṣẹ́_àṣẹ | `java -jar Fáìlì.jar`, `./Fáìlì.jar 인수`; Main-Class와 Store_iye/DEFLATE ZIP, CRC 검사 | 전체 Java SE, 임의의 모든 JAR 호환성 |
| 게스트 AOT | `jaot Fáìlì.class -o Fáìlì.elf`, `jaot Fáìlì.jar -o Fáìlì.elf`; gangan_détà ARM64 기계어 생성 | nǹkan_iye·예외·Thread·Swing·Socket의 AOT 변환, 여러 애플리케이션 ọ̀wọ́_iye Darapọ̀ |
| C ṣàkójọ_ìtumò_èdè_kọ̀ǹpútà_orísun | 게스트 `cc`/`tcc`, TinyCC C 전처리기·ARM64 생성기·링커; 한국어 식별자와 posix-kor | 전체 libc, 일반 Linux ṣiṣẹ́_àṣẹ Fáìlì, 게스트 C++ 컴파일러 |

| 한글 Java | 기존 `한국어.자체` 클래스와 외부 àdírẹ́ẹ̀sì UDP 오버로드 | 전체 JDK의 일대일 한국어 대응 API |

JVM은 ọ̀wọ́_iye 버전 45…52의 문서화한 부분집합이다. `java`는 바이트코드 실행기이고, `jaot`가 별도의 네이티브 ṣiṣẹ́_àṣẹ 파일을 만든다. **JAR Ìpamọ_ọlọ́jọ́pípẹ́_iye 해제나 JVM을 함께 묶는 것을 AOT라고 표시하지 않는다.** 지원하지 않는 바이트코드/API는 `jaot`가 진단하고 출력을 만들지 않는다. 기존 출력 ELF도 ṣàkójọ_ìtumò_èdè_kọ̀ǹpútà_orísun ìkùnà_iye 때 보존한다.

Android의 Dalvik/ART는 일반 JVM ọ̀wọ́_iye/JAR가 아닌 **DEX**를 실행한다. ART의 AOT에는 GC, ọ̀wọ́_iye 로딩, JNI 등 ṣiṣẹ́_àṣẹ 기반도 필요하다. 따라서 ART처럼 기계어로 바꾸는 기능만으로 임의의 OpenJDK JAR 및 Swing이 자동 호환되지는 않는다. [Android 공식 런타임 설명](https://source.android.com/docs/core/runtime)

FTP는 루트 RAM 파일만 공개한다. 익명 로그인이며 비밀번호로 권한을 구분하지 않는다. àdáwọ̀ olùpèsè 바인딩은 `127.0.0.1`이고, ìdarí_iye 포트는 2121, 데이터 포트는 50000…50007이다. `--ftp-port 2122`로 ìdarí_iye 포트를 바꿀 수 있다. 동시에 한 FTP 세션을 제공하며 명령이 없는 세션은 60초 후 닫는다. TYPE A도 바이트를 변경하지 않으므로 프로그램은 바이너리 전송한다.

파일은 **64개, 각각 16 KiB**, 경로는 UTF-8 63바이트이다. 부팅 시 준비되는 `/example`도 이 한도를 공유한다. 초과/끊어진 STOR는 기존 파일에 반영하지 않는다. FTP 업로드는 RAM에만 저장되며 재부팅하면 사라진다. 이 제한 때문에 일반적인 대형 JAR 배포판을 그대로 올릴 수 없다.

QEMU의 raspi4b에는 GENET Ethernet 장치가 없다. 따라서 `network_bridge.py`가 QEMU NAT의 Ethernet과 보조 UART의 SLIP를 변환한다. **TCP Darapọ̀ Ìlànà_iye_ìgbéwọlé·체크섬·재전송·FTP 명령과 Fáìlì 저장은 게스트 안에서 수행한다.** olùpèsè 브리지는 FTP 서버가 아니다. [QEMU 공식 ohun_èlò_iye àtìlẹ́yìn_iye ìgbéwọlé_Àtòkọ](https://www.qemu.org/docs/master/system/arm/raspi.html)

이 경로는 QEMU에서 검증했다. 보조 UART의 gangan_détà Pi 4 핀/클럭 설정과 내장 RJ45 GENET 드라이버는 구현·검증하지 않았으므로, SD 이미지에 커널이 포함되어 있다는 사실을 gangan_détà 보드의 LAN/FTP ìṣe 보장으로 해석하면 안 된다.

## 한국어 Java를 게스트에서 컴파일하고 AOT ṣiṣẹ́_àṣẹ

게스트 `vi 빛.java`로 다음 소스를 작성한다.

```java
public class 빛 {
    public static void main(String[] 인수) throws Exception {
        int 합 = 0;
        int 수 = 1;
        while (수 <= 10) {
            합 = 합 + 수;
            수 = 수 + 1;
        }
        한국어.자체.출력.수쓰기(합);
        한국어.자체.Fáìlì.Kọ("aot.txt", "한글 AOT Fáìlì 😀");
        한국어.자체.출력.kọ_ìlà(한국어.자체.Fáìlì.Kàá("aot.txt"));
    }
}
```

```text
javac 빛.java
java 빛
jaot 빛.class -o 빛.elf
run 빛.elf
```

`jaot`은 클래스의 바이트코드를 C로 변환하고, **게스트 TinyCC**가 ARM64 명령어를 생성·연결한다. ṣiṣẹ́_àṣẹ 때 JVM 인터프리터를 호출하지 않는다. JAR의 Main-Class가 같은 àtìlẹ́yìn_iye 범위이면 다음도 가능하다.

```text
jaot 빛.jar -o 빛.elf
run 빛.elf
```

AOT 지원은 한 애플리케이션 클래스의 ìdágún_iye ìlànà_iye/àayè_wúnrẹ̀n_iye, int 계열, nọ́ńbà_odindi 배열과 Ìtọ́ka, 인수 ÀRÉÈ_iye, kání·ẹ̀ka·àṣetúnṣe_iye, fọ́nrán_iye 리터럴, `System.out.print/println`의 int/String, 한국어 출력·Fáìlì Kàá/쓰기로 제한된다. ọ̀wọ́_iye/ìlànà_iye 수와 스택 등에도 고정 상한이 있다. Java 예외 Ìlànà_iye_ìgbéwọlé, nǹkan_iye 생성, 가상 ìlànà_iye 일반, switch/wide, long/float/double, invokedynamic, fọ́nrán_iye 결합용 StringBuilder, 일반 JDK·Socket·Thread·Swing은 이 AOT 백엔드에서 미지원이다. 내장 NUL/고립된 서로게이트 문자열도 거부한다. 잘못된 ÀRÉÈ_iye wáyè_sí_ìgbéwọlé/0으로 나누기 등은 네이티브 런타임 오류로 종료하며 Java 예외 객체로 전달하지 않는다.

입력 클래스뿐 아니라 **생성된 ELF도 16 KiB 이하**여야 한다. 기계어 확장과 ELF 페이지 mu_dọ́gba_iye 때문에 짧은 클래스도 이 한도를 넘을 수 있으며, 이 경우 오류를 내고 기존 출력을 보존한다.

게스트 `javac`도 부분집합이다. 일반적인 nǹkan_iye·Thread·Swing 소스는 호스트에서 `javac --release 8`로 컴파일하고, **기존 JVM의 àtìlẹ́yìn_iye ní_ṣókí 안에서** `java`/`java -jar`로 실행한다. 정확한 API는 [JVM 매뉴얼](자바실행환경.md)과 [한글 개발 매뉴얼](개발안내.md)을 참고한다.

JAR는 하나의 애플리케이션 ọ̀wọ́_iye 경로다. 내부 Orúkọ `àkópọ̀/àtòjọ_ètò_f5044b9b.class`와 점으로 구분한 Main-Class를 지원한다. 내부 클래스는 파일로 풀어 VFS 슬롯을 소비하지 않는다. 내장 한국어 클래스를 추가로 찾지만 현재 작업 폴더의 다른 클래스는 자동 혼합하지 않는다. ZIP64·pàroko_détà ZIP·manifest Class-Path·서명 검증은 지원하지 않는다. JAR 하나가 16 KiB 이하이어도 클래스당/적재 수/VM 힙 제한은 그대로 적용된다.

## C에서 한국어 POSIX 호출

게스트에서 `vi 인사.c`로 작성하거나 FTP로 소스를 업로드한다.

```c
#include <파일규약.h>

int main(void) {
    const char 인사말[] = "자체 ARM64 C에서 한글 POSIX 호출\n";
    int 문서 = ṣí_fáìlì("인사.txt", tí_a_lè_kà_tí_a_lè_kọ | 없으면만들기 | 내용비우기, 0600);
    if (문서 < 0) return 1;
    입출력결과형 기록한수 = kọ_fáìlì_détà(문서, 인사말, sizeof(인사말) - 1);
    pa_dé_fáìlì(문서);
    kọ_fáìlì_détà(1, 인사말, sizeof(인사말) - 1);
    return 기록한수 == sizeof(인사말) - 1 ? 0 : 2;

```

```text
cc 인사.c -o 인사.elf
run 인사.elf
cat 인사.txt
```

TinyCC의 표준 C ìgbéwọlé_kókó `main`을 사용한다. 기존 olùpèsè C/C++ SDK의 `bẹ̀rẹ̀_aṣàmúlò_àtòjọ_ètò(int)` 진입점과 구분한다. 포함 Fáìlì·Rọ́ọ̀nù nǹkan_iye·`libposix-kor-user.a`는 컴파일러 내부의 Kàá 전용 SDK에 들어 있다. C 전처리기/구조체/ÀKÀNṢEFỌMÚLÀ_iye/재귀/ìtọ́ka/부동소수점 생성 등을 사용하되 **일반 libc/libstdc++를 제공한다는 뜻은 아니다**. 제공하지 않는 함수는 Darapọ̀ 오류가 난다. 컴파일러 자체의 문자/díjììtì_iye 변환 지원도 완전한 libc 대체품이 아니다.

`ṣí_fáìlì` 등은 별도의 모의 호출이 아닌 기존 `pk_open` 등의 한국어 매크로이며, ELF의 SVC를 통해 gangan_détà Java Fáìlì 체계에 도달한다. Fáìlì/소켓 호출 목록은 [aṣàmúlò ABI](사용자호출규약.md)에 있다. C/C++ olùpèsè SDK ṣiṣẹ́_àṣẹ 파일도 FTP로 업로드 후 `run` 또는 `./Fáìlì`로 실행하며 확장자는 필요 없다. Linux ARM64 ìdágún_iye ELF에는 별도의 제한된 호환 ọ̀nà `run --linux Fáìlì`을 추가했다. [ELF·Linux ABI 매뉴얼](실행파일규약.md)에 정확한 ìgúnrégé_iye·시스템 호출·àdírẹ́ẹ̀sì 제한을 정리했다.

## 한국어 네트워크·작업·화면 API

| ọ̀wọ́_iye | 호출 예 | ṣiṣẹ́_àṣẹ ọ̀nà |
|---|---|---|
| `출력` | `kọ_ìlà("안녕")`, `수쓰기(42)` | JVM 및 제한형 AOT |
| `Fáìlì` | `Kọ("문서.txt", "Àkóónú_iye")`, `Kàá("문서.txt")` | JVM 및 제한형 AOT |
| `통신` | `Ṣi(0)`, `í_meèlì(종단, "10.0.2.2", 9000, "한글")`, `받기(종단)` | JVM의 UDP |
| `연결통신` | `Darapọ̀("10.0.2.2", 9000)`, `듣기(9000)`, `받기(apèsè_iye)` | JVM의 Socket/ServerSocket |
| `작업` | `Rọ́ọ̀nù(Runnable)`, `기다리기(Thread)`, `ti_dádúró_díẹ̀_iṣẹ́()` | JVM의 협력식 èròjà_atẹ̀lélànà_iye |
| `wínńdò`, `wíjẹ́ẹ̀tì` | wínńdò·버튼·ẹyọ_ọ̀rọ̀_iye·SMS_àayè_wúnrẹ̀n·ìgbéṣẹ̀ Darapọ̀ | JVM의 Swing 부분집합 |

명명에서는 표준 영어 API를 보존하고 한국어 호출 계층을 추가한다. `통신(通信)`, `Darapọ̀(連結)`, `출력(出力)`은 기존 단어의 뜻을 사용한다. `작업 èròjà_atẹ̀lélànà_iye`은 한 ṣiṣẹ́_àṣẹ 흐름을 가닥에 빗댄 기술 표현, `ojú_iye`는 포트의 접점을 설명하는 표현이다. 새 기술 결합어를 고대에 이미 존재한 용어처럼 설명하지 않는다. 전체 JDK의 번역을 완료했다고 표시하지 않는다.

외부 주소는 díjììtì_iye IPv4이며 QEMU 호스트는 `10.0.2.2`, 게스트는 `10.0.2.15`다. UDP 전문은 512바이트까지다. 소켓은 비차단 자체 ABI이며 JVM이 제한된 대기/재시도를 제공한다. TCP connect 대기는 최대 1초, aṣàmúlò àtòjọ_ètò_f5044b9b 전체에는 기존 약 2초 CPU 기한이 적용된다. 일반적인 장기 ṣiṣẹ́_àṣẹ aṣàmúlò 서버와 pthread는 아직 없다. FTP는 aṣàmúlò àtòjọ_ètò_f5044b9b 기한과 별개인 kánẹ́ẹ̀lì_iye 서비스다.

게스트의 aṣàmúlò TCP/UDP 서버로 들어오는 연결은 NAT 포트를 추가한다. 예를 들어 `python3 Àwọn_irinṣẹ́/ṣiṣẹ́_àṣẹ.py --network --forward tcp:9300:9300 --forward udp:9301:9301`로 실행하면 호스트의 localhost 9300/TCP·9301/UDP를 게스트의 같은 포트로 전달한다. FTP의 àdáwọ̀ ìdarí_iye/데이터 포트와 겹치면 ṣiṣẹ́_àṣẹ 전에 거부한다.

`build/verification/ftp/report.json`은 gangan_détà FTP ṣàgbélọ_iye, 한글 Fáìlì, Ìwọ̀n 초과 보존, Ìpamọ_ọlọ́jọ́pípẹ́_iye JAR ṣiṣẹ́_àṣẹ, 게스트 C ṣàkójọ_ìtumò_èdè_kọ̀ǹpútà_orísun/ELF 재업로드, 외부 Java TCP/UDP, 게스트 javac/AOT 실행을 기록한다. `serial.log`에서 게스트 명령과 결과를 확인할 수 있다. 보고서의 kánẹ́ẹ̀lì_iye SHA-256과 배포 이미지의 커널을 비교한다.

빌드는 기존 JDK/Clang/AArch64 binutils와 함께 `../rpi4/build/rootfs`의 ARM64 SDK 선언 헤더와 libgcc 산술 보조 함수를 사용한다(`make rpi-prepare`). **musl libc, Linux kánẹ́ẹ̀lì_iye, 동적 로더를 게스트에 링크하지 않는다.** TinyCC/lwIP/uzlib 원본과 라이선스·버전 정보는 `vendor/`, 이식 코드는 `ccompiler/`, `network/`, `aṣàmúlò/àkópọ̀.c`에 있다.

전체 JDK/AOT JVM으로 확장하려면 타입 ìfọwọ́síìwé·nǹkan_iye/예외/GC·동적 로딩·JNI, 영속 Fáìlì OS_iye·mmap/TLS/시그널·스레드 ABI, OpenJDK native ibi_ìpamọ́, GUI peer/폰트/입력기, GENET 및 실물 ohun_èlò_iye 검증이 더 필요하다. 이 문서의 ṣiṣẹ́_àṣẹ 시험은 그 전체 이식을 대신하지 않는다.
