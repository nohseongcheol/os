# မြန်မာ 명명 원칙과 근거

이 문서의 새 이름은 jkoros 프로젝트의 선택이다. မြန်မာ 전체나 특정 국가의 유일한 ဘာသာစကား 철학을 대표한다고 주장하지 않는다. 기존에 분명한 용어는 유지하고, 모호한 음역이나 여러 의미가 섞인 이름은 လက်ရှိအချက်အလက်တစ်ခု 코드의 동작을 중심으로 고친다. 다른 언어판은 ဦးတည်ချက်တန်ဖိုး 언어와 용례를 별도로 검토해야 한다.

함수는 대상과 동작을 결합한다. `ဖိုင်ဒေတာဖတ်`, `ဖိုင်နေရာရွှေ့`, `လိပ်စာချည်နှောင်`처럼 무엇에 무엇을 하는지 이름에서 읽히게 한다. 변수는 값의 역할과 단위를 나타내도록 `ဖိုင်အညွှန်း`, `ဘိုက်အရေအတွက်`, `လက်ခံစောင့်မီလီစက္ကန့်`, `မျိုးဆက်အမှတ်`로 쓴다. 구동기는 장치를 움직이는 အကောင်အထည်ဖော်မှု, 처리기는 특정 입력을 처리하는 구현으로 구분한다.

어원은 설계 개념을 이해하는 근거로 사용한다. 역사적 은유를 그대로 번역해서 လက်ရှိအချက်အလက်တစ်ခု 동작을 흐리게 만들지 않는다. 확인되지 않은 고어·최초 သုံးစွဲမှု 시점은 만들어 넣지 않는다. 아래의 မြန်မာ 표현이 해당 시기의 တကယ့်ဒေတာ 번역어였다는 의미도 아니다.

| 개념 | 선택한 အမည် | 의미와 역사적 근거 |
|---|---|---|
| file descriptor | ဖိုင်အညွှန်း | 열린 대상을 가리키는 ကိန်းပြည့် သတ်မှတ်ခွဲခြားတန်ဖိုး. အစဦးအခြေအနေ UNIX 문헌도 open/create가 돌려주는 서술자로 시스템 표의 အဝင်အထွက် 위치를 찾는 구조를 설명한다. အမည် အက္ခရာစဉ်·ဖိုင် 본체·열린 ဖိုင် 상태를 구분한다. |
| open file description | 열린 ဖိုင် အညွှန်းတန်ဖိုး | ဖွင့် 설정과 လက်ရှိအချက်အလက်တစ်ခု 위치를 담는 공유 အခြေအနေတန်ဖိုး. အညွှန်း 자체와 구별하는 POSIX의 정의를 따른다. |
| unlink | ဖိုင်အချက်အမည်ဖယ်ရှား | ဖိုင် အကြောင်းအရာတန်ဖိုး 즉시 폐기가 아닌 အမည် ချိတ်ဆက် အချက်ဖယ်ရှား. 열린 참조가 남으면 내용이 살아 있는 의미를 반영한다. |
| seek / offset | ဖိုင်နေရာရွှေ့ / အရွေ့တန်ဖိုး | 읽고 쓰는 위치를 기준점에서 이동한다. 수색·탐색이라는 일반어보다 해당 함수의 လက်ရှိအချက်အလက်တစ်ခု 역할을 표현한다. |
| socket | 통신종단점 | 통신이 드나드는 논리적 အဆုံးမှတ်. 1971년 RFC 147도 전송의 ထွက်ခွာမှု·ဆိုက်ရောက်မှု 식별자로 socket을 설명했다. 당시 32비트·짝홀 구분을 현대 API에 그대로 적용하지 않는다. |
| network port | ဆက်သွယ်ပေါက်ကိန်း | 인터넷 လိပ်စာ 안에서 ဆက်သွယ်မှု 상대를 구분하는 နံပါတ်. RFC 768의 ထွက်ခွာမှု/ဆိုက်ရောက်မှု စက်ပစ္စည်းဆက်သွယ်ပေါက် 정의를 반영하며 CPU အဝင်အထွက် 주소와 구별한다. |
| datagram | 자료전문 | 경계를 가진 하나의 메시지. RFC 768의 datagram 방식과 UDP အလျား 필드가 가리키는 단위를 드러낸다. |
| driver | 구동기 | ကိရိယာ 초기화와 송수신 명령을 수행하는 ကုဒ်တန်ဖိုး. RTL8139 အကောင်အထည်ဖော်မှု 이름은 망장치구동기다. |
| RAM file | မှတ်ဉာဏ်ဖိုင်စနစ် | စက်မောင်း 중 자료가 주기억에 놓이는 ဖွဲ့စည်းပုံ. သိုလှောင်ကိရိယာ 보존 계층과 역할을 구분한다. |
| snapshot / generation | ထိန်းသိမ်းမိတ္တူ / မျိုးဆက်အမှတ် | တစ်ပြေးညီလုပ် 시점의 ဖိုင် 표와 ဒေတာ 전체 및 그 အစဉ်တန်ဖိုး. 단순한 백업 ဖြစ်သောအပြည့်အစုံ 표식과 တကယ့်ဒေတာ 본문을 구분한다. |
| stream | ဖိုင် ဝင်ဒေတာ/အထွက် စီးကြောင်းတန်ဖိုး | 바이트를 순서대로 읽고 쓰는 လှုပ်ရှားမှု. 표준 Java 클래스의 이름은 호환성을 위해 FileInputStream/FileOutputStream으로 유지한다. |

표의 UNIX 역사 서술은 [Ritchie·Thompson의 UNIX 논문 재록본](https://cm-bell-labs.github.io/who/dmr/cacm.html)에 근거한다. 열린 အခြေအနေတန်ဖိုး·နေရာ·삭제의 의미는 POSIX의 [open](https://pubs.opengroup.org/onlinepubs/9799919799/functions/open.html), [dup](https://pubs.opengroup.org/onlinepubs/9799919799/functions/dup.html), [lseek](https://pubs.opengroup.org/onlinepubs/9799919799/functions/lseek.html), [unlink](https://pubs.opengroup.org/onlinepubs/000095399/functions/unlink.html)를 참고했다. ဆက်သွယ်မှု 용어의 역사와 လက်ရှိအချက်အလက်တစ်ခု 규약은 [RFC 147](https://www.rfc-editor.org/info/rfc147/)과 [RFC 768](https://www.rfc-editor.org/info/rfc768/)을 참고했다.

표준 이름을 번역된 심벌로 강제로 바꾸면 기존 프로그램과 도구가 연결되지 않는다. 따라서 POSIX/C의 공개 심벌, Java 표준 အတန်းတန်ဖိုး·နည်းလမ်းတန်ဖိုး, ELF/x86 ABI, စက်ပစ္စည်း 레지스터 명칭과 `Makefile` 같은 ကိရိယာစု အချက်အမှတ်တစ်ခုတန်ဖိုး 파일은 유지한다. မြန်မာ API는 같은 동작의 별칭이다. `စက်ပစ္စည်းဆက်သွယ်ပေါက်ဖတ်` 같은 프로젝트 내부 식별자는 အဝင်အထွက် ဘိုက်တန်ဖိုး 접근으로 뜻을 좁혀 တကယ့်ဒေတာ 코드와 네이티브 연결표까지 함께 바꿨다. တကယ့်ဒေတာ 적용 목록은 [용어대응.tsv](용어대응.tsv)에 있다.
