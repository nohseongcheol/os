# သုံးစွဲသူ ခေါ်လုပ် နယ်နိမိတ်တန်ဖိုး

대상은 jkoros i386 ELF32다. Linux i386의 ခေါ်လုပ် 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `စက်/운영체제호출.s`에서 EAX(နံပါတ်), EBX·ECX·EDX·ESI·EDI(ပထမအစဉ်~다섯째 အချက်များ)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. အူတိုင်တန်ဖိုး 실패는 အနုတ်တန်ဖိုး အမှား နံပါတ်, C စာကြည့်တိုက် 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 သုံးစွဲသူ နယ်ပယ်တန်ဖိုး 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C ဒေတာ 주소는 ဘိုက်တန်ဖိုး 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java ဖိုင် 흐름의 어셈블리 경계가 별도 ဘိုက်တန်ဖိုး 버퍼를 마련하여 같은 호출을 사용한다.

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 လိပ်စာ 두 칸이다. တန်ဖိုးလက်ခံရယူ 주소가 NULL이면 တစ်ဖက်တန်ဖိုး လိပ်စာ 기록을 생략한다. sockaddr_in은 16바이트이며 လိပ်စာ 체계는 ကိရိယာ ဘိုက်တန်ဖိုး အစဉ်လိုက်တန်ဖိုး, 접속번호와 IP 주소는 ကွန်ရက်ဆက် ဘိုက်တန်ဖိုး 차례다. 축소된 လိပ်စာ 버퍼에도 들어가는 앞부분을 쓰고 전체 လိပ်စာ အရွယ် 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 ထွက်ပရိုဂရမ်, 2·3은 기존 အချက်များ 조회다. လက်ရှိအချက်အလက်တစ်ခု 커널의 အချက်များ 목록이 စက်မောင်း 이름을 제외하므로 C 진입기는 argv[0]에 고정 အက္ခရာစဉ် `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX လုပ်ငန်းစဉ် ABI와 다른 점이다.

표준 헤더의 ကိန်းပြည့် အရွယ်, အလံများတန်ဖိုး တန်ဖိုး, stat အကွက်တန်ဖိုး 순서는 `မူရင်းကုဒ်/ခေါင်းစီးဖိုင်/`에 정의한다. 동적 ချိတ်ဆက်·다중 လုပ်ငန်းစဉ်·스레드가 추가되면 အမှား နံပါတ် 저장과 အရင်းအမြစ်တန်ဖိုး 수명, ခေါ်လုပ် 경계도 함께 검토해야 한다.
