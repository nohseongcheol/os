# 자체 ARM64 ядро_стойност: FTP, C, JAR와 AOT изпълнявам_команда

대상은 **Linux를 적재하지 않는 Raspberry Pi 4용 Java AOT ядро_стойност**이다. CPU·устройство_стойност 경계는 C/어셈블리, Файл 체계와 셸은 Java이며, 이번 TCP/IP 스택은 C로 작성된 lwIP 2.2.0을 이식했다. 게스트 TinyCC와 `jaot`도 EL0에서 실행한다. 호스트에 컴파일을 요청하거나 хост JVM으로 대신 실행하지 않는다.

## 먼저 알아둘 Поддръжка_стойност 경계

| искане | 이번 구현 | 남은 клип |
|---|---|---|
| JAR를 изпълнявам_команда 파일처럼 изпълнявам_команда | `java -jar Файл.jar`, `./Файл.jar Параметри`; Main-Class와 хранилище_стойност/DEFLATE ZIP, CRC 검사 | 전체 Java SE, 임의의 모든 JAR 호환성 |
| 게스트 AOT | `jaot Файл.class -o Файл.elf`, `jaot Файл.jar -o Файл.elf`; действителен_данни ARM64 기계어 генерирам | обект_стойност·изключение·Thread·Swing·Socket의 AOT преобразувам_стойност, 여러 애플리케이션 Клас_стойност Свързване |
| C компилирам_източник | 게스트 `cc`/`tcc`, TinyCC C 전처리기·ARM64 생성기·링커; Български 식별자와 posix-kor | 전체 libc, 일반 Linux изпълнявам_команда Файл, 게스트 C++ компилатор |

| FTP | 게스트 서비스, 패시브 прехвърлям_стойност, UTF-8 Име, STOR/RETR/SIZE/LIST/NLST/MLSD/DELE | TLS·사용자별 разрешение_стойност·하위 디렉터리·영속 хранилище_стойност |
| 한글 Java | 기존 `Български.자체` 클래스와 външен_стойност адрес UDP 오버로드 | 전체 JDK의 일대일 Български съпоставяне_стойност API |

JVM은 Клас_стойност 버전 45…52의 문서화한 부분집합이다. `java`는 바이트코드 실행기이고, `jaot`가 별도의 네이티브 изпълнявам_команда 파일을 만든다. **JAR Архив_стойност 해제나 JVM을 함께 묶는 것을 AOT라고 표시하지 않는다.** 지원하지 않는 바이트코드/API는 `jaot`가 진단하고 출력을 만들지 않는다. 기존 Изход ELF도 компилирам_източник отказ_стойност 때 보존한다.

Android의 Dalvik/ART는 일반 JVM Клас_стойност/JAR가 아닌 **DEX**를 실행한다. ART의 AOT에는 GC, Клас_стойност 로딩, JNI 등 изпълнявам_команда 기반도 필요하다. 따라서 ART처럼 기계어로 바꾸는 기능만으로 임의의 OpenJDK JAR 및 Swing이 자동 호환되지는 않는다. [Android 공식 런타임 설명](https://source.android.com/docs/core/runtime)

## Български Java를 게스트에서 컴파일하고 AOT изпълнявам_команда

게스트 `vi 빛.java`로 Следваща_артикул 소스를 작성한다.

```java
public class 빛 {
    public static void main(String[] Параметри) throws Exception {
        int 합 = 0;
        int 수 = 1;
        while (수 <= 10) {
            합 = 합 + 수;
            수 = 수 + 1;
        }
        Български.자체.Изход.수쓰기(합);
        Български.자체.Файл.Писане("aot.txt", "한글 AOT Файл 😀");
        Български.자체.Изход.записване_ред(Български.자체.Файл.Четене("aot.txt"));
    }
}
```

```text
javac 빛.java
java 빛
jaot 빛.class -o 빛.elf
run 빛.elf
```

`jaot`은 클래스의 바이트코드를 C로 변환하고, **게스트 TinyCC**가 ARM64 명령어를 генерирам·연결한다. изпълнявам_команда 때 JVM 인터프리터를 호출하지 않는다. JAR의 Main-Class가 같은 Поддръжка_стойност 범위이면 다음도 가능하다.

```text
jaot 빛.jar -o 빛.elf
run 빛.elf
```

AOT 지원은 한 애플리케이션 클래스의 정적 метод_стойност/стойност_на_поле, int 계열, цяло_число 배열과 препратка, Параметри масив_стойност, условие·клон·спринт_стойност, низ_стойност 리터럴, `System.out.print/println`의 int/String, Български Изход·Файл Четене/쓰기로 제한된다. Клас_стойност/метод_стойност 수와 операнд_стек 등에도 고정 상한이 있다. Java изключение Процес_стойност_запис, обект_стойност генерирам, 가상 метод_стойност 일반, switch/wide, long/float/double, invokedynamic, низ_стойност 결합용 StringBuilder, 일반 JDK·Socket·Thread·Swing은 이 AOT 백엔드에서 미지원이다. 내장 NUL/고립된 서로게이트 문자열도 거부한다. 잘못된 масив_стойност достъп_запис/0으로 나누기 등은 네이티브 런타임 오류로 종료하며 Java изключение 객체로 전달하지 않는다.

입력 클래스뿐 아니라 **생성된 ELF도 16 KiB 이하**여야 한다. 기계어 확장과 ELF 페이지 подравнявам_стойност 때문에 짧은 클래스도 이 한도를 넘을 수 있으며, 이 경우 오류를 내고 기존 출력을 보존한다.

게스트 `javac`도 부분집합이다. 일반적인 обект_стойност·Thread·Swing 소스는 호스트에서 `javac --release 8`로 컴파일하고, **기존 JVM의 Поддръжка_стойност клип 안에서** `java`/`java -jar`로 실행한다. 정확한 API는 [JVM 매뉴얼](자바실행환경.md)과 [한글 개발 매뉴얼](개발안내.md)을 참고한다.

JAR는 하나의 애플리케이션 Клас_стойност 경로다. 내부 Име `пакет/програма_f5044b9b.class`와 점으로 구분한 Main-Class를 지원한다. 내부 클래스는 파일로 풀어 VFS 슬롯을 소비하지 않는다. 내장 Български 클래스를 추가로 찾지만 в_срок_артикул 작업 폴더의 다른 클래스는 자동 혼합하지 않는다. ZIP64·шифровам_данни ZIP·manifest Class-Path·서명 검증은 지원하지 않는다. JAR 하나가 16 KiB 이하이어도 클래스당/적재 수/VM 힙 제한은 그대로 적용된다.

## C에서 Български POSIX 호출

게스트에서 `vi 인사.c`로 작성하거나 FTP로 소스를 업로드한다.

```c
#include <파일규약.h>

int main(void) {
    const char 인사말[] = "자체 ARM64 C에서 한글 POSIX 호출\n";
    int 문서 = отварям_Файл("인사.txt", 읽고쓰기 | 없으면만들기 | съкращавам_Съдържание, 0600);
    if (문서 < 0) return 1;
    입출력결과형 기록한수 = записване_Файл_данни(문서, 인사말, sizeof(인사말) - 1);
    затварям_Файл(문서);
    записване_Файл_данни(1, 인사말, sizeof(인사말) - 1);
    return 기록한수 == sizeof(인사말) - 1 ? 0 : 2;
}
```

```text
cc 인사.c -o 인사.elf
run 인사.elf
cat 인사.txt
```

TinyCC의 표준 C запис_пункт `main`을 사용한다. 기존 хост C/C++ SDK의 `Старт_потребител_програма(int)` 진입점과 구분한다. 포함 Файл·Стартиране обект_стойност·`libposix-kor-user.a`는 компилатор 내부의 Четене 전용 SDK에 들어 있다. C 전처리기/구조체/функция_стойност/재귀/показалец/부동소수점 генерирам 등을 사용하되 **일반 libc/libstdc++를 제공한다는 뜻은 아니다**. 제공하지 않는 함수는 Свързване 오류가 난다. компилатор 자체의 문자/цифра_стойност преобразувам_стойност 지원도 완전한 libc 대체품이 아니다.

`отварям_Файл` 등은 별도의 모의 호출이 아닌 기존 `pk_open` 등의 Български 매크로이며, ELF의 SVC를 통해 действителен_данни Java Файл 체계에 도달한다. Файл/소켓 호출 목록은 [потребител ABI](사용자호출규약.md)에 있다. C/C++ хост SDK изпълнявам_команда 파일도 FTP로 업로드 후 `run` 또는 `./Файл`로 실행하며 확장자는 필요 없다. Linux ARM64 정적 ELF에는 별도의 제한된 호환 ПЪТ `run --linux Файл`을 추가했다. [ELF·Linux ABI 매뉴얼](실행파일규약.md)에 정확한 формат_стойност·시스템 호출·адрес 제한을 정리했다.

## Български 네트워크·작업·화면 API

| Клас_стойност | 호출 예 | изпълнявам_команда ПЪТ |
|---|---|---|
| `Изход` | `записване_ред("안녕")`, `수쓰기(42)` | JVM 및 제한형 AOT |
| `Файл` | `Писане("문서.txt", "Съдържание_стойност")`, `Четене("문서.txt")` | JVM 및 제한형 AOT |
| `통신` | `Отваряне(0)`, `изпращам(участник, "10.0.2.2", 9000, "한글")`, `получавам(участник)` | JVM의 UDP |
| `연결통신` | `Свързване("10.0.2.2", 9000)`, `чакам_участник(9000)`, `получавам(сървър_стойност)` | JVM의 Socket/ServerSocket |
| `작업` | `Стартиране(Runnable)`, `기다리기(Thread)`, `преустановявам_временно_задача()` | JVM의 협력식 нишка_стойност |
| `Прозорец`, `изпълним_модул` | Прозорец·버튼·знак_стойност·текстово_поле·Събитие Свързване | JVM의 Swing 부분집합 |

명명에서는 표준 영어 API를 보존하고 Български 호출 계층을 추가한다. `통신(通信)`, `Свързване(連結)`, `Изход(出力)`은 기존 단어의 뜻을 사용한다. `작업 нишка_стойност`은 한 изпълнявам_команда 흐름을 가닥에 빗댄 기술 표현, `порт_стойност`는 포트의 접점을 설명하는 표현이다. 새 기술 결합어를 고대에 이미 존재한 용어처럼 설명하지 않는다. 전체 JDK의 번역을 완료했다고 표시하지 않는다.

външен_стойност 주소는 цифра_стойност IPv4이며 QEMU 호스트는 `10.0.2.2`, 게스트는 `10.0.2.15`다. UDP 전문은 512바이트까지다. 소켓은 비차단 자체 ABI이며 JVM이 제한된 почакай_стойност/재시도를 제공한다. TCP connect 대기는 최대 1초, потребител програма_f5044b9b 전체에는 기존 약 2초 CPU 기한이 적용된다. 일반적인 장기 изпълнявам_команда потребител 서버와 pthread는 아직 없다. FTP는 потребител програма_f5044b9b 기한과 별개인 ядро_стойност 서비스다.

게스트의 потребител TCP/UDP 서버로 들어오는 연결은 NAT 포트를 추가한다. 예를 들어 `python3 Инструменти/изпълнявам_команда.py --network --forward tcp:9300:9300 --forward udp:9301:9301`로 실행하면 호스트의 localhost 9300/TCP·9301/UDP를 게스트의 같은 포트로 전달한다. FTP의 стойност_по_подразбиране контрол_стойност/데이터 포트와 겹치면 изпълнявам_команда 전에 거부한다.

`build/verification/ftp/report.json`은 действителен_данни FTP прехвърлям_стойност, 한글 Файл, Размер 초과 보존, Архив_стойност JAR изпълнявам_команда, 게스트 C компилирам_източник/ELF 재업로드, външен_стойност Java TCP/UDP, 게스트 javac/AOT 실행을 기록한다. `serial.log`에서 게스트 명령과 결과를 확인할 수 있다. 보고서의 ядро_стойност SHA-256과 배포 이미지의 커널을 비교한다.

전체 JDK/AOT JVM으로 확장하려면 타입 проверка·обект_стойност/изключение/GC·동적 로딩·JNI, 영속 Файл операционна_система_стойност·mmap/TLS/시그널·스레드 ABI, OpenJDK native библиотека, GUI peer/폰트/입력기, GENET 및 실물 устройство_стойност 검증이 더 필요하다. 이 문서의 изпълнявам_команда 시험은 그 전체 이식을 대신하지 않는다.
