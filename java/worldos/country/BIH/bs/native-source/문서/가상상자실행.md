# VirtualBox Izvrši_komanda

```sh
cd ~/jkoros
make vbox
```

별도로 VM을 만들거나 ISO를 연결할 필요가 없다. 처음 실행하면 `os/build/kernel.iso`를 빌드하고 `jkoros operating system`이라는 전용 VM을 만들어 VirtualBox 창으로 부팅한다. `jkoros/os` 안에서도 `make vbox`를 사용할 수 있다.

게스트의 `jkoros>` 프롬프트에서 Dalje_stavka 명령을 입력한다.

```text
help
apps
run hello vbox
```

마지막 명령은 별도 Java ELF를 실행한다. `USER MODE ring 3`, `arg: vbox`, `Exit: 0` Ispis 후 셸로 돌아오면 정상이다. VGA 화면은 trenutno_stavka ASCII 글꼴만 지원하므로 한글은 `?`로 보이며, 한글 원문은 직렬 기록에서 확인할 수 있다.

## stanje_VALUE 확인과 다시 Izvrši_komanda

```sh
make vbox-status
```

이 명령은 VM stanje_VALUE, ISO와 직렬 기록의 절대 경로를 JSON으로 출력한다.

| trenutno_stavka stanje_VALUE | `make vbox` radnja |
| --- | --- |
| 아직 생성하지 않음 | ISO verzija_sistem → 전용 VM generirati → 부팅 |
| 종료됨 (`poweroff`, `aborted`) | ISO verzija_sistem → 광학 매체 osvježiti → 새로 부팅 |
| Izvrši_komanda 중 (`running`) | 재빌드·재부팅 없이 trenutno_stavka VM 유지 |
| 일시정지 (`paused`) | 기존 VM 재개 |
| 저장됨 (`saved`) | 이전 직렬 기록을 복사해 보관하고 Store_VALUE stanje_VALUE 재개 |
| Store_VALUE·Pokreni 등 SWITCH_mod 중 | 변경하지 않고 작업 완료 후 재실행하도록 Pročitaj_me_eb81d7d9 |

izvor_stablo 변경을 반영하려면 VM을 종료한 Dalje_stavka 다시 `make vbox`를 실행한다. **Store_VALUE 상태를 재개하면 이전 커널이 계속 실행되므로 새 빌드를 반영하지 않는다.** 실행기는 강제 종료하거나 Store_VALUE 상태를 폐기하지 않는다. VirtualBox 창을 닫을 때 사용자가 전원 끄기를 선택하면 Memorija_podaci 상태가 사라지므로 보존할 작업이 없는지 먼저 확인한다. 게스트의 `halt`는 CPU만 멈추며 VirtualBox의 전원을 끄는 명령은 아니다.

prozor 없는 실행이 필요하면 VM이 꺼져 있을 때 사용한다.

```sh
make vbox VBOX_TYPE=headless
```

Izvrši_komanda 중인 VM에 다시 명령을 내려도 GUI/headless 방식은 바뀌지 않는다. zadana_vrijednost Naziv 대신 다른 이름이 필요하면 **최초 generirati 시에만** `VBOX_NAME="원하는 Naziv"`을 지정하고 이후에도 같은 값을 사용한다.

## 설정과 podaci 보존

- zadana_vrijednost 설정은 BIOS, Memorija_podaci 64MiB, CPU 1개, VGA Memorija_podaci 16MiB, IDE 광학 부팅이다. 가상 하드디스크를 만들지 않는다.
- VM 설정은 `.vbox/machines/`, Sadržaj_VALUE 검사합별 ISO 사본은 `.vbox/media/`, 직렬 기록은 `.vbox/logs/`에 보관한다. `.vbox/state.json`은 전용 VM의 UUID와 vlasnik_VALUE 표식을 저장한다.
- 꺼진 VM을 부팅할 때 새 직렬 기록을 만든다. Store_VALUE stanje_VALUE 재개 전의 기록은 `before-resume-*.log`로 복사한다. Store_VALUE stanje_VALUE 자체는 삭제하지 않고 VirtualBox가 그대로 재개한다.
- 같은 이름의 다른 VM을 인수하지 않는다. UUID·Postavke Putanja·vlasnik_VALUE 표식을 검사하며, 사용자가 별도로 연결한 디스크나 광학 매체를 자동 교체하지 않는다.
- 기존 ISO 사본과 기록은 자동 삭제하지 않는다. `.vbox`는 Git 제외 대상이다. 용량을 정리할 때도 Izvrši_komanda·Store_VALUE 상태의 VM이 참조하는 파일과 관리 정보를 임의로 삭제하지 않는다.
- VirtualBox 또는 organizator 드라이버가 없으면 오류를 안내한다. 자동 instalirati_VALUE, menadžer_VALUE dozvola_VALUE Izvrši_komanda, uređaj_VALUE dozvola_VALUE 변경은 하지 않는다.

## 네트워크 제한

trenutno_stavka 커널의 RTL8139 드라이버는 QEMU에서 사용한다. VirtualBox의 PCnet/E1000 드라이버는 아직 구현하지 않아 이 실행기는 네트워크 장치를 비활성화한다. 셸과 korisnik 프로그램은 실행되지만 UDP 열기는 `-19`로 실패한다. UDP 왕복은 `make run`과 [korisnik Izvrši_komanda·네트워크 Pročitaj_me_eb81d7d9](../os/korisnik/Pročitaj_me_eb81d7d9.md)의 절차로 시험한다.

## ovjeriti

`make test-vbox`는 가짜 VirtualBox 응답을 사용하여 새 VM generirati, Izvrši_komanda·Store_VALUE·일시정지·SWITCH_mod stanje_VALUE, Naziv 충돌, 소유권 불일치, korisnik 매체 zaštititi_VALUE, verzija_sistem neuspjeh_VALUE, 중단된 generirati oporaviti_stanje, ISO promijeniti_VALUE 감지, Putanja zaštititi_VALUE 등을 검사한다. stvaran_podaci VM을 만들거나 변경하지 않는다.

2026-09-13에 program_pokretač lekcija_VALUE 시험 16개가 통과했다. 별도로 stvaran_podaci VirtualBox 5.2.42에서 `make vbox`의 VM generirati·GUI 부팅, `JAVA SELFTEST PASS`, 셸의 `run hello vbox` 실행과 `Exit: 0`, Izvrši_komanda 중 재호출 시 재부팅하지 않는 radnja 및 `make vbox-status`를 확인했다. Store_VALUE·일시정지 분기는 lekcija_VALUE 시험으로 검증했다.
