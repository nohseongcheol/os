# jkoros 안에서 Java napraviti_izvor·Izvrši_komanda

이 문서의 부팅·ljuska·Store_VALUE 명령은 **x86 verzija_VALUE** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 verzija_VALUE](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 fajl_naziv_SMS, `edit`의 단독 `.` Store_VALUE, 16개 RAM Fajl, 약 2초 Izvrši_komanda 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 stvaran_podaci JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. organizator napraviti_izvor 서버나 Linux 게스트는 사용하지 않는다.

**trenutno_stavka 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java program_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 Izvrši_komanda

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. Izvrši_komanda 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox Izvrši_komanda Pročitaj_me_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 Fajl 전체를 새 내용으로 작성한다. 기존 내용의 Linija uređivati_VALUE 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 bajt_VALUE 수 program_VALUE.
- `cat FILE`: Fajl Sadržaj_VALUE program_VALUE. 텍스트 소스에 사용한다.
- `rm FILE`: Memorija_podaci Fajl 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·TYPE_VALUE 검사 neuspjeh_VALUE 시 기존 `.class`는 유지된다. 소스를 고친 ZAD_VALUE 컴파일이 실패했다면 이전 Izvrši_komanda 파일이 남아 있으므로 napraviti_izvor 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 Store_VALUE 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 izvor_stablo·klasa_VALUE·podaci 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, Fajl 이름은 ASCII 1~63자다. izvor_stablo 이름은 `.class` 확장자 공간 때문에 최대 62자다. uređivati_VALUE 입력은 ASCII이고 한 Linija 최대 128자다. Linija 또는 Fajl 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. jezgro_VALUE/컴파일러/JVM 구현의 Java 식별자는 한국어이며, trenutno_stavka 게스트 입력 제한 때문에 korisnik 예제 이름은 ASCII로 작성한다.

## iz_eksternog_izvora_VALUE Fajl 적재

호스트에서 만든 소스나 Podrška_VALUE isječak 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 stvaran_podaci 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# organizator JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 Dalje_stavka 빌드에서는 추가 파일을 포함하지 않는다. Fajl Sadržaj_VALUE 변경과 unos_spisak 제거도 Dalje_stavka 빌드에 반영된다. 원본 organizator 파일에는 쓰지 않는다. zadana_vrijednost `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 zadana_vrijednost 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 klasa_VALUE Fajl 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 Podrška_VALUE isječak 안에 있어야 한다.

## Podrška_VALUE isječak

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| klasa_VALUE | 패키지 없는 단일 klasa_VALUE, statični_VALUE FUNCTION_VALUE, 재귀, Argumenti/vratiti_mjera | 실행마다 단일 klasa_VALUE 적재, public static main(String[]) |
| zadana_vrijednost VALUE | int, boolean, char, String, main의 String[] Argumenti | cijeli_broj·Reference operand_snop, String, int[], String[], 내부 StringBuilder |
| izjava_VALUE | 초기값 있는 lokalni_opseg 선언, zadatak_VALUE, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 cijeli_broj·Reference 바이트코드와 uvjet ogranak |
| izraz_VALUE | 십진 cijeli_broj, UTF-8 소스의 string_VALUE/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, string_VALUE 결합 | cijeli_broj operacija_VALUE·bit_VALUE operacija_VALUE·TYPE_VALUE CONVERT_VALUE, 단락 평가, niz_VALUE pristup_unos |
| Fajl | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | stvaran_podaci jezgro_VALUE 파일서술자와 Spoji_se, generirati·obrisati_TOC·이어쓰기·EOF |
| Ispis | System.out.print/println: int/boolean/char/String, println() | 동일 |
| string_VALUE/Argumenti | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), string_VALUE 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 lokalni_opseg 선언, 오버로드, 임의 TYPE_VALUE CONVERT_VALUE, niz_VALUE generirati IZVOR, 8/16진 리터럴, Unicode izvor_stablo 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 konstanta_VALUE 축소 변환을 구현하지 않는다. iz_eksternog_izvora_VALUE `.class`의 `int[]` generirati/Čitaj/쓰기는 지원하므로 organizator `javac --release 8`로 만든 niz_VALUE 예제는 실행할 수 있다.

objekt_VALUE polje_VALUE·일반 objekt_VALUE generirati·상속·인터페이스·여러 klasa_VALUE Spoji_se, long/float/double, izuzetak proces_VALUE_unos, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java izuzetak 객체를 던지지 않고 진단 후 trenutno_stavka 프로그램을 종료한다. 객체와 string_VALUE Store_VALUE 공간은 Izvrši_komanda izaći_program 시 korisnik 영역 전체와 함께 회수한다. 지속 Izvrši_komanda 중 GC는 없다.

## Izvrši_komanda 한도와 GRESKA

| resurs_VALUE | 한도 |
| --- | --- |
| izvor_stablo/klasa_VALUE Fajl | 각각 16KiB |
| 컴파일러 | token_VALUE 2,047개, generirati kod_VALUE 4KiB, konstanta_VALUE 풀 4KiB |
| FUNCTION_VALUE/Argumenti | 클래스당 32함수, 함수당 16인수 |
| JVM konstanta_VALUE | 511개 |
| JVM FUNCTION_VALUE kod_VALUE | 함수당 8KiB |
| JVM 호출/operand_snop/lokalni_opseg 변수 | 32프레임, 프레임당 operand_snop 128칸·lokalni_opseg 128칸 |
| JVM objekt_VALUE Store_VALUE 공간 | 8,192개 32비트 prostor_za_unos_unos, 헤더 포함 약 32KiB |
| Izvrši_komanda | 최대 500,000 Naredba, 기존 커널의 약 3초 CPU Izvrši_komanda 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 Podrška_VALUE 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM rječnik 검증기를 구현한 것은 아니다. Fajl/atribut_VALUE dužina_VALUE, konstanta_VALUE Reference, Naredba·ogranak 경계를 검사하고, Izvrši_komanda 중 operand_snop format_VALUE·lokalni_opseg inicijalizirati·niz_VALUE indeks_VALUE·objekt_VALUE 참조를 검사한다. korisnik 코드의 페이지·hardver_port 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, napraviti_izvor·JVM 오류는 `Exit: 1`, Naredba Argumenti 오류는 `Exit: 2`다. CPU TIME_VALUE 상한은 기존 `Exit: 124`이며, korisnik ELF 자체의 CPU/런타임 오류는 기존 izaći_program 코드를 따른다. neuspjeh_VALUE 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

- `os/korisnik/자바/자바가상기계.java`: klasa_VALUE 적재, operand_snop·프레임·objekt_VALUE Store_VALUE, Naredba 해석과 제한된 표준 호출.
- `os/IZVOR/Memorija_fajl_sistem.java`: Memorija_podaci fajl_sistem, uređivati_VALUE, 부팅 Fajl 적재.
- `os/IZVOR/체계호출.java`, `compiler/START_korisnik_program.s`: Fajl/문자 Ispis API와 korisnik pokazivač 검사.
- `os/Alati/자바파일묶기.py`: organizator 입력 Fajl ovjeriti·부팅 Grupa_VALUE generirati.


`os/시험/자바시험.py`는 ELF/ISO 부팅, 게스트 napraviti_izvor·Izvrši_komanda, korisnik 입력, 재귀·반복문·cijeli_broj 극값·string_VALUE 결합·단락 평가, 재실행, izvor_stablo GRESKA 후 기존 klasa_VALUE 보존, niz_VALUE/수 해독 GRESKA, 무한 ponavljanje_VALUE 제한, uređivati_VALUE 넘침과 Fajl 부족을 검사한다. 게스트 generirati 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 organizator OpenJDK의 klasa_VALUE, cijeli_broj 배열과 한글 상수를 게스트에 적재하며, 손상된 Fajl 표식·버전·konstanta_VALUE 수·ogranak·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 시험 VM만 생성하고 종료한다.

구현 형식의 참고 podaci: Oracle [JVM klasa_VALUE Fajl 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM Naredba 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java Fajl U_I

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 klasa_VALUE 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 ZAD_VALUE `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. zadana_vrijednost Ispis 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. izuzetak objekt_VALUE·try/catch·try-with-resources는 지원하지 않으며 Fajl 오류를 진단하고 프로그램을 종료한다. niz_VALUE U_I, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 Fajl 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 ljuska `sync`가 필요하다. 예제의 Fajl 이름은 trenutno_stavka 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 stvaran_podaci 게스트 napraviti_izvor 결과를 OpenJDK `-Xverify:all`로 다시 실행해 Fajl 바이트와 출력을 대조한다. 범위와 Store_VALUE 매체 사용법은 [posix-kor Pročitaj_me_eb81d7d9](../posix-kor/Pročitaj_me_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
