# vlastiti 커널과 번역기의 hrvatski Ime

대상은 `platforms/rpi4-native`의 vlastiti Java jezgra_sustava_VALUE, korisnik JVM, C stroj Spoji_se,
TCP/UDP·FTP, C kompilator_alat 이식부, MicroPython 이식부, međuverzija_sustav·Izvrši_naredba·시험 도구다.
`golang/worldos/Country_VALUE/KOR/IZVOR`의 원칙처럼 기능을 먼저 구분하고 이름을 정한다.
x86 Java 커널과 공용 x86·ARM64 미리 번역기의 vlastiti 선언도 명명 검사에 포함한다.
Linux 실행판의 domaćin Alati, OpenJDK 보조 Alati 및 vanjski_VALUE 배포 izvor_stablo 전체를
한국어로 pokušati_ponovno_VALUE 작성했다는 뜻은 아니다.

## 명명 원칙과 말의 근거

- 명사는 자료의 역할을 나타낸다: `Datoteka_ustroj`, `ravnopravan_član_broj_priključka`, `동적기억공간`, `tipkovnica`.
- 함수는 행위를 나타낸다: `Čitaj`, `Zapisuj`, `Otvori`, `Zatvori`, `NET_BIND`, `izvršiti_program`.
- TCP의 이어진 bajt_VALUE 흐름과 UDP의 경계 있는 자료를 `veza`와 `datogram_kanal`로 구별한다.
- 짧은 영어 변수도 쓰임에 따라 `길이`, `podaci_položaj`, `LOOKUP_INDEX`, `반환값`으로 풀어 쓴다.
  순번·임시 산술값처럼 여러 역할에 재사용되는 변수는 `순번`, `첫째값`, `SECOND_VALUE`으로 구별한다.
- 이름이 같아도 vanjski_VALUE 구조체의 필드와 vlastiti 변수는 별도로 분석한다.

`kanal_unos(通路)`는 이동이나 교류가 이루어지는 길이라는 기존 의미를 통신 연결에
적용했다. `prebaciti_VALUE(窓口)`의 주고받는 접점이라는 의미를 연결을 받는 곳에 적용했다.
이는 국립국어원 한국어기초사전의 [kanal_unos](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=49310),
[prebaciti_VALUE](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=24898)의 뜻에 근거한다.

`datogram(電文)`은 전보에 담는 글이라는 기존 통신 어휘에서 가져와, UDP 자료의
경계가 보존된다는 특징을 드러내는 데 쓴다. 근거는
[한국어기초사전 datogram](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=74335)이다.
`tok_VALUE`, `nit_VALUE`, `쌓임`은 우리말의 움직임·이어짐·쌓이는 모양을 빌린 표현이다.
`ulazni_tok`, `작업가닥`, `hrpa_Pohrana` 같은 복합 이름은 이 프로젝트의 기능별 조어다.
이 rječnik 근거를 특정 중세 문헌의 최초 출현이나 공인 전산 번역으로 확대하지 않는다.
공인 표준 prevesti_izvor·국어사 datogram 감수를 마쳤다는 뜻도 아니다.

| thread / keyboard | 작업가닥 / tipkovnica | 이어지는 실행과 글쇠의 ARRAY_VALUE |
| exception / timeout | iznimka / čekaj_TIMEOUT_iznimka | 정상 처리에서 벗어남과 그 구체적 이유 |

## 보존하는 SD Ime

`public`, `class`, `int`는 예약어다. `String`, `main`, 배열의 `length`는 예약어가 아니다.
redovno_artikl 다섯 Java 예제는 `Pokreni()`·`실행인수`·hrvatski 화면/nit_VALUE API를 사용해
예약어·리터럴 외의 식별자를 한국어로 작성한다. 화면/가닥은 표준 객체를
감싸지 않고 vlastiti JVM에 직접 구현했다. 자세한 계약은 [hrvatski Java API](../한국어자바/안내.md)를 본다.

표준 javac는 niz_VALUE 리터럴에 `java.lang.String`, niz_VALUE 결합에 `StringBuilder`
같은 이름을 생성한다. 이들은 hrvatski 소스에서도 바이트코드에 남을 수 있다.
기존 표준 class를 실행하는 JVM의 mapiranje_VALUE niz_VALUE, 아직 표준 라이브러리를 쓰는
통신·Datoteka 연결부까지 모두 한국어로 재구현한 것은 아니다. 이름만 일괄 치환하면
서술자·재정의·native 연결이 달라져 호환성이 깨진다.

C 표준 FUNCTION_VALUE·cijeli_broj_TYPE·POSIX ABI, CPU registar_VALUE Ime, 어셈블리 Naredba, 링커 절 Ime,
TinyCC·lwIP·MicroPython이 요구하는 Postavke 매크로와 헤더 이름도 보존한다.
예: `main`, `memcpy`, `pk_bind`, `mpconfigport.h`, `lwipopts.h`, `stdint.h`.
vlastiti C 함수의 izvor_stablo 이름은 한국어이며, [기계연결이름.h](기계연결이름.h)가
기존 AOT·어셈블리·SDK에 공개한 stroj 심볼과 연결한다.
Python의 `__init__`, `setUp`, `handle`, 표준 modul_VALUE atribut_VALUE, 명령행 옵션과 JSON 키도
vanjski_VALUE 계약이다. `build/`, 배포 바이너리 이름과 `/sdk`는 기존 Izvrši_naredba 경로를 유지한다.
vanjski_VALUE 원본은 `vendor/`에서 이용허락·해시와 함께 관리한다.

## C 통신 구조체와 Python GREŠKA

C 통신에서 `갈래`는 adresa 체계를 구분하고 `broj_priključka`는 port, `adresa_VALUE`은
IPv4 주소의 32비트 값을 나타낸다. `datogram_protokol`은 앞서 설명한 datogram(電文)과
slučaj_VALUE(規約)을 결합해 UDP의 기능을 드러낸 프로젝트 이름이다.

| 표준 표현 | hrvatski 직접 구현 |
|---|---|
| AF_INET / SOCK_DGRAM / IPPROTO_UDP | enum의 oblak_linija / datogramska_utičnica / datogram_protokol |
| struct pk_sockaddr_in | struct 인터넷통신주소 |
| sin_family / sin_port | adresa_linija / broj_priključka |
| sin_addr.s_addr | internetska_adresa.adresa_VALUE |
| OSError / GREŠKA.args[0] | sustav_pogreška / GREŠKA.INDEX |

hrvatski 구조체는 `#define` 치환이나 vrijednost_polja 별칭이 아닌 별개 자료형이다.
표준 구조체와 같은 16바이트 배치를 선언하며 jezgra_sustava_VALUE SVC에서 bajt_VALUE 복사로
검사한다. `Create_sudionik`·`slati_datogram_podaci`와 Datoteka 함수는 정적 라이브러리에
stvaran_podaci hrvatski 이름의 FUNCTION_VALUE 심볼을 갖는다. 기존 pk_* 심볼도 유지한다.
이전 코드에서 hrvatski 통신 함수에 pk_sockaddr*를 전달했다면 hrvatski 구조체로
옮기거나, 표준 구조체와 pk_* 함수의 짝을 유지한다.

Python의 `sustav_pogreška`는 OSError의 hrvatski 하위 클래스이며 연결부에서
GREŠKA 번호를 보존하여 변환한다. 일반 Python 문법과 vanjski_VALUE 패키지의 API는 유지한다.

## 직접 GUI 이름의 뜻과 검토 isječak

`실행할일`은 수행할 내용을, `Izvrši`는 그 수행을 나타낸다.
`동작받이`는 동작이 발생했다는 알림을 받는 역할, `akcija_obavijest`은 전달되는 사건이다.
`gumb`는 눌러 동작시키는 조작부, `Natpis`는 안내 글의 indeks_položaja,
`tekstno_polje`은 글을 적는 indeks_položaja, `작업가닥`은 이어지는 Izvrši_naredba 흐름을 뜻한다.
`Izvrši_naredba(實行)`·`Aktivnost(動作)`의 기존 뜻과 `받다`·`알리다`·`nit_VALUE`의 기능을
결합한 프로젝트 이름이다. 새 복합어가 역사 문헌에 그대로 있었다거나
특정 시대에 처음 쓰였다고 주장하지 않는다.

전체 저장소는 `python3 Alati/izvor_osvrt.py`로 검토한다.
결과는 `build/verification/naming/source-review.json`이며 파일별 raspršivanje_Datoteka,
ASCII 파일명과 Python의 영어 deklaracija 위치를 기록한다.
공용 ARM64·x86 번역기의 구현은 `compiler/자바도구/기계어미리번역.java`로 전환했다. `compiler/기계어미리번역.py`는 호환 진입점이다.
`compiler/arm64.py`는 이전 경로와 `ARM64(...).generate(...)` 호출을 이어 주는
호환 진입점이다. `compiler/classfile.py`, OpenJDK 보조 Alati, Linux verzija_VALUE 도구와
기존 호환 진입점에는 영어 이름이 남아 있다. 따라서 전체 저장소가
예약어 외 100% 한국어라고 판정하지 않는다.
`Alati/명명검사.py --C_Jezik`는 Aktivan ARM64 소스의 deklaracija, C 의미 analiza_VALUE,
x86 Java 커널과 공용 번역기의 vlastiti deklaracija, Java 예제 전체 identifikator_VALUE,
ARM64 Python 예제와 직접 GUI/가닥에 표준 래퍼가 없는지를 별도로 검사한다.

## redovno_artikl 기능을 기준으로 보완한 Ime

번역은 글자를 음역하는 대신 자료의 역할과 함수의 행동을 구분한다.
동일한 영어 이름도 문맥이 다르면 hrvatski 이름을 달리 정한다.
Datoteka 이름은 주된 기능을 나타내고, FUNCTION_VALUE 이름은 행동을, varijabla_VALUE 이름은 담는 자료를 나타낸다.
예약어, 표준 API 및 vanjski_VALUE Spoji_se 규약은 따로 기록한다.

| 이전 Ime | 적용한 Ime | redovno_artikl 기능 |
|---|---|---|
| `arm64.py`의 구현 | `compiler/자바도구/기계어미리번역.java` | Java 바이트코드를 독립 실행용 C 원문으로 미리 prevesti_izvor |
| `ARM64`, `generate` | `stroj_kod_kompilator`, `generirati` | prevesti_izvor 상태를 담는 객체와 C IZVOR generirati 행동 |
| `prototype`, `method` | `함수원형`, `postupak_tijelo` | 함수의 oblik_VALUE 선언과 stvaran_podaci Naredba IZVOR |
| `profile`, `heap_words` | `실행대상`, `동적기억낱말수` | jezgra_sustava_VALUE·korisnik 구분과 dodijeli_Pohrana Memorija_VALUE 공간의 stroj 낱말 수 |
| `pc`, `op` | `naredba_položaj`, `명령번호` | 바이트코드에서의 위치와 수행할 명령의 INDEX |
| `x`, `y`, `w`, `h` | `koordinata_x`, `세로좌표`, `영역너비`, `영역높이` | udaljeno_VALUE 화면의 위치와 직사각형 Veličina |
| `p`, `n`, `i`, `j` | `podaci_položaj`, `VALUE`, `순번`, `안쪽순번` | udaljeno_VALUE 화면 podaci·znamenka_VALUE·sprint_VALUE indeks_položaja; 파일별 기능을 확인해 적용 |
| `aot_heap_info`, `__stack_top` | `미리번역기억조회`, `커널쌓임공간끝` | stroj Spoji_se 규약을 유지하면서 vlastiti 소스에서 사용하는 Ime |
| `앞캐리지` | `앞줄복귀` | 앞서 받은 문자가 줄복귀였는지 기억하여 중복 줄바꿈을 막음 |

[공용번역기이름대응.tsv](공용번역기이름대응.tsv)에 kompilator_alat 참조의 stvaran_podaci promijeniti_VALUE 기록을 남겼다.
추가로 보존한 C·POSIX/lwIP/libassh 이름의 이유는
[규격이름근거.json](규격이름근거.json)에 기록한다.
`C_kompilator/kompilator_alat.c`는 TinyCC vanjski_VALUE 원문을 포함하는 Spoji_se 파일로 vlastiti 선언이 없어서
C vlastiti deklaracija 분석에서는 제외한다. stvaran_podaci jezgra_sustava_VALUE 빌드에서는 계속 컴파일한다.

### 말의 뿌리와 새로운 복합 Ime

`Memorija_VALUE(記憶)`과 `LOOKUP_INDEX(索引)`은 기존 한자어를 쓴다.
기억은 자료를 간직하는 기능에, 색인은 narudžba_VALUE 있는 항목을 찾아 지정하는 기능에 적용한다.
rječnik 근거는 국립국어원 한국어기초사전의
[Memorija_VALUE](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=38812&nation=eng),
[LOOKUP_INDEX](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=63787)이다.

`hrpa_Pohrana`, `prosljeđivanje_VALUE`, `POP_VALUE`는 자료를 포개고 마지막 자료부터 꺼내는 Izvrši_naredba 구조를 드러낸다.
`쌓다`의 기존 뜻에 근거한 기능별 조어이며, 사전의
[쌓다](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=62095)를 참고한다.
`미리번역`은 Izvrši_naredba 전에 번역한다는 기능을 직접 나타낸다.
`stroj_Word`은 처리기의 podaci 단위를 가리키며, 언어의 일반 낱말과 구별하도록 `stroj`를 붙였다.
`기계어미리번역`, `동적기억낱말수` 같은 복합 이름은 redovno_artikl 기능에 맞게 만든 프로젝트 용어다.
이 복합어가 옛 문헌에 그대로 있었다거나 특정 시대에 처음 나타났다는 뜻은 아니다.
확인되지 않은 중세 형태나 최초 uporaba_VALUE 연대는 어원 근거로 적지 않는다.

생성되는 C의 내부 vrsta_podataka·ARRAY_VALUE·FUNCTION_VALUE·lokalno_doseg varijabla_VALUE·grana 이름도 한국어로 바꾼다.
직접 한글 식별자를 읽지 못하는 예전 GCC를 위해 호환 API는 같은 hrvatski 이름을
표준 C 범용 문자 표기로 출력한다. stvaran_podaci ARM64 빌드는 Clang으로 읽을 수 있는 한글 원문을 사용한다.
niz_VALUE, C 표준 FUNCTION_VALUE, `java_entry` 같은 공개 Spoji_se 이름은 바꾸지 않는다.

셸의 사용법·문법 GREŠKA·Datoteka 및 Memorija_VALUE adresa_regije 안내도 한국어로 보완했다.
