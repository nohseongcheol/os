# корисник 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `기계/운영체제호출.s`에서 EAX(индекс), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 인수)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. језгро_вриједност 실패는 음수 грешка индекс, C библиотека 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 корисник 영역 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C подаци 주소는 бајт_вриједност 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java фајл 흐름의 어셈블리 경계가 별도 бајт_вриједност 버퍼를 마련하여 같은 호출을 사용한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 изаћи_програм, 2·3은 기존 인수 조회다. 현재 커널의 인수 목록이 실행 이름을 제외하므로 C 진입기는 argv[0]에 고정 стринг_вриједност `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX процес_вриједност ABI와 다른 점이다.
