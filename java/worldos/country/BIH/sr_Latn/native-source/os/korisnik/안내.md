# 셸에서 실행하는 korisnik 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 안내](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 Izvrši_komanda

host Terminal 1:

```sh
cd /home/user/jkoros
python3 os/Alatke/eho_podaci.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. spoljni_VALUE 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

host Terminal 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 stvarni_podaci CPU dozvola_VALUE `ring 3`, 인수 출력.
- `netcheck`: port_VALUE 중복, 잘못된 pokazivač_VALUE/pokazivač/길이, 비차단 받기와 TIME_VALUE 초과 verifikovati.
- `udp`: IPv4 adresa·odredište_VALUE port_VALUE·한 Word_VALUE 메시지를 받아 UDP로 보내고 같은 응답을 verifikovati. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: host `10.0.2.2`의 Dodeli_VALUE 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. primiti_VALUE Loop_VALUE 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. aktuelno_stavka 주소는 게스트 `10.0.2.15/24`, mrežni_prolaz_VALUE `10.0.2.2`로 고정돼 있다. QEMU korisnik 네트워크의 host pristup_stavka 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 program_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java program_f5044b9b dodati_stavka

`예제/내프로그램.java`를 Dalje_stavka 형식으로 만든다. 진입점은 인수 없는 `static int` 또는 `static void` 함수다. 인수는 korisnik API로 조회한다.

```java
public final class 내프로그램 {
    public static int koristiti() {
        korisnik.쓰기("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/korisnik/program_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := korisnik/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.koristiti
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `korisnik/deklaracija/korisnik.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 Izvrši_komanda 중인 VM에는 verzija_sistem 결과가 자동 반영되지 않는다. program_f5044b9b 이름은 aktuelno_stavka 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java Razred_VALUE·FUNCTION_VALUE·변수에는 한국어를 쓴다. 최대 32개 program_f5044b9b, 한 Izvrši_komanda 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/kompajler.py --target user --entry 인사.koristiti \
    -o os/build/apps/hello.elf os/korisnik/deklaracija/korisnik.java os/korisnik/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 host 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 Podrška_VALUE klip 안에서 실행한다. `.jar`와 일반 Linux Izvrši_komanda 파일은 지원하지 않는다.

## korisnik 네트워크 API

선언은 `deklaracija/korisnik.java`에 있다. `poslati_podaci`/`primiti_podaci`의 `int[]` stavka_element 한 개는 bajt_VALUE 하나(0~255)를 나타낸다. 한 데이터그램의 최대 podaci 길이는 1,024바이트다.

```java
int pokazivač_VALUE = korisnik.otvoren_Mreža(0); // 0: 임시 lokalni_skup UDP port_VALUE 자동 izbor_VALUE
int[] podaci = new int[32];
podaci[0] = 'H'; podaci[1] = 'i';
int 보낸길이 = korisnik.poslati_podaci(pokazivač_VALUE, 0x0a000202, 9000, podaci, 2);
int 받은길이 = korisnik.primiti_podaci(pokazivač_VALUE, podaci, 1500);
korisnik.Zatvori_Mreža(pokazivač_VALUE);
```

stvarni_podaci 프로그램에서는 otvoren·poslati·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `primiti_podaci`의 čekaj_VALUE 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 primiti_VALUE 대기열은 한 개뿐이므로 dodati_stavka 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | pokazivač_VALUE·Proces_VALUE_stavka 길이·성공 등 해당 함수의 KR |
| -5 | uređaj_VALUE poslati_VALUE otkazivanje_VALUE |
| -9 | 잘못되었거나 닫힌 통신 pokazivač_VALUE |
| -11 | 비차단 받기에서 도착한 podaci 없음 |
| -14 | korisnik pokazivač/niz_VALUE klip greška |
| -19 | Podrška_VALUE NIC 없음 |
| -22 | port_VALUE/čekaj_VALUE TIME_VALUE/인수 VALUE greška |
| -24 | 열린 Mreža_port 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | podaci 또는 primiti_VALUE niz_VALUE promeniti_veličinu 문제 |
| -98 | lokalni_skup port_VALUE INDEX 중복 |
| -101 | 지원하지 않는 odredište_VALUE adresa |
| -110 | ARP·uređaj_VALUE·primiti_VALUE TIME_VALUE 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 kodiranje_VALUE 있는 Java `int`의 bit_VALUE 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## Izvrši_komanda 경계와 시스템 호출

```text
ljuska run → JKAP에서 ELF potvrditi·적재 → ring 3 korisnik program_f5044b9b
                                 ↓ int 0x80
                      pokazivač 검사 → Java jezgro_VALUE API → RTL8139/UDP
                                 ↓ Izađi_program·izuzetak·TIME_VALUE 초과
                                ljuska 복귀
```

시스템 호출 레지스터는 `EAX=INDEX`, `EBX,ECX,EDX,ESI,EDI=인수`, `EAX=KR`다. Java 호출 operand_stek ABI는 컴파일러가 korisnik 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| INDEX | 호출 |
| --- | --- |
| 0 | Izađi_program(Status_VALUE kôd_VALUE) — koristiti/greška 런타임에서 koristiti_VALUE |
| 1 | niska_VALUE 쓰기 |
| 2 / 3 | 인수 stavka_COUNT / 인수 niska_VALUE adresa |
| 10 | UDP otvoren |
| 11 | UDP poslati(pokazivač_VALUE, IP, odredište_VALUE port_VALUE, niz_VALUE adresa, 길이) |
| 12 | UDP primiti(pokazivač_VALUE, niz_VALUE adresa, 제한 밀리초) |
| 13 | UDP Zatvori |
| 14 | lokalni_skup IP adresa |
| 15 / 16 | 마지막 ravnopravni_uređaj_VALUE IP / UDP port_VALUE |
| 20 | RAM Datoteka 읽기(ime int[] adresa, 출력 int[] adresa) |
| 21 | RAM Datoteka 쓰기(ime int[] adresa, 입력 int[] adresa, bajt_VALUE 길이) |
| 22 | UTF-16 kôd_VALUE lekcija_VALUE 문자 출력(0~65535) |

Datoteka API는 `korisnik.파일읽기(int[] ime, int[] podaci)`와 `korisnik.파일쓰기(int[] ime, int[] podaci, int 길이)`다. 이름은 ASCII kôd_VALUE niz_VALUE(최대 64칸, 0 Izađi_program 또는 niz_VALUE 끝), podaci stavka_element 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 Datoteka 없음 `-2`, pokazivač greška `-14`, ime/길이 greška `-22`, Datoteka 슬롯 부족 `-28`, promeniti_veličinu 초과 `-90`을 반환한다. 쓰기는 potvrditi 후 Datoteka 전체를 대체한다. `korisnik.문자쓰기(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 korisnik 모드에서 CS의 하위 비트를 직접 읽으므로 stvarni_podaci Izvrši_komanda 권한을 확인한다. jezgro_VALUE 포트 접근용 `uređaj_VALUE` native 함수는 korisnik cilj 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 Izvrši_komanda, 파이프, 프로세스 간 통신은 없다. Izvrši_komanda 파일은 커널의 읽기 전용 JKAP 묶음에서 적재한다. podaci 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- korisnik 가상 adresa `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. Izvrši_komanda 영상은 čeona_kamera_VALUE 2MiB, 인수는 `0x04300000`부터, 스택은 oblast_VALUE_0e9a97ab 끝에서 시작한다. jezgro_VALUE identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB korisnik 영역을 비우고 Datoteka 구역을 복사해 BSS·niz_VALUE 영역을 초기화한다. korisnik GC는 없지만 Izađi_program 후 Dalje_stavka Izvrši_komanda 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 Citat/이스케이프 파싱은 없다.
- korisnik 페이지의 kôd_VALUE/podaci 분리 읽기 전용 Postavke, NX, operand_stek guard, ASLR은 아직 없다. 커널과 korisnik Memorija_podaci·포트 dozvola_VALUE 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 Izvrši_komanda 상한을 두며 TIME_VALUE 초과는 `Exit: 124`다. korisnik CPU 예외는 `128 + izuzetak INDEX`(페이지 greška 142, 특권 위반 141), Java niz_VALUE/계산 오류는 101~105다. jezgro_VALUE 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, 정적 IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP kontrolni_zbir 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- korisnik Izvrši_komanda·네트워크·zaštititi_VALUE 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 Izvrši_komanda·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## potvrditi 근거

`make test`는 kompajler 14개 시험, Java 패킷 stanje 2,201개 검사, 기존 ljuska ELF/ISO 부팅 시험, korisnik ELF/stvarni_podaci UDP/zaštititi_VALUE 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 길이·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 komanda·무한 sprint_VALUE 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
