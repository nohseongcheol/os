# Java 네이티브 компилятор

OpenJDK свой 소스를 빌드하는 **`--target openjdk-build`**와 свой ядро_ЗНАЧЕН ABI 검사 도구를 추가했다.
이는 공식 javac/C/C++ 도구를 연결하는 별도 경로다. [сборка 방법·фактический_данные проверить·ядро_ЗНАЧЕН 이식 клип](OpenJDK-источник_BLD_И-собственный_ядро-이식.md)를 참고한다.

x86 직접 변환과 ARM64 C генерировать 후단은 모두 [ПредварительныйКомпилятор.java](СредстваJava/ПредварительныйКомпилятор.java)로 구현한다. `sh 미리번역.sh`로 직접 실행하며, [ПредварительныйКомпилятор.py](ПредварительныйКомпилятор.py)와 `компилятор.py`는 Назад_товар команда·API 및 OpenJDK 도구를 위한 호환 진입점이다. свой Pi4 후단은 freestanding C를 거쳐 AArch64로 만든다. [arm64.py](arm64.py)는 Назад_товар 경로와 Python 호출을 위한 호환 진입점이다. ФУНКЦИЯ_ЗНАЧЕН·переменная_ЗНАЧЕН·генерировать C 이름의 뜻과 예외는 [русский 명명 файл_сведений_eb81d7d9](../platforms/rpi4-native/명명/файл_сведений_eb81d7d9.md)를 참고한다. [ARM64 сборка·опора_ЗНАЧЕН клип](../platforms/rpi4-native/файл_сведений_eb81d7d9.md)에 실행 조건이 있다. 전체 OpenJDK나 일반 Класс_ЗНАЧЕН 실행기는 아니다.

실행 시 JVM이 필요 없는 x86 32비트 ELF를 만든다. JDK 11 이상으로 실행하는 Java свой AOT 후단이며, Java 전체를 새로 구현한 컴파일러는 아니다. Java 문법·доступ_ввод управление_ЗНАЧЕН·ТИП_ЗНАЧЕН 검사는 JDK의 `javac`에 맡기고, Java 8 Класс_ЗНАЧЕН 파일을 읽어 각 바이트코드를 x86 명령으로 직접 변환한다. C 코드로 우회하거나 바이트코드 해석기를 커널에 넣지 않는다.

```text
Java исходныйКод → javac의 문법·ТИП_ЗНАЧЕН 검사 → 임시 .class
          → свой x86 변환기 → GNU as/ld → 네이티브 ELF32
```

## 준비와 실행

сборка узел: Linux, Python 3.6 이상, JDK 11 이상(`javac --release 8`), GNU binutils(`as`, `ld`), Make. текущий_товар 환경의 OpenJDK 11, Python 3.6, binutils 2.30으로 검증했다. внешний_ЗНАЧЕН Python 패키지와 네트워크 다운로드는 사용하지 않는다.

```sh
cd /home/user/jkoros/compiler
make
./build/계산
echo $?                  # 0이면 예제 испытания 성공

python3 компилятор.py --target linux --entry 계산.запустить \
    -o build/계산 예제/계산.java

make test
```

`linux` 대상은 Linux의 32비트 실행 호환 기능이 필요하다. `int 0x80`을 차단하는 샌드박스에서는 `Bad system call`이 발생할 수 있다. ИТ_службы_обычный Linux узел 또는 해당 실행을 허용한 испытания 환경에서 실행한다. 시험의 비정상 종료를 통과로 처리하지 않는다.

진입점은 `static int запустить()` 또는 `static void запустить()`처럼 인수가 없어야 한다. `--entry 패키지.Класс_ЗНАЧЕН.ФУНКЦИЯ_ЗНАЧЕН`로 선택한다. `int` 반환값은 Linux 프로세스 Выход_программа 코드가 되며 셸에는 하위 8비트가 보인다. 일반 `main(String[] args)` 실행 환경이나 표준 входные_данные_выход 라이브러리는 제공하지 않는다.

`--target kernel`은 запуск_машины 코드와 연결할 재배치 ELF 오브젝트를 생성한다.

```sh
cd /home/user/jkoros
python3 compiler/компилятор.py --target kernel --entry Ядро.запустить \
    --export kernel_dispatch=системный_вызов.Процесс_ЗНАЧЕН_ввод \
    -o os/build/java.o os/исходныйКод/*.java
```

`--target user`는 jkoros 셸에서 실행할 독립 ELF를 생성한다. `пространство_пользователя` 클래스의 제한된 native API는 `int 0x80` 시스템 호출로 연결하며 `устройство_ЗНАЧЕН` 클래스의 аппаратный_ЗНАЧЕН 직접 접근은 거부한다. пространство_пользователя ELF는 Linux 실행 файл ABI와 다르므로 호스트에서 실행하지 않는다. генерировать·регистр_ввод 방법은 [пространство_пользователя 실행 файл_сведений_eb81d7d9](../os/пространство_пользователя/файл_сведений_eb81d7d9.md)에 있다. `--export 외부기호=Класс_ЗНАЧЕН.ФУНКЦИЯ_ЗНАЧЕН`는 오버로드되지 않은 статический_ЗНАЧЕН 함수를 свой операнд_стек ABI로 노출한다. 커널의 시스템 호출 진입점에 사용한다.

Java 파일은 필요한 클래스들을 한꺼번에 전달한다. текстовыйВывод 옆의 `.s`는 생성된 어셈블리, `.json`은 исходныйКод SHA-256 및 네이티브 символ↔Java ФУНКЦИЯ_ЗНАЧЕН 대응표다. русский 함수명은 원문과 대응표에 보존하고 ELF 내부에는 충돌 방지용 компьютер_5eb260fa 기호를 쓴다. компилировать_источник·собрать_ЗНАЧЕН·Подключить 중 실패하면 기존 результат 파일을 덮어쓰지 않는다.

## опора_ЗНАЧЕН клип

- `int`, `boolean`, `byte`, `short`, `char`의 32비트 계산 및 ТИП_ЗНАЧЕН ПРЕОБР_ЗНАЧЕН.
- статический_ЗНАЧЕН 필드와 статический_ЗНАЧЕН ФУНКЦИЯ_ЗНАЧЕН, 매개변수·반환값, 재귀, 클래스별 지연 초기화와 инициализировать цикл_ЗНАЧЕН.
- 조건문, 반복문, 단락 평가, 삼항식, целое_число `switch`, 넓은 локальный_Scope переменная_ЗНАЧЕН 인덱스.
- 덧셈·뺄셈·곱셈·나눗셈·나머지·бит_ЗНАЧЕН 연산과 переместить_ЗНАЧЕН. Java의 오버플로 및 `MIN_VALUE / -1` 동작을 유지한다.
- `int[]` генерировать·초기값 0·длина_ЗНАЧЕН·Чтение·Запись·ссылка 비교. 256KiB 고정 МАССИВ_ЗНАЧЕН регион_ЗНАЧЕН, 널/подстрочный_ЗНАЧЕН/Размер/АДРЕС_регион 검사.
- строка_ЗНАЧЕН 리터럴과 `String` ссылка, `length()` 및 `charAt()`. 문자열은 UTF-16 кодовое_значение 단위로 저장하고 같은 리터럴은 공유한다. NUL 및 대리쌍도 시험한다.
- русский Класс_ЗНАЧЕН·ФУНКЦИЯ_ЗНАЧЕН·переменная_ЗНАЧЕН·файл Название.

`new Object`, 인스턴스 значение_поля/ФУНКЦИЯ_ЗНАЧЕН, 상속/인터페이스, `long/float/double` 실행 операция_ЗНАЧЕН, `int[]` 이외 МАССИВ_ЗНАЧЕН, строка_ЗНАЧЕН 동적 결합, Java 표준 библиотека, исключение Процесс_ЗНАЧЕН_ввод, 스레드·синхронизировать·GC는 미지원이다. 실행에 필요한 미지원 바이트코드나 внешний_ЗНАЧЕН 호출을 발견하면 실패한다. 사용되지 않는 значение_по_умолчанию 생성자는 실행 코드로 만들지 않는다. Java 8 문법이어도 모든 프로그램을 컴파일할 수 있다는 뜻은 아니다.

исключение объект_ЗНАЧЕН 대신 런타임 ошибка 번호로 중단한다. Linux와 jkoros пространство_пользователя 대상에서는 `100 + ИНДЕКС`로 종료하고 ядро_ЗНАЧЕН 대상에서는 `JKOROS PANIC ИНДЕКС`를 출력하고 정지한다. пространство_пользователя 프로그램만 종료한 경우 셸은 계속 실행된다.

| ИНДЕКС | 원인 |
| --- | --- |
| 1 | 0으로 отдел_KR |
| 2 | 널 ссылка |
| 3 | МАССИВ_ЗНАЧЕН/строка_ЗНАЧЕН подстрочный_ЗНАЧЕН клип 초과 |
| 4 | 음수 МАССИВ_ЗНАЧЕН Размер |
| 5 | МАССИВ_ЗНАЧЕН регион_ЗНАЧЕН 부족 |

МАССИВ_ЗНАЧЕН 영역은 증가식 할당이며 회수하지 않는다. 재귀 스택의 граница_ЗНАЧЕН 검사도 아직 없으므로 무제한 재귀를 안전하게 처리하는 런타임은 아니다. 특권 ядро_ЗНАЧЕН 및 신뢰할 수 있는 작은 프로그램용 начальное_состояние 구현이다.

## native 경계와 ABI

ядро_ЗНАЧЕН 대상에서는 `os/исходныйКод/устройство_ЗНАЧЕН.java`, пространство_пользователя 대상에서는 `os/пространство_пользователя/декларация/пространство_пользователя.java`의 정확한 метод_имя_SMS·서술만 허용한다. 임의의 `native` 함수와 Linux/пространство_пользователя 대상의 аппаратный_ЗНАЧЕН 접근은 거부한다. Java 인수를 왼쪽부터 32비트 한 칸씩 스택에 놓으며, 반환값은 EAX, EBP/ESP 이외 레지스터는 호출자가 보존한다고 가정하지 않는다. C의 cdecl/JNI ABI가 아니므로 C 함수와 바로 연결하면 안 된다.

Java исходныйКод 또는 `.class` 입력을 받는다. 전체 JVM 바이트코드 검증기는 제공하지 않는다. 어노테이션 처리는 비활성화하고 비어 있는 Класс_ЗНАЧЕН путь/исходныйКод 경로에서 명시한 소스만 컴파일한다.

## 검증과 реализация 근거
