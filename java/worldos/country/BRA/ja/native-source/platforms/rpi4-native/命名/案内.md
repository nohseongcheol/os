# 内蔵 커널과 번역기의 日本語 名前

대상은 `platforms/rpi4-native`의 内蔵 Java 中核値, 利用者 JVM, C 機械 接続,
TCP/UDP·FTP, C コンパイラ道具要素 이식부, MicroPython 이식부, システム構築·命令実行·試験 도구다.
`golang/worldos/国別値/KOR/ソース`의 원칙처럼 기능을 먼저 구분하고 이름을 정한다.
x86 Java 커널과 공용 x86·ARM64 미리 번역기의 内蔵 선언도 命名 검사에 포함한다.
Linux 실행판의 ホスト 道具, OpenJDK 補助値 道具 및 外部値 配布値 ソース木 전체를
한국어로 再試行処理値 작성했다는 뜻은 아니다.

## 命名 원칙과 말의 근거

- 명사는 자료의 역할을 나타낸다: `ファイル取扱い`, `通信相手ポート番号`, `ヒープ記憶装置`, `キーボード`.
- 함수는 행위를 나타낸다: `読取`, `書込`, `開放`, `閉鎖`, `網結合`, `プログラム起動処理`.
- TCP의 이어진 バイト値 흐름과 UDP의 境界位置値 있는 자료를 `接続経路`와 `データグラムチャネル`로 구별한다.
- 짧은 영어 변수도 쓰임에 따라 `長さ`, `データ位置`, `検索添字`, `返却済み値`으로 풀어 쓴다.
  序数添字·一時値 산술값처럼 여러 역할에 재사용되는 변수는 `序数添字`, `先頭位置値`, `第二値`으로 구별한다.
- 이름이 같아도 外部値 구조체의 필드와 内蔵 변수는 별도로 분석한다.

`チャネル入口(通路)`는 이동이나 교류가 이루어지는 길이라는 기존 의미를 通信 연결에
적용했다. `ポート値(窓口)`의 주고받는 접점이라는 의미를 연결을 받는 곳에 적용했다.
이는 국립국어원 한국어기초사전의 [チャネル入口](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=49310),
[ポート値](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=24898)의 뜻에 근거한다.

`データグラム(電文)`은 전보에 담는 글이라는 기존 通信 어휘에서 가져와, UDP 자료의
경계가 보존된다는 특징을 드러내는 데 쓴다. 근거는
[한국어기초사전 データグラム](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=74335)이다.
`ストリーム値`, `スレッド値`, `쌓임`은 우리말의 움직임·判定継続状態·쌓이는 모양을 빌린 표현이다.
`入力ストリーム`, `作業担当`, `スタック記憶装置` 같은 복합 이름은 이 프로젝트의 기능별 조어다.
이 辞書 근거를 특정 중세 문헌의 최초 출현이나 공인 전산 번역으로 확대하지 않는다.
공인 표준 ソース翻訳処理·국어사 データグラム 감수를 마쳤다는 뜻도 아니다.

| 기능 | 채택한 名前 | 理由値 |
|---|---|---|
| TCP Socket | 接続経路 | 상대와 연결되어 順序値 있는 바이트를 주고받음 |
| ServerSocket | ポート受取 | 새 연결이 들어오는 접점 |
| DatagramSocket | データグラムチャネル | 각 자료의 경계를 보존하는 通信 |
| InputStream / OutputStream | 入力ストリーム / 出力ストリーム | 들어오고 나가는 바이트의 順序値 |
| heap / stack | ヒープ記憶装置 / スタック記憶装置 | 記憶装置確保 방식과 쌓고 꺼내는 構造 |
| thread / keyboard | 作業担当 / キーボード | 이어지는 실행과 글쇠의 配列値 |
| exception / timeout | 例外 / 待合待機期限例外 | 判定通常 처리에서 벗어남과 그 구체적 理由値 |

## 보존하는 標準定義 名前

`public`, `class`, `int`는 예약어다. `String`, `main`, 배열의 `length`는 예약어가 아니다.
現在項目 다섯 Java 예제는 `起動処理()`·`実行引数`·日本語 画面/スレッド値 API를 사용해
予約済み語一覧·리터럴 외의 식별자를 한국어로 작성한다. 画面/가닥은 표준 객체를
감싸지 않고 内蔵 JVM에 직접 구현했다. 자세한 계약은 [日本語 Java API](../日本語Java/案内.md)를 본다.

표준 javac는 文字列 리터럴에 `java.lang.String`, 文字列 결합에 `StringBuilder`
같은 이름을 생성한다. 이들은 日本語 소스에서도 바이트코드에 남을 数 있다.
기존 표준 class를 실행하는 JVM의 対応付け値 文字列, 아직 표준 라이브러리를 쓰는
通信·ファイル 연결부까지 全体構築 한국어로 재구현한 것은 아니다. 이름만 일괄 치환하면
記述子入口·재정의·native 연결이 달라져 호환성이 깨진다.

C 표준 関数·整数値型·POSIX ABI, CPU 値レジスタ 名前, 어셈블리 命令, 링커 절 名前,
TinyCC·lwIP·MicroPython이 요구하는 設定値 매크로와 헤더 이름도 보존한다.
예: `main`, `memcpy`, `pk_bind`, `mpconfigport.h`, `lwipopts.h`, `stdint.h`.
内蔵 C 함수의 ソース木 이름은 한국어이며, [機械連結名前一覧.h](機械連結名前一覧.h)先頭位置被演算子
기존 AOT·어셈블리·SDK에 공개한 機械 심볼과 연결한다.
Python의 `__init__`, `setUp`, `handle`, 표준 モジュール値 属性値, 명령행 옵션과 JSON 키도
外部値 계약이다. `build/`, 配布値 바이너리 이름과 `/sdk`는 기존 命令実行 경로를 유지한다.
外部値 원본은 `vendor/`에서 이용허락·해시와 함께 관리한다.

## 검사와 재실행

```sh
cd /home/user/jkoros/platforms/rpi4-native
python3 道具/命名検査.py
make システム構築
make 試験
make test-examples test-ftp test-elf
python3 道具/命令実行.py --desktop --network
```

`道具/C名前一覧分析.py`는 libclang 6으로 C 선언과 참조를 검사한다.
`道具/*이름반영.py`는 値変更 直前側値 ソース木·분석표를 필요로 하는 일회성 이행 도구다.
이미 변경된 소스에 再試行処理値 적용하여 대응표를 덮어쓰지 않는다.

## C 通信 구조체와 Python エラー

C 통신에서 `갈래`는 番地 체계를 구분하고 `ポート番号`는 port, `番地値`은
IPv4 주소의 32비트 값을 나타낸다. `データグラム通信規約`은 앞서 설명한 データグラム(電文)과
契約値(規約)을 결합해 UDP의 기능을 드러낸 프로젝트 이름이다.

| 표준 표현 | 日本語 직접 実装 |
|---|---|
| AF_INET / SOCK_DGRAM / IPPROTO_UDP | enum의 インターネット体系 / データグラムソケット / データグラム通信規約 |
| struct pk_sockaddr_in | struct インターネットソケット番地 |
| sin_family / sin_port | 番地体系 / ポート番号 |
| sin_addr.s_addr | インターネット番地.番地値 |
| OSError / エラー.args[0] | システムエラー / エラー.番号 |

日本語 구조체는 `#define` 치환이나 フィールド値 별칭이 아닌 별개 자료형이다.
표준 구조체와 같은 16바이트 배치를 선언하며 中核値 SVC에서 バイト値 복사로
검사한다. `通信端点作成`·`データグラムデータ送信`와 ファイル 함수는 静的値 라이브러리에
実際データ 日本語 이름의 関数 심볼을 갖는다. 기존 pk_* 심볼도 유지한다.
前回項目 코드에서 日本語 通信 함수에 pk_sockaddr*를 전달했다면 日本語 구조체로
옮기거나, 표준 구조체와 pk_* 함수의 짝을 유지한다.

Python의 `システムエラー`는 OSError의 日本語 하위 클래스이며 연결부에서
エラー 번호를 보존하여 변환한다. 일반 Python 문법과 外部値 패키지의 API는 유지한다.

## 직접 GUI 이름의 뜻과 검토 切抜き

`実行可能処理作業`은 수행할 내용을, `作業実行`는 그 수행을 나타낸다.
`動作受信先`는 동작이 발생했다는 알림을 받는 역할, `動作通知`은 전달되는 사건이다.
`ボタン`는 눌러 동작시키는 조작부, `ラベル`는 案内 글의 位置添字,
`本文フィールド`은 글을 적는 位置添字, `作業担当`은 이어지는 命令実行 흐름을 뜻한다.
`命令実行(實行)`·`動作(動作)`의 기존 뜻과 `받다`·`알리다`·`スレッド値`의 기능을
결합한 프로젝트 이름이다. 새 복합어가 역사 문헌에 그대로 있었다거나
특정 시대에 初期項目 쓰였다고 주장하지 않는다.

전체 저장소는 `python3 道具/ソース検討.py`로 검토한다.
결과는 `build/verification/naming/source-review.json`이며 파일별 ハッシュファイル,
ASCII 파일명과 Python의 영어 宣言 위치를 기록한다.
공용 ARM64·x86 번역기의 구현은 `compiler/Java道具/事前用時間コンパイラ.java`로 전환했다. `compiler/事前用時間コンパイラ.py`는 호환 진입점이다.
`compiler/arm64.py`는 前回項目 경로와 `ARM64(...).generate(...)` 호출을 継続状態値 주는
호환 진입점이다. `compiler/classfile.py`, OpenJDK 補助値 道具, Linux 版値 도구와
기존 호환 진입점에는 영어 이름이 남아 있다. 따라서 전체 저장소가
予約済み語一覧 외 100% 한국어라고 판정하지 않는다.
`道具/命名検査.py --C言語`는 活動中 ARM64 소스의 宣言, C 의미 値分析,
x86 Java 커널과 공용 번역기의 内蔵 宣言, Java 用例 전체 識別子値,
ARM64 Python 예제와 직접 GUI/가닥에 표준 래퍼가 없는지를 별도로 검사한다.

## 現在項目 기능을 기준으로 보완한 名前

번역은 글자를 음역하는 대신 자료의 역할과 함수의 행동을 구분한다.
동일한 영어 이름도 문맥이 다르면 日本語 이름을 달리 정한다.
ファイル 이름은 주된 기능을 나타내고, 関数 이름은 행동을, 変数値 이름은 담는 자료를 나타낸다.
予約済み語一覧, 표준 API 및 外部値 接続 규약은 따로 기록한다.

| 前回項目 名前 | 적용한 名前 | 現在項目 기능 |
|---|---|---|
| `arm64.py`의 実装 | `compiler/Java道具/事前用時間コンパイラ.java` | Java 바이트코드를 독립 실행용 C 원문으로 미리 ソース翻訳処理 |
| `ARM64`, `generate` | `機械コードコンパイラ`, `生成` | ソース翻訳処理 상태를 담는 객체와 C ソース 生成 挙動値 |
| `prototype`, `method` | `メソッド原型`, `メソッド本体` | 함수의 書式値 선언과 実際データ 命令 ソース |
| `profile`, `heap_words` | `実行状態対象`, `ヒープ語個数` | 中核値·利用者 구분과 記憶装置確保 記憶 공간의 機械 字句用語 数 |
| `pc`, `op` | `命令位置`, `명령번호` | 바이트코드에서의 위치와 수행할 명령의 番号 |
| `x`, `y`, `w`, `h` | `横座標`, `縦座標`, `領域幅`, `領域高さ` | 遠隔値 화면의 위치와 직사각형 容量 |
| `p`, `n`, `i`, `j` | `データ位置`, `値`, `序数添字`, `内側序数` | 遠隔値 画面 データ·桁値·反復回値 位置添字; 파일별 기능을 확인해 적용 |
| `aot_heap_info`, `__stack_top` | `事前翻訳記憶検索`, `スタック上端` | 機械 接続 규약을 유지하면서 内蔵 소스에서 사용하는 名前 |
| `앞캐리지` | `復帰到達先前回行` | 앞서 받은 문자가 줄복귀였는지 기억하여 중복 줄바꿈을 막음 |

[共有コンパイラ名前一覧.tsv](共有コンパイラ名前一覧.tsv)에 コンパイラ道具要素 참조의 実際データ 値変更 기록을 남겼다.
추가로 보존한 C·POSIX/lwIP/libassh 이름의 이유는
[標準名前根拠.json](標準名前根拠.json)에 기록한다.
`Cコンパイラ/コンパイラ道具要素.c`는 TinyCC 外部値 원문을 포함하는 接続 파일로 内蔵 선언이 없어서
C 内蔵 宣言 분석에서는 제외한다. 実際データ 中核値 빌드에서는 継続処理工程 컴파일한다.

### 말의 뿌리와 새로운 복합 名前

`記憶(記憶)`과 `検索添字(索引)`은 기존 한자어를 쓴다.
기억은 자료를 간직하는 기능에, 색인은 順序値 있는 항목을 찾아 지정하는 기능에 적용한다.
辞書 근거는 국립국어원 한국어기초사전의
[記憶](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=38812&nation=eng),
[検索添字](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=63787)이다.

`スタック記憶装置`, `値積載`, `値取出し`는 자료를 포개고 末尾項目 자료부터 꺼내는 命令実行 구조를 드러낸다.
`쌓다`의 기존 뜻에 근거한 기능별 조어이며, 사전의
[쌓다](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=62095)를 참고한다.
`事前用時間`은 命令実行 전에 번역한다는 기능을 직접 나타낸다.
`機械語`은 처리기의 データ 단위를 가리키며, 언어의 일반 낱말과 구별하도록 `機械`를 붙였다.
`事前用時間コンパイラ`, `ヒープ語個数` 같은 복합 이름은 現在項目 기능에 맞게 만든 프로젝트 용어다.
이 복합어가 옛 문헌에 그대로 있었다거나 특정 시대에 初期項目 나타났다는 뜻은 아니다.
확인되지 않은 중세 형태나 최초 使用値 연대는 어원 근거로 적지 않는다.

생성되는 C의 내부 データ型·配列値·関数·局所有効範囲 変数値·分岐 이름도 한국어로 바꾼다.
직접 ハングル文字列 식별자를 읽지 못하는 예전 GCC를 위해 호환 API는 같은 日本語 이름을
표준 C 범용 文字 표기로 출력한다. 実際データ ARM64 빌드는 Clang으로 읽을 数 있는 ハングル文字列 원문을 사용한다.
