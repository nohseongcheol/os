# Raspberry Pi 4 内蔵 Java 中核値 — 利用者 命令実行 基盤

現在項目 内蔵 코드의 COSL 상업 条件, 제3자 고지 및 LGPL 再接続通信端点 자료는 [COSL 配布値 案内](COSL配布手引.md)를 참고한다. 切替方式 直前側値 GPL 구성의 판단은 [前回項目 라이선스 검토](利用許諾検討.md)에 기록했다.

日本語 通信·例外 사용법은 [日本語 Java API](日本語Java/案内.md), 関数·変数値·ファイル 이름의 변경과 어원 근거는 [命名 案内](命名/案内.md)를 참고한다.

Linux 없이 부팅하는 内蔵 AArch64 커널이다. Java AOT 中核値 위에 **命令行 シェル, 게스트 Java コンパイラ·JVM, MicroPython, EL0 C++ 命令実行, ファイル·UDP 루프백 시스템 呼出, 여러 ハングル文字列 GUI 端末·vi 編集器·Swing 부분집합**을 제공한다. 커널의 ファイル データ/정책·루프백 転送値·シェル 상태는 Java, 画面 합성·画素 値変更·ポインタ·클리핑도 Java로 구현하며, CPU/MMU/装置 경계와 端末·文字値 塗装画面 연결은 C와 어셈블리다.

**전체 JDK/JRE·CPython·표준 C++ 런타임·Swing 이식은 아직 완료되지 않았다.** 기존 [ARM64 Linux 실행판](../rpi4/README.md)의 OpenJDK/Python 패키지를 이 内蔵 커널에 탑재했다고 표시하지 않는다.

새로운 게스트 `cc`/`jaot`, JAR 직접 命令実行, lwIP TCP/UDP와 FTP는 [FTP·C·JAR·AOT 매뉴얼](ファイル転送論理積翻訳工程.md)을 참고한다. 게스트 SSH·VNC와 Pi4 GENET/PHY·DHCP 드라이버를 추가했다. **SSH·VNC는 QEMU에서 검증하며, 物理機器 Pi4의 結線済み値 송수신은 아직 미검증이다.** 命令実行·接続状態·合言葉値 확인은 [外部値 接続状態 案内](外部接続状態手引.md)에 정리했다.

셸은 EL1 中核値, `java` 등 利用者 命令実行 파일은 EL0에서 실행한다.
`ps`·`top`의 표시와 上限値, QEMU 네트워크 命令実行·接続状態 방법 및 実際データ 검증은
[命令実行 계층과 外部値 通信 状況調査](実行環境論理積外部通信網検査項目.md)을 참고한다.

ELF는 확장자가 아닌 実際データ 命令実行 형식으로 검사한다. `./挨拶例`처럼 확장자 없이 실행하며, 제한된 Linux ARM64 静的値 ELF는 `run --linux ファイル名前本文`으로 실행한다. [ELF·Linux ABI 支援値 범위와 동일 바이너리 試験](実行形式ABI.md).

GUI와 네트워크는 `python3 道具/命令実行.py --desktop --network`로 함께 사용한다. Java·C·Python의 日本語 用例 13개는 [jkoros/example](../../example/README.md)에 있으며, **게스트 起動 시 `/example/java`, `/example/c`, `/example/python`에 자동으로 준비된다.** `example java|c|python`으로 지운 예제를 복원할 数 있다. Remmina에서 **F9/Shift+Space/한·零被演算子 キー値**로 `[EN]`↔`[KO]` 두벌식을 전환한다(`help ko`). `make test-examples`는 같은 GUI VM에서 FTP·実際データ TCP/UDP·ファイル バイト値·그래픽 픽셀을 검증한다.

게스트에서 `cd /example/java` 後続側状況 `java 窓例`로 日本語 Swing 예제를 실행한다. 端末 모서리에 마우스를 대고 **左側面 버튼으로 끌면 크기가 바뀐다**. `terminal size`는 現在項目 列値·行番号値 수를 보여 준다.

命令実行 버튼 화면은 5×7 영문 글꼴을 쓰며, 端末 창은 Noto CJK/DejaVu에서 생성한 ハングル文字列·Unicode 비트맵 글꼴을 쓴다. UART와 実際データ 프레임버퍼의 ハングル文字列 표시를 시험한다. 루프백은 동일 中核値 내부의 データグラム 전달이며 IP 패킷을 Ethernet으로 내보내는 드라이버가 아니다. 바깥 IPv4는 lwIP TCP/UDP 스택으로 補助値 UART SLIP 경로를 사용한다. `python3 道具/命令実行.py --network`로 QEMU NAT를 연결하고 `ftpd start`로 서비스를 시작한다.

Java의 정확한 API·문법·命令実行 제한과 日本語 사용법은 [内蔵 JVM과 日本語 ライブラリ](Java実行環境環境.md)에 정리했다. クラス値 ファイル/JAR 배포는 [日本語Java](日本語Java) 소스에서 재현한다. 기존 Linux판 `日本語.Java`와 별도인 `日本語.内蔵` 패키지다.

**vi·여러 窓·Swing·ハングル文字列 Java/Python/C/C++·posix-kor 예제는 [ハングル文字列 開発 매뉴얼](開発手引.md)에 정리했다.**

GUI 端末 命令実行·단축키·シェル 命令·제한은 [셸과 端末 사용법](シェル論理積端末.md)에 정리했다.

## 現在項目 컴퓨터에서 命令実行

```sh
cd /home/user/jkoros/platforms/rpi4-native
make test
make run
```

終了点プログラム: **Ctrl+A 次回項目 X**. 게스트 C/AOT 道具 빌드에는 `make rpi-prepare`로 준비한 ARM64 SDK 헤더와 libgcc 算術値 補助値 함수도 필요하다. libc나 Linux 커널을 게스트에 넣는 것은 아니다. ホスト 도구는 JDK 11 이상, Python 3.6 이상, Clang/Clang++, AArch64 GNU binutils, Make, `libnewlib-dev` 헤더다. MicroPython은 `/usr/include/newlib` 헤더를 사용하며 다른 위치는 `NEWLIB_INCLUDE`로 지정한다. newlib 런타임을 移植·링크한 것은 아니다. コンパイラ 의미 비교에는 GCC/UBSan도 사용한다. 기존 `../rpi4/build/host`의 QEMU 11.0.3이 있으면 이용하며, 그렇지 않으면 PATH의 QEMU를 사용한다. `QEMU_AARCH64=/절대/経路/qemu-system-aarch64`로 지정할 수도 있다. `raspi4b` 支援値 여부를 확인한 後続側状況 실행한다.

명령은 **Enter를 눌러 命令実行**한다. 기존 한 文字値 명령도 Enter가 필요하다.

```text
javac Hello.java
java Hello "ハングル文字列 引数 😀"
python hello.py
python -c 'print(2**100)'
ls
cat python.txt
run cpp
net test
gui
```

| 命令 | 動作 |
|---|---|
| `help` / `info` | 命令·実際データ 実装 状況値 |
| `ls` / `cat FILE` / `rm FILE` | RAM ファイル 入口一覧·内容物値·삭제 |
| `vi FILE` | 利用者 領域値 vi 부분집합, ハングル文字列 編集値·格納値·검색·되돌리기 |
| `edit FILE` | ファイル 전체를 새로 入力値; 단독 `.` 줄로 格納値, Ctrl-C로 取消処理操作 |
| `javac FILE.java` / `java CLASS [ARGS]` | 内蔵 제한형 Java ソースコンパイル·命令実行 |
| `python FILE.py [ARGS]` / `python -c 'CODE'` | MicroPython ソースコンパイル·命令実行 |
| `load FILE` / `hex FILE` | 16진수 바이너리 入力値/出力; 입력은 단독 `.` 줄로 格納値 |
| `run FILE.elf [ARGS]` / `run cpp` | 업로드한 内蔵 ABI ELF / 내장 C++ 用例 |
| `net test` / `tasks` / `selftest` | UDP 루프백 / 협력식 作業 / EL0 値防護 試験 |
| `gui` / `terminal` | 命令実行 画面 / ハングル文字列 GUI 端末; F12로 端末 開放·閉鎖 |
| `samples` | 삭제한 既定値 用例 状況復旧; 기존 파일은 보존 |

예를 들어 `edit 挨拶例.java`를 입력한 次回項目 下端値 소스를 입력한다.

```java
public class 挨拶例 { public static void main(String[] args) { int 値 = 7; System.out.println("ハングル文字列=" + 値); } }
```

그다음 단독 `.` 줄로 저장하고 `javac 挨拶例.java`, `java 挨拶例`를 실행한다. 편집기는 기존 파일에 커서를 이동하는 방식이 아니라 전체 교체 방식이다. 取消処理操作·잘못된 16진수·容積値 초과는 원본을 보존한다. 줄은 4096바이트, 파일은 16384바이트, 命令実行 인수는 最大値 8개·각각 UTF-8 255바이트다. 일반 命令 인수는 最大値 32개다. 引用·백슬래시·シェル 変数値·파이프·리다이렉션 범위는 [シェル 説明](シェル論理積端末.md)을 참고한다.

GUI 터미널은 다음과 같이 실행하고 Remmina에서 **VNC**, 番地 **127.0.0.1:5902**로 연결한다. 키보드·ハングル文字列 Unicode 入力値·명시적 貼付け値·命令実行 버튼의 마우스 클릭을 QEMU 도구가 UART에 전달한다.

```sh
make desktop
# GUI + 네트워크: python3 道具/命令実行.py --desktop --network
# 다른 機器ポート: python3 道具/命令実行.py --desktop --port 5903
```

종료는 실행한 ホスト 터미널에서 Ctrl+C다. 기존 `python3 道具/命令実行.py --vnc 127.0.0.1:2`는 画面 보기와 별도 UART 입력을 유지한다. `make run`은 일반 UART 셸이다. 実際データ Pi4 USB 입력기는 아직 없으며, VNC 接続 도구는 QEMU 시험용이다.

GUI의 다섯 버튼은 実際データ C++/UDP ELF 命令実行, `Hello.java` ソースコンパイル 後続側状況 JVM 命令実行, `hello.py` 命令実行, GUI 端末 열기를 수행한다. 한 번에 한 프로그램이 CPU에서 실행되며 일반 실행에는 약 2초 기한이 있다. vi·Swing은 対話式 대기에서 기한을 갱신하고 다른 터미널로 전환할 때 記憶データ·CPU 문맥을 보관한다. シェル·편집기에서 입력을 기다리는 시간에는 이 제한이 적용되지 않는다.

이미지는 확인된 공식 Pi 起動 묶음에서 `start4.elf`, `fixup4.dat`, Pi4 DTB와 disable-bt overlay를 가져온다. Linux kernel/initramfs/rootfs는 넣지 않는다. 펌웨어·MicroPython·端末 書体値 라이선스와 書体値 原点値 해시도 동봉한다. ファイル 生成 스크립트는 물리 디스크에 기록하지 않는다.

예비 microSD에 イメージ構築 履歴記録記録 도구로 `.img`를 기록하거나 FAT32 起動 파티션 최상위에 ZIP 내용을 푼다. イメージ構築 기록은 선택한 카드의 기존 내용을 지우므로 대상을 확인한다. Pi4 既定値 EEPROM SD 부팅을 전제로 한다. UART는 **3.3V TTL, 115200 8N1**, GPIO14/TXD(8번)→어댑터 RX, GPIO15/RXD(10번)→TX, GND(6번) 연결이다. GPIO에 5V 신호를 연결하지 않는다.

**物理機器 Pi4 부팅은 미검증이다.** QEMU `-kernel`은 SD의 VideoCore 펌웨어를 실행하지 않고 커널을 직접 적재한다. SD ファイル 구성·中核値 체크섬 검사와 물리 基板 起動 검증은 별개다. MMU 使用値 전에는 펌웨어의 캐시/MMU가 꺼져 있고 EL1 또는 EL2로 진입하는 통상 起動 조건을 전제로 한다. 三値 補助値 코어는 대기시키며 한 코어만 사용한다.

## C++와 日本語 API 使用値

SDK를 풀고 호스트에서 컴파일한다.

```sh
tar -xzf dist/jkoros-native-aarch64-sdk.tar.gz -C build
cd build/jkoros-native-sdk
python3 compile.py examples/ファイル例.cpp -o demo.elf
python3 compile.py examples/通信用例.cpp -o network.elf
```

진입점은 `extern "C" int 利用者プログラム開始処理(int)`이다. 利用者 C++는 FP/SIMD를 사용할 数 있다. 中核値 C/Java AOT는 일반 레지스터만 사용하므로 例外 プロセス値入口 중 利用者 FP 상태를 건드리지 않는다. 利用者 入口点値 시 FP 상태를 초기화하고 中核値 복귀에 필요한 상태를 보존한다.

```cpp
#include "ファイルABI.h"
extern "C" int 利用者プログラム開始処理(int) {
    int ファイル = ファイル開放("挨拶例.txt", 読取書込 | 作成条件未存在 | 切詰め内容, 0600);
    if (ファイル < 0) return 1;
    const char 内容物値[] = "안녕하세요";
    int 結果 = ファイルデータ書込(ファイル, 内容物値, sizeof(内容物値) - 1);
    ファイル閉鎖(ファイル);
    return 結果 == sizeof(内容物値) - 1 ? 0 : 2;
}
```

[ファイル 用例](利用者/ファイル例.cpp)와 [通信 用例](利用者/通信用例.cpp)先頭位置被演算子 実際データ 起動 試験 대상이다. `ファイルABI.h`의 이름은 커널용/사용자용 全体構築 같지만 **링크하는 라이브러리가 다르다**. 사용자용은 `svc #0`으로 호출하고 ファイル プロセス値入口 및 루프백 전달은 Java 커널에서 실행한다. `通信網ABI.h`의 ソケット値 함수는 現在項目 사용자용 라이브러리에 구현돼 있다.

새 프로그램은 中核値 재빌드 없이 `load FILE.elf`와 `run FILE.elf`로 실행한다. 호스트에서 次回項目 도구를 사용하면 **새 QEMU를 부팅해 업로드한 実際データ 바이트를 재확인한 後端値 게스트에서 命令実行**하고 종료한다. 이 도구의 새 VM에서 만든 RAM 자료는 종료할 때 사라진다.

```sh
cd /home/user/jkoros/platforms/rpi4-native
python3 道具/ファイル実行.py build/jkoros-native-sdk/demo.elf
python3 道具/ファイル実行.py 用例/Hello.java "ハングル文字列 引数"
python3 道具/ファイル実行.py 用例/hello.py
```

이 경로는 16KiB 이하의 `.elf`, `.java`, `.class`, `.py`를 지원한다. 큰 내장 Java/MicroPython ELF 자체는 中核値 묶음에 포함되어 이 ファイル 한도를 적용받지 않는다. **C++ 컴파일러는 ホスト SDK의 Clang++**이며 게스트 내부 GCC/Clang 컴파일러는 아직 없다. SDK만으로 일반 Linux 프로그램을 실행할 수는 없다. Linux ELF, 동적 ライブラリ, PT_TLS, PT_INTERP, PT_DYNAMIC, 命令実行·書込 겸용 세그먼트는 로더가 거부한다. 구체적인 呼出 番号·番地 切抜き·오류는 [利用者 ABI](利用者呼出しABI.md)를 참고한다.

RAM 파일은 재부팅 시 사라진다. `確定ファイル記憶装置`은 -1과 ENOSYS를 반환한다. 파일의 mode 인수를 저장하지 않으며 許可値·dup/fcntl은 없다. 디렉터리와 通信相手値/절대 경로는 같은 RAM 저장소에서 처리한다. UDP 전문은 最大値 512바이트, 소켓은 8개, 値受取 큐는 소켓당 4개다. 수신할 자료가 없거나 큐가 가득 차면 EAGAIN을 반환한다. 利用者 終了点プログラム 시 열린 ファイル 서술자와 소켓을 회수한다.

## Java와 Python의 정확한 切抜き

内蔵 `javac`는 버전 49 `.class`를 생성하며 JVM은 支援値 명령으로 구성된 버전 45–52 클래스를 실행한다. 静的値 関数·재귀·int/boolean/char/String·条件/反復回値·文字列 결합과 일부 ファイル 스트림을 지원한다. UTF-8 문자열과 文字 리터럴, ASCII 및 현대 ハングル文字列 음절/組合せ 字母値 식별자를 처리한다. Unicode 識別子値 전체 表·Unicode ソース木 이스케이프는 구현하지 않았다. 게스트 ソース木 컴파일러는 일반 オブジェクト値·例外·Thread 구문을 아직 컴파일하지 못한다. ホスト `javac --release 8`로 만든 支援値 부분집합 클래스는 内蔵 JVM 0.4의 オブジェクト値·例外·Thread·UDP와 日本語 API를 사용할 数 있다. Swing은 문서화한 内蔵 API 부분집합을 제공하며 JAR 로더는 제공하지만 전체 AWT/Swing·JDK 표준 라이브러리는 없다. 정확한 범위는 [内蔵 JVM 説明](Java実行環境環境.md)이 기준이다. 상세 言語 범위는 [공유 Java 道具 説明](../../文書/Java開発環境.md)을 참고하되, 그 문서의 x86 シェル/格納値/실행시간과 이 ARM64 판의 차이에 유의한다.

MicroPython은 공식 **1.24.1 ソース木**를 内蔵 AArch64 EL0/SVC 대상으로 빌드했다. Python 문법의 関数·クラス値·例外·리스트/辞書·Unicode·GC·가변 精度値 정수를 제공한다. 現在項目 구성은 整数値 빌드로 `float`, `complex`, `math`先頭位置被演算子 없으며 CPython 전체 표준 ライブラリ, pip, subprocess, threading, 일반 socket과 既定値 `open()` ファイル 객체는 제공하지 않는다. `python FILE.py` 및 `-c` 실행만 제공하며 REPL은 아직 없다. 각 실행의 オブジェクト値·모듈은 終了点プログラム 시 회수되고 RAM 파일만 次回項目 실행에 남는다.

`import jkoros`로 次回項目 시스템 연결을 쓴다. 全体構築 SVC를 통해 内蔵 Java 커널에 접근한다.

| 関数 | 動作 |
|---|---|
| `stdin(limit)` | 現在項目 표준 입력에서 最大値 limit바이트(0…16384)를 bytes로 結果読取; EOF는 빈 bytes, UART データ 없음은 OSError(11) |
| `read(name)` | 通信相手値/절대 RAM 경로의 ファイル 전체를 bytes로 結果読取 |
| `write(name, data)` | str/bytes 버퍼를 RAM 파일에 새로 格納値, 쓴 バイト値 数 復帰結果 |
| `remove(name)` | RAM ファイル 삭제 |
| `rect(x, y, w, h, color)` | 선택한 実際データ 画面 容量 안의 矩形 描画; 기존 보드의 RGB32 値 |
| `ticks_ms()` | 起動 後続側状況 ミリ秒, 32비트 周期値 |
| `udp_open(port)` | 127.0.0.1의 UDP ソケット値 開放/実行束梱包; 0은 자동 機器ポート |
| `udp_send(fd, port, data)` | 루프백 宛先値 포트에 str/bytes 버퍼 転送値 |
| `udp_recv(fd)` | `(bytes, 보낸포트)` 復帰結果; 비어 있으면 `OSError(11)` |
| `udp_close(fd)` | ソケット値 閉鎖 |

```python
import jkoros
first = jkoros.udp_open(9401)
second = jkoros.udp_open(9402)
jkoros.udp_send(first, 9402, b"hello")
print(jkoros.udp_recv(second))  # (b'hello', 9401)
jkoros.udp_close(first)
jkoros.udp_close(second)
```

移植 コード値: [python/](Python橋渡し/), [利用者 Java 接続](利用者/Java橋渡し.c). 공식 [MicroPython 移植 案内](https://docs.micropython.org/en/latest/develop/porting.html)를 참고했다. ソース木 URL·ハッシュファイル·라이선스는 [vendor 案内](vendor/README.md)에 기록했다.

`example/java`는 `実行可能処理作業`, `動作受信先`, `動作通知`, `ボタン`, `イベント待ち行列`,
