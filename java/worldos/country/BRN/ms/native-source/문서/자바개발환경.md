# jkoros 안에서 Java bina_sumber·laksanakan_perintah

이 문서의 permulaan_mesin·cangkerang·stor_VALUE 명령은 **x86 versi_VALUE** 기준이다. 공유 Java 컴파일러/JVM은 [Asli ARM64 Pi4 versi_VALUE](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 nama_fail_SMS, `edit`의 단독 `.` stor_VALUE, 16개 RAM Fail, 약 2초 laksanakan_perintah 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 sebenar_data JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. hos bina_sumber 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 Asli 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java aplikasi_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 laksanakan_perintah

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. laksanakan_perintah 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 permulaan_mesin 절차는 [VirtualBox laksanakan_perintah README_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 Fail 전체를 새 내용으로 작성한다. 기존 내용의 baris edit_VALUE 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 bait_VALUE 수 tayang_VALUE.
- `cat FILE`: Fail Kandungan_VALUE tayang_VALUE. 텍스트 소스에 사용한다.
- `rm FILE`: Memori_data Fail 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·TYPE_VALUE 검사 kegagalan_VALUE 시 기존 `.class`는 유지된다. 소스를 고친 BACK_VALUE 컴파일이 실패했다면 이전 laksanakan_perintah 파일이 남아 있으므로 bina_sumber 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 stor_VALUE 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 sumber_pepohon·Kelas_VALUE·data 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, Fail 이름은 ASCII 1~63자다. sumber_pepohon 이름은 `.class` 확장자 e_mel_rantau 때문에 최대 62자다. edit_VALUE 입력은 ASCII이고 한 baris 최대 128자다. baris 또는 Fail 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. kernel_VALUE/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 ruang_pengguna 예제 이름은 ASCII로 작성한다.

## 외부 Fail 적재

호스트에서 만든 소스나 Sokongan_VALUE klip 안의 `.class`를 permulaan_mesin 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 sebenar_data 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# hos JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 permulaan_mesin 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 Seterusnya_item 빌드에서는 Tambah_pemasukan 파일을 포함하지 않는다. Fail Kandungan_VALUE 변경과 pemasukan_Senarai 제거도 Seterusnya_item 빌드에 반영된다. 원본 hos 파일에는 쓰지 않는다. nilai_lalai `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 nilai_lalai 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 Kelas_VALUE Fail 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 Sokongan_VALUE klip 안에 있어야 한다.

## Sokongan_VALUE klip

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| Kelas_VALUE | 패키지 없는 단일 Kelas_VALUE, statik_VALUE fungsi_VALUE, 재귀, 인수/kembalikan_ukuran | 실행마다 단일 Kelas_VALUE 적재, public static main(String[]) |
| nilai_lalai VALUE | int, boolean, char, String, main의 String[] 인수 | integer·Rujukan 스택, String, int[], String[], 내부 StringBuilder |
| kenyataan_VALUE | 초기값 있는 setempat_Skop pengisytiharan_4f4f026b, tugasan_VALUE, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 integer·Rujukan 바이트코드와 syarat cabang |
| ungkapan_VALUE | 십진 integer, UTF-8 소스의 rentetan_VALUE/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, rentetan_VALUE 결합 | integer operasi_VALUE·bit_VALUE operasi_VALUE·TYPE_VALUE tukar_VALUE, 단락 평가, ARRAY_VALUE capai_pemasukan |
| Fail | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | sebenar_data kernel_VALUE 파일서술자와 Sambung, jana·buang_TOC·이어쓰기·EOF |
| 출력 | System.out.print/println: int/boolean/char/String, println() | 동일 |
| rentetan_VALUE/인수 | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), rentetan_VALUE 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 setempat_Skop pengisytiharan_4f4f026b, 오버로드, 임의 TYPE_VALUE tukar_VALUE, ARRAY_VALUE jana SUMBER, 8/16진 리터럴, Unicode sumber_pepohon 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 pemalar_VALUE 축소 변환을 구현하지 않는다. 외부 `.class`의 `int[]` jana/Baca/쓰기는 지원하므로 hos `javac --release 8`로 만든 ARRAY_VALUE 예제는 실행할 수 있다.

objek_VALUE medan_VALUE·일반 objek_VALUE jana·상속·인터페이스·여러 Kelas_VALUE Sambung, long/float/double, pengecualian Proses_VALUE_pemasukan, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java pengecualian 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 rentetan_VALUE stor_VALUE 공간은 laksanakan_perintah Keluar_aplikasi 시 ruang_pengguna rantau_VALUE 전체와 함께 회수한다. 지속 laksanakan_perintah 중 GC는 없다.

## laksanakan_perintah 한도와 RALAT

| sumber_VALUE | 한도 |
| --- | --- |
| sumber_pepohon/Kelas_VALUE Fail | 각각 16KiB |
| 컴파일러 | token_VALUE 2,047개, jana kod_VALUE 4KiB, pemalar_VALUE 풀 4KiB |
| fungsi_VALUE/인수 | 클래스당 32함수, 함수당 16인수 |
| JVM pemalar_VALUE | 511개 |
| JVM fungsi_VALUE kod_VALUE | 함수당 8KiB |
| JVM 호출/스택/setempat_Skop pemboleh_ubah_VALUE | 32프레임, 프레임당 스택 128칸·setempat_Skop 128칸 |
| JVM objek_VALUE stor_VALUE e_mel_rantau | 8,192개 32비트 칸, 헤더 pengisytiharan 약 32KiB |
| laksanakan_perintah | 최대 500,000 Perintah, 기존 커널의 약 3초 CPU laksanakan_perintah 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 Sokongan_VALUE 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM kamus 검증기를 구현한 것은 아니다. Fail/atribut_VALUE kepanjangan_VALUE, pemalar_VALUE Rujukan, Perintah·cabang 경계를 검사하고, laksanakan_perintah 중 스택 format_VALUE·setempat_Skop mengasal·ARRAY_VALUE subskrip_VALUE·objek_VALUE 참조를 검사한다. ruang_pengguna 코드의 페이지·포트 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, bina_sumber·JVM 오류는 `Exit: 1`, Perintah 인수 오류는 `Exit: 2`다. CPU nilai_masa 상한은 기존 `Exit: 124`이며, ruang_pengguna ELF 자체의 CPU/런타임 오류는 기존 Keluar_aplikasi 코드를 따른다. kegagalan_VALUE 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## pelaksanaan 위치와 ujian

- `os/ruang_pengguna/자바/자바컴파일러.java`: 게스트 어휘·구문·TYPE_VALUE 검사, pemalar_VALUE 풀 및 바이트코드 jana.
- `os/ruang_pengguna/자바/자바가상기계.java`: Kelas_VALUE 적재, 스택·프레임·objek_VALUE stor_VALUE, Perintah 해석과 제한된 표준 호출.
- `os/SUMBER/Memori_sistem_fail.java`: Memori_data sistem_fail, edit_VALUE, permulaan_mesin Fail 적재.
- `os/SUMBER/panggilan_sistem.java`, `compiler/Mula_pengguna_aplikasi.s`: Fail/문자 출력 API와 ruang_pengguna penuding 검사.
- `os/alat/자바파일묶기.py`: hos 입력 Fail sahkan·permulaan_mesin Kumpulan_VALUE jana.

```sh
make test-java
make test
```

`os/ujian/자바시험.py`는 ELF/ISO permulaan_mesin, 게스트 bina_sumber·laksanakan_perintah, ruang_pengguna 입력, 재귀·반복문·integer 극값·rentetan_VALUE 결합·단락 평가, 재실행, sumber_pepohon RALAT 후 기존 Kelas_VALUE 보존, ARRAY_VALUE/수 해독 RALAT, 무한 lelaran_VALUE 제한, edit_VALUE 넘침과 Fail 부족을 검사한다. 게스트 jana 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 hos OpenJDK의 Kelas_VALUE, integer 배열과 한글 상수를 게스트에 적재하며, 손상된 Fail penanda_VALUE·버전·pemalar_VALUE 수·cabang·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 ujian VM만 생성하고 종료한다.

pelaksanaan 형식의 참고 data: Oracle [JVM Kelas_VALUE Fail 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM Perintah 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java Fail I_O

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 Kelas_VALUE 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 permulaan_mesin 이미지에 넣은 BACK_VALUE `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. nilai_lalai 출력 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. pengecualian objek_VALUE·try/catch·try-with-resources는 지원하지 않으며 Fail 오류를 진단하고 프로그램을 종료한다. ARRAY_VALUE I_O, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 Fail 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 cangkerang `sync`가 필요하다. 예제의 Fail 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/ujian/자바파일시험.py`는 sebenar_data 게스트 bina_sumber 결과를 OpenJDK `-Xverify:all`로 다시 실행해 Fail 바이트와 출력을 대조한다. 범위와 stor_VALUE 매체 사용법은 [posix-kor README_eb81d7d9](../posix-kor/README_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
