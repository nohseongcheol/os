# 內建 ARM64 內核值: FTP, C, JAR와 AOT 執行命令

대상은 **Linux를 적재하지 않는 Raspberry Pi 4용 Java AOT 內核值**이다. CPU·設備 경계는 C/어셈블리, 檔案 체계와 셸은 Java이며, 이번 TCP/IP 스택은 C로 작성된 lwIP 2.2.0을 이식했다. 게스트 TinyCC와 `jaot`도 EL0에서 실행한다. 호스트에 컴파일을 요청하거나 宿主 JVM으로 대신 실행하지 않는다.

## 먼저 알아둘 支持值 邊界位置值

| 申請 | 이번 實現 | 남은 裁剪 |
|---|---|---|
| JAR를 執行命令 파일처럼 執行命令 | `java -jar 檔案.jar`, `./檔案.jar 實參`; Main-Class와 存儲值/DEFLATE ZIP, CRC 檢查項 | 전체 Java SE, 임의의 모든 JAR 호환성 |
| 게스트 AOT | `jaot 檔案.class -o 檔案.elf`, `jaot 檔案.jar -o 檔案.elf`; 實際資料 ARM64 기계어 生成 | 物件值·異常·Thread·Swing·Socket의 AOT 轉換值, 여러 애플리케이션 類別值 連接 |
| C 編譯原始碼 | 게스트 `cc`/`tcc`, TinyCC C 전처리기·ARM64 생성기·링커; 中文 식별자와 posix-kor | 전체 libc, 일반 Linux 執行命令 檔案, 게스트 C++ 編譯器 |
| 업로드한 ELF 執行命令 | ELF64/AArch64 헤더 檢查項, 확장자 없는 `./檔案`; 內建 ABI 및 명시적인 제한형 Linux ABI | 일반 Linux 바이너리 호환, 동적 링커, 공유 庫 |
| 外部值 TCP/UDP | 게스트 lwIP IPv4 操作數棧, POSIX 소켓과 JVM의 數字值 IPv4 地址 | GENET/Wi-Fi 드라이버, DHCP·DNS·TLS, 物理硬件 板 네트워크 測試 |
| FTP | 게스트 서비스, 패시브 傳送值, UTF-8 名稱, STOR/RETR/SIZE/LIST/NLST/MLSD/DELE | TLS·사용자별 權限值·하위 디렉터리·영속 存儲值 |
| 韓文文本 Java | 기존 `中文.內建` 클래스와 外部值 地址 UDP 오버로드 | 전체 JDK의 일대일 中文 映射值 API |

JVM은 類別值 버전 45…52의 문서화한 부분집합이다. `java`는 字節碼 실행기이고, `jaot`首位操作數 별도의 네이티브 執行命令 파일을 만든다. **JAR 存檔值 해제나 JVM을 함께 묶는 것을 AOT라고 표시하지 않는다.** 지원하지 않는 字節碼/API는 `jaot`首位操作數 진단하고 출력을 만들지 않는다. 기존 輸出 ELF도 編譯原始碼 失敗值 때 보존한다.

Android의 Dalvik/ART는 일반 JVM 類別值/JAR가 아닌 **DEX**를 실행한다. ART의 AOT에는 GC, 類別值 로딩, JNI 등 執行命令 기반도 필요하다. 따라서 ART처럼 기계어로 바꾸는 기능만으로 임의의 OpenJDK JAR 및 Swing이 자동 호환되지는 않는다. [Android 공식 런타임 說明](https://source.android.com/docs/core/runtime)

FTP는 루트 RAM 파일만 공개한다. 익명 로그인이며 비밀번호로 권한을 구분하지 않는다. 默認值 宿主 바인딩은 `127.0.0.1`이고, 控制值 포트는 2121, 데이터 포트는 50000…50007이다. `--ftp-port 2122`로 控制值 포트를 바꿀 數 있다. 동시에 한 FTP 세션을 제공하며 명령이 없는 세션은 60초 之後狀態 닫는다. TYPE A도 바이트를 변경하지 않으므로 프로그램은 바이너리 전송한다.

파일은 **64개, 각각 16 KiB**, 경로는 UTF-8 63바이트이다. 啓動 시 준비되는 `/example`도 이 한도를 공유한다. 초과/끊어진 STOR는 기존 파일에 반영하지 않는다. FTP 업로드는 RAM에만 저장되며 재부팅하면 사라진다. 이 限制值 때문에 일반적인 대형 JAR 배포판을 그대로 올릴 數 없다.

QEMU의 raspi4b에는 GENET Ethernet 장치가 없다. 따라서 `network_bridge.py`首位操作數 QEMU NAT의 Ethernet과 輔助值 UART의 SLIP를 변환한다. **TCP 連接 程序值條目·체크섬·재전송·FTP 명령과 檔案 저장은 게스트 안에서 수행한다.** 宿主 브리지는 FTP 서버가 아니다. [QEMU 공식 設備 支持值 條目列表](https://www.qemu.org/docs/master/system/arm/raspi.html)

이 경로는 QEMU에서 검증했다. 輔助值 UART의 實際資料 Pi 4 핀/클럭 설정과 내장 RJ45 GENET 드라이버는 實現·검증하지 않았으므로, SD 이미지에 커널이 포함되어 있다는 사실을 實際資料 보드의 LAN/FTP 動作 보장으로 해석하면 안 된다.

## 中文 Java를 게스트에서 컴파일하고 AOT 執行命令

게스트 `vi 顏色.java`로 下一項目 소스를 작성한다.

```java
public class 顏色 {
    public static void main(String[] 實參) throws Exception {
        int 總和值 = 0;
        int 數 = 1;
        while (數 <= 10) {
            總和值 = 總和值 + 數;
            數 = 數 + 1;
        }
        中文.內建.輸出.寫入編號(總和值);
        中文.內建.檔案.寫入("aot.txt", "韓文文本 AOT 檔案 😀");
        中文.內建.輸出.寫入行(中文.內建.檔案.讀取("aot.txt"));
    }
}
```

```text
javac 顏色.java
java 顏色
jaot 顏色.class -o 顏色.elf
run 顏色.elf
```

`jaot`은 클래스의 바이트코드를 C로 변환하고, **게스트 TinyCC**首位操作數 ARM64 명령어를 生成·연결한다. 執行命令 때 JVM 인터프리터를 호출하지 않는다. JAR의 Main-Class가 같은 支持值 범위이면 다음도 가능하다.

```text
jaot 顏色.jar -o 顏色.elf
run 顏色.elf
```

AOT 지원은 한 애플리케이션 클래스의 靜態值 方法值/字段值, int 계열, 整數 배열과 引用, 實參 陣列值, 條件·分支·迭代值, 字符串 리터럴, `System.out.print/println`의 int/String, 中文 輸出·檔案 讀取/쓰기로 제한된다. 類別值/方法值 수와 操作數棧 등에도 고정 상한이 있다. Java 異常 程序值條目, 物件值 生成, 가상 方法值 일반, switch/wide, long/float/double, invokedynamic, 字符串 결합용 StringBuilder, 일반 JDK·Socket·Thread·Swing은 이 AOT 백엔드에서 미지원이다. 내장 NUL/고립된 서로게이트 문자열도 거부한다. 잘못된 陣列值 存取條目/0으로 相割值列 등은 네이티브 런타임 오류로 종료하며 Java 異常 객체로 전달하지 않는다.

輸入值 클래스뿐 아니라 **생성된 ELF도 16 KiB 이하**여야 한다. 기계어 확장과 ELF 페이지 對齊值 때문에 짧은 클래스도 이 한도를 넘을 數 있으며, 이 경우 오류를 내고 기존 출력을 보존한다.

게스트 `javac`도 부분집합이다. 일반적인 物件值·Thread·Swing 소스는 호스트에서 `javac --release 8`로 컴파일하고, **기존 JVM의 支持值 裁剪 안에서** `java`/`java -jar`로 실행한다. 정확한 API는 [JVM 매뉴얼](Java運行時環境.md)과 [韓文文本 開發 매뉴얼](開發指南.md)을 참고한다.

JAR는 하나의 애플리케이션 類別值 경로다. 내부 名稱 `軟件包/程式.class`와 점으로 구분한 Main-Class를 지원한다. 내부 클래스는 파일로 풀어 VFS 슬롯을 소비하지 않는다. 내장 中文 클래스를 추가로 찾지만 當前項目 任務 폴더의 다른 클래스는 자동 혼합하지 않는다. ZIP64·加密資料 ZIP·manifest Class-Path·서명 검증은 지원하지 않는다. JAR 하나가 16 KiB 이하이어도 클래스당/적재 數/VM 堆值 제한은 그대로 적용된다.

## C에서 中文 POSIX 調用

게스트에서 `vi 問候例.c`로 작성하거나 FTP로 소스를 업로드한다.

```c
#include <檔案ABI.h>

int main(void) {
    const char 問候語[] = "內建 ARM64 C에서 韓文文本 POSIX 調用\n";
    int 文檔集 = 打開檔案("問候例.txt", 讀取寫入 | 創建條件缺失 | 截斷內容, 0600);
    if (文檔集 < 0) return 1;
    輸入輸出結果類型 已記錄個數 = 寫入檔案資料(文檔集, 問候語, sizeof(問候語) - 1);
    關閉檔案(文檔集);
    寫入檔案資料(1, 問候語, sizeof(問候語) - 1);
    return 已記錄個數 == sizeof(問候語) - 1 ? 0 : 2;
}
```

```text
cc 問候例.c -o 問候例.elf
run 問候例.elf
cat 問候例.txt
```

TinyCC의 표준 C 條目分 `main`을 사용한다. 기존 宿主 C/C++ SDK의 `開始用戶程式(int)` 진입점과 구분한다. 頭文件 檔案·運行 物件值·`libposix-kor-user.a`는 編譯器 내부의 讀取 전용 SDK에 들어 있다. C 전처리기/구조체/函數/재귀/指針/부동소수점 生成 등을 사용하되 **일반 libc/libstdc++를 제공한다는 뜻은 아니다**. 제공하지 않는 함수는 連接 오류가 난다. 編譯器 자체의 字元/數字值 轉換值 지원도 완전한 libc 대체품이 아니다.

`打開檔案` 등은 별도의 모의 호출이 아닌 기존 `pk_open` 등의 中文 매크로이며, ELF의 SVC를 통해 實際資料 Java 檔案 체계에 도달한다. 檔案/通訊端值 調用 목록은 [使用者 ABI](用戶呼叫ABI.md)에 있다. C/C++ 宿主 SDK 執行命令 파일도 FTP로 업로드 之後狀態 `run` 또는 `./檔案`로 실행하며 확장자는 所需條件值 없다. Linux ARM64 靜態值 ELF에는 별도의 제한된 호환 路徑 `run --linux 檔案`을 추가했다. [ELF·Linux ABI 매뉴얼](可執行文件ABI.md)에 정확한 格式值·시스템 調用·地址 제한을 정리했다.

## 中文 네트워크·任務·屏幕 API

| 類別值 | 調用 예 | 執行命令 路徑 |
|---|---|---|
| `輸出` | `寫入行("안녕")`, `寫入編號(42)` | JVM 및 제한형 AOT |
| `檔案` | `寫入("文檔集.txt", "內容值")`, `讀取("文檔集.txt")` | JVM 및 제한형 AOT |
| `通信` | `打開(0)`, `發送(端點, "10.0.2.2", 9000, "韓文文本")`, `接收(端點)` | JVM의 UDP |
| `連接狀態傳輸` | `連接("10.0.2.2", 9000)`, `偵聽端點(9000)`, `接收(服務器值)` | JVM의 Socket/ServerSocket |
| `任務` | `運行(Runnable)`, `等待(Thread)`, `掛起任務()` | JVM의 협력식 執行緒值 |
| `窗口`, `小組件` | 窗口·버튼·字元值·文本字段·事件 連接 | JVM의 Swing 부분집합 |

명명에서는 표준 영어 API를 보존하고 中文 調用 계층을 추가한다. `通信(通信)`, `連接(連結)`, `輸出(出力)`은 기존 단어의 뜻을 사용한다. `任務 執行緒值`은 한 執行命令 흐름을 가닥에 빗댄 描述符值 표현, `埠值`는 포트의 접점을 설명하는 표현이다. 새 描述符值 결합어를 고대에 이미 존재한 용어처럼 설명하지 않는다. 전체 JDK의 번역을 완료했다고 표시하지 않는다.

外部值 주소는 數字值 IPv4이며 QEMU 호스트는 `10.0.2.2`, 게스트는 `10.0.2.15`第三操作數. UDP 전문은 512바이트까지다. 소켓은 비차단 內建 ABI이며 JVM이 제한된 等待狀態值/재시도를 제공한다. TCP connect 대기는 最大值 1초, 使用者 程式 전체에는 기존 약 2초 CPU 기한이 적용된다. 일반적인 장기 執行命令 使用者 서버와 pthread는 아직 없다. FTP는 使用者 程式 기한과 별개인 內核值 서비스다.

게스트의 使用者 TCP/UDP 서버로 들어오는 연결은 NAT 포트를 추가한다. 예를 들어 `python3 工具集/執行命令.py --network --forward tcp:9300:9300 --forward udp:9301:9301`로 실행하면 호스트의 localhost 9300/TCP·9301/UDP를 게스트의 같은 포트로 전달한다. FTP의 默認值 控制值/데이터 포트와 겹치면 執行命令 전에 거부한다.

## 시험과 構建系統 재현

```sh
cd /home/user/jkoros/platforms/rpi4-native
make test-ftp
make test
make image
```

`build/verification/ftp/report.json`은 實際資料 FTP 傳送值, 韓文文本 檔案, 大小 초과 보존, 存檔值 JAR 執行命令, 게스트 C 編譯原始碼/ELF 재업로드, 外部值 Java TCP/UDP, 게스트 javac/AOT 실행을 기록한다. `serial.log`에서 게스트 명령과 결과를 확인할 數 있다. 보고서의 內核值 SHA-256과 分發值 이미지의 커널을 비교한다.

빌드는 기존 JDK/Clang/AArch64 binutils와 함께 `../rpi4/build/rootfs`의 ARM64 SDK 聲明 헤더와 libgcc 算術值 輔助值 함수를 사용한다(`make rpi-prepare`). **musl libc, Linux 內核值, 동적 로더를 게스트에 링크하지 않는다.** TinyCC/lwIP/uzlib 원본과 라이선스·버전 정보는 `vendor/`, 移植 코드는 `ccompiler/`, `network/`, `使用者/軟件包.c`에 있다.

전체 JDK/AOT JVM으로 확장하려면 타입 有效性校驗·物件值/異常/GC·동적 로딩·JNI, 영속 檔案 運行系統值·mmap/TLS/시그널·스레드 ABI, OpenJDK native 庫, GUI peer/폰트/입력기, GENET 및 物理硬件 設備 검증이 더 필요하다. 이 문서의 執行命令 시험은 그 전체 이식을 대신하지 않는다.
