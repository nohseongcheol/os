# निज 커널과 번역기의 नेपाली नाम

대상은 `platforms/rpi4-native`의 निज Java कर्णेल_मान, प्रयोगकर्ता JVM, C मेशिन जडान,
TCP/UDP·FTP, C 번역기 이식부, MicroPython 이식부, बनाउनुहोस्_प्रणाली·कार्यान्वयन_गर्नुहोस्_आदेश·시험 도구다.
`golang/worldos/나라/KOR/स्रोत`의 원칙처럼 기능을 먼저 구분하고 이름을 정한다.
x86 Java 커널과 공용 x86·ARM64 미리 번역기의 निज 선언도 명명 검사에 포함한다.
Linux 실행판의 होस्ट उपकरणहरू, OpenJDK 보조 उपकरणहरू 및 외부 배포 स्रोत_वृक्ष 전체를
한국어로 다시 작성했다는 뜻은 아니다.

## 명명 원칙과 말의 근거

- 명사는 자료의 역할을 나타낸다: `फाइल_ह्यान्डल`, `상대접속번호`, `동적기억공간`, `कुञ्जीपाटी`.
- 함수는 행위를 나타낸다: `पढनुहोस्`, `लेख्नुहोस्`, `खोल्नुहोस्`, `बन्दगर्नुहोस्`, `망주소묶기`, `चलाउनुहोस्_अनुप्रयोग`.
- TCP의 이어진 बाइट_मान 흐름과 UDP의 경계 있는 자료를 `जडान_d584d28a`와 `전문통로`로 구별한다.
- 짧은 영어 변수도 쓰임에 따라 `लम्बाइ_मान`, `लगत_राख्नुहोस्`, `विवरण_हेर्ने_सुविधा_अनुक्रमणिका`, `반환값`으로 풀어 쓴다.
  순번·임시 산술값처럼 여러 역할에 재사용되는 변수는 `순번`, `첫째값`, `둘째값`으로 구별한다.
- 이름이 같아도 외부 구조체의 필드와 निज 변수는 별도로 분석한다.

`च्यानल_प्रविष्टि(通路)`는 이동이나 교류가 이루어지는 길이라는 기존 의미를 통신 연결에
적용했다. `पोर्ट_मान(窓口)`의 주고받는 접점이라는 의미를 연결을 받는 곳에 적용했다.
이는 국립국어원 한국어기초사전의 [च्यानल_प्रविष्टि](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=49310),
[पोर्ट_मान](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=24898)의 뜻에 근거한다.

`전문(電文)`은 전보에 담는 글이라는 기존 통신 어휘에서 가져와, UDP 자료의
경계가 보존된다는 특징을 드러내는 데 쓴다. 근거는
[한국어기초사전 전문](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=74335)이다.
`प्रवाह_मान`, `धागो_मान`, `쌓임`은 우리말의 움직임·이어짐·쌓이는 모양을 빌린 표현이다.
`입력흐름`, `작업가닥`, `चाङ_भण्डारण` 같은 복합 이름은 이 프로젝트의 기능별 조어다.
이 शब्दकोष 근거를 특정 중세 문헌의 최초 출현이나 공인 전산 번역으로 확대하지 않는다.
공인 표준 अनुवाद_स्रोत·국어사 전문 감수를 마쳤다는 뜻도 아니다.

| 기능 | 채택한 नाम | 이유 |
|---|---|---|
| TCP Socket | जडान_d584d28a | 상대와 연결되어 अर्डर_मान 있는 바이트를 주고받음 |
| ServerSocket | 수신창구 | 새 연결이 들어오는 접점 |
| DatagramSocket | 전문통로 | 각 자료의 경계를 보존하는 통신 |
| InputStream / OutputStream | 입력흐름 / 출력흐름 | 들어오고 나가는 바이트의 अर्डर_मान |
| heap / stack | 동적기억공간 / चाङ_भण्डारण | निर्धारण_गर्नुहोस्_भण्डारण 방식과 쌓고 꺼내는 구조 |
| thread / keyboard | 작업가닥 / कुञ्जीपाटी | 이어지는 실행과 글쇠의 विन्यास_मान |
| exception / timeout | 예외 / 대기시간초과예외 | 정상 처리에서 벗어남과 그 구체적 이유 |

## 보존하는 एसडि नाम

`public`, `class`, `int`는 예약어다. `String`, `main`, 배열의 `length`는 예약어가 아니다.
현재 다섯 Java 예제는 `चलाउनुहोस्()`·`실행인수`·नेपाली 화면/धागो_मान API를 사용해
예약어·리터럴 외의 식별자를 한국어로 작성한다. 화면/가닥은 표준 객체를
감싸지 않고 निज JVM에 직접 구현했다. 자세한 계약은 [नेपाली Java API](../한국어자바/readme_फाइल_eb81d7d9.md)를 본다.

표준 javac는 स्ट्रिङ_मान 리터럴에 `java.lang.String`, स्ट्रिङ_मान 결합에 `StringBuilder`
같은 이름을 생성한다. 이들은 नेपाली 소스에서도 바이트코드에 남을 수 있다.
기존 표준 class를 실행하는 JVM의 대응 स्ट्रिङ_मान, 아직 표준 라이브러리를 쓰는
통신·फाइल 연결부까지 모두 한국어로 재구현한 것은 아니다. 이름만 일괄 치환하면
서술자·재정의·native 연결이 달라져 호환성이 깨진다.

C 표준 प्रकार्य_मान·पूर्ण_सङ्ख्या_प्रकार·POSIX ABI, CPU दर्ता_मान नाम, 어셈블리 आदेश, 링커 절 नाम,
TinyCC·lwIP·MicroPython이 요구하는 सेटिङ 매크로와 헤더 이름도 보존한다.
예: `main`, `memcpy`, `pk_bind`, `mpconfigport.h`, `lwipopts.h`, `stdint.h`.
निज C 함수의 स्रोत_वृक्ष 이름은 한국어이며, [기계연결이름.h](기계연결이름.h)가
기존 AOT·어셈블리·SDK에 공개한 मेशिन 심볼과 연결한다.
Python의 `__init__`, `setUp`, `handle`, 표준 मोड्युल_मान विशेषण_मान, 명령행 옵션과 JSON 키도
외부 계약이다. `build/`, 배포 바이너리 이름과 `/sdk`는 기존 कार्यान्वयन_गर्नुहोस्_आदेश 경로를 유지한다.
외부 원본은 `vendor/`에서 이용허락·해시와 함께 관리한다.

## 검사와 재실행

```sh
cd /home/user/jkoros/platforms/rpi4-native
python3 उपकरणहरू/명명검사.py
make बनाउनुहोस्_प्रणाली
make 시험
make test-examples test-ftp test-elf
python3 उपकरणहरू/कार्यान्वयन_गर्नुहोस्_आदेश.py --desktop --network
```

`उपकरणहरू/시언어이름분석.py`는 libclang 6으로 C 선언과 참조를 검사한다.
`उपकरणहरू/*이름반영.py`는 परिवर्तन_मान 전 स्रोत_वृक्ष·분석표를 필요로 하는 일회성 이행 도구다.
이미 변경된 소스에 다시 적용하여 대응표를 덮어쓰지 않는다.

## C 통신 구조체와 Python त्रुटि

C 통신에서 `갈래`는 ठेगाना 체계를 구분하고 `접속번호`는 port, `ठेगाना_मान`은
IPv4 주소의 32비트 값을 나타낸다. `전문전송규약`은 앞서 설명한 전문(電文)과
केस_मान(規約)을 결합해 UDP의 기능을 드러낸 프로젝트 이름이다.

| 표준 표현 | नेपाली 직접 구현 |
|---|---|
| AF_INET / SOCK_DGRAM / IPPROTO_UDP | enum의 क्लाउड_परिवार / 전문통신 / 전문전송규약 |
| struct pk_sockaddr_in | struct 인터넷통신주소 |
| sin_family / sin_port | ठेगाना_परिवार / 접속번호 |
| sin_addr.s_addr | इन्टरनेट_ठेगाना.ठेगाना_मान |
| OSError / त्रुटि.args[0] | प्रणाली_त्रुटि / त्रुटि.अनुक्रमणिका |

नेपाली 구조체는 `#define` 치환이나 फाँट_मान 별칭이 아닌 별개 자료형이다.
표준 구조체와 같은 16바이트 배치를 선언하며 कर्णेल_मान SVC에서 बाइट_मान 복사로
검사한다. `통신종단점만들기`·`자료전문보내기`와 फाइल 함수는 तथ्याङ्कित_मान 라이브러리에
वास्तविक_लगत नेपाली 이름의 प्रकार्य_मान 심볼을 갖는다. 기존 pk_* 심볼도 유지한다.
이전 코드에서 नेपाली 통신 함수에 pk_sockaddr*를 전달했다면 नेपाली 구조체로
옮기거나, 표준 구조체와 pk_* 함수의 짝을 유지한다.

Python의 `प्रणाली_त्रुटि`는 OSError의 नेपाली 하위 클래스이며 연결부에서
त्रुटि 번호를 보존하여 변환한다. 일반 Python 문법과 외부 패키지의 API는 유지한다.

## 직접 GUI 이름의 뜻과 검토 क्लिप

`실행할일`은 수행할 내용을, `कार्यान्वयन_गर्नुहोस्`는 그 수행을 나타낸다.
`동작받이`는 동작이 발생했다는 알림을 받는 역할, `동작알림`은 전달되는 사건이다.
`बटन`는 눌러 동작시키는 조작부, `लेबुल`는 readme_फाइल_eb81d7d9 글의 राख्नुहोस्_अनुक्रमणिका,
`पाठ_क्षेत्र`은 글을 적는 राख्नुहोस्_अनुक्रमणिका, `작업가닥`은 이어지는 कार्यान्वयन_गर्नुहोस्_आदेश 흐름을 뜻한다.
`कार्यान्वयन_गर्नुहोस्_आदेश(實行)`·`कार्य(動作)`의 기존 뜻과 `받다`·`알리다`·`धागो_मान`의 기능을
결합한 프로젝트 이름이다. 새 복합어가 역사 문헌에 그대로 있었다거나
특정 시대에 처음 쓰였다고 주장하지 않는다.

전체 저장소는 `python3 उपकरणहरू/स्रोत_समीक्षा.py`로 검토한다.
결과는 `build/verification/naming/source-review.json`이며 파일별 ह्यास_फाइल,
ASCII 파일명과 Python의 영어 선언 위치를 기록한다.
공용 ARM64·x86 번역기의 구현은 `compiler/자바도구/기계어미리번역.java`로 전환했다. `compiler/기계어미리번역.py`는 호환 진입점이다.
`compiler/arm64.py`는 이전 경로와 `ARM64(...).generate(...)` 호출을 이어 주는
호환 진입점이다. `compiler/classfile.py`, OpenJDK 보조 उपकरणहरू, Linux संस्करण_मान 도구와
기존 호환 진입점에는 영어 이름이 남아 있다. 따라서 전체 저장소가
예약어 외 100% 한국어라고 판정하지 않는다.
`उपकरणहरू/명명검사.py --시언어`는 सक्रिय ARM64 소스의 선언, C 의미 분석,
x86 Java 커널과 공용 번역기의 निज 선언, Java 예제 전체 परिचायक_मान,
ARM64 Python 예제와 직접 GUI/가닥에 표준 래퍼가 없는지를 별도로 검사한다.

## 현재 기능을 기준으로 보완한 नाम

번역은 글자를 음역하는 대신 자료의 역할과 함수의 행동을 구분한다.
동일한 영어 이름도 문맥이 다르면 नेपाली 이름을 달리 정한다.
फाइल 이름은 주된 기능을 나타내고, प्रकार्य_मान 이름은 행동을, 변수 이름은 담는 자료를 나타낸다.
예약어, 표준 API 및 외부 जडान 규약은 따로 기록한다.

| 이전 नाम | 적용한 नाम | 현재 기능 |
|---|---|---|
| `arm64.py`의 구현 | `compiler/자바도구/기계어미리번역.java` | Java 바이트코드를 독립 실행용 C 원문으로 미리 अनुवाद_स्रोत |
| `ARM64`, `generate` | `기계어번역기`, `सिर्जना_गर्नुहोस्` | अनुवाद_स्रोत 상태를 담는 객체와 C स्रोत सिर्जना_गर्नुहोस् 행동 |
| `prototype`, `method` | `함수원형`, `함수본문` | 함수의 ढाँचा_मान 선언과 वास्तविक_लगत आदेश स्रोत |
| `profile`, `heap_words` | `실행대상`, `동적기억낱말수` | कर्णेल_मान·प्रयोगकर्ता 구분과 निर्धारण_गर्नुहोस्_भण्डारण मेमोरी_मान 공간의 मेशिन 낱말 수 |
| `pc`, `op` | `आदेश_राख्नुहोस्`, `명령번호` | 바이트코드에서의 위치와 수행할 명령의 अनुक्रमणिका |
| `x`, `y`, `w`, `h` | `x_समन्वय`, `세로좌표`, `영역너비`, `영역높이` | दूर_मान 화면의 위치와 직사각형 आकार |
| `p`, `n`, `i`, `j` | `लगत_राख्नुहोस्`, `मान`, `순번`, `안쪽순번` | दूर_मान 화면 लगत·अङ्क_मान·दोहर्_याउनु_मान राख्नुहोस्_अनुक्रमणिका; 파일별 기능을 확인해 적용 |
| `aot_heap_info`, `__stack_top` | `미리번역기억조회`, `커널쌓임공간끝` | मेशिन जडान 규약을 유지하면서 निज 소스에서 사용하는 नाम |
| `앞캐리지` | `앞줄복귀` | 앞서 받은 문자가 줄복귀였는지 기억하여 중복 줄바꿈을 막음 |

[공용번역기이름대응.tsv](공용번역기이름대응.tsv)에 번역기 참조의 वास्तविक_लगत परिवर्तन_मान 기록을 남겼다.

C निज 선언 분석에서는 제외한다. वास्तविक_लगत कर्णेल_मान 빌드에서는 계속 컴파일한다.

### 말의 뿌리와 새로운 복합 नाम

`मेमोरी_मान(記憶)`과 `विवरण_हेर्ने_सुविधा_अनुक्रमणिका(索引)`은 기존 한자어를 쓴다.
기억은 자료를 간직하는 기능에, 색인은 अर्डर_मान 있는 항목을 찾아 지정하는 기능에 적용한다.
शब्दकोष 근거는 국립국어원 한국어기초사전의
[मेमोरी_मान](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=38812&nation=eng),
[विवरण_हेर्ने_सुविधा_अनुक्रमणिका](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=63787)이다.

`चाङ_भण्डारण`, `쌓기`, `हुलाक_प्रोटोकल_मान`는 자료를 포개고 마지막 자료부터 꺼내는 कार्यान्वयन_गर्नुहोस्_आदेश 구조를 드러낸다.
`쌓다`의 기존 뜻에 근거한 기능별 조어이며, 사전의
[쌓다](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=62095)를 참고한다.
`미리번역`은 कार्यान्वयन_गर्नुहोस्_आदेश 전에 번역한다는 기능을 직접 나타낸다.
`मेशिन_शब्द`은 처리기의 लगत 단위를 가리키며, 언어의 일반 낱말과 구별하도록 `मेशिन`를 붙였다.
`기계어미리번역`, `동적기억낱말수` 같은 복합 이름은 현재 기능에 맞게 만든 프로젝트 용어다.
이 복합어가 옛 문헌에 그대로 있었다거나 특정 시대에 처음 나타났다는 뜻은 아니다.
확인되지 않은 중세 형태나 최초 사용 연대는 어원 근거로 적지 않는다.

생성되는 C의 내부 लगत_प्रकार·विन्यास_मान·प्रकार्य_मान·स्थानीय_क्षेत्र 변수·शाखा 이름도 한국어로 바꾼다.
직접 한글 식별자를 읽지 못하는 예전 GCC를 위해 호환 API는 같은 नेपाली 이름을
표준 C 범용 문자 표기로 출력한다. वास्तविक_लगत ARM64 빌드는 Clang으로 읽을 수 있는 한글 원문을 사용한다.
स्ट्रिङ_मान, C 표준 प्रकार्य_मान, `java_entry` 같은 공개 जडान 이름은 바꾸지 않는다.

셸의 사용법·문법 त्रुटि·फाइल 및 मेमोरी_मान 공간 안내도 한국어로 보완했다.
`READY`, `PASS`, `HEX BEGIN`처럼 시험·फाइल ट्रान्सफर_मान 도구가 읽는 표식,
명령행 옵션과 기존 निर्देशन_मान, JVM वर्ग_मान नाम·फाइल ढाँचा_मान·मोबाइल_मान 이름은 호환 표기로 남는다.
x86 VGA 문자 화면은 한글을 표시하지 못하므로 नेपाली 문구는 UTF-8 직렬 단말에서 확인한다.
