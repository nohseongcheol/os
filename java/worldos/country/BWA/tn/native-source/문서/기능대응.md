## 기존 selwana_Boleng 기반 관리 Khenele_Boleng 전체를 부팅하기 위해 남은 Golaganya

다음 항목은 Java 문법만으로 실행할 수 없는 CPU/mobaele_Boleng 동작이므로 관리 계층과 별도로 AOT 런타임에 연결해야 한다.

- Multiboot tsenyo_ntlha_Boleng, CR0/CR2/CR3/CR4, IDT 적재, `iret`, x86 bokao_Boleng Store_Boleng
- tota_tshedimosetso PIC/PIT/PS2/ATA/PCI 포트 및 AMD PCnet DMA lupu_Boleng
- Java selwana_Boleng·setlhopha_Boleng_ed437109 Kgokagano_Boalo, 예외, e_e_emeng_Boleng go_baakanyetsa_tiriso, 가비지 수집기
- 컴파일된 Java 메서드를 freestanding i386 기계어로 바꾸는 AOT logato_Boleng
- FAT 디스크 구역을 tota_tshedimosetso ATA 장치와 연결하는 I_O 접착 boalo_Boleng

위 관리 계층은 engos 기능의 Java 관리 구현과 pinagare 검증판이다. 별도 `os/`에서는 제한형 AOT, Multiboot tsenyo_ntlha_Boleng, e_e_emeng_Boleng go_baakanyetsa_tiriso·Palotlalo setlhopha_Boleng_ed437109, VGA/직렬/PS2, 명령해석기, modirisi ELF/ring 3/시스템 호출, RTL8139/ARP/IPv4/UDP를 연결해 QEMU 부팅과 pinagare 루프백 패킷 왕복을 검증했다. 위 표의 selwana_Boleng 기반 관리 기능 전체나 VirtualBox 네트워크 실행까지 검증했다는 뜻은 아니다.
