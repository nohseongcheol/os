# 셸에서 실행하는 ઉપયોગકર્તા 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 રીડમી_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 અમલ_કરો_આદેશ

હોસ્ટ ટર્મિનલ 1:

```sh
cd /home/user/jkoros
python3 os/ઉપકરણો/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 외부 연결을 받도록 방화벽이나 હાર્ડવેર_પૉર્ટ 전달을 변경하지 않는다. Ctrl+C로 종료한다.

હોસ્ટ ટર્મિનલ 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 વાસ્તવિક_ડેટા CPU અનુમતિ_મૂલ્ય `ring 3`, દલીલો આઉટપુટ.
- `netcheck`: પૉર્ટ_મૂલ્ય 중복, 잘못된 હેન્ડલ_મૂલ્ય/સૂચક/લંબાઈ_મૂલ્ય, 비차단 받기와 સમય_મૂલ્ય 초과 ચકાસવું.
- `udp`: IPv4 સરનામું·ગંતવ્ય_મૂલ્ય પૉર્ટ_મૂલ્ય·한 શબ્દ_મૂલ્ય 메시지를 받아 UDP로 보내고 같은 응답을 ચકાસવું. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: હોસ્ટ `10.0.2.2`의 지정 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 લૂપ_મૂલ્ય 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 현재 주소는 게스트 `10.0.2.15/24`, ગેટવે_મૂલ્ય `10.0.2.2`로 고정돼 있다. QEMU ઉપયોગકર્તા 네트워크의 હોસ્ટ ઍક્સેસ_પ્રવેશ 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 એપ્લિકેશન_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java એપ્લિકેશન_f5044b9b 추가

`예제/내프로그램.java`를 આગલું_આઇટમ 형식으로 만든다. 진입점은 દલીલો 없는 `static int` 또는 `static void` 함수다. 인수는 ઉપયોગકર્તા API로 조회한다.

```java
public final class 내프로그램 {
    public static int ચલાવો_2() {
        ઉપયોગકર્તા.લખો("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/ઉપયોગકર્તા/એપ્લિકેશન_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := ઉપયોગકર્તા/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.ચલાવો_2
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `ઉપયોગકર્તા/선언/ઉપયોગકર્તા.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 અમલ_કરો_આદેશ 중인 VM에는 બિલ્ડ_સિસ્ટમ 결과가 자동 반영되지 않는다. એપ્લિકેશન_f5044b9b 이름은 현재 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java વર્ગ_મૂલ્ય·ફંક્શંસ_મૂલ્ય·변수에는 한국어를 쓴다. 최대 32개 એપ્લિકેશન_f5044b9b, 한 અમલ_કરો_આદેશ 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.ચલાવો_2 \
    -o os/build/apps/hello.elf os/ઉપયોગકર્તા/선언/ઉપયોગકર્તા.java os/ઉપયોગકર્તા/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 હોસ્ટ 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 સપોર્ટ_મૂલ્ય ક્લિપ 안에서 실행한다. `.jar`와 일반 Linux અમલ_કરો_આદેશ 파일은 지원하지 않는다.

## ઉપયોગકર્તા 네트워크 API

선언은 `선언/ઉપયોગકર્તા.java`에 있다. `મોકલો_ડેટા`/`자료받기`의 `int[]` આઇટમ_તત્વ 한 개는 બાઇટ_મૂલ્ય 하나(0~255)를 나타낸다. 한 데이터그램의 최대 ડેટા 길이는 1,024바이트다.

```java
int હેન્ડલ_મૂલ્ય = ઉપયોગકર્તા.બનાવો_નેટવર્ક(0); // 0: 임시 સ્થાનિક_અવકાશ UDP પૉર્ટ_મૂલ્ય 자동 ચયન_મૂલ્ય
int[] ડેટા = new int[32];
ડેટા[0] = 'H'; ડેટા[1] = 'i';
int 보낸길이 = ઉપયોગકર્તા.મોકલો_ડેટા(હેન્ડલ_મૂલ્ય, 0x0a000202, 9000, ડેટા, 2);
int 받은길이 = ઉપયોગકર્તા.자료받기(હેન્ડલ_મૂલ્ય, ડેટા, 1500);
ઉપયોગકર્તા.બંધ_કરો_નેટવર્ક(હેન્ડલ_મૂલ્ય);
```

વાસ્તવિક_ડેટા 프로그램에서는 ખોલો·મોકલો·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 પ્રતીક્ષા_મૂલ્ય 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 추가 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | હેન્ડલ_મૂલ્ય·પ્રક્રિયા_મૂલ્ય_પ્રવેશ લંબાઈ_મૂલ્ય·성공 등 해당 함수의 પરિમાણ |
| -5 | ડિવાઇસ_મૂલ્ય મોકલો_મૂલ્ય નિષ્ફળતા_મૂલ્ય |
| -9 | 잘못되었거나 닫힌 통신 હેન્ડલ_મૂલ્ય |
| -11 | 비차단 받기에서 도착한 ડેટા 없음 |
| -14 | ઉપયોગકર્તા સૂચક/અરે_મૂલ્ય ક્લિપ ભૂલ |
| -19 | સપોર્ટ_મૂલ્ય NIC 없음 |
| -22 | પૉર્ટ_મૂલ્ય/પ્રતીક્ષા_મૂલ્ય સમય_મૂલ્ય/દલીલો મૂલ્ય ભૂલ |
| -24 | 열린 નેટવર્ક_પૉર્ટ 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | ડેટા 또는 수신 અરે_મૂલ્ય માપ 문제 |
| -98 | સ્થાનિક_અવકાશ પૉર્ટ_મૂલ્ય અનુક્રમણિકા 중복 |
| -101 | 지원하지 않는 ગંતવ્ય_મૂલ્ય સરનામું |
| -110 | ARP·ડિવાઇસ_મૂલ્ય·수신 સમય_મૂલ્ય 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 એન્કોડિંગ_મૂલ્ય 있는 Java `int`의 બિટ_મૂલ્ય 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## અમલ_કરો_આદેશ 경계와 시스템 호출

```text
શેલ run → JKAP에서 ELF માન્ય_કરો·적재 → ring 3 ઉપયોગકર્તા એપ્લિકેશન_f5044b9b
                                 ↓ int 0x80
                      સૂચક 검사 → Java કર્નેલ_મૂલ્ય API → RTL8139/UDP
                                 ↓ પ્રસ્થાન_એપ્લિકેશન·예외·સમય_મૂલ્ય 초과
                                શેલ 복귀
```

시스템 호출 레지스터는 `EAX=અનુક્રમણિકા`, `EBX,ECX,EDX,ESI,EDI=દલીલો`, `EAX=પરિમાણ`다. Java 호출 스택 ABI는 컴파일러가 ઉપયોગકર્તા 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| અનુક્રમણિકા | 호출 |
| --- | --- |
| 0 | પ્રસ્થાન_એપ્લિકેશન(સ્થિતિ_મૂલ્ય_e10195a1 코드) — ચલાવો_2/ભૂલ 런타임에서 사용 |
| 1 | સ્ટ્રિંગ_મૂલ્ય લખો |
| 2 / 3 | દલીલો 개수 / દલીલો સ્ટ્રિંગ_મૂલ્ય સરનામું |
| 10 | UDP ખોલો |
| 11 | UDP મોકલો(હેન્ડલ_મૂલ્ય, IP, ગંતવ્ય_મૂલ્ય પૉર્ટ_મૂલ્ય, અરે_મૂલ્ય સરનામું, લંબાઈ_મૂલ્ય) |
| 12 | UDP 받기(હેન્ડલ_મૂલ્ય, અરે_મૂલ્ય સરનામું, 제한 밀리초) |
| 13 | UDP બંધ_કરો |
| 14 | સ્થાનિક_અવકાશ IP સરનામું |
| 15 / 16 | 마지막 પીઅર_મૂલ્ય IP / UDP પૉર્ટ_મૂલ્ય |
| 20 | RAM ફાઈલ વાંચો(નામ int[] સરનામું, આઉટપુટ int[] સરનામું) |
| 21 | RAM ફાઈલ લખો(નામ int[] સરનામું, 입력 int[] સરનામું, બાઇટ_મૂલ્ય લંબાઈ_મૂલ્ય) |
| 22 | UTF-16 코드 એકમ_મૂલ્ય 문자 આઉટપુટ(0~65535) |

ફાઈલ API는 `ઉપયોગકર્તા.파일읽기(int[] નામ, int[] ડેટા)`와 `ઉપયોગકર્તા.લખો_ફાઇલ(int[] નામ, int[] ડેટા, int લંબાઈ_મૂલ્ય)`다. 이름은 ASCII 코드 અરે_મૂલ્ય(최대 64칸, 0 પ્રસ્થાન_એપ્લિકેશન 또는 અરે_મૂલ્ય 끝), ડેટા આઇટમ_તત્વ 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 ફાઈલ 없음 `-2`, સૂચક ભૂલ `-14`, નામ/લંબાઈ_મૂલ્ય ભૂલ `-22`, ફાઈલ સ્લૉટ_મૂલ્ય 부족 `-28`, માપ 초과 `-90`을 반환한다. 쓰기는 માન્ય_કરો 후 ફાઈલ 전체를 대체한다. `ઉપયોગકર્તા.લખો_વર્ણ_મૂલ્ય(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 ઉપયોગકર્તા 모드에서 CS의 하위 비트를 직접 읽으므로 વાસ્તવિક_ડેટા અમલ_કરો_આદેશ 권한을 확인한다. કર્નેલ_મૂલ્ય હાર્ડવેર_પૉર્ટ 접근용 `ડિવાઇસ_મૂલ્ય` native 함수는 ઉપયોગકર્તા લક્ષ્ય 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 અમલ_કરો_આદેશ, 파이프, 프로세스 간 통신은 없다. અમલ_કરો_આદેશ 파일은 커널의 વાંચો 전용 JKAP 묶음에서 적재한다. ડેટા 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- ઉપયોગકર્તા 가상 સરનામું `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. અમલ_કરો_આદેશ 영상은 앞 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. કર્નેલ_મૂલ્ય identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB ઉપયોગકર્તા 영역을 비우고 ફાઈલ 구역을 복사해 BSS·અરે_મૂલ્ય 영역을 초기화한다. ઉપયોગકર્તા GC는 없지만 પ્રસ્થાન_એપ્લિકેશન 후 આગલું_આઇટમ અમલ_કરો_આદેશ 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 ક્વોટ/이스케이프 파싱은 없다.
- ઉપયોગકર્તા 페이지의 코드/ડેટા 분리 વાંચો 전용 સુયોજના, NX, 스택 guard, ASLR은 아직 없다. 커널과 ઉપયોગકર્તા મેમરી_ડેટા·હાર્ડવેર_પૉર્ટ અનુમતિ_મૂલ્ય 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 અમલ_કરો_આદેશ 상한을 두며 સમય_મૂલ્ય 초과는 `Exit: 124`다. ઉપયોગકર્તા CPU 예외는 `128 + 예외 અનુક્રમણિકા`(페이지 ભૂલ 142, 특권 위반 141), Java અરે_મૂલ્ય/계산 오류는 101~105다. કર્નેલ_મૂલ્ય 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, સ્થિર_મૂલ્ય IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP ચેકસમ 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- ઉપયોગકર્તા અમલ_કરો_આદેશ·네트워크·રક્ષણ_કરો_મૂલ્ય 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 અમલ_કરો_આદેશ·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## માન્ય_કરો 근거

`make test`는 컴파일러 14개 시험, Java 패킷 શરત 2,201개 검사, 기존 શેલ ELF/ISO 부팅 시험, ઉપયોગકર્તા ELF/વાસ્તવિક_ડેટા UDP/રક્ષણ_કરો_મૂલ્ય 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 લંબાઈ_મૂલ્ય·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 આદેશ·무한 પુનરાવર્તન_મૂલ્ય 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
