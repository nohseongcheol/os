# JCanOS 구조

아래는 ઑબ્જેક્ટ_મૂલ્ય 기반 관리 કર્નેલ_મૂલ્ય 전체의 લક્ષ્ય_ઑબ્જેક્ટ 구조다. 현재 વાસ્તવિક_ડેટા 부팅 가능한 제한형 구현은 `compiler/`와 `os/`에 있으며 [네이티브 ઑપરેટિંગ_સિસ્ટમ રીડમી_eb81d7d9](../os/રીડમી_eb81d7d9.md)에 구현 범위를 명시한다. 아래의 GC·સંદર્ભ_મૂલ્ય સ્વિચ_મોડ·ફાઇલ_સિસ્ટમ 등이 새 ISO에 모두 포함돼 있지는 않다.

```text
GRUB 또는 UEFI
  ↓
x86 최소 부트·트랩 થર_મૂલ્ય
  ↓
Java AOT 실행기와 ઑબ્જેક્ટ_મૂલ્ય·અરે_મૂલ્ય·GC 런타임
  ↓
હાર્ડવેર_મૂલ્ય 경계
  ↓
Java 관리 કર્નેલ_મૂલ્ય
  ├─ 기억공간/쪽관리/COW
  ├─ પ્રક્રિયા_મૂલ્ય/배정/wait
  ├─ ફાઇલ_સિસ્ટમ/ELF/POSIX
  └─ 입력/સંગ્રહ_ડિવાઇસ/નેટવર્ક_સ્ટેક
```

OpenJDK 자체는 이미 운영체제가 제공하는 ફાઈલ, 스레드, 가상 기억공간을 전제로 한다. 따라서 કર્નેલ_મૂલ્ય 부팅에는 OpenJDK를 그대로 넣지 않고 제한된 Java 바이트코드 AOT와 작은 런타임을 사용한다.

네이티브 계층에는 `in/out`, `hlt`, CR0/CR2/CR3/CR4, `iret`, સંદર્ભ_મૂલ્ય 저장처럼 Java로 표현할 수 없는 CPU 동작만 남긴다. 정책과 자료구조는 Java에 둔다.
