# TinyCC 소스와 재연결 자료

`dist/jkoros-native-compiler-source.tar.gz`에는 TinyCC 원본, 이식 코드,
내장 SDK 자료, TinyCC 외의 연결 객체가 들어 있다. TinyCC 변경판을 다시
연결할 때는 준비된 ARM64 SDK의 선언 헤더와 libgcc가 필요하다.
버전/원본 정보는 `vendor/tinycc/SOURCE-JKOROS.txt`, `vendor/README.md`를 참고한다.

압축을 푼 `jkoros-native` 디렉터리에서 다음처럼 실행한다. `JKOROS_SDK`는
원래 프로젝트에서 `make rpi-prepare`로 준비한 경로다.

```sh
JKOROS_SDK=/home/user/jkoros/platforms/rpi4/build/rootfs
clang --target=aarch64-none-elf -mcpu=cortex-a72 \
  -ffreestanding -fno-builtin -fno-stack-protector -fno-pic \
  -fno-unwind-tables -fno-asynchronous-unwind-tables -O2 \
  -ffunction-sections -fdata-sections \
  -I 시언어번역기 -I vendor/tinycc -I 사용자 -I relink \
  -isystem "$JKOROS_SDK/usr/include" \
  -c 시언어번역기/번역기.c -o relink/compiler.o
aarch64-linux-gnu-ld --gc-sections -T atuqtuq/kasurvik_ilinganinga.ld \
  -z max-page-size=4096 -o cc.elf \
  relink/user/start.o relink/user/runtime.o \
  relink/compiler.o relink/실행지원.o relink/시작.o relink/미리번역.o relink/되돌림.o \
  relink/user/jar.o relink/user/tinflate.o relink/user/crc32.o relink/user/adler32.o \
  "$JKOROS_SDK/usr/lib/gcc/aarch64-alpine-linux-musl/15.2.0/libgcc.a"
```

이식 코드까지 변경한다면 원래 프로젝트의 `도구/시언어번역기빌드.py`가
각 객체와 `resources.h`를 다시 만드는 기준이다. 가장 간단한 전체 재빌드는
원래 프로젝트의 `vendor/tinycc`를 수정하고 `platforms/rpi4-native`에서
`make image`를 실행하는 것이다. 만들어진 `cc.elf`는 RAM 파일 한도보다 커서
FTP 배포용 사용자 파일이 아니라 커널에 포함하는 기본 프로그램이다.
`도구/sanali_atuqtuq_SPACEBAR.py`가 이 ELF를 커널에 포함한다.

이 묶음은 전체 운영체제 소스 저장소를 대체하지 않는다. 커널·컴파일러·이미지
전체 빌드는 원래 프로젝트를 사용한다. TinyCC의 LGPL 라이선스와 libgcc의
GPL 및 GCC Runtime Library Exception 문서는 `vendor/`에 함께 제공한다.
