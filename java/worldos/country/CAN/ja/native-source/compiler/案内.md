# Java 네이티브 コンパイラ

OpenJDK 内蔵 소스를 빌드하는 **`--target openjdk-build`**와 内蔵 中核値 ABI 検査項目 도구를 추가했다.
이는 공식 javac/C/C++ 도구를 연결하는 별도 경로다. [システム構築 방법·実際データ 妥当性検査·中核値 移植 切抜き](OpenJDKソース構築とカーネル移植.md)를 참고한다.

x86 직접 변환과 ARM64 C 生成 후단은 全体構築 [事前用時間コンパイラ.java](Java道具/事前用時間コンパイラ.java)로 구현한다. `sh 事前用時間.sh`로 직접 실행하며, [事前用時間コンパイラ.py](事前用時間コンパイラ.py)와 `コンパイラ.py`는 前回項目 命令·API 및 OpenJDK 도구를 위한 호환 진입점이다. 内蔵 Pi4 후단은 freestanding C를 거쳐 AArch64로 만든다. [arm64.py](arm64.py)는 前回項目 경로와 Python 호출을 위한 호환 진입점이다. 関数·変数値·生成 C 이름의 뜻과 예외는 [日本語 命名 案内](../platforms/rpi4-native/命名/案内.md)를 참고한다. [ARM64 システム構築·支援値 切抜き](../platforms/rpi4-native/案内.md)에 命令実行 조건이 있다. 전체 OpenJDK나 일반 クラス値 실행기는 아니다.

命令実行 시 JVM이 必要値 없는 x86 32비트 ELF를 만든다. JDK 11 이상으로 실행하는 Java 内蔵 AOT 후단이며, Java 전체를 새로 구현한 컴파일러는 아니다. Java 문법·アクセス入口 制御値·型値 검사는 JDK의 `javac`에 맡기고, Java 8 クラス値 파일을 읽어 각 바이트코드를 x86 명령으로 직접 변환한다. C 코드로 우회하거나 バイトコード 해석기를 커널에 넣지 않는다.

```text
Java ソース → javac의 문법·型値 検査項目 → 一時値 .class
          → 内蔵 x86 변환기 → GNU as/ld → 네이티브 ELF32
```

## 준비와 命令実行

システム構築 ホスト: Linux, Python 3.6 이상, JDK 11 이상(`javac --release 8`), GNU binutils(`as`, `ld`), Make. 現在項目 환경의 OpenJDK 11, Python 3.6, binutils 2.30으로 검증했다. 外部値 Python 패키지와 네트워크 다운로드는 사용하지 않는다.

```sh
cd /home/user/jkoros/compiler
make
./build/計算結果
echo $?                  # 0이면 用例 試験 成功値

python3 コンパイラ.py --target linux --entry 計算結果.起動処理 \
    -o build/計算結果 用例/計算結果.java

make test
```

`linux` 대상은 Linux의 32비트 命令実行 호환 기능이 필요하다. `int 0x80`을 차단하는 샌드박스에서는 `Bad system call`이 발생할 数 있다. 判定通常 Linux ホスト 또는 해당 실행을 허용한 試験 환경에서 실행한다. 시험의 비정상 종료를 통과로 처리하지 않는다.

진입점은 `static int 起動処理()` 또는 `static void 起動処理()`처럼 인수가 없어야 한다. `--entry 패키지.クラス値.関数`로 선택한다. `int` 반환값은 Linux 프로세스 終了点プログラム 코드가 되며 셸에는 하위 8비트가 보인다. 일반 `main(String[] args)` 命令実行 환경이나 표준 入力出力 라이브러리는 제공하지 않는다.

`--target kernel`은 起動 코드와 연결할 재배치 ELF 오브젝트를 생성한다.

```sh
cd /home/user/jkoros
python3 compiler/コンパイラ.py --target kernel --entry 中核.起動処理 \
    --export kernel_dispatch=システム呼出.プロセス値入口 \
    -o os/build/java.o os/ソース/*.java
```

`--target user`는 jkoros 셸에서 실행할 독립 ELF를 생성한다. `利用者` 클래스의 제한된 native API는 `int 0x80` 시스템 호출로 연결하며 `装置` 클래스의 機器値 직접 접근은 거부한다. 利用者 ELF는 Linux 命令実行 ファイル ABI와 다르므로 호스트에서 실행하지 않는다. 生成·入口レジスタ 방법은 [利用者 命令実行 案内](../os/利用者/案内.md)에 있다. `--export 외부기호=クラス値.関数`는 오버로드되지 않은 静的値 함수를 内蔵 被演算子スタック ABI로 노출한다. 커널의 시스템 呼出 진입점에 사용한다.

Java 파일은 필요한 클래스들을 한꺼번에 전달한다. 出力 옆의 `.s`는 생성된 어셈블리, `.json`은 ソース SHA-256 및 네이티브 記号↔Java 関数 대응표다. 日本語 함수명은 원문과 대응표에 보존하고 ELF 내부에는 충돌 방지용 機械 기호를 쓴다. ソースコンパイル·値組立て·接続 중 실패하면 기존 結果 파일을 덮어쓰지 않는다.

## 支援値 切抜き

- `int`, `boolean`, `byte`, `short`, `char`의 32비트 計算結果 및 型値 値変換.
- 静的値 필드와 静的値 関数, 매개변수·返却済み値, 재귀, 클래스별 지연 초기화와 初期化 周期値.
- 조건문, 반복문, 단락 평가, 삼항식, 整数値 `switch`, 넓은 局所有効範囲 変数値 인덱스.
- 加算結果結果·減算結果結果·곱셈·나눗셈·剰余値·ビット値 연산과 移動値. Java의 오버플로 및 `MIN_VALUE / -1` 동작을 유지한다.
- `int[]` 生成·初期値 0·長さ·読取·書込·参照 비교. 256KiB 고정 配列値 領域値, 널/添え字値/容量/番地領域 検査項目.
- 文字列 리터럴과 `String` 参照, `length()` 및 `charAt()`. 문자열은 UTF-16 コード値 단위로 저장하고 같은 리터럴은 공유한다. NUL 및 대리쌍도 시험한다.
- 日本語 クラス値·関数·変数値·ファイル 名前.

`new Object`, 인스턴스 フィールド値/関数, 상속/인터페이스, `long/float/double` 命令実行 操作値, `int[]` 이외 配列値, 文字列 동적 結合処理値一覧, Java 표준 ライブラリ, 例外 プロセス値入口, 스레드·同期化·GC는 미지원이다. 실행에 필요한 判定未対応 바이트코드나 外部値 호출을 발견하면 실패한다. 사용되지 않는 既定値 생성자는 命令実行 코드로 만들지 않는다. Java 8 문법이어도 모든 프로그램을 컴파일할 数 있다는 뜻은 아니다.

例外 オブジェクト値 대신 런타임 エラー 번호로 중단한다. Linux와 jkoros 利用者 대상에서는 `100 + 番号`로 종료하고 中核値 대상에서는 `JKOROS PANIC 番号`를 출력하고 정지한다. 利用者 프로그램만 종료한 경우 셸은 継続処理工程 실행된다.

| 番号 | 원인 |
| --- | --- |
| 1 | 0으로 除算結果 |
| 2 | 널 参照 |
| 3 | 配列値/文字列 添え字値 切抜き 초과 |
| 4 | 負数値 配列値 容量 |
| 5 | 配列値 領域値 부족 |

配列値 영역은 증가식 할당이며 회수하지 않는다. 재귀 스택의 境界位置値 검사도 아직 없으므로 무제한 재귀를 안전하게 처리하는 런타임은 아니다. 특권 中核値 및 신뢰할 数 있는 작은 프로그램용 初期状況 구현이다.

## native 경계와 ABI

中核値 대상에서는 `os/ソース/装置.java`, 利用者 대상에서는 `os/利用者/宣言/利用者.java`의 정확한 メソッド名前本文·서술만 허용한다. 임의의 `native` 함수와 Linux/利用者 대상의 機器値 접근은 거부한다. Java 인수를 왼쪽부터 32비트 한 칸씩 스택에 놓으며, 반환값은 EAX, EBP/ESP 이외 레지스터는 호출자가 보존한다고 가정하지 않는다. C의 cdecl/JNI ABI가 아니므로 C 함수와 바로 연결하면 안 된다.

Java ソース 또는 `.class` 입력을 받는다. 전체 JVM バイトコード 검증기는 제공하지 않는다. 어노테이션 처리는 비활성화하고 비어 있는 クラス値 経路/ソース 경로에서 명시한 소스만 컴파일한다.

## 검증과 実装 근거

`試験/test_compiler.py`의 14개 시험에는 네이티브 ELF와 OpenJDK의 操作値 結果 대조, クラス値 初期化, 整数値 극값, 文字列/配列値, 재귀·switch·wide, 런타임 오류와 判定未対応 기능 値却下, 失敗値 시 出力 보존, 利用者 ELF/許可値 境界位置値 및 値出力 검증이 포함된다. 이것은 Java 전체 적합성 시험은 아니다.

命令 의미와 クラス値 ファイル 형식은 Oracle의 [JVM 命令 仕様](https://docs.oracle.com/javase/specs/jvms/se11/html/jvms-6.html), [クラス値 ファイル 仕様](https://docs.oracle.com/javase/specs/jvms/se11/html/jvms-4.html)를 참고했다.
