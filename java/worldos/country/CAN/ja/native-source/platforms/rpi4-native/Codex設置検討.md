# 内蔵 ARM64 커널의 Codex 値導入 가능성 검토

검토일: 2026-10-05. 소스와 공식 문서를 대조한 설계 검토이며, 게스트에 Codex를 설치하거나
로그인·모델 호출을 실행한 결과는 아니다. 内蔵 ARM64 커널과 `../rpi4` Linux 실행판은 구분한다.

現在項目 内蔵 커널에는 공식 Codex CLI를 그대로 値導入·실행할 数 없다.
기술적으로 필요한 命令実行 환경을 추가하거나 Codex를 이식하는 경로는 있으나,
다운로드 命令 하나를 추가하는 작업으로 해결되지 않는다. JDK/JRE 기능 확장만으로도 해결되지 않는다.

## 확인한 근거

| 入口値 | 現在項目 소스에서 확인한 状況値 | 직접 실행을 위한 作業 |
|---|---|---|
| 命令実行 ファイル | `機械/利用者.c`: AArch64 ET_EXEC만, PT_INTERP/PT_DYNAMIC/PT_TLS 値却下, 업로드 命令実行 버퍼 16384바이트 | 対象値 바이너리에 맞는 ELF 적재·재배치·命令実行 初期化, 記憶データ/ファイル 上限値 拡張子値 |
| Linux ABI | `機械/Linux互換性.inc`: read/write/openat/brk 등 제한된 번호만 プロセス値入口, 나머지는 ENOSYS | libc/런타임에 필요한 시스템 호출을 추가하거나 内蔵 ABI용 런타임 移植 |
| 프로세스·스레드 | 일반 fork/clone/execve, pthread/futex, 시그널, mmap, poll/epoll 계열이 미완성 | 비동기 I/O·스레드·子値 命令 命令実行·終了点プログラム/取消処理操作 기능 |
| ファイル | `ソース/記憶ファイル群.java`: RAM ファイル 64개, 파일당 16 KiB, 비영속 | 큰 命令実行 ファイル·프로젝트·設定値·세션을 위한 영속 VFS, ファイル 許可値·経路·디렉터리 拡張子値 |
| 네트워크 | lwIP TCP/UDP는 있으나 `通信網/lwipopts.h`의 LWIP_DNS=0, 일반 HTTPS 클라이언트 未存在メソッド | DNS, TLS 인증서 妥当性検査·신뢰 保管庫根·정확한 時刻印値, HTTPS/스트리밍 |
| 端末·道具 | 内蔵 셸과 GUI 터미널은 있지만 표준 PTY·일반 프로세스 作業 制御値 未存在メソッド | 対話式 CLI용 端末 기능, シェル/ファイル 검색/システム構築 道具 接続 |
| 命令実行 許可値 | EL0 보호는 있으나 Codex의 Linux 샌드박스와 같은 정책 집행 環境 未存在メソッド | ファイル·네트워크·命令 許可値 정책과 승인 기능; 内蔵 커널에 맞는 격리 実装 |

여기서 ELF의 PT_TLS는 스레드별 格納値 공간이다. HTTPS의 TLS 合言葉値 통신과 서로 다른 기능이다.
ELF ファイル 형식을 읽을 数 있다는 사실만으로 Linux 命令実行 환경을 제공하는 것은 아니다.
SSH/VNC를 위한 合言葉値 라이브러리를 넣은 상태도 HTTPS 実装 완료를 의미하지 않는다.

호스트의 `/home/user/.local/bin/codex`도 확인했다. 이것은 x86-64 ELF ET_DYN이며 약 209 MiB다.
해당 파일을 ARM64 게스트로 복사하여 실행할 数 없다. 이 크기를 ARM64 配布値 파일의 크기로
해석하지 않는다. 공식 ARM64 빌드의 実際データ 容量·의존성은 설치할 버전으로 入口追記 검사해야 한다.

## 가능한 実装 経路

1. **内蔵 커널에 공식 CLI 직접 移植**
   영속 格納値/VFS와 利用者 記憶データ, 프로세스·스레드·I/O, libc/런타임, DNS/HTTPS,
   端末·許可値 체계를 갖춘다. 後続側値 対象値 버전의 의존성을 조사하여 크로스 システム構築·이식한다.
   Linux 커널을 반드시 탑재할 필요는 없지만, 공식 Linux 바이너리를 그대로 쓸 경우
   그 바이너리가 사용하는 Linux ABI까지 호환해야 한다. 큰 稼働システム 開発 과제다.

2. **外部値 ホスト Codex와 内蔵 中核値 接続 — 先頭位置項目 구현으로 권장**
   Linux PC에서 공식 CLI 또는 app-server를 실행하고 jkoros에는 전용 利用者 命令/화면을 만든다.
   호스트의 인증된 연결과 게스트 ファイル 読取·値改変·업로드·命令 命令実行 어댑터가 필요하다.
   기존 SSH/TCP 경로를 활용할 数 있으나, ファイル 동기화나 Codex 전용 어댑터는 現在項目 구현되어 있지 않다.
   호스트에서 수행한 빌드와 게스트에서 수행한 命令実行 결과를 명확히 구분한다.
   이 구성은 内蔵 커널을 유지하지만, 공식 CLI 자체는 外部値 호스트에서 실행된다.

3. **内蔵 API 클라이언트 제작**
   内蔵 ABI의 C 또는 지원되는 Java 부분집합으로 対話式セッション UI와 ファイル/命令 道具 呼出 루프를 만든다.
   外部値 중계기를 쓰지 않는다면 DNS/妥当性検査 가능한 TLS/HTTPS와 인증 データ 저장을 먼저 구현해야 한다.
   이는 OpenAI API를 이용하는 별도 에이전트이며 공식 Codex CLI 전체의 이식으로 표시하지 않는다.

4. **별도 ARM64 Linux 실행판에서 値導入**
   `../rpi4`는 Linux와 musl 기반이므로 일반 Linux 値導入 경로를 검토할 数 있다.
   사용할 Codex 버전의 ARM64·musl 호환성, 依存項目, 커널의 샌드박스 지원을 実際データ 검증해야 한다.
   이번 검토에서 値導入 성공을 확인하지 않았다. 이 결과를 内蔵 Java 커널의 지원으로 표시하지 않는다.

## 단계별 判定完了 計画根

- 직접 移植: `--version` 起動処理 → 인증/HTTPS → ファイル 読取·値改変 → 子値 命令 命令実行 →
  対話式 入力値/스트리밍 → 許可値 上限値·取消処理操作 → 재부팅 後続側状況 設定値/세션 보존을 각각 実際データ 게스트에서 확인한다.
- ホスト 接続: 게스트에서 要求 入力値 → ホスト Codex プロセス値入口 → 게스트 ファイル 値変更 検証 →
  게스트 javac/cc 命令実行 → 結果 표시를 처음부터 끝까지 검증한다.
- COSL 상업 조건을 유지하려면 새로 도입하는 런타임/通信 라이브러리의 라이선스와
  Codex 配布値 버전의 제3자 고지를 검토한다. 外部値 구성요소를 일괄 COSL로 재라이선스하지 않는다.
