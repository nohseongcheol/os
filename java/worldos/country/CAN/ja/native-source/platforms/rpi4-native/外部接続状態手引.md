# 内蔵 ARM64 Java 커널의 外部値 接続状態

대상은 `jkoros/platforms/rpi4-native`이다. Linux를 실행하지 않는다. SSH와 VNC의 TCP 接続·인증·命令 プロセス値入口·画面 전송은 게스트 커널에서 수행한다. QEMU는 SLIP 통신로와 NAT만 제공한다. 기존 `--desktop`의 QEMU VNC 중계와 별개의 구현이다.

| 기능 | 現在項目 実装 | 妥当性検査 切抜き |
|---|---|---|
| 結線済み値 LAN | Pi4 GENET v5, BCM54213 계열 PHY, ARP, IPv4 TCP/UDP/ICMP, DHCP | ARM64 システム構築 및 모의 MMIO/MDIO 試験. **物理機器 基板 미검증** |
| SSH | TCP 22, libassh 1.1 (LGPL-2.1-or-later), 장치별 ECDSA キー値, 合言葉値 인증, 対話式 콘솔·命令 命令実行 | 実際データ OpenSSH 클라이언트로 QEMU 게스트에 接続状態 |
| VNC | TCP 5900, RFB 3.8, 合言葉値 인증, 実際データ 프레임버퍼·値変更 타일, 키보드·마우스·두벌식 入力値 | 実際データ RFB 전문을 주고받는 클라이언트로 QEMU 게스트 試験 |
| RDP | 미구현 | Remmina에서 **VNC**를 선택한다 |

SSH는 現在項目 中核値 シェル 콘솔을 공유하며 별도 利用者·독립 프로세스·POSIX PTY를 만들지 않는다. 한 번에 SSH 한 接続, VNC 한 연결을 받는다. 로컬 셸이 命令/vi/프로그램을 命令実行 중이면 새 SSH シェル 요청은 거절한다. 콘솔을 조작하는 사람은 한 명으로 운영한다. SFTP/SCP, SSH 機器ポート 前方値, 공개키 利用者 인증은 아직 지원하지 않는다. VNC 画面 자료는 암호화되지 않으므로 신뢰하는 LAN 또는 VPN 안에서 사용한다.

## 現在項目 PC에서 命令実行

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
python3 道具/遠隔設定値.py show
python3 道具/命令実行.py --remote --resolution 1920x1080
```

システム構築 때 `build/remote/access.json`과 `host-key.der`를 初期項目 한 번 생성하고 次回項目 빌드에서도 보존한다. 共通値 既定値 암호는 없다. `show`는 이 PC에 저장된 SSH·VNC 암호를 표시한다. 利用者 이름은 `user`第三被演算子. 비밀 파일은 소유자만 읽고 쓸 数 있도록 생성한다. 서로 다른 장치용 빌드는 각자의 `build/remote`를 사용해야 한다. 이미지를 그대로 복제하면 キー値·암호도 복제된다. 合言葉値 파일을 수정했다면 `make build` 後続側状況 새 커널로 재부팅해야 적용된다.

## 利用者 이름과 合言葉値 設定値

設定値 작업은 **jkoros 게스트 안이 아니라 システム構築 PC의 Linux 端末**에서 수행한다.

| 入口値 | 現在項目 設定値 방법과 제약 |
|---|---|
| SSH 利用者 | `user` 한 개로 고정. `root`第二被演算子 임의 이름으로 로그인할 数 未存在メソッド |
| SSH 合言葉値 | `access.json`의 `ssh_password`. 最小値 長さ 上限値 未存在メソッド. 서버의 UTF-8 256바이트 상한은 値維持 |
| VNC 利用者 | 未存在メソッド. Remmina의 利用者 이름은 비워 둠 |
| VNC 合言葉値 | `access.json`의 `vnc_password`. ASCII 문자열이며 長さ 上限値 未存在メソッド. 표준 인증에서는 前面値 8바이트만 사용하고 짧으면 0으로 値塗潰し |
| 계정 관리 | 게스트 `useradd`, `passwd`, `/etc/passwd`, `/etc/ssh/sshd_config` 基盤 관리 미구현 |
| 値変更 적용 | 設定値 ファイル 格納値 → システム構築 → 새 中核値/이미지로 재부팅 |

기존 설정을 확인하려면 次回項目 명령을 실행한다. 암호가 화면에 표시되므로 出力 결과를 공개 로그나 저장소에 올리지 않는다.

```sh
cd /home/user/jkoros/platforms/rpi4-native
python3 道具/遠隔設定値.py show
```

設定値 파일의 구조는 다음과 같다. 下端値 암호는 書式値 설명용이며 実際データ 암호로 사용하지 않는다.

```json
{
  "user": "user",
  "ssh_password": "1234",
  "vnc_password": "1234"
}
```

SSH의 16자 最小値 길이와 VNC의 厳密に値 8자 조건을 제거했다. 1자·4자 암호와 빈 文字列 `""`도
설정할 数 있다. VNC의 8자 초과 부분은 인증에 반영되지 않는다. 예를 들어 `abcdefghX`와
`abcdefghY`는 같은 VNC 인증 키가 된다. 이는 [RFB 표준의 合言葉値 プロセス値入口](https://www.rfc-editor.org/rfc/rfc6143.html#section-7.2.2)에 따른다.
VNC ASCII 조건과 SSH 서버의 256바이트 상한, 고정 利用者 이름은 별도 제약으로 유지한다.

システム構築 PC의 편집기로 두 암호를 수정하고 검사한다.

```sh
vi build/remote/access.json
chmod 600 build/remote/access.json
python3 道具/遠隔設定値.py prepare
```

`prepare`는 파일이 없을 때 キー値·암호를 생성하고, 이미 있는 경우 기존 값을 검사하여 빌드용 헤더를 준비한다.
기존 암호를 자동으로 새 암호로 바꾸거나 命令実行 중인 게스트 설정을 갱신하지 않는다.
`show` 역시 이 PC의 파일을 읽으므로, 命令実行 중인 옛 커널에 내장된 암호와 다를 数 있다.

QEMU에 적용하려면 기존 게스트를 判定通常 종료한 次回項目 再試行処理値 システム構築·실행한다.
게스트의 RAM 파일은 종료하면 사라지므로 필요한 자료는 먼저 옮긴다.

```text
# jkoros 게스트에서
poweroff
```

```sh
# システム構築 PC에서
make build
python3 道具/命令実行.py --remote --resolution 1920x1080
```

Pi4 SD 이미지에 적용할 때에는 `make cosl-dist RESOLUTION=1920x1080`으로 새 配布値 이미지를 만들고,
使用値 중인 SD 起動 영역에도 새 커널을 적용한 後端値 부팅한다. PC에서 設定値 파일만 바꾸면 SD의 커널은 바뀌지 않는다.

利用者 이름을 바꾸는 設定値 기능은 아직 없다. JSON의 `user`만 바꾸면 生成 도구가 거부하며,
서버의 `遠隔値/保安シェル.c`도 `user`를 직접 검사한다. 名前 변경을 지원하려면 生成 도구와 서버의
인증 처리를 함께 수정해야 한다. 이는 서로 다른 許可値·홈 디렉터리를 가진 다중 利用者 기능과는 별도다.
암호만 변경할 때 `host-key.der`를 지울 필요는 없다. ホスト 키는 SSH 서버의 신원을 나타낸다.

## SSH와 Remmina 接続状態

다른 터미널에서:

```sh
ssh -p 2222 user@127.0.0.1
# 命令 一値 命令実行
ssh -p 2222 user@127.0.0.1 'ipconfig'
```

Remmina 새 연결에서 프로토콜 **VNC**, サーバー値 `127.0.0.1:5903`, 암호는 `vnc_password` 값을 사용한다. SSH 암호와 VNC 암호는 서로 다르다. VNC는 최초 인증 後続側状況 GUI 터미널을 연다. `F9`, `Shift+Space`, 한/零被演算子 키로 영어·한글을 전환한다. `Ctrl+Shift+T`는 새 端末, `F6`는 窓 切替方式, `F12`는 窓 닫기다. 窓 窓表題 끌기와 隅値 左側面 버튼 끌기를 지원한다. 遠隔値 PC 입력기를 통해 전달한 Unicode 글쇠도 UTF-8로 입력된다. 게스트 VNC의 클립보드 전송은 아직 적용하지 않는다.

SSH에서는 遠隔値 PC의 입력기 또는 UTF-8 붙여넣기를 사용한다. 現在項目 콘솔의 ハングル文字列 두벌식 전환은 VNC キー描線 처리에 적용된다. SSH 연결만 종료하려면 `Ctrl+D`를 사용한다. `poweroff`는 게스트 稼働システム 전체를 종료한다.

`--remote`는 `--network`와 `--forward tcp:2222:22 --forward tcp:5903:5900`의 단축 옵션이다. `--desktop` 없이도 遠隔値 화면을 제공한다. 포트를 바꾸려면 직접 前方値 규칙을 지정한다:

```sh
python3 道具/命令実行.py --network --forward tcp:2223:22 --forward tcp:5904:5900
```

이 예에서는 SSH에 `-p 2223`, Remmina 서버에 `127.0.0.1:5904`를 사용한다.
게스트 안에서 대기하는 機器ポート 22·5900은 그대로다. 이 명령에서 `--remote`到達待ち 추가하면
既定値 2222·5903 규칙도 함께 추가되므로 機器ポート 교체 목적이라면 上端値 命令 그대로 사용한다.

| 接続状態 対象値 | SSH 클라이언트 番地 | Remmina VNC サーバー値 |
|---|---|---|
| 같은 PC의 QEMU (`--remote`) | `ssh -p 2222 user@127.0.0.1` | `127.0.0.1:5903` |
| 다른 PC에서 QEMU (`--network-host` 代入値) | `ssh -p 2222 user@실행_PC_IP` | `실행_PC_IP:5903` |
| 物理機器 Pi4의 주소가 判定通常 할당된 경우 | `ssh user@라즈베리파이_IP` | `라즈베리파이_IP:5900` |

기존 `--desktop`의 5902 포트는 QEMU 画面/入力値 중계다. 여기서 설명하는 게스트 `vncd`의
5900→5903 경로와 다르므로 `vncd stop`으로 `--desktop` 画面 서버가 중지되지는 않는다.

## 다른 PC에서 QEMU 게스트에 接続状態

```sh
python3 道具/命令実行.py --remote --network-host 0.0.0.0 --resolution 1920x1080
```

이 실행에 한해 호스트의 外部値 인터페이스로 機器ポート 전달을 연다. 기본값 `127.0.0.1`은 継続処理工程 이 PC에서만 접근할 数 있다. 다른 PC는 `ssh -p 2222 user@실행_PC의_LAN_IP`와 Remmina VNC `실행_PC의_LAN_IP:5903`으로 접속한다. ホスト 방화벽에서 TCP 2222·5903을 허용해야 하며, ホスト 자체가 가상 머신이면 상위 가상 머신의 브리지 또는 해당 機器ポート 전달도 필요하다. 테스트 도구는 ホスト 방화벽을 변경하지 않는다.

FTP는 기존 `ftpd start` 명령을 실행했을 때만 활성화된다. `--network-host 0.0.0.0`은 FTP 前方値 포트에도 적용된다. 現在項目 FTP는 익명 RAM ファイル 서비스이므로 필요한 동안에만 사용한다.

## 物理機器 Raspberry Pi 4

```sh
make image RESOLUTION=1920x1080
```

산출물은 `dist/jkoros-native-rpi4.img`와 `dist/jkoros-native-rpi4-boot.zip`이다. 이 작업은 PC의 물리 디스크를 열지 않는다. SD 카드 起動 방법은 기존 [案内](案内.md)를 따른다.

結線済み値 LAN을 공유기에 연결하고 부팅하면 펌웨어 基板 일련번호를 확인한 後端値 GENET을 초기화하고 DHCP 주소를 요청한다. 정상일 때 `ipconfig`에 `en0`, `LINK UP`, 実際データ LAN 주소가 나온다. QEMU에서는 `sl0`, `10.0.2.15`先頭位置被演算子 표시된다. 공유기의 DHCP 임대 목록에서도 Pi의 주소를 확인할 数 있다. 주소를 얻은 경우 다른 PC에서:

```sh
ssh user@라즈베리파이_IP
# Remmina VNC: 라즈베리파이_IP:5900
```

QEMU의 2222·5903은 ホスト 포트이며 실물에서는 사용하지 않는다. 物理機器 서비스는 22·5900이다. DHCP 없는 망에서는 UART 셸에서 망에 맞는 주소를 설정한다. 예:

```text
ipconfig set 192.168.1.50 255.255.255.0 192.168.1.1
ping -c 3 192.168.1.1
```

番地 値変更 전에 接続状態 중인 SSH/VNC/FTP와 일반 소켓을 닫는다. 番地 `0.0.0.0`에 묶인 대기용 SSH/VNC 창구는 유지할 数 있다. 番地·ファイル·게스트 プログラム 値導入 자료는 現在項目 RAM 상태이므로 재부팅 後続側状況 유지되지 않는다.

**物理機器 Pi4 接続 정보가 제공되지 않아 전원 투입·랜 케이블 송수신·外部値 PC 접속은 확인하지 못했다.** GENET 드라이버가 추가되었다는 사실과 실물에서 작동이 검증되었다는 사실은 구분한다. `LINK DOWN`, DHCP 미할당, RNG200 이상 등이 발생하면 UART 로그와 `ipconfig` 결과로 보드별 확인이 필요하다. Wi-Fi와 USB 키보드 드라이버는 이번 実装 범위에 없다.

## 서비스 명령과 試験

下端値 명령은 **부팅한 jkoros 端末**에서 실행한다. ホスト Linux의 `sshd`第二被演算子 `systemctl` 명령이 아니다.

```text
sshd status       # 保安シェル 状況値
sshd stop         # 保安シェル 停止
sshd start        # 保安シェル 起動処理
vncd status       # 遠隔表示処理 状況値
vncd stop
vncd start
保安シェル 状況値
保安シェル 停止
保安シェル 起動処理
遠隔表示処理 状況値
遠隔表示処理 停止
遠隔表示処理 起動処理
netstat
ipconfig
help
```

두 서비스는 起動 때 자동으로 시작한다. 合言葉値 난수 확보 失敗値 시 인증을 생략하지 않고 접속에 실패한다. 실물은 BCM2711 RNG200, QEMU는 실행기가 매번 OS 난수로 만든 새 씨앗을 제공한다. 원시 QEMU 명령으로 실행하면서 씨앗을 생략하면 SSH/VNC 인증을 사용할 数 없다. `道具/命令実行.py`를 사용한다.

- `RUNNING`: 서비스가 TCP 연결을 기다리는 状況値. 외부에서 接続状態 가능한지나 인증 성공을 보증하지 않는다.
- `STOPPED`: 値待合 창구가 닫힌 状況値. 初期化 오류가 있으면 오류도 표시할 数 있다.
- `sshd` 또는 `vncd`만 입력해도 상태를 확인한다. 명시적인 동작은 `start`, `stop`, `status`第三被演算子.
- `restart`는 구현하지 않았다. 알 数 없는 인수도 現在項目 状況値 조회로 처리되므로 `restart` 출력만 報告値 재시작됐다고 판단하면 안 된다.
- 재시작은 `stop` 次回項目 `start`第三被演算子. **現在項目 연결한 서비스 자체를 중지하면 연결이 끊긴다.**
  SSH 재시작은 UART/로컬 콘솔 또는 VNC에서, VNC 재시작은 UART/로컬 콘솔 또는 SSH에서 수행한다.
- 停止 상태는 영구 설정이 아니다. 次回項目 부팅에서는 두 서비스가 再試行処理値 자동 시작한다.
- 서비스 재시작만으로 수정한 `access.json`이 적용되지 않는다. 암호는 새 커널을 빌드하여 부팅해야 바뀐다.

接続状態 失敗値 시 먼저 `ipconfig`, `sshd status`, `vncd status`, `netstat`을 확인한다.
QEMU에는 `--remote` 또는 해당 `--forward`先頭位置被演算子 필요하며, 로컬 GUI만 제공하는 `--desktop`으로는
게스트 SSH/VNC의 既定値 前方値 포트가 자동 생성되지 않는다.
SSH는 `ssh -v -p 2222 user@127.0.0.1`로 接続状態 로그를 볼 数 있다.
合言葉値 오류는 設定値 파일과 実際データ 起動 커널이 일치하는지, 利用者 이름이 `user`인지 먼저 확인한다.
Remmina에서는 RDP가 아닌 VNC를 선택하고 `vnc_password`를 입력한다.
새 SSH 세션이 거절되면 기존 접속을 닫고 로컬 셸을 프롬프트 상태로 돌려놓는다.

```sh
make test-remote
make test-passwords
make test-genet
```

遠隔値 시험은 별도 QEMU를 띄우고 `127.0.0.5`의 一時値 포트만 사용한다. 결과는 `build/verification/native-remote/report.json`, SSH/直列値 履歴記録値 및 画面 캡처에 남는다. LAN·공인 인터넷·物理機器 보드를 시험한 결과가 아니다. GENET 시험은 MMIO/MDIO 모형으로 初期化, 値送信 ループ値 포화·周期値, 値受取 長さ 境界位置値, 링크 끊김, 返答 時間値 초과를 확인한다.

合言葉値 長さ 시험은 一時値 設定値·커널을 만들어 짧은 合言葉値·8자 초과 VNC 合言葉値·빈 암호로 SSH/VNC 인증을
검사한다. 개인 `access.json`은 수정하지 않으며 결과는 `build/verification/password-length/`에 저장한다.

遠隔値 서비스는 `遠隔値/`, 結線済み値 드라이버는 `通信網/結線済み通信網.c`에 있다. SSH는 libassh(LGPL-2.1-or-later), VNC 인증은 BearSSL(MIT)을 사용한다. GENET은 FreeBSD의 BSD 구현으로 교체했다. 버전·해시는 `vendor/remote-sources.json`, 配布値 조건과 再接続通信端点 방법은 [COSL 配布値 案内](COSL配布手引.md)를 참고한다.
