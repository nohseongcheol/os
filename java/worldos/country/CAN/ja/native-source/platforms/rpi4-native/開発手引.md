# 内蔵 커널에서 vi·여러 端末·ハングル文字列 프로그래밍 사용하기

日本語 通信·例外 사용법은 [日本語 Java API](日本語Java/案内.md), 関数·変数値·ファイル 이름의 변경과 어원 근거는 [命名 案内](命名/案内.md)를 참고한다.

대상은 `platforms/rpi4-native`의 内蔵 AArch64 Java 커널이다. vi와 Java/Python/C/C++ 프로그램은 EL0에서 실행한다. Linux 실행판과 별도이며 下端値 支援値 목록은 전체 OpenJDK·Vim·POSIX 구현을 뜻하지 않는다.

게스트 `cc`/`jaot`, JAR 직접 命令実行, 外部値 TCP/UDP와 FTP는 [새 命令実行 매뉴얼](ファイル転送論理積翻訳工程.md)을 참고한다.

## GUI와 여러 端末

```sh
cd /home/user/jkoros/platforms/rpi4-native
make desktop
```

Remmina에서 **VNC**, 番地 **127.0.0.1:5902**로 연결한다. 画面 上端値 **+ New terminal**, **Ctrl+Shift+T**로 터미널을 추가한다. 最大値 네 개다. 上限側側面 端末 버튼 또는 창을 클릭해 선택하고 **F6**으로 순환한다. 제목줄을 끌어서 옮기고 **右 上端値 X**를 클릭하면 닫힌다. 末尾項目 창을 닫아도 上限側側面 命令実行 버튼으로 再試行処理値 列値 数 있다. 기존 `terminal`, `exit`, F12도 사용할 数 있다.

창마다 現在項目 디렉터리, シェル 変数値, 命令 履歴記録記録, 入力値 중인 명령과 プログラム 命令実行 상태를 보관한다. ファイル 저장소는 공유한다. vi와 Swing의 이벤트 値待合 중에 다른 터미널로 전환하면 利用者 記憶データ·레지스터·ファイル/ソケット値 연결을 보존했다가 돌아올 때 재개한다. **現在項目 네 프로그램이 동시에 CPU에서 실행되는 선점형 스케줄러는 아니다.** 計算結果 중인 프로그램은 次回項目 入力値 値待合 또는 기존 命令実行 기한까지 전환이 지연될 数 있다.

X로 터미널을 닫으면 그 터미널의 命令実行 중인 프로그램도 종료하며 記述子入口·소켓을 회수한다. 저장하지 않은 編集値 내용은 사라진다. 종료한 슬롯은 새 창에서 재사용한다. 現在項目 모든 파일은 RAM에 있으며 VM 재시작 후에는 남지 않는다.

화면과 窓 판단은 게스트 커널이 처리한다. QEMU 命令実行 도구는 VNC 키와 마우스 좌표를 UART 패킷으로 전달한다. 実際データ Pi4 USB 입력기와 物理機器 부팅은 아직 검증하지 않았다. 일반 UART 셸은 `make run`, GUI 道具 종료는 ホスト 터미널의 Ctrl+C다.

## vi 使用値

```text
mkdir 作業
cd 作業
vi 挨拶例.py
```

`vi`는 새로 구현한 **vi 命令 부분집합** 편집기다. 내장 `build/user/vi.elf`를 보호된 利用者 영역에 적재한다. ファイル 크기는 UTF-8 バイト値 計画根 16 KiB, 경로는 63바이트까지다. 디스크에 설치한 Vim/Neovim 바이너리를 실행하는 것이 아니다.

| キー値/命令 | 動作 |
|---|---|
| `i`, `a`, `I`, `A` | 現在項目/次回項目 位置 또는 行 初期項目/끝에서 入力値 |
| `o`, `O` | 下端値/위에 새 줄을 만들고 入力値 |
| Esc | 일반 方式値 |
| `h j k l`, 방향키 | UTF-8 文字/行 移動値 |
| `0`, `$`, Home, End | 行 初期項目/終端 |
| `gg`, `G`, `:番号` | ファイル 初期項目/末尾項目 行/代入値 行 |
| PgUp, PgDn | 画面 単位値 移動値 |
| `x`, Delete | 現在項目 文字 삭제 |
| `dd`, `yy`, `p` | 行 삭제/値複写/貼付け本文 |
| `u` | 末尾項目 편집을 復帰橋渡し; 한 工程値 토글 |
| `/文字列`, `n` | 단순 文字列 검색/次回項目 判定等価; 정규식 未存在メソッド |
| `:w`, `:w 다른이름` | RAM ファイル 格納値/다른 경로로 格納値 |
| `:q` | 변경이 없을 때 終了点プログラム |
| `:q!` | 변경을 버리고 終了点プログラム |
| `:wq`, `ZZ` | 저장하고 終了点プログラム |

붙여 넣은 한글을 文字 경계에 맞춰 移動値·삭제한다. 일반 vi의 수량 접두사, マクロ値, 設定値 ファイル, 플러그인, 정규식, 여러 버퍼/분할 窓, 문법 강조 등은 아직 없다. `--desktop`에서는 F9·Shift+Space·한/零被演算子 키로 두벌식 조합을 전환한다. PC 입력기를 영어로 두고 窓 窓表題 `[KO]`에서 입력하며, `help ko`에 단축키를 표시한다. 완성된 Unicode 문자와 VNC의 명시적 붙여넣기도 전달한다.

vi와 Swing 프로그램은 **단독 命令**으로 실행한다. 파이프·리다이렉션·スクリプト値·`;`/`&&`/`||`로 연결한 실행에서 対話式 대기를 시작하면 거부한다. 入力値 대기는 약 2초 CPU 기한을 갱신하지만 入力値 値待合 없이 무한 반복하는 프로그램은 기존처럼 종료한다.

## ハングル文字列 Java

vi에서 다음을 `挨拶例.java`에 입력하고 Esc → `:wq`로 저장한다.

```java
public class 挨拶例 {
    static int 値一覧追加(int 先頭位置序数, int 第二序数) { return 先頭位置序数 + 第二序数; }
    public static void main(String[] 引数) {
        int 合計値 = 値一覧追加(20, 22);
        System.out.println("안녕하세요 · 合計値=" + 合計値);
    }
}
```

게스트 셸에서 실행한다.

```text
javac 挨拶例.java
java 挨拶例
```

ハングル文字列 ファイル名前本文·クラス名前·メソッド名前本文·변수명·문자열을 사용할 数 있다. **게스트 javac는 静的値 Java 부분집합**이다. オブジェクト値·리스너·Swing·소켓을 사용하는 소스는 現在項目 ホスト JDK에서 `javac --release 8 -encoding UTF-8`로 컴파일하고 内蔵 JVM에 class를 올린다. 内蔵 JVM에서 지원하는 バイトコード/API 범위는 [Java実行環境環境.md](Java実行環境環境.md)를 따른다.

```sh
# ホスト
mkdir -p build/my-java
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/my-java 試験/Java/Swing試験.java
python3 道具/送出転送ファイル群.py build/my-java/Swing試験.class
```

`upload.py`는 게스트 `load`에 붙여 넣을 16진수 명령을 생성한다. 出力 전체를 GUI 터미널에 보내면 업로드한다. 업로드 後続側状況 **별도로** `java Swing試験`을 실행한다. 종속 class가 있으면 각각 업로드한다. 패키지 class의 파일명은 `패키지.クラス値.class` 형식이다. 내장 日本語 라이브러리는 별도 업로드가 必要値 없다. 日本語 窓 API의 예제는 [ハングル窓試験.java](試験/Java/ハングル窓試験.java)이며 같은 방법으로 ソースコンパイル·업로드해 `java ハングル窓試験`으로 실행한다.

GUI가 必要値 없는 단일 ソース木/클래스는 호스트의 `python3 道具/ファイル実行.py 経路/挨拶例.java`로 별도 QEMU에 업로드·命令実行·종료할 数 있다. 対話式 Swing에는 命令実行 後続側状況 利用者 입력을 유지하는 `make desktop`을 사용한다.

## 内蔵 JVM의 Swing 切抜き

실제로 제공하는 것은 **표준 패키지 이름으로 호출하는 内蔵 Swing API 부분집합**이다. OpenJDK `java.desktop` 모듈이나 AWT 전체를 이식한 것은 아니다.

| API | 動作 |
|---|---|
| `JFrame` | 窓表題, 容量·位置, 窓表示, 閉鎖 정책, dispose |
| `JPanel` | 子値 요소를 담는 패널 |
| `JLabel` | 한글을 포함한 文字列 値表示·値変更 |
| `JButton` | 버튼과 ActionListener クリック値 プロセス値入口 |
| `JTextField` | 한 行 UTF-8 入力値, 삭제, getText/setText, Enter 이벤트 |
| 共通値 | setBounds, setSize, add, getContentPane, repaint, validate |
| `SwingUtilities` | invokeLater, isEventDispatchThread |
| `ActionEvent` | getSource, getActionCommand, getID |

`setLayout(null)`과 `setBounds`로 배치한다. FlowLayout/BorderLayout/GridLayout, pack, 폰트·스타일 전체, 메뉴·테이블·트리·스크롤 패널, Java2D, 네이티브 AWT peer/JNI, 복잡한 文字 조판은 아직 없다. 이벤트 콜백은 内蔵 JVM의 단일 이벤트 命令実行 흐름에서 처리하며 OpenJDK EDT 구현과 동일하지 않다. 窓·요소는 命令実行 하나당 合計値 32개, 要素値 글자는 最大値 127 코드포인트다. 既定値 서체와 색은 커널이 제공한다.

[Swing試験.java](試験/Java/Swing試験.java)는 窓·ハングル文字列 印札値·本文フィールド·버튼·이벤트 처리의 命令実行 가능한 예제다. [内蔵 Swing 画面](build/verification/swing/native-swing.png)을 참고한다.

日本語 라이브러리에는 다음을 추가했다. ホスト ソースコンパイル 시 `dist/jkoros-native-korean.jar`를 classpath에 넣는다.

- `日本語.内蔵.窓`: `要素追加`, `窓表示`, `閉鎖`.
- `日本語.内蔵.操作部品`: `印札値`, `ボタン`, `本文フィールド` 生成.
- `日本語.内蔵.接続状態輸送`: `接続`, `通信端点接続待機`, `受取`.
- 기존 `出力`, `文字`, `ファイル`, `作業`, `入口一覧`, `辞書`, `通信`, `画面`, `中核値`도 유지한다.

## Java 네트워크

기존 `DatagramSocket`/`DatagramPacket`의 UDP 루프백에 `Socket`/`ServerSocket`의 **中核値 내부 연결형 バイト値 ストリーム値**을 추가했다. ファイル/소켓과 마찬가지로 SVC를 통해 Java 커널이 전송한다. 물리 NIC의 TCP/IP 패킷 스택은 아니다.

```java
java.net.ServerSocket サーバー値 = new java.net.ServerSocket(9250);
java.net.Socket ゲスト値 = new java.net.Socket("localhost", 9250);
java.net.Socket 接続 = サーバー値.accept();
ゲスト値.getOutputStream().write("안녕하세요".getBytes("UTF-8"));
byte[] 受信済み項目 = new byte[64];
int 長さ = 接続.getInputStream().read(受信済み項目);
接続.close(); ゲスト値.close(); サーバー値.close();
```

生成·接続·accept·양방향 バイト値/配列値 入力出力·close·EOF·setSoTimeout을 지원한다. `String.getBytes()`와 UTF-8 이름을 지정한 getBytes도 제공한다. 루프백 주소는 `localhost`/`127.0.0.1`이다. 연결형 終端位置点 16개, 値受取 버퍼당 1024바이트, 値待合 接続 最大値 4개이며 Java의 대기는 내부 가닥에 실행을 양보한다. 既定値 時間値 上限値 0은 별도 ソケット値 기한을 설정하지 않지만 JVM 命令 数/中核値 命令実行 기한은 여전히 적용된다.

外部値 桁値 IPv4 TCP/UDP는 lwIP/SLIP로 지원한다. 実際データ Ethernet/Wi-Fi 드라이버, DNS·TLS·HTTP ライブラリ 전체는 미지원이다. `java.net`의 모든 메서드와 옵션, `SocketChannel`/select, SSL, shutdownInput/Output는 아직 없다. [ストリーム試験.java](試験/Java/ストリーム試験.java)는 実際データ 송수신·EOF·기한·接続 회수의 試験 예제다.

## ハングル文字列 Python

게스트 vi에서 ハングル文字列 이름을 사용해 작성한다.

```python
値 = 21

def 두배(桁値):
    return 桁値 * 2

print("結果:", 두배(値))
```

格納値 後続側状況 `python 挨拶例.py`로 실행한다. 실행기는 MicroPython 1.24.1이다. Python 문법 키워드는 그대로 사용하며 関数·変数値·ファイル 이름과 문자열을 한글로 쓴다.

[日本語.py](用例/ハングル符号化方式/日本語.py)를 같은 디렉터리에 두면 次回項目 별칭을 사용할 数 있다.

```python
import 日本語
日本語.ファイル書込("挨拶例.txt", "안녕하세요")
日本語.出力(日本語.ファイル読取("挨拶例.txt").decode())
```

出力·ファイル 読取/書込/삭제·표준 入力値·矩形·時間値·UDP를 연결한다. 기존 `udp_send`는 루프백, 새 `udp_sendto(fd, "10.0.2.2", port, data)`는 桁値 IPv4 番地 전송이다. `wait_key()`는 화면을 확인할 때 対話式 입력을 기다린다. Python 함수는 `jkoros` 내장 모듈을 통해 SVC를 사용한다. C ABI인 posix-kor 静的値 라이브러리를 Python이 직접 링크하는 구성은 아니다. CPython과 일반 拡張子値 모듈은 아직 없다. 제한형 `pip`의 ソース木 설치는 [Python パッケージ 案内](Python束.md)를 따른다. [三値 언어의 実際データ 用例](../../example/README.md).

## C·C++에서 posix-kor 呼出

두 言語 全体構築 日本語 헤더와 関数 이름을 직접 사용한다. [挨拶例.c](用例/ハングル符号化方式/挨拶例.c), [挨拶例.cpp](用例/ハングル符号化方式/挨拶例.cpp)先頭位置被演算子 実際データ EL0 命令実行 試験 대상이다.

```c
#include "ファイルABI.h"
#ifdef __cplusplus
extern "C"
#endif
int 利用者プログラム開始処理(int 引数) {
    (void)引数;
    const char 挨拶文[] = "안녕하세요\n";
    int 文書 = ファイル開放("挨拶例.txt", 読取書込 | 作成条件未存在 | 切詰め内容, 0600);
    if (文書 < 0) return 1;
    入出力結果型 記録済み個数 = ファイルデータ書込(文書, 挨拶文, sizeof(挨拶文) - 1);
    ファイル閉鎖(文書);
    ファイルデータ書込(1, 挨拶文, sizeof(挨拶文) - 1); /* 現在項目 端末 stdout */
    return 記録済み個数 == sizeof(挨拶文) - 1 ? 0 : 2;
}
```

파일은 게스트 vi로 작성할 数 있다. C는 게스트 `cc` 또는 ホスト SDK, C++는 ホスト SDK의 Clang++로 컴파일한다. 下端値 예제는 기존 ホスト SDK 경로다. 게스트 내부 GCC/Clang·libc/libstdc++ 전체를 탑재한 것은 아니다. SDK가 `.c`에는 C11, `.cpp`에는 C++11을 선택한다.

```sh
# 호스트에서 SDK 生成·抽出
make sdk
mkdir -p build/sdk-work
tar -xzf dist/jkoros-native-aarch64-sdk.tar.gz -C build/sdk-work
cd build/sdk-work/jkoros-native-sdk
python3 compile.py examples/挨拶例.c -o 挨拶例-c.elf
python3 compile.py examples/挨拶例.cpp -o 挨拶例-cpp.elf

# 프로젝트로 돌아와 별도 QEMU에서 実際データ 命令実行
cd /home/user/jkoros/platforms/rpi4-native
python3 道具/ファイル実行.py build/sdk-work/jkoros-native-sdk/挨拶例-c.elf
python3 道具/ファイル実行.py build/sdk-work/jkoros-native-sdk/挨拶例-cpp.elf
```

現在項目 GUI VM에서 실행하려면 `python3 道具/送出転送ファイル群.py 経路/挨拶例-c.elf`의 출력을 게스트에 보내고 `run 挨拶例-c.elf`를 입력한다. 게스트에서 작성한 소스의 전송은 `hex ファイル名前本文`으로 내용을 얻어 호스트에서 `bytes.fromhex(...)`로 복원할 数 있다. 호스트와 게스트의 ファイル 시스템은 별개다.

| 日本語 名前 | C 記号 | 切抜き |
|---|---|---|
| ファイル開放/ファイル閉鎖 | pk_open/pk_close | RAM ファイル, 通信相手値/절대 経路 |
| ファイルデータ読取/ファイルデータ書込 | pk_read/pk_write | ファイル, fd 0/1/2 표준 入力出力, 연결형 ソケット値 |
| ファイル位置移動 | pk_lseek | 起点先頭/現在根/終端位置原点 |
| ファイル容量/ファイル長さ設定 | pk_size/pk_ftruncate | 長さ 照会値/値変更 |
| ファイル入口名前除去 | pk_unlink | ファイル 名前 삭제 |
| 確定ファイル記憶装置 | pk_fsync | RAM이므로 -1, エラー番号=ENOSYS |
| 通信端点作成/番地結合 | pk_socket/pk_bind | AF_INET, SOCK_DGRAM 또는 SOCK_STREAM |
| データグラムデータ送信/データグラムデータ受取 | pk_sendto/pk_recvfrom | UDP 루프백 |
| 通信網接続 | pk_connect | 연결형 루프백 |
| 対象通信網接続状態待合 | pk_listen | 値待合 接続 最大値 4개 |
| 通信網接続状態受理 | pk_accept | 現在項目 番地 인수는 NULL/NULL만 支援値 |
| ソケット番地読取 | pk_getsockname | 로컬 番地/ポート値 |

`通信網ABI.h`의 内蔵 `pk_sockaddr_in`을 사용하며 ポート値·주소는 `通信網短整数`/`通信網整数値`로 변환한다. C ソケット値 호출은 비차단이며 データ/연결이 없으면 -1과 `エラー番号=11`(EAGAIN)을 반환한다. 양수 入力出力 결과가 요청보다 작을 数 있으므로 反復回値 처리한다. 失敗値 후에만 오류번호를 확인한다.

[ストリーム値.c](用例/ハングル符号化方式/ストリーム値.c)는 C에서 日本語 이름으로 接続·accept·部分要素値 読取/書込·큐 포화·EOF를 처리하는 命令実行 예제다. SDK의 `examples/ストリーム値.c`를 같은 `compile.py`로 컴파일한다.

SDK는 **libposix-kor-user.a**를 링크한다. 呼出 흐름은 C/C++ → 実際データ 日本語 C 関数 또는 호환용 `pk_*` → `svc #0` → 커널의 소유권·ポインタ 検査項目 → Java RAM ファイル/루프백 또는 外部値 lwIP TCP/UDP 구현이다. `libposix-kor-arm64.a`는 中核値 내부용이므로 EL0 프로그램에 링크하지 않는다. Linux 헤더나 Linux ELF와 혼합하지 않는다. 동적 接続, 표준 C printf, libstdc++/STL, 例外·RTTI는 제공하지 않으며 C++의 静的値 생성자·局所有効範囲 オブジェクト値 소멸자는 지원한다. 상세 番号·記憶データ 범위는 [利用者呼出しABI.md](利用者呼出しABI.md)를 참고한다.

## 妥当性検査

`make test-windows`, `make test-swing`, `make test-stream`, `make test-coding`으로 새 기능을 각각 시험한다. `make test`는 기존 シェル·VNC·JVM·AOT·中核値 値防護 시험까지 포함한다. 実際データ 基板 대신 QEMU raspi4b에서 수행한다. 결과는 [前回項目 GUI 拡張子値 妥当性検査 履歴記録記録](build/verification/release.json)과 [現在項目 実行環境 妥当性検査 履歴記録記録](build/verification/native-runtime-summary.json), [여러 端末 画面](build/verification/windows/four-terminals.png), [Swing 画面](build/verification/swing/native-swing.png)을 참고한다.

実装 시 참고한 표준 API: [Socket](https://docs.oracle.com/javase/8/docs/api/java/net/Socket.html), [JFrame](https://docs.oracle.com/javase/8/docs/api/javax/swing/JFrame.html), [JButton](https://docs.oracle.com/javase/8/docs/api/javax/swing/JButton.html). 이 문서의 実装 범위가 上端値 표준 전체를 지원한다는 뜻은 아니다.

## 日本語 이름으로 직접 작성하는 창과 スレッド値

`example/java/窓例.java`는 `実行可能処理作業.作業実行`,
`動作受信先.動作受取(動作通知)`, `ボタン`, `イベント待ち行列.後続呼出`, `起動処理()`을 쓴다.
内蔵 JVM에 이 이름들의 オブジェクト値·メソッド値·콜백을 직접 구현했으며 영어 Swing 객체를
보관하는 래퍼가 아니다. `作業担当`도 内蔵 스케줄러와 직접 연결된다.
세부 메서드와 기존 日本語 API에서의 변경은 [日本語 API 文書](日本語Java/案内.md)를 본다.

ホスト javac는 配布値 JAR를 クラス値 경로로 사용한다.

```sh
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/한국어사용 ../../example/java/窓例.java
python3 道具/命令実行.py --desktop --network --resolution 1920x1080
```

게스트에는 빌드한 예제가 `/example/java`에 설치된다.

```text
cd /example/java
java 窓例
```

직접 画面/スレッド値 API와 `起動処理()` 진입점은 内蔵 JVM 전용이다.
전체 OpenJDK·Swing 재구현이나 일반 OpenJDK에서 같은 API의 실행을 보장하지 않는다.
기존 표준 `main(String[])` 프로그램은 継続処理工程 실행할 数 있다.
