# 利用者 呼出 境界位置値

대상은 jkoros i386 ELF32다. Linux i386의 呼出 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `機械/稼働システム呼出し一覧.s`에서 EAX(番号), EBX·ECX·EDX·ESI·EDI(先頭位置序数~第五序数 引数)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. 中核値 실패는 負数値 エラー 番号, C ライブラリ 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 利用者 領域値 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C データ 주소는 バイト値 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java ファイル 흐름의 어셈블리 경계가 별도 バイト値 버퍼를 마련하여 같은 호출을 사용한다.

| 番号 | 動作 | 引数 |

| 30 | ファイル開放 | NUL 終端 名前 番地, 設定値, 許可許可権 |
| 31 | ファイルデータ読取 | 記述子入口, データ 番地, バイト値 数 |
| 32 | ファイルデータ書込 | 記述子入口, データ 番地, バイト値 数 |
| 33 | ファイル閉鎖 | 記述子入口 |
| 34 | ファイル位置移動 | 記述子入口, 符号化状態値 있는 変位量値, 計画根 |
| 35 | 複製ファイル記述子 | 記述子入口 |
| 36 | 複製ファイル記述子位置 | 記述子入口, 새 記述子入口 |
| 37 | ファイル状態読取 | 記述子入口, 48바이트 状況値 番地 |
| 38 | ファイル入口名前除去 | NUL 終端 名前 番地 |
| 39 | ファイル長さ設定 | 記述子入口, 새 長さ |

| 41 | 通信端点作成 | 番地 稼働システム値, 種別値, 契約値 番号 |

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 番地 두 칸이다. 値受取 주소가 NULL이면 通信相手値 番地 기록을 생략한다. sockaddr_in은 16바이트이며 番地 체계는 装置 バイト値 列順値, 접속번호와 IP 주소는 네트워크 バイト値 차례다. 축소된 番地 버퍼에도 들어가는 앞부분을 쓰고 전체 番地 容量 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 終了点プログラム, 2·3은 기존 引数 조회다. 現在項目 커널의 引数 목록이 命令実行 이름을 제외하므로 C 진입기는 argv[0]에 고정 文字列 `jkoros-app`을 넣고 後続側値 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX プロセス値 ABI와 다른 점이다.

표준 헤더의 整数値 容量, フラグ一覧値 値, stat フィールド値 순서는 `ソース/ヘッダー/`에 정의한다. 동적 接続·다중 プロセス値·스레드가 추가되면 エラー 番号 저장과 資源値 수명, 呼出 경계도 함께 검토해야 한다.
