# Java 네이티브 컴파일러

OpenJDK 자체 소스를 빌드하는 **`--target openjdk-build`**와 자체 ਪੱਕੇ_ਹੋਣਾ_ਕੀਮਤ ABI 검사 도구를 추가했다.
이는 공식 javac/C/C++ 도구를 연결하는 별도 경로다. [ਬਿਲਡ_ਪਰਬੰਧ 방법·ਅਸਲ_ਸਮੱਗਰੀ ਪ੍ਰਮਾਣਿਤ·ਪੱਕੇ_ਹੋਣਾ_ਕੀਮਤ 이식 ਕਲਿਪ](OpenJDK-소스빌드와-자체커널-이식.md)를 참고한다.

x86 직접 변환과 ARM64 C ਜਨਰੇਟ_ਕਰੋ 후단은 모두 [기계어미리번역.java](자바도구/기계어미리번역.java)로 구현한다. `sh 미리번역.sh`로 직접 실행하며, [기계어미리번역.py](기계어미리번역.py)와 `컴파일러.py`는 이전 ਕਮਾਂਡ·API 및 OpenJDK 도구를 위한 호환 진입점이다. 자체 Pi4 후단은 freestanding C를 거쳐 AArch64로 만든다. [arm64.py](arm64.py)는 이전 경로와 Python 호출을 위한 호환 진입점이다. ਫੰਗਸ਼ਨ_ਕੀਮਤ·변수·ਜਨਰੇਟ_ਕਰੋ C 이름의 뜻과 예외는 [ਪੰਜਾਬੀ 명명 ਫਈਲ_ਮੈਨੂੰ_ਪੜਨ_ਦਿਉ_eb81d7d9](../platforms/rpi4-native/명명/ਫਈਲ_ਮੈਨੂੰ_ਪੜਨ_ਦਿਉ_eb81d7d9.md)를 참고한다. [ARM64 ਬਿਲਡ_ਪਰਬੰਧ·ਸਮਰਥਨ_ਕੀਮਤ ਕਲਿਪ](../platforms/rpi4-native/ਫਈਲ_ਮੈਨੂੰ_ਪੜਨ_ਦਿਉ_eb81d7d9.md)에 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 조건이 있다. 전체 OpenJDK나 일반 ਸ੍ਰੇਣੀ_ਕੀਮਤ 실행기는 아니다.

ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 시 JVM이 필요 없는 x86 32비트 ELF를 만든다. JDK 11 이상으로 실행하는 Java 자체 AOT 후단이며, Java 전체를 새로 구현한 컴파일러는 아니다. Java 문법·ਐਕਸੈਸ_ਦਾਖਲਾ ਨਿਯੰਤਰਣ_ਕੀਮਤ·ਟਾਈਪ_ਕਰੋ_ਕੀਮਤ 검사는 JDK의 `javac`에 맡기고, Java 8 ਸ੍ਰੇਣੀ_ਕੀਮਤ 파일을 읽어 각 바이트코드를 x86 명령으로 직접 변환한다. C 코드로 우회하거나 바이트코드 해석기를 커널에 넣지 않는다.

```text
Java ਸਰੋਤ → javac의 문법·ਟਾਈਪ_ਕਰੋ_ਕੀਮਤ 검사 → 임시 .class
          → 자체 x86 변환기 → GNU as/ld → 네이티브 ELF32
```

## 준비와 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼

ਬਿਲਡ_ਪਰਬੰਧ ਹੋਸਟ: Linux, Python 3.6 이상, JDK 11 이상(`javac --release 8`), GNU binutils(`as`, `ld`), Make. 현재 환경의 OpenJDK 11, Python 3.6, binutils 2.30으로 검증했다. 외부 Python 패키지와 네트워크 다운로드는 사용하지 않는다.

```sh
cd /home/user/jkoros/compiler
make
./build/계산
echo $?                  # 0이면 예제 시험 성공

python3 컴파일러.py --target linux --entry 계산.ਚਲਾਓ_2 \
    -o build/계산 예제/계산.java

make test
```

`linux` 대상은 Linux의 32비트 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 호환 기능이 필요하다. `int 0x80`을 차단하는 샌드박스에서는 `Bad system call`이 발생할 수 있다. 정상 Linux ਹੋਸਟ 또는 해당 실행을 허용한 시험 환경에서 실행한다. 시험의 비정상 종료를 통과로 처리하지 않는다.

진입점은 `static int ਚਲਾਓ_2()` 또는 `static void ਚਲਾਓ_2()`처럼 인수가 없어야 한다. `--entry 패키지.ਸ੍ਰੇਣੀ_ਕੀਮਤ.ਫੰਗਸ਼ਨ_ਕੀਮਤ`로 선택한다. `int` 반환값은 Linux 프로세스 ਨਿਕਾਸ_ਐਪਲੀਕੇਸ਼ 코드가 되며 셸에는 하위 8비트가 보인다. 일반 `main(String[] args)` ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 환경이나 표준 ਦਾਖਲ_ਹੋਣਾ_ਬਾਹਰ_ਆਉਣਾ 라이브러리는 제공하지 않는다.

`--target kernel`은 부팅 코드와 연결할 재배치 ELF 오브젝트를 생성한다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target kernel --entry ਪੱਕੇ_ਹੋਣਾ.ਚਲਾਓ_2 \
    --export kernel_dispatch=체계호출.ਕਾਰਵਾਈ_ਕੀਮਤ_ਦਾਖਲਾ \
    -o os/build/java.o os/ਸਰੋਤ/*.java
```

`--target user`는 jkoros 셸에서 실행할 독립 ELF를 생성한다. `ਉਪਭੋਗਤਾ` 클래스의 제한된 native API는 `int 0x80` 시스템 호출로 연결하며 `ਤਜਵੀਜ_ਕੀਮਤ` 클래스의 하드웨어 직접 접근은 거부한다. ਉਪਭੋਗਤਾ ELF는 Linux ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ ਫਾਇਲ ABI와 다르므로 호스트에서 실행하지 않는다. ਜਨਰੇਟ_ਕਰੋ·ਰਜਿਸਟਰ_ਕਰੋ_ਦਾਖਲਾ 방법은 [ਉਪਭੋਗਤਾ ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ ਫਈਲ_ਮੈਨੂੰ_ਪੜਨ_ਦਿਉ_eb81d7d9](../os/ਉਪਭੋਗਤਾ/ਫਈਲ_ਮੈਨੂੰ_ਪੜਨ_ਦਿਉ_eb81d7d9.md)에 있다. `--export 외부기호=ਸ੍ਰੇਣੀ_ਕੀਮਤ.ਫੰਗਸ਼ਨ_ਕੀਮਤ`는 오버로드되지 않은 ਸਥਾਈ_ਕੀਮਤ 함수를 자체 스택 ABI로 노출한다. 커널의 시스템 호출 진입점에 사용한다.

Java 파일은 필요한 클래스들을 한꺼번에 전달한다. ਆਉਟਪੁੱਟ 옆의 `.s`는 생성된 어셈블리, `.json`은 ਸਰੋਤ SHA-256 및 네이티브 ਪ੍ਰਤੀਕ↔Java ਫੰਗਸ਼ਨ_ਕੀਮਤ 대응표다. ਪੰਜਾਬੀ 함수명은 원문과 대응표에 보존하고 ELF 내부에는 충돌 방지용 ਮਸ਼ੀਨ 기호를 쓴다. ਬਣਾਊਣਾ_ਸਰੋਤ·조립·ਕੁਨੈਕਸ਼ਨ_ਕਰੋ 중 실패하면 기존 ਮਾਪ 파일을 덮어쓰지 않는다.

## ਸਮਰਥਨ_ਕੀਮਤ ਕਲਿਪ

- `int`, `boolean`, `byte`, `short`, `char`의 32비트 계산 및 ਟਾਈਪ_ਕਰੋ_ਕੀਮਤ 변환.
- ਸਥਾਈ_ਕੀਮਤ 필드와 ਸਥਾਈ_ਕੀਮਤ ਫੰਗਸ਼ਨ_ਕੀਮਤ, 매개변수·반환값, 재귀, 클래스별 지연 초기화와 ਅਰੰਭ_ਕਰੋ ਸਾਇਕਲ_ਕੀਮਤ.
- 조건문, 반복문, 단락 평가, 삼항식, ਪੂਰਣ_ਅੰਕ `switch`, 넓은 ਲੋਕਲ_ਗੁੰਜਾਇਸ਼ 변수 인덱스.
- 덧셈·뺄셈·곱셈·나눗셈·나머지·ਬਿਟ_ਕੀਮਤ 연산과 ਖਿਸਕਾਉਣਾ_ਕੀਮਤ. Java의 오버플로 및 `MIN_VALUE / -1` 동작을 유지한다.
- `int[]` ਜਨਰੇਟ_ਕਰੋ·초기값 0·ਲੰਬਾਈ_ਕੀਮਤ·ਪੜ੍ਹਨ·ਲਿਖਣ·ਸੰਦਰਭ 비교. 256KiB 고정 ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ 영역, 널/ਉਪਲਿਪੀ_ਕੀਮਤ/ਆਕਾਰ/공간 검사.
- ਨਿਰਭਰ_ਰਹਿਣ_ਵਾਲਾ_ਕੀਮਤ 리터럴과 `String` ਸੰਦਰਭ, `length()` 및 `charAt()`. 문자열은 UTF-16 코드 단위로 저장하고 같은 리터럴은 공유한다. NUL 및 대리쌍도 시험한다.
- ਪੰਜਾਬੀ ਸ੍ਰੇਣੀ_ਕੀਮਤ·ਫੰਗਸ਼ਨ_ਕੀਮਤ·변수·ਫਾਇਲ ਨਾਂ.

`new Object`, 인스턴스 ਫਿਲਡ_ਕੀਮਤ/ਫੰਗਸ਼ਨ_ਕੀਮਤ, 상속/인터페이스, `long/float/double` ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ ਕਰਵਾਈ_ਕੀਮਤ, `int[]` 이외 ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ, ਨਿਰਭਰ_ਰਹਿਣ_ਵਾਲਾ_ਕੀਮਤ 동적 결합, Java 표준 ਪੁਸਤਕਾਲਾ, 예외 ਕਾਰਵਾਈ_ਕੀਮਤ_ਦਾਖਲਾ, 스레드·ਸਿੰਕ_ਕਰੋ·GC는 미지원이다. 실행에 필요한 미지원 바이트코드나 외부 호출을 발견하면 실패한다. 사용되지 않는 ਡਿਫੌਲਟ_ਵੈਲਯੂ 생성자는 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 코드로 만들지 않는다. Java 8 문법이어도 모든 프로그램을 컴파일할 수 있다는 뜻은 아니다.

예외 ਔਬਜੈਕਟ_ਕੀਮਤ 대신 런타임 ਗਲਤੀ 번호로 중단한다. Linux와 jkoros ਉਪਭੋਗਤਾ 대상에서는 `100 + ਅਨੁਕ੍ਰਮਣਿਕਾ`로 종료하고 ਪੱਕੇ_ਹੋਣਾ_ਕੀਮਤ 대상에서는 `JKOROS PANIC ਅਨੁਕ੍ਰਮਣਿਕਾ`를 출력하고 정지한다. ਉਪਭੋਗਤਾ 프로그램만 종료한 경우 셸은 계속 실행된다.

| ਅਨੁਕ੍ਰਮਣਿਕਾ | 원인 |
| --- | --- |
| 1 | 0으로 ਤਕਸੀਮ_ਮਾਪ |
| 2 | 널 ਸੰਦਰਭ |
| 3 | ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ/ਨਿਰਭਰ_ਰਹਿਣ_ਵਾਲਾ_ਕੀਮਤ ਉਪਲਿਪੀ_ਕੀਮਤ ਕਲਿਪ 초과 |
| 4 | 음수 ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ ਆਕਾਰ |
| 5 | ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ 영역 부족 |

ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ 영역은 증가식 할당이며 회수하지 않는다. 재귀 스택의 경계 검사도 아직 없으므로 무제한 재귀를 안전하게 처리하는 런타임은 아니다. 특권 ਪੱਕੇ_ਹੋਣਾ_ਕੀਮਤ 및 신뢰할 수 있는 작은 프로그램용 초기 구현이다.

## native 경계와 ABI

ਪੱਕੇ_ਹੋਣਾ_ਕੀਮਤ 대상에서는 `os/ਸਰੋਤ/ਤਜਵੀਜ_ਕੀਮਤ.java`, ਉਪਭੋਗਤਾ 대상에서는 `os/ਉਪਭੋਗਤਾ/선언/ਉਪਭੋਗਤਾ.java`의 정확한 ਮੈਥਡ_ਨਾਮ_ਪਾਠ·서술만 허용한다. 임의의 `native` 함수와 Linux/ਉਪਭੋਗਤਾ 대상의 하드웨어 접근은 거부한다. Java 인수를 왼쪽부터 32비트 한 칸씩 스택에 놓으며, 반환값은 EAX, EBP/ESP 이외 레지스터는 호출자가 보존한다고 가정하지 않는다. C의 cdecl/JNI ABI가 아니므로 C 함수와 바로 연결하면 안 된다.

Java ਸਰੋਤ 또는 `.class` 입력을 받는다. 전체 JVM 바이트코드 검증기는 제공하지 않는다. 어노테이션 처리는 비활성화하고 비어 있는 ਸ੍ਰੇਣੀ_ਕੀਮਤ ਮਾਰਗ/ਸਰੋਤ 경로에서 명시한 소스만 컴파일한다.

## 검증과 구현 근거

`시험/test_compiler.py`의 14개 시험에는 네이티브 ELF와 OpenJDK의 ਕਰਵਾਈ_ਕੀਮਤ ਮਾਪ 대조, ਸ੍ਰੇਣੀ_ਕੀਮਤ ਅਰੰਭ_ਕਰੋ, ਪੂਰਣ_ਅੰਕ 극값, ਨਿਰਭਰ_ਰਹਿਣ_ਵਾਲਾ_ਕੀਮਤ/ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ, 재귀·switch·wide, 런타임 오류와 미지원 기능 거부, ਅਸਫਲ_ਕੀਮਤ 시 ਆਉਟਪੁੱਟ 보존, ਉਪਭੋਗਤਾ ELF/ਆਗਿਆ_ਕੀਮਤ 경계 및 내보내기 검증이 포함된다. 이것은 Java 전체 적합성 시험은 아니다.

ਕਮਾਂਡ 의미와 ਸ੍ਰੇਣੀ_ਕੀਮਤ ਫਾਇਲ 형식은 Oracle의 [JVM ਕਮਾਂਡ 명세](https://docs.oracle.com/javase/specs/jvms/se11/html/jvms-6.html), [ਸ੍ਰੇਣੀ_ਕੀਮਤ ਫਾਇਲ 명세](https://docs.oracle.com/javase/specs/jvms/se11/html/jvms-4.html)를 참고했다.
