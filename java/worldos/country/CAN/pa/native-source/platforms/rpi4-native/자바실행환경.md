# 자체 ARM64 JVM 0.4와 ਪੰਜਾਬੀ ਪੁਸਤਕਾਲਾ

ਪੰਜਾਬੀ 통신·예외 사용법은 [ਪੰਜਾਬੀ Java API](한국어자바/ਫਈਲ_ਮੈਨੂੰ_ਪੜਨ_ਦਿਉ_eb81d7d9.md), ਫੰਗਸ਼ਨ_ਕੀਮਤ·변수·ਫਾਇਲ 이름의 변경과 어원 근거는 [명명 ਫਈਲ_ਮੈਨੂੰ_ਪੜਨ_ਦਿਉ_eb81d7d9](명명/ਫਈਲ_ਮੈਨੂੰ_ਪੜਨ_ਦਿਉ_eb81d7d9.md)를 참고한다.

JAR ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼, 외부 IPv4 TCP/UDP, 별도 ਸਥਾਈ_ਕੀਮਤ 부분집합 `jaot`와 게스트 C 컴파일은 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)에 설명한다. 아래 ਔਬਜੈਕਟ_ਕੀਮਤ·Thread·Swing은 JVM 경로의 기능이며 AOT ਸਮਰਥਨ_ਕੀਮਤ 범위와 같지 않다.

이 구현은 **Linux 없이 부팅한 Java AOT 커널의 EL0에서 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼**한다. JDK/JRE의 거의 모든 기능을 제공하는 단계는 아직 아니다. HotSpot·OpenJDK ਸ੍ਰੇਣੀ_ਕੀਮਤ ਪੁਸਤਕਾਲਾ 전체를 이식하거나 Java SE 인증/TCK를 통과한 구현도 아니다. 이번 확장은 단일 ਸ੍ਰੇਣੀ_ਕੀਮਤ·ਸਥਾਈ_ਕੀਮਤ ਮੈਥਡ_ਕੀਮਤ 중심이던 실행기를 ਔਬਜੈਕਟ_ਕੀਮਤ·ਪੁਸਤਕਾਲਾ ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 기반으로 넓힌 것이다.

## 실행과 ਬਣਾਊਣਾ_ਸਰੋਤ

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
# 자체 ਪੱਕੇ_ਹੋਣਾ_ਕੀਮਤ 안에서 ਸਰੋਤ_ਟ੍ਰੀ ਬਣਾਊਣਾ_ਸਰੋਤ → class ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼, ਪੰਜਾਬੀ API 호출
python3 ਸਾਧਨ/ਅਮਲ_ਕਰੋ_ਲਿਖਤ_ਪੱਤਰ.py 시험/자바/한글소스.java

# ਔਬਜੈਕਟ_ਕੀਮਤ·예외 등은 ਹੋਸਟ JDK로 Java 8 class를 만든 후 자체 커널에서 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼
mkdir -p build/my-java
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/my-java 시험/자바/한글시험.java
python3 ਸਾਧਨ/ਅਮਲ_ਕਰੋ_ਲਿਖਤ_ਪੱਤਰ.py build/my-java/한글시험.class

# 의존 class 파일은 --include로 함께 ਸਥਾਂਨਤਰ_ਕੀਮਤ
javac --release 8 -encoding UTF-8 -d build/my-java 시험/자바/객체시험.java
python3 ਸਾਧਨ/ਅਮਲ_ਕਰੋ_ਲਿਖਤ_ਪੱਤਰ.py build/my-java/객체시험.class \
  --include build/my-java/ਪਿਛੋਕੜ_ਕੀਮਤ.class --include build/my-java/ਸ਼ਾਖਾ_ਕੀਮਤ.class \
  --include build/my-java/계산가능.class

make test-jvm
```

`--include DIR`는 그 디렉터리의 class 파일을 재귀적으로 읽어 `패키지.ਸ੍ਰੇਣੀ_ਕੀਮਤ.class`라는 RAM ਫਾਇਲ 이름으로 전송한다. 주 클래스도 패키지가 있다면 `--class-name 패키지.ਸ੍ਰੇਣੀ_ਕੀਮਤ`를 지정한다. 셸에서는 해당 이름으로 업로드하고 `java 패키지.ਸ੍ਰੇਣੀ_ਕੀਮਤ`로 실행한다. JVM 0.4는 Main-Class가 있는 16 KiB 이하 JAR도 `java -jar ਫਾਇਲ.jar`로 실행한다. JAR 모드에서는 JAR 내부 클래스와 내장 ਪੰਜਾਬੀ 클래스만 찾는다. 배포 ਪੰਜਾਬੀ ਪੁਸਤਕਾਲਾ JAR는 ਹੋਸਟ javac의 classpath로 사용하며, 같은 클래스가 ਉਪਭੋਗਤਾ JVM ELF에도 ਪੜ੍ਹਨ 전용 자료로 포함된다. 일반 class 모드에서는 사용자가 같은 이름으로 올린 RAM class를 먼저 읽는다.

게스트 `javac`는 여전히 ਸਥਾਈ_ਕੀਮਤ ਮੈਥਡ_ਕੀਮਤ, int/boolean/char/String, ਸ਼ਰਤ·ਦੋਹਰਾਵ_ਕੀਮਤ, ਨਿਰਭਰ_ਰਹਿਣ_ਵਾਲਾ_ਕੀਮਤ 결합, 일부 ਫਾਇਲ 스트림 등의 **자체 부분집합 컴파일러**다. ਔਬਜੈਕਟ_ਕੀਮਤ 선언·상속·try/catch·Thread 사용 소스를 게스트 javac가 모두 컴파일하는 것은 아니다. 위 기능은 `javac --release 8`로 만든 class를 자체 JVM에서 실행한다. ਪੰਜਾਬੀ API 중 ਆਉਟਪੁੱਟ·문자 스칼라 ਫੰਗਸ਼ਨ_ਕੀਮਤ·ਫਾਇਲ ਪੜ੍ਹਨ/쓰기는 게스트 컴파일러에도 연결했다. 다음처럼 전체 이름으로 호출한다.

```java
public class 인사 {
    public static void main(String[] ਆਰਗੂਮੈਂਟ) throws Exception {
        ਪੰਜਾਬੀ.자체.ਆਉਟਪੁੱਟ.ਲਿੱਖੋ_ਕਤਾਰ("안녕하세요😀");
        ਪੰਜਾਬੀ.자체.ਆਉਟਪੁੱਟ.수쓰기(ਪੰਜਾਬੀ.자체.문자.코드포인트수("한글😀"));
        ਪੰਜਾਬੀ.자체.ਫਾਇਲ.ਲਿਖਣ("인사.txt", "한글 ਫਾਇਲ😀");
        ਪੰਜਾਬੀ.자체.ਆਉਟਪੁੱਟ.ਲਿੱਖੋ_ਕਤਾਰ(ਪੰਜਾਬੀ.자체.ਫਾਇਲ.ਪੜ੍ਹਨ("인사.txt"));
    }
}
```

예외는 Throwable/Exception/RuntimeException, ArithmeticException, NullPointerException, IndexOutOfBoundsException/ArrayIndexOutOfBoundsException/StringIndexOutOfBoundsException, IllegalArgumentException/NumberFormatException/IllegalThreadStateException, IOException/FileNotFoundException, IllegalStateException, ClassCastException, NegativeArraySizeException, ArrayStoreException, UnknownHostException, SocketTimeoutException의 제한된 ਜਨਰੇਟ_ਕਰੋ·ਸ਼੍ਰੇਣੀ_ਕੀਮਤ·처리를 제공한다. ਉਪਭੋਗਤਾ ਪਰਿਭਾਸ਼ਾ_ਕੀਮਤ Throwable 상속, stack trace/cause/suppressed 예외, try-with-resources의 addSuppressed, 완전한 ਅਰੰਭ_ਕਰੋ ਗਲਤੀ 포장은 아직 없다. 잡히지 않은 예외는 현재 전체 Java 실행을 실패로 끝낸다.

## ਪੰਜਾਬੀ API

독립 패키지 **`ਪੰਜਾਬੀ.자체`**를 사용한다. Linux판 `ਪੰਜਾਬੀ.자바`가 요구하는 NIO/Swing/HTTP API를 자체 커널에서 실행할 수 있다고 혼동하지 않도록 패키지를 나눴다. 이 라이브러리는 ਸ੍ਰੇਣੀ_ਕੀਮਤ ਨਾਂ·ਮੈਥਡ_ਕੀਮਤ·ਆਰਗੂਮੈਂਟ·ਫਿਲਡ_ਕੀਮਤ·ਫਾਇਲ 이름에 한국어를 사용한다. 표준 Java ਸ੍ਰੇਣੀ_ਕੀਮਤ 이름은 호환성을 위해 보존한다.

| ਸ੍ਰੇਣੀ_ਕੀਮਤ | 공개 기능 | 이름의 의미 |
|---|---|---|
| ਆਉਟਪੁੱਟ | ਲਿਖਣ, ਲਿੱਖੋ_ਕਤਾਰ, 수쓰기 | ਆਉਟਪੁੱਟ(出力): 내용을 바깥으로 내보냄 |
| 문자 | ਲੰਬਾਈ_ਕੀਮਤ, 같음, ਚਿਪਕਾਊਣਾ_ਪਾਠ, ਕੱਟ_ਕੀਮਤ, ਪਦ_ਵਿਆਖਿਆ_ਕਰੋ_ਪੂਰਣ_ਅੰਕ/ਲਿੱਖੋ_ਪੂਰਣ_ਅੰਕ_ਕੀਮਤ, 코드포인트수, 부호화/ਬਦਲਾਵ_ਕਰੋ_ਸਮੱਗਰੀ | 문자(文字), ਸੁਰੂ_ਤੋਂ_ਗਿਣਨਾ_ਕੀਮਤ(符號): 글의 단위와 그 값을 바이트로 나타내는 ਨਿਯਮ_ਕੀਮਤ |
| ਫਾਇਲ | ਪੜ੍ਹਨ/ਲਿਖਣ(String ਨਾਂ), 바이트읽기/ਲਿੱਖੋ_ਬਾਈਟ_ਕੀਮਤ | 널리 쓰는 ਉਪਭੋਗਤਾ 용어를 보존; RAM 자료의 ਨਾਂ |
| ਦਾਖਲਾ_ਸੂਚੀ | 더하기, ਪੜ੍ਹਨ, ਸਥਾਨ_ਬਦਲੋ_ਕੀਮਤ, 지우기, ਆਕਾਰ, 비었는가, ਹਟਾਓ_ਤਤਕਰਾ | ਦਾਖਲਾ_ਸੂਚੀ(目錄): 순서가 있는 ਦਾਖਲਾ_ਕੀਮਤ 모음 |
| ਸ਼ਬਦਕੋਸ਼ | 넣기, ਲੱਭੋ_ਦਾਖਲਾ, 있는가, 지우기, ਆਕਾਰ, ਹਟਾਓ_ਤਤਕਰਾ | ਸ਼ਬਦਕੋਸ਼(辭典): 찾는 말인 열쇠에 값을 대응 |
| 작업 | ਚਲਾਓ_2(실행할일), 기다리기(작업가닥), ਮੁਅੱਤਲ_ਕਾਰਜ, 살아있는가 | 작업 ਥ੍ਰੈਡ_ਕੀਮਤ: 한 ਐਪਲੀਕੇਸ਼_f5044b9b 안의 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ ਸਟ੍ਰੀਮ_ਕੀਮਤ |
| 통신 | ਖੋਲ੍ਹੋ, ਈਮੇਲ, 받기, ਸਮਾਂ_ਸਮਾਪਤ, ਬੰਦ_ਕਰੋ | 통신(通信), 전문(電文), ਪੋਰਟ_ਕੀਮਤ: ਸਮੱਗਰੀ 교환·메시지·포트의 역할 |
| 화면 | 사각형, 지우기 | 화면(畫面): ਅਸਲ_ਸਮੱਗਰੀ 그림을 표시하는 면 |
| ਪੱਕੇ_ਹੋਣਾ_ਕੀਮਤ | 밀리초, 사각형 | 자체 JVM의 고정 native ਕੁਨੈਕਸ਼ਨ_ਕਰੋ; 일반 JNI는 아님 |

이 명명은 현재 기능을 설명하는 용어 선택이다. 기존 한국어에 없던 역사적 어원을 만들어 주장하지 않는다. ਲਿਖਤ_ਪੱਤਰ_ਨਾਮ_ਪਾਠ·식별자는 UTF-8 소스로 보관한다. `문자.ਬਦਲਾਵ_ਕਰੋ_ਸਮੱਗਰੀ`는 잘못된 UTF-8에 IllegalArgumentException을 던지며, `부호화`는 짝이 없는 서로게이트를 `?`로 바꾼다. `ਫਾਇਲ.ਪੜ੍ਹਨ`는 엄격한 UTF-8 복호화를 적용한다. 화면 색은 `빨강 | (초록 << 8) | (파랑 << 16)` 형식이다.

## ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(ਪੰਜਾਬੀ ਸ੍ਰੇਣੀ_ਕੀਮਤ 포함), class당 16 KiB·ਸਥਿਰ_ਕੀਮਤ 풀 511항목, 전체 ਮੈਥਡ_ਕੀਮਤ/ਫਿਲਡ_ਕੀਮਤ 각각 512개. ਮੈਥਡ_ਕੀਮਤ 코드 8 KiB, ਲੋਕਲ_ਗੁੰਜਾਇਸ਼ 변수·피연산자 스택 각각 128슬롯, ਆਰਗੂਮੈਂਟ 최대 16개(this 포함).
- VM 가닥은 main 포함 **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- ਔਬਜੈਕਟ_ਕੀਮਤ 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 ਅਸਲ_ਸਮੱਗਰੀ 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 ਫਾਇਲ·대형 ਨਿਰਭਰ_ਰਹਿਣ_ਵਾਲਾ_ਕੀਮਤ·객체가 이 제한을 넘을 수 있다.
- 실행은 50만 바이트코드 ਕਮਾਂਡ 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 입력 대기는 기한을 갱신하고 ਵਿੰਡੋ ਸਵਿੱਚ_ਮੋਡ 시 중단·재개한다. 일반 ਸਰਵਰ_ਕੀਮਤ·계산의 무제한 실행은 아직 없다. 미지원 ਕਮਾਂਡ·ਸੰਸਾਧਨ_ਕੀਮਤ 부족은 명시적인 오류로 종료한다.
- RAM ਫਾਇਲ 최대 64개, 파일당 16384바이트, ਮਾਰਗ UTF-8 63바이트. RAM 디렉터리와 ਪਿਅਰ_ਕੀਮਤ/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 ਪੰਜਾਬੀ class는 RAM ਫਾਇਲ 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 현재 경로에서 ਸਰੋਤ_ਟ੍ਰੀ·ਸ੍ਰੇਣੀ_ਕੀਮਤ·ਸਮੱਗਰੀ 파일을 읽는다.
- UDP는 Java 루프백 및 lwIP/SLIP를 통한 외부 IPv4를 제공한다. ਅਸਲ_ਸਮੱਗਰੀ GENET/Wi-Fi/DNS/TLS/HTTP 전체는 없다. 전문 512바이트, 소켓 8개, 소켓당 큐 4개. receive는 VM 가닥을 양보하며 대기하고 setSoTimeout을 적용하지만 전체 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 기한은 여전히 적용된다.
- long/float/double, invokedynamic/람다, enum/annotation, 다차원 ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ, 완전한 ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ 공변성·인터페이스 ਲੇਅਰ_ਕੀਮਤ 검사, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/ਏਨਕ੍ਰਿਪਟ_ਕਰੋ_ਸਮੱਗਰੀ/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. Swing의 별도 ਸਮਰਥਨ_ਕੀਮਤ 부분집합은 아래 및 개발 매뉴얼을 참고한다. ਸ੍ਰੇਣੀ_ਕੀਮਤ ਫਾਇਲ 전체 검증기·ਐਕਸੈਸ_ਦਾਖਲਾ ਆਗਿਆ_ਕੀਮਤ/보호된 멤버 검사는 아직 완전하지 않다. 손상된 입력은 EL0 ਰੱਖਿਆ_ਕਰਨੀ_ਕੀਮਤ 경계 내에서 종료되도록 한다.

전체 OpenJDK를 목표로 하려면 다음은 별도의 주요 구현 단계다: 완전한 JVM ਕੀਮਤ/ਪ੍ਰਮਾਣਿਤ/ਸ੍ਰੇਣੀ_ਕੀਮਤ 로더와 예외 모델 → 영속 VFS·mmap·ਘੜੀ·원자 ਕਰਵਾਈ_ਕੀਮਤ·ਅਸਲ_ਸਮੱਗਰੀ 스레드/ਸਿੰਕ_ਕਰੋ ABI → OpenJDK java.base 및 native ਪੁਸਤਕਾਲਾ 이식 → ਤਜਵੀਜ_ਕੀਮਤ 네트워크·TCP/IP → ਵਿੰਡੋ 시스템/ਫੌਂਟ_ਕੀਮਤ/입력기·java.desktop → Java SE 호환성 시험. 현재 자체 JVM의 일부 메서드를 더하는 것으로 이 작업이 완료되지는 않는다.

## ਪ੍ਰਮਾਣਿਤ

`ਸਾਧਨ/자바가상기계시험.py`는 같은 Java 8 class 파일의 출력을 ਹੋਸਟ OpenJDK `-Xverify:all`과 QEMU raspi4b 자체 커널에서 비교한다. ਔਬਜੈਕਟ_ਕੀਮਤ/상속/인터페이스·switch·ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ, 예외/finally, 컬렉션/GC, Thread/잠금, ਪੰਜਾਬੀ UTF-8/ਫਾਇਲ/컬렉션, ਅਸਲ_ਸਮੱਗਰੀ UDP 루프백/시간 초과, 게스트 한글 ਸਰੋਤ_ਟ੍ਰੀ ਬਣਾਊਣਾ_ਸਰੋਤ, ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ ਟਾਈਪ_ਕਰੋ_ਕੀਮਤ/ਇਨਸਟੈਂਸ_ਕੀਮਤ/ਫਾਇਲ 경계·한글 패키지의 9개 비교 시험과 잘못된 class 버전/잘린 ਫਾਇਲ 거부 시험을 실행한다. UDP ਪ੍ਰੋਜੈਕਟ_ਰੂਟ 실행에는 ਹੋਸਟ 루프백 소켓 권한이 필요하다.

`ਸਾਧਨ/부팅시험.py`는 ਪੱਕੇ_ਹੋਣਾ_ਕੀਮਤ ਰੱਖਿਆ_ਕਰਨੀ_ਕੀਮਤ/회귀 시험과 별도로 ਪੰਜਾਬੀ Java 화면 API가 ਅਸਲ_ਸਮੱਗਰੀ 픽셀을 그렸는지도 QMP 화면 캡처로 검사한다. 보고서는 `build/verification/jvm/report.json`, `build/verification/report.json`이며 시험한 kernel8.img의 SHA-256을 기록한다. ਅਸਲ_ਸਮੱਗਰੀ Pi4 하드웨어 부팅 시험과 전체 JDK 호환성 시험 결과는 아니다.


## JVM 0.3: 네트워크와 GUI ਪ੍ਰਸਾਰ_ਕੀਮਤ

`Socket`/`ServerSocket` ਜਨਰੇਟ_ਕਰੋ·ਕੁਨੈਕਸ਼ਨ_ਕਰੋ·accept·양방향 InputStream/OutputStream·close·EOF·시간 제한과 UTF-8 `String.getBytes`를 추가했다. JVM 0.4에서는 외부 ਅੰਕ_ਕੀਮਤ IPv4 TCP도 lwIP/SLIP에 연결했다. 연결형 ਅੰਤ_ਪੌਇੰਟ 16개, Java 루프백 버퍼 1024바이트, 외부 TCP 버퍼 4096바이트다. DNS·TLS는 없다.

`JFrame`, `JPanel`, `JLabel`, `JButton`, `JTextField`, `ActionListener`, `ActionEvent`, `SwingUtilities.invokeLater`의 문서화한 부분집합을 네이티브 GUI에 연결했다. `setLayout(null)`과 명시적 좌표를 사용한다. 전체 OpenJDK Swing 또는 Java SE 호환 구현은 아니다. ਪਰਸਪਰਸਕ੍ਰਿਆਸ਼ੀਲ 이벤트 대기는 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 기한을 갱신하고 ਟਰਮੀਨਲ ਸਵਿੱਚ_ਮੋਡ 시 프로세스 상태를 ਸੰਭਾਲੋ_ਕੀਮਤ·복원한다. 이벤트 콜백 자체는 기존 바이트코드/CPU 기한을 따른다.

ਪੰਜਾਬੀ `ਵਿੰਡੋ`, `ਵਿਜੇਟ`, `연결통신` 클래스를 배포 JAR와 자체 JVM 내장 자원에 추가했다. 상세 ਮੈਥਡ_ਕੀਮਤ·제한·ਸਰੋਤ_ਟ੍ਰੀ·업로드 방법: [한글 개발 매뉴얼](개발안내.md).

## ਪੰਜਾਬੀ 객체의 직접 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼

`ਵਿੰਡੋ`, `ਲੇਬਲ`, `ਟੈਕਸਟ_ਖੇਤਰ`, `ਬਟਨ`, `ਇਵੈਂਟ_ਕਤਾਰ`, `동작알림`, `작업가닥`은
표준 GUI/Thread 객체를 보관하는 래퍼가 아니다. 자체 JVM의 ਔਬਜੈਕਟ_ਕੀਮਤ ਜਨਰੇਟ_ਕਰੋ,
ਸਰੂਪ_ਕੀਮਤ 검사, 화면 호출, ਇਵੈਂਟ 큐, ਥ੍ਰੈਡ_ਕੀਮਤ 스케줄러에 ਪੰਜਾਬੀ 계약을 직접 구현했다.
표준 `javax.swing`·`Thread` 코드의 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 경로도 유지한다.
ਪੰਜਾਬੀ 단추와 표준 JButton은 서로 다른 형식이며, 해당 instanceof 검사도 검증한다.

자체 실행기의 ਪੰਜਾਬੀ 진입점은 `public static void ਚਲਾਓ_2()`이다.
표준 `main(String[])`도 지원하며 둘 다 있으면 ਪੰਜਾਬੀ 진입점을 우선한다.
명령행 인수는 `실행인수.개수()`와 `실행인수.ਟੈਕਸਟ(순번)`으로 읽는다.
`example/java`의 다섯 예제는 이 규약을 사용한다. ਸਥਾਈ_ਕੀਮਤ ਫਾਇਲ 예제는 게스트
javac로도 컴파일하며, GUI/ਥ੍ਰੈਡ_ਕੀਮਤ 소스는 ਹੋਸਟ `javac --release 8`을 사용한다.
직접 GUI/ਥ੍ਰੈਡ_ਕੀਮਤ API는 자체 JVM 전용이다. 기존 OpenJDK 비교 시험과 별도로
ਪੰਜਾਬੀ 가닥의 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼·대기·중복 ਚਲਾਓ_2 거부, GUI ਇਵੈਂਟ 출처·ਅਨੁਕ੍ਰਮਣਿਕਾ·콜백을 검사한다.
전체 JDK 번역이나 모든 API의 jaot 지원을 뜻하지 않는다.

ਮੈਥਡ_ਕੀਮਤ 이름은 바이트코드에서도 유지된다. 이름과 참조를 같이 수정하면
ਪੰਜਾਬੀ 클래스도 실행되지만, ਨਿਰਭਰ_ਰਹਿਣ_ਵਾਲਾ_ਕੀਮਤ 리터럴·표준 ਪੁਸਤਕਾਲਾ 재정의·native
ਕੁਨੈਕਸ਼ਨ_ਕਰੋ·진입점은 각각 컴파일러와 실행기의 계약을 맞춰야 한다.
[상세 계약과 예제](한국어자바/ਫਈਲ_ਮੈਨੂੰ_ਪੜਨ_ਦਿਉ_eb81d7d9.md)를 참고한다.

## ਟਰਮੀਨਲ 부분 ਤਾਜ਼ਾ_ਕਰੋ

ਖਿਸਕਾਉਣਾ_ਕੀਮਤ·ਆਕਾਰ 변경은 새 ਵਿੰਡੋ 영역과 이전 자리에서 드러난 띠만 합성한다.
1920×32 ਬਿੰਦੂ(240 KiB)의 임시 그림에서 배경·겹친 ਵਿੰਡੋ·ਵਰਣ_ਕੀਮਤ·GUI를 먼저
완성하고, 현재 ਸ਼ੋਅ_ਕੀਮਤ 메모리와 비교하여 달라진 화소만 기록한다.
32줄보다 큰 영역은 여러 띠로 처리하므로 전체 프레임을 원자적으로
교체하거나 수직 동기에 맞추는 방식은 아니다. 전체 배경을 먼저 지우는
중간 화면은 표시하지 않는다. 좌표가 같으면 다시 그리지 않는다.

`make test-redraw`는 ਅਸਲ_ਸਮੱਗਰੀ C 그리기 코드를 호스트의 ਮੈਮਰੀ_ਸਮੱਗਰੀ 화면에 연결해
ਖਿਸਕਾਉਣਾ_ਕੀਮਤ 80회·ਆਕਾਰ ਬਦਲੋ_ਕੀਮਤ 40회·겹친 ਵਿੰਡੋ 4개를 전체 합성 결과와 ਬਿੰਦੂ 단위로 대조한다.
영역 밖 ਉਪਭੋਗਤਾ ਚਿੱਤਰ_ਬਨਾਉਣਾ_ਕੀਮਤ, 동일 ਬਿੰਦੂ 무기록, ਪੌਇੰਟਰ 밑그림, ਅਸਲ_ਸਮੱਗਰੀ 화면 ਲਾਈਨ 간격을
검사한다. 이 시험의 시간은 ਹੋਸਟ CPU 측정이며 Pi 4/QEMU 속도로 해석하지 않는다.
`make test-resize`는 QEMU/VNC의 640×480 및 1920×1080에서 왼쪽 모서리 ਖਿੱਚੋ_ਕੀਮਤ,
한글 입력·vi 미저장 ਤਤਕਰਾ_ਕੀਮਤ·독립 ਵਿੰਡੋ 크기를 검사한다.
