# свой ARM64 커널의 экран разрешение_ЗНАЧЕН

QEMU 실행 위치는 `jkoros/platforms/rpi4-native`다. 커널을 빌드한 BACK_ЗНАЧЕН 다음과 같이 실행한다.

```bash
make build
python3 инструменты/실행.py --desktop --network --resolution 1920x1080
```

Remmina의 **VNC** Подключить 주소는 `127.0.0.1:5902`다. 이미 실행 중인 VM은 종료하고 새 옵션으로 повторить_попытку_ЗНАЧЕН 시작한다. экран 전체가 보이지 않으면 Remmina에서 экран выровнять_граница 또는 전체 화면을 선택한다. 이 옵션은 게스트의 фактический_данные пиксель 수를 바꾼다.

`--resolution`은 일반 UART 실행, `--desktop`, `--vnc`, `--display`에서 동일하게 적용된다. `--network`와 함께 사용할 수 있다. 너비 640~1920, 높이 480~1080을 허용하며 기본값은 640×480이다. 1280×720과 1920×1080도 선택할 수 있다.

```bash
make desktop RESOLUTION=1920x1080
python3 инструменты/실행.py --resolution 1280x720 --vnc 127.0.0.1:2
```

запуск_машины 로그는 фактический_данные 할당된 크기를 표시한다.

```text
FRAMEBUFFER PASS 1920x1080 RGB32 (drawing only)
```

терминал 바탕과 위쪽 막대는 экран 전체를 채운다. 터미널은 право 아래까지 끌어서 이동하고 X로 닫을 수 있다. терминал Окно Размер(568×360)와 шрифт_ЗНАЧЕН 크기는 유지되므로 넓어진 화면에 여러 창을 배치할 수 있다. Swing 부분집합의 `setLocationRelativeTo(null)`도 фактический_данные экран 가운데를 사용한다. запуск_машины BACK_ЗНАЧЕН 해상도를 바꾸는 기능은 제공하지 않는다.

## 프로그램에서 экран Размер Чтение

| Язык | русский 호출 |
|---|---|
| Java | `русский.свой.экран.너비()`, `экран.높이()`, `экран.удалить_ввод_c8dbc399(색)` |
| C | `<экран_ABI.h>`의 `화면너비()`, `화면높이()`, `выписать_прямоугольник(...)` |
| C++ SDK | `호출.h`의 `화면너비읽기()`, `화면높이읽기()`, `экран_прямоугольник(...)` |
| Python | `from русский import экран_изменить_размер, выписать_прямоугольник`; `너비, 높이 = экран_изменить_размер()` |

C 함수는 макрос_ЗНАЧЕН 별칭이 아닌 фактический_данные 함수다. пространство_пользователя 호출 22로 크기를 조회하며, Paint_экран 호출 13과 GUI 호출 20은 фактический_данные экран 경계를 검사한다. 프레임버퍼 주소는 пространство_пользователя 프로그램에 노출하지 않는다. экран 밖의 요청은 오류를 반환한다.

게스트 `javac`에서는 `русский.свой.экран.너비()`처럼 전체 이름으로 호출한다. 지원하는 источник_дерево 문법에 맞춰 색상 상수는 십진수로 쓴다. 아래 호출은 запуск_машины 해상도와 관계없이 마지막 화소를 그린다.

```java
int 너비 = русский.свой.экран.너비();
int 높이 = русский.свой.экран.높이();
русский.свой.экран.прямоугольник(너비 - 1, 높이 - 1, 1, 1, 255);
```

`экран` 클래스의 프레임버퍼 호출은 свой JVM 전용이다. 이 API의 исключение Процесс_ЗНАЧЕН_ввод 시험은 узел `javac --release 8`로 컴파일한 class를 свой JVM에서 실행한다. 게스트 컴파일러의 일반적인 `try/catch` 문법 지원을 추가한 것은 아니다.

## Raspberry Pi 4 SD запуск_машины

```bash
make image RESOLUTION=1920x1080
```

생성되는 `dist/jkoros-native-rpi4.img`와 `dist/jkoros-native-rpi4-boot.zip`에 1080p 설정이 들어간다. SD фото_ЗНАЧЕН 생성은 640×480, 1280×720, 1920×1080을 지원한다. 이미 펼친 запуск_машины 파일을 수정할 경우 `config.txt`의 `[pi4]`에 아래 값을 사용한다.

```ini
max_framebuffer_width=1920
max_framebuffer_height=1080
framebuffer_width=1920
framebuffer_height=1080
hdmi_group=1
hdmi_mode=16
```

커널은 [Raspberry Pi почта сумма_контракта](https://github.com/raspberrypi/firmware/wiki/Mailbox-property-interface)의 текущий_товар экран Размер 조회와 экран выделить_Память 응답을 사용한다. 응답의 Размер·RGB32 формат_ЗНАЧЕН·한 줄의 байт_ЗНАЧЕН 수·выделить_Память 용량을 확인하고, 반환된 строка_ввода 간격으로 그린다. начальное_состояние 조회에 실패하거나 опора_ЗНАЧЕН 범위를 벗어나면 640×480을 요청한다. HDMI 설정은 [공식 펌웨어 экран Настройки 문서](https://www.raspberrypi.com/documentation/computers/legacy_config_txt.html)를 따른다. фактический_данные Pi 4와 모니터 조합에서의 HDMI 부팅은 아직 검증하지 않았다.
