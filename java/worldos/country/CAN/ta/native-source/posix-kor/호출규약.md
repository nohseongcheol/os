# பயனர் 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `இயந்திரம்/இயக்க_முறைமை_அழைப்புகள்.s`에서 EAX(அடைவு), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 செயலுருபுகள்)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. கரு_மதிப்பு 실패는 음수 பிழை அடைவு, C நூலகம் 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 பயனர் 영역 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C தரவு 주소는 பைட்_மதிப்பு 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java கோப்பின்_பெயர் 흐름의 어셈블리 경계가 별도 பைட்_மதிப்பு 버퍼를 마련하여 같은 호출을 사용한다.

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 முகவரி 두 칸이다. 수신 주소가 NULL이면 பியர்_மதிப்பு முகவரி 기록을 생략한다. sockaddr_in은 16바이트이며 முகவரி 체계는 சாதனம்_மதிப்பு பைட்_மதிப்பு 차례, 접속번호와 IP 주소는 네트워크 பைட்_மதிப்பு 차례다. 축소된 முகவரி 버퍼에도 들어가는 앞부분을 쓰고 전체 முகவரி அளவு 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 முடிவு_நிரல், 2·3은 기존 செயலுருபுகள் 조회다. 현재 커널의 செயலுருபுகள் 목록이 இயக்கு_கட்டளை 이름을 제외하므로 C 진입기는 argv[0]에 고정 சரம்_மதிப்பு `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX செயலகம்_மதிப்பு ABI와 다른 점이다.

표준 헤더의 முழு_எண் அளவு, 플래그 மதிப்பு, stat புலம்_மதிப்பு 순서는 `மூலக்_கோப்பு/포함/`에 정의한다. 동적 இணைக்க·다중 செயலகம்_மதிப்பு·스레드가 추가되면 பிழை அடைவு 저장과 வளம்_மதிப்பு 수명, 호출 경계도 함께 검토해야 한다.
