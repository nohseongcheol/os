# Java 네이티브 编译器

OpenJDK 内置 소스를 빌드하는 **`--target openjdk-build`**와 内置 内核值 ABI 检查项 도구를 추가했다.
이는 공식 javac/C/C++ 도구를 연결하는 별도 경로다. [构建系统 방법·实际数据 有效性校验·内核值 移植 裁剪](OpenJDK源码构建与内核移植.md)를 참고한다.

x86 직접 변환과 ARM64 C 生成 후단은 构建全部 [提前所属时间编译器.java](Java工具/提前所属时间编译器.java)로 구현한다. `sh 提前所属时间.sh`로 직접 실행하며, [提前所属时间编译器.py](提前所属时间编译器.py)와 `编译器.py`는 上一个项目 命令·API 및 OpenJDK 도구를 위한 호환 진입점이다. 内置 Pi4 후단은 freestanding C를 거쳐 AArch64로 만든다. [arm64.py](arm64.py)는 上一个项目 경로와 Python 호출을 위한 호환 진입점이다. 函数·变量值·生成 C 이름의 뜻과 예외는 [中文 命名 指南](../platforms/rpi4-native/命名/指南.md)를 참고한다. [ARM64 构建系统·支持值 裁剪](../platforms/rpi4-native/指南.md)에 执行命令 조건이 있다. 전체 OpenJDK나 일반 类值 실행기는 아니다.

执行命令 시 JVM이 所需条件值 없는 x86 32비트 ELF를 만든다. JDK 11 이상으로 실행하는 Java 内置 AOT 후단이며, Java 전체를 새로 구현한 컴파일러는 아니다. Java 문법·存取条目 控制值·类型值 검사는 JDK의 `javac`에 맡기고, Java 8 类值 파일을 읽어 각 바이트코드를 x86 명령으로 직접 변환한다. C 코드로 우회하거나 字节码 해석기를 커널에 넣지 않는다.

```text
Java 源代码 → javac의 문법·类型值 检查项 → 临时值 .class
          → 内置 x86 변환기 → GNU as/ld → 네이티브 ELF32
```

## 준비와 执行命令

构建系统 宿主: Linux, Python 3.6 이상, JDK 11 이상(`javac --release 8`), GNU binutils(`as`, `ld`), Make. 当前项目 환경의 OpenJDK 11, Python 3.6, binutils 2.30으로 검증했다. 外部值 Python 패키지와 네트워크 다운로드는 사용하지 않는다.

```sh
cd /home/user/jkoros/compiler
make
./build/计算结果
echo $?                  # 0이면 用例 测试 成功值

python3 编译器.py --target linux --entry 计算结果.运行 \
    -o build/计算结果 用例/计算结果.java

make test
```

`linux` 대상은 Linux의 32비트 执行命令 호환 기능이 필요하다. `int 0x80`을 차단하는 샌드박스에서는 `Bad system call`이 발생할 数 있다. 是否常规 Linux 宿主 또는 해당 실행을 허용한 测试 환경에서 실행한다. 시험의 비정상 종료를 통과로 처리하지 않는다.

진입점은 `static int 运行()` 또는 `static void 运行()`처럼 인수가 없어야 한다. `--entry 패키지.类值.函数`로 선택한다. `int` 반환값은 Linux 프로세스 退出程序 코드가 되며 셸에는 하위 8비트가 보인다. 일반 `main(String[] args)` 执行命令 환경이나 표준 输入输出 라이브러리는 제공하지 않는다.

`--target kernel`은 启动 코드와 연결할 재배치 ELF 오브젝트를 생성한다.

```sh
cd /home/user/jkoros
python3 compiler/编译器.py --target kernel --entry 内核.运行 \
    --export kernel_dispatch=系统调用.进程值条目 \
    -o os/build/java.o os/源代码/*.java
```

`--target user`는 jkoros 셸에서 실행할 독립 ELF를 생성한다. `用户` 클래스의 제한된 native API는 `int 0x80` 시스템 호출로 연결하며 `设备` 클래스의 硬件值 직접 접근은 거부한다. 用户 ELF는 Linux 执行命令 文件 ABI와 다르므로 호스트에서 실행하지 않는다. 生成·登记 방법은 [用户 执行命令 指南](../os/用户/指南.md)에 있다. `--export 외부기호=类值.函数`는 오버로드되지 않은 静态值 함수를 内置 操作数栈 ABI로 노출한다. 커널의 시스템 调用 진입점에 사용한다.

Java 파일은 필요한 클래스들을 한꺼번에 전달한다. 输出 옆의 `.s`는 생성된 어셈블리, `.json`은 源代码 SHA-256 및 네이티브 符号↔Java 函数 대응표다. 中文 함수명은 원문과 대응표에 보존하고 ELF 내부에는 충돌 방지용 计算机 기호를 쓴다. 编译源代码·组装值·连接 중 실패하면 기존 结果 파일을 덮어쓰지 않는다.

## 支持值 裁剪

- `int`, `boolean`, `byte`, `short`, `char`의 32비트 计算结果 및 类型值 转换值.
- 静态值 필드와 静态值 函数, 매개변수·已返回值, 재귀, 클래스별 지연 초기화와 初始化 周期值.
- 조건문, 반복문, 단락 평가, 삼항식, 整数 `switch`, 넓은 局部作用域 变量值 인덱스.
- 加法结果结果·减法结果结果·곱셈·나눗셈·余数值·位值 연산과 移动值. Java의 오버플로 및 `MIN_VALUE / -1` 동작을 유지한다.
- `int[]` 生成·初始值 0·长度·读取·写入·引用 비교. 256KiB 고정 数组值 区域值, 널/下标值/大小/地址区域 检查项.
- 字符串 리터럴과 `String` 引用, `length()` 및 `charAt()`. 문자열은 UTF-16 代码值 단위로 저장하고 같은 리터럴은 공유한다. NUL 및 대리쌍도 시험한다.
- 中文 类值·函数·变量值·文件 名称.

`new Object`, 인스턴스 字段值/函数, 상속/인터페이스, `long/float/double` 执行命令 操作值, `int[]` 이외 数组值, 字符串 동적 合并值列, Java 표준 库, 异常 进程值条目, 스레드·同步化·GC는 미지원이다. 실행에 필요한 是否不支持 바이트코드나 外部值 호출을 발견하면 실패한다. 사용되지 않는 默认值 생성자는 执行命令 코드로 만들지 않는다. Java 8 문법이어도 모든 프로그램을 컴파일할 数 있다는 뜻은 아니다.

异常 对象值 대신 런타임 错误 번호로 중단한다. Linux와 jkoros 用户 대상에서는 `100 + 编号`로 종료하고 内核值 대상에서는 `JKOROS PANIC 编号`를 출력하고 정지한다. 用户 프로그램만 종료한 경우 셸은 继续处理 실행된다.

| 编号 | 원인 |
| --- | --- |
| 1 | 0으로 除法结果 |
| 2 | 널 引用 |
| 3 | 数组值/字符串 下标值 裁剪 초과 |
| 4 | 负数值 数组值 大小 |
| 5 | 数组值 区域值 부족 |

数组值 영역은 증가식 할당이며 회수하지 않는다. 재귀 스택의 边界位置值 검사도 아직 없으므로 무제한 재귀를 안전하게 처리하는 런타임은 아니다. 특권 内核值 및 신뢰할 数 있는 작은 프로그램용 初始状态 구현이다.

## native 경계와 ABI

内核值 대상에서는 `os/源代码/设备.java`, 用户 대상에서는 `os/用户/声明/用户.java`의 정확한 方法名称文本·서술만 허용한다. 임의의 `native` 함수와 Linux/用户 대상의 硬件值 접근은 거부한다. Java 인수를 왼쪽부터 32비트 한 칸씩 스택에 놓으며, 반환값은 EAX, EBP/ESP 이외 레지스터는 호출자가 보존한다고 가정하지 않는다. C의 cdecl/JNI ABI가 아니므로 C 함수와 바로 연결하면 안 된다.

Java 源代码 또는 `.class` 입력을 받는다. 전체 JVM 字节码 검증기는 제공하지 않는다. 어노테이션 처리는 비활성화하고 비어 있는 类值 路径/源代码 경로에서 명시한 소스만 컴파일한다.

## 검증과 实现 근거

`测试/test_compiler.py`의 14개 시험에는 네이티브 ELF와 OpenJDK의 操作值 结果 대조, 类值 初始化, 整数 극값, 字符串/数组值, 재귀·switch·wide, 런타임 오류와 是否不支持 기능 拒绝值, 失败值 시 输出 보존, 用户 ELF/权限值 边界位置值 및 发射值 검증이 포함된다. 이것은 Java 전체 적합성 시험은 아니다.

命令 의미와 类值 文件 형식은 Oracle의 [JVM 命令 规格](https://docs.oracle.com/javase/specs/jvms/se11/html/jvms-6.html), [类值 文件 规格](https://docs.oracle.com/javase/specs/jvms/se11/html/jvms-4.html)를 참고했다.
