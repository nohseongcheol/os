# ئىشلەتكۈچى 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `ماشىنا/مەشغۇلات_سىستېمىسى_تېلېفون.s`에서 EAX(ئىندېكس), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 ئۆزگەرگۈچىلەر)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. يادرو_قىممىتى 실패는 음수 خاتالىق ئىندېكس, C ئامبار 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 ئىشلەتكۈچى 영역 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C مەلۇمات 주소는 بايت_قىممىتى 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java ھۆججەت 흐름의 어셈블리 경계가 별도 بايت_قىممىتى 버퍼를 마련하여 같은 호출을 사용한다.

| 32 | يازماق_ھۆججەت_مەلۇمات | 서술자, مەلۇمات ئادرېس, بايت_قىممىتى 수 |
| 33 | ئاياغ_ھۆججەت | 서술자 |
| 34 | ئىزدەش_ھۆججەت | 서술자, كودىلاش_قىممىتى 있는 ئاغما_قىممىتى, كۆرسىتىش_يىلتىز |
| 35 | 파일서술자복제 | 서술자 |

| 41 | 통신종단점만들기 | ئادرېس مەشغۇلات_سىستېمىسى_قىممىتى, 종류, خىزمەت_قىممىتى ئىندېكس |

| 44 | 자료전문받기 | 서술자, مەلۇمات ئادرېس, ئۇزۇنلۇق_قىممىتى, تەڭشەكلەر, 요청 ئادرېس |
| 45 | 통신주소읽기 | 서술자, sockaddr ئادرېس, socklen_t ئادرېس |
| 46 | 수신대기정하기 | 서술자, 0~2000 밀리초 |
| 47 | 파일저장확정 | 서술자 |

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 ئادرېس 두 칸이다. 수신 주소가 NULL이면 باراۋەرلىك_قىممىتى ئادرېس 기록을 생략한다. sockaddr_in은 16바이트이며 ئادرېس 체계는 كۆچمە_قىممىتى بايت_قىممىتى 차례, 접속번호와 IP 주소는 네트워크 بايت_قىممىتى 차례다. 축소된 ئادرېس 버퍼에도 들어가는 앞부분을 쓰고 전체 ئادرېس چوڭلۇقى 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 چىقىش_ئەپ, 2·3은 기존 ئۆزگەرگۈچىلەر 조회다. 현재 커널의 ئۆزگەرگۈچىلەر 목록이 ئىجرا_قىلىش_بۇيرۇق 이름을 제외하므로 C 진입기는 argv[0]에 고정 ھەرپ_تىزمىسى_قىممىتى `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX جەريان_قىممىتى ABI와 다른 점이다.

표준 헤더의 پۈتۈن_سان چوڭلۇقى, 플래그 قىممىتى, stat بۆلەك_قىممىتى_0f39cf1c 순서는 `مەنبە/포함/`에 정의한다. 동적 ئۇلا·다중 جەريان_قىممىتى·스레드가 추가되면 خاتالىق ئىندېكس 저장과 مەنبە_قىممىتى 수명, 호출 경계도 함께 검토해야 한다.
