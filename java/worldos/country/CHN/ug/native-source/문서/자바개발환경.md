# jkoros 안에서 Java قۇرماق_مەنبە·ئىجرا_قىلىش_بۇيرۇق

이 문서의 부팅·قاپ·ساقلىماق_قىممىتى 명령은 **x86 نەشىر_نومۇرى_قىممىتى** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 نەشىر_نومۇرى_قىممىتى](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 ھۆججەت_نامى_تېكست, `edit`의 단독 `.` ساقلىماق_قىممىتى, 16개 RAM ھۆججەت, 약 2초 ئىجرا_قىلىش_بۇيرۇق 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 ھەقىقىي_مەلۇمات JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. باقار قۇرماق_مەنبە 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java ئەپ_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 ئىجرا_قىلىش_بۇيرۇق

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. ئىجرا_قىلىش_بۇيرۇق 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox ئىجرا_قىلىش_بۇيرۇق چۈشەندۈرۈش_ھۆججىتى_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 ھۆججەت 전체를 새 내용으로 작성한다. 기존 내용의 قۇر تەھرىرلەش_قىممىتى 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 بايت_قىممىتى 수 كۆرسەتمەك_قىممىتى.
- `cat FILE`: ھۆججەت مەزمۇن_قىممىتى كۆرسەتمەك_قىممىتى. 텍스트 소스에 사용한다.
- `rm FILE`: ساقلىغۇچ_مەلۇمات ھۆججەت 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·تىپ_قىممىتى 검사 مەغلۇپ_بولۇش_قىممىتى 시 기존 `.class`는 유지된다. 소스를 고친 ئارقىغا_قىممىتى 컴파일이 실패했다면 이전 ئىجرا_قىلىش_بۇيرۇق 파일이 남아 있으므로 قۇرماق_مەنبە 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 ساقلىماق_قىممىتى 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 مەنبە_دەرەخ·تۈركۈم_قىممىتى·مەلۇمات 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, ھۆججەت 이름은 ASCII 1~63자다. مەنبە_دەرەخ 이름은 `.class` 확장자 공간 때문에 최대 62자다. تەھرىرلەش_قىممىتى 입력은 ASCII이고 한 قۇر 최대 128자다. قۇر 또는 ھۆججەت 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. يادرو_قىممىتى/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 ئىشلەتكۈچى 예제 이름은 ASCII로 작성한다.

## 외부 ھۆججەت 적재

호스트에서 만든 소스나 قوللاش_قىممىتى كەسمە 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 ھەقىقىي_مەلۇمات 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# باقار JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 كېيىنكى_تۈر 빌드에서는 추가 파일을 포함하지 않는다. ھۆججەت مەزمۇن_قىممىتى 변경과 كىرگۈزۈش_تىزىم 제거도 كېيىنكى_تۈر 빌드에 반영된다. 원본 باقار 파일에는 쓰지 않는다. سۈكۈتتىكى_قىممەت `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 سۈكۈتتىكى_قىممەت 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 تۈركۈم_قىممىتى ھۆججەت 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 قوللاش_قىممىتى كەسمە 안에 있어야 한다.

## قوللاش_قىممىتى كەسمە

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| تۈركۈم_قىممىتى | 패키지 없는 단일 تۈركۈم_قىممىتى, ئىستاتىك_قىممىتى فۇنكسىيە_قىممىتى, 재귀, ئۆزگەرگۈچىلەر/قايتۇرۇپ_بېرىش_ئۆلچەم | 실행마다 단일 تۈركۈم_قىممىتى 적재, public static main(String[]) |
| سۈكۈتتىكى_قىممەت قىممىتى | int, boolean, char, String, main의 String[] ئۆزگەرگۈچىلەر | پۈتۈن_سان·پايدىلانما 스택, String, int[], String[], 내부 StringBuilder |
| جۈملە_قىممىتى | 초기값 있는 يەرلىك_بوشلۇق 선언, ۋەزىپە_قىممىتى, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 پۈتۈن_سان·پايدىلانما 바이트코드와 شەرت شاخ |
| ئىپادە_قىممىتى | 십진 پۈتۈن_سان, UTF-8 소스의 ھەرپ_تىزمىسى_قىممىتى/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, ھەرپ_تىزمىسى_قىممىتى 결합 | پۈتۈن_سان مەشغۇلات_قىممىتى·بىت_قىممىتى مەشغۇلات_قىممىتى·تىپ_قىممىتى 변환, 단락 평가, رەت_قىممىتى زىيارەت_كىرگۈزۈش |
| ھۆججەت | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | ھەقىقىي_مەلۇمات يادرو_قىممىتى 파일서술자와 ئۇلا, ھاسىل_قىلىش·تازىلىماق_مۇندەرىجە·이어쓰기·EOF |
| چىقار | System.out.print/println: int/boolean/char/String, println() | 동일 |
| ھەرپ_تىزمىسى_قىممىتى/ئۆزگەرگۈچىلەر | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), ھەرپ_تىزمىسى_قىممىتى 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 يەرلىك_بوشلۇق 선언, 오버로드, 임의 تىپ_قىممىتى 변환, رەت_قىممىتى ھاسىل_قىلىش مەنبە, 8/16진 리터럴, Unicode مەنبە_دەرەخ 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 تۇراقلىق_مىقدار_قىممىتى 축소 변환을 구현하지 않는다. 외부 `.class`의 `int[]` ھاسىل_قىلىش/ئوقۇ/쓰기는 지원하므로 باقار `javac --release 8`로 만든 رەت_قىممىتى 예제는 실행할 수 있다.

ئوبيېكت_قىممىتى بۆلەك_قىممىتى_0f39cf1c·일반 ئوبيېكت_قىممىتى ھاسىل_قىلىش·상속·인터페이스·여러 تۈركۈم_قىممىتى ئۇلا, long/float/double, 예외 جەريان_قىممىتى_كىرگۈزۈش, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java 예외 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 ھەرپ_تىزمىسى_قىممىتى ساقلىماق_قىممىتى 공간은 ئىجرا_قىلىش_بۇيرۇق چىقىش_ئەپ 시 ئىشلەتكۈچى 영역 전체와 함께 회수한다. 지속 ئىجرا_قىلىش_بۇيرۇق 중 GC는 없다.

## ئىجرا_قىلىش_بۇيرۇق 한도와 خاتالىق

| مەنبە_قىممىتى | 한도 |
| --- | --- |
| مەنبە_دەرەخ/تۈركۈم_قىممىتى ھۆججەت | 각각 16KiB |
| 컴파일러 | ئالدىن_تۆلەش_كارتىسى_كودى_قىممىتى 2,047개, ھاسىل_قىلىش 코드 4KiB, تۇراقلىق_مىقدار_قىممىتى 풀 4KiB |
| فۇنكسىيە_قىممىتى/ئۆزگەرگۈچىلەر | 클래스당 32함수, 함수당 16인수 |
| JVM تۇراقلىق_مىقدار_قىممىتى | 511개 |
| JVM فۇنكسىيە_قىممىتى 코드 | 함수당 8KiB |
| JVM 호출/스택/يەرلىك_بوشلۇق 변수 | 32프레임, 프레임당 스택 128칸·يەرلىك_بوشلۇق 128칸 |
| JVM ئوبيېكت_قىممىتى ساقلىماق_قىممىتى 공간 | 8,192개 32비트 ئوقۇر_كىرگۈزۈش, 헤더 포함 약 32KiB |
| ئىجرا_قىلىش_بۇيرۇق | 최대 500,000 بۇيرۇق, 기존 커널의 약 3초 CPU ئىجرا_قىلىش_بۇيرۇق 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 قوللاش_قىممىتى 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM لۇغەت 검증기를 구현한 것은 아니다. ھۆججەت/خاسلىق_قىممىتى ئۇزۇنلۇق_قىممىتى, تۇراقلىق_مىقدار_قىممىتى پايدىلانما, بۇيرۇق·شاخ 경계를 검사하고, ئىجرا_قىلىش_بۇيرۇق 중 스택 فورمات_قىممىتى·يەرلىك_بوشلۇق دەسلەپلەشتۈرمەك·رەت_قىممىتى تۆۋەن_ئىندېكس_قىممىتى·ئوبيېكت_قىممىتى 참조를 검사한다. ئىشلەتكۈچى 코드의 페이지·قاتتىق_دېتال_ئېغىز 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, قۇرماق_مەنبە·JVM 오류는 `Exit: 1`, بۇيرۇق ئۆزگەرگۈچىلەر 오류는 `Exit: 2`다. CPU 시간 상한은 기존 `Exit: 124`이며, ئىشلەتكۈچى ELF 자체의 CPU/런타임 오류는 기존 چىقىش_ئەپ 코드를 따른다. مەغلۇپ_بولۇش_قىممىتى 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## 구현 위치와 시험

- `os/ئىشلەتكۈچى/자바/자바컴파일러.java`: 게스트 어휘·구문·تىپ_قىممىتى 검사, تۇراقلىق_مىقدار_قىممىتى 풀 및 바이트코드 ھاسىل_قىلىش.
- `os/ئىشلەتكۈچى/자바/자바가상기계.java`: تۈركۈم_قىممىتى 적재, 스택·프레임·ئوبيېكت_قىممىتى ساقلىماق_قىممىتى, بۇيرۇق 해석과 제한된 표준 호출.
- `os/مەنبە/ساقلىغۇچ_ھۆججەت_سىستېمىسى.java`: ساقلىغۇچ_مەلۇمات ھۆججەت_سىستېمىسى, تەھرىرلەش_قىممىتى, 부팅 ھۆججەت 적재.
- `os/مەنبە/체계호출.java`, `compiler/باشلاش_ئىشلەتكۈچى_ئەپ.s`: ھۆججەت/문자 چىقار API와 ئىشلەتكۈچى ئىسترېلكا 검사.
- `os/قوراللار/자바파일묶기.py`: باقار 입력 ھۆججەت دەلىللەش·부팅 توپ_قىممىتى ھاسىل_قىلىش.

```sh
make test-java
make test
```

`os/시험/자바시험.py`는 ELF/ISO 부팅, 게스트 قۇرماق_مەنبە·ئىجرا_قىلىش_بۇيرۇق, ئىشلەتكۈچى 입력, 재귀·반복문·پۈتۈن_سان 극값·ھەرپ_تىزمىسى_قىممىتى 결합·단락 평가, 재실행, مەنبە_دەرەخ خاتالىق 후 기존 تۈركۈم_قىممىتى 보존, رەت_قىممىتى/수 해독 خاتالىق, 무한 ئېنتىراتسىيە_قىممىتى 제한, تەھرىرلەش_قىممىتى 넘침과 ھۆججەت 부족을 검사한다. 게스트 ھاسىل_قىلىش 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 باقار OpenJDK의 تۈركۈم_قىممىتى, پۈتۈن_سان 배열과 한글 상수를 게스트에 적재하며, 손상된 ھۆججەت 표식·버전·تۇراقلىق_مىقدار_قىممىتى 수·شاخ·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 시험 VM만 생성하고 종료한다.

구현 형식의 참고 مەلۇمات: Oracle [JVM تۈركۈم_قىممىتى ھۆججەت 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM بۇيرۇق 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java ھۆججەت 입출력

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 تۈركۈم_قىممىتى 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 ئارقىغا_قىممىتى `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. سۈكۈتتىكى_قىممەت چىقار 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. 예외 ئوبيېكت_قىممىتى·try/catch·try-with-resources는 지원하지 않으며 ھۆججەت 오류를 진단하고 프로그램을 종료한다. رەت_قىممىتى 입출력, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 ھۆججەت 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 قاپ `sync`가 필요하다. 예제의 ھۆججەت 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 ھەقىقىي_مەلۇمات 게스트 قۇرماق_مەنبە 결과를 OpenJDK `-Xverify:all`로 다시 실행해 ھۆججەت 바이트와 출력을 대조한다. 범위와 ساقلىماق_قىممىتى مېدىيا_قىممىتى 사용법은 [posix-kor چۈشەندۈرۈش_ھۆججىتى_eb81d7d9](../posix-kor/چۈشەندۈرۈش_ھۆججىتى_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
