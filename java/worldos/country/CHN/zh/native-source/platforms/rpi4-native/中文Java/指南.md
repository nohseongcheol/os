# 中文 Java 通信·输入输出·异常 API

패키지는 `中文.内置`第三操作数. 宿主 `javac --release 8`로 컴파일한 class를
内置 ARM64 커널의 JVM에서 실행한다. 通信·文件·异常 API는 OpenJDK와 대조한다. 아래의 직접 구현한 屏幕·任务 线程值 API는 内置 JVM 전용이다.
기존 표준 Java 库 전체의 中文 번역판은 아니다.

```java
import 中文.内置.*;

public class 使用网络 {
    public static void main(String[] 实参) throws 输入输出异常 {
        连接通道 连接 = 连接通道.打开("10.0.2.2", 9000);
        try {
            连接.超时(700);
            连接.输出().写入(字符.编码("안녕하세요\n"));
            输入流 输入值 = 连接.输入值();
            输出.写入编号(输入值.读取());
        } catch (等待状态超时异常 错误) {
            输出.写入行(错误.说明());
        } finally {
            连接.关闭();
        }
    }
}
```

`Socket`, `getOutputStream`, `write`, `getInputStream`, `read`, `close`를
用户 예제에서 직접 호출할 필요가 없다. `try/catch/throws` 등 Java 문법은 유지한다. `String`은 예약어가 아니라 javac가 字符串 리터럴에 사용하는 표준 클래스다. 内置 실행기는 `public static void 运行()`도 진입점으로 받는다.

## 통신과 流值

| 类值 | 中文 调用 |
|---|---|
| 连接通道 | `打开(地址, 端口编号)`, `输入值()`, `输出()`, `超时(毫秒)`, `端口编号()`, `局部端口编号()`, `已连接()`, `是否已关闭()`, `关闭()` |
| 接收端口 | `打开(端口编号)`, `接收()`, `端口编号()`, `超时(毫秒)`, `是否已关闭()`, `关闭()` |
| 输入流 | `读取()`, `读取(byte[])`, `读取(byte[], 运行, 长度)`, `关闭()` |
| 输出流 | `写入(int)`, `写入(byte[])`, `写入(byte[], 运行, 长度)`, `发射值()`, `关闭()` |
| 数据报信道 | `打开(端口编号)`, `发送(地址, 端口编号, 文本)`, `接收()`, `超时(毫秒)`, `端口编号()`, `是否已关闭()`, `关闭()` |
| 连接状态传输 | `打开(...)`, `打开接收者(...)`는 顶端值 中文 객체를 发回结果 |
| 检查项 | `确认真值(条件, 原因值)` |

TCP 입력은 한 번에 요청한 모든 바이트가 도착한다고 가정하지 않는다.
`读取()`의 文件 끝은 -1, 数组值 읽기의 반환값은 实际数据 읽은 길이다.
네트워크 흐름을 닫으면 연결도 닫힌다. 端口编号 0은 빈 번호를 자동 배정한다.
UDP 전문은 当前项目 内置 커널에서 512바이트까지 받으며, 주소는 数字值 IPv4를 사용한다.
`localhost` 루프백 외의 名称 풀이(DNS)는 内置 커널에 아직 없다.

기존 `连接状态传输.连接/侦听端点/接收`, `通信.打开/发送/接收`는 표준 Java 객체를
사용하던 코드와의 연결용이다. 새 코드는 `连接通道`, `接收端口`, `数据报信道`를 쓴다.

## 中文 异常

모든 底端值 클래스는 默认值 생성자, `새예외("说明")` 형태의 字符串 생성자와
`说明()`을 제공한다. 实际数据 生成 문법은 `new 等待状态超时异常("等待状态状态 结尾")`이다.

| 中文 异常 | 상위 类值 / 용도 |
|---|---|
| 异常 | `java.lang.Exception`, 직접 던지는 일반 检查项 异常 |
| 执行状态异常 | `java.lang.RuntimeException` |
| 输入输出异常 | `java.io.IOException`, 中文 文件·通信 API의 检查项 异常 |
| 等待状态超时异常 | `输入输出异常`, 通信 超时 초과 |
| 地址查找异常 | `输入输出异常`, 地址 验证 失败值 |
| 缺失文件异常 | `输入输出异常`, 文件 打开 失败值 |
| 通信异常 | `输入输出异常`, 표준 SocketException 转换值 |
| 无效参数异常 | `java.lang.IllegalArgumentException` |
| 编号格式失败 | `无效参数异常` |
| 边界异常 | `java.lang.IndexOutOfBoundsException` |
| 数组边界异常 / 字符串边界异常 | `边界异常` |
| 空引用引用异常 | `java.lang.NullPointerException` |
| 算术失败 | `java.lang.ArithmeticException` |
| 状态异常 | `java.lang.IllegalStateException` |
| 类型类型转换异常 | `java.lang.ClassCastException` |
| 负数数组大小失败 | `java.lang.NegativeArraySizeException` |
| 数组存储失败 | `java.lang.ArrayStoreException` |
| 线程状态异常 | `java.lang.IllegalThreadStateException` |
| 等待状态已中断异常 | `java.lang.InterruptedException`, `任务.等待`의 等待状态值 중단 |

`异常`와 `执行状态异常`는 모든 中文 예외의 公用值 부모가 아니다. 顶端值 상속 관계를
사용하며, 文件·通信 전체를 잡으려면 `catch (输入输出异常 错误)`를 쓴다.
中文 API가 표준 输入输出 오류를 中文 예외로 변환한다.
기존 中文 通信 호출에서 `SocketTimeoutException`을 잡던 코드는
`等待状态超时异常`를 잡도록 옮긴다. 표준 `java.net`을 직접 사용하는 코드의
异常 유형은 기존 Java 규약을 따른다.
일반 Java 연산이 자동으로 던지는 표준 예외까지 이름을 바꾸지는 않는다.
예를 들어 `1 / 0`의 ArithmeticException과 직접 만든 산술예외는 서로 다른 형식이다.
当前项目 内置 JVM에 이 20종을 추가했다. 임의의 用户 Throwable 하위 类值 전체를
지원하도록 확장했다는 뜻은 아니다.

## 编译源代码·执行命令

```sh
cd /home/user/jkoros/platforms/rpi4-native
make 构建系统
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/한국어사용 测试/Java/测试韩语联网.java
python3 工具集/执行文件.py build/한국어사용/测试韩语联网.class
make test-jvm
```

내장 라이브러리는 用户 JVM ELF 안에 탑재된다. `.jar`는 宿主 javac의
类值 경로로 사용한다. 源代码树 묶음은 `dist/jkoros-native-korean-sources.zip`이다.
게스트의 제한형 `javac`는 中文 예외의 `throws` 선언과 그 import를 인식한다.
内置 JVM의 Thread.interrupt 동작을 새로 구현한 것은 아니다.
try/catch·对象值·套接字值 用例 전체의 源代码树 컴파일은 宿主 javac를 사용한다.
`/example/java/文件例.java`는 게스트 javac로도 컴파일할 数 있다.

实际数据 TCP/UDP 예제는 [网络例.java](../../../example/java/网络例.java),
执行命令 절차는 [example 指南](../../../example/README.md),
源代码树 命名 원칙은 [命名 指南](../命名/指南.md)에 있다.

## Swing 窗口 用例

`/example/java/窗口例.java`와 컴파일된 `.class`首位操作数 启动 시 준비된다.
`cd /example/java` 下一项目 `java 窗口例`로 연다. 名称 输入值, 问候 버튼,
인사말과 单击值 重复状态个数 刷新, X 닫기를 지원한다.

| 기능 | 中文 직접 API |
|---|---|
| Runnable / run | `可运行任务任务.执行任务()` |
| ActionListener / actionPerformed | `动作接收者.接收动作(动作通知 通知)` |
| ActionEvent | `动作通知.命令文本()`, `事件源代码()`, `编号()` |
| JFrame | `窗口(窗口标题, 宽度跨度, 高度值)`, `添加元素(屏幕元素)`, `显示窗口()`, `关闭()`, `是否可见()` |
| JButton | `按钮(文本, 水平位置, 垂直位置, 宽度跨度, 高度值, 接收者值)`, `设定动作接收者(接收者值)` |
| JLabel / JTextField | `标签(...)`, `文本字段(...)` |
| 公用值 屏幕 元素值 | `屏幕元素.读取文本()`, `写入文本(文本)`, `设定边界(水平位置, 垂直位置, 宽度跨度, 高度值)` |
| SwingUtilities.invokeLater | `事件排队.调用稍后(可运行任务任务)`, `是否事件分派中()` |
| Thread | `后台任务(可运行任务任务)`, `开始任务()`, `等待()`, `是否存活()`, `挂起任务()` |
| 명령행 | `运行()`, `运行参数.项目个数()`, `运行参数.文本(序数索引)` |

顶端值 클래스들은 `JButton`·`Thread` 등의 객체를 만들거나 보관하지 않는다.
内置 JVM의 `调用韩语屏幕`, `进程线程`首位操作数 中文 类值·方法值·서술자를
해석해 屏幕 요소와 执行命令 가닥을 직접 만든다. 动作 알림도 内置 객체이며
콜백으로 `执行任务`와 `接收动作`를 직접 찾는다. 표준 Swing/Thread를
사용하는 기존 프로그램의 执行命令 경로는 별도로 남아 있다.

Java 소스의 `native` 선언은 内置 JVM에 구현한 계약이다. 생성자의 예외는
이 계약이 없는 宿主 JVM에서 무동작 객체가 생기지 않도록 하는 拒绝值 경로다.
内置 JVM은 생성자를 직접 처리한다. 일반 OpenJDK에서는 이 직접 实现 API를
실행할 数 없다. 宿主 javac로 컴파일한 后端值 内置 JVM에서 실행한다.
`StringUtilities`라는 표준 Swing 클래스는 없으며, 屏幕 큐 기능은 `SwingUtilities`에 해당한다.

```java
import 中文.内置.*;
public class 가닥예제 implements 可运行任务任务 {
    public void 执行任务() { 输出.写入行("中文 任务 执行命令"); }
    public static void 运行() throws 等待状态已中断异常 {
        后台任务 线程值 = 任务.运行(new 가닥예제());
        任务.等待(线程值);
    }
}
```

`example/java`의 다섯 소스는 已保留位单词列·리터럴 외 식별자를 한국어로 작성한다.
数组值 实参 대신 `运行参数`, 길이는 `字符.字节个数`를 사용한다.
표준 Java의 `main(String[])`도 继续处理 지원한다. 二值 第三操作数 정의되어 있으면
内置 실행기는 实参 없는 `运行()`을 우선한다.
기존 中文 屏幕 래퍼의 표준 `Component`/`Runnable`/`ActionListener` 인수와
`任务.运行(Runnable)`을 사용하던 코드는 새 中文 계약으로 수정하고 재컴파일한다.
이는 전체 AWT/Swing·Thread API 支持值 또는 모든 JDK 소스의 번역을 뜻하지 않는다.

바이트코드에도 类值·方法值 이름과 서술자가 남는다.
中文 名称 자체는 합법이지만, 다른 클래스에서 그 이름을 참조하는 子部分值,
상속·方法值 재정의, native 连接, 런처의 진입점도 함께 맞춰야 한다.
근거는 [JLS 标识符值](https://docs.oracle.com/javase/specs/jls/se25/html/jls-3.html#jls-3.8)와
[JVMS 方法值 引用](https://docs.oracle.com/javase/specs/jvms/se25/html/jvms-4.html#jvms-4.4.2)第三操作数.
