# 内置 커널에서 vi·여러 终端·韩文文本 프로그래밍 사용하기

中文 通信·异常 사용법은 [中文 Java API](中文Java/指南.md), 函数·变量值·文件 이름의 변경과 어원 근거는 [命名 指南](命名/指南.md)를 참고한다.

대상은 `platforms/rpi4-native`의 内置 AArch64 Java 커널이다. vi와 Java/Python/C/C++ 프로그램은 EL0에서 실행한다. Linux 실행판과 별도이며 底端值 支持值 목록은 전체 OpenJDK·Vim·POSIX 구현을 뜻하지 않는다.

게스트 `cc`/`jaot`, JAR 직접 执行命令, 外部值 TCP/UDP와 FTP는 [새 执行命令 매뉴얼](文件传送与编译过程.md)을 참고한다.

## GUI와 여러 终端

```sh
cd /home/user/jkoros/platforms/rpi4-native
make desktop
```

Remmina에서 **VNC**, 地址 **127.0.0.1:5902**로 연결한다. 屏幕 顶端值 **+ New terminal**, **Ctrl+Shift+T**로 터미널을 추가한다. 最大值 네 개다. 上位侧侧 终端 버튼 또는 창을 클릭해 선택하고 **F6**으로 순환한다. 제목줄을 끌어서 옮기고 **右 顶端值 X**를 클릭하면 닫힌다. 最后项目 창을 닫아도 上位侧侧 执行命令 버튼으로 重试值 列值 数 있다. 기존 `terminal`, `exit`, F12도 사용할 数 있다.

창마다 当前项目 디렉터리, 命令壳 变量值, 命令 日志记录, 输入值 중인 명령과 程序 执行命令 상태를 보관한다. 文件 저장소는 공유한다. vi와 Swing의 이벤트 等待状态值 중에 다른 터미널로 전환하면 用户 内存数据·레지스터·文件/套接字值 연결을 보존했다가 돌아올 때 재개한다. **当前项目 네 프로그램이 동시에 CPU에서 실행되는 선점형 스케줄러는 아니다.** 计算结果 중인 프로그램은 下一项目 输入值 等待状态值 또는 기존 执行命令 기한까지 전환이 지연될 数 있다.

X로 터미널을 닫으면 그 터미널의 执行命令 중인 프로그램도 종료하며 描述符条目·소켓을 회수한다. 저장하지 않은 编辑值 내용은 사라진다. 종료한 슬롯은 새 창에서 재사용한다. 当前项目 모든 파일은 RAM에 있으며 VM 재시작 후에는 남지 않는다.

화면과 窗口 판단은 게스트 커널이 처리한다. QEMU 执行命令 도구는 VNC 키와 마우스 좌표를 UART 패킷으로 전달한다. 实际数据 Pi4 USB 입력기와 物理硬件 부팅은 아직 검증하지 않았다. 일반 UART 셸은 `make run`, GUI 工具集 종료는 宿主 터미널의 Ctrl+C다.

## vi 使用值

```text
mkdir 任务
cd 任务
vi 问候例.py
```

`vi`는 새로 구현한 **vi 命令 부분집합** 편집기다. 내장 `build/user/vi.elf`를 보호된 用户 영역에 적재한다. 文件 크기는 UTF-8 字节值 项目根 16 KiB, 경로는 63바이트까지다. 디스크에 설치한 Vim/Neovim 바이너리를 실행하는 것이 아니다.

| 键值/命令 | 动作 |
|---|---|
| `i`, `a`, `I`, `A` | 当前项目/下一项目 位置 또는 行 初始项目/끝에서 输入值 |
| `o`, `O` | 底端值/위에 새 줄을 만들고 输入值 |
| Esc | 일반 模式值 |
| `h j k l`, 방향키 | UTF-8 字符/行 移动值 |
| `0`, `$`, Home, End | 行 初始项目/结尾 |
| `gg`, `G`, `:编号` | 文件 初始项目/最后项目 行/赋值值 行 |
| PgUp, PgDn | 屏幕 单位值 移动值 |
| `x`, Delete | 当前项目 字符 삭제 |
| `dd`, `yy`, `p` | 行 삭제/复制值/粘贴文本 |
| `u` | 最后项目 편집을 发回桥接; 한 阶段值 토글 |
| `/字符串`, `n` | 단순 字符串 검색/下一项目 是否相等; 정규식 缺失方法 |
| `:w`, `:w 다른이름` | RAM 文件 存储值/다른 경로로 存储值 |
| `:q` | 변경이 없을 때 退出程序 |
| `:q!` | 변경을 버리고 退出程序 |
| `:wq`, `ZZ` | 저장하고 退出程序 |

붙여 넣은 한글을 字符 경계에 맞춰 移动值·삭제한다. 일반 vi의 수량 접두사, 宏值, 设置 文件, 플러그인, 정규식, 여러 버퍼/분할 窗口, 문법 강조 등은 아직 없다. `--desktop`에서는 F9·Shift+Space·한/零操作数 키로 두벌식 조합을 전환한다. PC 입력기를 영어로 두고 窗口 窗口标题 `[KO]`에서 입력하며, `help ko`에 단축키를 표시한다. 완성된 Unicode 문자와 VNC의 명시적 붙여넣기도 전달한다.

vi와 Swing 프로그램은 **단독 命令**으로 실행한다. 파이프·리다이렉션·脚本值·`;`/`&&`/`||`로 연결한 실행에서 交互式 대기를 시작하면 거부한다. 输入值 대기는 약 2초 CPU 기한을 갱신하지만 输入值 等待状态值 없이 무한 반복하는 프로그램은 기존처럼 종료한다.

## 韩文文本 Java

vi에서 다음을 `问候例.java`에 입력하고 Esc → `:wq`로 저장한다.

```java
public class 问候例 {
    static int 添加值列(int 首位序数, int 第二序数) { return 首位序数 + 第二序数; }
    public static void main(String[] 实参) {
        int 总计值 = 添加值列(20, 22);
        System.out.println("안녕하세요 · 总计值=" + 总计值);
    }
}
```

게스트 셸에서 실행한다.

```text
javac 问候例.java
java 问候例
```

韩文文本 文件名称文本·类名称·方法名称文本·변수명·문자열을 사용할 数 있다. **게스트 javac는 静态值 Java 부분집합**이다. 对象值·리스너·Swing·소켓을 사용하는 소스는 当前项目 宿主 JDK에서 `javac --release 8 -encoding UTF-8`로 컴파일하고 内置 JVM에 class를 올린다. 内置 JVM에서 지원하는 字节码/API 범위는 [Java运行时环境.md](Java运行时环境.md)를 따른다.

```sh
# 宿主
mkdir -p build/my-java
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/my-java 测试/Java/Swing测试.java
python3 工具集/上传文件集.py build/my-java/Swing测试.class
```

`upload.py`는 게스트 `load`에 붙여 넣을 16진수 명령을 생성한다. 输出 전체를 GUI 터미널에 보내면 업로드한다. 업로드 之后状态 **별도로** `java Swing测试`을 실행한다. 종속 class가 있으면 각각 업로드한다. 패키지 class의 파일명은 `패키지.类值.class` 형식이다. 내장 中文 라이브러리는 별도 업로드가 所需条件值 없다. 中文 窗口 API의 예제는 [测试韩文字母窗口.java](测试/Java/测试韩文字母窗口.java)이며 같은 방법으로 编译源代码·업로드해 `java 测试韩文字母窗口`으로 실행한다.

GUI가 所需条件值 없는 단일 源代码树/클래스는 호스트의 `python3 工具集/执行文件.py 路径/问候例.java`로 별도 QEMU에 업로드·执行命令·종료할 数 있다. 交互式 Swing에는 执行命令 之后状态 用户 입력을 유지하는 `make desktop`을 사용한다.

## 内置 JVM의 Swing 裁剪

실제로 제공하는 것은 **표준 패키지 이름으로 호출하는 内置 Swing API 부분집합**이다. OpenJDK `java.desktop` 모듈이나 AWT 전체를 이식한 것은 아니다.

| API | 动作 |
|---|---|
| `JFrame` | 窗口标题, 大小·位置, 显示窗口, 关闭 정책, dispose |
| `JPanel` | 子值 요소를 담는 패널 |
| `JLabel` | 한글을 포함한 字符串 显示值·更改值 |
| `JButton` | 버튼과 ActionListener 单击值 进程值条目 |
| `JTextField` | 한 行 UTF-8 输入值, 삭제, getText/setText, Enter 이벤트 |
| 公用值 | setBounds, setSize, add, getContentPane, repaint, validate |
| `SwingUtilities` | invokeLater, isEventDispatchThread |
| `ActionEvent` | getSource, getActionCommand, getID |

`setLayout(null)`과 `setBounds`로 배치한다. FlowLayout/BorderLayout/GridLayout, pack, 폰트·스타일 전체, 메뉴·테이블·트리·스크롤 패널, Java2D, 네이티브 AWT peer/JNI, 복잡한 字符 조판은 아직 없다. 이벤트 콜백은 内置 JVM의 단일 이벤트 执行命令 흐름에서 처리하며 OpenJDK EDT 구현과 동일하지 않다. 窗口·요소는 执行命令 하나당 总计值 32개, 元素值 글자는 最大值 127 코드포인트다. 默认值 서체와 색은 커널이 제공한다.

[Swing测试.java](测试/Java/Swing测试.java)는 窗口·韩文文本 标签值·文本字段·버튼·이벤트 처리의 执行命令 가능한 예제다. [内置 Swing 屏幕](build/verification/swing/native-swing.png)을 참고한다.

中文 라이브러리에는 다음을 추가했다. 宿主 编译源代码 시 `dist/jkoros-native-korean.jar`를 classpath에 넣는다.

- `中文.内置.窗口`: `添加元素`, `显示窗口`, `关闭`.
- `中文.内置.小组件`: `标签值`, `按钮`, `文本字段` 生成.
- `中文.内置.连接状态传输`: `连接`, `侦听端点`, `接收`.
- 기존 `输出`, `字符`, `文件`, `任务`, `条目列表`, `字典`, `通信`, `屏幕`, `内核值`도 유지한다.

## Java 네트워크

기존 `DatagramSocket`/`DatagramPacket`의 UDP 루프백에 `Socket`/`ServerSocket`의 **内核值 내부 연결형 字节值 流值**을 추가했다. 文件/소켓과 마찬가지로 SVC를 통해 Java 커널이 전송한다. 물리 NIC의 TCP/IP 패킷 스택은 아니다.

```java
java.net.ServerSocket 服务器值 = new java.net.ServerSocket(9250);
java.net.Socket 客户机值 = new java.net.Socket("localhost", 9250);
java.net.Socket 连接 = 服务器值.accept();
客户机值.getOutputStream().write("안녕하세요".getBytes("UTF-8"));
byte[] 已接收项目 = new byte[64];
int 长度 = 连接.getInputStream().read(已接收项目);
连接.close(); 客户机值.close(); 服务器值.close();
```

生成·连接·accept·양방향 字节值/数组值 输入输出·close·EOF·setSoTimeout을 지원한다. `String.getBytes()`와 UTF-8 이름을 지정한 getBytes도 제공한다. 루프백 주소는 `localhost`/`127.0.0.1`이다. 연결형 结束分 16개, 接收值 버퍼당 1024바이트, 等待状态值 连接 最大值 4개이며 Java의 대기는 내부 가닥에 실행을 양보한다. 默认值 时间值 限制值 0은 별도 套接字值 기한을 설정하지 않지만 JVM 命令 数/内核值 执行命令 기한은 여전히 적용된다.

外部值 数字值 IPv4 TCP/UDP는 lwIP/SLIP로 지원한다. 实际数据 Ethernet/Wi-Fi 드라이버, DNS·TLS·HTTP 库 전체는 미지원이다. `java.net`의 모든 메서드와 옵션, `SocketChannel`/select, SSL, shutdownInput/Output는 아직 없다. [测试流.java](测试/Java/测试流.java)는 实际数据 송수신·EOF·기한·连接 회수의 测试 예제다.

## 韩文文本 Python

게스트 vi에서 韩文文本 이름을 사용해 작성한다.

```python
值 = 21

def 두배(数字值):
    return 数字值 * 2

print("结果:", 두배(值))
```

存储值 之后状态 `python 问候例.py`로 실행한다. 실행기는 MicroPython 1.24.1이다. Python 문법 키워드는 그대로 사용하며 函数·变量值·文件 이름과 문자열을 한글로 쓴다.

[中文.py](用例/韩文字母编码方式/中文.py)를 같은 디렉터리에 두면 下一项目 별칭을 사용할 数 있다.

```python
import 中文
中文.写入文件("问候例.txt", "안녕하세요")
中文.输出(中文.读取文件("问候例.txt").decode())
```

输出·文件 读取/写入/삭제·표준 输入值·矩形·时间值·UDP를 연결한다. 기존 `udp_send`는 루프백, 새 `udp_sendto(fd, "10.0.2.2", port, data)`는 数字值 IPv4 地址 전송이다. `wait_key()`는 화면을 확인할 때 交互式 입력을 기다린다. Python 함수는 `jkoros` 내장 모듈을 통해 SVC를 사용한다. C ABI인 posix-kor 静态值 라이브러리를 Python이 직접 링크하는 구성은 아니다. CPython과 일반 扩展名值 모듈은 아직 없다. 제한형 `pip`의 源代码树 설치는 [Python 软件包 指南](Python捆绑.md)를 따른다. [三值 언어의 实际数据 用例](../../example/README.md).

## C·C++에서 posix-kor 调用

두 语言 构建全部 中文 헤더와 函数 이름을 직접 사용한다. [问候例.c](用例/韩文字母编码方式/问候例.c), [问候例.cpp](用例/韩文字母编码方式/问候例.cpp)首位操作数 实际数据 EL0 执行命令 测试 대상이다.

```c
#include "文件ABI.h"
#ifdef __cplusplus
extern "C"
#endif
int 开始用户程序(int 实参) {
    (void)实参;
    const char 问候语[] = "안녕하세요\n";
    int 文档集 = 打开文件("问候例.txt", 读取写入 | 创建条件缺失 | 截断内容, 0600);
    if (文档集 < 0) return 1;
    输入输出结果类型 已记录个数 = 写入文件数据(文档集, 问候语, sizeof(问候语) - 1);
    关闭文件(文档集);
    写入文件数据(1, 问候语, sizeof(问候语) - 1); /* 当前项目 终端 stdout */
    return 已记录个数 == sizeof(问候语) - 1 ? 0 : 2;
}
```

파일은 게스트 vi로 작성할 数 있다. C는 게스트 `cc` 또는 宿主 SDK, C++는 宿主 SDK의 Clang++로 컴파일한다. 底端值 예제는 기존 宿主 SDK 경로다. 게스트 내부 GCC/Clang·libc/libstdc++ 전체를 탑재한 것은 아니다. SDK가 `.c`에는 C11, `.cpp`에는 C++11을 선택한다.

```sh
# 호스트에서 SDK 生成·提取
make sdk
mkdir -p build/sdk-work
tar -xzf dist/jkoros-native-aarch64-sdk.tar.gz -C build/sdk-work
cd build/sdk-work/jkoros-native-sdk
python3 compile.py examples/问候例.c -o 问候例-c.elf
python3 compile.py examples/问候例.cpp -o 问候例-cpp.elf

# 프로젝트로 돌아와 별도 QEMU에서 实际数据 执行命令
cd /home/user/jkoros/platforms/rpi4-native
python3 工具集/执行文件.py build/sdk-work/jkoros-native-sdk/问候例-c.elf
python3 工具集/执行文件.py build/sdk-work/jkoros-native-sdk/问候例-cpp.elf
```

当前项目 GUI VM에서 실행하려면 `python3 工具集/上传文件集.py 路径/问候例-c.elf`의 출력을 게스트에 보내고 `run 问候例-c.elf`를 입력한다. 게스트에서 작성한 소스의 전송은 `hex 文件名称文本`으로 내용을 얻어 호스트에서 `bytes.fromhex(...)`로 복원할 数 있다. 호스트와 게스트의 文件 시스템은 별개다.

| 中文 名称 | C 符号 | 裁剪 |
|---|---|---|
| 打开文件/关闭文件 | pk_open/pk_close | RAM 文件, 对端值/절대 路径 |
| 读取文件数据/写入文件数据 | pk_read/pk_write | 文件, fd 0/1/2 표준 输入输出, 연결형 套接字值 |
| 寻道文件 | pk_lseek | 起点开头/当前根/结束原点 |
| 文件大小/设定文件长度 | pk_size/pk_ftruncate | 长度 查询值/更改值 |
| 移除文件条目名称 | pk_unlink | 文件 名称 삭제 |
| 提交文件存储装置 | pk_fsync | RAM이므로 -1, 错误编号=ENOSYS |
| 创建端点/绑定地址 | pk_socket/pk_bind | AF_INET, SOCK_DGRAM 또는 SOCK_STREAM |
| 发送数据报数据/接收数据报数据 | pk_sendto/pk_recvfrom | UDP 루프백 |
| 连接网络 | pk_connect | 연결형 루프백 |
| 等待状态用于网络连接状态 | pk_listen | 等待状态值 连接 最大值 4개 |
| 接受网络连接状态 | pk_accept | 当前项目 地址 인수는 NULL/NULL만 支持值 |
| 读取套接字地址 | pk_getsockname | 로컬 地址/端口值 |

`网络ABI.h`의 内置 `pk_sockaddr_in`을 사용하며 端口值·주소는 `网络短整数`/`网络整数`로 변환한다. C 套接字值 호출은 비차단이며 数据/연결이 없으면 -1과 `错误编号=11`(EAGAIN)을 반환한다. 양수 输入输出 결과가 요청보다 작을 数 있으므로 迭代值 처리한다. 失败值 후에만 오류번호를 확인한다.

[流值.c](用例/韩文字母编码方式/流值.c)는 C에서 中文 이름으로 连接·accept·子部分值 读取/写入·큐 포화·EOF를 처리하는 执行命令 예제다. SDK의 `examples/流值.c`를 같은 `compile.py`로 컴파일한다.

SDK는 **libposix-kor-user.a**를 링크한다. 调用 흐름은 C/C++ → 实际数据 中文 C 函数 또는 호환용 `pk_*` → `svc #0` → 커널의 소유권·指针 检查项 → Java RAM 文件/루프백 또는 外部值 lwIP TCP/UDP 구현이다. `libposix-kor-arm64.a`는 内核值 내부용이므로 EL0 프로그램에 링크하지 않는다. Linux 헤더나 Linux ELF와 혼합하지 않는다. 동적 连接, 표준 C printf, libstdc++/STL, 异常·RTTI는 제공하지 않으며 C++의 静态值 생성자·局部作用域 对象值 소멸자는 지원한다. 상세 编号·内存数据 범위는 [用户调用ABI.md](用户调用ABI.md)를 참고한다.

## 有效性校验

`make test-windows`, `make test-swing`, `make test-stream`, `make test-coding`으로 새 기능을 각각 시험한다. `make test`는 기존 命令壳·VNC·JVM·AOT·内核值 保护值 시험까지 포함한다. 实际数据 板 대신 QEMU raspi4b에서 수행한다. 결과는 [上一个项目 GUI 扩展名值 有效性校验 日志记录](build/verification/release.json)과 [当前项目 运行时 有效性校验 日志记录](build/verification/native-runtime-summary.json), [여러 终端 屏幕](build/verification/windows/four-terminals.png), [Swing 屏幕](build/verification/swing/native-swing.png)을 참고한다.

实现 시 참고한 표준 API: [Socket](https://docs.oracle.com/javase/8/docs/api/java/net/Socket.html), [JFrame](https://docs.oracle.com/javase/8/docs/api/javax/swing/JFrame.html), [JButton](https://docs.oracle.com/javase/8/docs/api/javax/swing/JButton.html). 이 문서의 实现 범위가 顶端值 표준 전체를 지원한다는 뜻은 아니다.

## 中文 이름으로 직접 작성하는 창과 线程值

`example/java/窗口例.java`는 `可运行任务任务.执行任务`,
`动作接收者.接收动作(动作通知)`, `按钮`, `事件排队.调用稍后`, `运行()`을 쓴다.
内置 JVM에 이 이름들의 对象值·方法值·콜백을 직접 구현했으며 영어 Swing 객체를
보관하는 래퍼가 아니다. `后台任务`도 内置 스케줄러와 직접 연결된다.
세부 메서드와 기존 中文 API에서의 변경은 [中文 API 文档集](中文Java/指南.md)를 본다.

宿主 javac는 分发值 JAR를 类值 경로로 사용한다.

```sh
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/한국어사용 ../../example/java/窗口例.java
python3 工具集/执行命令.py --desktop --network --resolution 1920x1080
```

게스트에는 빌드한 예제가 `/example/java`에 설치된다.

```text
cd /example/java
java 窗口例
```

직접 屏幕/线程值 API와 `运行()` 진입점은 内置 JVM 전용이다.
전체 OpenJDK·Swing 재구현이나 일반 OpenJDK에서 같은 API의 실행을 보장하지 않는다.
기존 표준 `main(String[])` 프로그램은 继续处理 실행할 数 있다.
