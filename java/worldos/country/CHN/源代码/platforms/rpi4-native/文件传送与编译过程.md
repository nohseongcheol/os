# 内置 ARM64 内核值: FTP, C, JAR와 AOT 执行命令

대상은 **Linux를 적재하지 않는 Raspberry Pi 4용 Java AOT 内核值**이다. CPU·设备 경계는 C/어셈블리, 文件 체계와 셸은 Java이며, 이번 TCP/IP 스택은 C로 작성된 lwIP 2.2.0을 이식했다. 게스트 TinyCC와 `jaot`도 EL0에서 실행한다. 호스트에 컴파일을 요청하거나 宿主 JVM으로 대신 실행하지 않는다.

## 먼저 알아둘 支持值 边界位置值

| 申请 | 이번 实现 | 남은 裁剪 |
|---|---|---|
| JAR를 执行命令 파일처럼 执行命令 | `java -jar 文件.jar`, `./文件.jar 实参`; Main-Class와 存储值/DEFLATE ZIP, CRC 检查项 | 전체 Java SE, 임의의 모든 JAR 호환성 |
| 게스트 AOT | `jaot 文件.class -o 文件.elf`, `jaot 文件.jar -o 文件.elf`; 实际数据 ARM64 기계어 生成 | 对象值·异常·Thread·Swing·Socket의 AOT 转换值, 여러 애플리케이션 类值 连接 |
| C 编译源代码 | 게스트 `cc`/`tcc`, TinyCC C 전처리기·ARM64 생성기·링커; 中文 식별자와 posix-kor | 전체 libc, 일반 Linux 执行命令 文件, 게스트 C++ 编译器 |
| 업로드한 ELF 执行命令 | ELF64/AArch64 헤더 检查项, 확장자 없는 `./文件`; 内置 ABI 및 명시적인 제한형 Linux ABI | 일반 Linux 바이너리 호환, 동적 링커, 공유 库 |
| 外部值 TCP/UDP | 게스트 lwIP IPv4 操作数栈, POSIX 소켓과 JVM의 数字值 IPv4 地址 | GENET/Wi-Fi 드라이버, DHCP·DNS·TLS, 物理硬件 板 네트워크 测试 |
| FTP | 게스트 서비스, 패시브 传送值, UTF-8 名称, STOR/RETR/SIZE/LIST/NLST/MLSD/DELE | TLS·사용자별 权限值·하위 디렉터리·영속 存储值 |
| 韩文文本 Java | 기존 `中文.内置` 클래스와 外部值 地址 UDP 오버로드 | 전체 JDK의 일대일 中文 映射值 API |

JVM은 类值 버전 45…52의 문서화한 부분집합이다. `java`는 字节码 실행기이고, `jaot`首位操作数 별도의 네이티브 执行命令 파일을 만든다. **JAR 存档值 해제나 JVM을 함께 묶는 것을 AOT라고 표시하지 않는다.** 지원하지 않는 字节码/API는 `jaot`首位操作数 진단하고 출력을 만들지 않는다. 기존 输出 ELF도 编译源代码 失败值 때 보존한다.

Android의 Dalvik/ART는 일반 JVM 类值/JAR가 아닌 **DEX**를 실행한다. ART의 AOT에는 GC, 类值 로딩, JNI 등 执行命令 기반도 필요하다. 따라서 ART처럼 기계어로 바꾸는 기능만으로 임의의 OpenJDK JAR 및 Swing이 자동 호환되지는 않는다. [Android 공식 런타임 说明](https://source.android.com/docs/core/runtime)

FTP는 루트 RAM 파일만 공개한다. 익명 로그인이며 비밀번호로 권한을 구분하지 않는다. 默认值 宿主 바인딩은 `127.0.0.1`이고, 控制值 포트는 2121, 데이터 포트는 50000…50007이다. `--ftp-port 2122`로 控制值 포트를 바꿀 数 있다. 동시에 한 FTP 세션을 제공하며 명령이 없는 세션은 60초 之后状态 닫는다. TYPE A도 바이트를 변경하지 않으므로 프로그램은 바이너리 전송한다.

파일은 **64개, 각각 16 KiB**, 경로는 UTF-8 63바이트이다. 启动 시 준비되는 `/example`도 이 한도를 공유한다. 초과/끊어진 STOR는 기존 파일에 반영하지 않는다. FTP 업로드는 RAM에만 저장되며 재부팅하면 사라진다. 이 限制值 때문에 일반적인 대형 JAR 배포판을 그대로 올릴 数 없다.

QEMU의 raspi4b에는 GENET Ethernet 장치가 없다. 따라서 `network_bridge.py`首位操作数 QEMU NAT의 Ethernet과 辅助值 UART의 SLIP를 변환한다. **TCP 连接 进程值条目·체크섬·재전송·FTP 명령과 文件 저장은 게스트 안에서 수행한다.** 宿主 브리지는 FTP 서버가 아니다. [QEMU 공식 设备 支持值 条目列表](https://www.qemu.org/docs/master/system/arm/raspi.html)

이 경로는 QEMU에서 검증했다. 辅助值 UART의 实际数据 Pi 4 핀/클럭 설정과 내장 RJ45 GENET 드라이버는 实现·검증하지 않았으므로, SD 이미지에 커널이 포함되어 있다는 사실을 实际数据 보드의 LAN/FTP 动作 보장으로 해석하면 안 된다.

## 中文 Java를 게스트에서 컴파일하고 AOT 执行命令

게스트 `vi 颜色.java`로 下一项目 소스를 작성한다.

```java
public class 颜色 {
    public static void main(String[] 实参) throws Exception {
        int 总和值 = 0;
        int 数 = 1;
        while (数 <= 10) {
            总和值 = 总和值 + 数;
            数 = 数 + 1;
        }
        中文.内置.输出.写入编号(总和值);
        中文.内置.文件.写入("aot.txt", "韩文文本 AOT 文件 😀");
        中文.内置.输出.写入行(中文.内置.文件.读取("aot.txt"));
    }
}
```

```text
javac 颜色.java
java 颜色
jaot 颜色.class -o 颜色.elf
run 颜色.elf
```

`jaot`은 클래스의 바이트코드를 C로 변환하고, **게스트 TinyCC**首位操作数 ARM64 명령어를 生成·연결한다. 执行命令 때 JVM 인터프리터를 호출하지 않는다. JAR의 Main-Class가 같은 支持值 범위이면 다음도 가능하다.

```text
jaot 颜色.jar -o 颜色.elf
run 颜色.elf
```

AOT 지원은 한 애플리케이션 클래스의 静态值 方法值/字段值, int 계열, 整数 배열과 引用, 实参 数组值, 条件·分支·迭代值, 字符串 리터럴, `System.out.print/println`의 int/String, 中文 输出·文件 读取/쓰기로 제한된다. 类值/方法值 수와 操作数栈 등에도 고정 상한이 있다. Java 异常 进程值条目, 对象值 生成, 가상 方法值 일반, switch/wide, long/float/double, invokedynamic, 字符串 결합용 StringBuilder, 일반 JDK·Socket·Thread·Swing은 이 AOT 백엔드에서 미지원이다. 내장 NUL/고립된 서로게이트 문자열도 거부한다. 잘못된 数组值 存取条目/0으로 相割值列 등은 네이티브 런타임 오류로 종료하며 Java 异常 객체로 전달하지 않는다.

输入值 클래스뿐 아니라 **생성된 ELF도 16 KiB 이하**여야 한다. 기계어 확장과 ELF 페이지 对齐值 때문에 짧은 클래스도 이 한도를 넘을 数 있으며, 이 경우 오류를 내고 기존 출력을 보존한다.

게스트 `javac`도 부분집합이다. 일반적인 对象值·Thread·Swing 소스는 호스트에서 `javac --release 8`로 컴파일하고, **기존 JVM의 支持值 裁剪 안에서** `java`/`java -jar`로 실행한다. 정확한 API는 [JVM 매뉴얼](Java运行时环境.md)과 [韩文文本 开发 매뉴얼](开发指南.md)을 참고한다.

JAR는 하나의 애플리케이션 类值 경로다. 내부 名称 `软件包/程序.class`와 점으로 구분한 Main-Class를 지원한다. 내부 클래스는 파일로 풀어 VFS 슬롯을 소비하지 않는다. 내장 中文 클래스를 추가로 찾지만 当前项目 任务 폴더의 다른 클래스는 자동 혼합하지 않는다. ZIP64·加密数据 ZIP·manifest Class-Path·서명 검증은 지원하지 않는다. JAR 하나가 16 KiB 이하이어도 클래스당/적재 数/VM 堆值 제한은 그대로 적용된다.

## C에서 中文 POSIX 调用

게스트에서 `vi 问候例.c`로 작성하거나 FTP로 소스를 업로드한다.

```c
#include <文件ABI.h>

int main(void) {
    const char 问候语[] = "内置 ARM64 C에서 韩文文本 POSIX 调用\n";
    int 文档集 = 打开文件("问候例.txt", 读取写入 | 创建条件缺失 | 截断内容, 0600);
    if (文档集 < 0) return 1;
    输入输出结果类型 已记录个数 = 写入文件数据(文档集, 问候语, sizeof(问候语) - 1);
    关闭文件(文档集);
    写入文件数据(1, 问候语, sizeof(问候语) - 1);
    return 已记录个数 == sizeof(问候语) - 1 ? 0 : 2;
}
```

```text
cc 问候例.c -o 问候例.elf
run 问候例.elf
cat 问候例.txt
```

TinyCC의 표준 C 条目分 `main`을 사용한다. 기존 宿主 C/C++ SDK의 `开始用户程序(int)` 진입점과 구분한다. 头文件 文件·运行 对象值·`libposix-kor-user.a`는 编译器 내부의 读取 전용 SDK에 들어 있다. C 전처리기/구조체/函数/재귀/指针/부동소수점 生成 등을 사용하되 **일반 libc/libstdc++를 제공한다는 뜻은 아니다**. 제공하지 않는 함수는 连接 오류가 난다. 编译器 자체의 字符/数字值 转换值 지원도 완전한 libc 대체품이 아니다.

`打开文件` 등은 별도의 모의 호출이 아닌 기존 `pk_open` 등의 中文 매크로이며, ELF의 SVC를 통해 实际数据 Java 文件 체계에 도달한다. 文件/套接字值 调用 목록은 [用户 ABI](用户调用ABI.md)에 있다. C/C++ 宿主 SDK 执行命令 파일도 FTP로 업로드 之后状态 `run` 또는 `./文件`로 실행하며 확장자는 所需条件值 없다. Linux ARM64 静态值 ELF에는 별도의 제한된 호환 路径 `run --linux 文件`을 추가했다. [ELF·Linux ABI 매뉴얼](可执行文件ABI.md)에 정확한 格式值·시스템 调用·地址 제한을 정리했다.

## 中文 네트워크·任务·屏幕 API

| 类值 | 调用 예 | 执行命令 路径 |
|---|---|---|
| `输出` | `写入行("안녕")`, `写入编号(42)` | JVM 및 제한형 AOT |
| `文件` | `写入("文档集.txt", "内容值")`, `读取("文档集.txt")` | JVM 및 제한형 AOT |
| `通信` | `打开(0)`, `发送(端点, "10.0.2.2", 9000, "韩文文本")`, `接收(端点)` | JVM의 UDP |
| `连接状态传输` | `连接("10.0.2.2", 9000)`, `侦听端点(9000)`, `接收(服务器值)` | JVM의 Socket/ServerSocket |
| `任务` | `运行(Runnable)`, `等待(Thread)`, `挂起任务()` | JVM의 협력식 线程值 |
| `窗口`, `小组件` | 窗口·버튼·字符值·文本字段·事件 连接 | JVM의 Swing 부분집합 |

명명에서는 표준 영어 API를 보존하고 中文 调用 계층을 추가한다. `通信(通信)`, `连接(連結)`, `输出(出力)`은 기존 단어의 뜻을 사용한다. `任务 线程值`은 한 执行命令 흐름을 가닥에 빗댄 描述符值 표현, `端口值`는 포트의 접점을 설명하는 표현이다. 새 描述符值 결합어를 고대에 이미 존재한 용어처럼 설명하지 않는다. 전체 JDK의 번역을 완료했다고 표시하지 않는다.

外部值 주소는 数字值 IPv4이며 QEMU 호스트는 `10.0.2.2`, 게스트는 `10.0.2.15`第三操作数. UDP 전문은 512바이트까지다. 소켓은 비차단 内置 ABI이며 JVM이 제한된 等待状态值/재시도를 제공한다. TCP connect 대기는 最大值 1초, 用户 程序 전체에는 기존 약 2초 CPU 기한이 적용된다. 일반적인 장기 执行命令 用户 서버와 pthread는 아직 없다. FTP는 用户 程序 기한과 별개인 内核值 서비스다.

게스트의 用户 TCP/UDP 서버로 들어오는 연결은 NAT 포트를 추가한다. 예를 들어 `python3 工具集/执行命令.py --network --forward tcp:9300:9300 --forward udp:9301:9301`로 실행하면 호스트의 localhost 9300/TCP·9301/UDP를 게스트의 같은 포트로 전달한다. FTP의 默认值 控制值/데이터 포트와 겹치면 执行命令 전에 거부한다.

`build/verification/ftp/report.json`은 实际数据 FTP 传送值, 韩文文本 文件, 大小 초과 보존, 存档值 JAR 执行命令, 게스트 C 编译源代码/ELF 재업로드, 外部值 Java TCP/UDP, 게스트 javac/AOT 실행을 기록한다. `serial.log`에서 게스트 명령과 결과를 확인할 数 있다. 보고서의 内核值 SHA-256과 分发值 이미지의 커널을 비교한다.

전체 JDK/AOT JVM으로 확장하려면 타입 有效性校验·对象值/异常/GC·동적 로딩·JNI, 영속 文件 运行系统值·mmap/TLS/시그널·스레드 ABI, OpenJDK native 库, GUI peer/폰트/입력기, GENET 및 物理硬件 设备 검증이 더 필요하다. 이 문서의 执行命令 시험은 그 전체 이식을 대신하지 않는다.
