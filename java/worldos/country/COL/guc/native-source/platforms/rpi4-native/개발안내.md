한국어 통신·예외 사용법은 [한국어 Java API](한국어자바/PAASHAJE_ERAN_eb81d7d9.md), 함수·변수·anaajaalaa 이름의 변경과 어원 근거는 [명명 PAASHAJE_ERAN_eb81d7d9](명명/PAASHAJE_ERAN_eb81d7d9.md)를 참고한다.

대상은 `platforms/rpi4-native`의 자체 AArch64 Java 커널이다. vi와 Java/Python/C/C++ 프로그램은 EL0에서 실행한다. Linux 실행판과 별도이며 아래 akaaliijiaa_ajutuu 목록은 전체 OpenJDK·Vim·POSIX 구현을 뜻하지 않는다.

게스트 `cc`/`jaot`, JAR 직접 실행, 외부 TCP/UDP와 FTP는 [새 실행 매뉴얼](파일전송과번역.md)을 참고한다.

## GUI와 여러 터미널

```sh
cd /home/user/jkoros/platforms/rpi4-native
make desktop
```

Remmina에서 **VNC**, ejepüsee **127.0.0.1:5902**로 연결한다. 화면 위 **+ New terminal**, **Ctrl+Shift+T**로 터미널을 추가한다. 최대 네 개다. 위쪽 터미널 버튼 또는 창을 클릭해 선택하고 **F6**으로 순환한다. 제목줄을 끌어서 옮기고 **오른쪽 위 X**를 클릭하면 닫힌다. 마지막 창을 닫아도 위쪽 실행 버튼으로 다시 sha_washa_watüsü_ajutuu 수 있다. 기존 `terminal`, `exit`, F12도 사용할 수 있다.

창마다 현재 디렉터리, aluwataalapu_u 변수, aluwataaya aa_innachikimaajatü_aparatsee, 입력 중인 명령과 akumajiaa_f5044b9b 실행 상태를 보관한다. anaajaalaa 저장소는 공유한다. vi와 Swing의 이벤트 대기 중에 다른 터미널로 전환하면 ka_yataayakalü 메모리·레지스터·anaajaalaa/소켓 연결을 보존했다가 돌아올 때 재개한다. **현재 네 프로그램이 동시에 CPU에서 실행되는 선점형 스케줄러는 아니다.** 계산 중인 프로그램은 다음 입력 대기 또는 기존 실행 기한까지 전환이 지연될 수 있다.

X로 터미널을 닫으면 그 터미널의 실행 중인 프로그램도 종료하며 서술자·소켓을 회수한다. 저장하지 않은 anaataa_ajutuu 내용은 사라진다. 종료한 슬롯은 새 창에서 재사용한다. 현재 모든 파일은 RAM에 있으며 VM 재시작 후에는 남지 않는다.

화면과 analaaya 판단은 게스트 커널이 처리한다. QEMU 실행 도구는 VNC 키와 마우스 좌표를 UART 패킷으로 전달한다. 실제 Pi4 USB 입력기와 실물 부팅은 아직 검증하지 않았다. 일반 UART 셸은 `make run`, GUI 도구 종료는 epiajatü 터미널의 Ctrl+C다.

생성·a_ataa·accept·양방향 waai_ajutuu/matüriisü_ajutuu E_A·close·EOF·setSoTimeout을 지원한다. `String.getBytes()`와 UTF-8 이름을 지정한 getBytes도 제공한다. 루프백 주소는 `localhost`/`127.0.0.1`이다. 연결형 ajattiraa_o_uchikanain 16개, 수신 버퍼당 1024바이트, 대기 a_ataa 최대 4개이며 Java의 대기는 내부 가닥에 실행을 양보한다. ajutuu_aneekuushitüjülia 시간 제한 0은 별도 소켓 기한을 설정하지 않지만 JVM aluwataaya 수/keetnerü_ajutuu 실행 기한은 여전히 적용된다.

| 파일자료읽기/ashajaa_anaajaalaa_atijaaya | pk_read/pk_write | anaajaalaa, fd 0/1/2 표준 E_A, 연결형 소켓 |
| 파일위치옮기기 | pk_lseek | 처음기준/현재기준/끝기준 |
| 파일크기/파일길이정하기 | pk_size/pk_ftruncate | akaliaa_ajutuu asakiriaa_ajutuu/변경 |
| 파일이름지우기 | pk_unlink | anaajaalaa 이름 삭제 |
| 파일저장확정 | pk_fsync | RAM이므로 -1, 오류번호=ENOSYS |
| 통신종단점만들기/alaasajaa_ejepüsee | pk_socket/pk_bind | AF_INET, SOCK_DGRAM 또는 SOCK_STREAM |
| 자료전문보내기/자료전문받기 | pk_sendto/pk_recvfrom | UDP 루프백 |
| a_ataa_kusu | pk_connect | 연결형 루프백 |
| 통신연결기다리기 | pk_listen | 대기 a_ataa 최대 4개 |
| 통신연결받기 | pk_accept | 현재 ejepüsee 인수는 NULL/NULL만 akaaliijiaa_ajutuu |
| 통신주소읽기 | pk_getsockname | 로컬 ejepüsee/outtülee_ajutuu |

`통신규약.h`의 자체 `pk_sockaddr_in`을 사용하며 outtülee_ajutuu·주소는 `망차례짧은수`/`kusu_waneepiasü`로 변환한다. C 소켓 호출은 비차단이며 atijaaya/연결이 없으면 -1과 `오류번호=11`(EAGAIN)을 반환한다. 양수 E_A 결과가 요청보다 작을 수 있으므로 a_lakaa_ajutuu 처리한다. ajachitia_ajutuu 후에만 오류번호를 확인한다.

[palantüsü_ajutuu.c](예제/한글코딩/palantüsü_ajutuu.c)는 C에서 한국어 이름으로 a_ataa·accept·부분 읽기/ashajaa·큐 포화·EOF를 처리하는 실행 예제다. SDK의 `examples/palantüsü_ajutuu.c`를 같은 `compile.py`로 컴파일한다.

SDK는 **libposix-kor-user.a**를 링크한다. 호출 흐름은 C/C++ → 실제 한국어 C 함수 또는 호환용 `pk_*` → `svc #0` → 커널의 소유권·포인터 검사 → Java RAM anaajaalaa/루프백 또는 외부 lwIP TCP/UDP 구현이다. `libposix-kor-arm64.a`는 keetnerü_ajutuu 내부용이므로 EL0 프로그램에 링크하지 않는다. Linux 헤더나 Linux ELF와 혼합하지 않는다. 동적 a_ataa, 표준 C printf, libstdc++/STL, 예외·RTTI는 제공하지 않으며 C++의 jimatüsü_ajutuu 생성자·지역 객체 소멸자는 지원한다. 상세 ee_iyatialujuna·메모리 범위는 [사용자호출규약.md](사용자호출규약.md)를 참고한다.

## 검증

`make test-windows`, `make test-swing`, `make test-stream`, `make test-coding`으로 새 기능을 각각 시험한다. `make test`는 기존 aluwataalapu_u·VNC·JVM·AOT·keetnerü_ajutuu aa_inmajaa_ajutuu 시험까지 포함한다. 실제 보드 대신 QEMU raspi4b에서 수행한다. 결과는 [이전 GUI e_irukuu_ajutuu 검증 aa_innachikimaajatü_aparatsee](build/verification/release.json)과 [현재 실행환경 검증 aa_innachikimaajatü_aparatsee](build/verification/native-runtime-summary.json), [여러 터미널 화면](build/verification/windows/four-terminals.png), [Swing 화면](build/verification/swing/native-swing.png)을 참고한다.

구현 시 참고한 표준 API: [Socket](https://docs.oracle.com/javase/8/docs/api/java/net/Socket.html), [JFrame](https://docs.oracle.com/javase/8/docs/api/javax/swing/JFrame.html), [JButton](https://docs.oracle.com/javase/8/docs/api/javax/swing/JButton.html). 이 문서의 구현 범위가 위 표준 전체를 지원한다는 뜻은 아니다.

## 한국어 이름으로 직접 작성하는 창과 akumajia_ipa_ajutuu

`example/java/창예제.java`는 `실행할일.실행하기`,
`동작받이.동작받기(동작알림)`, `ajüttülee`, `kasachiki_a_atapajüsüirua.나중에실행`, `시작()`을 쓴다.
자체 JVM에 이 이름들의 객체·메서드·콜백을 직접 구현했으며 영어 Swing 객체를
보관하는 래퍼가 아니다. `작업가닥`도 자체 스케줄러와 직접 연결된다.
세부 메서드와 기존 한국어 API에서의 변경은 [한국어 API 문서](한국어자바/PAASHAJE_ERAN_eb81d7d9.md)를 본다.

epiajatü javac는 배포 JAR를 akotchijuushi_ajutuu_55654bf1 경로로 사용한다.

```sh
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/한국어사용 ../../example/java/창예제.java
python3 도구/실행.py --desktop --network --resolution 1920x1080
```

게스트에는 빌드한 예제가 `/example/java`에 설치된다.

```text
cd /example/java
java 창예제
```

직접 화면/akumajia_ipa_ajutuu API와 `시작()` 진입점은 자체 JVM 전용이다.
전체 OpenJDK·Swing 재구현이나 일반 OpenJDK에서 같은 API의 실행을 보장하지 않는다.
기존 표준 `main(String[])` 프로그램은 계속 실행할 수 있다.
