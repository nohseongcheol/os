# Java 네이티브 kompilátor

OpenJDK vlastní 소스를 빌드하는 **`--target openjdk-build`**와 vlastní jádro_HODNOTA ABI 검사 도구를 추가했다.
이는 공식 javac/C/C++ 도구를 연결하는 별도 경로다. [BLD_Systém 방법·skutečný_data ověřit_5fb2b747·jádro_HODNOTA 이식 oříznout](OpenJDK-zdroj_BLD_A-nativní_jádro-이식.md)를 참고한다.

x86 직접 변환과 ARM64 C generovat 후단은 모두 [기계어미리번역.java](자바도구/기계어미리번역.java)로 구현한다. `sh 미리번역.sh`로 직접 실행하며, [기계어미리번역.py](기계어미리번역.py)와 `kompilátor.py`는 Předchozí_zboží příkaz·API 및 OpenJDK 도구를 위한 호환 진입점이다. vlastní Pi4 후단은 freestanding C를 거쳐 AArch64로 만든다. [arm64.py](arm64.py)는 Předchozí_zboží 경로와 Python 호출을 위한 호환 진입점이다. funkce_HODNOTA·proměnná_HODNOTA·generovat C 이름의 뜻과 예외는 [čeština 명명 안내](../platforms/rpi4-native/명명/안내.md)를 참고한다. [ARM64 BLD_Systém·vzpěra_HODNOTA oříznout](../platforms/rpi4-native/안내.md)에 Provést_příkaz 조건이 있다. 전체 OpenJDK나 일반 Třída_HODNOTA 실행기는 아니다.

Provést_příkaz 시 JVM이 필요 없는 x86 32비트 ELF를 만든다. JDK 11 이상으로 실행하는 Java vlastní AOT 후단이며, Java 전체를 새로 구현한 컴파일러는 아니다. Java 문법·přístup_položka řízení_HODNOTA·TYP_HODNOTA 검사는 JDK의 `javac`에 맡기고, Java 8 Třída_HODNOTA 파일을 읽어 각 바이트코드를 x86 명령으로 직접 변환한다. C 코드로 우회하거나 바이트코드 해석기를 커널에 넣지 않는다.

```text
Java zdrojový_soubor → javac의 문법·TYP_HODNOTA 검사 → 임시 .class
          → vlastní x86 변환기 → GNU as/ld → 네이티브 ELF32
```

## 준비와 Provést_příkaz

BLD_Systém hostit: Linux, Python 3.6 이상, JDK 11 이상(`javac --release 8`), GNU binutils(`as`, `ld`), Make. dobrá_zboží 환경의 OpenJDK 11, Python 3.6, binutils 2.30으로 검증했다. externí_HODNOTA Python 패키지와 네트워크 다운로드는 사용하지 않는다.

```sh
cd /home/user/jkoros/compiler
make
./build/계산
echo $?                  # 0이면 예제 zkoušky 성공

python3 kompilátor.py --target linux --entry 계산.Spustit_2 \
    -o build/계산 예제/계산.java

make test
```

`linux` 대상은 Linux의 32비트 Provést_příkaz 호환 기능이 필요하다. `int 0x80`을 차단하는 샌드박스에서는 `Bad system call`이 발생할 číslo 있다. informační_systémy_normální Linux hostit 또는 해당 실행을 허용한 zkoušky 환경에서 실행한다. 시험의 비정상 종료를 통과로 처리하지 않는다.

진입점은 `static int Spustit_2()` 또는 `static void Spustit_2()`처럼 인수가 없어야 한다. `--entry 패키지.Třída_HODNOTA.funkce_HODNOTA`로 선택한다. `int` 반환값은 Linux 프로세스 Konec_program 코드가 되며 셸에는 하위 8비트가 보인다. 일반 `main(String[] args)` Provést_příkaz 환경이나 표준 vstup_a_výstup 라이브러리는 제공하지 않는다.

`--target kernel`은 spuštění_stroje 코드와 연결할 재배치 ELF 오브젝트를 생성한다.

```sh
cd /home/user/jkoros
python3 compiler/kompilátor.py --target kernel --entry jádro.Spustit_2 \
    --export kernel_dispatch=systémové_volání.Proces_HODNOTA_položka \
    -o os/build/java.o os/zdrojový_soubor/*.java
```

`--target user`는 jkoros 셸에서 실행할 독립 ELF를 생성한다. `uživatelský_prostor` 클래스의 제한된 native API는 `int 0x80` 시스템 호출로 연결하며 `mobilní_HODNOTA` 클래스의 hardware_HODNOTA 직접 접근은 거부한다. uživatelský_prostor ELF는 Linux Provést_příkaz název_souboru ABI와 다르므로 호스트에서 실행하지 않는다. generovat·registr_položka 방법은 [uživatelský_prostor Provést_příkaz 안내](../os/uživatelský_prostor/안내.md)에 있다. `--export 외부기호=Třída_HODNOTA.funkce_HODNOTA`는 오버로드되지 않은 statický_HODNOTA 함수를 vlastní operand_Štos ABI로 노출한다. 커널의 시스템 호출 진입점에 사용한다.

Java 파일은 필요한 클래스들을 한꺼번에 전달한다. výstupní_pozice 옆의 `.s`는 생성된 어셈블리, `.json`은 zdrojový_soubor SHA-256 및 네이티브 symbol↔Java funkce_HODNOTA 대응표다. čeština 함수명은 원문과 대응표에 보존하고 ELF 내부에는 충돌 방지용 počítač 기호를 쓴다. kompilovat_zdroj·sestavit_HODNOTA·Připojit 중 실패하면 기존 VÝSLEDEK 파일을 덮어쓰지 않는다.

## vzpěra_HODNOTA oříznout

- `int`, `boolean`, `byte`, `short`, `char`의 32비트 계산 및 TYP_HODNOTA CONVERT_HODNOTA.
- statický_HODNOTA 필드와 statický_HODNOTA funkce_HODNOTA, 매개변수·반환값, 재귀, 클래스별 지연 초기화와 inicializovat Cyklus_HODNOTA.
- 조건문, 반복문, 단락 평가, 삼항식, integer `switch`, 넓은 místní_obor proměnná_HODNOTA 인덱스.
- 덧셈·뺄셈·곱셈·나눗셈·나머지·bit_HODNOTA 연산과 přesunout_HODNOTA. Java의 오버플로 및 `MIN_VALUE / -1` 동작을 유지한다.
- `int[]` generovat·초기값 0·délka_HODNOTA·Čtení·Zápis·odkaz 비교. 256KiB 고정 pole_HODNOTA oblast_HODNOTA_0e9a97ab, 널/dolní_index_HODNOTA/Velikost/ODKAZ_oblast 검사.

- čeština Třída_HODNOTA·funkce_HODNOTA·proměnná_HODNOTA·název_souboru Název.

`new Object`, 인스턴스 hodnota_pole/funkce_HODNOTA, 상속/인터페이스, `long/float/double` Provést_příkaz operace_HODNOTA, `int[]` 이외 pole_HODNOTA, řetězec_HODNOTA 동적 결합, Java 표준 knihovna, výjimka Proces_HODNOTA_položka, 스레드·synchronizovat·GC는 미지원이다. 실행에 필요한 미지원 바이트코드나 externí_HODNOTA 호출을 발견하면 실패한다. 사용되지 않는 výchozí_hodnota 생성자는 Provést_příkaz 코드로 만들지 않는다. ## native 경계와 ABI

jádro_HODNOTA 대상에서는 `os/zdrojový_soubor/mobilní_HODNOTA.java`, uživatelský_prostor 대상에서는 `os/uživatelský_prostor/deklarace_4f4f026b/uživatelský_prostor.java`의 정확한 metoda_název_SMS·서술만 허용한다. 임의의 `native` 함수와 Linux/uživatelský_prostor 대상의 hardware_HODNOTA 접근은 거부한다. Java 인수를 왼쪽부터 32비트 한 칸씩 스택에 놓으며, 반환값은 EAX, EBP/ESP 이외 레지스터는 호출자가 보존한다고 가정하지 않는다. C의 cdecl/JNI ABI가 아니므로 C 함수와 바로 연결하면 안 된다.

Java zdrojový_soubor 또는 `.class` 입력을 받는다. 전체 JVM 바이트코드 검증기는 제공하지 않는다. 어노테이션 처리는 비활성화하고 비어 있는 Třída_HODNOTA cesta_2/zdrojový_soubor 경로에서 명시한 소스만 컴파일한다.
