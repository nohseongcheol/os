## Slovenský Java를 게스트에서 컴파일하고 AOT Vykonať_príkaz

게스트 `vi 빛.java`로 Ďalej_položka 소스를 작성한다.

```java
public class 빛 {
    public static void main(String[] Argumenty) throws Exception {
        int SUM_VALUE = 0;
        int 수 = 1;
        while (수 <= 10) {
            SUM_VALUE = SUM_VALUE + 수;
            수 = 수 + 1;
        }
        Slovenský.vlastné.Výstup.수쓰기(SUM_VALUE);
        Slovenský.vlastné.Súbor.Zápis("aot.txt", "한글 AOT Súbor 😀");
        Slovenský.vlastné.Výstup.zapísať_linka(Slovenský.vlastné.Súbor.Čítanie("aot.txt"));
    }
}
```

```text
javac 빛.java
java 빛
jaot 빛.class -o 빛.elf
run 빛.elf
```

`jaot`은 클래스의 바이트코드를 C로 변환하고, **게스트 TinyCC**가 ARM64 명령어를 generovať·연결한다. Vykonať_príkaz 때 JVM 인터프리터를 호출하지 않는다. JAR의 Main-Class가 같은 Podpora_VALUE 범위이면 다음도 가능하다.

```text
jaot 빛.jar -o 빛.elf
run 빛.elf
```

AOT 지원은 한 애플리케이션 클래스의 정적 metóda_VALUE/hodnota_poľa, int 계열, celé_číslo 배열과 zdroj, Argumenty pole_VALUE, podmienka·vetva·šprint_VALUE, reťazec_VALUE 리터럴, `System.out.print/println`의 int/String, Slovenský Výstup·Súbor Čítanie/쓰기로 제한된다. lekcia_VALUE/metóda_VALUE 수와 operand_Vrstvy 등에도 고정 상한이 있다. Java výnimka Proces_VALUE_položka, objekt_VALUE generovať, 가상 metóda_VALUE 일반, switch/wide, long/float/double, invokedynamic, reťazec_VALUE 결합용 StringBuilder, 일반 JDK·Socket·Thread·Swing은 이 AOT 백엔드에서 미지원이다. 내장 NUL/고립된 서로게이트 문자열도 거부한다. 잘못된 pole_VALUE prístup_položka/0으로 나누기 등은 네이티브 런타임 오류로 종료하며 Java výnimka 객체로 전달하지 않는다.

vstup_VALUE 클래스뿐 아니라 **생성된 ELF도 16 KiB 이하**여야 한다. 기계어 확장과 ELF 페이지 zarovnať_VALUE 때문에 짧은 클래스도 이 한도를 넘을 수 있으며, 이 경우 오류를 내고 기존 출력을 보존한다.

게스트 `javac`도 부분집합이다. 일반적인 objekt_VALUE·Thread·Swing 소스는 호스트에서 `javac --release 8`로 컴파일하고, **기존 JVM의 Podpora_VALUE klip 안에서** `java`/`java -jar`로 실행한다. 정확한 API는 [JVM 매뉴얼](자바실행환경.md)과 [한글 개발 매뉴얼](개발안내.md)을 참고한다.

JAR는 하나의 애플리케이션 lekcia_VALUE 경로다. 내부 Názov `zväzok/program_f5044b9b.class`와 점으로 구분한 Main-Class를 지원한다. 내부 클래스는 파일로 풀어 VFS 슬롯을 소비하지 않는다. 내장 Slovenský 클래스를 추가로 찾지만 v_termíne_splatnosti_položka 작업 폴더의 다른 클래스는 자동 혼합하지 않는다. ZIP64·šifrovať_údaje ZIP·manifest Class-Path·서명 검증은 지원하지 않는다. JAR 하나가 16 KiB 이하이어도 클래스당/적재 수/VM halda_VALUE 제한은 그대로 적용된다.

## C에서 Slovenský POSIX 호출

게스트에서 `vi 인사.c`로 작성하거나 FTP로 소스를 업로드한다.

```c

    const char 인사말[] = "vlastné ARM64 C에서 한글 POSIX 호출\n";
    int 문서 = otvoriť_Súbor("인사.txt", na_čítanie_a_zapisovanie | 없으면만들기 | skrátiť_Obsah, 0600);
    if (문서 < 0) return 1;

```

```text
run 인사.elf
cat 인사.txt
```

TinyCC의 표준 C položka_bod `main`을 사용한다. 기존 hostiteľ C/C++ SDK의 `START_používateľ_program(int)` 진입점과 구분한다. 포함 Súbor·Spustiť_2 objekt_VALUE·`libposix-kor-user.a`는 kompilátor 내부의 Čítanie 전용 SDK에 들어 있다. C 전처리기/구조체/funkcia_VALUE/재귀/ukazovateľ/부동소수점 generovať 등을 사용하되 **일반 libc/libstdc++를 제공한다는 뜻은 아니다**. 제공하지 않는 함수는 Pripojiť 오류가 난다. kompilátor 자체의 문자/číslica_VALUE CONVERT_VALUE 지원도 완전한 libc 대체품이 아니다.

`otvoriť_Súbor` 등은 별도의 모의 호출이 아닌 기존 `pk_open` 등의 Slovenský 매크로이며, ELF의 SVC를 통해 skutočný_údaje Java Súbor 체계에 도달한다. Súbor/soket_VALUE 호출 목록은 [používateľ ABI](사용자호출규약.md)에 있다. C/C++ hostiteľ SDK Vykonať_príkaz 파일도 FTP로 업로드 후 `run` 또는 `./Súbor`로 실행하며 확장자는 필요 없다. Linux ARM64 정적 ELF에는 별도의 제한된 호환 Cesta `run --linux Súbor`을 추가했다. [ELF·Linux ABI 매뉴얼](실행파일규약.md)에 정확한 formát_VALUE·시스템 호출·adresa 제한을 정리했다.

## Slovenský 네트워크·작업·화면 API

| lekcia_VALUE | 호출 예 | Vykonať_príkaz Cesta |
|---|---|---|
| `Výstup` | `zapísať_linka("안녕")`, `수쓰기(42)` | JVM 및 제한형 AOT |
| `Súbor` | `Zápis("문서.txt", "obsah_VALUE")`, `Čítanie("문서.txt")` | JVM 및 제한형 AOT |
| `통신` | `Otvoriť(0)`, `odoslať(účastník, "10.0.2.2", 9000, "한글")`, `dostať(účastník)` | JVM의 UDP |
| `연결통신` | `Pripojiť("10.0.2.2", 9000)`, `načúvať_účastník(9000)`, `dostať(server_VALUE)` | JVM의 Socket/ServerSocket |
| `작업` | `Spustiť_2(Runnable)`, `기다리기(Thread)`, `YIELD_úloha()` | JVM의 협력식 vlákno_VALUE |
| `Okno`, `widget` | Okno·버튼·znak_VALUE·textové_pole·Udalosť Pripojiť | JVM의 Swing 부분집합 |

명명에서는 표준 영어 API를 보존하고 Slovenský 호출 계층을 추가한다. `통신(通信)`, `Pripojiť(連結)`, `Výstup(出力)`은 기존 단어의 뜻을 사용한다. `작업 vlákno_VALUE`은 한 Vykonať_príkaz 흐름을 가닥에 빗댄 기술 표현, `port_VALUE`는 포트의 접점을 설명하는 표현이다. 새 기술 결합어를 고대에 이미 존재한 용어처럼 설명하지 않는다. 전체 JDK의 번역을 완료했다고 표시하지 않는다.

externý_VALUE 주소는 číslica_VALUE IPv4이며 QEMU 호스트는 `10.0.2.2`, 게스트는 `10.0.2.15`다. UDP 전문은 512바이트까지다. 소켓은 비차단 vlastné ABI이며 JVM이 제한된 počkaj_VALUE/재시도를 제공한다. TCP connect 대기는 최대 1초, používateľ program_f5044b9b 전체에는 기존 약 2초 CPU 기한이 적용된다. 일반적인 장기 Vykonať_príkaz používateľ 서버와 pthread는 아직 없다. FTP는 používateľ program_f5044b9b 기한과 별개인 jadro_VALUE 서비스다.

게스트의 používateľ TCP/UDP 서버로 들어오는 연결은 NAT 포트를 추가한다. 예를 들어 `python3 Nástroje/Vykonať_príkaz.py --network --forward tcp:9300:9300 --forward udp:9301:9301`로 실행하면 호스트의 localhost 9300/TCP·9301/UDP를 게스트의 같은 포트로 전달한다. FTP의 predvolená_hodnota riadenie_VALUE/데이터 포트와 겹치면 Vykonať_príkaz 전에 거부한다.
