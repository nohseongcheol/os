# jkoros 안에서 Java kompilovať_zdroj·Vykonať_príkaz

이 문서의 부팅·셸·Store_VALUE 명령은 **x86 verzia_VALUE** 기준이다. 공유 Java kompilátor/JVM은 [vlastné ARM64 Pi4 verzia_VALUE](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART vstup_VALUE·한글 názov_súboru_SMS, `edit`의 단독 `.` Store_VALUE, 16개 RAM Súbor, 약 2초 Vykonať_príkaz 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 skutočný_údaje JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. hostiteľ kompilovať_zdroj 서버나 Linux 게스트는 사용하지 않는다.

**v_termíne_splatnosti_položka 구현은 vlastné 제한형 kompilátor·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java program_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 Vykonať_príkaz

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. Vykonať_príkaz 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox Vykonať_príkaz 안내](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 Súbor 전체를 새 내용으로 작성한다. 기존 내용의 riadok úprava_VALUE 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 Byte_VALUE 수 zobraziť_VALUE_487749b8.
- `cat FILE`: Súbor obsah_VALUE zobraziť_VALUE_487749b8. 텍스트 소스에 사용한다.
- `rm FILE`: Pamäť_údaje Súbor 삭제.
- `edit FILE`: 전체 내용을 새로 vstup_VALUE. 빈 파일도 저장할 수 있다.
- 구문·Typ_VALUE 검사 zlyhanie_VALUE 시 기존 `.class`는 유지된다. 소스를 고친 BACK_VALUE 컴파일이 실패했다면 이전 Vykonať_príkaz 파일이 남아 있으므로 kompilovať_zdroj 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 Store_VALUE 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 zdroj_strom·lekcia_VALUE·údaje 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, Súbor 이름은 ASCII 1~63자다. zdroj_strom 이름은 `.class` 확장자 adresa_oblasť 때문에 최대 62자다. úprava_VALUE 입력은 ASCII이고 한 riadok 최대 128자다. riadok 또는 Súbor 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. jadro_VALUE/kompilátor/JVM 구현의 Java 식별자는 한국어이며, v_termíne_splatnosti_položka 게스트 vstup_VALUE 제한 때문에 používateľ 예제 이름은 ASCII로 작성한다.

## externý_VALUE Súbor 적재

호스트에서 만든 소스나 Podpora_VALUE klip 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 skutočný_údaje 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# hostiteľ JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 Ďalej_položka 빌드에서는 Pripojiť_položka 파일을 포함하지 않는다. Súbor obsah_VALUE 변경과 položka_Zoznam 제거도 Ďalej_položka 빌드에 반영된다. 원본 hostiteľ 파일에는 쓰지 않는다. predvolená_hodnota `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 predvolená_hodnota 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 lekcia_VALUE Súbor 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 Podpora_VALUE klip 안에 있어야 한다.

## Podpora_VALUE klip

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| lekcia_VALUE | 패키지 없는 단일 lekcia_VALUE, 정적 funkcia_VALUE, 재귀, Argumenty/vrátiť_KR | 실행마다 단일 lekcia_VALUE 적재, public static main(String[]) |
| predvolená_hodnota VALUE | int, boolean, char, String, main의 String[] Argumenty | celé_číslo·zdroj operand_Vrstvy, String, int[], String[], 내부 StringBuilder |
| príkaz_VALUE | 초기값 있는 miestny_Rozsah deklarácia, úloha_VALUE, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 celé_číslo·zdroj 바이트코드와 podmienka vetva |
| výraz_VALUE | 십진 celé_číslo, UTF-8 소스의 reťazec_VALUE/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, reťazec_VALUE 결합 | celé_číslo operácia_VALUE·Bit_VALUE operácia_VALUE·Typ_VALUE CONVERT_VALUE, 단락 평가, pole_VALUE prístup_položka |
| Súbor | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | skutočný_údaje jadro_VALUE 파일서술자와 Pripojiť, generovať·vymazať_Obsah·이어쓰기·EOF |
| Výstup | System.out.print/println: int/boolean/char/String, println() | 동일 |
| reťazec_VALUE/Argumenty | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), reťazec_VALUE 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 miestny_Rozsah deklarácia, 오버로드, 임의 Typ_VALUE CONVERT_VALUE, pole_VALUE generovať ZDROJ, 8/16진 리터럴, Unicode zdroj_strom 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 konštanta_VALUE 축소 변환을 구현하지 않는다. externý_VALUE `.class`의 `int[]` generovať/Čítanie/쓰기는 지원하므로 hostiteľ `javac --release 8`로 만든 pole_VALUE 예제는 실행할 수 있다.

objekt_VALUE hodnota_poľa·일반 objekt_VALUE generovať·상속·인터페이스·여러 lekcia_VALUE Pripojiť, long/float/double, výnimka Proces_VALUE_položka, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java výnimka 객체를 던지지 않고 진단 후 v_termíne_splatnosti_položka 프로그램을 종료한다. 객체와 reťazec_VALUE Store_VALUE 공간은 Vykonať_príkaz Skončiť_program 시 používateľ oblasť_VALUE_0e9a97ab 전체와 함께 회수한다. 지속 Vykonať_príkaz 중 GC는 없다.

## Vykonať_príkaz 한도와 chyba

| zdroj_VALUE | 한도 |
| --- | --- |
| zdroj_strom/lekcia_VALUE Súbor | 각각 16KiB |
| kompilátor | token_VALUE 2,047개, generovať kód_VALUE 4KiB, konštanta_VALUE 풀 4KiB |
| funkcia_VALUE/Argumenty | 클래스당 32함수, 함수당 16인수 |
| JVM konštanta_VALUE | 511개 |
| JVM funkcia_VALUE kód_VALUE | 함수당 8KiB |
| JVM 호출/operand_Vrstvy/miestny_Rozsah 변수 | 32프레임, 프레임당 operand_Vrstvy 128칸·miestny_Rozsah 128칸 |
| JVM objekt_VALUE Store_VALUE adresa_oblasť | 8,192개 32비트 칸, 헤더 포함 약 32KiB |
| Vykonať_príkaz | 최대 500,000 Príkaz, 기존 커널의 약 3초 CPU Vykonať_príkaz 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 Podpora_VALUE 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM slovník 검증기를 구현한 것은 아니다. Súbor/atribút_VALUE dĺžka_VALUE, konštanta_VALUE zdroj, Príkaz·vetva 경계를 검사하고, Vykonať_príkaz 중 operand_Vrstvy formát_VALUE·miestny_Rozsah incializovať·pole_VALUE dolný_index_VALUE·objekt_VALUE 참조를 검사한다. používateľ 코드의 페이지·hardvér_port 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, kompilovať_zdroj·JVM 오류는 `Exit: 1`, Príkaz Argumenty 오류는 `Exit: 2`다. CPU čas_VALUE 상한은 기존 `Exit: 124`이며, používateľ ELF 자체의 CPU/런타임 오류는 기존 Skončiť_program 코드를 따른다. zlyhanie_VALUE 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## Java Súbor vstup_a_výstup

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 lekcia_VALUE 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 BACK_VALUE `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. predvolená_hodnota Výstup 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. výnimka objekt_VALUE·try/catch·try-with-resources는 지원하지 않으며 Súbor 오류를 진단하고 프로그램을 종료한다. pole_VALUE vstup_a_výstup, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 Súbor 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 셸 `sync`가 필요하다. 예제의 Súbor 이름은 v_termíne_splatnosti_položka 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 skutočný_údaje 게스트 kompilovať_zdroj 결과를 OpenJDK `-Xverify:all`로 skúsiť_znova_VALUE 실행해 Súbor 바이트와 출력을 대조한다. 범위와 Store_VALUE médiá_VALUE 사용법은 [posix-kor 안내](../posix-kor/안내.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
