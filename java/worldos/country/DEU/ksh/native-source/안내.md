# JDeuOS

현재 자체 ARM64 배포판은 [LICENSE](LICENSE)의 COSL 상업 조건을 유지한다. 제3자 라이선스의 권리는 별도로 보장하며, 배포 시 소스·재연결 자료를 포함하는 절차는 [COSL 배포 안내](platforms/rpi4-native/COSL배포안내.md)에 있다.

자체 ARM64 판의 `ipconfig`/`ip`, `ping`, `ps`/`top`, `free`/`df`, `poweroff`와 한국어 명령은 [네트워크·체계 명령 안내](platforms/rpi4-native/네트워크와체계명령.md)를 참고한다. 새 커널을 부팅한 뒤 `help system`으로 볼 수 있다.

Raspberry Pi 4 **자체 Java ARM64 커널**은 [자체 Pi4 안내](platforms/rpi4-native/안내.md)에 있다. Linux 없이 부팅하며 GUI 터미널·vi, 자체 JVM의 Swing 일부 API, TCP/UDP·FTP, 게스트 TinyCC·MicroPython, C/C++의 posix-kor 호출을 제공한다. [한국어 Java 통신·예외 API](platforms/rpi4-native/한국어자바/안내.md)와 [한국어 소스 명명](platforms/rpi4-native/명명/안내.md)을 지원한다. [자체 SSH·VNC 및 GENET 드라이버](platforms/rpi4-native/외부접속안내.md)를 포함하며, 네트워크는 QEMU의 UART SLIP 경로로 검증했다. 실제 Pi 4 GENET 동작은 미검증이고, USB 입력·영속 저장과 전체 OpenJDK·Swing은 아직 지원 범위 밖이다.

Raspberry Pi 4용 Linux·OpenJDK 실행판과 사용자 환경 이동 기능은 [라즈베리파이 실행판](platforms/rpi4/README.md)에 있다. 실제 ARM64 JDK/JRE와 시스템·사용자 이미지 빌드 경로를 제공한다. 기존 자체 x86 커널과는 별도 실행 기반이다. 일반 Java `.class`/JAR의 실행 파일 생성은 [OpenJDK 실행 파일](compiler/OpenJDK-실행파일.md), 한국어 API는 [한국어 Java 라이브러리](한국어자바/안내.md)를 참고한다.

`jkoros`는 `engos`의 기능을 Java 관리 커널로 옮기는 프로젝트다. 프로젝트가 소유하는 Java 함수, 변수, 형식 및 Java 파일 이름은 한국어로 작성한다. 표준 Java 실행기의 `main`, Java 표준 라이브러리 형식, x86 부트 ABI 등 외부 계약은 보존한다. 자체 ARM64 실행기는 한국어 `시작()`도 진입점으로 지원하며, 한국어 GUI·작업 가닥을 JVM에 직접 구현했다. 자체 ARM64 C 연결부·Python 도구와 공용 x86·ARM64 AOT 번역기의 자체 이름도 한국어로 작성한다. 이전 경로의 호환 진입점, OpenJDK 보조 도구와 Linux 판 도구에는 영어 이름이 남아 있고 [명명 원칙·말의 근거·전체 원문 검토 범위](platforms/rpi4-native/명명/안내.md)를 별도로 기록한다.

## 현재 구현

아래 목록은 기존 `원천/`의 JVM 관리 커널에 대한 것이다. 실제 네이티브 커널의 범위는 `os/안내.md`에서 별도로 설명한다.

- 정렬 할당과 해제를 지원하는 기억공간 관리자
- 주소 공간, 쪽 연결, 쓰기 시 복사(COW)
- 과정 식별자, 준비 대기열, fork/wait 상태
- 과정별 파일 서술자, open/read/seek/dup/close
- ELF32 식별 및 구역 검사
- 키보드·마우스 입력 사건 대기열
- 직렬 단말과 네이티브 하드웨어 경계
- 관리 커널 전체 자동 시험

세부 대응 범위와 아직 필요한 네이티브 연결은 [기능 대응표](문서/기능대응.md)에 기록한다.

## 빌드와 시험

새 네이티브 구현은 `compiler/`와 `os/`에 있다. 기존 `원천/`의 JVM 관리 커널은 그대로 보존하며, 두 구현의 시험과 기능 범위는 서로 다르다.

```sh
cd /home/user/jkoros
make                 # 네이티브 계산 예제 + Java 커널 ELF
make iso             # os/build/kernel.iso
make run             # QEMU 직렬 단말; help 입력 (종료는 Ctrl+A, X)
make run-gui         # ISO를 QEMU 화면/PS2 키보드로 실행
make vbox            # 전용 VirtualBox VM 자동 생성·실행 (GUI)
make vbox-status     # VirtualBox 상태·ISO·직렬 기록 경로 확인
make test-vbox       # VirtualBox 실행기 상태 처리 시험 (실제 VM 변경 없음)
make test            # 컴파일러 시험 + ELF/ISO 부팅 및 명령 입력 시험
make apps            # 독립 사용자 ELF 프로그램 빌드
make test-network    # 사용자 모드·UDP 왕복·메모리 보호 시험
make test-java       # 게스트 javac/JVM + OpenJDK 양방향 교차 실행 시험
make posix-kor       # 한국어 C 헤더와 실제 커널 호출 라이브러리
make test-posix      # 파일/UDP/저장/Java 파일 입출력 시험
make -C os run-store # 전용 저장 매체로 QEMU 부팅
make legacy-test     # 아래 기존 JVM 관리 커널의 47개 시험
```

`compiler/`는 호스트의 `javac`를 문법·형 검사 전단으로 사용하고 자체 바이트코드→x86 변환기로 ELF32 기계어를 만든다. 빌드할 때는 JDK가 필요하지만 생성된 커널과 ELF는 외부 JVM 없이 실행된다. 전체 Java, 객체 모델, 표준 라이브러리와 기존 관리 커널 전체의 AOT 변환은 아직 지원하지 않는다. 자세한 지원 문법과 명령은 [컴파일러 안내](compiler/안내.md), 실제 부팅 기능과 한계는 [네이티브 운영체제 안내](os/안내.md)를 참고한다.

네이티브 셸에 자체 제한형 `javac`와 `java`를 추가했다. `edit Demo.java`로 소스를 입력하고 `.save`로 저장한 뒤 `javac Demo.java`, `java Demo`로 **게스트 내부에서 컴파일하고 실행**할 수 있다. 기본 예제는 `javac Hello.java`, `java Hello`다. 파일은 RAM에서 동작하며, 전용 저장 매체를 연결하면 `sync`로 재부팅 후에도 보존할 수 있다. **OpenJDK/JDK 전체 이식은 아니며**, 단일 클래스·정적 함수·정수·문자열·조건/반복문과 일부 표준 호출을 지원한다. 지원 범위, 외부 파일 적재와 시험은 [Java 개발 환경 안내](문서/자바개발환경.md)에 있다.

네이티브 셸에서 `apps`, `run hello first second`, `net`, `run netcheck`를 사용할 수 있다. 독립 ELF를 ring 3에 적재하고 `int 0x80` 호출을 통해 출력·인수·UDP 네트워크를 제공한다. 별도 호스트 터미널에서 `python3 os/도구/자료되돌리기.py --port 9000`을 실행한 뒤 게스트에서 `run udp 10.0.2.2 9000 hello`로 실제 왕복을 확인한다. 새 프로그램 등록, API 및 제한은 [사용자 실행·네트워크 안내](os/사용자/안내.md)를 참고한다. 현재 QEMU RTL8139·정적 IPv4·UDP 전용이며 TCP/DNS는 미지원이며, 전용 IDE 저장 형식과 POSIX 파일/UDP 일부 기능을 추가했다.

`make vbox`는 `jkoros operating system` 전용 VM을 만들고 디스크 없이 ISO로 부팅한다. 실행 중이면 유지하고, 저장·일시정지 상태이면 재개하며, 꺼져 있을 때만 새 ISO를 빌드해 연결한다. VirtualBox에서 부팅과 셸의 사용자 프로그램 실행을 확인했다. 다만 현재 VirtualBox용 네트워크 드라이버는 없어 네트워크 장치를 비활성화한다. UDP 시험에는 `make run`을 사용한다. 상태별 동작과 새 빌드 반영 방법은 [VirtualBox 실행 안내](문서/가상상자실행.md)에 있다.

기존 관리 커널만 시험하려면:

```sh
cd /home/user/jkoros
make -f 만들기.mk 검사
make -f 만들기.mk 호스트
```

`호스트`는 여전히 JVM 관리 계층의 동작 시험이다. `make -f 만들기.mk 이미지`는 새 `os/`의 제한형 네이티브 커널 ISO를 만든다. 기존 `원천/`의 파일체계·과정·통신망 구현 전체를 이 ISO에 이식했다는 의미는 아니다.

한국어 함수·변수·파일 이름과 실제 C API는 [posix-kor](posix-kor/안내.md)에 있다. 게스트 Java에서는 `FileInputStream`·`FileOutputStream`의 단일 바이트 입출력도 지원한다. 전체 POSIX·OpenJDK·Swing 지원으로 확대된 것은 아니다.

외부 배포용 `pack.sh` / `unpack.sh`와 자동 의존성 복원은 [배포 안내](distribution/README.md)를 참고하세요.
