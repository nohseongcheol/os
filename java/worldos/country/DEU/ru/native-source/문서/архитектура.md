# JDeuOS архитектура

아래는 объект_ЗНАЧЕН 기반 관리 ядро_ЗНАЧЕН 전체의 цель_объект 구조다. текущий_товар фактический_данные запуск_машины 가능한 제한형 구현은 `compiler/`와 `os/`에 있으며 [네이티브 операционная_система файл_сведений_eb81d7d9](../os/файл_сведений_eb81d7d9.md)에 реализация 범위를 명시한다. 아래의 GC·контекст_ЗНАЧЕН перейти_МОДА·файловая_система 등이 새 ISO에 모두 포함돼 있지는 않다.

```text
GRUB 또는 UEFI
  ↓
x86 최소 부트·트랩 слой_ЗНАЧЕН
  ↓
Java AOT 실행기와 объект_ЗНАЧЕН·МАССИВ_ЗНАЧЕН·GC 런타임
  ↓
аппаратный_ЗНАЧЕН граница_ЗНАЧЕН
  ↓
Java 관리 ядро_ЗНАЧЕН
  ├─ Память_регион/쪽관리/COW
  ├─ Процесс_ЗНАЧЕН/배정/wait
  ├─ файловая_система/ELF/POSIX
  └─ входные_данные_ЗНАЧЕН/запоминающее_устройство/сеть_стек
```

OpenJDK 자체는 이미 운영체제가 제공하는 файл, 스레드, 가상 기억공간을 전제로 한다. 따라서 ядро_ЗНАЧЕН 부팅에는 OpenJDK를 그대로 넣지 않고 제한된 Java 바이트코드 AOT와 작은 런타임을 사용한다.

네이티브 계층에는 `in/out`, `hlt`, CR0/CR2/CR3/CR4, `iret`, контекст_ЗНАЧЕН 저장처럼 Java로 표현할 수 없는 CPU 동작만 남긴다. 정책과 자료구조는 Java에 둔다.
