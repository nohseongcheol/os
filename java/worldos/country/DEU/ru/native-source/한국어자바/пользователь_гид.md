# jkoros русский библиотека пользователь_гид

확인일: 2026-09-27. 대상은 `platforms/rpi4`의 **ARM64 Linux + OpenJDK 실행판**이며, QEMU에서도 같은 Java 라이브러리를 사용한다. `os/`의 свой x86 ядро_ЗНАЧЕН 및 `устаревший_источник/`의 관리 ядро_ЗНАЧЕН 모형과 구분한다.

## 1. текущий_товар 제공하는 библиотека

패키지는 `русский.자바`, операционная_система 안의 JAR 경로는 `/opt/jkoros/lib/한국어자바.jar`다. **вспомогательное_приложение_ЗНАЧЕН Класс_ЗНАЧЕН 5개, 공개 статический_ЗНАЧЕН метод_ЗНАЧЕН 22개, 별도 GUI 프로그램인 рабочая_область 1개**가 있다. JAR는 Java 11 이상을 대상으로 빌드하며 текущий_товар ARM64 배포판에는 OpenJDK 25가 포함돼 있다.

| Класс_ЗНАЧЕН | метод_ЗНАЧЕН 수 | 기능 | исходныйКод |
|---|---:|---|---|
| `файл` | 9 | UTF-8 텍스트·байт_ЗНАЧЕН файл, Каталог_ЗНАЧЕН, ввод_Список | [файл.java](исходныйКод/русский/자바/файл.java) |
| `문자` | 5 | UTF-8 ПРЕОБР_ЗНАЧЕН, NFC нормализовать_ЗНАЧЕН, кодовое_значение 포인트, строка_ЗНАЧЕН граница_ЗНАЧЕН | [문자.java](исходныйКод/русский/자바/문자.java) |

| `작업` | 4 | 스레드 실행·минутку_ЗНАЧЕН, 고정 Размер 작업 программа_Launcher | [작업.java](исходныйКод/русский/자바/작업.java) |

표준 JDK 전체를 한국어로 번역한 라이브러리는 아니다. Java 키워드와 `String`, `Path`, `Socket`, `JFrame`, `IOException` 같은 표준 тип_данных·예외를 함께 사용한다. 이 도우미에 없는 기능은 OpenJDK의 표준 API 또는 별도 라이브러리로 구현한다. 예를 들어 HTTP POST, UDP, Swing кнопка·메뉴에는 각각 표준 Java API를 사용한다.

## 2. Java에서 Пуск_дело

게스트 운영체제의 작업 폴더에서 `사용예.java`를 작성한다.

```java
import русский.자바.*;
import java.nio.file.Path;

public class 사용예 {
    public static void main(String[] аргументы) throws Exception {
        Path Каталог_ЗНАЧЕН = файл.Create_Каталог(файл.путь("사용예자료"));
        Path 문서 = Каталог_ЗНАЧЕН.resolve("приветствие_ae353e94.txt");
        файл.Запись(문서, "한글 😀");
        String контент_ЗНАЧЕН = файл.Чтение(문서);
        System.out.println(контент_ЗНАЧЕН);
        System.out.println(문자.код_знака_СЧЁТ(контент_ЗНАЧЕН)); // 한, текст, 공백, 😀 → 4
        Thread работа_ЗНАЧЕН = 작업.запустить("приветствие_ae353e94 작업", () -> System.out.println("작업 실행"));
        작업.기다리기(работа_ЗНАЧЕН);
    }
}
```

```sh
javac -encoding UTF-8 -cp /opt/jkoros/lib/한국어자바.jar 사용예.java
java -cp .:/opt/jkoros/lib/한국어자바.jar 사용예
```

로그인 환경에 значение_по_умолчанию `CLASSPATH`도 설정돼 있지만, 명시적인 `-cp`는 다른 실행 환경에서도 경로를 분명하게 한다. 사용자가 `-cp`를 지정하면 필요한 JAR와 Класс_ЗНАЧЕН 폴더를 모두 그 값에 포함해야 한다.

узел 저장소에서는 다음처럼 сборка·실행한다. узел 경로와 게스트의 `/opt/...` 경로는 서로 다르다.

```sh
cd /home/user/jkoros/한국어자바
make
javac -encoding UTF-8 -cp build/한국어자바.jar 예제/приветствие_ae353e94.java
java -cp build/한국어자바.jar:예제 приветствие_ae353e94
```

## 3. 전체 вспомогательное_приложение_ЗНАЧЕН API

아래 메서드는 모두 `public static`이며, 객체를 만들지 않고 `файл.Чтение(...)`처럼 호출한다. 표의 이름은 фактический_данные источник_дерево 및 JAR의 `javap -public` 결과와 대조했다. 선언된 검사 исключение 외에도 잘못된 аргументы 등에 대한 표준 Java 실행 시 예외가 발생할 수 있다.

### файл: `русский.자바.файл`

`Path`는 `java.nio.file.Path`, `List`는 `java.util.List`다.

| метод_ЗНАЧЕН | тип_возвращаемого_значения | Действие·условие |
|---|---|---|
| `путь(String Название)` | `Path` | 이름을 путь 객체로 ПРЕОБР_ЗНАЧЕН. фактический_данные 파일을 만들지는 않음 |
| `Чтение(Path путь)` | `String` | файл 전체를 UTF-8 텍스트로 чтение_KR |
| `Запись(Path путь, String контент_ЗНАЧЕН)` | `Path` | UTF-8 Store_ЗНАЧЕН. 파일이 없으면 생성하고, 있으면 기존 내용을 비움 |
| `чтение_байт_ЗНАЧЕН(Path путь)` | `byte[]` | файл 전체를 байт_ЗНАЧЕН 배열로 чтение_KR |
| `запись_байт_ЗНАЧЕН(Path путь, byte[] контент_ЗНАЧЕН)` | `Path` | байт_ЗНАЧЕН Store_ЗНАЧЕН. 없으면 생성하고, 있으면 기존 내용을 비움 |
| `Create_Каталог(Path путь)` | `Path` | 필요한 상위 폴더까지 генерировать |
| `있는가(Path путь)` | `boolean` | 존재 여부 проверять. 확인할 수 없는 경우도 `false`работа_ЗНАЧЕН 수 있음 |
| `удалить_ввод_c8dbc399(Path путь)` | `boolean` | 삭제했으면 `true`, 없으면 `false`. 폴더의 재귀 삭제는 아님 |
| `ввод_Список(Path путь)` | `List<Path>` | 바로 아래 항목을 путь выровнять_ЗНАЧЕН 순서로 Возврат_KR. 재귀 탐색은 아님 |

`путь`, `있는가`를 제외한 위 메서드는 `IOException`을 선언한다. `Запись`와 `запись_байт_ЗНАЧЕН`는 상위 폴더를 자동으로 만들거나 내용을 이어 쓰지 않는다. 필요한 폴더는 먼저 생성한다. 큰 파일은 전체 내용을 메모리에 담는 대신 표준 Java 스트림·канал_ЗНАЧЕН_a391a59a API를 사용하는 방식으로 작성할 수 있다.

### 문자: `русский.자바.문자`

| метод_ЗНАЧЕН | тип_возвращаемого_значения | Действие·условие |
|---|---|---|
| `кодировать(String контент_ЗНАЧЕН)` | `byte[]` | 문자열을 UTF-8 바이트로 ПРЕОБР_ЗНАЧЕН |
| `расшифровать_данные(byte[] контент_ЗНАЧЕН)` | `String` | UTF-8 바이트를 문자열로 ПРЕОБР_ЗНАЧЕН. 잘못된 입력은 대체 문자로 Процесс_ЗНАЧЕН_ввод |
| `нормализовать_ЗНАЧЕН(String контент_ЗНАЧЕН)` | `String` | Юникод_ЗНАЧЕН NFC нормализовать_ЗНАЧЕН. 예: состав_ЗНАЧЕН 자모 `ᄀ` + `ᅡ` → `가` |
| `код_знака_СЧЁТ(String контент_ЗНАЧЕН)` | `int` | UTF-16 кодовое_значение 단위가 아닌 Юникод_ЗНАЧЕН кодовое_значение 포인트 수 |
| `낱말(String контент_ЗНАЧЕН, Locale Язык)` | `List<String>` | Назначить_ЗНАЧЕН 언어의 `BreakIterator` 낱말 경계로 나눈 SMS_диапазон |

`낱말`은 공백·문장부호 구간도 반환한다. 자연어 형태소 분석기나 공백을 제거한 Word_ЗНАЧЕН ввод_Список API는 아니다. `нормализовать_ЗНАЧЕН`는 입력기나 ПЕРЕВОД_источник 기능이 아니다. кодовое_значение 포인트 수 역시 사람이 보는 знак_ЗНАЧЕН 수와 항상 같지는 않다. 여러 кодовое_значение 포인트로 이루어진 결합 문자·가족 이모지 등을 구분해야 한다.

### коммуникация: `русский.자바.коммуникация`

| метод_ЗНАЧЕН | тип_возвращаемого_значения | Действие·условие |
|---|---|---|
| `ВЗЯТЬ_ЗНАЧЕН(URI АДРЕС, Duration ограничение_времени)` | `HttpResponse<String>` | HTTP(S) GET. Подключить 및 запрос ограничение_времени Настройки. ответ 본문을 UTF-8로 анализировать_ЗНАЧЕН |
| `Connect_Endpoint(String АДРЕС, int аппаратный_порт, int 제한밀리초)` | `Socket` | TCP Подключить 후 같은 값으로 Чтение 제한시간도 Настройки |

`ВЗЯТЬ_ЗНАЧЕН`는 `IOException`, `InterruptedException`을 선언한다. 제한시간은 양수다. 404·500 같은 HTTP ошибка 상태도 응답으로 반환하므로 `statusCode()`로 판단하고 `body()`로 본문을 읽는다. текущий_товар 구현은 호출마다 HTTP 클라이언트를 만들며 자동 리다이렉트 설정을 추가하지 않는다.

`Connect_Endpoint`는 `IOException`을 선언한다. 연결된 소켓은 호출자가 `close()` 또는 try-with-resources로 닫아야 한다. 제한밀리초의 0은 제한 없음이며, Запись 전체의 крайний_срок_ЗНАЧЕН 시간을 보장하는 옵션은 아니다.

```java
var ответ = коммуникация.ВЗЯТЬ_ЗНАЧЕН(
    java.net.URI.create("http://127.0.0.1:8000/"),
    java.time.Duration.ofSeconds(5));
System.out.println(ответ.statusCode());
System.out.println(ответ.body());
```

위 조각은 метод_ЗНАЧЕН 안에서 실행하며 별도로 해당 주소의 서버를 실행해야 한다. Java исключение 처리가 필요하다.

### 작업: `русский.자바.작업`

| метод_ЗНАЧЕН | тип_возвращаемого_значения | Действие·условие |
|---|---|---|
| `запустить(String Название, Runnable Действие)` | `Thread` | 이름을 지정한 스레드를 만들고 즉시 запустить |
| `기다리기(Thread поток_ЗНАЧЕН_5b72a632)` | `void` | 해당 스레드가 종료할 때까지 `join()` |
| `쉬기(long 밀리초)` | `void` | 호출한 스레드를 Назначить_ЗНАЧЕН значение_времени 동안 `sleep()` |
| `Workbench_ЗНАЧЕН(int количество_потоков)` | `ExecutorService` | 고정 Размер 작업 программа_Launcher генерировать. 가닥수는 양수 |

`기다리기`, `쉬기`는 `InterruptedException`을 선언한다. 작업 실행기는 использовать_ЗНАЧЕН 후 `shutdown()`으로 종료하고 필요하면 `awaitTermination(...)`으로 완료를 기다린다. Swing 이벤트 Процесс_ЗНАЧЕН_ввод 가닥에서 긴 작업이나 `기다리기`를 실행하면 화면이 멈출 수 있다.

### экран: `русский.자바.экран`

| метод_ЗНАЧЕН | тип_возвращаемого_значения | Действие·условие |
|---|---|---|
| `나중에(Runnable Действие)` | `void` | Swing 이벤트 Процесс_ЗНАЧЕН_ввод 가닥에 실행을 예약하고 Возврат_KR |

`Окно`을 Swing 이벤트 Процесс_ЗНАЧЕН_ввод поток_ЗНАЧЕН_5b72a632 밖에서 부르면 `IllegalStateException`이 발생한다. 그래픽 세션도 필요하다. QEMU에서는 VNC 데스크톱의 터미널에서 실행한다.

반환된 `JFrame`에 표준 Swing API를 추가로 사용할 수 있다. 창의 Закрыть 동작은 `DISPOSE_ON_CLOSE`다. `экран.나중에`가 반환됐다고 Окно 생성이 이미 끝난 것은 아니다.

## 4. Python과 C++에서 사용할 수 있는가?

| метод_МОДА | текущий_товар объявления Состояние_ЗНАЧЕН | 호출 가능 клип |
|---|---|---|
| Java → русский JAR | значение_по_умолчанию объявления | 위 22개 메서드와 рабочая_область |
| Python → `java` ребенок_ЗНАЧЕН 프로세스 | Python·Java значение_по_умолчанию объявления | 작은 Java 진입점을 통해 호출하고 표준 текстовыйВывод·файл 등으로 результат вперед_ЗНАЧЕН |
| Python → JPype → JVM | JPype는 значение_по_умолчанию 배포에 없음 | 별도 установить_ЗНАЧЕН 후 Java Класс_ЗНАЧЕН·метод_ЗНАЧЕН 호출 가능. 이 배포판의 ARM64/musl/Python 3.14 조합은 добавить_ввод проверить 필요 |
| C++ → JNI → JVM | `g++`, JNI 헤더, `libjvm.so` объявления | JVM을 생성하고 русский Класс_ЗНАЧЕН·메서드를 직접 호출할 수 있음 |
| Python용 독립 русский библиотека | текущий_товар значение_по_умолчанию 제공 없음 | 필요하면 Python 표준 라이브러리를 감싸는 русский 모듈을 별도로 작성 |
| C/C++용 독립 русский библиотека | свой x86 `posix-kor`와 свой ARM64 커널용 начальное_состояние RAM файл 연결이 별도로 존재 | 둘 다 이 Linux/OpenJDK 실행판의 libc 라이브러리는 아님 |

Python의 일반 `import`СЕКУНДЫ_операнд `ctypes.CDLL`로 JAR를 바로 읽을 수는 없다. C++의 `#include`СЕКУНДЫ_операнд 일반 네이티브 링커만으로 Java 메서드를 연결할 수도 없다. JVM 프로세스 또는 JVM Подключить 계층을 거쳐야 한다.

### Python: добавить_ввод 패키지 없이 호출

실행 가능한 예제 원문은 [문자명령.java](예제/다른언어/문자명령.java), [PYTHON_Вызовы.py](예제/다른언어/PYTHON_Вызовы.py)다. Python이 Java 진입점을 실행하고 `문자.код_знака_СЧЁТ`의 целое_число 결과를 받는다. аргументы 목록을 사용하며 оболочка команда 문자열을 조립하지 않는다. `subprocess.run`의 프로세스 실행·Выход_программа кодовое_значение·текстовыйВывод Процесс_ЗНАЧЕН_ввод 방식은 [Python 공식 문서](https://docs.python.org/3/library/subprocess.html)를 따른다.

두 예제 파일을 게스트의 같은 폴더에 복사한 BACK_ЗНАЧЕН 그 폴더에서 실행한다. 예제 файл 자체는 значение_по_умолчанию 시스템 이미지에 자동 설치돼 있지 않다.

```sh
mkdir -p classes
javac -encoding UTF-8 -cp /opt/jkoros/lib/한국어자바.jar -d classes 문자명령.java
python3 PYTHON_Вызовы.py --text '한글 😀'
```

текстовыйВывод: `Python → русский.자바.문자.код_знака_СЧЁТ: 4`

이 예제의 Python ФУНКЦИЯ_ЗНАЧЕН `код_знака_СЧЁТ`는 이번 문서의 Подключить 예제이며 기존에 설치된 Python 라이브러리는 아니다. текущий_товар 예제는 호출할 때마다 JVM 프로세스를 시작한다. Java объект_ЗНАЧЕН 자체를 Python으로 가져오는 방식은 아니며, 다른 메서드를 사용하려면 진입점의 аргументы·результат 형식을 확장한다.

### Python: JPype로 같은 프로세스에서 호출

JPype를 별도 설치한 환경에서는 Далее_товар 형태로 연결할 수 있다. **아래는 выделение_ЗНАЧЕН 가능한 Подключить 방법이며, текущий_товар 배포판에 JPype가 설치돼 있거나 실행 검증됐다는 뜻은 아니다.** JVM 시작과 `JClass`를 통한 Класс_ЗНАЧЕН 접근은 [JPype 공식 описание](https://jpype.readthedocs.io/en/latest/userguide.html)을 참고한다.

```python
import jpype

jpype.startJVM(
    "/usr/lib/jvm/java-25-openjdk/lib/server/libjvm.so",
    classpath=["/opt/jkoros/lib/한국어자바.jar"])
try:
    문자 = jpype.JClass("русский.자바.문자")
    print(문자.код_знака_СЧЁТ(jpype.JString("한글 😀")))
finally:
    jpype.shutdownJVM()
```

Python·JVM·Подключить 모듈의 CPU 아키텍처가 맞아야 한다. 이 실행판은 ARM64 + musl이므로 일반 x86_64/glibc용 바이너리를 그대로 설치하는 방식은 맞지 않는다. JPype установить_ЗНАЧЕН·패키지 빌드는 이번 문서 작업에서 수행하지 않았다.

### C++: JNI로 직접 호출

[자바호출.cpp](예제/다른언어/자바호출.cpp)는 фактический_данные 실행 가능한 예제다. JVM을 작업 스레드에서 생성하고 Далее_товар 메서드를 찾는다.

```cpp
jclass type = env->FindClass("русский/자바/문자");
jmethodID method = env->GetStaticMethodID(
    type, "код_знака_СЧЁТ", "(Ljava/lang/String;)I");
```

JVM генерировать·종료와 스레드 연결은 [JNI Invocation API](https://docs.oracle.com/en/java/javase/25/docs/specs/jni/invocation.html)의 방식이다. `JNIEnv*`는 генерировать·연결된 스레드에서 사용해야 한다. 예제는 Java 예외를 확인하고 JVM 종료까지 처리한다.

게스트에 `자바호출.cpp`를 복사한 BACK_ЗНАЧЕН 컴파일한다. 로그인 환경의 `JAVA_HOME`은 `/usr/lib/jvm/java-25-openjdk`다.

```sh
g++ -std=c++11 -Wall -Wextra -pthread \
  -I"$JAVA_HOME/include" -I"$JAVA_HOME/include/linux" \
  자바호출.cpp -L"$JAVA_HOME/lib/server" \
  -Wl,-rpath,"$JAVA_HOME/lib/server" -ljvm -o 자바호출
./자바호출 /opt/jkoros/lib/한국어자바.jar
```

текстовыйВывод: `C++ → русский.자바.문자.код_знака_СЧЁТ: 4`

예제는 `한글 😀`을 UTF-16으로 만들어 `NewString`에 전달한다. `NewStringUTF`가 받는 modified UTF-8은 일반 UTF-8과 차이가 있으므로, 일반 UTF-8 이모지 바이트를 그대로 넘기는 예제로 작성하지 않았다. [JNI строка_ЗНАЧЕН формат_ЗНАЧЕН](https://docs.oracle.com/en/java/javase/25/docs/specs/jni/types.html#modified-utf-8-strings)

다른 русский 메서드도 JNI 서명과 аргументы 자료형을 맞춰 호출할 수 있다. 예를 들어 `Path`를 받는 файл API는 먼저 `файл.путь`로 Java путь 객체를 얻어 전달한다. Swing 호출에는 그래픽 세션과 이벤트 Процесс_ЗНАЧЕН_ввод поток_ЗНАЧЕН_5b72a632 규칙도 그대로 적용된다. JNI는 Java 실행을 기계어로 대체하는 기능이 아니며 JVM이 계속 필요하다.

### 기존 posix-kor와의 관계

추가된 [свой ARM64 Подключить](../posix-kor/arm64-native/файл_сведений_eb81d7d9.md)은 C++에서 AOT Java 커널의 RAM файл API를 직접 호출하며, 별도 EL0 пространство_пользователя 라이브러리로 файл/UDP 루프백 SVC 호출도 제공한다. JNI를 사용하지 않는다. 이 문서의 ARM64 **Linux** 및 русский Java JAR와는 다른 실행 기반이며 свой 커널은 별도 제한형 Java компилятор/JVM과 MicroPython 1.24.1을 실행한다. MicroPython의 `import jkoros`로 Java ядро_ЗНАЧЕН файл·UDP 루프백·прямоугольник 호출이 가능하지만 이 문서의 JAR를 가져오는 기능은 아니다. свой 커널의 전체 OpenJDK/JRE/CPython 이식은 아직 미완성이다.

[posix-kor](../posix-kor/файл_сведений_eb81d7d9.md)에는 `открыть_файл`, `чтение_файл_данные`, `запись_файл_данные`, `Close_файл`, `Create_участник`, `написать_датаграмма_данные` 등의 русский C 별칭이 있다. 그러나 구현은 **свой jkoros i386 커널의 `int 0x80` 호출 규약용**이다.

이 `libposix-kor.a`와 свой `sys/stat.h` 등의 헤더는 текущий_товар ARM64 Linux 실행판의 libc/C++용 라이브러리가 아니다. 해당 헤더·바이너리를 ARM64 Linux 프로그램에 그대로 연결해서는 ABI가 맞지 않는다. C++용 русский Класс_ЗНАЧЕН 라이브러리나 Python용 바인딩을 значение_по_умолчанию 제공하는 상태도 아니다. текущий_товар Linux 실행판에서 그와 같은 독립 API를 제공하려면 Linux 표준 라이브러리를 대상으로 별도로 реализация·빌드해야 한다.

## 5. проверять 범위와 재현

패키지 объявления 여부는 [распределение_ЗНАЧЕН 패키지 ввод_Список](../platforms/rpi4/dist/packages.lock.json) 및 сборка 루트의 фактический_данные 파일로 확인했다. JNI 헤더는 JDK의 `include/jni.h`, `include/linux/jni_md.h`, JVM 라이브러리는 `lib/server/libjvm.so`에 있다. 사용자가 이후 별도로 설치한 패키지는 이 значение_по_умолчанию распределение_ЗНАЧЕН 목록과 다를 수 있다.

이번에 **узел x86_64/OpenJDK 11에서** Python ребенок_ЗНАЧЕН 프로세스 호출과 C++ JNI 직접 호출을 компилировать_источник·실행해 각각 результат 4를 확인했다. JAR 공개 메서드도 소스와 대조했다. Python Подключить 예제는 добавить_ввод 패키지를 설치하지 않는다.

문서의 Java использовать_ЗНАЧЕН 예제도 компилировать_источник·실행했고, 22개 메서드의 문서 объявления 여부와 로컬 문서 링크를 확인했다. [예제 проверить LOG_ЗАПИСЬ](build/다른언어/проверка_Отчет.json)

기존 ARM64 QEMU에서는 Java의 файл·Юникод_ЗНАЧЕН·스레드·HTTP 및 Swing испытания 결과가 있다. 이번 Python/C++ Подключить 예제의 **ARM64 게스트 실행과 JPype 설치는 별도 검증하지 않았다.** 이미지와 실행 중인 пространство_пользователя 환경은 이 문서 작업에서 변경하지 않았다. [기존 операционная_система проверить LOG_ЗАПИСЬ](../platforms/rpi4/VERIFICATION.md)
