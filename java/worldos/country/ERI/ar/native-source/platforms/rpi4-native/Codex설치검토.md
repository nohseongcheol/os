# ذاتي ARM64 커널의 Codex تثبيت_قيمة 가능성 검토

검토일: 2026-10-05. 소스와 공식 문서를 대조한 설계 검토이며, 게스트에 Codex를 설치하거나
로그인·모델 호출을 실행한 결과는 아니다. ذاتي ARM64 커널과 `../rpi4` Linux 실행판은 구분한다.

حديث_عنصر ذاتي 커널에는 공식 Codex CLI를 그대로 تثبيت_قيمة·실행할 رقم 없다.
기술적으로 필요한 ينفذ_أمر 환경을 추가하거나 Codex를 이식하는 경로는 있으나,
다운로드 أمر 하나를 추가하는 작업으로 해결되지 않는다. JDK/JRE 기능 확장만으로도 해결되지 않는다.

## 확인한 근거

| إدخال_قيمة_962f286b | حديث_عنصر 소스에서 확인한 حالة_قيمة | 직접 실행을 위한 작업 |
|---|---|---|
| ينفذ_أمر ملف | `جهاز/فضاء_المستخدم.c`: AArch64 ET_EXEC만, PT_INTERP/PT_DYNAMIC/PT_TLS يرفض_قيمة, 업로드 ينفذ_أمر 버퍼 16384바이트 | الهدف 바이너리에 맞는 ELF 적재·재배치·ينفذ_أمر تهيئة, ذاكرة_بيانات/ملف 제한 ملحق_قيمة |
| Linux ABI | `جهاز/리눅스호환.inc`: read/write/openat/brk 등 제한된 번호만 عملية_قيمة_إدخال, 나머지는 ENOSYS | libc/런타임에 필요한 시스템 호출을 추가하거나 ذاتي ABI용 런타임 이식 |
| 프로세스·스레드 | 일반 fork/clone/execve, pthread/futex, 시그널, mmap, poll/epoll 계열이 미완성 | 비동기 I/O·스레드·طفل_قيمة أمر ينفذ_أمر·خروج_تطبيق/يلغي_تشغيل 기능 |
| ملف | `مصدر/ذاكرة_الملفات.java`: RAM ملف 64개, 파일당 16 KiB, 비영속 | 큰 ينفذ_أمر ملف·프로젝트·إعدادات·세션을 위한 영속 VFS, ملف إذن_قيمة·مسار·디렉터리 ملحق_قيمة |
| 네트워크 | lwIP TCP/UDP는 있으나 `شبكة_رمز/lwipopts.h`의 LWIP_DNS=0, 일반 HTTPS 클라이언트 없음 | DNS, TLS 인증서 التحقق_من_صحة·신뢰 مستودع_جذر·정확한 طابع_زمني_قيمة, HTTPS/스트리밍 |
| طرفية·أدوات | ذاتي 셸과 GUI 터미널은 있지만 표준 PTY·일반 프로세스 작업 تحكم_قيمة 없음 | تفاعلي CLI용 طرفية 기능, 셸/ملف 검색/بنية_نظام أدوات اتصال |
| ينفذ_أمر إذن_قيمة | EL0 보호는 있으나 Codex의 Linux 샌드박스와 같은 정책 집행 بيئة_التشغيل 없음 | ملف·네트워크·أمر إذن_قيمة 정책과 승인 기능; ذاتي 커널에 맞는 격리 구현 |

여기서 ELF의 PT_TLS는 스레드별 مخزن_قيمة 공간이다. HTTPS의 TLS رمز_الوصول_قيمة 통신과 서로 다른 기능이다.
ELF ملف 형식을 읽을 رقم 있다는 사실만으로 Linux ينفذ_أمر 환경을 제공하는 것은 아니다.
SSH/VNC를 위한 رمز_الوصول_قيمة 라이브러리를 넣은 상태도 HTTPS 구현 완료를 의미하지 않는다.

호스트의 `/home/user/.local/bin/codex`도 확인했다. 이것은 x86-64 ELF ET_DYN이며 약 209 MiB다.
해당 파일을 ARM64 게스트로 복사하여 실행할 رقم 없다. 이 크기를 ARM64 توزيع_قيمة 파일의 크기로
해석하지 않는다. 공식 ARM64 빌드의 الفعلي_بيانات حجم·의존성은 설치할 버전으로 إلحاق_إدخال 검사해야 한다.

## 가능한 구현 مسار

1. **ذاتي 커널에 공식 CLI 직접 이식**
   영속 مخزن_قيمة/VFS와 فضاء_المستخدم ذاكرة_بيانات, 프로세스·스레드·I/O, libc/런타임, DNS/HTTPS,
   طرفية·إذن_قيمة 체계를 갖춘다. 이후 الهدف 버전의 의존성을 조사하여 크로스 بنية_نظام·이식한다.
   Linux 커널을 반드시 탑재할 필요는 없지만, 공식 Linux 바이너리를 그대로 쓸 경우
   그 바이너리가 사용하는 Linux ABI까지 호환해야 한다. 큰 نظام_تشغيل 개발 과제다.

2. **خارجي_قيمة مضيف Codex와 ذاتي نواة_قيمة اتصال — 첫 구현으로 권장**
   Linux PC에서 공식 CLI 또는 app-server를 실행하고 jkoros에는 전용 فضاء_المستخدم أمر/화면을 만든다.
   호스트의 인증된 연결과 게스트 ملف قراءة·수정·업로드·أمر ينفذ_أمر 어댑터가 필요하다.
   기존 SSH/TCP 경로를 활용할 رقم 있으나, ملف 동기화나 Codex 전용 어댑터는 حديث_عنصر 구현되어 있지 않다.
   호스트에서 수행한 빌드와 게스트에서 수행한 ينفذ_أمر 결과를 명확히 구분한다.
   이 구성은 ذاتي 커널을 유지하지만, 공식 CLI 자체는 خارجي_قيمة 호스트에서 실행된다.

3. **ذاتي API 클라이언트 제작**
   ذاتي ABI의 C 또는 지원되는 Java 부분집합으로 تفاعلي_جلسة UI와 ملف/أمر أدوات 호출 루프를 만든다.
   خارجي_قيمة 중계기를 쓰지 않는다면 DNS/التحقق_من_صحة 가능한 TLS/HTTPS와 인증 بيانات 저장을 먼저 구현해야 한다.
   이는 OpenAI API를 이용하는 별도 에이전트이며 공식 Codex CLI 전체의 이식으로 표시하지 않는다.

4. **별도 ARM64 Linux 실행판에서 تثبيت_قيمة**
   `../rpi4`는 Linux와 musl 기반이므로 일반 Linux تثبيت_قيمة 경로를 검토할 رقم 있다.
   사용할 Codex 버전의 ARM64·musl 호환성, 의존성, 커널의 샌드박스 지원을 الفعلي_بيانات 검증해야 한다.
   이번 검토에서 تثبيت_قيمة 성공을 확인하지 않았다. 이 결과를 ذاتي Java 커널의 지원으로 표시하지 않는다.

## 단계별 완료 يعرض_جذر

- 직접 이식: `--version` تشغيل → 인증/HTTPS → ملف قراءة·수정 → طفل_قيمة أمر ينفذ_أمر →
  تفاعلي إدخال_قيمة/스트리밍 → إذن_قيمة 제한·يلغي_تشغيل → 재부팅 후 إعدادات/세션 보존을 각각 الفعلي_بيانات 게스트에서 확인한다.
- مضيف اتصال: 게스트에서 طلب إدخال_قيمة → مضيف Codex عملية_قيمة_إدخال → 게스트 ملف يغيّر_قيمة يتحقق →
  게스트 javac/cc ينفذ_أمر → نتيجة 표시를 처음부터 끝까지 검증한다.
- COSL 상업 조건을 유지하려면 새로 도입하는 런타임/통신 라이브러리의 라이선스와
  Codex توزيع_قيمة 버전의 제3자 고지를 검토한다. خارجي_قيمة 구성요소를 일괄 COSL로 재라이선스하지 않는다.

- [인증](https://learn.chatgpt.com/docs/auth): ChatGPT/API 인증, 헤드리스 장치의 `codex login --device-auth`, HTTPS 인증서 إعدادات.
- [샌드박스](https://learn.chatgpt.com/docs/sandboxing): 운영체제별 집행 أسلوب_الوضع, Linux의 bubblewrap 및 فضاء_المستخدم 네임스페이스 متطلب_قيمة 사항.
- [공개 구성요소](https://learn.chatgpt.com/docs/open-source): CLI/SDK/app-server의 공개 مصدر_شجرة 위치와 비공개 구성요소 محدِّد_قيمة.

공식 문서에는 jkoros를 دعم_قيمة 대상으로 명시한 내용이 없다. 위 구현 مسار·개발 순서는
حديث_عنصر 소스와 متطلب_قيمة 기능을 대조한 기술적 판단이다.
