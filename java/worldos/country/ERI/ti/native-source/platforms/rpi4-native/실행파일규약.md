# ELF 형식과 Linux ተግብር_ትእዛዝ ፋይል 호환성

**ELF는 확장자가 아니다.** Executable and Linkable Format이라는 바이너리
형식이며, Linux 외의 운영체제도 사용한다. 첫 네 ባይት_ዋጋ `7f 45 4c 46`,
ELF ክፍሊ_ዋጋ, CPU 종류, መተግበሪ_f5044b9b 헤더와 ምእታው_ነጥቢ_ዋጋ 주소를 읽어서 해석한다.
[ELF ABI 명세](https://gabi.xinuos.com/elf/02-eheader.html)

기존 jkoros 로더도 ትኽክለኛ_ሓበሬታ ELF64/AArch64 ተግብር_ትእዛዝ 파일을 읽었다. `.elf`는 예제의
이름일 뿐이었다. 다만 **ELF ቅረጽ_ዋጋ 지원과 Linux 시스템 호출 ABI 지원은 별개**다.
기존에는 `JKOROS` ABI note를 가진 자체 ተግብር_ትእዛዝ 파일만 허용했고, Linux 바이너리는
호환되지 않았다. ARM64 Linux는 SVC의 x8에 Linux 시스템 호출 번호를 넣는다.
같은 번호를 자체 ABI로 해석하면 다른 동작이 되므로 두 경로를 구분한다.
[Linux syscall ABI 설명](https://man7.org/linux/man-pages/man2/syscall.2.html)

## 이번 반영

| 입력 | ተግብር_ትእዛዝ 방법 | ሓገዝ_ዋጋ ቅንጣብ |
|---|---|---|
| 자체 ABI의 ARM64 ELF | `./인사`, `/작업/인사`, `run 인사` | 확장자 없이 ተግብር_ትእዛዝ; 내용이 ELF이면 `.txt`라는 이름도 동일 |
| Linux ARM64 ቀዋሚ_ዋጋ ELF | `run --linux 리눅스인사 한글인수` | 아래 시스템 호출·ኣድራሻ·መጠን 제한을 만족하는 መተግበሪ_f5044b9b |
| 텍스트를 `.elf`로 이름만 ለውጥ_ዋጋ | ተግብር_ትእዛዝ 거부 | 확장자로 ተግብር_ትእዛዝ 파일을 인정하지 않음 |
| x86/x86-64, ARM32 ተግብር_ትእዛዝ ፋይል | ተግብር_ትእዛዝ 거부 | AArch64 전용이며 CPU መምርሒ_ዋጋ 번역기 없음 |
| 일반 glibc/musl መተግበሪ_f5044b9b, PIE, 공유 ቤት_ንባብ | 아직 미지원 | 동적 로더·재배치·TLS·mmap·시그널 등 추가 이식 필요 |

자체 바이너리와 JAR의 ሽፋን 직접 실행은 ፋይል 헤더로 구분한다. `run`은 자체 ELF,
`run --linux`는 명시적으로 Linux ABI를 선택한다. Linux 바이너리를 자동으로
자체 ABI에 넣지 않으며, 자체 ABI note가 있는 파일은 Linux 모드에서 거부한다.
현재 RAM ፋይል 체계에는 ተግብር_ትእዛዝ ፍቓድ_ዋጋ 비트와 `chmod`, PATH 검색이 없다.

게스트 C ህነጽ_ምንጪ 예:

```text
cc 인사.c -o 인사
./인사
run 인사
```

`posix-kor`는 이 자체 ABI 경로로 연결한다. 일반 Linux에서 링크한 프로그램에
ትግርኛ ተግባር_ዋጋ 이름을 붙이는 것만으로 자체 ABI 호환이 되는 것은 아니다.

## 제한된 Linux ABI

이 기능은 **자체 Java ፍረ_ዋጋ 안의 호환 ንጻፍ_ዋጋ**이며 Linux 커널을 적재하지 않는다.

| Linux 호출 | መሐበሪ | 현재 제약 |
|---|---:|---|
| read / write / close / lseek | 63 / 64 / 57 / 62 | RAM 파일과 표준 입출력; 입력 대기는 EAGAIN 가능 |
| openat / unlinkat | 56 / 35 | AT_FDCWD 또는 절대 መገዲ; 파일만, 제한된 플래그 |
| ftruncate / fsync | 46 / 82 | RAM ፋይል; fsync가 영속 저장을 의미하지 않음 |
| exit / exit_group | 93 / 94 | 현재 መተግበሪ_f5044b9b ውጻእ_መተግበሪ |
| brk | 214 | 자체 ተጠቃሚ 힙 ቅንጣብ; ፍሽለት_ዋጋ 시 이전 break 반환 |
| clock_gettime | 113 | CLOCK_MONOTONIC만, 밀리초 ንጹርነት_ዋጋ |
| getpid / gettid | 172 / 178 | 한 ተጠቃሚ ተግብር_ትእዛዝ 흐름의 ፈላዪ_ዋጋ_5b7b8b77 |

미지원 번호는 `-ENOSYS`를 반환한다. Linux ABI의 socket, fork/clone/execve,
pthread, mmap, signal, ioctl, fstat, 동적 로더와 일반 libc 초기화는 구현하지
않았다. 기존 자체 POSIX/Java 소켓은 별도로 TCP/UDP를 지원한다.

초기 스택에는 argc, UTF-8 argv, 빈 envp, AT_PAGESZ/AT_ENTRY/AT_NULL을 넣는다.
입력은 ELF64 little-endian AArch64 **ET_EXEC**, ፋይል 전체 **16 KiB 이하**,
PT_LOAD 주소는 **0x02000000 이상 0x02c00000 미만**이어야 한다.
ፋይል 오프셋과 가상 주소의 페이지 መስመር_ኣትሕዝ_ዋጋ 관계를 검사하며, 서로 페이지를 공유하는
세그먼트와 ጸሓፍ·ተግብር_ትእዛዝ 동시 허용은 거부한다. PT_INTERP/PT_DYNAMIC/PT_TLS와
ET_DYN은 아직 받지 않는다.

일반 Linux 바이너리의 ንቡር_ዋጋ 적재 ኣድራሻ 0x00400000은 커널과 겹치므로 아직 받지
않는다. 예제는 GNU 링커의 `-Ttext-segment=0x02000000 -z max-page-size=4096`을
사용한다. 이 파일도 정상적인 Linux ELF이며 같은 파일이 Linux와 자체 커널에서
실행됨을 시험한다. ፋይል 이름이나 헤더만 바꿔 기존 Linux መተግበሪ_f5044b9b 전체를 지원할
수는 없다.

## ትኽክለኛ_ሓበሬታ 동일 바이너리 비교 시험

```sh
cd /home/user/jkoros/platforms/rpi4-native
make test-elf
```

시험은 `예제/리눅스ABI/ኣኺድ.S`와 `인사.c`를 Linux AArch64 대상으로 컴파일해,
**JKOROS note가 없는 확장자 없는 ተግብር_ትእዛዝ ፋይል** `build/verification/elf/리눅스인사`를
만든다. 같은 바이트를 다음 두 경로로 실행한다.

```sh
qemu-aarch64 build/verification/elf/리눅스인사 한글인수
python3 መሳርሒታት/ተግብር_ፋይል.py --linux build/verification/elf/리눅스인사 한글인수
```

첫 명령은 Linux 시스템 호출을 사용하는 기준 실행이고, 두 번째는 Linux를
적재하지 않은 raspi4b 자체 ፍረ_ዋጋ 실행이다. 한글 인수, ፋይል 입출력, ሰዓት, ውጻእ_መተግበሪ,
ፍረ_ዋጋ ኣድራሻ ፍቓድ_ምእታው 거부를 비교한다. FTP로 같은 파일을 올려 실행하는 시험도 있다.
ምዝጉብ_ሪጋ: `build/verification/elf/report.json`, `readelf.txt`, `serial.log` 및 FTP 보고서.

일반 Linux 프로그램까지 지원하려면 별도 ተጠቃሚ ኣድራሻ 공간, 더 큰 영속 VFS,
전체 ተግብር_ትእዛዝ ኣተስእ/auxv, 동적 링커와 재배치, mmap/TLS/시그널/스레드,
시스템 호출 및 libc 호환성을 확장해야 한다. 이번 구현은 첫 제한된 ተግብር_ትእዛዝ 경로다.
