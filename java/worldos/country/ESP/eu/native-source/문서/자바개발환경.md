# jkoros 안에서 Java eraiki_iturburu·exekutatu_komando

이 문서의 부팅·shell·Store_balio 명령은 **x86 bertsio_balio** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 bertsio_balio](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 fitxategi_izen_SMS, `edit`의 단독 `.` Store_balio, 16개 RAM Fitxategia, 약 2초 exekutatu_komando 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 benetako_datuak JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. Ostalari eraiki_iturburu 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java aplik_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 exekutatu_komando

호스트에서:

```sh
cd /home/user/jkoros

make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. exekutatu_komando 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox exekutatu_komando IRAKHAU_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 Fitxategia 전체를 새 내용으로 작성한다. 기존 내용의 Marra edizio_balio 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 byte_balio 수 erakutsi_balio.
- `cat FILE`: Fitxategia eduki_balio erakutsi_balio. 텍스트 소스에 사용한다.
- `rm FILE`: Memoria_datuak Fitxategia 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·MOTA_balio 검사 hutsegite_balio 시 기존 `.class`는 유지된다. 소스를 고친 ATZERA_balio 컴파일이 실패했다면 이전 exekutatu_komando 파일이 남아 있으므로 eraiki_iturburu 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 Store_balio 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 iturburu_zuhaitz·Gela_balio·datuak 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, Fitxategia 이름은 ASCII 1~63자다. iturburu_zuhaitz 이름은 `.class` 확장자 공간 때문에 최대 62자다. edizio_balio 입력은 ASCII이고 한 Marra 최대 128자다. Marra 또는 Fitxategia 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. nukleo_balio/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 erabiltzaile 예제 이름은 ASCII로 작성한다.

## 외부 Fitxategia 적재

호스트에서 만든 소스나 Laguntza_balio klip 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 benetako_datuak 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# Ostalari JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 Hurrengoa_elementu 빌드에서는 Erantsi_sarrera 파일을 포함하지 않는다. Fitxategia eduki_balio 변경과 sarrera_Zerrenda 제거도 Hurrengoa_elementu 빌드에 반영된다. 원본 Ostalari 파일에는 쓰지 않는다. balio_lehenetsi `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 balio_lehenetsi 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 Gela_balio Fitxategia 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 Laguntza_balio klip 안에 있어야 한다.

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 lokal_esparru deklarazio, 오버로드, 임의 MOTA_balio BIHURTU_balio, matrize_balio sortu ITURBURUA, 8/16진 리터럴, Unicode iturburu_zuhaitz 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 konstante_balio 축소 변환을 구현하지 않는다. 외부 `.class`의 `int[]` sortu/Irakurri/쓰기는 지원하므로 Ostalari `javac --release 8`로 만든 matrize_balio 예제는 실행할 수 있다.

objektu_balio eremu_balio·일반 objektu_balio sortu·상속·인터페이스·여러 Gela_balio Konektatu, long/float/double, salbuespen prozesu_balio_sarrera, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java salbuespen 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 kate_balio Store_balio 공간은 exekutatu_komando irten_aplik 시 erabiltzaile 영역 전체와 함께 회수한다. 지속 exekutatu_komando 중 GC는 없다.

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 Laguntza_balio 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM hiztegi 검증기를 구현한 것은 아니다. Fitxategia/atributu_balio luzera_balio, konstante_balio Erreferentzia_materiala, Komandoa·adar 경계를 검사하고, exekutatu_komando 중 스택 formatu_balio·lokal_esparru hasieratu·matrize_balio azpiindize_balio·objektu_balio 참조를 검사한다. erabiltzaile 코드의 페이지·포트 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, eraiki_iturburu·JVM 오류는 `Exit: 1`, Komandoa Argumentuak 오류는 `Exit: 2`다. CPU ordua_balio 상한은 기존 `Exit: 124`이며, erabiltzaile ELF 자체의 CPU/런타임 오류는 기존 irten_aplik 코드를 따른다. hutsegite_balio 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## Java Fitxategia S_I

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 Gela_balio 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 ATZERA_balio `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. balio_lehenetsi Irteera 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. salbuespen objektu_balio·try/catch·try-with-resources는 지원하지 않으며 Fitxategia 오류를 진단하고 프로그램을 종료한다. matrize_balio S_I, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 Fitxategia 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 shell `sync`가 필요하다. 예제의 Fitxategia 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 benetako_datuak 게스트 eraiki_iturburu 결과를 OpenJDK `-Xverify:all`로 다시 실행해 Fitxategia 바이트와 출력을 대조한다. 범위와 Store_balio 매체 사용법은 [posix-kor IRAKHAU_eb81d7d9](../posix-kor/IRAKHAU_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
