# 자체 ARM64 JVM 0.4와 Galego biblioteca

Galego 통신·excepción 사용법은 [Galego Java API](한국어자바/Léame_eb81d7d9.md), FUNCIÓN_VALOR·변수·Ficheiro 이름의 변경과 어원 근거는 [명명 Léame_eb81d7d9](명명/Léame_eb81d7d9.md)를 참고한다.

JAR executar_comando, externo_VALOR IPv4 TCP/UDP, 별도 estático_VALOR 부분집합 `jaot`와 게스트 C 컴파일은 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)에 설명한다. 아래 obxecto_VALOR·Thread·Swing은 JVM 경로의 기능이며 AOT soporte_VALOR 범위와 같지 않다.

이 구현은 **Linux 없이 부팅한 Java AOT 커널의 EL0에서 executar_comando**한다. JDK/JRE의 거의 모든 기능을 제공하는 단계는 아직 아니다. HotSpot·OpenJDK Clase_VALOR biblioteca 전체를 이식하거나 Java SE 인증/TCK를 통과한 구현도 아니다. 이번 확장은 단일 Clase_VALOR·estático_VALOR 메서드 중심이던 실행기를 obxecto_VALOR·biblioteca executar_comando 기반으로 넓힌 것이다.

## 실행과 compilar_fonte

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
# 자체 kernel_VALOR 안에서 fonte_árbore compilar_fonte → class executar_comando, Galego API 호출
python3 Ferramentas/executar_Ficheiro.py 시험/자바/한글소스.java

# obxecto_VALOR·excepción 등은 hospedar JDK로 Java 8 class를 만든 후 자체 커널에서 executar_comando
mkdir -p build/my-java
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/my-java 시험/자바/한글시험.java
python3 Ferramentas/executar_Ficheiro.py build/my-java/한글시험.class

# 의존 class 파일은 --include로 함께 Transferir_VALOR
javac --release 8 -encoding UTF-8 -d build/my-java 시험/자바/객체시험.java
python3 Ferramentas/executar_Ficheiro.py build/my-java/객체시험.class \
  --include build/my-java/Fondo_VALOR.class --include build/my-java/ramificación_VALOR.class \
  --include build/my-java/계산가능.class

make test-jvm
```

`--include DIR`는 그 디렉터리의 class 파일을 재귀적으로 읽어 `패키지.Clase_VALOR.class`라는 RAM Ficheiro 이름으로 전송한다. 주 클래스도 패키지가 있다면 `--class-name 패키지.Clase_VALOR`를 지정한다. 셸에서는 해당 이름으로 업로드하고 `java 패키지.Clase_VALOR`로 실행한다. JVM 0.4는 Main-Class가 있는 16 KiB 이하 JAR도 `java -jar Ficheiro.jar`로 실행한다. JAR 모드에서는 JAR 내부 클래스와 내장 Galego 클래스만 찾는다. 배포 Galego biblioteca JAR는 hospedar javac의 classpath로 사용하며, 같은 클래스가 usuario JVM ELF에도 Lectura 전용 자료로 포함된다. 일반 class 모드에서는 사용자가 같은 이름으로 올린 RAM class를 먼저 읽는다.

게스트 `javac`는 여전히 estático_VALOR 메서드, int/boolean/char/String, condición·sprint_VALOR, cadea_VALOR 결합, 일부 Ficheiro 스트림 등의 **자체 부분집합 컴파일러**다. obxecto_VALOR declaración·상속·try/catch·Thread 사용 소스를 게스트 javac가 모두 컴파일하는 것은 아니다. 위 기능은 `javac --release 8`로 만든 class를 자체 JVM에서 실행한다. Galego API 중 Saída·문자 스칼라 FUNCIÓN_VALOR·Ficheiro Lectura/쓰기는 게스트 컴파일러에도 연결했다. 다음처럼 전체 이름으로 호출한다.

```java
public class 인사 {
    public static void main(String[] Argumentos) throws Exception {
        Galego.자체.Saída.escribir_liña("안녕하세요😀");
        Galego.자체.Saída.수쓰기(Galego.자체.문자.código_de_carácter_CONTAR("한글😀"));
        Galego.자체.Ficheiro.Escritura("인사.txt", "한글 Ficheiro😀");
        Galego.자체.Saída.escribir_liña(Galego.자체.Ficheiro.Lectura("인사.txt"));
    }
}
```

## Galego API

독립 패키지 **`Galego.자체`**를 사용한다. Linux판 `Galego.자바`가 요구하는 NIO/Swing/HTTP API를 자체 커널에서 실행할 수 있다고 혼동하지 않도록 패키지를 나눴다. 이 라이브러리는 Clase_VALOR Nome·메서드·Argumentos·campo_VALOR·Ficheiro 이름에 한국어를 사용한다. 표준 Java Clase_VALOR 이름은 호환성을 위해 보존한다.

| Ficheiro | Lectura/Escritura(String Nome), 바이트읽기/escribir_byte_VALOR | 널리 쓰는 usuario 용어를 보존; RAM 자료의 Nome |

## executar_comando 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(Galego Clase_VALOR 포함), class당 16 KiB·constante_VALOR 풀 511항목, 전체 메서드/campo_VALOR 각각 512개. 메서드 CÓDIGO_VALOR 8 KiB, local_Ámbito 변수·피연산자 스택 각각 128슬롯, Argumentos 최대 16개(this 포함).
- VM 가닥은 main 포함 **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 executar_comando 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- obxecto_VALOR 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 real_datos 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 Ficheiro·대형 cadea_VALOR·객체가 이 제한을 넘을 수 있다.
- 실행은 50만 바이트코드 Orde 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 입력 대기는 기한을 갱신하고 Xanela mudar_MODO 시 중단·재개한다. 일반 servidor_VALOR·계산의 무제한 실행은 아직 없다. 미지원 Orde·Recurso_VALOR 부족은 명시적인 오류로 종료한다.
- RAM Ficheiro 최대 64개, 파일당 16384바이트, CAMIÑO UTF-8 63바이트. RAM 디렉터리와 punto_VALOR/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 Galego class는 RAM Ficheiro 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 ao_corrente_elemento 경로에서 fonte_árbore·Clase_VALOR·datos 파일을 읽는다.
- UDP는 Java 루프백 및 lwIP/SLIP를 통한 externo_VALOR IPv4를 제공한다. real_datos GENET/Wi-Fi/DNS/TLS/HTTP 전체는 없다. 전문 512바이트, 소켓 8개, 소켓당 큐 4개. receive는 VM 가닥을 양보하며 대기하고 setSoTimeout을 적용하지만 전체 executar_comando 기한은 여전히 적용된다.
- long/float/double, invokedynamic/람다, enum/annotation, 다차원 MATRIZ_VALOR, 완전한 MATRIZ_VALOR 공변성·인터페이스 capa_VALOR 검사, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/cifrar_datos/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. Swing의 별도 soporte_VALOR 부분집합은 아래 및 개발 매뉴얼을 참고한다. Clase_VALOR Ficheiro 전체 검증기·acceso_introdución permiso_VALOR/보호된 멤버 검사는 아직 완전하지 않다. 손상된 입력은 EL0 protexer_VALOR 경계 내에서 종료되도록 한다.

전체 OpenJDK를 목표로 하려면 다음은 별도의 주요 구현 단계다: 완전한 JVM VALOR/validar/Clase_VALOR 로더와 excepción 모델 → 영속 VFS·mmap·Reloxo·원자 cirurxía_VALOR·real_datos 스레드/sinc ABI → OpenJDK java.base 및 native biblioteca 이식 → dispositivo_VALOR 네트워크·TCP/IP → Xanela 시스템/tipo_de_letra_VALOR/입력기·java.desktop → Java SE 호환성 시험. ao_corrente_elemento 자체 JVM의 일부 메서드를 더하는 것으로 이 작업이 완료되지는 않는다.

## validar

`Ferramentas/자바가상기계시험.py`는 같은 Java 8 class 파일의 출력을 hospedar OpenJDK `-Xverify:all`과 QEMU raspi4b 자체 커널에서 비교한다. obxecto_VALOR/상속/인터페이스·switch·MATRIZ_VALOR, excepción/finally, 컬렉션/GC, Thread/bloquear_VALOR, Galego UTF-8/Ficheiro/컬렉션, real_datos UDP 루프백/hora_VALOR 초과, 게스트 한글 fonte_árbore compilar_fonte, MATRIZ_VALOR TIPO_VALOR/copiar_VALOR/Ficheiro 경계·한글 패키지의 9개 비교 시험과 잘못된 class 버전/잘린 Ficheiro rexeitar_VALOR_e3ecc00b 시험을 실행한다. UDP Project_raíz 실행에는 hospedar 루프백 소켓 권한이 필요하다.

`Ferramentas/부팅시험.py`는 kernel_VALOR protexer_VALOR/회귀 시험과 별도로 Galego Java 화면 API가 real_datos 픽셀을 그렸는지도 QMP 화면 캡처로 검사한다. 보고서는 `build/verification/jvm/report.json`, `build/verification/report.json`이며 시험한 kernel8.img의 SHA-256을 기록한다. real_datos Pi4 하드웨어 부팅 시험과 전체 JDK 호환성 시험 결과는 아니다.


## JVM 0.3: 네트워크와 GUI extensión_VALOR

`Socket`/`ServerSocket` xerar·Conectar·accept·양방향 InputStream/OutputStream·close·EOF·hora_VALOR 제한과 UTF-8 `String.getBytes`를 추가했다. JVM 0.4에서는 externo_VALOR díxito_VALOR IPv4 TCP도 lwIP/SLIP에 연결했다. 연결형 finalizar_p 16개, Java 루프백 버퍼 1024바이트, externo_VALOR TCP 버퍼 4096바이트다. DNS·TLS는 없다.

`JFrame`, `JPanel`, `JLabel`, `JButton`, `JTextField`, `ActionListener`, `ActionEvent`, `SwingUtilities.invokeLater`의 문서화한 부분집합을 네이티브 GUI에 연결했다. `setLayout(null)`과 명시적 좌표를 사용한다. 전체 OpenJDK Swing 또는 Java SE 호환 구현은 아니다. interactivo 이벤트 대기는 executar_comando 기한을 갱신하고 Terminal mudar_MODO 시 프로세스 상태를 Store_VALOR·복원한다. 이벤트 콜백 자체는 기존 바이트코드/CPU 기한을 따른다.

Galego `Xanela`, `widget`, `연결통신` 클래스를 배포 JAR와 자체 JVM 내장 자원에 추가했다. 상세 메서드·제한·fonte_árbore·업로드 방법: [한글 개발 매뉴얼](개발안내.md).

## Galego 객체의 직접 executar_comando

`Xanela`, `Etiqueta`, `SMS_campo`, `botón`, `evento_cola`, `동작알림`, `작업가닥`은
표준 GUI/Thread 객체를 보관하는 래퍼가 아니다. 자체 JVM의 obxecto_VALOR xerar,
formato_VALOR 검사, 화면 호출, Evento 큐, tema_VALOR 스케줄러에 Galego 계약을 직접 구현했다.
표준 `javax.swing`·`Thread` 코드의 executar_comando 경로도 유지한다.
Galego 단추와 표준 JButton은 서로 다른 형식이며, 해당 instanceof 검사도 검증한다.

자체 실행기의 Galego 진입점은 `public static void Executar_2()`이다.
표준 `main(String[])`도 지원하며 둘 다 있으면 Galego 진입점을 우선한다.
명령행 인수는 `실행인수.elemento_CONTAR()`와 `실행인수.Texto(순번)`으로 읽는다.
`example/java`의 다섯 예제는 이 규약을 사용한다. estático_VALOR Ficheiro 예제는 게스트
javac로도 컴파일하며, GUI/tema_VALOR 소스는 hospedar `javac --release 8`을 사용한다.
직접 GUI/tema_VALOR API는 자체 JVM 전용이다. 기존 OpenJDK 비교 시험과 별도로
