# 셸에서 실행하는 사용자 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 안내](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 실행

호스트 터미널 1:

```sh
cd /home/user/jkoros
python3 os/도구/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 외부 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

호스트 터미널 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 실제 CPU 권한 `ring 3`, 인수 Sortida.
- `netcheck`: 창구 중복, 잘못된 손잡이/포인터/길이, 비차단 받기와 시간 초과 확인.
- `udp`: IPv4 주소·목적 창구·한 단어 메시지를 받아 UDP로 보내고 같은 응답을 확인. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: 호스트 `10.0.2.2`의 지정 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 고리 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 현재 주소는 게스트 `10.0.2.15/24`, 관문 `10.0.2.2`로 고정돼 있다. QEMU 사용자 네트워크의 호스트 접근 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 프로그램 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java 프로그램 추가

`예제/내프로그램.java`를 다음 형식으로 만든다. 진입점은 인수 없는 `static int` 또는 `static void` 함수다. 인수는 사용자 API로 조회한다.

```java
public final class 내프로그램 {
    public static int Executar_2() {
        사용자.Escritura("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/사용자/프로그램.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := 사용자/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.Executar_2
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `사용자/선언/사용자.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 실행 중인 VM에는 빌드 결과가 자동 반영되지 않는다. 프로그램 이름은 현재 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java 클래스·함수·변수에는 한국어를 쓴다. 최대 32개 프로그램, 한 실행 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.Executar_2 \
    -o os/build/apps/hello.elf os/사용자/선언/사용자.java os/사용자/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 호스트 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 지원 범위 안에서 실행한다. `.jar`와 일반 Linux 실행 파일은 지원하지 않는다.

## 사용자 네트워크 API

선언은 `선언/사용자.java`에 있다. `자료보내기`/`자료받기`의 `int[]` 원소 한 개는 바이트 하나(0~255)를 나타낸다. 한 데이터그램의 최대 자료 길이는 1,024바이트다.

```java
int 손잡이 = 사용자.통신열기(0); // 0: 임시 지역 UDP 창구 자동 선택
int[] 자료 = new int[32];
자료[0] = 'H'; 자료[1] = 'i';
int 보낸길이 = 사용자.자료보내기(손잡이, 0x0a000202, 9000, 자료, 2);
int 받은길이 = 사용자.자료받기(손잡이, 자료, 1500);
사용자.통신닫기(손잡이);
```

실제 프로그램에서는 Dobrir·보내기·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 대기 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 추가 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | 손잡이·처리 길이·성공 등 해당 함수의 결과 |
| -5 | 장치 송신 실패 |
| -9 | 잘못되었거나 닫힌 통신 손잡이 |
| -11 | 비차단 받기에서 도착한 자료 없음 |
| -14 | 사용자 포인터/배열 범위 오류 |
| -19 | 지원 NIC 없음 |
| -22 | 창구/대기 시간/인수 값 오류 |
| -24 | 열린 통신창구 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | 자료 또는 수신 배열 Talha 문제 |
| -98 | 지역 창구 번호 중복 |
| -101 | 지원하지 않는 목적 주소 |
| -110 | ARP·장치·수신 시간 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 부호 있는 Java `int`의 비트 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## 실행 경계와 시스템 호출

```text
셸 run → JKAP에서 ELF 검증·적재 → ring 3 사용자 프로그램
                                 ↓ int 0x80
                      포인터 검사 → Java 커널 API → RTL8139/UDP
                                 ↓ 종료·예외·시간 초과
                                셸 복귀
```

시스템 호출 레지스터는 `EAX=번호`, `EBX,ECX,EDX,ESI,EDI=인수`, `EAX=결과`다. Java 호출 스택 ABI는 컴파일러가 사용자 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| 번호 | 호출 |
| --- | --- |
| 0 | 종료(상태 코드) — Executar_2/오류 런타임에서 사용 |
| 1 | 문자열 Escritura |
| 2 / 3 | 인수 개수 / 인수 문자열 주소 |
| 10 | UDP Dobrir |
| 11 | UDP 보내기(손잡이, IP, 목적 창구, 배열 주소, 길이) |
| 12 | UDP 받기(손잡이, 배열 주소, 제한 밀리초) |
| 13 | UDP Tampar |
| 14 | 지역 IP 주소 |
| 15 / 16 | 마지막 상대 IP / UDP 창구 |
| 20 | RAM Fichièr Lectura(Nom int[] 주소, Sortida int[] 주소) |
| 21 | RAM Fichièr Escritura(Nom int[] 주소, 입력 int[] 주소, 바이트 길이) |
| 22 | UTF-16 코드 단위 문자 Sortida(0~65535) |

Fichièr API는 `사용자.파일읽기(int[] Nom, int[] 자료)`와 `사용자.파일쓰기(int[] Nom, int[] 자료, int 길이)`다. 이름은 ASCII 코드 배열(최대 64칸, 0 종료 또는 배열 끝), 자료 원소 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 Fichièr 없음 `-2`, 포인터 오류 `-14`, Nom/길이 오류 `-22`, Fichièr 슬롯 부족 `-28`, Talha 초과 `-90`을 반환한다. 쓰기는 검증 후 Fichièr 전체를 대체한다. `사용자.문자쓰기(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 사용자 모드에서 CS의 하위 비트를 직접 읽으므로 실제 실행 권한을 확인한다. 커널 포트 접근용 `장치` native 함수는 사용자 대상 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 실행, 파이프, 프로세스 간 통신은 없다. 실행 파일은 커널의 Lectura 전용 JKAP 묶음에서 적재한다. 자료 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- 사용자 가상 주소 `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. 실행 영상은 앞 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. 커널 identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB 사용자 영역을 비우고 Fichièr 구역을 복사해 BSS·배열 영역을 초기화한다. 사용자 GC는 없지만 종료 후 다음 실행 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 따옴표/이스케이프 파싱은 없다.
- 사용자 페이지의 코드/자료 분리 Lectura 전용 Paramètres, NX, 스택 guard, ASLR은 아직 없다. 커널과 사용자 메모리·포트 권한 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 실행 상한을 두며 시간 초과는 `Exit: 124`다. 사용자 CPU 예외는 `128 + 예외 번호`(페이지 오류 142, 특권 위반 141), Java 배열/계산 오류는 101~105다. 커널 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, 정적 IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP 검사합 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- 사용자 실행·네트워크·보호 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 실행·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## 검증 근거

`make test`는 컴파일러 14개 시험, Java 패킷 조건 2,201개 검사, 기존 셸 ELF/ISO 부팅 시험, 사용자 ELF/실제 UDP/보호 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 길이·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 Comanda·무한 반복 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
