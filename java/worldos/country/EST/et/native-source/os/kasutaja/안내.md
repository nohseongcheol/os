# 셸에서 실행하는 kasutaja 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 안내](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 Täida_käsk

host terminal 1:

```sh
cd /home/user/jkoros
python3 os/Tööriistad/kaja_andmed.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. väline_VALUE 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

host terminal 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 tegelik_andmed CPU luba_VALUE `ring 3`, Argumendid Väljund.
- `netcheck`: port_VALUE 중복, 잘못된 pide_VALUE/kursor/길이, 비차단 받기와 Aeg_VALUE 초과 kinnitama.
- `udp`: IPv4 ADDRESS·sihtkoht_VALUE port_VALUE·한 Word_VALUE 메시지를 받아 UDP로 보내고 같은 응답을 kinnitama. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: host `10.0.2.2`의 Määra_VALUE 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. saama_VALUE Loop_VALUE 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. tähtaja_piires_kaup 주소는 게스트 `10.0.2.15/24`, lüüs_VALUE `10.0.2.2`로 고정돼 있다. QEMU kasutaja 네트워크의 host pöördus_kirje 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 programm_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java programm_f5044b9b Lisa_kirje

`예제/내프로그램.java`를 Edasi_kaup 형식으로 만든다. 진입점은 Argumendid 없는 `static int` 또는 `static void` 함수다. 인수는 kasutaja API로 조회한다.

```java
public final class 내프로그램 {
    public static int Käivita_2() {
        kasutaja.Kirjutamine("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/kasutaja/programm_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := kasutaja/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.Käivita_2
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `kasutaja/deklaratsioon/kasutaja.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 Täida_käsk 중인 VM에는 järk_süsteem 결과가 자동 반영되지 않는다. programm_f5044b9b 이름은 tähtaja_piires_kaup 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java tund_VALUE·FUNCTION_VALUE·변수에는 한국어를 쓴다. 최대 32개 programm_f5044b9b, 한 Täida_käsk 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/kompilaator.py --target user --entry 인사.Käivita_2 \
    -o os/build/apps/hello.elf os/kasutaja/deklaratsioon/kasutaja.java os/kasutaja/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 host 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 tugi_VALUE klipp 안에서 실행한다. `.jar`와 일반 Linux Täida_käsk 파일은 지원하지 않는다.

## kasutaja 네트워크 API

선언은 `deklaratsioon/kasutaja.java`에 있다. `saatma_andmed`/`saama_andmed`의 `int[]` kaup_element 한 개는 bait_VALUE 하나(0~255)를 나타낸다. 한 데이터그램의 최대 andmed 길이는 1,024바이트다.

```java
int pide_VALUE = kasutaja.avama_võrk(0); // 0: 임시 kohalik_skoop UDP port_VALUE 자동 valim_VALUE
int[] andmed = new int[32];
andmed[0] = 'H'; andmed[1] = 'i';
int 보낸길이 = kasutaja.saatma_andmed(pide_VALUE, 0x0a000202, 9000, andmed, 2);
int 받은길이 = kasutaja.saama_andmed(pide_VALUE, andmed, 1500);
kasutaja.Sule_võrk(pide_VALUE);
```

tegelik_andmed 프로그램에서는 Ava·saatma·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `saama_andmed`의 Oota_VALUE 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 saama_VALUE 대기열은 한 개뿐이므로 Lisa_kirje 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | pide_VALUE·Joonis_VALUE_kirje 길이·성공 등 해당 함수의 TULEMUS |
| -5 | seade_VALUE saatma_VALUE tõrge_VALUE |
| -9 | 잘못되었거나 닫힌 통신 pide_VALUE |
| -11 | 비차단 받기에서 도착한 andmed 없음 |
| -14 | kasutaja kursor/ARRAY_VALUE klipp VIGA |
| -19 | tugi_VALUE NIC 없음 |
| -22 | port_VALUE/Oota_VALUE Aeg_VALUE/Argumendid VALUE VIGA |
| -24 | 열린 võrk_port 4개 한도 |
| -38 | 알 number 없는 시스템 호출 |
| -90 | andmed 또는 saama_VALUE ARRAY_VALUE Suurus 문제 |
| -98 | kohalik_skoop port_VALUE INDEX 중복 |
| -101 | 지원하지 않는 sihtkoht_VALUE ADDRESS |
| -110 | ARP·seade_VALUE·saama_VALUE Aeg_VALUE 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 kodeerimine_VALUE 있는 Java `int`의 bitt_VALUE 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 number 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## Täida_käsk 경계와 시스템 호출

```text
kest run → JKAP에서 ELF valideerima·적재 → ring 3 kasutaja programm_f5044b9b
                                 ↓ int 0x80
                      kursor 검사 → Java tuum_VALUE API → RTL8139/UDP
                                 ↓ Välju_programm·erand·Aeg_VALUE 초과
                                kest 복귀
```

시스템 호출 레지스터는 `EAX=INDEX`, `EBX,ECX,EDX,ESI,EDI=Argumendid`, `EAX=TULEMUS`다. Java 호출 operand_Virn ABI는 컴파일러가 kasutaja 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| INDEX | 호출 |
| --- | --- |
| 0 | Välju_programm(Olek_VALUE CODE_VALUE) — Käivita_2/VIGA 런타임에서 kasutus_VALUE |
| 1 | string_VALUE Kirjutamine |
| 2 / 3 | Argumendid kaup_COUNT / Argumendid string_VALUE ADDRESS |
| 10 | UDP Ava |
| 11 | UDP saatma(pide_VALUE, IP, sihtkoht_VALUE port_VALUE, ARRAY_VALUE ADDRESS, 길이) |
| 12 | UDP saama(pide_VALUE, ARRAY_VALUE ADDRESS, 제한 밀리초) |
| 13 | UDP Suletud |
| 14 | kohalik_skoop IP ADDRESS |
| 15 / 16 | 마지막 partner_VALUE IP / UDP port_VALUE |
| 20 | RAM Fail Lugemine(Nimi_2 int[] ADDRESS, Väljund int[] ADDRESS) |
| 21 | RAM Fail Kirjutamine(Nimi_2 int[] ADDRESS, 입력 int[] ADDRESS, bait_VALUE 길이) |
| 22 | UTF-16 CODE_VALUE ühik_VALUE 문자 Väljund(0~65535) |

Fail API는 `kasutaja.파일읽기(int[] Nimi_2, int[] andmed)`와 `kasutaja.kirjutamine_Fail(int[] Nimi_2, int[] andmed, int 길이)`다. 이름은 ASCII CODE_VALUE ARRAY_VALUE(최대 64칸, 0 Välju_programm 또는 ARRAY_VALUE 끝), andmed kaup_element 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 Fail 없음 `-2`, kursor VIGA `-14`, Nimi_2/길이 VIGA `-22`, Fail 슬롯 부족 `-28`, Suurus 초과 `-90`을 반환한다. 쓰기는 valideerima 후 Fail 전체를 대체한다. `kasutaja.kirjutamine_märk_VALUE(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 kasutaja 모드에서 CS의 하위 비트를 직접 읽으므로 tegelik_andmed Täida_käsk 권한을 확인한다. tuum_VALUE 포트 접근용 `seade_VALUE` native 함수는 kasutaja siht 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 Täida_käsk, 파이프, 프로세스 간 통신은 없다. Täida_käsk 파일은 커널의 Lugemine 전용 JKAP 묶음에서 적재한다. andmed 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- kasutaja 가상 ADDRESS `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. Täida_käsk 영상은 esikaamera_VALUE 2MiB, 인수는 `0x04300000`부터, 스택은 regioon_VALUE 끝에서 시작한다. tuum_VALUE identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB kasutaja 영역을 비우고 Fail 구역을 복사해 BSS·ARRAY_VALUE 영역을 초기화한다. kasutaja GC는 없지만 Välju_programm 후 Edasi_kaup Täida_käsk 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 Tsitaat/이스케이프 파싱은 없다.
- kasutaja 페이지의 CODE_VALUE/andmed 분리 Lugemine 전용 Seaded, NX, operand_Virn guard, ASLR은 아직 없다. 커널과 kasutaja Mälu_andmed·포트 luba_VALUE 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 Täida_käsk 상한을 두며 Aeg_VALUE 초과는 `Exit: 124`다. kasutaja CPU 예외는 `128 + erand INDEX`(페이지 VIGA 142, 특권 위반 141), Java ARRAY_VALUE/계산 오류는 101~105다. tuum_VALUE 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, 정적 IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP kontrollsumma 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- kasutaja Täida_käsk·네트워크·kaitsma_VALUE 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 Täida_käsk·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.
