# Java 네이티브 операционная_система

이 문서는 기존 **x86 ядро_ЗНАЧЕН**을 설명한다. Raspberry Pi 4의 свой ARM64 начальное_состояние 이식은 [별도 файл_сведений_eb81d7d9](../platforms/rpi4-native/README.md)를 참고한다. 아래 x86 пространство_пользователя ELF·네트워크·IDE Store_ЗНАЧЕН 기능이 ARM64에 모두 이식된 상태는 아니다.

Java 원문을 свой AOT 후단으로 x86 기계어로 컴파일해 부팅하는 작은 운영체제다. 커널과 별도로 свой 제한형 Java компилятор·JVM ELF를 пространство_пользователя 모드에 적재할 수 있다. Linux, engos, koros4와 внешний_ЗНАЧЕН OpenJDK는 게스트에 적재하지 않는다. запуск_машины 진입과 аппаратный_порт/물리 Память_регион 접근은 어셈블리이며, 문자 단말·входные_данные_ЗНАЧЕН Процесс_ЗНАЧЕН_ввод·команда анализировать_ЗНАЧЕН·작업 раздел_ЗНАЧЕН_366e0bfa 관리는 `исходныйКод/*.java`에 있다.

## 게스트 Java 개발

`javac Hello.java`, `java Hello`로 부팅된 операционная_система 안에서 компилировать_источник·실행한다. `edit FILE.java`와 `.save`로 소스를 작성하며 `ls`, `cat`, `rm`을 제공한다. RAM 파일은 최대 8개, 각각 16KiB이다. 전용 IDE 매체를 연결하면 `sync`로 보존할 수 있다. 이 기능은 свой 제한형 구현이며 전체 OpenJDK/JDK 호환은 아니다. 사용법·опора_ЗНАЧЕН 문법·файл 적재·교차 시험은 [Java 개발 среда](../문서/Java_IDE.md)에 있다. `make test-java`로 검증한다.

## 빌드와 실행

`compiler/`가 요구하는 도구에 더해 ISO 생성에는 `grub-file`, `grub-mkrescue`, GRUB BIOS модуль_ЗНАЧЕН, `xorriso`가 필요하다. 실행에는 QEMU 또는 VirtualBox가 필요하다. текущий_товар 설치된 도구만 사용한다. `make run-store`는 새 전용 가상 Store_ЗНАЧЕН 매체를 만들어 연결한다. VirtualBox 실행기는 이 프로젝트가 만든 전용 VM만 설정하고 다른 VM은 변경하지 않는다. 가상 메모리는 значение_по_умолчанию 64MiB이며 최소 16MiB가 필요하다.

```sh
cd /home/user/jkoros/os
make                 # build/kernel.elf
make iso             # build/kernel.iso (пространство_пользователя ELF Группа_ЗНАЧЕН объявления)
make run             # ELF 직접 запуск_машины, 직렬 단말
make run-gui         # GRUB ISO запуск_машины, VGA 창과 PS/2 자판
make vbox            # 상위 폴더의 실행기로 전용 VirtualBox VM 실행
make vbox-status     # 전용 VirtualBox VM Состояние_ЗНАЧЕН проверять
make test            # ELF와 ISO 두 경로의 фактический_данные запуск_машины/входные_данные_ЗНАЧЕН испытания
make apps            # пространство_пользователя 프로그램만 сборка
make test-network    # пространство_пользователя 실행/UDP/защитить_ЗНАЧЕН испытания
```

`make run`은 QEMU의 직렬 표준 입출력을 쓴다. `Ctrl+A`를 누른 BACK_ЗНАЧЕН `X`로 QEMU를 종료할 수 있다. `halt`는 게스트 CPU만 정지시키므로 QEMU Окно/프로세스는 별도로 닫는다. 폴링 방식이라 минутку_ЗНАЧЕН 중에도 узел CPU를 사용할 수 있다.

VirtualBox는 `make vbox`로 실행한다. 새 전용 VM을 Память_данные 64MiB, BIOS, 광학 드라이브 부팅으로 자동 설정하며 디스크는 필요 없다. фактический_данные VirtualBox 5.2.42에서 запуск_машины, Java свой испытания, оболочка входные_данные_ЗНАЧЕН, `run hello vbox`의 ring 3 실행과 ИТ_службы_обычный 종료를 확인했다. текущий_товар коммуникация 드라이버는 QEMU의 RTL8139 전용이며 VirtualBox의 PCnet/E1000에서는 네트워크를 사용할 수 없어 네트워크 장치를 비활성화한다. Store_ЗНАЧЕН Состояние_ЗНАЧЕН 재개와 새 сборка 반영 방법은 [VirtualBox 실행 файл_сведений_eb81d7d9](../문서/가상상자실행.md)에 있다.

## 셸에서 пространство_пользователя программа_f5044b9b 실행 및 네트워크 호출

## 명시적인 한계

이 커널은 **пространство_пользователя 프로그램을 한 번에 하나 실행하는 начальное_состояние ядро_ЗНАЧЕН**이다. PIT IRQ0만 사용하며 키보드와 NIC는 폴링한다. пространство_пользователя CPU 예외는 해당 프로그램을 끝내고 셸로 복귀시키지만 ядро_ЗНАЧЕН 예외는 중단한다. 실행 시간은 약 3초로 제한한다. 완전한 선점 다중 Процесс_ЗНАЧЕН 스케줄러, FAT/ext 등 일반 디스크 файловая_система, TCP·DNS·DHCP·IPv6·HTTP, 전체 POSIX, 일반 объект_ЗНАЧЕН 모델/GC는 아직 없다. 전용 IDE файл 보존과 POSIX файл/UDP 일부 기능은 구현했다. JVM은 RAM 파일의 단일 클래스를 실행 시 적재하며 일반 ClassLoader나 JAR 로딩은 지원하지 않는다. 네이티브 실행 파일은 сборка 시 Чтение 전용 묶음에 넣으며, 일반 Linux ELF를 실행하는 환경이 아니다. 기존 `../устаревший_источник/`의 JVM 관리 ядро_ЗНАЧЕН 전체를 이식한 것도 아니다.

Java 식별자는 한국어다. 직렬 출력은 이 프로젝트의 한글(BMP 문자)을 UTF-8로 표시한다. VGA는 значение_по_умолчанию ASCII 글꼴만 사용하므로 한글 자리에 `?`가 나온다. команда 입력도 текущий_товар ASCII만 지원하며 한글 шрифт_ЗНАЧЕН·입력기 및 보조 평면 문자 출력은 후속 작업이다. `test`는 작은 배열을 새로 할당하고 GC가 없으므로 무한 반복하지 않는다.

## 자동 испытания

`испытания/부팅시험.py`는 디스크 없는 독립 QEMU를 생성해 다음을 검증하고 종료한다.

- ELF 직접 запуск_машины 및 GRUB ISO запуск_машины.
- Java свой 시험과 UTF-8 직렬 문구.
- команда показать_справку·msinfo32_exe·Память_данные·текстовыйВывод·ошибка входные_данные_ЗНАЧЕН·экран удалить_ввод_c8dbc399.
- 작업 раздел_ЗНАЧЕН_366e0bfa 8개 выделить_Память, 부족 Процесс_ЗНАЧЕН_ввод, Возврат_KR/중복 Возврат_KR/재할당.
- 직렬 줄바꿈·백스페이스·긴 входные_данные_ЗНАЧЕН Процесс_ЗНАЧЕН_ввод.
- QEMU PS/2 Ключ_ЗНАЧЕН 입력으로 `info` 실행, `halt` 정지.

성공 로그는 `build/부팅시험.json`에 남는다. 로컬 Unix 소켓을 금지하는 샌드박스에서는 испытания 도구에 해당 권한이 필요하다. испытания 도중 새로 만든 QEMU만 종료하며 기존 VM과 фактический_данные 디스크는 건드리지 않는다.

`испытания/тест_пользователь_сеть.py`는 ELF/ISO 각각에서 пространство_пользователя ELF, фактический_данные ring 3, аргументы, узел 루프백 UDP 왕복, 1,023/1,024바이트 24회 연속 왕복, значение_времени 초과, NIC 없음, Память_данные/аппаратный_порт доступ_ввод 차단, CPU исключение, 무한 спринт_ЗНАЧЕН, 잘못된 ELF를 시험한다. `build/тест_пользователь_сеть.json`에 게스트 기록과 호스트가 받은 데이터의 длина_ЗНАЧЕН·해시를 저장한다. `испытания/пакет_тест.py`는 фактический_данные Java сумма_контракта 처리기에 손상된 패킷을 넣어 2,201개 граница_ЗНАЧЕН/контрольная_сумма 조건을 검사한다. узел 루프백 외 внешний_ЗНАЧЕН 서버에는 испытания 트래픽을 보내지 않는다.

부트 경계는 GNU의 [Multiboot спецификация](https://www.gnu.org/software/grub/manual/multiboot/multiboot.html)를 따른다.

새 файл_дескриптор·C ABI·IDE Store_ЗНАЧЕН·Java файл 흐름의 범위와 русский 명명 대응은 [posix-kor файл_сведений_eb81d7d9](../posix-kor/файл_сведений_eb81d7d9.md)에 있다. `make test-posix`로 ELF/ISO 실행과 재부팅 보존을 검증한다.
