# jkoros 안에서 Java kompileerima_lähe·Täida_käsk

이 문서의 부팅·kest·salv_VALUE 명령은 **x86 versioon_VALUE** 기준이다. 공유 Java kompilaator/JVM은 [oma ARM64 Pi4 versioon_VALUE](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 failinimi_SMS, `edit`의 단독 `.` salv_VALUE, 16개 RAM Fail, 약 2초 Täida_käsk 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 tegelik_andmed JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. host kompileerima_lähe 서버나 Linux 게스트는 사용하지 않는다.

**tähtaja_piires_kaup 구현은 oma 제한형 kompilaator·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java programm_f5044b9b 실행은 아직 지원하지 않는다.

## 직접 작성

`edit`는 Fail 전체를 새 내용으로 작성한다. 기존 내용의 Joon muudatus_VALUE 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text

...>  public static int square(int n) { return n * n; }

...>  }
...> }
```

- `ls`: 파일과 bait_VALUE number saade_VALUE.
- `cat FILE`: Fail Sisu_VALUE saade_VALUE. 텍스트 소스에 사용한다.
- `rm FILE`: Mälu_andmed Fail 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 number 있다.
- 구문·TYPE_VALUE 검사 tõrge_VALUE 시 기존 `.class`는 유지된다. 소스를 고친 Tagasi_VALUE 컴파일이 실패했다면 이전 Täida_käsk 파일이 남아 있으므로 kompileerima_lähe 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 salv_VALUE 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 lähe_puu·tund_VALUE·andmed 파일을 보존할 number 있다. 최대 8개, 파일마다 16KiB, Fail 이름은 ASCII 1~63자다. lähe_puu 이름은 `.class` 확장자 ADDRESS_regioon 때문에 최대 62자다. muudatus_VALUE 입력은 ASCII이고 한 Joon 최대 128자다. Joon 또는 Fail 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. tuum_VALUE/kompilaator/JVM 구현의 Java 식별자는 한국어이며, tähtaja_piires_kaup 게스트 입력 제한 때문에 kasutaja 예제 이름은 ASCII로 작성한다.

## väline_VALUE Fail 적재

호스트에서 만든 소스나 tugi_VALUE klipp 안의 `.class`를 부팅 이미지에 포함할 number 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 tegelik_andmed 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# host JDK로 컴파일한 클래스도 사용할 number 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 Edasi_kaup 빌드에서는 Lisa_kirje 파일을 포함하지 않는다. Fail Sisu_VALUE 변경과 kirje_Loend 제거도 Edasi_kaup 빌드에 반영된다. 원본 host 파일에는 쓰지 않는다. vaikeväärtus `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 vaikeväärtus 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 tund_VALUE Fail 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 tugi_VALUE klipp 안에 있어야 한다.

## Java Fail I_O

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 tund_VALUE 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 Tagasi_VALUE `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. vaikeväärtus Väljund 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.
