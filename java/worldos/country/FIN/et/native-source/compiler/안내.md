# Java 네이티브 kompilaator

OpenJDK oma 소스를 빌드하는 **`--target openjdk-build`**와 oma tuum_VALUE ABI 검사 도구를 추가했다.
이는 공식 javac/C/C++ 도구를 연결하는 별도 경로다. [järk_süsteem 방법·tegelik_andmed valideerima·tuum_VALUE 이식 klipp](OpenJDK-lähe_järk_AND-자체커널-이식.md)를 참고한다.

x86 직접 변환과 ARM64 C genereerima 후단은 모두 [기계어미리번역.java](자바도구/기계어미리번역.java)로 구현한다. `sh 미리번역.sh`로 직접 실행하며, [기계어미리번역.py](기계어미리번역.py)와 `kompilaator.py`는 이전 Käsk·API 및 OpenJDK 도구를 위한 호환 진입점이다. oma Pi4 후단은 freestanding C를 거쳐 AArch64로 만든다. [arm64.py](arm64.py)는 이전 경로와 Python 호출을 위한 호환 진입점이다. FUNCTION_VALUE·변수·genereerima C 이름의 뜻과 예외는 [Eesti 명명 안내](../platforms/rpi4-native/명명/안내.md)를 참고한다. [ARM64 järk_süsteem·tugi_VALUE klipp](../platforms/rpi4-native/안내.md)에 Täida_käsk 조건이 있다. 전체 OpenJDK나 일반 tund_VALUE 실행기는 아니다.

Täida_käsk 시 JVM이 필요 없는 x86 32비트 ELF를 만든다. JDK 11 이상으로 실행하는 Java oma AOT 후단이며, Java 전체를 새로 구현한 컴파일러는 아니다. Java 문법·pöördus_kirje meede_VALUE·TYPE_VALUE 검사는 JDK의 `javac`에 맡기고, Java 8 tund_VALUE 파일을 읽어 각 바이트코드를 x86 명령으로 직접 변환한다. C 코드로 우회하거나 바이트코드 해석기를 커널에 넣지 않는다.

```text
Java ALLIKAS → javac의 문법·TYPE_VALUE 검사 → 임시 .class
          → oma x86 변환기 → GNU as/ld → 네이티브 ELF32
```

## 준비와 Täida_käsk

järk_süsteem host: Linux, Python 3.6 이상, JDK 11 이상(`javac --release 8`), GNU binutils(`as`, `ld`), Make. tähtaja_piires_kaup 환경의 OpenJDK 11, Python 3.6, binutils 2.30으로 검증했다. väline_VALUE Python 패키지와 네트워크 다운로드는 사용하지 않는다.

```sh
cd /home/user/jkoros/compiler
make
./build/계산
echo $?                  # 0이면 예제 시험 성공

python3 kompilaator.py --target linux --entry 계산.Käivita_2 \
    -o build/계산 예제/계산.java

make test
```

`linux` 대상은 Linux의 32비트 Täida_käsk 호환 기능이 필요하다. `int 0x80`을 차단하는 샌드박스에서는 `Bad system call`이 발생할 number 있다. 정상 Linux host 또는 해당 실행을 허용한 시험 환경에서 실행한다. 시험의 비정상 종료를 통과로 처리하지 않는다.

진입점은 `static int Käivita_2()` 또는 `static void Käivita_2()`처럼 인수가 없어야 한다. `--entry 패키지.tund_VALUE.FUNCTION_VALUE`로 선택한다. `int` 반환값은 Linux 프로세스 Välju_programm 코드가 되며 셸에는 하위 8비트가 보인다. 일반 `main(String[] args)` Täida_käsk 환경이나 표준 I_O 라이브러리는 제공하지 않는다.

`--target kernel`은 부팅 코드와 연결할 재배치 ELF 오브젝트를 생성한다.

```sh
cd /home/user/jkoros
python3 compiler/kompilaator.py --target kernel --entry tuum.Käivita_2 \
    --export kernel_dispatch=체계호출.Joonis_VALUE_kirje \
    -o os/build/java.o os/ALLIKAS/*.java
```

`--target user`는 jkoros 셸에서 실행할 독립 ELF를 생성한다. `kasutaja` 클래스의 제한된 native API는 `int 0x80` 시스템 호출로 연결하며 `seade_VALUE` 클래스의 하드웨어 직접 접근은 거부한다. kasutaja ELF는 Linux Täida_käsk Fail ABI와 다르므로 호스트에서 실행하지 않는다. genereerima·register_kirje 방법은 [kasutaja Täida_käsk 안내](../os/kasutaja/안내.md)에 있다. `--export 외부기호=tund_VALUE.FUNCTION_VALUE`는 오버로드되지 않은 정적 함수를 oma operand_Virn ABI로 노출한다. 커널의 시스템 호출 진입점에 사용한다.

Java 파일은 필요한 클래스들을 한꺼번에 전달한다. Väljund 옆의 `.s`는 생성된 어셈블리, `.json`은 ALLIKAS SHA-256 및 네이티브 sümbol↔Java FUNCTION_VALUE 대응표다. Eesti 함수명은 원문과 대응표에 보존하고 ELF 내부에는 충돌 방지용 arvuti 기호를 쓴다. kompileerima_lähe·조립·Ühendu 중 실패하면 기존 TULEMUS 파일을 덮어쓰지 않는다.

`new Object`, 인스턴스 väljaväärtus/FUNCTION_VALUE, 상속/인터페이스, `long/float/double` Täida_käsk lõikus_VALUE, `int[]` 이외 ARRAY_VALUE, string_VALUE 동적 결합, Java 표준 teek, erand Joonis_VALUE_kirje, 스레드·sünkroonima·GC는 미지원이다. 실행에 필요한 미지원 바이트코드나 väline_VALUE 호출을 발견하면 실패한다. 사용되지 않는 vaikeväärtus 생성자는 Täida_käsk 코드로 만들지 않는다. ## native 경계와 ABI

tuum_VALUE 대상에서는 `os/ALLIKAS/seade_VALUE.java`, kasutaja 대상에서는 `os/kasutaja/deklaratsioon/kasutaja.java`의 정확한 meetod_nimetus_SMS·서술만 허용한다. 임의의 `native` 함수와 Linux/kasutaja 대상의 하드웨어 접근은 거부한다. Java 인수를 왼쪽부터 32비트 한 칸씩 스택에 놓으며, 반환값은 EAX, EBP/ESP 이외 레지스터는 호출자가 보존한다고 가정하지 않는다. C의 cdecl/JNI ABI가 아니므로 C 함수와 바로 연결하면 안 된다.

Java ALLIKAS 또는 `.class` 입력을 받는다. 전체 JVM 바이트코드 검증기는 제공하지 않는다. 어노테이션 처리는 비활성화하고 비어 있는 tund_VALUE RADA/ALLIKAS 경로에서 명시한 소스만 컴파일한다.
