# пространство_пользователя 호출 граница_ЗНАЧЕН

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `компьютер_5eb260fa/операционная_система_Вызовы.s`에서 EAX(ИНДЕКС), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 аргументы)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. ядро_ЗНАЧЕН 실패는 음수 ошибка ИНДЕКС, C библиотека 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 пространство_пользователя регион_ЗНАЧЕН 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C данные 주소는 байт_ЗНАЧЕН 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java файл 흐름의 어셈블리 경계가 별도 байт_ЗНАЧЕН 버퍼를 마련하여 같은 호출을 사용한다.

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 АДРЕС 두 칸이다. получить_ЗНАЧЕН 주소가 NULL이면 одноранговый_ЗНАЧЕН АДРЕС 기록을 생략한다. sockaddr_in은 16바이트이며 АДРЕС 체계는 устройство_ЗНАЧЕН байт_ЗНАЧЕН ПОСЛЕД_ЗНАЧЕН, 접속번호와 IP 주소는 네트워크 байт_ЗНАЧЕН 차례다. 축소된 АДРЕС 버퍼에도 들어가는 앞부분을 쓰고 전체 АДРЕС Размер 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 Выход_программа, 2·3은 기존 аргументы 조회다. текущий_товар 커널의 аргументы 목록이 실행 이름을 제외하므로 C 진입기는 argv[0]에 고정 строка_ЗНАЧЕН `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX Процесс_ЗНАЧЕН ABI와 다른 점이다.

표준 헤더의 целое_число Размер, 플래그 ЗНАЧЕН, stat значение_поля 순서는 `исходныйКод/объявления/`에 정의한다. 동적 Подключить·다중 Процесс_ЗНАЧЕН·스레드가 추가되면 ошибка ИНДЕКС 저장과 ресурс_ЗНАЧЕН 수명, 호출 경계도 함께 검토해야 한다.
