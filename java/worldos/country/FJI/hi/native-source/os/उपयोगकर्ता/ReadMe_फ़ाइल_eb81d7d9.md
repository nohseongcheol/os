# 셸에서 실행하는 उपयोगकर्ता 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 ReadMe_फ़ाइल_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 निष्पादित_करें_आदेश

आयोजक आदेशपटल 1:

```sh
cd /home/user/jkoros
python3 os/उपकरण/प्रतिध्वनि_डेटा.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. बाहरी_मान 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

आयोजक आदेशपटल 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 वास्तविक_डेटा CPU अनुमति_मान `ring 3`, तर्क निर्गम.
- `netcheck`: पोर्ट_मान 중복, 잘못된 हैंडल_मान/सूचक/길이, 비차단 받기와 समय_उपयोगिता 초과 सत्यापित_करें.
- `udp`: IPv4 पता·गंतव्य_मान पोर्ट_मान·한 शब्द_मान 메시지를 받아 UDP로 보내고 같은 응답을 सत्यापित_करें. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: आयोजक `10.0.2.2`의 असाइन_करें_मान 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 लूप_मान 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. अद्यतित_आइटम 주소는 게스트 `10.0.2.15/24`, गेटवे_मान `10.0.2.2`로 고정돼 있다. QEMU उपयोगकर्ता 네트워크의 आयोजक पहुँच_एन्ट्री 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 ऐप_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java ऐप_f5044b9b जोड़ें_एन्ट्री

`예제/내프로그램.java`를 अगला_आइटम 형식으로 만든다. 진입점은 तर्क 없는 `static int` 또는 `static void` 함수다. 인수는 उपयोगकर्ता API로 조회한다.

```java
public final class 내프로그램 {
    public static int चलाएँ() {
        उपयोगकर्ता.लिखें("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/उपयोगकर्ता/ऐप_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := उपयोगकर्ता/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.चलाएँ
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `उपयोगकर्ता/घोषणा/उपयोगकर्ता.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 निष्पादित_करें_आदेश 중인 VM에는 बिल्ड_सिस्टम 결과가 자동 반영되지 않는다. ऐप_f5044b9b 이름은 अद्यतित_आइटम 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java कक्षा_मान·फ़ंक्_शन_मान·변수에는 한국어를 쓴다. 최대 32개 ऐप_f5044b9b, 한 निष्पादित_करें_आदेश 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/कंपाइलर.py --target user --entry अभिनन्दन_ae353e94.चलाएँ \
    -o os/build/apps/hello.elf os/उपयोगकर्ता/घोषणा/उपयोगकर्ता.java os/उपयोगकर्ता/예제/अभिनन्दन_ae353e94.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 आयोजक 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 समर्थन_मान क्लिप 안에서 실행한다. `.jar`와 일반 Linux निष्पादित_करें_आदेश 파일은 지원하지 않는다.

## उपयोगकर्ता 네트워크 API

선언은 `घोषणा/उपयोगकर्ता.java`에 있다. `भेजें_डेटा`/`자료받기`의 `int[]` आइटम_तत्व 한 개는 बाइट_मान 하나(0~255)를 나타낸다. 한 데이터그램의 최대 आँकड़े 길이는 1,024바이트다.

```java
int हैंडल_मान = उपयोगकर्ता.जारी_नेटवर्क(0); // 0: 임시 स्थानीय_दायरा UDP पोर्ट_मान 자동 चयन_मान
int[] आँकड़े = new int[32];
आँकड़े[0] = 'H'; आँकड़े[1] = 'i';
int 보낸길이 = उपयोगकर्ता.भेजें_डेटा(हैंडल_मान, 0x0a000202, 9000, आँकड़े, 2);
int 받은길이 = उपयोगकर्ता.자료받기(हैंडल_मान, आँकड़े, 1500);
उपयोगकर्ता.बंद_नेटवर्क(हैंडल_मान);
```

वास्तविक_डेटा 프로그램에서는 खोलें·भेजें·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 प्रतीक्षा_करें_मान 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 जोड़ें_एन्ट्री 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | हैंडल_मान·प्रक्रिया_मान_एन्ट्री 길이·성공 등 해당 함수의 परिणाम |
| -5 | उपकरण_मान भेजें_मान विफलता_मान |
| -9 | 잘못되었거나 닫힌 통신 हैंडल_मान |
| -11 | 비차단 받기에서 도착한 आँकड़े 없음 |
| -14 | उपयोगकर्ता सूचक/सरणी_मान क्लिप त्रुटि |
| -19 | समर्थन_मान NIC 없음 |
| -22 | पोर्ट_मान/प्रतीक्षा_करें_मान समय_उपयोगिता/तर्क मान त्रुटि |
| -24 | 열린 नेटवर्क_पोर्ट 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | आँकड़े 또는 수신 सरणी_मान आकार 문제 |
| -98 | स्थानीय_दायरा पोर्ट_मान इंडेक्स 중복 |
| -101 | 지원하지 않는 गंतव्य_मान पता |
| -110 | ARP·उपकरण_मान·수신 समय_उपयोगिता 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 एन्कोडिंग_मान 있는 Java `int`의 बिट_मान 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## निष्पादित_करें_आदेश 경계와 시스템 호출

```text
शेल run → JKAP에서 ELF मान्य_करें·적재 → ring 3 उपयोगकर्ता ऐप_f5044b9b
                                 ↓ int 0x80
                      सूचक 검사 → Java कर्नेल_मान API → RTL8139/UDP
                                 ↓ निर्गमन_ऐप·अपवाद·समय_उपयोगिता 초과
                                शेल 복귀
```

시스템 호출 레지스터는 `EAX=इंडेक्स`, `EBX,ECX,EDX,ESI,EDI=तर्क`, `EAX=परिणाम`다. Java 호출 ऑपरेंड_स्टैक ABI는 컴파일러가 उपयोगकर्ता 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| इंडेक्स | 호출 |
| --- | --- |
| 0 | निर्गमन_ऐप(अवस्था_मान कोड_मान) — चलाएँ/त्रुटि 런타임에서 사용 |
| 1 | स्ट्रिंग_मान लिखें |
| 2 / 3 | तर्क 개수 / तर्क स्ट्रिंग_मान पता |
| 10 | UDP खोलें |
| 11 | UDP भेजें(हैंडल_मान, IP, गंतव्य_मान पोर्ट_मान, सरणी_मान पता, 길이) |
| 12 | UDP 받기(हैंडल_मान, सरणी_मान पता, 제한 밀리초) |
| 13 | UDP बंदकरें |
| 14 | स्थानीय_दायरा IP पता |
| 15 / 16 | 마지막 पीअर_मान IP / UDP पोर्ट_मान |
| 20 | RAM संचिका पढ़ें(नाम int[] पता, निर्गम int[] पता) |
| 21 | RAM संचिका लिखें(नाम int[] पता, 입력 int[] पता, बाइट_मान 길이) |
| 22 | UTF-16 कोड_मान इकाई_मान 문자 निर्गम(0~65535) |

संचिका API는 `उपयोगकर्ता.पढें_फ़ाइल(int[] नाम, int[] आँकड़े)`와 `उपयोगकर्ता.लिखना_फ़ाइल(int[] नाम, int[] आँकड़े, int 길이)`다. 이름은 ASCII कोड_मान सरणी_मान(최대 64칸, 0 निर्गमन_ऐप 또는 सरणी_मान 끝), आँकड़े आइटम_तत्व 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 संचिका 없음 `-2`, सूचक त्रुटि `-14`, नाम/길이 त्रुटि `-22`, संचिका 슬롯 부족 `-28`, आकार 초과 `-90`을 반환한다. 쓰기는 मान्य_करें 후 संचिका 전체를 대체한다. `उपयोगकर्ता.लिखना_कैरेक्टर_मान(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 उपयोगकर्ता 모드에서 CS의 하위 비트를 직접 읽으므로 वास्तविक_डेटा निष्पादित_करें_आदेश 권한을 확인한다. कर्नेल_मान 포트 접근용 `उपकरण_मान` native 함수는 उपयोगकर्ता लक्ष्य 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 निष्पादित_करें_आदेश, 파이프, 프로세스 간 통신은 없다. निष्पादित_करें_आदेश 파일은 커널의 पढ़ें 전용 JKAP 묶음에서 적재한다. आँकड़े 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- उपयोगकर्ता 가상 पता `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. निष्पादित_करें_आदेश 영상은 सामने_मान 2MiB, 인수는 `0x04300000`부터, 스택은 क्षेत्र_मान 끝에서 시작한다. कर्नेल_मान identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB उपयोगकर्ता 영역을 비우고 संचिका 구역을 복사해 BSS·सरणी_मान 영역을 초기화한다. उपयोगकर्ता GC는 없지만 निर्गमन_ऐप 후 अगला_आइटम निष्पादित_करें_आदेश 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 कोट/이스케이프 파싱은 없다.
- उपयोगकर्ता 페이지의 कोड_मान/आँकड़े 분리 पढ़ें 전용 विन्यास, NX, ऑपरेंड_स्टैक guard, ASLR은 아직 없다. 커널과 उपयोगकर्ता मेमोरी_डेटा·포트 अनुमति_मान 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 निष्पादित_करें_आदेश 상한을 두며 समय_उपयोगिता 초과는 `Exit: 124`다. उपयोगकर्ता CPU 예외는 `128 + अपवाद इंडेक्स`(페이지 त्रुटि 142, 특권 위반 141), Java सरणी_मान/계산 오류는 101~105다. कर्नेल_मान 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, 정적 IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP योगफल_की_जाँच 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- उपयोगकर्ता निष्पादित_करें_आदेश·네트워크·रक्षित_करें_मान 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 निष्पादित_करें_आदेश·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## मान्य_करें 근거

`make test`는 कंपाइलर 14개 시험, Java 패킷 शर्त 2,201개 검사, 기존 शेल ELF/ISO 부팅 시험, उपयोगकर्ता ELF/वास्तविक_डेटा UDP/रक्षित_करें_मान 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 길이·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 आदेश·무한 पुनरावृति_मान 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.

참고한 일차 आँकड़े: [Intel 시스템 프로그래밍 명세](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html), [QEMU RTL8139 구현](https://github.com/qemu/qemu/blob/master/hw/net/rtl8139.c), [QEMU 네트워크 ReadMe_फ़ाइल_eb81d7d9](https://www.qemu.org/docs/master/system/devices/net.html), [IPv4 RFC 791](https://www.rfc-editor.org/rfc/rfc791), [ARP RFC 826](https://www.rfc-editor.org/rfc/rfc826), [UDP RFC 768](https://www.rfc-editor.org/rfc/rfc768).
