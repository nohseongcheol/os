# निज 커널과 번역기의 हिंदी नाम

대상은 `platforms/rpi4-native`의 निज Java कर्नेल_मान, उपयोगकर्ता JVM, C यंत्र जोड़ना,
TCP/UDP·FTP, C कंपाइलर_उपकरण 이식부, MicroPython 이식부, बिल्ड_सिस्टम·निष्पादित_करें_आदेश·시험 도구다.
`golang/worldos/कंट्री_मान/KOR/स्रोत`의 원칙처럼 기능을 먼저 구분하고 이름을 정한다.
x86 Java 커널과 공용 x86·ARM64 미리 번역기의 निज 선언도 명명 검사에 포함한다.
Linux 실행판의 आयोजक उपकरण, OpenJDK 보조 उपकरण 및 बाहरी_मान 배포 स्रोत_ट्री 전체를
한국어로 다시 작성했다는 뜻은 아니다.

## 명명 원칙과 말의 근거

- 명사는 자료의 역할을 나타낸다: `फ़ाइल_हैंडल`, `पीअर_पोर्ट_संख्या`, `ढ़ेर_संग्रहण`, `कीबोर्ड`.
- 함수는 행위를 나타낸다: `पढ़ें`, `लिखें`, `खोलें`, `बंदकरें`, `망주소묶기`, `चलाएँ_ऐप`.
- TCP의 이어진 बाइट_मान 흐름과 UDP의 경계 있는 자료를 `कनेक्शन`와 `전문통로`로 구별한다.
- 짧은 영어 변수도 쓰임에 따라 `길이`, `डेटा_पद`, `लुकअप_इंडेक्स`, `반환값`으로 풀어 쓴다.
  순번·임시 산술값처럼 여러 역할에 재사용되는 변수는 `순번`, `첫째값`, `둘째값`으로 구별한다.
- 이름이 같아도 बाहरी_मान 구조체의 필드와 निज 변수는 별도로 분석한다.

`चैनल_एन्ट्री(通路)`는 이동이나 교류가 이루어지는 길이라는 기존 의미를 통신 연결에
적용했다. `पोर्ट_मान(窓口)`의 주고받는 접점이라는 의미를 연결을 받는 곳에 적용했다.
이는 국립국어원 한국어기초사전의 [चैनल_एन्ट्री](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=49310),
[पोर्ट_मान](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=24898)의 뜻에 근거한다.

`स्वतंत्रसंदेश(電文)`은 전보에 담는 글이라는 기존 통신 어휘에서 가져와, UDP 자료의
경계가 보존된다는 특징을 드러내는 데 쓴다. 근거는
[한국어기초사전 स्वतंत्रसंदेश](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=74335)이다.
`स्ट्रीम_मान`, `थ्रेड_मान`, `쌓임`은 우리말의 움직임·이어짐·쌓이는 모양을 빌린 표현이다.
`इनपुट_प्रवाह`, `कार्यसूत्र`, `स्टैक_संग्रहण` 같은 복합 이름은 이 프로젝트의 기능별 조어다.
이 कोश 근거를 특정 중세 문헌의 최초 출현이나 공인 전산 번역으로 확대하지 않는다.
공인 표준 अनुवाद_स्रोत·국어사 स्वतंत्रसंदेश 감수를 마쳤다는 뜻도 아니다.

| 기능 | 채택한 नाम | 이유 |
|---|---|---|
| TCP Socket | कनेक्शन | 상대와 연결되어 क्रम_मान 있는 바이트를 주고받음 |
| ServerSocket | 수신창구 | 새 연결이 들어오는 접점 |
| DatagramSocket | 전문통로 | 각 자료의 경계를 보존하는 통신 |
| InputStream / OutputStream | इनपुट_प्रवाह / आउटपुट_प्रवाह | 들어오고 나가는 바이트의 क्रम_मान |
| heap / stack | ढ़ेर_संग्रहण / स्टैक_संग्रहण | आवंटित_करें_संग्रहण 방식과 쌓고 꺼내는 구조 |
| thread / keyboard | कार्यसूत्र / कीबोर्ड | 이어지는 실행과 글쇠의 सरणी_मान |
| exception / timeout | अपवाद / 대기시간초과예외 | 정상 처리에서 벗어남과 그 구체적 이유 |

호환 진입점이며 구현을 두 벌 유지하지 않는다.

## 보존하는 규격 नाम

`public`, `class`, `int`는 예약어다. `String`, `main`, 배열의 `length`는 예약어가 아니다.
अद्यतित_आइटम 다섯 Java 예제는 `चलाएँ()`·`실행인수`·हिंदी 화면/थ्रेड_मान API를 사용해
예약어·리터럴 외의 식별자를 한국어로 작성한다. 화면/가닥은 표준 객체를
감싸지 않고 निज JVM에 직접 구현했다. 자세한 계약은 [हिंदी Java API](../한국어자바/ReadMe_फ़ाइल_eb81d7d9.md)를 본다.

표준 javac는 स्ट्रिंग_मान 리터럴에 `java.lang.String`, स्ट्रिंग_मान 결합에 `StringBuilder`
같은 이름을 생성한다. 이들은 हिंदी 소스에서도 바이트코드에 남을 수 있다.
기존 표준 class를 실행하는 JVM의 대응 स्ट्रिंग_मान, 아직 표준 라이브러리를 쓰는
통신·संचिका 연결부까지 모두 한국어로 재구현한 것은 아니다. 이름만 일괄 치환하면
서술자·재정의·native 연결이 달라져 호환성이 깨진다.

C 표준 फ़ंक्_शन_मान·पूर्णांक_लिखें·POSIX ABI, CPU रजिस्टर_मान नाम, 어셈블리 आदेश, 링커 절 नाम,
TinyCC·lwIP·MicroPython이 요구하는 विन्यास 매크로와 헤더 이름도 보존한다.
예: `main`, `memcpy`, `pk_bind`, `mpconfigport.h`, `lwipopts.h`, `stdint.h`.
निज C 함수의 स्रोत_ट्री 이름은 한국어이며, [기계연결이름.h](기계연결이름.h)가
기존 AOT·어셈블리·SDK에 공개한 यंत्र 심볼과 연결한다.
Python의 `__init__`, `setUp`, `handle`, 표준 मॉड्यूल_मान विशेषता_मान, 명령행 옵션과 JSON 키도
बाहरी_मान 계약이다. `build/`, 배포 바이너리 이름과 `/sdk`는 기존 निष्पादित_करें_आदेश 경로를 유지한다.
बाहरी_मान 원본은 `vendor/`에서 이용허락·해시와 함께 관리한다.

## 검사와 재실행

```sh
cd /home/user/jkoros/platforms/rpi4-native
python3 उपकरण/명명검사.py
make बिल्ड_सिस्टम
make 시험
make test-examples test-ftp test-elf
python3 उपकरण/निष्पादित_करें_आदेश.py --desktop --network
```

`उपकरण/시언어이름분석.py`는 libclang 6으로 C 선언과 참조를 검사한다.
`उपकरण/*이름반영.py`는 परिवर्तित_करें_मान 전 स्रोत_ट्री·분석표를 필요로 하는 일회성 이행 도구다.
이미 변경된 소스에 다시 적용하여 대응표를 덮어쓰지 않는다.

## C 통신 구조체와 Python त्रुटि

C 통신에서 `갈래`는 पता 체계를 구분하고 `पोर्ट_संख्या`는 port, `पता_मान`은
IPv4 주소의 32비트 값을 나타낸다. `전문전송규약`은 앞서 설명한 स्वतंत्रसंदेश(電文)과
मामला_मान(規約)을 결합해 UDP의 기능을 드러낸 프로젝트 이름이다.

| 표준 표현 | हिंदी 직접 구현 |
|---|---|
| AF_INET / SOCK_DGRAM / IPPROTO_UDP | enum의 क्लाउड_समूह / 전문통신 / 전문전송규약 |
| struct pk_sockaddr_in | struct क्लाउड_सॉकेट_पता |
| sin_family / sin_port | पता_समूह / पोर्ट_संख्या |
| sin_addr.s_addr | इंटरनेट_पता.पता_मान |
| OSError / त्रुटि.args[0] | सिस्टम_त्रुटि / त्रुटि.इंडेक्स |

हिंदी 구조체는 `#define` 치환이나 फ़ील्ड_मान 별칭이 아닌 별개 자료형이다.
표준 구조체와 같은 16바이트 배치를 선언하며 कर्नेल_मान SVC에서 बाइट_मान 복사로
검사한다. `बनाएँ_एंडपॉइंट`·`자료전문보내기`와 संचिका 함수는 정적 라이브러리에
वास्तविक_डेटा हिंदी 이름의 फ़ंक्_शन_मान 심볼을 갖는다. 기존 pk_* 심볼도 유지한다.
이전 코드에서 हिंदी 통신 함수에 pk_sockaddr*를 전달했다면 हिंदी 구조체로
옮기거나, 표준 구조체와 pk_* 함수의 짝을 유지한다.

Python의 `सिस्टम_त्रुटि`는 OSError의 हिंदी 하위 클래스이며 연결부에서
त्रुटि 번호를 보존하여 변환한다. 일반 Python 문법과 बाहरी_मान 패키지의 API는 유지한다.

## 직접 GUI 이름의 뜻과 검토 क्लिप

`실행할일`은 수행할 내용을, `निष्पादन`는 그 수행을 나타낸다.
`동작받이`는 동작이 발생했다는 알림을 받는 역할, `एक्शन_सूचना`은 전달되는 사건이다.
`बटन`는 눌러 동작시키는 조작부, `लेबल`는 ReadMe_फ़ाइल_eb81d7d9 글의 पद_इंडेक्स,
`पाठ_फ़ील्ड`은 글을 적는 पद_इंडेक्स, `कार्यसूत्र`은 이어지는 निष्पादित_करें_आदेश 흐름을 뜻한다.
`निष्पादित_करें_आदेश(實行)`·`क्रिया(動作)`의 기존 뜻과 `받다`·`알리다`·`थ्रेड_मान`의 기능을
결합한 프로젝트 이름이다. 새 복합어가 역사 문헌에 그대로 있었다거나
특정 시대에 처음 쓰였다고 주장하지 않는다.

전체 저장소는 `python3 उपकरण/स्रोत_समीक्षा.py`로 검토한다.
결과는 `build/verification/naming/source-review.json`이며 파일별 हैश_फ़ाइल,
ASCII 파일명과 Python의 영어 घोषणा 위치를 기록한다.
공용 ARM64·x86 번역기의 구현은 `compiler/जावासाधन/पूर्वसंकलक.java`로 전환했다. `compiler/पूर्वसंकलक.py`는 호환 진입점이다.
`compiler/arm64.py`는 이전 경로와 `ARM64(...).generate(...)` 호출을 이어 주는
호환 진입점이다. `compiler/classfile.py`, OpenJDK 보조 उपकरण, Linux संस्करण_मान 도구와
기존 호환 진입점에는 영어 이름이 남아 있다. 따라서 전체 저장소가
예약어 외 100% 한국어라고 판정하지 않는다.
`उपकरण/명명검사.py --सी_भाषा`는 सक्रिय ARM64 소스의 घोषणा, C 의미 विश्लेषण_मान,
x86 Java 커널과 공용 번역기의 निज घोषणा, Java 예제 전체 पहचानकर्ता_मान,
ARM64 Python 예제와 직접 GUI/가닥에 표준 래퍼가 없는지를 별도로 검사한다.

## अद्यतित_आइटम 기능을 기준으로 보완한 नाम

번역은 글자를 음역하는 대신 자료의 역할과 함수의 행동을 구분한다.
동일한 영어 이름도 문맥이 다르면 हिंदी 이름을 달리 정한다.
संचिका 이름은 주된 기능을 나타내고, फ़ंक्_शन_मान 이름은 행동을, चर_मान 이름은 담는 자료를 나타낸다.
예약어, 표준 API 및 बाहरी_मान जोड़ना 규약은 따로 기록한다.

| 이전 नाम | 적용한 नाम | अद्यतित_आइटम 기능 |
|---|---|---|
| `arm64.py`의 구현 | `compiler/जावासाधन/पूर्वसंकलक.java` | Java 바이트코드를 독립 실행용 C 원문으로 미리 अनुवाद_स्रोत |
| `ARM64`, `generate` | `यंत्र_कोड_कंपाइलर`, `जनरेट_करें` | अनुवाद_स्रोत 상태를 담는 객체와 C स्रोत जनरेट_करें 행동 |
| `prototype`, `method` | `विधि_मूलरुप`, `विधि_मुख्य_संदेश` | 함수의 फॉर्मैट_मान 선언과 वास्तविक_डेटा आदेश स्रोत |
| `profile`, `heap_words` | `실행대상`, `동적기억낱말수` | कर्नेल_मान·उपयोगकर्ता 구분과 आवंटित_करें_संग्रहण मेमोरी_मान 공간의 यंत्र 낱말 수 |
| `pc`, `op` | `आदेश_पद`, `명령번호` | 바이트코드에서의 위치와 수행할 명령의 इंडेक्स |
| `x`, `y`, `w`, `h` | `x_निर्देशांक`, `세로좌표`, `영역너비`, `영역높이` | दूरस्थ_मान 화면의 위치와 직사각형 आकार |
| `p`, `n`, `i`, `j` | `डेटा_पद`, `मान`, `순번`, `안쪽순번` | दूरस्थ_मान 화면 आँकड़े·अंक_मान·पुनरावृति_मान पद_इंडेक्स; 파일별 기능을 확인해 적용 |
| `aot_heap_info`, `__stack_top` | `미리번역기억조회`, `커널쌓임공간끝` | यंत्र जोड़ना 규약을 유지하면서 निज 소스에서 사용하는 नाम |
| `앞캐리지` | `앞줄복귀` | 앞서 받은 문자가 줄복귀였는지 기억하여 중복 줄바꿈을 막음 |

[공용번역기이름대응.tsv](공용번역기이름대응.tsv)에 कंपाइलर_उपकरण 참조의 वास्तविक_डेटा परिवर्तित_करें_मान 기록을 남겼다.
추가로 보존한 C·POSIX/lwIP/libassh 이름의 이유는
[규격이름근거.json](규격이름근거.json)에 기록한다.
`सी_कंपाइलर/कंपाइलर_उपकरण.c`는 TinyCC बाहरी_मान 원문을 포함하는 जोड़ना 파일로 निज 선언이 없어서
C निज घोषणा 분석에서는 제외한다. वास्तविक_डेटा कर्नेल_मान 빌드에서는 계속 컴파일한다.

### 말의 뿌리와 새로운 복합 नाम

`मेमोरी_मान(記憶)`과 `लुकअप_इंडेक्स(索引)`은 기존 한자어를 쓴다.
기억은 자료를 간직하는 기능에, 색인은 क्रम_मान 있는 항목을 찾아 지정하는 기능에 적용한다.
कोश 근거는 국립국어원 한국어기초사전의
[मेमोरी_मान](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=38812&nation=eng),
[लुकअप_इंडेक्स](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=63787)이다.

`स्टैक_संग्रहण`, `पुश_मान`, `पॉप_मान`는 자료를 포개고 마지막 자료부터 꺼내는 निष्पादित_करें_आदेश 구조를 드러낸다.
`쌓다`의 기존 뜻에 근거한 기능별 조어이며, 사전의
[쌓다](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=62095)를 참고한다.
`미리번역`은 निष्पादित_करें_आदेश 전에 번역한다는 기능을 직접 나타낸다.
`यंत्र_शब्द`은 처리기의 आँकड़े 단위를 가리키며, 언어의 일반 낱말과 구별하도록 `यंत्र`를 붙였다.
`पूर्वसंकलक`, `동적기억낱말수` 같은 복합 이름은 अद्यतित_आइटम 기능에 맞게 만든 프로젝트 용어다.
이 복합어가 옛 문헌에 그대로 있었다거나 특정 시대에 처음 나타났다는 뜻은 아니다.
확인되지 않은 중세 형태나 최초 사용 연대는 어원 근거로 적지 않는다.

생성되는 C의 내부 डेटा_प्रकार·सरणी_मान·फ़ंक्_शन_मान·स्थानीय_दायरा चर_मान·शाखा 이름도 한국어로 바꾼다.
직접 한글 식별자를 읽지 못하는 예전 GCC를 위해 호환 API는 같은 हिंदी 이름을
표준 C 범용 문자 표기로 출력한다. वास्तविक_डेटा ARM64 빌드는 Clang으로 읽을 수 있는 한글 원문을 사용한다.
स्ट्रिंग_मान, C 표준 फ़ंक्_शन_मान, `java_entry` 같은 공개 जोड़ना 이름은 바꾸지 않는다.

셸의 사용법·문법 त्रुटि·संचिका 및 मेमोरी_मान पता_क्षेत्र 안내도 한국어로 보완했다.
`READY`, `PASS`, `HEX BEGIN`처럼 시험·संचिका हस्तांतरण_मान 도구가 읽는 मार्कर_मान,
명령행 옵션과 기존 명령어, JVM कक्षा_मान नाम·संचिका फॉर्मैट_मान·उपकरण_मान 이름은 호환 표기로 남는다.
x86 VGA 문자 화면은 한글을 표시하지 못하므로 हिंदी 문구는 UTF-8 직렬 단말에서 확인한다.
