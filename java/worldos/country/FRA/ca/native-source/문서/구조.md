# JFraOS 구조

아래는 objecte_VALOR 기반 관리 nucli_VALOR 전체의 objectiu_objecte 구조다. 현재 real_dades 부팅 가능한 제한형 구현은 `compiler/`와 `os/`에 있으며 [네이티브 sistema_operatiu LLEGIU_ME_eb81d7d9](../os/LLEGIU_ME_eb81d7d9.md)에 구현 범위를 명시한다. 아래의 GC·문맥 canvi_MODA·sistema_d_arxius 등이 새 ISO에 모두 포함돼 있지는 않다.

```text
GRUB 또는 UEFI
  ↓
x86 최소 부트·트랩 capa_VALOR
  ↓
Java AOT 실행기와 objecte_VALOR·MATRIU_VALOR·GC 런타임
  ↓
하드웨어 경계
  ↓
Java 관리 nucli_VALOR
  ├─ 기억공간/쪽관리/COW
  ├─ Procés_VALOR/배정/wait
  ├─ sistema_d_arxius/ELF/POSIX
  └─ 입력/Emmagatzematge_dispositiu/xarxa_Pila
```

OpenJDK 자체는 이미 운영체제가 제공하는 Fitxer, 스레드, 가상 기억공간을 전제로 한다. 따라서 nucli_VALOR 부팅에는 OpenJDK를 그대로 넣지 않고 제한된 Java 바이트코드 AOT와 작은 런타임을 사용한다.

네이티브 계층에는 `in/out`, `hlt`, CR0/CR2/CR3/CR4, `iret`, 문맥 저장처럼 Java로 표현할 수 없는 CPU 동작만 남긴다. 정책과 자료구조는 Java에 둔다.
