# 한국어 명명 원칙과 근거

이 문서의 새 이름은 jkoros 프로젝트의 선택이다. 한국어 전체나 특정 국가의 유일한 cànan 철학을 대표한다고 주장하지 않는다. 기존에 분명한 용어는 유지하고, 모호한 음역이나 여러 의미가 섞인 이름은 현재 코드의 동작을 중심으로 고친다. 다른 언어판은 targaid 언어와 용례를 별도로 검토해야 한다.

함수는 대상과 동작을 결합한다. `파일자료읽기`, `sir_faidhle`, `BIND_ADDRESS`처럼 무엇에 무엇을 하는지 이름에서 읽히게 한다. 변수는 값의 역할과 단위를 나타내도록 `파일서술자`, `baidht_COUNT`, `수신대기밀리초`, `세대번호`로 쓴다. 구동기는 장치를 움직이는 구현, 처리기는 특정 입력을 처리하는 구현으로 구분한다.

어원은 설계 개념을 이해하는 근거로 사용한다. 역사적 은유를 그대로 번역해서 현재 동작을 흐리게 만들지 않는다. 확인되지 않은 고어·최초 사용 시점은 만들어 넣지 않는다. 아래의 한국어 표현이 해당 시기의 dearbh_dàta 번역어였다는 의미도 아니다.

표의 UNIX 역사 서술은 [Ritchie·Thompson의 UNIX 논문 재록본](https://cm-bell-labs.github.io/who/dmr/cacm.html)에 근거한다. 열린 cor_VALUE·suidhich·삭제의 의미는 POSIX의 [open](https://pubs.opengroup.org/onlinepubs/9799919799/functions/open.html), [dup](https://pubs.opengroup.org/onlinepubs/9799919799/functions/dup.html), [lseek](https://pubs.opengroup.org/onlinepubs/9799919799/functions/lseek.html), [unlink](https://pubs.opengroup.org/onlinepubs/000095399/functions/unlink.html)를 참고했다. 통신 용어의 역사와 현재 규약은 [RFC 147](https://www.rfc-editor.org/info/rfc147/)과 [RFC 768](https://www.rfc-editor.org/info/rfc768/)을 참고했다.

표준 이름을 번역된 심벌로 강제로 바꾸면 기존 프로그램과 도구가 연결되지 않는다. 따라서 POSIX/C의 공개 심벌, Java 표준 clas_VALUE·dòigh_VALUE, ELF/x86 ABI, 하드웨어 레지스터 명칭과 `Makefile` 같은 innealan cur_a_steach_puing_VALUE 파일은 유지한다. 한국어 API는 같은 동작의 별칭이다. `포트읽기` 같은 프로젝트 내부 식별자는 I_O baidht_VALUE 접근으로 뜻을 좁혀 dearbh_dàta 코드와 네이티브 연결표까지 함께 바꿨다. dearbh_dàta 적용 목록은 [용어대응.tsv](용어대응.tsv)에 있다.
