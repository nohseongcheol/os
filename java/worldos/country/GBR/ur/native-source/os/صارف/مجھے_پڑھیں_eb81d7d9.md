# 셸에서 실행하는 صارف 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 مجھے_پڑھیں_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 نفاذ_کریں_حکم

میزبان حکم_کی_تشریح_کرنے_والا 1:

```sh
cd /home/user/jkoros
python3 os/ٹولز/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 외부 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

میزبان حکم_کی_تشریح_کرنے_والا 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 اصل_کوائف CPU اجازت_قدر `ring 3`, دلائل اخراج_کا_مقام.
- `netcheck`: پورٹ_قدر 중복, 잘못된 ہینڈل_قدر/پوائنٹر/لمبا_ئی_قدر, 비차단 받기와 وقت_قدر 초과 تصدیق_کریں.
- `udp`: IPv4 پتہ·منزل_مقصود_قدر پورٹ_قدر·한 الفاظ_قدر 메시지를 받아 UDP로 보내고 같은 응답을 تصدیق_کریں. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: میزبان `10.0.2.2`의 تفویض_کریں_قدر 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 لوپ_قدر 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 현재 주소는 게스트 `10.0.2.15/24`, گیٹ_وے_قدر `10.0.2.2`로 고정돼 있다. QEMU صارف 네트워크의 میزبان رسائی_اندراج 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 ایپ_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java ایپ_f5044b9b 추가

`예제/내프로그램.java`를 اگلا_شے 형식으로 만든다. 진입점은 دلائل 없는 `static int` 또는 `static void` 함수다. 인수는 صارف API로 조회한다.

```java
public final class 내프로그램 {
    public static int چلائیں() {
        صارف.لکھیں("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/صارف/ایپ_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := صارف/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.چلائیں
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `صارف/선언/صارف.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 نفاذ_کریں_حکم 중인 VM에는 بلڈ_نظام 결과가 자동 반영되지 않는다. ایپ_f5044b9b 이름은 현재 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java صنف_قدر·فعل_قدر·변수에는 한국어를 쓴다. 최대 32개 ایپ_f5044b9b, 한 نفاذ_کریں_حکم 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.چلائیں \
    -o os/build/apps/hello.elf os/صارف/선언/صارف.java os/صارف/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 میزبان 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 معاونت_قدر تراشہ 안에서 실행한다. `.jar`와 일반 Linux نفاذ_کریں_حکم 파일은 지원하지 않는다.

## صارف 네트워크 API

선언은 `선언/صارف.java`에 있다. `بھیجیں_کوائف`/`자료받기`의 `int[]` شے_عنصر 한 개는 بائٹ_قدر 하나(0~255)를 나타낸다. 한 데이터그램의 최대 کوائف 길이는 1,024바이트다.

```java
int ہینڈل_قدر = صارف.بنائیں_نیٹ_ورک(0); // 0: 임시 مقامی_اسکوپ UDP پورٹ_قدر 자동 انتخاب_قدر
int[] کوائف = new int[32];
کوائف[0] = 'H'; کوائف[1] = 'i';
int 보낸길이 = صارف.بھیجیں_کوائف(ہینڈل_قدر, 0x0a000202, 9000, کوائف, 2);
int 받은길이 = صارف.자료받기(ہینڈل_قدر, کوائف, 1500);
صارف.بند_نیٹ_ورک(ہینڈل_قدر);
```

اصل_کوائف 프로그램에서는 کھولیں·بھیجیں·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 انتظار_قدر 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 추가 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | ہینڈل_قدر·عمل_قدر_اندراج لمبا_ئی_قدر·성공 등 해당 함수의 پیمائش |
| -5 | آلہ_قدر بھیجیں_قدر ناکامی_قدر |
| -9 | 잘못되었거나 닫힌 통신 ہینڈل_قدر |
| -11 | 비차단 받기에서 도착한 کوائف 없음 |
| -14 | صارف پوائنٹر/لڑی_قدر تراشہ غلطی |
| -19 | معاونت_قدر NIC 없음 |
| -22 | پورٹ_قدر/انتظار_قدر وقت_قدر/دلائل قدر غلطی |
| -24 | 열린 نیٹ_ورک_پورٹ 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | کوائف 또는 수신 لڑی_قدر حجم 문제 |
| -98 | مقامی_اسکوپ پورٹ_قدر اشاریہ 중복 |
| -101 | 지원하지 않는 منزل_مقصود_قدر پتہ |
| -110 | ARP·آلہ_قدر·수신 وقت_قدر 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 ضابطہ_بندی_قدر 있는 Java `int`의 بٹ_قدر 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## نفاذ_کریں_حکم 경계와 시스템 호출

```text
شیل run → JKAP에서 ELF جواز_دہی_کریں·적재 → ring 3 صارف ایپ_f5044b9b
                                 ↓ int 0x80
                      پوائنٹر 검사 → Java کرنیل_قدر API → RTL8139/UDP
                                 ↓ خروج_ایپ·استثنا·وقت_قدر 초과
                                شیل 복귀
```

시스템 호출 레지스터는 `EAX=اشاریہ`, `EBX,ECX,EDX,ESI,EDI=دلائل`, `EAX=پیمائش`다. Java 호출 스택 ABI는 컴파일러가 صارف 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| اشاریہ | 호출 |
| --- | --- |
| 0 | خروج_ایپ(حالت_قدر 코드) — چلائیں/غلطی 런타임에서 사용 |
| 1 | سلک_قدر لکھیں |
| 2 / 3 | دلائل 개수 / دلائل سلک_قدر پتہ |
| 10 | UDP کھولیں |
| 11 | UDP بھیجیں(ہینڈل_قدر, IP, منزل_مقصود_قدر پورٹ_قدر, لڑی_قدر پتہ, لمبا_ئی_قدر) |
| 12 | UDP 받기(ہینڈل_قدر, لڑی_قدر پتہ, 제한 밀리초) |
| 13 | UDP بند_کریں |
| 14 | مقامی_اسکوپ IP پتہ |
| 15 / 16 | 마지막 ساتھی_قدر IP / UDP پورٹ_قدر |
| 20 | RAM فائل_کا_نام پڑھیں(نام int[] پتہ, اخراج_کا_مقام int[] پتہ) |
| 21 | RAM فائل_کا_نام لکھیں(نام int[] پتہ, 입력 int[] پتہ, بائٹ_قدر لمبا_ئی_قدر) |
| 22 | UTF-16 코드 سبق_قدر 문자 اخراج_کا_مقام(0~65535) |

فائل_کا_نام API는 `صارف.파일읽기(int[] نام, int[] کوائف)`와 `صارف.لکھیں_فائل(int[] نام, int[] کوائف, int لمبا_ئی_قدر)`다. 이름은 ASCII 코드 لڑی_قدر(최대 64칸, 0 خروج_ایپ 또는 لڑی_قدر 끝), کوائف شے_عنصر 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 فائل_کا_نام 없음 `-2`, پوائنٹر غلطی `-14`, نام/لمبا_ئی_قدر غلطی `-22`, فائل_کا_نام سلاٹ_قدر 부족 `-28`, حجم 초과 `-90`을 반환한다. 쓰기는 جواز_دہی_کریں 후 فائل_کا_نام 전체를 대체한다. `صارف.لکھیں_کریکٹر_قدر(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 صارف 모드에서 CS의 하위 비트를 직접 읽으므로 اصل_کوائف نفاذ_کریں_حکم 권한을 확인한다. کرنیل_قدر 포트 접근용 `آلہ_قدر` native 함수는 صارف ہدف 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 نفاذ_کریں_حکم, 파이프, 프로세스 간 통신은 없다. نفاذ_کریں_حکم 파일은 커널의 پڑھیں 전용 JKAP 묶음에서 적재한다. کوائف 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- صارف 가상 پتہ `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. نفاذ_کریں_حکم 영상은 앞 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. کرنیل_قدر identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB صارف 영역을 비우고 فائل_کا_نام 구역을 복사해 BSS·لڑی_قدر 영역을 초기화한다. صارف GC는 없지만 خروج_ایپ 후 اگلا_شے نفاذ_کریں_حکم 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 اقتباس/이스케이프 파싱은 없다.
- صارف 페이지의 코드/کوائف 분리 پڑھیں 전용 ترتیبات, NX, 스택 guard, ASLR은 아직 없다. 커널과 صارف میموری_کوائف·포트 اجازت_قدر 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 نفاذ_کریں_حکم 상한을 두며 وقت_قدر 초과는 `Exit: 124`다. صارف CPU 예외는 `128 + استثنا اشاریہ`(페이지 غلطی 142, 특권 위반 141), Java لڑی_قدر/계산 오류는 101~105다. کرنیل_قدر 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, جامد_قدر IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP میزان_کی_جانچ_کرنا 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- صارف نفاذ_کریں_حکم·네트워크·بچانا_قدر 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 نفاذ_کریں_حکم·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## جواز_دہی_کریں 근거

`make test`는 컴파일러 14개 시험, Java 패킷 شرط 2,201개 검사, 기존 شیل ELF/ISO 부팅 시험, صارف ELF/اصل_کوائف UDP/بچانا_قدر 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 لمبا_ئی_قدر·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 حکم·무한 تکرار_قدر 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
