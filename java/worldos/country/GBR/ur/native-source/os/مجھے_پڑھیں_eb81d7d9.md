# Java 네이티브 آپریٹنگ_سسٹم

이 문서는 기존 **x86 کرنیل_قدر**을 설명한다. Raspberry Pi 4의 اپنا ARM64 초기 이식은 [별도 مجھے_پڑھیں_eb81d7d9](../platforms/rpi4-native/README.md)를 참고한다. 아래 x86 صارف ELF·네트워크·IDE ذخیرہ_کریں_قدر 기능이 ARM64에 모두 이식된 상태는 아니다.

Java 원문을 اپنا AOT 후단으로 x86 기계어로 컴파일해 부팅하는 작은 운영체제다. 커널과 별도로 اپنا 제한형 Java 컴파일러·JVM ELF를 صارف 모드에 적재할 수 있다. Linux, engos, koros4와 외부 OpenJDK는 게스트에 적재하지 않는다. 부팅 진입과 포트/물리 기억공간 접근은 어셈블리이며, 문자 단말·입력 عمل_قدر_اندراج·حکم پارس_قدر·작업 صیغہ_قدر 관리는 `ماخذ_فائل/*.java`에 있다.

## 게스트 Java 개발

`javac Hello.java`, `java Hello`로 부팅된 آپریٹنگ_سسٹم 안에서 مرتب_کریں_ماخذ·실행한다. `edit FILE.java`와 `.save`로 소스를 작성하며 `ls`, `cat`, `rm`을 제공한다. RAM 파일은 최대 8개, 각각 16KiB이다. 전용 IDE 매체를 연결하면 `sync`로 보존할 수 있다. 이 기능은 اپنا 제한형 구현이며 전체 OpenJDK/JDK 호환은 아니다. 사용법·معاونت_قدر 문법·فائل_کا_نام 적재·교차 시험은 [Java 개발 환경](../문서/자바개발환경.md)에 있다. `make test-java`로 검증한다.

## 빌드와 نفاذ_کریں_حکم

`compiler/`가 요구하는 도구에 더해 ISO 생성에는 `grub-file`, `grub-mkrescue`, GRUB BIOS ماڈیول_قدر, `xorriso`가 필요하다. 실행에는 QEMU 또는 VirtualBox가 필요하다. 현재 설치된 도구만 사용한다. `make run-store`는 새 전용 가상 ذخیرہ_کریں_قدر 매체를 만들어 연결한다. VirtualBox 실행기는 이 프로젝트가 만든 전용 VM만 설정하고 다른 VM은 변경하지 않는다. 가상 메모리는 طے_شدہ_قدر 64MiB이며 최소 16MiB가 필요하다.

```sh
cd /home/user/jkoros/os
make                 # build/kernel.elf
make iso             # build/kernel.iso (صارف ELF گروپ_قدر 포함)
make run             # ELF 직접 부팅, 직렬 단말
make run-gui         # GRUB ISO 부팅, VGA 창과 PS/2 자판
make vbox            # 상위 폴더의 실행기로 전용 VirtualBox VM نفاذ_کریں_حکم
make vbox-status     # 전용 VirtualBox VM حالت_قدر تصدیق_کریں
make test            # ELF와 ISO 두 경로의 اصل_کوائف 부팅/입력 시험
make apps            # صارف 프로그램만 بلڈ_نظام
make test-network    # صارف نفاذ_کریں_حکم/UDP/بچانا_قدر 시험
```

`make run`은 QEMU의 직렬 표준 입출력을 쓴다. `Ctrl+A`를 누른 واپس_قدر `X`로 QEMU를 종료할 수 있다. `halt`는 게스트 CPU만 정지시키므로 QEMU ونڈو/프로세스는 별도로 닫는다. 폴링 방식이라 انتظار_قدر 중에도 میزبان CPU를 사용할 수 있다.

VirtualBox는 `make vbox`로 실행한다. 새 전용 VM을 میموری_کوائف 64MiB, BIOS, 광학 드라이브 부팅으로 자동 설정하며 디스크는 필요 없다. اصل_کوائف VirtualBox 5.2.42에서 부팅, Java اپنا 시험, شیل 입력, `run hello vbox`의 ring 3 실행과 정상 종료를 확인했다. 현재 통신 드라이버는 QEMU의 RTL8139 전용이며 VirtualBox의 PCnet/E1000에서는 네트워크를 사용할 수 없어 네트워크 장치를 비활성화한다. ذخیرہ_کریں_قدر حالت_قدر 재개와 새 بلڈ_نظام 반영 방법은 [VirtualBox نفاذ_کریں_حکم مجھے_پڑھیں_eb81d7d9](../문서/가상상자실행.md)에 있다.

## 셸에서 صارف ایپ_f5044b9b نفاذ_کریں_حکم 및 네트워크 호출

독립 ELF32 نفاذ_کریں_حکم 파일을 적재해 **ring 3**에서 실행한다. `int 0x80` 시스템 호출을 통해 단말 اخراج_کا_مقام, دلائل طلب_قدر, UDP کھولیں·بھیجیں·받기·닫기를 제공한다. صارف 코드를 کرنیل_قدر 함수로 직접 호출하는 구조가 아니다.

```text
jkoros> apps
jkoros> run hello first second
jkoros> net
jkoros> run netcheck
jkoros> run udp 10.0.2.2 9000 hello
```

마지막 명령의 응답을 받으려면 호스트의 별도 터미널에서 `python3 /home/user/jkoros/os/ٹولز/자료되돌리기.py --port 9000`을 먼저 실행한다. 상세 API, ایپ_f5044b9b 추가, پتہ 공간과 제한은 [صارف نفاذ_کریں_حکم·네트워크 مجھے_پڑھیں_eb81d7d9](صارف/مجھے_پڑھیں_eb81d7d9.md)에 있다.

부팅 تصدیق_کریں 문구:

```text
JKOROS NATIVE JAVA
자바 기계어 کرنیل_قدر چلائیں
JAVA SELFTEST PASS
USER ELF: ring 3 / paging / int 0x80
help | info | mem | alloc | free N | echo TEXT | clear | test | halt
apps | run NAME [ARGS] | net
READY
jkoros>
```

## 구현한 기능

- GRUB Multiboot 1 ELF 부팅, x86 بچانا_قدر موڈ_قدر GDT, BSS ابتدا_کریں, 64KiB 스택.
- Java فعل_قدر اصل_کوائف 실행과 부팅 نظام_کی_معلومات 표식 تصدیق_کریں.
- COM1 직렬 ان_پٹ_آؤٹ_پٹ, VGA 문자 화면·کرسر_قدر·스크롤·지우기.
- PS/2 طے_شدہ_قدر 자판, 좌우 Shift, Enter, Backspace. توسیع_قدر کلید_قدر/마우스 자료는 حکم 입력으로 쓰지 않는다.
- لمبا_ئی_قدر 128의 حکم 입력 버퍼, اوور_فلو_قدر 방지, CR/LF عمل_قدر_اندراج.
- `help`, `info`, `mem`, `alloc`, `free N`, `echo TEXT`, `clear`, `test`, `halt`.
- 4KiB 작업 صیغہ_قدر 8개의 مختص_کریں_ذخیرہ·반환·재사용과 중복 반환 방지.
- Java لڑی_قدر 256KiB 영역의 حجم·زیر_تحریر_قدر 검사와 런타임 غلطی 중단.
- پڑھیں 전용 JKAP نفاذ_کریں_حکم گروپ_قدر, ELF32 صیغہ_قدر/اندراج_نقطہ جواز_دہی_کریں, صارف موڈ_قدر·دلائل·خروج_ایپ 코드.
- کرنیل_قدر/صارف 페이지 اجازت_قدر 분리, TSS, IDT, PIT 100Hz, صارف CPU استثنا عمل_قدر_اندراج 및 نفاذ_کریں_حکم وقت_قدر 상한.
- PCI RTL8139 폴링 드라이버, ARP, جامد_قدر IPv4, UDP میزان_کی_جانچ_کرنا·송수신·انتظار_قدر 제한.

`mem`의 Upper memory는 Multiboot의 1MiB 위쪽 연속 میموری_کوائف حجم(KiB)이며, 전체 میموری_کوائف 지도 분석이나 자유 물리 میموری_کوائف 수치가 아니다. `alloc`은 이미 확보한 سالم_عدد لڑی_قدر 안의 작업 صیغہ_قدر 번호를 반환한다. 일반 물리 صفحہ_قدر مختص_کریں_ذخیرہ, پتہ 공간 또는 صارف عمل_قدر میموری_کوائف 관리가 아니다.

## 명시적인 한계

이 커널은 **صارف 프로그램을 한 번에 하나 실행하는 초기 کرنیل_قدر**이다. PIT IRQ0만 사용하며 키보드와 NIC는 폴링한다. صارف CPU 예외는 해당 프로그램을 끝내고 셸로 복귀시키지만 کرنیل_قدر 예외는 중단한다. نفاذ_کریں_حکم 시간은 약 3초로 제한한다. 완전한 선점 다중 عمل_قدر 스케줄러, FAT/ext 등 일반 디스크 فائل_نظام, TCP·DNS·DHCP·IPv6·HTTP, 전체 POSIX, 일반 آبجیکٹ_قدر 모델/GC는 아직 없다. 전용 IDE فائل_کا_نام 보존과 POSIX فائل_کا_نام/UDP 일부 기능은 구현했다. JVM은 RAM 파일의 단일 클래스를 نفاذ_کریں_حکم 시 적재하며 일반 ClassLoader나 JAR 로딩은 지원하지 않는다. 네이티브 نفاذ_کریں_حکم 파일은 بلڈ_نظام 시 پڑھیں 전용 묶음에 넣으며, 일반 Linux ELF를 실행하는 환경이 아니다. 기존 `../ورثہ_ماخذ/`의 JVM 관리 کرنیل_قدر 전체를 이식한 것도 아니다.

Java 식별자는 한국어다. 직렬 출력은 이 프로젝트의 한글(BMP 문자)을 UTF-8로 표시한다. VGA는 طے_شدہ_قدر ASCII 글꼴만 사용하므로 한글 자리에 `?`가 나온다. حکم 입력도 현재 ASCII만 지원하며 한글 فانٹ_قدر·입력기 및 보조 평면 문자 출력은 후속 작업이다. `test`는 작은 배열을 새로 할당하고 GC가 없으므로 무한 반복하지 않는다.

## 자동 시험

`시험/부팅시험.py`는 디스크 없는 독립 QEMU를 생성해 다음을 검증하고 종료한다.

- ELF 직접 부팅 및 GRUB ISO 부팅.
- Java اپنا 시험과 UTF-8 직렬 문구.
- حکم مدد_دکھانا·نظام_کی_معلومات·میموری_کوائف·اخراج_کا_مقام·غلطی 입력·화면 지우기.
- 작업 صیغہ_قدر 8개 مختص_کریں_ذخیرہ, 부족 عمل_قدر_اندراج, 반환/중복 반환/재할당.
- 직렬 줄바꿈·백스페이스·긴 입력 عمل_قدر_اندراج.
- QEMU PS/2 کلید_قدر 입력으로 `info` نفاذ_کریں_حکم, `halt` 정지.

성공 로그는 `build/부팅시험.json`에 남는다. 로컬 Unix 소켓을 금지하는 샌드박스에서는 시험 도구에 해당 권한이 필요하다. 시험 도중 새로 만든 QEMU만 종료하며 기존 VM과 اصل_کوائف 디스크는 건드리지 않는다.

`시험/사용자통신시험.py`는 ELF/ISO 각각에서 صارف ELF, اصل_کوائف ring 3, دلائل, میزبان 루프백 UDP 왕복, 1,023/1,024바이트 24회 연속 왕복, وقت_قدر 초과, NIC 없음, میموری_کوائف/포트 رسائی_اندراج 차단, CPU استثنا, 무한 تکرار_قدر, 잘못된 ELF를 시험한다. `build/사용자통신시험.json`에 게스트 기록과 호스트가 받은 데이터의 لمبا_ئی_قدر·해시를 저장한다. `시험/패킷시험.py`는 اصل_کوائف Java جاب_قدر 처리기에 손상된 패킷을 넣어 2,201개 경계/میزان_کی_جانچ_کرنا 조건을 검사한다. میزبان 루프백 외 외부 서버에는 시험 트래픽을 보내지 않는다.

부트 경계는 GNU의 [Multiboot 명세](https://www.gnu.org/software/grub/manual/multiboot/multiboot.html)를 따른다.

새 파일서술자·C ABI·IDE ذخیرہ_کریں_قدر·Java فائل_کا_نام 흐름의 범위와 اردو 명명 대응은 [posix-kor مجھے_پڑھیں_eb81d7d9](../posix-kor/مجھے_پڑھیں_eb81d7d9.md)에 있다. `make test-posix`로 ELF/ISO 실행과 재부팅 보존을 검증한다.
