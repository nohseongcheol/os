# потребител 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `машина/операционна_система_Обаждания.s`에서 EAX(индекс), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 Параметри)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. ядро_стойност 실패는 음수 ГРЕШКА индекс, C библиотека 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 потребител област_стойност_0e9a97ab 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C данни 주소는 байт_стойност 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java Файл 흐름의 어셈블리 경계가 별도 байт_стойност 버퍼를 마련하여 같은 호출을 사용한다.

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 адрес 두 칸이다. получавам_стойност_cef4d8ab 주소가 NULL이면 крайно_устройство_стойност адрес 기록을 생략한다. sockaddr_in은 16바이트이며 адрес 체계는 устройство_стойност байт_стойност 차례, 접속번호와 IP 주소는 네트워크 байт_стойност 차례다. 축소된 адрес 버퍼에도 들어가는 앞부분을 쓰고 전체 адрес Размер 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 Изход_програма, 2·3은 기존 Параметри 조회다. в_срок_артикул 커널의 Параметри 목록이 изпълнявам_команда 이름을 제외하므로 C 진입기는 argv[0]에 고정 низ_стойност `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX Процес_стойност ABI와 다른 점이다.

표준 헤더의 цяло_число Размер, 플래그 стойност, stat стойност_на_поле 순서는 `ИЗТОЧНИК/포함/`에 정의한다. 동적 Свързване·다중 Процес_стойност·스레드가 추가되면 ГРЕШКА индекс 저장과 ресурс_стойност 수명, 호출 경계도 함께 검토해야 한다.
