# 셸에서 실행하는 使用者 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 開發 環境 指南](../../文檔集/Java開發環境.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 執行命令

宿主 終端 1:

```sh
cd /home/user/jkoros
python3 os/工具集/資料復原.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 外部值 연결을 받도록 방화벽이나 硬件埠 전달을 변경하지 않는다. Ctrl+C로 종료한다.

宿主 終端 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 輸入值:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 實際資料 CPU 權限值 `ring 3`, 實參 輸出.
- `netcheck`: 埠值 중복, 잘못된 句柄值/指針/長度, 비차단 받기와 時間值 초과 驗證.
- `udp`: IPv4 地址·目的地址值 埠值·한 機器字值 메시지를 받아 UDP로 보내고 같은 응답을 驗證. `UDP ECHO PASS`, `Exit: 0`이면 成功值.
- `stress`: 宿主 `10.0.2.2`의 賦值值 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 接收值 循環值 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 當前項目 주소는 게스트 `10.0.2.15/24`, 網關值 `10.0.2.2`로 고정돼 있다. QEMU 使用者 네트워크의 宿主 存取條目 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 程式 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java 程式 追加條目

`範例/내프로그램.java`를 下一項目 형식으로 만든다. 진입점은 實參 없는 `static int` 또는 `static void` 함수다. 인수는 使用者 API로 조회한다.

```java
public final class 내프로그램 {
    public static int 運行() {
        使用者.寫入("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/使用者/程式.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := 使用者/範例/내프로그램.java
APP_ENTRY_mine := 내프로그램.運行
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 構建全部 나열한다. `使用者/聲明/使用者.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 執行命令 중인 VM에는 構建系統 결과가 자동 반영되지 않는다. 程式 이름은 當前項目 셸의 ASCII 輸入值 제한에 맞춘 1~15자의 소문자 이름이며 Java 類別值·函數·변수에는 한국어를 쓴다. 最大值 32개 程式, 한 執行命令 파일은 最大值 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/編譯器.py --target user --entry 問候例.運行 \
    -o os/build/apps/hello.elf os/使用者/聲明/使用者.java os/使用者/範例/問候例.java
```

`--target user`는 **jkoros 전용 ABI**第三操作數. Linux 대상과 시스템 調用 번호가 다르므로 宿主 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 支持值 裁剪 안에서 실행한다. `.jar`와 일반 Linux 執行命令 파일은 지원하지 않는다.

## 使用者 네트워크 API

선언은 `聲明/使用者.java`에 있다. `發送資料`/`接收資料`의 `int[]` 項目元素 한 개는 位元組值 一值(0~255)를 나타낸다. 한 데이터그램의 最大值 資料 길이는 1,024바이트다.

```java
int 句柄值 = 使用者.打開網路(0); // 0: 臨時值 局部作用域 UDP 埠值 자동 選中狀態值
int[] 資料 = new int[32];
資料[0] = 'H'; 資料[1] = 'i';
int 보낸길이 = 使用者.發送資料(句柄值, 0x0a000202, 9000, 資料, 2);
int 已接收長度 = 使用者.接收資料(句柄值, 資料, 1500);
使用者.關閉網路(句柄值);
```

實際資料 프로그램에서는 打開·發送·받기의 負數值 반환값을 각각 검사한다. 완성된 예제는 `範例/資料通信.java`에 있다. `接收資料`의 等待狀態值 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 接收值 대기열은 한 개뿐이므로 追加條目 도착분은 버린다. `已發送地址`와 `已發送埠`로 마지막으로 받은 상대를 조회한다.

| 已返回值 | 의미 |
| --- | --- |
| 0 이상 | 句柄值·程序值條目 長度·成功值 등 해당 함수의 結果 |
| -5 | 設備 發送值 失敗值 |
| -9 | 잘못되었거나 닫힌 通信 句柄值 |
| -11 | 비차단 받기에서 도착한 資料 缺失方法 |
| -14 | 使用者 指針/陣列值 裁剪 錯誤 |
| -19 | 支持值 NIC 缺失方法 |
| -22 | 埠值/等待狀態值 時間值/實參 值 錯誤 |
| -24 | 열린 網路埠 4개 容量限制 |
| -38 | 알 數 없는 시스템 調用 |
| -90 | 資料 또는 接收值 陣列值 大小 문제 |
| -98 | 局部作用域 埠值 編號 중복 |
| -101 | 지원하지 않는 目的地址值 地址 |
| -110 | ARP·設備·接收值 時間值 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 編碼狀態值 있는 Java `int`의 位元值 패턴을 사용하므로 상위 비트가 1인 是否常規 IP 주소가 음수로 보일 數 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## 執行命令 경계와 시스템 調用

```text
命令殼 run → JKAP에서 ELF 有效性校驗·적재 → ring 3 使用者 程式
                                 ↓ int 0x80
                      指針 檢查項 → Java 內核值 API → RTL8139/UDP
                                 ↓ 退出程式·異常·時間值 초과
                                命令殼 복귀
```

시스템 調用 레지스터는 `EAX=編號`, `EBX,ECX,EDX,ESI,EDI=實參`, `EAX=結果`第三操作數. Java 調用 操作數棧 ABI는 컴파일러가 使用者 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| 編號 | 調用 |
| --- | --- |
| 0 | 退出程式(狀態值 程式碼值) — 運行/錯誤 런타임에서 使用值 |
| 1 | 字符串 寫入 |
| 2 / 3 | 實參 項目個數 / 實參 字符串 地址 |
| 10 | UDP 打開 |
| 11 | UDP 發送(句柄值, IP, 目的地址值 埠值, 陣列值 地址, 長度) |
| 12 | UDP 接收(句柄值, 陣列值 地址, 限制值 毫秒) |
| 13 | UDP 關閉 |
| 14 | 局部作用域 IP 地址 |
| 15 / 16 | 最後項目 對端值 IP / UDP 埠值 |
| 20 | RAM 檔案 讀取(名稱 int[] 地址, 輸出 int[] 地址) |
| 21 | RAM 檔案 寫入(名稱 int[] 地址, 輸入值 int[] 地址, 位元組值 長度) |
| 22 | UTF-16 程式碼值 單位值 字元 輸出(0~65535) |

檔案 API는 `使用者.讀取檔案(int[] 名稱, int[] 資料)`와 `使用者.寫入檔案(int[] 名稱, int[] 資料, int 長度)`第三操作數. 이름은 ASCII 程式碼值 陣列值(最大值 64칸, 0 退出程式 또는 陣列值 結尾), 資料 項目元素 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 檔案 缺失方法 `-2`, 指針 錯誤 `-14`, 名稱/長度 錯誤 `-22`, 檔案 槽值 부족 `-28`, 大小 초과 `-90`을 반환한다. 쓰기는 有效性校驗 之後狀態 檔案 전체를 대체한다. `使用者.寫入字元值(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`執行狀態權限()`은 시스템 호출이 아니라 使用者 모드에서 CS의 하위 비트를 직접 읽으므로 實際資料 執行命令 권한을 확인한다. 內核值 硬件埠 접근용 `設備` native 함수는 使用者 目標值 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 限制值

- 한 번에 한 프로그램만 실행하며 是否完成 之後狀態 셸로 돌아온다. 백그라운드 執行命令, 파이프, 프로세스 간 통신은 없다. 執行命令 파일은 커널의 讀取 전용 JKAP 묶음에서 적재한다. 資料 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- 使用者 가상 地址 `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. 執行命令 영상은 前端值 2MiB, 인수는 `0x04300000`부터, 스택은 區域值 끝에서 시작한다. 內核值 identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB 使用者 영역을 비우고 檔案 구역을 복사해 BSS·陣列值 영역을 초기화한다. 使用者 GC는 없지만 退出程式 之後狀態 下一項目 執行命令 때 영역을 재사용한다. 인수는 공백으로 분리한 最大值 16개이며 引號/이스케이프 파싱은 없다.
- 使用者 페이지의 程式碼值/資料 분리 讀取 전용 設置, NX, 操作數棧 guard, ASLR은 아직 없다. 커널과 使用者 記憶體資料·硬件埠 權限值 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 執行命令 상한을 두며 時間值 초과는 `Exit: 124`第三操作數. 使用者 CPU 예외는 `128 + 異常 編號`(페이지 錯誤 142, 특권 위반 141), Java 陣列值/計算結果 오류는 101~105다. 內核值 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, 靜態值 IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP 校驗和 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- 使用者 執行命令·네트워크·保護值 邊界位置值 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 執行命令·是否常規 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## 有效性校驗 근거

`make test`는 編譯器 14개 測試, Java 패킷 條件 2,201개 檢查項, 기존 命令殼 ELF/ISO 啓動 測試, 使用者 ELF/實際資料 UDP/保護值 邊界位置值 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 長度·해시까지 `os/build/測試用戶網路.json`에 기록한다. 시험용 손상된 ELF·특권 命令·무한 迭代值 프로그램은 臨時值 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
