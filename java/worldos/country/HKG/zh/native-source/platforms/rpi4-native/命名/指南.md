# 内置 커널과 번역기의 中文 名称

대상은 `platforms/rpi4-native`의 内置 Java 内核值, 用户 JVM, C 计算机 连接,
TCP/UDP·FTP, C 编译器工具 이식부, MicroPython 이식부, 构建系统·执行命令·测试 도구다.
`golang/worldos/国家值/KOR/源代码`의 원칙처럼 기능을 먼저 구분하고 이름을 정한다.
x86 Java 커널과 공용 x86·ARM64 미리 번역기의 内置 선언도 命名 검사에 포함한다.
Linux 실행판의 宿主 工具集, OpenJDK 辅助值 工具集 및 外部值 分发值 源代码树 전체를
한국어로 重试值 작성했다는 뜻은 아니다.

## 命名 원칙과 말의 근거

- 명사는 자료의 역할을 나타낸다: `文件句柄`, `对端端口编号`, `堆存储装置`, `键盘`.
- 함수는 행위를 나타낸다: `读取`, `写入`, `打开`, `关闭`, `网络层绑定`, `运行程序`.
- TCP의 이어진 字节值 흐름과 UDP의 边界位置值 있는 자료를 `连接通道`와 `数据报信道`로 구별한다.
- 짧은 영어 변수도 쓰임에 따라 `长度`, `数据位置`, `查找索引`, `已返回值`으로 풀어 쓴다.
  序数索引·临时值 산술값처럼 여러 역할에 재사용되는 변수는 `序数索引`, `首位值`, `第二值`으로 구별한다.
- 이름이 같아도 外部值 구조체의 필드와 内置 변수는 별도로 분석한다.

`信道条目(通路)`는 이동이나 교류가 이루어지는 길이라는 기존 의미를 通信 연결에
적용했다. `端口值(窓口)`의 주고받는 접점이라는 의미를 연결을 받는 곳에 적용했다.
이는 국립국어원 한국어기초사전의 [信道条目](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=49310),
[端口值](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=24898)의 뜻에 근거한다.

`数据报(電文)`은 전보에 담는 글이라는 기존 通信 어휘에서 가져와, UDP 자료의
경계가 보존된다는 특징을 드러내는 데 쓴다. 근거는
[한국어기초사전 数据报](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=74335)이다.
`流值`, `线程值`, `쌓임`은 우리말의 움직임·是否继续状态·쌓이는 모양을 빌린 표현이다.
`输入流`, `后台任务`, `栈存储装置` 같은 복합 이름은 이 프로젝트의 기능별 조어다.
이 字典 근거를 특정 중세 문헌의 최초 출현이나 공인 전산 번역으로 확대하지 않는다.
공인 표준 翻译源代码·국어사 数据报 감수를 마쳤다는 뜻도 아니다.

| 기능 | 채택한 名称 | 理由值 |
|---|---|---|
| TCP Socket | 连接通道 | 상대와 연결되어 排序值 있는 바이트를 주고받음 |
| ServerSocket | 接收端口 | 새 연결이 들어오는 접점 |
| DatagramSocket | 数据报信道 | 각 자료의 경계를 보존하는 通信 |
| InputStream / OutputStream | 输入流 / 输出流 | 들어오고 나가는 바이트의 排序值 |
| heap / stack | 堆存储装置 / 栈存储装置 | 分配存储装置 방식과 쌓고 꺼내는 结构 |
| thread / keyboard | 后台任务 / 键盘 | 이어지는 실행과 글쇠의 数组值 |
| exception / timeout | 异常 / 等待状态超时异常 | 是否常规 처리에서 벗어남과 그 구체적 理由值 |

## 보존하는 标准定义 名称

`public`, `class`, `int`는 예약어다. `String`, `main`, 배열의 `length`는 예약어가 아니다.
当前项目 다섯 Java 예제는 `运行()`·`运行参数`·中文 屏幕/线程值 API를 사용해
已保留位单词列·리터럴 외의 식별자를 한국어로 작성한다. 屏幕/가닥은 표준 객체를
감싸지 않고 内置 JVM에 직접 구현했다. 자세한 계약은 [中文 Java API](../中文Java/指南.md)를 본다.

표준 javac는 字符串 리터럴에 `java.lang.String`, 字符串 결합에 `StringBuilder`
같은 이름을 생성한다. 이들은 中文 소스에서도 바이트코드에 남을 数 있다.
기존 표준 class를 실행하는 JVM의 映射值 字符串, 아직 표준 라이브러리를 쓰는
通信·文件 연결부까지 构建全部 한국어로 재구현한 것은 아니다. 이름만 일괄 치환하면
描述符条目·재정의·native 연결이 달라져 호환성이 깨진다.

C 표준 函数·整数类型·POSIX ABI, CPU 寄存器值 名称, 어셈블리 命令, 링커 절 名称,
TinyCC·lwIP·MicroPython이 요구하는 设置 매크로와 헤더 이름도 보존한다.
예: `main`, `memcpy`, `pk_bind`, `mpconfigport.h`, `lwipopts.h`, `stdint.h`.
内置 C 함수의 源代码树 이름은 한국어이며, [计算机连接名称列.h](计算机连接名称列.h)首位操作数
기존 AOT·어셈블리·SDK에 공개한 计算机 심볼과 연결한다.
Python의 `__init__`, `setUp`, `handle`, 표준 模块值 属性值, 명령행 옵션과 JSON 키도
外部值 계약이다. `build/`, 分发值 바이너리 이름과 `/sdk`는 기존 执行命令 경로를 유지한다.
外部值 원본은 `vendor/`에서 이용허락·해시와 함께 관리한다.

## C 通信 구조체와 Python 错误

C 통신에서 `갈래`는 地址 체계를 구분하고 `端口编号`는 port, `地址值`은
IPv4 주소의 32비트 값을 나타낸다. `数据报协议`은 앞서 설명한 数据报(電文)과
契约值(規約)을 결합해 UDP의 기능을 드러낸 프로젝트 이름이다.

| 표준 표현 | 中文 직접 实现 |
|---|---|
| AF_INET / SOCK_DGRAM / IPPROTO_UDP | enum의 互联网族 / 数据报套接字 / 数据报协议 |
| struct pk_sockaddr_in | struct 互联网套接字地址 |
| sin_family / sin_port | 地址族 / 端口编号 |
| sin_addr.s_addr | 互联网地址.地址值 |
| OSError / 错误.args[0] | 系统错误 / 错误.编号 |

中文 구조체는 `#define` 치환이나 字段值 별칭이 아닌 별개 자료형이다.
표준 구조체와 같은 16바이트 배치를 선언하며 内核值 SVC에서 字节值 복사로
검사한다. `创建端点`·`发送数据报数据`와 文件 함수는 静态值 라이브러리에
实际数据 中文 이름의 函数 심볼을 갖는다. 기존 pk_* 심볼도 유지한다.
上一个项目 코드에서 中文 通信 함수에 pk_sockaddr*를 전달했다면 中文 구조체로
옮기거나, 표준 구조체와 pk_* 함수의 짝을 유지한다.

Python의 `系统错误`는 OSError의 中文 하위 클래스이며 연결부에서
错误 번호를 보존하여 변환한다. 일반 Python 문법과 外部值 패키지의 API는 유지한다.

## 직접 GUI 이름의 뜻과 검토 裁剪

`可运行任务任务`은 수행할 내용을, `执行任务`는 그 수행을 나타낸다.
`动作接收者`는 동작이 발생했다는 알림을 받는 역할, `动作通知`은 전달되는 사건이다.
`按钮`는 눌러 동작시키는 조작부, `标签`는 指南 글의 位置索引,
`文本字段`은 글을 적는 位置索引, `后台任务`은 이어지는 执行命令 흐름을 뜻한다.
`执行命令(實行)`·`动作(動作)`의 기존 뜻과 `받다`·`알리다`·`线程值`의 기능을
결합한 프로젝트 이름이다. 새 복합어가 역사 문헌에 그대로 있었다거나
특정 시대에 初始项目 쓰였다고 주장하지 않는다.

전체 저장소는 `python3 工具集/源代码审阅.py`로 검토한다.
결과는 `build/verification/naming/source-review.json`이며 파일별 哈希文件,
ASCII 파일명과 Python의 영어 声明 위치를 기록한다.
공용 ARM64·x86 번역기의 구현은 `compiler/Java工具/提前所属时间编译器.java`로 전환했다. `compiler/提前所属时间编译器.py`는 호환 진입점이다.
`compiler/arm64.py`는 上一个项目 경로와 `ARM64(...).generate(...)` 호출을 继续状态值 주는
호환 진입점이다. `compiler/classfile.py`, OpenJDK 辅助值 工具集, Linux 版本值 도구와
기존 호환 진입점에는 영어 이름이 남아 있다. 따라서 전체 저장소가
已保留位单词列 외 100% 한국어라고 판정하지 않는다.
`工具集/检查命名.py --C语言`는 活跃 ARM64 소스의 声明, C 의미 分析值,
x86 Java 커널과 공용 번역기의 内置 声明, Java 用例 전체 标识符值,
ARM64 Python 예제와 직접 GUI/가닥에 표준 래퍼가 없는지를 별도로 검사한다.

## 当前项目 기능을 기준으로 보완한 名称

번역은 글자를 음역하는 대신 자료의 역할과 함수의 행동을 구분한다.
동일한 영어 이름도 문맥이 다르면 中文 이름을 달리 정한다.
文件 이름은 주된 기능을 나타내고, 函数 이름은 행동을, 变量值 이름은 담는 자료를 나타낸다.
已保留位单词列, 표준 API 및 外部值 连接 규약은 따로 기록한다.

| 上一个项目 名称 | 적용한 名称 | 当前项目 기능 |
|---|---|---|
| `arm64.py`의 实现 | `compiler/Java工具/提前所属时间编译器.java` | Java 바이트코드를 독립 실행용 C 원문으로 미리 翻译源代码 |
| `ARM64`, `generate` | `计算机代码编译器`, `生成` | 翻译源代码 상태를 담는 객체와 C 源代码 生成 行为值 |
| `prototype`, `method` | `方法原型`, `方法主体` | 함수의 格式值 선언과 实际数据 命令 源代码 |
| `profile`, `heap_words` | `执行状态目标`, `堆机器字个数` | 内核值·用户 구분과 分配存储装置 内存 공간의 计算机 词法用机器字 数 |
| `pc`, `op` | `命令位置`, `명령번호` | 바이트코드에서의 위치와 수행할 명령의 编号 |
| `x`, `y`, `w`, `h` | `横坐标坐标`, `Y_按钮坐标`, `区域宽度`, `区域高度` | 远程值 화면의 위치와 직사각형 大小 |
| `p`, `n`, `i`, `j` | `数据位置`, `值`, `序数索引`, `内部侧序数` | 远程值 屏幕 数据·数字值·迭代值 位置索引; 파일별 기능을 확인해 적용 |
| `aot_heap_info`, `__stack_top` | `提前编译内存查找`, `栈顶端` | 计算机 连接 규약을 유지하면서 内置 소스에서 사용하는 名称 |
| `앞캐리지` | `发回目标侧上一个行` | 앞서 받은 문자가 줄복귀였는지 기억하여 중복 줄바꿈을 막음 |

[共享编译器名称列.tsv](共享编译器名称列.tsv)에 编译器工具 참조의 实际数据 更改值 기록을 남겼다.
추가로 보존한 C·POSIX/lwIP/libassh 이름의 이유는
[标准名称证据.json](标准名称证据.json)에 기록한다.
`C编译器/编译器工具.c`는 TinyCC 外部值 원문을 포함하는 连接 파일로 内置 선언이 없어서
C 内置 声明 분석에서는 제외한다. 实际数据 内核值 빌드에서는 继续处理 컴파일한다.

### 말의 뿌리와 새로운 복합 名称

`内存(記憶)`과 `查找索引(索引)`은 기존 한자어를 쓴다.
기억은 자료를 간직하는 기능에, 색인은 排序值 있는 항목을 찾아 지정하는 기능에 적용한다.
字典 근거는 국립국어원 한국어기초사전의
[内存](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=38812&nation=eng),
[查找索引](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=63787)이다.

`栈存储装置`, `压栈值`, `弹栈值`는 자료를 포개고 最后项目 자료부터 꺼내는 执行命令 구조를 드러낸다.
`쌓다`의 기존 뜻에 근거한 기능별 조어이며, 사전의
[쌓다](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=62095)를 참고한다.
`提前所属时间`은 执行命令 전에 번역한다는 기능을 직접 나타낸다.
`计算机机器字`은 처리기의 数据 단위를 가리키며, 언어의 일반 낱말과 구별하도록 `计算机`를 붙였다.
`提前所属时间编译器`, `堆机器字个数` 같은 복합 이름은 当前项目 기능에 맞게 만든 프로젝트 용어다.
이 복합어가 옛 문헌에 그대로 있었다거나 특정 시대에 初始项目 나타났다는 뜻은 아니다.
확인되지 않은 중세 형태나 최초 使用值 연대는 어원 근거로 적지 않는다.

생성되는 C의 내부 数据类型·数组值·函数·局部作用域 变量值·分支 이름도 한국어로 바꾼다.
직접 韩文文本 식별자를 읽지 못하는 예전 GCC를 위해 호환 API는 같은 中文 이름을
표준 C 범용 字符 표기로 출력한다. 实际数据 ARM64 빌드는 Clang으로 읽을 数 있는 韩文文本 원문을 사용한다.
字符串, C 표준 函数, `java_entry` 같은 공개 连接 이름은 바꾸지 않는다.

셸의 사용법·문법 错误·文件 및 内存 地址区域 안내도 한국어로 보완했다.
`READY`, `PASS`, `HEX BEGIN`처럼 测试·文件 传送值 도구가 읽는 标记值,
명령행 옵션과 기존 指令值, JVM 类值 名称·文件 格式值·设备 이름은 호환 표기로 남는다.
x86 VGA 字符 화면은 한글을 표시하지 못하므로 中文 문구는 UTF-8 串行值 단말에서 확인한다.
