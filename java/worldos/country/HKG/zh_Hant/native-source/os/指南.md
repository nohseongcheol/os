# Java 네이티브 操作系統

이 문서는 기존 **x86 內核值**을 설명한다. Raspberry Pi 4의 內建 ARM64 初始狀態 이식은 [별도 指南](../platforms/rpi4-native/README.md)를 참고한다. 底端值 x86 使用者 ELF·네트워크·IDE 存儲值 기능이 ARM64에 構建全部 이식된 상태는 아니다.

Java 원문을 內建 AOT 후단으로 x86 기계어로 컴파일해 부팅하는 작은 운영체제다. 커널과 별도로 內建 제한형 Java 編譯器·JVM ELF를 使用者 모드에 적재할 數 있다. Linux, engos, koros4와 外部值 OpenJDK는 게스트에 적재하지 않는다. 啓動 진입과 硬件埠/물리 記憶體空間 접근은 어셈블리이며, 字元 終端輸入輸出·輸入值 程序值條目·命令 解析值·任務 區段值 관리는 `原始碼/*.java`에 있다.

## 게스트 Java 開發

`javac Hello.java`, `java Hello`로 부팅된 操作系統 안에서 編譯原始碼·실행한다. `edit FILE.java`와 `.save`로 소스를 작성하며 `ls`, `cat`, `rm`을 제공한다. RAM 파일은 最大值 8개, 각각 16KiB이다. 전용 IDE 매체를 연결하면 `sync`로 보존할 數 있다. 이 기능은 內建 제한형 구현이며 전체 OpenJDK/JDK 호환은 아니다. 사용법·支持值 문법·檔案 적재·교차 시험은 [Java 開發 環境](../文檔集/Java開發環境.md)에 있다. `make test-java`로 검증한다.

## 빌드와 執行命令

`compiler/`首位操作數 요구하는 도구에 더해 ISO 생성에는 `grub-file`, `grub-mkrescue`, GRUB BIOS 模塊值, `xorriso`首位操作數 필요하다. 실행에는 QEMU 또는 VirtualBox가 필요하다. 當前項目 설치된 도구만 사용한다. `make run-store`는 새 전용 가상 存儲值 매체를 만들어 연결한다. VirtualBox 실행기는 이 프로젝트가 만든 전용 VM만 설정하고 다른 VM은 변경하지 않는다. 가상 메모리는 默認值 64MiB이며 最小值 16MiB가 필요하다.

```sh
cd /home/user/jkoros/os
make                 # build/kernel.elf
make iso             # build/kernel.iso (使用者 ELF 組值 頭文件)
make run             # ELF 직접 啓動, 串行值 終端輸入輸出
make run-gui         # GRUB ISO 啓動, VGA 창과 PS/2 자판
make vbox            # 상위 폴더의 실행기로 전용 VirtualBox VM 執行命令
make vbox-status     # 전용 VirtualBox VM 狀態值 驗證
make test            # ELF와 ISO 두 경로의 實際資料 啓動/輸入值 測試
make apps            # 使用者 프로그램만 構建系統
make test-network    # 使用者 執行命令/UDP/保護值 測試
```

`make run`은 QEMU의 串行值 표준 입출력을 쓴다. `Ctrl+A`를 누른 後端值 `X`로 QEMU를 종료할 數 있다. `halt`는 게스트 CPU만 정지시키므로 QEMU 窗口/프로세스는 별도로 닫는다. 폴링 방식이라 等待狀態值 중에도 宿主 CPU를 사용할 數 있다.

VirtualBox는 `make vbox`로 실행한다. 새 전용 VM을 記憶體資料 64MiB, BIOS, 광학 드라이브 부팅으로 자동 설정하며 디스크는 所需條件值 없다. 實際資料 VirtualBox 5.2.42에서 啓動, Java 內建 測試, 命令殼 輸入值, `run hello vbox`의 ring 3 실행과 是否常規 종료를 확인했다. 當前項目 通信 드라이버는 QEMU의 RTL8139 전용이며 VirtualBox의 PCnet/E1000에서는 네트워크를 사용할 數 없어 네트워크 장치를 비활성화한다. 存儲值 狀態值 재개와 새 構建系統 반영 방법은 [VirtualBox 執行命令 指南](../文檔集/VirtualBox運行.md)에 있다.

## 셸에서 使用者 程式 執行命令 및 네트워크 調用

독립 ELF32 執行命令 파일을 적재해 **ring 3**에서 실행한다. `int 0x80` 시스템 호출을 통해 終端輸入輸出 輸出, 實參 查詢值, UDP 打開·發送·接收·닫기를 제공한다. 使用者 코드를 內核值 함수로 직접 호출하는 구조가 아니다.

```text
jkoros> apps
jkoros> run hello first second
jkoros> net
jkoros> run netcheck
jkoros> run udp 10.0.2.2 9000 hello
```

最後項目 명령의 응답을 받으려면 호스트의 별도 터미널에서 `python3 /home/user/jkoros/os/工具集/資料復原.py --port 9000`을 먼저 실행한다. 상세 API, 程式 追加條目, 地址 공간과 제한은 [使用者 執行命令·네트워크 指南](使用者/指南.md)에 있다.

啓動 驗證 短語值:

```text
JKOROS NATIVE JAVA
Java 기계어 內核值 運行
JAVA SELFTEST PASS
USER ELF: ring 3 / paging / int 0x80
help | info | mem | alloc | free N | echo TEXT | clear | test | halt
apps | run NAME [ARGS] | net
READY
jkoros>
```

## 구현한 기능

- GRUB Multiboot 1 ELF 啓動, x86 保護值 模式值 GDT, BSS 初始化, 64KiB 操作數棧.
- Java 函數 實際資料 실행과 啓動 系統信息 標記值 驗證.
- COM1 串行值 輸入輸出, VGA 字元 屏幕·光標值·스크롤·擦除條目.
- PS/2 默認值 자판, 좌우 Shift, Enter, Backspace. 擴展名值 鍵值/마우스 자료는 命令 입력으로 쓰지 않는다.
- 長度 128의 命令 輸入值 버퍼, 溢出值 방지, CR/LF 程序值條目.
- `help`, `info`, `mem`, `alloc`, `free N`, `echo TEXT`, `clear`, `test`, `halt`.
- 4KiB 任務 區段值 8개의 分配存儲裝置·發回結果·재사용과 중복 發回結果 방지.
- Java 陣列值 256KiB 영역의 大小·下標值 검사와 런타임 錯誤 중단.
- 讀取 전용 JKAP 執行命令 組值, ELF32 區段值/條目分 有效性校驗, 使用者 模式值·實參·退出程式 程式碼值.
- 內核值/使用者 페이지 權限值 분리, TSS, IDT, PIT 100Hz, 使用者 CPU 異常 程序值條目 및 執行命令 時間值 상한.
- PCI RTL8139 폴링 드라이버, ARP, 靜態值 IPv4, UDP 校驗和·송수신·等待狀態值 限制值.

`mem`의 Upper memory는 Multiboot의 1MiB 上位側側 稠密切換分支項集 記憶體資料 大小(KiB)이며, 전체 記憶體資料 지도 분석이나 자유 물리 記憶體資料 수치가 아니다. `alloc`은 이미 확보한 整數 陣列值 안의 任務 區段值 번호를 반환한다. 일반 물리 頁值 分配存儲裝置, 地址 地址區域 또는 使用者 程序值 記憶體資料 관리가 아니다.

## 명시적인 邊界位置限制

이 커널은 **使用者 프로그램을 한 번에 一值 실행하는 初始狀態 內核值**이다. PIT IRQ0만 사용하며 키보드와 NIC는 폴링한다. 使用者 CPU 예외는 해당 프로그램을 끝내고 셸로 복귀시키지만 內核值 예외는 중단한다. 執行命令 시간은 약 3초로 제한한다. 완전한 선점 다중 程序值 스케줄러, FAT/ext 등 일반 디스크 檔案系統, TCP·DNS·DHCP·IPv6·HTTP, 전체 POSIX, 일반 物件值 모델/GC는 아직 없다. 전용 IDE 檔案 보존과 POSIX 檔案/UDP 일부 기능은 구현했다. JVM은 RAM 파일의 단일 클래스를 執行命令 시 적재하며 일반 ClassLoader나 JAR 로딩은 지원하지 않는다. 네이티브 執行命令 파일은 構建系統 시 讀取 전용 묶음에 넣으며, 일반 Linux ELF를 실행하는 환경이 아니다. 기존 `../基礎原始碼/`의 JVM 관리 內核值 전체를 이식한 것도 아니다.

Java 식별자는 한국어다. 串行值 출력은 이 프로젝트의 韓文文本(BMP 字元)을 UTF-8로 표시한다. VGA는 默認值 ASCII 글꼴만 사용하므로 韓文文本 자리에 `?`首位操作數 나온다. 命令 입력도 當前項目 ASCII만 지원하며 韓文文本 字體值·입력기 및 輔助值 평면 字元 출력은 후속 작업이다. `test`는 작은 배열을 새로 할당하고 GC가 없으므로 무한 반복하지 않는다.

## 자동 測試

`測試/啓動測試.py`는 디스크 없는 독립 QEMU를 생성해 다음을 검증하고 종료한다.

- ELF 직접 啓動 및 GRUB ISO 啓動.
- Java 內建 시험과 UTF-8 串行值 短語值.
- 命令 顯示幫助·系統信息·記憶體資料·輸出·錯誤 輸入值·屏幕 擦除條目.
- 任務 區段值 8개 分配存儲裝置, 부족 程序值條目, 發回結果/중복 發回結果/재할당.
- 串行值 換行·백스페이스·긴 輸入值 程序值條目.
- QEMU PS/2 鍵值 입력으로 `info` 執行命令, `halt` 停機執行狀態.

成功值 로그는 `build/啓動測試.json`에 남는다. 로컬 Unix 소켓을 금지하는 샌드박스에서는 測試 도구에 해당 권한이 필요하다. 測試 도중 새로 만든 QEMU만 종료하며 기존 VM과 實際資料 디스크는 건드리지 않는다.

`測試/測試用戶網路.py`는 ELF/ISO 각각에서 使用者 ELF, 實際資料 ring 3, 實參, 宿主 루프백 UDP 왕복, 1,023/1,024바이트 24회 稠密切換分支項集 왕복, 時間值 초과, NIC 缺失方法, 記憶體資料/硬件埠 存取條目 차단, CPU 異常, 무한 迭代值, 잘못된 ELF를 시험한다. `build/測試用戶網路.json`에 게스트 기록과 호스트가 받은 데이터의 長度·해시를 저장한다. `測試/數據包測試.py`는 實際資料 Java 契約值 처리기에 손상된 패킷을 넣어 2,201개 邊界位置值/校驗和 조건을 검사한다. 宿主 루프백 외 外部值 서버에는 測試 트래픽을 보내지 않는다.

부트 경계는 GNU의 [Multiboot 規格](https://www.gnu.org/software/grub/manual/multiboot/multiboot.html)를 따른다.

새 檔案描述符·C ABI·IDE 存儲值·Java 檔案 흐름의 범위와 中文 命名 대응은 [posix-kor 指南](../posix-kor/指南.md)에 있다. `make test-posix`로 ELF/ISO 실행과 재부팅 보존을 검증한다.
