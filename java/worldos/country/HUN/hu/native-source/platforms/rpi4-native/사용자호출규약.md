# saját ARM64 felhasználó végrehajt_parancs ABI v1

이 ABI는 `platforms/rpi4-native`의 제한된 freestanding végrehajt_parancs 환경이다. Linux AArch64 ABI나 POSIX 전체 구현이 아니다. **OpenJDK/JRE, CPython, libc, libstdc++는 아직 이식되지 않았다.**

ELF 로더는 Fájl 확장자 대신 tényleges_adat ELF 헤더를 검사한다. 아래 saját ABI와 별도로 `run --linux FILE`에 제한된 Linux ARM64 statikus_ÉRTÉK végrehajt_parancs Fájl 경로를 추가했다. 두 시스템 호출 번호표를 혼합하지 않는다. [ELF·Linux ABI 매뉴얼](실행파일규약.md).

## ELF와 végrehajt_parancs 수명

- ELF64 little endian, ET_EXEC, EM_AARCH64, 버전 1, e_flags=0.
- app_f5044b9b 헤더 최대 16개. PT_LOAD는 Olvasás 가능, 4 KiB igazít_ÉRTÉK, 페이지 간 beágyazás_ÉRTÉK 없음, filesz≤memsz, épít_KÉP CÍM klip 안이어야 한다. W+X는 거부한다.
- 진입점은 Fájl 내용이 있는 végrehajt_parancs 세그먼트 안의 4바이트 igazít_ÉRTÉK 주소다.
- PT_NOTE에 Név `JKOROS\0`(namesz=7), type=1, descsz=4, 버전 1의 little endian uint32가 필요하다. SDK의 `start.o`가 넣는다.
- PT_DYNAMIC/PT_INTERP/PT_TLS 등은 거부한다. 동적 재배치·공유 kódtár·TLS 로더가 없다.
- 커널에 포함한 ELF 묶음을 검증하고 별도 felhasználó 메모리에 복사한 BACK_ÉRTÉK EL0로 진입한다. 커널에 함수로 statikus_ÉRTÉK 링크해 호출하는 Előző_cikk `cpp_test`와 다르다.

## UDP 루프백의 계약

바깥 IPv4는 lwIP/SLIP로 확장했다. 기존 fd/구조체/mutató 검사 규약을 유지하며 0.0.0.0 또는 10.0.2.15에 bind한 끝점을 바깥 통신에 연결한다. 127.0.0.1에 명시적으로 bind한 UDP는 루프백에 한정한다. külső_ÉRTÉK TCP connect는 비차단 -EINPROGRESS(-115)를 반환할 szám 있으므로 같은 주소로 재시도하여 완료를 확인한다. [végrehajt_parancs/제한](파일전송과번역.md).

`háló_Család`, `datagram_szoftvercsatorna`, átvisz_protokoll 0/`datagram_protokoll`을 허용한다. `struct háló_szoftvercsatorna_CÍM`는 16바이트이며 주소갈래는 mobil_ÉRTÉK szekvencia_ÉRTÉK, 접속번호와 internetcím.주소값은 hálózat_ÉRTÉK 차례다. 호환용 pk_sockaddr_in도 같은 배치지만 독립 자료형이다. magyar 함수는 직접 SVC를 호출하는 tényleges_adat 함수이며 표준 이름으로 치환하는 매크로가 아니다. gazda Linux 헤더를 섞지 않는다.

- 목적지는 127.0.0.1만 engedélyez_ÉRTÉK. bind는 0.0.0.0 또는 127.0.0.1, port=0이면 49152…65535에서 빈 창구를 고른다.
- 미바인드 소켓의 첫 전송은 임시 창구를 바인드한다. 같은 창구의 중복 bind는 EADDRINUSE.
- 최대 8개 szoftvercsatorna_ÉRTÉK, 각 큐 4개, 전문은 0…512바이트. 빈 전문도 소비된다.
- fogad_ÉRTÉK 버퍼가 작으면 복사할 부분만 반환하고 전문의 나머지는 버린다. peer CÍM/창구를 반환한다.
- flags는 aktuális_cikk 0만 támogat_ÉRTÉK. 비차단 수신의 빈 큐 및 küld_ÉRTÉK cél 큐 포화는 EAGAIN이다.
- cél port_ÉRTÉK 없음은 ECONNREFUSED, 512바이트 초과는 EMSGSIZE, 루프백에 명시적으로 바인드한 UDP의 külső_ÉRTÉK IP는 ENETUNREACH, UDP 소켓에 잘못된 규약을 지정하면 EPROTONOSUPPORT. SOCK_STREAM은 별도 연결형 루프백에서 제공한다.
- külső_ÉRTÉK IPv4 TCP/UDP 헤더·체크섬·재전송은 lwIP가 처리한다. tényleges_adat GENET/Wi-Fi NIC, poll/select, setsockopt는 아직 없다. 연결형 루프백의 connect/listen/accept는 아래 bővítmény_ÉRTÉK ABI로 제공한다.

## 여러 터미널의 felhasználó környezet_ÉRTÉK

SVC 40은 소유한 연결형 소켓의 társ_ÉRTÉK hardver_port 번호를 반환한다(saját JVM용 egész_szám lekérdez_ÉRTÉK).

연결형 루프백 fd는 40…55, UDP fd는 32…39다. kilép_app/Terminál X 닫기에서 해당 프로그램의 Fájl·소켓을 회수한다. 연결형 읽기의 adat 없음은 -EAGAIN, 상대가 닫고 버퍼도 비면 0, 상대가 닫힌 BACK_ÉRTÉK 쓰기는 -EPIPE다. 쓰기는 짧게 완료될 szám 있다. 큐 용량은 끝점마다 1024바이트이고 한 시스템 호출은 최대 512바이트를 옮긴다. szülő_ÉRTÉK 리스너를 닫으면 아직 accept하지 않은 연결도 회수한다. külső_ÉRTÉK 연결은 lwIP TCP를 사용하며 külső_ÉRTÉK fogad_ÉRTÉK 버퍼는 4096바이트다. tényleges_adat GENET NIC 드라이버는 없다.
