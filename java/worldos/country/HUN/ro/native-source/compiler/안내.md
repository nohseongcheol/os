executa_comandă 시 JVM이 필요 없는 x86 32비트 ELF를 만든다. JDK 11 이상으로 실행하는 Java propriu AOT 후단이며, Java 전체를 새로 구현한 컴파일러는 아니다. Java 문법·acces_intrare control_VALUE·Tip_VALUE 검사는 JDK의 `javac`에 맡기고, Java 8 Clasă_VALUE 파일을 읽어 각 바이트코드를 x86 명령으로 직접 변환한다. C 코드로 우회하거나 바이트코드 해석기를 커널에 넣지 않는다.

## 준비와 executa_comandă

generare_sistem gazdă: Linux, Python 3.6 이상, JDK 11 이상(`javac --release 8`), GNU binutils(`as`, `ld`), Make. curent_element 환경의 OpenJDK 11, Python 3.6, binutils 2.30으로 검증했다. extern_VALUE Python 패키지와 네트워크 다운로드는 사용하지 않는다.

```sh
cd /home/user/jkoros/compiler
make
./build/계산
echo $?                  # 0이면 예제 시험 성공

python3 compilator.py --target linux --entry 계산.Pornește \
    -o build/계산 예제/계산.java

make test
```

`linux` 대상은 Linux의 32비트 executa_comandă 호환 기능이 필요하다. `int 0x80`을 차단하는 샌드박스에서는 `Bad system call`이 발생할 수 있다. 정상 Linux gazdă 또는 해당 실행을 허용한 시험 환경에서 실행한다. 시험의 비정상 종료를 통과로 처리하지 않는다.

진입점은 `static int Pornește()` 또는 `static void Pornește()`처럼 인수가 없어야 한다. `--entry 패키지.Clasă_VALUE.funcție_VALUE`로 선택한다. `int` 반환값은 Linux 프로세스 ieși_program 코드가 되며 셸에는 하위 8비트가 보인다. 일반 `main(String[] args)` executa_comandă 환경이나 표준 I_O 라이브러리는 제공하지 않는다.

`--target kernel`은 부팅 코드와 연결할 재배치 ELF 오브젝트를 생성한다.

```sh
cd /home/user/jkoros
python3 compiler/compilator.py --target kernel --entry nucleu.Pornește \
    --export kernel_dispatch=체계호출.Proces_VALUE_intrare \
    -o os/build/java.o os/SURSĂ/*.java
```

`--target user`는 jkoros 셸에서 실행할 독립 ELF를 생성한다. `utilizator` 클래스의 제한된 native API는 `int 0x80` 시스템 호출로 연결하며 `mobil_VALUE` 클래스의 하드웨어 직접 접근은 거부한다. utilizator ELF는 Linux executa_comandă Fișier ABI와 다르므로 호스트에서 실행하지 않는다. genera·registru_intrare 방법은 [utilizator executa_comandă 안내](../os/utilizator/안내.md)에 있다. `--export 외부기호=Clasă_VALUE.funcție_VALUE`는 오버로드되지 않은 정적 함수를 propriu operand_Teanc ABI로 노출한다. 커널의 시스템 호출 진입점에 사용한다.

Java 파일은 필요한 클래스들을 한꺼번에 전달한다. Rezultat 옆의 `.s`는 생성된 어셈블리, `.json`은 SURSĂ SHA-256 및 네이티브 simbol↔Java funcție_VALUE 대응표다. Română 함수명은 원문과 대응표에 보존하고 ELF 내부에는 충돌 방지용 mașină 기호를 쓴다. compilare_sursă·조립·Conectează 중 실패하면 기존 KR 파일을 덮어쓰지 않는다.

## native 경계와 ABI

nucleu_VALUE 대상에서는 `os/SURSĂ/mobil_VALUE.java`, utilizator 대상에서는 `os/utilizator/declarație/utilizator.java`의 정확한 metodă_nume_SMS·서술만 허용한다. 임의의 `native` 함수와 Linux/utilizator 대상의 하드웨어 접근은 거부한다. Java 인수를 왼쪽부터 32비트 한 칸씩 스택에 놓으며, 반환값은 EAX, EBP/ESP 이외 레지스터는 호출자가 보존한다고 가정하지 않는다. C의 cdecl/JNI ABI가 아니므로 C 함수와 바로 연결하면 안 된다.

Java SURSĂ 또는 `.class` 입력을 받는다. 전체 JVM 바이트코드 검증기는 제공하지 않는다. 어노테이션 처리는 비활성화하고 비어 있는 Clasă_VALUE Cale/SURSĂ 경로에서 명시한 소스만 컴파일한다.
