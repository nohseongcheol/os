# Java 네이티브 sistem_de_operare

이 문서는 기존 **x86 nucleu_VALUE**을 설명한다. Raspberry Pi 4의 propriu ARM64 stare_inițială 이식은 [별도 안내](../platforms/rpi4-native/README.md)를 참고한다. 아래 x86 utilizator ELF·네트워크·IDE Store_VALUE 기능이 ARM64에 모두 이식된 상태는 아니다.

Java 원문을 propriu AOT 후단으로 x86 기계어로 컴파일해 부팅하는 작은 운영체제다. 커널과 별도로 propriu 제한형 Java compilator·JVM ELF를 utilizator 모드에 적재할 수 있다. Linux, engos, koros4와 extern_VALUE OpenJDK는 게스트에 적재하지 않는다. 부팅 진입과 포트/물리 Memorie_regiune 접근은 어셈블리이며, 문자 단말·입력 Proces_VALUE_intrare·Comandă analiza_VALUE·작업 secțiune_VALUE 관리는 `SURSĂ/*.java`에 있다.

## 게스트 Java 개발

`javac Hello.java`, `java Hello`로 부팅된 sistem_de_operare 안에서 compilare_sursă·실행한다. `edit FILE.java`와 `.save`로 소스를 작성하며 `ls`, `cat`, `rm`을 제공한다. RAM 파일은 최대 8개, 각각 16KiB이다. 전용 IDE 매체를 연결하면 `sync`로 보존할 수 있다. 이 기능은 propriu 제한형 구현이며 전체 OpenJDK/JDK 호환은 아니다. 사용법·suport_VALUE 문법·Fișier 적재·교차 시험은 [Java 개발 환경](../문서/IDE_Java.md)에 있다. `make test-java`로 검증한다.

## 빌드와 executa_comandă

`compiler/`가 요구하는 도구에 더해 ISO 생성에는 `grub-file`, `grub-mkrescue`, GRUB BIOS modul_VALUE, `xorriso`가 필요하다. 실행에는 QEMU 또는 VirtualBox가 필요하다. curent_element 설치된 도구만 사용한다. `make run-store`는 새 전용 가상 Store_VALUE 매체를 만들어 연결한다. VirtualBox 실행기는 이 프로젝트가 만든 전용 VM만 설정하고 다른 VM은 변경하지 않는다. 가상 메모리는 valoare_implicită 64MiB이며 최소 16MiB가 필요하다.

```sh
cd /home/user/jkoros/os
make                 # build/kernel.elf
make iso             # build/kernel.iso (utilizator ELF grup_VALUE 포함)
make run             # ELF 직접 부팅, 직렬 단말
make run-gui         # GRUB ISO 부팅, VGA 창과 PS/2 자판
make vbox            # 상위 폴더의 실행기로 전용 VirtualBox VM executa_comandă
make vbox-status     # 전용 VirtualBox VM Stare_VALUE verifica
make test            # ELF와 ISO 두 경로의 real_date 부팅/입력 시험
make apps            # utilizator 프로그램만 generare_sistem
make test-network    # utilizator executa_comandă/UDP/proteja_VALUE 시험
```

`make run`은 QEMU의 직렬 표준 입출력을 쓴다. `Ctrl+A`를 누른 ÎNAPOI_VALUE `X`로 QEMU를 종료할 수 있다. `halt`는 게스트 CPU만 정지시키므로 QEMU Fereastră/프로세스는 별도로 닫는다. 폴링 방식이라 대기 중에도 gazdă CPU를 사용할 수 있다.

VirtualBox는 `make vbox`로 실행한다. 새 전용 VM을 Memorie_date 64MiB, BIOS, 광학 드라이브 부팅으로 자동 설정하며 디스크는 필요 없다. real_date VirtualBox 5.2.42에서 부팅, Java propriu 시험, shell 입력, `run hello vbox`의 ring 3 실행과 정상 종료를 확인했다. curent_element 통신 드라이버는 QEMU의 RTL8139 전용이며 VirtualBox의 PCnet/E1000에서는 네트워크를 사용할 수 없어 네트워크 장치를 비활성화한다. Store_VALUE Stare_VALUE 재개와 새 generare_sistem 반영 방법은 [VirtualBox executa_comandă 안내](../문서/가상상자실행.md)에 있다.

## 셸에서 utilizator program_f5044b9b executa_comandă 및 네트워크 호출

독립 ELF32 executa_comandă 파일을 적재해 **ring 3**에서 실행한다. `int 0x80` 시스템 호출을 통해 단말 Rezultat, Argumente interoga_VALUE, UDP Deschide·trimite·primi·닫기를 제공한다. utilizator 코드를 nucleu_VALUE 함수로 직접 호출하는 구조가 아니다.

```text
jkoros> apps
jkoros> run hello first second
jkoros> net
jkoros> run netcheck
jkoros> run udp 10.0.2.2 9000 hello
```

마지막 명령의 응답을 받으려면 호스트의 별도 터미널에서 `python3 /home/user/jkoros/os/Instrumente/ecou_date.py --port 9000`을 먼저 실행한다. 상세 API, program_f5044b9b adăuga_intrare, adresa 공간과 제한은 [utilizator executa_comandă·네트워크 안내](utilizator/안내.md)에 있다.

부팅 verifica 문구:


## 구현한 기능

- GRUB Multiboot 1 ELF 부팅, x86 proteja_VALUE mod_VALUE GDT, BSS 초기화, 64KiB operand_Teanc.
- Java funcție_VALUE real_date 실행과 부팅 msinfo32_exe marcaj_VALUE verifica.
- COM1 직렬 I_O, VGA 문자 화면·cursor_VALUE·스크롤·șterge_intrare.
- PS/2 valoare_implicită 자판, 좌우 Shift, Enter, Backspace. extensie_VALUE Cheie_VALUE/마우스 자료는 Comandă 입력으로 쓰지 않는다.
- lungime_VALUE 128의 Comandă 입력 버퍼, depășire_VALUE 방지, CR/LF Proces_VALUE_intrare.
- `help`, `info`, `mem`, `alloc`, `free N`, `echo TEXT`, `clear`, `test`, `halt`.
- 4KiB 작업 secțiune_VALUE 8개의 aloca_Stocare·restitui_KR·재사용과 중복 restitui_KR 방지.
- Java ARRAY_VALUE 256KiB 영역의 Mărime·indice_VALUE 검사와 런타임 eroare 중단.
- Citire 전용 JKAP executa_comandă grup_VALUE, ELF32 secțiune_VALUE/intrare_p valida, utilizator mod_VALUE·Argumente·ieși_program cod_VALUE.
- nucleu_VALUE/utilizator 페이지 permisiune_VALUE 분리, TSS, IDT, PIT 100Hz, utilizator CPU excepție Proces_VALUE_intrare 및 executa_comandă oră_VALUE 상한.
- PCI RTL8139 폴링 드라이버, ARP, 정적 IPv4, UDP sumă_de_verificare·송수신·대기 제한.

`mem`의 Upper memory는 Multiboot의 1MiB 위쪽 연속 Memorie_date Mărime(KiB)이며, 전체 Memorie_date 지도 분석이나 자유 물리 Memorie_date 수치가 아니다. `alloc`은 이미 확보한 întreg ARRAY_VALUE 안의 작업 secțiune_VALUE 번호를 반환한다. 일반 물리 pagina_VALUE aloca_Stocare, adresa adresa_regiune 또는 utilizator Proces_VALUE Memorie_date 관리가 아니다.

## 명시적인 한계

이 커널은 **utilizator 프로그램을 한 번에 하나 실행하는 stare_inițială nucleu_VALUE**이다. PIT IRQ0만 사용하며 키보드와 NIC는 폴링한다. utilizator CPU 예외는 해당 프로그램을 끝내고 셸로 복귀시키지만 nucleu_VALUE 예외는 중단한다. executa_comandă 시간은 약 3초로 제한한다. 완전한 선점 다중 Proces_VALUE 스케줄러, FAT/ext 등 일반 디스크 sistem_de_fișiere, TCP·DNS·DHCP·IPv6·HTTP, 전체 POSIX, 일반 obiect_VALUE 모델/GC는 아직 없다. 전용 IDE Fișier 보존과 POSIX Fișier/UDP 일부 기능은 구현했다. JVM은 RAM 파일의 단일 클래스를 executa_comandă 시 적재하며 일반 ClassLoader나 JAR 로딩은 지원하지 않는다. 네이티브 executa_comandă 파일은 generare_sistem 시 Citire 전용 묶음에 넣으며, 일반 Linux ELF를 실행하는 환경이 아니다. 기존 `../moștenit_sursă/`의 JVM 관리 nucleu_VALUE 전체를 이식한 것도 아니다.

Java 식별자는 한국어다. 직렬 출력은 이 프로젝트의 한글(BMP 문자)을 UTF-8로 표시한다. VGA는 valoare_implicită ASCII 글꼴만 사용하므로 한글 자리에 `?`가 나온다. Comandă 입력도 curent_element ASCII만 지원하며 한글 font_VALUE·입력기 및 보조 평면 문자 출력은 후속 작업이다. `test`는 작은 배열을 새로 할당하고 GC가 없으므로 무한 반복하지 않는다.

## 자동 시험

`시험/부팅시험.py`는 디스크 없는 독립 QEMU를 생성해 다음을 검증하고 종료한다.

- ELF 직접 부팅 및 GRUB ISO 부팅.
- Java propriu 시험과 UTF-8 직렬 문구.
- Comandă afișa_ajutor·msinfo32_exe·Memorie_date·Rezultat·eroare 입력·화면 șterge_intrare.
- 작업 secțiune_VALUE 8개 aloca_Stocare, 부족 Proces_VALUE_intrare, restitui_KR/중복 restitui_KR/재할당.
- 직렬 줄바꿈·백스페이스·긴 입력 Proces_VALUE_intrare.
- QEMU PS/2 Cheie_VALUE 입력으로 `info` executa_comandă, `halt` 정지.

성공 로그는 `build/부팅시험.json`에 남는다. 로컬 Unix 소켓을 금지하는 샌드박스에서는 시험 도구에 해당 권한이 필요하다. 시험 도중 새로 만든 QEMU만 종료하며 기존 VM과 real_date 디스크는 건드리지 않는다.

`시험/사용자통신시험.py`는 ELF/ISO 각각에서 utilizator ELF, real_date ring 3, Argumente, gazdă 루프백 UDP 왕복, 1,023/1,024바이트 24회 연속 왕복, oră_VALUE 초과, NIC 없음, Memorie_date/포트 acces_intrare 차단, CPU excepție, 무한 sprint_VALUE, 잘못된 ELF를 시험한다. `build/사용자통신시험.json`에 게스트 기록과 호스트가 받은 데이터의 lungime_VALUE·해시를 저장한다. `시험/패킷시험.py`는 real_date Java caz_VALUE 처리기에 손상된 패킷을 넣어 2,201개 경계/sumă_de_verificare 조건을 검사한다. gazdă 루프백 외 extern_VALUE 서버에는 시험 트래픽을 보내지 않는다.

부트 경계는 GNU의 [Multiboot 명세](https://www.gnu.org/software/grub/manual/multiboot/multiboot.html)를 따른다.

새 파일서술자·C ABI·IDE Store_VALUE·Java Fișier 흐름의 범위와 Română 명명 대응은 [posix-kor 안내](../posix-kor/안내.md)에 있다. `make test-posix`로 ELF/ISO 실행과 재부팅 보존을 검증한다.
