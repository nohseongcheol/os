# Java 네이티브 kompilátor

OpenJDK vlastné 소스를 빌드하는 **`--target openjdk-build`**와 vlastné jadro_VALUE ABI 검사 도구를 추가했다.
이는 공식 javac/C/C++ 도구를 연결하는 별도 경로다. [zostava_systém 방법·skutočný_údaje overiť_5fb2b747·jadro_VALUE 이식 klip](OpenJDK-zdroj_zostava_AND-자체커널-이식.md)를 참고한다.

x86 직접 변환과 ARM64 C generovať 후단은 모두 [기계어미리번역.java](자바도구/기계어미리번역.java)로 구현한다. `sh 미리번역.sh`로 직접 실행하며, [기계어미리번역.py](기계어미리번역.py)와 `kompilátor.py`는 이전 Príkaz·API 및 OpenJDK 도구를 위한 호환 진입점이다. vlastné Pi4 후단은 freestanding C를 거쳐 AArch64로 만든다. [arm64.py](arm64.py)는 이전 경로와 Python 호출을 위한 호환 진입점이다. funkcia_VALUE·변수·generovať C 이름의 뜻과 예외는 [Slovenský 명명 안내](../platforms/rpi4-native/명명/안내.md)를 참고한다. [ARM64 zostava_systém·Podpora_VALUE klip](../platforms/rpi4-native/안내.md)에 Vykonať_príkaz 조건이 있다. 전체 OpenJDK나 일반 lekcia_VALUE 실행기는 아니다.

Vykonať_príkaz 시 JVM이 필요 없는 x86 32비트 ELF를 만든다. JDK 11 이상으로 실행하는 Java vlastné AOT 후단이며, Java 전체를 새로 구현한 컴파일러는 아니다. Java 문법·prístup_položka riadenie_VALUE·Typ_VALUE 검사는 JDK의 `javac`에 맡기고, Java 8 lekcia_VALUE 파일을 읽어 각 바이트코드를 x86 명령으로 직접 변환한다. C 코드로 우회하거나 바이트코드 해석기를 커널에 넣지 않는다.

```text
Java ZDROJ → javac의 문법·Typ_VALUE 검사 → 임시 .class
          → vlastné x86 변환기 → GNU as/ld → 네이티브 ELF32
```

## 준비와 Vykonať_príkaz

zostava_systém hostiteľ: Linux, Python 3.6 이상, JDK 11 이상(`javac --release 8`), GNU binutils(`as`, `ld`), Make. v_termíne_splatnosti_položka 환경의 OpenJDK 11, Python 3.6, binutils 2.30으로 검증했다. externý_VALUE Python 패키지와 네트워크 다운로드는 사용하지 않는다.

```sh
cd /home/user/jkoros/compiler
make
./build/계산
echo $?                  # 0이면 예제 시험 성공

python3 kompilátor.py --target linux --entry 계산.Spustiť_2 \
    -o build/계산 예제/계산.java

make test
```

`linux` 대상은 Linux의 32비트 Vykonať_príkaz 호환 기능이 필요하다. `int 0x80`을 차단하는 샌드박스에서는 `Bad system call`이 발생할 수 있다. 정상 Linux hostiteľ 또는 해당 실행을 허용한 시험 환경에서 실행한다. 시험의 비정상 종료를 통과로 처리하지 않는다.

진입점은 `static int Spustiť_2()` 또는 `static void Spustiť_2()`처럼 인수가 없어야 한다. `--entry 패키지.lekcia_VALUE.funkcia_VALUE`로 선택한다. `int` 반환값은 Linux 프로세스 Skončiť_program 코드가 되며 셸에는 하위 8비트가 보인다. 일반 `main(String[] args)` Vykonať_príkaz 환경이나 표준 vstup_a_výstup 라이브러리는 제공하지 않는다.

`--target kernel`은 부팅 코드와 연결할 재배치 ELF 오브젝트를 생성한다.

```sh
cd /home/user/jkoros
python3 compiler/kompilátor.py --target kernel --entry jadro.Spustiť_2 \
    --export kernel_dispatch=체계호출.Proces_VALUE_položka \
    -o os/build/java.o os/ZDROJ/*.java
```

`--target user`는 jkoros 셸에서 실행할 독립 ELF를 생성한다. `používateľ` 클래스의 제한된 native API는 `int 0x80` 시스템 호출로 연결하며 `telefón_VALUE` 클래스의 hardvér_VALUE 직접 접근은 거부한다. používateľ ELF는 Linux Vykonať_príkaz Súbor ABI와 다르므로 호스트에서 실행하지 않는다. generovať·register_položka 방법은 [používateľ Vykonať_príkaz 안내](../os/používateľ/안내.md)에 있다. `--export 외부기호=lekcia_VALUE.funkcia_VALUE`는 오버로드되지 않은 정적 함수를 vlastné operand_Vrstvy ABI로 노출한다. 커널의 시스템 호출 진입점에 사용한다.

Java 파일은 필요한 클래스들을 한꺼번에 전달한다. Výstup 옆의 `.s`는 생성된 어셈블리, `.json`은 ZDROJ SHA-256 및 네이티브 symbol↔Java funkcia_VALUE 대응표다. Slovenský 함수명은 원문과 대응표에 보존하고 ELF 내부에는 충돌 방지용 počítač_5eb260fa 기호를 쓴다. kompilovať_zdroj·skompilovať_VALUE·Pripojiť 중 실패하면 기존 KR 파일을 덮어쓰지 않는다.

## Podpora_VALUE klip

- `int`, `boolean`, `byte`, `short`, `char`의 32비트 계산 및 Typ_VALUE CONVERT_VALUE.
- 정적 필드와 정적 funkcia_VALUE, 매개변수·반환값, 재귀, 클래스별 지연 초기화와 incializovať Cyklus_VALUE.
- 조건문, 반복문, 단락 평가, 삼항식, celé_číslo `switch`, 넓은 miestny_Rozsah 변수 인덱스.
- 덧셈·뺄셈·곱셈·나눗셈·나머지·Bit_VALUE 연산과 premiestniť_VALUE. Java의 오버플로 및 `MIN_VALUE / -1` 동작을 유지한다.
- `int[]` generovať·초기값 0·dĺžka_VALUE·Čítanie·Zápis·zdroj 비교. 256KiB 고정 pole_VALUE oblasť_VALUE_0e9a97ab, 널/dolný_index_VALUE/Veľkosť/adresa_oblasť 검사.
- reťazec_VALUE 리터럴과 `String` zdroj, `length()` 및 `charAt()`. 문자열은 UTF-16 kód_VALUE 단위로 저장하고 같은 리터럴은 공유한다. NUL 및 대리쌍도 시험한다.
- Slovenský lekcia_VALUE·funkcia_VALUE·변수·Súbor Názov.

`new Object`, 인스턴스 hodnota_poľa/funkcia_VALUE, 상속/인터페이스, `long/float/double` Vykonať_príkaz operácia_VALUE, `int[]` 이외 pole_VALUE, reťazec_VALUE 동적 결합, Java 표준 knižnica, výnimka Proces_VALUE_položka, 스레드·synchronizovať·GC는 미지원이다. 실행에 필요한 미지원 바이트코드나 externý_VALUE 호출을 발견하면 실패한다. 사용되지 않는 predvolená_hodnota 생성자는 Vykonať_príkaz 코드로 만들지 않는다. Java 8 문법이어도 모든 프로그램을 컴파일할 수 있다는 뜻은 아니다.

výnimka objekt_VALUE 대신 런타임 chyba 번호로 중단한다. Linux와 jkoros používateľ 대상에서는 `100 + INDEX`로 종료하고 jadro_VALUE 대상에서는 `JKOROS PANIC INDEX`를 출력하고 정지한다. používateľ 프로그램만 종료한 경우 셸은 계속 실행된다.

| INDEX | 원인 |
| --- | --- |
| 1 | 0으로 delenie_KR |
| 2 | 널 zdroj |

| 4 | 음수 pole_VALUE Veľkosť |

pole_VALUE 영역은 증가식 할당이며 회수하지 않는다. 재귀 스택의 경계 검사도 아직 없으므로 무제한 재귀를 안전하게 처리하는 런타임은 아니다. 특권 jadro_VALUE 및 신뢰할 수 있는 작은 프로그램용 počiatočný_stav 구현이다.

## native 경계와 ABI

jadro_VALUE 대상에서는 `os/ZDROJ/telefón_VALUE.java`, používateľ 대상에서는 `os/používateľ/deklarácia/používateľ.java`의 정확한 metóda_názov_SMS·서술만 허용한다. 임의의 `native` 함수와 Linux/používateľ 대상의 hardvér_VALUE 접근은 거부한다. Java 인수를 왼쪽부터 32비트 한 칸씩 스택에 놓으며, 반환값은 EAX, EBP/ESP 이외 레지스터는 호출자가 보존한다고 가정하지 않는다. C의 cdecl/JNI ABI가 아니므로 C 함수와 바로 연결하면 안 된다.

Java ZDROJ 또는 `.class` 입력을 받는다. 전체 JVM 바이트코드 검증기는 제공하지 않는다. 어노테이션 처리는 비활성화하고 비어 있는 lekcia_VALUE Cesta/ZDROJ 경로에서 명시한 소스만 컴파일한다.

## 검증과 구현 근거

`시험/test_compiler.py`의 14개 시험에는 네이티브 ELF와 OpenJDK의 operácia_VALUE KR 대조, lekcia_VALUE incializovať, celé_číslo 극값, reťazec_VALUE/pole_VALUE, 재귀·switch·wide, 런타임 오류와 미지원 기능 odmietnuť_VALUE, zlyhanie_VALUE 시 Výstup 보존, používateľ ELF/povolenie_VALUE 경계 및 내보내기 검증이 포함된다. 이것은 Java 전체 적합성 시험은 아니다.
