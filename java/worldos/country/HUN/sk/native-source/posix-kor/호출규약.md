# používateľ 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `počítač_5eb260fa/operačný_systém_Hovory.s`에서 EAX(INDEX), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 Argumenty)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. jadro_VALUE 실패는 음수 chyba INDEX, C knižnica 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 používateľ oblasť_VALUE_0e9a97ab 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C údaje 주소는 Byte_VALUE 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java Súbor 흐름의 어셈블리 경계가 별도 Byte_VALUE 버퍼를 마련하여 같은 호출을 사용한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 Skončiť_program, 2·3은 기존 Argumenty 조회다. v_termíne_splatnosti_položka 커널의 Argumenty 목록이 Vykonať_príkaz 이름을 제외하므로 C 진입기는 argv[0]에 고정 reťazec_VALUE `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX Proces_VALUE ABI와 다른 점이다.

표준 헤더의 celé_číslo Veľkosť, 플래그 VALUE, stat hodnota_poľa 순서는 `ZDROJ/포함/`에 정의한다. 동적 Pripojiť·다중 Proces_VALUE·스레드가 추가되면 chyba INDEX 저장과 zdroj_VALUE 수명, 호출 경계도 함께 검토해야 한다.
