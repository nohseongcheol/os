# ELF 형식과 Linux Izvedi_ukaz Datoteka 호환성

**ELF는 확장자가 아니다.** Executable and Linkable Format이라는 바이너리
형식이며, Linux 외의 운영체제도 사용한다. 첫 네 bajt_VALUE `7f 45 4c 46`,
ELF Razred_VALUE, CPU 종류, aplikacija_f5044b9b 헤더와 vnos_p_VALUE 주소를 읽어서 해석한다.
[ELF ABI 명세](https://gabi.xinuos.com/elf/02-eheader.html)

기존 jkoros 로더도 dejanski_podatki ELF64/AArch64 Izvedi_ukaz 파일을 읽었다. `.elf`는 예제의
이름일 뿐이었다. 다만 **ELF oblika_VALUE 지원과 Linux 시스템 호출 ABI 지원은 별개**다.
기존에는 `JKOROS` ABI note를 가진 lastno Izvedi_ukaz 파일만 허용했고, Linux 바이너리는
호환되지 않았다. ARM64 Linux는 SVC의 x8에 Linux 시스템 호출 번호를 넣는다.
같은 번호를 lastno ABI로 해석하면 다른 동작이 되므로 두 경로를 구분한다.
[Linux syscall ABI 설명](https://man7.org/linux/man-pages/man2/syscall.2.html)

## 이번 반영

| 입력 | Izvedi_ukaz 방법 | Podpora_VALUE izrezek |
|---|---|---|
| lastno ABI의 ARM64 ELF | `./인사`, `/작업/인사`, `run 인사` | 확장자 없이 Izvedi_ukaz; 내용이 ELF이면 `.txt`라는 이름도 동일 |
| Linux ARM64 statičen_VALUE ELF | `run --linux 리눅스인사 한글인수` | 아래 시스템 호출·naslov·Velikost 제한을 만족하는 aplikacija_f5044b9b |
| 텍스트를 `.elf`로 이름만 spremeniti_VALUE | Izvedi_ukaz zavrniti_VALUE | 확장자로 Izvedi_ukaz 파일을 인정하지 않음 |
| x86/x86-64, ARM32 Izvedi_ukaz Datoteka | Izvedi_ukaz zavrniti_VALUE | AArch64 전용이며 CPU navodilo_VALUE prevajalnik_orodje 없음 |
| 일반 glibc/musl aplikacija_f5044b9b, PIE, 공유 knjižnica | 아직 미지원 | 동적 로더·재배치·TLS·mmap·시그널 등 dodati_vnos 이식 필요 |

lastno 바이너리와 JAR의 lupina 직접 실행은 Datoteka 헤더로 구분한다. `run`은 lastno ELF,
`run --linux`는 명시적으로 Linux ABI를 선택한다. Linux 바이너리를 자동으로
lastno ABI에 넣지 않으며, lastno ABI note가 있는 파일은 Linux 모드에서 거부한다.
sprotno_element RAM Datoteka 체계에는 Izvedi_ukaz dovoljenje_VALUE 비트와 `chmod`, PATH 검색이 없다.

게스트 C prevajati_vir 예:

```text
cc 인사.c -o 인사
./인사
run 인사
```

`posix-kor`는 이 lastno ABI 경로로 연결한다. 일반 Linux에서 링크한 프로그램에
slovenščina FUNCTION_VALUE 이름을 붙이는 것만으로 lastno ABI 호환이 되는 것은 아니다.

## 제한된 Linux ABI

이 기능은 **lastno Java jedro_VALUE 안의 호환 sloj_VALUE**이며 Linux 커널을 적재하지 않는다.

| Linux 호출 | INDEX | sprotno_element 제약 |
|---|---:|---|
| read / write / close / lseek | 63 / 64 / 57 / 62 | RAM 파일과 표준 V_I; 입력 대기는 EAGAIN 가능 |
| openat / unlinkat | 56 / 35 | AT_FDCWD 또는 절대 POT; 파일만, 제한된 플래그 |
| ftruncate / fsync | 46 / 82 | RAM Datoteka; fsync가 영속 저장을 의미하지 않음 |
| exit / exit_group | 93 / 94 | sprotno_element aplikacija_f5044b9b Izhod_aplikacija |
| brk | 214 | lastno uporabnik kopica_VALUE izrezek; napaka_VALUE 시 이전 break vrni_KR |
| clock_gettime | 113 | CLOCK_MONOTONIC만, 밀리초 ločljivost_VALUE |
| getpid / gettid | 172 / 178 | 한 uporabnik Izvedi_ukaz 흐름의 identifikator_VALUE |

미지원 번호는 `-ENOSYS`를 반환한다. Linux ABI의 socket, fork/clone/execve,
pthread, mmap, signal, ioctl, fstat, 동적 로더와 일반 libc 초기화는 구현하지
않았다. 기존 lastno POSIX/Java 소켓은 별도로 TCP/UDP를 지원한다.

začetno_stanje 스택에는 argc, UTF-8 argv, 빈 envp, AT_PAGESZ/AT_ENTRY/AT_NULL을 넣는다.
입력은 ELF64 little-endian AArch64 **ET_EXEC**, Datoteka 전체 **16 KiB 이하**,
PT_LOAD 주소는 **0x02000000 이상 0x02c00000 미만**이어야 한다.
Datoteka 오프셋과 가상 주소의 페이지 poravnati_VALUE 관계를 검사하며, 서로 페이지를 공유하는
세그먼트와 Pisanje·Izvedi_ukaz 동시 허용은 거부한다. PT_INTERP/PT_DYNAMIC/PT_TLS와
ET_DYN은 아직 받지 않는다.

일반 Linux 바이너리의 privzeta_vrednost 적재 naslov 0x00400000은 커널과 겹치므로 아직 받지
않는다. 예제는 GNU 링커의 `-Ttext-segment=0x02000000 -z max-page-size=4096`을
사용한다. 이 파일도 정상적인 Linux ELF이며 같은 파일이 Linux와 lastno 커널에서
실행됨을 시험한다. Datoteka 이름이나 헤더만 바꿔 기존 Linux aplikacija_f5044b9b 전체를 지원할
수는 없다.

## dejanski_podatki 동일 바이너리 비교 시험

```sh
cd /home/user/jkoros/platforms/rpi4-native
make test-elf
```

시험은 `예제/리눅스ABI/Zaženi.S`와 `인사.c`를 Linux AArch64 대상으로 컴파일해,
**JKOROS note가 없는 확장자 없는 Izvedi_ukaz Datoteka** `build/verification/elf/리눅스인사`를
만든다. 같은 바이트를 Naprej_element 두 경로로 실행한다.

```sh
qemu-aarch64 build/verification/elf/리눅스인사 한글인수
python3 Orodja/Izvedi_Datoteka.py --linux build/verification/elf/리눅스인사 한글인수
```

첫 명령은 Linux 시스템 호출을 사용하는 pobuda_koren 실행이고, 두 번째는 Linux를
적재하지 않은 raspi4b lastno jedro_VALUE 실행이다. 한글 Argumenti, Datoteka V_I, Ura, Izhod_aplikacija,
jedro_VALUE naslov dostop_vnos 거부를 비교한다. FTP로 같은 파일을 올려 실행하는 시험도 있다.
LOG_zapis: `build/verification/elf/report.json`, `readelf.txt`, `serial.log` 및 FTP 보고서.

일반 Linux 프로그램까지 지원하려면 별도 uporabnik naslov naslov_območje, 더 큰 영속 VFS,
전체 Izvedi_ukaz inicializirati/auxv, 동적 링커와 재배치, mmap/TLS/시그널/스레드,
시스템 호출 및 libc 호환성을 확장해야 한다. 이번 구현은 첫 제한된 Izvedi_ukaz 경로다.
