# Raspberry Pi 4 lastno Java jedro_VALUE — uporabnik Izvedi_ukaz 기반

sprotno_element lastno 코드의 COSL 상업 pogoj, 제3자 고지 및 LGPL 재연결 자료는 [COSL 배포 안내](COSL배포안내.md)를 참고한다. SWITCH_MODE 전 GPL 구성의 판단은 [이전 라이선스 검토](licenca_mnenje.md)에 기록했다.

slovenščina 통신·izjema 사용법은 [slovenščina Java API](한국어자바/안내.md), FUNCTION_VALUE·변수·Datoteka 이름의 변경과 어원 근거는 [명명 안내](명명/안내.md)를 참고한다.

Linux 없이 부팅하는 lastno AArch64 커널이다. Java AOT jedro_VALUE 위에 **ukazna_vrstica lupina, 게스트 Java prevajalnik·JVM, MicroPython, EL0 C++ Izvedi_ukaz, Datoteka·UDP 루프백 시스템 호출, 여러 한글 GUI Terminal·vi Urejevalnik·Swing 부분집합**을 제공한다. 커널의 Datoteka podatki/정책·루프백 Prenos_VALUE·lupina 상태는 Java, 화면 합성·slikovna_pika spremeniti_VALUE·kazalec·클리핑도 Java로 구현하며, CPU/MMU/naprava_VALUE 경계와 Terminal·znak_VALUE 그리기 연결은 C와 어셈블리다.

**전체 JDK/JRE·CPython·표준 C++ 런타임·Swing 이식은 아직 완료되지 않았다.** 기존 [ARM64 Linux 실행판](../rpi4/README.md)의 OpenJDK/Python 패키지를 이 lastno 커널에 탑재했다고 표시하지 않는다.

새로운 게스트 `cc`/`jaot`, JAR 직접 Izvedi_ukaz, lwIP TCP/UDP와 FTP는 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)을 참고한다. 게스트 SSH·VNC와 Pi4 GENET/PHY·DHCP 드라이버를 추가했다. **SSH·VNC는 QEMU에서 검증하며, 실물 Pi4의 žičen_VALUE 송수신은 아직 미검증이다.** Izvedi_ukaz·povezava_e05f319b·geslo_VALUE 확인은 [zunanji_VALUE povezava_e05f319b 안내](zunanji_povezava_vodnik.md)에 정리했다.

셸은 EL1 jedro_VALUE, `java` 등 uporabnik Izvedi_ukaz 파일은 EL0에서 실행한다.
`ps`·`top`의 표시와 제한, QEMU 네트워크 Izvedi_ukaz·povezava_e05f319b 방법 및 dejanski_podatki 검증은
[Izvedi_ukaz 계층과 zunanji_VALUE 통신 점검](실행계층과외부통신점검.md)을 참고한다.

ELF는 확장자가 아닌 dejanski_podatki Izvedi_ukaz 형식으로 검사한다. `./인사`처럼 확장자 없이 실행하며, 제한된 Linux ARM64 statičen_VALUE ELF는 `run --linux ime_datoteke_SMS`으로 실행한다. [ELF·Linux ABI Podpora_VALUE 범위와 동일 바이너리 시험](실행파일규약.md).

GUI와 네트워크는 `python3 Orodja/Izvedi_ukaz.py --desktop --network`로 함께 사용한다. Java·C·Python의 slovenščina 예제 13개는 [jkoros/example](../../example/README.md)에 있으며, **게스트 부팅 시 `/example/java`, `/example/c`, `/example/python`에 자동으로 준비된다.** `example java|c|python`으로 지운 예제를 복원할 수 있다. Remmina에서 **F9/Shift+Space/한·nič_operand Ključ_VALUE**로 `[EN]`↔`[KO]` 두벌식을 전환한다(`help ko`). `make test-examples`는 같은 GUI VM에서 FTP·dejanski_podatki TCP/UDP·Datoteka bajt_VALUE·그래픽 픽셀을 검증한다.

게스트에서 `cd /example/java` 후 `java PrimerOkna`로 slovenščina Swing 예제를 실행한다. Terminal 모서리에 마우스를 대고 **왼쪽 버튼으로 끌면 크기가 바뀐다**. `terminal size`는 sprotno_element COLUMN_VALUE·ROW_VALUE 수를 보여 준다.

```sh

```

Izhod_aplikacija: **Ctrl+A Naprej_element X**. 게스트 C/AOT Orodja 빌드에는 `make rpi-prepare`로 준비한 ARM64 SDK 헤더와 libgcc 산술 보조 함수도 필요하다. libc나 Linux 커널을 게스트에 넣는 것은 아니다. gostiti 도구는 JDK 11 이상, Python 3.6 이상, Clang/Clang++, AArch64 GNU binutils, Make, `libnewlib-dev` 헤더다. 이미지는 확인된 공식 Pi 부팅 묶음에서 `start4.elf`, `fixup4.dat`, Pi4 DTB와 disable-bt overlay를 가져온다. Linux kernel/initramfs/rootfs는 넣지 않는다. 펌웨어·MicroPython·Terminal pisava_VALUE 라이선스와 pisava_VALUE 출처 해시도 동봉한다. Datoteka ustvariti 스크립트는 물리 디스크에 기록하지 않는다.

예비 microSD에 graditev_IMAGE LOG_zapis 도구로 `.img`를 기록하거나 FAT32 부팅 파티션 최상위에 ZIP 내용을 푼다. graditev_IMAGE 기록은 선택한 카드의 기존 내용을 지우므로 대상을 확인한다. Pi4 privzeta_vrednost EEPROM SD 부팅을 전제로 한다. UART는 **3.3V TTL, 115200 8N1**, GPIO14/TXD(8번)→어댑터 RX, GPIO15/RXD(10번)→TX, GND(6번) 연결이다. GPIO에 5V 신호를 연결하지 않는다.

**실물 Pi4 부팅은 미검증이다.** QEMU `-kernel`은 SD의 VideoCore 펌웨어를 실행하지 않고 커널을 직접 적재한다. SD Datoteka 구성·jedro_VALUE 체크섬 검사와 물리 Tabla 부팅 검증은 별개다. MMU uporaba_VALUE 전에는 펌웨어의 캐시/MMU가 꺼져 있고 EL1 또는 EL2로 진입하는 통상 부팅 조건을 전제로 한다. 세 보조 코어는 대기시키며 한 코어만 사용한다.

진입점은 `extern "C" int Start_uporabnik_aplikacija(int)`이다. uporabnik C++는 FP/SIMD를 사용할 수 있다. jedro_VALUE C/Java AOT는 일반 레지스터만 사용하므로 izjema Proces_VALUE_vnos 중 uporabnik FP 상태를 건드리지 않는다. uporabnik vnos_p_VALUE 시 FP 상태를 초기화하고 jedro_VALUE 복귀에 필요한 상태를 보존한다.

```cpp
#include "파일규약.h"
extern "C" int Start_uporabnik_aplikacija(int) {
    int Datoteka = odprto_Datoteka("인사.txt", branje_pisanje | 없으면만들기 | 내용비우기, 0600);
    if (Datoteka < 0) return 1;
    const char vsebina_VALUE[] = "안녕하세요";
    int REZULTAT = pisati_Datoteka_podatki(Datoteka, vsebina_VALUE, sizeof(vsebina_VALUE) - 1);
    Zapri_Datoteka(Datoteka);
    return REZULTAT == sizeof(vsebina_VALUE) - 1 ? 0 : 2;
}
```

[Datoteka 예제](uporabnik/PrimerDatoteke.cpp)와 [통신 예제](uporabnik/통신예제.cpp)가 dejanski_podatki 부팅 시험 대상이다. `파일규약.h`의 이름은 커널용/사용자용 모두 같지만 **링크하는 라이브러리가 다르다**. 사용자용은 `svc #0`으로 호출하고 Datoteka Proces_VALUE_vnos 및 루프백 전달은 Java 커널에서 실행한다. `통신규약.h`의 vtičnica_VALUE 함수는 sprotno_element 사용자용 라이브러리에 구현돼 있다.

새 프로그램은 jedro_VALUE 재빌드 없이 `load FILE.elf`와 `run FILE.elf`로 실행한다. 호스트에서 Naprej_element 도구를 사용하면 **새 QEMU를 부팅해 업로드한 dejanski_podatki 바이트를 재확인한 ZAJ_VALUE 게스트에서 Izvedi_ukaz**하고 종료한다. 이 도구의 새 VM에서 만든 RAM 자료는 종료할 때 사라진다.

```sh
cd /home/user/jkoros/platforms/rpi4-native
python3 Orodja/Izvedi_Datoteka.py build/jkoros-native-sdk/demo.elf
python3 Orodja/Izvedi_Datoteka.py 예제/Hello.java "한글 Argumenti"
python3 Orodja/Izvedi_Datoteka.py 예제/hello.py
```

이 경로는 16KiB 이하의 `.elf`, `.java`, `.class`, `.py`를 지원한다. 큰 내장 Java/MicroPython ELF 자체는 jedro_VALUE 묶음에 포함되어 이 Datoteka 한도를 적용받지 않는다. **C++ 컴파일러는 gostiti SDK의 Clang++**이며 게스트 내부 GCC/Clang 컴파일러는 아직 없다. SDK만으로 일반 Linux 프로그램을 실행할 수는 없다. Linux ELF, 동적 knjižnica, PT_TLS, PT_INTERP, PT_DYNAMIC, Izvedi_ukaz·Pisanje 겸용 세그먼트는 로더가 거부한다. 구체적인 호출 INDEX·naslov izrezek·오류는 [uporabnik ABI](사용자호출규약.md)를 참고한다.

RAM 파일은 재부팅 시 사라진다. `potrjevanje_datotečna_shramba`은 -1과 ENOSYS를 반환한다. 파일의 mode 인수를 저장하지 않으며 dovoljenje_VALUE·dup/fcntl은 없다. 디렉터리와 enakovreden_VALUE/절대 경로는 같은 RAM 저장소에서 처리한다. UDP 전문은 최대 512바이트, 소켓은 8개, sprejeti_sprejemati_prejeti_prejemati_VALUE 큐는 소켓당 4개다. 수신할 자료가 없거나 큐가 가득 차면 EAGAIN을 반환한다. uporabnik Izhod_aplikacija 시 열린 Datoteka 서술자와 소켓을 회수한다.

## Java와 Python의 정확한 izrezek

lastno `javac`는 버전 49 `.class`를 생성하며 JVM은 Podpora_VALUE 명령으로 구성된 버전 45–52 클래스를 실행한다. statičen_VALUE FUNCTION_VALUE·재귀·int/boolean/char/String·pogoj/sprint_VALUE·niz_VALUE 결합과 일부 Datoteka 스트림을 지원한다. UTF-8 문자열과 문자 리터럴, ASCII 및 현대 한글 음절/조합 자모 식별자를 처리한다. Unicode identifikator_VALUE 전체 iskalna_tabela·Unicode vir_drevo 이스케이프는 구현하지 않았다. 게스트 vir_drevo 컴파일러는 일반 predmet_VALUE·izjema·Thread 구문을 아직 컴파일하지 못한다. gostiti `javac --release 8`로 만든 Podpora_VALUE 부분집합 클래스는 lastno JVM 0.4의 predmet_VALUE·izjema·Thread·UDP와 slovenščina API를 사용할 수 있다. Swing은 문서화한 lastno API 부분집합을 제공하며 JAR 로더는 제공하지만 전체 AWT/Swing·JDK 표준 라이브러리는 없다. 정확한 범위는 [lastno JVM 설명](자바실행환경.md)이 기준이다. 상세 jezik 범위는 [공유 Java Orodja 설명](../../문서/자바개발환경.md)을 참고하되, 그 문서의 x86 lupina/Store_VALUE/실행시간과 이 ARM64 판의 차이에 유의한다.

MicroPython은 공식 **1.24.1 vir_drevo**를 lastno AArch64 EL0/SVC 대상으로 빌드했다. Python 문법의 FUNCTION_VALUE·Razred_VALUE·izjema·리스트/slovar·Unicode·GC·가변 natančnost_VALUE 정수를 제공한다. sprotno_element 구성은 celo_število 빌드로 `float`, `complex`, `math`가 없으며 CPython 전체 표준 knjižnica, pip, subprocess, threading, 일반 socket과 privzeta_vrednost `open()` Datoteka 객체는 제공하지 않는다. `python FILE.py` 및 `-c` 실행만 제공하며 REPL은 아직 없다. 각 실행의 predmet_VALUE·모듈은 Izhod_aplikacija 시 회수되고 RAM 파일만 Naprej_element 실행에 남는다.

`import jkoros`로 Naprej_element 시스템 연결을 쓴다. 모두 SVC를 통해 lastno Java 커널에 접근한다.

| FUNCTION_VALUE | Dejanje |
|---|---|
| `stdin(limit)` | sprotno_element 표준 입력에서 최대 limit바이트(0…16384)를 bytes로 읽음; EOF는 빈 bytes, UART podatki 없음은 OSError(11) |
| `read(name)` | enakovreden_VALUE/절대 RAM 경로의 Datoteka 전체를 bytes로 읽음 |
| `write(name, data)` | str/bytes 버퍼를 RAM 파일에 새로 Store_VALUE, 쓴 bajt_VALUE 수 vrni_KR |
| `remove(name)` | RAM Datoteka 삭제 |
| `rect(x, y, w, h, color)` | 선택한 dejanski_podatki 화면 Velikost 안의 pravokotnik risba_VALUE; 기존 보드의 RGB32 VALUE |
| `ticks_ms()` | 부팅 후 밀리초, 32비트 Krog_VALUE |
| `udp_open(port)` | 127.0.0.1의 UDP vtičnica_VALUE Odpri/BIND_končna_točka; 0은 자동 strojna_oprema_vrata |
| `udp_send(fd, port, data)` | 루프백 cilj_VALUE 포트에 str/bytes 버퍼 Prenos_VALUE |
| `udp_recv(fd)` | `(bytes, 보낸포트)` vrni_KR; 비어 있으면 `OSError(11)` |
| `udp_close(fd)` | vtičnica_VALUE Zapri |

```python
import jkoros
first = jkoros.udp_open(9401)
second = jkoros.udp_open(9402)
jkoros.udp_send(first, 9402, b"hello")
print(jkoros.udp_recv(second))  # (b'hello', 9401)
jkoros.udp_close(first)
jkoros.udp_close(second)
```
