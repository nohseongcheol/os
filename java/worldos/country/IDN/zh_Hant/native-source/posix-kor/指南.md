# jkoros posix-kor

**內建 ARM64 Java 커널용 C++ 連接**은 [arm64-native](arm64-native/指南.md)에 있다. 內核值 내부 직접 檔案 호출과 EL0 使用者 프로그램의 檔案/UDP 루프백 SVC 호출을 별도 라이브러리로 제공한다. 底端值 i386 庫 및 ARM64 Linux libc와는 目標值·ABI가 다르다.

內建 jkoros 커널에서 실행되는 i386 C 라이브러리와 中文 API다. 宿主 libc를 연결하지 않고 `int 0x80`으로 實際資料 커널의 檔案描述符·終端輸入輸出·UDP·存儲值 계층을 호출한다. `基礎原始碼/`의 宿主 JVM 모형과 별개다.

**현재는 POSIX의 일부 기능을 제공하는 호환 계층이며, POSIX 인증·전체 libc·전체 OpenJDK를 뜻하지 않는다.** 實現 범위와 제한을 아래에 명시한다. 한국어를 먼저 적용했다. 다른 국가·언어의 번역판은 아직 만들지 않았다.

## 빌드와 執行命令

```sh
cd /home/user/jkoros
make posix-kor
make iso
make test-posix
make -C os run-store
```

`run-store`는 `os/build/files.img`首位操作數 없을 때만 새 전용 파일을 만들고 QEMU IDE 首位項目 장치로 연결한다. 기존 파일을 덮어써서 초기화하지 않는다. 일반 `make run`은 디스크 없이 실행된다. VirtualBox 실행기의 디스크 연결은 변경하지 않았다.

부팅된 jkoros에서:

```text
run posixcheck check
run posixstore
cat stored.txt
edit note.txt
hello from jkoros
.save
sync
```

`Sync: 0`은 연결된 전용 매체에 저장했다는 뜻이다. 디스크가 없거나 賦值值 형식이 아니면 `Sync: -19`第三操作數. 같은 `files.img`로 重試值 부팅하면 最後項目 同步化 상태를 복원한다. Java 소스와 `.class`도 같은 存儲值 대상이다. `close`第二操作數 편집기의 `.save`만으로 재부팅 보존을 보장하지 않으므로 退出程式 전에 `sync`를 실행한다.

## 한국어로 C 程式 작성

```c
#include <檔案ABI.h>

int main(int 參數列個數, char **實際參數列表) {
    (void)參數列個數;
    (void)實際參數列表;
    int 檔案描述符 = 打開檔案("note.txt", 讀取寫入 | 創建條件缺失, 0600);
    if (檔案描述符 < 0) return 錯誤編號;
    if (寫入檔案資料(檔案描述符, "hello\n", 6) != 6) return 1;
    if (提交檔案存儲裝置(檔案描述符) < 0) return 錯誤編號;
    return 關閉檔案(檔案描述符);
}
```

작성 원문은 한글을 그대로 유지한다. `工具集/標識符轉換結果.py`首位操作數 構建系統 복사본의 식별자만 C 표준 UCN 표기로 바꾸어 GCC 7에서도 컴파일되게 한다. 字符串, 주석, `#include` 경로는 변환하지 않는다. 이 도구는 C의 모든 預處理原始碼 표기법을 해석하는 전처리기가 아니며, 프로젝트가 사용하는 일반 토큰과 include 문법을 대상으로 한다.

라이브러리는 `build/libposix-kor.a`, 運行 코드는 `build/開始用戶程式.o`, 生成 헤더는 `build/原始碼/頭文件/`이다. 構建系統 옵션과 連接 명령은 [Makefile](Makefile), 實際資料 예제는 [檔案ABI測試.c](原始碼/測試/檔案ABI測試.c)와 [數據報測試.c](原始碼/測試/數據報測試.c)에 있다. 새 ELF를 OS에 포함하려면 `os/Makefile`의 使用者 執行命令 묶음에 명시적으로 등록한다. 게스트 안에서 C를 컴파일하는 도구는 제공하지 않는다.

표준 C/POSIX 外部值 名稱 `open`, `read`, `write`, `socket`, `errno`, `main`과 헤더 경로는 유지한다. 中文 별칭은 같은 함수를 가리킨다. 변수와 實現 파일에는 의미를 드러내는 中文 이름을 사용한다. 翻譯原始碼 근거는 [命名 원칙](命名原則.md), 實際資料 대응은 [용어 대응표](術語映射.tsv)에 기록했다.

## 제공하는 기능

| 裁剪 | 實現 | 當前項目 限制值 |
|---|---|---|
| 檔案 | open/creat/read/write/close/lseek/unlink/ftruncate/fstat/fsync | 루트의 단일 名稱, ASCII 63바이트, 8개 檔案, 파일당 16KiB |
| 描述符條目 | dup/dup2, F_DUPFD/F_DUPFD_CLOEXEC/F_GETFD/F_SETFD/F_GETFL/F_SETFL | 程序值 一值, 最大值 32개; 鎖值·exec 미구현 |
| 輸入輸出 設置 | O_RDONLY/O_WRONLY/O_RDWR/O_CREAT/O_EXCL/O_TRUNC/O_APPEND/O_NONBLOCK/O_CLOEXEC | 그 밖의 비트는 ENOTSUP; 實際資料 使用者·그룹 存取條目 權限值 검사는 缺失方法 |
| 표준 終端輸入輸出 | 0 讀取, 1·2 寫入, 位元組值 單位值 輸入值 | 終端 編輯值·termios·시그널 缺失方法, 韓文文本 字體值/입력기 缺失方法 |
| UDP | socket/bind/sendto/recvfrom/getsockname, SO_RCVTIMEO | IPv4 UDP만, 묶인 端點值 4개, 전문당 1,024바이트, 接收值 等待狀態值 設置 最大值 2초 |
| 地址 | htons/ntohs/htonl/ntohl/inet_pton/inet_ntop | IPv4 數字值 주소만; DNS/IPv6 缺失方法 |
| 작은 C 支持值 | strlen/strcmp/memcpy/memset/memcmp/puts/putchar | 전체 libc·stdio FILE·malloc 缺失方法 |
| 存儲值 | JKSTORE1 전용 IDE 存儲值, 두 보존본과 校驗和 | FAT/ext 檔案系統·디렉터리·하드 링크·심볼릭 링크 缺失方法 |
| 게스트 Java | FileInputStream(String).read()/close(), FileOutputStream(String[, boolean]).write(int)/close() | 陣列值 輸入輸出·일반 java.io·異常 程序值條目 缺失方法 |

`dup`으로 복제한 서술자는 檔案 위치와 追加繼續狀態 설정을 공유한다. `FD_CLOEXEC`는 서술자마다 저장한다. `unlink`는 이름만 제거하며, 열린 파일의 내용은 最後項目 참조가 닫힐 때까지 접근할 數 있다. 빈 위치를 건너뛰어 쓰거나 길이를 늘린 영역은 0으로 읽힌다. 檔案描述符 부족으로 실패한 `open`은 파일을 생성하거나 비우지 않는다. C 調用 실패는 `-1`과 `errno`, 내부 內核值 호출은 負數值 錯誤 번호를 반환한다.

`fstat`는 이 프로젝트 전용 48바이트 구조체에 種類值·大小·링크 數·授權權限 位元值 등을 반환한다. POSIX의 전체 時間值 속성은 아직 제공하지 않는다. 다른 운영체제의 `struct stat` 또는 Linux 바이너리 ABI와 호환되지 않는다. `O_CLOEXEC`는 기록할 數 있지만 當前項目 exec 기능은 없다. 성공하는 函數 이름만으로 전체 POSIX 의미가 구현되었다고 간주하면 안 된다.

UDP는 QEMU RTL8139의 實際資料 宿主 왕복을 지원한다. 짧은 接收值 버퍼에는 앞부분을 복사하고 餘數值 전문을 버린다. 빈 전문도 송수신한다. `SO_RCVTIMEO` 또는 비차단 수신의 資料 없음은 `EAGAIN`이다. TCP를 요청하면 `EPROTONOSUPPORT`를 반환한다. 루프백·브로드캐스트·멀티캐스트·연결형 通訊端值·listen/accept는 아직 없다. 기존 AOT Java UDP 손잡이는 이 POSIX 서술자와 별개이므로 서로 섞어 닫지 않는다.

모든 使用者 프로그램에는 기존 약 3초 執行命令 상한이 적용된다. `errno`는 當前項目 단일 程序值·단일 스레드 변수다. JDK 전체, Swing/AWT/JavaFX, TCP/DNS/HTTP/TLS, 스레드·GC·JIT·동적 연결은 아직 구현하지 않았다. 전체 Java SE 執行命令 환경을 만들려면 해당 內核值 기반과 런타임 이식을 繼續處理 진행하거나 별도 Linux 基礎 執行命令 방식을 결정해야 한다.

## 存儲值 형식과 有效性校驗

매체는 512바이트 區段值 2,048개(1MiB)第三操作數. 區段值 0의 `JKSTORE1` 標識符值·大小·格式值 번호가 構建全部 맞는 장치만 寫入 대상으로 삼는다. 區段值 1과 260에서 각각 259구역짜리 보존본이 시작한다. 각 보존본은 是否完成 頭值 1구역, 檔案 表 2구역, 檔案 資料 256구역으로 구성된다.

`fsync`와 `sync`는 이름이 남아 있는 모든 파일의 當前項目 상태를 저장한다. 반대편 보존본을 무효화한 後端值 檔案 표와 자료를 쓰고 ATA 캐시 비우기를 실행한다. 마지막에 代次值 번호와 FNV-1a 검사합을 가진 是否完成 머리를 기록하고 重試值 캐시를 비운다. 啓動 시 검사합과 표가 유효한 가장 最近值 세대를 선택한다. 검사합은 우발적인 손상을 查找條目 위한 것이며 암호학적 무결성 검증은 아니다. 實際資料 設備 전원 차단 시험은 하지 않았다.

복원된 檔案 목록은 啓動 이미지의 默認值 範例/`JAVA_FILES` 목록을 대체한다. 새 예제를 이미지에 추가해도 기존 存儲值 매체를 연결하면 저장된 목록이 우선한다. 동기화하지 않은 변경은 재부팅 之後狀態 사라진다.

`make test-posix`는 中文 標識符值 轉換值, ELF/ISO의 實際資料 C ABI 調用, 공유 位置, 삭제된 파일의 수명, 檔案/描述符條目 고갈, 指針 錯誤, 표준 輸入值, UDP, `fsync`, 재부팅, 손상된 最新值 보존본의 회피, 다른 형식의 介質值 비변경, 게스트 Java 檔案 처리와 OpenJDK 교차 실행을 확인한다. 기록은 `os/build/契約測試.json`, `持久化測試.json`, `Java檔案測試.json`이다.
