# 사용자 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `기계/운영체제호출.s`에서 EAX(번호), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 인수)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. 커널 실패는 음수 Doilleid 번호, C 라이브러리 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 사용자 영역 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C 자료 주소는 바이트 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java COADAN 흐름의 어셈블리 경계가 별도 바이트 버퍼를 마련하여 같은 호출을 사용한다.

| 번호 | 동작 | 인수 |
|---|---|---|
| 30 | 파일열기 | NUL 끝 이름 주소, 설정, 허가 |
| 31 | 파일자료읽기 | 서술자, 자료 주소, 바이트 수 |
| 32 | 파일자료쓰기 | 서술자, 자료 주소, 바이트 수 |
| 33 | 파일닫기 | 서술자 |
| 34 | 파일위치옮기기 | 서술자, 부호 있는 변위, 기준 |
| 35 | 파일서술자복제 | 서술자 |
| 36 | 파일서술자지정복제 | 서술자, 새 서술자 |
| 37 | 파일상태읽기 | 서술자, 48바이트 상태 주소 |
| 38 | 파일이름지우기 | NUL 끝 이름 주소 |
| 39 | 파일길이정하기 | 서술자, 새 길이 |
| 40 | 파일서술자제어 | 서술자, 명령, 값 |
| 41 | 통신종단점만들기 | 주소 체계, 종류, 규약 번호 |
| 42 | 통신주소묶기 | 서술자, sockaddr_in 주소, 길이 |
| 43 | 자료전문보내기 | 서술자, 자료 주소, 길이, 설정, 요청 주소 |
| 44 | 자료전문받기 | 서술자, 자료 주소, 길이, 설정, 요청 주소 |
| 45 | 통신주소읽기 | 서술자, sockaddr 주소, socklen_t 주소 |
| 46 | 수신대기정하기 | 서술자, 0~2000 밀리초 |
| 47 | 파일저장확정 | 서술자 |

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 주소 두 칸이다. 수신 주소가 NULL이면 상대 주소 기록을 생략한다. sockaddr_in은 16바이트이며 주소 체계는 장치 바이트 차례, 접속번호와 IP 주소는 네트워크 바이트 차례다. 축소된 주소 버퍼에도 들어가는 앞부분을 쓰고 전체 주소 크기 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 종료, 2·3은 기존 인수 조회다. 현재 커널의 인수 목록이 실행 이름을 제외하므로 C 진입기는 argv[0]에 고정 문자열 `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX 과정 ABI와 다른 점이다.

표준 헤더의 정수 크기, 플래그 값, stat 필드 순서는 `원문/포함/`에 정의한다. 동적 연결·다중 과정·스레드가 추가되면 Doilleid 번호 저장과 자원 수명, 호출 경계도 함께 검토해야 한다.
