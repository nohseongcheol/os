# 셸에서 실행하는 ব্যৱহাৰকৰ্তা 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 ৰিডমি_ফাইল_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 নিষ্পাদন_আদেশ

হ_ষ্ট টাৰ্মিনেল 1:

```sh
cd /home/user/jkoros
python3 os/সঁজুলিসমূহ/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 외부 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

হ_ষ্ট টাৰ্মিনেল 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 প্ৰকৃত_ডাটা CPU অনুমতি_মান `ring 3`, 인수 নিৰ্গম.
- `netcheck`: পৰ্ট_মান 중복, 잘못된 হেণ্ডেল_মান/পইণ্টাৰ/দৈর্ঘ্য_মান, 비차단 받기와 시간 초과 প্ৰমাণিত_কৰক.
- `udp`: IPv4 ঠিকনা·গন্তব্য_স্থান_মান পৰ্ট_মান·한 단어 메시지를 받아 UDP로 보내고 같은 응답을 প্ৰমাণিত_কৰক. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: হ_ষ্ট `10.0.2.2`의 지정 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 লুপ_মান 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 현재 주소는 게스트 `10.0.2.15/24`, গেটৱে_মান `10.0.2.2`로 고정돼 있다. QEMU ব্যৱহাৰকৰ্তা 네트워크의 হ_ষ্ট প্ৰৱেশ_কৰক_প্রবিষ্ট 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 এপ্প্_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java এপ্প্_f5044b9b 추가

`예제/내프로그램.java`를 পৰৱৰ্তী_আইটেম 형식으로 만든다. 진입점은 인수 없는 `static int` 또는 `static void` 함수다. 인수는 ব্যৱহাৰকৰ্তা API로 조회한다.

```java
public final class 내프로그램 {
    public static int সঞ্চালন() {
        ব্যৱহাৰকৰ্তা.লিখা("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/ব্যৱহাৰকৰ্তা/এপ্প্_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := ব্যৱহাৰকৰ্তা/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.সঞ্চালন
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `ব্যৱহাৰকৰ্তা/선언/ব্যৱহাৰকৰ্তা.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 নিষ্পাদন_আদেশ 중인 VM에는 বিল্ড_ছিষ্টেম 결과가 자동 반영되지 않는다. এপ্প্_f5044b9b 이름은 현재 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java শ্ৰেণী_মান·ফাংছন_মান·변수에는 한국어를 쓴다. 최대 32개 এপ্প্_f5044b9b, 한 নিষ্পাদন_আদেশ 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.সঞ্চালন \
    -o os/build/apps/hello.elf os/ব্যৱহাৰকৰ্তা/선언/ব্যৱহাৰকৰ্তা.java os/ব্যৱহাৰকৰ্তা/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 হ_ষ্ট 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 সমর্থন_মান ক্লিপ 안에서 실행한다. `.jar`와 일반 Linux নিষ্পাদন_আদেশ 파일은 지원하지 않는다.

## ব্যৱহাৰকৰ্তা 네트워크 API

선언은 `선언/ব্যৱহাৰকৰ্তা.java`에 있다. `ই_মেইল_কৰক_ডাটা`/`자료받기`의 `int[]` আইটেম_উপাদান 한 개는 বাইট_মান 하나(0~255)를 나타낸다. 한 데이터그램의 최대 ডাটা 길이는 1,024바이트다.

```java
int হেণ্ডেল_মান = ব্যৱহাৰকৰ্তা.খোলক_নেটৱৰ্ক(0); // 0: 임시 স্থানীয়_সুযোগ UDP পৰ্ট_মান 자동 চয়ন_মান
int[] ডাটা = new int[32];
ডাটা[0] = 'H'; ডাটা[1] = 'i';
int 보낸길이 = ব্যৱহাৰকৰ্তা.ই_মেইল_কৰক_ডাটা(হেণ্ডেল_মান, 0x0a000202, 9000, ডাটা, 2);
int 받은길이 = ব্যৱহাৰকৰ্তা.자료받기(হেণ্ডেল_মান, ডাটা, 1500);
ব্যৱহাৰকৰ্তা.বন্ধ_কৰক_নেটৱৰ্ক(হেণ্ডেল_মান);
```

প্ৰকৃত_ডাটা 프로그램에서는 খোলো·ই_মেইল_কৰক·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 대기 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 추가 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | হেণ্ডেল_মান·প্ৰক্ৰিয়া_মান_প্রবিষ্ট দৈর্ঘ্য_মান·성공 등 해당 함수의 পৰিমাপ |
| -5 | চেলফোন_মান ই_মেইল_কৰক_মান বিফলতা_মান |
| -9 | 잘못되었거나 닫힌 통신 হেণ্ডেল_মান |
| -11 | 비차단 받기에서 도착한 ডাটা 없음 |
| -14 | ব্যৱহাৰকৰ্তা পইণ্টাৰ/শৃঙ্খলা_মান ক্লিপ ত্ৰুটি |
| -19 | সমর্থন_মান NIC 없음 |
| -22 | পৰ্ট_মান/대기 시간/인수 মান ত্ৰুটি |
| -24 | 열린 নেটৱৰ্ক_পৰ্ট 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | ডাটা 또는 수신 শৃঙ্খলা_মান মাপ 문제 |
| -98 | স্থানীয়_সুযোগ পৰ্ট_মান ইনডেক্স 중복 |
| -101 | 지원하지 않는 গন্তব্য_স্থান_মান ঠিকনা |
| -110 | ARP·চেলফোন_মান·수신 시간 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 এনকোডিং_মান 있는 Java `int`의 বিট_মান 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## নিষ্পাদন_আদেশ 경계와 시스템 호출

```text
শ্বেল run → JKAP에서 ELF বৈধকৰণ_কৰক·적재 → ring 3 ব্যৱহাৰকৰ্তা এপ্প্_f5044b9b
                                 ↓ int 0x80
                      পইণ্টাৰ 검사 → Java কাৰ্ণেল_মান API → RTL8139/UDP
                                 ↓ প্ৰস্থান_এপ্প্·예외·시간 초과
                                শ্বেল 복귀
```

시스템 호출 레지스터는 `EAX=ইনডেক্স`, `EBX,ECX,EDX,ESI,EDI=인수`, `EAX=পৰিমাপ`다. Java 호출 스택 ABI는 컴파일러가 ব্যৱহাৰকৰ্তা 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| ইনডেক্স | 호출 |
| --- | --- |
| 0 | প্ৰস্থান_এপ্প্(অৱস্থা_মান 코드) — সঞ্চালন/ত্ৰুটি 런타임에서 사용 |
| 1 | ষ্ট্ৰিং_মান লিখা |
| 2 / 3 | 인수 개수 / 인수 ষ্ট্ৰিং_মান ঠিকনা |
| 10 | UDP খোলো |
| 11 | UDP ই_মেইল_কৰক(হেণ্ডেল_মান, IP, গন্তব্য_স্থান_মান পৰ্ট_মান, শৃঙ্খলা_মান ঠিকনা, দৈর্ঘ্য_মান) |
| 12 | UDP 받기(হেণ্ডেল_মান, শৃঙ্খলা_মান ঠিকনা, 제한 밀리초) |
| 13 | UDP বন্ধ_কৰক |
| 14 | স্থানীয়_সুযোগ IP ঠিকনা |
| 15 / 16 | 마지막 পীয়েৰ_মান IP / UDP পৰ্ট_মান |
| 20 | RAM নথিপত্ৰ পড়া(নাম int[] ঠিকনা, নিৰ্গম int[] ঠিকনা) |
| 21 | RAM নথিপত্ৰ লিখা(নাম int[] ঠিকনা, 입력 int[] ঠিকনা, বাইট_মান দৈর্ঘ্য_মান) |
| 22 | UTF-16 코드 পাঠ্য_মান 문자 নিৰ্গম(0~65535) |

নথিপত্ৰ API는 `ব্যৱহাৰকৰ্তা.파일읽기(int[] নাম, int[] ডাটা)`와 `ব্যৱহাৰকৰ্তা.লিখক_ফাইল(int[] নাম, int[] ডাটা, int দৈর্ঘ্য_মান)`다. 이름은 ASCII 코드 শৃঙ্খলা_মান(최대 64칸, 0 প্ৰস্থান_এপ্প্ 또는 শৃঙ্খলা_মান 끝), ডাটা আইটেম_উপাদান 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 নথিপত্ৰ 없음 `-2`, পইণ্টাৰ ত্ৰুটি `-14`, নাম/দৈর্ঘ্য_মান ত্ৰুটি `-22`, নথিপত্ৰ শ্লট_মান 부족 `-28`, মাপ 초과 `-90`을 반환한다. 쓰기는 বৈধকৰণ_কৰক 후 নথিপত্ৰ 전체를 대체한다. `ব্যৱহাৰকৰ্তা.লিখক_বৰ্ণ_মান(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 ব্যৱহাৰকৰ্তা 모드에서 CS의 하위 비트를 직접 읽으므로 প্ৰকৃত_ডাটা নিষ্পাদন_আদেশ 권한을 확인한다. কাৰ্ণেল_মান 포트 접근용 `চেলফোন_মান` native 함수는 ব্যৱহাৰকৰ্তা লক্ষ্য 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 নিষ্পাদন_আদেশ, 파이프, 프로세스 간 통신은 없다. নিষ্পাদন_আদেশ 파일은 커널의 পড়া 전용 JKAP 묶음에서 적재한다. ডাটা 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- ব্যৱহাৰকৰ্তা 가상 ঠিকনা `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. নিষ্পাদন_আদেশ 영상은 앞 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. কাৰ্ণেল_মান identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB ব্যৱহাৰকৰ্তা 영역을 비우고 নথিপত্ৰ 구역을 복사해 BSS·শৃঙ্খলা_মান 영역을 초기화한다. ব্যৱহাৰকৰ্তা GC는 없지만 প্ৰস্থান_এপ্প্ 후 পৰৱৰ্তী_আইটেম নিষ্পাদন_আদেশ 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 কোট/이스케이프 파싱은 없다.
- ব্যৱহাৰকৰ্তা 페이지의 코드/ডাটা 분리 পড়া 전용 বৈশিষ্ট্য, NX, 스택 guard, ASLR은 아직 없다. 커널과 ব্যৱহাৰকৰ্তা মেম_ৰি_ডাটা·포트 অনুমতি_মান 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 নিষ্পাদন_আদেশ 상한을 두며 시간 초과는 `Exit: 124`다. ব্যৱহাৰকৰ্তা CPU 예외는 `128 + 예외 ইনডেক্স`(페이지 ত্ৰুটি 142, 특권 위반 141), Java শৃঙ্খলা_মান/계산 오류는 101~105다. কাৰ্ণেল_মান 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, স্থিৰ_মান IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP 검사합 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- ব্যৱহাৰকৰ্তা নিষ্পাদন_আদেশ·네트워크·প্রতিৰোধ_কৰক_মান 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 নিষ্পাদন_আদেশ·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## বৈধকৰণ_কৰক 근거

`make test`는 컴파일러 14개 시험, Java 패킷 চৰ্ত 2,201개 검사, 기존 শ্বেল ELF/ISO 부팅 시험, ব্যৱহাৰকৰ্তা ELF/প্ৰকৃত_ডাটা UDP/প্রতিৰোধ_কৰক_মান 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 দৈর্ঘ্য_মান·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 কমান্ড·무한 পুণৰাবৃত্তি_মান 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
