# JIndOS 구조

아래는 অবজেক্ট_মান 기반 관리 কাৰ্ণেল_মান 전체의 লক্ষ্য_অবজেক্ট 구조다. 현재 প্ৰকৃত_ডাটা 부팅 가능한 제한형 구현은 `compiler/`와 `os/`에 있으며 [네이티브 অপাৰেটিং_ছিষ্টেম ৰিডমি_ফাইল_eb81d7d9](../os/ৰিডমি_ফাইল_eb81d7d9.md)에 구현 범위를 명시한다. 아래의 GC·প্ৰসংগ_মান সাল_সলনি_মোড·ফাইল_ছিষ্টেম 등이 새 ISO에 모두 포함돼 있지는 않다.

```text
GRUB 또는 UEFI
  ↓
x86 최소 부트·트랩 তৰপ_মান
  ↓
Java AOT 실행기와 অবজেক্ট_মান·শৃঙ্খলা_মান·GC 런타임
  ↓
하드웨어 경계
  ↓
Java 관리 কাৰ্ণেল_মান
  ├─ 기억공간/쪽관리/COW
  ├─ প্ৰক্ৰিয়া_মান/배정/wait
  ├─ ফাইল_ছিষ্টেম/ELF/POSIX
  └─ 입력/ষ্ট_ৰেজ_চেলফোন/নেটৱৰ্ক_ষ্টেক
```

OpenJDK 자체는 이미 운영체제가 제공하는 নথিপত্ৰ, 스레드, 가상 기억공간을 전제로 한다. 따라서 কাৰ্ণেল_মান 부팅에는 OpenJDK를 그대로 넣지 않고 제한된 Java 바이트코드 AOT와 작은 런타임을 사용한다.

네이티브 계층에는 `in/out`, `hlt`, CR0/CR2/CR3/CR4, `iret`, প্ৰসংগ_মান 저장처럼 Java로 표현할 수 없는 CPU 동작만 남긴다. 정책과 자료구조는 Java에 둔다.
