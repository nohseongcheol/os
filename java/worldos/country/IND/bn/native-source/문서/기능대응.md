# engos 기능 대응표

이 표는 기존 `ঐতিহ্য_উত্স/`의 বস্তু_মান 기반 JVM 관리 커널을 설명한다. 새 `compiler/`와 `os/`는 별도 제한형 네이티브 구현이며 [প্রকৃত_ডাটা 부팅 기능과 한계](../os/স্বনিবন্ধ_eb81d7d9.md)를 따로 기록한다.

## Java 관리 স্তর_মান 구현 완료

| engos 영역 | JIndOS 구현 |
|---|---|
| memorymanager, phymem | `মেমরি_ব্যবস্থাপক` সারিকরণ_করা_মান বন্টন_করা_স্টোরেজ·রিলিজ_স্টোরেজ·병합 |
| paging, virtmem | `পৃষ্ঠা_ব্যবস্থাপক` ইমেইল 공간·পৃষ্ঠা_মান সংযোগ_স্থাপনা·COW·개인 লেখা |
| gdt, tss | `전역서술자표`, `কার্য_অবস্হা_অংশ` |
| interrupt | `বিঘ্ন_ব্যবস্থাপক` নিবন্ধন_করুন_ভুক্তি·চালু_করুন·বিতরণ_মান |
| process, scheduler, thread | `প্রসেসর_মান`, `সময়সূচি_নির্ধারণকারী` PID·fork·wait·অবস্হা_মান সুইচ_মোড |
| systemcall/POSIX 1단계 | পড়া·লেখা·খুলুন·বন্ধ_করুন·seek·dup·fcntl·অ্যাক্সেস_ভুক্তি·작업목록·ব্যবহারকারী/무리 ID·সমলয়_করা·brk·fork·wait·exec·stat·uname 의미 |
| ATA | `고급기술결합장치` 512바이트 শাখা_মান_366e0bfa পড়া·লেখা |
| MSDOS partition | `기본분할영역표` MBR 검증과 네 ভুক্তি_মান বিভাজন_করা_মান |
| FAT 공개 নথির_নাম স্তর_মান | `ফাইল_পদ্ধতি`, `파일서술자표` পড়া 전용 파일과 과정별 FD |
| ELF | ELF32 검사, শাখা_মান_366e0bfa ক্লিপ 검사, 적재, NOBITS 영 শুরু_করা, চালনা ইমেইল·প্যারামিটার_যুক্তি·환경 반영 |
| keyboard, mouse | `입력관리자`의 손실 계수 포함 ঘটনা 대기열 |
| timer | `ঘড়ি` 틱과 সময়_মান 변환 |
| PCI | `আনুষঙ্গিক_বাস_ব্যবস্থাপক` 검색 결과와 ডিভাইস_মান বাছাই_মান |

## 기존 বস্তু_মান 기반 관리 কারনেল_মান 전체를 부팅하기 위해 남은 সংযোগ_স্থাপনা

পরবর্তী_দফা 항목은 Java 문법만으로 실행할 수 없는 CPU/ডিভাইস_মান 동작이므로 관리 계층과 별도로 AOT 런타임에 연결해야 한다.

- Multiboot ভুক্তি_বিন্দু_মান, CR0/CR2/CR3/CR4, IDT 적재, `iret`, x86 প্রসঙ্গ_মান ভাণ্ডার_মান
- প্রকৃত_ডাটা PIC/PIT/PS2/ATA/PCI হার্ডওয়্যার_পোর্ট 및 AMD PCnet DMA লুপ_মান
- Java বস্তু_মান·অ্যারে_মান লিংক_লেআউট, ব্যতিক্রম, স্থির_মান শুরু_করা, 가비지 수집기
- 컴파일된 Java 메서드를 freestanding i386 기계어로 바꾸는 AOT স্টেজ_মান
- FAT 디스크 구역을 প্রকৃত_ডাটা ATA 장치와 연결하는 ইনপুট_আউটপুট 접착 স্তর_মান

위 관리 계층은 engos 기능의 Java 관리 구현과 হোস্ট 검증판이다. 별도 `os/`에서는 제한형 AOT, Multiboot ভুক্তি_বিন্দু_মান, স্থির_মান শুরু_করা·পূর্ণসংখ্যা অ্যারে_মান, VGA/직렬/PS2, 명령해석기, ব্যবহারকারী ELF/ring 3/시스템 호출, RTL8139/ARP/IPv4/UDP를 연결해 QEMU 부팅과 হোস্ট 루프백 패킷 왕복을 검증했다. 위 표의 বস্তু_মান 기반 관리 기능 전체나 VirtualBox 네트워크 실행까지 검증했다는 뜻은 아니다.
