# 자체 ARM64 JVM 0.4와 ગુજરાતી લાઇબ્રેરી

ગુજરાતી 통신·예외 사용법은 [ગુજરાતી Java API](한국어자바/રીડમી_eb81d7d9.md), ફંક્શંસ_મૂલ્ય·변수·ફાઈલ 이름의 변경과 어원 근거는 [명명 રીડમી_eb81d7d9](명명/રીડમી_eb81d7d9.md)를 참고한다.

JAR અમલ_કરો_આદેશ, 외부 IPv4 TCP/UDP, 별도 સ્થિર_મૂલ્ય 부분집합 `jaot`와 게스트 C 컴파일은 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)에 설명한다. 아래 ઑબ્જેક્ટ_મૂલ્ય·Thread·Swing은 JVM 경로의 기능이며 AOT સપોર્ટ_મૂલ્ય 범위와 같지 않다.

이 구현은 **Linux 없이 부팅한 Java AOT 커널의 EL0에서 અમલ_કરો_આદેશ**한다. JDK/JRE의 거의 모든 기능을 제공하는 단계는 아직 아니다. HotSpot·OpenJDK વર્ગ_મૂલ્ય લાઇબ્રેરી 전체를 이식하거나 Java SE 인증/TCK를 통과한 구현도 아니다. 이번 확장은 단일 વર્ગ_મૂલ્ય·સ્થિર_મૂલ્ય પદ્ધતિ_મૂલ્ય 중심이던 실행기를 ઑબ્જેક્ટ_મૂલ્ય·લાઇબ્રેરી અમલ_કરો_આદેશ 기반으로 넓힌 것이다.

## 실행과 બિલ્ડ_કરો_સ્રોત

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
# 자체 કર્નેલ_મૂલ્ય 안에서 સ્રોત_ટ્રી બિલ્ડ_કરો_સ્રોત → class અમલ_કરો_આદેશ, ગુજરાતી API 호출
python3 ઉપકરણો/અમલ_કરો_ફાઇલ.py 시험/자바/한글소스.java

# ઑબ્જેક્ટ_મૂલ્ય·예외 등은 હોસ્ટ JDK로 Java 8 class를 만든 후 자체 커널에서 અમલ_કરો_આદેશ
mkdir -p build/my-java
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/my-java 시험/자바/한글시험.java
python3 ઉપકરણો/અમલ_કરો_ફાઇલ.py build/my-java/한글시험.class

# 의존 class 파일은 --include로 함께 સ્થાનાંતર_મૂલ્ય
javac --release 8 -encoding UTF-8 -d build/my-java 시험/자바/객체시험.java
python3 ઉપકરણો/અમલ_કરો_ફાઇલ.py build/my-java/객체시험.class \
  --include build/my-java/વૉલપેપર_મૂલ્ય.class --include build/my-java/શાખા_મૂલ્ય.class \
  --include build/my-java/계산가능.class

make test-jvm
```

`--include DIR`는 그 디렉터리의 class 파일을 재귀적으로 읽어 `패키지.વર્ગ_મૂલ્ય.class`라는 RAM ફાઈલ 이름으로 전송한다. 주 클래스도 패키지가 있다면 `--class-name 패키지.વર્ગ_મૂલ્ય`를 지정한다. 셸에서는 해당 이름으로 업로드하고 `java 패키지.વર્ગ_મૂલ્ય`로 실행한다. JVM 0.4는 Main-Class가 있는 16 KiB 이하 JAR도 `java -jar ફાઈલ.jar`로 실행한다. JAR 모드에서는 JAR 내부 클래스와 내장 ગુજરાતી 클래스만 찾는다. 배포 ગુજરાતી લાઇબ્રેરી JAR는 હોસ્ટ javac의 classpath로 사용하며, 같은 클래스가 ઉપયોગકર્તા JVM ELF에도 વાંચો 전용 자료로 포함된다. 일반 class 모드에서는 사용자가 같은 이름으로 올린 RAM class를 먼저 읽는다.

게스트 `javac`는 여전히 સ્થિર_મૂલ્ય પદ્ધતિ_મૂલ્ય, int/boolean/char/String, શરત·પુનરાવર્તન_મૂલ્ય, સ્ટ્રિંગ_મૂલ્ય 결합, 일부 ફાઈલ 스트림 등의 **자체 부분집합 컴파일러**다. ઑબ્જેક્ટ_મૂલ્ય 선언·상속·try/catch·Thread 사용 소스를 게스트 javac가 모두 컴파일하는 것은 아니다. 위 기능은 `javac --release 8`로 만든 class를 자체 JVM에서 실행한다. ગુજરાતી API 중 આઉટપુટ·문자 스칼라 ફંક્શંસ_મૂલ્ય·ફાઈલ વાંચો/쓰기는 게스트 컴파일러에도 연결했다. 다음처럼 전체 이름으로 호출한다.

```java
public class 인사 {
    public static void main(String[] દલીલો) throws Exception {
        ગુજરાતી.자체.આઉટપુટ.લખો_લાઇન("안녕하세요😀");
        ગુજરાતી.자체.આઉટપુટ.수쓰기(ગુજરાતી.자체.문자.코드포인트수("한글😀"));
        ગુજરાતી.자체.ફાઈલ.લખો("인사.txt", "한글 ફાઈલ😀");
        ગુજરાતી.자체.આઉટપુટ.લખો_લાઇન(ગુજરાતી.자체.ફાઈલ.વાંચો("인사.txt"));
    }
}
```

컬렉션은 지정한 메서드만 제공하며 iterator/stream/સંરેખિત_કરો_મૂલ્ય·ઉપયોગકર્તા વ્યાખ્યા_મૂલ્ય equals/hashCode 콜백은 없다. 사전의 열쇠는 String/Integer/null 사용을 시험했다. UTF-16 코드 단위와 Unicode 코드 포인트 수는 구분한다. 한글 입력 조합·સામાન્ય_બનાવો_મૂલ્ય·아랍어 조판·GUI 다국어 글꼴은 이 સ્ટ્રિંગ_મૂલ્ય 지원과 별개다.

예외는 Throwable/Exception/RuntimeException, ArithmeticException, NullPointerException, IndexOutOfBoundsException/ArrayIndexOutOfBoundsException/StringIndexOutOfBoundsException, IllegalArgumentException/NumberFormatException/IllegalThreadStateException, IOException/FileNotFoundException, IllegalStateException, ClassCastException, NegativeArraySizeException, ArrayStoreException, UnknownHostException, SocketTimeoutException의 제한된 જનરેટ_કરો·શ્રેણી_મૂલ્ય·처리를 제공한다. ઉપયોગકર્તા વ્યાખ્યા_મૂલ્ય Throwable 상속, stack trace/cause/suppressed 예외, try-with-resources의 addSuppressed, 완전한 શરૂ_કરો ભૂલ 포장은 아직 없다. 잡히지 않은 예외는 현재 전체 Java 실행을 실패로 끝낸다.

## ગુજરાતી API

독립 패키지 **`ગુજરાતી.자체`**를 사용한다. Linux판 `ગુજરાતી.자바`가 요구하는 NIO/Swing/HTTP API를 자체 커널에서 실행할 수 있다고 혼동하지 않도록 패키지를 나눴다. 이 라이브러리는 વર્ગ_મૂલ્ય નામ·પદ્ધતિ_મૂલ્ય·દલીલો·ફીલ્ડ_મૂલ્ય·ફાઈલ 이름에 한국어를 사용한다. 표준 Java વર્ગ_મૂલ્ય 이름은 호환성을 위해 보존한다.

| વર્ગ_મૂલ્ય | 공개 기능 | 이름의 의미 |
|---|---|---|
| આઉટપુટ | લખો, લખો_લાઇન, 수쓰기 | આઉટપુટ(出力): 내용을 바깥으로 내보냄 |
| 문자 | લંબાઈ_મૂલ્ય, 같음, ચોંટાડો_પાઠ, કટ_મૂલ્ય, પાર્સ_કરો_પૂર્ણાંક/લખો_પૂર્ણાંક_મૂલ્ય, 코드포인트수, 부호화/ડિક્રિપ્ટ_કરો_ડેટા | 문자(文字), એન્કોડિંગ_મૂલ્ય(符號): 글의 단위와 그 값을 바이트로 나타내는 નિયમ_મૂલ્ય |
| ફાઈલ | વાંચો/લખો(String નામ), 바이트읽기/લખો_બાઇટ_મૂલ્ય | 널리 쓰는 ઉપયોગકર્તા 용어를 보존; RAM 자료의 નામ |
| પ્રવેશ_સૂચી | 더하기, વાંચો, બદલો_મૂલ્ય, 지우기, માપ, ઇન્ટરમિટેંટ_ખાલી_મૂલ્ય, 비우기 | પ્રવેશ_સૂચી(目錄): 순서가 있는 પ્રવેશ_મૂલ્ય 모음 |
| શબ્દકોશ | 넣기, શોધો_પ્રવેશ, 있는가, 지우기, માપ, 비우기 | શબ્દકોશ(辭典): 찾는 말인 열쇠에 값을 대응 |
| 작업 | ચલાવો_2(실행할일), 기다리기(작업가닥), સ્થગિત_કરો_કાર્ય, 살아있는가 | 작업 થ્રેડ_મૂલ્ય: 한 એપ્લિકેશન_f5044b9b 안의 અમલ_કરો_આદેશ સ્ટ્રીમ_મૂલ્ય |
| 통신 | ખોલો, મોકલો, 받기, 대기시간, બંધ_કરો | 통신(通信), 전문(電文), પૉર્ટ_મૂલ્ય: ડેટા 교환·메시지·포트의 역할 |
| 화면 | 사각형, 지우기 | 화면(畫面): વાસ્તવિક_ડેટા 그림을 표시하는 면 |
| કર્નેલ_મૂલ્ય | 밀리초, 사각형 | 자체 JVM의 고정 native સંપર્ક_કરો; 일반 JNI는 아님 |

이 명명은 현재 기능을 설명하는 용어 선택이다. 기존 한국어에 없던 역사적 어원을 만들어 주장하지 않는다. ફાઇલ_નામ_પાઠ·식별자는 UTF-8 소스로 보관한다. `문자.ડિક્રિપ્ટ_કરો_ડેટા`는 잘못된 UTF-8에 IllegalArgumentException을 던지며, `부호화`는 짝이 없는 서로게이트를 `?`로 바꾼다. `ફાઈલ.વાંચો`는 엄격한 UTF-8 복호화를 적용한다. 화면 색은 `빨강 | (초록 << 8) | (파랑 << 16)` 형식이다.

## અમલ_કરો_આદેશ 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(ગુજરાતી વર્ગ_મૂલ્ય 포함), class당 16 KiB·અચલ_મૂલ્ય 풀 511항목, 전체 પદ્ધતિ_મૂલ્ય/ફીલ્ડ_મૂલ્ય 각각 512개. પદ્ધતિ_મૂલ્ય 코드 8 KiB, સ્થાનિક_અવકાશ 변수·피연산자 스택 각각 128슬롯, દલીલો 최대 16개(this 포함).
- VM 가닥은 main 포함 **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 અમલ_કરો_આદેશ 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- ઑબ્જેક્ટ_મૂલ્ય 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 વાસ્તવિક_ડેટા 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 ફાઈલ·대형 સ્ટ્રિંગ_મૂલ્ય·객체가 이 제한을 넘을 수 있다.
- 실행은 50만 바이트코드 આદેશ 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 입력 대기는 기한을 갱신하고 વિંડો સ્વિચ_મોડ 시 중단·재개한다. 일반 સર્વર_મૂલ્ય·계산의 무제한 실행은 아직 없다. 미지원 આદેશ·સાધન_મૂલ્ય 부족은 명시적인 오류로 종료한다.
- RAM ફાઈલ 최대 64개, 파일당 16384바이트, પથ UTF-8 63바이트. RAM 디렉터리와 પીઅર_મૂલ્ય/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 ગુજરાતી class는 RAM ફાઈલ 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 현재 경로에서 સ્રોત_ટ્રી·વર્ગ_મૂલ્ય·ડેટા 파일을 읽는다.
- UDP는 Java 루프백 및 lwIP/SLIP를 통한 외부 IPv4를 제공한다. વાસ્તવિક_ડેટા GENET/Wi-Fi/DNS/TLS/HTTP 전체는 없다. 전문 512바이트, 소켓 8개, 소켓당 큐 4개. receive는 VM 가닥을 양보하며 대기하고 setSoTimeout을 적용하지만 전체 અમલ_કરો_આદેશ 기한은 여전히 적용된다.
- long/float/double, invokedynamic/람다, enum/annotation, 다차원 અરે_મૂલ્ય, 완전한 અરે_મૂલ્ય 공변성·인터페이스 થર_મૂલ્ય 검사, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/એન્ક્રિપ્ટ_કરો_ડેટા/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. Swing의 별도 સપોર્ટ_મૂલ્ય 부분집합은 아래 및 개발 매뉴얼을 참고한다. વર્ગ_મૂલ્ય ફાઈલ 전체 검증기·ઍક્સેસ_પ્રવેશ અનુમતિ_મૂલ્ય/보호된 멤버 검사는 아직 완전하지 않다. 손상된 입력은 EL0 રક્ષણ_કરો_મૂલ્ય 경계 내에서 종료되도록 한다.

전체 OpenJDK를 목표로 하려면 다음은 별도의 주요 구현 단계다: 완전한 JVM મૂલ્ય/માન્ય_કરો/વર્ગ_મૂલ્ય 로더와 예외 모델 → 영속 VFS·mmap·ઘડિયાળ·원자 ઑપરેશન_મૂલ્ય·વાસ્તવિક_ડેટા 스레드/સિંક્રનાઇઝ ABI → OpenJDK java.base 및 native લાઇબ્રેરી 이식 → ડિવાઇસ_મૂલ્ય 네트워크·TCP/IP → વિંડો 시스템/ફૉન્ટ_મૂલ્ય/입력기·java.desktop → Java SE 호환성 시험. 현재 자체 JVM의 일부 메서드를 더하는 것으로 이 작업이 완료되지는 않는다.

## માન્ય_કરો

`ઉપકરણો/자바가상기계시험.py`는 같은 Java 8 class 파일의 출력을 હોસ્ટ OpenJDK `-Xverify:all`과 QEMU raspi4b 자체 커널에서 비교한다. ઑબ્જેક્ટ_મૂલ્ય/상속/인터페이스·switch·અરે_મૂલ્ય, 예외/finally, 컬렉션/GC, Thread/잠금, ગુજરાતી UTF-8/ફાઈલ/컬렉션, વાસ્તવિક_ડેટા UDP 루프백/સમય_મૂલ્ય 초과, 게스트 한글 સ્રોત_ટ્રી બિલ્ડ_કરો_સ્રોત, અરે_મૂલ્ય લખો_મૂલ્ય/ઉદાહરણ_મૂલ્ય/ફાઈલ 경계·한글 패키지의 9개 비교 시험과 잘못된 class 버전/잘린 ફાઈલ નકારો_મૂલ્ય 시험을 실행한다. UDP પ્રોજેક્ટ_રૂટ 실행에는 હોસ્ટ 루프백 소켓 권한이 필요하다.

`ઉપકરણો/부팅시험.py`는 કર્નેલ_મૂલ્ય રક્ષણ_કરો_મૂલ્ય/회귀 시험과 별도로 ગુજરાતી Java 화면 API가 વાસ્તવિક_ડેટા 픽셀을 그렸는지도 QMP 화면 캡처로 검사한다. 보고서는 `build/verification/jvm/report.json`, `build/verification/report.json`이며 시험한 kernel8.img의 SHA-256을 기록한다. વાસ્તવિક_ડેટા Pi4 હાર્ડવેર_મૂલ્ય 부팅 시험과 전체 JDK 호환성 시험 결과는 아니다.


## JVM 0.3: 네트워크와 GUI એક્સ્ટેંશન_મૂલ્ય

`Socket`/`ServerSocket` જનરેટ_કરો·સંપર્ક_કરો·accept·양방향 InputStream/OutputStream·close·EOF·સમય_મૂલ્ય 제한과 UTF-8 `String.getBytes`를 추가했다. JVM 0.4에서는 외부 અંક_મૂલ્ય IPv4 TCP도 lwIP/SLIP에 연결했다. 연결형 અંત_કરો_બિંદુ 16개, Java 루프백 버퍼 1024바이트, 외부 TCP 버퍼 4096바이트다. DNS·TLS는 없다.

`JFrame`, `JPanel`, `JLabel`, `JButton`, `JTextField`, `ActionListener`, `ActionEvent`, `SwingUtilities.invokeLater`의 문서화한 부분집합을 네이티브 GUI에 연결했다. `setLayout(null)`과 명시적 좌표를 사용한다. 전체 OpenJDK Swing 또는 Java SE 호환 구현은 아니다. સહભાગી 이벤트 대기는 અમલ_કરો_આદેશ 기한을 갱신하고 ટર્મિનલ સ્વિચ_મોડ 시 프로세스 상태를 સંગ્રહ_કરવો_મૂલ્ય·복원한다. 이벤트 콜백 자체는 기존 바이트코드/CPU 기한을 따른다.

ગુજરાતી `વિંડો`, `વિજેટ`, `연결통신` 클래스를 배포 JAR와 자체 JVM 내장 자원에 추가했다. 상세 પદ્ધતિ_મૂલ્ય·제한·સ્રોત_ટ્રી·업로드 방법: [한글 개발 매뉴얼](개발안내.md).

## ગુજરાતી 객체의 직접 અમલ_કરો_આદેશ

`વિંડો`, `લેબલ`, `ટેક્સ્ટ_ફીલ્ડ`, `બટન`, `ઇવેંટ_કતાર`, `동작알림`, `작업가닥`은
표준 GUI/Thread 객체를 보관하는 래퍼가 아니다. 자체 JVM의 ઑબ્જેક્ટ_મૂલ્ય જનરેટ_કરો,
સ્વરૂપ_મૂલ્ય 검사, 화면 호출, ઇવેંટ 큐, થ્રેડ_મૂલ્ય 스케줄러에 ગુજરાતી 계약을 직접 구현했다.
표준 `javax.swing`·`Thread` 코드의 અમલ_કરો_આદેશ 경로도 유지한다.
ગુજરાતી 단추와 표준 JButton은 서로 다른 형식이며, 해당 instanceof 검사도 검증한다.

자체 실행기의 ગુજરાતી 진입점은 `public static void ચલાવો_2()`이다.
표준 `main(String[])`도 지원하며 둘 다 있으면 ગુજરાતી 진입점을 우선한다.
명령행 인수는 `실행인수.개수()`와 `실행인수.લખાણ(순번)`으로 읽는다.
`example/java`의 다섯 예제는 이 규약을 사용한다. સ્થિર_મૂલ્ય ફાઈલ 예제는 게스트
javac로도 컴파일하며, GUI/થ્રેડ_મૂલ્ય 소스는 હોસ્ટ `javac --release 8`을 사용한다.
직접 GUI/થ્રેડ_મૂલ્ય API는 자체 JVM 전용이다. 기존 OpenJDK 비교 시험과 별도로
ગુજરાતી 가닥의 અમલ_કરો_આદેશ·પ્રતીક્ષા_મૂલ્ય·중복 ચલાવો_2 નકારો_મૂલ્ય, GUI ઇવેંટ 출처·અનુક્રમણિકા·콜백을 검사한다.
전체 JDK 번역이나 모든 API의 jaot 지원을 뜻하지 않는다.

પદ્ધતિ_મૂલ્ય 이름은 바이트코드에서도 유지된다. 이름과 참조를 같이 수정하면
ગુજરાતી 클래스도 실행되지만, સ્ટ્રિંગ_મૂલ્ય 리터럴·표준 લાઇબ્રેરી 재정의·native
સંપર્ક_કરો·진입점은 각각 컴파일러와 실행기의 계약을 맞춰야 한다.
[상세 계약과 예제](한국어자바/રીડમી_eb81d7d9.md)를 참고한다.

## ટર્મિનલ 부분 તાજું_કરો

ખસેડવું_મૂલ્ય·માપ 변경은 새 વિંડો 영역과 이전 자리에서 드러난 띠만 합성한다.
1920×32 પેલ(240 KiB)의 임시 그림에서 배경·겹친 વિંડો·વર્ણ_મૂલ્ય·GUI를 먼저
완성하고, 현재 શૉ_મૂલ્ય 메모리와 비교하여 달라진 화소만 기록한다.
32줄보다 큰 영역은 여러 띠로 처리하므로 전체 프레임을 원자적으로
교체하거나 수직 동기에 맞추는 방식은 아니다. 전체 배경을 먼저 지우는
중간 화면은 표시하지 않는다. 좌표가 같으면 다시 그리지 않는다.

`make test-redraw`는 વાસ્તવિક_ડેટા C 그리기 코드를 호스트의 મેમરી_ડેટા 화면에 연결해
ખસેડવું_મૂલ્ય 80회·માપ પરિવર્તન_કરો_મૂલ્ય 40회·겹친 વિંડો 4개를 전체 합성 결과와 પેલ 단위로 대조한다.
영역 밖 ઉપયોગકર્તા રેખાંકન_મૂલ્ય, 동일 પેલ 무기록, સૂચક 밑그림, વાસ્તવિક_ડેટા 화면 લાઇન 간격을
검사한다. 이 시험의 시간은 હોસ્ટ CPU 측정이며 Pi 4/QEMU 속도로 해석하지 않는다.
`make test-resize`는 QEMU/VNC의 640×480 및 1920×1080에서 왼쪽 모서리 ખેંચો_મૂલ્ય,
한글 입력·vi 미저장 સામગ્રી_મૂલ્ય·독립 વિંડો 크기를 검사한다.
