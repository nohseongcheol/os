# 셸에서 실행하는 ಬಳಕೆದಾರ 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 README_ಫೈಲ್_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 ಪೂರೈಸು_ಆದೇಶ

ಹೋಸ್ಟ್ ಟರ್ಮಿನಲ್ 1:

```sh
cd /home/user/jkoros
python3 os/ಪರಿಕರಗಳು/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 외부 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

ಹೋಸ್ಟ್ ಟರ್ಮಿನಲ್ 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 ನಿಜವಾದ_ಡೇಟಾ CPU ಅನುಮತಿ_ಮೌಲ್ಯ `ring 3`, 인수 ಔಟ್_ಪುಟ್.
- `netcheck`: ಪೋರ್ಟ್_ಮೌಲ್ಯ 중복, 잘못된 ಹ್ಯಾಂಡಲ್_ಮೌಲ್ಯ/ಸೂಚಕ/ಉದ್ದ_ಮೌಲ್ಯ, 비차단 받기와 ಸಮಯ_ಮೌಲ್ಯ 초과 ಖಚಿತಪಡಿಸಿಕೊಳ್ಳು.
- `udp`: IPv4 ಇಮೇಲ್·ಗಮ್ಯಸ್ಥಾನ_ಮೌಲ್ಯ ಪೋರ್ಟ್_ಮೌಲ್ಯ·한 ಪದ_ಮೌಲ್ಯ 메시지를 받아 UDP로 보내고 같은 응답을 ಖಚಿತಪಡಿಸಿಕೊಳ್ಳು. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: ಹೋಸ್ಟ್ `10.0.2.2`의 ನಿಯೋಜಿಸು_ಮೌಲ್ಯ 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 ಲೂಪ್_ಮೌಲ್ಯ 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 현재 주소는 게스트 `10.0.2.15/24`, ಗೇಟ್_ವೇ_ಮೌಲ್ಯ `10.0.2.2`로 고정돼 있다. QEMU ಬಳಕೆದಾರ 네트워크의 ಹೋಸ್ಟ್ ಪ್ರವೇಶ_ನಮೂದು 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 ಅಪ್ಲಿ_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java ಅಪ್ಲಿ_f5044b9b 추가

`예제/내프로그램.java`를 ಮುಂದೆ_ಅಂಶ 형식으로 만든다. 진입점은 인수 없는 `static int` 또는 `static void` 함수다. 인수는 ಬಳಕೆದಾರ API로 조회한다.

```java
public final class 내프로그램 {
    public static int ಚಲಾಯಿಸು_2() {
        ಬಳಕೆದಾರ.ಬರೆ("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/ಬಳಕೆದಾರ/ಅಪ್ಲಿ_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := ಬಳಕೆದಾರ/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.ಚಲಾಯಿಸು_2
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `ಬಳಕೆದಾರ/ದೃಢೀಕರಣ/ಬಳಕೆದಾರ.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 ಪೂರೈಸು_ಆದೇಶ 중인 VM에는 ಬಿಲ್ಡ್_ಸಿಸ್ಟಂ 결과가 자동 반영되지 않는다. ಅಪ್ಲಿ_f5044b9b 이름은 현재 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java ವರ್ಗ_ಮೌಲ್ಯ_55654bf1·ಕಾರ್ಯ_ಮೌಲ್ಯ·변수에는 한국어를 쓴다. 최대 32개 ಅಪ್ಲಿ_f5044b9b, 한 ಪೂರೈಸು_ಆದೇಶ 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.ಚಲಾಯಿಸು_2 \
    -o os/build/apps/hello.elf os/ಬಳಕೆದಾರ/ದೃಢೀಕರಣ/ಬಳಕೆದಾರ.java os/ಬಳಕೆದಾರ/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 ಹೋಸ್ಟ್ 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 ಬೆಂಬಲ_ಮೌಲ್ಯ ಕ್ಲಿಪ್ 안에서 실행한다. `.jar`와 일반 Linux ಪೂರೈಸು_ಆದೇಶ 파일은 지원하지 않는다.

## ಬಳಕೆದಾರ 네트워크 API

선언은 `ದೃಢೀಕರಣ/ಬಳಕೆದಾರ.java`에 있다. `ಕಳುಹಿಸಿ_ಡೇಟಾ`/`자료받기`의 `int[]` ಅಂಶ_ಮೂಲಾಂಶ 한 개는 ಬೈಟ್_ಮೌಲ್ಯ 하나(0~255)를 나타낸다. 한 데이터그램의 최대 ಡೇಟಾ 길이는 1,024바이트다.

```java
int ಹ್ಯಾಂಡಲ್_ಮೌಲ್ಯ = ಬಳಕೆದಾರ.ರಚಿಸು_ನೆಟ್_ವರ್ಕ್(0); // 0: 임시 ಸ್ಥಳೀಯ_ವ್ಯಾಪ್ತಿ UDP ಪೋರ್ಟ್_ಮೌಲ್ಯ 자동 ಆಯ್ಕೆ_ಮೌಲ್ಯ
int[] ಡೇಟಾ = new int[32];
ಡೇಟಾ[0] = 'H'; ಡೇಟಾ[1] = 'i';
int 보낸길이 = ಬಳಕೆದಾರ.ಕಳುಹಿಸಿ_ಡೇಟಾ(ಹ್ಯಾಂಡಲ್_ಮೌಲ್ಯ, 0x0a000202, 9000, ಡೇಟಾ, 2);
int 받은길이 = ಬಳಕೆದಾರ.자료받기(ಹ್ಯಾಂಡಲ್_ಮೌಲ್ಯ, ಡೇಟಾ, 1500);
ಬಳಕೆದಾರ.ಮುಚ್ಚು_ನೆಟ್_ವರ್ಕ್(ಹ್ಯಾಂಡಲ್_ಮೌಲ್ಯ);
```

ನಿಜವಾದ_ಡೇಟಾ 프로그램에서는 ತೆರೆ·ಕಳುಹಿಸಿ·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 ನಿರೀಕ್ಷಣೆ_ಮೌಲ್ಯ 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 추가 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | ಹ್ಯಾಂಡಲ್_ಮೌಲ್ಯ·ಪ್ರಕ್ರಿಯೆ_ಮೌಲ್ಯ_ನಮೂದು ಉದ್ದ_ಮೌಲ್ಯ·성공 등 해당 함수의 ಮಾಪನ |
| -5 | ಸಾಧನ_ಮೌಲ್ಯ ಕಳುಹಿಸಿ_ಮೌಲ್ಯ ವೈಫಲ್ಯ_ಮೌಲ್ಯ |
| -9 | 잘못되었거나 닫힌 통신 ಹ್ಯಾಂಡಲ್_ಮೌಲ್ಯ |
| -11 | 비차단 받기에서 도착한 ಡೇಟಾ 없음 |
| -14 | ಬಳಕೆದಾರ ಸೂಚಕ/ಅರೇ_ಮೌಲ್ಯ ಕ್ಲಿಪ್ ದೋಷ |
| -19 | ಬೆಂಬಲ_ಮೌಲ್ಯ NIC 없음 |
| -22 | ಪೋರ್ಟ್_ಮೌಲ್ಯ/ನಿರೀಕ್ಷಣೆ_ಮೌಲ್ಯ ಸಮಯ_ಮೌಲ್ಯ/인수 ಮೌಲ್ಯ ದೋಷ |
| -24 | 열린 ನೆಟ್_ವರ್ಕ್_ಪೋರ್ಟ್ 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | ಡೇಟಾ 또는 수신 ಅರೇ_ಮೌಲ್ಯ ಗಾತ್ರ 문제 |
| -98 | ಸ್ಥಳೀಯ_ವ್ಯಾಪ್ತಿ ಪೋರ್ಟ್_ಮೌಲ್ಯ ಪದಸೂಚಿ 중복 |
| -101 | 지원하지 않는 ಗಮ್ಯಸ್ಥಾನ_ಮೌಲ್ಯ ಇಮೇಲ್ |
| -110 | ARP·ಸಾಧನ_ಮೌಲ್ಯ·수신 ಸಮಯ_ಮೌಲ್ಯ 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 ಎನ್ಕೋಡಿಂಗ್_ಮೌಲ್ಯ 있는 Java `int`의 ಬಿಟ್_ಮೌಲ್ಯ 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## ಪೂರೈಸು_ಆದೇಶ 경계와 시스템 호출

```text
ಶೆಲ್ run → JKAP에서 ELF ಸಕ್ರಮೀಕರಿಸು·적재 → ring 3 ಬಳಕೆದಾರ ಅಪ್ಲಿ_f5044b9b
                                 ↓ int 0x80
                      ಸೂಚಕ 검사 → Java ಕರ್ನಲ್_ಮೌಲ್ಯ API → RTL8139/UDP
                                 ↓ ನಿರ್ಗಮನ_ಅಪ್ಲಿ·ವಿನಾಯಿತಿ·ಸಮಯ_ಮೌಲ್ಯ 초과
                                ಶೆಲ್ 복귀
```

시스템 호출 레지스터는 `EAX=ಪದಸೂಚಿ`, `EBX,ECX,EDX,ESI,EDI=인수`, `EAX=ಮಾಪನ`다. Java 호출 스택 ABI는 컴파일러가 ಬಳಕೆದಾರ 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| ಪದಸೂಚಿ | 호출 |
| --- | --- |
| 0 | ನಿರ್ಗಮನ_ಅಪ್ಲಿ(ಸ್ಥಿತಿ_ಮೌಲ್ಯ ಕೋಡ್_ಮೌಲ್ಯ) — ಚಲಾಯಿಸು_2/ದೋಷ 런타임에서 사용 |
| 1 | ಸ್ಟ್ರಿಂಗ್_ಮೌಲ್ಯ ಬರೆ |
| 2 / 3 | 인수 개수 / 인수 ಸ್ಟ್ರಿಂಗ್_ಮೌಲ್ಯ ಇಮೇಲ್ |
| 10 | UDP ತೆರೆ |
| 11 | UDP ಕಳುಹಿಸಿ(ಹ್ಯಾಂಡಲ್_ಮೌಲ್ಯ, IP, ಗಮ್ಯಸ್ಥಾನ_ಮೌಲ್ಯ ಪೋರ್ಟ್_ಮೌಲ್ಯ, ಅರೇ_ಮೌಲ್ಯ ಇಮೇಲ್, ಉದ್ದ_ಮೌಲ್ಯ) |
| 12 | UDP 받기(ಹ್ಯಾಂಡಲ್_ಮೌಲ್ಯ, ಅರೇ_ಮೌಲ್ಯ ಇಮೇಲ್, 제한 밀리초) |
| 13 | UDP ಮುಚ್ಚು |
| 14 | ಸ್ಥಳೀಯ_ವ್ಯಾಪ್ತಿ IP ಇಮೇಲ್ |
| 15 / 16 | 마지막 ಪೀರ್_ಮೌಲ್ಯ IP / UDP ಪೋರ್ಟ್_ಮೌಲ್ಯ |
| 20 | RAM ಕಡತ ಓದು(ಹೆಸರು int[] ಇಮೇಲ್, ಔಟ್_ಪುಟ್ int[] ಇಮೇಲ್) |
| 21 | RAM ಕಡತ ಬರೆ(ಹೆಸರು int[] ಇಮೇಲ್, 입력 int[] ಇಮೇಲ್, ಬೈಟ್_ಮೌಲ್ಯ ಉದ್ದ_ಮೌಲ್ಯ) |
| 22 | UTF-16 ಕೋಡ್_ಮೌಲ್ಯ ಅಧ್ಯಯನ_ಮೌಲ್ಯ 문자 ಔಟ್_ಪುಟ್(0~65535) |

ಕಡತ API는 `ಬಳಕೆದಾರ.파일읽기(int[] ಹೆಸರು, int[] ಡೇಟಾ)`와 `ಬಳಕೆದಾರ.ಬರೆ_ಫೈಲ್(int[] ಹೆಸರು, int[] ಡೇಟಾ, int ಉದ್ದ_ಮೌಲ್ಯ)`다. 이름은 ASCII ಕೋಡ್_ಮೌಲ್ಯ ಅರೇ_ಮೌಲ್ಯ(최대 64칸, 0 ನಿರ್ಗಮನ_ಅಪ್ಲಿ 또는 ಅರೇ_ಮೌಲ್ಯ 끝), ಡೇಟಾ ಅಂಶ_ಮೂಲಾಂಶ 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 ಕಡತ 없음 `-2`, ಸೂಚಕ ದೋಷ `-14`, ಹೆಸರು/ಉದ್ದ_ಮೌಲ್ಯ ದೋಷ `-22`, ಕಡತ ಸ್ಲಾಟ್_ಮೌಲ್ಯ 부족 `-28`, ಗಾತ್ರ 초과 `-90`을 반환한다. 쓰기는 ಸಕ್ರಮೀಕರಿಸು 후 ಕಡತ 전체를 대체한다. `ಬಳಕೆದಾರ.ಬರೆ_ಅಕ್ಷರ_ಮೌಲ್ಯ(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 ಬಳಕೆದಾರ 모드에서 CS의 하위 비트를 직접 읽으므로 ನಿಜವಾದ_ಡೇಟಾ ಪೂರೈಸು_ಆದೇಶ 권한을 확인한다. ಕರ್ನಲ್_ಮೌಲ್ಯ 포트 접근용 `ಸಾಧನ_ಮೌಲ್ಯ` native 함수는 ಬಳಕೆದಾರ ಲಕ್ಷ್ಯ 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 ಪೂರೈಸು_ಆದೇಶ, 파이프, 프로세스 간 통신은 없다. ಪೂರೈಸು_ಆದೇಶ 파일은 커널의 ಓದು 전용 JKAP 묶음에서 적재한다. ಡೇಟಾ 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- ಬಳಕೆದಾರ 가상 ಇಮೇಲ್ `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. ಪೂರೈಸು_ಆದೇಶ 영상은 ಮುಂದೆ_ಮೌಲ್ಯ 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. ಕರ್ನಲ್_ಮೌಲ್ಯ identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB ಬಳಕೆದಾರ 영역을 비우고 ಕಡತ 구역을 복사해 BSS·ಅರೇ_ಮೌಲ್ಯ 영역을 초기화한다. ಬಳಕೆದಾರ GC는 없지만 ನಿರ್ಗಮನ_ಅಪ್ಲಿ 후 ಮುಂದೆ_ಅಂಶ ಪೂರೈಸು_ಆದೇಶ 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 ಕೋಟ್/이스케이프 파싱은 없다.
- ಬಳಕೆದಾರ 페이지의 ಕೋಡ್_ಮೌಲ್ಯ/ಡೇಟಾ 분리 ಓದು 전용 ಸಿದ್ಧತೆಗಳು, NX, 스택 guard, ASLR은 아직 없다. 커널과 ಬಳಕೆದಾರ ಮೆಮೊರಿ_ಡೇಟಾ·포트 ಅನುಮತಿ_ಮೌಲ್ಯ 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 ಪೂರೈಸು_ಆದೇಶ 상한을 두며 ಸಮಯ_ಮೌಲ್ಯ 초과는 `Exit: 124`다. ಬಳಕೆದಾರ CPU 예외는 `128 + ವಿನಾಯಿತಿ ಪದಸೂಚಿ`(페이지 ದೋಷ 142, 특권 위반 141), Java ಅರೇ_ಮೌಲ್ಯ/계산 오류는 101~105다. ಕರ್ನಲ್_ಮೌಲ್ಯ 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, ಸ್ಥಾಯಿ_ಮೌಲ್ಯ IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP 검사합 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- ಬಳಕೆದಾರ ಪೂರೈಸು_ಆದೇಶ·네트워크·ರಕ್ಷಿಸಿ_ಮೌಲ್ಯ 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 ಪೂರೈಸು_ಆದೇಶ·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## ಸಕ್ರಮೀಕರಿಸು 근거

`make test`는 컴파일러 14개 시험, Java 패킷 ಸ್ಥಿತಿ 2,201개 검사, 기존 ಶೆಲ್ ELF/ISO 부팅 시험, ಬಳಕೆದಾರ ELF/ನಿಜವಾದ_ಡೇಟಾ UDP/ರಕ್ಷಿಸಿ_ಮೌಲ್ಯ 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 ಉದ್ದ_ಮೌಲ್ಯ·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 ಆಜ್ಞೆ·무한 ಸ್ಪ್ರಿಂಟ್_ಮೌಲ್ಯ 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
