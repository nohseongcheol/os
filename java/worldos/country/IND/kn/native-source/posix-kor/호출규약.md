# ಬಳಕೆದಾರ 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `ಯಂತ್ರ/ಆಪರೇಟಿಂಗ್_ಸಿಸ್ಟಂ_ಕರೆಗಳು.s`에서 EAX(ಪದಸೂಚಿ), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 인수)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. ಕರ್ನಲ್_ಮೌಲ್ಯ 실패는 음수 ದೋಷ ಪದಸೂಚಿ, C ಲೈಬ್ರರಿ 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 ಬಳಕೆದಾರ 영역 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C ಡೇಟಾ 주소는 ಬೈಟ್_ಮೌಲ್ಯ 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java ಕಡತ 흐름의 어셈블리 경계가 별도 ಬೈಟ್_ಮೌಲ್ಯ 버퍼를 마련하여 같은 호출을 사용한다.

|---|---|---|
| 30 | ರಚಿಸು_ಫೈಲ್ | NUL 끝 ಹೆಸರು ಇಮೇಲ್, ಸಿದ್ಧತೆಗಳು, 허가 |
| 31 | 파일자료읽기 | 서술자, ಡೇಟಾ ಇಮೇಲ್, ಬೈಟ್_ಮೌಲ್ಯ 수 |

| 33 | ಮುಚ್ಚು_ಫೈಲ್ | 서술자 |
| 34 | ಸೀಕ್_ಫೈಲ್ | 서술자, ಎನ್ಕೋಡಿಂಗ್_ಮೌಲ್ಯ 있는 ಆಫ್_ಸೆಟ್_ಮೌಲ್ಯ, ಬಿಂಬಿಸು_ಮೂಲ |

| 39 | ಸೆಟ್_ಫೈಲ್_ಉದ್ದ | 서술자, 새 ಉದ್ದ_ಮೌಲ್ಯ |

| 45 | 통신주소읽기 | 서술자, sockaddr ಇಮೇಲ್, socklen_t ಇಮೇಲ್ |
| 46 | 수신대기정하기 | 서술자, 0~2000 밀리초 |
| 47 | 파일저장확정 | 서술자 |

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 ಇಮೇಲ್ 두 칸이다. 수신 주소가 NULL이면 ಪೀರ್_ಮೌಲ್ಯ ಇಮೇಲ್ 기록을 생략한다. sockaddr_in은 16바이트이며 ಇಮೇಲ್ 체계는 ಸಾಧನ_ಮೌಲ್ಯ ಬೈಟ್_ಮೌಲ್ಯ 차례, 접속번호와 IP 주소는 네트워크 ಬೈಟ್_ಮೌಲ್ಯ 차례다. 축소된 ಇಮೇಲ್ 버퍼에도 들어가는 앞부분을 쓰고 전체 ಇಮೇಲ್ ಗಾತ್ರ 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 ನಿರ್ಗಮನ_ಅಪ್ಲಿ, 2·3은 기존 인수 조회다. 현재 커널의 인수 목록이 ಪೂರೈಸು_ಆದೇಶ 이름을 제외하므로 C 진입기는 argv[0]에 고정 ಸ್ಟ್ರಿಂಗ್_ಮೌಲ್ಯ `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX ಪ್ರಕ್ರಿಯೆ_ಮೌಲ್ಯ ABI와 다른 점이다.

표준 헤더의 ಪೂರ್ಣಸಂಖ್ಯೆ ಗಾತ್ರ, 플래그 ಮೌಲ್ಯ, stat ಕ್ಷೇತ್ರ_ಮೌಲ್ಯ 순서는 `ಮೂಲ/포함/`에 정의한다. 동적 ಸಂಪರ್ಕ_ಕಲ್ಪಿಸು·다중 ಪ್ರಕ್ರಿಯೆ_ಮೌಲ್ಯ·스레드가 추가되면 ದೋಷ ಪದಸೂಚಿ 저장과 ಸಂಪನ್ಮೂಲ_ಮೌಲ್ಯ 수명, 호출 경계도 함께 검토해야 한다.
