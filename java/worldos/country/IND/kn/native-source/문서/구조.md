# JIndOS 구조

아래는 ಆಬ್ಜೆಕ್ಟ್_ಮೌಲ್ಯ 기반 관리 ಕರ್ನಲ್_ಮೌಲ್ಯ 전체의 ಲಕ್ಷ್ಯ_ಆಬ್ಜೆಕ್ಟ್ 구조다. 현재 ನಿಜವಾದ_ಡೇಟಾ 부팅 가능한 제한형 구현은 `compiler/`와 `os/`에 있으며 [네이티브 ಆಪರೇಟಿಂಗ್_ಸಿಸ್ಟಂ README_ಫೈಲ್_eb81d7d9](../os/README_ಫೈಲ್_eb81d7d9.md)에 구현 범위를 명시한다. 아래의 GC·ಸಂದರ್ಭ_ಮೌಲ್ಯ ಸ್ವಿಚ್_ಮಾಡಿ_ಮೋಡ್·ಫೈಲ್_ಸಿಸ್ಟಂ 등이 새 ISO에 모두 포함돼 있지는 않다.

```text
GRUB 또는 UEFI
  ↓
x86 최소 부트·트랩 ಪದರ_ಮೌಲ್ಯ
  ↓
Java AOT 실행기와 ಆಬ್ಜೆಕ್ಟ್_ಮೌಲ್ಯ·ಅರೇ_ಮೌಲ್ಯ·GC 런타임
  ↓
하드웨어 경계
  ↓
Java 관리 ಕರ್ನಲ್_ಮೌಲ್ಯ
  ├─ 기억공간/쪽관리/COW
  ├─ ಪ್ರಕ್ರಿಯೆ_ಮೌಲ್ಯ/배정/wait
  ├─ ಫೈಲ್_ಸಿಸ್ಟಂ/ELF/POSIX
  └─ 입력/ಸಂಗ್ರಹ_ಸಾಧನ/ನೆಟ್_ವರ್ಕ್_ಸ್ಟ್ಯಾಕ್
```

OpenJDK 자체는 이미 운영체제가 제공하는 ಕಡತ, 스레드, 가상 기억공간을 전제로 한다. 따라서 ಕರ್ನಲ್_ಮೌಲ್ಯ 부팅에는 OpenJDK를 그대로 넣지 않고 제한된 Java 바이트코드 AOT와 작은 런타임을 사용한다.

네이티브 계층에는 `in/out`, `hlt`, CR0/CR2/CR3/CR4, `iret`, ಸಂದರ್ಭ_ಮೌಲ್ಯ 저장처럼 Java로 표현할 수 없는 CPU 동작만 남긴다. 정책과 자료구조는 Java에 둔다.
