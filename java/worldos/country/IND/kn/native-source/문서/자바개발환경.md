# jkoros 안에서 Java ಸಂಕಲಿಸು_ಮೂಲ·ಪೂರೈಸು_ಆದೇಶ

이 문서의 부팅·ಶೆಲ್·ಸ್ಟೋರ್_ಮೌಲ್ಯ 명령은 **x86 ಆವೃತ್ತಿ_ಮೌಲ್ಯ** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 ಆವೃತ್ತಿ_ಮೌಲ್ಯ](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 ಫೈಲ್_ಹೆಸರು_ಪಠ್ಯ, `edit`의 단독 `.` ಸ್ಟೋರ್_ಮೌಲ್ಯ, 16개 RAM ಕಡತ, 약 2초 ಪೂರೈಸು_ಆದೇಶ 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 ನಿಜವಾದ_ಡೇಟಾ JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. ಹೋಸ್ಟ್ ಸಂಕಲಿಸು_ಮೂಲ 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java ಅಪ್ಲಿ_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 ಪೂರೈಸು_ಆದೇಶ

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. ಪೂರೈಸು_ಆದೇಶ 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox ಪೂರೈಸು_ಆದೇಶ README_ಫೈಲ್_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 ಕಡತ 전체를 새 내용으로 작성한다. 기존 내용의 ಸಾಲು ಸಂಪಾದನೆ_ಮೌಲ್ಯ 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 ಬೈಟ್_ಮೌಲ್ಯ 수 ಶೋ_ಮೌಲ್ಯ.
- `cat FILE`: ಕಡತ ವಿಷಯ_ಮೌಲ್ಯ ಶೋ_ಮೌಲ್ಯ. 텍스트 소스에 사용한다.
- `rm FILE`: ಮೆಮೊರಿ_ಡೇಟಾ ಕಡತ 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·ಪ್ರಕಾರ_ಮೌಲ್ಯ 검사 ವೈಫಲ್ಯ_ಮೌಲ್ಯ 시 기존 `.class`는 유지된다. 소스를 고친 ಹಿಂದೆ_ಮೌಲ್ಯ 컴파일이 실패했다면 이전 ಪೂರೈಸು_ಆದೇಶ 파일이 남아 있으므로 ಸಂಕಲಿಸು_ಮೂಲ 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 ಸ್ಟೋರ್_ಮೌಲ್ಯ 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 ಮೂಲ_ವೃಕ್ಷ·ವರ್ಗ_ಮೌಲ್ಯ_55654bf1·ಡೇಟಾ 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, ಕಡತ 이름은 ASCII 1~63자다. ಮೂಲ_ವೃಕ್ಷ 이름은 `.class` 확장자 공간 때문에 최대 62자다. ಸಂಪಾದನೆ_ಮೌಲ್ಯ 입력은 ASCII이고 한 ಸಾಲು 최대 128자다. ಸಾಲು 또는 ಕಡತ 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. ಕರ್ನಲ್_ಮೌಲ್ಯ/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 ಬಳಕೆದಾರ 예제 이름은 ASCII로 작성한다.

## 외부 ಕಡತ 적재

호스트에서 만든 소스나 ಬೆಂಬಲ_ಮೌಲ್ಯ ಕ್ಲಿಪ್ 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 ನಿಜವಾದ_ಡೇಟಾ 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# ಹೋಸ್ಟ್ JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 ಮುಂದೆ_ಅಂಶ 빌드에서는 추가 파일을 포함하지 않는다. ಕಡತ ವಿಷಯ_ಮೌಲ್ಯ 변경과 ನಮೂದು_ಪಟ್ಟಿ 제거도 ಮುಂದೆ_ಅಂಶ 빌드에 반영된다. 원본 ಹೋಸ್ಟ್ 파일에는 쓰지 않는다. ಅಕ್ಷಮ_ಬೆಲೆ `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 ಅಕ್ಷಮ_ಬೆಲೆ 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 ವರ್ಗ_ಮೌಲ್ಯ_55654bf1 ಕಡತ 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 ಬೆಂಬಲ_ಮೌಲ್ಯ ಕ್ಲಿಪ್ 안에 있어야 한다.

## ಬೆಂಬಲ_ಮೌಲ್ಯ ಕ್ಲಿಪ್

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| ವರ್ಗ_ಮೌಲ್ಯ_55654bf1 | 패키지 없는 단일 ವರ್ಗ_ಮೌಲ್ಯ_55654bf1, ಸ್ಥಾಯಿ_ಮೌಲ್ಯ ಕಾರ್ಯ_ಮೌಲ್ಯ, 재귀, 인수/반환 | 실행마다 단일 ವರ್ಗ_ಮೌಲ್ಯ_55654bf1 적재, public static main(String[]) |
| ಅಕ್ಷಮ_ಬೆಲೆ ಮೌಲ್ಯ | int, boolean, char, String, main의 String[] 인수 | ಪೂರ್ಣಸಂಖ್ಯೆ·ಉಲ್ಲೇಖ 스택, String, int[], String[], 내부 StringBuilder |
| ಹೇಳಿಕೆ_ಮೌಲ್ಯ | 초기값 있는 ಸ್ಥಳೀಯ_ವ್ಯಾಪ್ತಿ ದೃಢೀಕರಣ, ನಿಯೋಜನೆ_ಮೌಲ್ಯ, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 ಪೂರ್ಣಸಂಖ್ಯೆ·ಉಲ್ಲೇಖ 바이트코드와 ಸ್ಥಿತಿ ಶಾಖೆ |
| ಅಭಿವ್ಯಕ್ತಿ_ಮೌಲ್ಯ | 십진 ಪೂರ್ಣಸಂಖ್ಯೆ, UTF-8 소스의 ಸ್ಟ್ರಿಂಗ್_ಮೌಲ್ಯ/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, ಸ್ಟ್ರಿಂಗ್_ಮೌಲ್ಯ 결합 | ಪೂರ್ಣಸಂಖ್ಯೆ ಆಪರೇಶನ್_ಮೌಲ್ಯ·ಬಿಟ್_ಮೌಲ್ಯ ಆಪರೇಶನ್_ಮೌಲ್ಯ·ಪ್ರಕಾರ_ಮೌಲ್ಯ 변환, 단락 평가, ಅರೇ_ಮೌಲ್ಯ ಪ್ರವೇಶ_ನಮೂದು |
| ಕಡತ | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | ನಿಜವಾದ_ಡೇಟಾ ಕರ್ನಲ್_ಮೌಲ್ಯ 파일서술자와 ಸಂಪರ್ಕ_ಕಲ್ಪಿಸು, ರಚಿಸಿ·ತೆರವುಗೊಳಿಸು_ವಿಷಯಗಳು·이어쓰기·EOF |
| ಔಟ್_ಪುಟ್ | System.out.print/println: int/boolean/char/String, println() | 동일 |
| ಸ್ಟ್ರಿಂಗ್_ಮೌಲ್ಯ/인수 | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), ಸ್ಟ್ರಿಂಗ್_ಮೌಲ್ಯ 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 ಸ್ಥಳೀಯ_ವ್ಯಾಪ್ತಿ ದೃಢೀಕರಣ, 오버로드, 임의 ಪ್ರಕಾರ_ಮೌಲ್ಯ 변환, ಅರೇ_ಮೌಲ್ಯ ರಚಿಸಿ ಮೂಲ, 8/16진 리터럴, Unicode ಮೂಲ_ವೃಕ್ಷ 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 ಸ್ಧಿರ_ಮೌಲ್ಯ 축소 변환을 구현하지 않는다. 외부 `.class`의 `int[]` ರಚಿಸಿ/ಓದು/쓰기는 지원하므로 ಹೋಸ್ಟ್ `javac --release 8`로 만든 ಅರೇ_ಮೌಲ್ಯ 예제는 실행할 수 있다.

ಆಬ್ಜೆಕ್ಟ್_ಮೌಲ್ಯ ಕ್ಷೇತ್ರ_ಮೌಲ್ಯ·일반 ಆಬ್ಜೆಕ್ಟ್_ಮೌಲ್ಯ ರಚಿಸಿ·상속·인터페이스·여러 ವರ್ಗ_ಮೌಲ್ಯ_55654bf1 ಸಂಪರ್ಕ_ಕಲ್ಪಿಸು, long/float/double, ವಿನಾಯಿತಿ ಪ್ರಕ್ರಿಯೆ_ಮೌಲ್ಯ_ನಮೂದು, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java ವಿನಾಯಿತಿ 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 ಸ್ಟ್ರಿಂಗ್_ಮೌಲ್ಯ ಸ್ಟೋರ್_ಮೌಲ್ಯ 공간은 ಪೂರೈಸು_ಆದೇಶ ನಿರ್ಗಮನ_ಅಪ್ಲಿ 시 ಬಳಕೆದಾರ 영역 전체와 함께 회수한다. 지속 ಪೂರೈಸು_ಆದೇಶ 중 GC는 없다.

## ಪೂರೈಸು_ಆದೇಶ 한도와 ದೋಷ

| ಸಂಪನ್ಮೂಲ_ಮೌಲ್ಯ | 한도 |
| --- | --- |
| ಮೂಲ_ವೃಕ್ಷ/ವರ್ಗ_ಮೌಲ್ಯ_55654bf1 ಕಡತ | 각각 16KiB |
| 컴파일러 | ಟೋಕನ್_ಮೌಲ್ಯ 2,047개, ರಚಿಸಿ ಕೋಡ್_ಮೌಲ್ಯ 4KiB, ಸ್ಧಿರ_ಮೌಲ್ಯ 풀 4KiB |
| ಕಾರ್ಯ_ಮೌಲ್ಯ/인수 | 클래스당 32함수, 함수당 16인수 |
| JVM ಸ್ಧಿರ_ಮೌಲ್ಯ | 511개 |
| JVM ಕಾರ್ಯ_ಮೌಲ್ಯ ಕೋಡ್_ಮೌಲ್ಯ | 함수당 8KiB |
| JVM 호출/스택/ಸ್ಥಳೀಯ_ವ್ಯಾಪ್ತಿ 변수 | 32프레임, 프레임당 스택 128칸·ಸ್ಥಳೀಯ_ವ್ಯಾಪ್ತಿ 128칸 |
| JVM ಆಬ್ಜೆಕ್ಟ್_ಮೌಲ್ಯ ಸ್ಟೋರ್_ಮೌಲ್ಯ 공간 | 8,192개 32비트 ಸ್ಲಾಟ್_ನಮೂದು, 헤더 포함 약 32KiB |
| ಪೂರೈಸು_ಆದೇಶ | 최대 500,000 ಆಜ್ಞೆ, 기존 커널의 약 3초 CPU ಪೂರೈಸು_ಆದೇಶ 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 ಬೆಂಬಲ_ಮೌಲ್ಯ 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM ನಿಘಂಟು 검증기를 구현한 것은 아니다. ಕಡತ/ವಿಶೇಷಣ_ಮೌಲ್ಯ ಉದ್ದ_ಮೌಲ್ಯ, ಸ್ಧಿರ_ಮೌಲ್ಯ ಉಲ್ಲೇಖ, ಆಜ್ಞೆ·ಶಾಖೆ 경계를 검사하고, ಪೂರೈಸು_ಆದೇಶ 중 스택 ಸ್ವರೂಪ_ಮೌಲ್ಯ·ಸ್ಥಳೀಯ_ವ್ಯಾಪ್ತಿ ಆರಂಭಗೊಳಿಸು·ಅರೇ_ಮೌಲ್ಯ ಉಪಲಿಪಿ_ಮೌಲ್ಯ·ಆಬ್ಜೆಕ್ಟ್_ಮೌಲ್ಯ 참조를 검사한다. ಬಳಕೆದಾರ 코드의 페이지·포트 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, ಸಂಕಲಿಸು_ಮೂಲ·JVM 오류는 `Exit: 1`, ಆಜ್ಞೆ 인수 오류는 `Exit: 2`다. CPU ಸಮಯ_ಮೌಲ್ಯ 상한은 기존 `Exit: 124`이며, ಬಳಕೆದಾರ ELF 자체의 CPU/런타임 오류는 기존 ನಿರ್ಗಮನ_ಅಪ್ಲಿ 코드를 따른다. ವೈಫಲ್ಯ_ಮೌಲ್ಯ 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## 구현 위치와 시험

- `os/ಬಳಕೆದಾರ/자바/자바컴파일러.java`: 게스트 어휘·구문·ಪ್ರಕಾರ_ಮೌಲ್ಯ 검사, ಸ್ಧಿರ_ಮೌಲ್ಯ 풀 및 바이트코드 ರಚಿಸಿ.
- `os/ಬಳಕೆದಾರ/자바/자바가상기계.java`: ವರ್ಗ_ಮೌಲ್ಯ_55654bf1 적재, 스택·프레임·ಆಬ್ಜೆಕ್ಟ್_ಮೌಲ್ಯ ಸ್ಟೋರ್_ಮೌಲ್ಯ, ಆಜ್ಞೆ 해석과 제한된 표준 호출.
- `os/ಮೂಲ/ಮೆಮೊರಿ_ಫೈಲ್_ಸಿಸ್ಟಂ.java`: ಮೆಮೊರಿ_ಡೇಟಾ ಫೈಲ್_ಸಿಸ್ಟಂ, ಸಂಪಾದನೆ_ಮೌಲ್ಯ, 부팅 ಕಡತ 적재.
- `os/ಮೂಲ/체계호출.java`, `compiler/ಆರಂಭಿಸು_ಬಳಕೆದಾರ_ಅಪ್ಲಿ.s`: ಕಡತ/문자 ಔಟ್_ಪುಟ್ API와 ಬಳಕೆದಾರ ಸೂಚಕ 검사.
- `os/ಪರಿಕರಗಳು/자바파일묶기.py`: ಹೋಸ್ಟ್ 입력 ಕಡತ ಸಕ್ರಮೀಕರಿಸು·부팅 ಸಮೂಹ_ಮೌಲ್ಯ ರಚಿಸಿ.

## Java ಕಡತ ಇನ್_ಪುಟ್_ಔಟ್_ಪುಟ್

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 ವರ್ಗ_ಮೌಲ್ಯ_55654bf1 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 ಹಿಂದೆ_ಮೌಲ್ಯ `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. ಅಕ್ಷಮ_ಬೆಲೆ ಔಟ್_ಪುಟ್ 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. ವಿನಾಯಿತಿ ಆಬ್ಜೆಕ್ಟ್_ಮೌಲ್ಯ·try/catch·try-with-resources는 지원하지 않으며 ಕಡತ 오류를 진단하고 프로그램을 종료한다. ಅರೇ_ಮೌಲ್ಯ ಇನ್_ಪುಟ್_ಔಟ್_ಪುಟ್, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 ಕಡತ 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 ಶೆಲ್ `sync`가 필요하다. 예제의 ಕಡತ 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 ನಿಜವಾದ_ಡೇಟಾ 게스트 ಸಂಕಲಿಸು_ಮೂಲ 결과를 OpenJDK `-Xverify:all`로 다시 실행해 ಕಡತ 바이트와 출력을 대조한다. 범위와 ಸ್ಟೋರ್_ಮೌಲ್ಯ 매체 사용법은 [posix-kor README_ಫೈಲ್_eb81d7d9](../posix-kor/README_ಫೈಲ್_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
