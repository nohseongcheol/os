# 자체 ARM64 JVM 0.4와 한국어 लायब्ररी

한국어 통신·예외 사용법은 [한국어 Java API](한국어자바/README_eb81d7d9.md), फंक्शन_मोल·변수·फायल 이름의 변경과 어원 근거는 [명명 README_eb81d7d9](명명/README_eb81d7d9.md)를 참고한다.

JAR पाळो_दिवचो_आदेश, 외부 IPv4 TCP/UDP, 별도 थीर_मोल 부분집합 `jaot`와 게스트 C 컴파일은 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)에 설명한다. 아래 ऑब्जॅक्ट_मोल·Thread·Swing은 JVM 경로의 기능이며 AOT तेंको_मोल 범위와 같지 않다.

이 구현은 **Linux 없이 부팅한 Java AOT 커널의 EL0에서 पाळो_दिवचो_आदेश**한다. JDK/JRE의 거의 모든 기능을 제공하는 단계는 아직 아니다. HotSpot·OpenJDK वर्ग_मोल_55654bf1 लायब्ररी 전체를 이식하거나 Java SE 인증/TCK를 통과한 구현도 아니다. 이번 확장은 단일 वर्ग_मोल_55654bf1·थीर_मोल पद्दत_मोल 중심이던 실행기를 ऑब्जॅक्ट_मोल·लायब्ररी पाळो_दिवचो_आदेश 기반으로 넓힌 것이다.

## 실행과 दाळचे_स्त्रोत

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
# 자체 कर्नेल_मोल 안에서 स्त्रोत_ट्री दाळचे_स्त्रोत → class पाळो_दिवचो_आदेश, 한국어 API 호출
python3 साधनां/पाळो_दिवचो_फायल.py 시험/자바/한글소스.java

# ऑब्जॅक्ट_मोल·예외 등은 येजमान JDK로 Java 8 class를 만든 후 자체 커널에서 पाळो_दिवचो_आदेश
mkdir -p build/my-java
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/my-java 시험/자바/한글시험.java
python3 साधनां/पाळो_दिवचो_फायल.py build/my-java/한글시험.class

# 의존 class 파일은 --include로 함께 ट्रान्सफर_मोल
javac --release 8 -encoding UTF-8 -d build/my-java 시험/자바/객체시험.java
python3 साधनां/पाळो_दिवचो_फायल.py build/my-java/객체시험.class \
  --include build/my-java/फाटभूंय_मोल.class --include build/my-java/शाखा_मोल.class \
  --include build/my-java/계산가능.class

make test-jvm
```

`--include DIR`는 그 디렉터리의 class 파일을 재귀적으로 읽어 `패키지.वर्ग_मोल_55654bf1.class`라는 RAM फायल 이름으로 전송한다. 주 클래스도 패키지가 있다면 `--class-name 패키지.वर्ग_मोल_55654bf1`를 지정한다. 셸에서는 해당 이름으로 업로드하고 `java 패키지.वर्ग_मोल_55654bf1`로 실행한다. JVM 0.4는 Main-Class가 있는 16 KiB 이하 JAR도 `java -jar फायल.jar`로 실행한다. JAR 모드에서는 JAR 내부 클래스와 내장 한국어 클래스만 찾는다. 배포 한국어 लायब्ररी JAR는 येजमान javac의 classpath로 사용하며, 같은 클래스가 उपेगकर्तो JVM ELF에도 읽기 전용 자료로 포함된다. 일반 class 모드에서는 사용자가 같은 이름으로 올린 RAM class를 먼저 읽는다.

게스트 `javac`는 여전히 थीर_मोल पद्दत_मोल, int/boolean/char/String, स्थिती_291ac971·परतवण_मोल, स्ट्रिंग_मोल 결합, 일부 फायल 스트림 등의 **자체 부분집합 컴파일러**다. ऑब्जॅक्ट_मोल 선언·상속·try/catch·Thread 사용 소스를 게스트 javac가 모두 컴파일하는 것은 아니다. 위 기능은 `javac --release 8`로 만든 class를 자체 JVM에서 실행한다. 한국어 API 중 출력·문자 스칼라 फंक्शन_मोल·फायल 읽기/쓰기는 게스트 컴파일러에도 연결했다. 다음처럼 전체 이름으로 호출한다.

```java
public class 인사 {
    public static void main(String[] 인수) throws Exception {
        한국어.자체.출력.बरोवचें_रेग("안녕하세요😀");
        한국어.자체.출력.수쓰기(한국어.자체.문자.वर्ण_कोड_COUNT("한글😀"));
        한국어.자체.फायल.बरोवचें("인사.txt", "한글 फायल😀");
        한국어.자체.출력.बरोवचें_रेग(한국어.자체.फायल.읽기("인사.txt"));
    }
}
```

## पाळो_दिवचो_आदेश 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(한국어 वर्ग_मोल_55654bf1 포함), class당 16 KiB·अचल_मोल 풀 511항목, 전체 पद्दत_मोल/फिल्ड_मोल 각각 512개. पद्दत_मोल CODE_मोल 8 KiB, थळावो_मळ 변수·피연산자 스택 각각 128슬롯, 인수 최대 16개(this 포함).
- VM 가닥은 main 포함 **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 पाळो_दिवचो_आदेश 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- ऑब्जॅक्ट_मोल 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 प्रत्यक्ष_डेटा 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 फायल·대형 स्ट्रिंग_मोल·객체가 이 제한을 넘을 수 있다.
- 실행은 50만 바이트코드 आदेश 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 입력 대기는 기한을 갱신하고 विंडो स्विच_मोड 시 중단·재개한다. 일반 सर्वर_मोल·계산의 무제한 실행은 아직 없다. 미지원 आदेश·साधनसामुग्री_मोल 부족은 명시적인 오류로 종료한다.
- RAM फायल 최대 64개, 파일당 16384바이트, पाथ UTF-8 63바이트. RAM 디렉터리와 पीयर_मोल/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 한국어 class는 RAM फायल 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 현재 경로에서 स्त्रोत_ट्री·वर्ग_मोल_55654bf1·डेटा 파일을 읽는다.
- UDP는 Java 루프백 및 lwIP/SLIP를 통한 외부 IPv4를 제공한다. प्रत्यक्ष_डेटा GENET/Wi-Fi/DNS/TLS/HTTP 전체는 없다. 전문 512바이트, 소켓 8개, 소켓당 큐 4개. receive는 VM 가닥을 양보하며 대기하고 setSoTimeout을 적용하지만 전체 पाळो_दिवचो_आदेश 기한은 여전히 적용된다.
- long/float/double, invokedynamic/람다, enum/annotation, 다차원 क्रम_मोल_ed437109, 완전한 क्रम_मोल_ed437109 공변성·인터페이스 थर_मोल 검사, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/एनक्रिप्ट_डेटा/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. Swing의 별도 तेंको_मोल 부분집합은 아래 및 개발 매뉴얼을 참고한다. वर्ग_मोल_55654bf1 फायल 전체 검증기·ऍक्सॅस_प्रवेश अनुमती_मोल/보호된 멤버 검사는 아직 완전하지 않다. 손상된 입력은 EL0 राखचें_मोल 경계 내에서 종료되도록 한다.

## JVM 0.3: 네트워크와 GUI विस्तार_मोल

`Socket`/`ServerSocket` तयार_करचें·कनॅक्ट·accept·양방향 InputStream/OutputStream·close·EOF·TIME_मोल 제한과 UTF-8 `String.getBytes`를 추가했다. JVM 0.4에서는 외부 अंक_मोल IPv4 TCP도 lwIP/SLIP에 연결했다. 연결형 सोपोवचें_पॉयंट 16개, Java 루프백 버퍼 1024바이트, 외부 TCP 버퍼 4096바이트다. DNS·TLS는 없다.

`JFrame`, `JPanel`, `JLabel`, `JButton`, `JTextField`, `ActionListener`, `ActionEvent`, `SwingUtilities.invokeLater`의 문서화한 부분집합을 네이티브 GUI에 연결했다. `setLayout(null)`과 명시적 좌표를 사용한다. 전체 OpenJDK Swing 또는 Java SE 호환 구현은 아니다. परस्पर_संवादी 이벤트 대기는 पाळो_दिवचो_आदेश 기한을 갱신하고 टर्मिनल स्विच_मोड 시 프로세스 상태를 Store_मोल·복원한다. 이벤트 콜백 자체는 기존 바이트코드/CPU 기한을 따른다.

한국어 `विंडो`, `विजीट`, `연결통신` 클래스를 배포 JAR와 자체 JVM 내장 자원에 추가했다. 상세 पद्दत_मोल·제한·स्त्रोत_ट्री·업로드 방법: [한글 개발 매뉴얼](개발안내.md).

## 한국어 객체의 직접 पाळो_दिवचो_आदेश

`विंडो`, `लेबल`, `लिखीत_मळ`, `बटन`, `प्रसंग_प्रतिक्षावळ`, `동작알림`, `작업가닥`은
표준 GUI/Thread 객체를 보관하는 래퍼가 아니다. 자체 JVM의 ऑब्जॅक्ट_मोल तयार_करचें,
स्वरूप_मोल 검사, 화면 호출, प्रसंग 큐, थ्रॅड_मोल 스케줄러에 한국어 계약을 직접 구현했다.
표준 `javax.swing`·`Thread` 코드의 पाळो_दिवचो_आदेश 경로도 유지한다.
한국어 단추와 표준 JButton은 서로 다른 형식이며, 해당 instanceof 검사도 검증한다.

자체 실행기의 한국어 진입점은 `public static void चलोवप()`이다.
표준 `main(String[])`도 지원하며 둘 다 있으면 한국어 진입점을 우선한다.
명령행 인수는 `실행인수.आयटम_COUNT()`와 `실행인수.SMS(순번)`으로 읽는다.
`example/java`의 다섯 예제는 이 규약을 사용한다. थीर_मोल फायल 예제는 게스트
javac로도 컴파일하며, GUI/थ्रॅड_मोल 소스는 येजमान `javac --release 8`을 사용한다.
직접 GUI/थ्रॅड_मोल API는 자체 JVM 전용이다. 기존 OpenJDK 비교 시험과 별도로
한국어 가닥의 पाळो_दिवचो_आदेश·대기·중복 चलोवप 거부, GUI प्रसंग 출처·INDEX·콜백을 검사한다.
전체 JDK 번역이나 모든 API의 jaot 지원을 뜻하지 않는다.

पद्दत_मोल 이름은 바이트코드에서도 유지된다. 이름과 참조를 같이 수정하면
한국어 클래스도 실행되지만, स्ट्रिंग_मोल 리터럴·표준 लायब्ररी 재정의·native
कनॅक्ट·진입점은 각각 컴파일러와 실행기의 계약을 맞춰야 한다.
[상세 계약과 예제](한국어자바/README_eb81d7d9.md)를 참고한다.
