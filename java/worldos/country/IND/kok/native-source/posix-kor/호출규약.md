# उपेगकर्तो 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `यंत्र/ऑपरेटिंग_प्रणाली_कॉलां.s`에서 EAX(INDEX), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 인수)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. कर्नेल_मोल 실패는 음수 चूक INDEX, C लायब्ररी 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 उपेगकर्तो 영역 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C डेटा 주소는 बायट_मोल 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java फायल 흐름의 어셈블리 경계가 별도 बायट_मोल 버퍼를 마련하여 같은 호출을 사용한다.

| INDEX | कृती | 인수 |
|---|---|---|
| 30 | उगडचें_फायल | NUL 끝 नांव नामो, मांडावळी, 허가 |
| 31 | 파일자료읽기 | 서술자, डेटा नामो, बायट_मोल 수 |
| 32 | बरोवचें_फायल_डेटा | 서술자, डेटा नामो, बायट_मोल 수 |
| 33 | शेवट_फायल | 서술자 |
| 34 | सोद_फायल | 서술자, एनकोडिंग_मोल 있는 ऑफसॅट_मोल, प्रॉजॅक्ट_रूट |
| 35 | 파일서술자복제 | 서술자 |
| 36 | 파일서술자지정복제 | 서술자, 새 서술자 |

| 38 | काडचें_फायल_प्रवेश_नांव | NUL 끝 नांव नामो |

| 42 | BIND_नामो | 서술자, sockaddr_in नामो, लांबाय_मोल |
| 43 | 자료전문보내기 | 서술자, डेटा नामो, लांबाय_मोल, मांडावळी, 요청 नामो |
| 44 | 자료전문받기 | 서술자, डेटा नामो, लांबाय_मोल, मांडावळी, 요청 नामो |
| 45 | 통신주소읽기 | 서술자, sockaddr नामो, socklen_t नामो |
| 46 | 수신대기정하기 | 서술자, 0~2000 밀리초 |
| 47 | 파일저장확정 | 서술자 |

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 नामो 두 칸이다. 수신 주소가 NULL이면 पीयर_मोल नामो 기록을 생략한다. sockaddr_in은 16바이트이며 नामो 체계는 मोबायल_मोल बायट_मोल SEQUENCE_मोल, 접속번호와 IP 주소는 네트워크 बायट_मोल 차례다. 축소된 नामो 버퍼에도 들어가는 앞부분을 쓰고 전체 नामो आवाठ 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 प्रस्थान_करचें_एप्लिकेशन, 2·3은 기존 인수 조회다. 현재 커널의 인수 목록이 पाळो_दिवचो_आदेश 이름을 제외하므로 C 진입기는 argv[0]에 고정 स्ट्रिंग_मोल `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX प्रक्रिया_मोल ABI와 다른 점이다.

표준 헤더의 पुर्णांक आवाठ, 플래그 मोल, stat फिल्ड_मोल 순서는 `स्त्रोत/포함/`에 정의한다. 동적 कनॅक्ट·다중 प्रक्रिया_मोल·스레드가 추가되면 चूक INDEX 저장과 साधनसामुग्री_मोल 수명, 호출 경계도 함께 검토해야 한다.
