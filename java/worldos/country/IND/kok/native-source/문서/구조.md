# JIndOS 구조

아래는 ऑब्जॅक्ट_मोल 기반 관리 कर्नेल_मोल 전체의 लक्ष्य_ऑब्जॅक्ट 구조다. 현재 प्रत्यक्ष_डेटा 부팅 가능한 제한형 구현은 `compiler/`와 `os/`에 있으며 [네이티브 ऑपरेटिंग_प्रणाली README_eb81d7d9](../os/README_eb81d7d9.md)에 구현 범위를 명시한다. 아래의 GC·मजकूर_मोल स्विच_मोड·फायल_प्रणाली 등이 새 ISO에 모두 포함돼 있지는 않다.

```text
GRUB 또는 UEFI
  ↓
x86 최소 부트·트랩 थर_मोल
  ↓
Java AOT 실행기와 ऑब्जॅक्ट_मोल·क्रम_मोल_ed437109·GC 런타임
  ↓
हार्डवॅर_मोल 경계
  ↓
Java 관리 कर्नेल_मोल
  ├─ 기억공간/쪽관리/COW
  ├─ प्रक्रिया_मोल/배정/wait
  ├─ फायल_प्रणाली/ELF/POSIX
  └─ 입력/सांठवण_मोबायल/नॅटवर्क_स्टॅक
```

OpenJDK 자체는 이미 운영체제가 제공하는 फायल, 스레드, 가상 기억공간을 전제로 한다. 따라서 कर्नेल_मोल 부팅에는 OpenJDK를 그대로 넣지 않고 제한된 Java 바이트코드 AOT와 작은 런타임을 사용한다.

네이티브 계층에는 `in/out`, `hlt`, CR0/CR2/CR3/CR4, `iret`, मजकूर_मोल 저장처럼 Java로 표현할 수 없는 CPU 동작만 남긴다. 정책과 자료구조는 Java에 둔다.
