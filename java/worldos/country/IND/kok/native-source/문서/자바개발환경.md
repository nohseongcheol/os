# jkoros 안에서 Java दाळचे_स्त्रोत·पाळो_दिवचो_आदेश

이 문서의 부팅·शॅल·Store_मोल 명령은 **x86 वर्जन_मोल** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 वर्जन_मोल](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 फायल_नांव_SMS, `edit`의 단독 `.` Store_मोल, 16개 RAM फायल, 약 2초 पाळो_दिवचो_आदेश 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 प्रत्यक्ष_डेटा JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. येजमान दाळचे_स्त्रोत 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java एप्लिकेशन_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 पाळो_दिवचो_आदेश

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. पाळो_दिवचो_आदेश 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox पाळो_दिवचो_आदेश README_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 फायल 전체를 새 내용으로 작성한다. 기존 내용의 रेग संपादन_करचें_मोल 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 बायट_मोल 수 शो_मोल.
- `cat FILE`: फायल अनुक्रमणिका_मोल शो_मोल. 텍스트 소스에 사용한다.
- `rm FILE`: मेमरी_डेटा फायल 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·TYPE_मोल 검사 अपेस_मोल 시 기존 `.class`는 유지된다. 소스를 고친 फाटीं_मोल 컴파일이 실패했다면 이전 पाळो_दिवचो_आदेश 파일이 남아 있으므로 दाळचे_स्त्रोत 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 Store_मोल 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 स्त्रोत_ट्री·वर्ग_मोल_55654bf1·डेटा 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, फायल 이름은 ASCII 1~63자다. स्त्रोत_ट्री 이름은 `.class` 확장자 공간 때문에 최대 62자다. संपादन_करचें_मोल 입력은 ASCII이고 한 रेग 최대 128자다. रेग 또는 फायल 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. कर्नेल_मोल/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 उपेगकर्तो 예제 이름은 ASCII로 작성한다.

## 외부 फायल 적재

호스트에서 만든 소스나 तेंको_मोल क्लिप 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 प्रत्यक्ष_डेटा 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# येजमान JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 फुडलें_आयटम 빌드에서는 추가 파일을 포함하지 않는다. फायल अनुक्रमणिका_मोल 변경과 प्रवेश_सुची 제거도 फुडलें_आयटम 빌드에 반영된다. 원본 येजमान 파일에는 쓰지 않는다. डिफॉल्ट_मोल `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 डिफॉल्ट_मोल 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 वर्ग_मोल_55654bf1 फायल 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 तेंको_मोल क्लिप 안에 있어야 한다.

## तेंको_मोल क्लिप

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| वर्ग_मोल_55654bf1 | 패키지 없는 단일 वर्ग_मोल_55654bf1, थीर_मोल फंक्शन_मोल, 재귀, 인수/return_मेजप | 실행마다 단일 वर्ग_मोल_55654bf1 적재, public static main(String[]) |
| डिफॉल्ट_मोल मोल | int, boolean, char, String, main의 String[] 인수 | पुर्णांक·संदर्भ 스택, String, int[], String[], 내부 StringBuilder |
| निवेदन_मोल | 초기값 있는 थळावो_मळ 선언, प्रकल्प_मोल, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 पुर्णांक·संदर्भ 바이트코드와 स्थिती_291ac971 शाखा |
| ऍक्सप्रॅशन_मोल | 십진 पुर्णांक, UTF-8 소스의 स्ट्रिंग_मोल/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, स्ट्रिंग_मोल 결합 | पुर्णांक क्रिया_मोल·बिट_मोल क्रिया_मोल·TYPE_मोल CONVERT_मोल, 단락 평가, क्रम_मोल_ed437109 ऍक्सॅस_प्रवेश |
| फायल | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | प्रत्यक्ष_डेटा कर्नेल_मोल 파일서술자와 कनॅक्ट, तयार_करचें·पुसचें_TOC·이어쓰기·EOF |
| 출력 | System.out.print/println: int/boolean/char/String, println() | 동일 |
| स्ट्रिंग_मोल/인수 | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), स्ट्रिंग_मोल 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 थळावो_मळ 선언, 오버로드, 임의 TYPE_मोल CONVERT_मोल, क्रम_मोल_ed437109 तयार_करचें स्त्रोत, 8/16진 리터럴, Unicode स्त्रोत_ट्री 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 अचल_मोल 축소 변환을 구현하지 않는다. 외부 `.class`의 `int[]` तयार_करचें/읽기/쓰기는 지원하므로 येजमान `javac --release 8`로 만든 क्रम_मोल_ed437109 예제는 실행할 수 있다.

ऑब्जॅक्ट_मोल फिल्ड_मोल·일반 ऑब्जॅक्ट_मोल तयार_करचें·상속·인터페이스·여러 वर्ग_मोल_55654bf1 कनॅक्ट, long/float/double, 예외 प्रक्रिया_मोल_प्रवेश, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java 예외 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 स्ट्रिंग_मोल Store_मोल 공간은 पाळो_दिवचो_आदेश प्रस्थान_करचें_एप्लिकेशन 시 उपेगकर्तो 영역 전체와 함께 회수한다. 지속 पाळो_दिवचो_आदेश 중 GC는 없다.

## पाळो_दिवचो_आदेश 한도와 चूक

| साधनसामुग्री_मोल | 한도 |
| --- | --- |
| स्त्रोत_ट्री/वर्ग_मोल_55654bf1 फायल | 각각 16KiB |
| 컴파일러 | टोकन_मोल 2,047개, तयार_करचें CODE_मोल 4KiB, अचल_मोल 풀 4KiB |
| फंक्शन_मोल/인수 | 클래스당 32함수, 함수당 16인수 |
| JVM अचल_मोल | 511개 |
| JVM फंक्शन_मोल CODE_मोल | 함수당 8KiB |
| JVM 호출/스택/थळावो_मळ 변수 | 32프레임, 프레임당 스택 128칸·थळावो_मळ 128칸 |
| JVM ऑब्जॅक्ट_मोल Store_मोल 공간 | 8,192개 32비트 स्लॉट_प्रवेश, 헤더 포함 약 32KiB |
| पाळो_दिवचो_आदेश | 최대 500,000 आदेश, 기존 커널의 약 3초 CPU पाळो_दिवचो_आदेश 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 तेंको_मोल 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM डिक्शनरी 검증기를 구현한 것은 아니다. फायल/खाशेलपण_मोल लांबाय_मोल, अचल_मोल संदर्भ, आदेश·शाखा 경계를 검사하고, पाळो_दिवचो_आदेश 중 스택 स्वरूप_मोल·थळावो_मळ प्रारंभ_करचें·क्रम_मोल_ed437109 सबस्क्रिप्ट_मोल·ऑब्जॅक्ट_मोल 참조를 검사한다. उपेगकर्तो 코드의 페이지·हार्डवॅर_पोर्ट 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, दाळचे_स्त्रोत·JVM 오류는 `Exit: 1`, आदेश 인수 오류는 `Exit: 2`다. CPU TIME_मोल 상한은 기존 `Exit: 124`이며, उपेगकर्तो ELF 자체의 CPU/런타임 오류는 기존 प्रस्थान_करचें_एप्लिकेशन 코드를 따른다. अपेस_मोल 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

`os/시험/자바시험.py`는 ELF/ISO 부팅, 게스트 दाळचे_स्त्रोत·पाळो_दिवचो_आदेश, उपेगकर्तो 입력, 재귀·반복문·पुर्णांक 극값·स्ट्रिंग_मोल 결합·단락 평가, 재실행, स्त्रोत_ट्री चूक 후 기존 वर्ग_मोल_55654bf1 보존, क्रम_मोल_ed437109/수 해독 चूक, 무한 परतवण_मोल 제한, संपादन_करचें_मोल 넘침과 फायल 부족을 검사한다. 게스트 तयार_करचें 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 येजमान OpenJDK의 वर्ग_मोल_55654bf1, पुर्णांक 배열과 한글 상수를 게스트에 적재하며, 손상된 फायल 표식·버전·अचल_मोल 수·शाखा·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 시험 VM만 생성하고 종료한다.

구현 형식의 참고 डेटा: Oracle [JVM वर्ग_मोल_55654bf1 फायल 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM आदेश 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java फायल I_O

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 वर्ग_मोल_55654bf1 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 फाटीं_मोल `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. डिफॉल्ट_मोल 출력 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. 예외 ऑब्जॅक्ट_मोल·try/catch·try-with-resources는 지원하지 않으며 फायल 오류를 진단하고 프로그램을 종료한다. क्रम_मोल_ed437109 I_O, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 फायल 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 शॅल `sync`가 필요하다. 예제의 फायल 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 प्रत्यक्ष_डेटा 게스트 दाळचे_स्त्रोत 결과를 OpenJDK `-Xverify:all`로 다시 실행해 फायल 바이트와 출력을 대조한다. 범위와 Store_मोल 매체 사용법은 [posix-kor README_eb81d7d9](../posix-kor/README_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
