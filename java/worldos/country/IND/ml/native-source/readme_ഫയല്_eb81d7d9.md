# JIndOS

현재 자체 ARM64 배포판은 [LICENSE](LICENSE)의 COSL 상업 조건을 유지한다. 제3자 라이선스의 권리는 별도로 보장하며, 배포 시 ഉറവിടം_ശാഖി·재연결 자료를 포함하는 절차는 [COSL 배포 readme_ഫയല്_eb81d7d9](platforms/rpi4-native/COSL배포안내.md)에 있다.

자체 ARM64 판의 `ipconfig`/`ip`, `ping`, `ps`/`top`, `free`/`df`, `poweroff`와 한국어 명령은 [네트워크·ഓപ്പറേറ്റിംഗ്_സിസ്റ്റം_മൂല്യം ആജ്ഞ readme_ഫയല്_eb81d7d9](platforms/rpi4-native/네트워크와체계명령.md)를 참고한다. 새 커널을 부팅한 പിന്നിലേക്ക്_മൂല്യം `help system`으로 볼 수 있다.

Raspberry Pi 4 **자체 Java ARM64 കെര്_ണല്_മൂല്യം**은 [자체 Pi4 readme_ഫയല്_eb81d7d9](platforms/rpi4-native/readme_ഫയല്_eb81d7d9.md)에 있다. Linux 없이 부팅하며 GUI ടെ_ര്മിനല്·vi, 자체 JVM의 Swing 일부 API, TCP/UDP·FTP, 게스트 TinyCC·MicroPython, C/C++의 posix-kor 호출을 제공한다. [한국어 Java 통신·ഒഴിവാക്കൽ API](platforms/rpi4-native/한국어자바/readme_ഫയല്_eb81d7d9.md)와 [한국어 ഉറവിടം_ശാഖി 명명](platforms/rpi4-native/명명/readme_ഫയല്_eb81d7d9.md)을 지원한다. [자체 SSH·VNC 및 GENET 드라이버](platforms/rpi4-native/외부접속안내.md)를 포함하며, 네트워크는 QEMU의 UART SLIP 경로로 검증했다. വാസ്തവമായ_ഡാറ്റാ Pi 4 GENET 동작은 미검증이고, USB 입력·영속 저장과 전체 OpenJDK·Swing은 아직 പിന്തുണ_മൂല്യം ക്ലിപ്പ് 밖이다.

Raspberry Pi 4용 Linux·OpenJDK 실행판과 ഉപയോക്താവ് 환경 നീക്കുക_മൂല്യം 기능은 [라즈베리파이 실행판](platforms/rpi4/README.md)에 있다. വാസ്തവമായ_ഡാറ്റാ ARM64 JDK/JRE와 시스템·ഉപയോക്താവ് ബിൽഡ്_ഇമേജ് ബിൽഡ്_సిస్టమ్ 경로를 제공한다. 기존 자체 x86 커널과는 별도 നടപ്പാക്കുക_കമാന്_ഡ് 기반이다. 일반 Java `.class`/JAR의 നടപ്പാക്കുക_കമാന്_ഡ് ഫയല് 생성은 [OpenJDK നടപ്പാക്കുക_കമാന്_ഡ് ഫയല്](compiler/OpenJDK-നിര്_വ്വഹണക്ഷമമായ_ഫയല്.md), 한국어 API는 [한국어 Java లైబ్రరీ](한국어자바/readme_ഫയല്_eb81d7d9.md)를 참고한다.

`jkoros`는 `engos`의 기능을 Java 관리 커널로 옮기는 프로젝트다. 프로젝트가 소유하는 Java കാര്യപ്രവര്_ത്തനം_മൂല്യം, 변수, ఫార్మాట్_മൂല്യം 및 Java ഫയല് 이름은 한국어로 작성한다. 표준 Java 실행기의 `main`, Java 표준 లైబ్రరీ ఫార్మాట్_മൂല്യം, x86 부트 ABI 등 외부 계약은 보존한다. 자체 ARM64 실행기는 한국어 `നടപ്പിലാക്കുക()`도 진입점으로 지원하며, 한국어 GUI·작업 가닥을 JVM에 직접 구현했다. 자체 ARM64 C 연결부·Python 도구와 공용 x86·ARM64 AOT 번역기의 자체 이름도 한국어로 작성한다. 이전 경로의 호환 എന്_ട്രി_പോയിന്_റ്, OpenJDK 보조 도구와 Linux പതിപ്പ്_മൂല്യം 도구에는 영어 이름이 남아 있고 [명명 원칙·말의 근거·전체 ഉറവിടം 검토 ക്ലിപ്പ്](platforms/rpi4-native/명명/readme_ഫയല്_eb81d7d9.md)를 별도로 기록한다.

## 현재 구현

아래 목록은 기존 `പാരമ്പര്യ_ഉറവിടം/`의 JVM 관리 커널에 대한 것이다. വാസ്തവമായ_ഡാറ്റാ 네이티브 커널의 범위는 `os/readme_ഫയല്_eb81d7d9.md`에서 별도로 설명한다.

- വിന്യസിക്കുക_മൂല്യം 할당과 해제를 지원하는 기억공간 മാനേജര്_മൂല്യം
- ഇമെയിൽ 공간, പേജ്_മൂല്യം കണക്ടു്_ചെയ്യുക, എഴുത്തു് 시 ദൃഷ്ടാന്തം_മൂല്യം(COW)
- പ്രോസസ്_മൂല്യം ఐడెంటిఫయర్_മൂല്യം, തയ്യാറാക്കുക 대기열, fork/wait അവസ്ഥ_മൂല്യം
- 과정별 ഫയല് 서술자, open/read/seek/dup/close
- ELF32 식별 및 വിഭാഗം_മൂല്യം 검사
- 키보드·마우스 입력 ഇവന്റ് 대기열
- 직렬 단말과 네이티브 하드웨어 경계
- 관리 കെര്_ണല്_മൂല്യം 전체 자동 시험

세부 대응 범위와 아직 필요한 네이티브 연결은 [기능 대응표](문서/기능대응.md)에 기록한다.

## 빌드와 시험

새 네이티브 구현은 `compiler/`와 `os/`에 있다. 기존 `പാരമ്പര്യ_ഉറവിടം/`의 JVM 관리 커널은 그대로 보존하며, 두 구현의 시험과 기능 범위는 서로 다르다.

```sh
cd /home/user/jkoros
make                 # 네이티브 계산 예제 + Java കെര്_ണല്_മൂല്യം ELF
make iso             # os/build/kernel.iso
make run             # QEMU 직렬 단말; help 입력 (종료는 Ctrl+A, X)
make run-gui         # ISO를 QEMU 화면/PS2 키보드로 നടപ്പാക്കുക_കമാന്_ഡ്
make vbox            # 전용 VirtualBox VM 자동 സൃഷ്_ടിക്കുക·നടപ്പാക്കുക_കമാന്_ഡ് (GUI)
make vbox-status     # VirtualBox അവസ്ഥ_മൂല്യം·ISO·직렬 ലോഗ്_രേഖ വഴി പരിശോധിക്കുക
make test-vbox       # VirtualBox പ്രോഗ്രാം_ആപ്പ്_ഡ്രോയർ അവസ്ഥ_മൂല്യം പ്രോസസ്_മൂല്യം_എന്_ട്രി 시험 (വാസ്തവമായ_ഡാറ്റാ VM മാറ്റികൊടുക്കുക_മൂല്യം 없음)
make test            # 컴파일러 시험 + ELF/ISO 부팅 및 ആജ്ഞ 입력 시험
make apps            # 독립 ഉപയോക്താവ് ELF പ്രോഗ്രാം_f5044b9b ബിൽഡ്_సిస్టమ్
make test-network    # ഉപയോക്താവ് മോഡ്_മൂല്യം·UDP 왕복·മെമ്മറി_ഡാറ്റാ പരിരക്ഷിക്കുക_മൂല്യം 시험
make test-java       # 게스트 javac/JVM + OpenJDK 양방향 교차 നടപ്പാക്കുക_കമാന്_ഡ് 시험
make posix-kor       # 한국어 C 헤더와 വാസ്തവമായ_ഡാറ്റാ കെര്_ണല്_മൂല്യം 호출 లైబ్రరీ
make test-posix      # ഫയല്/UDP/സ്_റ്റോർ_മൂല്യം/Java ഫയല് ഇന്_പുട്ട്_ഔട്ട്_പുട്ട് 시험
make -C os run-store # 전용 സ്_റ്റോർ_മൂല്യം 매체로 QEMU 부팅
make legacy-test     # 아래 기존 JVM 관리 커널의 47개 시험
```

`compiler/`는 호스트의 `javac`를 문법·ടൈപ്പ്_ചെയ്യുക_മൂല്യം 검사 전단으로 사용하고 자체 바이트코드→x86 변환기로 ELF32 기계어를 만든다. 빌드할 때는 JDK가 필요하지만 생성된 커널과 ELF는 외부 JVM 없이 실행된다. 전체 Java, ഓബ്ജക്റ്റ്_മൂല്യം 모델, 표준 라이브러리와 기존 관리 കെര്_ണല്_മൂല്യം 전체의 AOT 변환은 아직 지원하지 않는다. 자세한 പിന്തുണ_മൂല്യം 문법과 명령은 [컴파일러 readme_ഫയല്_eb81d7d9](compiler/readme_ഫയല്_eb81d7d9.md), വാസ്തവമായ_ഡാറ്റാ 부팅 기능과 한계는 [네이티브 ഓപ്പറേറ്റിംഗ്_സിസ്റ്റം readme_ഫയല്_eb81d7d9](os/readme_ഫയല്_eb81d7d9.md)를 참고한다.

네이티브 셸에 자체 제한형 `javac`와 `java`를 추가했다. `edit Demo.java`로 소스를 입력하고 `.save`로 저장한 പിന്നിലേക്ക്_മൂല്യം `javac Demo.java`, `java Demo`로 **게스트 내부에서 컴파일하고 നടപ്പാക്കുക_കമാന്_ഡ്**할 수 있다. സ്ഥിരസ്ഥിതി_മൂല്യം 예제는 `javac Hello.java`, `java Hello`다. 파일은 RAM에서 동작하며, 전용 സ്_റ്റോർ_മൂല്യം 매체를 연결하면 `sync`로 재부팅 후에도 보존할 수 있다. **OpenJDK/JDK 전체 이식은 아니며**, 단일 ക്ലാസ്_മൂല്യം·സ്ഥിരമായ_മൂല്യം കാര്യപ്രവര്_ത്തനം_മൂല്യം·പൂര്_ണ്ണസംഖ്യ·സ്ട്രിംഗ്_മൂല്യം·അവസ്ഥ/반복문과 일부 표준 호출을 지원한다. പിന്തുണ_മൂല്യം ക്ലിപ്പ്, 외부 ഫയല് 적재와 시험은 [Java 개발 환경 readme_ഫയല്_eb81d7d9](문서/자바개발환경.md)에 있다.

네이티브 셸에서 `apps`, `run hello first second`, `net`, `run netcheck`를 사용할 수 있다. 독립 ELF를 ring 3에 적재하고 `int 0x80` 호출을 통해 ഫലം·인수·UDP 네트워크를 제공한다. 별도 ഹോസ്റ്റ് 터미널에서 `python3 os/ഉപകരണങ്ങൾ/자료되돌리기.py --port 9000`을 실행한 പിന്നിലേക്ക്_മൂല്യം 게스트에서 `run udp 10.0.2.2 9000 hello`로 വാസ്തവമായ_ഡാറ്റാ 왕복을 확인한다. 새 പ്രോഗ്രാം_f5044b9b രജിസ്_റ്റർ_ചെയ്യുക_എന്_ട്രി, API 및 제한은 [ഉപയോക്താവ് നടപ്പാക്കുക_കമാന്_ഡ്·네트워크 readme_ഫയല്_eb81d7d9](os/ഉപയോക്താവ്/readme_ഫയല്_eb81d7d9.md)를 참고한다. 현재 QEMU RTL8139·സ്ഥിരമായ_മൂല്യം IPv4·UDP 전용이며 TCP/DNS는 미지원이며, 전용 IDE സ്_റ്റോർ_മൂല്യം 형식과 POSIX ഫയല്/UDP 일부 기능을 추가했다.

`make vbox`는 `jkoros operating system` 전용 VM을 만들고 디스크 없이 ISO로 부팅한다. നടപ്പാക്കുക_കമാന്_ഡ് 중이면 유지하고, സ്_റ്റോർ_മൂല്യം·일시정지 상태이면 재개하며, 꺼져 있을 때만 새 ISO를 빌드해 연결한다. VirtualBox에서 부팅과 셸의 ഉപയോക്താവ് പ്രോഗ്രാം_f5044b9b 실행을 확인했다. 다만 현재 VirtualBox용 네트워크 드라이버는 없어 네트워크 장치를 비활성화한다. UDP 시험에는 `make run`을 사용한다. 상태별 동작과 새 ബിൽഡ്_సిస్టమ్ 반영 방법은 [VirtualBox നടപ്പാക്കുക_കമാന്_ഡ് readme_ഫയല്_eb81d7d9](문서/가상상자실행.md)에 있다.

기존 관리 커널만 시험하려면:

```sh
cd /home/user/jkoros
make -f സൃഷ്_ടിക്കുക_എന്_ട്രി.mk 검사
make -f സൃഷ്_ടിക്കുക_എന്_ട്രി.mk ഹോസ്റ്റ്
```

`ഹോസ്റ്റ്`는 여전히 JVM 관리 계층의 നടപടി 시험이다. `make -f സൃഷ്_ടിക്കുക_എന്_ട്രി.mk ബിൽഡ്_ഇമേജ്`는 새 `os/`의 제한형 네이티브 കെര്_ണല്_മൂല്യം ISO를 만든다. 기존 `പാരമ്പര്യ_ഉറവിടം/`의 ഫയല്_സിസ്റ്റം·പ്രോസസ്_മൂല്യം·നെറ്റ്_വർക്ക്_സ്റ്റാക്ക്_ചെയ്യുക 구현 전체를 이 ISO에 이식했다는 의미는 아니다.

한국어 കാര്യപ്രവര്_ത്തനം_മൂല്യം·변수·ഫയല് 이름과 വാസ്തവമായ_ഡാറ്റാ C API는 [posix-kor](posix-kor/readme_ഫയല്_eb81d7d9.md)에 있다. 게스트 Java에서는 `FileInputStream`·`FileOutputStream`의 단일 బైట్_മൂല്യം 입출력도 지원한다. 전체 POSIX·OpenJDK·Swing 지원으로 확대된 것은 아니다.

외부 배포용 `pack.sh` / `unpack.sh`와 자동 의존성 복원은 [배포 readme_ഫയല്_eb81d7d9](distribution/README.md)를 참고하세요.
