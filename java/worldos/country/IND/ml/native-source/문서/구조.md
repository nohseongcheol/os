# JIndOS 구조

아래는 ഓബ്ജക്റ്റ്_മൂല്യം 기반 관리 കെര്_ണല്_മൂല്യം 전체의 ലക്ഷ്യം_ഓബ്ജക്റ്റ് 구조다. 현재 വാസ്തവമായ_ഡാറ്റാ 부팅 가능한 제한형 구현은 `compiler/`와 `os/`에 있으며 [네이티브 ഓപ്പറേറ്റിംഗ്_സിസ്റ്റം readme_ഫയല്_eb81d7d9](../os/readme_ഫയല്_eb81d7d9.md)에 구현 범위를 명시한다. 아래의 GC·സന്ദര്_ഭം_മൂല്യം സ്വിച്ച്_മോഡ്·ഫയല്_സിസ്റ്റം 등이 새 ISO에 모두 포함돼 있지는 않다.

```text
GRUB 또는 UEFI
  ↓
x86 최소 부트·트랩 ലെയര്_മൂല്യം
  ↓
Java AOT 실행기와 ഓബ്ജക്റ്റ്_മൂല്യം·അരേ_മൂല്യം·GC 런타임
  ↓
하드웨어 경계
  ↓
Java 관리 കെര്_ണല്_മൂല്യം
  ├─ 기억공간/쪽관리/COW
  ├─ പ്രോസസ്_മൂല്യം/배정/wait
  ├─ ഫയല്_സിസ്റ്റം/ELF/POSIX
  └─ 입력/സംഭരണം_മൊബൈൽ/നെറ്റ്_വർക്ക്_സ്റ്റാക്ക്_ചെയ്യുക
```

OpenJDK 자체는 이미 운영체제가 제공하는 ഫയല്, 스레드, 가상 기억공간을 전제로 한다. 따라서 കെര്_ണല്_മൂല്യം 부팅에는 OpenJDK를 그대로 넣지 않고 제한된 Java 바이트코드 AOT와 작은 런타임을 사용한다.

네이티브 계층에는 `in/out`, `hlt`, CR0/CR2/CR3/CR4, `iret`, സന്ദര്_ഭം_മൂല്യം 저장처럼 Java로 표현할 수 없는 CPU 동작만 남긴다. 정책과 자료구조는 Java에 둔다.
