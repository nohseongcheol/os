# 일반 Java 클래스의 आज्ञा_कार्यवाही_करा फाइल प्रविष्टी_तयार_करा

OpenJDK 자체를 소스에서 만드는 기능은 [OpenJDK स्रोत_ट्री 빌드와 स्वकीय गाभा_मूल्य अनुकूलन](जावाविकाससंच_स्रोत_बांधणी_आणि_गाभा_पॉर्ट_उघडा.md)의 `openjdk-build` 대상이다. तळ_मूल्य `openjdk` 대상은 Java 응용프로그램 포장 기능이다.

`--target openjdk`는 OpenJDK로 실행하는 네이티브 ELF 실행기와 `.app` डेटा 폴더를 만든다. Java 바이트코드를 सर्व_बांधणी 기계어로 미리 변환하는 AOT는 아니다. ऑब्जेक्ट_मूल्य·상속·인터페이스·अपवाद·스레드·리플렉션·람다·표준 라이브러리는 설치된 OpenJDK가 실행하며, 필요한 코드는 JVM의 JIT가 기계어로 컴파일한다.

```sh
python3 compiler/संकलक.py --target openjdk --entry उदाहरणे.Main \
  -o build/अनुप्रयोग_f5044b9b build/classes
./build/अनुप्रयोग_f5044b9b "फॉरवर्ड_मूल्य बाबी"
```

Pi 실행판에서는 같은 도구가 `jclassc` 명령으로 설치된다.

```sh
jclassc --target openjdk --entry Main -o अनुप्रयोग_f5044b9b Main.java
jclassc --target openjdk --entry Main -o अनुप्रयोग_f5044b9b Main.class
jclassc --target openjdk --entry Main --classpath helper.jar -o अनुप्रयोग_f5044b9b app.jar
jclassc --target openjdk --entry Main --bundle-runtime /usr/lib/jvm/java-25-jre \
  -o अनुप्रयोग_f5044b9b classes
```

입력은 `.java`, `.class`, `.jar`/`.zip`, 또는 컴파일된 클래스와 리소스가 있는 디렉터리다. शेवटीजोडा_प्रविष्टी 의존성은 `--classpath`를 반복해서 지정한다. 개별 `.class` 입력은 फाइल 내부의 वर्ग_मूल्य 이름을 읽어 올바른 패키지 경로에 배치한다. 내부 वर्ग_मूल्य·다른 वर्ग_मूल्य·리소스까지 포함하려면 वर्ग_मूल्य 디렉터리를 전달한다. स्रोत 입력은 `javac`로 컴파일한 नंतर_राज्य 포함한다.

आज्ञा_कार्यवाही_करा फाइल `अनुप्रयोग_f5044b9b`과 `अनुप्रयोग_f5044b9b.app`를 **함께** 이동한다. सध्याचे_आयटम पारपाडा_कार्य 폴더와 관계없이 자신의 경로를 기준으로 자료를 찾는다. संचालनप्रणाली·CPU는 빌드한 실행기와 일치해야 한다. `--cc`로 C 컴파일러를 지정할 संख्या 있으며, Pi에서는 डिफॉल्ट_मूल्य GCC가 ARM64 실행기를 만든다. 번들 런타임을 지정하지 않으면 `JAVA_HOME/bin/java` 또는 PATH의 `java`를 사용한다.

आज्ञा_कार्यवाही_करा 가능한 응용프로그램은 `public static void main(String[])` प्रविष्टी_गुण_मूल्य 클래스가 필요하다. लायब्ररी·인터페이스·`module-info.class` 하나만으로 आज्ञा_कार्यवाही_करा 프로그램이 되지는 않는다. वर्ग_मूल्य 버전을 지원하는 JDK, बाह्य_मूल्य JAR, JNI 네이티브 लायब्ररी, वापर_मूल्य 장치와 권한은 해당 프로그램의 요구사항에 맞춰 제공해야 한다. मॉड्यूल_मूल्य मार्ग·शेवटीजोडा_प्रविष्टी JVM 설정이 필요한 응용프로그램은 별도 आज्ञा_कार्यवाही_करा 설정이 필요하다. `JDK_JAVA_OPTIONS`로 JVM 옵션을 전달할 संख्या 있다. 모든 बाह्य_मूल्य Java 응용프로그램을 개별 검증했다는 뜻은 아니다.

기존 `linux`, `kernel`, `user` 대상은 제한형 x86 ELF32 AOT로 유지된다. 이 경로에도 `.class` 직접 입력을 추가했지만 지원하지 않는 ऑब्जेक्ट_मूल्य·표준 라이브러리를 자동으로 네이티브 변환하지는 않는다. ARM64 Linux에서 사용할 때는 `openjdk` 대상을 선택한다.
