# OpenJDK स्रोत_ट्री 빌드와 स्वकीय Java गाभा_मूल्य अनुकूलन

**소스에서 OpenJDK를 만드는 일과, 그 결과를 स्वकीय 커널에서 실행하는 일은 별도다.**
`compiler`에 공식 OpenJDK 빌드를 실행하는 `openjdk-build` 대상을 추가했다.
Java 코드에는 부트 JDK의 javac, HotSpot·네이티브 라이브러리에는 C/C++ 도구를 사용한다.
기존 स्वकीय Java AOT 후단이 Java 전체나 C++ 전체를 처리하게 된 것은 아니다.

## स्रोत_बांधणी 경로의 डीलिमीटर_मूल्य

| लक्ष्य | 입력과 मोजमाप | आज्ञा_कार्यवाही_करा सशर्त |
|---|---|---|
| `linux`, `kernel`, `user` | 제한된 Java → स्वकीय x86 AOT → ELF32 | 해당 CPU·स्वकीय ABI |
| `arm64.py` | 제한된 Java class → freestanding C → AArch64 | स्वकीय ARM64 गाभा_मूल्य/प्रयोक्ता ABI |
| `openjdk` | Java 앱 → 기존 OpenJDK를 호출하는 실행기와 `.app` | 일치하는 OS/CPU의 설치된 JVM |
| **`openjdk-build`** | OpenJDK 전체 स्रोत_ट्री → 공식 configure/make → JDK चित्र_बांधणी | **सिस्टम_बांधणी लक्ष्य OS/CPU의 आज्ञा_कार्यवाही_करा काम_मूल्य** |

OpenJDK는 Java फाइल 묶음만으로 이루어져 있지 않다. HotSpot VM, JNI जोडा,
वर्ग_मूल्य 라이브러리의 C/C++ अंमलबजावणी, अनुप्रयोग_चालक, मॉड्यूल_मूल्य चित्र_बांधणी 및 तयार_करा 도구를 함께 빌드한다.
따라서 स्वकीय AOT에 Java 명령을 더하는 것만으로 OpenJDK 전체 빌드가 완성되지는 않는다.
공식 절차는 [OpenJDK सिस्टम_बांधणी मार्गदर्शिका](https://github.com/openjdk/jdk25u/blob/jdk-25.0.4%2B7/doc/building.md)를 따른다.

## स्रोत_ट्री सिस्टम_बांधणी आदेश

호스트에 해당 OpenJDK 버전이 요구하는 부트 JDK·C/C++ संकलक·Autoconf·Make와
विकास 헤더를 준비한다. Swing/AWT의 Linux लायब्ररी 빌드에는 X11·फॉन्ट_मूल्य 등의
विकास 라이브러리도 필요하다. 이 도구가 시스템 패키지를 자동으로 설치하지는 않는다.

```sh
cd /home/user/jkoros
python3 compiler/संकलक.py --target openjdk-build \
  --java-home /मार्ग/부트JDK --jobs 2 \
  -o compiler/build/openjdk-linux /मार्ग/OpenJDK소스
```

`--entry`는 지정하지 않는다. `-o`는 स्रोत_ट्री 트리 밖의 전용 सिस्टम_बांधणी 디렉터리다.
स्रोत_ट्री·सिस्टम_बांधणी·부트 JDK 경로에 공백을 허용하지 않는다. 다른 프로젝트의 비어 있지 않은
디렉터리를 덮어쓰지 않으며, 같은 소스의 관리된 सिस्टम_बांधणी 디렉터리는 재실행할 संख्या 있다.

주요 산출물:

- `images/jdk/bin/java`, `images/jdk/bin/javac`
- `images/jdk/lib/server/libjvm.so`, `images/jdk/lib/modules`, JNI लायब्ररी
- `jkoros-openjdk-build.json`: टप्पा_मूल्य·आदेश·स्रोत_ट्री ओळखा_मूल्य हॅश_संचिका·यश_मूल्य/बिघाड_मूल्य·ABI पडताळण्या
- `driver-configure.log`, `images.log`: 단계별 लॉग_मूल्य

실패하면 निर्गमन_करा_अनुप्रयोग 상태가 0이 아니며 보고서의 `passed`도 false다. 예전 이미지가 남아
있더라도 새 सिस्टम_बांधणी 성공으로 기록하지 않는다. `native_kernel_port_complete`는 false다.
स्रोत_ट्री 빌드만으로 स्वकीय गाभा_मूल्य आज्ञा_कार्यवाही_करा 시험을 통과한 것으로 처리하지 않는다.

다른 CPU용 Linux JDK를 만들 때는 대상에 맞는 नवीनतम_मूल्य 교차 컴파일러와 **लक्ष्य libc/헤더/लायब्ररी**पहिले_संकार्य 필요하다.
다음은 그러한 도구를 준비한 환경에서 사용하는 형식이다.

```sh
python3 compiler/संकलक.py --target openjdk-build \
  --java-home /मार्ग/호스트용부트JDK \
  --openjdk-target aarch64-linux-gnu \
  --cc /교차도구/bin/aarch64-linux-gnu-gcc \
  --cxx /교차도구/bin/aarch64-linux-gnu-g++ \
  --sysroot /मार्ग/ARM64-Linux-sysroot --jobs 2 \
  -o compiler/build/openjdk-aarch64 /मार्ग/OpenJDK소스
```

부트 JDK는 सिस्टम_बांधणी 호스트에서 실행된다. 교차 सिस्टम_बांधणी 결과를 호스트에서 실행하지 않는다.
`aarch64-jkoros`를 지정하는 것만으로 새 OS 이식이 생기지 않으므로 현재는 거부한다.
공식 configure 옵션은 `--configure-arg=--옵션`을 반복해 전달한다.

## सध्याचे_आयटम पारपाडा_कार्य 공간의 प्रमाणित डेटा

विश्लेषणकरा_मूल्य प्रोजेक्ट_मूळ 소스는 OpenJDK `jdk25u`, 태그 `jdk-25.0.4+7`, 커밋
`0b8bc780f976dab23ec798018fef0b674e885b0c`이다.
[स्रोत_ट्री 출처와 다운로드 हॅश_संचिका](build/openjdk-port/source.json)를 보관한다.
सिस्टम_बांधणी 도구는 `build/openjdk-port/host`의 별도 Alpine x86_64 환경에 준비했다.
이 환경은 सिस्टम_बांधणी 호스트용이며 स्वकीय गाभा_मूल्य 이미지에 들어가지 않는다.

이 소스로 `make images`를 완료하고, 생성한 **OpenJDK 25.0.4-internal / Linux x86_64 musl**의
java·javac आज्ञा_कार्यवाही_करा 시험을 통과했다. 기존 संकलक 회귀 시험과 새 सिस्टम_बांधणी मार्ग 시험도
총 **25개 उत्तीर्ण_मूल्य**했다. 공식 वितरण_मूल्य 바이너리나 Java SE 호환 인증을 받은 배포판은 아니다.
[통합 प्रमाणित लॉग_नोंद](build/openjdk-port/verification.json)은 सिस्टम_बांधणी 산출물과 आज्ञा_कार्यवाही_करा 시험의
java·libjvm 해시가 일치하는지도 확인한 결과다.

[सिस्टम_बांधणी लॉग_नोंद](build/openjdk-port/linux-x86_64/jkoros-openjdk-build.json)의 `passed`와
[आज्ञा_कार्यवाही_करा चाचण्या](build/openjdk-port/smoke/report.json)을 각각 확인한다.
आज्ञा_कार्यवाही_करा 시험은 새로 빌드한 java/javac로 हांगुल_मजकूर स्रोत_ट्री, long/double, UTF-8 फाइल,
Thread·Linux 루프백 TCP·Swing 이벤트 처리를 검사한다.
`window_tested: false`인 결과는 वास्तविक_डेटा JFrame पडदा 시험을 뜻하지 않는다.
Linux에서 한 시험이 स्वकीय गाभा_मूल्य 시험으로 바뀌는 것은 아니다.

```sh
python3 compiler/test_openjdk_image.py \
  --jdk /실행가능한/빌드결과/images/jdk --output compiler/build/openjdk-port/smoke
```

सध्याचे_आयटम 별도 환경에서 만든 JDK는 **Linux x86_64 musl용**이다. 일반 glibc 호스트에서
경로만 지정해 실행할 संख्या 없으며, 준비한 musl पर्यावरण 또는 일치하는 Linux 환경이 필요하다.
Raspberry Pi용 ARM64 산출물이라고 표시하지 않는다.

준비된 이 पारपाडा_कार्य 공간에서는 पुढील_आयटम 단축 명령으로 같은 musl 환경을 사용한다.
प्रयोक्ता·마운트·PID 네임스페이스를 허용하는 호스트에서 실행하며, `build`는 앞의 고정 स्रोत_ट्री/전용 환경을 재사용한다. 마운트는 새 네임스페이스 안에서만 생성되고 종료하면 사라진다. 네임스페이스를 사용할 संख्या 없으면 `openjdk_local.py --proot build` 형식의 느린 대체 경로가 있다.

```sh
python3 compiler/openjdk_local.py build
python3 compiler/openjdk_local.py test
python3 compiler/openjdk_local.py java -version
python3 compiler/openjdk_local.py javac -version
```

`/home/user` 아래에서 호출하면 सध्याचे_आयटम 디렉터리를 유지하므로, हांगुल_मजकूर 소스도 समकक्ष_मूल्य 경로로
컴파일하고 실행할 संख्या 있다. 예를 들어 앞의 시험에서 생성한 소스를 पुनःप्रयत्न_मूल्य 실행하려면:

```sh
python3 compiler/openjdk_local.py javac -encoding UTF-8 \
  compiler/build/openjdk-port/smoke/स्वकीय_बांधणी_चाचणी.java
python3 compiler/openjdk_local.py java -Djava.awt.headless=true \
  -cp compiler/build/openjdk-port/smoke स्वकीय_बांधणी_चाचणी
```

## 기존 ARM64 OpenJDK를 स्वकीय 커널에 복사할 संख्या करते_अस्तित्व

현재는 실행할 संख्या 없다. 저장되어 있는 ARM64 OpenJDK 25의 स्थिर_मूल्य पडताळण्या 결과는
[arm64-runtime.json](build/openjdk-port/arm64-runtime.json)에 있다.
पडताळण्या 도구는 आज्ञा_कार्यवाही_करा 파일을 **실행하지 않고** ELF와 동적 चिन्ह·모듈을 읽는다.

```sh
python3 compiler/openjdk_probe.py \
  --jdk platforms/rpi4/build/rootfs/usr/lib/jvm/java-25-openjdk \
  -o compiler/build/openjdk-port/arm64-runtime.json --require-native
```

स्वकीय 커널에 직접 적재할 संख्या 없으면 पडताळण्या 결과를 저장한 मागे_मूल्य **निर्गमन_करा_अनुप्रयोग संहिता_मूल्य 3**을 반환한다.
ELF 호환성 검사는 वास्तविक_डेटा गाभा_मूल्य 로더의 모든 검증을 대체하지 않는다.

| 확인한 सशर्त | ARM64 OpenJDK | सध्याचे_आयटम स्वकीय गाभा_मूल्य |
|---|---|---|
| ELF | PIE/공유 लायब्ररी, 동적 재배치 | 고정 पत्ता ET_EXEC, स्वकीय ABI note |
| अनुप्रयोग_चालक | `/lib/ld-musl-aarch64.so.1` आवश्यक_मूल्य | PT_INTERP/PT_DYNAMIC/PT_TLS अस्वीकृत_करा_मूल्य |
| 네이티브 VM | pthread, mmap/mprotect, signal, dlopen 등 आवाहन | 일부 फाइल·루프백·GUI SVC와 협력식 세션 |
| स्मृती_डेटा | VM·GC·वर्ग_मूल्य·संहिता_मूल्य 캐시의 동적 पत्ता पत्ता_प्रदेश | प्रयोक्ता प्रदेश_मूल्य 16 MiB, चित्र_बांधणी प्रदेश_मूल्य 12 MiB |
| फाइल | 큰 `lib/modules`, 공유 लायब्ररी 및 डेटा | RAM फाइल 하나당 16 KiB, 영속 साठवणे_मूल्य अनुपस्थित_पद्धत |
| Java वर्ग_मूल्य | OpenJDK 25 class 버전 69 | स्वकीय JVM은 class 45…52 부분집합 |
| Swing | OpenJDK AWT/Java2D/JNI·फॉन्ट_मूल्य·विंडो 시스템 | 별도로 구현한 Swing API 부분집합 |

वास्तविक_डेटा ARM64 이미지의 `libjvm.so`는 19,708,720바이트, `lib/modules`는
146,199,951바이트다. 커널의 सध्याचे_आयटम 제한은
[ELF 로더](../platforms/rpi4-native/मशीन/प्रयोक्ता.c),
[पत्ता पत्ता_प्रदेश व्याख्या_मूल्य](../platforms/rpi4-native/मशीन/प्रयोक्ता.h),
[RAM फाइल अंमलबजावणी](../platforms/rpi4-native/स्रोत/स्मृती_संचिका.java),
[प्रयोक्ता ABI](../platforms/rpi4-native/USER-ABI.md)에서 확인할 संख्या 있다.
큰 내장 프로그램을 커널에 묶는 기존 경로는 RAM फाइल 업로드 제한을 피하지만,
OpenJDK에 필요한 पत्ता पत्ता_प्रदेश·스레드·동적 जोडा 기능까지 제공하지는 않는다.

같은 AArch64 기계어라는 사실만으로 संचालनप्रणाली आवाहन·स्मृती_डेटा·동적 जोडा 규약까지 맞지는 않는다.
फाइल आकार 제한이나 ELF स्वरूप_मूल्य 검사만 풀어도 해결되는 문제가 아니다.

## स्वकीय 커널을 유지하면서 이식하는 टप्पा_मूल्य

커널을 Java로 작성했다는 사실은 이식의 장애가 아니다. 이미 제공하는 EL0 C/C++ 실행처럼
OpenJDK의 네이티브 VM도 संचालनप्रणाली ABI를 갖춘 प्रयोक्ता 프로그램으로 실행할 संख्या 있다.

기술적으로는 새 운영체제용 OpenJDK हार्डवेअर_पॉर्ट 또는 충분한 Linux प्रयोक्ता ABI 호환 계층을
구현하는 방식으로 가능하다. 아래는 सध्याचे_आयटम 코드와 वास्तविक_डेटा 의존성에 근거한 설계 방향이며,
이미 구현되었다는 목록은 아니다.

1. **संचालनप्रणाली ABI와 libc पाया**: 큰 फाइल·पत्ता पत्ता_प्रदेश, 페이지 예약/स्थिरकरा_मूल्य/해제와 संरक्षण_मूल्य बदल_करा_मूल्य,
   표준 फाइल/घड्याळ 인터페이스, त्रुटी अनुक्रमणिका·C 런타임·लक्ष्य sysroot를 구현한다.
2. **वास्तविक_डेटा 네이티브 스레드와 समन्वय_साधा**: pthread에 대응하는 스케줄링·TLS·뮤텍스·सशर्त चल_मूल्य,
   원자 क्रिया_मूल्य·स्मृती_डेटा क्रम_मूल्य·중단/깨우기, 신호/अपवाद 문맥과 가드 페이지를 제공한다.
   सध्याचे_आयटम vi/Swing의 आदान_मूल्य 대기에서 문맥을 보관하는 기능만으로 대체할 संख्या 없다.
3. **로더와 런타임 수명**: ELF 재배치·공유 लायब्ररी·TLS 또는 이식에 맞는 स्थिर_मूल्य जोडा,
   JVM 네이티브 चिन्ह 해결, 영속 फाइल 시스템, 일반 프로그램의 2초 मर्यादा_मूल्य 재설계를 수행한다.
4. **HotSpot OS हार्डवेअर_पॉर्ट**: सिस्टम_बांधणी 시스템과 `src/hotspot/os`, `os_cpu`에 स्वकीय OS/AArch64 경계를
   구현한다. 기존 AArch64 आदेश 생성기는 재사용할 संख्या 있지만 OS 종속부를 구현해야 한다.
   पहिले_आयटम आज्ञा_कार्यवाही_करा 목표는 `java -Xint -version`과 작은 HelloWorld다.
5. **वर्ग_मूल्य लायब्ररी·javac**: java.base의 JNI/फाइल/네트워크/프로세스 연결과 मॉड्यूल_मूल्य 적재를
   구현한 मागे_मूल्य स्वकीय गाभा_मूल्य 안에서 `javac Hello.java`, `java Hello`를 확인한다.
6. **GUI와 बाह्य_मूल्य 네트워크**: AWT/Java2D의 विंडो·आदान_मूल्य·फॉन्ट_मूल्य 백엔드와 वास्तविक_डेटा NIC/TCP/IP를
   이식한다. सध्याचे_आयटम स्वकीय Swing 부분집합이나 루프백 API가 OpenJDK의 구현을 대신하지 않는다.
7. **प्रमाणित**: 단계별 OS ABI चाचण्या, OpenJDK jtreg चाचण्या, GUI/हांगुल_मजकूर/네트워크 부하 चाचण्या,
   वास्तविक_डेटा Pi4 검증을 수행한다. 일부 चाचण्या 통과를 Java SE 전체 호환 인증으로 표시하지 않는다.

근거가 되는 OpenJDK संहिता_मूल्य:
[POSIX स्मृती_डेटा·OS अंमलबजावणी](https://github.com/openjdk/jdk25u/blob/jdk-25.0.4%2B7/src/hotspot/os/posix/os_posix.cpp),
[Linux AArch64 OS सीमा_मूल्य](https://github.com/openjdk/jdk25u/blob/jdk-25.0.4%2B7/src/hotspot/os_cpu/linux_aarch64/os_linux_aarch64.cpp),
[Linux 스레드·신호·स्मृती_डेटा प्रक्रिया_मूल्य_प्रविष्टी](https://github.com/openjdk/jdk25u/blob/jdk-25.0.4%2B7/src/hotspot/os/linux/os_linux.cpp).

स्वकीय Java AOT 자체를 OpenJDK의 Java संहिता_मूल्य 전체를 처리하도록 확장하는 경로도 별도 개발이다.
ऑब्जेक्ट_मूल्य 모델·가상/인터페이스 आवाहन·अपवाद·GC·long/float/double·모든 ऍरे_मूल्य·समन्वय_साधा·동적 आवाहन·
वर्ग_मूल्य आरंभ_करा/로딩·JNI 경계가 필요하며, HotSpot C/C++ 빌드와 OS 이식은 그 뒤에도 남는다.
