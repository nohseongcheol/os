# Java 네이티브 संकलक

OpenJDK स्वकीय 소스를 빌드하는 **`--target openjdk-build`**와 स्वकीय गाभा_मूल्य ABI पडताळण्या 도구를 추가했다.
이는 공식 javac/C/C++ 도구를 연결하는 별도 경로다. [सिस्टम_बांधणी 방법·वास्तविक_डेटा प्रमाणित·गाभा_मूल्य अनुकूलन क्लिप](जावाविकाससंच_स्रोत_बांधणी_आणि_गाभा_पॉर्ट_उघडा.md)를 참고한다.

x86 직접 변환과 ARM64 C तयार_करा 후단은 सर्व_बांधणी [आगाऊ_संबंधित_वेळ_संकलक.java](जावा_साधने/आगाऊ_संबंधित_वेळ_संकलक.java)로 구현한다. `sh आगाऊ_संबंधित_वेळ.sh`로 직접 실행하며, [आगाऊ_संबंधित_वेळ_संकलक.py](आगाऊ_संबंधित_वेळ_संकलक.py)와 `संकलक.py`는 मागील_आयटम आदेश·API 및 OpenJDK 도구를 위한 호환 진입점이다. स्वकीय Pi4 후단은 freestanding C를 거쳐 AArch64로 만든다. [arm64.py](arm64.py)는 मागील_आयटम 경로와 Python 호출을 위한 호환 진입점이다. फलन_मूल्य·चल_मूल्य·तयार_करा C 이름의 뜻과 예외는 [मराठी नामकरण वापरमार्गदर्शिका_eb81d7d9](../platforms/rpi4-native/नामकरण/वापरमार्गदर्शिका_eb81d7d9.md)를 참고한다. [ARM64 सिस्टम_बांधणी·समर्थन_मूल्य क्लिप](../platforms/rpi4-native/वापरमार्गदर्शिका_eb81d7d9.md)에 आज्ञा_कार्यवाही_करा 조건이 있다. 전체 OpenJDK나 일반 वर्ग_मूल्य 실행기는 아니다.

आज्ञा_कार्यवाही_करा 시 JVM이 आवश्यक_मूल्य 없는 x86 32비트 ELF를 만든다. JDK 11 이상으로 실행하는 Java स्वकीय AOT 후단이며, Java 전체를 새로 구현한 컴파일러는 아니다. Java 문법·ऍक्सेस_प्रविष्टी नियंत्रण_मूल्य·टाइप_करा_मूल्य 검사는 JDK의 `javac`에 맡기고, Java 8 वर्ग_मूल्य 파일을 읽어 각 바이트코드를 x86 명령으로 직접 변환한다. C 코드로 우회하거나 बाइटसंहिता 해석기를 커널에 넣지 않는다.

```text
Java स्रोत → javac의 문법·टाइप_करा_मूल्य पडताळण्या → तात्पुरते_मूल्य .class
          → स्वकीय x86 변환기 → GNU as/ld → 네이티브 ELF32
```

## 준비와 आज्ञा_कार्यवाही_करा

सिस्टम_बांधणी होस्ट: Linux, Python 3.6 이상, JDK 11 이상(`javac --release 8`), GNU binutils(`as`, `ld`), Make. सध्याचे_आयटम 환경의 OpenJDK 11, Python 3.6, binutils 2.30으로 검증했다. बाह्य_मूल्य Python 패키지와 네트워크 다운로드는 사용하지 않는다.

```sh
cd /home/user/jkoros/compiler
make
./build/गणना
echo $?                  # 0이면 उदाहरणे चाचण्या यश_मूल्य

python3 संकलक.py --target linux --entry गणना.सुरू_करा \
    -o build/गणना उदाहरणे/गणना.java

make test
```

`linux` 대상은 Linux의 32비트 आज्ञा_कार्यवाही_करा 호환 기능이 필요하다. `int 0x80`을 차단하는 샌드박스에서는 `Bad system call`이 발생할 संख्या 있다. आहे_सामान्य Linux होस्ट 또는 해당 실행을 허용한 चाचण्या 환경에서 실행한다. 시험의 비정상 종료를 통과로 처리하지 않는다.

진입점은 `static int सुरू_करा()` 또는 `static void सुरू_करा()`처럼 인수가 없어야 한다. `--entry 패키지.वर्ग_मूल्य.फलन_मूल्य`로 선택한다. `int` 반환값은 Linux 프로세스 निर्गमन_करा_अनुप्रयोग 코드가 되며 셸에는 하위 8비트가 보인다. 일반 `main(String[] args)` आज्ञा_कार्यवाही_करा 환경이나 표준 इनपुट_आउटपुट 라이브러리는 제공하지 않는다.

`--target kernel`은 प्रणालीप्रारंभ 코드와 연결할 재배치 ELF 오브젝트를 생성한다.

```sh
cd /home/user/jkoros
python3 compiler/संकलक.py --target kernel --entry गाभा.सुरू_करा \
    --export kernel_dispatch=सिस्टम_कॉल_आवाहन.प्रक्रिया_मूल्य_प्रविष्टी \
    -o os/build/java.o os/स्रोत/*.java
```

`--target user`는 jkoros 셸에서 실행할 독립 ELF를 생성한다. `प्रयोक्ता` 클래스의 제한된 native API는 `int 0x80` 시스템 호출로 연결하며 `मोबाइल_मूल्य` 클래스의 हार्डवेअर_मूल्य 직접 접근은 거부한다. प्रयोक्ता ELF는 Linux आज्ञा_कार्यवाही_करा फाइल ABI와 다르므로 호스트에서 실행하지 않는다. तयार_करा·रजिस्टर_प्रविष्टी 방법은 [प्रयोक्ता आज्ञा_कार्यवाही_करा वापरमार्गदर्शिका_eb81d7d9](../os/प्रयोक्ता/वापरमार्गदर्शिका_eb81d7d9.md)에 있다. `--export 외부기호=वर्ग_मूल्य.फलन_मूल्य`는 오버로드되지 않은 स्थिर_मूल्य 함수를 स्वकीय संकार्य_स्टॅक ABI로 노출한다. 커널의 시스템 आवाहन 진입점에 사용한다.

Java 파일은 필요한 클래스들을 한꺼번에 전달한다. आउटपुट 옆의 `.s`는 생성된 어셈블리, `.json`은 स्रोत SHA-256 및 네이티브 चिन्ह↔Java फलन_मूल्य 대응표다. मराठी 함수명은 원문과 대응표에 보존하고 ELF 내부에는 충돌 방지용 मशीन 기호를 쓴다. स्रोत_बांधणी·जोडणीकरा_मूल्य·जोडा 중 실패하면 기존 मोजमाप 파일을 덮어쓰지 않는다.

## समर्थन_मूल्य क्लिप

- `int`, `boolean`, `byte`, `short`, `char`의 32비트 गणना 및 टाइप_करा_मूल्य रूपांतरकरा_मूल्य.
- स्थिर_मूल्य 필드와 स्थिर_मूल्य फलन_मूल्य, 매개변수·परतलेले_मूल्य, 재귀, 클래스별 지연 초기화와 आरंभ_करा चक्र_मूल्य.
- 조건문, 반복문, 단락 평가, 삼항식, पूर्णांक `switch`, 넓은 स्थानिक_संधी चल_मूल्य 인덱스.
- बेरीज_मोजमाप·वजाबाकी_मोजमाप·곱셈·나눗셈·बाकी_मूल्य·बिट_मूल्य 연산과 हलवा_मूल्य. Java의 오버플로 및 `MIN_VALUE / -1` 동작을 유지한다.
- `int[]` तयार_करा·प्रारंभिक_मूल्य 0·लांबी_मूल्य·वाचन·लेखन·संदर्भ 비교. 256KiB 고정 ऍरे_मूल्य प्रदेश_मूल्य, 널/उपलिपी_मूल्य/आकार/पत्ता_प्रदेश पडताळण्या.
- स्ट्रींग_मूल्य 리터럴과 `String` संदर्भ, `length()` 및 `charAt()`. 문자열은 UTF-16 संहिता_मूल्य 단위로 저장하고 같은 리터럴은 공유한다. NUL 및 대리쌍도 시험한다.
- मराठी वर्ग_मूल्य·फलन_मूल्य·चल_मूल्य·फाइल नाव.

`new Object`, 인스턴스 फील्ड_मूल्य/फलन_मूल्य, 상속/인터페이스, `long/float/double` आज्ञा_कार्यवाही_करा क्रिया_मूल्य, `int[]` 이외 ऍरे_मूल्य, स्ट्रींग_मूल्य 동적 एकत्र_मूल्ये, Java 표준 लायब्ररी, अपवाद प्रक्रिया_मूल्य_प्रविष्टी, 스레드·समन्वय_साधा·GC는 미지원이다. 실행에 필요한 आहे_असमर्थित 바이트코드나 बाह्य_मूल्य 호출을 발견하면 실패한다. 사용되지 않는 डिफॉल्ट_मूल्य 생성자는 आज्ञा_कार्यवाही_करा 코드로 만들지 않는다. Java 8 문법이어도 모든 프로그램을 컴파일할 संख्या 있다는 뜻은 아니다.

अपवाद ऑब्जेक्ट_मूल्य 대신 런타임 त्रुटी 번호로 중단한다. Linux와 jkoros प्रयोक्ता 대상에서는 `100 + अनुक्रमणिका`로 종료하고 गाभा_मूल्य 대상에서는 `JKOROS PANIC अनुक्रमणिका`를 출력하고 정지한다. प्रयोक्ता 프로그램만 종료한 경우 셸은 पुढेचालूकरा_प्रक्रियाकरण 실행된다.

| अनुक्रमणिका | 원인 |
| --- | --- |
| 1 | 0으로 भागाकार_मोजमाप |
| 2 | 널 संदर्भ |
| 3 | ऍरे_मूल्य/स्ट्रींग_मूल्य उपलिपी_मूल्य क्लिप 초과 |
| 4 | ऋण_मूल्य ऍरे_मूल्य आकार |
| 5 | ऍरे_मूल्य प्रदेश_मूल्य 부족 |

ऍरे_मूल्य 영역은 증가식 할당이며 회수하지 않는다. 재귀 스택의 सीमा_मूल्य 검사도 아직 없으므로 무제한 재귀를 안전하게 처리하는 런타임은 아니다. 특권 गाभा_मूल्य 및 신뢰할 संख्या 있는 작은 프로그램용 प्रारंभिक_राज्य 구현이다.

## native 경계와 ABI

गाभा_मूल्य 대상에서는 `os/स्रोत/मोबाइल_मूल्य.java`, प्रयोक्ता 대상에서는 `os/प्रयोक्ता/घोषणा/प्रयोक्ता.java`의 정확한 पद्धत_नाव_मजकूर·서술만 허용한다. 임의의 `native` 함수와 Linux/प्रयोक्ता 대상의 हार्डवेअर_मूल्य 접근은 거부한다. Java 인수를 왼쪽부터 32비트 한 칸씩 스택에 놓으며, 반환값은 EAX, EBP/ESP 이외 레지스터는 호출자가 보존한다고 가정하지 않는다. C의 cdecl/JNI ABI가 아니므로 C 함수와 바로 연결하면 안 된다.

Java स्रोत 또는 `.class` 입력을 받는다. 전체 JVM बाइटसंहिता 검증기는 제공하지 않는다. 어노테이션 처리는 비활성화하고 비어 있는 वर्ग_मूल्य मार्ग/स्रोत 경로에서 명시한 소스만 컴파일한다.

## 검증과 अंमलबजावणी 근거

`चाचण्या/test_compiler.py`의 14개 시험에는 네이티브 ELF와 OpenJDK의 क्रिया_मूल्य मोजमाप 대조, वर्ग_मूल्य आरंभ_करा, पूर्णांक 극값, स्ट्रींग_मूल्य/ऍरे_मूल्य, 재귀·switch·wide, 런타임 오류와 आहे_असमर्थित 기능 अस्वीकृत_करा_मूल्य, बिघाड_मूल्य 시 आउटपुट 보존, प्रयोक्ता ELF/परवानगी_मूल्य सीमा_मूल्य 및 निर्गमितकरा_मूल्य 검증이 포함된다. 이것은 Java 전체 적합성 시험은 아니다.

आदेश 의미와 वर्ग_मूल्य फाइल 형식은 Oracle의 [JVM आदेश विनिर्देश](https://docs.oracle.com/javase/specs/jvms/se11/html/jvms-6.html), [वर्ग_मूल्य फाइल विनिर्देश](https://docs.oracle.com/javase/specs/jvms/se11/html/jvms-4.html)를 참고했다.
