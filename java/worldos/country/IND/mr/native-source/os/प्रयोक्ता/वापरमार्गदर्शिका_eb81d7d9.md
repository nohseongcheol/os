# 셸에서 실행하는 प्रयोक्ता 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java विकास पर्यावरण वापरमार्गदर्शिका_eb81d7d9](../../मार्गदर्शिका/जावा_विकास_पर्यावरण.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 आज्ञा_कार्यवाही_करा

होस्ट टर्मिनल 1:

```sh
cd /home/user/jkoros
python3 os/साधने/प्रतिध्वनी_डेटा.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. बाह्य_मूल्य 연결을 받도록 방화벽이나 हार्डवेअर_पॉर्ट 전달을 변경하지 않는다. Ctrl+C로 종료한다.

होस्ट टर्मिनल 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 आदान_मूल्य:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 वास्तविक_डेटा CPU परवानगी_मूल्य `ring 3`, बाबी आउटपुट.
- `netcheck`: पॉर्ट_मूल्य 중복, 잘못된 हाताळा_मूल्य/निर्देशक/लांबी_मूल्य, 비차단 받기와 वेळ_मूल्य 초과 पडताळा.
- `udp`: IPv4 पत्ता·गंतव्यस्थान_मूल्य पॉर्ट_मूल्य·한 शब्द_मूल्य 메시지를 받아 UDP로 보내고 같은 응답을 पडताळा. `UDP ECHO PASS`, `Exit: 0`이면 यश_मूल्य.
- `stress`: होस्ट `10.0.2.2`의 नेमा_मूल्य 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. मूल्य_स्वीकारा लूप_मूल्य 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. सध्याचे_आयटम 주소는 게스트 `10.0.2.15/24`, गेटवे_मूल्य `10.0.2.2`로 고정돼 있다. QEMU प्रयोक्ता 네트워크의 होस्ट ऍक्सेस_प्रविष्टी 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 अनुप्रयोग_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java अनुप्रयोग_f5044b9b शेवटीजोडा_प्रविष्टी

`उदाहरणे/내프로그램.java`를 पुढील_आयटम 형식으로 만든다. 진입점은 बाबी 없는 `static int` 또는 `static void` 함수다. 인수는 प्रयोक्ता API로 조회한다.

```java
public final class 내프로그램 {
    public static int सुरू_करा() {
        प्रयोक्ता.लेखन("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/प्रयोक्ता/अनुप्रयोग_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := प्रयोक्ता/उदाहरणे/내프로그램.java
APP_ENTRY_mine := 내프로그램.सुरू_करा
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 सर्व_बांधणी 나열한다. `प्रयोक्ता/घोषणा/प्रयोक्ता.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 आज्ञा_कार्यवाही_करा 중인 VM에는 सिस्टम_बांधणी 결과가 자동 반영되지 않는다. अनुप्रयोग_f5044b9b 이름은 सध्याचे_आयटम 셸의 ASCII आदान_मूल्य 제한에 맞춘 1~15자의 소문자 이름이며 Java वर्ग_मूल्य·फलन_मूल्य·변수에는 한국어를 쓴다. कमाल_मूल्य 32개 अनुप्रयोग_f5044b9b, 한 आज्ञा_कार्यवाही_करा 파일은 कमाल_मूल्य 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/संकलक.py --target user --entry अभिवादन_ae353e94.सुरू_करा \
    -o os/build/apps/hello.elf os/प्रयोक्ता/घोषणा/प्रयोक्ता.java os/प्रयोक्ता/उदाहरणे/अभिवादन_ae353e94.java
```

`--target user`는 **jkoros 전용 ABI**तिसरे_संकार्य. Linux 대상과 시스템 आवाहन 번호가 다르므로 होस्ट 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 समर्थन_मूल्य क्लिप 안에서 실행한다. `.jar`와 일반 Linux आज्ञा_कार्यवाही_करा 파일은 지원하지 않는다.

## प्रयोक्ता 네트워크 API

선언은 `घोषणा/प्रयोक्ता.java`에 있다. `डेटा_पाठवा`/`डेटा_स्वीकारा`의 `int[]` आयटम_घटक 한 개는 बाइट_मूल्य एक_मूल्य(0~255)를 나타낸다. 한 데이터그램의 कमाल_मूल्य डेटा 길이는 1,024바이트다.

```java
int हाताळा_मूल्य = प्रयोक्ता.संचारजाळे_उघडा(0); // 0: तात्पुरते_मूल्य स्थानिक_संधी UDP पॉर्ट_मूल्य 자동 निवड_मूल्य
int[] डेटा = new int[32];
डेटा[0] = 'H'; डेटा[1] = 'i';
int 보낸길이 = प्रयोक्ता.डेटा_पाठवा(हाताळा_मूल्य, 0x0a000202, 9000, डेटा, 2);
int स्वीकारलेले_लांबी = प्रयोक्ता.डेटा_स्वीकारा(हाताळा_मूल्य, डेटा, 1500);
प्रयोक्ता.संचारजाळे_मिटवा(हाताळा_मूल्य);
```

वास्तविक_डेटा 프로그램에서는 उघडा·पाठवा·받기의 ऋण_मूल्य 반환값을 각각 검사한다. 완성된 예제는 `उदाहरणे/डेटा_संचार.java`에 있다. `डेटा_स्वीकारा`의 प्रतीक्षा_करा_मूल्य 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 मूल्य_स्वीकारा 대기열은 한 개뿐이므로 शेवटीजोडा_प्रविष्टी 도착분은 버린다. `पाठवलेले_पत्ता`와 `पाठवलेले_पॉर्ट`로 마지막으로 받은 상대를 조회한다.

| परतलेले_मूल्य | 의미 |
| --- | --- |
| 0 이상 | हाताळा_मूल्य·प्रक्रिया_मूल्य_प्रविष्टी लांबी_मूल्य·यश_मूल्य 등 해당 함수의 मोजमाप |
| -5 | मोबाइल_मूल्य मूल्य_पाठवा बिघाड_मूल्य |
| -9 | 잘못되었거나 닫힌 संचार हाताळा_मूल्य |
| -11 | 비차단 받기에서 도착한 डेटा अनुपस्थित_पद्धत |
| -14 | प्रयोक्ता निर्देशक/ऍरे_मूल्य क्लिप त्रुटी |
| -19 | समर्थन_मूल्य NIC अनुपस्थित_पद्धत |
| -22 | पॉर्ट_मूल्य/प्रतीक्षा_करा_मूल्य वेळ_मूल्य/बाबी मूल्य त्रुटी |
| -24 | 열린 संचारजाळे_पॉर्ट 4개 धारणक्षमता_मर्यादा |
| -38 | 알 संख्या 없는 시스템 आवाहन |
| -90 | डेटा 또는 मूल्य_स्वीकारा ऍरे_मूल्य आकार 문제 |
| -98 | स्थानिक_संधी पॉर्ट_मूल्य अनुक्रमणिका 중복 |
| -101 | 지원하지 않는 गंतव्यस्थान_मूल्य पत्ता |
| -110 | ARP·मोबाइल_मूल्य·मूल्य_स्वीकारा वेळ_मूल्य 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 एन्कोडिंग_मूल्य 있는 Java `int`의 बिट_मूल्य 패턴을 사용하므로 상위 비트가 1인 आहे_सामान्य IP 주소가 음수로 보일 संख्या 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## आज्ञा_कार्यवाही_करा 경계와 시스템 आवाहन

```text
शेल run → JKAP에서 ELF प्रमाणित·적재 → ring 3 प्रयोक्ता अनुप्रयोग_f5044b9b
                                 ↓ int 0x80
                      निर्देशक पडताळण्या → Java गाभा_मूल्य API → RTL8139/UDP
                                 ↓ निर्गमन_करा_अनुप्रयोग·अपवाद·वेळ_मूल्य 초과
                                शेल 복귀
```

시스템 आवाहन 레지스터는 `EAX=अनुक्रमणिका`, `EBX,ECX,EDX,ESI,EDI=बाबी`, `EAX=मोजमाप`तिसरे_संकार्य. Java आवाहन संकार्य_स्टॅक ABI는 컴파일러가 प्रयोक्ता 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| अनुक्रमणिका | आवाहन |
| --- | --- |
| 0 | निर्गमन_करा_अनुप्रयोग(राज्य_मूल्य संहिता_मूल्य) — सुरू_करा/त्रुटी 런타임에서 वापर_मूल्य |
| 1 | स्ट्रींग_मूल्य लेखन |
| 2 / 3 | बाबी आयटम_संख्या / बाबी स्ट्रींग_मूल्य पत्ता |
| 10 | UDP उघडा |
| 11 | UDP पाठवा(हाताळा_मूल्य, IP, गंतव्यस्थान_मूल्य पॉर्ट_मूल्य, ऍरे_मूल्य पत्ता, लांबी_मूल्य) |
| 12 | UDP स्वीकारा(हाताळा_मूल्य, ऍरे_मूल्य पत्ता, मर्यादा_मूल्य मिलिसेकंद) |
| 13 | UDP बंद_करा |
| 14 | स्थानिक_संधी IP पत्ता |
| 15 / 16 | शेवटचे_आयटम समकक्ष_मूल्य IP / UDP पॉर्ट_मूल्य |
| 20 | RAM फाइल वाचन(नाव int[] पत्ता, आउटपुट int[] पत्ता) |
| 21 | RAM फाइल लेखन(नाव int[] पत्ता, आदान_मूल्य int[] पत्ता, बाइट_मूल्य लांबी_मूल्य) |
| 22 | UTF-16 संहिता_मूल्य एकक_मूल्य वर्ण आउटपुट(0~65535) |

फाइल API는 `प्रयोक्ता.संचिका_वाचा(int[] नाव, int[] डेटा)`와 `प्रयोक्ता.संचिका_लिहा(int[] नाव, int[] डेटा, int लांबी_मूल्य)`तिसरे_संकार्य. 이름은 ASCII संहिता_मूल्य ऍरे_मूल्य(कमाल_मूल्य 64칸, 0 निर्गमन_करा_अनुप्रयोग 또는 ऍरे_मूल्य शेवट), डेटा आयटम_घटक 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 फाइल अनुपस्थित_पद्धत `-2`, निर्देशक त्रुटी `-14`, नाव/लांबी_मूल्य त्रुटी `-22`, फाइल खाच_मूल्य 부족 `-28`, आकार 초과 `-90`을 반환한다. 쓰기는 प्रमाणित नंतर_राज्य फाइल 전체를 대체한다. `प्रयोक्ता.वर्ण_मूल्य_लिहा(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`निष्पादन_परवानगी()`은 시스템 호출이 아니라 प्रयोक्ता 모드에서 CS의 하위 비트를 직접 읽으므로 वास्तविक_डेटा आज्ञा_कार्यवाही_करा 권한을 확인한다. गाभा_मूल्य हार्डवेअर_पॉर्ट 접근용 `मोबाइल_मूल्य` native 함수는 प्रयोक्ता लक्ष्य 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 मर्यादा_मूल्य

- 한 번에 한 프로그램만 실행하며 आहे_पूर्ण नंतर_राज्य 셸로 돌아온다. 백그라운드 आज्ञा_कार्यवाही_करा, 파이프, 프로세스 간 통신은 없다. आज्ञा_कार्यवाही_करा 파일은 커널의 वाचन 전용 JKAP 묶음에서 적재한다. डेटा 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- प्रयोक्ता 가상 पत्ता `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. आज्ञा_कार्यवाही_करा 영상은 पुढील_मूल्य 2MiB, 인수는 `0x04300000`부터, 스택은 प्रदेश_मूल्य 끝에서 시작한다. गाभा_मूल्य identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB प्रयोक्ता 영역을 비우고 फाइल 구역을 복사해 BSS·ऍरे_मूल्य 영역을 초기화한다. प्रयोक्ता GC는 없지만 निर्गमन_करा_अनुप्रयोग नंतर_राज्य पुढील_आयटम आज्ञा_कार्यवाही_करा 때 영역을 재사용한다. 인수는 공백으로 분리한 कमाल_मूल्य 16개이며 कोट/이스케이프 파싱은 없다.
- प्रयोक्ता 페이지의 संहिता_मूल्य/डेटा 분리 वाचन 전용 संयोजना, NX, संकार्य_स्टॅक guard, ASLR은 아직 없다. 커널과 प्रयोक्ता स्मृती_डेटा·हार्डवेअर_पॉर्ट परवानगी_मूल्य 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 आज्ञा_कार्यवाही_करा 상한을 두며 वेळ_मूल्य 초과는 `Exit: 124`तिसरे_संकार्य. प्रयोक्ता CPU 예외는 `128 + अपवाद अनुक्रमणिका`(페이지 त्रुटी 142, 특권 위반 141), Java ऍरे_मूल्य/गणना 오류는 101~105다. गाभा_मूल्य 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, स्थिर_मूल्य IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP चेकसम 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- प्रयोक्ता आज्ञा_कार्यवाही_करा·네트워크·संरक्षण_मूल्य सीमा_मूल्य 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 आज्ञा_कार्यवाही_करा·आहे_सामान्य 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## प्रमाणित 근거

`make test`는 संकलक 14개 चाचण्या, Java 패킷 सशर्त 2,201개 पडताळण्या, 기존 शेल ELF/ISO प्रणालीप्रारंभ चाचण्या, प्रयोक्ता ELF/वास्तविक_डेटा UDP/संरक्षण_मूल्य सीमा_मूल्य 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 लांबी_मूल्य·해시까지 `os/build/प्रयोक्ता_संचारजाळे_चाचणी.json`에 기록한다. 시험용 손상된 ELF·특권 आदेश·무한 पुनरावृत्ती_मूल्य 프로그램은 तात्पुरते_मूल्य 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
