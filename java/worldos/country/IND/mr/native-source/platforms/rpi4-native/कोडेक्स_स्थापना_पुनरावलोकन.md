# स्वकीय ARM64 커널의 Codex स्थापित_करा_मूल्य 가능성 검토

검토일: 2026-10-05. 소스와 공식 문서를 대조한 설계 검토이며, 게스트에 Codex를 설치하거나
로그인·모델 호출을 실행한 결과는 아니다. स्वकीय ARM64 커널과 `../rpi4` Linux 실행판은 구분한다.

सध्याचे_आयटम स्वकीय 커널에는 공식 Codex CLI를 그대로 स्थापित_करा_मूल्य·실행할 संख्या 없다.
기술적으로 필요한 आज्ञा_कार्यवाही_करा 환경을 추가하거나 Codex를 이식하는 경로는 있으나,
다운로드 आदेश 하나를 추가하는 작업으로 해결되지 않는다. JDK/JRE 기능 확장만으로도 해결되지 않는다.

## 확인한 근거

| प्रविष्टी_मूल्य | सध्याचे_आयटम 소스에서 확인한 राज्य_मूल्य | 직접 실행을 위한 पारपाडा_कार्य |
|---|---|---|
| आज्ञा_कार्यवाही_करा फाइल | `मशीन/प्रयोक्ता.c`: AArch64 ET_EXEC만, PT_INTERP/PT_DYNAMIC/PT_TLS अस्वीकृत_करा_मूल्य, 업로드 आज्ञा_कार्यवाही_करा 버퍼 16384바이트 | लक्ष्य 바이너리에 맞는 ELF 적재·재배치·आज्ञा_कार्यवाही_करा आरंभ_करा, स्मृती_डेटा/फाइल मर्यादा_मूल्य एक्सटेंशन_मूल्य |
| Linux ABI | `मशीन/लिनक्स_सुसंगती.inc`: read/write/openat/brk 등 제한된 번호만 प्रक्रिया_मूल्य_प्रविष्टी, 나머지는 ENOSYS | libc/런타임에 필요한 시스템 호출을 추가하거나 स्वकीय ABI용 런타임 अनुकूलन |
| 프로세스·스레드 | 일반 fork/clone/execve, pthread/futex, 시그널, mmap, poll/epoll 계열이 미완성 | 비동기 I/O·스레드·उपघटक_मूल्य आदेश आज्ञा_कार्यवाही_करा·निर्गमन_करा_अनुप्रयोग/रद्द_करा_क्रिया 기능 |
| फाइल | `स्रोत/स्मृती_संचिका.java`: RAM फाइल 64개, 파일당 16 KiB, 비영속 | 큰 आज्ञा_कार्यवाही_करा फाइल·프로젝트·संयोजना·세션을 위한 영속 VFS, फाइल परवानगी_मूल्य·मार्ग·디렉터리 एक्सटेंशन_मूल्य |
| 네트워크 | lwIP TCP/UDP는 있으나 `संचारजाळे_स्टॅक/lwipopts.h`의 LWIP_DNS=0, 일반 HTTPS 클라이언트 अनुपस्थित_पद्धत | DNS, TLS 인증서 प्रमाणित·신뢰 भांडार_मूळ·정확한 कालमुद्रा_मूल्य, HTTPS/스트리밍 |
| टर्मिनल·साधने | स्वकीय 셸과 GUI 터미널은 있지만 표준 PTY·일반 프로세스 पारपाडा_कार्य नियंत्रण_मूल्य अनुपस्थित_पद्धत | परस्परसंवादी CLI용 टर्मिनल 기능, शेल/फाइल 검색/सिस्टम_बांधणी साधने जोडा |
| आज्ञा_कार्यवाही_करा परवानगी_मूल्य | EL0 보호는 있으나 Codex의 Linux 샌드박스와 같은 정책 집행 पर्यावरण अनुपस्थित_पद्धत | फाइल·네트워크·आदेश परवानगी_मूल्य 정책과 승인 기능; स्वकीय 커널에 맞는 격리 अंमलबजावणी |

여기서 ELF의 PT_TLS는 스레드별 साठवणे_मूल्य 공간이다. HTTPS의 TLS पासवर्ड_मूल्य 통신과 서로 다른 기능이다.
ELF फाइल 형식을 읽을 संख्या 있다는 사실만으로 Linux आज्ञा_कार्यवाही_करा 환경을 제공하는 것은 아니다.
SSH/VNC를 위한 पासवर्ड_मूल्य 라이브러리를 넣은 상태도 HTTPS अंमलबजावणी 완료를 의미하지 않는다.

호스트의 `/home/user/.local/bin/codex`도 확인했다. 이것은 x86-64 ELF ET_DYN이며 약 209 MiB다.
해당 파일을 ARM64 게스트로 복사하여 실행할 संख्या 없다. 이 크기를 ARM64 वितरण_मूल्य 파일의 크기로
해석하지 않는다. 공식 ARM64 빌드의 वास्तविक_डेटा आकार·의존성은 설치할 버전으로 शेवटीजोडा_प्रविष्टी 검사해야 한다.

## 가능한 अंमलबजावणी मार्ग

1. **स्वकीय 커널에 공식 CLI 직접 अनुकूलन**
   영속 साठवणे_मूल्य/VFS와 प्रयोक्ता स्मृती_डेटा, 프로세스·스레드·I/O, libc/런타임, DNS/HTTPS,
   टर्मिनल·परवानगी_मूल्य 체계를 갖춘다. नंतर_मूल्य_ee1d8655 लक्ष्य 버전의 의존성을 조사하여 크로스 सिस्टम_बांधणी·이식한다.
   Linux 커널을 반드시 탑재할 필요는 없지만, 공식 Linux 바이너리를 그대로 쓸 경우
   그 바이너리가 사용하는 Linux ABI까지 호환해야 한다. 큰 संचालनप्रणाली विकास 과제다.

2. **बाह्य_मूल्य होस्ट Codex와 स्वकीय गाभा_मूल्य जोडा — पहिले_आयटम 구현으로 권장**
   Linux PC에서 공식 CLI 또는 app-server를 실행하고 jkoros에는 전용 प्रयोक्ता आदेश/화면을 만든다.
   호스트의 인증된 연결과 게스트 फाइल वाचन·सुधारा_मूल्य·업로드·आदेश आज्ञा_कार्यवाही_करा 어댑터가 필요하다.
   기존 SSH/TCP 경로를 활용할 संख्या 있으나, फाइल 동기화나 Codex 전용 어댑터는 सध्याचे_आयटम 구현되어 있지 않다.
   호스트에서 수행한 빌드와 게스트에서 수행한 आज्ञा_कार्यवाही_करा 결과를 명확히 구분한다.
   이 구성은 स्वकीय 커널을 유지하지만, 공식 CLI 자체는 बाह्य_मूल्य 호스트에서 실행된다.

3. **स्वकीय API 클라이언트 제작**
   स्वकीय ABI의 C 또는 지원되는 Java 부분집합으로 परस्परसंवादी_सत्र UI와 फाइल/आदेश साधने आवाहन 루프를 만든다.
   बाह्य_मूल्य 중계기를 쓰지 않는다면 DNS/प्रमाणित 가능한 TLS/HTTPS와 인증 डेटा 저장을 먼저 구현해야 한다.
   이는 OpenAI API를 이용하는 별도 에이전트이며 공식 Codex CLI 전체의 이식으로 표시하지 않는다.

4. **별도 ARM64 Linux 실행판에서 स्थापित_करा_मूल्य**
   `../rpi4`는 Linux와 musl 기반이므로 일반 Linux स्थापित_करा_मूल्य 경로를 검토할 संख्या 있다.
   사용할 Codex 버전의 ARM64·musl 호환성, अवलंबने, 커널의 샌드박스 지원을 वास्तविक_डेटा 검증해야 한다.
   이번 검토에서 स्थापित_करा_मूल्य 성공을 확인하지 않았다. 이 결과를 स्वकीय Java 커널의 지원으로 표시하지 않는다.

## 단계별 आहे_पूर्ण प्रोजेक्ट_मूळ

- 직접 अनुकूलन: `--version` सुरू_करा → 인증/HTTPS → फाइल वाचन·सुधारा_मूल्य → उपघटक_मूल्य आदेश आज्ञा_कार्यवाही_करा →
  परस्परसंवादी आदान_मूल्य/스트리밍 → परवानगी_मूल्य मर्यादा_मूल्य·रद्द_करा_क्रिया → 재부팅 नंतर_राज्य संयोजना/세션 보존을 각각 वास्तविक_डेटा 게스트에서 확인한다.
- होस्ट जोडा: 게스트에서 विनंती आदान_मूल्य → होस्ट Codex प्रक्रिया_मूल्य_प्रविष्टी → 게스트 फाइल बदल_करा_मूल्य पडताळा →
  게스트 javac/cc आज्ञा_कार्यवाही_करा → मोजमाप 표시를 처음부터 끝까지 검증한다.
- COSL 상업 조건을 유지하려면 새로 도입하는 런타임/संचार 라이브러리의 라이선스와
  Codex वितरण_मूल्य 버전의 제3자 고지를 검토한다. बाह्य_मूल्य 구성요소를 일괄 COSL로 재라이선스하지 않는다.

सध्याचे_आयटम 소스와 आवश्यकता_मूल्य 기능을 대조한 기술적 판단이다.
