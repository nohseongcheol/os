# स्वकीय ARM64 JVM 0.4와 मराठी लायब्ररी

मराठी संचार·अपवाद 사용법은 [मराठी Java API](स्वकीय_जावा/वापरमार्गदर्शिका_eb81d7d9.md), फलन_मूल्य·चल_मूल्य·फाइल 이름의 변경과 어원 근거는 [नामकरण वापरमार्गदर्शिका_eb81d7d9](नामकरण/वापरमार्गदर्शिका_eb81d7d9.md)를 참고한다.

JAR आज्ञा_कार्यवाही_करा, बाह्य_मूल्य IPv4 TCP/UDP, 별도 स्थिर_मूल्य 부분집합 `jaot`와 게스트 C 컴파일은 [FTP·C·JAR·AOT 매뉴얼](संचिका_स्थानांतर_आणि_संकलन.md)에 설명한다. तळ_मूल्य ऑब्जेक्ट_मूल्य·Thread·Swing은 JVM 경로의 기능이며 AOT समर्थन_मूल्य 범위와 같지 않다.

이 구현은 **Linux 없이 부팅한 Java AOT 커널의 EL0에서 आज्ञा_कार्यवाही_करा**한다. JDK/JRE의 거의 모든 기능을 제공하는 단계는 아직 아니다. HotSpot·OpenJDK वर्ग_मूल्य लायब्ररी 전체를 이식하거나 Java SE 인증/TCK를 통과한 구현도 아니다. 이번 확장은 단일 वर्ग_मूल्य·स्थिर_मूल्य पद्धत_मूल्य 중심이던 실행기를 ऑब्जेक्ट_मूल्य·लायब्ररी आज्ञा_कार्यवाही_करा 기반으로 넓힌 것이다.

## 실행과 स्रोत_बांधणी

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
# स्वकीय गाभा_मूल्य 안에서 स्रोत_ट्री स्रोत_बांधणी → class आज्ञा_कार्यवाही_करा, मराठी API आवाहन
python3 साधने/संचिका_कार्यवाही_करा.py चाचण्या/जावा/हांगुल_स्रोत.java

# ऑब्जेक्ट_मूल्य·अपवाद 등은 होस्ट JDK로 Java 8 class를 만든 नंतर_राज्य स्वकीय 커널에서 आज्ञा_कार्यवाही_करा
mkdir -p build/my-java
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/my-java चाचण्या/जावा/हांगुल_चाचणी.java
python3 साधने/संचिका_कार्यवाही_करा.py build/my-java/हांगुल_चाचणी.class

# 의존 class 파일은 --include로 함께 स्थानांतर_मूल्य
javac --release 8 -encoding UTF-8 -d build/my-java चाचण्या/जावा/वस्तू_चाचणी.java
python3 साधने/संचिका_कार्यवाही_करा.py build/my-java/वस्तू_चाचणी.class \
  --include build/my-java/वॉलपेपर_मूल्य.class --include build/my-java/शाखा_मूल्य.class \
  --include build/my-java/शक्य_गणनाकरा.class

make test-jvm
```

`--include DIR`는 그 디렉터리의 class 파일을 재귀적으로 읽어 `패키지.वर्ग_मूल्य.class`라는 RAM फाइल 이름으로 전송한다. 주 클래스도 패키지가 있다면 `--class-name 패키지.वर्ग_मूल्य`를 지정한다. 셸에서는 해당 이름으로 업로드하고 `java 패키지.वर्ग_मूल्य`로 실행한다. JVM 0.4는 Main-Class가 있는 16 KiB 이하 JAR도 `java -jar फाइल.jar`로 실행한다. JAR 모드에서는 JAR 내부 클래스와 내장 मराठी 클래스만 찾는다. वितरण_मूल्य मराठी लायब्ररी JAR는 होस्ट javac의 classpath로 사용하며, 같은 클래스가 प्रयोक्ता JVM ELF에도 वाचन 전용 자료로 포함된다. 일반 class 모드에서는 사용자가 같은 이름으로 올린 RAM class를 먼저 읽는다.

게스트 `javac`는 여전히 स्थिर_मूल्य पद्धत_मूल्य, int/boolean/char/String, सशर्त·पुनरावृत्ती_मूल्य, स्ट्रींग_मूल्य एकत्र_मूल्ये, 일부 फाइल 스트림 등의 **स्वकीय 부분집합 संकलक**तिसरे_संकार्य. ऑब्जेक्ट_मूल्य घोषणा·상속·try/catch·Thread वापर_मूल्य 소스를 게스트 javac가 सर्व_बांधणी 컴파일하는 것은 아니다. वरचे_मूल्य 기능은 `javac --release 8`로 만든 class를 स्वकीय JVM에서 실행한다. मराठी API 중 आउटपुट·वर्ण 스칼라 फलन_मूल्य·फाइल वाचन/쓰기는 게스트 컴파일러에도 연결했다. 다음처럼 전체 이름으로 호출한다.

```java
public class अभिवादन_ae353e94 {
    public static void main(String[] बाबी) throws Exception {
        मराठी.स्वकीय.आउटपुट.ओळ_लिहा("안녕하세요😀");
        मराठी.स्वकीय.आउटपुट.संख्या_लिहा(मराठी.स्वकीय.वर्ण.वर्ण_कोड_संख्या("हांगुल_मजकूर😀"));
        मराठी.स्वकीय.फाइल.लेखन("अभिवादन_ae353e94.txt", "हांगुल_मजकूर फाइल😀");
        मराठी.स्वकीय.आउटपुट.ओळ_लिहा(मराठी.स्वकीय.फाइल.वाचन("अभिवादन_ae353e94.txt"));
    }
}
```

UTF-16 संहिता_मूल्य 단위와 Unicode संहिता_मूल्य 포인트 수는 구분한다. हांगुल_मजकूर आदान_मूल्य संयोजन_मूल्य·सामान्यीकरण_करा_मूल्य·아랍어 조판·GUI 다국어 글꼴은 이 स्ट्रींग_मूल्य 지원과 별개다.

예외는 Throwable/Exception/RuntimeException, ArithmeticException, NullPointerException, IndexOutOfBoundsException/ArrayIndexOutOfBoundsException/StringIndexOutOfBoundsException, IllegalArgumentException/NumberFormatException/IllegalThreadStateException, IOException/FileNotFoundException, IllegalStateException, ClassCastException, NegativeArraySizeException, ArrayStoreException, UnknownHostException, SocketTimeoutException의 제한된 तयार_करा·वर्गवारी_मूल्य·처리를 제공한다. प्रयोक्ता व्याख्या_मूल्य Throwable 상속, stack trace/cause/suppressed अपवाद, try-with-resources의 addSuppressed, 완전한 आरंभ_करा त्रुटी 포장은 아직 없다. 잡히지 않은 예외는 सध्याचे_आयटम 전체 Java 실행을 실패로 끝낸다.

## मराठी API

독립 패키지 **`मराठी.स्वकीय`**를 사용한다. Linux판 `मराठी.जावा`पहिले_संकार्य 요구하는 NIO/Swing/HTTP API를 स्वकीय 커널에서 실행할 संख्या 있다고 혼동하지 않도록 패키지를 나눴다. 이 라이브러리는 वर्ग_मूल्य नाव·पद्धत_मूल्य·बाबी·फील्ड_मूल्य·फाइल 이름에 한국어를 사용한다. 표준 Java वर्ग_मूल्य 이름은 호환성을 위해 보존한다.

| वर्ग_मूल्य | 공개 기능 | 이름의 의미 |
|---|---|---|
| आउटपुट | लेखन, ओळ_लिहा, संख्या_लिहा | आउटपुट(出力): 내용을 바깥으로 निर्यातकेलेले_मूल्य |
| वर्ण | लांबी_मूल्य, समान_मजकूर, चिकटवा_मजकूर, कट_मूल्य, पूर्णांक_पार्स_करा/पूर्णांक_मूल्य_लिहा, वर्ण_कोड_संख्या, संकेतन/डिक्रिप्ट_करा_डेटा | वर्ण(文字), एन्कोडिंग_मूल्य(符號): 글의 단위와 그 값을 바이트로 나타내는 नियम_मूल्य |
| फाइल | वाचन/लेखन(String नाव), बाइट_मूल्य_वाचा/बाइट_मूल्य_लिहा | 널리 쓰는 प्रयोक्ता 용어를 보존; RAM 자료의 नाव |
| प्रविष्टी_यादी | जोडा_मूल्ये, वाचन, बदलावे_मूल्य, पुसा_प्रविष्टी, आकार, आहे_रिक्त_मूल्य, साफ_करा_सामुग्री | प्रविष्टी_यादी(目錄): 순서가 있는 प्रविष्टी_मूल्य 모음 |
| शब्दकोश | ठेवा_मूल्य, प्रविष्टी_शोधा, करते_अस्तित्व, पुसा_प्रविष्टी, आकार, साफ_करा_सामुग्री | शब्दकोश(辭典): 찾는 말인 열쇠에 값을 प्रतिचित्रण_मूल्य |
| पारपाडा_कार्य | सुरू_करा(चालवण्यायोग्य_कार्य), प्रतीक्षाकरा(कार्यसूत्र), निलंबित_करा_कार्य, आहे_कार्यरत | पारपाडा_कार्य कार्यसूत्र_मूल्य_5b72a632: 한 अनुप्रयोग_f5044b9b 안의 आज्ञा_कार्यवाही_करा प्रवाह_मूल्य |
| संचार | उघडा, पाठवा, स्वीकारा, प्रतीक्षामर्यादा, बंद_करा | संचार(通信), स्वतंत्रसंदेश(電文), पॉर्ट_मूल्य: डेटा 교환·메시지·포트의 역할 |
| पडदा | आयत, पुसा_प्रविष्टी | पडदा(畫面): वास्तविक_डेटा 그림을 표시하는 면 |
| गाभा_मूल्य | मिलिसेकंद, आयत | स्वकीय JVM의 고정 native जोडा; 일반 JNI는 아님 |

이 명명은 सध्याचे_आयटम 기능을 설명하는 용어 선택이다. 기존 한국어에 없던 역사적 어원을 만들어 주장하지 않는다. संचिका_नाव_मजकूर·식별자는 UTF-8 소스로 보관한다. `वर्ण.डिक्रिप्ट_करा_डेटा`는 잘못된 UTF-8에 IllegalArgumentException을 던지며, `संकेतन`는 짝이 없는 서로게이트를 `?`로 바꾼다. `फाइल.वाचन`는 엄격한 UTF-8 복호화를 적용한다. पडदा 색은 `빨강 | (초록 << 8) | (파랑 << 16)` 형식이다.

## आज्ञा_कार्यवाही_करा 제한과 남은 पारपाडा_कार्य

- 동시에 적재하는 class कमाल_मूल्य 16개(मराठी वर्ग_मूल्य घोषणाशीर्षे), class당 16 KiB·स्थिरांक_मूल्य 풀 511항목, 전체 पद्धत_मूल्य/फील्ड_मूल्य 각각 512개. पद्धत_मूल्य संहिता_मूल्य 8 KiB, स्थानिक_संधी चल_मूल्य·피연산자 संकार्य_स्टॅक 각각 128슬롯, बाबी कमाल_मूल्य 16개(this घोषणाशीर्षे).
- VM 가닥은 main घोषणाशीर्षे **실행당 कमाल_मूल्य 4개**, 가닥당 आवाहन खोली_मूल्य 32. 100개 명령마다 आज्ञा_कार्यवाही_करा 대상을 바꾼다. 네이티브 आवाहन 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- ऑब्जेक्ट_मूल्य 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 वास्तविक_डेटा 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 फाइल·대형 स्ट्रींग_मूल्य·객체가 이 제한을 넘을 संख्या 있다.
- 실행은 50만 बाइटसंहिता आदेश 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 आदान_मूल्य 대기는 기한을 갱신하고 विंडो स्विच_मोड 시 중단·재개한다. 일반 सर्व्हर_मूल्य·계산의 무제한 실행은 아직 없다. आहे_असमर्थित आदेश·संसाधन_मूल्य 부족은 명시적인 오류로 종료한다.
- RAM फाइल कमाल_मूल्य 64개, 파일당 16384바이트, मार्ग UTF-8 63바이트. RAM 디렉터리와 समकक्ष_मूल्य/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 मराठी class는 RAM फाइल 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 सध्याचे_आयटम 경로에서 स्रोत_ट्री·वर्ग_मूल्य·डेटा 파일을 읽는다.
- UDP는 Java 루프백 및 lwIP/SLIP를 통한 बाह्य_मूल्य IPv4를 제공한다. वास्तविक_डेटा GENET/Wi-Fi/DNS/TLS/HTTP 전체는 없다. स्वतंत्रसंदेश 512바이트, संचारद्वार_मूल्य 8개, 소켓당 큐 4개. receive는 VM 가닥을 양보하며 대기하고 setSoTimeout을 적용하지만 전체 आज्ञा_कार्यवाही_करा 기한은 여전히 적용된다.
- long/float/double, invokedynamic/람다, enum/annotation, 다차원 ऍरे_मूल्य, 완전한 ऍरे_मूल्य 공변성·인터페이스 थर_मूल्य पडताळण्या, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/ऍनक्रिप्ट_करा_डेटा/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. Swing의 별도 समर्थन_मूल्य 부분집합은 तळ_मूल्य 및 विकास 매뉴얼을 참고한다. वर्ग_मूल्य फाइल 전체 검증기·ऍक्सेस_प्रविष्टी परवानगी_मूल्य/보호된 멤버 검사는 아직 완전하지 않다. 손상된 입력은 EL0 संरक्षण_मूल्य सीमा_मूल्य 내에서 종료되도록 한다.

전체 OpenJDK를 목표로 하려면 다음은 별도의 주요 अंमलबजावणी 단계다: 완전한 JVM मूल्य/प्रमाणित/वर्ग_मूल्य 로더와 अपवाद 모델 → 영속 VFS·mmap·घड्याळ·원자 क्रिया_मूल्य·वास्तविक_डेटा 스레드/समन्वय_साधा ABI → OpenJDK java.base 및 native लायब्ररी अनुकूलन → मोबाइल_मूल्य 네트워크·TCP/IP → विंडो 시스템/फॉन्ट_मूल्य/입력기·java.desktop → Java SE 호환성 चाचण्या. सध्याचे_आयटम स्वकीय JVM의 일부 메서드를 더하는 것으로 이 작업이 완료되지는 않는다.

## प्रमाणित

`साधने/जावाआभासीयंत्र_चाचणी.py`는 같은 Java 8 class 파일의 출력을 होस्ट OpenJDK `-Xverify:all`과 QEMU raspi4b स्वकीय 커널에서 비교한다. ऑब्जेक्ट_मूल्य/상속/인터페이스·switch·ऍरे_मूल्य, अपवाद/finally, 컬렉션/GC, Thread/कुलूप_मूल्य, मराठी UTF-8/फाइल/컬렉션, वास्तविक_डेटा UDP 루프백/वेळ_मूल्य 초과, 게스트 हांगुल_मजकूर स्रोत_ट्री स्रोत_बांधणी, ऍरे_मूल्य टाइप_करा_मूल्य/इन्स्टन्स_मूल्य/फाइल सीमा_मूल्य·हांगुल_मजकूर 패키지의 9개 비교 시험과 잘못된 class 버전/कापलेले_मूल्य फाइल अस्वीकृत_करा_मूल्य 시험을 실행한다. UDP प्रोजेक्ट_मूळ 실행에는 होस्ट 루프백 संचारद्वार_मूल्य 권한이 필요하다.

`साधने/प्रणालीप्रारंभ_चाचणी.py`는 गाभा_मूल्य संरक्षण_मूल्य/회귀 시험과 별도로 मराठी Java पडदा API가 वास्तविक_डेटा 픽셀을 그렸는지도 QMP पडदा 캡처로 검사한다. 보고서는 `build/verification/jvm/report.json`, `build/verification/report.json`이며 시험한 kernel8.img의 SHA-256을 기록한다. वास्तविक_डेटा Pi4 हार्डवेअर_मूल्य प्रणालीप्रारंभ 시험과 전체 JDK 호환성 चाचण्या 결과는 아니다.


## JVM 0.3: 네트워크와 GUI एक्सटेंशन_मूल्य

`Socket`/`ServerSocket` तयार_करा·जोडा·accept·양방향 InputStream/OutputStream·close·EOF·वेळ_मूल्य 제한과 UTF-8 `String.getBytes`를 추가했다. JVM 0.4에서는 बाह्य_मूल्य अंक_मूल्य IPv4 TCP도 lwIP/SLIP에 연결했다. 연결형 शेवट_करा_गुण 16개, Java 루프백 버퍼 1024바이트, बाह्य_मूल्य TCP 버퍼 4096바이트다. DNS·TLS는 없다.

`JFrame`, `JPanel`, `JLabel`, `JButton`, `JTextField`, `ActionListener`, `ActionEvent`, `SwingUtilities.invokeLater`의 문서화한 부분집합을 네이티브 GUI에 연결했다. `setLayout(null)`과 명시적 좌표를 사용한다. 전체 OpenJDK Swing 또는 Java SE 호환 구현은 아니다. परस्परसंवादी 이벤트 대기는 आज्ञा_कार्यवाही_करा 기한을 갱신하고 टर्मिनल स्विच_मोड 시 프로세스 상태를 साठवणे_मूल्य·복원한다. 이벤트 콜백 자체는 기존 बाइटसंहिता/CPU 기한을 따른다.

मराठी `विंडो`, `विजेट`, `कनेक्शन_वाहतूक` 클래스를 वितरण_मूल्य JAR와 स्वकीय JVM 내장 자원에 추가했다. 상세 पद्धत_मूल्य·मर्यादा_मूल्य·स्रोत_ट्री·업로드 방법: [हांगुल_मजकूर विकास 매뉴얼](विकास_मार्गदर्शी.md).

## मराठी 객체의 직접 आज्ञा_कार्यवाही_करा

`विंडो`, `लेबल`, `मजकूर_फील्_ड`, `बटण`, `इव्हेंट_रांग`, `क्रिया_सूचना`, `कार्यसूत्र`은
표준 GUI/Thread 객체를 보관하는 래퍼가 아니다. स्वकीय JVM의 ऑब्जेक्ट_मूल्य तयार_करा,
स्वरूप_मूल्य पडताळण्या, पडदा आवाहन, इव्हेंट 큐, कार्यसूत्र_मूल्य_5b72a632 스케줄러에 मराठी 계약을 직접 구현했다.
표준 `javax.swing`·`Thread` 코드의 आज्ञा_कार्यवाही_करा 경로도 유지한다.
मराठी 단추와 표준 JButton은 서로 다른 형식이며, 해당 instanceof 검사도 검증한다.

स्वकीय 실행기의 मराठी 진입점은 `public static void सुरू_करा()`이다.
표준 `main(String[])`도 지원하며 दोन_मूल्य तिसरे_संकार्य 있으면 मराठी 진입점을 우선한다.
명령행 인수는 `वितर्क.आयटम_संख्या()`와 `वितर्क.पाठ्य(क्रमांक_अनुक्रमणिका)`으로 읽는다.
`example/java`의 다섯 예제는 이 규약을 사용한다. स्थिर_मूल्य फाइल 예제는 게스트
javac로도 컴파일하며, GUI/कार्यसूत्र_मूल्य_5b72a632 소스는 होस्ट `javac --release 8`을 사용한다.
직접 GUI/कार्यसूत्र_मूल्य_5b72a632 API는 स्वकीय JVM 전용이다. 기존 OpenJDK 비교 시험과 별도로
मराठी 가닥의 आज्ञा_कार्यवाही_करा·प्रतीक्षा_करा_मूल्य·중복 सुरू_करा अस्वीकृत_करा_मूल्य, GUI इव्हेंट उगम_मूल्य·अनुक्रमणिका·콜백을 검사한다.
전체 JDK 번역이나 모든 API의 jaot 지원을 뜻하지 않는다.

पद्धत_मूल्य 이름은 바이트코드에서도 유지된다. 이름과 참조를 같이 수정하면
मराठी 클래스도 실행되지만, स्ट्रींग_मूल्य 리터럴·표준 लायब्ररी 재정의·native
जोडा·진입점은 각각 컴파일러와 실행기의 계약을 맞춰야 한다.
[상세 계약과 उदाहरणे](स्वकीय_जावा/वापरमार्गदर्शिका_eb81d7d9.md)를 참고한다.

## टर्मिनल उपभाग_मूल्य ताजे_करा

हलवा_मूल्य·आकार 변경은 새 विंडो 영역과 मागील_आयटम 자리에서 드러난 띠만 합성한다.
1920×32 पिक्सेल(240 KiB)의 तात्पुरते_मूल्य 그림에서 배경·겹친 विंडो·वर्ण_मूल्य·GUI를 먼저
완성하고, सध्याचे_आयटम मूल्य_शो 메모리와 비교하여 달라진 화소만 기록한다.
32줄보다 큰 영역은 여러 띠로 처리하므로 전체 프레임을 원자적으로
교체하거나 수직 동기에 맞추는 방식은 아니다. 전체 배경을 먼저 지우는
중간 화면은 표시하지 않는다. 좌표가 같으면 पुनःप्रयत्न_मूल्य 그리지 않는다.

`make test-redraw`는 वास्तविक_डेटा C पेंट_पडदा 코드를 호스트의 स्मृती_डेटा 화면에 연결해
हलवा_मूल्य 80회·आकार बदल_करा_मूल्य 40회·겹친 विंडो 4개를 전체 합성 결과와 पिक्सेल 단위로 대조한다.
प्रदेश_मूल्य 밖 प्रयोक्ता रेखांकन_मूल्य, 동일 पिक्सेल 무기록, निर्देशक 밑그림, वास्तविक_डेटा पडदा ओळ 간격을
검사한다. 이 시험의 시간은 होस्ट CPU 측정이며 Pi 4/QEMU 속도로 해석하지 않는다.
`make test-resize`는 QEMU/VNC의 640×480 및 1920×1080에서 डावे_बाजू कोपरा_मूल्य ओढा_मूल्य,
हांगुल_मजकूर आदान_मूल्य·vi 미저장 सामुग्री_मूल्य·독립 विंडो 크기를 검사한다.
