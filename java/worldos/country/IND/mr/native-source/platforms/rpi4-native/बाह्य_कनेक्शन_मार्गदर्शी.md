# स्वकीय ARM64 Java 커널의 बाह्य_मूल्य कनेक्शन_e05f319b

대상은 `jkoros/platforms/rpi4-native`이다. Linux를 실행하지 않는다. SSH와 VNC의 TCP जोडा·인증·आदेश प्रक्रिया_मूल्य_प्रविष्टी·पडदा 전송은 게스트 커널에서 수행한다. QEMU는 SLIP 통신로와 NAT만 제공한다. 기존 `--desktop`의 QEMU VNC 중계와 별개의 구현이다.

| 기능 | सध्याचे_आयटम अंमलबजावणी | प्रमाणित क्लिप |
|---|---|---|
| वायर्ड_मूल्य LAN | Pi4 GENET v5, BCM54213 계열 PHY, ARP, IPv4 TCP/UDP/ICMP, DHCP | ARM64 सिस्टम_बांधणी 및 모의 MMIO/MDIO चाचण्या. **भौतिक_हार्डवेअर बोर्ड 미검증** |
| SSH | TCP 22, libassh 1.1 (LGPL-2.1-or-later), 장치별 ECDSA कळ_मूल्य, पासवर्ड_मूल्य 인증, परस्परसंवादी 콘솔·आदेश आज्ञा_कार्यवाही_करा | वास्तविक_डेटा OpenSSH 클라이언트로 QEMU 게스트에 कनेक्शन_e05f319b |
| VNC | TCP 5900, RFB 3.8, पासवर्ड_मूल्य 인증, वास्तविक_डेटा 프레임버퍼·बदल_करा_मूल्य 타일, 키보드·마우스·두벌식 आदान_मूल्य | वास्तविक_डेटा RFB 전문을 주고받는 클라이언트로 QEMU 게스트 चाचण्या |
| RDP | 미구현 | Remmina에서 **VNC**를 선택한다 |

SSH는 सध्याचे_आयटम गाभा_मूल्य शेल 콘솔을 공유하며 별도 प्रयोक्ता·독립 프로세스·POSIX PTY를 만들지 않는다. 한 번에 SSH 한 जोडा, VNC 한 연결을 받는다. 로컬 셸이 आदेश/vi/프로그램을 आज्ञा_कार्यवाही_करा 중이면 새 SSH शेल 요청은 거절한다. 콘솔을 조작하는 사람은 한 명으로 운영한다. SFTP/SCP, SSH हार्डवेअर_पॉर्ट फॉरवर्ड_मूल्य, 공개키 प्रयोक्ता 인증은 아직 지원하지 않는다. VNC पडदा 자료는 암호화되지 않으므로 신뢰하는 LAN 또는 VPN 안에서 사용한다.

## सध्याचे_आयटम PC에서 आज्ञा_कार्यवाही_करा

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
python3 साधने/दूरस्_थ_सेटिंग्ज.py show
python3 साधने/आज्ञा_कार्यवाही_करा.py --remote --resolution 1920x1080
```

सिस्टम_बांधणी 때 `build/remote/access.json`과 `host-key.der`를 प्रारंभिक_आयटम 한 번 생성하고 पुढील_आयटम 빌드에서도 보존한다. सामायिक_मूल्य डिफॉल्ट_मूल्य 암호는 없다. `show`는 이 PC에 저장된 SSH·VNC 암호를 표시한다. प्रयोक्ता 이름은 `user`तिसरे_संकार्य. 비밀 파일은 소유자만 읽고 쓸 संख्या 있도록 생성한다. 서로 다른 장치용 빌드는 각자의 `build/remote`를 사용해야 한다. 이미지를 그대로 복제하면 कळ_मूल्य·암호도 복제된다. पासवर्ड_मूल्य 파일을 수정했다면 `make build` नंतर_राज्य 새 커널로 재부팅해야 적용된다.

## प्रयोक्ता 이름과 पासवर्ड_मूल्य संयोजना

संयोजना 작업은 **jkoros 게스트 안이 아니라 सिस्टम_बांधणी PC의 Linux टर्मिनल**에서 수행한다.

| प्रविष्टी_मूल्य | सध्याचे_आयटम संयोजना 방법과 제약 |
|---|---|
| SSH प्रयोक्ता | `user` 한 개로 고정. `root`दुसरे_संकार्य 임의 이름으로 로그인할 संख्या अनुपस्थित_पद्धत |
| SSH पासवर्ड_मूल्य | `access.json`의 `ssh_password`. किमान_मूल्य लांबी_मूल्य मर्यादा_मूल्य अनुपस्थित_पद्धत. 서버의 UTF-8 256바이트 상한은 राखा_मूल्य |
| VNC प्रयोक्ता | अनुपस्थित_पद्धत. Remmina의 प्रयोक्ता 이름은 비워 둠 |
| VNC पासवर्ड_मूल्य | `access.json`의 `vnc_password`. ASCII 문자열이며 लांबी_मूल्य मर्यादा_मूल्य अनुपस्थित_पद्धत. 표준 인증에서는 पुढील_मूल्य 8바이트만 사용하고 짧으면 0으로 भरणे_मूल्य |
| 계정 관리 | 게스트 `useradd`, `passwd`, `/etc/passwd`, `/etc/ssh/sshd_config` पाया 관리 미구현 |
| बदल_करा_मूल्य 적용 | संयोजना फाइल साठवणे_मूल्य → सिस्टम_बांधणी → 새 गाभा_मूल्य/이미지로 재부팅 |

기존 설정을 확인하려면 पुढील_आयटम 명령을 실행한다. 암호가 화면에 표시되므로 आउटपुट 결과를 공개 로그나 저장소에 올리지 않는다.

```sh
cd /home/user/jkoros/platforms/rpi4-native
python3 साधने/दूरस्_थ_सेटिंग्ज.py show
```

संयोजना 파일의 구조는 다음과 같다. तळ_मूल्य 암호는 स्वरूप_मूल्य 설명용이며 वास्तविक_डेटा 암호로 사용하지 않는다.

```json
{
  "user": "user",
  "ssh_password": "1234",
  "vnc_password": "1234"
}
```

SSH의 16자 किमान_मूल्य 길이와 VNC의 नेमके_मूल्य 8자 조건을 제거했다. 1자·4자 암호와 빈 स्ट्रींग_मूल्य `""`도
설정할 संख्या 있다. VNC의 8자 초과 부분은 인증에 반영되지 않는다. 예를 들어 `abcdefghX`와
`abcdefghY`는 같은 VNC 인증 키가 된다. 이는 [RFB 표준의 पासवर्ड_मूल्य प्रक्रिया_मूल्य_प्रविष्टी](https://www.rfc-editor.org/rfc/rfc6143.html#section-7.2.2)에 따른다.
VNC ASCII 조건과 SSH 서버의 256바이트 상한, 고정 प्रयोक्ता 이름은 별도 제약으로 유지한다.

सिस्टम_बांधणी PC의 편집기로 두 암호를 수정하고 검사한다.

```sh
vi build/remote/access.json
chmod 600 build/remote/access.json
python3 साधने/दूरस्_थ_सेटिंग्ज.py prepare
```

`prepare`는 파일이 없을 때 कळ_मूल्य·암호를 생성하고, 이미 있는 경우 기존 값을 검사하여 빌드용 헤더를 준비한다.
기존 암호를 자동으로 새 암호로 바꾸거나 आज्ञा_कार्यवाही_करा 중인 게스트 설정을 갱신하지 않는다.
`show` 역시 이 PC의 파일을 읽으므로, आज्ञा_कार्यवाही_करा 중인 옛 커널에 내장된 암호와 다를 संख्या 있다.

QEMU에 적용하려면 기존 게스트를 आहे_सामान्य 종료한 पुढील_आयटम पुनःप्रयत्न_मूल्य सिस्टम_बांधणी·실행한다.
게스트의 RAM 파일은 종료하면 사라지므로 필요한 자료는 먼저 옮긴다.

```text
# jkoros 게스트에서
poweroff
```

```sh
# सिस्टम_बांधणी PC에서
make build
python3 साधने/आज्ञा_कार्यवाही_करा.py --remote --resolution 1920x1080
```

Pi4 SD 이미지에 적용할 때에는 `make cosl-dist RESOLUTION=1920x1080`으로 새 वितरण_मूल्य 이미지를 만들고,
वापर_मूल्य 중인 SD प्रणालीप्रारंभ 영역에도 새 커널을 적용한 मागे_मूल्य 부팅한다. PC에서 संयोजना 파일만 바꾸면 SD의 커널은 바뀌지 않는다.

प्रयोक्ता 이름을 바꾸는 संयोजना 기능은 아직 없다. JSON의 `user`만 바꾸면 तयार_करा 도구가 거부하며,
서버의 `दूरस्_थ_मूल्य/सुरक्षित_शेल.c`도 `user`를 직접 검사한다. नाव 변경을 지원하려면 तयार_करा 도구와 서버의
인증 처리를 함께 수정해야 한다. 이는 서로 다른 परवानगी_मूल्य·홈 디렉터리를 가진 다중 प्रयोक्ता 기능과는 별도다.
암호만 변경할 때 `host-key.der`를 지울 필요는 없다. होस्ट 키는 SSH 서버의 신원을 나타낸다.

## SSH와 Remmina कनेक्शन_e05f319b

다른 터미널에서:

```sh
ssh -p 2222 user@127.0.0.1
# आदेश एक_मूल्य आज्ञा_कार्यवाही_करा
ssh -p 2222 user@127.0.0.1 'ipconfig'
```

Remmina 새 연결에서 프로토콜 **VNC**, सर्व्हर_मूल्य `127.0.0.1:5903`, 암호는 `vnc_password` 값을 사용한다. SSH 암호와 VNC 암호는 서로 다르다. VNC는 최초 인증 नंतर_राज्य GUI 터미널을 연다. `F9`, `Shift+Space`, 한/शून्य_संकार्य 키로 영어·한글을 전환한다. `Ctrl+Shift+T`는 새 टर्मिनल, `F6`는 विंडो स्विच_मोड, `F12`는 विंडो 닫기다. विंडो विंडो_शीर्षक 끌기와 कोपरा_मूल्य डावे_बाजू 버튼 끌기를 지원한다. दूरस्_थ_मूल्य PC 입력기를 통해 전달한 Unicode 글쇠도 UTF-8로 입력된다. 게스트 VNC의 클립보드 전송은 아직 적용하지 않는다.

SSH에서는 दूरस्_थ_मूल्य PC의 입력기 또는 UTF-8 붙여넣기를 사용한다. सध्याचे_आयटम 콘솔의 हांगुल_मजकूर 두벌식 전환은 VNC कळ_रेघ 처리에 적용된다. SSH 연결만 종료하려면 `Ctrl+D`를 사용한다. `poweroff`는 게스트 संचालनप्रणाली 전체를 종료한다.

`--remote`는 `--network`와 `--forward tcp:2222:22 --forward tcp:5903:5900`의 단축 옵션이다. `--desktop` 없이도 दूरस्_थ_मूल्य 화면을 제공한다. 포트를 바꾸려면 직접 फॉरवर्ड_मूल्य 규칙을 지정한다:

```sh
python3 साधने/आज्ञा_कार्यवाही_करा.py --network --forward tcp:2223:22 --forward tcp:5904:5900
```

이 예에서는 SSH에 `-p 2223`, Remmina 서버에 `127.0.0.1:5904`를 사용한다.
게스트 안에서 대기하는 हार्डवेअर_पॉर्ट 22·5900은 그대로다. 이 명령에서 `--remote`पर्यंत 추가하면
डिफॉल्ट_मूल्य 2222·5903 규칙도 함께 추가되므로 हार्डवेअर_पॉर्ट 교체 목적이라면 वरचे_मूल्य आदेश 그대로 사용한다.

| कनेक्शन_e05f319b लक्ष्य | SSH 클라이언트 पत्ता | Remmina VNC सर्व्हर_मूल्य |
|---|---|---|
| 같은 PC의 QEMU (`--remote`) | `ssh -p 2222 user@127.0.0.1` | `127.0.0.1:5903` |
| 다른 PC에서 QEMU (`--network-host` नेमा_मूल्य) | `ssh -p 2222 user@실행_PC_IP` | `실행_PC_IP:5903` |
| भौतिक_हार्डवेअर Pi4의 주소가 आहे_सामान्य 할당된 경우 | `ssh user@라즈베리파이_IP` | `라즈베리파이_IP:5900` |

기존 `--desktop`의 5902 포트는 QEMU पडदा/आदान_मूल्य 중계다. 여기서 설명하는 게스트 `vncd`의
5900→5903 경로와 다르므로 `vncd stop`으로 `--desktop` पडदा 서버가 중지되지는 않는다.

## 다른 PC에서 QEMU 게스트에 कनेक्शन_e05f319b

```sh
python3 साधने/आज्ञा_कार्यवाही_करा.py --remote --network-host 0.0.0.0 --resolution 1920x1080
```

이 실행에 한해 호스트의 बाह्य_मूल्य 인터페이스로 हार्डवेअर_पॉर्ट 전달을 연다. 기본값 `127.0.0.1`은 पुढेचालूकरा_प्रक्रियाकरण 이 PC에서만 접근할 संख्या 있다. 다른 PC는 `ssh -p 2222 user@실행_PC의_LAN_IP`와 Remmina VNC `실행_PC의_LAN_IP:5903`으로 접속한다. होस्ट 방화벽에서 TCP 2222·5903을 허용해야 하며, होस्ट 자체가 가상 머신이면 상위 가상 머신의 브리지 또는 해당 हार्डवेअर_पॉर्ट 전달도 필요하다. 테스트 도구는 होस्ट 방화벽을 변경하지 않는다.

FTP는 기존 `ftpd start` 명령을 실행했을 때만 활성화된다. `--network-host 0.0.0.0`은 FTP फॉरवर्ड_मूल्य 포트에도 적용된다. सध्याचे_आयटम FTP는 익명 RAM फाइल 서비스이므로 필요한 동안에만 사용한다.

## भौतिक_हार्डवेअर Raspberry Pi 4

```sh
make image RESOLUTION=1920x1080
```

산출물은 `dist/jkoros-native-rpi4.img`와 `dist/jkoros-native-rpi4-boot.zip`이다. 이 작업은 PC의 물리 디스크를 열지 않는다. SD 카드 प्रणालीप्रारंभ 방법은 기존 [वापरमार्गदर्शिका_eb81d7d9](वापरमार्गदर्शिका_eb81d7d9.md)를 따른다.

वायर्ड_मूल्य LAN을 공유기에 연결하고 부팅하면 펌웨어 बोर्ड 일련번호를 확인한 मागे_मूल्य GENET을 초기화하고 DHCP 주소를 요청한다. 정상일 때 `ipconfig`에 `en0`, `LINK UP`, वास्तविक_डेटा LAN 주소가 나온다. QEMU에서는 `sl0`, `10.0.2.15`पहिले_संकार्य 표시된다. 공유기의 DHCP 임대 목록에서도 Pi의 주소를 확인할 संख्या 있다. 주소를 얻은 경우 다른 PC에서:

```sh
ssh user@라즈베리파이_IP
# Remmina VNC: 라즈베리파이_IP:5900
```

QEMU의 2222·5903은 होस्ट 포트이며 실물에서는 사용하지 않는다. भौतिक_हार्डवेअर 서비스는 22·5900이다. DHCP 없는 망에서는 UART 셸에서 망에 맞는 주소를 설정한다. 예:

```text
ipconfig set 192.168.1.50 255.255.255.0 192.168.1.1
ping -c 3 192.168.1.1
```

पत्ता बदल_करा_मूल्य 전에 कनेक्शन_e05f319b 중인 SSH/VNC/FTP와 일반 소켓을 닫는다. पत्ता `0.0.0.0`에 묶인 대기용 SSH/VNC 창구는 유지할 संख्या 있다. पत्ता·फाइल·게스트 अनुप्रयोग_f5044b9b स्थापित_करा_मूल्य 자료는 सध्याचे_आयटम RAM 상태이므로 재부팅 नंतर_राज्य 유지되지 않는다.

**भौतिक_हार्डवेअर Pi4 जोडा 정보가 제공되지 않아 전원 투입·랜 케이블 송수신·बाह्य_मूल्य PC 접속은 확인하지 못했다.** GENET 드라이버가 추가되었다는 사실과 실물에서 작동이 검증되었다는 사실은 구분한다. `LINK DOWN`, DHCP 미할당, RNG200 이상 등이 발생하면 UART 로그와 `ipconfig` 결과로 보드별 확인이 필요하다. Wi-Fi와 USB 키보드 드라이버는 이번 अंमलबजावणी 범위에 없다.

## 서비스 명령과 चाचण्या

तळ_मूल्य 명령은 **부팅한 jkoros टर्मिनल**에서 실행한다. होस्ट Linux의 `sshd`दुसरे_संकार्य `systemctl` 명령이 아니다.

```text
sshd status       # सुरक्षित_शेल राज्य_मूल्य
sshd stop         # सुरक्षित_शेल थांबा
sshd start        # सुरक्षित_शेल सुरू_करा
vncd status       # दूरस्_थ_प्रदर्शन राज्य_मूल्य
vncd stop
vncd start
सुरक्षित_शेल राज्य_मूल्य
सुरक्षित_शेल थांबा
सुरक्षित_शेल सुरू_करा
दूरस्_थ_प्रदर्शन राज्य_मूल्य
दूरस्_थ_प्रदर्शन थांबा
दूरस्_थ_प्रदर्शन सुरू_करा
netstat
ipconfig
help
```

두 서비스는 प्रणालीप्रारंभ 때 자동으로 시작한다. पासवर्ड_मूल्य 난수 확보 बिघाड_मूल्य 시 인증을 생략하지 않고 접속에 실패한다. 실물은 BCM2711 RNG200, QEMU는 실행기가 매번 OS 난수로 만든 새 씨앗을 제공한다. 원시 QEMU 명령으로 실행하면서 씨앗을 생략하면 SSH/VNC 인증을 사용할 संख्या 없다. `साधने/आज्ञा_कार्यवाही_करा.py`를 사용한다.

- `RUNNING`: 서비스가 TCP 연결을 기다리는 राज्य_मूल्य. 외부에서 कनेक्शन_e05f319b 가능한지나 인증 성공을 보증하지 않는다.
- `STOPPED`: प्रतीक्षा_करा_मूल्य 창구가 닫힌 राज्य_मूल्य. आरंभ_करा 오류가 있으면 오류도 표시할 संख्या 있다.
- `sshd` 또는 `vncd`만 입력해도 상태를 확인한다. 명시적인 동작은 `start`, `stop`, `status`तिसरे_संकार्य.
- `restart`는 구현하지 않았다. 알 संख्या 없는 인수도 सध्याचे_आयटम राज्य_मूल्य 조회로 처리되므로 `restart` 출력만 अहवाल_मूल्य 재시작됐다고 판단하면 안 된다.
- 재시작은 `stop` पुढील_आयटम `start`तिसरे_संकार्य. **सध्याचे_आयटम 연결한 서비스 자체를 중지하면 연결이 끊긴다.**
  SSH 재시작은 UART/로컬 콘솔 또는 VNC에서, VNC 재시작은 UART/로컬 콘솔 또는 SSH에서 수행한다.
- थांबा 상태는 영구 설정이 아니다. पुढील_आयटम 부팅에서는 두 서비스가 पुनःप्रयत्न_मूल्य 자동 시작한다.
- 서비스 재시작만으로 수정한 `access.json`이 적용되지 않는다. 암호는 새 커널을 빌드하여 부팅해야 바뀐다.

कनेक्शन_e05f319b बिघाड_मूल्य 시 먼저 `ipconfig`, `sshd status`, `vncd status`, `netstat`을 확인한다.
QEMU에는 `--remote` 또는 해당 `--forward`पहिले_संकार्य 필요하며, 로컬 GUI만 제공하는 `--desktop`으로는
게스트 SSH/VNC의 डिफॉल्ट_मूल्य फॉरवर्ड_मूल्य 포트가 자동 생성되지 않는다.
SSH는 `ssh -v -p 2222 user@127.0.0.1`로 कनेक्शन_e05f319b 로그를 볼 संख्या 있다.
पासवर्ड_मूल्य 오류는 संयोजना 파일과 वास्तविक_डेटा प्रणालीप्रारंभ 커널이 일치하는지, प्रयोक्ता 이름이 `user`인지 먼저 확인한다.
Remmina에서는 RDP가 아닌 VNC를 선택하고 `vnc_password`를 입력한다.
새 SSH 세션이 거절되면 기존 접속을 닫고 로컬 셸을 프롬프트 상태로 돌려놓는다.

```sh
make test-remote
make test-passwords
make test-genet
```

दूरस्_थ_मूल्य 시험은 별도 QEMU를 띄우고 `127.0.0.5`의 तात्पुरते_मूल्य 포트만 사용한다. 결과는 `build/verification/native-remote/report.json`, SSH/अनुक्रमिक_मूल्य लॉग_मूल्य 및 पडदा 캡처에 남는다. LAN·공인 인터넷·भौतिक_हार्डवेअर 보드를 시험한 결과가 아니다. GENET 시험은 MMIO/MDIO 모형으로 आरंभ_करा, मूल्य_पाठवा लूप_मूल्य 포화·चक्र_मूल्य, मूल्य_स्वीकारा लांबी_मूल्य सीमा_मूल्य, 링크 끊김, प्रत्युत्तर_द्या वेळ_मूल्य 초과를 확인한다.

पासवर्ड_मूल्य लांबी_मूल्य 시험은 तात्पुरते_मूल्य संयोजना·커널을 만들어 짧은 पासवर्ड_मूल्य·8자 초과 VNC पासवर्ड_मूल्य·빈 암호로 SSH/VNC 인증을
검사한다. 개인 `access.json`은 수정하지 않으며 결과는 `build/verification/password-length/`에 저장한다.

दूरस्_थ_मूल्य 서비스는 `दूरस्_थ_मूल्य/`, वायर्ड_मूल्य 드라이버는 `संचारजाळे_स्टॅक/वायर्ड_संचारजाळे.c`에 있다. SSH는 libassh(LGPL-2.1-or-later), VNC 인증은 BearSSL(MIT)을 사용한다. GENET은 FreeBSD의 BSD 구현으로 교체했다. 버전·해시는 `vendor/remote-sources.json`, वितरण_मूल्य 조건과 पुन्हाजोडा_संचारटोक 방법은 [COSL वितरण_मूल्य वापरमार्गदर्शिका_eb81d7d9](सीओएसएल_वितरण_मार्गदर्शी.md)를 참고한다.
