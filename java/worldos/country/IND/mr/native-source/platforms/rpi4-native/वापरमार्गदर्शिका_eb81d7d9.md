# Raspberry Pi 4 स्वकीय Java गाभा_मूल्य — प्रयोक्ता आज्ञा_कार्यवाही_करा पाया

सध्याचे_आयटम स्वकीय 코드의 COSL 상업 सशर्त, 제3자 고지 및 LGPL पुन्हाजोडा_संचारटोक 자료는 [COSL वितरण_मूल्य वापरमार्गदर्शिका_eb81d7d9](सीओएसएल_वितरण_मार्गदर्शी.md)를 참고한다. स्विच_मोड आधी_मूल्य GPL 구성의 판단은 [मागील_आयटम 라이선스 검토](परवाना_पुनरावलोकन.md)에 기록했다.

मराठी संचार·अपवाद 사용법은 [मराठी Java API](स्वकीय_जावा/वापरमार्गदर्शिका_eb81d7d9.md), फलन_मूल्य·चल_मूल्य·फाइल 이름의 변경과 어원 근거는 [नामकरण वापरमार्गदर्शिका_eb81d7d9](नामकरण/वापरमार्गदर्शिका_eb81d7d9.md)를 참고한다.

Linux 없이 부팅하는 स्वकीय AArch64 커널이다. Java AOT गाभा_मूल्य 위에 **आज्ञा_ओळी शेल, 게스트 Java संकलक·JVM, MicroPython, EL0 C++ आज्ञा_कार्यवाही_करा, फाइल·UDP 루프백 시스템 आवाहन, 여러 हांगुल_मजकूर GUI टर्मिनल·vi संपादक·Swing 부분집합**을 제공한다. 커널의 फाइल डेटा/정책·루프백 स्थानांतर_मूल्य·शेल 상태는 Java, पडदा 합성·पिक्सेल बदल_करा_मूल्य·निर्देशक·클리핑도 Java로 구현하며, CPU/MMU/मोबाइल_मूल्य 경계와 टर्मिनल·वर्ण_मूल्य पेंट_पडदा 연결은 C와 어셈블리다.

**전체 JDK/JRE·CPython·표준 C++ 런타임·Swing 이식은 아직 완료되지 않았다.** 기존 [ARM64 Linux 실행판](../rpi4/README.md)의 OpenJDK/Python 패키지를 이 स्वकीय 커널에 탑재했다고 표시하지 않는다.

새로운 게스트 `cc`/`jaot`, JAR 직접 आज्ञा_कार्यवाही_करा, lwIP TCP/UDP와 FTP는 [FTP·C·JAR·AOT 매뉴얼](संचिका_स्थानांतर_आणि_संकलन.md)을 참고한다. 게스트 SSH·VNC와 Pi4 GENET/PHY·DHCP 드라이버를 추가했다. **SSH·VNC는 QEMU에서 검증하며, भौतिक_हार्डवेअर Pi4의 वायर्ड_मूल्य 송수신은 아직 미검증이다.** आज्ञा_कार्यवाही_करा·कनेक्शन_e05f319b·पासवर्ड_मूल्य 확인은 [बाह्य_मूल्य कनेक्शन_e05f319b वापरमार्गदर्शिका_eb81d7d9](बाह्य_कनेक्शन_मार्गदर्शी.md)에 정리했다.

셸은 EL1 गाभा_मूल्य, `java` 등 प्रयोक्ता आज्ञा_कार्यवाही_करा 파일은 EL0에서 실행한다.
`ps`·`top`의 표시와 मर्यादा_मूल्य, QEMU 네트워크 आज्ञा_कार्यवाही_करा·कनेक्शन_e05f319b 방법 및 वास्तविक_डेटा 검증은
[आज्ञा_कार्यवाही_करा 계층과 बाह्य_मूल्य संचार तपासा_राज्य](सामान्य_भाषा_रनटाइम_आणि_बाह्य_संचारजाळे_पडताळण्या.md)을 참고한다.

ELF는 확장자가 아닌 वास्तविक_डेटा आज्ञा_कार्यवाही_करा 형식으로 검사한다. `./अभिवादन_ae353e94`처럼 확장자 없이 실행하며, 제한된 Linux ARM64 स्थिर_मूल्य ELF는 `run --linux संचिका_नाव_मजकूर`으로 실행한다. [ELF·Linux ABI समर्थन_मूल्य 범위와 동일 바이너리 चाचण्या](निष्पादनीय_द्विमानजोडणी.md).

GUI와 네트워크는 `python3 साधने/आज्ञा_कार्यवाही_करा.py --desktop --network`로 함께 사용한다. Java·C·Python의 मराठी उदाहरणे 13개는 [jkoros/example](../../example/README.md)에 있으며, **게스트 प्रणालीप्रारंभ 시 `/example/java`, `/example/c`, `/example/python`에 자동으로 준비된다.** `example java|c|python`으로 지운 예제를 복원할 संख्या 있다. Remmina에서 **F9/Shift+Space/한·शून्य_संकार्य कळ_मूल्य**로 `[EN]`↔`[KO]` 두벌식을 전환한다(`help ko`). `make test-examples`는 같은 GUI VM에서 FTP·वास्तविक_डेटा TCP/UDP·फाइल बाइट_मूल्य·그래픽 픽셀을 검증한다.

게스트에서 `cd /example/java` नंतर_राज्य `java खिडकीउदाहरण`로 मराठी Swing 예제를 실행한다. टर्मिनल 모서리에 마우스를 대고 **डावे_बाजू 버튼으로 끌면 크기가 바뀐다**. `terminal size`는 सध्याचे_आयटम स्तंभ_मूल्य·ओळ_मूल्य 수를 보여 준다.

आज्ञा_कार्यवाही_करा 버튼 화면은 5×7 영문 글꼴을 쓰며, टर्मिनल 창은 Noto CJK/DejaVu에서 생성한 हांगुल_मजकूर·Unicode 비트맵 글꼴을 쓴다. UART와 वास्तविक_डेटा 프레임버퍼의 हांगुल_मजकूर 표시를 시험한다. 루프백은 동일 गाभा_मूल्य 내부의 स्वतंत्रसंदेश 전달이며 IP 패킷을 Ethernet으로 내보내는 드라이버가 아니다. 바깥 IPv4는 lwIP TCP/UDP 스택으로 सहायक_मूल्य UART SLIP 경로를 사용한다. `python3 साधने/आज्ञा_कार्यवाही_करा.py --network`로 QEMU NAT를 연결하고 `ftpd start`로 서비스를 시작한다.

Java의 정확한 API·문법·आज्ञा_कार्यवाही_करा 제한과 मराठी 사용법은 [स्वकीय JVM과 मराठी लायब्ररी](जावा_सामान्य_भाषा_रनटाइम_पर्यावरण.md)에 정리했다. वर्ग_मूल्य फाइल/JAR 배포는 [स्वकीय_जावा](स्वकीय_जावा) 소스에서 재현한다. 기존 Linux판 `मराठी.जावा`와 별도인 `मराठी.स्वकीय` 패키지다.

**vi·여러 विंडो·Swing·हांगुल_मजकूर Java/Python/C/C++·posix-kor 예제는 [हांगुल_मजकूर विकास 매뉴얼](विकास_मार्गदर्शी.md)에 정리했다.**

GUI टर्मिनल आज्ञा_कार्यवाही_करा·단축키·शेल आदेश·제한은 [셸과 टर्मिनल 사용법](शेल_आणि_टर्मिनल.md)에 정리했다.

## सध्याचे_आयटम 컴퓨터에서 आज्ञा_कार्यवाही_करा

```sh
cd /home/user/jkoros/platforms/rpi4-native
make test
make run
```

निर्गमन_करा_अनुप्रयोग: **Ctrl+A पुढील_आयटम X**. 게스트 C/AOT साधने 빌드에는 `make rpi-prepare`로 준비한 ARM64 SDK 헤더와 libgcc अंकगणिती_मूल्य सहायक_मूल्य 함수도 필요하다. libc나 Linux 커널을 게스트에 넣는 것은 아니다. होस्ट 도구는 JDK 11 이상, Python 3.6 이상, Clang/Clang++, AArch64 GNU binutils, Make, `libnewlib-dev` 헤더다. MicroPython은 `/usr/include/newlib` 헤더를 사용하며 다른 위치는 `NEWLIB_INCLUDE`로 지정한다. newlib 런타임을 अनुकूलन·링크한 것은 아니다. संकलक 의미 비교에는 GCC/UBSan도 사용한다. 기존 `../rpi4/build/host`의 QEMU 11.0.3이 있으면 이용하며, 그렇지 않으면 PATH의 QEMU를 사용한다. `QEMU_AARCH64=/절대/मार्ग/qemu-system-aarch64`로 지정할 수도 있다. `raspi4b` समर्थन_मूल्य 여부를 확인한 नंतर_राज्य 실행한다.

명령은 **Enter를 눌러 आज्ञा_कार्यवाही_करा**한다. 기존 한 वर्ण_मूल्य 명령도 Enter가 필요하다.

```text
javac Hello.java
java Hello "हांगुल_मजकूर बाबी 😀"
python hello.py
python -c 'print(2**100)'
ls
cat python.txt
run cpp
net test
gui
```

| आदेश | कृती |
|---|---|
| `help` / `info` | आदेश·वास्तविक_डेटा अंमलबजावणी राज्य_मूल्य |
| `ls` / `cat FILE` / `rm FILE` | RAM फाइल प्रविष्टी_यादी·सामुग्री_मूल्य·삭제 |
| `vi FILE` | प्रयोक्ता प्रदेश_मूल्य vi 부분집합, हांगुल_मजकूर संपादन_मूल्य·साठवणे_मूल्य·검색·되돌리기 |
| `edit FILE` | फाइल 전체를 새로 आदान_मूल्य; 단독 `.` 줄로 साठवणे_मूल्य, Ctrl-C로 रद्द_करा_क्रिया |
| `javac FILE.java` / `java CLASS [ARGS]` | स्वकीय 제한형 Java स्रोत_बांधणी·आज्ञा_कार्यवाही_करा |
| `python FILE.py [ARGS]` / `python -c 'CODE'` | MicroPython स्रोत_बांधणी·आज्ञा_कार्यवाही_करा |
| `load FILE` / `hex FILE` | 16진수 바이너리 आदान_मूल्य/आउटपुट; 입력은 단독 `.` 줄로 साठवणे_मूल्य |
| `run FILE.elf [ARGS]` / `run cpp` | 업로드한 स्वकीय ABI ELF / 내장 C++ उदाहरणे |
| `net test` / `tasks` / `selftest` | UDP 루프백 / 협력식 पारपाडा_कार्य / EL0 संरक्षण_मूल्य चाचण्या |
| `gui` / `terminal` | आज्ञा_कार्यवाही_करा पडदा / हांगुल_मजकूर GUI टर्मिनल; F12로 टर्मिनल उघडा·बंद_करा |
| `samples` | 삭제한 डिफॉल्ट_मूल्य उदाहरणे पुनर्प्राप्त_करा_राज्य; 기존 파일은 보존 |

예를 들어 `edit अभिवादन_ae353e94.java`를 입력한 पुढील_आयटम तळ_मूल्य 소스를 입력한다.

```java
public class अभिवादन_ae353e94 { public static void main(String[] args) { int मूल्य = 7; System.out.println("हांगुल_मजकूर=" + मूल्य); } }
```

그다음 단독 `.` 줄로 저장하고 `javac अभिवादन_ae353e94.java`, `java अभिवादन_ae353e94`를 실행한다. 편집기는 기존 파일에 커서를 이동하는 방식이 아니라 전체 교체 방식이다. रद्द_करा_क्रिया·잘못된 16진수·धारणक्षमता_मूल्य 초과는 원본을 보존한다. 줄은 4096바이트, 파일은 16384바이트, आज्ञा_कार्यवाही_करा 인수는 कमाल_मूल्य 8개·각각 UTF-8 255바이트다. 일반 आदेश 인수는 कमाल_मूल्य 32개다. कोट·백슬래시·शेल चल_मूल्य·파이프·리다이렉션 범위는 [शेल वर्णन](शेल_आणि_टर्मिनल.md)을 참고한다.

GUI 터미널은 다음과 같이 실행하고 Remmina에서 **VNC**, पत्ता **127.0.0.1:5902**로 연결한다. 키보드·हांगुल_मजकूर Unicode आदान_मूल्य·명시적 चिकटवा_मूल्य·आज्ञा_कार्यवाही_करा 버튼의 마우스 클릭을 QEMU 도구가 UART에 전달한다.

```sh
make desktop
# GUI + 네트워크: python3 साधने/आज्ञा_कार्यवाही_करा.py --desktop --network
# 다른 हार्डवेअर_पॉर्ट: python3 साधने/आज्ञा_कार्यवाही_करा.py --desktop --port 5903
```

종료는 실행한 होस्ट 터미널에서 Ctrl+C다. 기존 `python3 साधने/आज्ञा_कार्यवाही_करा.py --vnc 127.0.0.1:2`는 पडदा 보기와 별도 UART 입력을 유지한다. `make run`은 일반 UART 셸이다. वास्तविक_डेटा Pi4 USB 입력기는 아직 없으며, VNC जोडा 도구는 QEMU 시험용이다.

GUI의 다섯 버튼은 वास्तविक_डेटा C++/UDP ELF आज्ञा_कार्यवाही_करा, `Hello.java` स्रोत_बांधणी नंतर_राज्य JVM आज्ञा_कार्यवाही_करा, `hello.py` आज्ञा_कार्यवाही_करा, GUI टर्मिनल 열기를 수행한다. 한 번에 한 프로그램이 CPU에서 실행되며 일반 실행에는 약 2초 기한이 있다. vi·Swing은 परस्परसंवादी 대기에서 기한을 갱신하고 다른 터미널로 전환할 때 स्मृती_डेटा·CPU 문맥을 보관한다. शेल·편집기에서 입력을 기다리는 시간에는 이 제한이 적용되지 않는다.

이미지는 확인된 공식 Pi प्रणालीप्रारंभ 묶음에서 `start4.elf`, `fixup4.dat`, Pi4 DTB와 disable-bt overlay를 가져온다. Linux kernel/initramfs/rootfs는 넣지 않는다. 펌웨어·MicroPython·टर्मिनल फॉन्ट_मूल्य 라이선스와 फॉन्ट_मूल्य उगम_मूल्य 해시도 동봉한다. फाइल तयार_करा 스크립트는 물리 디스크에 기록하지 않는다.

예비 microSD에 चित्र_बांधणी लॉग_नोंद 도구로 `.img`를 기록하거나 FAT32 प्रणालीप्रारंभ 파티션 최상위에 ZIP 내용을 푼다. चित्र_बांधणी 기록은 선택한 카드의 기존 내용을 지우므로 대상을 확인한다. Pi4 डिफॉल्ट_मूल्य EEPROM SD 부팅을 전제로 한다. UART는 **3.3V TTL, 115200 8N1**, GPIO14/TXD(8번)→어댑터 RX, GPIO15/RXD(10번)→TX, GND(6번) 연결이다. GPIO에 5V 신호를 연결하지 않는다.

**भौतिक_हार्डवेअर Pi4 부팅은 미검증이다.** QEMU `-kernel`은 SD의 VideoCore 펌웨어를 실행하지 않고 커널을 직접 적재한다. SD फाइल 구성·गाभा_मूल्य 체크섬 검사와 물리 बोर्ड प्रणालीप्रारंभ 검증은 별개다. MMU वापर_मूल्य 전에는 펌웨어의 캐시/MMU가 꺼져 있고 EL1 또는 EL2로 진입하는 통상 प्रणालीप्रारंभ 조건을 전제로 한다. तीन_मूल्य सहायक_मूल्य 코어는 대기시키며 한 코어만 사용한다.

## C++와 मराठी API वापर_मूल्य

SDK를 풀고 호스트에서 컴파일한다.

```sh
tar -xzf dist/jkoros-native-aarch64-sdk.tar.gz -C build
cd build/jkoros-native-sdk
python3 compile.py examples/संचिका_उदाहरण.cpp -o demo.elf
python3 compile.py examples/संचार_उदाहरण.cpp -o network.elf
```

진입점은 `extern "C" int प्रारंभ_प्रयोक्ता_अनुप्रयोग(int)`이다. प्रयोक्ता C++는 FP/SIMD를 사용할 संख्या 있다. गाभा_मूल्य C/Java AOT는 일반 레지스터만 사용하므로 अपवाद प्रक्रिया_मूल्य_प्रविष्टी 중 प्रयोक्ता FP 상태를 건드리지 않는다. प्रयोक्ता प्रविष्टी_गुण_मूल्य 시 FP 상태를 초기화하고 गाभा_मूल्य 복귀에 필요한 상태를 보존한다.

```cpp
#include "संचिका_द्विमानजोडणी.h"
extern "C" int प्रारंभ_प्रयोक्ता_अनुप्रयोग(int) {
    int फाइल = संचिका_उघडा("अभिवादन_ae353e94.txt", वाचणे_लिहिणे | जर_अनुपस्थित_तयार_करा | छाटूनरिकामेकरा_सामुग्री, 0600);
    if (फाइल < 0) return 1;
    const char सामुग्री_मूल्य[] = "안녕하세요";
    int मोजमाप = संचिका_डेटा_लिहा(फाइल, सामुग्री_मूल्य, sizeof(सामुग्री_मूल्य) - 1);
    संचिका_मिटवा(फाइल);
    return मोजमाप == sizeof(सामुग्री_मूल्य) - 1 ? 0 : 2;
}
```

[फाइल उदाहरणे](प्रयोक्ता/संचिका_उदाहरण.cpp)와 [संचार उदाहरणे](प्रयोक्ता/संचार_उदाहरण.cpp)पहिले_संकार्य वास्तविक_डेटा प्रणालीप्रारंभ चाचण्या 대상이다. `संचिका_द्विमानजोडणी.h`의 이름은 커널용/사용자용 सर्व_बांधणी 같지만 **링크하는 라이브러리가 다르다**. 사용자용은 `svc #0`으로 호출하고 फाइल प्रक्रिया_मूल्य_प्रविष्टी 및 루프백 전달은 Java 커널에서 실행한다. `संचारजाळे_द्विमानजोडणी.h`의 संचारद्वार_मूल्य 함수는 सध्याचे_आयटम 사용자용 라이브러리에 구현돼 있다.

새 프로그램은 गाभा_मूल्य 재빌드 없이 `load FILE.elf`와 `run FILE.elf`로 실행한다. 호스트에서 पुढील_आयटम 도구를 사용하면 **새 QEMU를 부팅해 업로드한 वास्तविक_डेटा 바이트를 재확인한 मागे_मूल्य 게스트에서 आज्ञा_कार्यवाही_करा**하고 종료한다. 이 도구의 새 VM에서 만든 RAM 자료는 종료할 때 사라진다.

```sh
cd /home/user/jkoros/platforms/rpi4-native
python3 साधने/संचिका_कार्यवाही_करा.py build/jkoros-native-sdk/demo.elf
python3 साधने/संचिका_कार्यवाही_करा.py उदाहरणे/Hello.java "हांगुल_मजकूर बाबी"
python3 साधने/संचिका_कार्यवाही_करा.py उदाहरणे/hello.py
```

이 경로는 16KiB 이하의 `.elf`, `.java`, `.class`, `.py`를 지원한다. 큰 내장 Java/MicroPython ELF 자체는 गाभा_मूल्य 묶음에 포함되어 이 फाइल 한도를 적용받지 않는다. **C++ 컴파일러는 होस्ट SDK의 Clang++**이며 게스트 내부 GCC/Clang 컴파일러는 아직 없다. SDK만으로 일반 Linux 프로그램을 실행할 수는 없다. Linux ELF, 동적 लायब्ररी, PT_TLS, PT_INTERP, PT_DYNAMIC, आज्ञा_कार्यवाही_करा·लेखन 겸용 세그먼트는 로더가 거부한다. 구체적인 आवाहन अनुक्रमणिका·पत्ता क्लिप·오류는 [प्रयोक्ता ABI](प्रयोक्ता_कॉल_द्विमानजोडणी.md)를 참고한다.

RAM 파일은 재부팅 시 사라진다. `स्थिरकरा_फाईल_संग्रहण`은 -1과 ENOSYS를 반환한다. 파일의 mode 인수를 저장하지 않으며 परवानगी_मूल्य·dup/fcntl은 없다. 디렉터리와 समकक्ष_मूल्य/절대 경로는 같은 RAM 저장소에서 처리한다. UDP 전문은 कमाल_मूल्य 512바이트, 소켓은 8개, मूल्य_स्वीकारा 큐는 소켓당 4개다. 수신할 자료가 없거나 큐가 가득 차면 EAGAIN을 반환한다. प्रयोक्ता निर्गमन_करा_अनुप्रयोग 시 열린 फाइल 서술자와 소켓을 회수한다.

## प्रमाणित मोजमाप

`make test-jvm`은 9개 프로그램을 OpenJDK와 वास्तविक_डेटा स्वकीय 커널에서 실행해 결과를 비교한다. `make test`에도 포함된다. 별도 `साधने/प्रणालीप्रारंभ_चाचणी.py`는 Java आयत API의 वास्तविक_डेटा पडदा 픽셀까지 검사한다. `make test-shell`, `make test-desktop`은 새 셸과 वास्तविक_डेटा VNC आदान_मूल्य·हांगुल_मजकूर टर्मिनल 화면을 검사하며 `make test`에도 포함된다.

`make test-windows`, `make test-swing`, `make test-stream`, `make test-coding`도 제공하며 `make test`에 포함된다.

`make test`는 OpenJDK와 AOT क्रिया_मूल्य मोजमाप 비교, 런타임 त्रुटी 중단, आहे_असमर्थित Java 거부와 함께 별도 QEMU VM에서 다음을 검사한다.

- 기존 Java गाभा_मूल्य गणना·UTF-8·C++ 직접 आवाहन·협력식 पारपाडा_कार्य 및 프레임버퍼.
- 손상/잘못된 ABI/पत्ता 초과/겹친 페이지/W+X 등 ELF अस्वीकृत_करा_मूल्य 사례 22개.
- EL0 C++ 생성자·RAII·तरंगता_गुण_मूल्य क्रिया_मूल्य·फाइल·गतिमानस्मृतिराशी_मूल्य 및 잘못된 시스템 आवाहन निर्देशक.
- गाभा_मूल्य/संहिता_मूल्य/MMIO लेखन·ऍक्सेस_प्रविष्टी, NX संकार्य_स्टॅक·NULL आज्ञा_कार्यवाही_करा, guard page, 특권 आदेश 차단.

## Java와 Python의 정확한 क्लिप

स्वकीय `javac`는 버전 49 `.class`를 생성하며 JVM은 समर्थन_मूल्य 명령으로 구성된 버전 45–52 클래스를 실행한다. स्थिर_मूल्य फलन_मूल्य·재귀·int/boolean/char/String·सशर्त/पुनरावृत्ती_मूल्य·स्ट्रींग_मूल्य 결합과 일부 फाइल 스트림을 지원한다. UTF-8 문자열과 वर्ण 리터럴, ASCII 및 현대 हांगुल_मजकूर 음절/संयोजन_मूल्य हांगुलवर्णघटक_मूल्य 식별자를 처리한다. Unicode आयडेंटिफायर_मूल्य 전체 लुकअप_सारणी·Unicode स्रोत_ट्री 이스케이프는 구현하지 않았다. 게스트 स्रोत_ट्री 컴파일러는 일반 ऑब्जेक्ट_मूल्य·अपवाद·Thread 구문을 아직 컴파일하지 못한다. होस्ट `javac --release 8`로 만든 समर्थन_मूल्य 부분집합 클래스는 स्वकीय JVM 0.4의 ऑब्जेक्ट_मूल्य·अपवाद·Thread·UDP와 मराठी API를 사용할 संख्या 있다. Swing은 문서화한 स्वकीय API 부분집합을 제공하며 JAR 로더는 제공하지만 전체 AWT/Swing·JDK 표준 라이브러리는 없다. 정확한 범위는 [स्वकीय JVM वर्णन](जावा_सामान्य_भाषा_रनटाइम_पर्यावरण.md)이 기준이다. 상세 भाषा 범위는 [공유 Java साधने वर्णन](../../मार्गदर्शिका/जावा_विकास_पर्यावरण.md)을 참고하되, 그 문서의 x86 शेल/साठवणे_मूल्य/실행시간과 이 ARM64 판의 차이에 유의한다.

MicroPython은 공식 **1.24.1 स्रोत_ट्री**를 स्वकीय AArch64 EL0/SVC 대상으로 빌드했다. Python 문법의 फलन_मूल्य·वर्ग_मूल्य·अपवाद·리스트/शब्दकोश·Unicode·GC·가변 अचूकता_मूल्य 정수를 제공한다. सध्याचे_आयटम 구성은 पूर्णांक 빌드로 `float`, `complex`, `math`पहिले_संकार्य 없으며 CPython 전체 표준 लायब्ररी, pip, subprocess, threading, 일반 socket과 डिफॉल्ट_मूल्य `open()` फाइल 객체는 제공하지 않는다. `python FILE.py` 및 `-c` 실행만 제공하며 REPL은 아직 없다. 각 실행의 ऑब्जेक्ट_मूल्य·모듈은 निर्गमन_करा_अनुप्रयोग 시 회수되고 RAM 파일만 पुढील_आयटम 실행에 남는다.

`import jkoros`로 पुढील_आयटम 시스템 연결을 쓴다. सर्व_बांधणी SVC를 통해 स्वकीय Java 커널에 접근한다.

| फलन_मूल्य | कृती |
|---|---|
| `stdin(limit)` | सध्याचे_आयटम 표준 입력에서 कमाल_मूल्य limit바이트(0…16384)를 bytes로 मोजमाप_वाचा; EOF는 빈 bytes, UART डेटा 없음은 OSError(11) |
| `read(name)` | समकक्ष_मूल्य/절대 RAM 경로의 फाइल 전체를 bytes로 मोजमाप_वाचा |
| `write(name, data)` | str/bytes 버퍼를 RAM 파일에 새로 साठवणे_मूल्य, 쓴 बाइट_मूल्य संख्या परतकरा_मोजमाप |
| `remove(name)` | RAM फाइल 삭제 |
| `rect(x, y, w, h, color)` | 선택한 वास्तविक_डेटा पडदा आकार 안의 आयत रेखांकन_मूल्य; 기존 보드의 RGB32 मूल्य |
| `ticks_ms()` | प्रणालीप्रारंभ नंतर_राज्य मिलिसेकंद, 32비트 चक्र_मूल्य |
| `udp_open(port)` | 127.0.0.1의 UDP संचारद्वार_मूल्य उघडा/बाइंड_करा_संचारटोक; 0은 자동 हार्डवेअर_पॉर्ट |
| `udp_send(fd, port, data)` | 루프백 गंतव्यस्थान_मूल्य 포트에 str/bytes 버퍼 स्थानांतर_मूल्य |
| `udp_recv(fd)` | `(bytes, 보낸포트)` परतकरा_मोजमाप; 비어 있으면 `OSError(11)` |
| `udp_close(fd)` | संचारद्वार_मूल्य बंद_करा |

```python
import jkoros
first = jkoros.udp_open(9401)
second = jkoros.udp_open(9402)
jkoros.udp_send(first, 9402, b"hello")
print(jkoros.udp_recv(second))  # (b'hello', 9401)
jkoros.udp_close(first)
jkoros.udp_close(second)
```

अनुकूलन संहिता_मूल्य: [python/](पायथन_ब्रिज/), [प्रयोक्ता Java जोडा](प्रयोक्ता/जावा_ब्रिज.c). 공식 [MicroPython अनुकूलन वापरमार्गदर्शिका_eb81d7d9](https://docs.micropython.org/en/latest/develop/porting.html)를 참고했다. स्रोत_ट्री URL·हॅश_संचिका·라이선스는 [vendor वापरमार्गदर्शिका_eb81d7d9](vendor/README.md)에 기록했다.

## मराठी C डेटा_टाइप·Python त्रुटी·बंडल स्थापित_करा_मूल्य

C 네트워크 API는 `struct क्लाउड_संचारद्वार_पत्ता`, enum 상수와 वास्तविक_डेटा मराठी 함수로
구현한다. मॅक्रो_मूल्य 별칭을 사용하지 않으며 मागील_आयटम pk_* ABI도 유지한다.
Python 예제는 `सिस्टम_त्रुटी`, `त्रुटी.अनुक्रमणिका`, `त्रुटी.वर्णन`을 사용한다.

`python3 साधने/आज्ञा_कार्यवाही_करा.py --desktop --network --pip`로 시작하면 게스트에서
`pip install micropython-bisect==3.3.3`을 사용할 संख्या 있다. 현재는 होस्ट 중계를
이용하는 제한형 MicroPython स्रोत_ट्री 설치기이며 CPython pip·자동 अवलंबने 해결·C 확장은
미지원이다. 설치한 `/lib` 자료는 RAM이다. [사용법과 मर्यादा_मूल्य](पायथन_बंडल.md).

## पडदा आकार निवड_मूल्य

`python3 साधने/आज्ञा_कार्यवाही_करा.py --desktop --network --resolution 1920x1080`으로 Full HD 화면을 사용한다. 기본값은 640×480이며 1280×720도 가능하다. टर्मिनल हलवा_मूल्य, Swing मध्य लिंक_लेआउट, Java·C·Python 그리기도 वास्तविक_डेटा 크기를 따른다. SD 영상은 `make image RESOLUTION=1920x1080`으로 만든다. [संयोजना·मराठी API·प्रमाणित वापरमार्गदर्शिका_eb81d7d9](पडदा_बिंदूघनता.md).

## मराठी 직접 API와 पडदा ताजे_करा
