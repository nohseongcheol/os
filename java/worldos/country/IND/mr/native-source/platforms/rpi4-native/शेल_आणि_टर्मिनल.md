# स्वकीय 커널의 GUI 터미널과 शेल

이 터미널은 स्वकीय Java 커널의 셸을 프레임버퍼 창과 UART에서 사용한다. आदेश प्रक्रिया_मूल्य_प्रविष्टी·RAM फाइल·파이프는 Java गाभा_मूल्य, 화면의 वर्ण_मूल्य 그리기는 freestanding C에서 수행한다. Linux·X11·Bash 없이 동작하며, स्वकीय JVM의 Swing समर्थन_मूल्य 부분집합도 같은 विंडो 시스템을 이용한다. 자세한 vi·다중 विंडो·코딩 사용법은 [विकास 매뉴얼](विकास_मार्गदर्शी.md)을 참고한다.

## सध्याचे_आयटम 컴퓨터에서 आज्ञा_कार्यवाही_करा

```sh
cd /home/user/jkoros/platforms/rpi4-native
make desktop
```

Remmina에서 **VNC**, पत्ता **127.0.0.1:5902**로 연결한다. टर्मिनल 창은 자동으로 열린다. 연결한 VNC 창에 키를 입력하면 स्वकीय 커널의 셸로 전달된다. 종료하려면 `make desktop`을 실행한 होस्ट 터미널에서 Ctrl+C를 누른다. 포트를 바꾸려면 सिस्टम_बांधणी नंतर_राज्य `python3 साधने/आज्ञा_कार्यवाही_करा.py --desktop --port 5903`을 사용한다. 서버는 localhost에만 바인드하며 동시에 한 클라이언트가 제어한다.

일반 UART 셸은 `make run`으로 시작한다. QEMU 종료는 Ctrl+A पुढील_आयटम X이다. 같은 VM의 UART에서 `terminal` 또는 F12로 GUI 터미널을 स्तंभ_मूल्य संख्या 있다. `gui` आज्ञा_कार्यवाही_करा 화면에서는 다섯 번째 **OPEN TERMINAL** 버튼, अंक_मूल्य 5 또는 T로 연다. `--vnc 127.0.0.1:2`만 사용한 기존 आज्ञा_कार्यवाही_करा 방식은 पडदा 보기용이며, VNC 키보드를 연결하려면 `--desktop`을 사용한다.

FTP와 बाह्य_मूल्य 네트워크도 함께 쓰려면 `python3 साधने/आज्ञा_कार्यवाही_करा.py --desktop --network`로
실행한다. Remmina VNC는 `127.0.0.1:5902`, 게스트에서 `ftpd start` नंतर_राज्य FTP는
`127.0.0.1:2121`이다. `--port`, `--ftp-port`, `--forward`를 함께 지정할 संख्या 있다.
한 VM의 सहायक_मूल्य UART로 SLIP를 전송하고 주 UART로 GUI 입력을 전달한다.

QEMU आज्ञा_कार्यवाही_करा 도구가 VNC 키보드/마우스를 UART 입력으로 변환한다. वास्तविक_डेटा Pi4의 USB 키보드·마우스 드라이버를 구현한 것은 아니다. वास्तविक_डेटा 보드에서는 सध्याचे_आयटम UART 입력이 필요하며 भौतिक_हार्डवेअर 부팅은 아직 미검증이다.

## 창과 आदान_मूल्य

- 640×480~1920×1080 화면에서 कमाल_मूल्य 네 개 टर्मिनल विंडो, डिफॉल्ट_मूल्य 568×360(68열 × 19행)과 अलीकडे_मूल्य 160행 जतनकरा_मूल्य, डिफॉल्ट_मूल्य ANSI पिक्सेल_रंग·कर्सर_मूल्य·पुसा_प्रविष्टी प्रक्रिया_मूल्य_प्रविष्टी.
- 상단 **+ New terminal** 또는 Ctrl+Shift+T로 새 창을 연다. 제목줄을 끌어 이동하고 विंडो/상단 버튼을 클릭하거나 F6으로 전환한다. 각 창의 पारपाडा_कार्य मार्ग·चल_मूल्य·आदेश लॉग_नोंद·आदान_मूल्य 중인 줄은 독립적이다.
- UTF-8 हांगुल_मजकूर·CJK·라틴 문자와 일부 이모지 비트맵 फॉन्ट_मूल्य. 복잡한 वर्ण 조판·एकत्र_मूल्ये वर्ण·양방향 लिंक_लेआउट·모든 Unicode 글리프를 보장하지 않는다.
- 좌우 방향키/Home/End/Delete/Backspace로 명령을 편집하고 위아래 방향키로 अलीकडे_मूल्य 16개 명령을 찾는다. 긴 명령은 आदान_मूल्य 줄을 가로로 이동해 보여 주며 `<`, `>`पहिले_संकार्य 숨겨진 부분을 나타낸다.
- Tab은 आदेश नाव 또는 सध्याचे_आयटम 디렉터리의 파일명에서 후보가 하나일 때 완성한다. 디렉터리를 포함한 मार्ग 접두사·कोट 안의 완성은 아직 없다.
- Ctrl+A/E: प्रारंभिक_आयटम/शेवट, Ctrl+U/K: कर्सर_मूल्य पुढील_मूल्य/मागे_मूल्य 삭제, Ctrl+C: आदान_मूल्य रद्द_करा_क्रिया. आज्ञा_कार्यवाही_करा 중인 임의 프로그램에 SIGINT를 보내는 기능은 없다. vi와 Swing의 आदान_मूल्य 대기는 आज्ञा_कार्यवाही_करा 기한을 갱신하지만 일반 계산의 약 2초 제한은 유지한다.
- PgUp/PgDn 또는 마우스 휠: मागील_आयटम आउटपुट. 새 출력이 오면 नवीनतम_मूल्य 위치로 돌아온다.
- F12/शीर्षक_पट्_टी उजवे 버튼/`exit`: विंडो बंद_करा. 빈 입력에서 Ctrl+D도 창을 닫는다. VM을 종료하는 명령은 아니다.

`--desktop`의 VNC आदान_मूल्य 연결에 **두벌식 हांगुल_मजकूर संयोजन_मूल्य**을 제공한다. 접속한 PC의
입력기를 영어로 두고 **F9**, **Shift+Space**, **한/शून्य_संकार्य कळ_मूल्य** 중 하나를 누르면
विंडो 제목이 `[EN]`에서 `[KO]`로 바뀐다. `gksrmf` → `हांगुल_मजकूर`,
`dkssudgktpdy` → `안녕하세요`. 같은 키로 영어로 돌아간다.
겹받침·복합 모음과 संयोजन_मूल्य 단계별 Backspace를 지원한다. कर्सर_मूल्य हलवा_मूल्य·마우스 क्लिक_करा_मूल्य·
단축키·चिकटवा_मूल्य·Enter 때 조합을 확정한다. PC가 Shift+Space나 한/शून्य_संकार्य 키를
स्वकीय 처리하면 **F9**를 사용한다. Alt 단독은 स्विच_मोड 키가 아니다.

이 조합기는 QEMU의 VNC→UART आदान_मूल्य 연결에서 실행된다. 일반 अनुक्रमिक_मूल्य 접속과
भौतिक_हार्डवेअर Pi의 USB 키보드 입력기에 추가된 기능은 아니다. 이미 완성된 Unicode
हांगुल_मजकूर 키도 그대로 전달한다. 클립보드 공유가 활성화되어 표준 VNC ClientCutText가
도착하면 Ctrl+Shift+V로 붙여 넣는다. 클립보드 동기화만으로 명령을 실행하지 않는다.
줄바꿈을 포함해 명시적으로 붙여 넣으면 해당 줄이 실행된다.

게스트에서 `help` 또는 `help ko`를 입력하면 हांगुल_मजकूर आदान_मूल्य 안내를 볼 संख्या 있다.
`help`와 `help ko`에는 한/शून्य_संकार्य कळ_मूल्य·Shift+Space·F9 및 `[EN]`/`[KO]` 안내를 표시한다.
긴 도움말은 PgUp/PgDn으로 스크롤한다.

터미널에서 Java·Python·C++ आज्ञा_कार्यवाही_करा 결과를 바로 볼 संख्या 있다. 프로그램이 직접 프레임버퍼에 그림을 그린 경우 निर्गमन_करा_अनुप्रयोग नंतर_राज्य टर्मिनल 창을 복원한다. vi/Swing प्रतीक्षा_करा_मूल्य 중 다른 창으로 전환하면 해당 EL0 프로그램의 स्मृती_डेटा·레지스터를 보관하고 돌아올 때 재개한다. निवड_मूल्य इन्स्टन्स_मूल्य·PTY·전체 VT100/xterm 호환과 임의 프로그램의 동시 병렬 실행은 제공하지 않는다. X로 닫으면 해당 창의 프로그램도 종료되므로 vi에서 저장하지 않은 내용은 사라진다.

## 문법과 मर्यादा_मूल्य

작은따옴표·큰따옴표·백슬래시, `$NAME`/`${NAME}`/`$?`, शब्द_मूल्य पुढील_मूल्य `~`, ओळ 주석 `#`, 순차 आज्ञा_कार्यवाही_करा `;`, सशर्त आज्ञा_कार्यवाही_करा `&&`/`||`, 파이프 `|`, आदान_मूल्य `<`, 새 आउटपुट `>`, शेवटीजोडा_प्रविष्टी आउटपुट `>>`를 제공한다. चल_मूल्य 확장은 बाबी 안에서 수행하며 एक्सटेंशन_मूल्य 결과를 공백으로 पुनःप्रयत्न_मूल्य 나누지 않는다. `export`의 값은 शेल 안에서만 공유하며 प्रयोक्ता ELF의 envp/getenv 환경은 아직 없다.

파이프는 각 단계를 순서대로 실행하고 कमाल_मूल्य **16384바이트**를 पुढील_आयटम 단계로 넘긴다. 여러 프로세스가 동시에 읽고 쓰는 POSIX 파이프가 아니다. धारणक्षमता_मूल्य 초과는 त्रुटी 28과 बिघाड_मूल्य 상태를 반환하고 해당 실행을 중단한다. `<`는 EOF를 제공하며 `>`/`>>`는 stdout만 바꾼다. EL0 fd 2는 पडदा/UART로 출력된다. `2>` 등 번호를 붙인 리다이렉션은 거부한다. 일부 내장 명령의 진단은 stdout을 사용한다. 연결한 프로그램의 `exit N` 진단은 데이터에 섞이지 않도록 생략한다.

`vi`, `edit`, `load`, `gui`, `terminal`, `sh`, `source`에는 파이프와 리다이렉션을 적용할 संख्या 없다. 리다이렉션 파일을 열지 못하거나 파이프 용량을 초과하면 सध्याचे_आयटम 명령줄을 중단하며, 그 줄의 뒤쪽 `||` 명령도 실행하지 않는다. लिपी_मूल्य 파일을 입력할 때 멀티라인 कोट·पुढीलक्रम_मूल्य 쓰기는 제공하지 않는다. `if`/`for`/`while`, फलन_मूल्य, आदेश 치환, glob, पर्यायी_नाव, 백그라운드 `&`, jobs/fg/bg, 일반 프로세스·신호·PTY는 아직 없다. Bash/POSIX sh 전체 호환으로 표시하지 않는다.

फाइल 64개 × 각 16384바이트, 루트 외 디렉터리 15개, फाइल विवरणक_प्रविष्टी 16개, मार्ग कमाल_मूल्य UTF-8 63바이트다. समकक्ष_मूल्य/절대 경로와 `.`/`..`를 정규화하지만 परवानगी_मूल्य·심볼릭 링크·마운트·디스크 영속 저장은 없다. **फाइल·디렉터리·चल_मूल्य·기록의 सुधारा_मूल्य 내용은 재부팅하면 사라진다.** प्रयोक्ता 실행도 सध्याचे_आयटम शेल 경로를 사용한다. Java/Python/C++의 फाइल API는 같은 RAM 저장소를 본다. `/example`의 तीन_मूल्य भाषा 예제와 설명서는 부팅할 때 원본으로 준비된다.

한 명령줄은 4096바이트, 구문 टोकन_मूल्य 128개, आज्ञा_कार्यवाही_करा बाबी 32개, 변수는 16개(नाव 31바이트·मूल्य 255바이트)까지다. प्रयोक्ता 프로그램에 전달하는 인수는 기존 ABI대로 कमाल_मूल्य 8개·각 255바이트다. आदेश 기록은 1024바이트 이하 줄을 अलीकडे_मूल्य 16개까지 저장한다.

शेल 시험은 वास्तविक_डेटा raspi4b QEMU에서 मार्ग·फाइल·चल_मूल्य·सशर्त·파이프·리다이렉션·त्रुटी पुनर्प्राप्त_करा_राज्य·लिपी_मूल्य·편집을 검사하고, Java/Python 출력과 Python stdin의 EOF를 확인한다. 결과와 पडदा: [शेल मोजमाप](build/verification/shell/report.json), [VNC मोजमाप](build/verification/desktop/report.json), [टर्मिनल पडदा](build/verification/desktop/vnc-terminal.png). फॉन्ट_मूल्य उगम_मूल्य·हॅश_संचिका·라이선스는 [vendor](vendor/README.md)에 있다.

## 마우스로 आकार बदल_करा_मूल्य

네 모서리의 안쪽 8픽셀에 마우스를 대면 방향에 맞는 대각선 양방향 포인터가
나타난다. **डावे_बाजू 버튼을 누른 채 끌고 놓는다.** उजवे 버튼으로는 크기가 바뀌지 않는다.
विंडो_शीर्षक 표시줄의 बाकी_मूल्य 부분은 हलवा_मूल्य, उजवे वरचे_मूल्य X는 닫기다.
किमान_मूल्य 크기는 360×216이며 कमाल_मूल्य 크기는 सध्याचे_आयटम पडदा 안에 제한된다.
각 창의 वर्ण_मूल्य 칸은 `(रुंदी_विस्तार-24)/8`स्तंभ_मूल्य, `(उंची_मूल्य-56)/16`행이다. `terminal size`로 조회한다.

명령줄의 आदान_मूल्य·कर्सर_मूल्य·기록과 vi의 미저장 문서를 유지하며 보이는 영역을 갱신한다.
지난 출력은 저장된 ओळ 단위를 유지하고, 좁아진 창에서 가려진 열은 पुनःप्रयत्न_मूल्य 넓히면
볼 संख्या 있다. 과거 आउटपुट 전체를 새 너비에 맞춰 재배열하는 기능은 아니다.
크기를 바꾼 मागे_मूल्य 출력되는 글은 새 स्तंभ_मूल्य 수로 줄바꿈한다. vi는 आदान_मूल्य प्रतीक्षा_करा_मूल्य 중에도
SVC 16의 कृती 3으로 सध्याचे_आयटम आकार(상위 16비트 ओळ_मूल्य, 하위 16비트 स्तंभ_मूल्य)를 조회한다.
परस्परसंवादी tty의 गाभा_मूल्य पडदा आउटपुट 시간은 प्रयोक्ता गणना 기한에서 제외하며, आदान_मूल्य प्रतीक्षा_करा_मूल्य 없이
계산만 반복하는 प्रयोक्ता 프로그램의 वेळ_मूल्य 제한은 유지한다.
커널이 프레임버퍼에 포인터를 그리며, Remmina 중계는 दूरस्_थ_मूल्य 포인터를 숨겨 중복을 피한다.
로컬 VNC 중계는 डिफॉल्ट_मूल्य Raw 인코딩을 사용한다.

प्रमाणित: `make test-resize` — 640×480·1920×1080에서 네 कोपरा_मूल्य, डावे_बाजू/उजवे 버튼,
किमान_मूल्य·कमाल_मूल्य आकार, निर्देशक 복원, आदान_मूल्य 보존, vi साठवणे_मूल्य·पुढेचालूकरा_प्रक्रियाकरण आदान_मूल्य, 창별 크기를 확인한다.
