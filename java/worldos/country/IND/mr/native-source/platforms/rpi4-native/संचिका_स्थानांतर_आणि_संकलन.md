# स्वकीय ARM64 गाभा_मूल्य: FTP, C, JAR와 AOT आज्ञा_कार्यवाही_करा

대상은 **Linux를 적재하지 않는 Raspberry Pi 4용 Java AOT गाभा_मूल्य**이다. CPU·मोबाइल_मूल्य 경계는 C/어셈블리, फाइल 체계와 셸은 Java이며, 이번 TCP/IP 스택은 C로 작성된 lwIP 2.2.0을 이식했다. 게스트 TinyCC와 `jaot`도 EL0에서 실행한다. 호스트에 컴파일을 요청하거나 होस्ट JVM으로 대신 실행하지 않는다.

## 먼저 알아둘 समर्थन_मूल्य सीमा_मूल्य

| विनंती | 이번 अंमलबजावणी | 남은 क्लिप |
|---|---|---|
| JAR를 आज्ञा_कार्यवाही_करा 파일처럼 आज्ञा_कार्यवाही_करा | `java -jar फाइल.jar`, `./फाइल.jar बाबी`; Main-Class와 साठवणे_मूल्य/DEFLATE ZIP, CRC पडताळण्या | 전체 Java SE, 임의의 모든 JAR 호환성 |
| 게스트 AOT | `jaot फाइल.class -o फाइल.elf`, `jaot फाइल.jar -o फाइल.elf`; वास्तविक_डेटा ARM64 기계어 तयार_करा | ऑब्जेक्ट_मूल्य·अपवाद·Thread·Swing·Socket의 AOT रूपांतरकरा_मूल्य, 여러 애플리케이션 वर्ग_मूल्य जोडा |
| C स्रोत_बांधणी | 게스트 `cc`/`tcc`, TinyCC C 전처리기·ARM64 생성기·링커; मराठी 식별자와 posix-kor | 전체 libc, 일반 Linux आज्ञा_कार्यवाही_करा फाइल, 게스트 C++ संकलक |
| 업로드한 ELF आज्ञा_कार्यवाही_करा | ELF64/AArch64 헤더 पडताळण्या, 확장자 없는 `./फाइल`; स्वकीय ABI 및 명시적인 제한형 Linux ABI | 일반 Linux 바이너리 호환, 동적 링커, 공유 लायब्ररी |
| बाह्य_मूल्य TCP/UDP | 게스트 lwIP IPv4 संकार्य_स्टॅक, POSIX 소켓과 JVM의 अंक_मूल्य IPv4 पत्ता | GENET/Wi-Fi 드라이버, DHCP·DNS·TLS, भौतिक_हार्डवेअर बोर्ड 네트워크 चाचण्या |
| FTP | 게스트 서비스, 패시브 स्थानांतर_मूल्य, UTF-8 नाव, STOR/RETR/SIZE/LIST/NLST/MLSD/DELE | TLS·사용자별 परवानगी_मूल्य·하위 디렉터리·영속 साठवणे_मूल्य |
| हांगुल_मजकूर Java | 기존 `मराठी.स्वकीय` 클래스와 बाह्य_मूल्य पत्ता UDP 오버로드 | 전체 JDK의 일대일 मराठी प्रतिचित्रण_मूल्य API |

JVM은 वर्ग_मूल्य 버전 45…52의 문서화한 부분집합이다. `java`는 बाइटसंहिता 실행기이고, `jaot`पहिले_संकार्य 별도의 네이티브 आज्ञा_कार्यवाही_करा 파일을 만든다. **JAR संग्रह_मूल्य 해제나 JVM을 함께 묶는 것을 AOT라고 표시하지 않는다.** 지원하지 않는 बाइटसंहिता/API는 `jaot`पहिले_संकार्य 진단하고 출력을 만들지 않는다. 기존 आउटपुट ELF도 स्रोत_बांधणी बिघाड_मूल्य 때 보존한다.

Android의 Dalvik/ART는 일반 JVM वर्ग_मूल्य/JAR가 아닌 **DEX**를 실행한다. ART의 AOT에는 GC, वर्ग_मूल्य 로딩, JNI 등 आज्ञा_कार्यवाही_करा 기반도 필요하다. 따라서 ART처럼 기계어로 바꾸는 기능만으로 임의의 OpenJDK JAR 및 Swing이 자동 호환되지는 않는다. [Android 공식 런타임 वर्णन](https://source.android.com/docs/core/runtime)

FTP는 루트 RAM 파일만 공개한다. 익명 로그인이며 비밀번호로 권한을 구분하지 않는다. डिफॉल्ट_मूल्य होस्ट 바인딩은 `127.0.0.1`이고, नियंत्रण_मूल्य 포트는 2121, 데이터 포트는 50000…50007이다. `--ftp-port 2122`로 नियंत्रण_मूल्य 포트를 바꿀 संख्या 있다. 동시에 한 FTP 세션을 제공하며 명령이 없는 세션은 60초 नंतर_राज्य 닫는다. TYPE A도 바이트를 변경하지 않으므로 프로그램은 바이너리 전송한다.

파일은 **64개, 각각 16 KiB**, 경로는 UTF-8 63바이트이다. प्रणालीप्रारंभ 시 준비되는 `/example`도 이 한도를 공유한다. 초과/끊어진 STOR는 기존 파일에 반영하지 않는다. FTP 업로드는 RAM에만 저장되며 재부팅하면 사라진다. 이 मर्यादा_मूल्य 때문에 일반적인 대형 JAR 배포판을 그대로 올릴 संख्या 없다.

QEMU의 raspi4b에는 GENET Ethernet 장치가 없다. 따라서 `network_bridge.py`पहिले_संकार्य QEMU NAT의 Ethernet과 सहायक_मूल्य UART의 SLIP를 변환한다. **TCP जोडा प्रक्रिया_मूल्य_प्रविष्टी·체크섬·재전송·FTP 명령과 फाइल 저장은 게스트 안에서 수행한다.** होस्ट 브리지는 FTP 서버가 아니다. [QEMU 공식 मोबाइल_मूल्य समर्थन_मूल्य प्रविष्टी_यादी](https://www.qemu.org/docs/master/system/arm/raspi.html)

이 경로는 QEMU에서 검증했다. सहायक_मूल्य UART의 वास्तविक_डेटा Pi 4 핀/클럭 설정과 내장 RJ45 GENET 드라이버는 अंमलबजावणी·검증하지 않았으므로, SD 이미지에 커널이 포함되어 있다는 사실을 वास्तविक_डेटा 보드의 LAN/FTP कृती 보장으로 해석하면 안 된다.

## मराठी Java를 게스트에서 컴파일하고 AOT आज्ञा_कार्यवाही_करा

게스트 `vi रंग.java`로 पुढील_आयटम 소스를 작성한다.

```java
public class रंग {
    public static void main(String[] बाबी) throws Exception {
        int बेरीज_मूल्य = 0;
        int संख्या = 1;
        while (संख्या <= 10) {
            बेरीज_मूल्य = बेरीज_मूल्य + संख्या;
            संख्या = संख्या + 1;
        }
        मराठी.स्वकीय.आउटपुट.संख्या_लिहा(बेरीज_मूल्य);
        मराठी.स्वकीय.फाइल.लेखन("aot.txt", "हांगुल_मजकूर AOT फाइल 😀");
        मराठी.स्वकीय.आउटपुट.ओळ_लिहा(मराठी.स्वकीय.फाइल.वाचन("aot.txt"));
    }
}
```

```text
javac रंग.java
java रंग
jaot रंग.class -o रंग.elf
run रंग.elf
```

`jaot`은 클래스의 바이트코드를 C로 변환하고, **게스트 TinyCC**पहिले_संकार्य ARM64 명령어를 तयार_करा·연결한다. आज्ञा_कार्यवाही_करा 때 JVM 인터프리터를 호출하지 않는다. JAR의 Main-Class가 같은 समर्थन_मूल्य 범위이면 다음도 가능하다.

```text
jaot रंग.jar -o रंग.elf
run रंग.elf
```

AOT 지원은 한 애플리케이션 클래스의 स्थिर_मूल्य पद्धत_मूल्य/फील्ड_मूल्य, int 계열, पूर्णांक 배열과 संदर्भ, बाबी ऍरे_मूल्य, सशर्त·शाखा·पुनरावृत्ती_मूल्य, स्ट्रींग_मूल्य 리터럴, `System.out.print/println`의 int/String, मराठी आउटपुट·फाइल वाचन/쓰기로 제한된다. वर्ग_मूल्य/पद्धत_मूल्य 수와 संकार्य_स्टॅक 등에도 고정 상한이 있다. Java अपवाद प्रक्रिया_मूल्य_प्रविष्टी, ऑब्जेक्ट_मूल्य तयार_करा, 가상 पद्धत_मूल्य 일반, switch/wide, long/float/double, invokedynamic, स्ट्रींग_मूल्य 결합용 StringBuilder, 일반 JDK·Socket·Thread·Swing은 이 AOT 백엔드에서 미지원이다. 내장 NUL/고립된 서로게이트 문자열도 거부한다. 잘못된 ऍरे_मूल्य ऍक्सेस_प्रविष्टी/0으로 भागाकारकरा_मूल्ये 등은 네이티브 런타임 오류로 종료하며 Java अपवाद 객체로 전달하지 않는다.

आदान_मूल्य 클래스뿐 아니라 **생성된 ELF도 16 KiB 이하**여야 한다. 기계어 확장과 ELF 페이지 संरेखन_करावे_मूल्य 때문에 짧은 클래스도 이 한도를 넘을 संख्या 있으며, 이 경우 오류를 내고 기존 출력을 보존한다.

게스트 `javac`도 부분집합이다. 일반적인 ऑब्जेक्ट_मूल्य·Thread·Swing 소스는 호스트에서 `javac --release 8`로 컴파일하고, **기존 JVM의 समर्थन_मूल्य क्लिप 안에서** `java`/`java -jar`로 실행한다. 정확한 API는 [JVM 매뉴얼](जावा_सामान्य_भाषा_रनटाइम_पर्यावरण.md)과 [हांगुल_मजकूर विकास 매뉴얼](विकास_मार्गदर्शी.md)을 참고한다.

JAR는 하나의 애플리케이션 वर्ग_मूल्य 경로다. 내부 नाव `बंडल/अनुप्रयोग_f5044b9b.class`와 점으로 구분한 Main-Class를 지원한다. 내부 클래스는 파일로 풀어 VFS 슬롯을 소비하지 않는다. 내장 मराठी 클래스를 추가로 찾지만 सध्याचे_आयटम पारपाडा_कार्य 폴더의 다른 클래스는 자동 혼합하지 않는다. ZIP64·ऍनक्रिप्ट_करा_डेटा ZIP·manifest Class-Path·서명 검증은 지원하지 않는다. JAR 하나가 16 KiB 이하이어도 클래스당/적재 संख्या/VM गतिमानस्मृतिराशी_मूल्य 제한은 그대로 적용된다.

## C에서 मराठी POSIX आवाहन

게스트에서 `vi अभिवादन_ae353e94.c`로 작성하거나 FTP로 소스를 업로드한다.

```c
#include <संचिका_द्विमानजोडणी.h>

int main(void) {
    const char अभिवादन[] = "स्वकीय ARM64 C에서 हांगुल_मजकूर POSIX आवाहन\n";
    int मार्गदर्शिका = संचिका_उघडा("अभिवादन_ae353e94.txt", वाचणे_लिहिणे | जर_अनुपस्थित_तयार_करा | छाटूनरिकामेकरा_सामुग्री, 0600);
    if (मार्गदर्शिका < 0) return 1;
    आदानप्रदान_मोजमाप_टाइप_करा नोंदवलेले_संख्या = संचिका_डेटा_लिहा(मार्गदर्शिका, अभिवादन, sizeof(अभिवादन) - 1);
    संचिका_मिटवा(मार्गदर्शिका);
    संचिका_डेटा_लिहा(1, अभिवादन, sizeof(अभिवादन) - 1);
    return नोंदवलेले_संख्या == sizeof(अभिवादन) - 1 ? 0 : 2;
}
```

```text
cc अभिवादन_ae353e94.c -o अभिवादन_ae353e94.elf
run अभिवादन_ae353e94.elf
cat अभिवादन_ae353e94.txt
```

TinyCC의 표준 C प्रविष्टी_गुण `main`을 사용한다. 기존 होस्ट C/C++ SDK의 `प्रारंभ_प्रयोक्ता_अनुप्रयोग(int)` 진입점과 구분한다. घोषणाशीर्षे फाइल·सुरू_करा ऑब्जेक्ट_मूल्य·`libposix-kor-user.a`는 संकलक 내부의 वाचन 전용 SDK에 들어 있다. C 전처리기/구조체/फलन_मूल्य/재귀/निर्देशक/부동소수점 तयार_करा 등을 사용하되 **일반 libc/libstdc++를 제공한다는 뜻은 아니다**. 제공하지 않는 함수는 जोडा 오류가 난다. संकलक 자체의 वर्ण/अंक_मूल्य रूपांतरकरा_मूल्य 지원도 완전한 libc 대체품이 아니다.

`संचिका_उघडा` 등은 별도의 모의 호출이 아닌 기존 `pk_open` 등의 मराठी 매크로이며, ELF의 SVC를 통해 वास्तविक_डेटा Java फाइल 체계에 도달한다. फाइल/संचारद्वार_मूल्य आवाहन 목록은 [प्रयोक्ता ABI](प्रयोक्ता_कॉल_द्विमानजोडणी.md)에 있다. C/C++ होस्ट SDK आज्ञा_कार्यवाही_करा 파일도 FTP로 업로드 नंतर_राज्य `run` 또는 `./फाइल`로 실행하며 확장자는 आवश्यक_मूल्य 없다. Linux ARM64 स्थिर_मूल्य ELF에는 별도의 제한된 호환 मार्ग `run --linux फाइल`을 추가했다. [ELF·Linux ABI 매뉴얼](निष्पादनीय_द्विमानजोडणी.md)에 정확한 स्वरूप_मूल्य·시스템 आवाहन·पत्ता 제한을 정리했다.

## मराठी 네트워크·पारपाडा_कार्य·पडदा API

| वर्ग_मूल्य | आवाहन 예 | आज्ञा_कार्यवाही_करा मार्ग |
|---|---|---|
| `आउटपुट` | `ओळ_लिहा("안녕")`, `संख्या_लिहा(42)` | JVM 및 제한형 AOT |
| `फाइल` | `लेखन("मार्गदर्शिका.txt", "सामुग्री_मूल्य")`, `वाचन("मार्गदर्शिका.txt")` | JVM 및 제한형 AOT |
| `संचार` | `उघडा(0)`, `पाठवा(संचारटोक, "10.0.2.2", 9000, "हांगुल_मजकूर")`, `स्वीकारा(संचारटोक)` | JVM의 UDP |
| `कनेक्शन_वाहतूक` | `जोडा("10.0.2.2", 9000)`, `ऐका_संचारटोक(9000)`, `स्वीकारा(सर्व्हर_मूल्य)` | JVM의 Socket/ServerSocket |
| `पारपाडा_कार्य` | `सुरू_करा(Runnable)`, `प्रतीक्षाकरा(Thread)`, `निलंबित_करा_कार्य()` | JVM의 협력식 कार्यसूत्र_मूल्य_5b72a632 |
| `विंडो`, `विजेट` | विंडो·버튼·वर्ण_मूल्य·मजकूर_फील्_ड·इव्हेंट जोडा | JVM의 Swing 부분집합 |

명명에서는 표준 영어 API를 보존하고 मराठी आवाहन 계층을 추가한다. `संचार(通信)`, `जोडा(連結)`, `आउटपुट(出力)`은 기존 단어의 뜻을 사용한다. `पारपाडा_कार्य कार्यसूत्र_मूल्य_5b72a632`은 한 आज्ञा_कार्यवाही_करा 흐름을 가닥에 빗댄 विवरणक_मूल्य 표현, `पॉर्ट_मूल्य`는 포트의 접점을 설명하는 표현이다. 새 विवरणक_मूल्य 결합어를 고대에 이미 존재한 용어처럼 설명하지 않는다. 전체 JDK의 번역을 완료했다고 표시하지 않는다.

बाह्य_मूल्य 주소는 अंक_मूल्य IPv4이며 QEMU 호스트는 `10.0.2.2`, 게스트는 `10.0.2.15`तिसरे_संकार्य. UDP 전문은 512바이트까지다. 소켓은 비차단 स्वकीय ABI이며 JVM이 제한된 प्रतीक्षा_करा_मूल्य/재시도를 제공한다. TCP connect 대기는 कमाल_मूल्य 1초, प्रयोक्ता अनुप्रयोग_f5044b9b 전체에는 기존 약 2초 CPU 기한이 적용된다. 일반적인 장기 आज्ञा_कार्यवाही_करा प्रयोक्ता 서버와 pthread는 아직 없다. FTP는 प्रयोक्ता अनुप्रयोग_f5044b9b 기한과 별개인 गाभा_मूल्य 서비스다.

게스트의 प्रयोक्ता TCP/UDP 서버로 들어오는 연결은 NAT 포트를 추가한다. 예를 들어 `python3 साधने/आज्ञा_कार्यवाही_करा.py --network --forward tcp:9300:9300 --forward udp:9301:9301`로 실행하면 호스트의 localhost 9300/TCP·9301/UDP를 게스트의 같은 포트로 전달한다. FTP의 डिफॉल्ट_मूल्य नियंत्रण_मूल्य/데이터 포트와 겹치면 आज्ञा_कार्यवाही_करा 전에 거부한다.

## 시험과 सिस्टम_बांधणी 재현

```sh
cd /home/user/jkoros/platforms/rpi4-native
make test-ftp
make test
make image
```

`build/verification/ftp/report.json`은 वास्तविक_डेटा FTP स्थानांतर_मूल्य, हांगुल_मजकूर फाइल, आकार 초과 보존, संग्रह_मूल्य JAR आज्ञा_कार्यवाही_करा, 게스트 C स्रोत_बांधणी/ELF 재업로드, बाह्य_मूल्य Java TCP/UDP, 게스트 javac/AOT 실행을 기록한다. `serial.log`에서 게스트 명령과 결과를 확인할 संख्या 있다. 보고서의 गाभा_मूल्य SHA-256과 वितरण_मूल्य 이미지의 커널을 비교한다.

빌드는 기존 JDK/Clang/AArch64 binutils와 함께 `../rpi4/build/rootfs`의 ARM64 SDK घोषणा 헤더와 libgcc अंकगणिती_मूल्य सहायक_मूल्य 함수를 사용한다(`make rpi-prepare`). **musl libc, Linux गाभा_मूल्य, 동적 로더를 게스트에 링크하지 않는다.** TinyCC/lwIP/uzlib 원본과 라이선스·버전 정보는 `vendor/`, अनुकूलन 코드는 `ccompiler/`, `network/`, `प्रयोक्ता/बंडल.c`에 있다.

전체 JDK/AOT JVM으로 확장하려면 타입 प्रमाणित·ऑब्जेक्ट_मूल्य/अपवाद/GC·동적 로딩·JNI, 영속 फाइल ऑपरेटिंग_सिस्टम_मूल्य·mmap/TLS/시그널·스레드 ABI, OpenJDK native लायब्ररी, GUI peer/폰트/입력기, GENET 및 भौतिक_हार्डवेअर मोबाइल_मूल्य 검증이 더 필요하다. 이 문서의 आज्ञा_कार्यवाही_करा 시험은 그 전체 이식을 대신하지 않는다.
