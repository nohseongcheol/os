# स्वकीय ARM64 커널의 आज्ञा_कार्यवाही_करा थर_मूल्य·프로세스 मूल्य_शो·QEMU बाह्य_मूल्य संचार

2026-10-04 तपासा_राज्य. 대상은 `jkoros/platforms/rpi4-native`의 स्वकीय Java 커널이다.
`platforms/rpi4`의 Linux/OpenJDK 판이나 `os`의 기존 x86 판에 이 결과를 적용하지 않는다.

## आज्ञा_कार्यवाही_करा थर_मूल्य

| लक्ष्य | आज्ञा_कार्यवाही_करा जागा | सध्याचे_आयटम अंमलबजावणी |
|---|---|---|
| शेल, `sh` लिपी_मूल्य, `ps`, `top`, फाइल 내장 आदेश | EL1 गाभा_मूल्य | Java AOT गाभा_मूल्य 함수로 आवाहन |
| टर्मिनल 창과 शेल राज्य_मूल्य | गाभा_मूल्य | कमाल_मूल्य 4개의 상태를 जतनकरा_मूल्य·복원; 독립 शेल 프로세스가 아님 |
| `java`, `javac` | EL0 प्रयोक्ता प्रदेश_मूल्य | `java-tools.elf`를 적재하고 별도 प्रयोक्ता संकार्य_स्टॅक·페이지 권한으로 आज्ञा_कार्यवाही_करा |
| `java CLASS`, `java -jar`의 अनुप्रयोग_f5044b9b | EL0의 स्वकीय JVM 내부 | बाइटसंहिता आज्ञा_कार्यवाही_करा. 전체 OpenJDK가 아님 |
| `jaot` मोजमाप ELF | EL0 | 지원되는 부분집합을 ARM64 코드로 컴파일한 नंतर_राज्य ELF로 आज्ञा_कार्यवाही_करा |
| `python`, `vi`, `cc`, प्रयोक्ता ELF | EL0 | प्रयोक्ता आज्ञा_कार्यवाही_करा फाइल 적재 मार्ग वापर_मूल्य |
| फाइल·संचारद्वार_मूल्य·그래픽 시스템 आवाहन | EL1 | EL0에서 SVC로 들어와 처리한 मागे_मूल्य प्रयोक्ता 프로그램으로 복귀 |

근거:

- `स्रोत/आज्ञा_अर्थविश्लेषक.java`: `साधन_प्रविष्टी()` 및 `java`/`javac` आदेश शाखा.
- `मशीन/प्रयोक्ता.c`: `रन_अनुप्रयोग()`의 ELF 적재, 페이지 परवानगी_मूल्य संयोजना, PID 배정, `प्रयोक्ता_प्रविष्ठ_करणे()`.
- `प्रणालीप्रारंभ/प्रविष्टी_गुण_मूल्य.S`: `user_enter`의 `SP_EL0`, `SPSR_EL1=0x340`, `eret`.
- `स्रोत/विंडो_सत्र.java`: 네 터미널의 शेल 상태와 प्रयोक्ता 세션 जतनकरा_मूल्य·पुन्हाचालूकरा_निष्पादन.

QEMU QMP로 CPU 0을 वास्तविक_डेटा 정지하여 읽은 परवानगी_मूल्य 상태는 शेल प्रतीक्षा_करा_मूल्य 중 `EL1h`, Java गणना 중 `EL0t`였다.
이 결과는 소스의 주석이나 आउटपुट 문자열만으로 판정한 것이 아니다.

## ps와 top에 기대한 항목이 없는 कारण_मूल्य

`स्रोत/सिस्टम_साधन.java`의 `कामे_शो()`पहिले_संकार्य 두 명령의 सामायिक_मूल्य 출력이다.
`1 ... kernel/shell`은 고정된 गाभा_मूल्य/शेल सांख्यिकी_मूल्य 행이다. 셸마다 생성한 वास्तविक_डेटा PID가 아니다.
그 다음에는 살아 있는 गाभा_मूल्य 협력 작업과 कमाल_मूल्य 4개의 EL0 세션을 조회한다.

1. 셸은 독립 प्रयोक्ता 프로세스가 아니므로 터미널을 더 열어도 `shell` 행이 각각 생기지 않는다.
2. 같은 터미널의 `java अभिवादन_ae353e94`पहिले_संकार्य 끝난 मागे_मूल्य `ps`를 실행하면 해당 Java 세션은 이미 정리되어 표시되지 않는다.
3. `vi`दुसरे_संकार्य Swing 프로그램은 다른 터미널로 전환할 때 CPU संदर्भ_मूल्य·메모리를 보관한다. 이 상태가 `SUSPENDED`तिसरे_संकार्य.
4. 한 번에 सक्रिय EL0 프로그램은 하나다. 다른 창의 프로그램을 동시에 돌리는 일반 선점형 프로세스 스케줄러와 `&` पारपाडा_कार्य 제어는 없다.
5. Java의 पारपाडा_कार्य 가닥은 स्वकीय JVM 내부에서 협력적으로 전환한다. 별도 गाभा_मूल्य 스레드/TID가 아니므로 `ps`에 각각 나타나지 않는다.
6. `ps`·`top` 자체도 गाभा_मूल्य 내장 명령이므로 별도의 प्रयोक्ता PID가 생성되지 않는다. `top`은 같은 पारपाडा_कार्य 목록과 स्मृती_डेटा 정보를 주기적으로 보여 준다.

`RUN_ms`는 세션이 선택된 동안의 경과 시간이며 시스템 आवाहन 시간도 포함한다.
Linux의 정밀 CPU वापर_मूल्य 시간이나 CPU 사용률이 아니다. `MAPPED_KiB`도 प्रयोक्ता 페이지 매핑량이다.

실제로 확인하는 방법:

```text
cd /example/java
java खिडकीउदाहरण
```

GUI에서 `Ctrl+Shift+T`로 새 터미널을 열거나 `F6`으로 다른 터미널을 선택한 मागे_मूल्य:

```text
ps
top -n 1
```

이번 시험에서 두 명령에 पुढील_आयटम प्रयोक्ता 행이 나타났다. PID와 시간은 실행마다 달라진다.

```text
PID SLOT STATE MAPPED_KiB RUN_ms AGE_ms COMMAND
1 - RUN - - 25144 kernel/shell
24 0 SUSPENDED 9608 507 3960 java खिडकीउदाहरण
```

`खिडकीउदाहरण.class`는 चित्र_बांधणी सिस्टम_बांधणी 때 होस्ट `javac`로 컴파일되어 소스와 함께 탑재된다.
게스트 `javac खिडकीउदाहरण.java`는 सध्याचे_आयटम समर्थन_मूल्य 범위를 넘으며 `unsupported throws type` 오류를 낸다.
이 GUI 점검에는 이미 탑재된 클래스를 실행한다.

셸까지 EL0로 옮기고 프로그램을 동시에 실행하려면 प्रयोक्ता शेल आज्ञा_कार्यवाही_करा फाइल, 프로세스별 पत्ता पत्ता_प्रदेश·फाइल 기술자·पारपाडा_कार्य 디렉터리,
프로세스 तयार_करा/प्रतीक्षा_करा_मूल्य/निर्गमन_करा_अनुप्रयोग, 스케줄러, TTY इनपुट_आउटपुट, गाभा_मूल्य पारपाडा_कार्य·प्रयोक्ता पारपाडा_कार्य 구분을 추가해야 한다.
`ps` 출력에 이름만 추가해서는 प्रयोक्ता परवानगी_मूल्य 분리나 동시 실행이 구현되지 않는다.

## QEMU에서 외부로 통신하기

होस्ट 터미널에서 पुढील_आयटम 중 하나로 실행한다.

```sh
cd /home/user/jkoros/platforms/rpi4-native
make desktop ARGS="--network"
```

पडदा 없이 UART 셸만 사용할 때는 `make network`를 사용한다.
이미 VM이 आज्ञा_कार्यवाही_करा 중이면 निर्गमन_करा_अनुप्रयोग आधी_मूल्य RAM 자료를 보관한다. 별도 VM을 띄우려면
`make desktop ARGS="--network --port 5903 --network-host 127.0.0.2"`처럼 VNC와 फॉरवर्ड_मूल्य 주소를 구분한다.

게스트 안에서:

```text
ipconfig
ip route show
ping -c 2 10.0.2.2
```

초깃값은 `sl0`, पत्ता `10.0.2.15`, 넷마스크 `255.255.255.0`, गेटवे_मूल्य `10.0.2.2`तिसरे_संकार्य.
정상이면 पुनःप्रयत्न_मूल्य 설정할 필요가 없다. 주소를 바꿔 둔 경우 संचारद्वार_मूल्य/FTP를 닫은 मागे_मूल्य 기본값으로 돌릴 संख्या 있다.

```text
ftpd stop
ipconfig set 10.0.2.15 255.255.255.0 10.0.2.2
```

संचार मार्ग:

```text
게스트 Java/C/Python → SVC → गाभा_मूल्य lwIP → सहायक_मूल्य UART SLIP
    → होस्ट संचारजाळे_ब्रिज.py → QEMU user NAT → होस्ट TCP/IP → LAN/인터넷
```

QEMU `raspi4b`의 GENET Ethernet Controller는 미구현이다.
सध्याचे_आयटम 실행기는 일반 PC용 `-device e1000`이나 `virtio-net-pci` 대신 सहायक_मूल्य UART를 사용한다.
따라서 `-nic user`만 추가하거나 게스트 주소만 바꿔서는 이 संचार 경로를 대신할 संख्या 없다.
[QEMU Raspberry Pi मोबाइल_मूल्य समर्थन_मूल्य](https://www.qemu.org/docs/master/system/arm/raspi.html)

게스트에서 `127.0.0.1`은 게스트 자신이며, `10.0.2.2`पहिले_संकार्य QEMU 호스트에 접근하는 주소다.
그 밖의 वास्तविक_डेटा IPv4 주소로 향하는 TCP/UDP는 호스트의 मार्ग·방화벽·संचार 가능 여부에 따른다.
게스트 DNS와 일반 TLS 소켓은 아직 없다. 도메인 नाव 대신 अंक_मूल्य IPv4를 사용해야 한다. नंतर_मूल्य_ee1d8655 추가된 GENET·DHCP 및 게스트 SSH·VNC는 [बाह्य_मूल्य कनेक्शन_e05f319b वापरमार्गदर्शिका_eb81d7d9](बाह्य_कनेक्शन_मार्गदर्शी.md)를 참고한다.
`ping 10.0.2.2` 성공은 NAT 관문까지의 확인이지 인터넷 통신의 증거는 아니다.
인터넷 ICMP는 QEMU user NAT와 होस्ट `ping_group_range` 설정에 영향받으므로,
बाह्य_मूल्य ping 실패만으로 TCP/UDP 통신까지 불가능하다고 판단하지 않는다.
[QEMU NAT 및 ICMP वर्णन](https://www.qemu.org/docs/master/system/devices/net.html)

## वास्तविक_डेटा TCP/UDP 왕복 उदाहरणे

VM을 실행한 상태에서 호스트의 다른 터미널에서:

```sh
cd /home/user/jkoros/platforms/rpi4-native
python3 साधने/उदाहरण_प्रतिध्वनी.py --tcp-port 9000 --udp-port 9001
```

게스트 안에서:

```text
cd /example/java
java जाळेउदाहरण 9000 9001
cd /example/python
python जाळेउदाहरण.py 9001
```

Java 예제는 TCP와 UDP, Python 예제는 UDP를 होस्ट 응답기로 보내고 वास्तविक_डेटा 받은 자료를 비교한다.
Java 예제의 클래스는 이미 탑재되어 있다. 이 예제의 मूल्य_स्वीकारा 제한은 700ms이므로 느린 호스트에서는
उदाहरणे 자체의 वेळ_मूल्य 제한을 조정해야 할 संख्या 있다.

## होस्ट 또는 다른 PC에서 게스트로 접속하기

हार्डवेअर_पॉर्ट 전달을 आज्ञा_कार्यवाही_करा 시 명시한다.

```sh
make desktop ARGS="--network --forward tcp:18080:8080 --forward udp:19001:9001"
```

- होस्ट `127.0.0.1:18080/TCP` → 게스트 `10.0.2.15:8080/TCP`.
- होस्ट `127.0.0.1:19001/UDP` → 게스트 `10.0.2.15:9001/UDP`.
- 게스트 프로그램이 그 포트에서 실제로 수신해야 한다. फॉरवर्ड_मूल्य 옵션이 서버를 시작하지는 않는다.
- `ftpd start`는 별도로 게스트 FTP를 시작한다. डिफॉल्ट_मूल्य होस्ट नियंत्रण_मूल्य 포트는 2121, 수동 डेटा 포트는 50000~50007이다.

डिफॉल्ट_मूल्य `--network-host 127.0.0.1`은 루프백에만 연결한다. नंतर_मूल्य_ee1d8655 추가한 बाह्य_मूल्य कनेक्शन_e05f319b 기능에서는
`--network-host 0.0.0.0` 또는 होस्ट LAN 주소를 명시하면 다른 PC의 직접 접속도 허용한다.
[게스트 SSH·VNC आज्ञा_कार्यवाही_करा वापरमार्गदर्शिका_eb81d7d9](बाह्य_कनेक्शन_मार्गदर्शी.md)를 참고한다.
루프백 연결을 유지하면서 호스트의 SSH 서버를 이용할 경우 다른 PC에서 다음처럼 TCP 터널을 만든다.
`192.168.0.10`은 QEMU를 실행하는 호스트의 वास्तविक_डेटा ऍक्सेस_प्रविष्टी 가능한 IP로 바꾼다.

```sh
ssh -N -L 18080:127.0.0.1:18080 user@192.168.0.10
```

다른 PC의 클라이언트는 이제 स्वतः_संदर्भ `127.0.0.1:18080`에 연결한다.
이것이 SSH를 거쳐 호스트의 QEMU फॉरवर्ड_मूल्य 포트와 게스트 8080에 연결된다.
SSH의 `-L`은 TCP 전용이다. UDP를 LAN에서 직접 받거나 게스트를 LAN의 독립 IP로 쓰려면
शेवटीजोडा_प्रविष्टी UDP संदेशमध्यस्थ_मूल्य 또는 TAP/브리지 백엔드 연결이 필요하며 सध्याचे_आयटम आज्ञा_कार्यवाही_करा 옵션만으로는 제공하지 않는다.
FTP는 नियंत्रण_मूल्य 포트뿐 아니라 수동 डेटा हार्डवेअर_पॉर्ट 전체도 전달해야 한다.

QEMU를 Ubuntu 가상머신 안에서 실행하는 경우 위의 'होस्ट IP'는 그 Ubuntu의 주소다.
Ubuntu를 실행하는 바깥 가상화 프로그램도 해당 IP/SSH 포트에 ऍक्सेस_प्रविष्टी 가능한 네트워크 구성이 필요하다.

## तपासा_राज्य 재현과 पडताळा क्लिप

```sh
make test-layers
```

- QMP CPU 0 레지스터: शेल `EL1h`, Java गणना `EL0t`.
- 종료된 Java 프로그램의 `ps` प्रविष्टी_मूल्य प्रविष्टी_काढणे.
- Java GUI의 다른 टर्मिनल स्विच_मोड नंतर_राज्य 별도 PID 및 `SUSPENDED` 상태를 `ps`와 `top`에서 पडताळा.
- गेटवे_मूल्य ICMP 왕복, FTP वर्ग_मूल्य 업로드.
- 독립 होस्ट 상대와 TCP/UDP 발신, 명시적 हार्डवेअर_पॉर्ट 전달을 통한 TCP/UDP मूल्य_स्वीकारा 및 डेटा 비교.
- निर्गमन_करा_अनुप्रयोग 시 이번 점검이 만든 QEMU만 सुबक_बांधणी.

결과는 [보고서](build/verification/execution-network-review/report.json)와
[अनुक्रमिक_मूल्य लॉग_मूल्य](build/verification/execution-network-review/serial.log)에 저장한다.
보고서에 사용한 गाभा_मूल्य SHA-256과 원시 QMP 레지스터를 남긴다.
최초 시도에서는 지원하지 않는 GUI 소스의 게스트 재컴파일 단계가 실패했고,
`initial-attempt-report.json`/`initial-attempt-serial.log`에 기록을 보관했다.
탑재된 GUI वर्ग_मूल्य 사용으로 तपासा_राज्य 절차를 수정한 नंतर_राज्य वरचे_मूल्य 항목은 सर्व_बांधणी 통과했다.
