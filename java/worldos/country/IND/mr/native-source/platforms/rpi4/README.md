# jkoros Raspberry Pi 4 실행판

Raspberry Pi 4의 ARM64 Linux 실행판이다. 기존 `../../os`의 स्वकीय x86 Java 커널과 별도 प्रणालीप्रारंभ 경로다. Linux가 CPU·मोबाइल_मूल्य·स्मृती_डेटा·스레드·फाइल·네트워크를 제공하고, 전체 OpenJDK와 मराठी Java 작업마당이 그 위에서 실행된다.

Linux 없이 부팅하는 **स्वकीय Java ARM64 커널의 प्रारंभिक_राज्य 이식판**은 [rpi4-native](../rpi4-native/README.md)에 있다. 그 이식판에는 이 문서의 OpenJDK·Python·Swing 기능이 아직 구현되지 않았다.

## 제공 फाइल

`dist/`에 वास्तविक_डेटा 바이너리를 생성한다.

| फाइल | 용도 |
|---|---|
| `jkoros-rpi4-system.img` | microSD에 기록할 FAT प्रणालीप्रारंभ 파티션 + वाचन 전용 SquashFS 시스템 |
| `jkoros-user.img` | 별도 USB 저장장치에 기록할 ext4 प्रयोक्ता डेटा चित्र_बांधणी, 4 GiB |
| `*.img.gz`, `SHA256SUMS` | 전달용 संग्रह_मूल्य 이미지와 SHA256 प्रमाणित प्रविष्टी_यादी |
| `openjdk25-jdk-linux-aarch64-musl.tar.gz` | 컴파일된 ARM64 JDK |
| `openjdk25-jre-linux-aarch64-musl.tar.gz` | jlink로 구성한 컴파일된 ARM64 JRE |
| `स्वकीय_जावा.jar` | मराठी 이름으로 फाइल·वर्ण·संचार·पारपाडा_कार्य·화면을 사용하는 Java लायब्ररी |
| `manifest.json`, `java-runtimes.json` | चित्र_बांधणी/런타임 SHA256, 아키텍처와 구성 |
| `packages.lock.json`, `sources.lock.json` | वास्तविक_डेटा 설치된 패키지 버전·उगम_मूल्य·라이선스 सिस्टम_माहिती |

JDK/JRE는 이 실행판과 같은 **Linux ARM64 + musl** 환경용이다. 다른 libc/CPU/운영체제에서 단독 실행을 보장하지 않는다. 네이티브 의존 라이브러리는 संचालनप्रणाली 이미지에 함께 들어 있다. JRE는 Java SE와 문자셋·다국어·पासवर्ड_मूल्य·ZIP फाइल_सिस्टम 등 निवड_मूल्य 모듈을 포함하고, 전체 विकास 도구는 JDK에 있다.

## 설치와 आज्ञा_कार्यवाही_करा

1. Raspberry Pi Imager의 प्रयोक्ता नेमा_मूल्य चित्र_बांधणी 기능으로 `jkoros-rpi4-system.img`를 microSD에 기록한다.
2. **별도 USB संग्रह_मोबाइल**에 `jkoros-user.img`를 기록한다. 이미지가 4 GiB이므로 그보다 큰 장치가 필요하다. 장치의 기존 데이터는 चित्र_बांधणी लॉग_नोंद 시 지워진다.
3. microSD와 USB डेटा मोबाइल_मूल्य, HDMI पडदा, USB 키보드·마우스를 Raspberry Pi 4에 연결하고 부팅한다.
4. प्रयोक्ता 이름은 `user`, 홈은 `/home/user`, UID는 1000이다. 로컬 콘솔은 자동 로그인하며, `sudo`로 विकास साधने·시스템 패키지를 설치할 संख्या 있다. SSH 서버는 डिफॉल्ट_मूल्य 제공하지 않는다.

संग्रह_मूल्य 파일을 받은 경우 먼저 `gzip -dk संचिका_प्रविष्टी_नाव.img.gz`로 풀어 기록할 संख्या 있다. वितरण_मूल्य 파일이 सर्व_बांधणी 같은 폴더에 있으면 `sha256sum -c SHA256SUMS`로 무결성을 확인한다.

प्रणालीप्रारंभ 프로그램은 डेटा 장치의 ext4 라벨 `JKDATA`를 찾는다. डेटा 장치가 없으면 오류와 पुनर्प्राप्त_करा_राज्य 셸을 표시하며 **자동 포맷하지 않는다**. प्रारंभिक_आयटम 부팅하면 `/home/user/workspace/अभिवादन_ae353e94.java`पहिले_संकार्य 준비된다. `Ctrl+Space`로 हांगुल_मजकूर 입력을 전환한다. 작업마당의 स्रोत_बांधणी·आज्ञा_कार्यवाही_करा 단추나 명령창에서 `javac`, `java`, `python3`, `gcc`, `jclassc`를 사용한다.

वायर्ड_मूल्य 네트워크는 DHCP로 구성한다. Wi-Fi는 `/home/user/.config/jkoros/wifi.conf`에 `wpa_supplicant` 설정을 넣고 फाइल 권한을 600으로 설정한 मागे_मूल्य 재부팅한다. 국가 코드와 SSID·인증 방식은 사용하는 무선망에 맞춰 지정한다. सध्याचे_आयटम लक्ष्य 인터페이스는 `wlan0`이다.

인터넷 जोडा नंतर_राज्य NTP로 시간을 맞춘다. Pi 4에 별도 RTC가 없을 때는 मागील_आयटम निर्गमन_करा_अनुप्रयोग कालमुद्रा_मूल्य 또는 चित्र_बांधणी सिस्टम_बांधणी 시각에서 시작하므로, HTTPS 이용 आधी_मूल्य वास्तविक_डेटा 시각이 맞는지 확인한다. संपादन_मूल्य 창을 닫아도 विंडो 관리자는 पुढेचालूकरा_प्रक्रियाकरण 실행된다.

आहे_सामान्य 종료는 `sudo poweroff`तिसरे_संकार्य. प्रणालीप्रारंभ 파티션의 `cmdline.txt`에 `jkoros.desktop=off`를 추가하면 그래픽 환경을 시작하지 않는다. अनुक्रमिक_मूल्य 콘솔은 GPIO UART이며 Bluetooth 대신 PL011을 사용하도록 설정했다.

## सध्याचे_आयटम PC의 QEMU에서 그래픽 आज्ञा_कार्यवाही_करा

이미 आज्ञा_कार्यवाही_करा 중인 QEMU가 있다면 게스트에서 `sudo poweroff`로 종료한다. 같은 डेटा 이미지를 두 QEMU에서 동시에 열지 않는다. होस्ट 터미널에서 다음을 실행한다.

```sh
cd /home/user/jkoros/platforms/rpi4
make run
```

다른 **होस्ट टर्मिनल**에서 화면에 연결한다. सध्याचे_आयटम PC에 Remmina가 설치되어 있다.

```sh
remmina -c /home/user/jkoros/platforms/rpi4/build/qemu-5901.remmina
```

처음에는 화면이 검을 संख्या 있다. x86 PC에서 ARM64를 소프트웨어로 에뮬레이션하므로 Java와 다국어 फॉन्ट_मूल्य 초기화에 몇 분이 걸릴 संख्या 있다. 부팅과 Java वर्कस्पेस 초기화가 끝나면 데스크톱과 터미널이 표시된다. **VNC पडदा 안의 टर्मिनल**에서 실행한다.

```sh
cd ~/workspace
javac अभिवादन_ae353e94.java
java अभिवादन_ae353e94
```

`make run`은 기존 `build/manual-user.img`를 사용하고, 없을 때만 새 2 GiB डेटा 이미지를 만든다. 다른 डेटा 이미지는 `python3 tools/run_qemu.py --data /मार्ग/डेटा.img`로 지정한다. VNC는 호스트의 `127.0.0.1:5901`에서만 수신한다. 포트가 वापर_मूल्य 중이면 `--vnc-port 5902`로 변경하고 생성된 `build/qemu-5902.remmina`에 연결한다. आहे_सामान्य 종료는 게스트에서 `sudo poweroff`तिसरे_संकार्य. Remmina 창을 닫아도 QEMU는 पुढेचालूकरा_प्रक्रियाकरण 실행된다.

기존 `-display none`과 `jkoros.desktop=off` 조합은 그래픽 장치와 X 서버가 없는 टर्मिनल 전용 실행이다. 이 상태에서 `JFrame`을 만들면 `HeadlessException`이 발생한다. `DISPLAY=:0`만 지정하거나 `-Djava.awt.headless=false`만 추가해도 X 서버가 생기지는 않는다.

새 실행기는 가상 그래픽 카드·USB 키보드·마우스를 연결하고 QEMU 전용 initramfs에서 드라이버를 미리 로딩한다. 기존 시스템 이미지와 `base-id`를 그대로 사용하므로 **이번 सुधारा_मूल्य 적용에 `make image`दुसरे_संकार्य डेटा चित्र_बांधणी 재생성은 필요하지 않다**. डिफॉल्ट_मूल्य अनुक्रमिक_मूल्य 터미널로만 사용하려면 `make run-console`을 사용한다.

그래픽으로 부팅한 मागे_मूल्य **अनुक्रमिक_मूल्य 콘솔에서** Swing 창을 VNC 화면으로 열고 싶다면 다음처럼 कनेक्शन_e05f319b 정보도 지정한다.

```sh
export DISPLAY=:0
export XAUTHORITY=/run/user/1000/Xauthority
cd ~/workspace
java अभिवादन_ae353e94
```

이 설정은 `make run`으로 X 서버가 실행된 상태에서만 유효하다. स्रोत उदाहरणे `स्वकीय_जावा/उदाहरणे/अभिवादन_ae353e94.java`에는 화면이 없으면 टर्मिनल 결과만 출력하는 분기도 추가했다. 이미 प्रयोक्ता 폴더에 저장된 예제는 자동으로 덮어쓰지 않는다.

`make test-desktop`은 별도 डेटा 이미지에서 वास्तविक_डेटा Xorg/VNC 화면과 USB 키보드·마우스 입력을 Swing으로 검사한다. होस्ट Python의 Pillow가 필요하며 결과와 पडदा 캡처는 `build/verification/desktop*`에 저장된다. 기존 `make test`의 Swing 시험은 Xvfb를 사용하는 별도 자동 시험이다.

### हांगुल_मजकूर 입력과 फॉन्ट_मूल्य

आज्ञा_कार्यवाही_करा 중인 게스트에서 `sudo poweroff`한 पुढील_आयटम, 호스트에서 पुनःप्रयत्न_मूल्य `make run`하고 वरचे_मूल्य Remmina 파일로 연결하면 입력기·फॉन्ट_मूल्य 수정이 적용된다. 기존 `build/manual-user.img`와 시스템 이미지를 그대로 사용한다. `make image`दुसरे_संकार्य डेटा चित्र_बांधणी 초기화는 필요하지 않다.

VNC पडदा 안의 터미널이나 Java 편집기를 클릭하고 **Ctrl+Space**로 한·영을 전환한다. **한/शून्य_संकार्य कळ_मूल्य**도 등록되어 있다. डिफॉल्ट_मूल्य हांगुल_मजकूर 배열은 두벌식이다. `gksrmf` 키를 누르면 `हांगुल_मजकूर`이 입력된다. होस्ट 입력기는 영문 상태로 두고 게스트의 입력기로 조합한다. 호스트가 Ctrl+Space를 먼저 처리한다면 VNC 클라이언트의 키보드 잡기 기능을 사용한다.

वर्ण 로케일은 `ko_KR.UTF-8`, 입력기는 Fcitx5의 Hangul/XIM이다. 입력기 응답을 확인한 नंतर_राज्य 터미널과 Java를 실행한다. 터미널은 영문에 DejaVu Sans Mono, 한글에 Noto Sans Mono CJK KR을 사용하며, Java 작업마당은 16 크기의 मुख्य_मजकूर 글꼴과 안티앨리어싱을 사용한다. 새 X 터미널은 `jkoros-terminal`로 स्तंभ_मूल्य संख्या 있다. टर्मिनल फॉन्ट_मूल्य 크기는 `jkoros-terminal -fs 14`처럼 지정할 संख्या 있다. पिक्सेल_रंग 등 개인 X 리소스 설정은 `~/.Xresources`에서 읽는다.

QEMU 실행기가 전달하는 सुधारा_मूल्य 파일은 प्रयोक्ता 자료의 시스템 변경분에 저장된다. 교체 आधी_मूल्य 시스템 파일은 `~/.jkoros/desktop-updates/`, 기존 Fcitx 설정과 Java फॉन्ट_मूल्य 캐시는 `~/.local/state/jkoros/desktop-settings/`에 보관한다. पारपाडा_कार्य 중인 문서와 설치한 프로그램은 유지한다. 같은 सुधारा_मूल्य 버전은 재부팅 때 पुनरावृत्ती_मूल्य 적용하지 않아 이후의 개인 설정을 보존한다. 향후 `make image`로 새 이미지를 빌드할 때도 같은 डिफॉल्ट_मूल्य 설정이 포함된다.

`make test-korean`은 별도 चाचण्या डेटा 이미지에서 वास्तविक_डेटा VNC कळ_मूल्य 입력으로 Swing과 xterm에 `हांगुल_मजकूर आदान_मूल्य`을 조합하고, UTF-8 फाइल साठवणे_मूल्य 결과를 확인한다. 결과와 पडदा 캡처는 `build/verification/korean*`에 저장한다.

संयोजना 근거: [Fcitx의 XIM·로케일 वापरमार्गदर्शिका_eb81d7d9](https://fcitx-im.org/wiki/Input_method_related_environment_variables/en), [xterm의 फॉन्ट_मूल्य·입력기 옵션](https://invisible-island.net/xterm/manpage/xterm.html).

## 시스템과 प्रयोक्ता पर्यावरण 분리

```text
microSD: firmware + kernel + initramfs + immutable system
USB(ext4, JKDATA): /user  → आज्ञा_कार्यवाही_करा 중 /home/user
  ├── workspace, .config, .local, .venvs, प्रयोक्ता फाइल
  └── .jkoros/system/
        ├── base-id      같은 시스템 이미지인지 पडताळा
        ├── upper/       /usr, /opt, /etc, 패키지 DB 등 모든 시스템 변경분
        └── work/        OverlayFS पारपाडा_कार्य प्रदेश_मूल्य
```

시스템 डिफॉल्ट_मूल्य 파일은 वाचन 전용이다. `sudo apk add अनुप्रयोग_f5044b9b`으로 설치한 फाइल, 패키지 데이터베이스, `/etc` संयोजना, 기존 파일의 삭제 정보도 प्रयोक्ता 폴더의 OverlayFS 변경분에 들어간다. 따라서 일반 प्रयोक्ता 파일과 प्रयोक्ता स्थापित_करा_मूल्य 프로그램을 함께 옮길 संख्या 있다. `/run`, `/tmp`, `/dev/shm`은 일시 자료다.

**हलवा_मूल्य सशर्त:** 양쪽의 시스템 चित्र_बांधणी `base-id`, ARM64 아키텍처, प्रयोक्ता मार्ग `/home/user`, UID 1000이 같아야 한다. प्रणालीप्रारंभ 시 चित्र_बांधणी 식별자를 검사하며 다르면 해당 변경분을 임의로 적용하지 않는다. 이 버전은 서로 다른 시스템 버전 사이의 자동 마이그레이션을 제공하지 않는다.

두 운영체제를 आहे_सामान्य 종료하고 다른 Linux에서 डेटा 장치를 마운트한 मागे_मूल्य, 새 डेटा 장치에 `user` 폴더가 없는 상태에서 다음처럼 복사한다.

```sh
sudo cp -a /media/OLD/user /media/NEW/
sync
```

आज्ञा_कार्यवाही_करा 중에는 이 폴더가 `/home/user`로 보인다. 반드시 लपलेले_मूल्य फाइल, 심볼릭 링크, 소유권, परवानगी_मूल्य, एक्सटेंशन_मूल्य गुणधर्म_मूल्य, OverlayFS 삭제 정보를 보존해야 한다. ext4 사이의 हलवा_मूल्य 또는 Linux의 `sudo cp -a`/적절한 tar 보관을 사용한다. FAT/exFAT에 일반 폴더로 복사하면 이 정보가 보존되지 않는다. `user`를 기존 환경과 병합하지 않는다.

`jkoros-environment info`는 सध्याचे_आयटम 환경의 식별자를 보여준다. आहे_ऑफलाइन 보관은 다른 Linux에서 `sudo python3 runtime/environment export --home /media/OLD/user --output /backup/user.tar`로 수행한다. 복원은 빈 대상에서 `sudo tar --xattrs --acls --numeric-owner -xpf /backup/user.tar -C /media/NEW`तिसरे_संकार्य.

이 구조는 환경의 휴대성을 위한 것이다. 호스트와 격리하는 보안 샌드박스는 아니다. 별도 बाह्य_मूल्य 디스크·दूरस्_थ_मूल्य 서비스의 डेटा, प्रणालीप्रारंभ 펌웨어 변경은 `/home/user` 이동에 포함되지 않는다.

## अनुप्रयोग_f5044b9b स्थापित_करा_मूल्य

मराठी Java 라이브러리는 `/opt/jkoros/lib/स्वकीय_जावा.jar`에 있다. फाइल·वर्ण·संचार·스레드·Swing सहायक_मूल्य_44c0808f 22개 메서드와 Java 작업마당의 사용법은 [मराठी लायब्ररी प्रयोक्ता_मार्गदर्शी](../../स्वकीय_जावा/प्रयोक्ता_मार्गदर्शी.md)를 참고한다. Python의 Java 프로세스 आवाहन, C++의 JNI 직접 आवाहन 예제와 शेवटीजोडा_प्रविष्टी 설치가 필요한 Python जोडा 방식도 구분해 설명한다.

```sh
sudo apk update
sudo apk add tree
python3 -m virtualenv ~/.venvs/dev
. ~/.venvs/dev/bin/activate
pip install 패키지이름
```

Python 가상환경, 직접 빌드한 अनुप्रयोग_f5044b9b, प्रयोक्ता 설정도 `/home/user`에 둔다. 시스템에 설치하는 패키지도 변경분이 같은 폴더에 보관된다.

## 빌드와 चाचण्या

Linux x86-64 सिस्टम_बांधणी 호스트에서 Python 3, curl, JDK 11 이상, GNU C संकलक, make, kmod, squashfs-tools, dosfstools, mtools, e2fsprogs가 필요하다. 일반 चित्र_बांधणी 빌드는 root 권한이나 वास्तविक_डेटा 디스크 접근을 사용하지 않는다.

```sh
make prepare       # 서명된 ARM64 패키지와 Pi 공식 펌웨어 확보
make prepare-host  # 프로젝트 내부에 नवीनतम_मूल्य QEMU·jlink·proot 확보
make runtimes      # ARM64 JRE 구성 및 JDK/JRE 아카이브 तयार_करा
make image         # संचालनप्रणाली चित्र_बांधणी तयार_करा; 기존 प्रयोक्ता 이미지는 राखा_मूल्य
make test          # ARM64 प्रणालीप्रारंभ/आज्ञा_कार्यवाही_करा/재부팅/आहे_ऑफलाइन 홈 हलवा_मूल्य चाचण्या
make verify        # Pi चित्र_बांधणी 구조와 ARM64 JDK/JRE प्रमाणित
make release       # स्थापित_करा_मूल्य चित्र_बांधणी संग्रह_मूल्य 및 SHA256SUMS तयार_करा
```

`proot`는 ptrace가 허용된 सिस्टम_बांधणी 환경에서 실행한다. 패키지 검증을 끄는 옵션은 사용하지 않는다. 버전 고정 저장소의 패키지 갱신에 따라 पुढील_आयटम सिस्टम_बांधणी 결과는 달라질 संख्या 있으며, वितरण_मूल्य 이미지의 वास्तविक_डेटा 버전과 해시는 कुलूप_मूल्य 파일에 기록한다.

चाचण्या 결과는 `build/verification/`에 있다. QEMU `virt` 시험은 같은 ARM64 प्रयोक्ता पर्यावरण·प्रारंभिक_राज्य प्रणालीप्रारंभ संहिता_मूल्य·साठवणे_मूल्य 구조를 검증하지만, वास्तविक_डेटा Pi 4의 HDMI·USB·Wi-Fi·SD 드라이버 동작을 대신 검증하지 않는다. 이 저장소에 वास्तविक_डेटा Pi 4 보드를 연결한 प्रणालीप्रारंभ 결과는 아직 없다.

वितरण_मूल्य 결과와 प्रमाणित 범위는 [VERIFICATION.md](VERIFICATION.md)를 참조한다. 컴파일러의 OpenJDK आज्ञा_कार्यवाही_करा फाइल 방식과 제약은 [संकलक वापरमार्गदर्शिका_eb81d7d9](../../compiler/OpenJDK-निष्पादनीय_संचिका.md)에 설명되어 있다.
