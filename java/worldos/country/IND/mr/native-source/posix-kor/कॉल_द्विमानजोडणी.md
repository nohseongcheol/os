# प्रयोक्ता आवाहन सीमा_मूल्य

대상은 jkoros i386 ELF32다. Linux i386의 आवाहन 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `मशीन/ऑपरेटिंग_सिस्टम_कॉल्स.s`에서 EAX(अनुक्रमणिका), EBX·ECX·EDX·ESI·EDI(पहिले_क्रमांक~पाचवे_क्रमांक बाबी)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. गाभा_मूल्य 실패는 ऋण_मूल्य त्रुटी अनुक्रमणिका, C लायब्ररी 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 प्रयोक्ता प्रदेश_मूल्य 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C डेटा 주소는 बाइट_मूल्य 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java फाइल 흐름의 어셈블리 경계가 별도 बाइट_मूल्य 버퍼를 마련하여 같은 호출을 사용한다.

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 पत्ता 두 칸이다. मूल्य_स्वीकारा 주소가 NULL이면 समकक्ष_मूल्य पत्ता 기록을 생략한다. sockaddr_in은 16바이트이며 पत्ता 체계는 मोबाइल_मूल्य बाइट_मूल्य क्रम_मूल्य_e9fa7815, 접속번호와 IP 주소는 네트워크 बाइट_मूल्य 차례다. 축소된 पत्ता 버퍼에도 들어가는 앞부분을 쓰고 전체 पत्ता आकार 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 निर्गमन_करा_अनुप्रयोग, 2·3은 기존 बाबी 조회다. सध्याचे_आयटम 커널의 बाबी 목록이 आज्ञा_कार्यवाही_करा 이름을 제외하므로 C 진입기는 argv[0]에 고정 स्ट्रींग_मूल्य `jkoros-app`을 넣고 नंतर_मूल्य_ee1d8655 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX प्रक्रिया_मूल्य ABI와 다른 점이다.

표준 헤더의 पूर्णांक आकार, ध्वज_मूल्य मूल्य, stat फील्ड_मूल्य 순서는 `स्रोत/घोषणाशीर्षे/`에 정의한다. 동적 जोडा·다중 प्रक्रिया_मूल्य·스레드가 추가되면 त्रुटी अनुक्रमणिका 저장과 संसाधन_मूल्य 수명, आवाहन 경계도 함께 검토해야 한다.
