# मराठी नामकरण 원칙과 근거

이 문서의 새 이름은 jkoros 프로젝트의 선택이다. मराठी 전체나 특정 국가의 유일한 भाषा 철학을 대표한다고 주장하지 않는다. 기존에 분명한 용어는 유지하고, 모호한 음역이나 여러 의미가 섞인 이름은 सध्याचे_आयटम 코드의 동작을 중심으로 고친다. 다른 언어판은 लक्ष्य 언어와 용례를 별도로 검토해야 한다.

함수는 대상과 동작을 결합한다. `संचिका_डेटा_वाचा`, `शोधा_संचिका`, `बाइंड_करा_पत्ता`처럼 무엇에 무엇을 하는지 이름에서 읽히게 한다. 변수는 값의 역할과 단위를 나타내도록 `संचिका_विवरणक`, `बाइट_संख्या`, `प्रतीक्षामर्यादा_मिलिसेकंद_स्वीकारा`, `पिढी_संख्या`로 쓴다. 구동기는 장치를 움직이는 अंमलबजावणी, 처리기는 특정 입력을 처리하는 구현으로 구분한다.

어원은 설계 개념을 이해하는 근거로 사용한다. 역사적 은유를 그대로 번역해서 सध्याचे_आयटम 동작을 흐리게 만들지 않는다. 확인되지 않은 고어·최초 वापर_मूल्य 시점은 만들어 넣지 않는다. 아래의 मराठी 표현이 해당 시기의 वास्तविक_डेटा 번역어였다는 의미도 아니다.

| 개념 | 선택한 नाव | 의미와 역사적 근거 |
|---|---|---|
| file descriptor | संचिका_विवरणक | 열린 대상을 가리키는 पूर्णांक खाते_मूल्य. प्रारंभिक_राज्य UNIX 문헌도 open/create가 돌려주는 서술자로 시스템 표의 इनपुट_आउटपुट 위치를 찾는 구조를 설명한다. नाव स्ट्रींग_मूल्य·फाइल 본체·열린 फाइल 상태를 구분한다. |
| open file description | 열린 फाइल विवरणक_मूल्य | उघडा 설정과 सध्याचे_आयटम 위치를 담는 공유 राज्य_मूल्य. विवरणक_प्रविष्टी 자체와 구별하는 POSIX의 정의를 따른다. |
| unlink | संचिका_प्रविष्टी_नाव_काढणे | फाइल सामुग्री_मूल्य 즉시 폐기가 아닌 नाव जोडा प्रविष्टी_काढणे. 열린 참조가 남으면 내용이 살아 있는 의미를 반영한다. |
| seek / offset | शोधा_संचिका / ऑफसेट_मूल्य | 읽고 쓰는 위치를 기준점에서 이동한다. 수색·탐색이라는 일반어보다 해당 함수의 सध्याचे_आयटम 역할을 표현한다. |
| socket | संचारद्वार_संचारटोक | 통신이 드나드는 논리적 शेवट_करा_गुण. 1971년 RFC 147도 전송의 प्रस्थान_मूल्य·आगमन_मूल्य 식별자로 socket을 설명했다. 당시 32비트·짝홀 구분을 현대 API에 그대로 적용하지 않는다. |
| network port | पोर्ट_नंबर | 인터넷 पत्ता 안에서 संचार 상대를 구분하는 अनुक्रमणिका. RFC 768의 प्रस्थान_मूल्य/आगमन_मूल्य हार्डवेअर_पॉर्ट 정의를 반영하며 CPU इनपुट_आउटपुट 주소와 구별한다. |
| datagram | 자료전문 | 경계를 가진 하나의 메시지. RFC 768의 datagram 방식과 UDP लांबी_मूल्य 필드가 가리키는 단위를 드러낸다. |
| driver | 구동기 | मोबाइल_मूल्य 초기화와 송수신 명령을 수행하는 संहिता_मूल्य. RTL8139 अंमलबजावणी 이름은 망장치구동기다. |
| RAM file | स्मृती_फाइल_सिस्टम | आज्ञा_कार्यवाही_करा 중 자료가 주기억에 놓이는 वास्तुरचना. संग्रह_मोबाइल 보존 계층과 역할을 구분한다. |
| snapshot / generation | जतनकेलेले_इन्स्टन्स / पिढी_संख्या | समन्वय_साधा 시점의 फाइल 표와 डेटा 전체 및 그 क्रम_मूल्य. 단순한 백업 आहे_पूर्ण 표식과 वास्तविक_डेटा 본문을 구분한다. |
| stream | फाइल आदान_मूल्य/आउटपुट प्रवाह_मूल्य | 바이트를 순서대로 읽고 쓰는 कृती. 표준 Java 클래스의 이름은 호환성을 위해 FileInputStream/FileOutputStream으로 유지한다. |

표의 UNIX 역사 서술은 [Ritchie·Thompson의 UNIX 논문 재록본](https://cm-bell-labs.github.io/who/dmr/cacm.html)에 근거한다. 열린 राज्य_मूल्य·जागा·삭제의 의미는 POSIX의 [open](https://pubs.opengroup.org/onlinepubs/9799919799/functions/open.html), [dup](https://pubs.opengroup.org/onlinepubs/9799919799/functions/dup.html), [lseek](https://pubs.opengroup.org/onlinepubs/9799919799/functions/lseek.html), [unlink](https://pubs.opengroup.org/onlinepubs/000095399/functions/unlink.html)를 참고했다. संचार 용어의 역사와 सध्याचे_आयटम 규약은 [RFC 147](https://www.rfc-editor.org/info/rfc147/)과 [RFC 768](https://www.rfc-editor.org/info/rfc768/)을 참고했다.

표준 이름을 번역된 심벌로 강제로 바꾸면 기존 프로그램과 도구가 연결되지 않는다. 따라서 POSIX/C의 공개 심벌, Java 표준 वर्ग_मूल्य·पद्धत_मूल्य, ELF/x86 ABI, हार्डवेअर_मूल्य 레지스터 명칭과 `Makefile` 같은 साधने प्रविष्टी_गुण_मूल्य 파일은 유지한다. मराठी API는 같은 동작의 별칭이다. `हार्डवेअर_पॉर्ट_वाचा` 같은 프로젝트 내부 식별자는 इनपुट_आउटपुट बाइट_मूल्य 접근으로 뜻을 좁혀 वास्तविक_डेटा 코드와 네이티브 연결표까지 함께 바꿨다. वास्तविक_डेटा 적용 목록은 [परिभाषा_प्रतिचित्रण.tsv](परिभाषा_प्रतिचित्रण.tsv)에 있다.
