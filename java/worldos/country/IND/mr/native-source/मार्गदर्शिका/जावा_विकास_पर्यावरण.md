# jkoros 안에서 Java स्रोत_बांधणी·आज्ञा_कार्यवाही_करा

이 문서의 प्रणालीप्रारंभ·शेल·साठवणे_मूल्य 명령은 **x86 आवृत्ती_मूल्य** 기준이다. 공유 Java संकलक/JVM은 [स्वकीय ARM64 Pi4 आवृत्ती_मूल्य](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART आदान_मूल्य·हांगुल_मजकूर संचिका_नाव_मजकूर, `edit`의 단독 `.` साठवणे_मूल्य, 16개 RAM फाइल, 약 2초 आज्ञा_कार्यवाही_करा 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 वास्तविक_डेटा JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. होस्ट स्रोत_बांधणी 서버나 Linux 게스트는 사용하지 않는다.

**सध्याचे_आयटम 구현은 स्वकीय 제한형 संकलक·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java अनुप्रयोग_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 आज्ञा_कार्यवाही_करा

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`तिसरे_संकार्य. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. आज्ञा_कार्यवाही_करा 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 प्रणालीप्रारंभ 절차는 [VirtualBox आज्ञा_कार्यवाही_करा वापरमार्गदर्शिका_eb81d7d9](व्हर्च्युअल_पेटी_निष्पादन.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 फाइल 전체를 새 내용으로 작성한다. 기존 내용의 ओळ संपादन_मूल्य 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 बाइट_मूल्य संख्या मूल्य_शो.
- `cat FILE`: फाइल सामुग्री_मूल्य मूल्य_शो. 텍스트 소스에 사용한다.
- `rm FILE`: स्मृती_डेटा फाइल 삭제.
- `edit FILE`: 전체 내용을 새로 आदान_मूल्य. 빈 파일도 저장할 संख्या 있다.
- 구문·टाइप_करा_मूल्य पडताळण्या बिघाड_मूल्य 시 기존 `.class`는 유지된다. 소스를 고친 मागे_मूल्य 컴파일이 실패했다면 मागील_आयटम आज्ञा_कार्यवाही_करा 파일이 남아 있으므로 स्रोत_बांधणी यश_मूल्य 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 साठवणे_मूल्य 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 स्रोत_ट्री·वर्ग_मूल्य·डेटा 파일을 보존할 संख्या 있다. कमाल_मूल्य 8개, 파일마다 16KiB, फाइल 이름은 ASCII 1~63자다. स्रोत_ट्री 이름은 `.class` 확장자 पत्ता_प्रदेश 때문에 कमाल_मूल्य 62자다. संपादन_मूल्य 입력은 ASCII이고 한 ओळ कमाल_मूल्य 128자다. ओळ 또는 फाइल 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. गाभा_मूल्य/संकलक/JVM 구현의 Java 식별자는 한국어이며, सध्याचे_आयटम 게스트 आदान_मूल्य मर्यादा_मूल्य 때문에 प्रयोक्ता उदाहरणे 이름은 ASCII로 작성한다.

## बाह्य_मूल्य फाइल 적재

호스트에서 만든 소스나 समर्थन_मूल्य क्लिप 안의 `.class`를 प्रणालीप्रारंभ 이미지에 포함할 संख्या 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 वास्तविक_डेटा 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# होस्ट JDK로 컴파일한 클래스도 사용할 संख्या 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 प्रणालीप्रारंभ नंतर_राज्य `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 पुढील_आयटम 빌드에서는 शेवटीजोडा_प्रविष्टी 파일을 포함하지 않는다. फाइल सामुग्री_मूल्य 변경과 प्रविष्टी_यादी 제거도 पुढील_आयटम 빌드에 반영된다. मूळ होस्ट 파일에는 쓰지 않는다. डिफॉल्ट_मूल्य `Hello.java`पर्यंत 합해 8개이며, 같은 이름을 명시하면 डिफॉल्ट_मूल्य 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 वर्ग_मूल्य फाइल 버전을 맞추는 옵션이다. 사용하는 문법·बाइटसंहिता·라이브러리도 तळ_मूल्य समर्थन_मूल्य क्लिप 안에 있어야 한다.

## समर्थन_मूल्य क्लिप

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| वर्ग_मूल्य | 패키지 없는 단일 वर्ग_मूल्य, स्थिर_मूल्य फलन_मूल्य, 재귀, बाबी/परतकरा_मोजमाप | 실행마다 단일 वर्ग_मूल्य 적재, public static main(String[]) |
| डिफॉल्ट_मूल्य मूल्य | int, boolean, char, String, main의 String[] बाबी | पूर्णांक·संदर्भ संकार्य_स्टॅक, String, int[], String[], 내부 StringBuilder |
| विधान_मूल्य | प्रारंभिक_मूल्य 있는 स्थानिक_संधी घोषणा, नियुक्ती_मूल्य, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 पूर्णांक·संदर्भ 바이트코드와 सशर्त शाखा |
| अभिव्यक्ती_मूल्य | 십진 पूर्णांक, UTF-8 소스의 स्ट्रींग_मूल्य/वर्ण, + - * / %, 비교, ==/!=, !/&&/\|\|, स्ट्रींग_मूल्य एकत्र_मूल्ये | पूर्णांक क्रिया_मूल्य·बिट_मूल्य क्रिया_मूल्य·टाइप_करा_मूल्य रूपांतरकरा_मूल्य, 단락 평가, ऍरे_मूल्य ऍक्सेस_प्रविष्टी |
| फाइल | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | वास्तविक_डेटा गाभा_मूल्य 파일서술자와 जोडा, तयार_करा·साफ_करा_सामुग्री·शेवटीजोडा_पुढीलक्रम·EOF |
| आउटपुट | System.out.print/println: int/boolean/char/String, println() | 동일 |
| स्ट्रींग_मूल्य/बाबी | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), स्ट्रींग_मूल्य 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, प्रारंभिक_मूल्य 없는 स्थानिक_संधी घोषणा, 오버로드, 임의 टाइप_करा_मूल्य रूपांतरकरा_मूल्य, ऍरे_मूल्य तयार_करा स्रोत, 8/16진 리터럴, Unicode स्रोत_ट्री 이스케이프 등은 미지원이다. `char`는 वर्ण 리터럴로 초기화하며 일반 JDK의 모든 स्थिरांक_मूल्य 축소 변환을 구현하지 않는다. बाह्य_मूल्य `.class`의 `int[]` तयार_करा/वाचन/쓰기는 지원하므로 होस्ट `javac --release 8`로 만든 ऍरे_मूल्य 예제는 실행할 संख्या 있다.

ऑब्जेक्ट_मूल्य फील्ड_मूल्य·일반 ऑब्जेक्ट_मूल्य तयार_करा·상속·인터페이스·여러 वर्ग_मूल्य जोडा, long/float/double, अपवाद प्रक्रिया_मूल्य_प्रविष्टी, 스레드·모니터, 리플렉션, JNI, JIT, GC, वरचे_मूल्य 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java अपवाद 객체를 던지지 않고 निदान_मूल्य नंतर_राज्य सध्याचे_आयटम 프로그램을 종료한다. 객체와 स्ट्रींग_मूल्य साठवणे_मूल्य 공간은 आज्ञा_कार्यवाही_करा निर्गमन_करा_अनुप्रयोग 시 प्रयोक्ता प्रदेश_मूल्य 전체와 함께 회수한다. 지속 आज्ञा_कार्यवाही_करा 중 GC는 없다.

## आज्ञा_कार्यवाही_करा 한도와 त्रुटी

| संसाधन_मूल्य | धारणक्षमता_मर्यादा |
| --- | --- |
| स्रोत_ट्री/वर्ग_मूल्य फाइल | 각각 16KiB |
| संकलक | टोकन_मूल्य 2,047개, तयार_करा संहिता_मूल्य 4KiB, स्थिरांक_मूल्य 풀 4KiB |
| फलन_मूल्य/बाबी | 클래스당 32함수, 함수당 16인수 |
| JVM स्थिरांक_मूल्य | 511개 |
| JVM फलन_मूल्य संहिता_मूल्य | 함수당 8KiB |
| JVM आवाहन/संकार्य_स्टॅक/स्थानिक_संधी चल_मूल्य | 32프레임, 프레임당 संकार्य_स्टॅक 128칸·स्थानिक_संधी 128칸 |
| JVM ऑब्जेक्ट_मूल्य साठवणे_मूल्य पत्ता_प्रदेश | 8,192개 32비트 खाच_प्रविष्टी, 헤더 घोषणाशीर्षे 약 32KiB |
| आज्ञा_कार्यवाही_करा | कमाल_मूल्य 500,000 आदेश, 기존 커널의 약 3초 CPU आज्ञा_कार्यवाही_करा 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 समर्थन_मूल्य 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM शब्दकोश 검증기를 구현한 것은 아니다. फाइल/गुणधर्म_मूल्य लांबी_मूल्य, स्थिरांक_मूल्य संदर्भ, आदेश·शाखा 경계를 검사하고, आज्ञा_कार्यवाही_करा 중 संकार्य_स्टॅक स्वरूप_मूल्य·स्थानिक_संधी आरंभ_करा·ऍरे_मूल्य उपलिपी_मूल्य·ऑब्जेक्ट_मूल्य 참조를 검사한다. प्रयोक्ता 코드의 페이지·हार्डवेअर_पॉर्ट 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, स्रोत_बांधणी·JVM 오류는 `Exit: 1`, आदेश बाबी 오류는 `Exit: 2`तिसरे_संकार्य. CPU वेळ_मूल्य 상한은 기존 `Exit: 124`이며, प्रयोक्ता ELF 자체의 CPU/런타임 오류는 기존 निर्गमन_करा_अनुप्रयोग 코드를 따른다. बिघाड_मूल्य नंतर_राज्य 셸에서 다른 프로그램을 पुढेचालूकरा_प्रक्रियाकरण 실행할 संख्या 있다.

## अंमलबजावणी 위치와 चाचण्या

- `os/प्रयोक्ता/जावा/जावा_संकलक.java`: 게스트 어휘·구문·टाइप_करा_मूल्य पडताळण्या, स्थिरांक_मूल्य 풀 및 बाइटसंहिता तयार_करा.
- `os/प्रयोक्ता/जावा/जावा_मशीन.java`: वर्ग_मूल्य 적재, संकार्य_स्टॅक·프레임·ऑब्जेक्ट_मूल्य साठवणे_मूल्य, आदेश 해석과 제한된 표준 आवाहन.
- `os/स्रोत/स्मृती_फाइल_सिस्टम.java`: स्मृती_डेटा फाइल_सिस्टम, संपादन_मूल्य, प्रणालीप्रारंभ फाइल 적재.
- `os/स्रोत/सिस्टम_कॉल_आवाहन.java`, `compiler/प्रारंभ_प्रयोक्ता_अनुप्रयोग.s`: फाइल/वर्ण आउटपुट API와 प्रयोक्ता निर्देशक पडताळण्या.
- `os/साधने/बंडल_जावा_संचिका.py`: होस्ट आदान_मूल्य फाइल प्रमाणित·प्रणालीप्रारंभ समूह_मूल्य तयार_करा.

```sh
make test-java
make test
```

`os/चाचण्या/जावा_चाचणी.py`는 ELF/ISO प्रणालीप्रारंभ, 게스트 स्रोत_बांधणी·आज्ञा_कार्यवाही_करा, प्रयोक्ता आदान_मूल्य, 재귀·반복문·पूर्णांक 극값·स्ट्रींग_मूल्य एकत्र_मूल्ये·단락 평가, 재실행, स्रोत_ट्री त्रुटी नंतर_राज्य 기존 वर्ग_मूल्य 보존, ऍरे_मूल्य/संख्या 해독 त्रुटी, 무한 पुनरावृत्ती_मूल्य मर्यादा_मूल्य, संपादन_मूल्य 넘침과 फाइल 부족을 검사한다. 게스트 तयार_करा 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 होस्ट OpenJDK의 वर्ग_मूल्य, पूर्णांक 배열과 हांगुल_मजकूर 상수를 게스트에 적재하며, 손상된 फाइल खूण_मूल्य·버전·स्थिरांक_मूल्य संख्या·शाखा·스택을 거부하는지도 검사한다. 기록은 `os/build/जावा_चाचणी.json`에 남는다. 디스크 없는 별도 चाचण्या VM만 생성하고 종료한다.

अंमलबजावणी 형식의 참고 डेटा: Oracle [JVM वर्ग_मूल्य फाइल विनिर्देश](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM आदेश विनिर्देश](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java फाइल इनपुट_आउटपुट

[FileDemo.java](../posix-kor/जावा_उदाहरण/FileDemo.java)는 일반 Java 표준 वर्ग_मूल्य 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 प्रणालीप्रारंभ 이미지에 넣은 मागे_मूल्य `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`तिसरे_संकार्य. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. डिफॉल्ट_मूल्य आउटपुट 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. अपवाद ऑब्जेक्ट_मूल्य·try/catch·try-with-resources는 지원하지 않으며 फाइल 오류를 진단하고 프로그램을 종료한다. ऍरे_मूल्य इनपुट_आउटपुट, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 फाइल 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 शेल `sync`पहिले_संकार्य 필요하다. 예제의 फाइल 이름은 सध्याचे_आयटम 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/चाचण्या/जावा_संचिका_चाचणी.py`는 वास्तविक_डेटा 게스트 स्रोत_बांधणी 결과를 OpenJDK `-Xverify:all`로 पुनःप्रयत्न_मूल्य 실행해 फाइल 바이트와 출력을 대조한다. 범위와 साठवणे_मूल्य माध्यमे_मूल्य 사용법은 [posix-kor वापरमार्गदर्शिका_eb81d7d9](../posix-kor/वापरमार्गदर्शिका_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
