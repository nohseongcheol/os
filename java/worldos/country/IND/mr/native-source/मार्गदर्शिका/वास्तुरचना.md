# JIndOS वास्तुरचना

아래는 ऑब्जेक्ट_मूल्य पाया 관리 गाभा_मूल्य 전체의 लक्ष्य_ऑब्जेक्ट 구조다. सध्याचे_आयटम वास्तविक_डेटा प्रणालीप्रारंभ 가능한 제한형 구현은 `compiler/`와 `os/`에 있으며 [네이티브 संचालनप्रणाली वापरमार्गदर्शिका_eb81d7d9](../os/वापरमार्गदर्शिका_eb81d7d9.md)에 अंमलबजावणी 범위를 명시한다. 아래의 GC·संदर्भ_मूल्य स्विच_मोड·फाइल_सिस्टम 등이 새 ISO에 सर्व_बांधणी 포함돼 있지는 않다.

```text
GRUB 또는 UEFI
  ↓
x86 किमान_मूल्य 부트·트랩 थर_मूल्य
  ↓
Java AOT 실행기와 ऑब्जेक्ट_मूल्य·ऍरे_मूल्य·GC 런타임
  ↓
हार्डवेअर_मूल्य सीमा_मूल्य
  ↓
Java 관리 गाभा_मूल्य
  ├─ स्मृती_प्रदेश/पृष्ठ_व्यवस्थापन/COW
  ├─ प्रक्रिया_मूल्य/배정/wait
  ├─ फाइल_सिस्टम/ELF/POSIX
  └─ आदान_मूल्य/संग्रह_मोबाइल/संचारजाळे_स्टॅक
```

OpenJDK 자체는 이미 운영체제가 제공하는 फाइल, 스레드, 가상 기억공간을 전제로 한다. 따라서 गाभा_मूल्य 부팅에는 OpenJDK를 그대로 넣지 않고 제한된 Java बाइटसंहिता AOT와 작은 런타임을 사용한다.

네이티브 계층에는 `in/out`, `hlt`, CR0/CR2/CR3/CR4, `iret`, संदर्भ_मूल्य 저장처럼 Java로 표현할 संख्या 없는 CPU 동작만 남긴다. 정책과 자료구조는 Java에 둔다.
