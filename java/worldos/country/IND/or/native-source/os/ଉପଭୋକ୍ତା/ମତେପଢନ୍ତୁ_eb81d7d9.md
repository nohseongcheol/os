# 셸에서 실행하는 ଉପଭୋକ୍ତା 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 ମତେପଢନ୍ତୁ_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ

ଆୟୋଜକ ଟର୍ମିନାଲ 1:

```sh
cd /home/user/jkoros
python3 os/ଉପକରଣସମୂହ/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 외부 연결을 받도록 방화벽이나 ହାର୍ଡୱେର୍_ପୋର୍ଟ 전달을 변경하지 않는다. Ctrl+C로 종료한다.

ଆୟୋଜକ ଟର୍ମିନାଲ 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 ପ୍ରକୃତ_ଡାଟା CPU ଅନୁମତି_ମୂଲ୍ୟ `ring 3`, 인수 ନିର୍ଗମ.
- `netcheck`: ପୋର୍ଟ_ମୂଲ୍ୟ 중복, 잘못된 ହାଣ୍ଡେଲ୍_ମୂଲ୍ୟ/ପଏଣ୍ଟର୍/ଦୈର୍ଘ୍ୟ_ମୂଲ୍ୟ, 비차단 받기와 ସମୟ_ମୂଲ୍ୟ 초과 ଯାଞ୍ଚ୍_କରିବା.
- `udp`: IPv4 ଠିକଣା·ଲକ୍ଷସ୍ଥଳ_ମୂଲ୍ୟ ପୋର୍ଟ_ମୂଲ୍ୟ·한 단어 메시지를 받아 UDP로 보내고 같은 응답을 ଯାଞ୍ଚ୍_କରିବା. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: ଆୟୋଜକ `10.0.2.2`의 ନ୍ୟସ୍ତ_କରିବା_ମୂଲ୍ୟ 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 ଲୁପ୍_ମୂଲ୍ୟ 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 현재 주소는 게스트 `10.0.2.15/24`, ପ୍ରବେଶ_ପଥ_ମୂଲ୍ୟ `10.0.2.2`로 고정돼 있다. QEMU ଉପଭୋକ୍ତା 네트워크의 ଆୟୋଜକ ପ୍ରବେଶ_ଏଣ୍ଟ୍ରି 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 ଅନୁପ୍ରୟୋଗ_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java ଅନୁପ୍ରୟୋଗ_f5044b9b 추가

`예제/내프로그램.java`를 ପରବର୍ତ୍ତୀ_ଆଇଟମ୍ 형식으로 만든다. 진입점은 인수 없는 `static int` 또는 `static void` 함수다. 인수는 ଉପଭୋକ୍ତା API로 조회한다.

```java
public final class 내프로그램 {
    public static int ଚଳାନ୍ତୁ() {
        ଉପଭୋକ୍ତା.ଲେଖନ୍ତୁ("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/ଉପଭୋକ୍ତା/ଅନୁପ୍ରୟୋଗ_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := ଉପଭୋକ୍ତା/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.ଚଳାନ୍ତୁ
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `ଉପଭୋକ୍ତା/선언/ଉପଭୋକ୍ତା.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 중인 VM에는 ବିଲ୍ଡ୍_ସିଷ୍ଟମ 결과가 자동 반영되지 않는다. ଅନୁପ୍ରୟୋଗ_f5044b9b 이름은 현재 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java ଶ୍ରେଣୀ_ମୂଲ୍ୟ_55654bf1·Excel_ଟେବଲ୍_ମୂଲ୍ୟ·변수에는 한국어를 쓴다. 최대 32개 ଅନୁପ୍ରୟୋଗ_f5044b9b, 한 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.ଚଳାନ୍ତୁ \
    -o os/build/apps/hello.elf os/ଉପଭୋକ୍ତା/선언/ଉପଭୋକ୍ତା.java os/ଉପଭୋକ୍ତା/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 ଆୟୋଜକ 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 ସମର୍ଥନ_ମୂଲ୍ୟ କ୍ଲିପ୍ 안에서 실행한다. `.jar`와 일반 Linux ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 파일은 지원하지 않는다.

## ଉପଭୋକ୍ତା 네트워크 API

선언은 `선언/ଉପଭୋକ୍ତା.java`에 있다. `ପଠାନ୍ତୁ_ଡାଟା`/`자료받기`의 `int[]` ଆଇଟମ୍_ଉପାଦାନ 한 개는 ବାଇଟ୍_ମୂଲ୍ୟ 하나(0~255)를 나타낸다. 한 데이터그램의 최대 ଡାଟା 길이는 1,024바이트다.

```java
int ହାଣ୍ଡେଲ୍_ମୂଲ୍ୟ = ଉପଭୋକ୍ତା.ଖୋଲିବା_ନେଟ୍_ୱାର୍କ୍(0); // 0: 임시 ସ୍ଥାନୀୟ_ପରିସର UDP ପୋର୍ଟ_ମୂଲ୍ୟ 자동 ଚୟନ_ମୂଲ୍ୟ
int[] ଡାଟା = new int[32];
ଡାଟା[0] = 'H'; ଡାଟା[1] = 'i';
int 보낸길이 = ଉପଭୋକ୍ତା.ପଠାନ୍ତୁ_ଡାଟା(ହାଣ୍ଡେଲ୍_ମୂଲ୍ୟ, 0x0a000202, 9000, ଡାଟା, 2);
int 받은길이 = ଉପଭୋକ୍ତା.자료받기(ହାଣ୍ଡେଲ୍_ମୂଲ୍ୟ, ଡାଟା, 1500);
ଉପଭୋକ୍ତା.ବନ୍ଦ_ନେଟ୍_ୱାର୍କ୍(ହାଣ୍ଡେଲ୍_ମୂଲ୍ୟ);
```

ପ୍ରକୃତ_ଡାଟା 프로그램에서는 ଖୋଲନ୍ତୁ·ପଠାନ୍ତୁ·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 ଅପେକ୍ଷା_ମୂଲ୍ୟ 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 추가 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | ହାଣ୍ଡେଲ୍_ମୂଲ୍ୟ·ପ୍ରୋସେସ୍_ମୂଲ୍ୟ_ଏଣ୍ଟ୍ରି ଦୈର୍ଘ୍ୟ_ମୂଲ୍ୟ·성공 등 해당 함수의 ମାପ |
| -5 | ଡିଭାଇସ_ମୂଲ୍ୟ ପଠାନ୍ତୁ_ମୂଲ୍ୟ ବିଫଳତା_ମୂଲ୍ୟ |
| -9 | 잘못되었거나 닫힌 통신 ହାଣ୍ଡେଲ୍_ମୂଲ୍ୟ |
| -11 | 비차단 받기에서 도착한 ଡାଟା 없음 |
| -14 | ଉପଭୋକ୍ତା ପଏଣ୍ଟର୍/ଆରେ_ମୂଲ୍ୟ କ୍ଲିପ୍ ତ୍ରୁଟି |
| -19 | ସମର୍ଥନ_ମୂଲ୍ୟ NIC 없음 |
| -22 | ପୋର୍ଟ_ମୂଲ୍ୟ/ଅପେକ୍ଷା_ମୂଲ୍ୟ ସମୟ_ମୂଲ୍ୟ/인수 ମୂଲ୍ୟ ତ୍ରୁଟି |
| -24 | 열린 ନେଟ୍_ୱାର୍କ୍_ପୋର୍ଟ 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | ଡାଟା 또는 수신 ଆରେ_ମୂଲ୍ୟ ଆକାର 문제 |
| -98 | ସ୍ଥାନୀୟ_ପରିସର ପୋର୍ଟ_ମୂଲ୍ୟ ଅନୁକ୍ରମଣିକା 중복 |
| -101 | 지원하지 않는 ଲକ୍ଷସ୍ଥଳ_ମୂଲ୍ୟ ଠିକଣା |
| -110 | ARP·ଡିଭାଇସ_ମୂଲ୍ୟ·수신 ସମୟ_ମୂଲ୍ୟ 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 ଏନକୋଡିଂ_ମୂଲ୍ୟ 있는 Java `int`의 ବିଟ୍_ମୂଲ୍ୟ 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 경계와 시스템 호출

```text
ଖୋଳ run → JKAP에서 ELF ବୈଧକରଣ·적재 → ring 3 ଉପଭୋକ୍ତା ଅନୁପ୍ରୟୋଗ_f5044b9b
                                 ↓ int 0x80
                      ପଏଣ୍ଟର୍ 검사 → Java କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ API → RTL8139/UDP
                                 ↓ ପ୍ରସ୍ଥାନ_ଅନୁପ୍ରୟୋଗ·ବ୍ୟତିକ୍ରମ·ସମୟ_ମୂଲ୍ୟ 초과
                                ଖୋଳ 복귀
```

시스템 호출 레지스터는 `EAX=ଅନୁକ୍ରମଣିକା`, `EBX,ECX,EDX,ESI,EDI=인수`, `EAX=ମାପ`다. Java 호출 스택 ABI는 컴파일러가 ଉପଭୋକ୍ତା 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| ଅନୁକ୍ରମଣିକା | 호출 |
| --- | --- |
| 0 | ପ୍ରସ୍ଥାନ_ଅନୁପ୍ରୟୋଗ(ସ୍ଥିତି_ମୂଲ୍ୟ_e10195a1 코드) — ଚଳାନ୍ତୁ/ତ୍ରୁଟି 런타임에서 사용 |
| 1 | ଷ୍ଟ୍ରିଂ_ମୂଲ୍ୟ ଲେଖନ୍ତୁ |
| 2 / 3 | 인수 개수 / 인수 ଷ୍ଟ୍ରିଂ_ମୂଲ୍ୟ ଠିକଣା |
| 10 | UDP ଖୋଲନ୍ତୁ |
| 11 | UDP ପଠାନ୍ତୁ(ହାଣ୍ଡେଲ୍_ମୂଲ୍ୟ, IP, ଲକ୍ଷସ୍ଥଳ_ମୂଲ୍ୟ ପୋର୍ଟ_ମୂଲ୍ୟ, ଆରେ_ମୂଲ୍ୟ ଠିକଣା, ଦୈର୍ଘ୍ୟ_ମୂଲ୍ୟ) |
| 12 | UDP 받기(ହାଣ୍ଡେଲ୍_ମୂଲ୍ୟ, ଆରେ_ମୂଲ୍ୟ ଠିକଣା, 제한 밀리초) |
| 13 | UDP ବନ୍ଦ_କରନ୍ତୁ |
| 14 | ସ୍ଥାନୀୟ_ପରିସର IP ଠିକଣା |
| 15 / 16 | 마지막 ସମକକ୍ଷ_ମୂଲ୍ୟ IP / UDP ପୋର୍ଟ_ମୂଲ୍ୟ |
| 20 | RAM ଫାଇଲ ପଢନ୍ତୁ(ନାମ int[] ଠିକଣା, ନିର୍ଗମ int[] ଠିକଣା) |
| 21 | RAM ଫାଇଲ ଲେଖନ୍ତୁ(ନାମ int[] ଠିକଣା, 입력 int[] ଠିକଣା, ବାଇଟ୍_ମୂଲ୍ୟ ଦୈର୍ଘ୍ୟ_ମୂଲ୍ୟ) |
| 22 | UTF-16 코드 ଶିକ୍ଷା_ମୂଲ୍ୟ 문자 ନିର୍ଗମ(0~65535) |

ଫାଇଲ API는 `ଉପଭୋକ୍ତା.파일읽기(int[] ନାମ, int[] ଡାଟା)`와 `ଉପଭୋକ୍ତା.ଲିଖନ_ଫାଇଲ୍(int[] ନାମ, int[] ଡାଟା, int ଦୈର୍ଘ୍ୟ_ମୂଲ୍ୟ)`다. 이름은 ASCII 코드 ଆରେ_ମୂଲ୍ୟ(최대 64칸, 0 ପ୍ରସ୍ଥାନ_ଅନୁପ୍ରୟୋଗ 또는 ଆରେ_ମୂଲ୍ୟ 끝), ଡାଟା ଆଇଟମ୍_ଉପାଦାନ 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 ଫାଇଲ 없음 `-2`, ପଏଣ୍ଟର୍ ତ୍ରୁଟି `-14`, ନାମ/ଦୈର୍ଘ୍ୟ_ମୂଲ୍ୟ ତ୍ରୁଟି `-22`, ଫାଇଲ ସ୍ଲଟ୍_ମୂଲ୍ୟ 부족 `-28`, ଆକାର 초과 `-90`을 반환한다. 쓰기는 ବୈଧକରଣ 후 ଫାଇଲ 전체를 대체한다. `ଉପଭୋକ୍ତା.ଲିଖନ_ବର୍ଣ୍ଣ_ମୂଲ୍ୟ(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 ଉପଭୋକ୍ତା 모드에서 CS의 하위 비트를 직접 읽으므로 ପ୍ରକୃତ_ଡାଟା ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 권한을 확인한다. କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ ହାର୍ଡୱେର୍_ପୋର୍ଟ 접근용 `ଡିଭାଇସ_ମୂଲ୍ୟ` native 함수는 ଉପଭୋକ୍ତା ଲକ୍ଷ୍ୟସ୍ଥଳ 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ, 파이프, 프로세스 간 통신은 없다. ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 파일은 커널의 ପଢନ୍ତୁ 전용 JKAP 묶음에서 적재한다. ଡାଟା 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- ଉପଭୋକ୍ତା 가상 ଠିକଣା `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 영상은 앞 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB ଉପଭୋକ୍ତା 영역을 비우고 ଫାଇଲ 구역을 복사해 BSS·ଆରେ_ମୂଲ୍ୟ 영역을 초기화한다. ଉପଭୋକ୍ତା GC는 없지만 ପ୍ରସ୍ଥାନ_ଅନୁପ୍ରୟୋଗ 후 ପରବର୍ତ୍ତୀ_ଆଇଟମ୍ ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 କ୍ୟୁଏଟ୍/이스케이프 파싱은 없다.
- ଉପଭୋକ୍ତା 페이지의 코드/ଡାଟା 분리 ପଢନ୍ତୁ 전용 ବିନ୍ଯାସ, NX, 스택 guard, ASLR은 아직 없다. 커널과 ଉପଭୋକ୍ତା ମୋମରୀ_ଡାଟା·ହାର୍ଡୱେର୍_ପୋର୍ଟ ଅନୁମତି_ମୂଲ୍ୟ 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 상한을 두며 ସମୟ_ମୂଲ୍ୟ 초과는 `Exit: 124`다. ଉପଭୋକ୍ତା CPU 예외는 `128 + ବ୍ୟତିକ୍ରମ ଅନୁକ୍ରମଣିକା`(페이지 ତ୍ରୁଟି 142, 특권 위반 141), Java ଆରେ_ମୂଲ୍ୟ/계산 오류는 101~105다. କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, ସ୍ଥିର_ମୂଲ୍ୟ IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP ଚେକସୁମ୍ 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- ଉପଭୋକ୍ତା ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ·네트워크·ପ୍ରତିରୋଧ_ମୂଲ୍ୟ 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## ବୈଧକରଣ 근거

`make test`는 컴파일러 14개 시험, Java 패킷 ସର୍ତ୍ତ 2,201개 검사, 기존 ଖୋଳ ELF/ISO 부팅 시험, ଉପଭୋକ୍ତା ELF/ପ୍ରକୃତ_ଡାଟା UDP/ପ୍ରତିରୋଧ_ମୂଲ୍ୟ 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 ଦୈର୍ଘ୍ୟ_ମୂଲ୍ୟ·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 ନିର୍ଦ୍ଦେଶ·무한 ବାରମ୍ବାର_ମୂଲ୍ୟ 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
