# 자체 ARM64 커널의 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ ସ୍ତର_ମୂଲ୍ୟ·프로세스 ପ୍ରଦର୍ଶନ_କରିବା_ମୂଲ୍ୟ·QEMU 외부 통신

2026-10-04 점검. 대상은 `jkoros/platforms/rpi4-native`의 자체 Java 커널이다.
`platforms/rpi4`의 Linux/OpenJDK 판이나 `os`의 기존 x86 판에 이 결과를 적용하지 않는다.

## ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ ସ୍ତର_ମୂଲ୍ୟ

| ଲକ୍ଷ୍ୟସ୍ଥଳ | ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ ଅବସ୍ଥାନ | 현재 구현 |
|---|---|---|
| ଖୋଳ, `sh` ସ୍କ୍ରିପ୍ଟ_ମୂଲ୍ୟ, `ps`, `top`, ଫାଇଲ 내장 ନିର୍ଦ୍ଦେଶ | EL1 କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ | Java AOT କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ 함수로 호출 |
| ଟର୍ମିନାଲ 창과 ଖୋଳ ସ୍ଥିତି_ମୂଲ୍ୟ_e10195a1 | କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ | 최대 4개의 상태를 보관·복원; 독립 ଖୋଳ 프로세스가 아님 |
| `java`, `javac` | EL0 ଉପଭୋକ୍ତା 영역 | `java-tools.elf`를 적재하고 별도 ଉପଭୋକ୍ତା 스택·페이지 권한으로 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ |
| `java CLASS`, `java -jar`의 ଅନୁପ୍ରୟୋଗ_f5044b9b | EL0의 자체 JVM 내부 | 바이트코드 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ. 전체 OpenJDK가 아님 |
| `jaot` ମାପ ELF | EL0 | 지원되는 부분집합을 ARM64 코드로 컴파일한 후 ELF로 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ |
| `python`, `vi`, `cc`, ଉପଭୋକ୍ତା ELF | EL0 | ଉପଭୋକ୍ତା ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ ଫାଇଲ 적재 ପଥ 사용 |
| ଫାଇଲ·소켓·그래픽 시스템 호출 | EL1 | EL0에서 SVC로 들어와 처리한 ପଛ_ମୂଲ୍ୟ ଉପଭୋକ୍ତା 프로그램으로 복귀 |

근거:

- `ଉତ୍ସ/명령해석기.java`: `ଉପକରଣ_ଏଣ୍ଟ୍ରି()` 및 `java`/`javac` ନିର୍ଦ୍ଦେଶ ଶାଖା.
- `ମେସିନ୍/ଉପଭୋକ୍ତା.c`: `ରନ୍_ଅନୁପ୍ରୟୋଗ()`의 ELF 적재, 페이지 ଅନୁମତି_ମୂଲ୍ୟ ବିନ୍ଯାସ, PID 배정, `ଉପଭୋକ୍ତା_ଏଣ୍ଟର୍_କରନ୍ତୁ()`.
- `부팅/ଏଣ୍ଟ୍ରି_ପଏଣ୍ଟ୍_ମୂଲ୍ୟ.S`: `user_enter`의 `SP_EL0`, `SPSR_EL1=0x340`, `eret`.
- `ଉତ୍ସ/ଓ୍ୱିଣ୍ଡୋ_ଅଧିବେଶନ.java`: 네 터미널의 ଖୋଳ 상태와 ଉପଭୋକ୍ତା 세션 보관·재개.

QEMU QMP로 CPU 0을 ପ୍ରକୃତ_ଡାଟା 정지하여 읽은 ଅନୁମତି_ମୂଲ୍ୟ 상태는 ଖୋଳ ଅପେକ୍ଷା_ମୂଲ୍ୟ 중 `EL1h`, Java 계산 중 `EL0t`였다.
이 결과는 소스의 주석이나 ନିର୍ଗମ 문자열만으로 판정한 것이 아니다.

## ps와 top에 기대한 항목이 없는 이유

`ଉତ୍ସ/ସିଷ୍ଟମ_ଉପକରଣ.java`의 `작업보기()`가 두 명령의 공통 출력이다.
`1 ... kernel/shell`은 고정된 କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ/ଖୋଳ 집계 행이다. 셸마다 생성한 ପ୍ରକୃତ_ଡାଟା PID가 아니다.
그 다음에는 살아 있는 କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ 협력 작업과 최대 4개의 EL0 세션을 조회한다.

1. 셸은 독립 ଉପଭୋକ୍ତା 프로세스가 아니므로 터미널을 더 열어도 `shell` 행이 각각 생기지 않는다.
2. 같은 터미널의 `java 인사`가 끝난 ପଛ_ମୂଲ୍ୟ `ps`를 실행하면 해당 Java 세션은 이미 정리되어 표시되지 않는다.
3. `vi`나 Swing 프로그램은 다른 터미널로 전환할 때 CPU ପ୍ରସଙ୍ଗ_ମୂଲ୍ୟ·메모리를 보관한다. 이 상태가 `SUSPENDED`다.
4. 한 번에 ସକ୍ରିୟ EL0 프로그램은 하나다. 다른 창의 프로그램을 동시에 돌리는 일반 선점형 프로세스 스케줄러와 `&` 작업 제어는 없다.
5. Java의 작업 가닥은 자체 JVM 내부에서 협력적으로 전환한다. 별도 କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ 스레드/TID가 아니므로 `ps`에 각각 나타나지 않는다.
6. `ps`·`top` 자체도 କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ 내장 명령이므로 별도의 ଉପଭୋକ୍ତା PID가 생성되지 않는다. `top`은 같은 작업 목록과 ମୋମରୀ_ଡାଟା 정보를 주기적으로 보여 준다.

`RUN_ms`는 세션이 선택된 동안의 경과 시간이며 시스템 호출 시간도 포함한다.
Linux의 정밀 CPU 사용 시간이나 CPU 사용률이 아니다. `MAPPED_KiB`도 ଉପଭୋକ୍ତା 페이지 매핑량이다.

실제로 확인하는 방법:

```text
cd /example/java
java 창예제
```

GUI에서 `Ctrl+Shift+T`로 새 터미널을 열거나 `F6`으로 다른 터미널을 선택한 ପଛ_ମୂଲ୍ୟ:

```text
ps
top -n 1
```

이번 시험에서 두 명령에 ପରବର୍ତ୍ତୀ_ଆଇଟମ୍ ଉପଭୋକ୍ତା 행이 나타났다. PID와 시간은 실행마다 달라진다.

```text
PID SLOT STATE MAPPED_KiB RUN_ms AGE_ms COMMAND
1 - RUN - - 25144 kernel/shell
24 0 SUSPENDED 9608 507 3960 java 창예제
```

`창예제.class`는 ବିଲ୍ଡ୍_ଚିତ୍ର ବିଲ୍ଡ୍_ସିଷ୍ଟମ 때 ଆୟୋଜକ `javac`로 컴파일되어 소스와 함께 탑재된다.
게스트 `javac 창예제.java`는 현재 ସମର୍ଥନ_ମୂଲ୍ୟ 범위를 넘으며 `unsupported throws type` 오류를 낸다.
이 GUI 점검에는 이미 탑재된 클래스를 실행한다.

셸까지 EL0로 옮기고 프로그램을 동시에 실행하려면 ଉପଭୋକ୍ତା ଖୋଳ ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ ଫାଇଲ, 프로세스별 ଠିକଣା 공간·ଫାଇଲ 기술자·작업 디렉터리,
프로세스 ସୃଷ୍ଟି_କରିବା/ଅପେକ୍ଷା_ମୂଲ୍ୟ/ପ୍ରସ୍ଥାନ_ଅନୁପ୍ରୟୋଗ, 스케줄러, TTY ଇନପୁଟ୍_ଆଉଟପୁଟ୍, କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ 작업·ଉପଭୋକ୍ତା 작업 구분을 추가해야 한다.
`ps` 출력에 이름만 추가해서는 ଉପଭୋକ୍ତା ଅନୁମତି_ମୂଲ୍ୟ 분리나 동시 실행이 구현되지 않는다.

## QEMU에서 외부로 통신하기

ଆୟୋଜକ 터미널에서 ପରବର୍ତ୍ତୀ_ଆଇଟମ୍ 중 하나로 실행한다.

```sh
cd /home/user/jkoros/platforms/rpi4-native
make desktop ARGS="--network"
```

화면 없이 UART 셸만 사용할 때는 `make network`를 사용한다.
이미 VM이 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 중이면 ପ୍ରସ୍ଥାନ_ଅନୁପ୍ରୟୋଗ 전 RAM 자료를 보관한다. 별도 VM을 띄우려면
`make desktop ARGS="--network --port 5903 --network-host 127.0.0.2"`처럼 VNC와 ଅଗ୍ରଗାମୀ_ମୂଲ୍ୟ 주소를 구분한다.

게스트 안에서:

```text
ipconfig
ip route show
ping -c 2 10.0.2.2
```

초깃값은 `sl0`, ଠିକଣା `10.0.2.15`, 넷마스크 `255.255.255.0`, ପ୍ରବେଶ_ପଥ_ମୂଲ୍ୟ `10.0.2.2`다.
정상이면 다시 설정할 필요가 없다. 주소를 바꿔 둔 경우 소켓/FTP를 닫은 ପଛ_ମୂଲ୍ୟ 기본값으로 돌릴 수 있다.

```text
ftpd stop
ipconfig set 10.0.2.15 255.255.255.0 10.0.2.2
```

통신 ପଥ:

```text
게스트 Java/C/Python → SVC → କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ lwIP → 보조 UART SLIP
    → ଆୟୋଜକ ନେଟ୍_ୱାର୍କ୍_ବ୍ରିଜ୍.py → QEMU user NAT → ଆୟୋଜକ TCP/IP → LAN/인터넷
```

QEMU `raspi4b`의 GENET Ethernet Controller는 미구현이다.
현재 실행기는 일반 PC용 `-device e1000`이나 `virtio-net-pci` 대신 보조 UART를 사용한다.
따라서 `-nic user`만 추가하거나 게스트 주소만 바꿔서는 이 통신 경로를 대신할 수 없다.
[QEMU Raspberry Pi ଡିଭାଇସ_ମୂଲ୍ୟ ସମର୍ଥନ_ମୂଲ୍ୟ](https://www.qemu.org/docs/master/system/arm/raspi.html)

게스트에서 `127.0.0.1`은 게스트 자신이며, `10.0.2.2`가 QEMU 호스트에 접근하는 주소다.
그 밖의 ପ୍ରକୃତ_ଡାଟା IPv4 주소로 향하는 TCP/UDP는 호스트의 ପଥ·방화벽·통신 가능 여부에 따른다.
게스트 DNS와 일반 TLS 소켓은 아직 없다. 도메인 ନାମ 대신 ଅଙ୍କ_ମୂଲ୍ୟ IPv4를 사용해야 한다. 이후 추가된 GENET·DHCP 및 게스트 SSH·VNC는 [외부 ସଂଯୋଗ_e05f319b ମତେପଢନ୍ତୁ_eb81d7d9](외부접속안내.md)를 참고한다.
`ping 10.0.2.2` 성공은 NAT 관문까지의 확인이지 인터넷 통신의 증거는 아니다.
인터넷 ICMP는 QEMU user NAT와 ଆୟୋଜକ `ping_group_range` 설정에 영향받으므로,
외부 ping 실패만으로 TCP/UDP 통신까지 불가능하다고 판단하지 않는다.
[QEMU NAT 및 ICMP 설명](https://www.qemu.org/docs/master/system/devices/net.html)

## ପ୍ରକୃତ_ଡାଟା TCP/UDP 왕복 예제

VM을 실행한 상태에서 호스트의 다른 터미널에서:

```sh
cd /home/user/jkoros/platforms/rpi4-native
python3 ଉପକରଣସମୂହ/예제되돌림서버.py --tcp-port 9000 --udp-port 9001
```

게스트 안에서:

```text
cd /example/java
java 네트워크예제 9000 9001
cd /example/python
python 네트워크예제.py 9001
```

Java 예제는 TCP와 UDP, Python 예제는 UDP를 ଆୟୋଜକ 응답기로 보내고 ପ୍ରକୃତ_ଡାଟା 받은 자료를 비교한다.
Java 예제의 클래스는 이미 탑재되어 있다. 이 예제의 수신 제한은 700ms이므로 느린 호스트에서는
예제 자체의 ସମୟ_ମୂଲ୍ୟ 제한을 조정해야 할 수 있다.

## ଆୟୋଜକ 또는 다른 PC에서 게스트로 접속하기

ହାର୍ଡୱେର୍_ପୋର୍ଟ 전달을 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 시 명시한다.

```sh
make desktop ARGS="--network --forward tcp:18080:8080 --forward udp:19001:9001"
```

- ଆୟୋଜକ `127.0.0.1:18080/TCP` → 게스트 `10.0.2.15:8080/TCP`.
- ଆୟୋଜକ `127.0.0.1:19001/UDP` → 게스트 `10.0.2.15:9001/UDP`.
- 게스트 프로그램이 그 포트에서 실제로 수신해야 한다. ଅଗ୍ରଗାମୀ_ମୂଲ୍ୟ 옵션이 서버를 시작하지는 않는다.
- `ftpd start`는 별도로 게스트 FTP를 시작한다. ଡିଫଲ୍ଟ_ମାନ ଆୟୋଜକ ନିୟନ୍ତ୍ରଣ_ମୂଲ୍ୟ 포트는 2121, 수동 ଡାଟା 포트는 50000~50007이다.

ଡିଫଲ୍ଟ_ମାନ `--network-host 127.0.0.1`은 루프백에만 연결한다. 이후 추가한 외부 ସଂଯୋଗ_e05f319b 기능에서는
`--network-host 0.0.0.0` 또는 ଆୟୋଜକ LAN 주소를 명시하면 다른 PC의 직접 접속도 허용한다.
[게스트 SSH·VNC ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ ମତେପଢନ୍ତୁ_eb81d7d9](외부접속안내.md)를 참고한다.
루프백 연결을 유지하면서 호스트의 SSH 서버를 이용할 경우 다른 PC에서 다음처럼 TCP 터널을 만든다.
`192.168.0.10`은 QEMU를 실행하는 호스트의 ପ୍ରକୃତ_ଡାଟା ପ୍ରବେଶ_ଏଣ୍ଟ୍ରି 가능한 IP로 바꾼다.

```sh
ssh -N -L 18080:127.0.0.1:18080 user@192.168.0.10
```

다른 PC의 클라이언트는 이제 자기 `127.0.0.1:18080`에 연결한다.
이것이 SSH를 거쳐 호스트의 QEMU ଅଗ୍ରଗାମୀ_ମୂଲ୍ୟ 포트와 게스트 8080에 연결된다.
SSH의 `-L`은 TCP 전용이다. UDP를 LAN에서 직접 받거나 게스트를 LAN의 독립 IP로 쓰려면
추가 UDP 중계 또는 TAP/브리지 백엔드 연결이 필요하며 현재 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 옵션만으로는 제공하지 않는다.
FTP는 ନିୟନ୍ତ୍ରଣ_ମୂଲ୍ୟ 포트뿐 아니라 수동 ଡାଟା ହାର୍ଡୱେର୍_ପୋର୍ଟ 전체도 전달해야 한다.

QEMU를 Ubuntu 가상머신 안에서 실행하는 경우 위의 'ଆୟୋଜକ IP'는 그 Ubuntu의 주소다.
Ubuntu를 실행하는 바깥 가상화 프로그램도 해당 IP/SSH 포트에 ପ୍ରବେଶ_ଏଣ୍ଟ୍ରି 가능한 네트워크 구성이 필요하다.

## 점검 재현과 ଯାଞ୍ଚ୍_କରିବା କ୍ଲିପ୍

```sh
make test-layers
```

- QMP CPU 0 레지스터: ଖୋଳ `EL1h`, Java 계산 `EL0t`.
- 종료된 Java 프로그램의 `ps` ଏଣ୍ଟ୍ରି_ମୂଲ୍ୟ ଅପସାରଣ_କରିବା_ଏଣ୍ଟ୍ରି.
- Java GUI의 다른 ଟର୍ମିନାଲ ସୁଇଚ୍_ମୋଡ୍ 후 별도 PID 및 `SUSPENDED` 상태를 `ps`와 `top`에서 ଯାଞ୍ଚ୍_କରିବା.
- ପ୍ରବେଶ_ପଥ_ମୂଲ୍ୟ ICMP 왕복, FTP ଶ୍ରେଣୀ_ମୂଲ୍ୟ_55654bf1 업로드.
- 독립 ଆୟୋଜକ 상대와 TCP/UDP 발신, 명시적 ହାର୍ଡୱେର୍_ପୋର୍ଟ 전달을 통한 TCP/UDP 수신 및 ଡାଟା 비교.
- ପ୍ରସ୍ଥାନ_ଅନୁପ୍ରୟୋଗ 시 이번 점검이 만든 QEMU만 କ୍ଲିନ୍_ବିଲ୍ଡ୍.

결과는 [보고서](build/verification/execution-network-review/report.json)와
[직렬 ଲଗ୍_ମୂଲ୍ୟ](build/verification/execution-network-review/serial.log)에 저장한다.
보고서에 사용한 କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ SHA-256과 원시 QMP 레지스터를 남긴다.
최초 시도에서는 지원하지 않는 GUI 소스의 게스트 재컴파일 단계가 실패했고,
