# JIndOS 구조

아래는 ଅବଜେକ୍ଟ_ମୂଲ୍ୟ 기반 관리 କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ 전체의 ଲକ୍ଷ୍ୟସ୍ଥଳ_ଅବଜେକ୍ଟ 구조다. 현재 ପ୍ରକୃତ_ଡାଟା 부팅 가능한 제한형 구현은 `compiler/`와 `os/`에 있으며 [네이티브 ଅପରେଟିଂ_ସିଷ୍ଟମ ମତେପଢନ୍ତୁ_eb81d7d9](../os/ମତେପଢନ୍ତୁ_eb81d7d9.md)에 구현 범위를 명시한다. 아래의 GC·ପ୍ରସଙ୍ଗ_ମୂଲ୍ୟ ସୁଇଚ୍_ମୋଡ୍·ଫାଇଲ୍_ସିଷ୍ଟମ୍ 등이 새 ISO에 모두 포함돼 있지는 않다.

```text
GRUB 또는 UEFI
  ↓
x86 최소 부트·트랩 ସ୍ତର_ମୂଲ୍ୟ
  ↓
Java AOT 실행기와 ଅବଜେକ୍ଟ_ମୂଲ୍ୟ·ଆରେ_ମୂଲ୍ୟ·GC 런타임
  ↓
ହାର୍ଡୱେର୍_ମୂଲ୍ୟ 경계
  ↓
Java 관리 କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ
  ├─ 기억공간/쪽관리/COW
  ├─ ପ୍ରୋସେସ୍_ମୂଲ୍ୟ/배정/wait
  ├─ ଫାଇଲ୍_ସିଷ୍ଟମ୍/ELF/POSIX
  └─ 입력/ଷ୍ଟୋରେଜ୍_ଡିଭାଇସ/ନେଟ୍_ୱାର୍କ୍_ଗଦା
```

OpenJDK 자체는 이미 운영체제가 제공하는 ଫାଇଲ, 스레드, 가상 기억공간을 전제로 한다. 따라서 କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ 부팅에는 OpenJDK를 그대로 넣지 않고 제한된 Java 바이트코드 AOT와 작은 런타임을 사용한다.

네이티브 계층에는 `in/out`, `hlt`, CR0/CR2/CR3/CR4, `iret`, ପ୍ରସଙ୍ଗ_ମୂଲ୍ୟ 저장처럼 Java로 표현할 수 없는 CPU 동작만 남긴다. 정책과 자료구조는 Java에 둔다.
