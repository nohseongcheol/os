# jkoros 안에서 Java ସଙ୍କଳନ_ଉତ୍ସ·ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ

이 문서의 부팅·ଖୋଳ·ସଞ୍ଚୟ_କରିବା_ମୂଲ୍ୟ 명령은 **x86 ସଂସ୍କରଣ_ମୂଲ୍ୟ** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 ସଂସ୍କରଣ_ମୂଲ୍ୟ](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 ଫାଇଲ୍_ନାମ_ପାଠ, `edit`의 단독 `.` ସଞ୍ଚୟ_କରିବା_ମୂଲ୍ୟ, 16개 RAM ଫାଇଲ, 약 2초 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 ପ୍ରକୃତ_ଡାଟା JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. ଆୟୋଜକ ସଙ୍କଳନ_ଉତ୍ସ 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java ଅନୁପ୍ରୟୋଗ_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ ମତେପଢନ୍ତୁ_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 ଫାଇଲ 전체를 새 내용으로 작성한다. 기존 내용의 ରେଖା ସଂପାଦନା_ମୂଲ୍ୟ 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 ବାଇଟ୍_ମୂଲ୍ୟ 수 ପ୍ରଦର୍ଶନ_କରିବା_ମୂଲ୍ୟ.
- `cat FILE`: ଫାଇଲ ବିଷୟ_ମୂଲ୍ୟ ପ୍ରଦର୍ଶନ_କରିବା_ମୂଲ୍ୟ. 텍스트 소스에 사용한다.
- `rm FILE`: ମୋମରୀ_ଡାଟା ଫାଇଲ 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·ଟାଇପ୍_କରିବା_ମୂଲ୍ୟ 검사 ବିଫଳତା_ମୂଲ୍ୟ 시 기존 `.class`는 유지된다. 소스를 고친 ପଛ_ମୂଲ୍ୟ 컴파일이 실패했다면 이전 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 파일이 남아 있으므로 ସଙ୍କଳନ_ଉତ୍ସ 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 ସଞ୍ଚୟ_କରିବା_ମୂଲ୍ୟ 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 ଉତ୍ସ_ବୃକ୍ଷ·ଶ୍ରେଣୀ_ମୂଲ୍ୟ_55654bf1·ଡାଟା 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, ଫାଇଲ 이름은 ASCII 1~63자다. ଉତ୍ସ_ବୃକ୍ଷ 이름은 `.class` 확장자 공간 때문에 최대 62자다. ସଂପାଦନା_ମୂଲ୍ୟ 입력은 ASCII이고 한 ରେଖା 최대 128자다. ରେଖା 또는 ଫାଇଲ 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. କେନ୍ଦ୍ରିକ_ମୂଲ୍ୟ/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 ଉପଭୋକ୍ତା 예제 이름은 ASCII로 작성한다.

## 외부 ଫାଇଲ 적재

호스트에서 만든 소스나 ସମର୍ଥନ_ମୂଲ୍ୟ କ୍ଲିପ୍ 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 ପ୍ରକୃତ_ଡାଟା 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# ଆୟୋଜକ JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 ପରବର୍ତ୍ତୀ_ଆଇଟମ୍ 빌드에서는 추가 파일을 포함하지 않는다. ଫାଇଲ ବିଷୟ_ମୂଲ୍ୟ 변경과 ଏଣ୍ଟ୍ରି_ତାଲିକା 제거도 ପରବର୍ତ୍ତୀ_ଆଇଟମ୍ 빌드에 반영된다. 원본 ଆୟୋଜକ 파일에는 쓰지 않는다. ଡିଫଲ୍ଟ_ମାନ `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 ଡିଫଲ୍ଟ_ମାନ 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 ଶ୍ରେଣୀ_ମୂଲ୍ୟ_55654bf1 ଫାଇଲ 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 ସମର୍ଥନ_ମୂଲ୍ୟ କ୍ଲିପ୍ 안에 있어야 한다.

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 ସ୍ଥାନୀୟ_ପରିସର 선언, 오버로드, 임의 ଟାଇପ୍_କରିବା_ମୂଲ୍ୟ 변환, ଆରେ_ମୂଲ୍ୟ ସୃଷ୍ଟି_କରିବା ଉତ୍ସ, 8/16진 리터럴, Unicode ଉତ୍ସ_ବୃକ୍ଷ 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 ସ୍ଥିରାଙ୍କ_ମୂଲ୍ୟ 축소 변환을 구현하지 않는다. 외부 `.class`의 `int[]` ସୃଷ୍ଟି_କରିବା/ପଢନ୍ତୁ/쓰기는 지원하므로 ଆୟୋଜକ `javac --release 8`로 만든 ଆରେ_ମୂଲ୍ୟ 예제는 실행할 수 있다.

ଅବଜେକ୍ଟ_ମୂଲ୍ୟ ଫିଲ୍ଡ_ମୂଲ୍ୟ·일반 ଅବଜେକ୍ଟ_ମୂଲ୍ୟ ସୃଷ୍ଟି_କରିବା·상속·인터페이스·여러 ଶ୍ରେଣୀ_ମୂଲ୍ୟ_55654bf1 ସଂଯୋଗ_କରନ୍ତୁ, long/float/double, ବ୍ୟତିକ୍ରମ ପ୍ରୋସେସ୍_ମୂଲ୍ୟ_ଏଣ୍ଟ୍ରି, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java ବ୍ୟତିକ୍ରମ 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 ଷ୍ଟ୍ରିଂ_ମୂଲ୍ୟ ସଞ୍ଚୟ_କରିବା_ମୂଲ୍ୟ 공간은 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ ପ୍ରସ୍ଥାନ_ଅନୁପ୍ରୟୋଗ 시 ଉପଭୋକ୍ତା 영역 전체와 함께 회수한다. 지속 ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 중 GC는 없다.

## ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 한도와 ତ୍ରୁଟି

| 컴파일러 | ଟୋକନ୍_ମୂଲ୍ୟ 2,047개, ସୃଷ୍ଟି_କରିବା 코드 4KiB, ସ୍ଥିରାଙ୍କ_ମୂଲ୍ୟ 풀 4KiB |
| Excel_ଟେବଲ୍_ମୂଲ୍ୟ/인수 | 클래스당 32함수, 함수당 16인수 |

| ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ | 최대 500,000 ନିର୍ଦ୍ଦେଶ, 기존 커널의 약 3초 CPU ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 ସମର୍ଥନ_ମୂଲ୍ୟ 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM ଅଭିଧାନ 검증기를 구현한 것은 아니다. ଫାଇଲ/ଗୁଣ_ମୂଲ୍ୟ ଦୈର୍ଘ୍ୟ_ମୂଲ୍ୟ, ସ୍ଥିରାଙ୍କ_ମୂଲ୍ୟ ପ୍ରସଙ୍ଗ, ନିର୍ଦ୍ଦେଶ·ଶାଖା 경계를 검사하고, ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ 중 스택 ଫର୍ମାଟ୍_ମୂଲ୍ୟ·ସ୍ଥାନୀୟ_ପରିସର ପ୍ରାରମ୍ଭିକରଣ·ଆରେ_ମୂଲ୍ୟ ପାଦାଙ୍କ_ମୂଲ୍ୟ·ଅବଜେକ୍ଟ_ମୂଲ୍ୟ 참조를 검사한다. ଉପଭୋକ୍ତା 코드의 페이지·ହାର୍ଡୱେର୍_ପୋର୍ଟ 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, ସଙ୍କଳନ_ଉତ୍ସ·JVM 오류는 `Exit: 1`, ନିର୍ଦ୍ଦେଶ 인수 오류는 `Exit: 2`다. CPU ସମୟ_ମୂଲ୍ୟ 상한은 기존 `Exit: 124`이며, ଉପଭୋକ୍ତା ELF 자체의 CPU/런타임 오류는 기존 ପ୍ରସ୍ଥାନ_ଅନୁପ୍ରୟୋଗ 코드를 따른다. ବିଫଳତା_ମୂଲ୍ୟ 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## 구현 위치와 시험

- `os/ଉପଭୋକ୍ତା/자바/자바컴파일러.java`: 게스트 어휘·구문·ଟାଇପ୍_କରିବା_ମୂଲ୍ୟ 검사, ସ୍ଥିରାଙ୍କ_ମୂଲ୍ୟ 풀 및 바이트코드 ସୃଷ୍ଟି_କରିବା.
- `os/ଉପଭୋକ୍ତା/자바/자바가상기계.java`: ଶ୍ରେଣୀ_ମୂଲ୍ୟ_55654bf1 적재, 스택·프레임·ଅବଜେକ୍ଟ_ମୂଲ୍ୟ ସଞ୍ଚୟ_କରିବା_ମୂଲ୍ୟ, ନିର୍ଦ୍ଦେଶ 해석과 제한된 표준 호출.
- `os/ଉତ୍ସ/ମୋମରୀ_ଫାଇଲ୍_ସିଷ୍ଟମ୍.java`: ମୋମରୀ_ଡାଟା ଫାଇଲ୍_ସିଷ୍ଟମ୍, ସଂପାଦନା_ମୂଲ୍ୟ, 부팅 ଫାଇଲ 적재.
- `os/ଉତ୍ସ/체계호출.java`, `compiler/ଆରମ୍ଭ_ଉପଭୋକ୍ତା_ଅନୁପ୍ରୟୋଗ.s`: ଫାଇଲ/문자 ନିର୍ଗମ API와 ଉପଭୋକ୍ତା ପଏଣ୍ଟର୍ 검사.
- `os/ଉପକରଣସମୂହ/자바파일묶기.py`: ଆୟୋଜକ 입력 ଫାଇଲ ବୈଧକରଣ·부팅 ଗୋଷ୍ଠୀ_ମୂଲ୍ୟ ସୃଷ୍ଟି_କରିବା.

```sh
make test-java
make test
```

`os/시험/자바시험.py`는 ELF/ISO 부팅, 게스트 ସଙ୍କଳନ_ଉତ୍ସ·ନିର୍ବାହ_କରିବା_ନିର୍ଦ୍ଦେଶ, ଉପଭୋକ୍ତା 입력, 재귀·반복문·ଇଣ୍ଟିଜର 극값·ଷ୍ଟ୍ରିଂ_ମୂଲ୍ୟ 결합·단락 평가, 재실행, ଉତ୍ସ_ବୃକ୍ଷ ତ୍ରୁଟି 후 기존 ଶ୍ରେଣୀ_ମୂଲ୍ୟ_55654bf1 보존, ଆରେ_ମୂଲ୍ୟ/수 해독 ତ୍ରୁଟି, 무한 ବାରମ୍ବାର_ମୂଲ୍ୟ 제한, ସଂପାଦନା_ମୂଲ୍ୟ 넘침과 ଫାଇଲ 부족을 검사한다. 게스트 ସୃଷ୍ଟି_କରିବା 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 ଆୟୋଜକ OpenJDK의 ଶ୍ରେଣୀ_ମୂଲ୍ୟ_55654bf1, ଇଣ୍ଟିଜର 배열과 한글 상수를 게스트에 적재하며, 손상된 ଫାଇଲ 표식·버전·ସ୍ଥିରାଙ୍କ_ମୂଲ୍ୟ 수·ଶାଖା·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 시험 VM만 생성하고 종료한다.

구현 형식의 참고 ଡାଟା: Oracle [JVM ଶ୍ରେଣୀ_ମୂଲ୍ୟ_55654bf1 ଫାଇଲ 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM ନିର୍ଦ୍ଦେଶ 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java ଫାଇଲ ଇନପୁଟ୍_ଆଉଟପୁଟ୍

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 ଶ୍ରେଣୀ_ମୂଲ୍ୟ_55654bf1 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 ପଛ_ମୂଲ୍ୟ `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. ଡିଫଲ୍ଟ_ମାନ ନିର୍ଗମ 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. ବ୍ୟତିକ୍ରମ ଅବଜେକ୍ଟ_ମୂଲ୍ୟ·try/catch·try-with-resources는 지원하지 않으며 ଫାଇଲ 오류를 진단하고 프로그램을 종료한다. ଆରେ_ମୂଲ୍ୟ ଇନପୁଟ୍_ଆଉଟପୁଟ୍, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 ଫାଇଲ 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 ଖୋଳ `sync`가 필요하다. 예제의 ଫାଇଲ 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 ପ୍ରକୃତ_ଡାଟା 게스트 ସଙ୍କଳନ_ଉତ୍ସ 결과를 OpenJDK `-Xverify:all`로 다시 실행해 ଫାଇଲ 바이트와 출력을 대조한다. 범위와 ସଞ୍ଚୟ_କରିବା_ମୂଲ୍ୟ 매체 사용법은 [posix-kor ମତେପଢନ୍ତୁ_eb81d7d9](../posix-kor/ମତେପଢନ୍ତୁ_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
