# 셸에서 실행하는 వినియోగదారు 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 మార్గదర్శక_సమాచారం_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 అమలు_చేయి_ఆదేశం

హోస్ట్ టెర్మినల్ 1:

```sh
cd /home/user/jkoros
python3 os/ఉపకరణాలు/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 외부 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

హోస్ట్ టెర్మినల్ 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 వాస్తవ_డేటా CPU అనుమతి_మూల్యం `ring 3`, 인수 అవుట్పుట్.
- `netcheck`: పోర్టు_మూల్యం 중복, 잘못된 నిర్వాహకం_మూల్యం/పాయింటర్/పొడవు_మూల్యం, 비차단 받기와 సమయం_మూల్యం 초과 సరిచూడు.
- `udp`: IPv4 ఇమెయిల్·గమ్యం_మూల్యం పోర్టు_మూల్యం·한 పదం_మూల్యం 메시지를 받아 UDP로 보내고 같은 응답을 సరిచూడు. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: హోస్ట్ `10.0.2.2`의 కేటాయించు_మూల్యం 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 లూప్_మూల్యం 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 현재 주소는 게스트 `10.0.2.15/24`, ప్రవేశద్వారం_మూల్యం `10.0.2.2`로 고정돼 있다. QEMU వినియోగదారు 네트워크의 హోస్ట్ ప్రాప్తి_ప్రవేశం 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 అనువర్తనం_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java అనువర్తనం_f5044b9b 추가

`예제/내프로그램.java`를 తదుపరి_అంశం 형식으로 만든다. 진입점은 인수 없는 `static int` 또는 `static void` 함수다. 인수는 వినియోగదారు API로 조회한다.

```java
public final class 내프로그램 {
    public static int నడుపుము() {
        వినియోగదారు.వ్రాయుము("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/వినియోగదారు/అనువర్తనం_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := వినియోగదారు/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.నడుపుము
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `వినియోగదారు/ప్రకటన/వినియోగదారు.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 అమలు_చేయి_ఆదేశం 중인 VM에는 బిల్డ్_సిస్టం 결과가 자동 반영되지 않는다. అనువర్తనం_f5044b9b 이름은 현재 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java తరగతి_మూల్యం·కార్యం_మూల్యం·변수에는 한국어를 쓴다. 최대 32개 అనువర్తనం_f5044b9b, 한 అమలు_చేయి_ఆదేశం 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.నడుపుము \
    -o os/build/apps/hello.elf os/వినియోగదారు/ప్రకటన/వినియోగదారు.java os/వినియోగదారు/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 హోస్ట్ 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 మద్దతు_మూల్యం క్లిప్ 안에서 실행한다. `.jar`와 일반 Linux అమలు_చేయి_ఆదేశం 파일은 지원하지 않는다.

## వినియోగదారు 네트워크 API

선언은 `ప్రకటన/వినియోగదారు.java`에 있다. `పంపు_డేటా`/`자료받기`의 `int[]` అంశం_మూలకం 한 개는 బైట్_మూల్యం 하나(0~255)를 나타낸다. 한 데이터그램의 최대 డేటా 길이는 1,024바이트다.

```java
int నిర్వాహకం_మూల్యం = వినియోగదారు.తెరువు_నెట్_వర్క్(0); // 0: 임시 స్థానిక_పరిధి UDP పోర్టు_మూల్యం 자동 ఎంపిక_మూల్యం
int[] డేటా = new int[32];
డేటా[0] = 'H'; డేటా[1] = 'i';
int 보낸길이 = వినియోగదారు.పంపు_డేటా(నిర్వాహకం_మూల్యం, 0x0a000202, 9000, డేటా, 2);
int 받은길이 = వినియోగదారు.자료받기(నిర్వాహకం_మూల్యం, డేటా, 1500);
వినియోగదారు.మూసివేయి_నెట్_వర్క్(నిర్వాహకం_మూల్యం);
```

వాస్తవ_డేటా 프로그램에서는 తెరువు·పంపు·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 వేచియుండు_మూల్యం 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 추가 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | నిర్వాహకం_మూల్యం·విధానం_మూల్యం_ప్రవేశం పొడవు_మూల్యం·성공 등 해당 함수의 ప్రమాణం |
| -5 | పరికరం_మూల్యం పంపు_మూల్యం వైఫల్యం_మూల్యం |
| -9 | 잘못되었거나 닫힌 통신 నిర్వాహకం_మూల్యం |
| -11 | 비차단 받기에서 도착한 డేటా 없음 |
| -14 | వినియోగదారు పాయింటర్/శ్రేణి_మూల్యం క్లిప్ దోషం |
| -19 | మద్దతు_మూల్యం NIC 없음 |
| -22 | పోర్టు_మూల్యం/వేచియుండు_మూల్యం సమయం_మూల్యం/인수 మూల్యం దోషం |
| -24 | 열린 నెట్_వర్క్_పోర్టు 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | డేటా 또는 수신 శ్రేణి_మూల్యం పరిమాణం 문제 |
| -98 | స్థానిక_పరిధి పోర్టు_మూల్యం సూచీ 중복 |
| -101 | 지원하지 않는 గమ్యం_మూల్యం ఇమెయిల్ |
| -110 | ARP·పరికరం_మూల్యం·수신 సమయం_మూల్యం 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 సంకేతీకరణం_మూల్యం 있는 Java `int`의 బిట్_మూల్యం 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## అమలు_చేయి_ఆదేశం 경계와 시스템 호출

```text
షెల్ run → JKAP에서 ELF నిర్థారీకరించు·적재 → ring 3 వినియోగదారు అనువర్తనం_f5044b9b
                                 ↓ int 0x80
                      పాయింటర్ 검사 → Java కెర్నల్_మూల్యం API → RTL8139/UDP
                                 ↓ నిష్క్రమణ_అనువర్తనం·మినహాయింపు·సమయం_మూల్యం 초과
                                షెల్ 복귀
```

시스템 호출 레지스터는 `EAX=సూచీ`, `EBX,ECX,EDX,ESI,EDI=인수`, `EAX=ప్రమాణం`다. Java 호출 스택 ABI는 컴파일러가 వినియోగదారు 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| సూచీ | 호출 |
| --- | --- |
| 0 | నిష్క్రమణ_అనువర్తనం(స్థితి_మూల్యం కోడ్_మూల్యం) — నడుపుము/దోషం 런타임에서 사용 |
| 1 | అక్షరసరం_మూల్యం వ్రాయుము |
| 2 / 3 | 인수 개수 / 인수 అక్షరసరం_మూల్యం ఇమెయిల్ |
| 10 | UDP తెరువు |
| 11 | UDP పంపు(నిర్వాహకం_మూల్యం, IP, గమ్యం_మూల్యం పోర్టు_మూల్యం, శ్రేణి_మూల్యం ఇమెయిల్, పొడవు_మూల్యం) |
| 12 | UDP 받기(నిర్వాహకం_మూల్యం, శ్రేణి_మూల్యం ఇమెయిల్, 제한 밀리초) |
| 13 | UDP మూసివేయి |
| 14 | స్థానిక_పరిధి IP ఇమెయిల్ |
| 15 / 16 | 마지막 పియర్_మూల్యం IP / UDP పోర్టు_మూల్యం |
| 20 | RAM దస్త్రం చదువు(పేరు int[] ఇమెయిల్, అవుట్పుట్ int[] ఇమెయిల్) |
| 21 | RAM దస్త్రం వ్రాయుము(పేరు int[] ఇమెయిల్, 입력 int[] ఇమెయిల్, బైట్_మూల్యం పొడవు_మూల్యం) |
| 22 | UTF-16 కోడ్_మూల్యం పాఠం_మూల్యం 문자 అవుట్పుట్(0~65535) |

దస్త్రం API는 `వినియోగదారు.파일읽기(int[] పేరు, int[] డేటా)`와 `వినియోగదారు.వ్రాయి_ఫైలు(int[] పేరు, int[] డేటా, int పొడవు_మూల్యం)`다. 이름은 ASCII కోడ్_మూల్యం శ్రేణి_మూల్యం(최대 64칸, 0 నిష్క్రమణ_అనువర్తనం 또는 శ్రేణి_మూల్యం 끝), డేటా అంశం_మూలకం 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 దస్త్రం 없음 `-2`, పాయింటర్ దోషం `-14`, పేరు/పొడవు_మూల్యం దోషం `-22`, దస్త్రం స్లాట్_మూల్యం 부족 `-28`, పరిమాణం 초과 `-90`을 반환한다. 쓰기는 నిర్థారీకరించు 후 దస్త్రం 전체를 대체한다. `వినియోగదారు.వ్రాయి_అక్షరం_మూల్యం(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 వినియోగదారు 모드에서 CS의 하위 비트를 직접 읽으므로 వాస్తవ_డేటా అమలు_చేయి_ఆదేశం 권한을 확인한다. కెర్నల్_మూల్యం 포트 접근용 `పరికరం_మూల్యం` native 함수는 వినియోగదారు లక్ష్యం 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 అమలు_చేయి_ఆదేశం, 파이프, 프로세스 간 통신은 없다. అమలు_చేయి_ఆదేశం 파일은 커널의 చదువు 전용 JKAP 묶음에서 적재한다. డేటా 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- వినియోగదారు 가상 ఇమెయిల్ `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. అమలు_చేయి_ఆదేశం 영상은 ముందు_మూల్యం 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. కెర్నల్_మూల్యం identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB వినియోగదారు 영역을 비우고 దస్త్రం 구역을 복사해 BSS·శ్రేణి_మూల్యం 영역을 초기화한다. వినియోగదారు GC는 없지만 నిష్క్రమణ_అనువర్తనం 후 తదుపరి_అంశం అమలు_చేయి_ఆదేశం 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 కోట్/이스케이프 파싱은 없다.
- వినియోగదారు 페이지의 కోడ్_మూల్యం/డేటా 분리 చదువు 전용 అమరికలు, NX, 스택 guard, ASLR은 아직 없다. 커널과 వినియోగదారు మెమరీ_డేటా·포트 అనుమతి_మూల్యం 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 అమలు_చేయి_ఆదేశం 상한을 두며 సమయం_మూల్యం 초과는 `Exit: 124`다. వినియోగదారు CPU 예외는 `128 + మినహాయింపు సూచీ`(페이지 దోషం 142, 특권 위반 141), Java శ్రేణి_మూల్యం/계산 오류는 101~105다. కెర్నల్_మూల్యం 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, నిశ్చల_మూల్యం IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP 검사합 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- వినియోగదారు అమలు_చేయి_ఆదేశం·네트워크·రక్షించు_మూల్యం 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 అమలు_చేయి_ఆదేశం·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## నిర్థారీకరించు 근거

`make test`는 컴파일러 14개 시험, Java 패킷 నిబంధన 2,201개 검사, 기존 షెల్ ELF/ISO 부팅 시험, వినియోగదారు ELF/వాస్తవ_డేటా UDP/రక్షించు_మూల్యం 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 పొడవు_మూల్యం·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 ఆదేశము·무한 పునరావృతం_మూల్యం 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
