# 자체 ARM64 커널의 Codex వ్యవస్థాపించు_మూల్యం 가능성 검토

검토일: 2026-10-05. 소스와 공식 문서를 대조한 설계 검토이며, 게스트에 Codex를 설치하거나
로그인·모델 호출을 실행한 결과는 아니다. 자체 ARM64 커널과 `../rpi4` Linux 실행판은 구분한다.

현재 자체 커널에는 공식 Codex CLI를 그대로 వ్యవస్థాపించు_మూల్యం·실행할 수 없다.
기술적으로 필요한 అమలు_చేయి_ఆదేశం 환경을 추가하거나 Codex를 이식하는 경로는 있으나,
다운로드 ఆదేశము 하나를 추가하는 작업으로 해결되지 않는다. JDK/JRE 기능 확장만으로도 해결되지 않는다.

## 확인한 근거

| ప్రవేశం_మూల్యం | 현재 소스에서 확인한 స్థితి_మూల్యం | 직접 실행을 위한 작업 |
|---|---|---|
| అమలు_చేయి_ఆదేశం దస్త్రం | `యంత్రం/వినియోగదారు.c`: AArch64 ET_EXEC만, PT_INTERP/PT_DYNAMIC/PT_TLS తిరస్కరించు_మూల్యం, 업로드 అమలు_చేయి_ఆదేశం 버퍼 16384바이트 | లక్ష్యం 바이너리에 맞는 ELF 적재·재배치·అమలు_చేయి_ఆదేశం సంకల్పించు, మెమరీ_డేటా/దస్త్రం 제한 పొడిగింపు_మూల్యం |
| Linux ABI | `యంత్రం/리눅스호환.inc`: read/write/openat/brk 등 제한된 번호만 విధానం_మూల్యం_ప్రవేశం, 나머지는 ENOSYS | libc/런타임에 필요한 시스템 호출을 추가하거나 자체 ABI용 런타임 이식 |
| 프로세스·스레드 | 일반 fork/clone/execve, pthread/futex, 시그널, mmap, poll/epoll 계열이 미완성 | 비동기 I/O·스레드·ఉపాంశం_మూల్యం ఆదేశము అమలు_చేయి_ఆదేశం·నిష్క్రమణ_అనువర్తనం/రద్దు_ఆపరేషన్ 기능 |
| దస్త్రం | `వనరు/మెమరీ_ఫైల్_లు.java`: RAM దస్త్రం 64개, 파일당 16 KiB, 비영속 | 큰 అమలు_చేయి_ఆదేశం దస్త్రం·프로젝트·అమరికలు·세션을 위한 영속 VFS, దస్త్రం అనుమతి_మూల్యం·పాత్·디렉터리 పొడిగింపు_మూల్యం |
| 네트워크 | lwIP TCP/UDP는 있으나 `నెట్_వర్క్_దొంతర/lwipopts.h`의 LWIP_DNS=0, 일반 HTTPS 클라이언트 없음 | DNS, TLS 인증서 నిర్థారీకరించు·신뢰 రిపోజిటరీ_మూలం·정확한 시각, HTTPS/스트리밍 |
| టెర్మినల్·ఉపకరణాలు | 자체 셸과 GUI 터미널은 있지만 표준 PTY·일반 프로세스 작업 నియంత్రణ_మూల్యం 없음 | పరస్పర CLI용 టెర్మినల్ 기능, షెల్/దస్త్రం 검색/బిల్డ్_సిస్టం ఉపకరణాలు కనెక్టుచేయి |
| అమలు_చేయి_ఆదేశం అనుమతి_మూల్యం | EL0 보호는 있으나 Codex의 Linux 샌드박스와 같은 정책 집행 환경 없음 | దస్త్రం·네트워크·ఆదేశము అనుమతి_మూల్యం 정책과 승인 기능; 자체 커널에 맞는 격리 구현 |

여기서 ELF의 PT_TLS는 스레드별 నిల్వ_మూల్యం 공간이다. HTTPS의 TLS అనుమతిపదం_మూల్యం 통신과 서로 다른 기능이다.
ELF దస్త్రం 형식을 읽을 수 있다는 사실만으로 Linux అమలు_చేయి_ఆదేశం 환경을 제공하는 것은 아니다.
SSH/VNC를 위한 అనుమతిపదం_మూల్యం 라이브러리를 넣은 상태도 HTTPS 구현 완료를 의미하지 않는다.

호스트의 `/home/user/.local/bin/codex`도 확인했다. 이것은 x86-64 ELF ET_DYN이며 약 209 MiB다.
해당 파일을 ARM64 게스트로 복사하여 실행할 수 없다. 이 크기를 ARM64 배포 파일의 크기로
해석하지 않는다. 공식 ARM64 빌드의 వాస్తవ_డేటా పరిమాణం·의존성은 설치할 버전으로 추가 검사해야 한다.

## 가능한 구현 పాత్

1. **자체 커널에 공식 CLI 직접 이식**
   영속 నిల్వ_మూల్యం/VFS와 వినియోగదారు మెమరీ_డేటా, 프로세스·스레드·I/O, libc/런타임, DNS/HTTPS,
   టెర్మినల్·అనుమతి_మూల్యం 체계를 갖춘다. 이후 లక్ష్యం 버전의 의존성을 조사하여 크로스 బిల్డ్_సిస్టం·이식한다.
   Linux 커널을 반드시 탑재할 필요는 없지만, 공식 Linux 바이너리를 그대로 쓸 경우
   그 바이너리가 사용하는 Linux ABI까지 호환해야 한다. 큰 నిర్వహణా_వ్యవస్థ 개발 과제다.

2. **외부 హోస్ట్ Codex와 자체 కెర్నల్_మూల్యం కనెక్టుచేయి — 첫 구현으로 권장**
   Linux PC에서 공식 CLI 또는 app-server를 실행하고 jkoros에는 전용 వినియోగదారు ఆదేశము/화면을 만든다.
   호스트의 인증된 연결과 게스트 దస్త్రం చదువు·수정·업로드·ఆదేశము అమలు_చేయి_ఆదేశం 어댑터가 필요하다.
   기존 SSH/TCP 경로를 활용할 수 있으나, దస్త్రం 동기화나 Codex 전용 어댑터는 현재 구현되어 있지 않다.
   호스트에서 수행한 빌드와 게스트에서 수행한 అమలు_చేయి_ఆదేశం 결과를 명확히 구분한다.
   이 구성은 자체 커널을 유지하지만, 공식 CLI 자체는 외부 호스트에서 실행된다.

3. **자체 API 클라이언트 제작**
   자체 ABI의 C 또는 지원되는 Java 부분집합으로 పరస్పర_సెషన్ UI와 దస్త్రం/ఆదేశము ఉపకరణాలు 호출 루프를 만든다.
   외부 중계기를 쓰지 않는다면 DNS/నిర్థారీకరించు 가능한 TLS/HTTPS와 인증 డేటా 저장을 먼저 구현해야 한다.
   이는 OpenAI API를 이용하는 별도 에이전트이며 공식 Codex CLI 전체의 이식으로 표시하지 않는다.

4. **별도 ARM64 Linux 실행판에서 వ్యవస్థాపించు_మూల్యం**
   `../rpi4`는 Linux와 musl 기반이므로 일반 Linux వ్యవస్థాపించు_మూల్యం 경로를 검토할 수 있다.
   사용할 Codex 버전의 ARM64·musl 호환성, 의존성, 커널의 샌드박스 지원을 వాస్తవ_డేటా 검증해야 한다.
   이번 검토에서 వ్యవస్థాపించు_మూల్యం 성공을 확인하지 않았다. 이 결과를 자체 Java 커널의 지원으로 표시하지 않는다.

## 단계별 완료 ప్రొజెక్ట్_మూలం

- 직접 이식: `--version` నడుపుము → 인증/HTTPS → దస్త్రం చదువు·수정 → ఉపాంశం_మూల్యం ఆదేశము అమలు_చేయి_ఆదేశం →
  పరస్పర 입력/스트리밍 → అనుమతి_మూల్యం 제한·రద్దు_ఆపరేషన్ → 재부팅 후 అమరికలు/세션 보존을 각각 వాస్తవ_డేటా 게스트에서 확인한다.
- హోస్ట్ కనెక్టుచేయి: 게스트에서 요청 입력 → హోస్ట్ Codex విధానం_మూల్యం_ప్రవేశం → 게스트 దస్త్రం మార్చు_మూల్యం సరిచూడు →
  게스트 javac/cc అమలు_చేయి_ఆదేశం → ప్రమాణం 표시를 처음부터 끝까지 검증한다.
- COSL 상업 조건을 유지하려면 새로 도입하는 런타임/통신 라이브러리의 라이선스와
  Codex 배포 버전의 제3자 고지를 검토한다. 외부 구성요소를 일괄 COSL로 재라이선스하지 않는다.

## 공식 문서

- [Codex CLI వ్యవస్థాపించు_మూల్యం 및 చర్య](https://learn.chatgpt.com/docs/codex/cli): 표준 Linux/macOS 독립 వ్యవస్థాపించు_మూల్యం 경로와 프로젝트 దస్త్రం·ఆదేశము 작업.
- [인증](https://learn.chatgpt.com/docs/auth): ChatGPT/API 인증, 헤드리스 장치의 `codex login --device-auth`, HTTPS 인증서 అమరికలు.
- [샌드박스](https://learn.chatgpt.com/docs/sandboxing): 운영체제별 집행 విధానం_మోడ్_3f5e5497, Linux의 bubblewrap 및 వినియోగదారు 네임스페이스 요구 사항.
- [공개 구성요소](https://learn.chatgpt.com/docs/open-source): CLI/SDK/app-server의 공개 మూలం_వృక్షాకృతి 위치와 비공개 구성요소 డెలీమీటర్_మూల్యం.

공식 문서에는 jkoros를 మద్దతు_మూల్యం 대상으로 명시한 내용이 없다. 위 구현 పాత్·개발 순서는
현재 소스와 요구 기능을 대조한 기술적 판단이다.
