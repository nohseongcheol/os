# వినియోగదారు 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `యంత్రం/నిర్వహణా_వ్యవస్థ_కాల్_లు.s`에서 EAX(సూచీ), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 인수)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. కెర్నల్_మూల్యం 실패는 음수 దోషం సూచీ, C లైబ్రరీ 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 వినియోగదారు 영역 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C డేటా 주소는 బైట్_మూల్యం 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java దస్త్రం 흐름의 어셈블리 경계가 별도 బైట్_మూల్యం 버퍼를 마련하여 같은 호출을 사용한다.

| 31 | 파일자료읽기 | 서술자, డేటా ఇమెయిల్, బైట్_మూల్యం 수 |

| 44 | 자료전문받기 | 서술자, డేటా ఇమెయిల్, పొడవు_మూల్యం, అమరికలు, 요청 ఇమెయిల్ |
| 45 | 통신주소읽기 | 서술자, sockaddr ఇమెయిల్, socklen_t ఇమెయిల్ |
| 46 | 수신대기정하기 | 서술자, 0~2000 밀리초 |
| 47 | 파일저장확정 | 서술자 |

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 ఇమెయిల్ 두 칸이다. 수신 주소가 NULL이면 పియర్_మూల్యం ఇమెయిల్ 기록을 생략한다. sockaddr_in은 16바이트이며 ఇమెయిల్ 체계는 పరికరం_మూల్యం బైట్_మూల్యం 차례, 접속번호와 IP 주소는 네트워크 బైట్_మూల్యం 차례다. 축소된 ఇమెయిల్ 버퍼에도 들어가는 앞부분을 쓰고 전체 ఇమెయిల్ పరిమాణం 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 నిష్క్రమణ_అనువర్తనం, 2·3은 기존 인수 조회다. 현재 커널의 인수 목록이 అమలు_చేయి_ఆదేశం 이름을 제외하므로 C 진입기는 argv[0]에 고정 అక్షరసరం_మూల్యం `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX విధానం_మూల్యం ABI와 다른 점이다.

표준 헤더의 పూర్ణాంకం పరిమాణం, 플래그 మూల్యం, stat ఫీల్డ్_మూల్యం 순서는 `వనరు/포함/`에 정의한다. 동적 కనెక్టుచేయి·다중 విధానం_మూల్యం·스레드가 추가되면 దోషం సూచీ 저장과 వనరు_మూల్యం 수명, 호출 경계도 함께 검토해야 한다.
