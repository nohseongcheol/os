# JIndOS 구조

아래는 అంశం_మూల్యం 기반 관리 కెర్నల్_మూల్యం 전체의 లక్ష్యం_అంశం 구조다. 현재 వాస్తవ_డేటా 부팅 가능한 제한형 구현은 `compiler/`와 `os/`에 있으며 [네이티브 నిర్వహణా_వ్యవస్థ మార్గదర్శక_సమాచారం_eb81d7d9](../os/మార్గదర్శక_సమాచారం_eb81d7d9.md)에 구현 범위를 명시한다. 아래의 GC·సందర్భం_మూల్యం మారు_మోడ్·ఫైల్_వ్యవస్థ 등이 새 ISO에 모두 포함돼 있지는 않다.

```text
GRUB 또는 UEFI
  ↓
x86 최소 부트·트랩 పొర_మూల్యం
  ↓
Java AOT 실행기와 అంశం_మూల్యం·శ్రేణి_మూల్యం·GC 런타임
  ↓
하드웨어 경계
  ↓
Java 관리 కెర్నల్_మూల్యం
  ├─ 기억공간/쪽관리/COW
  ├─ విధానం_మూల్యం/배정/wait
  ├─ ఫైల్_వ్యవస్థ/ELF/POSIX
  └─ 입력/నిల్వ_పరికరం/నెట్_వర్క్_దొంతర
```

OpenJDK 자체는 이미 운영체제가 제공하는 దస్త్రం, 스레드, 가상 기억공간을 전제로 한다. 따라서 కెర్నల్_మూల్యం 부팅에는 OpenJDK를 그대로 넣지 않고 제한된 Java 바이트코드 AOT와 작은 런타임을 사용한다.

네이티브 계층에는 `in/out`, `hlt`, CR0/CR2/CR3/CR4, `iret`, సందర్భం_మూల్యం 저장처럼 Java로 표현할 수 없는 CPU 동작만 남긴다. 정책과 자료구조는 Java에 둔다.
