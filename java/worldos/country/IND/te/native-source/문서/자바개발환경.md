# jkoros 안에서 Java నిర్మించు_మూలం·అమలు_చేయి_ఆదేశం

이 문서의 부팅·షెల్·నిల్వ_మూల్యం 명령은 **x86 సంస్కరణ_మూల్యం** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 సంస్కరణ_మూల్యం](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 ఫైలు_పేరు_పాఠం, `edit`의 단독 `.` నిల్వ_మూల్యం, 16개 RAM దస్త్రం, 약 2초 అమలు_చేయి_ఆదేశం 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 వాస్తవ_డేటా JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. హోస్ట్ నిర్మించు_మూలం 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java అనువర్తనం_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 అమలు_చేయి_ఆదేశం

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. అమలు_చేయి_ఆదేశం 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox అమలు_చేయి_ఆదేశం మార్గదర్శక_సమాచారం_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 దస్త్రం 전체를 새 내용으로 작성한다. 기존 내용의 పంక్తి సంకలనంచేయు_మూల్యం 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 బైట్_మూల్యం 수 చూపించు_మూల్యం.
- `cat FILE`: దస్త్రం విషయం_మూల్యం చూపించు_మూల్యం. 텍스트 소스에 사용한다.
- `rm FILE`: మెమరీ_డేటా దస్త్రం 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·టైప్_చేయండి_మూల్యం 검사 వైఫల్యం_మూల్యం 시 기존 `.class`는 유지된다. 소스를 고친 వెనుకకు_మూల్యం 컴파일이 실패했다면 이전 అమలు_చేయి_ఆదేశం 파일이 남아 있으므로 నిర్మించు_మూలం 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 నిల్వ_మూల్యం 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 మూలం_వృక్షాకృతి·తరగతి_మూల్యం·డేటా 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, దస్త్రం 이름은 ASCII 1~63자다. మూలం_వృక్షాకృతి 이름은 `.class` 확장자 공간 때문에 최대 62자다. సంకలనంచేయు_మూల్యం 입력은 ASCII이고 한 పంక్తి 최대 128자다. పంక్తి 또는 దస్త్రం 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. కెర్నల్_మూల్యం/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 వినియోగదారు 예제 이름은 ASCII로 작성한다.

## 외부 దస్త్రం 적재

호스트에서 만든 소스나 మద్దతు_మూల్యం క్లిప్ 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 వాస్తవ_డేటా 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# హోస్ట్ JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 తదుపరి_అంశం 빌드에서는 추가 파일을 포함하지 않는다. దస్త్రం విషయం_మూల్యం 변경과 ప్రవేశం_జాబితా 제거도 తదుపరి_అంశం 빌드에 반영된다. 원본 హోస్ట్ 파일에는 쓰지 않는다. స్వయంసిద్ధ_విలువ `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 స్వయంసిద్ధ_విలువ 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 తరగతి_మూల్యం దస్త్రం 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 మద్దతు_మూల్యం క్లిప్ 안에 있어야 한다.

## మద్దతు_మూల్యం క్లిప్

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| తరగతి_మూల్యం | 패키지 없는 단일 తరగతి_మూల్యం, నిశ్చల_మూల్యం కార్యం_మూల్యం, 재귀, 인수/반환 | 실행마다 단일 తరగతి_మూల్యం 적재, public static main(String[]) |
| స్వయంసిద్ధ_విలువ మూల్యం | int, boolean, char, String, main의 String[] 인수 | పూర్ణాంకం·సూచన 스택, String, int[], String[], 내부 StringBuilder |
| ప్రకటన_మూల్యం | 초기값 있는 స్థానిక_పరిధి ప్రకటన, కేటాయింపు_మూల్యం, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 పూర్ణాంకం·సూచన 바이트코드와 నిబంధన శాఖ |
| సూత్రీకరణ_మూల్యం | 십진 పూర్ణాంకం, UTF-8 소스의 అక్షరసరం_మూల్యం/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, అక్షరసరం_మూల్యం 결합 | పూర్ణాంకం ఆపరేషన్_మూల్యం·బిట్_మూల్యం ఆపరేషన్_మూల్యం·టైప్_చేయండి_మూల్యం 변환, 단락 평가, శ్రేణి_మూల్యం ప్రాప్తి_ప్రవేశం |
| దస్త్రం | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | వాస్తవ_డేటా కెర్నల్_మూల్యం 파일서술자와 కనెక్టుచేయి, రూపొందించు·క్లియర్_చేయి_విషయసూచీ·이어쓰기·EOF |
| అవుట్పుట్ | System.out.print/println: int/boolean/char/String, println() | 동일 |
| అక్షరసరం_మూల్యం/인수 | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), అక్షరసరం_మూల్యం 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 స్థానిక_పరిధి ప్రకటన, 오버로드, 임의 టైప్_చేయండి_మూల్యం 변환, శ్రేణి_మూల్యం రూపొందించు వనరు, 8/16진 리터럴, Unicode మూలం_వృక్షాకృతి 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 స్థిర_మూల్యం 축소 변환을 구현하지 않는다. 외부 `.class`의 `int[]` రూపొందించు/చదువు/쓰기는 지원하므로 హోస్ట్ `javac --release 8`로 만든 శ్రేణి_మూల్యం 예제는 실행할 수 있다.

అంశం_మూల్యం ఫీల్డ్_మూల్యం·일반 అంశం_మూల్యం రూపొందించు·상속·인터페이스·여러 తరగతి_మూల్యం కనెక్టుచేయి, long/float/double, మినహాయింపు విధానం_మూల్యం_ప్రవేశం, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java మినహాయింపు 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 అక్షరసరం_మూల్యం నిల్వ_మూల్యం 공간은 అమలు_చేయి_ఆదేశం నిష్క్రమణ_అనువర్తనం 시 వినియోగదారు 영역 전체와 함께 회수한다. 지속 అమలు_చేయి_ఆదేశం 중 GC는 없다.

## అమలు_చేయి_ఆదేశం 한도와 దోషం

| వనరు_మూల్యం | 한도 |
| --- | --- |
| మూలం_వృక్షాకృతి/తరగతి_మూల్యం దస్త్రం | 각각 16KiB |
| 컴파일러 | టోకెన్_మూల్యం 2,047개, రూపొందించు కోడ్_మూల్యం 4KiB, స్థిర_మూల్యం 풀 4KiB |
| కార్యం_మూల్యం/인수 | 클래스당 32함수, 함수당 16인수 |
| JVM స్థిర_మూల్యం | 511개 |
| JVM కార్యం_మూల్యం కోడ్_మూల్యం | 함수당 8KiB |
| JVM 호출/스택/స్థానిక_పరిధి 변수 | 32프레임, 프레임당 스택 128칸·స్థానిక_పరిధి 128칸 |
| JVM అంశం_మూల్యం నిల్వ_మూల్యం 공간 | 8,192개 32비트 స్లాట్_ప్రవేశం, 헤더 포함 약 32KiB |
| అమలు_చేయి_ఆదేశం | 최대 500,000 ఆదేశము, 기존 커널의 약 3초 CPU అమలు_చేయి_ఆదేశం 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 మద్దతు_మూల్యం 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM నిఘంటువు 검증기를 구현한 것은 아니다. దస్త్రం/లక్షణం_మూల్యం పొడవు_మూల్యం, స్థిర_మూల్యం సూచన, ఆదేశము·శాఖ 경계를 검사하고, అమలు_చేయి_ఆదేశం 중 스택 ఆకృతి_మూల్యం·స్థానిక_పరిధి సంకల్పించు·శ్రేణి_మూల్యం ఉపలిపి_మూల్యం·అంశం_మూల్యం 참조를 검사한다. వినియోగదారు 코드의 페이지·포트 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, నిర్మించు_మూలం·JVM 오류는 `Exit: 1`, ఆదేశము 인수 오류는 `Exit: 2`다. CPU సమయం_మూల్యం 상한은 기존 `Exit: 124`이며, వినియోగదారు ELF 자체의 CPU/런타임 오류는 기존 నిష్క్రమణ_అనువర్తనం 코드를 따른다. వైఫల్యం_మూల్యం 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## 구현 위치와 시험

- `os/వినియోగదారు/자바/자바컴파일러.java`: 게스트 어휘·구문·టైప్_చేయండి_మూల్యం 검사, స్థిర_మూల్యం 풀 및 바이트코드 రూపొందించు.
- `os/వినియోగదారు/자바/자바가상기계.java`: తరగతి_మూల్యం 적재, 스택·프레임·అంశం_మూల్యం నిల్వ_మూల్యం, ఆదేశము 해석과 제한된 표준 호출.
- `os/వనరు/మెమరీ_ఫైల్_వ్యవస్థ.java`: మెమరీ_డేటా ఫైల్_వ్యవస్థ, సంకలనంచేయు_మూల్యం, 부팅 దస్త్రం 적재.
- `os/వనరు/체계호출.java`, `compiler/ప్రారంభం_వినియోగదారు_అనువర్తనం.s`: దస్త్రం/문자 అవుట్పుట్ API와 వినియోగదారు పాయింటర్ 검사.
- `os/ఉపకరణాలు/자바파일묶기.py`: హోస్ట్ 입력 దస్త్రం నిర్థారీకరించు·부팅 సమూహం_మూల్యం రూపొందించు.

```sh
make test-java
make test
```

`os/시험/자바시험.py`는 ELF/ISO 부팅, 게스트 నిర్మించు_మూలం·అమలు_చేయి_ఆదేశం, వినియోగదారు 입력, 재귀·반복문·పూర్ణాంకం 극값·అక్షరసరం_మూల్యం 결합·단락 평가, 재실행, మూలం_వృక్షాకృతి దోషం 후 기존 తరగతి_మూల్యం 보존, శ్రేణి_మూల్యం/수 해독 దోషం, 무한 పునరావృతం_మూల్యం 제한, సంకలనంచేయు_మూల్యం 넘침과 దస్త్రం 부족을 검사한다. 게스트 రూపొందించు 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 హోస్ట్ OpenJDK의 తరగతి_మూల్యం, పూర్ణాంకం 배열과 한글 상수를 게스트에 적재하며, 손상된 దస్త్రం 표식·버전·స్థిర_మూల్యం 수·శాఖ·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 시험 VM만 생성하고 종료한다.

구현 형식의 참고 డేటా: Oracle [JVM తరగతి_మూల్యం దస్త్రం 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM ఆదేశము 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java దస్త్రం మూ_ఫ

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 తరగతి_మూల్యం 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 వెనుకకు_మూల్యం `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. స్వయంసిద్ధ_విలువ అవుట్పుట్ 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. మినహాయింపు అంశం_మూల్యం·try/catch·try-with-resources는 지원하지 않으며 దస్త్రం 오류를 진단하고 프로그램을 종료한다. శ్రేణి_మూల్యం మూ_ఫ, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 దస్త్రం 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 షెల్ `sync`가 필요하다. 예제의 దస్త్రం 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 వాస్తవ_డేటా 게스트 నిర్మించు_మూలం 결과를 OpenJDK `-Xverify:all`로 다시 실행해 దస్త్రం 바이트와 출력을 대조한다. 범위와 నిల్వ_మూల్యం 매체 사용법은 [posix-kor మార్గదర్శక_సమాచారం_eb81d7d9](../posix-kor/మార్గదర్శక_సమాచారం_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
