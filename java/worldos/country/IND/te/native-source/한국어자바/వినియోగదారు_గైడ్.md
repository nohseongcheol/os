# jkoros 한국어 లైబ్రరీ వినియోగదారు_గైడ్

확인일: 2026-09-27. 대상은 `platforms/rpi4`의 **ARM64 Linux + OpenJDK 실행판**이며, QEMU에서도 같은 Java 라이브러리를 사용한다. `os/`의 자체 x86 కెర్నల్_మూల్యం 및 `లెగసి_మూలం/`의 관리 కెర్నల్_మూల్యం 모형과 구분한다.

## 1. 현재 제공하는 లైబ్రరీ

패키지는 `한국어.자바`, నిర్వహణా_వ్యవస్థ 안의 JAR 경로는 `/opt/jkoros/lib/한국어자바.jar`다. **도우미 తరగతి_మూల్యం 5개, 공개 నిశ్చల_మూల్యం విధానం_మూల్యం_ba7ce9bf 22개, 별도 GUI 프로그램인 కార్యస్థలం 1개**가 있다. JAR는 Java 11 이상을 대상으로 빌드하며 현재 ARM64 배포판에는 OpenJDK 25가 포함돼 있다.

표준 JDK 전체를 한국어로 번역한 라이브러리는 아니다. Java 키워드와 `String`, `Path`, `Socket`, `JFrame`, `IOException` 같은 표준 డేటా_రకం·예외를 함께 사용한다. 이 도우미에 없는 기능은 OpenJDK의 표준 API 또는 별도 라이브러리로 구현한다. 예를 들어 HTTP POST, UDP, Swing బటన్·메뉴에는 각각 표준 Java API를 사용한다.

## 2. Java에서 ప్రారంభం_విధి

게스트 운영체제의 작업 폴더에서 `사용예.java`를 작성한다.

```java
import 한국어.자바.*;
import java.nio.file.Path;

public class 사용예 {
    public static void main(String[] 인수) throws Exception {
        Path సంచయని_మూల్యం = దస్త్రం.క్రియేట్_సంచయని(దస్త్రం.పాత్("사용예자료"));
        Path 문서 = సంచయని_మూల్యం.resolve("인사.txt");
        దస్త్రం.వ్రాయుము(문서, "한글 😀");
        String విషయం_మూల్యం = దస్త్రం.చదువు(문서);
        System.out.println(విషయం_మూల్యం);
        System.out.println(문자.코드포인트수(విషయం_మూల్యం)); // 한, పాఠ్యము, 공백, 😀 → 4
        Thread పని_మూల్యం = 작업.నడుపుము("인사 작업", () -> System.out.println("작업 అమలు_చేయి_ఆదేశం"));
        작업.기다리기(పని_మూల్యం);
    }
}
```

```sh
javac -encoding UTF-8 -cp /opt/jkoros/lib/한국어자바.jar 사용예.java
java -cp .:/opt/jkoros/lib/한국어자바.jar 사용예
```

로그인 환경에 స్వయంసిద్ధ_విలువ `CLASSPATH`도 설정돼 있지만, 명시적인 `-cp`는 다른 అమలు_చేయి_ఆదేశం 환경에서도 경로를 분명하게 한다. 사용자가 `-cp`를 지정하면 필요한 JAR와 తరగతి_మూల్యం 폴더를 모두 그 값에 포함해야 한다.

హోస్ట్ 저장소에서는 다음처럼 బిల్డ్_సిస్టం·실행한다. హోస్ట్ 경로와 게스트의 `/opt/...` 경로는 서로 다르다.

```sh
cd /home/user/jkoros/한국어자바
make
javac -encoding UTF-8 -cp build/한국어자바.jar 예제/인사.java
java -cp build/한국어자바.jar:예제 인사
```

## 3. 전체 도우미 API

아래 메서드는 모두 `public static`이며, 객체를 만들지 않고 `దస్త్రం.చదువు(...)`처럼 호출한다. 표의 이름은 వాస్తవ_డేటా మూలం_వృక్షాకృతి 및 JAR의 `javap -public` 결과와 대조했다. 선언된 검사 మినహాయింపు 외에도 잘못된 인수 등에 대한 표준 Java అమలు_చేయి_ఆదేశం 시 예외가 발생할 수 있다.

### దస్త్రం: `한국어.자바.దస్త్రం`

`Path`는 `java.nio.file.Path`, `List`는 `java.util.List`다.

| విధానం_మూల్యం_ba7ce9bf | 반환형 | చర్య·నిబంధన |
|---|---|---|
| `పాత్(String పేరు)` | `Path` | 이름을 పాత్ 객체로 변환. వాస్తవ_డేటా 파일을 만들지는 않음 |
| `చదువు(Path పాత్)` | `String` | దస్త్రం 전체를 UTF-8 텍스트로 읽음 |
| `వ్రాయుము(Path పాత్, String విషయం_మూల్యం)` | `Path` | UTF-8 నిల్వ_మూల్యం. 파일이 없으면 생성하고, 있으면 기존 내용을 비움 |
| `바이트읽기(Path పాత్)` | `byte[]` | దస్త్రం 전체를 బైట్_మూల్యం 배열로 읽음 |
| `వ్రాయి_బైట్_మూల్యం(Path పాత్, byte[] విషయం_మూల్యం)` | `Path` | బైట్_మూల్యం నిల్వ_మూల్యం. 없으면 생성하고, 있으면 기존 내용을 비움 |
| `క్రియేట్_సంచయని(Path పాత్)` | `Path` | 필요한 상위 폴더까지 రూపొందించు |
| `있는가(Path పాత్)` | `boolean` | 존재 여부 సరిచూడు. 확인할 수 없는 경우도 `false`పని_మూల్యం 수 있음 |
| `తుడిచివేయి_ప్రవేశం(Path పాత్)` | `boolean` | 삭제했으면 `true`, 없으면 `false`. 폴더의 재귀 삭제는 아님 |
| `ప్రవేశం_జాబితా(Path పాత్)` | `List<Path>` | 바로 아래 항목을 పాత్ సమలేఖనం_చెయ్యి_మూల్యం 순서로 반환. 재귀 탐색은 아님 |

`పాత్`, `있는가`를 제외한 위 메서드는 `IOException`을 선언한다. `వ్రాయుము`와 `వ్రాయి_బైట్_మూల్యం`는 상위 폴더를 자동으로 만들거나 내용을 이어 쓰지 않는다. 필요한 폴더는 먼저 생성한다. 큰 파일은 전체 내용을 메모리에 담는 대신 표준 Java 스트림·ఛానల్_మూల్యం API를 사용하는 방식으로 작성할 수 있다.

### 문자: `한국어.자바.문자`

| విధానం_మూల్యం_ba7ce9bf | 반환형 | చర్య·నిబంధన |
|---|---|---|
| `부호화(String విషయం_మూల్యం)` | `byte[]` | 문자열을 UTF-8 바이트로 변환 |
| `వ్యక్తపరుచు_డేటా(byte[] విషయం_మూల్యం)` | `String` | UTF-8 바이트를 문자열로 변환. 잘못된 입력은 대체 문자로 విధానం_మూల్యం_ప్రవేశం |
| `సాధారణీకరించు_మూల్యం(String విషయం_మూల్యం)` | `String` | యూనికోడ్_మూల్యం NFC సాధారణీకరించు_మూల్యం. 예: 조합 자모 `ᄀ` + `ᅡ` → `가` |
| `코드포인트수(String విషయం_మూల్యం)` | `int` | UTF-16 కోడ్_మూల్యం 단위가 아닌 యూనికోడ్_మూల్యం కోడ్_మూల్యం 포인트 수 |
| `낱말(String విషయం_మూల్యం, Locale భాష)` | `List<String>` | కేటాయించు_మూల్యం 언어의 `BreakIterator` 낱말 경계로 나눈 구간 |

`낱말`은 공백·문장부호 구간도 반환한다. 자연어 형태소 분석기나 공백을 제거한 పదం_మూల్యం ప్రవేశం_జాబితా API는 아니다. `సాధారణీకరించు_మూల్యం`는 입력기나 అనువదించు_మూలం 기능이 아니다. కోడ్_మూల్యం 포인트 수 역시 사람이 보는 అక్షరం_మూల్యం 수와 항상 같지는 않다. 여러 కోడ్_మూల్యం 포인트로 이루어진 결합 문자·가족 이모지 등을 구분해야 한다.

### 통신: `한국어.자바.통신`

| విధానం_మూల్యం_ba7ce9bf | 반환형 | చర్య·నిబంధన |
|---|---|---|
| `가져오기(URI ఇమెయిల్, Duration సమయ_పరిమితి)` | `HttpResponse<String>` | HTTP(S) GET. కనెక్టుచేయి 및 요청 సమయ_పరిమితి అమరికలు. ప్రత్యుత్తరం_ఇవ్వు 본문을 UTF-8로 పార్స్_మూల్యం |
| `연결하기(String ఇమెయిల్, int 포트, int 제한밀리초)` | `Socket` | TCP కనెక్టుచేయి 후 같은 값으로 చదువు 제한시간도 అమరికలు |

`가져오기`는 `IOException`, `InterruptedException`을 선언한다. 제한시간은 양수다. 404·500 같은 HTTP దోషం 상태도 응답으로 반환하므로 `statusCode()`로 판단하고 `body()`로 본문을 읽는다. 현재 구현은 호출마다 HTTP 클라이언트를 만들며 자동 리다이렉트 설정을 추가하지 않는다.

`연결하기`는 `IOException`을 선언한다. 연결된 소켓은 호출자가 `close()` 또는 try-with-resources로 닫아야 한다. 제한밀리초의 0은 제한 없음이며, వ్రాయుము 전체의 마감 시간을 보장하는 옵션은 아니다.

```java
var ప్రత్యుత్తరం_ఇవ్వు = 통신.가져오기(
    java.net.URI.create("http://127.0.0.1:8000/"),
    java.time.Duration.ofSeconds(5));
System.out.println(ప్రత్యుత్తరం_ఇవ్వు.statusCode());
System.out.println(ప్రత్యుత్తరం_ఇవ్వు.body());
```

위 조각은 విధానం_మూల్యం_ba7ce9bf 안에서 실행하며 별도로 해당 주소의 서버를 실행해야 한다. Java మినహాయింపు 처리가 필요하다.

### 작업: `한국어.자바.작업`

| విధానం_మూల్యం_ba7ce9bf | 반환형 | చర్య·నిబంధన |
|---|---|---|
| `నడుపుము(String పేరు, Runnable చర్య)` | `Thread` | 이름을 지정한 스레드를 만들고 즉시 నడుపుము |
| `기다리기(Thread థ్రెడ్_మూల్యం)` | `void` | 해당 스레드가 종료할 때까지 `join()` |
| `쉬기(long 밀리초)` | `void` | 호출한 스레드를 కేటాయించు_మూల్యం సమయం_మూల్యం 동안 `sleep()` |
| `작업대(int 가닥수)` | `ExecutorService` | 고정 పరిమాణం 작업 అనువర్తనం_లాంచర్ రూపొందించు. 가닥수는 양수 |

`기다리기`, `쉬기`는 `InterruptedException`을 선언한다. 작업 실행기는 사용 후 `shutdown()`으로 종료하고 필요하면 `awaitTermination(...)`으로 완료를 기다린다. Swing 이벤트 విధానం_మూల్యం_ప్రవేశం 가닥에서 긴 작업이나 `기다리기`를 실행하면 화면이 멈출 수 있다.

### 화면: `한국어.자바.화면`

| విధానం_మూల్యం_ba7ce9bf | 반환형 | చర్య·నిబంధన |
|---|---|---|
| `나중에(Runnable చర్య)` | `void` | Swing 이벤트 విధానం_మూల్యం_ప్రవేశం 가닥에 실행을 예약하고 반환 |
| `విండో(String గవాక్షం_శీర్షిక, JComponent విషయం_మూల్యం, int 너비, int 높이)` | `JFrame` | విషయం_మూల్యం·크기를 지정한 창을 생성해 చూపించు_మూల్యం |

`విండో`을 Swing 이벤트 విధానం_మూల్యం_ప్రవేశం థ్రెడ్_మూల్యం 밖에서 부르면 `IllegalStateException`이 발생한다. 그래픽 세션도 필요하다. QEMU에서는 VNC 데스크톱의 터미널에서 실행한다.

```java
화면.나중에(() -> 화면.విండో(
    "한국어 화면", new javax.swing.JLabel("안녕하세요"), 500, 180));
```

반환된 `JFrame`에 표준 Swing API를 추가로 사용할 수 있다. 창의 మూసివేయి 동작은 `DISPOSE_ON_CLOSE`다. `화면.나중에`가 반환됐다고 విండో 생성이 이미 끝난 것은 아니다.

### కార్యస్థలం: సంకలనంచేయు_మూల్యం·నిర్మించు_మూలం GUI

```sh
java -cp /opt/jkoros/lib/한국어자바.jar 한국어.자바.కార్యస్థలం
```

`~/workspace`의 원문을 తెరువు·저장하고, `javac`로 컴파일해 `java`로 실행한다. అమలు_చేయి_ఆదేశం దస్త్రం 만들기는 `jclassc --target openjdk` 경로를 사용한다. 작업마당은 개발용 프로그램이며 별도의 దస్త్రం·문자 API 클래스가 아니다. 생성하는 అమలు_చేయి_ఆదేశం దస్త్రం 방식은 [컴파일러 설명](../compiler/OpenJDK-실행파일.md)을 따른다.

## 4. Python과 C++에서 사용할 수 있는가?

| విధానం_మోడ్_3f5e5497 | 현재 포함 స్థితి_మూల్యం | 호출 가능 క్లిప్ |
|---|---|---|
| Java → 한국어 JAR | స్వయంసిద్ధ_విలువ 포함 | 위 22개 메서드와 కార్యస్థలం |
| Python → `java` ఉపాంశం_మూల్యం 프로세스 | Python·Java స్వయంసిద్ధ_విలువ 포함 | 작은 Java 진입점을 통해 호출하고 표준 అవుట్పుట్·దస్త్రం 등으로 ప్రమాణం ఫార్వార్డ్_మూల్యం |
| Python → JPype → JVM | JPype는 స్వయంసిద్ధ_విలువ 배포에 없음 | 별도 వ్యవస్థాపించు_మూల్యం 후 Java తరగతి_మూల్యం·విధానం_మూల్యం_ba7ce9bf 호출 가능. 이 배포판의 ARM64/musl/Python 3.14 조합은 추가 నిర్థారీకరించు 필요 |
| C++ → JNI → JVM | `g++`, JNI 헤더, `libjvm.so` 포함 | JVM을 생성하고 한국어 తరగతి_మూల్యం·메서드를 직접 호출할 수 있음 |
| Python용 독립 한국어 లైబ్రరీ | 현재 స్వయంసిద్ధ_విలువ 제공 없음 | 필요하면 Python 표준 라이브러리를 감싸는 한국어 모듈을 별도로 작성 |
| C/C++용 독립 한국어 లైబ్రరీ | 자체 x86 `posix-kor`와 자체 ARM64 커널용 초기 RAM దస్త్రం 연결이 별도로 존재 | 둘 다 이 Linux/OpenJDK 실행판의 libc 라이브러리는 아님 |

Python의 일반 `import`나 `ctypes.CDLL`로 JAR를 바로 읽을 수는 없다. C++의 `#include`나 일반 네이티브 링커만으로 Java 메서드를 연결할 수도 없다. JVM 프로세스 또는 JVM కనెక్టుచేయి 계층을 거쳐야 한다.

### Python: 추가 패키지 없이 호출

అమలు_చేయి_ఆదేశం 가능한 예제 원문은 [문자명령.java](예제/다른언어/문자명령.java), [파이썬호출.py](예제/다른언어/파이썬호출.py)다. Python이 Java 진입점을 실행하고 `문자.코드포인트수`의 పూర్ణాంకం 결과를 받는다. 인수 목록을 사용하며 షెల్ ఆదేశము 문자열을 조립하지 않는다. `subprocess.run`의 프로세스 అమలు_చేయి_ఆదేశం·నిష్క్రమణ_అనువర్తనం కోడ్_మూల్యం·అవుట్పుట్ విధానం_మూల్యం_ప్రవేశం 방식은 [Python 공식 문서](https://docs.python.org/3/library/subprocess.html)를 따른다.

두 예제 파일을 게스트의 같은 폴더에 복사한 వెనుకకు_మూల్యం 그 폴더에서 실행한다. 예제 దస్త్రం 자체는 స్వయంసిద్ధ_విలువ 시스템 이미지에 자동 설치돼 있지 않다.

```sh
mkdir -p classes
javac -encoding UTF-8 -cp /opt/jkoros/lib/한국어자바.jar -d classes 문자명령.java
python3 파이썬호출.py --text '한글 😀'
```

అవుట్పుట్: `Python → 한국어.자바.문자.코드포인트수: 4`

이 예제의 Python కార్యం_మూల్యం `코드포인트수`는 이번 문서의 కనెక్టుచేయి 예제이며 기존에 설치된 Python 라이브러리는 아니다. 현재 예제는 호출할 때마다 JVM 프로세스를 시작한다. Java అంశం_మూల్యం 자체를 Python으로 가져오는 방식은 아니며, 다른 메서드를 사용하려면 진입점의 인수·ప్రమాణం 형식을 확장한다.

### Python: JPype로 같은 프로세스에서 호출

JPype를 별도 설치한 환경에서는 తదుపరి_అంశం 형태로 연결할 수 있다. **아래는 ఎంపిక_మూల్యం 가능한 కనెక్టుచేయి 방법이며, 현재 배포판에 JPype가 설치돼 있거나 అమలు_చేయి_ఆదేశం 검증됐다는 뜻은 아니다.** JVM 시작과 `JClass`를 통한 తరగతి_మూల్యం 접근은 [JPype 공식 설명](https://jpype.readthedocs.io/en/latest/userguide.html)을 참고한다.

```python
import jpype

jpype.startJVM(
    "/usr/lib/jvm/java-25-openjdk/lib/server/libjvm.so",
    classpath=["/opt/jkoros/lib/한국어자바.jar"])
try:
    문자 = jpype.JClass("한국어.자바.문자")
    print(문자.코드포인트수(jpype.JString("한글 😀")))
finally:
    jpype.shutdownJVM()
```

Python·JVM·కనెక్టుచేయి 모듈의 CPU 아키텍처가 맞아야 한다. 이 실행판은 ARM64 + musl이므로 일반 x86_64/glibc용 바이너리를 그대로 설치하는 방식은 맞지 않는다. JPype వ్యవస్థాపించు_మూల్యం·패키지 빌드는 이번 문서 작업에서 수행하지 않았다.

### C++: JNI로 직접 호출

[자바호출.cpp](예제/다른언어/자바호출.cpp)는 వాస్తవ_డేటా అమలు_చేయి_ఆదేశం 가능한 예제다. JVM을 작업 스레드에서 생성하고 తదుపరి_అంశం 메서드를 찾는다.

```cpp
jclass type = env->FindClass("한국어/자바/문자");
jmethodID method = env->GetStaticMethodID(
    type, "코드포인트수", "(Ljava/lang/String;)I");
```

JVM రూపొందించు·종료와 스레드 연결은 [JNI Invocation API](https://docs.oracle.com/en/java/javase/25/docs/specs/jni/invocation.html)의 방식이다. `JNIEnv*`는 రూపొందించు·연결된 스레드에서 사용해야 한다. 예제는 Java 예외를 확인하고 JVM 종료까지 처리한다.

게스트에 `자바호출.cpp`를 복사한 వెనుకకు_మూల్యం 컴파일한다. 로그인 환경의 `JAVA_HOME`은 `/usr/lib/jvm/java-25-openjdk`다.

```sh
g++ -std=c++11 -Wall -Wextra -pthread \
  -I"$JAVA_HOME/include" -I"$JAVA_HOME/include/linux" \
  자바호출.cpp -L"$JAVA_HOME/lib/server" \
  -Wl,-rpath,"$JAVA_HOME/lib/server" -ljvm -o 자바호출
./자바호출 /opt/jkoros/lib/한국어자바.jar
```

అవుట్పుట్: `C++ → 한국어.자바.문자.코드포인트수: 4`

예제는 `한글 😀`을 UTF-16으로 만들어 `NewString`에 전달한다. `NewStringUTF`가 받는 modified UTF-8은 일반 UTF-8과 차이가 있으므로, 일반 UTF-8 이모지 바이트를 그대로 넘기는 예제로 작성하지 않았다. [JNI అక్షరసరం_మూల్యం ఆకృతి_మూల్యం](https://docs.oracle.com/en/java/javase/25/docs/specs/jni/types.html#modified-utf-8-strings)

다른 한국어 메서드도 JNI 서명과 인수 자료형을 맞춰 호출할 수 있다. 예를 들어 `Path`를 받는 దస్త్రం API는 먼저 `దస్త్రం.పాత్`로 Java పాత్ 객체를 얻어 전달한다. Swing 호출에는 그래픽 세션과 이벤트 విధానం_మూల్యం_ప్రవేశం థ్రెడ్_మూల్యం 규칙도 그대로 적용된다. JNI는 Java 실행을 기계어로 대체하는 기능이 아니며 JVM이 계속 필요하다.

### 기존 posix-kor와의 관계

추가된 [자체 ARM64 కనెక్టుచేయి](../posix-kor/arm64-native/మార్గదర్శక_సమాచారం_eb81d7d9.md)은 C++에서 AOT Java 커널의 RAM దస్త్రం API를 직접 호출하며, 별도 EL0 వినియోగదారు 라이브러리로 దస్త్రం/UDP 루프백 SVC 호출도 제공한다. JNI를 사용하지 않는다. 이 문서의 ARM64 **Linux** 및 한국어 Java JAR와는 다른 అమలు_చేయి_ఆదేశం 기반이며 자체 커널은 별도 제한형 Java 컴파일러/JVM과 MicroPython 1.24.1을 실행한다. MicroPython의 `import jkoros`로 Java కెర్నల్_మూల్యం దస్త్రం·UDP 루프백·사각형 호출이 가능하지만 이 문서의 JAR를 가져오는 기능은 아니다. 자체 커널의 전체 OpenJDK/JRE/CPython 이식은 아직 미완성이다.

[posix-kor](../posix-kor/మార్గదర్శక_సమాచారం_eb81d7d9.md)에는 `తెరువు_ఫైలు`, `파일자료읽기`, `వ్రాయి_ఫైలు_డేటా`, `మూసివేయి_ఫైలు`, `통신종단점만들기`, `자료전문보내기` 등의 한국어 C 별칭이 있다. 그러나 구현은 **자체 jkoros i386 커널의 `int 0x80` 호출 규약용**이다.

이 `libposix-kor.a`와 자체 `sys/stat.h` 등의 헤더는 현재 ARM64 Linux 실행판의 libc/C++용 라이브러리가 아니다. 해당 헤더·바이너리를 ARM64 Linux 프로그램에 그대로 연결해서는 ABI가 맞지 않는다. C++용 한국어 తరగతి_మూల్యం 라이브러리나 Python용 바인딩을 స్వయంసిద్ధ_విలువ 제공하는 상태도 아니다. 현재 Linux 실행판에서 그와 같은 독립 API를 제공하려면 Linux 표준 라이브러리를 대상으로 별도로 구현·빌드해야 한다.

## 5. సరిచూడు 범위와 재현

패키지 포함 여부는 [배포 패키지 ప్రవేశం_జాబితా](../platforms/rpi4/dist/packages.lock.json) 및 బిల్డ్_సిస్టం 루트의 వాస్తవ_డేటా 파일로 확인했다. JNI 헤더는 JDK의 `include/jni.h`, `include/linux/jni_md.h`, JVM 라이브러리는 `lib/server/libjvm.so`에 있다. 사용자가 이후 별도로 설치한 패키지는 이 స్వయంసిద్ధ_విలువ 배포 목록과 다를 수 있다.

이번에 **హోస్ట్ x86_64/OpenJDK 11에서** Python ఉపాంశం_మూల్యం 프로세스 호출과 C++ JNI 직접 호출을 నిర్మించు_మూలం·실행해 각각 ప్రమాణం 4를 확인했다. JAR 공개 메서드도 소스와 대조했다. Python కనెక్టుచేయి 예제는 추가 패키지를 설치하지 않는다.

문서의 Java 사용 예제도 నిర్మించు_మూలం·실행했고, 22개 메서드의 문서 포함 여부와 로컬 문서 링크를 확인했다. [예제 నిర్థారీకరించు లాగ్_వరుస](build/다른언어/నిర్ధారణ_నివేదిక.json)

기존 ARM64 QEMU에서는 Java의 దస్త్రం·యూనికోడ్_మూల్యం·스레드·HTTP 및 Swing 시험 결과가 있다. 이번 Python/C++ కనెక్టుచేయి 예제의 **ARM64 게스트 실행과 JPype 설치는 별도 검증하지 않았다.** 이미지와 అమలు_చేయి_ఆదేశం 중인 వినియోగదారు 환경은 이 문서 작업에서 변경하지 않았다. [기존 నిర్వహణా_వ్యవస్థ నిర్థారీకరించు లాగ్_వరుస](../platforms/rpi4/VERIFICATION.md)

호스트에서 Python 예제를 재현하려면:

```sh
cd /home/user/jkoros/한국어자바
make
mkdir -p build/다른언어
javac -encoding UTF-8 --release 11 -cp build/한국어자바.jar \
  -d build/다른언어 예제/다른언어/문자명령.java
python3 예제/다른언어/파이썬호출.py \
  --jar build/한국어자바.jar --classes build/다른언어
```

హోస్ట్ C++ 예제는 위 JNI నిర్మించు_మూలం 명령의 JDK 경로를 **హోస్ట్ JDK పాత్**로 바꾸고, వనరు `예제/다른언어/자바호출.cpp`와 JAR `build/한국어자바.jar`를 지정한다. ARM64 게스트 JDK의 헤더·లైబ్రరీ 경로를 హోస్ట్ x86_64 링크 명령에 섞지 않는다.
