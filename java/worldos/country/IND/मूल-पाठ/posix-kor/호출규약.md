# उपयोगकर्ता 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `यंत्र/ऑपरेटिंग_सिस्टम_कॉल्स.s`에서 EAX(इंडेक्स), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 तर्क)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. कर्नेल_मान 실패는 음수 त्रुटि इंडेक्स, C लाइब्रेरी 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 उपयोगकर्ता क्षेत्र_मान 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C आँकड़े 주소는 बाइट_मान 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java संचिका 흐름의 어셈블리 경계가 별도 बाइट_मान 버퍼를 마련하여 같은 호출을 사용한다.

| इंडेक्स | क्रिया | तर्क |
|---|---|---|
| 30 | जारी_फ़ाइल | NUL 끝 नाम पता, विन्यास, 허가 |
| 31 | पढें_फ़ाइल_डेटा | 서술자, आँकड़े पता, बाइट_मान 수 |
| 32 | लिखना_फ़ाइल_डेटा | 서술자, आँकड़े पता, बाइट_मान 수 |
| 33 | बंद_फ़ाइल | 서술자 |
| 34 | खोजें_फ़ाइल | 서술자, एन्कोडिंग_मान 있는 ऑफ़सेट_मान, प्रोजेक्ट_करें_मूल |
| 35 | 파일서술자복제 | 서술자 |
| 36 | 파일서술자지정복제 | 서술자, 새 서술자 |

| 38 | निकालें_फ़ाइल_एन्ट्री_नाम | NUL 끝 नाम पता |
| 39 | 파일길이정하기 | 서술자, 새 길이 |

| 44 | 자료전문받기 | 서술자, आँकड़े पता, 길이, विन्यास, अनुरोध पता |
| 45 | पढें_सॉकेट_पता | 서술자, sockaddr पता, socklen_t पता |
| 46 | 수신대기정하기 | 서술자, 0~2000 밀리초 |
| 47 | कमिट_फ़ाइल_संग्रहण | 서술자 |

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 पता 두 칸이다. 수신 주소가 NULL이면 पीअर_मान पता 기록을 생략한다. sockaddr_in은 16바이트이며 पता 체계는 उपकरण_मान बाइट_मान 차례, 접속번호와 IP 주소는 네트워크 बाइट_मान 차례다. 축소된 पता 버퍼에도 들어가는 앞부분을 쓰고 전체 पता आकार 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 निर्गमन_ऐप, 2·3은 기존 तर्क 조회다. अद्यतित_आइटम 커널의 तर्क 목록이 निष्पादित_करें_आदेश 이름을 제외하므로 C 진입기는 argv[0]에 고정 स्ट्रिंग_मान `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX प्रक्रिया_मान ABI와 다른 점이다.

표준 헤더의 पूर्णांक आकार, 플래그 मान, stat फ़ील्ड_मान 순서는 `स्रोत/포함/`에 정의한다. 동적 जोड़ना·다중 प्रक्रिया_मान·스레드가 추가되면 त्रुटि इंडेक्स 저장과 संसाधन_मान 수명, 호출 경계도 함께 검토해야 한다.
