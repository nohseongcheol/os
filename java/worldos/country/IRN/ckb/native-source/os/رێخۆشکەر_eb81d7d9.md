# Java 네이티브 سیستەمی_کارپێکردن

이 문서는 기존 **x86 کوورەک_نرخ**을 설명한다. Raspberry Pi 4의 자체 ARM64 초기 이식은 [별도 رێخۆشکەر_eb81d7d9](../platforms/rpi4-native/README.md)를 참고한다. 아래 x86 بەکارهێنەر ELF·네트워크·IDE Store_نرخ 기능이 ARM64에 모두 이식된 상태는 아니다.

Java 원문을 자체 AOT 후단으로 x86 기계어로 컴파일해 부팅하는 작은 운영체제다. 커널과 별도로 자체 제한형 Java 컴파일러·JVM ELF를 بەکارهێنەر 모드에 적재할 수 있다. Linux, engos, koros4와 외부 OpenJDK는 게스트에 적재하지 않는다. 부팅 진입과 포트/물리 기억공간 접근은 어셈블리이며, 문자 단말·입력 پرۆسە_نرخ_تێنووسین·فەرمان 해석·작업 بەش_نرخ 관리는 `ژێدەر/*.java`에 있다.

## 게스트 Java 개발

`javac Hello.java`, `java Hello`로 부팅된 سیستەمی_کارپێکردن 안에서 دروست_کردن_ژێدەر·실행한다. `edit FILE.java`와 `.save`로 소스를 작성하며 `ls`, `cat`, `rm`을 제공한다. RAM 파일은 최대 8개, 각각 16KiB이다. 전용 IDE 매체를 연결하면 `sync`로 보존할 수 있다. 이 기능은 자체 제한형 구현이며 전체 OpenJDK/JDK 호환은 아니다. 사용법·پشتیوانی_نرخ 문법·فایل 적재·교차 시험은 [Java 개발 환경](../문서/자바개발환경.md)에 있다. `make test-java`로 검증한다.

## 빌드와 جێبەجێکردن_فەرمان

`compiler/`가 요구하는 도구에 더해 ISO 생성에는 `grub-file`, `grub-mkrescue`, GRUB BIOS 모듈, `xorriso`가 필요하다. 실행에는 QEMU 또는 VirtualBox가 필요하다. 현재 설치된 도구만 사용한다. `make run-store`는 새 전용 가상 Store_نرخ 매체를 만들어 연결한다. VirtualBox 실행기는 이 프로젝트가 만든 전용 VM만 설정하고 다른 VM은 변경하지 않는다. 가상 메모리는 بەهای_گریمانە 64MiB이며 최소 16MiB가 필요하다.

```sh
cd /home/user/jkoros/os
make                 # build/kernel.elf
make iso             # build/kernel.iso (بەکارهێنەر ELF گروپ_نرخ 포함)
make run             # ELF 직접 부팅, 직렬 단말
make run-gui         # GRUB ISO 부팅, VGA 창과 PS/2 자판
make vbox            # 상위 폴더의 실행기로 전용 VirtualBox VM جێبەجێکردن_فەرمان
make vbox-status     # 전용 VirtualBox VM دۆخ_نرخ سەلماندن
make test            # ELF와 ISO 두 경로의 ڕاستەکی_دەیتا 부팅/입력 시험
make apps            # بەکارهێنەر 프로그램만 دروستکراو_سیستم
make test-network    # بەکارهێنەر جێبەجێکردن_فەرمان/UDP/پاراستن_نرخ 시험
```

`make run`은 QEMU의 직렬 표준 입출력을 쓴다. `Ctrl+A`를 누른 دواوە_نرخ `X`로 QEMU를 종료할 수 있다. `halt`는 게스트 CPU만 정지시키므로 QEMU پەنجەرە/프로세스는 별도로 닫는다. 폴링 방식이라 چاوەڕوان_کردن_نرخ 중에도 جێدەر CPU를 사용할 수 있다.

VirtualBox는 `make vbox`로 실행한다. 새 전용 VM을 بیرگە_دەیتا 64MiB, BIOS, 광학 드라이브 부팅으로 자동 설정하며 디스크는 필요 없다. ڕاستەکی_دەیتا VirtualBox 5.2.42에서 부팅, Java 자체 시험, توێکڵ 입력, `run hello vbox`의 ring 3 실행과 정상 종료를 확인했다. 현재 통신 드라이버는 QEMU의 RTL8139 전용이며 VirtualBox의 PCnet/E1000에서는 네트워크를 사용할 수 없어 네트워크 장치를 비활성화한다. Store_نرخ دۆخ_نرخ 재개와 새 دروستکراو_سیستم 반영 방법은 [VirtualBox جێبەجێکردن_فەرمان رێخۆشکەر_eb81d7d9](../문서/가상상자실행.md)에 있다.

## 셸에서 بەکارهێنەر بەرنامە_f5044b9b جێبەجێکردن_فەرمان 및 네트워크 호출

독립 ELF32 جێبەجێکردن_فەرمان 파일을 적재해 **ring 3**에서 실행한다. `int 0x80` 시스템 호출을 통해 단말 출력, 인수 پرس_نرخ, UDP کردنەوە·ناردن·받기·닫기를 제공한다. بەکارهێنەر 코드를 کوورەک_نرخ 함수로 직접 호출하는 구조가 아니다.

```text
jkoros> apps
jkoros> run hello first second
jkoros> net
jkoros> run netcheck
jkoros> run udp 10.0.2.2 9000 hello
```

마지막 명령의 응답을 받으려면 호스트의 별도 터미널에서 `python3 /home/user/jkoros/os/ئامرازەکان/자료되돌리기.py --port 9000`을 먼저 실행한다. 상세 API, بەرنامە_f5044b9b 추가, ناونیشان 공간과 제한은 [بەکارهێنەر جێبەجێکردن_فەرمان·네트워크 رێخۆشکەر_eb81d7d9](بەکارهێنەر/رێخۆشکەر_eb81d7d9.md)에 있다.

부팅 سەلماندن 문구:

```text
JKOROS NATIVE JAVA
자바 기계어 کوورەک_نرخ ڕادان
JAVA SELFTEST PASS
USER ELF: ring 3 / paging / int 0x80
help | info | mem | alloc | free N | echo TEXT | clear | test | halt
apps | run NAME [ARGS] | net
READY
jkoros>
```

## 구현한 기능

- GRUB Multiboot 1 ELF 부팅, x86 پاراستن_نرخ دۆخ_نرخ_a83655ea GDT, BSS ئامادە_کردن, 64KiB 스택.
- Java کردار_نرخ ڕاستەکی_دەیتا 실행과 부팅 msinfo32_exe 표식 سەلماندن.
- COM1 직렬 I_O, VGA 문자 화면·جێنیشاندەر_نرخ·스크롤·지우기.
- PS/2 بەهای_گریمانە 자판, 좌우 Shift, Enter, Backspace. پاشبەند_نرخ کلیل_نرخ/마우스 자료는 فەرمان 입력으로 쓰지 않는다.
- درێژی_نرخ 128의 فەرمان 입력 버퍼, لێوڕێژ_نرخ 방지, CR/LF پرۆسە_نرخ_تێنووسین.
- `help`, `info`, `mem`, `alloc`, `free N`, `echo TEXT`, `clear`, `test`, `halt`.
- 4KiB 작업 بەش_نرخ 8개의 تەرخانکردن_هەمارگە·반환·재사용과 중복 반환 방지.
- Java ڕیزی_داتا_نرخ 256KiB 영역의 گۆڕینی_ئەندازە·ژێرنەسک_نرخ 검사와 런타임 هەڵە 중단.
- 읽기 전용 JKAP جێبەجێکردن_فەرمان گروپ_نرخ, ELF32 بەش_نرخ/تێنووسین_خاڵ ڕەوایی, بەکارهێنەر دۆخ_نرخ_a83655ea·인수·بزربوون_بەرنامە 코드.
- کوورەک_نرخ/بەکارهێنەر 페이지 ڕێپێدان_نرخ 분리, TSS, IDT, PIT 100Hz, بەکارهێنەر CPU 예외 پرۆسە_نرخ_تێنووسین 및 جێبەجێکردن_فەرمان کات_نرخ 상한.
- PCI RTL8139 폴링 드라이버, ARP, ستاتیک_نرخ IPv4, UDP 검사합·송수신·چاوەڕوان_کردن_نرخ 제한.

`mem`의 Upper memory는 Multiboot의 1MiB 위쪽 연속 بیرگە_دەیتا گۆڕینی_ئەندازە(KiB)이며, 전체 بیرگە_دەیتا 지도 분석이나 자유 물리 بیرگە_دەیتا 수치가 아니다. `alloc`은 이미 확보한 ژمارەی_سروشتی ڕیزی_داتا_نرخ 안의 작업 بەش_نرخ 번호를 반환한다. 일반 물리 لاپەڕە_نرخ تەرخانکردن_هەمارگە, ناونیشان 공간 또는 بەکارهێنەر پرۆسە_نرخ بیرگە_دەیتا 관리가 아니다.

## 명시적인 한계

이 커널은 **بەکارهێنەر 프로그램을 한 번에 하나 실행하는 초기 کوورەک_نرخ**이다. PIT IRQ0만 사용하며 키보드와 NIC는 폴링한다. بەکارهێنەر CPU 예외는 해당 프로그램을 끝내고 셸로 복귀시키지만 کوورەک_نرخ 예외는 중단한다. جێبەجێکردن_فەرمان 시간은 약 3초로 제한한다. 완전한 선점 다중 پرۆسە_نرخ 스케줄러, FAT/ext 등 일반 디스크 سیستمی_فایل, TCP·DNS·DHCP·IPv6·HTTP, 전체 POSIX, 일반 شت_نرخ 모델/GC는 아직 없다. 전용 IDE فایل 보존과 POSIX فایل/UDP 일부 기능은 구현했다. JVM은 RAM 파일의 단일 클래스를 جێبەجێکردن_فەرمان 시 적재하며 일반 ClassLoader나 JAR 로딩은 지원하지 않는다. 네이티브 جێبەجێکردن_فەرمان 파일은 دروستکراو_سیستم 시 읽기 전용 묶음에 넣으며, 일반 Linux ELF를 실행하는 환경이 아니다. 기존 `../جێماو_ژێدەر/`의 JVM 관리 کوورەک_نرخ 전체를 이식한 것도 아니다.

Java 식별자는 한국어다. 직렬 출력은 이 프로젝트의 한글(BMP 문자)을 UTF-8로 표시한다. VGA는 بەهای_گریمانە ASCII 글꼴만 사용하므로 한글 자리에 `?`가 나온다. فەرمان 입력도 현재 ASCII만 지원하며 한글 جۆرەپیت_نرخ·입력기 및 보조 평면 문자 출력은 후속 작업이다. `test`는 작은 배열을 새로 할당하고 GC가 없으므로 무한 반복하지 않는다.

## 자동 시험

`시험/부팅시험.py`는 디스크 없는 독립 QEMU를 생성해 다음을 검증하고 종료한다.

- ELF 직접 부팅 및 GRUB ISO 부팅.
- Java 자체 시험과 UTF-8 직렬 문구.
- فەرمان نیشاندان_ڕێنوێنی·msinfo32_exe·بیرگە_دەیتا·출력·هەڵە 입력·화면 지우기.
- 작업 بەش_نرخ 8개 تەرخانکردن_هەمارگە, 부족 پرۆسە_نرخ_تێنووسین, 반환/중복 반환/재할당.
- 직렬 줄바꿈·백스페이스·긴 입력 پرۆسە_نرخ_تێنووسین.
- QEMU PS/2 کلیل_نرخ 입력으로 `info` جێبەجێکردن_فەرمان, `halt` 정지.

성공 로그는 `build/부팅시험.json`에 남는다. 로컬 Unix 소켓을 금지하는 샌드박스에서는 시험 도구에 해당 권한이 필요하다. 시험 도중 새로 만든 QEMU만 종료하며 기존 VM과 ڕاستەکی_دەیتا 디스크는 건드리지 않는다.

`시험/사용자통신시험.py`는 ELF/ISO 각각에서 بەکارهێنەر ELF, ڕاستەکی_دەیتا ring 3, 인수, جێدەر 루프백 UDP 왕복, 1,023/1,024바이트 24회 연속 왕복, کات_نرخ 초과, NIC 없음, بیرگە_دەیتا/포트 دەسگەیشتن_تێنووسین 차단, CPU 예외, 무한 دووبارەکردنەوە_نرخ, 잘못된 ELF를 시험한다. `build/사용자통신시험.json`에 게스트 기록과 호스트가 받은 데이터의 درێژی_نرخ·해시를 저장한다. `시험/패킷시험.py`는 ڕاستەکی_دەیتا Java ئەرک_نرخ 처리기에 손상된 패킷을 넣어 2,201개 경계/검사합 조건을 검사한다. جێدەر 루프백 외 외부 서버에는 시험 트래픽을 보내지 않는다.

부트 경계는 GNU의 [Multiboot 명세](https://www.gnu.org/software/grub/manual/multiboot/multiboot.html)를 따른다.

새 파일서술자·C ABI·IDE Store_نرخ·Java فایل 흐름의 범위와 한국어 명명 대응은 [posix-kor رێخۆشکەر_eb81d7d9](../posix-kor/رێخۆشکەر_eb81d7d9.md)에 있다. `make test-posix`로 ELF/ISO 실행과 재부팅 보존을 검증한다.
