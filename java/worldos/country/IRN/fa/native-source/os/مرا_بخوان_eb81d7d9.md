# Java 네이티브 سیستم_عامل

이 문서는 기존 **x86 هسته_مقدار**을 설명한다. Raspberry Pi 4의 بومی ARM64 초기 이식은 [별도 مرا_بخوان_eb81d7d9](../platforms/rpi4-native/README.md)를 참고한다. 아래 x86 کاربر ELF·네트워크·IDE ذخیره_مقدار 기능이 ARM64에 모두 이식된 상태는 아니다.

Java 원문을 بومی AOT 후단으로 x86 기계어로 컴파일해 부팅하는 작은 운영체제다. 커널과 별도로 بومی 제한형 Java 컴파일러·JVM ELF를 کاربر 모드에 적재할 수 있다. Linux, engos, koros4와 외부 OpenJDK는 게스트에 적재하지 않는다. 부팅 진입과 포트/물리 기억공간 접근은 어셈블리이며, 문자 단말·입력 فرآیند_مقدار_ورودی·فرمان تفسیر_مقدار·작업 قسمت_مقدار 관리는 `مبداء/*.java`에 있다.

## 게스트 Java 개발

`javac Hello.java`, `java Hello`로 부팅된 سیستم_عامل 안에서 ساختن_منبع·실행한다. `edit FILE.java`와 `.save`로 소스를 작성하며 `ls`, `cat`, `rm`을 제공한다. RAM 파일은 최대 8개, 각각 16KiB이다. 전용 IDE 매체를 연결하면 `sync`로 보존할 수 있다. 이 기능은 بومی 제한형 구현이며 전체 OpenJDK/JDK 호환은 아니다. 사용법·پشتیبان_مقدار 문법·پرونده 적재·교차 시험은 [Java 개발 환경](../문서/자바개발환경.md)에 있다. `make test-java`로 검증한다.

## 빌드와 اجرا_فرمان

`compiler/`가 요구하는 도구에 더해 ISO 생성에는 `grub-file`, `grub-mkrescue`, GRUB BIOS مدول_مقدار, `xorriso`가 필요하다. 실행에는 QEMU 또는 VirtualBox가 필요하다. 현재 설치된 도구만 사용한다. `make run-store`는 새 전용 가상 ذخیره_مقدار 매체를 만들어 연결한다. VirtualBox 실행기는 이 프로젝트가 만든 전용 VM만 설정하고 다른 VM은 변경하지 않는다. 가상 메모리는 مقدار_پیش_فرض 64MiB이며 최소 16MiB가 필요하다.

```sh
cd /home/user/jkoros/os
make                 # build/kernel.elf
make iso             # build/kernel.iso (کاربر ELF گروه_مقدار 포함)
make run             # ELF 직접 부팅, 직렬 단말
make run-gui         # GRUB ISO 부팅, VGA 창과 PS/2 자판
make vbox            # 상위 폴더의 실행기로 전용 VirtualBox VM اجرا_فرمان
make vbox-status     # 전용 VirtualBox VM وضعیت_مقدار تأیید_صحت
make test            # ELF와 ISO 두 경로의 واقعی_داده_ها 부팅/입력 시험
make apps            # کاربر 프로그램만 ساخت_سیستم
make test-network    # کاربر اجرا_فرمان/UDP/حفاظت_کردن_مقدار 시험
```

`make run`은 QEMU의 직렬 표준 입출력을 쓴다. `Ctrl+A`를 누른 برگشت_مقدار `X`로 QEMU를 종료할 수 있다. `halt`는 게스트 CPU만 정지시키므로 QEMU پنجره/프로세스는 별도로 닫는다. 폴링 방식이라 منتظر_ماندن_مقدار 중에도 میزبان CPU를 사용할 수 있다.

VirtualBox는 `make vbox`로 실행한다. 새 전용 VM을 حافظه_داده_ها 64MiB, BIOS, 광학 드라이브 부팅으로 자동 설정하며 디스크는 필요 없다. واقعی_داده_ها VirtualBox 5.2.42에서 부팅, Java بومی 시험, واسط 입력, `run hello vbox`의 ring 3 실행과 정상 종료를 확인했다. 현재 통신 드라이버는 QEMU의 RTL8139 전용이며 VirtualBox의 PCnet/E1000에서는 네트워크를 사용할 수 없어 네트워크 장치를 비활성화한다. ذخیره_مقدار وضعیت_مقدار 재개와 새 ساخت_سیستم 반영 방법은 [VirtualBox اجرا_فرمان مرا_بخوان_eb81d7d9](../문서/가상상자실행.md)에 있다.

## 셸에서 کاربر برنامه_f5044b9b اجرا_فرمان 및 네트워크 호출

독립 ELF32 اجرا_فرمان 파일을 적재해 **ring 3**에서 실행한다. `int 0x80` 시스템 호출을 통해 단말 خروجی, نشانوندها جستار_مقدار, UDP باز_کردن·ارسال·받기·닫기를 제공한다. کاربر 코드를 هسته_مقدار 함수로 직접 호출하는 구조가 아니다.

```text
jkoros> apps
jkoros> run hello first second
jkoros> net
jkoros> run netcheck
jkoros> run udp 10.0.2.2 9000 hello
```

마지막 명령의 응답을 받으려면 호스트의 별도 터미널에서 `python3 /home/user/jkoros/os/ابزارها/자료되돌리기.py --port 9000`을 먼저 실행한다. 상세 API, برنامه_f5044b9b 추가, آدرس 공간과 제한은 [کاربر اجرا_فرمان·네트워크 مرا_بخوان_eb81d7d9](کاربر/مرا_بخوان_eb81d7d9.md)에 있다.

부팅 تأیید_صحت 문구:

```text
JKOROS NATIVE JAVA
자바 기계어 هسته_مقدار اجرا_2
JAVA SELFTEST PASS
USER ELF: ring 3 / paging / int 0x80
help | info | mem | alloc | free N | echo TEXT | clear | test | halt
apps | run NAME [ARGS] | net
READY
jkoros>
```

## 구현한 기능

- GRUB Multiboot 1 ELF 부팅, x86 حفاظت_کردن_مقدار حالت_مقدار GDT, BSS آماده_سازی, 64KiB 스택.
- Java عملکرد_مقدار واقعی_داده_ها 실행과 부팅 اطلاعات_سیستم 표식 تأیید_صحت.
- COM1 직렬 ورودی_خروجی, VGA 문자 화면·مکان_نما_مقدار·스크롤·پاک_کردن_ورودی.
- PS/2 مقدار_پیش_فرض 자판, 좌우 Shift, Enter, Backspace. تمدید_مقدار کلید_مقدار/마우스 자료는 فرمان 입력으로 쓰지 않는다.
- طول_مقدار 128의 فرمان 입력 버퍼, سرریز_مقدار 방지, CR/LF فرآیند_مقدار_ورودی.
- `help`, `info`, `mem`, `alloc`, `free N`, `echo TEXT`, `clear`, `test`, `halt`.
- 4KiB 작업 قسمت_مقدار 8개의 اختصاص_دادن_حافظه_تلفن·بازگرداندن_سنجش·재사용과 중복 بازگرداندن_سنجش 방지.
- Java آرايه_مقدار 256KiB 영역의 اندازه·زیرنگاشت_مقدار 검사와 런타임 خطا 중단.
- خواندن 전용 JKAP اجرا_فرمان گروه_مقدار, ELF32 قسمت_مقدار/ورودی_نقطه ارزیابی_کردن, کاربر حالت_مقدار·نشانوندها·خروج_برنامه کد_مقدار.
- هسته_مقدار/کاربر 페이지 مجوز_مقدار 분리, TSS, IDT, PIT 100Hz, کاربر CPU استثنا فرآیند_مقدار_ورودی 및 اجرا_فرمان زمان_مقدار 상한.
- PCI RTL8139 폴링 드라이버, ARP, ایستا_مقدار IPv4, UDP مجموع_مقابله_ای·송수신·منتظر_ماندن_مقدار 제한.

`mem`의 Upper memory는 Multiboot의 1MiB 위쪽 연속 حافظه_داده_ها اندازه(KiB)이며, 전체 حافظه_داده_ها 지도 분석이나 자유 물리 حافظه_داده_ها 수치가 아니다. `alloc`은 이미 확보한 عدد_صحیح آرايه_مقدار 안의 작업 قسمت_مقدار 번호를 반환한다. 일반 물리 صفحه_مقدار اختصاص_دادن_حافظه_تلفن, آدرس 공간 또는 کاربر فرآیند_مقدار حافظه_داده_ها 관리가 아니다.

## 명시적인 한계

이 커널은 **کاربر 프로그램을 한 번에 하나 실행하는 초기 هسته_مقدار**이다. PIT IRQ0만 사용하며 키보드와 NIC는 폴링한다. کاربر CPU 예외는 해당 프로그램을 끝내고 셸로 복귀시키지만 هسته_مقدار 예외는 중단한다. اجرا_فرمان 시간은 약 3초로 제한한다. 완전한 선점 다중 فرآیند_مقدار 스케줄러, FAT/ext 등 일반 디스크 سیستم_پرونده, TCP·DNS·DHCP·IPv6·HTTP, 전체 POSIX, 일반 شئ_مقدار 모델/GC는 아직 없다. 전용 IDE پرونده 보존과 POSIX پرونده/UDP 일부 기능은 구현했다. JVM은 RAM 파일의 단일 클래스를 اجرا_فرمان 시 적재하며 일반 ClassLoader나 JAR 로딩은 지원하지 않는다. 네이티브 اجرا_فرمان 파일은 ساخت_سیستم 시 خواندن 전용 묶음에 넣으며, 일반 Linux ELF를 실행하는 환경이 아니다. 기존 `../موروثی_منبع/`의 JVM 관리 هسته_مقدار 전체를 이식한 것도 아니다.

Java 식별자는 한국어다. 직렬 출력은 이 프로젝트의 한글(BMP 문자)을 UTF-8로 표시한다. VGA는 مقدار_پیش_فرض ASCII 글꼴만 사용하므로 한글 자리에 `?`가 나온다. فرمان 입력도 현재 ASCII만 지원하며 한글 قلم_مقدار·입력기 및 보조 평면 문자 출력은 후속 작업이다. `test`는 작은 배열을 새로 할당하고 GC가 없으므로 무한 반복하지 않는다.

## 자동 시험

`시험/부팅시험.py`는 디스크 없는 독립 QEMU를 생성해 다음을 검증하고 종료한다.

- ELF 직접 부팅 및 GRUB ISO 부팅.
- Java بومی 시험과 UTF-8 직렬 문구.
- فرمان نمایش_راهنما·اطلاعات_سیستم·حافظه_داده_ها·خروجی·خطا 입력·화면 پاک_کردن_ورودی.
- 작업 قسمت_مقدار 8개 اختصاص_دادن_حافظه_تلفن, 부족 فرآیند_مقدار_ورودی, بازگرداندن_سنجش/중복 بازگرداندن_سنجش/재할당.
- 직렬 줄바꿈·백스페이스·긴 입력 فرآیند_مقدار_ورودی.
- QEMU PS/2 کلید_مقدار 입력으로 `info` اجرا_فرمان, `halt` 정지.

성공 로그는 `build/부팅시험.json`에 남는다. 로컬 Unix 소켓을 금지하는 샌드박스에서는 시험 도구에 해당 권한이 필요하다. 시험 도중 새로 만든 QEMU만 종료하며 기존 VM과 واقعی_داده_ها 디스크는 건드리지 않는다.

`시험/사용자통신시험.py`는 ELF/ISO 각각에서 کاربر ELF, واقعی_داده_ها ring 3, نشانوندها, میزبان 루프백 UDP 왕복, 1,023/1,024바이트 24회 연속 왕복, زمان_مقدار 초과, NIC 없음, حافظه_داده_ها/포트 دسترسی_ورودی 차단, CPU استثنا, 무한 تکرار_مقدار, 잘못된 ELF를 시험한다. `build/사용자통신시험.json`에 게스트 기록과 호스트가 받은 데이터의 طول_مقدار·해시를 저장한다. `시험/패킷시험.py`는 واقعی_داده_ها Java شغل_مقدار 처리기에 손상된 패킷을 넣어 2,201개 경계/مجموع_مقابله_ای 조건을 검사한다. میزبان 루프백 외 외부 서버에는 시험 트래픽을 보내지 않는다.

부트 경계는 GNU의 [Multiboot 명세](https://www.gnu.org/software/grub/manual/multiboot/multiboot.html)를 따른다.

새 파일서술자·C ABI·IDE ذخیره_مقدار·Java پرونده 흐름의 범위와 فارسی 명명 대응은 [posix-kor مرا_بخوان_eb81d7d9](../posix-kor/مرا_بخوان_eb81d7d9.md)에 있다. `make test-posix`로 ELF/ISO 실행과 재부팅 보존을 검증한다.
