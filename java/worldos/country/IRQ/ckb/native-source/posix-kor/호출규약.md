# بەکارهێنەر 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `مەکینه/운영체제호출.s`에서 EAX(پێرست), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 인수)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. کوورەک_نرخ 실패는 음수 هەڵە پێرست, C کتێبخانە 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 بەکارهێنەر 영역 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C دەیتا 주소는 بایت_نرخ 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java فایل 흐름의 어셈블리 경계가 별도 بایت_نرخ 버퍼를 마련하여 같은 호출을 사용한다.

| پێرست | ئاکشن | 인수 |
|---|---|---|
| 30 | کردنەوە_فایل | NUL 끝 ناو ناونیشان, ڕێكبەندەكان, 허가 |
| 31 | 파일자료읽기 | 서술자, دەیتا ناونیشان, بایت_نرخ 수 |
| 32 | ڕایت_کردن_فایل_دەیتا | 서술자, دەیتا ناونیشان, بایت_نرخ 수 |
| 33 | داخستن_فایل | 서술자 |
| 34 | گەڕان_فایل | 서술자, نهێنبەندی_نرخ 있는 ئۆفسێت_نرخ, 기준 |
| 35 | 파일서술자복제 | 서술자 |
| 36 | 파일서술자지정복제 | 서술자, 새 서술자 |
| 37 | 파일상태읽기 | 서술자, 48바이트 دۆخ_نرخ ناونیشان |
| 38 | لابردن_فایل_تێنووسین_ناو | NUL 끝 ناو ناونیشان |
| 39 | سێت_فایل_درێژی | 서술자, 새 درێژی_نرخ |
| 40 | 파일서술자제어 | 서술자, فەرمان, نرخ |
| 41 | 통신종단점만들기 | ناونیشان سیستەمی_کارپێکردن_نرخ, 종류, ئەرک_نرخ پێرست |
| 42 | BIND_ناونیشان | 서술자, sockaddr_in ناونیشان, درێژی_نرخ |
| 43 | 자료전문보내기 | 서술자, دەیتا ناونیشان, درێژی_نرخ, ڕێكبەندەكان, 요청 ناونیشان |
| 44 | 자료전문받기 | 서술자, دەیتا ناونیشان, درێژی_نرخ, ڕێكبەندەكان, 요청 ناونیشان |
| 45 | 통신주소읽기 | 서술자, sockaddr ناونیشان, socklen_t ناونیشان |
| 46 | 수신대기정하기 | 서술자, 0~2000 밀리초 |
| 47 | 파일저장확정 | 서술자 |

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 ناونیشان 두 칸이다. 수신 주소가 NULL이면 هاوتا_نرخ ناونیشان 기록을 생략한다. sockaddr_in은 16바이트이며 ناونیشان 체계는 ئامێر_نرخ بایت_نرخ زنجیره_نرخ, 접속번호와 IP 주소는 네트워크 بایت_نرخ 차례다. 축소된 ناونیشان 버퍼에도 들어가는 앞부분을 쓰고 전체 ناونیشان گۆڕینی_ئەندازە 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 بزربوون_بەرنامە, 2·3은 기존 인수 조회다. 현재 커널의 인수 목록이 جێبەجێکردن_فەرمان 이름을 제외하므로 C 진입기는 argv[0]에 고정 رست_نرخ `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX پرۆسە_نرخ ABI와 다른 점이다.

표준 헤더의 ژمارەی_سروشتی گۆڕینی_ئەندازە, 플래그 نرخ, stat خانە_نرخ 순서는 `ژێدەر/포함/`에 정의한다. 동적 لكاندن·다중 پرۆسە_نرخ·스레드가 추가되면 هەڵە پێرست 저장과 ژێدەر_نرخ 수명, 호출 경계도 함께 검토해야 한다.
