# jkoros 안에서 Java دروست_کردن_ژێدەر·جێبەجێکردن_فەرمان

이 문서의 부팅·توێکڵ·Store_نرخ 명령은 **x86 وەشان_نرخ** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 وەشان_نرخ](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 فایل_ناو_دەق, `edit`의 단독 `.` Store_نرخ, 16개 RAM فایل, 약 2초 جێبەجێکردن_فەرمان 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 ڕاستەکی_دەیتا JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. جێدەر دروست_کردن_ژێدەر 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java بەرنامە_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 جێبەجێکردن_فەرمان

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. جێبەجێکردن_فەرمان 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox جێبەجێکردن_فەرمان رێخۆشکەر_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 فایل 전체를 새 내용으로 작성한다. 기존 내용의 دێڕ بژار_نرخ 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 بایت_نرخ 수 نیشاندان_نرخ.
- `cat FILE`: فایل ناوەرۆک_نرخ نیشاندان_نرخ. 텍스트 소스에 사용한다.
- `rm FILE`: بیرگە_دەیتا فایل 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·چاپکردن_نرخ 검사 شکستهێنان_نرخ 시 기존 `.class`는 유지된다. 소스를 고친 دواوە_نرخ 컴파일이 실패했다면 이전 جێبەجێکردن_فەرمان 파일이 남아 있으므로 دروست_کردن_ژێدەر 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 Store_نرخ 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 ژێدەر_دار·کلاس_نرخ·دەیتا 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, فایل 이름은 ASCII 1~63자다. ژێدەر_دار 이름은 `.class` 확장자 공간 때문에 최대 62자다. بژار_نرخ 입력은 ASCII이고 한 دێڕ 최대 128자다. دێڕ 또는 فایل 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. کوورەک_نرخ/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 بەکارهێنەر 예제 이름은 ASCII로 작성한다.

## 외부 فایل 적재

호스트에서 만든 소스나 پشتیوانی_نرخ کلیپ 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 ڕاستەکی_دەیتا 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# جێدەر JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 다음 빌드에서는 추가 파일을 포함하지 않는다. فایل ناوەرۆک_نرخ 변경과 تێنووسین_لیست 제거도 다음 빌드에 반영된다. 원본 جێدەر 파일에는 쓰지 않는다. بەهای_گریمانە `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 بەهای_گریمانە 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 کلاس_نرخ فایل 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 پشتیوانی_نرخ کلیپ 안에 있어야 한다.

## پشتیوانی_نرخ کلیپ

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| کلاس_نرخ | 패키지 없는 단일 کلاس_نرخ, ستاتیک_نرخ کردار_نرخ, 재귀, 인수/반환 | 실행마다 단일 کلاس_نرخ 적재, public static main(String[]) |
| بەهای_گریمانە نرخ | int, boolean, char, String, main의 String[] 인수 | ژمارەی_سروشتی·سەرچاوە 스택, String, int[], String[], 내부 StringBuilder |
| وتە_نرخ | 초기값 있는 مەحەلی_داوێنە 선언, کاری_سپێردراو_نرخ, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 ژمارەی_سروشتی·سەرچاوە 바이트코드와 دۆخ لق |
| دەربڕین_نرخ | 십진 ژمارەی_سروشتی, UTF-8 소스의 رست_نرخ/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, رست_نرخ 결합 | ژمارەی_سروشتی کار_نرخ·بیت_نرخ کار_نرخ·چاپکردن_نرخ 변환, 단락 평가, ڕیزی_داتا_نرخ دەسگەیشتن_تێنووسین |
| فایل | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | ڕاستەکی_دەیتا کوورەک_نرخ 파일서술자와 لكاندن, 생성·سڕینەوە_TOC·이어쓰기·EOF |
| 출력 | System.out.print/println: int/boolean/char/String, println() | 동일 |
| رست_نرخ/인수 | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), رست_نرخ 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 مەحەلی_داوێنە 선언, 오버로드, 임의 چاپکردن_نرخ 변환, ڕیزی_داتا_نرخ 생성 ژێدەر, 8/16진 리터럴, Unicode ژێدەر_دار 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 نەگۆڕ_نرخ 축소 변환을 구현하지 않는다. 외부 `.class`의 `int[]` 생성/읽기/쓰기는 지원하므로 جێدەر `javac --release 8`로 만든 ڕیزی_داتا_نرخ 예제는 실행할 수 있다.

شت_نرخ خانە_نرخ·일반 شت_نرخ 생성·상속·인터페이스·여러 کلاس_نرخ لكاندن, long/float/double, 예외 پرۆسە_نرخ_تێنووسین, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java 예외 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 رست_نرخ Store_نرخ 공간은 جێبەجێکردن_فەرمان بزربوون_بەرنامە 시 بەکارهێنەر 영역 전체와 함께 회수한다. 지속 جێبەجێکردن_فەرمان 중 GC는 없다.

## جێبەجێکردن_فەرمان 한도와 هەڵە

| ژێدەر_نرخ | 한도 |
| --- | --- |
| ژێدەر_دار/کلاس_نرخ فایل | 각각 16KiB |
| 컴파일러 | فیشە_نرخ 2,047개, 생성 코드 4KiB, نەگۆڕ_نرخ 풀 4KiB |
| کردار_نرخ/인수 | 클래스당 32함수, 함수당 16인수 |
| JVM نەگۆڕ_نرخ | 511개 |
| JVM کردار_نرخ 코드 | 함수당 8KiB |
| JVM 호출/스택/مەحەلی_داوێنە 변수 | 32프레임, 프레임당 스택 128칸·مەحەلی_داوێنە 128칸 |
| JVM شت_نرخ Store_نرخ 공간 | 8,192개 32비트 کەلێن_بۆ_نووسین_یان_رەمز_تێنووسین, 헤더 포함 약 32KiB |
| جێبەجێکردن_فەرمان | 최대 500,000 فەرمان, 기존 커널의 약 3초 CPU جێبەجێکردن_فەرمان 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 پشتیوانی_نرخ 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM فەرهەنگ 검증기를 구현한 것은 아니다. فایل/تایبەتمەندی_نرخ درێژی_نرخ, نەگۆڕ_نرخ سەرچاوە, فەرمان·لق 경계를 검사하고, جێبەجێکردن_فەرمان 중 스택 بیچم_نرخ·مەحەلی_داوێنە ئامادە_کردن·ڕیزی_داتا_نرخ ژێرنەسک_نرخ·شت_نرخ 참조를 검사한다. بەکارهێنەر 코드의 페이지·포트 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, دروست_کردن_ژێدەر·JVM 오류는 `Exit: 1`, فەرمان 인수 오류는 `Exit: 2`다. CPU کات_نرخ 상한은 기존 `Exit: 124`이며, بەکارهێنەر ELF 자체의 CPU/런타임 오류는 기존 بزربوون_بەرنامە 코드를 따른다. شکستهێنان_نرخ 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## 구현 위치와 시험

- `os/بەکارهێنەر/자바/자바컴파일러.java`: 게스트 어휘·구문·چاپکردن_نرخ 검사, نەگۆڕ_نرخ 풀 및 바이트코드 생성.
- `os/بەکارهێنەر/자바/자바가상기계.java`: کلاس_نرخ 적재, 스택·프레임·شت_نرخ Store_نرخ, فەرمان 해석과 제한된 표준 호출.
- `os/ژێدەر/بیرگە_سیستمی_فایل.java`: بیرگە_دەیتا سیستمی_فایل, بژار_نرخ, 부팅 فایل 적재.
- `os/ژێدەر/체계호출.java`, `compiler/دەستپێك_بەکارهێنەر_بەرنامە.s`: فایل/문자 출력 API와 بەکارهێنەر نیشاندەر 검사.
- `os/ئامرازەکان/자바파일묶기.py`: جێدەر 입력 فایل ڕەوایی·부팅 گروپ_نرخ 생성.

```sh
make test-java
make test
```

`os/시험/자바시험.py`는 ELF/ISO 부팅, 게스트 دروست_کردن_ژێدەر·جێبەجێکردن_فەرمان, بەکارهێنەر 입력, 재귀·반복문·ژمارەی_سروشتی 극값·رست_نرخ 결합·단락 평가, 재실행, ژێدەر_دار هەڵە 후 기존 کلاس_نرخ 보존, ڕیزی_داتا_نرخ/수 해독 هەڵە, 무한 دووبارەکردنەوە_نرخ 제한, بژار_نرخ 넘침과 فایل 부족을 검사한다. 게스트 생성 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 جێدەر OpenJDK의 کلاس_نرخ, ژمارەی_سروشتی 배열과 한글 상수를 게스트에 적재하며, 손상된 فایل 표식·버전·نەگۆڕ_نرخ 수·لق·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 시험 VM만 생성하고 종료한다.

구현 형식의 참고 دەیتا: Oracle [JVM کلاس_نرخ فایل 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM فەرمان 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java فایل I_O

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 کلاس_نرخ 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 دواوە_نرخ `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. بەهای_گریمانە 출력 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. 예외 شت_نرخ·try/catch·try-with-resources는 지원하지 않으며 فایل 오류를 진단하고 프로그램을 종료한다. ڕیزی_داتا_نرخ I_O, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 فایل 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 توێکڵ `sync`가 필요하다. 예제의 فایل 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 ڕاستەکی_دەیتا 게스트 دروست_کردن_ژێدەر 결과를 OpenJDK `-Xverify:all`로 다시 실행해 فایل 바이트와 출력을 대조한다. 범위와 Store_نرخ میدیا_نرخ 사용법은 [posix-kor رێخۆشکەر_eb81d7d9](../posix-kor/رێخۆشکەر_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
