# 셸에서 실행하는 ተጠቃሚ 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 አንበኝ_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 ፈጽም_ትእዛዝ

አዘጋጅ_b78e430d ተርሚናል 1:

```sh
cd /home/user/jkoros
python3 os/መሳሪያዎች/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 외부 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

አዘጋጅ_b78e430d ተርሚናል 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 ትክክለኛ_ውሂብ CPU ፈቃድ_እሴት `ring 3`, 인수 ውጤት.
- `netcheck`: ወደብ_እሴት 중복, 잘못된 እጀታ_እሴት/ጠቋሚ/ርዝመት_እሴት, 비차단 받기와 ጊዜ_እሴት 초과 አረጋግጥ.
- `udp`: IPv4 አድራሻ·መድረሻ_እሴት ወደብ_እሴት·한 ቃል_እሴት 메시지를 받아 UDP로 보내고 같은 응답을 አረጋግጥ. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: አዘጋጅ_b78e430d `10.0.2.2`의 지정 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 ድግግሞሽ_እሴት 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 현재 주소는 게스트 `10.0.2.15/24`, አግባቢ_ፍኖት_እሴት `10.0.2.2`로 고정돼 있다. QEMU ተጠቃሚ 네트워크의 አዘጋጅ_b78e430d መዳረሻ_ምዝግብ 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 ፕሮግራም_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java ፕሮግራም_f5044b9b 추가

`예제/내프로그램.java`를 ቀጣይ_ንጥል_ነገር 형식으로 만든다. 진입점은 인수 없는 `static int` 또는 `static void` 함수다. 인수는 ተጠቃሚ API로 조회한다.

```java
public final class 내프로그램 {
    public static int ማስኬጃ() {
        ተጠቃሚ.መጻፊያ("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/ተጠቃሚ/ፕሮግራም_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := ተጠቃሚ/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.ማስኬጃ
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `ተጠቃሚ/እወጃ/ተጠቃሚ.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 ፈጽም_ትእዛዝ 중인 VM에는 ግንብ_ስርዓት 결과가 자동 반영되지 않는다. ፕሮግራም_f5044b9b 이름은 현재 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java መደብ_እሴት·ተግባር_እሴት·변수에는 한국어를 쓴다. 최대 32개 ፕሮግራም_f5044b9b, 한 ፈጽም_ትእዛዝ 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.ማስኬጃ \
    -o os/build/apps/hello.elf os/ተጠቃሚ/እወጃ/ተጠቃሚ.java os/ተጠቃሚ/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 አዘጋጅ_b78e430d 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 ድገፍ_እሴት ቅንጥብ 안에서 실행한다. `.jar`와 일반 Linux ፈጽም_ትእዛዝ 파일은 지원하지 않는다.

## ተጠቃሚ 네트워크 API

선언은 `እወጃ/ተጠቃሚ.java`에 있다. `ላክ_ውሂብ`/`자료받기`의 `int[]` ንጥል_ነገር_አባል 한 개는 ባይት_እሴት 하나(0~255)를 나타낸다. 한 데이터그램의 최대 ውሂብ 길이는 1,024바이트다.

```java
int እጀታ_እሴት = ተጠቃሚ.ክፈት_መረብ(0); // 0: 임시 የአካባቢ_ስፋት UDP ወደብ_እሴት 자동 የተመረጠ_እሴት
int[] ውሂብ = new int[32];
ውሂብ[0] = 'H'; ውሂብ[1] = 'i';
int 보낸길이 = ተጠቃሚ.ላክ_ውሂብ(እጀታ_እሴት, 0x0a000202, 9000, ውሂብ, 2);
int 받은길이 = ተጠቃሚ.자료받기(እጀታ_እሴት, ውሂብ, 1500);
ተጠቃሚ.ዝጋ_መረብ(እጀታ_እሴት);
```

ትክክለኛ_ውሂብ 프로그램에서는 መክፈቻ·ላክ·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 መጠበቅ_እሴት 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 추가 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | እጀታ_እሴት·ሂደት_እሴት_ምዝግብ ርዝመት_እሴት·성공 등 해당 함수의 ልኬት |
| -5 | መሳሪያ_እሴት ላክ_እሴት ተስኖት_እሴት |
| -9 | 잘못되었거나 닫힌 통신 እጀታ_እሴት |
| -11 | 비차단 받기에서 도착한 ውሂብ 없음 |
| -14 | ተጠቃሚ ጠቋሚ/ድርድር_እሴት ቅንጥብ ስህተት |
| -19 | ድገፍ_እሴት NIC 없음 |
| -22 | ወደብ_እሴት/መጠበቅ_እሴት ጊዜ_እሴት/인수 እሴት ስህተት |
| -24 | 열린 መረብ_ወደብ 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | ውሂብ 또는 수신 ድርድር_እሴት መጠን 문제 |
| -98 | የአካባቢ_ስፋት ወደብ_እሴት መረጃ_ጠቆመ 중복 |
| -101 | 지원하지 않는 መድረሻ_እሴት አድራሻ |
| -110 | ARP·መሳሪያ_እሴት·수신 ጊዜ_እሴት 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 በኮድ_መክተት_እሴት 있는 Java `int`의 ቢት_እሴት 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## ፈጽም_ትእዛዝ 경계와 시스템 호출

```text
ሼል run → JKAP에서 ELF ትክክለኛነት_አረጋግጥ·적재 → ring 3 ተጠቃሚ ፕሮግራም_f5044b9b
                                 ↓ int 0x80
                      ጠቋሚ 검사 → Java ዓንኳር_እሴት API → RTL8139/UDP
                                 ↓ ውጣ_ፕሮግራም·ልዩነት·ጊዜ_እሴት 초과
                                ሼል 복귀
```

시스템 호출 레지스터는 `EAX=መረጃ_ጠቆመ`, `EBX,ECX,EDX,ESI,EDI=인수`, `EAX=ልኬት`다. Java 호출 스택 ABI는 컴파일러가 ተጠቃሚ 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| መረጃ_ጠቆመ | 호출 |
| --- | --- |
| 0 | ውጣ_ፕሮግራም(ዞን_እሴት 코드) — ማስኬጃ/ስህተት 런타임에서 사용 |
| 1 | ኅብረቁምፊ_እሴት መጻፊያ |
| 2 / 3 | 인수 개수 / 인수 ኅብረቁምፊ_እሴት አድራሻ |
| 10 | UDP መክፈቻ |
| 11 | UDP ላክ(እጀታ_እሴት, IP, መድረሻ_እሴት ወደብ_እሴት, ድርድር_እሴት አድራሻ, ርዝመት_እሴት) |
| 12 | UDP 받기(እጀታ_እሴት, ድርድር_እሴት አድራሻ, 제한 밀리초) |
| 13 | UDP መዝጊያ |
| 14 | የአካባቢ_ስፋት IP አድራሻ |
| 15 / 16 | 마지막 አቻ_እሴት IP / UDP ወደብ_እሴት |
| 20 | RAM ፋይል ማንበቢያ(ስም int[] አድራሻ, ውጤት int[] አድራሻ) |
| 21 | RAM ፋይል መጻፊያ(ስም int[] አድራሻ, 입력 int[] አድራሻ, ባይት_እሴት ርዝመት_እሴት) |
| 22 | UTF-16 코드 አሀዶች_እሴት 문자 ውጤት(0~65535) |

ፋይል API는 `ተጠቃሚ.파일읽기(int[] ስም, int[] ውሂብ)`와 `ተጠቃሚ.ጻፍ_ፋይል(int[] ስም, int[] ውሂብ, int ርዝመት_እሴት)`다. 이름은 ASCII 코드 ድርድር_እሴት(최대 64칸, 0 ውጣ_ፕሮግራም 또는 ድርድር_እሴት 끝), ውሂብ ንጥል_ነገር_አባል 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 ፋይል 없음 `-2`, ጠቋሚ ስህተት `-14`, ስም/ርዝመት_እሴት ስህተት `-22`, ፋይል ማስገቢያ_ቀዳዳ_እሴት 부족 `-28`, መጠን 초과 `-90`을 반환한다. 쓰기는 ትክክለኛነት_አረጋግጥ 후 ፋይል 전체를 대체한다. `ተጠቃሚ.ጻፍ_ቁምፊ_እሴት(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 ተጠቃሚ 모드에서 CS의 하위 비트를 직접 읽으므로 ትክክለኛ_ውሂብ ፈጽም_ትእዛዝ 권한을 확인한다. ዓንኳር_እሴት 포트 접근용 `መሳሪያ_እሴት` native 함수는 ተጠቃሚ ዓላማ 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 ፈጽም_ትእዛዝ, 파이프, 프로세스 간 통신은 없다. ፈጽም_ትእዛዝ 파일은 커널의 ማንበቢያ 전용 JKAP 묶음에서 적재한다. ውሂብ 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- ተጠቃሚ 가상 አድራሻ `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. ፈጽም_ትእዛዝ 영상은 ፊት_እሴት 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. ዓንኳር_እሴት identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB ተጠቃሚ 영역을 비우고 ፋይል 구역을 복사해 BSS·ድርድር_እሴት 영역을 초기화한다. ተጠቃሚ GC는 없지만 ውጣ_ፕሮግራም 후 ቀጣይ_ንጥል_ነገር ፈጽም_ትእዛዝ 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 ጥቅስ/이스케이프 파싱은 없다.
- ተጠቃሚ 페이지의 코드/ውሂብ 분리 ማንበቢያ 전용 ማሰናጃዎች, NX, 스택 guard, ASLR은 아직 없다. 커널과 ተጠቃሚ ማስቀመጫ_ውሂብ·포트 ፈቃድ_እሴት 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 ፈጽም_ትእዛዝ 상한을 두며 ጊዜ_እሴት 초과는 `Exit: 124`다. ተጠቃሚ CPU 예외는 `128 + ልዩነት መረጃ_ጠቆመ`(페이지 ስህተት 142, 특권 위반 141), Java ድርድር_እሴት/계산 오류는 101~105다. ዓንኳር_እሴት 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, አይንቀሳቀሴ_እሴት IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP ድምር_ፍተሻ 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- ተጠቃሚ ፈጽም_ትእዛዝ·네트워크·ጠብቅ_እሴት 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 ፈጽም_ትእዛዝ·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## ትክክለኛነት_አረጋግጥ 근거

`make test`는 컴파일러 14개 시험, Java 패킷 ሁኔታ 2,201개 검사, 기존 ሼል ELF/ISO 부팅 시험, ተጠቃሚ ELF/ትክክለኛ_ውሂብ UDP/ጠብቅ_እሴት 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 ርዝመት_እሴት·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 ትእዛዝ·무한 ሽምጥ_እሴት 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
