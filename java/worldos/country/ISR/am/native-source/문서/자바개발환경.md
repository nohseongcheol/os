# jkoros 안에서 Java መገንባት_ምንጭ·ፈጽም_ትእዛዝ

이 문서의 부팅·ሼል·ማከማቻ_እሴት 명령은 **x86 ስሪት_እሴት** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 ስሪት_እሴት](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 ፋይል_ስም_ጽሁፍ, `edit`의 단독 `.` ማከማቻ_እሴት, 16개 RAM ፋይል, 약 2초 ፈጽም_ትእዛዝ 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 ትክክለኛ_ውሂብ JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. አዘጋጅ_b78e430d መገንባት_ምንጭ 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java ፕሮግራም_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 ፈጽም_ትእዛዝ

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. ፈጽም_ትእዛዝ 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox ፈጽም_ትእዛዝ አንበኝ_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 ፋይል 전체를 새 내용으로 작성한다. 기존 내용의 መስመር አርትዕ_እሴት 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 ባይት_እሴት 수 አሳይ_እሴት.
- `cat FILE`: ፋይል ይዘት_እሴት አሳይ_እሴት. 텍스트 소스에 사용한다.
- `rm FILE`: ማስቀመጫ_ውሂብ ፋይል 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·ተይብ_እሴት 검사 ተስኖት_እሴት 시 기존 `.class`는 유지된다. 소스를 고친 ተመለስ_እሴት 컴파일이 실패했다면 이전 ፈጽም_ትእዛዝ 파일이 남아 있으므로 መገንባት_ምንጭ 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 ማከማቻ_እሴት 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 ምንጭ_ዛፍ·መደብ_እሴት·ውሂብ 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, ፋይል 이름은 ASCII 1~63자다. ምንጭ_ዛፍ 이름은 `.class` 확장자 공간 때문에 최대 62자다. አርትዕ_እሴት 입력은 ASCII이고 한 መስመር 최대 128자다. መስመር 또는 ፋይል 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. ዓንኳር_እሴት/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 ተጠቃሚ 예제 이름은 ASCII로 작성한다.

## 외부 ፋይል 적재

호스트에서 만든 소스나 ድገፍ_እሴት ቅንጥብ 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 ትክክለኛ_ውሂብ 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# አዘጋጅ_b78e430d JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 ቀጣይ_ንጥል_ነገር 빌드에서는 추가 파일을 포함하지 않는다. ፋይል ይዘት_እሴት 변경과 ምዝግብ_ዝርዝር 제거도 ቀጣይ_ንጥል_ነገር 빌드에 반영된다. 원본 አዘጋጅ_b78e430d 파일에는 쓰지 않는다. ነባሪ_እሴት `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 ነባሪ_እሴት 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 መደብ_እሴት ፋይል 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 ድገፍ_እሴት ቅንጥብ 안에 있어야 한다.

## ድገፍ_እሴት ቅንጥብ

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| መደብ_እሴት | 패키지 없는 단일 መደብ_እሴት, አይንቀሳቀሴ_እሴት ተግባር_እሴት, 재귀, 인수/반환 | 실행마다 단일 መደብ_እሴት 적재, public static main(String[]) |
| ነባሪ_እሴት እሴት | int, boolean, char, String, main의 String[] 인수 | ኢንተጀር·ማጣቀሻ 스택, String, int[], String[], 내부 StringBuilder |
| መግለጫ_እሴት | 초기값 있는 የአካባቢ_ስፋት እወጃ, ስራ_እሴት, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 ኢንተጀር·ማጣቀሻ 바이트코드와 ሁኔታ ቅርንጫፍ |
| የሒሳብ_ሓረግ_እሴት | 십진 ኢንተጀር, UTF-8 소스의 ኅብረቁምፊ_እሴት/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, ኅብረቁምፊ_እሴት 결합 | ኢንተጀር ክወና_እሴት·ቢት_እሴት ክወና_እሴት·ተይብ_እሴት 변환, 단락 평가, ድርድር_እሴት መዳረሻ_ምዝግብ |
| ፋይል | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | ትክክለኛ_ውሂብ ዓንኳር_እሴት 파일서술자와 መገናኛ, አዘጋጅ·አጽዳ_ይዞታዎች·이어쓰기·EOF |
| ውጤት | System.out.print/println: int/boolean/char/String, println() | 동일 |
| ኅብረቁምፊ_እሴት/인수 | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), ኅብረቁምፊ_እሴት 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 የአካባቢ_ስፋት እወጃ, 오버로드, 임의 ተይብ_እሴት 변환, ድርድር_እሴት አዘጋጅ ምንጭ, 8/16진 리터럴, Unicode ምንጭ_ዛፍ 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 ቋሚ_እሴት 축소 변환을 구현하지 않는다. 외부 `.class`의 `int[]` አዘጋጅ/ማንበቢያ/쓰기는 지원하므로 አዘጋጅ_b78e430d `javac --release 8`로 만든 ድርድር_እሴት 예제는 실행할 수 있다.

ነገር_እሴት መስክ_እሴት·일반 ነገር_እሴት አዘጋጅ·상속·인터페이스·여러 መደብ_እሴት መገናኛ, long/float/double, ልዩነት ሂደት_እሴት_ምዝግብ, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java ልዩነት 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 ኅብረቁምፊ_እሴት ማከማቻ_እሴት 공간은 ፈጽም_ትእዛዝ ውጣ_ፕሮግራም 시 ተጠቃሚ 영역 전체와 함께 회수한다. 지속 ፈጽም_ትእዛዝ 중 GC는 없다.

## ፈጽም_ትእዛዝ 한도와 ስህተት

| ሃብት_እሴት | 한도 |
| --- | --- |
| ምንጭ_ዛፍ/መደብ_እሴት ፋይል | 각각 16KiB |
| 컴파일러 | ቦኖ_እሴት 2,047개, አዘጋጅ 코드 4KiB, ቋሚ_እሴት 풀 4KiB |
| ተግባር_እሴት/인수 | 클래스당 32함수, 함수당 16인수 |
| JVM ቋሚ_እሴት | 511개 |
| JVM ተግባር_እሴት 코드 | 함수당 8KiB |
| JVM 호출/스택/የአካባቢ_ስፋት 변수 | 32프레임, 프레임당 스택 128칸·የአካባቢ_ስፋት 128칸 |
| JVM ነገር_እሴት ማከማቻ_እሴት 공간 | 8,192개 32비트 ማስገቢያ_ቀዳዳ_ምዝግብ, 헤더 포함 약 32KiB |
| ፈጽም_ትእዛዝ | 최대 500,000 ትእዛዝ, 기존 커널의 약 3초 CPU ፈጽም_ትእዛዝ 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 ድገፍ_እሴት 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM መዝገበ_ቃላት 검증기를 구현한 것은 아니다. ፋይል/ዓይነታ_እሴት ርዝመት_እሴት, ቋሚ_እሴት ማጣቀሻ, ትእዛዝ·ቅርንጫፍ 경계를 검사하고, ፈጽም_ትእዛዝ 중 스택 ቅርጸት_እሴት·የአካባቢ_ስፋት ጀምር·ድርድር_እሴት ግርጌአደር_እሴት·ነገር_እሴት 참조를 검사한다. ተጠቃሚ 코드의 페이지·포트 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, መገንባት_ምንጭ·JVM 오류는 `Exit: 1`, ትእዛዝ 인수 오류는 `Exit: 2`다. CPU ጊዜ_እሴት 상한은 기존 `Exit: 124`이며, ተጠቃሚ ELF 자체의 CPU/런타임 오류는 기존 ውጣ_ፕሮግራም 코드를 따른다. ተስኖት_እሴት 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## 구현 위치와 시험

- `os/ተጠቃሚ/자바/자바컴파일러.java`: 게스트 어휘·구문·ተይብ_እሴት 검사, ቋሚ_እሴት 풀 및 바이트코드 አዘጋጅ.
- `os/ተጠቃሚ/자바/자바가상기계.java`: መደብ_እሴት 적재, 스택·프레임·ነገር_እሴት ማከማቻ_እሴት, ትእዛዝ 해석과 제한된 표준 호출.
- `os/ምንጭ/ማስቀመጫ_የፋይል_ስርዓት.java`: ማስቀመጫ_ውሂብ የፋይል_ስርዓት, አርትዕ_እሴት, 부팅 ፋይል 적재.
- `os/ምንጭ/체계호출.java`, `compiler/ጀምር_ተጠቃሚ_ፕሮግራም.s`: ፋይል/문자 ውጤት API와 ተጠቃሚ ጠቋሚ 검사.
- `os/መሳሪያዎች/자바파일묶기.py`: አዘጋጅ_b78e430d 입력 ፋይል ትክክለኛነት_አረጋግጥ·부팅 ቡድን_እሴት አዘጋጅ.

```sh
make test-java
make test
```

`os/시험/자바시험.py`는 ELF/ISO 부팅, 게스트 መገንባት_ምንጭ·ፈጽም_ትእዛዝ, ተጠቃሚ 입력, 재귀·반복문·ኢንተጀር 극값·ኅብረቁምፊ_እሴት 결합·단락 평가, 재실행, ምንጭ_ዛፍ ስህተት 후 기존 መደብ_እሴት 보존, ድርድር_እሴት/수 해독 ስህተት, 무한 ሽምጥ_እሴት 제한, አርትዕ_እሴት 넘침과 ፋይል 부족을 검사한다. 게스트 አዘጋጅ 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 አዘጋጅ_b78e430d OpenJDK의 መደብ_እሴት, ኢንተጀር 배열과 한글 상수를 게스트에 적재하며, 손상된 ፋይል 표식·버전·ቋሚ_እሴት 수·ቅርንጫፍ·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 시험 VM만 생성하고 종료한다.

## Java ፋይል ግቤት_ውጤት

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 መደብ_እሴት 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 ተመለስ_እሴት `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. ነባሪ_እሴት ውጤት 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. ልዩነት ነገር_እሴት·try/catch·try-with-resources는 지원하지 않으며 ፋይል 오류를 진단하고 프로그램을 종료한다. ድርድር_እሴት ግቤት_ውጤት, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 ፋይል 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 ሼል `sync`가 필요하다. 예제의 ፋይል 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 ትክክለኛ_ውሂብ 게스트 መገንባት_ምንጭ 결과를 OpenJDK `-Xverify:all`로 다시 실행해 ፋይል 바이트와 출력을 대조한다. 범위와 ማከማቻ_እሴት 매체 사용법은 [posix-kor አንበኝ_eb81d7d9](../posix-kor/አንበኝ_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
