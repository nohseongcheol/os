# 셸에서 실행하는 משתמש 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 סביבה 안내](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 לבצע_פקודה

ארח מסוף 1:

```sh
cd /home/user/jkoros
python3 os/כלים/הד_נתונים.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. חיצוני_ערך 연결을 받도록 방화벽이나 חומרה_הסב 전달을 변경하지 않는다. Ctrl+C로 종료한다.

ארח מסוף 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 קלט_ערך:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 בפועל_נתונים CPU הרשאה_ערך `ring 3`, ארגומנטים פלטטקסט.
- `netcheck`: הסב_ערך 중복, 잘못된 נקודת_אחיזה_ערך/מצביע/길이, 비차단 받기와 ערך_זמן 초과 ודא_אמת.
- `udp`: IPv4 למען·יעד_ערך הסב_ערך·한 מילים_ערך 메시지를 받아 UDP로 보내고 같은 응답을 ודא_אמת. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: ארח `10.0.2.2`의 הקצה_ערך 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. לקבל_ערך_cef4d8ab לולאה_ערך 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. נוכחי_פריט 주소는 게스트 `10.0.2.15/24`, שער_ערך `10.0.2.2`로 고정돼 있다. QEMU משתמש 네트워크의 ארח גישה_ערך_68aed533 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 תוכנית_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java תוכנית_f5044b9b צירוף_ערך_b73accca

`예제/내프로그램.java`를 הבא_פריט 형식으로 만든다. 진입점은 ארגומנטים 없는 `static int` 또는 `static void` 함수다. 인수는 משתמש API로 조회한다.

```java
public final class 내프로그램 {
    public static int הפעלה() {
        משתמש.כתוב("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/משתמש/תוכנית_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := משתמש/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.הפעלה
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `משתמש/הצהרה/משתמש.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 לבצע_פקודה 중인 VM에는 בנייה 결과가 자동 반영되지 않는다. תוכנית_f5044b9b 이름은 נוכחי_פריט 셸의 ASCII קלט_ערך 제한에 맞춘 1~15자의 소문자 이름이며 Java כיתה_ערך·פונקציה_ערך·변수에는 한국어를 쓴다. 최대 32개 תוכנית_f5044b9b, 한 לבצע_פקודה 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/מהדר.py --target user --entry 인사.הפעלה \
    -o os/build/apps/hello.elf os/משתמש/הצהרה/משתמש.java os/משתמש/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 ארח 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 תמך_ערך לגזור 안에서 실행한다. `.jar`와 일반 Linux לבצע_פקודה 파일은 지원하지 않는다.

## משתמש 네트워크 API

선언은 `הצהרה/משתמש.java`에 있다. `שלח_נתונים`/`לקבל_נתונים`의 `int[]` פריט_רכיב 한 개는 בית_ערך 하나(0~255)를 나타낸다. 한 데이터그램의 최대 נתונים 길이는 1,024바이트다.

```java
int נקודת_אחיזה_ערך = משתמש.פתח_רשת(0); // 0: 임시 מקומי_היקף UDP הסב_ערך 자동 קטע_נבחר_ערך
int[] נתונים = new int[32];
נתונים[0] = 'H'; נתונים[1] = 'i';
int 보낸길이 = משתמש.שלח_נתונים(נקודת_אחיזה_ערך, 0x0a000202, 9000, נתונים, 2);
int 받은길이 = משתמש.לקבל_נתונים(נקודת_אחיזה_ערך, נתונים, 1500);
משתמש.סגור_רשת(נקודת_אחיזה_ערך);
```

בפועל_נתונים 프로그램에서는 פתח·שלח·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `לקבל_נתונים`의 רק_רגע_ערך 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 לקבל_ערך_cef4d8ab 대기열은 한 개뿐이므로 צירוף_ערך_b73accca 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | נקודת_אחיזה_ערך·תהליך_ערך_ערך 길이·성공 등 해당 함수의 תוצאה |
| -5 | התקן_ערך_e13f0cd9 שלח_ערך כשל_ערך |
| -9 | 잘못되었거나 닫힌 통신 נקודת_אחיזה_ערך |
| -11 | 비차단 받기에서 도착한 נתונים 없음 |
| -14 | משתמש מצביע/מערך_ערך לגזור שגיאה |
| -19 | תמך_ערך NIC 없음 |
| -22 | הסב_ערך/רק_רגע_ערך ערך_זמן/ארגומנטים ערך שגיאה |
| -24 | 열린 רשת_הסב 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | נתונים 또는 לקבל_ערך_cef4d8ab מערך_ערך גודל 문제 |
| -98 | מקומי_היקף הסב_ערך מדד 중복 |
| -101 | 지원하지 않는 יעד_ערך למען |
| -110 | ARP·התקן_ערך_e13f0cd9·לקבל_ערך_cef4d8ab ערך_זמן 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 קידוד_ערך 있는 Java `int`의 ביט_ערך 패턴을 사용하므로 상위 비트가 1인 מערכות_מידע_רגיל IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## לבצע_פקודה 경계와 시스템 호출

```text
מעטפת run → JKAP에서 ELF לאמת·적재 → ring 3 משתמש תוכנית_f5044b9b
                                 ↓ int 0x80
                      מצביע 검사 → Java ליבה_ערך API → RTL8139/UDP
                                 ↓ יציאה_תוכנית·חריגה·ערך_זמן 초과
                                מעטפת 복귀
```

시스템 호출 레지스터는 `EAX=מדד`, `EBX,ECX,EDX,ESI,EDI=ארגומנטים`, `EAX=תוצאה`다. Java 호출 אופרנד_רמז ABI는 컴파일러가 משתמש 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| מדד | 호출 |
| --- | --- |
| 0 | יציאה_תוכנית(מצב_ערך קוד_ערך) — הפעלה/שגיאה 런타임에서 שימוש_ערך |
| 1 | מחרוזת_ערך כתוב |
| 2 / 3 | ארגומנטים 개수 / ארגומנטים מחרוזת_ערך למען |
| 10 | UDP פתח |
| 11 | UDP שלח(נקודת_אחיזה_ערך, IP, יעד_ערך הסב_ערך, מערך_ערך למען, 길이) |
| 12 | UDP לקבל(נקודת_אחיזה_ערך, מערך_ערך למען, 제한 밀리초) |
| 13 | UDP סגירה |
| 14 | מקומי_היקף IP למען |
| 15 / 16 | 마지막 עמית_ערך IP / UDP הסב_ערך |
| 20 | RAM קובץ קרא(שם int[] למען, פלטטקסט int[] למען) |
| 21 | RAM קובץ כתוב(שם int[] למען, קלט_ערך int[] למען, בית_ערך 길이) |
| 22 | UTF-16 קוד_ערך יחידה_ערך 문자 פלטטקסט(0~65535) |

קובץ API는 `משתמש.파일읽기(int[] שם, int[] נתונים)`와 `משתמש.כתיבה_קובץ(int[] שם, int[] נתונים, int 길이)`다. 이름은 ASCII קוד_ערך מערך_ערך(최대 64칸, 0 יציאה_תוכנית 또는 מערך_ערך 끝), נתונים פריט_רכיב 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 קובץ 없음 `-2`, מצביע שגיאה `-14`, שם/길이 שגיאה `-22`, קובץ חריץ_ערך_ff41a4f1 부족 `-28`, גודל 초과 `-90`을 반환한다. 쓰기는 לאמת 후 קובץ 전체를 대체한다. `משתמש.כתיבה_תו_ערך(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 משתמש 모드에서 CS의 하위 비트를 직접 읽으므로 בפועל_נתונים לבצע_פקודה 권한을 확인한다. ליבה_ערך חומרה_הסב 접근용 `התקן_ערך_e13f0cd9` native 함수는 משתמש יעד 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 לבצע_פקודה, 파이프, 프로세스 간 통신은 없다. לבצע_פקודה 파일은 커널의 קרא 전용 JKAP 묶음에서 적재한다. נתונים 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- משתמש 가상 למען `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. לבצע_פקודה 영상은 מצלמה_קדמית_ערך_ec1a6b96 2MiB, 인수는 `0x04300000`부터, 스택은 אזור_ערך_0e9a97ab 끝에서 시작한다. ליבה_ערך identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB משתמש 영역을 비우고 קובץ 구역을 복사해 BSS·מערך_ערך 영역을 초기화한다. משתמש GC는 없지만 יציאה_תוכנית 후 הבא_פריט לבצע_פקודה 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 ציטוט/이스케이프 파싱은 없다.
- משתמש 페이지의 קוד_ערך/נתונים 분리 קרא 전용 הגדרות, NX, אופרנד_רמז guard, ASLR은 아직 없다. 커널과 משתמש זיכרון_נתונים·חומרה_הסב הרשאה_ערך 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 לבצע_פקודה 상한을 두며 ערך_זמן 초과는 `Exit: 124`다. משתמש CPU 예외는 `128 + חריגה מדד`(페이지 שגיאה 142, 특권 위반 141), Java מערך_ערך/계산 오류는 101~105다. ליבה_ערך 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, סטטי_ערך IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP בדיקת_סיכום 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- משתמש לבצע_פקודה·네트워크·הגן_ערך 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 לבצע_פקודה·מערכות_מידע_רגיל 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## לאמת 근거

`make test`는 מהדר 14개 시험, Java 패킷 תנאי 2,201개 검사, 기존 מעטפת ELF/ISO 부팅 시험, משתמש ELF/בפועל_נתונים UDP/הגן_ערך 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 길이·해시까지 `os/build/נסה_משתמש_רשת.json`에 기록한다. 시험용 손상된 ELF·특권 פקודה·무한 סבב_ערך 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
