# עצמי ARM64 커널의 Codex התקן_ערך 가능성 검토

검토일: 2026-10-05. 소스와 공식 문서를 대조한 설계 검토이며, 게스트에 Codex를 설치하거나
로그인·모델 호출을 실행한 결과는 아니다. עצמי ARM64 커널과 `../rpi4` Linux 실행판은 구분한다.

נוכחי_פריט עצמי 커널에는 공식 Codex CLI를 그대로 התקן_ערך·실행할 수 없다.
기술적으로 필요한 לבצע_פקודה 환경을 추가하거나 Codex를 이식하는 경로는 있으나,
다운로드 פקודה 하나를 추가하는 작업으로 해결되지 않는다. JDK/JRE 기능 확장만으로도 해결되지 않는다.

## 확인한 근거

| ערך_ערך | נוכחי_פריט 소스에서 확인한 מצב_ערך | 직접 실행을 위한 작업 |
|---|---|---|
| לבצע_פקודה קובץ | `מחשב/משתמש.c`: AArch64 ET_EXEC만, PT_INTERP/PT_DYNAMIC/PT_TLS דחייה_ערך, 업로드 לבצע_פקודה 버퍼 16384바이트 | יעד 바이너리에 맞는 ELF 적재·재배치·לבצע_פקודה אתחול, זיכרון_נתונים/קובץ 제한 הרחבה_ערך |
| Linux ABI | `מחשב/리눅스호환.inc`: read/write/openat/brk 등 제한된 번호만 תהליך_ערך_ערך, 나머지는 ENOSYS | libc/런타임에 필요한 시스템 호출을 추가하거나 עצמי ABI용 런타임 이식 |
| 프로세스·스레드 | 일반 fork/clone/execve, pthread/futex, 시그널, mmap, poll/epoll 계열이 미완성 | 비동기 I/O·스레드·ילד_ערך פקודה לבצע_פקודה·יציאה_תוכנית/לבטל_ניתוח 기능 |
| קובץ | `קודמקור/קבציםבזיכרון.java`: RAM קובץ 64개, 파일당 16 KiB, 비영속 | 큰 לבצע_פקודה קובץ·프로젝트·הגדרות·세션을 위한 영속 VFS, קובץ הרשאה_ערך·נתיב·디렉터리 הרחבה_ערך |
| 네트워크 | lwIP TCP/UDP는 있으나 `רשת_רמז/lwipopts.h`의 LWIP_DNS=0, 일반 HTTPS 클라이언트 없음 | DNS, TLS 인증서 לאמת·신뢰 מאגר_בסיס·정확한 חותמת_זמן_ערך, HTTPS/스트리밍 |
| מסוף·כלים | עצמי 셸과 GUI 터미널은 있지만 표준 PTY·일반 프로세스 작업 פקד_ערך 없음 | אינטראקטיבי CLI용 מסוף 기능, מעטפת/קובץ 검색/בנייה כלים חיבור |
| לבצע_פקודה הרשאה_ערך | EL0 보호는 있으나 Codex의 Linux 샌드박스와 같은 정책 집행 סביבה 없음 | קובץ·네트워크·פקודה הרשאה_ערך 정책과 승인 기능; עצמי 커널에 맞는 격리 구현 |

여기서 ELF의 PT_TLS는 스레드별 מאגר_ערך 공간이다. HTTPS의 TLS סיסמה_ערך 통신과 서로 다른 기능이다.
ELF קובץ 형식을 읽을 수 있다는 사실만으로 Linux לבצע_פקודה 환경을 제공하는 것은 아니다.
SSH/VNC를 위한 סיסמה_ערך 라이브러리를 넣은 상태도 HTTPS 구현 완료를 의미하지 않는다.

호스트의 `/home/user/.local/bin/codex`도 확인했다. 이것은 x86-64 ELF ET_DYN이며 약 209 MiB다.
해당 파일을 ARM64 게스트로 복사하여 실행할 수 없다. 이 크기를 ARM64 הפצה_ערך 파일의 크기로
해석하지 않는다. 공식 ARM64 빌드의 בפועל_נתונים גודל·의존성은 설치할 버전으로 צירוף_ערך_b73accca 검사해야 한다.

## 가능한 구현 נתיב

1. **עצמי 커널에 공식 CLI 직접 이식**
   영속 מאגר_ערך/VFS와 משתמש זיכרון_נתונים, 프로세스·스레드·I/O, libc/런타임, DNS/HTTPS,
   מסוף·הרשאה_ערך 체계를 갖춘다. 이후 יעד 버전의 의존성을 조사하여 크로스 בנייה·이식한다.
   Linux 커널을 반드시 탑재할 필요는 없지만, 공식 Linux 바이너리를 그대로 쓸 경우
   그 바이너리가 사용하는 Linux ABI까지 호환해야 한다. 큰 מערכת_הפעלה 개발 과제다.

2. **חיצוני_ערך ארח Codex와 עצמי ליבה_ערך חיבור — 첫 구현으로 권장**
   Linux PC에서 공식 CLI 또는 app-server를 실행하고 jkoros에는 전용 משתמש פקודה/화면을 만든다.
   호스트의 인증된 연결과 게스트 קובץ קרא·수정·업로드·פקודה לבצע_פקודה 어댑터가 필요하다.
   기존 SSH/TCP 경로를 활용할 수 있으나, קובץ 동기화나 Codex 전용 어댑터는 נוכחי_פריט 구현되어 있지 않다.
   호스트에서 수행한 빌드와 게스트에서 수행한 לבצע_פקודה 결과를 명확히 구분한다.
   이 구성은 עצמי 커널을 유지하지만, 공식 CLI 자체는 חיצוני_ערך 호스트에서 실행된다.

3. **עצמי API 클라이언트 제작**
   עצמי ABI의 C 또는 지원되는 Java 부분집합으로 אינטראקטיבי_הפעלה UI와 קובץ/פקודה כלים 호출 루프를 만든다.
   חיצוני_ערך 중계기를 쓰지 않는다면 DNS/לאמת 가능한 TLS/HTTPS와 인증 נתונים 저장을 먼저 구현해야 한다.
   이는 OpenAI API를 이용하는 별도 에이전트이며 공식 Codex CLI 전체의 이식으로 표시하지 않는다.

4. **별도 ARM64 Linux 실행판에서 התקן_ערך**
   `../rpi4`는 Linux와 musl 기반이므로 일반 Linux התקן_ערך 경로를 검토할 수 있다.
   사용할 Codex 버전의 ARM64·musl 호환성, 의존성, 커널의 샌드박스 지원을 בפועל_נתונים 검증해야 한다.
   이번 검토에서 התקן_ערך 성공을 확인하지 않았다. 이 결과를 עצמי Java 커널의 지원으로 표시하지 않는다.

## 단계별 완료 לשקף_בסיס

- 직접 이식: `--version` הפעלה → 인증/HTTPS → קובץ קרא·수정 → ילד_ערך פקודה לבצע_פקודה →
  אינטראקטיבי קלט_ערך/스트리밍 → הרשאה_ערך 제한·לבטל_ניתוח → 재부팅 후 הגדרות/세션 보존을 각각 בפועל_נתונים 게스트에서 확인한다.
- ארח חיבור: 게스트에서 בקשה קלט_ערך → ארח Codex תהליך_ערך_ערך → 게스트 קובץ שנה_ערך ודא_אמת →
  게스트 javac/cc לבצע_פקודה → תוצאה 표시를 처음부터 끝까지 검증한다.
- COSL 상업 조건을 유지하려면 새로 도입하는 런타임/통신 라이브러리의 라이선스와
  Codex הפצה_ערך 버전의 제3자 고지를 검토한다. חיצוני_ערך 구성요소를 일괄 COSL로 재라이선스하지 않는다.
