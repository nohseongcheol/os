# עצמי ARM64 ליבה_ערך: FTP, C, JAR와 AOT לבצע_פקודה

대상은 **Linux를 적재하지 않는 Raspberry Pi 4용 Java AOT ליבה_ערך**이다. CPU·התקן_ערך_e13f0cd9 경계는 C/어셈블리, קובץ 체계와 셸은 Java이며, 이번 TCP/IP 스택은 C로 작성된 lwIP 2.2.0을 이식했다. 게스트 TinyCC와 `jaot`도 EL0에서 실행한다. 호스트에 컴파일을 요청하거나 ארח JVM으로 대신 실행하지 않는다.

## 먼저 알아둘 תמך_ערך 경계

| בקשה | 이번 구현 | 남은 לגזור |
|---|---|---|
| JAR를 לבצע_פקודה 파일처럼 לבצע_פקודה | `java -jar קובץ.jar`, `./קובץ.jar ארגומנטים`; Main-Class와 מאגר_ערך/DEFLATE ZIP, CRC 검사 | 전체 Java SE, 임의의 모든 JAR 호환성 |
| 게스트 AOT | `jaot קובץ.class -o קובץ.elf`, `jaot קובץ.jar -o קובץ.elf`; בפועל_נתונים ARM64 기계어 יצר | אובייקט_ערך·חריגה·Thread·Swing·Socket의 AOT המר_ערך, 여러 애플리케이션 כיתה_ערך חיבור |
| C בנה_מקור | 게스트 `cc`/`tcc`, TinyCC C 전처리기·ARM64 생성기·링커; עברית 식별자와 posix-kor | 전체 libc, 일반 Linux לבצע_פקודה קובץ, 게스트 C++ מהדר |
| 업로드한 ELF לבצע_פקודה | ELF64/AArch64 헤더 검사, 확장자 없는 `./קובץ`; עצמי ABI 및 명시적인 제한형 Linux ABI | 일반 Linux 바이너리 호환, 동적 링커, 공유 ספריה |
| חיצוני_ערך TCP/UDP | 게스트 lwIP IPv4 אופרנד_רמז, POSIX 소켓과 JVM의 ספרה_ערך IPv4 למען | GENET/Wi-Fi 드라이버, DHCP·DNS·TLS, 실물 לוח 네트워크 시험 |
| FTP | 게스트 서비스, 패시브 העבר_ערך, UTF-8 שם, STOR/RETR/SIZE/LIST/NLST/MLSD/DELE | TLS·사용자별 הרשאה_ערך·하위 디렉터리·영속 מאגר_ערך |
| 한글 Java | 기존 `עברית.עצמי` 클래스와 חיצוני_ערך למען UDP 오버로드 | 전체 JDK의 일대일 עברית 대응 API |

JVM은 כיתה_ערך 버전 45…52의 문서화한 부분집합이다. `java`는 바이트코드 실행기이고, `jaot`가 별도의 네이티브 לבצע_פקודה 파일을 만든다. **JAR ארכיון_ערך 해제나 JVM을 함께 묶는 것을 AOT라고 표시하지 않는다.** 지원하지 않는 바이트코드/API는 `jaot`가 진단하고 출력을 만들지 않는다. 기존 פלטטקסט ELF도 בנה_מקור כשל_ערך 때 보존한다.

Android의 Dalvik/ART는 일반 JVM כיתה_ערך/JAR가 아닌 **DEX**를 실행한다. ART의 AOT에는 GC, כיתה_ערך 로딩, JNI 등 לבצע_פקודה 기반도 필요하다. 따라서 ART처럼 기계어로 바꾸는 기능만으로 임의의 OpenJDK JAR 및 Swing이 자동 호환되지는 않는다. [Android 공식 런타임 설명](https://source.android.com/docs/core/runtime)

FTP는 루트 RAM 파일만 공개한다. 익명 로그인이며 비밀번호로 권한을 구분하지 않는다. ערך_ברירת_מחדל ארח 바인딩은 `127.0.0.1`이고, פקד_ערך 포트는 2121, 데이터 포트는 50000…50007이다. `--ftp-port 2122`로 פקד_ערך 포트를 바꿀 수 있다. 동시에 한 FTP 세션을 제공하며 명령이 없는 세션은 60초 후 닫는다. TYPE A도 바이트를 변경하지 않으므로 프로그램은 바이너리 전송한다.

파일은 **64개, 각각 16 KiB**, 경로는 UTF-8 63바이트이다. 부팅 시 준비되는 `/example`도 이 한도를 공유한다. 초과/끊어진 STOR는 기존 파일에 반영하지 않는다. FTP 업로드는 RAM에만 저장되며 재부팅하면 사라진다. 이 제한 때문에 일반적인 대형 JAR 배포판을 그대로 올릴 수 없다.

QEMU의 raspi4b에는 GENET Ethernet 장치가 없다. 따라서 `network_bridge.py`가 QEMU NAT의 Ethernet과 보조 UART의 SLIP를 변환한다. **TCP חיבור תהליך_ערך_ערך·체크섬·재전송·FTP 명령과 קובץ 저장은 게스트 안에서 수행한다.** ארח 브리지는 FTP 서버가 아니다. [QEMU 공식 התקן_ערך_e13f0cd9 תמך_ערך ערך_רשימה](https://www.qemu.org/docs/master/system/arm/raspi.html)

이 경로는 QEMU에서 검증했다. 보조 UART의 בפועל_נתונים Pi 4 핀/클럭 설정과 내장 RJ45 GENET 드라이버는 구현·검증하지 않았으므로, SD 이미지에 커널이 포함되어 있다는 사실을 בפועל_נתונים 보드의 LAN/FTP פעולה 보장으로 해석하면 안 된다.

## עברית Java를 게스트에서 컴파일하고 AOT לבצע_פקודה

게스트 `vi 빛.java`로 הבא_פריט 소스를 작성한다.

```java
public class 빛 {
    public static void main(String[] ארגומנטים) throws Exception {
        int 합 = 0;
        int 수 = 1;
        while (수 <= 10) {
            합 = 합 + 수;
            수 = 수 + 1;
        }
        עברית.עצמי.פלטטקסט.수쓰기(합);
        עברית.עצמי.קובץ.כתוב("aot.txt", "한글 AOT קובץ 😀");
        עברית.עצמי.פלטטקסט.כתיבה_קו(עברית.עצמי.קובץ.קרא("aot.txt"));
    }
}
```

```text
javac 빛.java
java 빛
jaot 빛.class -o 빛.elf
run 빛.elf
```

`jaot`은 클래스의 바이트코드를 C로 변환하고, **게스트 TinyCC**가 ARM64 명령어를 יצר·연결한다. לבצע_פקודה 때 JVM 인터프리터를 호출하지 않는다. JAR의 Main-Class가 같은 תמך_ערך 범위이면 다음도 가능하다.

```text
jaot 빛.jar -o 빛.elf
run 빛.elf
```

AOT 지원은 한 애플리케이션 클래스의 סטטי_ערך פעולת_שירות_ערך/ערך_שדה, int 계열, מספר_שלם 배열과 הפנה, ארגומנטים מערך_ערך, תנאי·ענף·סבב_ערך, מחרוזת_ערך 리터럴, `System.out.print/println`의 int/String, עברית פלטטקסט·קובץ קרא/쓰기로 제한된다. כיתה_ערך/פעולת_שירות_ערך 수와 אופרנד_רמז 등에도 고정 상한이 있다. Java חריגה תהליך_ערך_ערך, אובייקט_ערך יצר, 가상 פעולת_שירות_ערך 일반, switch/wide, long/float/double, invokedynamic, מחרוזת_ערך 결합용 StringBuilder, 일반 JDK·Socket·Thread·Swing은 이 AOT 백엔드에서 미지원이다. 내장 NUL/고립된 서로게이트 문자열도 거부한다. 잘못된 מערך_ערך גישה_ערך_68aed533/0으로 나누기 등은 네이티브 런타임 오류로 종료하며 Java חריגה 객체로 전달하지 않는다.

קלט_ערך 클래스뿐 아니라 **생성된 ELF도 16 KiB 이하**여야 한다. 기계어 확장과 ELF 페이지 ליישר_ערך 때문에 짧은 클래스도 이 한도를 넘을 수 있으며, 이 경우 오류를 내고 기존 출력을 보존한다.

게스트 `javac`도 부분집합이다. 일반적인 אובייקט_ערך·Thread·Swing 소스는 호스트에서 `javac --release 8`로 컴파일하고, **기존 JVM의 תמך_ערך לגזור 안에서** `java`/`java -jar`로 실행한다. 정확한 API는 [JVM 매뉴얼](자바실행환경.md)과 [한글 개발 매뉴얼](개발안내.md)을 참고한다.

JAR는 하나의 애플리케이션 כיתה_ערך 경로다. 내부 שם `חבילה/תוכנית_f5044b9b.class`와 점으로 구분한 Main-Class를 지원한다. 내부 클래스는 파일로 풀어 VFS 슬롯을 소비하지 않는다. 내장 עברית 클래스를 추가로 찾지만 נוכחי_פריט 작업 폴더의 다른 클래스는 자동 혼합하지 않는다. ZIP64·הצפן_נתונים ZIP·manifest Class-Path·서명 검증은 지원하지 않는다. JAR 하나가 16 KiB 이하이어도 클래스당/적재 수/VM ערימה_ערך 제한은 그대로 적용된다.

## C에서 עברית POSIX 호출

게스트에서 `vi 인사.c`로 작성하거나 FTP로 소스를 업로드한다.

```c
#include <파일규약.h>

int main(void) {
    const char 인사말[] = "עצמי ARM64 C에서 한글 POSIX 호출\n";
    int 문서 = פתח_קובץ("인사.txt", קריאה_כתיבה | 없으면만들기 | 내용비우기, 0600);
    if (문서 < 0) return 1;
    입출력결과형 기록한수 = כתיבה_קובץ_נתונים(문서, 인사말, sizeof(인사말) - 1);
    סגור_קובץ(문서);
    כתיבה_קובץ_נתונים(1, 인사말, sizeof(인사말) - 1);
    return 기록한수 == sizeof(인사말) - 1 ? 0 : 2;
}
```

```text
cc 인사.c -o 인사.elf
run 인사.elf
cat 인사.txt
```

TinyCC의 표준 C נקודת_כניסה `main`을 사용한다. 기존 ארח C/C++ SDK의 `התחל_משתמש_תוכנית(int)` 진입점과 구분한다. 포함 קובץ·הפעלה אובייקט_ערך·`libposix-kor-user.a`는 מהדר 내부의 קרא 전용 SDK에 들어 있다. C 전처리기/구조체/פונקציה_ערך/재귀/מצביע/부동소수점 יצר 등을 사용하되 **일반 libc/libstdc++를 제공한다는 뜻은 아니다**. 제공하지 않는 함수는 חיבור 오류가 난다. מהדר 자체의 문자/ספרה_ערך המר_ערך 지원도 완전한 libc 대체품이 아니다.

`פתח_קובץ` 등은 별도의 모의 호출이 아닌 기존 `pk_open` 등의 עברית 매크로이며, ELF의 SVC를 통해 בפועל_נתונים Java קובץ 체계에 도달한다. קובץ/소켓 호출 목록은 [משתמש ABI](사용자호출규약.md)에 있다. C/C++ ארח SDK לבצע_פקודה 파일도 FTP로 업로드 후 `run` 또는 `./קובץ`로 실행하며 확장자는 필요 없다. Linux ARM64 סטטי_ערך ELF에는 별도의 제한된 호환 נתיב `run --linux קובץ`을 추가했다. [ELF·Linux ABI 매뉴얼](실행파일규약.md)에 정확한 לעצב_ערך·시스템 호출·למען 제한을 정리했다.

## עברית 네트워크·작업·화면 API

| כיתה_ערך | 호출 예 | לבצע_פקודה נתיב |
|---|---|---|
| `פלטטקסט` | `כתיבה_קו("안녕")`, `수쓰기(42)` | JVM 및 제한형 AOT |
| `קובץ` | `כתוב("문서.txt", "תוכן_ערך")`, `קרא("문서.txt")` | JVM 및 제한형 AOT |
| `통신` | `פתח(0)`, `שלח(משתתף, "10.0.2.2", 9000, "한글")`, `לקבל(משתתף)` | JVM의 UDP |
| `קשר_הובלה` | `חיבור("10.0.2.2", 9000)`, `להאזין_משתתף(9000)`, `לקבל(שרת_ערך)` | JVM의 Socket/ServerSocket |
| `작업` | `הפעלה(Runnable)`, `기다리기(Thread)`, `רווח_משימה()` | JVM의 협력식 שרשור_ערך |
| `חלון`, `רכיב_גרפי` | חלון·버튼·תו_ערך·שדה_טקסט·אירוע חיבור | JVM의 Swing 부분집합 |

명명에서는 표준 영어 API를 보존하고 עברית 호출 계층을 추가한다. `통신(通信)`, `חיבור(連結)`, `פלטטקסט(出力)`은 기존 단어의 뜻을 사용한다. `작업 שרשור_ערך`은 한 לבצע_פקודה 흐름을 가닥에 빗댄 기술 표현, `הסב_ערך`는 포트의 접점을 설명하는 표현이다. 새 기술 결합어를 고대에 이미 존재한 용어처럼 설명하지 않는다. 전체 JDK의 번역을 완료했다고 표시하지 않는다.

חיצוני_ערך 주소는 ספרה_ערך IPv4이며 QEMU 호스트는 `10.0.2.2`, 게스트는 `10.0.2.15`다. UDP 전문은 512바이트까지다. 소켓은 비차단 עצמי ABI이며 JVM이 제한된 רק_רגע_ערך/재시도를 제공한다. TCP connect 대기는 최대 1초, משתמש תוכנית_f5044b9b 전체에는 기존 약 2초 CPU 기한이 적용된다. 일반적인 장기 לבצע_פקודה משתמש 서버와 pthread는 아직 없다. FTP는 משתמש תוכנית_f5044b9b 기한과 별개인 ליבה_ערך 서비스다.

게스트의 משתמש TCP/UDP 서버로 들어오는 연결은 NAT 포트를 추가한다. 예를 들어 `python3 כלים/לבצע_פקודה.py --network --forward tcp:9300:9300 --forward udp:9301:9301`로 실행하면 호스트의 localhost 9300/TCP·9301/UDP를 게스트의 같은 포트로 전달한다. FTP의 ערך_ברירת_מחדל פקד_ערך/데이터 포트와 겹치면 לבצע_פקודה 전에 거부한다.

`build/verification/ftp/report.json`은 בפועל_נתונים FTP העבר_ערך, 한글 קובץ, גודל 초과 보존, ארכיון_ערך JAR לבצע_פקודה, 게스트 C בנה_מקור/ELF 재업로드, חיצוני_ערך Java TCP/UDP, 게스트 javac/AOT 실행을 기록한다. `serial.log`에서 게스트 명령과 결과를 확인할 수 있다. 보고서의 ליבה_ערך SHA-256과 הפצה_ערך 이미지의 커널을 비교한다.

빌드는 기존 JDK/Clang/AArch64 binutils와 함께 `../rpi4/build/rootfs`의 ARM64 SDK הצהרה 헤더와 libgcc 산술 보조 함수를 사용한다(`make rpi-prepare`). **musl libc, Linux ליבה_ערך, 동적 로더를 게스트에 링크하지 않는다.** TinyCC/lwIP/uzlib 원본과 라이선스·버전 정보는 `vendor/`, 이식 코드는 `ccompiler/`, `network/`, `משתמש/חבילה.c`에 있다.
