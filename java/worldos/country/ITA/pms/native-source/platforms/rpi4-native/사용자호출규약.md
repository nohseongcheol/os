# 자체 ARM64 사용자 실행 ABI v1

이 ABI는 `platforms/rpi4-native`의 제한된 freestanding 실행 환경이다. Linux AArch64 ABI나 POSIX 전체 구현이 아니다. **OpenJDK/JRE, CPython, libc, libstdc++는 아직 이식되지 않았다.**

ELF 로더는 파일 확장자 대신 실제 ELF 헤더를 검사한다. 아래 자체 ABI와 별도로 `run --linux FILE`에 제한된 Linux ARM64 정적 실행 파일 경로를 추가했다. 두 시스템 호출 번호표를 혼합하지 않는다. [ELF·Linux ABI 매뉴얼](실행파일규약.md).

## ELF와 실행 수명

- ELF64 little endian, ET_EXEC, EM_AARCH64, 버전 1, e_flags=0.
- 프로그램 헤더 최대 16개. PT_LOAD는 읽기 가능, 4 KiB 정렬, 페이지 간 중첩 없음, filesz≤memsz, 이미지 주소 범위 안이어야 한다. W+X는 거부한다.
- 진입점은 파일 내용이 있는 실행 세그먼트 안의 4바이트 정렬 주소다.
- PT_NOTE에 Nòm `JKOROS\0`(namesz=7), type=1, descsz=4, 버전 1의 little endian uint32가 필요하다. SDK의 `start.o`가 넣는다.
- PT_DYNAMIC/PT_INTERP/PT_TLS 등은 거부한다. 동적 재배치·공유 라이브러리·TLS 로더가 없다.
- 커널에 포함한 ELF 묶음을 검증하고 별도 사용자 메모리에 복사한 뒤 EL0로 진입한다. 커널에 함수로 정적 링크해 호출하는 이전 `cpp_test`와 다르다.
- 내장 프로그램은 `demo.elf`, `fault.elf`의 8개 보호 시험 모드, `network.elf`, 자체 Java 도구, MicroPython이다. 셸의 `load`/`run FILE`로 RAM의 16KiB 이하 ELF도 같은 검증 경로로 실행한다.
- `_start`가 `user_start`를 호출하고 `.init_array` → `사용자시작(int)` → `.fini_array` 순서로 실행한 뒤 exit 호출을 수행한다. 인수는 호출 15로 읽으며 표준 argc/argv/envp 스택 배치는 없다.
- 한 번에 한 사용자 프로그램이 CPU에서 실행된다. 네 터미널에 각 하나씩 대화형 프로그램을 일시 정지해 보관할 수 있다. 정상 종료·예외·시간 초과 시 커널에 복귀하고 열린 파일/소켓을 닫으며 사용자 페이지 권한을 제거한다.
- 정적 생성자와 자동 객체의 RAII 소멸자를 시험했다. `__cxa_atexit`, 표준 C++ 예외/RTTI/STL, 일반적인 전역 객체 종료 등록은 제공하지 않는다.

## 주소와 보호

| 가상 주소 범위 | 용도 |
|---|---|
| 0x02000000–0x02bfffff | ELF 이미지, 최대 12 MiB |
| 0x02c00000–0x02ecffff | brk 힙, 최대 2880 KiB |
| 0x02ed0000–0x02efffff | 미매핑 구간/스택 아래 보호 구간 |
| 0x02f00000–0x02ffffff | 1 MiB 사용자 스택 |

자체 JVM의 클래스·객체 자료를 수용하도록 사용자 창을 16 MiB로 확장했다. 프로그램 헤더의 허용 범위, 페이지 권한 검사, SDK 링커 스크립트 및 보호 시험이 같은 배치를 사용한다. 기존에 brk 시작 주소를 상수로 가정한 프로그램은 새 SDK로 다시 빌드한다. 일반 프로그램은 호출 8로 현재 brk를 조회한다.

실행 코드는 EL0 읽기/실행만, 자료·힙·스택은 EL0 읽기/쓰기만 허용한다. 나머지 커널 RAM·장치 MMIO에는 EL0 권한을 주지 않는다. 이번 W^X 보장은 **사용자 페이지에 대한 것**이다. kernel identity map의 전체 권한 분할이나 다중 프로세스 주소 공간 전환을 구현했다고 의미하지 않는다.

커널은 `-mgeneral-regs-only`로 빌드한다. 사용자 C/C++는 FP/SIMD를 허용하고, 사용자 진입 시 벡터 레지스터와 FPCR/FPSR를 초기화한다. 커널 복귀용 callee-saved FP 상태를 보관한다. syscall/IRQ의 C 처리부는 FP 레지스터를 사용하지 않는다. 향후 여러 사용자 스레드를 전환할 때에는 각 스레드의 전체 FP 문맥 보존을 별도로 구현해야 한다.

GIC-400의 물리 타이머 IRQ로 약 2초의 실행 기한을 적용한다. SVC 없는 무한 반복도 종료한다. 시스템 호출 시작 시 기한을 검사하지만 EL1 처리 중에는 IRQ를 마스킹하므로 긴 출력/그리기 호출의 종료는 지연될 수 있다. 이것은 프로그램 실행 기한이며 일반 선점 스케줄러가 아니다.

## 시스템 호출

`svc #0`, 번호 x8, 인수 x0…x5, 결과 x0. 실패는 음수 Eror 번호다. `libposix-kor-user.a`는 이를 -1과 `오류번호`로 바꾼다. 사용자 프로그램의 errno는 현재 단일 실행 흐름용이며 pthread TLS가 아니다.

| 번호 | 호출 | 인수 |
|---:|---|---|
| 0 | ABI 버전 | 없음, 1 반환 |
| 1 | write | fd, buffer, count |
| 2 | read | fd, buffer, count |
| 3 | open | NUL 종료 경로, flags; mode는 저장하지 않음 |
| 4 | close | 파일 또는 루프백 소켓 fd |
| 5 | lseek | fd, signed offset, origin |
| 6 | exit | 하위 8비트 종료 상태 |
| 7 | 밀리초 | 부팅 후 32비트 카운터; wrap 가능, POSIX clock_gettime 아님 |
| 8 | brk | 0이면 현재 끝, 그 외 새 끝; 매핑 확장 시 새 페이지 초기화 |
| 9 | 파일 크기 | fd; fstat ABI 아님 |
| 10 | ftruncate | fd, length |
| 11 | unlink | NUL 종료 경로 |
| 12 | fsync | fd; RAM 파일은 ENOSYS |
| 13 | 사각형 | x, y, RGB32 값, width, height |
| 14 | UART 바이트 | 입력 없음은 -1, POSIX read와 별도 보조 호출 |
| 15 | 실행 인수 | index, buffer, capacity; index=UINTPTR_MAX이면 개수, 나머지는 UTF-8 길이 반환 및 NUL 종료 복사 |
| 16 | 대화형 tty | 0: 시작/현재 행·열 반환, 1: 입력 대기(자료 없음 -11), 2: 종료, 3: 현재 크기 조회(상위 16비트 행, 하위 16비트 열) |
| 17 | 협력 대기 | 밀리초(0~100); 통신·FTP를 처리하며 CPU 기한 갱신 |
| 18 | 경로 작업 | NUL 종료 경로, 동작(0: 종류, 1: mkdir, 2: rmdir); 종류 0: 없음, 1: 파일, 2: 폴더 |

| 22 | 화면 크기 | x0=0: 실제 너비, x0=1: 실제 높이; 다른 값은 -EINVAL, 화면 없음은 -ENODEV |
| 32 | socket | domain, type, protocol |
| 33 | bind | fd, sockaddr, address length |
| 34 | sendto | fd, buffer, count, flags, sockaddr, address length |
| 35 | recvfrom | fd, buffer, count, flags, peer sockaddr, length pointer |
| 36 | getsockname | fd, sockaddr, length pointer |
| 37 | connect | 연결형 fd, sockaddr, address length |
| 38 | listen | 연결형 fd, backlog; 실제 대기 최대 4개 |
| 39 | accept | 연결형 fd, 0, 0; peer 주소 반환은 아직 없음 |

미지원 호출은 -ENOSYS이다. 모든 사용자 포인터와 해당 페이지의 읽기/쓰기 권한을 확인한다. 파일은 3…18의 프로세스별 서술자를 커널 서술자로 변환한다. 0은 현재 셸의 표준 입력(UART 또는 리다이렉션/파이프), 1은 표준 출력(UART/GUI 또는 리다이렉션/파이프), 2는 UART/GUI 진단 출력이다. UART에 읽을 자료가 없으면 -EAGAIN, 파일/파이프 입력 끝이면 read가 0을 반환한다. 출력은 파일/파이프에서 LF를 그대로 유지하고 UART에서만 CRLF로 표시한다. 파이프는 16 KiB 순차 버퍼이며 프로세스 간 동시 파이프/PTY는 아니다. read/write 요청은 65536바이트 이하이며, RAM 파일은 최대 64개, 각각 16384바이트다. 파일 경로는 현재 셸 경로에 대한 상대 경로 또는 `/`로 시작하는 절대 경로이며 UTF-8 63바이트까지다. 디렉터리 생성·빈 폴더 제거·종류 조회는 호출 18로도 제공한다. 현재 경로 변경은 셸 내장 cd가 담당한다. 그래픽 요청은 호출 22로 조회한 실제 화면 크기 안의 직사각형만 허용한다. 프레임버퍼 주소 자체는 사용자에게 노출하지 않는다.

힙의 페이지 단위 축소·재확장에서 다시 노출하는 페이지는 0으로 만든다. 같은 페이지 안에서 brk만 줄였다 늘리는 경우에는 해당 페이지 내용이 남을 수 있다. malloc/free나 mmap/mprotect의 구현은 아니다.

인수는 최대 8개·각 255바이트다. 잘못된 번호는 -EINVAL, 작은 버퍼는 -ENAMETOOLONG, 쓰기 불가능한 포인터는 -EFAULT다. `run FILE [ARGS]`는 파일명을 인수 0으로 포함한다. `javac`/`java`/`python`은 명령어 자체를 제외한 토큰을 전달한다. 인수는 커널 보관 자료를 사용자 버퍼로 복사하며 커널 포인터를 반환하지 않는다.

## UDP 루프백의 계약

바깥 IPv4는 lwIP/SLIP로 확장했다. 기존 fd/구조체/포인터 검사 규약을 유지하며 0.0.0.0 또는 10.0.2.15에 bind한 끝점을 바깥 통신에 연결한다. 127.0.0.1에 명시적으로 bind한 UDP는 루프백에 한정한다. 외부 TCP connect는 비차단 -EINPROGRESS(-115)를 반환할 수 있으므로 같은 주소로 재시도하여 완료를 확인한다. [실행/제한](파일전송과번역.md).

`인터넷주소갈래`, `전문통신`, 전송규약 0/`전문전송규약`을 허용한다. `struct 인터넷통신주소`는 16바이트이며 주소갈래는 장치 차례, 접속번호와 인터넷주소.주소값은 망 차례다. 호환용 pk_sockaddr_in도 같은 배치지만 독립 자료형이다. 한국어 함수는 직접 SVC를 호출하는 실제 함수이며 표준 이름으로 치환하는 매크로가 아니다. 호스트 Linux 헤더를 섞지 않는다.

- 목적지는 127.0.0.1만 허용. bind는 0.0.0.0 또는 127.0.0.1, port=0이면 49152…65535에서 빈 창구를 고른다.
- 미바인드 소켓의 첫 전송은 임시 창구를 바인드한다. 같은 창구의 중복 bind는 EADDRINUSE.
- 최대 8개 소켓, 각 큐 4개, 전문은 0…512바이트. 빈 전문도 소비된다.
- 수신 버퍼가 작으면 복사할 부분만 반환하고 전문의 나머지는 버린다. peer 주소/창구를 반환한다.
- flags는 현재 0만 지원. 비차단 수신의 빈 큐 및 송신 대상 큐 포화는 EAGAIN이다.
- 대상 창구 없음은 ECONNREFUSED, 512바이트 초과는 EMSGSIZE, 루프백에 명시적으로 바인드한 UDP의 외부 IP는 ENETUNREACH, UDP 소켓에 잘못된 규약을 지정하면 EPROTONOSUPPORT. SOCK_STREAM은 별도 연결형 루프백에서 제공한다.
- 외부 IPv4 TCP/UDP 헤더·체크섬·재전송은 lwIP가 처리한다. 실제 GENET/Wi-Fi NIC, poll/select, setsockopt는 아직 없다. 연결형 루프백의 connect/listen/accept는 아래 확장 ABI로 제공한다.

## 커널로 돌아오는 결과

Java의 `보드.사용자실행(index)`는 정상 exit 상태 0…255 또는 다음 값을 받는다. GUI는 실패를 표시하고 셸을 유지한다.

| 값 | 의미 |
|---:|---|
| -8 | ELF/ABI/주소/권한 검증 실패 |
| -16 | 사용자 프로그램 중첩 실행 거부 |
| -22 | 등록되지 않은 프로그램 번호 |
| -1001 | 사용자 자료 접근 예외 |
| -1002 | 사용자 명령어 접근 예외 |
| -1003 | 특권/미지원 명령 등 사용자 예외 |
| -1004 | 사용자 실행 기한 초과 |
| -1005 | 대화형 사용자 프로그램 일시 정지; 커널 셸 전용 결과 |

이는 완성된 POSIX signal/wait 상태가 아닌 현재 자체 실행기의 진단 규약이다.


## 여러 터미널의 사용자 문맥

대화형 tty/GUI 대기를 명시적으로 시작한 프로그램은 입력 대기에서 약 2초 기한을 갱신한다. 대기 없이 무한 반복하면 타이머로 종료한다. 파이프/리다이렉션/복합 명령/스크립트에서 대화형 시작은 -ENOTSUP로 거부한다. vi와 Swing의 이벤트 루프가 이 API를 사용한다.

다른 창으로 전환하면 다음 대기 SVC에서 EL0 문맥을 저장하고 해당 SVC를 재실행할 위치에서 재개한다. x0…x30, SP/PC/PSTATE, v0…v31, FPCR/FPSR, 매핑·힙·실행 인수·파일/소켓 소유권을 보관한다. 스냅샷은 커널 전용 물리 주소 0x04000000…0x07ffffff(네 슬롯 ×16 MiB)에 저장한다. 현재 활성 EL0 주소 창은 종전 0x02000000…0x02ffffff를 사용한다. 스냅샷 저장소는 EL0에서 접근할 수 없다. fork/exec/wait, SMP 또는 일반 선점형 프로세스 스케줄러의 구현은 아니다.

SVC 40은 소유한 연결형 소켓의 상대 포트 번호를 반환한다(자체 JVM용 정수 조회).

연결형 루프백 fd는 40…55, UDP fd는 32…39다. 종료/터미널 X 닫기에서 해당 프로그램의 파일·소켓을 회수한다. 연결형 읽기의 자료 없음은 -EAGAIN, 상대가 닫고 버퍼도 비면 0, 상대가 닫힌 뒤 쓰기는 -EPIPE다. 쓰기는 짧게 완료될 수 있다. 큐 용량은 끝점마다 1024바이트이고 한 시스템 호출은 최대 512바이트를 옮긴다. 부모 리스너를 닫으면 아직 accept하지 않은 연결도 회수한다. 외부 연결은 lwIP TCP를 사용하며 외부 수신 버퍼는 4096바이트다. 실제 GENET NIC 드라이버는 없다.

협력 대기(17)는 일반 선점형 sleep/scheduler 구현이 아니다. 호출마다 최대 100 ms 동안 통신을 처리하고 사용자 실행 기한을 갱신한다. 꾸러미 설치기의 비차단 TCP 대기에 사용한다.
