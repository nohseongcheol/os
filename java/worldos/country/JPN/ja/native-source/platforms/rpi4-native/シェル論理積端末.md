# 内蔵 커널의 GUI 터미널과 シェル

이 터미널은 内蔵 Java 커널의 셸을 프레임버퍼 창과 UART에서 사용한다. 命令 プロセス値入口·RAM ファイル·파이프는 Java 中核値, 화면의 文字値 그리기는 freestanding C에서 수행한다. Linux·X11·Bash 없이 동작하며, 内蔵 JVM의 Swing 支援値 부분집합도 같은 窓 시스템을 이용한다. 자세한 vi·다중 窓·코딩 사용법은 [開発 매뉴얼](開発手引.md)을 참고한다.

## 現在項目 컴퓨터에서 命令実行

```sh
cd /home/user/jkoros/platforms/rpi4-native
make desktop
```

Remmina에서 **VNC**, 番地 **127.0.0.1:5902**로 연결한다. 端末 창은 자동으로 열린다. 연결한 VNC 창에 키를 입력하면 内蔵 커널의 셸로 전달된다. 종료하려면 `make desktop`을 실행한 ホスト 터미널에서 Ctrl+C를 누른다. 포트를 바꾸려면 システム構築 後続側状況 `python3 道具/命令実行.py --desktop --port 5903`을 사용한다. 서버는 localhost에만 바인드하며 동시에 한 클라이언트가 제어한다.

일반 UART 셸은 `make run`으로 시작한다. QEMU 종료는 Ctrl+A 次回項目 X이다. 같은 VM의 UART에서 `terminal` 또는 F12로 GUI 터미널을 列値 数 있다. `gui` 命令実行 화면에서는 다섯 번째 **OPEN TERMINAL** 버튼, 桁値 5 또는 T로 연다. `--vnc 127.0.0.1:2`만 사용한 기존 命令実行 방식은 画面 보기용이며, VNC 키보드를 연결하려면 `--desktop`을 사용한다.

FTP와 外部値 네트워크도 함께 쓰려면 `python3 道具/命令実行.py --desktop --network`로
실행한다. Remmina VNC는 `127.0.0.1:5902`, 게스트에서 `ftpd start` 後続側状況 FTP는
`127.0.0.1:2121`이다. `--port`, `--ftp-port`, `--forward`를 함께 지정할 数 있다.
한 VM의 補助値 UART로 SLIP를 전송하고 주 UART로 GUI 입력을 전달한다.

QEMU 命令実行 도구가 VNC 키보드/마우스를 UART 입력으로 변환한다. 実際データ Pi4의 USB 키보드·마우스 드라이버를 구현한 것은 아니다. 実際データ 보드에서는 現在項目 UART 입력이 필요하며 物理機器 부팅은 아직 미검증이다.

## 창과 入力値

- 640×480~1920×1080 화면에서 最大値 네 개 端末 窓, 既定値 568×360(68열 × 19행)과 直近値 160행 値保持, 既定値 ANSI 画素色·カーソル値·入口消去処理 プロセス値入口.
- 상단 **+ New terminal** 또는 Ctrl+Shift+T로 새 창을 연다. 제목줄을 끌어 이동하고 窓/상단 버튼을 클릭하거나 F6으로 전환한다. 각 창의 作業 経路·変数値·命令 履歴記録記録·入力値 중인 줄은 독립적이다.
- UTF-8 ハングル文字列·CJK·라틴 문자와 일부 이모지 비트맵 書体値. 복잡한 文字 조판·結合処理値一覧 文字·양방향 連結配置·모든 Unicode 글리프를 보장하지 않는다.
- 좌우 방향키/Home/End/Delete/Backspace로 명령을 편집하고 위아래 방향키로 直近値 16개 명령을 찾는다. 긴 명령은 入力値 줄을 가로로 이동해 보여 주며 `<`, `>`先頭位置被演算子 숨겨진 부분을 나타낸다.
- Tab은 命令 名前 또는 現在項目 디렉터리의 파일명에서 후보가 하나일 때 완성한다. 디렉터리를 포함한 経路 접두사·引用 안의 완성은 아직 없다.
- Ctrl+A/E: 初期項目/終端, Ctrl+U/K: カーソル値 前面値/後端値 삭제, Ctrl+C: 入力値 取消処理操作. 命令実行 중인 임의 프로그램에 SIGINT를 보내는 기능은 없다. vi와 Swing의 入力値 대기는 命令実行 기한을 갱신하지만 일반 계산의 약 2초 제한은 유지한다.
- PgUp/PgDn 또는 마우스 휠: 前回項目 出力. 새 출력이 오면 最新値 위치로 돌아온다.
- F12/表題棒 右 버튼/`exit`: 窓 閉鎖. 빈 입력에서 Ctrl+D도 창을 닫는다. VM을 종료하는 명령은 아니다.

`--desktop`의 VNC 入力値 연결에 **두벌식 ハングル文字列 組合せ**을 제공한다. 접속한 PC의
입력기를 영어로 두고 **F9**, **Shift+Space**, **한/零被演算子 キー値** 중 하나를 누르면
窓 제목이 `[EN]`에서 `[KO]`로 바뀐다. `gksrmf` → `ハングル文字列`,
`dkssudgktpdy` → `안녕하세요`. 같은 키로 영어로 돌아간다.
겹받침·복합 모음과 組合せ 단계별 Backspace를 지원한다. カーソル値 移動値·마우스 クリック値·
단축키·貼付け値·Enter 때 조합을 확정한다. PC가 Shift+Space나 한/零被演算子 키를
内蔵 처리하면 **F9**를 사용한다. Alt 단독은 切替方式 키가 아니다.

이 조합기는 QEMU의 VNC→UART 入力値 연결에서 실행된다. 일반 直列値 접속과
物理機器 Pi의 USB 키보드 입력기에 추가된 기능은 아니다. 이미 완성된 Unicode
ハングル文字列 키도 그대로 전달한다. 클립보드 공유가 활성화되어 표준 VNC ClientCutText가
도착하면 Ctrl+Shift+V로 붙여 넣는다. 클립보드 동기화만으로 명령을 실행하지 않는다.
줄바꿈을 포함해 명시적으로 붙여 넣으면 해당 줄이 실행된다.

게스트에서 `help` 또는 `help ko`를 입력하면 ハングル文字列 入力値 안내를 볼 数 있다.
`help`와 `help ko`에는 한/零被演算子 キー値·Shift+Space·F9 및 `[EN]`/`[KO]` 안내를 표시한다.
긴 도움말은 PgUp/PgDn으로 스크롤한다.

터미널에서 Java·Python·C++ 命令実行 결과를 바로 볼 数 있다. 프로그램이 직접 프레임버퍼에 그림을 그린 경우 終了点プログラム 後続側状況 端末 창을 복원한다. vi/Swing 値待合 중 다른 창으로 전환하면 해당 EL0 프로그램의 記憶データ·레지스터를 보관하고 돌아올 때 재개한다. 選択状態値 値複写·PTY·전체 VT100/xterm 호환과 임의 프로그램의 동시 병렬 실행은 제공하지 않는다. X로 닫으면 해당 창의 프로그램도 종료되므로 vi에서 저장하지 않은 내용은 사라진다.

## 문법과 上限値

작은따옴표·큰따옴표·백슬래시, `$NAME`/`${NAME}`/`$?`, 語値 前面値 `~`, 行 주석 `#`, 순차 命令実行 `;`, 条件 命令実行 `&&`/`||`, 파이프 `|`, 入力値 `<`, 새 出力 `>`, 入口追記 出力 `>>`를 제공한다. 変数値 확장은 引数 안에서 수행하며 拡張子値 결과를 공백으로 再試行処理値 나누지 않는다. `export`의 값은 シェル 안에서만 공유하며 利用者 ELF의 envp/getenv 환경은 아직 없다.

파이프는 각 단계를 순서대로 실행하고 最大値 **16384바이트**를 次回項目 단계로 넘긴다. 여러 프로세스가 동시에 읽고 쓰는 POSIX 파이프가 아니다. 容積値 초과는 エラー 28과 失敗値 상태를 반환하고 해당 실행을 중단한다. `<`는 EOF를 제공하며 `>`/`>>`는 stdout만 바꾼다. EL0 fd 2는 画面/UART로 출력된다. `2>` 등 번호를 붙인 리다이렉션은 거부한다. 일부 내장 명령의 진단은 stdout을 사용한다. 연결한 프로그램의 `exit N` 진단은 데이터에 섞이지 않도록 생략한다.

`vi`, `edit`, `load`, `gui`, `terminal`, `sh`, `source`에는 파이프와 리다이렉션을 적용할 数 없다. 리다이렉션 파일을 열지 못하거나 파이프 용량을 초과하면 現在項目 명령줄을 중단하며, 그 줄의 뒤쪽 `||` 명령도 실행하지 않는다. スクリプト値 파일을 입력할 때 멀티라인 引用·継続状態値 쓰기는 제공하지 않는다. `if`/`for`/`while`, 関数, 命令 치환, glob, 代替用名前, 백그라운드 `&`, jobs/fg/bg, 일반 프로세스·신호·PTY는 아직 없다. Bash/POSIX sh 전체 호환으로 표시하지 않는다.

ファイル 64개 × 각 16384바이트, 루트 외 디렉터리 15개, ファイル 記述子入口 16개, 経路 最大値 UTF-8 63바이트다. 通信相手値/절대 경로와 `.`/`..`를 정규화하지만 許可値·심볼릭 링크·마운트·디스크 영속 저장은 없다. **ファイル·디렉터리·変数値·기록의 値改変 내용은 재부팅하면 사라진다.** 利用者 실행도 現在項目 シェル 경로를 사용한다. Java/Python/C++의 ファイル API는 같은 RAM 저장소를 본다. `/example`의 三値 言語 예제와 설명서는 부팅할 때 원본으로 준비된다.

한 명령줄은 4096바이트, 구문 トークン値 128개, 命令実行 引数 32개, 변수는 16개(名前 31바이트·値 255바이트)까지다. 利用者 프로그램에 전달하는 인수는 기존 ABI대로 最大値 8개·각 255바이트다. 命令 기록은 1024바이트 이하 줄을 直近値 16개까지 저장한다.

make test-shell

## 마우스로 容量 値変更

네 모서리의 안쪽 8픽셀에 마우스를 대면 방향에 맞는 대각선 양방향 포인터가
나타난다. **左側面 버튼을 누른 채 끌고 놓는다.** 右 버튼으로는 크기가 바뀌지 않는다.
窓表題 표시줄의 剰余値 부분은 移動値, 右 上端値 X는 닫기다.
最小値 크기는 360×216이며 最大値 크기는 現在項目 画面 안에 제한된다.
각 창의 文字値 칸은 `(幅跨域-24)/8`列値, `(高さ値-56)/16`행이다. `terminal size`로 조회한다.

명령줄의 入力値·カーソル値·기록과 vi의 미저장 문서를 유지하며 보이는 영역을 갱신한다.
지난 출력은 저장된 行 단위를 유지하고, 좁아진 창에서 가려진 열은 再試行処理値 넓히면
볼 数 있다. 과거 出力 전체를 새 너비에 맞춰 재배열하는 기능은 아니다.
크기를 바꾼 後端値 출력되는 글은 새 列値 수로 줄바꿈한다. vi는 入力値 値待合 중에도
SVC 16의 動作 3으로 現在項目 容量(상위 16비트 行番号値, 하위 16비트 列値)를 조회한다.
対話式 tty의 中核値 画面 出力 시간은 利用者 計算結果 기한에서 제외하며, 入力値 値待合 없이
계산만 반복하는 利用者 프로그램의 時間値 제한은 유지한다.
커널이 프레임버퍼에 포인터를 그리며, Remmina 중계는 遠隔値 포인터를 숨겨 중복을 피한다.
로컬 VNC 중계는 既定値 Raw 인코딩을 사용한다.

妥当性検査: `make test-resize` — 640×480·1920×1080에서 네 隅値, 左側面/右 버튼,
最小値·最大値 容量, ポインタ 복원, 入力値 보존, vi 格納値·継続処理工程 入力値, 창별 크기를 확인한다.
