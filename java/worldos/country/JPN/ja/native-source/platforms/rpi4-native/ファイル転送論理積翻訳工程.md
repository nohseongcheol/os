# 内蔵 ARM64 中核値: FTP, C, JAR와 AOT 命令実行

대상은 **Linux를 적재하지 않는 Raspberry Pi 4용 Java AOT 中核値**이다. CPU·装置 경계는 C/어셈블리, ファイル 체계와 셸은 Java이며, 이번 TCP/IP 스택은 C로 작성된 lwIP 2.2.0을 이식했다. 게스트 TinyCC와 `jaot`도 EL0에서 실행한다. 호스트에 컴파일을 요청하거나 ホスト JVM으로 대신 실행하지 않는다.

## 먼저 알아둘 支援値 境界位置値

| 要求 | 이번 実装 | 남은 切抜き |
|---|---|---|
| JAR를 命令実行 파일처럼 命令実行 | `java -jar ファイル.jar`, `./ファイル.jar 引数`; Main-Class와 格納値/DEFLATE ZIP, CRC 検査項目 | 전체 Java SE, 임의의 모든 JAR 호환성 |
| 게스트 AOT | `jaot ファイル.class -o ファイル.elf`, `jaot ファイル.jar -o ファイル.elf`; 実際データ ARM64 기계어 生成 | オブジェクト値·例外·Thread·Swing·Socket의 AOT 値変換, 여러 애플리케이션 クラス値 接続 |
| C ソースコンパイル | 게스트 `cc`/`tcc`, TinyCC C 전처리기·ARM64 생성기·링커; 日本語 식별자와 posix-kor | 전체 libc, 일반 Linux 命令実行 ファイル, 게스트 C++ コンパイラ |
| 업로드한 ELF 命令実行 | ELF64/AArch64 헤더 検査項目, 확장자 없는 `./ファイル`; 内蔵 ABI 및 명시적인 제한형 Linux ABI | 일반 Linux 바이너리 호환, 동적 링커, 공유 ライブラリ |
| 外部値 TCP/UDP | 게스트 lwIP IPv4 被演算子スタック, POSIX 소켓과 JVM의 桁値 IPv4 番地 | GENET/Wi-Fi 드라이버, DHCP·DNS·TLS, 物理機器 基板 네트워크 試験 |
| FTP | 게스트 서비스, 패시브 転送値, UTF-8 名前, STOR/RETR/SIZE/LIST/NLST/MLSD/DELE | TLS·사용자별 許可値·하위 디렉터리·영속 格納値 |
| ハングル文字列 Java | 기존 `日本語.内蔵` 클래스와 外部値 番地 UDP 오버로드 | 전체 JDK의 일대일 日本語 対応付け値 API |

JVM은 クラス値 버전 45…52의 문서화한 부분집합이다. `java`는 バイトコード 실행기이고, `jaot`先頭位置被演算子 별도의 네이티브 命令実行 파일을 만든다. **JAR 書庫値 해제나 JVM을 함께 묶는 것을 AOT라고 표시하지 않는다.** 지원하지 않는 バイトコード/API는 `jaot`先頭位置被演算子 진단하고 출력을 만들지 않는다. 기존 出力 ELF도 ソースコンパイル 失敗値 때 보존한다.

Android의 Dalvik/ART는 일반 JVM クラス値/JAR가 아닌 **DEX**를 실행한다. ART의 AOT에는 GC, クラス値 로딩, JNI 등 命令実行 기반도 필요하다. 따라서 ART처럼 기계어로 바꾸는 기능만으로 임의의 OpenJDK JAR 및 Swing이 자동 호환되지는 않는다. [Android 공식 런타임 説明](https://source.android.com/docs/core/runtime)

FTP는 루트 RAM 파일만 공개한다. 익명 로그인이며 비밀번호로 권한을 구분하지 않는다. 既定値 ホスト 바인딩은 `127.0.0.1`이고, 制御値 포트는 2121, 데이터 포트는 50000…50007이다. `--ftp-port 2122`로 制御値 포트를 바꿀 数 있다. 동시에 한 FTP 세션을 제공하며 명령이 없는 세션은 60초 後続側状況 닫는다. TYPE A도 바이트를 변경하지 않으므로 프로그램은 바이너리 전송한다.

파일은 **64개, 각각 16 KiB**, 경로는 UTF-8 63바이트이다. 起動 시 준비되는 `/example`도 이 한도를 공유한다. 초과/끊어진 STOR는 기존 파일에 반영하지 않는다. FTP 업로드는 RAM에만 저장되며 재부팅하면 사라진다. 이 上限値 때문에 일반적인 대형 JAR 배포판을 그대로 올릴 数 없다.

QEMU의 raspi4b에는 GENET Ethernet 장치가 없다. 따라서 `network_bridge.py`先頭位置被演算子 QEMU NAT의 Ethernet과 補助値 UART의 SLIP를 변환한다. **TCP 接続 プロセス値入口·체크섬·재전송·FTP 명령과 ファイル 저장은 게스트 안에서 수행한다.** ホスト 브리지는 FTP 서버가 아니다. [QEMU 공식 装置 支援値 入口一覧](https://www.qemu.org/docs/master/system/arm/raspi.html)

이 경로는 QEMU에서 검증했다. 補助値 UART의 実際データ Pi 4 핀/클럭 설정과 내장 RJ45 GENET 드라이버는 実装·검증하지 않았으므로, SD 이미지에 커널이 포함되어 있다는 사실을 実際データ 보드의 LAN/FTP 動作 보장으로 해석하면 안 된다.

## 日本語 Java를 게스트에서 컴파일하고 AOT 命令実行

게스트 `vi 色.java`로 次回項目 소스를 작성한다.

```java
public class 色 {
    public static void main(String[] 引数) throws Exception {
        int 総和値 = 0;
        int 数 = 1;
        while (数 <= 10) {
            総和値 = 総和値 + 数;
            数 = 数 + 1;
        }
        日本語.内蔵.出力.番号書込(総和値);
        日本語.内蔵.ファイル.書込("aot.txt", "ハングル文字列 AOT ファイル 😀");
        日本語.内蔵.出力.行書込(日本語.内蔵.ファイル.読取("aot.txt"));
    }
}
```

```text
javac 色.java
java 色
jaot 色.class -o 色.elf
run 色.elf
```

`jaot`은 클래스의 바이트코드를 C로 변환하고, **게스트 TinyCC**先頭位置被演算子 ARM64 명령어를 生成·연결한다. 命令実行 때 JVM 인터프리터를 호출하지 않는다. JAR의 Main-Class가 같은 支援値 범위이면 다음도 가능하다.

```text
jaot 色.jar -o 色.elf
run 色.elf
```

AOT 지원은 한 애플리케이션 클래스의 静的値 メソッド値/フィールド値, int 계열, 整数値 배열과 参照, 引数 配列値, 条件·分岐·反復回値, 文字列 리터럴, `System.out.print/println`의 int/String, 日本語 出力·ファイル 読取/쓰기로 제한된다. クラス値/メソッド値 수와 被演算子スタック 등에도 고정 상한이 있다. Java 例外 プロセス値入口, オブジェクト値 生成, 가상 メソッド値 일반, switch/wide, long/float/double, invokedynamic, 文字列 결합용 StringBuilder, 일반 JDK·Socket·Thread·Swing은 이 AOT 백엔드에서 미지원이다. 내장 NUL/고립된 서로게이트 문자열도 거부한다. 잘못된 配列値 アクセス入口/0으로 除算処理値一覧 등은 네이티브 런타임 오류로 종료하며 Java 例外 객체로 전달하지 않는다.

入力値 클래스뿐 아니라 **생성된 ELF도 16 KiB 이하**여야 한다. 기계어 확장과 ELF 페이지 整列値 때문에 짧은 클래스도 이 한도를 넘을 数 있으며, 이 경우 오류를 내고 기존 출력을 보존한다.

게스트 `javac`도 부분집합이다. 일반적인 オブジェクト値·Thread·Swing 소스는 호스트에서 `javac --release 8`로 컴파일하고, **기존 JVM의 支援値 切抜き 안에서** `java`/`java -jar`로 실행한다. 정확한 API는 [JVM 매뉴얼](Java実行環境環境.md)과 [ハングル文字列 開発 매뉴얼](開発手引.md)을 참고한다.

JAR는 하나의 애플리케이션 クラス値 경로다. 내부 名前 `パッケージ/プログラム.class`와 점으로 구분한 Main-Class를 지원한다. 내부 클래스는 파일로 풀어 VFS 슬롯을 소비하지 않는다. 내장 日本語 클래스를 추가로 찾지만 現在項目 作業 폴더의 다른 클래스는 자동 혼합하지 않는다. ZIP64·データ暗号化 ZIP·manifest Class-Path·서명 검증은 지원하지 않는다. JAR 하나가 16 KiB 이하이어도 클래스당/적재 数/VM ヒープ値 제한은 그대로 적용된다.

## C에서 日本語 POSIX 呼出

게스트에서 `vi 挨拶例.c`로 작성하거나 FTP로 소스를 업로드한다.

```c
#include <ファイルABI.h>

int main(void) {
    const char 挨拶文[] = "内蔵 ARM64 C에서 ハングル文字列 POSIX 呼出\n";
    int 文書 = ファイル開放("挨拶例.txt", 読取書込 | 作成条件未存在 | 切詰め内容, 0600);
    if (文書 < 0) return 1;
    入出力結果型 記録済み個数 = ファイルデータ書込(文書, 挨拶文, sizeof(挨拶文) - 1);
    ファイル閉鎖(文書);
    ファイルデータ書込(1, 挨拶文, sizeof(挨拶文) - 1);
    return 記録済み個数 == sizeof(挨拶文) - 1 ? 0 : 2;
}
```

```text
cc 挨拶例.c -o 挨拶例.elf
run 挨拶例.elf
cat 挨拶例.txt
```

TinyCC의 표준 C 入口点 `main`을 사용한다. 기존 ホスト C/C++ SDK의 `利用者プログラム開始処理(int)` 진입점과 구분한다. ヘッダー ファイル·起動処理 オブジェクト値·`libposix-kor-user.a`는 コンパイラ 내부의 読取 전용 SDK에 들어 있다. C 전처리기/구조체/関数/재귀/ポインタ/부동소수점 生成 등을 사용하되 **일반 libc/libstdc++를 제공한다는 뜻은 아니다**. 제공하지 않는 함수는 接続 오류가 난다. コンパイラ 자체의 文字/桁値 値変換 지원도 완전한 libc 대체품이 아니다.

`ファイル開放` 등은 별도의 모의 호출이 아닌 기존 `pk_open` 등의 日本語 매크로이며, ELF의 SVC를 통해 実際データ Java ファイル 체계에 도달한다. ファイル/ソケット値 呼出 목록은 [利用者 ABI](利用者呼出しABI.md)에 있다. C/C++ ホスト SDK 命令実行 파일도 FTP로 업로드 後続側状況 `run` 또는 `./ファイル`로 실행하며 확장자는 必要値 없다. Linux ARM64 静的値 ELF에는 별도의 제한된 호환 経路 `run --linux ファイル`을 추가했다. [ELF·Linux ABI 매뉴얼](実行形式ABI.md)에 정확한 書式値·시스템 呼出·番地 제한을 정리했다.

## 日本語 네트워크·作業·画面 API

| クラス値 | 呼出 예 | 命令実行 経路 |
|---|---|---|
| `出力` | `行書込("안녕")`, `番号書込(42)` | JVM 및 제한형 AOT |
| `ファイル` | `書込("文書.txt", "内容物値")`, `読取("文書.txt")` | JVM 및 제한형 AOT |
| `通信` | `開放(0)`, `送信(通信端点, "10.0.2.2", 9000, "ハングル文字列")`, `受取(通信端点)` | JVM의 UDP |
| `接続状態輸送` | `接続("10.0.2.2", 9000)`, `通信端点接続待機(9000)`, `受取(サーバー値)` | JVM의 Socket/ServerSocket |
| `作業` | `起動処理(Runnable)`, `待機(Thread)`, `作業実行権譲渡()` | JVM의 협력식 スレッド値 |
| `窓`, `操作部品` | 窓·버튼·文字値·本文フィールド·イベント 接続 | JVM의 Swing 부분집합 |

명명에서는 표준 영어 API를 보존하고 日本語 呼出 계층을 추가한다. `通信(通信)`, `接続(連結)`, `出力(出力)`은 기존 단어의 뜻을 사용한다. `作業 スレッド値`은 한 命令実行 흐름을 가닥에 빗댄 記述子値 표현, `ポート値`는 포트의 접점을 설명하는 표현이다. 새 記述子値 결합어를 고대에 이미 존재한 용어처럼 설명하지 않는다. 전체 JDK의 번역을 완료했다고 표시하지 않는다.

外部値 주소는 桁値 IPv4이며 QEMU 호스트는 `10.0.2.2`, 게스트는 `10.0.2.15`第三被演算子. UDP 전문은 512바이트까지다. 소켓은 비차단 内蔵 ABI이며 JVM이 제한된 値待合/재시도를 제공한다. TCP connect 대기는 最大値 1초, 利用者 プログラム 전체에는 기존 약 2초 CPU 기한이 적용된다. 일반적인 장기 命令実行 利用者 서버와 pthread는 아직 없다. FTP는 利用者 プログラム 기한과 별개인 中核値 서비스다.

게스트의 利用者 TCP/UDP 서버로 들어오는 연결은 NAT 포트를 추가한다. 예를 들어 `python3 道具/命令実行.py --network --forward tcp:9300:9300 --forward udp:9301:9301`로 실행하면 호스트의 localhost 9300/TCP·9301/UDP를 게스트의 같은 포트로 전달한다. FTP의 既定値 制御値/데이터 포트와 겹치면 命令実行 전에 거부한다.

## 시험과 システム構築 재현

```sh
cd /home/user/jkoros/platforms/rpi4-native
make test-ftp
make test
make image
```

`build/verification/ftp/report.json`은 実際データ FTP 転送値, ハングル文字列 ファイル, 容量 초과 보존, 書庫値 JAR 命令実行, 게스트 C ソースコンパイル/ELF 재업로드, 外部値 Java TCP/UDP, 게스트 javac/AOT 실행을 기록한다. `serial.log`에서 게스트 명령과 결과를 확인할 数 있다. 보고서의 中核値 SHA-256과 配布値 이미지의 커널을 비교한다.

빌드는 기존 JDK/Clang/AArch64 binutils와 함께 `../rpi4/build/rootfs`의 ARM64 SDK 宣言 헤더와 libgcc 算術値 補助値 함수를 사용한다(`make rpi-prepare`). **musl libc, Linux 中核値, 동적 로더를 게스트에 링크하지 않는다.** TinyCC/lwIP/uzlib 원본과 라이선스·버전 정보는 `vendor/`, 移植 코드는 `ccompiler/`, `network/`, `利用者/パッケージ.c`에 있다.

전체 JDK/AOT JVM으로 확장하려면 타입 妥当性検査·オブジェクト値/例外/GC·동적 로딩·JNI, 영속 ファイル 稼働システム値·mmap/TLS/시그널·스레드 ABI, OpenJDK native ライブラリ, GUI peer/폰트/입력기, GENET 및 物理機器 装置 검증이 더 필요하다. 이 문서의 命令実行 시험은 그 전체 이식을 대신하지 않는다.
