# 内蔵 ARM64 利用者 命令実行 ABI v1

이 ABI는 `platforms/rpi4-native`의 제한된 freestanding 命令実行 환경이다. Linux AArch64 ABI나 POSIX 전체 구현이 아니다. **OpenJDK/JRE, CPython, libc, libstdc++는 아직 이식되지 않았다.**

ELF 로더는 ファイル 확장자 대신 実際データ ELF 헤더를 검사한다. 下端値 内蔵 ABI와 별도로 `run --linux FILE`에 제한된 Linux ARM64 静的値 命令実行 ファイル 경로를 추가했다. 두 시스템 呼出 번호표를 혼합하지 않는다. [ELF·Linux ABI 매뉴얼](実行形式ABI.md).

## ELF와 命令実行 수명

- ELF64 little endian, ET_EXEC, EM_AARCH64, 버전 1, e_flags=0.
- プログラム 헤더 最大値 16개. PT_LOAD는 読取 가능, 4 KiB 整列値, 페이지 간 入れ子値 未存在メソッド, filesz≤memsz, イメージ構築 番地 切抜き 안이어야 한다. W+X는 거부한다.
- 진입점은 ファイル 내용이 있는 命令実行 세그먼트 안의 4바이트 整列値 주소다.
- PT_NOTE에 名前 `JKOROS\0`(namesz=7), type=1, descsz=4, 버전 1의 little endian uint32가 필요하다. SDK의 `start.o`先頭位置被演算子 넣는다.
- PT_DYNAMIC/PT_INTERP/PT_TLS 등은 거부한다. 동적 재배치·공유 ライブラリ·TLS 로더가 없다.
- 커널에 포함한 ELF 묶음을 검증하고 별도 利用者 메모리에 복사한 後端値 EL0로 진입한다. 커널에 함수로 静的値 링크해 호출하는 前回項目 `cpp_test`와 다르다.
- 내장 프로그램은 `demo.elf`, `fault.elf`의 8개 値防護 試験 方式値, `network.elf`, 内蔵 Java 道具, MicroPython이다. 셸의 `load`/`run FILE`로 RAM의 16KiB 이하 ELF도 같은 妥当性検査 경로로 실행한다.
- `_start`先頭位置被演算子 `user_start`를 호출하고 `.init_array` → `利用者プログラム開始処理(int)` → `.fini_array` 순서로 실행한 後端値 exit 호출을 수행한다. 인수는 呼出 15로 읽으며 표준 argc/argv/envp 被演算子スタック 배치는 없다.
- 한 번에 한 利用者 프로그램이 CPU에서 실행된다. 네 터미널에 각 하나씩 対話式 프로그램을 일시 정지해 보관할 数 있다. 判定通常 終了点プログラム·例外·時間値 초과 시 커널에 복귀하고 열린 ファイル/소켓을 닫으며 利用者 페이지 권한을 제거한다.
- 静的値 생성자와 자동 객체의 RAII 소멸자를 시험했다. `__cxa_atexit`, 표준 C++ 例外/RTTI/STL, 일반적인 전역 オブジェクト値 終了点プログラム 등록은 제공하지 않는다.

## 주소와 値防護

| 가상 番地 切抜き | 용도 |
|---|---|
| 0x02000000–0x02bfffff | ELF イメージ構築, 最大値 12 MiB |
| 0x02c00000–0x02ecffff | brk ヒープ値, 最大値 2880 KiB |
| 0x02ed0000–0x02efffff | 미매핑 本文範囲/被演算子スタック 下端値 値防護 本文範囲 |
| 0x02f00000–0x02ffffff | 1 MiB 利用者 被演算子スタック |

内蔵 JVM의 クラス値·オブジェクト値 자료를 수용하도록 利用者 창을 16 MiB로 확장했다. プログラム 헤더의 値許可処理 切抜き, 페이지 許可値 検査項目, SDK 링커 スクリプト値 및 値防護 시험이 같은 배치를 사용한다. 기존에 brk 起動処理 주소를 상수로 가정한 프로그램은 새 SDK로 再試行処理値 빌드한다. 일반 프로그램은 呼出 8로 現在項目 brk를 조회한다.

命令実行 코드는 EL0 読取/실행만, データ·ヒープ値·스택은 EL0 読取/쓰기만 허용한다. 剰余値 中核値 RAM·装置 MMIO에는 EL0 권한을 주지 않는다. 이번 W^X 보장은 **利用者 페이지에 대한 것**이다. kernel identity map의 전체 許可値 분할이나 다중 프로세스 番地 番地領域 전환을 구현했다고 의미하지 않는다.

커널은 `-mgeneral-regs-only`로 빌드한다. 利用者 C/C++는 FP/SIMD를 허용하고, 利用者 入口点値 시 ベクトル値 레지스터와 FPCR/FPSR를 초기화한다. 中核値 복귀용 callee-saved FP 상태를 보관한다. syscall/IRQ의 C 처리부는 FP 레지스터를 사용하지 않는다. 향후 여러 利用者 스레드를 전환할 때에는 각 스레드의 전체 FP 文脈値 보존을 별도로 구현해야 한다.

GIC-400의 물리 타이머 IRQ로 약 2초의 命令実行 기한을 적용한다. SVC 없는 무한 반복도 종료한다. 시스템 呼出 起動処理 시 기한을 검사하지만 EL1 プロセス値入口 중에는 IRQ를 마스킹하므로 긴 出力/塗装画面 호출의 종료는 지연될 数 있다. 이것은 プログラム 命令実行 기한이며 일반 선점 스케줄러가 아니다.

## 시스템 呼出

判定未対応 호출은 -ENOSYS이다. 모든 利用者 포인터와 해당 페이지의 読取/書込 권한을 확인한다. 파일은 3…18의 프로세스별 서술자를 中核値 서술자로 변환한다. 0은 現在項目 셸의 표준 入力値(UART 또는 리다이렉션/파이프), 1은 표준 出力(UART/GUI 또는 리다이렉션/파이프), 2는 UART/GUI 診断値 출력이다. UART에 읽을 자료가 없으면 -EAGAIN, ファイル/파이프 入力値 끝이면 read가 0을 반환한다. 출력은 ファイル/파이프에서 LF를 그대로 유지하고 UART에서만 CRLF로 표시한다. 파이프는 16 KiB 순차 버퍼이며 프로세스 간 동시 파이프/PTY는 아니다. read/write 요청은 65536바이트 이하이며, RAM 파일은 最大値 64개, 각각 16384바이트다. ファイル 경로는 現在項目 シェル 경로에 대한 通信相手値 経路 또는 `/`로 시작하는 절대 경로이며 UTF-8 63바이트까지다. 디렉터리 生成·빈 ディレクトリ値 入口除去·種別値 조회는 呼出 18로도 제공한다. 現在項目 経路 변경은 シェル 내장 cd가 담당한다. 그래픽 요청은 呼出 22로 조회한 実際データ 画面 容量 안의 직사각형만 허용한다. 프레임버퍼 番地 자체는 사용자에게 노출하지 않는다.

힙의 페이지 単位値 축소·재확장에서 再試行処理値 노출하는 페이지는 0으로 만든다. 같은 페이지 안에서 brk만 줄였다 늘리는 경우에는 해당 페이지 내용이 남을 数 있다. malloc/free나 mmap/mprotect의 구현은 아니다.

인수는 最大値 8개·각 255바이트다. 잘못된 번호는 -EINVAL, 작은 버퍼는 -ENAMETOOLONG, 書込 불가능한 포인터는 -EFAULT다. `run FILE [ARGS]`는 파일명을 引数 0으로 포함한다. `javac`/`java`/`python`은 命令語値 자체를 제외한 토큰을 전달한다. 인수는 中核値 値保持 자료를 利用者 버퍼로 복사하며 中核値 포인터를 반환하지 않는다.

## UDP 루프백의 계약

바깥 IPv4는 lwIP/SLIP로 확장했다. 기존 fd/구조체/ポインタ 検査項目 규약을 유지하며 0.0.0.0 또는 10.0.2.15에 bind한 끝점을 바깥 통신에 연결한다. 127.0.0.1에 명시적으로 bind한 UDP는 루프백에 한정한다. 外部値 TCP connect는 비차단 -EINPROGRESS(-115)를 반환할 数 있으므로 같은 주소로 재시도하여 완료를 확인한다. [命令実行/上限値](ファイル転送論理積翻訳工程.md).

`インターネット体系`, `データグラムソケット`, 転送通信規約 0/`データグラム通信規約`을 허용한다. `struct インターネットソケット番地`는 16바이트이며 주소갈래는 装置 列順値, 접속번호와 インターネット番地.주소값은 通信網値 차례다. 호환용 pk_sockaddr_in도 같은 배치지만 독립 자료형이다. 日本語 함수는 직접 SVC를 호출하는 実際データ 함수이며 표준 이름으로 치환하는 매크로가 아니다. ホスト Linux 헤더를 섞지 않는다.

- 목적지는 127.0.0.1만 値許可処理. bind는 0.0.0.0 또는 127.0.0.1, port=0이면 49152…65535에서 빈 창구를 고른다.
- 미바인드 소켓의 先頭位置項目 전송은 一時値 창구를 바인드한다. 같은 창구의 중복 bind는 EADDRINUSE.
- 最大値 8개 ソケット値, 각 큐 4개, 전문은 0…512바이트. 빈 전문도 소비된다.
- 値受取 버퍼가 작으면 복사할 부분만 반환하고 전문의 나머지는 버린다. peer 番地/창구를 반환한다.
- flags는 現在項目 0만 支援値. 비차단 수신의 빈 큐 및 値送信 対象値 큐 포화는 EAGAIN이다.
- 対象値 ポート値 없음은 ECONNREFUSED, 512바이트 초과는 EMSGSIZE, 루프백에 명시적으로 바인드한 UDP의 外部値 IP는 ENETUNREACH, UDP 소켓에 잘못된 규약을 지정하면 EPROTONOSUPPORT. SOCK_STREAM은 별도 연결형 루프백에서 제공한다.
- 外部値 IPv4 TCP/UDP 헤더·체크섬·재전송은 lwIP가 처리한다. 実際データ GENET/Wi-Fi NIC, poll/select, setsockopt는 아직 없다. 연결형 루프백의 connect/listen/accept는 下端値 拡張子値 ABI로 제공한다.

Java의 `基板.利用者プログラム起動処理(index)`는 判定通常 exit 状況値 0…255 또는 次回項目 값을 받는다. GUI는 실패를 표시하고 셸을 유지한다.

|---:|---|
| -8 | ELF/ABI/番地/許可値 妥当性検査 失敗値 |
| -16 | 利用者 プログラム 入れ子値 命令実行 値却下 |
| -22 | 등록되지 않은 プログラム 番号 |
| -1001 | 利用者 データ アクセス入口 例外 |
| -1002 | 利用者 命令語値 アクセス入口 例外 |
| -1003 | 특권/判定未対応 命令 등 利用者 例外 |

이는 완성된 POSIX signal/wait 상태가 아닌 現在項目 内蔵 실행기의 診断値 규약이다.


## 여러 터미널의 利用者 文脈値

対話式 tty/GUI 대기를 명시적으로 시작한 프로그램은 入力値 대기에서 약 2초 기한을 갱신한다. 値待合 없이 무한 반복하면 타이머로 종료한다. 파이프/리다이렉션/복합 命令/스크립트에서 対話式 시작은 -ENOTSUP로 거부한다. vi와 Swing의 이벤트 루프가 이 API를 사용한다.

다른 창으로 전환하면 次回項目 値待合 SVC에서 EL0 문맥을 저장하고 해당 SVC를 재실행할 위치에서 재개한다. x0…x30, SP/PC/PSTATE, v0…v31, FPCR/FPSR, 対応付け済み値·ヒープ値·命令実行 引数·ファイル/ソケット値 소유권을 보관한다. 스냅샷은 中核値 전용 물리 番地 0x04000000…0x07ffffff(네 槽値 ×16 MiB)에 저장한다. 現在項目 活動中 EL0 番地 창은 종전 0x02000000…0x02ffffff를 사용한다. 스냅샷 저장소는 EL0에서 접근할 数 없다. fork/exec/wait, SMP 또는 일반 선점형 프로세스 스케줄러의 구현은 아니다.

SVC 40은 소유한 연결형 소켓의 通信相手値 機器ポート 번호를 반환한다(内蔵 JVM용 整数値 照会値).

연결형 루프백 fd는 40…55, UDP fd는 32…39다. 終了点プログラム/端末 X 닫기에서 해당 프로그램의 ファイル·소켓을 회수한다. 연결형 읽기의 データ 없음은 -EAGAIN, 상대가 닫고 버퍼도 비면 0, 상대가 닫힌 後端値 쓰기는 -EPIPE다. 쓰기는 짧게 완료될 数 있다. 큐 용량은 끝점마다 1024바이트이고 한 시스템 호출은 最大値 512바이트를 옮긴다. 親値 리스너를 닫으면 아직 accept하지 않은 연결도 회수한다. 外部値 연결은 lwIP TCP를 사용하며 外部値 値受取 버퍼는 4096바이트다. 実際データ GENET NIC 드라이버는 없다.

협력 値待合(17)는 일반 선점형 sleep/scheduler 구현이 아니다. 호출마다 最大値 100 ms 동안 통신을 처리하고 利用者 命令実行 기한을 갱신한다. パッケージ 설치기의 비차단 TCP 대기에 사용한다.
