# 日本語 Java 通信·入力出力·例外 API

패키지는 `日本語.内蔵`第三被演算子. ホスト `javac --release 8`로 컴파일한 class를
内蔵 ARM64 커널의 JVM에서 실행한다. 通信·ファイル·例外 API는 OpenJDK와 대조한다. 아래의 직접 구현한 画面·作業 スレッド値 API는 内蔵 JVM 전용이다.
기존 표준 Java ライブラリ 전체의 日本語 번역판은 아니다.

```java
import 日本語.内蔵.*;

public class 通信使用 {
    public static void main(String[] 引数) throws 入力出力例外 {
        接続経路 接続 = 接続経路.開放("10.0.2.2", 9000);
        try {
            接続.待機期限(700);
            接続.出力().書込(文字.符号化("안녕하세요\n"));
            入力ストリーム 入力値 = 接続.入力値();
            出力.番号書込(入力値.読取());
        } catch (待合待機期限例外 エラー) {
            出力.行書込(エラー.説明());
        } finally {
            接続.閉鎖();
        }
    }
}
```

`Socket`, `getOutputStream`, `write`, `getInputStream`, `read`, `close`를
利用者 예제에서 직접 호출할 필요가 없다. `try/catch/throws` 등 Java 문법은 유지한다. `String`은 예약어가 아니라 javac가 文字列 리터럴에 사용하는 표준 클래스다. 内蔵 실행기는 `public static void 起動処理()`도 진입점으로 받는다.

## 통신과 ストリーム値

| クラス値 | 日本語 呼出 |
|---|---|
| 接続経路 | `開放(番地, ポート番号)`, `入力値()`, `出力()`, `待機期限(ミリ秒)`, `ポート番号()`, `局所ポート番号()`, `接続済み()`, `判定閉鎖済み()`, `閉鎖()` |
| ポート受取 | `開放(ポート番号)`, `受取()`, `ポート番号()`, `待機期限(ミリ秒)`, `判定閉鎖済み()`, `閉鎖()` |
| 入力ストリーム | `読取()`, `読取(byte[])`, `読取(byte[], 起動処理, 長さ)`, `閉鎖()` |
| 出力ストリーム | `書込(int)`, `書込(byte[])`, `書込(byte[], 起動処理, 長さ)`, `値出力()`, `閉鎖()` |
| データグラムチャネル | `開放(ポート番号)`, `送信(番地, ポート番号, 文)`, `受取()`, `待機期限(ミリ秒)`, `ポート番号()`, `判定閉鎖済み()`, `閉鎖()` |
| 接続状態輸送 | `開放(...)`, `受信先開放(...)`는 上端値 日本語 객체를 復帰結果 |
| 検査項目 | `真偽確認(条件, 原因値)` |

TCP 입력은 한 번에 요청한 모든 바이트가 도착한다고 가정하지 않는다.
`読取()`의 ファイル 끝은 -1, 配列値 읽기의 반환값은 実際データ 읽은 길이다.
네트워크 흐름을 닫으면 연결도 닫힌다. ポート番号 0은 빈 번호를 자동 배정한다.
UDP 전문은 現在項目 内蔵 커널에서 512바이트까지 받으며, 주소는 桁値 IPv4를 사용한다.
`localhost` 루프백 외의 名前 풀이(DNS)는 内蔵 커널에 아직 없다.

기존 `接続状態輸送.接続/通信端点接続待機/受取`, `通信.開放/送信/受取`는 표준 Java 객체를
사용하던 코드와의 연결용이다. 새 코드는 `接続経路`, `ポート受取`, `データグラムチャネル`를 쓴다.

## 日本語 例外

모든 下端値 클래스는 既定値 생성자, `새예외("説明")` 형태의 文字列 생성자와
`説明()`을 제공한다. 実際データ 生成 문법은 `new 待合待機期限例外("状況待合 終端")`이다.

| 日本語 例外 | 상위 クラス値 / 용도 |
|---|---|
| 例外 | `java.lang.Exception`, 직접 던지는 일반 検査項目 例外 |
| 実行状態例外 | `java.lang.RuntimeException` |
| 入力出力例外 | `java.io.IOException`, 日本語 ファイル·通信 API의 検査項目 例外 |
| 待合待機期限例外 | `入力出力例外`, 通信 待機期限 초과 |
| 番地検索例外 | `入力出力例外`, 番地 検証 失敗値 |
| 未存在ファイル例外 | `入力出力例外`, ファイル 開放 失敗値 |
| 通信例外 | `入力出力例外`, 표준 SocketException 値変換 |
| 無効引数例外 | `java.lang.IllegalArgumentException` |
| 番号書式失敗 | `無効引数例外` |
| 境界例外 | `java.lang.IndexOutOfBoundsException` |
| 配列境界例外 / 文字列境界例外 | `境界例外` |
| 空参照参照例外 | `java.lang.NullPointerException` |
| 算術失敗 | `java.lang.ArithmeticException` |
| 状況例外 | `java.lang.IllegalStateException` |
| 型型変換例外 | `java.lang.ClassCastException` |
| 負数配列容量失敗 | `java.lang.NegativeArraySizeException` |
| 配列格納失敗 | `java.lang.ArrayStoreException` |
| スレッド状況例外 | `java.lang.IllegalThreadStateException` |
| 待合中断済み例外 | `java.lang.InterruptedException`, `作業.待機`의 値待合 중단 |

`例外`와 `実行状態例外`는 모든 日本語 예외의 共通値 부모가 아니다. 上端値 상속 관계를
사용하며, ファイル·通信 전체를 잡으려면 `catch (入力出力例外 エラー)`를 쓴다.
日本語 API가 표준 入力出力 오류를 日本語 예외로 변환한다.
기존 日本語 通信 호출에서 `SocketTimeoutException`을 잡던 코드는
`待合待機期限例外`를 잡도록 옮긴다. 표준 `java.net`을 직접 사용하는 코드의
例外 유형은 기존 Java 규약을 따른다.
일반 Java 연산이 자동으로 던지는 표준 예외까지 이름을 바꾸지는 않는다.
예를 들어 `1 / 0`의 ArithmeticException과 직접 만든 산술예외는 서로 다른 형식이다.
現在項目 内蔵 JVM에 이 20종을 추가했다. 임의의 利用者 Throwable 하위 クラス値 전체를
지원하도록 확장했다는 뜻은 아니다.

## ソースコンパイル·命令実行

```sh
cd /home/user/jkoros/platforms/rpi4-native
make システム構築
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/한국어사용 試験/Java/韓国語通信機構試験.java
python3 道具/ファイル実行.py build/한국어사용/韓国語通信機構試験.class
make test-jvm
```

내장 라이브러리는 利用者 JVM ELF 안에 탑재된다. `.jar`는 ホスト javac의
クラス値 경로로 사용한다. ソース木 묶음은 `dist/jkoros-native-korean-sources.zip`이다.
게스트의 제한형 `javac`는 日本語 예외의 `throws` 선언과 그 import를 인식한다.
内蔵 JVM의 Thread.interrupt 동작을 새로 구현한 것은 아니다.
try/catch·オブジェクト値·ソケット値 用例 전체의 ソース木 컴파일은 ホスト javac를 사용한다.
`/example/java/ファイル例.java`는 게스트 javac로도 컴파일할 数 있다.

実際データ TCP/UDP 예제는 [通信例.java](../../../example/java/通信例.java),
命令実行 절차는 [example 案内](../../../example/README.md),
ソース木 命名 원칙은 [命名 案内](../命名/案内.md)에 있다.

## Swing 窓 用例

`/example/java/窓例.java`와 컴파일된 `.class`先頭位置被演算子 起動 시 준비된다.
`cd /example/java` 次回項目 `java 窓例`로 연다. 名前 入力値, 挨拶 버튼,
인사말과 クリック値 反復状態個数 再読込, X 닫기를 지원한다.

| 기능 | 日本語 직접 API |
|---|---|
| Runnable / run | `実行可能処理作業.作業実行()` |
| ActionListener / actionPerformed | `動作受信先.動作受取(動作通知 通知)` |
| ActionEvent | `動作通知.命令本文()`, `イベントソース()`, `番号()` |
| JFrame | `窓(窓表題, 幅跨域, 高さ値)`, `要素追加(画面要素)`, `窓表示()`, `閉鎖()`, `判定可視()` |
| JButton | `ボタン(文, 水平位置, 垂直位置, 幅跨域, 高さ値, 受信先値)`, `動作受信先設定(受信先値)` |
| JLabel / JTextField | `ラベル(...)`, `本文フィールド(...)` |
| 共通値 画面 要素値 | `画面要素.本文読取()`, `本文書込(文)`, `境界設定(水平位置, 垂直位置, 幅跨域, 高さ値)` |
| SwingUtilities.invokeLater | `イベント待ち行列.後続呼出(実行可能処理作業)`, `判定イベント配送中()` |
| Thread | `作業担当(実行可能処理作業)`, `作業開始処理()`, `待機()`, `判定稼働中()`, `作業実行権譲渡()` |
| 명령행 | `起動処理()`, `実行引数.項目個数()`, `実行引数.文(序数添字)` |

上端値 클래스들은 `JButton`·`Thread` 등의 객체를 만들거나 보관하지 않는다.
内蔵 JVM의 `韓国語画面呼出`, `プロセススレッド`先頭位置被演算子 日本語 クラス値·メソッド値·서술자를
해석해 画面 요소와 命令実行 가닥을 직접 만든다. 動作 알림도 内蔵 객체이며
콜백으로 `作業実行`와 `動作受取`를 직접 찾는다. 표준 Swing/Thread를
사용하는 기존 프로그램의 命令実行 경로는 별도로 남아 있다.

Java 소스의 `native` 선언은 内蔵 JVM에 구현한 계약이다. 생성자의 예외는
이 계약이 없는 ホスト JVM에서 무동작 객체가 생기지 않도록 하는 値却下 경로다.
内蔵 JVM은 생성자를 직접 처리한다. 일반 OpenJDK에서는 이 직접 実装 API를
실행할 数 없다. ホスト javac로 컴파일한 後端値 内蔵 JVM에서 실행한다.
`StringUtilities`라는 표준 Swing 클래스는 없으며, 画面 큐 기능은 `SwingUtilities`에 해당한다.

```java
import 日本語.内蔵.*;
public class 가닥예제 implements 実行可能処理作業 {
    public void 作業実行() { 出力.行書込("日本語 作業 命令実行"); }
    public static void 起動処理() throws 待合中断済み例外 {
        作業担当 スレッド値 = 作業.起動処理(new 가닥예제());
        作業.待機(スレッド値);
    }
}
```

`example/java`의 다섯 소스는 予約済み語一覧·리터럴 외 식별자를 한국어로 작성한다.
配列値 引数 대신 `実行引数`, 길이는 `文字.バイト個数`를 사용한다.
표준 Java의 `main(String[])`도 継続処理工程 지원한다. 二値 第三被演算子 정의되어 있으면
内蔵 실행기는 引数 없는 `起動処理()`을 우선한다.
기존 日本語 画面 래퍼의 표준 `Component`/`Runnable`/`ActionListener` 인수와
`作業.起動処理(Runnable)`을 사용하던 코드는 새 日本語 계약으로 수정하고 재컴파일한다.
이는 전체 AWT/Swing·Thread API 支援値 또는 모든 JDK 소스의 번역을 뜻하지 않는다.

바이트코드에도 クラス値·メソッド値 이름과 서술자가 남는다.
日本語 名前 자체는 합법이지만, 다른 클래스에서 그 이름을 참조하는 部分要素値,
상속·メソッド値 재정의, native 接続, 런처의 진입점도 함께 맞춰야 한다.
근거는 [JLS 識別子値](https://docs.oracle.com/javase/specs/jls/se25/html/jls-3.html#jls-3.8)와
[JVMS メソッド値 参照](https://docs.oracle.com/javase/specs/jvms/se25/html/jvms-4.html#jvms-4.4.2)第三被演算子.
