# 内蔵 커널의 네트워크와 稼働システム値 命令

게스트 SSH·VNC, LAN 공개 命令実行, Pi4 GENET·DHCP 추가분은 [外部値 接続状態 案内](外部接続状態手引.md)를 먼저 참고한다. QEMU는 `sl0`, 物理機器 GENET은 `en0`를 사용한다. 物理機器 드라이버는 아직 보드에서 검증하지 않았다.

이 문서는 `platforms/rpi4-native`의 内蔵 ARM64 Java 커널용이다. Linux/OpenJDK 실행환경의 명령어와 구분한다. 새 커널을 빌드하고 再試行処理値 부팅해야 적용된다.

셸과 Java의 実際データ CPU 許可値, `ps`/`top`에 표시되는 単位値, ホスト·外部値 PC 接続 방법은
[命令実行 계층과 外部値 通信 状況調査](実行環境論理積外部通信網検査項目.md)에 정리했다.

```sh
cd /home/user/jkoros/platforms/rpi4-native
make desktop ARGS=--network RESOLUTION=1920x1080
# 直列値 셸만 사용할 때
make run ARGS=--network
```

게스트에서 `help`, `help system` 또는 `ヘルプ表示 system`을 입력한다. 下端値 두 이름은 같은 동작을 하며 현지어 이름도 Tab으로 완성할 数 있다.

| 표준 命令 | 日本語 命令 | 기능 |
|---|---|---|
| ipconfig, ifconfig | 아이피설정 | 実際データ IPv4 番地·넷마스크·中継門値·송수신 통계 |
| ip | IP番地 | 番地 照会値·設定値, 接続 送出転送ファイル群·내리기, 経路 照会値 |
| ping | 応答試験 | 実際データ ICMPv4 返答·손실률·왕복 時間値 |
| route | 경로표 | 직접 연결망과 既定値 中継門値 |
| netstat, ss | 통신현황 | 実際データ TCP/UDP 끝점의 番地·機器ポート·状況値·値受取 대기량 |
| ps | 작업목록 | 中核値 작업과 利用者 プログラム PID·状況値·매핑량·時間値 |

## IP 설정과 通信 検証

```sh
ipconfig
ip addr show
ipconfig set 10.0.2.20 255.255.255.0 10.0.2.2
아이피설정 set 10.0.2.20 255.255.255.0 10.0.2.2
ping -c 4 -W 1 10.0.2.2
応答試験 -c 4 10.0.2.2
ip route show
ip link set dev sl0 down
ip link set dev sl0 up
netstat
```

초깃값은 `sl0`, `10.0.2.15/24`, 中継門値 `10.0.2.2`第三被演算子. 番地 설정은 재부팅 전까지 유지된다. TCP/UDP 끝점이 열려 있으면 `error -16`으로 변경을 거부한다. 먼저 `ftpd stop` 등으로 서비스를 닫고 프로그램의 소켓을 닫는다. 잘못된 番地·비연속 넷마스크·다른 망의 관문은 적용하지 않는다.

`ip`는 上端値 구문의 부분집합이며 Linux iproute2 전체 문법을 구현하지 않는다. `ping`은 IPv4 桁値 番地, `-c 1..100`, `-W 1..10`초를 지원한다. 名前 値解析·IPv6는 미지원이며 GENET의 DHCP는 外部値 接続状態 구현에 추가했다. 응답이 없으면 終了点コード 1, 잘못된 인수는 2, 利用者 취소는 130이다. `ping ...; echo $?`로 확인한다.

QEMU 外部値 통신은 UART SLIP→NAT 연결을 사용한다. `--network` 없이도 内蔵 番地 照会値·설정은 가능하지만 外部値 응답은 오지 않는다. 既定値 NAT는 `10.0.2.0/24`第三被演算子. 物理機器 Pi의 GENET 드라이버는 별도로 추가했으며 基板 검증이 필요하다. Wi-Fi는 미지원이다.

주소를 `.20`으로 바꾼 後端値 FTP 등 **외부에서 들어오는 接続**到達待ち 사용할 때는 命令実行 시 前方値 대상도 지정한다.

```sh
make desktop ARGS="--network --guest-ip 10.0.2.20"
# 부팅한 게스트 안에서
ipconfig set 10.0.2.20 255.255.255.0 10.0.2.2
ftpd start
```

`--guest-ip`는 NAT 前方値 대상이며 게스트의 주소를 자동 설정하지 않는다. FTP 制御値 포트는 ホスト `127.0.0.1:2121`, 수동 데이터 포트는 50000~50007이다. 여러 VM을 함께 띄울 때는 `--network-host 127.0.0.2 --port 5903`처럼 ホスト 루프백 주소와 VNC 포트를 구분한다. FTP와 Java/C 소켓은 변경된 実際データ 게스트 IP를 사용한다.

## 状況値 조회의 의미

`ps`는 中核値/シェル, 살아 있는 협력 作業, 最大値 4개의 EL0 利用者 세션을 표시한다. 다른 터미널에 열린 `vi` 등을 `SUSPENDED` 상태로 볼 数 있다. `MAPPED_KiB`는 実際データ 페이지 対応付け済み値, `RUN_ms`는 해당 세션이 선택된 동안의 경과 時間値(시스템 呼出 ヘッダー)이며 정밀 CPU 사용률이 아니다. `top -n 1`은 한 번, `top -n 2`는 두 번 표시한다. 리다이렉션된 `top`의 기본값은 한 번이다.

`free`의 AOT ヒープ値 사용량은 할당기에서 읽는다. 힙은 中核値 BSS에 포함되므로 각 줄을 全体構築 더하면 중복된다. 고정 예약 영역과 利用者 페이지 매핑을 표시하며 Linux의 가용 RAM 계산이나 ホスト 記憶データ 통계를 꾸며서 표시하지 않는다.

`df`는 RAM 파일시스템의 ファイル 64칸 × 16 KiB를 표시한다. ファイル 하나는 논리 크기와 별도로 16 KiB 칸을 예약한다. `Data`는 実際データ データ 長さ 合計値, `Reserved`는 使用値 중인 槽入口 용량이다. 삭제 후에도 열린 파일은 末尾項目 참조를 닫을 때까지 계산한다. SD/영구 디스크 사용량은 아직 지원하지 않는다.

## 종료와 妥当性検査

게스트에서 `poweroff` 또는 `電源停止側`를 입력한다. FTP·ソケット値·利用者 세션을 닫은 後端値 BCM PM 終了点プログラム 절차를 실행한다. RAM 파일은 재부팅 後続側状況 보존되지 않는다. QEMU에서는 게스트의 `SHUTDOWN / guest-shutdown` 이벤트와 判定通常 종료를 검증한다. 物理機器 Pi 4 전원 회로 동작은 아직 시험하지 않았다.

実装 근거: [Linux BCM watchdog의 power-off 절차](https://github.com/torvalds/linux/blob/master/drivers/watchdog/bcm2835_wdt.c), [QEMU BCM PM 装置](https://github.com/qemu/qemu/blob/master/hw/misc/bcm2835_powermgt.c).

```sh
make test-system
# 結果: build/verification/system-tools/report.json 및 serial.log
```

이 시험은 잘못된 IP 値却下, 実際データ ICMP 成功値·시간초과, 接続 up/down, IP 値変更 後続側状況 FTP 송수신, df 生成·삭제, ヒープ値 計算結果, 다른 터미널의 vi PID·記憶データ, top 再読込·終了点プログラム, ハングル文字列 命令·Tab, 게스트 poweroff를 검사한다.

`java/worldos/国別値/국가코드` 판에는 같은 기능과 국가별 命令 대응표 `native-commands.json`이 들어간다. 표준 명령은 모든 판에서 유지한다. 새 현지어 이름은 기능 중심 제안이며 현지 화자·어원 검토를 완료한 표준 용어는 아니다. 미번역 항목은 대응표의 `pending`에 명시한다.
