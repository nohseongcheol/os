# VirtualBox 命令実行

```sh
cd ~/jkoros
make vbox
```

별도로 VM을 만들거나 ISO를 연결할 필요가 없다. 初期項目 실행하면 `os/build/kernel.iso`를 빌드하고 `jkoros operating system`이라는 전용 VM을 만들어 VirtualBox 창으로 부팅한다. `jkoros/os` 안에서도 `make vbox`를 사용할 数 있다.

게스트의 `jkoros>` 프롬프트에서 次回項目 명령을 입력한다.

```text
help
apps
run hello vbox
```

末尾項目 명령은 별도 Java ELF를 실행한다. `USER MODE ring 3`, `arg: vbox`, `Exit: 0` 出力 後続側状況 셸로 돌아오면 정상이다. VGA 화면은 現在項目 ASCII 글꼴만 지원하므로 한글은 `?`로 보이며, ハングル文字列 원문은 直列値 기록에서 확인할 数 있다.

## 状況値 확인과 再試行処理値 命令実行

```sh
make vbox-status
```

이 명령은 VM 状況値, ISO와 直列値 기록의 절대 경로를 JSON으로 출력한다.

| 現在項目 状況値 | `make vbox` 動作 |
| --- | --- |
| 아직 생성하지 않음 | ISO システム構築 → 전용 VM 生成 → 起動 |
| 保有終了済み (`poweroff`, `aborted`) | ISO システム構築 → 광학 媒体値 再読込 → 새로 起動 |
| 命令実行 중 (`running`) | 재빌드·재부팅 없이 現在項目 VM 値維持 |
| 일시정지 (`paused`) | 기존 VM 再開実行状態 |
| 저장됨 (`saved`) | 前回項目 直列値 기록을 복사해 보관하고 格納値 状況値 再開実行状態 |
| 格納値·起動処理 등 切替方式 중 | 변경하지 않고 作業 判定完了 後続側状況 재실행하도록 案内 |

ソース木 변경을 반영하려면 VM을 종료한 次回項目 再試行処理値 `make vbox`를 실행한다. **格納値 상태를 재개하면 前回項目 커널이 継続処理工程 실행되므로 새 빌드를 반영하지 않는다.** 실행기는 강제 종료하거나 格納値 상태를 폐기하지 않는다. VirtualBox 창을 닫을 때 사용자가 전원 끄기를 선택하면 記憶データ 상태가 사라지므로 보존할 작업이 없는지 먼저 확인한다. 게스트의 `halt`는 CPU만 멈추며 VirtualBox의 전원을 끄는 명령은 아니다.

窓 없는 실행이 필요하면 VM이 꺼져 있을 때 사용한다.

```sh
make vbox VBOX_TYPE=headless
```

命令実行 중인 VM에 再試行処理値 명령을 내려도 GUI/headless 방식은 바뀌지 않는다. 既定値 名前 대신 다른 이름이 필요하면 **최초 生成 시에만** `VBOX_NAME="원하는 名前"`을 지정하고 이후에도 같은 값을 사용한다.

## 설정과 データ 보존

- 既定値 설정은 BIOS, 記憶データ 64MiB, CPU 1개, VGA 記憶データ 16MiB, IDE 광학 부팅이다. 가상 하드디스크를 만들지 않는다.
- VM 설정은 `.vbox/machines/`, 内容物値 검사합별 ISO 사본은 `.vbox/media/`, 直列値 기록은 `.vbox/logs/`에 보관한다. `.vbox/state.json`은 전용 VM의 UUID와 所有者値 표식을 저장한다.
- 꺼진 VM을 부팅할 때 새 直列値 기록을 만든다. 格納値 状況値 再開実行状態 전의 기록은 `before-resume-*.log`로 복사한다. 格納値 状況値 자체는 삭제하지 않고 VirtualBox가 그대로 재개한다.
- 같은 이름의 다른 VM을 인수하지 않는다. UUID·設定値 経路·所有者値 표식을 검사하며, 사용자가 별도로 연결한 디스크나 광학 매체를 자동 교체하지 않는다.
- 기존 ISO 사본과 기록은 자동 삭제하지 않는다. `.vbox`는 Git 除外値 대상이다. 용량을 정리할 때도 命令実行·格納値 상태의 VM이 참조하는 파일과 관리 정보를 임의로 삭제하지 않는다.
- VirtualBox 또는 ホスト 드라이버가 없으면 오류를 안내한다. 자동 値導入, 管理器値 許可値 命令実行, 装置 許可値 변경은 하지 않는다.

## 네트워크 上限値

現在項目 커널의 RTL8139 드라이버는 QEMU에서 사용한다. VirtualBox의 PCnet/E1000 드라이버는 아직 구현하지 않아 이 실행기는 네트워크 장치를 비활성화한다. 셸과 利用者 프로그램은 실행되지만 UDP 열기는 `-19`로 실패한다. UDP 왕복은 `make run`과 [利用者 命令実行·네트워크 案内](../os/利用者/案内.md)의 절차로 시험한다.

## 妥当性検査

`make test-vbox`는 가짜 VirtualBox 응답을 사용하여 새 VM 生成, 命令実行·格納値·일시정지·切替方式 状況値, 名前 충돌, 소유권 불일치, 利用者 媒体値 値防護, システム構築 失敗値, 중단된 生成 状況復旧, ISO 値変更 감지, 経路 値防護 등을 검사한다. 実際データ VM을 만들거나 변경하지 않는다.

2026-09-13에 プログラム実行器 単位値 試験 16개가 통과했다. 별도로 実際データ VirtualBox 5.2.42에서 `make vbox`의 VM 生成·GUI 起動, `JAVA SELFTEST PASS`, 셸의 `run hello vbox` 실행과 `Exit: 0`, 命令実行 중 재호출 시 재부팅하지 않는 動作 및 `make vbox-status`를 확인했다. 格納値·일시정지 분기는 単位値 시험으로 검증했다.
