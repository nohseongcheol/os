# 셸에서 실행하는 利用者 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 開発 環境 案内](../../文書/Java開発環境.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 命令実行

ホスト 端末 1:

```sh
cd /home/user/jkoros
python3 os/道具/データ復元.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 外部値 연결을 받도록 방화벽이나 機器ポート 전달을 변경하지 않는다. Ctrl+C로 종료한다.

ホスト 端末 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 入力値:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 実際データ CPU 許可値 `ring 3`, 引数 出力.
- `netcheck`: ポート値 중복, 잘못된 取扱い値/ポインタ/長さ, 비차단 받기와 時間値 초과 検証.
- `udp`: IPv4 番地·宛先値 ポート値·한 語値 메시지를 받아 UDP로 보내고 같은 응답을 検証. `UDP ECHO PASS`, `Exit: 0`이면 成功値.
- `stress`: ホスト `10.0.2.2`의 代入値 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 値受取 ループ値 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 現在項目 주소는 게스트 `10.0.2.15/24`, 中継門値 `10.0.2.2`로 고정돼 있다. QEMU 利用者 네트워크의 ホスト アクセス入口 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 プログラム 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java プログラム 入口追記

`用例/내프로그램.java`를 次回項目 형식으로 만든다. 진입점은 引数 없는 `static int` 또는 `static void` 함수다. 인수는 利用者 API로 조회한다.

```java
public final class 내프로그램 {
    public static int 起動処理() {
        利用者.書込("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/利用者/プログラム.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := 利用者/用例/내프로그램.java
APP_ENTRY_mine := 내프로그램.起動処理
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 全体構築 나열한다. `利用者/宣言/利用者.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 命令実行 중인 VM에는 システム構築 결과가 자동 반영되지 않는다. プログラム 이름은 現在項目 셸의 ASCII 入力値 제한에 맞춘 1~15자의 소문자 이름이며 Java クラス値·関数·변수에는 한국어를 쓴다. 最大値 32개 プログラム, 한 命令実行 파일은 最大値 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/コンパイラ.py --target user --entry 挨拶例.起動処理 \
    -o os/build/apps/hello.elf os/利用者/宣言/利用者.java os/利用者/用例/挨拶例.java
```

`--target user`는 **jkoros 전용 ABI**第三被演算子. Linux 대상과 시스템 呼出 번호가 다르므로 ホスト 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 支援値 切抜き 안에서 실행한다. `.jar`와 일반 Linux 命令実行 파일은 지원하지 않는다.

## 利用者 네트워크 API

선언은 `宣言/利用者.java`에 있다. `データ送信`/`データ受取`의 `int[]` 項目要素 한 개는 バイト値 一値(0~255)를 나타낸다. 한 데이터그램의 最大値 データ 길이는 1,024바이트다.

```java
int 取扱い値 = 利用者.通信網開放(0); // 0: 一時値 局所有効範囲 UDP ポート値 자동 選択状態値
int[] データ = new int[32];
データ[0] = 'H'; データ[1] = 'i';
int 보낸길이 = 利用者.データ送信(取扱い値, 0x0a000202, 9000, データ, 2);
int 受信済み長さ = 利用者.データ受取(取扱い値, データ, 1500);
利用者.通信網閉鎖(取扱い値);
```

実際データ 프로그램에서는 開放·送信·받기의 負数値 반환값을 각각 검사한다. 완성된 예제는 `用例/データ通信.java`에 있다. `データ受取`의 値待合 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 値受取 대기열은 한 개뿐이므로 入口追記 도착분은 버린다. `送信済み番地`와 `送信済みポート`로 마지막으로 받은 상대를 조회한다.

| 返却済み値 | 의미 |
| --- | --- |
| 0 이상 | 取扱い値·プロセス値入口 長さ·成功値 등 해당 함수의 結果 |
| -5 | 装置 値送信 失敗値 |
| -9 | 잘못되었거나 닫힌 通信 取扱い値 |
| -11 | 비차단 받기에서 도착한 データ 未存在メソッド |
| -14 | 利用者 ポインタ/配列値 切抜き エラー |
| -19 | 支援値 NIC 未存在メソッド |
| -22 | ポート値/値待合 時間値/引数 値 エラー |
| -24 | 열린 通信網ポート 4개 容積上限 |
| -38 | 알 数 없는 시스템 呼出 |
| -90 | データ 또는 値受取 配列値 容量 문제 |
| -98 | 局所有効範囲 ポート値 番号 중복 |
| -101 | 지원하지 않는 宛先値 番地 |
| -110 | ARP·装置·値受取 時間値 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 符号化状態値 있는 Java `int`의 ビット値 패턴을 사용하므로 상위 비트가 1인 判定通常 IP 주소가 음수로 보일 数 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## 命令実行 경계와 시스템 呼出

```text
シェル run → JKAP에서 ELF 妥当性検査·적재 → ring 3 利用者 プログラム
                                 ↓ int 0x80
                      ポインタ 検査項目 → Java 中核値 API → RTL8139/UDP
                                 ↓ 終了点プログラム·例外·時間値 초과
                                シェル 복귀
```

시스템 呼出 레지스터는 `EAX=番号`, `EBX,ECX,EDX,ESI,EDI=引数`, `EAX=結果`第三被演算子. Java 呼出 被演算子スタック ABI는 컴파일러가 利用者 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| 番号 | 呼出 |
| --- | --- |
| 0 | 終了点プログラム(状況値 コード値) — 起動処理/エラー 런타임에서 使用値 |
| 1 | 文字列 書込 |
| 2 / 3 | 引数 項目個数 / 引数 文字列 番地 |
| 10 | UDP 開放 |
| 11 | UDP 送信(取扱い値, IP, 宛先値 ポート値, 配列値 番地, 長さ) |
| 12 | UDP 受取(取扱い値, 配列値 番地, 上限値 ミリ秒) |
| 13 | UDP 閉鎖 |
| 14 | 局所有効範囲 IP 番地 |
| 15 / 16 | 末尾項目 通信相手値 IP / UDP ポート値 |
| 20 | RAM ファイル 読取(名前 int[] 番地, 出力 int[] 番地) |
| 21 | RAM ファイル 書込(名前 int[] 番地, 入力値 int[] 番地, バイト値 長さ) |
| 22 | UTF-16 コード値 単位値 文字 出力(0~65535) |

ファイル API는 `利用者.ファイル読取(int[] 名前, int[] データ)`와 `利用者.ファイル書込(int[] 名前, int[] データ, int 長さ)`第三被演算子. 이름은 ASCII コード値 配列値(最大値 64칸, 0 終了点プログラム 또는 配列値 終端), データ 項目要素 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 ファイル 未存在メソッド `-2`, ポインタ エラー `-14`, 名前/長さ エラー `-22`, ファイル 槽値 부족 `-28`, 容量 초과 `-90`을 반환한다. 쓰기는 妥当性検査 後続側状況 ファイル 전체를 대체한다. `利用者.文字値書込(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`実行状態許可()`은 시스템 호출이 아니라 利用者 모드에서 CS의 하위 비트를 직접 읽으므로 実際データ 命令実行 권한을 확인한다. 中核値 機器ポート 접근용 `装置` native 함수는 利用者 対象値 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 上限値

- 한 번에 한 프로그램만 실행하며 判定完了 後続側状況 셸로 돌아온다. 백그라운드 命令実行, 파이프, 프로세스 간 통신은 없다. 命令実行 파일은 커널의 読取 전용 JKAP 묶음에서 적재한다. データ 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- 利用者 가상 番地 `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. 命令実行 영상은 前面値 2MiB, 인수는 `0x04300000`부터, 스택은 領域値 끝에서 시작한다. 中核値 identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB 利用者 영역을 비우고 ファイル 구역을 복사해 BSS·配列値 영역을 초기화한다. 利用者 GC는 없지만 終了点プログラム 後続側状況 次回項目 命令実行 때 영역을 재사용한다. 인수는 공백으로 분리한 最大値 16개이며 引用/이스케이프 파싱은 없다.
- 利用者 페이지의 コード値/データ 분리 読取 전용 設定値, NX, 被演算子スタック guard, ASLR은 아직 없다. 커널과 利用者 記憶データ·機器ポート 許可値 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 命令実行 상한을 두며 時間値 초과는 `Exit: 124`第三被演算子. 利用者 CPU 예외는 `128 + 例外 番号`(페이지 エラー 142, 특권 위반 141), Java 配列値/計算結果 오류는 101~105다. 中核値 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, 静的値 IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP 検査和 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- 利用者 命令実行·네트워크·値防護 境界位置値 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 命令実行·判定通常 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## 妥当性検査 근거

`make test`는 コンパイラ 14개 試験, Java 패킷 条件 2,201개 検査項目, 기존 シェル ELF/ISO 起動 試験, 利用者 ELF/実際データ UDP/値防護 境界位置値 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 長さ·해시까지 `os/build/利用者通信網試験.json`에 기록한다. 시험용 손상된 ELF·특권 命令·무한 反復回値 프로그램은 一時値 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
