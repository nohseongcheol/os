# Java 네이티브 稼働システム

이 문서는 기존 **x86 中核値**을 설명한다. Raspberry Pi 4의 内蔵 ARM64 初期状況 이식은 [별도 案内](../platforms/rpi4-native/README.md)를 참고한다. 下端値 x86 利用者 ELF·네트워크·IDE 格納値 기능이 ARM64에 全体構築 이식된 상태는 아니다.

Java 원문을 内蔵 AOT 후단으로 x86 기계어로 컴파일해 부팅하는 작은 운영체제다. 커널과 별도로 内蔵 제한형 Java コンパイラ·JVM ELF를 利用者 모드에 적재할 数 있다. Linux, engos, koros4와 外部値 OpenJDK는 게스트에 적재하지 않는다. 起動 진입과 機器ポート/물리 記憶領域 접근은 어셈블리이며, 文字 端末入出力·入力値 プロセス値入口·命令 値解析·作業 区画値 관리는 `ソース/*.java`에 있다.

## 게스트 Java 開発

`javac Hello.java`, `java Hello`로 부팅된 稼働システム 안에서 ソースコンパイル·실행한다. `edit FILE.java`와 `.save`로 소스를 작성하며 `ls`, `cat`, `rm`을 제공한다. RAM 파일은 最大値 8개, 각각 16KiB이다. 전용 IDE 매체를 연결하면 `sync`로 보존할 数 있다. 이 기능은 内蔵 제한형 구현이며 전체 OpenJDK/JDK 호환은 아니다. 사용법·支援値 문법·ファイル 적재·교차 시험은 [Java 開発 環境](../文書/Java開発環境.md)에 있다. `make test-java`로 검증한다.

## 빌드와 命令実行

`compiler/`先頭位置被演算子 요구하는 도구에 더해 ISO 생성에는 `grub-file`, `grub-mkrescue`, GRUB BIOS モジュール値, `xorriso`先頭位置被演算子 필요하다. 실행에는 QEMU 또는 VirtualBox가 필요하다. 現在項目 설치된 도구만 사용한다. `make run-store`는 새 전용 가상 格納値 매체를 만들어 연결한다. VirtualBox 실행기는 이 프로젝트가 만든 전용 VM만 설정하고 다른 VM은 변경하지 않는다. 가상 메모리는 既定値 64MiB이며 最小値 16MiB가 필요하다.

```sh
cd /home/user/jkoros/os
make                 # build/kernel.elf
make iso             # build/kernel.iso (利用者 ELF 集合値 ヘッダー)
make run             # ELF 직접 起動, 直列値 端末入出力
make run-gui         # GRUB ISO 起動, VGA 창과 PS/2 자판
make vbox            # 상위 폴더의 실행기로 전용 VirtualBox VM 命令実行
make vbox-status     # 전용 VirtualBox VM 状況値 検証
make test            # ELF와 ISO 두 경로의 実際データ 起動/入力値 試験
make apps            # 利用者 프로그램만 システム構築
make test-network    # 利用者 命令実行/UDP/値防護 試験
```

`make run`은 QEMU의 直列値 표준 입출력을 쓴다. `Ctrl+A`를 누른 後端値 `X`로 QEMU를 종료할 数 있다. `halt`는 게스트 CPU만 정지시키므로 QEMU 窓/프로세스는 별도로 닫는다. 폴링 방식이라 値待合 중에도 ホスト CPU를 사용할 数 있다.

VirtualBox는 `make vbox`로 실행한다. 새 전용 VM을 記憶データ 64MiB, BIOS, 광학 드라이브 부팅으로 자동 설정하며 디스크는 必要値 없다. 実際データ VirtualBox 5.2.42에서 起動, Java 内蔵 試験, シェル 入力値, `run hello vbox`의 ring 3 실행과 判定通常 종료를 확인했다. 現在項目 通信 드라이버는 QEMU의 RTL8139 전용이며 VirtualBox의 PCnet/E1000에서는 네트워크를 사용할 数 없어 네트워크 장치를 비활성화한다. 格納値 状況値 재개와 새 システム構築 반영 방법은 [VirtualBox 命令実行 案内](../文書/VirtualBox実行.md)에 있다.

## 셸에서 利用者 プログラム 命令実行 및 네트워크 呼出

독립 ELF32 命令実行 파일을 적재해 **ring 3**에서 실행한다. `int 0x80` 시스템 호출을 통해 端末入出力 出力, 引数 照会値, UDP 開放·送信·受取·닫기를 제공한다. 利用者 코드를 中核値 함수로 직접 호출하는 구조가 아니다.

```text
jkoros> apps
jkoros> run hello first second
jkoros> net
jkoros> run netcheck
jkoros> run udp 10.0.2.2 9000 hello
```

末尾項目 명령의 응답을 받으려면 호스트의 별도 터미널에서 `python3 /home/user/jkoros/os/道具/データ復元.py --port 9000`을 먼저 실행한다. 상세 API, プログラム 入口追記, 番地 공간과 제한은 [利用者 命令実行·네트워크 案内](利用者/案内.md)에 있다.

起動 検証 句値:

```text
JKOROS NATIVE JAVA
Java 기계어 中核値 起動処理
JAVA SELFTEST PASS
USER ELF: ring 3 / paging / int 0x80
help | info | mem | alloc | free N | echo TEXT | clear | test | halt
apps | run NAME [ARGS] | net
READY
jkoros>
```

## 구현한 기능

- GRUB Multiboot 1 ELF 起動, x86 値防護 方式値 GDT, BSS 初期化, 64KiB 被演算子スタック.
- Java 関数 実際データ 실행과 起動 システム情報 標識値 検証.
- COM1 直列値 入力出力, VGA 文字 画面·カーソル値·스크롤·入口消去処理.
- PS/2 既定値 자판, 좌우 Shift, Enter, Backspace. 拡張子値 キー値/마우스 자료는 命令 입력으로 쓰지 않는다.
- 長さ 128의 命令 入力値 버퍼, 桁あふれ値 방지, CR/LF プロセス値入口.
- `help`, `info`, `mem`, `alloc`, `free N`, `echo TEXT`, `clear`, `test`, `halt`.
- 4KiB 作業 区画値 8개의 記憶装置確保·復帰結果·재사용과 중복 復帰結果 방지.
- Java 配列値 256KiB 영역의 容量·添え字値 검사와 런타임 エラー 중단.
- 読取 전용 JKAP 命令実行 集合値, ELF32 区画値/入口点 妥当性検査, 利用者 方式値·引数·終了点プログラム コード値.
- 中核値/利用者 페이지 許可値 분리, TSS, IDT, PIT 100Hz, 利用者 CPU 例外 プロセス値入口 및 命令実行 時間値 상한.
- PCI RTL8139 폴링 드라이버, ARP, 静的値 IPv4, UDP 検査和·송수신·値待合 上限値.

`mem`의 Upper memory는 Multiboot의 1MiB 上限側側面 密切替分岐一覧 記憶データ 容量(KiB)이며, 전체 記憶データ 지도 분석이나 자유 물리 記憶データ 수치가 아니다. `alloc`은 이미 확보한 整数値 配列値 안의 作業 区画値 번호를 반환한다. 일반 물리 ページ値 記憶装置確保, 番地 番地領域 또는 利用者 プロセス値 記憶データ 관리가 아니다.

## 명시적인 境界位置上限

이 커널은 **利用者 프로그램을 한 번에 一値 실행하는 初期状況 中核値**이다. PIT IRQ0만 사용하며 키보드와 NIC는 폴링한다. 利用者 CPU 예외는 해당 프로그램을 끝내고 셸로 복귀시키지만 中核値 예외는 중단한다. 命令実行 시간은 약 3초로 제한한다. 완전한 선점 다중 プロセス値 스케줄러, FAT/ext 등 일반 디스크 ファイルシステム, TCP·DNS·DHCP·IPv6·HTTP, 전체 POSIX, 일반 オブジェクト値 모델/GC는 아직 없다. 전용 IDE ファイル 보존과 POSIX ファイル/UDP 일부 기능은 구현했다. JVM은 RAM 파일의 단일 클래스를 命令実行 시 적재하며 일반 ClassLoader나 JAR 로딩은 지원하지 않는다. 네이티브 命令実行 파일은 システム構築 시 読取 전용 묶음에 넣으며, 일반 Linux ELF를 실행하는 환경이 아니다. 기존 `../基幹ソース/`의 JVM 관리 中核値 전체를 이식한 것도 아니다.

Java 식별자는 한국어다. 直列値 출력은 이 프로젝트의 ハングル文字列(BMP 文字)을 UTF-8로 표시한다. VGA는 既定値 ASCII 글꼴만 사용하므로 ハングル文字列 자리에 `?`先頭位置被演算子 나온다. 命令 입력도 現在項目 ASCII만 지원하며 ハングル文字列 書体値·입력기 및 補助値 평면 文字 출력은 후속 작업이다. `test`는 작은 배열을 새로 할당하고 GC가 없으므로 무한 반복하지 않는다.

## 자동 試験

`試験/起動試験.py`는 디스크 없는 독립 QEMU를 생성해 다음을 검증하고 종료한다.

- ELF 직접 起動 및 GRUB ISO 起動.
- Java 内蔵 시험과 UTF-8 直列値 句値.
- 命令 ヘルプ表示·システム情報·記憶データ·出力·エラー 入力値·画面 入口消去処理.
- 作業 区画値 8개 記憶装置確保, 부족 プロセス値入口, 復帰結果/중복 復帰結果/재할당.
- 直列値 改行·백스페이스·긴 入力値 プロセス値入口.
- QEMU PS/2 キー値 입력으로 `info` 命令実行, `halt` 機械停止実行状態.

成功値 로그는 `build/起動試験.json`에 남는다. 로컬 Unix 소켓을 금지하는 샌드박스에서는 試験 도구에 해당 권한이 필요하다. 試験 도중 새로 만든 QEMU만 종료하며 기존 VM과 実際データ 디스크는 건드리지 않는다.

`試験/利用者通信網試験.py`는 ELF/ISO 각각에서 利用者 ELF, 実際データ ring 3, 引数, ホスト 루프백 UDP 왕복, 1,023/1,024바이트 24회 密切替分岐一覧 왕복, 時間値 초과, NIC 未存在メソッド, 記憶データ/機器ポート アクセス入口 차단, CPU 例外, 무한 反復回値, 잘못된 ELF를 시험한다. `build/利用者通信網試験.json`에 게스트 기록과 호스트가 받은 데이터의 長さ·해시를 저장한다. `試験/パケット試験.py`는 実際データ Java 契約値 처리기에 손상된 패킷을 넣어 2,201개 境界位置値/検査和 조건을 검사한다. ホスト 루프백 외 外部値 서버에는 試験 트래픽을 보내지 않는다.

부트 경계는 GNU의 [Multiboot 仕様](https://www.gnu.org/software/grub/manual/multiboot/multiboot.html)를 따른다.

새 ファイル記述子·C ABI·IDE 格納値·Java ファイル 흐름의 범위와 日本語 命名 대응은 [posix-kor 案内](../posix-kor/案内.md)에 있다. `make test-posix`로 ELF/ISO 실행과 재부팅 보존을 검증한다.
