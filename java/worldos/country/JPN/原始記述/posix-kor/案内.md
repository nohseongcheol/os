# jkoros posix-kor

**内蔵 ARM64 Java 커널용 C++ 接続**은 [arm64-native](arm64-native/案内.md)에 있다. 中核値 내부 직접 ファイル 호출과 EL0 利用者 프로그램의 ファイル/UDP 루프백 SVC 호출을 별도 라이브러리로 제공한다. 下端値 i386 ライブラリ 및 ARM64 Linux libc와는 対象値·ABI가 다르다.

内蔵 jkoros 커널에서 실행되는 i386 C 라이브러리와 日本語 API다. ホスト libc를 연결하지 않고 `int 0x80`으로 実際データ 커널의 ファイル記述子·端末入出力·UDP·格納値 계층을 호출한다. `基幹ソース/`의 ホスト JVM 모형과 별개다.

**현재는 POSIX의 일부 기능을 제공하는 호환 계층이며, POSIX 인증·전체 libc·전체 OpenJDK를 뜻하지 않는다.** 実装 범위와 제한을 아래에 명시한다. 한국어를 먼저 적용했다. 다른 국가·언어의 번역판은 아직 만들지 않았다.

## 빌드와 命令実行

```sh
cd /home/user/jkoros
make posix-kor
make iso
make test-posix
make -C os run-store
```

`run-store`는 `os/build/files.img`先頭位置被演算子 없을 때만 새 전용 파일을 만들고 QEMU IDE 先頭位置項目 장치로 연결한다. 기존 파일을 덮어써서 초기화하지 않는다. 일반 `make run`은 디스크 없이 실행된다. VirtualBox 실행기의 디스크 연결은 변경하지 않았다.

부팅된 jkoros에서:

```text
run posixcheck check
run posixstore
cat stored.txt
edit note.txt
hello from jkoros
.save
sync
```

`Sync: 0`은 연결된 전용 매체에 저장했다는 뜻이다. 디스크가 없거나 代入値 형식이 아니면 `Sync: -19`第三被演算子. 같은 `files.img`로 再試行処理値 부팅하면 末尾項目 同期化 상태를 복원한다. Java 소스와 `.class`도 같은 格納値 대상이다. `close`第二被演算子 편집기의 `.save`만으로 재부팅 보존을 보장하지 않으므로 終了点プログラム 전에 `sync`를 실행한다.

## 한국어로 C プログラム 작성

```c
#include <ファイルABI.h>

int main(int 引数列個数, char **引数一覧) {
    (void)引数列個数;
    (void)引数一覧;
    int ファイル記述子 = ファイル開放("note.txt", 読取書込 | 作成条件未存在, 0600);
    if (ファイル記述子 < 0) return エラー番号;
    if (ファイルデータ書込(ファイル記述子, "hello\n", 6) != 6) return 1;
    if (確定ファイル記憶装置(ファイル記述子) < 0) return エラー番号;
    return ファイル閉鎖(ファイル記述子);
}
```

작성 원문은 한글을 그대로 유지한다. `道具/識別子変換結果.py`先頭位置被演算子 システム構築 복사본의 식별자만 C 표준 UCN 표기로 바꾸어 GCC 7에서도 컴파일되게 한다. 文字列, 주석, `#include` 경로는 변환하지 않는다. 이 도구는 C의 모든 前処理ソース 표기법을 해석하는 전처리기가 아니며, 프로젝트가 사용하는 일반 토큰과 include 문법을 대상으로 한다.

라이브러리는 `build/libposix-kor.a`, 起動処理 코드는 `build/利用者プログラム開始処理.o`, 生成 헤더는 `build/ソース/ヘッダー/`이다. システム構築 옵션과 接続 명령은 [Makefile](Makefile), 実際データ 예제는 [ファイルABI試験.c](ソース/試験/ファイルABI試験.c)와 [データグラム試験.c](ソース/試験/データグラム試験.c)에 있다. 새 ELF를 OS에 포함하려면 `os/Makefile`의 利用者 命令実行 묶음에 명시적으로 등록한다. 게스트 안에서 C를 컴파일하는 도구는 제공하지 않는다.

표준 C/POSIX 外部値 名前 `open`, `read`, `write`, `socket`, `errno`, `main`과 헤더 경로는 유지한다. 日本語 별칭은 같은 함수를 가리킨다. 변수와 実装 파일에는 의미를 드러내는 日本語 이름을 사용한다. ソース翻訳処理 근거는 [命名 원칙](命名原則.md), 実際データ 대응은 [용어 대응표](用語対応付け.tsv)에 기록했다.

## 제공하는 기능

| 切抜き | 実装 | 現在項目 上限値 |
|---|---|---|
| ファイル | open/creat/read/write/close/lseek/unlink/ftruncate/fstat/fsync | 루트의 단일 名前, ASCII 63바이트, 8개 ファイル, 파일당 16KiB |
| 記述子入口 | dup/dup2, F_DUPFD/F_DUPFD_CLOEXEC/F_GETFD/F_SETFD/F_GETFL/F_SETFL | プロセス値 一値, 最大値 32개; 錠値·exec 미구현 |
| 入力出力 設定値 | O_RDONLY/O_WRONLY/O_RDWR/O_CREAT/O_EXCL/O_TRUNC/O_APPEND/O_NONBLOCK/O_CLOEXEC | 그 밖의 비트는 ENOTSUP; 実際データ 利用者·그룹 アクセス入口 許可値 검사는 未存在メソッド |
| 표준 端末入出力 | 0 読取, 1·2 書込, バイト値 単位値 入力値 | 端末 編集値·termios·시그널 未存在メソッド, ハングル文字列 書体値/입력기 未存在メソッド |
| UDP | socket/bind/sendto/recvfrom/getsockname, SO_RCVTIMEO | IPv4 UDP만, 묶인 通信端点値 4개, 전문당 1,024바이트, 値受取 値待合 設定値 最大値 2초 |
| 番地 | htons/ntohs/htonl/ntohl/inet_pton/inet_ntop | IPv4 桁値 주소만; DNS/IPv6 未存在メソッド |
| 작은 C 支援値 | strlen/strcmp/memcpy/memset/memcmp/puts/putchar | 전체 libc·stdio FILE·malloc 未存在メソッド |
| 格納値 | JKSTORE1 전용 IDE 格納値, 두 보존본과 検査和 | FAT/ext ファイルシステム·디렉터리·하드 링크·심볼릭 링크 未存在メソッド |
| 게스트 Java | FileInputStream(String).read()/close(), FileOutputStream(String[, boolean]).write(int)/close() | 配列値 入力出力·일반 java.io·例外 プロセス値入口 未存在メソッド |

`dup`으로 복제한 서술자는 ファイル 위치와 継続状態追記 설정을 공유한다. `FD_CLOEXEC`는 서술자마다 저장한다. `unlink`는 이름만 제거하며, 열린 파일의 내용은 末尾項目 참조가 닫힐 때까지 접근할 数 있다. 빈 위치를 건너뛰어 쓰거나 길이를 늘린 영역은 0으로 읽힌다. ファイル記述子 부족으로 실패한 `open`은 파일을 생성하거나 비우지 않는다. C 呼出 실패는 `-1`과 `errno`, 내부 中核値 호출은 負数値 エラー 번호를 반환한다.

`fstat`는 이 프로젝트 전용 48바이트 구조체에 種別値·容量·링크 数·許可許可権 ビット値 등을 반환한다. POSIX의 전체 時間値 속성은 아직 제공하지 않는다. 다른 운영체제의 `struct stat` 또는 Linux 바이너리 ABI와 호환되지 않는다. `O_CLOEXEC`는 기록할 数 있지만 現在項目 exec 기능은 없다. 성공하는 関数 이름만으로 전체 POSIX 의미가 구현되었다고 간주하면 안 된다.

UDP는 QEMU RTL8139의 実際データ ホスト 왕복을 지원한다. 짧은 値受取 버퍼에는 앞부분을 복사하고 剰余値 전문을 버린다. 빈 전문도 송수신한다. `SO_RCVTIMEO` 또는 비차단 수신의 データ 없음은 `EAGAIN`이다. TCP를 요청하면 `EPROTONOSUPPORT`를 반환한다. 루프백·브로드캐스트·멀티캐스트·연결형 ソケット値·listen/accept는 아직 없다. 기존 AOT Java UDP 손잡이는 이 POSIX 서술자와 별개이므로 서로 섞어 닫지 않는다.

모든 利用者 프로그램에는 기존 약 3초 命令実行 상한이 적용된다. `errno`는 現在項目 단일 プロセス値·단일 스레드 변수다. JDK 전체, Swing/AWT/JavaFX, TCP/DNS/HTTP/TLS, 스레드·GC·JIT·동적 연결은 아직 구현하지 않았다. 전체 Java SE 命令実行 환경을 만들려면 해당 中核値 기반과 런타임 이식을 継続処理工程 진행하거나 별도 Linux 基盤 命令実行 방식을 결정해야 한다.

## 格納値 형식과 妥当性検査

매체는 512바이트 区画値 2,048개(1MiB)第三被演算子. 区画値 0의 `JKSTORE1` 識別子値·容量·書式値 번호가 全体構築 맞는 장치만 書込 대상으로 삼는다. 区画値 1과 260에서 각각 259구역짜리 보존본이 시작한다. 각 보존본은 判定完了 先頭部値 1구역, ファイル 表 2구역, ファイル データ 256구역으로 구성된다.

`fsync`와 `sync`는 이름이 남아 있는 모든 파일의 現在項目 상태를 저장한다. 반대편 보존본을 무효화한 後端値 ファイル 표와 자료를 쓰고 ATA 캐시 비우기를 실행한다. 마지막에 世代値 번호와 FNV-1a 검사합을 가진 判定完了 머리를 기록하고 再試行処理値 캐시를 비운다. 起動 시 검사합과 표가 유효한 가장 直近値 세대를 선택한다. 검사합은 우발적인 손상을 入口探索 위한 것이며 암호학적 무결성 검증은 아니다. 実際データ 装置 전원 차단 시험은 하지 않았다.

복원된 ファイル 목록은 起動 이미지의 既定値 用例/`JAVA_FILES` 목록을 대체한다. 새 예제를 이미지에 추가해도 기존 格納値 매체를 연결하면 저장된 목록이 우선한다. 동기화하지 않은 변경은 재부팅 後続側状況 사라진다.

`make test-posix`는 日本語 識別子値 値変換, ELF/ISO의 実際データ C ABI 呼出, 공유 位置, 삭제된 파일의 수명, ファイル/記述子入口 고갈, ポインタ エラー, 표준 入力値, UDP, `fsync`, 재부팅, 손상된 最新値 보존본의 회피, 다른 형식의 媒体値 비변경, 게스트 Java ファイル 처리와 OpenJDK 교차 실행을 확인한다. 기록은 `os/build/契約試験.json`, `永続化試験.json`, `Javaファイル試験.json`이다.
