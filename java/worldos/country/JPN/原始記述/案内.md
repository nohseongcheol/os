# JJpnOS

現在項目 内蔵 ARM64 배포판은 [LICENSE](LICENSE)의 COSL 상업 조건을 유지한다. 제3자 라이선스의 권리는 별도로 보장하며, 配布値 시 ソース木·再接続通信端点 자료를 포함하는 절차는 [COSL 配布値 案内](platforms/rpi4-native/COSL配布手引.md)에 있다.

内蔵 ARM64 판의 `ipconfig`/`ip`, `ping`, `ps`/`top`, `free`/`df`, `poweroff`와 日本語 명령은 [네트워크·稼働システム値 命令 案内](platforms/rpi4-native/通信網論理積システム命令一覧.md)를 참고한다. 새 커널을 부팅한 後端値 `help system`으로 볼 数 있다.

Raspberry Pi 4 **内蔵 Java ARM64 中核値**은 [内蔵 Pi4 案内](platforms/rpi4-native/案内.md)에 있다. Linux 없이 부팅하며 GUI 端末·vi, 内蔵 JVM의 Swing 일부 API, TCP/UDP·FTP, 게스트 TinyCC·MicroPython, C/C++의 posix-kor 호출을 제공한다. [日本語 Java 通信·例外 API](platforms/rpi4-native/日本語Java/案内.md)와 [日本語 ソース木 命名](platforms/rpi4-native/命名/案内.md)을 지원한다. [内蔵 SSH·VNC 및 GENET 드라이버](platforms/rpi4-native/外部接続状態手引.md)를 포함하며, 네트워크는 QEMU의 UART SLIP 경로로 검증했다. 実際データ Pi 4 GENET 동작은 미검증이고, USB 入力値·영속 저장과 전체 OpenJDK·Swing은 아직 支援値 切抜き 밖이다.

Raspberry Pi 4용 Linux·OpenJDK 실행판과 利用者 環境 移動値 기능은 [라즈베리파이 실행판](platforms/rpi4/README.md)에 있다. 実際データ ARM64 JDK/JRE와 시스템·利用者 イメージ構築 システム構築 경로를 제공한다. 기존 内蔵 x86 커널과는 별도 命令実行 기반이다. 일반 Java `.class`/JAR의 命令実行 ファイル 생성은 [OpenJDK 命令実行 ファイル](compiler/OpenJDK-実行形式ファイル.md), 日本語 API는 [日本語 Java ライブラリ](日本語Java/案内.md)를 참고한다.

`jkoros`는 `engos`의 기능을 Java 관리 커널로 옮기는 프로젝트다. 프로젝트가 소유하는 Java 関数, 変数値, 書式値 및 Java ファイル 이름은 한국어로 작성한다. 표준 Java 실행기의 `main`, Java 표준 ライブラリ 書式値, x86 부트 ABI 등 外部値 계약은 보존한다. 内蔵 ARM64 실행기는 日本語 `起動処理()`도 진입점으로 지원하며, 日本語 GUI·作業 가닥을 JVM에 직접 구현했다. 内蔵 ARM64 C 연결부·Python 도구와 공용 x86·ARM64 AOT 번역기의 内蔵 이름도 한국어로 작성한다. 前回項目 경로의 호환 入口点, OpenJDK 補助値 도구와 Linux 版値 도구에는 영어 이름이 남아 있고 [命名 원칙·말의 근거·전체 ソース 검토 切抜き](platforms/rpi4-native/命名/案内.md)를 별도로 기록한다.

## 現在項目 実装

下端値 목록은 기존 `基幹ソース/`의 JVM 관리 커널에 대한 것이다. 実際データ 네이티브 커널의 범위는 `os/案内.md`에서 별도로 설명한다.

- 整列値 할당과 해제를 지원하는 記憶領域 管理器値
- 番地 番地領域, ページ値 接続, 書込 시 値複写(COW)
- プロセス値 識別子値, 用意 대기열, fork/wait 状況値
- 과정별 ファイル 記述子入口, open/read/seek/dup/close
- ELF32 値識別処理 및 区画値 検査項目
- 키보드·마우스 入力値 イベント 대기열
- 直列値 단말과 네이티브 機器値 境界位置値
- 관리 中核値 전체 자동 試験

세부 対応付け値 범위와 아직 필요한 네이티브 연결은 [기능 대응표](文書/機能対応.md)에 기록한다.

## 빌드와 試験

새 네이티브 구현은 `compiler/`와 `os/`에 있다. 기존 `基幹ソース/`의 JVM 관리 커널은 그대로 보존하며, 두 구현의 시험과 기능 범위는 서로 다르다.

```sh
cd /home/user/jkoros
make                 # 네이티브 計算結果 用例 + Java 中核値 ELF
make iso             # os/build/kernel.iso
make run             # QEMU 直列値 端末入出力; help 入力値 (종료는 Ctrl+A, X)
make run-gui         # ISO를 QEMU 画面/PS2 키보드로 命令実行
make vbox            # 전용 VirtualBox VM 자동 生成·命令実行 (GUI)
make vbox-status     # VirtualBox 状況値·ISO·直列値 履歴記録記録 経路 検証
make test-vbox       # VirtualBox プログラム実行器 状況値 プロセス値入口 試験 (実際データ VM 値変更 未存在メソッド)
make test            # コンパイラ 試験 + ELF/ISO 起動 및 命令 入力値 試験
make apps            # 독립 利用者 ELF プログラム システム構築
make test-network    # 利用者 方式値·UDP 왕복·記憶データ 値防護 試験
make test-java       # 게스트 javac/JVM + OpenJDK 양방향 교차 命令実行 試験
make posix-kor       # 日本語 C 헤더와 実際データ 中核値 呼出 ライブラリ
make test-posix      # ファイル/UDP/格納値/Java ファイル 入力出力 試験
make -C os run-store # 전용 格納値 매체로 QEMU 起動
make legacy-test     # 下端値 기존 JVM 관리 커널의 47개 試験
```

`compiler/`는 호스트의 `javac`를 문법·型値 検査項目 전단으로 사용하고 内蔵 バイトコード→x86 변환기로 ELF32 기계어를 만든다. 빌드할 때는 JDK가 필요하지만 생성된 커널과 ELF는 外部値 JVM 없이 실행된다. 전체 Java, オブジェクト値 모델, 표준 라이브러리와 기존 관리 中核値 전체의 AOT 변환은 아직 지원하지 않는다. 자세한 支援値 문법과 명령은 [コンパイラ 案内](compiler/案内.md), 実際データ 起動 기능과 한계는 [네이티브 稼働システム 案内](os/案内.md)를 참고한다.

네이티브 셸에 内蔵 제한형 `javac`와 `java`를 추가했다. `edit Demo.java`로 소스를 입력하고 `.save`로 저장한 後端値 `javac Demo.java`, `java Demo`로 **게스트 내부에서 컴파일하고 命令実行**할 数 있다. 既定値 예제는 `javac Hello.java`, `java Hello`第三被演算子. 파일은 RAM에서 동작하며, 전용 格納値 매체를 연결하면 `sync`로 재부팅 후에도 보존할 数 있다. **OpenJDK/JDK 전체 이식은 아니며**, 단일 クラス値·静的値 関数·整数値·文字列·条件/반복문과 일부 표준 호출을 지원한다. 支援値 切抜き, 外部値 ファイル 적재와 시험은 [Java 開発 環境 案内](文書/Java開発環境.md)에 있다.

네이티브 셸에서 `apps`, `run hello first second`, `net`, `run netcheck`를 사용할 数 있다. 독립 ELF를 ring 3에 적재하고 `int 0x80` 호출을 통해 出力·引数·UDP 네트워크를 제공한다. 별도 ホスト 터미널에서 `python3 os/道具/データ復元.py --port 9000`을 실행한 後端値 게스트에서 `run udp 10.0.2.2 9000 hello`로 実際データ 왕복을 확인한다. 새 プログラム 入口レジスタ, API 및 제한은 [利用者 命令実行·네트워크 案内](os/利用者/案内.md)를 참고한다. 現在項目 QEMU RTL8139·静的値 IPv4·UDP 전용이며 TCP/DNS는 미지원이며, 전용 IDE 格納値 형식과 POSIX ファイル/UDP 일부 기능을 추가했다.

`make vbox`는 `jkoros operating system` 전용 VM을 만들고 디스크 없이 ISO로 부팅한다. 命令実行 중이면 유지하고, 格納値·일시정지 상태이면 재개하며, 꺼져 있을 때만 새 ISO를 빌드해 연결한다. VirtualBox에서 부팅과 셸의 利用者 プログラム 실행을 확인했다. 다만 現在項目 VirtualBox용 네트워크 드라이버는 없어 네트워크 장치를 비활성화한다. UDP 시험에는 `make run`을 사용한다. 상태별 동작과 새 システム構築 반영 방법은 [VirtualBox 命令実行 案内](文書/VirtualBox実行.md)에 있다.

기존 관리 커널만 시험하려면:

```sh
cd /home/user/jkoros
make -f 入口作成.mk 検査項目
make -f 入口作成.mk ホスト
```

`ホスト`는 여전히 JVM 관리 계층의 動作 시험이다. `make -f 入口作成.mk イメージ構築`는 새 `os/`의 제한형 네이티브 中核値 ISO를 만든다. 기존 `基幹ソース/`의 ファイルシステム·プロセス値·通信網 実装 전체를 이 ISO에 이식했다는 의미는 아니다.

日本語 関数·変数値·ファイル 이름과 実際データ C API는 [posix-kor](posix-kor/案内.md)에 있다. 게스트 Java에서는 `FileInputStream`·`FileOutputStream`의 단일 バイト値 입출력도 지원한다. 전체 POSIX·OpenJDK·Swing 지원으로 확대된 것은 아니다.

外部値 배포용 `pack.sh` / `unpack.sh`와 자동 依存項目 복원은 [配布値 案内](distribution/README.md)를 참고하세요.
