# 셸에서 실행하는 пайдаланушы 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 readme_файлы_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 орындау_пәрмен

орналастыру Терминал 1:

```sh
cd /home/user/jkoros
python3 os/Құралдар/экранға_шығару_деректер.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. сыртқы_мән 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

орналастыру Терминал 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 нақты_деректер CPU рұқсат_мән `ring 3`, Аргументтер Шығысы.
- `netcheck`: порт_мән 중복, 잘못된 дескриптор_мән/меңзер/ұзындық_мән, 비차단 받기와 уақыт_мән 초과 тексеру.
- `udp`: IPv4 мекенжай·тағайындау_мән порт_мән·한 Сөз_мән 메시지를 받아 UDP로 보내고 같은 응답을 тексеру. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: орналастыру `10.0.2.2`의 белгілеу_мән 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 тұйық_мән 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. ток_элемент 주소는 게스트 `10.0.2.15/24`, шлюз_мән `10.0.2.2`로 고정돼 있다. QEMU пайдаланушы 네트워크의 орналастыру қатынас_енгізу 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 бағдарлама_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java бағдарлама_f5044b9b қосу_енгізу

`예제/내프로그램.java`를 Келесі_элемент 형식으로 만든다. 진입점은 Аргументтер 없는 `static int` 또는 `static void` 함수다. 인수는 пайдаланушы API로 조회한다.

```java
public final class 내프로그램 {
    public static int Орындау_2() {
        пайдаланушы.Жазу("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/пайдаланушы/бағдарлама_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := пайдаланушы/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.Орындау_2
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `пайдаланушы/мәлімдеме/пайдаланушы.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 орындау_пәрмен 중인 VM에는 құрастыру_жүйе 결과가 자동 반영되지 않는다. бағдарлама_f5044b9b 이름은 ток_элемент 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java оқу_мән·функция_мән·변수에는 한국어를 쓴다. 최대 32개 бағдарлама_f5044b9b, 한 орындау_пәрмен 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.Орындау_2 \
    -o os/build/apps/hello.elf os/пайдаланушы/мәлімдеме/пайдаланушы.java os/пайдаланушы/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 орналастыру 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 тіреу_мән клип 안에서 실행한다. `.jar`와 일반 Linux орындау_пәрмен 파일은 지원하지 않는다.

## пайдаланушы 네트워크 API

선언은 `мәлімдеме/пайдаланушы.java`에 있다. `жіберу_деректер`/`자료받기`의 `int[]` элемент_элемент 한 개는 байт_мән 하나(0~255)를 나타낸다. 한 데이터그램의 최대 деректер 길이는 1,024바이트다.

```java
int дескриптор_мән = пайдаланушы.ашу_желі(0); // 0: 임시 жергілікті_Аумақ UDP порт_мән 자동 таңдау_мән
int[] деректер = new int[32];
деректер[0] = 'H'; деректер[1] = 'i';
int 보낸길이 = пайдаланушы.жіберу_деректер(дескриптор_мән, 0x0a000202, 9000, деректер, 2);
int 받은길이 = пайдаланушы.자료받기(дескриптор_мән, деректер, 1500);
пайдаланушы.Жабу_желі(дескриптор_мән);
```

нақты_деректер 프로그램에서는 Ашу·жіберу·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 күте_тұрыңыз_мән 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 қосу_енгізу 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | дескриптор_мән·Процесс_мән_енгізу ұзындық_мән·성공 등 해당 함수의 НӘТИЖЕ |
| -5 | құрылғы_мән жіберу_мән_f993dacd қате_мән |
| -9 | 잘못되었거나 닫힌 통신 дескриптор_мән |
| -11 | 비차단 받기에서 도착한 деректер 없음 |
| -14 | пайдаланушы меңзер/массив_мән клип Қате |
| -19 | тіреу_мән NIC 없음 |
| -22 | порт_мән/күте_тұрыңыз_мән уақыт_мән/Аргументтер мән Қате |
| -24 | 열린 желі_порт 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | деректер 또는 수신 массив_мән Өлшемі 문제 |
| -98 | жергілікті_Аумақ порт_мән индекс 중복 |
| -101 | 지원하지 않는 тағайындау_мән мекенжай |
| -110 | ARP·құрылғы_мән·수신 уақыт_мән 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 кодтау_мән 있는 Java `int`의 бит_мән 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## орындау_пәрмен 경계와 시스템 호출

```text
қоршам run → JKAP에서 ELF тексеру_5fb2b747·적재 → ring 3 пайдаланушы бағдарлама_f5044b9b
                                 ↓ int 0x80
                      меңзер 검사 → Java ядро_мән API → RTL8139/UDP
                                 ↓ Шығу_бағдарлама·ерекшелік·уақыт_мән 초과
                                қоршам 복귀
```

시스템 호출 레지스터는 `EAX=индекс`, `EBX,ECX,EDX,ESI,EDI=Аргументтер`, `EAX=НӘТИЖЕ`다. Java 호출 операнд_Бума ABI는 컴파일러가 пайдаланушы 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| индекс | 호출 |
| --- | --- |
| 0 | Шығу_бағдарлама(күй_мән код_мән) — Орындау_2/Қате 런타임에서 사용 |
| 1 | жол_мән_6ca8363c Жазу |
| 2 / 3 | Аргументтер 개수 / Аргументтер жол_мән_6ca8363c мекенжай |
| 10 | UDP Ашу |
| 11 | UDP жіберу(дескриптор_мән, IP, тағайындау_мән порт_мән, массив_мән мекенжай, ұзындық_мән) |
| 12 | UDP 받기(дескриптор_мән, массив_мән мекенжай, 제한 밀리초) |
| 13 | UDP Жабу |
| 14 | жергілікті_Аумақ IP мекенжай |
| 15 / 16 | 마지막 бір_рангілі_мән IP / UDP порт_мән |
| 20 | RAM Файл Оқу(Аты int[] мекенжай, Шығысы int[] мекенжай) |
| 21 | RAM Файл Жазу(Аты int[] мекенжай, 입력 int[] мекенжай, байт_мән ұзындық_мән) |
| 22 | UTF-16 код_мән сабақ_мән 문자 Шығысы(0~65535) |

Файл API는 `пайдаланушы.파일읽기(int[] Аты, int[] деректер)`와 `пайдаланушы.жазу_файл(int[] Аты, int[] деректер, int ұзындық_мән)`다. 이름은 ASCII код_мән массив_мән(최대 64칸, 0 Шығу_бағдарлама 또는 массив_мән 끝), деректер элемент_элемент 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 Файл 없음 `-2`, меңзер Қате `-14`, Аты/ұзындық_мән Қате `-22`, Файл 슬롯 부족 `-28`, Өлшемі 초과 `-90`을 반환한다. 쓰기는 тексеру_5fb2b747 후 Файл 전체를 대체한다. `пайдаланушы.жазу_таңба_мән(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 пайдаланушы 모드에서 CS의 하위 비트를 직접 읽으므로 нақты_деректер орындау_пәрмен 권한을 확인한다. ядро_мән 포트 접근용 `құрылғы_мән` native 함수는 пайдаланушы мақсатты_мән 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 орындау_пәрмен, 파이프, 프로세스 간 통신은 없다. орындау_пәрмен 파일은 커널의 Оқу 전용 JKAP 묶음에서 적재한다. деректер 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- пайдаланушы 가상 мекенжай `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. орындау_пәрмен 영상은 алдыңғы_камера_мән 2MiB, 인수는 `0x04300000`부터, 스택은 аумақ_мән 끝에서 시작한다. ядро_мән identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB пайдаланушы 영역을 비우고 Файл 구역을 복사해 BSS·массив_мән 영역을 초기화한다. пайдаланушы GC는 없지만 Шығу_бағдарлама 후 Келесі_элемент орындау_пәрмен 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 Цитата/이스케이프 파싱은 없다.
- пайдаланушы 페이지의 код_мән/деректер 분리 Оқу 전용 Баптаулар, NX, операнд_Бума guard, ASLR은 아직 없다. 커널과 пайдаланушы Жад_деректер·포트 рұқсат_мән 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 орындау_пәрмен 상한을 두며 уақыт_мән 초과는 `Exit: 124`다. пайдаланушы CPU 예외는 `128 + ерекшелік индекс`(페이지 Қате 142, 특권 위반 141), Java массив_мән/계산 오류는 101~105다. ядро_мән 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, тұрақты_мән IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP тексеру_қорытындысы 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- пайдаланушы орындау_пәрмен·네트워크·қорғау_мән 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 орындау_пәрмен·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## тексеру_5fb2b747 근거

`make test`는 컴파일러 14개 시험, Java 패킷 шарт 2,201개 검사, 기존 қоршам ELF/ISO 부팅 시험, пайдаланушы ELF/нақты_деректер UDP/қорғау_мән 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 ұзындық_мән·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 Команда·무한 спринт_мән 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
