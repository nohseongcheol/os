# пайдаланушы 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `компьютер/операциялық_жүйе_Қоңыраулар.s`에서 EAX(индекс), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 Аргументтер)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. ядро_мән 실패는 음수 Қате индекс, C кітапхана 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 пайдаланушы аумақ_мән 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C деректер 주소는 байт_мән 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java Файл 흐름의 어셈블리 경계가 별도 байт_мән 버퍼를 마련하여 같은 호출을 사용한다.

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 мекенжай 두 칸이다. 수신 주소가 NULL이면 бір_рангілі_мән мекенжай 기록을 생략한다. sockaddr_in은 16바이트이며 мекенжай 체계는 құрылғы_мән байт_мән 차례, 접속번호와 IP 주소는 네트워크 байт_мән 차례다. 축소된 мекенжай 버퍼에도 들어가는 앞부분을 쓰고 전체 мекенжай Өлшемі 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 Шығу_бағдарлама, 2·3은 기존 Аргументтер 조회다. ток_элемент 커널의 Аргументтер 목록이 орындау_пәрмен 이름을 제외하므로 C 진입기는 argv[0]에 고정 жол_мән_6ca8363c `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX Процесс_мән ABI와 다른 점이다.

표준 헤더의 бүтін_сан Өлшемі, 플래그 мән, stat өріс_мәні 순서는 `Неден/포함/`에 정의한다. 동적 Байланысу·다중 Процесс_мән·스레드가 추가되면 Қате индекс 저장과 ресурс_мән 수명, 호출 경계도 함께 검토해야 한다.
