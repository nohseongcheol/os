# свой ARM64 пространство_пользователя 실행 ABI v1

이 ABI는 `platforms/rpi4-native`의 제한된 freestanding 실행 환경이다. Linux AArch64 ABI나 POSIX 전체 구현이 아니다. **OpenJDK/JRE, CPython, libc, libstdc++는 아직 이식되지 않았다.**

ELF 로더는 файл 확장자 대신 фактический_данные ELF 헤더를 검사한다. 아래 свой ABI와 별도로 `run --linux FILE`에 제한된 Linux ARM64 статический_ЗНАЧЕН 실행 файл 경로를 추가했다. 두 시스템 호출 번호표를 혼합하지 않는다. [ELF·Linux ABI 매뉴얼](исполняемый_ABI.md).

## ELF와 실행 수명

- ELF64 little endian, ET_EXEC, EM_AARCH64, 버전 1, e_flags=0.
- программа_f5044b9b 헤더 최대 16개. PT_LOAD는 Чтение 가능, 4 KiB выровнять_ЗНАЧЕН, 페이지 간 вложение_ЗНАЧЕН 없음, filesz≤memsz, BLD_фото АДРЕС клип 안이어야 한다. W+X는 거부한다.
- 진입점은 файл 내용이 있는 실행 세그먼트 안의 4바이트 выровнять_ЗНАЧЕН 주소다.
- PT_NOTE에 Название `JKOROS\0`(namesz=7), type=1, descsz=4, 버전 1의 little endian uint32가 필요하다. SDK의 `start.o`가 넣는다.
- PT_DYNAMIC/PT_INTERP/PT_TLS 등은 거부한다. 동적 재배치·공유 библиотека·TLS 로더가 없다.
- 커널에 포함한 ELF 묶음을 검증하고 별도 пространство_пользователя 메모리에 복사한 BACK_ЗНАЧЕН EL0로 진입한다. 커널에 함수로 статический_ЗНАЧЕН 링크해 호출하는 Назад_товар `cpp_test`와 다르다.
- 내장 프로그램은 `demo.elf`, `fault.elf`의 8개 защитить_ЗНАЧЕН испытания МОДА_ЗНАЧЕН, `network.elf`, свой Java инструменты, MicroPython이다. 셸의 `load`/`run FILE`로 RAM의 16KiB 이하 ELF도 같은 проверить 경로로 실행한다.
- `_start`가 `user_start`를 호출하고 `.init_array` → `Пуск_пользователь_программа(int)` → `.fini_array` 순서로 실행한 BACK_ЗНАЧЕН exit 호출을 수행한다. 인수는 호출 15로 읽으며 표준 argc/argv/envp операнд_стек 배치는 없다.
- 한 번에 한 пространство_пользователя 프로그램이 CPU에서 실행된다. 네 터미널에 각 하나씩 интерактивный 프로그램을 일시 정지해 보관할 수 있다. ИТ_службы_обычный Выход_программа·исключение·значение_времени 초과 시 커널에 복귀하고 열린 файл/소켓을 닫으며 пространство_пользователя 페이지 권한을 제거한다.
- статический_ЗНАЧЕН 생성자와 자동 객체의 RAII 소멸자를 시험했다. `__cxa_atexit`, 표준 C++ исключение/RTTI/STL, 일반적인 전역 объект_ЗНАЧЕН Выход_программа 등록은 제공하지 않는다.

## 주소와 защитить_ЗНАЧЕН

| 가상 АДРЕС клип | 용도 |
|---|---|
| 0x02000000–0x02bfffff | ELF BLD_фото, 최대 12 MiB |
| 0x02c00000–0x02ecffff | brk куча_ЗНАЧЕН, 최대 2880 KiB |
| 0x02ed0000–0x02efffff | 미매핑 SMS_диапазон/операнд_стек 아래 защитить_ЗНАЧЕН SMS_диапазон |
| 0x02f00000–0x02ffffff | 1 MiB пространство_пользователя операнд_стек |

свой JVM의 Класс_ЗНАЧЕН·объект_ЗНАЧЕН 자료를 수용하도록 пространство_пользователя 창을 16 MiB로 확장했다. программа_f5044b9b 헤더의 разрешить_ЗНАЧЕН клип, 페이지 Полномочие_ЗНАЧЕН 검사, SDK 링커 скрипт_ЗНАЧЕН 및 защитить_ЗНАЧЕН 시험이 같은 배치를 사용한다. 기존에 brk запустить 주소를 상수로 가정한 프로그램은 새 SDK로 повторить_попытку_ЗНАЧЕН 빌드한다. 일반 프로그램은 호출 8로 текущий_товар brk를 조회한다.

실행 코드는 EL0 Чтение/실행만, данные·куча_ЗНАЧЕН·스택은 EL0 Чтение/쓰기만 허용한다. 나머지 ядро_ЗНАЧЕН RAM·устройство_ЗНАЧЕН MMIO에는 EL0 권한을 주지 않는다. 이번 W^X 보장은 **пространство_пользователя 페이지에 대한 것**이다. kernel identity map의 전체 Полномочие_ЗНАЧЕН 분할이나 다중 프로세스 АДРЕС АДРЕС_регион 전환을 구현했다고 의미하지 않는다.

커널은 `-mgeneral-regs-only`로 빌드한다. пространство_пользователя C/C++는 FP/SIMD를 허용하고, пространство_пользователя точка_входа_ЗНАЧЕН 시 вектор_ЗНАЧЕН 레지스터와 FPCR/FPSR를 초기화한다. ядро_ЗНАЧЕН 복귀용 callee-saved FP 상태를 보관한다. syscall/IRQ의 C 처리부는 FP 레지스터를 사용하지 않는다. 향후 여러 пространство_пользователя 스레드를 전환할 때에는 각 스레드의 전체 FP контекст_ЗНАЧЕН 보존을 별도로 구현해야 한다.

GIC-400의 물리 타이머 IRQ로 약 2초의 실행 기한을 적용한다. SVC 없는 무한 반복도 종료한다. 시스템 호출 запустить 시 기한을 검사하지만 EL1 Процесс_ЗНАЧЕН_ввод 중에는 IRQ를 마스킹하므로 긴 текстовыйВывод/Paint_экран 호출의 종료는 지연될 수 있다. 이것은 программа_f5044b9b 실행 기한이며 일반 선점 스케줄러가 아니다.

UART에 읽을 자료가 없으면 -EAGAIN, файл/파이프 входные_данные_ЗНАЧЕН 끝이면 read가 0을 반환한다. 출력은 файл/파이프에서 LF를 그대로 유지하고 UART에서만 CRLF로 표시한다. 파이프는 16 KiB 순차 버퍼이며 프로세스 간 동시 파이프/PTY는 아니다. read/write 요청은 65536바이트 이하이며, RAM 파일은 최대 64개, 각각 16384바이트다. файл 경로는 текущий_товар оболочка 경로에 대한 одноранговый_ЗНАЧЕН путь 또는 `/`로 시작하는 절대 경로이며 UTF-8 63바이트까지다. 디렉터리 генерировать·빈 Каталог_ЗНАЧЕН удалить_ввод·Вид_ЗНАЧЕН 조회는 호출 18로도 제공한다. текущий_товар путь 변경은 оболочка 내장 cd가 담당한다. 그래픽 요청은 호출 22로 조회한 фактический_данные экран Размер 안의 직사각형만 허용한다. 프레임버퍼 АДРЕС 자체는 사용자에게 노출하지 않는다.

힙의 페이지 урок_ЗНАЧЕН 축소·재확장에서 повторить_попытку_ЗНАЧЕН 노출하는 페이지는 0으로 만든다. 같은 페이지 안에서 brk만 줄였다 늘리는 경우에는 해당 페이지 내용이 남을 수 있다. malloc/free나 mmap/mprotect의 구현은 아니다.

인수는 최대 8개·각 255바이트다. 잘못된 번호는 -EINVAL, 작은 버퍼는 -ENAMETOOLONG, Запись 불가능한 포인터는 -EFAULT다. `run FILE [ARGS]`는 파일명을 аргументы 0으로 포함한다. `javac`/`java`/`python`은 명령어 자체를 제외한 토큰을 전달한다. 인수는 ядро_ЗНАЧЕН 보관 자료를 пространство_пользователя 버퍼로 복사하며 ядро_ЗНАЧЕН 포인터를 반환하지 않는다.

## UDP 루프백의 계약

바깥 IPv4는 lwIP/SLIP로 확장했다. 기존 fd/구조체/указатель 검사 규약을 유지하며 0.0.0.0 또는 10.0.2.15에 bind한 끝점을 바깥 통신에 연결한다. 127.0.0.1에 명시적으로 bind한 UDP는 루프백에 한정한다. внешний_ЗНАЧЕН TCP connect는 비차단 -EINPROGRESS(-115)를 반환할 수 있으므로 같은 주소로 재시도하여 완료를 확인한다. [실행/제한](파일전송과번역.md).

`облако_Семья`, `сокет_датаграмм`, передать_протокол 0/`датаграмма_протокол`을 허용한다. `struct облако_сокет_АДРЕС`는 16바이트이며 주소갈래는 устройство_ЗНАЧЕН ПОСЛЕД_ЗНАЧЕН, 접속번호와 адрес_в_Интернете.주소값은 сеть_ЗНАЧЕН 차례다. 호환용 pk_sockaddr_in도 같은 배치지만 독립 자료형이다. русский 함수는 직접 SVC를 호출하는 фактический_данные 함수이며 표준 이름으로 치환하는 매크로가 아니다. узел Linux 헤더를 섞지 않는다.

- 목적지는 127.0.0.1만 разрешить_ЗНАЧЕН. bind는 0.0.0.0 또는 127.0.0.1, port=0이면 49152…65535에서 빈 창구를 고른다.
- 미바인드 소켓의 첫 전송은 임시 창구를 바인드한다. 같은 창구의 중복 bind는 EADDRINUSE.
- 최대 8개 сокет_ЗНАЧЕН, 각 큐 4개, 전문은 0…512바이트. 빈 전문도 소비된다.
- получить_ЗНАЧЕН 버퍼가 작으면 복사할 부분만 반환하고 전문의 나머지는 버린다. peer АДРЕС/창구를 반환한다.
- flags는 текущий_товар 0만 опора_ЗНАЧЕН. 비차단 수신의 빈 큐 및 написать_ЗНАЧЕН целевое_значение 큐 포화는 EAGAIN이다.
- целевое_значение порт_ЗНАЧЕН 없음은 ECONNREFUSED, 512바이트 초과는 EMSGSIZE, 루프백에 명시적으로 바인드한 UDP의 внешний_ЗНАЧЕН IP는 ENETUNREACH, UDP 소켓에 잘못된 규약을 지정하면 EPROTONOSUPPORT. SOCK_STREAM은 별도 연결형 루프백에서 제공한다.
- внешний_ЗНАЧЕН IPv4 TCP/UDP 헤더·체크섬·재전송은 lwIP가 처리한다. фактический_данные GENET/Wi-Fi NIC, poll/select, setsockopt는 아직 없다. 연결형 루프백의 connect/listen/accept는 아래 расширение_ЗНАЧЕН ABI로 제공한다.

## 여러 터미널의 пространство_пользователя контекст_ЗНАЧЕН

интерактивный tty/GUI 대기를 명시적으로 시작한 프로그램은 входные_данные_ЗНАЧЕН 대기에서 약 2초 기한을 갱신한다. минутку_ЗНАЧЕН 없이 무한 반복하면 타이머로 종료한다. 파이프/리다이렉션/복합 команда/스크립트에서 интерактивный 시작은 -ENOTSUP로 거부한다. vi와 Swing의 이벤트 루프가 이 API를 사용한다.
