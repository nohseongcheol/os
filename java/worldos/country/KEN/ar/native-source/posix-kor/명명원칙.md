# العربية 명명 원칙과 근거

이 문서의 새 이름은 jkoros 프로젝트의 선택이다. العربية 전체나 특정 국가의 유일한 لغة 철학을 대표한다고 주장하지 않는다. 기존에 분명한 용어는 유지하고, 모호한 음역이나 여러 의미가 섞인 이름은 حديث_عنصر 코드의 동작을 중심으로 고친다. 다른 언어판은 الهدف 언어와 용례를 별도로 검토해야 한다.

함수는 대상과 동작을 결합한다. `يقرأ_ملف_بيانات`, `يبحث_ملف`, `يربط_عنوان`처럼 무엇에 무엇을 하는지 이름에서 읽히게 한다. 변수는 값의 역할과 단위를 나타내도록 `파일서술자`, `바이트수`, `수신대기밀리초`, `جيل_رقم`로 쓴다. 구동기는 장치를 움직이는 구현, 처리기는 특정 입력을 처리하는 구현으로 구분한다.

어원은 설계 개념을 이해하는 근거로 사용한다. 역사적 은유를 그대로 번역해서 حديث_عنصر 동작을 흐리게 만들지 않는다. 확인되지 않은 고어·최초 يستخدم_قيمة 시점은 만들어 넣지 않는다. 아래의 العربية 표현이 해당 시기의 الفعلي_بيانات 번역어였다는 의미도 아니다.

| 개념 | 선택한 اسم | 의미와 역사적 근거 |
|---|---|---|
| file descriptor | 파일서술자 | 열린 대상을 가리키는 عدد_صحيح حساب_قيمة. حالة_أولية UNIX 문헌도 open/create가 돌려주는 서술자로 시스템 표의 إدخال_إخراج 위치를 찾는 구조를 설명한다. اسم سلسلة_قيمة·ملف 본체·열린 ملف 상태를 구분한다. |
| open file description | 열린 ملف 기술 | فتح 설정과 حديث_عنصر 위치를 담는 공유 حالة_قيمة. 서술자 자체와 구별하는 POSIX의 정의를 따른다. |
| unlink | يزيل_ملف_إدخال_اسم | ملف محتوى_قيمة 즉시 폐기가 아닌 اسم اتصال يزيل_إدخال. 열린 참조가 남으면 내용이 살아 있는 의미를 반영한다. |
| seek / offset | يبحث_ملف / إزاحة_قيمة | 읽고 쓰는 위치를 기준점에서 이동한다. 수색·탐색이라는 일반어보다 해당 함수의 حديث_عنصر 역할을 표현한다. |
| socket | مأخذ_التوصيل_المشارك | 통신이 드나드는 논리적 إنهاء_مكالمة_نقطة. 1971년 RFC 147도 전송의 출발·도착 식별자로 socket을 설명했다. 당시 32비트·짝홀 구분을 현대 API에 그대로 적용하지 않는다. |
| network port | رقم_المنفذ | 인터넷 عنوان 안에서 통신 상대를 구분하는 فهرس. RFC 768의 출발/도착 أجهزة_منفذ 정의를 반영하며 CPU إدخال_إخراج 주소와 구별한다. |
| datagram | 자료전문 | 경계를 가진 하나의 메시지. RFC 768의 datagram 방식과 UDP 길이 필드가 가리키는 단위를 드러낸다. |
| driver | 구동기 | جهاز_قيمة 초기화와 송수신 명령을 수행하는 رمز_قيمة_f3cd31ee. RTL8139 구현 이름은 망장치구동기다. |
| RAM file | ذاكرة_نظام_الملفات | ينفذ_أمر 중 자료가 주기억에 놓이는 تصميم. جهاز_تخزين 보존 계층과 역할을 구분한다. |
| snapshot / generation | 보존본 / جيل_رقم | تزامن 시점의 ملف 표와 بيانات 전체 및 그 أمر_قيمة. 단순한 백업 완료 표식과 الفعلي_بيانات 본문을 구분한다. |
| stream | ملف إدخال_قيمة/مخرجات بث_قيمة | 바이트를 순서대로 읽고 쓰는 إجراء. 표준 Java 클래스의 이름은 호환성을 위해 FileInputStream/FileOutputStream으로 유지한다. |

표의 UNIX 역사 서술은 [Ritchie·Thompson의 UNIX 논문 재록본](https://cm-bell-labs.github.io/who/dmr/cacm.html)에 근거한다. 열린 حالة_قيمة·موضع·삭제의 의미는 POSIX의 [open](https://pubs.opengroup.org/onlinepubs/9799919799/functions/open.html), [dup](https://pubs.opengroup.org/onlinepubs/9799919799/functions/dup.html), [lseek](https://pubs.opengroup.org/onlinepubs/9799919799/functions/lseek.html), [unlink](https://pubs.opengroup.org/onlinepubs/000095399/functions/unlink.html)를 참고했다. 통신 용어의 역사와 حديث_عنصر 규약은 [RFC 147](https://www.rfc-editor.org/info/rfc147/)과 [RFC 768](https://www.rfc-editor.org/info/rfc768/)을 참고했다.

표준 이름을 번역된 심벌로 강제로 바꾸면 기존 프로그램과 도구가 연결되지 않는다. 따라서 POSIX/C의 공개 심벌, Java 표준 فئة_قيمة_55654bf1·أسلوب_قيمة, ELF/x86 ABI, أجهزة_قيمة 레지스터 명칭과 `Makefile` 같은 أدوات نقطة_الإدخال_قيمة 파일은 유지한다. العربية API는 같은 동작의 별칭이다. `يقرأ_أجهزة_منفذ` 같은 프로젝트 내부 식별자는 إدخال_إخراج بايت_قيمة 접근으로 뜻을 좁혀 الفعلي_بيانات 코드와 네이티브 연결표까지 함께 바꿨다. الفعلي_بيانات 적용 목록은 [용어대응.tsv](용어대응.tsv)에 있다.
