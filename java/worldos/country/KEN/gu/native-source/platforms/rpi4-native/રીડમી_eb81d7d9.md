# Raspberry Pi 4 자체 Java કર્નેલ_મૂલ્ય — ઉપયોગકર્તા અમલ_કરો_આદેશ 기반

현재 자체 코드의 COSL 상업 શરત, 제3자 고지 및 LGPL 재연결 자료는 [COSL 배포 રીડમી_eb81d7d9](COSL배포안내.md)를 참고한다. સ્વિચ_મોડ 전 GPL 구성의 판단은 [이전 라이선스 검토](લાઇસન્સ_સમીક્ષા.md)에 기록했다.

ગુજરાતી 통신·예외 사용법은 [ગુજરાતી Java API](한국어자바/રીડમી_eb81d7d9.md), ફંક્શંસ_મૂલ્ય·변수·ફાઈલ 이름의 변경과 어원 근거는 [명명 રીડમી_eb81d7d9](명명/રીડમી_eb81d7d9.md)를 참고한다.

Linux 없이 부팅하는 자체 AArch64 커널이다. Java AOT કર્નેલ_મૂલ્ય 위에 **આદેશ_પંક્તિ શેલ, 게스트 Java 컴파일러·JVM, MicroPython, EL0 C++ અમલ_કરો_આદેશ, ફાઈલ·UDP 루프백 시스템 호출, 여러 한글 GUI ટર્મિનલ·vi સંપાદક·Swing 부분집합**을 제공한다. 커널의 ફાઈલ ડેટા/정책·루프백 સ્થાનાંતર_મૂલ્ય·શેલ 상태는 Java, 화면 합성·પેલ પરિવર્તન_કરો_મૂલ્ય·સૂચક·클리핑도 Java로 구현하며, CPU/MMU/ડિવાઇસ_મૂલ્ય 경계와 ટર્મિનલ·વર્ણ_મૂલ્ય 그리기 연결은 C와 어셈블리다.

**전체 JDK/JRE·CPython·표준 C++ 런타임·Swing 이식은 아직 완료되지 않았다.** 기존 [ARM64 Linux 실행판](../rpi4/README.md)의 OpenJDK/Python 패키지를 이 자체 커널에 탑재했다고 표시하지 않는다.

새로운 게스트 `cc`/`jaot`, JAR 직접 અમલ_કરો_આદેશ, lwIP TCP/UDP와 FTP는 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)을 참고한다. 게스트 SSH·VNC와 Pi4 GENET/PHY·DHCP 드라이버를 추가했다. **SSH·VNC는 QEMU에서 검증하며, 실물 Pi4의 વાયર્ડ_મૂલ્ય 송수신은 아직 미검증이다.** અમલ_કરો_આદેશ·કનેક્શન_e05f319b·પાસવર્ડ_મૂલ્ય 확인은 [외부 કનેક્શન_e05f319b રીડમી_eb81d7d9](외부접속안내.md)에 정리했다.

셸은 EL1 કર્નેલ_મૂલ્ય, `java` 등 ઉપયોગકર્તા અમલ_કરો_આદેશ 파일은 EL0에서 실행한다.
`ps`·`top`의 표시와 제한, QEMU 네트워크 અમલ_કરો_આદેશ·કનેક્શન_e05f319b 방법 및 વાસ્તવિક_ડેટા 검증은
[અમલ_કરો_આદેશ 계층과 외부 통신 점검](실행계층과외부통신점검.md)을 참고한다.

ELF는 확장자가 아닌 વાસ્તવિક_ડેટા અમલ_કરો_આદેશ 형식으로 검사한다. `./인사`처럼 확장자 없이 실행하며, 제한된 Linux ARM64 સ્થિર_મૂલ્ય ELF는 `run --linux ફાઇલ_નામ_પાઠ`으로 실행한다. [ELF·Linux ABI સપોર્ટ_મૂલ્ય 범위와 동일 바이너리 시험](실행파일규약.md).

GUI와 네트워크는 `python3 ઉપકરણો/અમલ_કરો_આદેશ.py --desktop --network`로 함께 사용한다. Java·C·Python의 ગુજરાતી 예제 13개는 [jkoros/example](../../example/README.md)에 있으며, **게스트 부팅 시 `/example/java`, `/example/c`, `/example/python`에 자동으로 준비된다.** `example java|c|python`으로 지운 예제를 복원할 수 있다. Remmina에서 **F9/Shift+Space/한·영 કી_મૂલ્ય**로 `[EN]`↔`[KO]` 두벌식을 전환한다(`help ko`). `make test-examples`는 같은 GUI VM에서 FTP·વાસ્તવિક_ડેટા TCP/UDP·ફાઈલ બાઇટ_મૂલ્ય·그래픽 픽셀을 검증한다.

게스트에서 `cd /example/java` 후 `java 창예제`로 ગુજરાતી Swing 예제를 실행한다. ટર્મિનલ 모서리에 마우스를 대고 **왼쪽 버튼으로 끌면 크기가 바뀐다**. `terminal size`는 현재 હરોળ_મૂલ્ય·પંક્તિ_મૂલ્ય 수를 보여 준다.

અમલ_કરો_આદેશ 버튼 화면은 5×7 영문 글꼴을 쓰며, ટર્મિનલ 창은 Noto CJK/DejaVu에서 생성한 한글·Unicode 비트맵 글꼴을 쓴다. UART와 વાસ્તવિક_ડેટા 프레임버퍼의 한글 표시를 시험한다. 루프백은 동일 કર્નેલ_મૂલ્ય 내부의 전문 전달이며 IP 패킷을 Ethernet으로 내보내는 드라이버가 아니다. 바깥 IPv4는 lwIP TCP/UDP 스택으로 보조 UART SLIP 경로를 사용한다. `python3 ઉપકરણો/અમલ_કરો_આદેશ.py --network`로 QEMU NAT를 연결하고 `ftpd start`로 서비스를 시작한다.

Java의 정확한 API·문법·અમલ_કરો_આદેશ 제한과 ગુજરાતી 사용법은 [자체 JVM과 ગુજરાતી લાઇબ્રેરી](자바실행환경.md)에 정리했다. વર્ગ_મૂલ્ય ફાઈલ/JAR 배포는 [한국어자바](한국어자바) 소스에서 재현한다. 기존 Linux판 `ગુજરાતી.자바`와 별도인 `ગુજરાતી.자체` 패키지다.

**vi·여러 વિંડો·Swing·한글 Java/Python/C/C++·posix-kor 예제는 [한글 개발 매뉴얼](개발안내.md)에 정리했다.**

GUI ટર્મિનલ અમલ_કરો_આદેશ·단축키·શેલ આદેશ·제한은 [셸과 ટર્મિનલ 사용법](셸과터미널.md)에 정리했다.

## 현재 컴퓨터에서 અમલ_કરો_આદેશ

```sh
cd /home/user/jkoros/platforms/rpi4-native
make test
make run
```

પ્રસ્થાન_એપ્લિકેશન: **Ctrl+A આગલું_આઇટમ X**. 게스트 C/AOT ઉપકરણો 빌드에는 `make rpi-prepare`로 준비한 ARM64 SDK 헤더와 libgcc 산술 보조 함수도 필요하다. libc나 Linux 커널을 게스트에 넣는 것은 아니다. હોસ્ટ 도구는 JDK 11 이상, Python 3.6 이상, Clang/Clang++, AArch64 GNU binutils, Make, `libnewlib-dev` 헤더다. MicroPython은 `/usr/include/newlib` 헤더를 사용하며 다른 위치는 `NEWLIB_INCLUDE`로 지정한다. newlib 런타임을 이식·링크한 것은 아니다. 컴파일러 의미 비교에는 GCC/UBSan도 사용한다. 기존 `../rpi4/build/host`의 QEMU 11.0.3이 있으면 이용하며, 그렇지 않으면 PATH의 QEMU를 사용한다. `QEMU_AARCH64=/절대/પથ/qemu-system-aarch64`로 지정할 수도 있다. `raspi4b` સપોર્ટ_મૂલ્ય 여부를 확인한 후 실행한다.

명령은 **Enter를 눌러 અમલ_કરો_આદેશ**한다. 기존 한 વર્ણ_મૂલ્ય 명령도 Enter가 필요하다.

```text
javac Hello.java
java Hello "한글 દલીલો 😀"
python hello.py
python -c 'print(2**100)'
ls
cat python.txt
run cpp
net test
gui
```

| `ls` / `cat FILE` / `rm FILE` | RAM ફાઈલ પ્રવેશ_સૂચી·સામગ્રી_મૂલ્ય·삭제 |

예를 들어 `edit 인사.java`를 입력한 આગલું_આઇટમ 아래 소스를 입력한다.

```java
public class 인사 { public static void main(String[] args) { int મૂલ્ય = 7; System.out.println("한글=" + મૂલ્ય); } }
```

그다음 단독 `.` 줄로 저장하고 `javac 인사.java`, `java 인사`를 실행한다. 편집기는 기존 파일에 커서를 이동하는 방식이 아니라 전체 교체 방식이다. રદ_કરો_ઑપરેશન·잘못된 16진수·용량 초과는 원본을 보존한다. 줄은 4096바이트, 파일은 16384바이트, અમલ_કરો_આદેશ 인수는 최대 8개·각각 UTF-8 255바이트다. 일반 આદેશ 인수는 최대 32개다. ક્વોટ·백슬래시·શેલ 변수·파이프·리다이렉션 범위는 [શેલ 설명](셸과터미널.md)을 참고한다.

GUI 터미널은 다음과 같이 실행하고 Remmina에서 **VNC**, સરનામું **127.0.0.1:5902**로 연결한다. 키보드·한글 Unicode 입력·명시적 ચોંટાડો_મૂલ્ય·અમલ_કરો_આદેશ 버튼의 마우스 클릭을 QEMU 도구가 UART에 전달한다.

```sh
make desktop
# GUI + 네트워크: python3 ઉપકરણો/અમલ_કરો_આદેશ.py --desktop --network
# 다른 હાર્ડવેર_પૉર્ટ: python3 ઉપકરણો/અમલ_કરો_આદેશ.py --desktop --port 5903
```

종료는 실행한 હોસ્ટ 터미널에서 Ctrl+C다. 기존 `python3 ઉપકરણો/અમલ_કરો_આદેશ.py --vnc 127.0.0.1:2`는 화면 보기와 별도 UART 입력을 유지한다. `make run`은 일반 UART 셸이다. વાસ્તવિક_ડેટા Pi4 USB 입력기는 아직 없으며, VNC સંપર્ક_કરો 도구는 QEMU 시험용이다.

GUI의 다섯 버튼은 વાસ્તવિક_ડેટા C++/UDP ELF અમલ_કરો_આદેશ, `Hello.java` બિલ્ડ_કરો_સ્રોત 후 JVM અમલ_કરો_આદેશ, `hello.py` અમલ_કરો_આદેશ, GUI ટર્મિનલ 열기를 수행한다. 한 번에 한 프로그램이 CPU에서 실행되며 일반 실행에는 약 2초 기한이 있다. vi·Swing은 સહભાગી 대기에서 기한을 갱신하고 다른 터미널로 전환할 때 મેમરી_ડેટા·CPU 문맥을 보관한다. શેલ·편집기에서 입력을 기다리는 시간에는 이 제한이 적용되지 않는다.

make image   # કર્નેલ_મૂલ્ય, SD બિલ્ડ_છબી, 부팅 ZIP, 사용자용 SDK

예비 microSD에 બિલ્ડ_છબી લૉગ_પંક્તિ 도구로 `.img`를 기록하거나 FAT32 부팅 파티션 최상위에 ZIP 내용을 푼다. બિલ્ડ_છબી 기록은 선택한 카드의 기존 내용을 지우므로 대상을 확인한다. Pi4 ડિફૉલ્ટ_મૂલ્ય EEPROM SD 부팅을 전제로 한다. UART는 **3.3V TTL, 115200 8N1**, GPIO14/TXD(8번)→어댑터 RX, GPIO15/RXD(10번)→TX, GND(6번) 연결이다. GPIO에 5V 신호를 연결하지 않는다.

**실물 Pi4 부팅은 미검증이다.** QEMU `-kernel`은 SD의 VideoCore 펌웨어를 실행하지 않고 커널을 직접 적재한다. SD ફાઈલ 구성·કર્નેલ_મૂલ્ય 체크섬 검사와 물리 બોર્ડ 부팅 검증은 별개다. MMU 사용 전에는 펌웨어의 캐시/MMU가 꺼져 있고 EL1 또는 EL2로 진입하는 통상 부팅 조건을 전제로 한다. 세 보조 코어는 대기시키며 한 코어만 사용한다.

## C++와 ગુજરાતી API 사용

SDK를 풀고 호스트에서 컴파일한다.

```sh
tar -xzf dist/jkoros-native-aarch64-sdk.tar.gz -C build
cd build/jkoros-native-sdk
python3 compile.py examples/파일예제.cpp -o demo.elf
python3 compile.py examples/통신예제.cpp -o network.elf
```

진입점은 `extern "C" int પ્રારંભ_ઉપયોગકર્તા_એપ્લિકેશન(int)`이다. ઉપયોગકર્તા C++는 FP/SIMD를 사용할 수 있다. કર્નેલ_મૂલ્ય C/Java AOT는 일반 레지스터만 사용하므로 예외 પ્રક્રિયા_મૂલ્ય_પ્રવેશ 중 ઉપયોગકર્તા FP 상태를 건드리지 않는다. ઉપયોગકર્તા પ્રવેશ_બિંદુ_મૂલ્ય 시 FP 상태를 초기화하고 કર્નેલ_મૂલ્ય 복귀에 필요한 상태를 보존한다.

```cpp
#include "파일규약.h"
extern "C" int પ્રારંભ_ઉપયોગકર્તા_એપ્લિકેશન(int) {
    int ફાઈલ = બનાવો_ફાઇલ("인사.txt", વાંચન_લેખન | 없으면만들기 | 내용비우기, 0600);
    if (ફાઈલ < 0) return 1;
    const char સામગ્રી_મૂલ્ય[] = "안녕하세요";
    int પરિમાણ = લખો_ફાઇલ_ડેટા(ફાઈલ, સામગ્રી_મૂલ્ય, sizeof(સામગ્રી_મૂલ્ય) - 1);
    બંધ_કરો_ફાઇલ(ફાઈલ);
    return પરિમાણ == sizeof(સામગ્રી_મૂલ્ય) - 1 ? 0 : 2;
}
```

[ફાઈલ 예제](ઉપયોગકર્તા/파일예제.cpp)와 [통신 예제](ઉપયોગકર્તા/통신예제.cpp)가 વાસ્તવિક_ડેટા 부팅 시험 대상이다. `파일규약.h`의 이름은 커널용/사용자용 모두 같지만 **링크하는 라이브러리가 다르다**. 사용자용은 `svc #0`으로 호출하고 ફાઈલ પ્રક્રિયા_મૂલ્ય_પ્રવેશ 및 루프백 전달은 Java 커널에서 실행한다. `통신규약.h`의 소켓 함수는 현재 사용자용 라이브러리에 구현돼 있다.

새 프로그램은 કર્નેલ_મૂલ્ય 재빌드 없이 `load FILE.elf`와 `run FILE.elf`로 실행한다. 호스트에서 આગલું_આઇટમ 도구를 사용하면 **새 QEMU를 부팅해 업로드한 વાસ્તવિક_ડેટા 바이트를 재확인한 બેક_મૂલ્ય 게스트에서 અમલ_કરો_આદેશ**하고 종료한다. 이 도구의 새 VM에서 만든 RAM 자료는 종료할 때 사라진다.

```sh
cd /home/user/jkoros/platforms/rpi4-native
python3 ઉપકરણો/અમલ_કરો_ફાઇલ.py build/jkoros-native-sdk/demo.elf
python3 ઉપકરણો/અમલ_કરો_ફાઇલ.py 예제/Hello.java "한글 દલીલો"
python3 ઉપકરણો/અમલ_કરો_ફાઇલ.py 예제/hello.py
```

이 경로는 16KiB 이하의 `.elf`, `.java`, `.class`, `.py`를 지원한다. 큰 내장 Java/MicroPython ELF 자체는 કર્નેલ_મૂલ્ય 묶음에 포함되어 이 ફાઈલ 한도를 적용받지 않는다. **C++ 컴파일러는 હોસ્ટ SDK의 Clang++**이며 게스트 내부 GCC/Clang 컴파일러는 아직 없다. SDK만으로 일반 Linux 프로그램을 실행할 수는 없다. Linux ELF, 동적 લાઇબ્રેરી, PT_TLS, PT_INTERP, PT_DYNAMIC, અમલ_કરો_આદેશ·લખો 겸용 세그먼트는 로더가 거부한다. 구체적인 호출 અનુક્રમણિકા·સરનામું ક્લિપ·오류는 [ઉપયોગકર્તા ABI](사용자호출규약.md)를 참고한다.

RAM 파일은 재부팅 시 사라진다. `파일저장확정`은 -1과 ENOSYS를 반환한다. 파일의 mode 인수를 저장하지 않으며 અનુમતિ_મૂલ્ય·dup/fcntl은 없다. 디렉터리와 પીઅર_મૂલ્ય/절대 경로는 같은 RAM 저장소에서 처리한다. UDP 전문은 최대 512바이트, 소켓은 8개, 수신 큐는 소켓당 4개다. 수신할 자료가 없거나 큐가 가득 차면 EAGAIN을 반환한다. ઉપયોગકર્તા પ્રસ્થાન_એપ્લિકેશન 시 열린 ફાઈલ 서술자와 소켓을 회수한다.

## માન્ય_કરો પરિમાણ

`make test-jvm`은 9개 프로그램을 OpenJDK와 વાસ્તવિક_ડેટા 자체 커널에서 실행해 결과를 비교한다. `make test`에도 포함된다. 별도 `ઉપકરણો/부팅시험.py`는 Java 사각형 API의 વાસ્તવિક_ડેટા 화면 픽셀까지 검사한다. `make test-shell`, `make test-desktop`은 새 셸과 વાસ્તવિક_ડેટા VNC 입력·한글 ટર્મિનલ 화면을 검사하며 `make test`에도 포함된다.

`make test-windows`, `make test-swing`, `make test-stream`, `make test-coding`도 제공하며 `make test`에 포함된다.

`make test`는 OpenJDK와 AOT ઑપરેશન_મૂલ્ય પરિમાણ 비교, 런타임 ભૂલ 중단, 미지원 Java 거부와 함께 별도 QEMU VM에서 다음을 검사한다.

- 기존 Java કર્નેલ_મૂલ્ય 계산·UTF-8·C++ 직접 호출·협력식 작업 및 프레임버퍼.
- 손상/잘못된 ABI/સરનામું 초과/겹친 페이지/W+X 등 ELF નકારો_મૂલ્ય 사례 22개.
- EL0 C++ 생성자·RAII·실수 ઑપરેશન_મૂલ્ય·ફાઈલ·힙 및 잘못된 시스템 호출 સૂચક.
- કર્નેલ_મૂલ્ય/코드/MMIO લખો·ઍક્સેસ_પ્રવેશ, NX 스택·NULL અમલ_કરો_આદેશ, guard page, 특권 આદેશ 차단.
- SVC를 호출하지 않는 무한 반복을 타이머로 종료한 후 정상 એપ્લિકેશન_f5044b9b 재실행.
- પુનરાવર્તન_મૂલ્ય અમલ_કરો_આદેશ 시 ફાઈલ/소켓 누수 방지, UDP 왕복·보낸 સરનામું·잘린 수신·큐 포화·빈 전문·미지원 통신 ભૂલ.
- શેલ સંપાદન_મૂલ્ય·રદ_કરો_ઑપરેશન·16진수 업로드/다운로드·ઉપયોગકર્તા ELF 실행과 잘못된 ELF નકારો_મૂલ્ય.
- 게스트 Java → OpenJDK `-Xverify:all`, OpenJDK → 게스트 JVM 교차 અમલ_કરો_આદેશ, 한글 વર્ગ_મૂલ્ય·변수·ફાઇલ_નામ_પાઠ.
- 여러 વિંડો·vi સંગ્રહ_કરવો_મૂલ્ય·સંપાદન_મૂલ્ય·되돌림·ઉપયોગકર્તા સ્થિતિ_મૂલ્ય_e10195a1 중단/재개, Swing 한글 입력·이벤트·X બંધ_કરો, 연결형 루프백, C/C++ 한글 SDK 예제.

## Java와 Python의 정확한 ક્લિપ

자체 `javac`는 버전 49 `.class`를 생성하며 JVM은 સપોર્ટ_મૂલ્ય 명령으로 구성된 버전 45–52 클래스를 실행한다. સ્થિર_મૂલ્ય ફંક્શંસ_મૂલ્ય·재귀·int/boolean/char/String·શરત/પુનરાવર્તન_મૂલ્ય·સ્ટ્રિંગ_મૂલ્ય 결합과 일부 ફાઈલ 스트림을 지원한다. UTF-8 문자열과 문자 리터럴, ASCII 및 현대 한글 음절/조합 자모 식별자를 처리한다. Unicode ઓળખકર્તા_મૂલ્ય 전체 લુકઅપ_કોષ્ટક·Unicode સ્રોત_ટ્રી 이스케이프는 구현하지 않았다. 게스트 સ્રોત_ટ્રી 컴파일러는 일반 ઑબ્જેક્ટ_મૂલ્ય·예외·Thread 구문을 아직 컴파일하지 못한다. હોસ્ટ `javac --release 8`로 만든 સપોર્ટ_મૂલ્ય 부분집합 클래스는 자체 JVM 0.4의 ઑબ્જેક્ટ_મૂલ્ય·예외·Thread·UDP와 ગુજરાતી API를 사용할 수 있다. Swing은 문서화한 자체 API 부분집합을 제공하며 JAR 로더는 제공하지만 전체 AWT/Swing·JDK 표준 라이브러리는 없다. 정확한 범위는 [자체 JVM 설명](자바실행환경.md)이 기준이다. 상세 ભાષા 범위는 [공유 Java ઉપકરણો 설명](../../문서/자바개발환경.md)을 참고하되, 그 문서의 x86 શેલ/સંગ્રહ_કરવો_મૂલ્ય/실행시간과 이 ARM64 판의 차이에 유의한다.

MicroPython은 공식 **1.24.1 સ્રોત_ટ્રી**를 자체 AArch64 EL0/SVC 대상으로 빌드했다. Python 문법의 ફંક્શંસ_મૂલ્ય·વર્ગ_મૂલ્ય·예외·리스트/શબ્દકોશ·Unicode·GC·가변 정밀도 정수를 제공한다. 현재 구성은 પૂર્ણાંક 빌드로 `float`, `complex`, `math`가 없으며 CPython 전체 표준 લાઇબ્રેરી, pip, subprocess, threading, 일반 socket과 ડિફૉલ્ટ_મૂલ્ય `open()` ફાઈલ 객체는 제공하지 않는다. `python FILE.py` 및 `-c` 실행만 제공하며 REPL은 아직 없다. 각 실행의 ઑબ્જેક્ટ_મૂલ્ય·모듈은 પ્રસ્થાન_એપ્લિકેશન 시 회수되고 RAM 파일만 આગલું_આઇટમ 실행에 남는다.

`import jkoros`로 આગલું_આઇટમ 시스템 연결을 쓴다. 모두 SVC를 통해 자체 Java 커널에 접근한다.

| ફંક્શંસ_મૂલ્ય | ક્રિયા |
|---|---|
| `stdin(limit)` | 현재 표준 입력에서 최대 limit바이트(0…16384)를 bytes로 읽음; EOF는 빈 bytes, UART ડેટા 없음은 OSError(11) |
| `read(name)` | પીઅર_મૂલ્ય/절대 RAM 경로의 ફાઈલ 전체를 bytes로 읽음 |
| `write(name, data)` | str/bytes 버퍼를 RAM 파일에 새로 સંગ્રહ_કરવો_મૂલ્ય, 쓴 બાઇટ_મૂલ્ય 수 반환 |
| `remove(name)` | RAM ફાઈલ 삭제 |
| `rect(x, y, w, h, color)` | 선택한 વાસ્તવિક_ડેટા 화면 માપ 안의 사각형 રેખાંકન_મૂલ્ય; 기존 보드의 RGB32 મૂલ્ય |
| `ticks_ms()` | 부팅 후 밀리초, 32비트 સાયકલ_મૂલ્ય |
| `udp_open(port)` | 127.0.0.1의 UDP 소켓 ખોલો/묶기; 0은 자동 હાર્ડવેર_પૉર્ટ |
| `udp_send(fd, port, data)` | 루프백 ગંતવ્ય_મૂલ્ય 포트에 str/bytes 버퍼 સ્થાનાંતર_મૂલ્ય |
| `udp_recv(fd)` | `(bytes, 보낸포트)` 반환; 비어 있으면 `OSError(11)` |
| `udp_close(fd)` | 소켓 બંધ_કરો |

```python
import jkoros
first = jkoros.udp_open(9401)
second = jkoros.udp_open(9402)
jkoros.udp_send(first, 9402, b"hello")
print(jkoros.udp_recv(second))  # (b'hello', 9401)
jkoros.udp_close(first)
jkoros.udp_close(second)
```

이식 코드: [python/](파이썬연결/), [ઉપયોગકર્તા Java સંપર્ક_કરો](ઉપયોગકર્તા/자바연결.c). 공식 [MicroPython 이식 રીડમી_eb81d7d9](https://docs.micropython.org/en/latest/develop/porting.html)를 참고했다. સ્રોત_ટ્રી URL·હૅશ_ફાઇલ·라이선스는 [vendor રીડમી_eb81d7d9](vendor/README.md)에 기록했다.

## 남은 작업

| આગલું_આઇટમ સ્ટેજ_મૂલ્ય | 완료 પ્રોજેક્ટ_રૂટ |

| CPython | 해당 libc와 OS API 대상으로 이식·교차 빌드하고 ફાઈલ/Unicode/스레드/소켓 시험 |
| OpenJDK/JRE | HotSpot OS થર_મૂલ્ય, GC/JIT/스레드/신호/동적 연결과 Java 네이티브 લાઇબ્રેરી 이식; javac/java વાસ્તવિક_ડેટા અમલ_કરો_આદેશ |
| 외부 네트워크 | 추가한 GENET/PHY·DHCP 드라이버의 વાસ્તવિક_ડેટા બોર્ડ 송수신 માન્ય_કરો, DNS·Wi-Fi |

## ગુજરાતી C ડેટા_પ્રકાર·Python ભૂલ·બન્ડલ સ્થાપિત_કરો_મૂલ્ય

C 네트워크 API는 `struct 인터넷통신주소`, enum 상수와 વાસ્તવિક_ડેટા ગુજરાતી 함수로
구현한다. મૅક્રો_મૂલ્ય 별칭을 사용하지 않으며 이전 pk_* ABI도 유지한다.
Python 예제는 `સિસ્ટમ_ભૂલ`, `ભૂલ.અનુક્રમણિકા`, `ભૂલ.설명`을 사용한다.

`python3 ઉપકરણો/અમલ_કરો_આદેશ.py --desktop --network --pip`로 시작하면 게스트에서
`pip install micropython-bisect==3.3.3`을 사용할 수 있다. 현재는 હોસ્ટ 중계를
이용하는 제한형 MicroPython સ્રોત_ટ્રી 설치기이며 CPython pip·자동 의존성 해결·C 확장은
미지원이다. 설치한 `/lib` 자료는 RAM이다. [사용법과 제한](파이썬꾸러미.md).

## 화면 માપ ચયન_મૂલ્ય

`python3 ઉપકરણો/અમલ_કરો_આદેશ.py --desktop --network --resolution 1920x1080`으로 Full HD 화면을 사용한다. 기본값은 640×480이며 1280×720도 가능하다. ટર્મિનલ ખસેડવું_મૂલ્ય, Swing 가운데 લિંક_લેઆઉટ, Java·C·Python 그리기도 વાસ્તવિક_ડેટા 크기를 따른다. SD 영상은 `make image RESOLUTION=1920x1080`으로 만든다. [સુયોજના·ગુજરાતી API·માન્ય_કરો રીડમી_eb81d7d9](화면해상도.md).

## ગુજરાતી 직접 API와 화면 તાજું_કરો

`example/java`는 `실행할일`, `동작받이`, `동작알림`, `બટન`, `ઇવેંટ_કતાર`,
`작업가닥`, `ચલાવો_2()`을 사용할 수 있다. ગુજરાતી GUI/가닥을 자체 JVM에 직접
연결했으며, 표준 Swing/Thread를 감싸지 않는다. સ્ટ્રિંગ_મૂલ્ય 등 javac의 표준
계약과 전체 સ્રોત_ટ્રી 검토 범위는 [명명 રીડમી_eb81d7d9](명명/રીડમી_eb81d7d9.md), 사용법과 호환성 변경은
[ગુજરાતી Java API](한국어자바/રીડમી_eb81d7d9.md)를 본다.

ટર્મિનલ ખસેડવું_મૂલ્ય·માપ 변경은 바뀐 영역만 합성하고 달라진 화소만 표시한다.
