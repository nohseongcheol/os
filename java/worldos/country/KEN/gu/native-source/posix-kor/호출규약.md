# ઉપયોગકર્તા 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `મશીન/ઑપરેટિંગ_સિસ્ટમ_કૉલ્સ.s`에서 EAX(અનુક્રમણિકા), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 દલીલો)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. કર્નેલ_મૂલ્ય 실패는 음수 ભૂલ અનુક્રમણિકા, C લાઇબ્રેરી 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 ઉપયોગકર્તા 영역 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C ડેટા 주소는 બાઇટ_મૂલ્ય 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java ફાઈલ 흐름의 어셈블리 경계가 별도 બાઇટ_મૂલ્ય 버퍼를 마련하여 같은 호출을 사용한다.

|---|---|---|
| 30 | બનાવો_ફાઇલ | NUL 끝 નામ સરનામું, સુયોજના, 허가 |
| 31 | 파일자료읽기 | 서술자, ડેટા સરનામું, બાઇટ_મૂલ્ય 수 |

| 33 | બંધ_કરો_ફાઇલ | 서술자 |
| 34 | સીક_ફાઇલ | 서술자, એન્કોડિંગ_મૂલ્ય 있는 ઑફસેટ_મૂલ્ય, પ્રોજેક્ટ_રૂટ |

| 44 | 자료전문받기 | 서술자, ડેટા સરનામું, લંબાઈ_મૂલ્ય, સુયોજના, 요청 સરનામું |
| 45 | 통신주소읽기 | 서술자, sockaddr સરનામું, socklen_t સરનામું |
| 46 | 수신대기정하기 | 서술자, 0~2000 밀리초 |
| 47 | 파일저장확정 | 서술자 |

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 સરનામું 두 칸이다. 수신 주소가 NULL이면 પીઅર_મૂલ્ય સરનામું 기록을 생략한다. sockaddr_in은 16바이트이며 સરનામું 체계는 ડિવાઇસ_મૂલ્ય બાઇટ_મૂલ્ય 차례, 접속번호와 IP 주소는 네트워크 બાઇટ_મૂલ્ય 차례다. 축소된 સરનામું 버퍼에도 들어가는 앞부분을 쓰고 전체 સરનામું માપ 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 પ્રસ્થાન_એપ્લિકેશન, 2·3은 기존 દલીલો 조회다. 현재 커널의 દલીલો 목록이 અમલ_કરો_આદેશ 이름을 제외하므로 C 진입기는 argv[0]에 고정 સ્ટ્રિંગ_મૂલ્ય `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX પ્રક્રિયા_મૂલ્ય ABI와 다른 점이다.

표준 헤더의 પૂર્ણાંક માપ, 플래그 મૂલ્ય, stat ફીલ્ડ_મૂલ્ય 순서는 `સ્રોત/포함/`에 정의한다. 동적 સંપર્ક_કરો·다중 પ્રક્રિયા_મૂલ્ય·스레드가 추가되면 ભૂલ અનુક્રમણિકા 저장과 સાધન_મૂલ્ય 수명, 호출 경계도 함께 검토해야 한다.
