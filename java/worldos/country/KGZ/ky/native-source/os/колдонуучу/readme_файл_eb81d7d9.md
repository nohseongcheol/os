# 셸에서 실행하는 колдонуучу 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 readme_файл_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 аткаруу_буйрук

кабылдоо Терминал 1:

```sh
cd /home/user/jkoros
python3 os/Куралдар/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 외부 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

кабылдоо Терминал 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 актуалдуу_берилмелер CPU уруксат_маани `ring 3`, 인수 Чыгыш.
- `netcheck`: порт_маани 중복, 잘못된 тутка_маани/көрсөткүч/узундук_маани, 비차단 받기와 시간 초과 тууралыгын_аныктоо.
- `udp`: IPv4 дарек·көздөө_жайы_маани порт_маани·한 Сөз_маани 메시지를 받아 UDP로 보내고 같은 응답을 тууралыгын_аныктоо. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: кабылдоо `10.0.2.2`의 지정 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 цикл_маани 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 현재 주소는 게스트 `10.0.2.15/24`, шлюз_маани `10.0.2.2`로 고정돼 있다. QEMU колдонуучу 네트워크의 кабылдоо мүмкүндүк_алуу_киргизме_жазуу 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 програм_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java програм_f5044b9b 추가

`예제/내프로그램.java`를 다음 형식으로 만든다. 진입점은 인수 없는 `static int` 또는 `static void` 함수다. 인수는 колдонуучу API로 조회한다.

```java
public final class 내프로그램 {
    public static int Жүргүзүү() {
        колдонуучу.Жазуу("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/колдонуучу/програм_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := колдонуучу/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.Жүргүзүү
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `колдонуучу/선언/колдонуучу.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 аткаруу_буйрук 중인 VM에는 курам_тутум 결과가 자동 반영되지 않는다. програм_f5044b9b 이름은 현재 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java класс_маани·функция_маани·변수에는 한국어를 쓴다. 최대 32개 програм_f5044b9b, 한 аткаруу_буйрук 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.Жүргүзүү \
    -o os/build/apps/hello.elf os/колдонуучу/선언/колдонуучу.java os/колдонуучу/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 кабылдоо 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 Колдоо_маани клип 안에서 실행한다. `.jar`와 일반 Linux аткаруу_буйрук 파일은 지원하지 않는다.

## колдонуучу 네트워크 API

선언은 `선언/колдонуучу.java`에 있다. `жөнөтүү_берилмелер`/`자료받기`의 `int[]` элемент_элемент 한 개는 байт_маани 하나(0~255)를 나타낸다. 한 데이터그램의 최대 берилмелер 길이는 1,024바이트다.

```java
int тутка_маани = колдонуучу.ачуу_Желе(0); // 0: 임시 локалдык_арым UDP порт_маани 자동 белгилөө_маани
int[] берилмелер = new int[32];
берилмелер[0] = 'H'; берилмелер[1] = 'i';
int 보낸길이 = колдонуучу.жөнөтүү_берилмелер(тутка_маани, 0x0a000202, 9000, берилмелер, 2);
int 받은길이 = колдонуучу.자료받기(тутка_маани, берилмелер, 1500);
колдонуучу.жабуу_Желе(тутка_маани);
```

актуалдуу_берилмелер 프로그램에서는 Ачуу·жөнөтүү·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 대기 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 추가 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | тутка_маани·Процесс_маани_киргизме_жазуу узундук_маани·성공 등 해당 함수의 결과 |
| -5 | түзмөк_маани жөнөтүү_маани натыйжасыз_маани |
| -9 | 잘못되었거나 닫힌 통신 тутка_маани |
| -11 | 비차단 받기에서 도착한 берилмелер 없음 |
| -14 | колдонуучу көрсөткүч/МАССИВ_маани клип Ката |
| -19 | Колдоо_маани NIC 없음 |
| -22 | порт_маани/대기 시간/인수 маани Ката |
| -24 | 열린 Желе_порт 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | берилмелер 또는 수신 МАССИВ_маани Өлчөмү 문제 |
| -98 | локалдык_арым порт_маани индекс 중복 |
| -101 | 지원하지 않는 көздөө_жайы_маани дарек |
| -110 | ARP·түзмөк_маани·수신 시간 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 коддоо_маани 있는 Java `int`의 бит_маани 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## аткаруу_буйрук 경계와 시스템 호출

```text
сырты run → JKAP에서 ELF жарактуулугун_текшерүү·적재 → ring 3 колдонуучу програм_f5044b9b
                                 ↓ int 0x80
                      көрсөткүч 검사 → Java өзөк_маани API → RTL8139/UDP
                                 ↓ Чыгуу_програм·예외·시간 초과
                                сырты 복귀
```

시스템 호출 레지스터는 `EAX=индекс`, `EBX,ECX,EDX,ESI,EDI=인수`, `EAX=결과`다. Java 호출 스택 ABI는 컴파일러가 колдонуучу 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| индекс | 호출 |
| --- | --- |
| 0 | Чыгуу_програм(абал_маани 코드) — Жүргүзүү/Ката 런타임에서 사용 |
| 1 | сап_маани Жазуу |
| 2 / 3 | 인수 개수 / 인수 сап_маани дарек |
| 10 | UDP Ачуу |
| 11 | UDP жөнөтүү(тутка_маани, IP, көздөө_жайы_маани порт_маани, МАССИВ_маани дарек, узундук_маани) |
| 12 | UDP 받기(тутка_маани, МАССИВ_маани дарек, 제한 밀리초) |
| 13 | UDP Жабуу |
| 14 | локалдык_арым IP дарек |
| 15 / 16 | 마지막 бирдей_маани IP / UDP порт_маани |
| 20 | RAM Файл Окуу(Аты int[] дарек, Чыгыш int[] дарек) |
| 21 | RAM Файл Жазуу(Аты int[] дарек, 입력 int[] дарек, байт_маани узундук_маани) |
| 22 | UTF-16 코드 сабак_маани 문자 Чыгыш(0~65535) |

Файл API는 `колдонуучу.파일읽기(int[] Аты, int[] берилмелер)`와 `колдонуучу.жазуу_файл(int[] Аты, int[] берилмелер, int узундук_маани)`다. 이름은 ASCII 코드 МАССИВ_маани(최대 64칸, 0 Чыгуу_програм 또는 МАССИВ_маани 끝), берилмелер элемент_элемент 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 Файл 없음 `-2`, көрсөткүч Ката `-14`, Аты/узундук_маани Ката `-22`, Файл оюкча_маани 부족 `-28`, Өлчөмү 초과 `-90`을 반환한다. 쓰기는 жарактуулугун_текшерүү 후 Файл 전체를 대체한다. `колдонуучу.жазуу_символ_маани(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 колдонуучу 모드에서 CS의 하위 비트를 직접 읽으므로 актуалдуу_берилмелер аткаруу_буйрук 권한을 확인한다. өзөк_маани 포트 접근용 `түзмөк_маани` native 함수는 колдонуучу максат 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 аткаруу_буйрук, 파이프, 프로세스 간 통신은 없다. аткаруу_буйрук 파일은 커널의 Окуу 전용 JKAP 묶음에서 적재한다. берилмелер 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- колдонуучу 가상 дарек `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. аткаруу_буйрук 영상은 앞 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. өзөк_маани identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB колдонуучу 영역을 비우고 Файл 구역을 복사해 BSS·МАССИВ_маани 영역을 초기화한다. колдонуучу GC는 없지만 Чыгуу_програм 후 다음 аткаруу_буйрук 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 따옴표/이스케이프 파싱은 없다.
- колдонуучу 페이지의 코드/берилмелер 분리 Окуу 전용 Орнотуулар, NX, 스택 guard, ASLR은 아직 없다. 커널과 колдонуучу эс_берилмелер·포트 уруксат_маани 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 аткаруу_буйрук 상한을 두며 시간 초과는 `Exit: 124`다. колдонуучу CPU 예외는 `128 + 예외 индекс`(페이지 Ката 142, 특권 위반 141), Java МАССИВ_маани/계산 오류는 101~105다. өзөк_маани 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, статикалык_маани IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP 검사합 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- колдонуучу аткаруу_буйрук·네트워크·коргоо_маани 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 аткаруу_буйрук·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## жарактуулугун_текшерүү 근거

`make test`는 컴파일러 14개 시험, Java 패킷 шарт 2,201개 검사, 기존 сырты ELF/ISO 부팅 시험, колдонуучу ELF/актуалдуу_берилмелер UDP/коргоо_маани 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 узундук_маани·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 Команда·무한 итерация_маани 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
