# 자체 커널과 번역기의 한국어 Аты

대상은 `platforms/rpi4-native`의 자체 Java өзөк_маани, колдонуучу JVM, C машина Туташуу,
TCP/UDP·FTP, C 번역기 이식부, MicroPython 이식부, курам_тутум·аткаруу_буйрук·시험 도구다.
`golang/worldos/나라/KOR/Булак`의 원칙처럼 기능을 먼저 구분하고 이름을 정한다.
x86 Java 커널과 공용 x86·ARM64 미리 번역기의 자체 선언도 명명 검사에 포함한다.
Linux 실행판의 кабылдоо Куралдар, OpenJDK 보조 Куралдар 및 외부 배포 башат_дарак 전체를
한국어로 다시 작성했다는 뜻은 아니다.

## 명명 원칙과 말의 근거

- 명사는 자료의 역할을 나타낸다: `файл_тутка`, `상대접속번호`, `동적기억공간`, `баскычтоп`.
- 함수는 행위를 나타낸다: `Окуу`, `Жазуу`, `Ачуу`, `Жабуу`, `망주소묶기`, `топтом_програм`.
- TCP의 이어진 байт_маани 흐름과 UDP의 경계 있는 자료를 `туташуу`와 `전문통로`로 구별한다.
- 짧은 영어 변수도 쓰임에 따라 `узундук_маани`, `자료위치`, `색인`, `반환값`으로 풀어 쓴다.
  순번·임시 산술값처럼 여러 역할에 재사용되는 변수는 `순번`, `첫째값`, `둘째값`으로 구별한다.
- 이름이 같아도 외부 구조체의 필드와 자체 변수는 별도로 분석한다.

`канал_киргизме_жазуу(通路)`는 이동이나 교류가 이루어지는 길이라는 기존 의미를 통신 연결에
적용했다. `порт_маани(窓口)`의 주고받는 접점이라는 의미를 연결을 받는 곳에 적용했다.
이는 국립국어원 한국어기초사전의 [канал_киргизме_жазуу](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=49310),
[порт_маани](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=24898)의 뜻에 근거한다.

`전문(電文)`은 전보에 담는 글이라는 기존 통신 어휘에서 가져와, UDP 자료의
경계가 보존된다는 특징을 드러내는 데 쓴다. 근거는
[한국어기초사전 전문](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=74335)이다.
`агым_маани`, `трэд_маани`, `쌓임`은 우리말의 움직임·이어짐·쌓이는 모양을 빌린 표현이다.
`입력흐름`, `작업가닥`, `стек_сактагыч` 같은 복합 이름은 이 프로젝트의 기능별 조어다.
이 сөздүк 근거를 특정 중세 문헌의 최초 출현이나 공인 전산 번역으로 확대하지 않는다.
공인 표준 Которуу_башат·국어사 전문 감수를 마쳤다는 뜻도 아니다.

| 기능 | 채택한 Аты | 이유 |
|---|---|---|
| TCP Socket | туташуу | 상대와 연결되어 ылгоо_ирети_маани 있는 바이트를 주고받음 |
| ServerSocket | 수신창구 | 새 연결이 들어오는 접점 |
| DatagramSocket | 전문통로 | 각 자료의 경계를 보존하는 통신 |
| InputStream / OutputStream | 입력흐름 / 출력흐름 | 들어오고 나가는 바이트의 ылгоо_ирети_маани |
| heap / stack | 동적기억공간 / стек_сактагыч | энчилөө_сактагыч 방식과 쌓고 꺼내는 구조 |
| thread / keyboard | 작업가닥 / баскычтоп | 이어지는 실행과 글쇠의 МАССИВ_маани |
| exception / timeout | 예외 / 대기시간초과예외 | 정상 처리에서 벗어남과 그 구체적 이유 |

## 보존하는 규격 Аты

`public`, `class`, `int`는 예약어다. `String`, `main`, 배열의 `length`는 예약어가 아니다.
현재 다섯 Java 예제는 `Жүргүзүү()`·`실행인수`·한국어 화면/трэд_маани API를 사용해
예약어·리터럴 외의 식별자를 한국어로 작성한다. 화면/가닥은 표준 객체를
감싸지 않고 자체 JVM에 직접 구현했다. 자세한 계약은 [한국어 Java API](../한국어자바/readme_файл_eb81d7d9.md)를 본다.

표준 javac는 сап_маани 리터럴에 `java.lang.String`, сап_маани 결합에 `StringBuilder`
같은 이름을 생성한다. 이들은 한국어 소스에서도 바이트코드에 남을 수 있다.
기존 표준 class를 실행하는 JVM의 대응 сап_маани, 아직 표준 라이브러리를 쓰는
통신·Файл 연결부까지 모두 한국어로 재구현한 것은 아니다. 이름만 일괄 치환하면
서술자·재정의·native 연결이 달라져 호환성이 깨진다.

C 표준 функция_маани·бүтүн_сан_түрү·POSIX ABI, CPU 저장기 Аты, 어셈블리 Команда, 링커 절 Аты,
TinyCC·lwIP·MicroPython이 요구하는 Орнотуулар 매크로와 헤더 이름도 보존한다.
예: `main`, `memcpy`, `pk_bind`, `mpconfigport.h`, `lwipopts.h`, `stdint.h`.
자체 C 함수의 башат_дарак 이름은 한국어이며, [기계연결이름.h](기계연결이름.h)가
기존 AOT·어셈블리·SDK에 공개한 машина 심볼과 연결한다.
Python의 `__init__`, `setUp`, `handle`, 표준 모듈 атрибут_маани, 명령행 옵션과 JSON 키도
외부 계약이다. `build/`, 배포 바이너리 이름과 `/sdk`는 기존 аткаруу_буйрук 경로를 유지한다.
외부 원본은 `vendor/`에서 이용허락·해시와 함께 관리한다.

## 검사와 재실행

```sh
cd /home/user/jkoros/platforms/rpi4-native
python3 Куралдар/명명검사.py
make курам_тутум
make 시험
make test-examples test-ftp test-elf
python3 Куралдар/аткаруу_буйрук.py --desktop --network
```

`Куралдар/시언어이름분석.py`는 libclang 6으로 C 선언과 참조를 검사한다.
`Куралдар/*이름반영.py`는 өзгөртүү_маани 전 башат_дарак·분석표를 필요로 하는 일회성 이행 도구다.
이미 변경된 소스에 다시 적용하여 대응표를 덮어쓰지 않는다.

## C 통신 구조체와 Python Ката

C 통신에서 `갈래`는 дарек 체계를 구분하고 `접속번호`는 port, `дарек_маани`은
IPv4 주소의 32비트 값을 나타낸다. `전문전송규약`은 앞서 설명한 전문(電文)과
иш_маани(規約)을 결합해 UDP의 기능을 드러낸 프로젝트 이름이다.

| 표준 표현 | 한국어 직접 구현 |
|---|---|
| AF_INET / SOCK_DGRAM / IPPROTO_UDP | enum의 Интернет_Үй_бүлө / 전문통신 / 전문전송규약 |
| struct pk_sockaddr_in | struct 인터넷통신주소 |
| sin_family / sin_port | дарек_Үй_бүлө / 접속번호 |
| sin_addr.s_addr | Интернет_дарек.дарек_маани |
| OSError / Ката.args[0] | тутум_ката / Ката.индекс |

한국어 구조체는 `#define` 치환이나 талаа_маани 별칭이 아닌 별개 자료형이다.
표준 구조체와 같은 16바이트 배치를 선언하며 өзөк_маани SVC에서 байт_маани 복사로
검사한다. `통신종단점만들기`·`자료전문보내기`와 Файл 함수는 статикалык_маани 라이브러리에
актуалдуу_берилмелер 한국어 이름의 функция_маани 심볼을 갖는다. 기존 pk_* 심볼도 유지한다.
이전 코드에서 한국어 통신 함수에 pk_sockaddr*를 전달했다면 한국어 구조체로
옮기거나, 표준 구조체와 pk_* 함수의 짝을 유지한다.

Python의 `тутум_ката`는 OSError의 한국어 하위 클래스이며 연결부에서
Ката 번호를 보존하여 변환한다. 일반 Python 문법과 외부 패키지의 API는 유지한다.

## 직접 GUI 이름의 뜻과 검토 клип

`실행할일`은 수행할 내용을, `аткаруу_маселе`는 그 수행을 나타낸다.
`동작받이`는 동작이 발생했다는 알림을 받는 역할, `동작알림`은 전달되는 사건이다.
`баскыч`는 눌러 동작시키는 조작부, `метка`는 readme_файл_eb81d7d9 글의 자리,
`текст_талаасы`은 글을 적는 자리, `작업가닥`은 이어지는 аткаруу_буйрук 흐름을 뜻한다.
`аткаруу_буйрук(實行)`·`Аракети(動作)`의 기존 뜻과 `받다`·`알리다`·`трэд_маани`의 기능을
결합한 프로젝트 이름이다. 새 복합어가 역사 문헌에 그대로 있었다거나
특정 시대에 처음 쓰였다고 주장하지 않는다.

전체 저장소는 `python3 Куралдар/башат_карап_чыгуу.py`로 검토한다.
결과는 `build/verification/naming/source-review.json`이며 파일별 хэш_файл,
ASCII 파일명과 Python의 영어 선언 위치를 기록한다.
공용 ARM64·x86 번역기의 구현은 `compiler/자바도구/기계어미리번역.java`로 전환했다. `compiler/기계어미리번역.py`는 호환 진입점이다.
`compiler/arm64.py`는 이전 경로와 `ARM64(...).generate(...)` 호출을 이어 주는
호환 진입점이다. `compiler/classfile.py`, OpenJDK 보조 Куралдар, Linux нуска_маани 도구와
기존 호환 진입점에는 영어 이름이 남아 있다. 따라서 전체 저장소가
예약어 외 100% 한국어라고 판정하지 않는다.
`Куралдар/명명검사.py --시언어`는 активдүү ARM64 소스의 선언, C 의미 분석,
x86 Java 커널과 공용 번역기의 자체 선언, Java 예제 전체 аныктагыч_маани,
ARM64 Python 예제와 직접 GUI/가닥에 표준 래퍼가 없는지를 별도로 검사한다.

## 현재 기능을 기준으로 보완한 Аты

번역은 글자를 음역하는 대신 자료의 역할과 함수의 행동을 구분한다.
동일한 영어 이름도 문맥이 다르면 한국어 이름을 달리 정한다.
Файл 이름은 주된 기능을 나타내고, функция_маани 이름은 행동을, 변수 이름은 담는 자료를 나타낸다.
예약어, 표준 API 및 외부 Туташуу 규약은 따로 기록한다.

| 이전 Аты | 적용한 Аты | 현재 기능 |
|---|---|---|
| `arm64.py`의 구현 | `compiler/자바도구/기계어미리번역.java` | Java 바이트코드를 독립 실행용 C 원문으로 미리 Которуу_башат |
| `ARM64`, `generate` | `기계어번역기`, `생성` | Которуу_башат 상태를 담는 객체와 C Булак 생성 행동 |
| `prototype`, `method` | `함수원형`, `함수본문` | 함수의 формат_маани 선언과 актуалдуу_берилмелер Команда Булак |
| `profile`, `heap_words` | `실행대상`, `동적기억낱말수` | өзөк_маани·колдонуучу 구분과 энчилөө_сактагыч эс_маани 공간의 машина 낱말 수 |
| `pc`, `op` | `명령위치`, `명령번호` | 바이트코드에서의 위치와 수행할 명령의 индекс |
| `x`, `y`, `w`, `h` | `x_координата`, `세로좌표`, `영역너비`, `영역높이` | алыскы_маани 화면의 위치와 직사각형 Өлчөмү |
| `p`, `n`, `i`, `j` | `자료위치`, `маани`, `순번`, `안쪽순번` | алыскы_маани 화면 берилмелер·санарип_маани·итерация_маани 자리; 파일별 기능을 확인해 적용 |
| `aot_heap_info`, `__stack_top` | `미리번역기억조회`, `커널쌓임공간끝` | машина Туташуу 규약을 유지하면서 자체 소스에서 사용하는 Аты |
| `앞캐리지` | `앞줄복귀` | 앞서 받은 문자가 줄복귀였는지 기억하여 중복 줄바꿈을 막음 |

[공용번역기이름대응.tsv](공용번역기이름대응.tsv)에 번역기 참조의 актуалдуу_берилмелер өзгөртүү_маани 기록을 남겼다.
추가로 보존한 C·POSIX/lwIP/libassh 이름의 이유는
[규격이름근거.json](규격이름근거.json)에 기록한다.
`시언어번역기/번역기.c`는 TinyCC 외부 원문을 포함하는 Туташуу 파일로 자체 선언이 없어서
C 자체 선언 분석에서는 제외한다. актуалдуу_берилмелер өзөк_маани 빌드에서는 계속 컴파일한다.

### 말의 뿌리와 새로운 복합 Аты

`эс_маани(記憶)`과 `색인(索引)`은 기존 한자어를 쓴다.
기억은 자료를 간직하는 기능에, 색인은 ылгоо_ирети_маани 있는 항목을 찾아 지정하는 기능에 적용한다.
сөздүк 근거는 국립국어원 한국어기초사전의
[эс_маани](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=38812&nation=eng),
[색인](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=63787)이다.

`стек_сактагыч`, `쌓기`, `꺼내기`는 자료를 포개고 마지막 자료부터 꺼내는 аткаруу_буйрук 구조를 드러낸다.
`쌓다`의 기존 뜻에 근거한 기능별 조어이며, 사전의
[쌓다](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=62095)를 참고한다.
`미리번역`은 аткаруу_буйрук 전에 번역한다는 기능을 직접 나타낸다.
