# 셸에서 실행하는 អ្នកប្រើ 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 អានខ្ញុំ_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 អនុវត្ត_ពាក្យបញ្ជា

ហូស ស្ថានីយ 1:

```sh
cd /home/user/jkoros
python3 os/ឧបករណ៍/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 외부 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

ហូស ស្ថានីយ 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 ដែលពិត_ទិន្នន័យ CPU ការអនុញ្ញាត_តំលៃ `ring 3`, អាគុយម៉ង់ លទ្ធផល.
- `netcheck`: ច្រក_តំលៃ 중복, 잘못된 ការកាន់កាប់_តំលៃ/អង្គ_ចង្អុល_កណ្ដុរ/ប្រវែង_តំលៃ, 비차단 받기와 ពេល_វេលា_តំលៃ 초과 ផ្ទៀងផ្ទាត់.
- `udp`: IPv4 អ៊ីម៉ែល·ទិសដៅ_តំលៃ ច្រក_តំលៃ·한 ពាក្យ_តំលៃ 메시지를 받아 UDP로 보내고 같은 응답을 ផ្ទៀងផ្ទាត់. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: ហូស `10.0.2.2`의 កំណត់_តំលៃ 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 រង្វិលជុំ_តំលៃ 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 현재 주소는 게스트 `10.0.2.15/24`, ច្រកចេញចូល_តំលៃ `10.0.2.2`로 고정돼 있다. QEMU អ្នកប្រើ 네트워크의 ហូស ការចូលប្រើ_ការបញ្ចូល 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 កម្មវិធី_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java កម្មវិធី_f5044b9b 추가

`예제/내프로그램.java`를 បន្ទាប់_ធាតុ 형식으로 만든다. 진입점은 អាគុយម៉ង់ 없는 `static int` 또는 `static void` 함수다. 인수는 អ្នកប្រើ API로 조회한다.

```java
public final class 내프로그램 {
    public static int រត់() {
        អ្នកប្រើ.សរសេរ("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/អ្នកប្រើ/កម្មវិធី_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := អ្នកប្រើ/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.រត់
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `អ្នកប្រើ/ការប្រកាស/អ្នកប្រើ.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 អនុវត្ត_ពាក្យបញ្ជា 중인 VM에는 ចងក្រង_ប្រព័ន្ធ 결과가 자동 반영되지 않는다. កម្មវិធី_f5044b9b 이름은 현재 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java ថ្នាក់_តំលៃ·អនុគមន៍_តំលៃ·변수에는 한국어를 쓴다. 최대 32개 កម្មវិធី_f5044b9b, 한 អនុវត្ត_ពាក្យបញ្ជា 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.រត់ \
    -o os/build/apps/hello.elf os/អ្នកប្រើ/ការប្រកាស/អ្នកប្រើ.java os/អ្នកប្រើ/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 ហូស 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 ទម្រ_តំលៃ មេឌៀខ្លីៗ 안에서 실행한다. `.jar`와 일반 Linux អនុវត្ត_ពាក្យបញ្ជា 파일은 지원하지 않는다.

## អ្នកប្រើ 네트워크 API

선언은 `ការប្រកាស/អ្នកប្រើ.java`에 있다. `ផ្ញើ_ទិន្នន័យ`/`자료받기`의 `int[]` ធាតុ_ធាតុ 한 개는 បៃ_តំលៃ 하나(0~255)를 나타낸다. 한 데이터그램의 최대 ទិន្នន័យ 길이는 1,024바이트다.

```java
int ការកាន់កាប់_តំលៃ = អ្នកប្រើ.បើក_ណិតវឺក(0); // 0: 임시 ក្នុងតំបន់_ដែនកំណត់_វិសាលភាព UDP ច្រក_តំលៃ 자동 ការជ្រើស_តំលៃ
int[] ទិន្នន័យ = new int[32];
ទិន្នន័យ[0] = 'H'; ទិន្នន័យ[1] = 'i';
int 보낸길이 = អ្នកប្រើ.ផ្ញើ_ទិន្នន័យ(ការកាន់កាប់_តំលៃ, 0x0a000202, 9000, ទិន្នន័យ, 2);
int 받은길이 = អ្នកប្រើ.자료받기(ការកាន់កាប់_តំលៃ, ទិន្នន័យ, 1500);
អ្នកប្រើ.បិទ_ណិតវឺក(ការកាន់កាប់_តំលៃ);
```

ដែលពិត_ទិន្នន័យ 프로그램에서는 បើក·ផ្ញើ·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 រង់ចាំ_តំលៃ 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 추가 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | ការកាន់កាប់_តំលៃ·ដំណើរការ_តំលៃ_ការបញ្ចូល ប្រវែង_តំលៃ·성공 등 해당 함수의 ការវាស់វែង |
| -5 | ឧបករណ៍_តំលៃ ផ្ញើ_តំលៃ បរាជ័យ_តំលៃ |
| -9 | 잘못되었거나 닫힌 통신 ការកាន់កាប់_តំលៃ |
| -11 | 비차단 받기에서 도착한 ទិន្នន័យ 없음 |
| -14 | អ្នកប្រើ អង្គ_ចង្អុល_កណ្ដុរ/អារេ_តំលៃ មេឌៀខ្លីៗ កំហុស |
| -19 | ទម្រ_តំលៃ NIC 없음 |
| -22 | ច្រក_តំលៃ/រង់ចាំ_តំលៃ ពេល_វេលា_តំលៃ/អាគុយម៉ង់ តំលៃ កំហុស |
| -24 | 열린 ណិតវឺក_ច្រក 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | ទិន្នន័យ 또는 수신 អារេ_តំលៃ ដាក់ទំហំ 문제 |
| -98 | ក្នុងតំបន់_ដែនកំណត់_វិសាលភាព ច្រក_តំលៃ សន្ទស្សន៏ 중복 |
| -101 | 지원하지 않는 ទិសដៅ_តំលៃ អ៊ីម៉ែល |
| -110 | ARP·ឧបករណ៍_តំលៃ·수신 ពេល_វេលា_តំលៃ 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 ការបំលែងកូដ_តំលៃ 있는 Java `int`의 ប៊ីត_តំលៃ 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## អនុវត្ត_ពាក្យបញ្ជា 경계와 시스템 호출

```text
셸 run → JKAP에서 ELF ធ្វើអោយមានសុពលភាព·적재 → ring 3 អ្នកប្រើ កម្មវិធី_f5044b9b
                                 ↓ int 0x80
                      អង្គ_ចង្អុល_កណ្ដុរ 검사 → Java ខឺណេល_តំលៃ API → RTL8139/UDP
                                 ↓ ចេញ_កម្មវិធី·ការលើកលែង·ពេល_វេលា_តំលៃ 초과
                                셸 복귀
```

시스템 호출 레지스터는 `EAX=សន្ទស្សន៏`, `EBX,ECX,EDX,ESI,EDI=អាគុយម៉ង់`, `EAX=ការវាស់វែង`다. Java 호출 스택 ABI는 컴파일러가 អ្នកប្រើ 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| សន្ទស្សន៏ | 호출 |
| --- | --- |
| 0 | ចេញ_កម្មវិធី(ភាព_តំលៃ កូដ_តំលៃ) — រត់/កំហុស 런타임에서 사용 |
| 1 | សំនុំអក្សរ_តំលៃ សរសេរ |
| 2 / 3 | អាគុយម៉ង់ 개수 / អាគុយម៉ង់ សំនុំអក្សរ_តំលៃ អ៊ីម៉ែល |
| 10 | UDP បើក |
| 11 | UDP ផ្ញើ(ការកាន់កាប់_តំលៃ, IP, ទិសដៅ_តំលៃ ច្រក_តំលៃ, អារេ_តំលៃ អ៊ីម៉ែល, ប្រវែង_តំលៃ) |
| 12 | UDP 받기(ការកាន់កាប់_តំលៃ, អារេ_តំលៃ អ៊ីម៉ែល, 제한 밀리초) |
| 13 | UDP បិទ |
| 14 | ក្នុងតំបន់_ដែនកំណត់_វិសាលភាព IP អ៊ីម៉ែល |
| 15 / 16 | 마지막 សិទ្ធស្មើ_តំលៃ IP / UDP ច្រក_តំលៃ |
| 20 | RAM ឯកសារ អាន(ឈ្មោះ int[] អ៊ីម៉ែល, លទ្ធផល int[] អ៊ីម៉ែល) |
| 21 | RAM ឯកសារ សរសេរ(ឈ្មោះ int[] អ៊ីម៉ែល, 입력 int[] អ៊ីម៉ែល, បៃ_តំលៃ ប្រវែង_តំលៃ) |
| 22 | UTF-16 កូដ_តំលៃ ឯកតា_តំលៃ 문자 លទ្ធផល(0~65535) |

ឯកសារ API는 `អ្នកប្រើ.파일읽기(int[] ឈ្មោះ, int[] ទិន្នន័យ)`와 `អ្នកប្រើ.សរសេរ_ឯកសារ(int[] ឈ្មោះ, int[] ទិន្នន័យ, int ប្រវែង_តំលៃ)`다. 이름은 ASCII កូដ_តំលៃ អារេ_តំលៃ(최대 64칸, 0 ចេញ_កម្មវិធី 또는 អារេ_តំលៃ 끝), ទិន្នន័យ ធាតុ_ធាតុ 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 ឯកសារ 없음 `-2`, អង្គ_ចង្អុល_កណ្ដុរ កំហុស `-14`, ឈ្មោះ/ប្រវែង_តំលៃ កំហុស `-22`, ឯកសារ ចន្លោះប្រហោង_តំលៃ 부족 `-28`, ដាក់ទំហំ 초과 `-90`을 반환한다. 쓰기는 ធ្វើអោយមានសុពលភាព 후 ឯកសារ 전체를 대체한다. `អ្នកប្រើ.សរសេរ_តួអក្សរ_តំលៃ(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 អ្នកប្រើ 모드에서 CS의 하위 비트를 직접 읽으므로 ដែលពិត_ទិន្នន័យ អនុវត្ត_ពាក្យបញ្ជា 권한을 확인한다. ខឺណេល_តំលៃ 포트 접근용 `ឧបករណ៍_តំលៃ` native 함수는 អ្នកប្រើ គោលដៅ 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 អនុវត្ត_ពាក្យបញ្ជា, 파이프, 프로세스 간 통신은 없다. អនុវត្ត_ពាក្យបញ្ជា 파일은 커널의 អាន 전용 JKAP 묶음에서 적재한다. ទិន្នន័យ 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- អ្នកប្រើ 가상 អ៊ីម៉ែល `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. អនុវត្ត_ពាក្យបញ្ជា 영상은 ខាងមុខ_តំលៃ 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. ខឺណេល_តំលៃ identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB អ្នកប្រើ 영역을 비우고 ឯកសារ 구역을 복사해 BSS·អារេ_តំលៃ 영역을 초기화한다. អ្នកប្រើ GC는 없지만 ចេញ_កម្មវិធី 후 បន្ទាប់_ធាតុ អនុវត្ត_ពាក្យបញ្ជា 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 សម្រង់/이스케이프 파싱은 없다.
- អ្នកប្រើ 페이지의 កូដ_តំលៃ/ទិន្នន័យ 분리 អាន 전용 ការកំណត់, NX, 스택 guard, ASLR은 아직 없다. 커널과 អ្នកប្រើ សតិ_ទិន្នន័យ·포트 ការអនុញ្ញាត_តំលៃ 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 អនុវត្ត_ពាក្យបញ្ជា 상한을 두며 ពេល_វេលា_តំលៃ 초과는 `Exit: 124`다. អ្នកប្រើ CPU 예외는 `128 + ការលើកលែង សន្ទស្សន៏`(페이지 កំហុស 142, 특권 위반 141), Java អារេ_តំលៃ/계산 오류는 101~105다. ខឺណេល_តំលៃ 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, នឹង_តំលៃ IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP លេខសរុបដើម្បីពិនិត្យមើលទិន្នន័យត្រឹមត្រូវ 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- អ្នកប្រើ អនុវត្ត_ពាក្យបញ្ជា·네트워크·ការពារ_តំលៃ 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 អនុវត្ត_ពាក្យបញ្ជា·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## ធ្វើអោយមានសុពលភាព 근거

`make test`는 컴파일러 14개 시험, Java 패킷 លក្ខខណ្ឌ 2,201개 검사, 기존 셸 ELF/ISO 부팅 시험, អ្នកប្រើ ELF/ដែលពិត_ទិន្នន័យ UDP/ការពារ_តំលៃ 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 ប្រវែង_តំលៃ·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 ពាក្យ_បញ្ជា·무한 ការធ្វើឡើងវិញ_តំលៃ 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
