# អ្នកប្រើ 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `ម៉ាស៊ីន/ប្រព័ន្ធប្រតិបត្តិការណ៏_ការហៅ.s`에서 EAX(សន្ទស្សន៏), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 អាគុយម៉ង់)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. ខឺណេល_តំលៃ 실패는 음수 កំហុស សន្ទស្សន៏, C បណ្ណាល័យ 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 អ្នកប្រើ 영역 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C ទិន្នន័យ 주소는 បៃ_តំលៃ 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java ឯកសារ 흐름의 어셈블리 경계가 별도 បៃ_តំលៃ 버퍼를 마련하여 같은 호출을 사용한다.

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 អ៊ីម៉ែល 두 칸이다. 수신 주소가 NULL이면 សិទ្ធស្មើ_តំលៃ អ៊ីម៉ែល 기록을 생략한다. sockaddr_in은 16바이트이며 អ៊ីម៉ែល 체계는 ឧបករណ៍_តំលៃ បៃ_តំលៃ 차례, 접속번호와 IP 주소는 네트워크 បៃ_តំលៃ 차례다. 축소된 អ៊ីម៉ែល 버퍼에도 들어가는 앞부분을 쓰고 전체 អ៊ីម៉ែល ដាក់ទំហំ 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 ចេញ_កម្មវិធី, 2·3은 기존 អាគុយម៉ង់ 조회다. 현재 커널의 អាគុយម៉ង់ 목록이 អនុវត្ត_ពាក្យបញ្ជា 이름을 제외하므로 C 진입기는 argv[0]에 고정 សំនុំអក្សរ_តំលៃ `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX ដំណើរការ_តំលៃ ABI와 다른 점이다.

표준 헤더의 ចំនួនគត់ ដាក់ទំហំ, 플래그 តំលៃ, stat កន្លែង_បញ្ចូល_តំលៃ 순서는 `ប្រភព/포함/`에 정의한다. 동적 ភ្ជាប់·다중 ដំណើរការ_តំលៃ·스레드가 추가되면 កំហុស សន្ទស្សន៏ 저장과 ធនធាន_តំលៃ 수명, 호출 경계도 함께 검토해야 한다.
