# jkoros 안에서 Java ចងក្រង_ប្រភព·អនុវត្ត_ពាក្យបញ្ជា

이 문서의 부팅·셸·ផ្ទុក_តំលៃ 명령은 **x86 កំណែ_តំលៃ** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 កំណែ_តំលៃ](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 ឯកសារ_ឈ្មោះ_អត្ថបទ, `edit`의 단독 `.` ផ្ទុក_តំលៃ, 16개 RAM ឯកសារ, 약 2초 អនុវត្ត_ពាក្យបញ្ជា 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 ដែលពិត_ទិន្នន័យ JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. ហូស ចងក្រង_ប្រភព 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java កម្មវិធី_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 អនុវត្ត_ពាក្យបញ្ជា

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. អនុវត្ត_ពាក្យបញ្ជា 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox អនុវត្ត_ពាក្យបញ្ជា អានខ្ញុំ_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 ឯកសារ 전체를 새 내용으로 작성한다. 기존 내용의 បន្ទាត់ កែសម្រួល_តំលៃ 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 បៃ_តំលៃ 수 បង្ហាញ_តំលៃ.
- `cat FILE`: ឯកសារ មាតិកា_តំលៃ បង្ហាញ_តំលៃ. 텍스트 소스에 사용한다.
- `rm FILE`: សតិ_ទិន្នន័យ ឯកសារ 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·វាយបញ្ចូល_តំលៃ 검사 បរាជ័យ_តំលៃ 시 기존 `.class`는 유지된다. 소스를 고친 ការថយ_តំលៃ 컴파일이 실패했다면 이전 អនុវត្ត_ពាក្យបញ្ជា 파일이 남아 있으므로 ចងក្រង_ប្រភព 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 ផ្ទុក_តំលៃ 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 ប្រភព_មែកធាង·ថ្នាក់_តំលៃ·ទិន្នន័យ 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, ឯកសារ 이름은 ASCII 1~63자다. ប្រភព_មែកធាង 이름은 `.class` 확장자 공간 때문에 최대 62자다. កែសម្រួល_តំលៃ 입력은 ASCII이고 한 បន្ទាត់ 최대 128자다. បន្ទាត់ 또는 ឯកសារ 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. ខឺណេល_តំលៃ/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 អ្នកប្រើ 예제 이름은 ASCII로 작성한다.

## 외부 ឯកសារ 적재

호스트에서 만든 소스나 ទម្រ_តំលៃ មេឌៀខ្លីៗ 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 ដែលពិត_ទិន្នន័យ 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# ហូស JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 បន្ទាប់_ធាតុ 빌드에서는 추가 파일을 포함하지 않는다. ឯកសារ មាតិកា_តំលៃ 변경과 ការបញ្ចូល_បញ្ជី 제거도 បន្ទាប់_ធាតុ 빌드에 반영된다. 원본 ហូស 파일에는 쓰지 않는다. តំលៃស្វ័យប្រវត្តិ `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 តំលៃស្វ័យប្រវត្តិ 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 ថ្នាក់_តំលៃ ឯកសារ 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 ទម្រ_តំលៃ មេឌៀខ្លីៗ 안에 있어야 한다.

## ទម្រ_តំលៃ មេឌៀខ្លីៗ

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| ថ្នាក់_តំលៃ | 패키지 없는 단일 ថ្នាក់_តំលៃ, នឹង_តំលៃ អនុគមន៍_តំលៃ, 재귀, អាគុយម៉ង់/반환 | 실행마다 단일 ថ្នាក់_តំលៃ 적재, public static main(String[]) |
| តំលៃស្វ័យប្រវត្តិ តំលៃ | int, boolean, char, String, main의 String[] អាគុយម៉ង់ | ចំនួនគត់·យោង 스택, String, int[], String[], 내부 StringBuilder |
| ឃ្លា_សេចក្តី_តំលៃ | 초기값 있는 ក្នុងតំបន់_ដែនកំណត់_វិសាលភាព ការប្រកាស, កិច្ចការ_តំលៃ, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 ចំនួនគត់·យោង 바이트코드와 លក្ខខណ្ឌ មែក |
| កន្សោមពាក្យ_តំលៃ | 십진 ចំនួនគត់, UTF-8 소스의 សំនុំអក្សរ_តំលៃ/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, សំនុំអក្សរ_តំលៃ 결합 | ចំនួនគត់ ការវះកាត់_តំលៃ·ប៊ីត_តំលៃ ការវះកាត់_តំលៃ·វាយបញ្ចូល_តំលៃ 변환, 단락 평가, អារេ_តំលៃ ការចូលប្រើ_ការបញ្ចូល |
| ឯកសារ | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | ដែលពិត_ទិន្នន័យ ខឺណេល_តំលៃ 파일서술자와 ភ្ជាប់, បង្កើត·លុប_មាតិការ·이어쓰기·EOF |
| លទ្ធផល | System.out.print/println: int/boolean/char/String, println() | 동일 |
| សំនុំអក្សរ_តំលៃ/អាគុយម៉ង់ | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), សំនុំអក្សរ_តំលៃ 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 ក្នុងតំបន់_ដែនកំណត់_វិសាលភាព ការប្រកាស, 오버로드, 임의 វាយបញ្ចូល_តំលៃ 변환, អារេ_តំលៃ បង្កើត ប្រភព, 8/16진 리터럴, Unicode ប្រភព_មែកធាង 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 តំលៃថេរ_តំលៃ 축소 변환을 구현하지 않는다. 외부 `.class`의 `int[]` បង្កើត/អាន/쓰기는 지원하므로 ហូស `javac --release 8`로 만든 អារេ_តំលៃ 예제는 실행할 수 있다.

វត្ថុ_តំលៃ កន្លែង_បញ្ចូល_តំលៃ·일반 វត្ថុ_តំលៃ បង្កើត·상속·인터페이스·여러 ថ្នាក់_តំលៃ ភ្ជាប់, long/float/double, ការលើកលែង ដំណើរការ_តំលៃ_ការបញ្ចូល, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java ការលើកលែង 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 សំនុំអក្សរ_តំលៃ ផ្ទុក_តំលៃ 공간은 អនុវត្ត_ពាក្យបញ្ជា ចេញ_កម្មវិធី 시 អ្នកប្រើ 영역 전체와 함께 회수한다. 지속 អនុវត្ត_ពាក្យបញ្ជា 중 GC는 없다.

## អនុវត្ត_ពាក្យបញ្ជា 한도와 កំហុស

| ធនធាន_តំលៃ | 한도 |
| --- | --- |
| ប្រភព_មែកធាង/ថ្នាក់_តំលៃ ឯកសារ | 각각 16KiB |
| 컴파일러 | កាក់_តំលៃ 2,047개, បង្កើត កូដ_តំលៃ 4KiB, តំលៃថេរ_តំលៃ 풀 4KiB |
| អនុគមន៍_តំលៃ/អាគុយម៉ង់ | 클래스당 32함수, 함수당 16인수 |
| JVM តំលៃថេរ_តំលៃ | 511개 |
| JVM អនុគមន៍_តំលៃ កូដ_តំលៃ | 함수당 8KiB |
| JVM 호출/스택/ក្នុងតំបន់_ដែនកំណត់_វិសាលភាព 변수 | 32프레임, 프레임당 스택 128칸·ក្នុងតំបន់_ដែនកំណត់_វិសាលភាព 128칸 |
| JVM វត្ថុ_តំលៃ ផ្ទុក_តំលៃ 공간 | 8,192개 32비트 ចន្លោះប្រហោង_ការបញ្ចូល, 헤더 포함 약 32KiB |
| អនុវត្ត_ពាក្យបញ្ជា | 최대 500,000 ពាក្យ_បញ្ជា, 기존 커널의 약 3초 CPU អនុវត្ត_ពាក្យបញ្ជា 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 ទម្រ_តំលៃ 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM វចនានុក្រម 검증기를 구현한 것은 아니다. ឯកសារ/លក្ខណះ_តំលៃ ប្រវែង_តំលៃ, តំលៃថេរ_តំលៃ យោង, ពាក្យ_បញ្ជា·មែក 경계를 검사하고, អនុវត្ត_ពាក្យបញ្ជា 중 스택 ទំរង់_តំលៃ·ក្នុងតំបន់_ដែនកំណត់_វិសាលភាព ចាប់ផ្តើម·អារេ_តំលៃ អក្សរតូចក្រោម_តំលៃ·វត្ថុ_តំលៃ 참조를 검사한다. អ្នកប្រើ 코드의 페이지·포트 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, ចងក្រង_ប្រភព·JVM 오류는 `Exit: 1`, ពាក្យ_បញ្ជា អាគុយម៉ង់ 오류는 `Exit: 2`다. CPU ពេល_វេលា_តំលៃ 상한은 기존 `Exit: 124`이며, អ្នកប្រើ ELF 자체의 CPU/런타임 오류는 기존 ចេញ_កម្មវិធី 코드를 따른다. បរាជ័យ_តំលៃ 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## 구현 위치와 시험

- `os/អ្នកប្រើ/자바/자바컴파일러.java`: 게스트 어휘·구문·វាយបញ្ចូល_តំលៃ 검사, តំលៃថេរ_តំលៃ 풀 및 바이트코드 បង្កើត.
- `os/អ្នកប្រើ/자바/자바가상기계.java`: ថ្នាក់_តំលៃ 적재, 스택·프레임·វត្ថុ_តំលៃ ផ្ទុក_តំលៃ, ពាក្យ_បញ្ជា 해석과 제한된 표준 호출.
- `os/ប្រភព/សតិ_ឯកសារនៃប្រព័ន្ធ.java`: សតិ_ទិន្នន័យ ឯកសារនៃប្រព័ន្ធ, កែសម្រួល_តំលៃ, 부팅 ឯកសារ 적재.
- `os/ប្រភព/체계호출.java`, `compiler/ផ្តើម_អ្នកប្រើ_កម្មវិធី.s`: ឯកសារ/문자 លទ្ធផល API와 អ្នកប្រើ អង្គ_ចង្អុល_កណ្ដុរ 검사.
- `os/ឧបករណ៍/자바파일묶기.py`: ហូស 입력 ឯកសារ ធ្វើអោយមានសុពលភាព·부팅 ក្រុម_តំលៃ បង្កើត.

```sh
make test-java
make test
```

`os/시험/자바시험.py`는 ELF/ISO 부팅, 게스트 ចងក្រង_ប្រភព·អនុវត្ត_ពាក្យបញ្ជា, អ្នកប្រើ 입력, 재귀·반복문·ចំនួនគត់ 극값·សំនុំអក្សរ_តំលៃ 결합·단락 평가, 재실행, ប្រភព_មែកធាង កំហុស 후 기존 ថ្នាក់_តំលៃ 보존, អារេ_តំលៃ/수 해독 កំហុស, 무한 ការធ្វើឡើងវិញ_តំលៃ 제한, កែសម្រួល_តំលៃ 넘침과 ឯកសារ 부족을 검사한다. 게스트 បង្កើត 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 ហូស OpenJDK의 ថ្នាក់_តំលៃ, ចំនួនគត់ 배열과 한글 상수를 게스트에 적재하며, 손상된 ឯកសារ 표식·버전·តំលៃថេរ_តំលៃ 수·មែក·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 시험 VM만 생성하고 종료한다.

구현 형식의 참고 ទិន្នន័យ: Oracle [JVM ថ្នាក់_តំលៃ ឯកសារ 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM ពាក្យ_បញ្ជា 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java ឯកសារ ចូល_ចេញ

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 ថ្នាក់_តំលៃ 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 ការថយ_តំលៃ `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. តំលៃស្វ័យប្រវត្តិ លទ្ធផល 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. ការលើកលែង វត្ថុ_តំលៃ·try/catch·try-with-resources는 지원하지 않으며 ឯកសារ 오류를 진단하고 프로그램을 종료한다. អារេ_តំលៃ ចូល_ចេញ, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 ឯកសារ 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 셸 `sync`가 필요하다. 예제의 ឯកសារ 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 ដែលពិត_ទិន្នន័យ 게스트 ចងក្រង_ប្រភព 결과를 OpenJDK `-Xverify:all`로 다시 실행해 ឯកសារ 바이트와 출력을 대조한다. 범위와 ផ្ទុក_តំលៃ 매체 사용법은 [posix-kor អានខ្ញុំ_eb81d7d9](../posix-kor/អានខ្ញុំ_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
