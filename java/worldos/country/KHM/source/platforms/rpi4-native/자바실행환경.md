# 자체 ARM64 JVM 0.4와 한국어 បណ្ណាល័យ

한국어 통신·ការលើកលែង 사용법은 [한국어 Java API](한국어자바/អានខ្ញុំ_eb81d7d9.md), អនុគមន៍_តំលៃ·변수·ឯកសារ 이름의 변경과 어원 근거는 [명명 អានខ្ញុំ_eb81d7d9](명명/អានខ្ញុំ_eb81d7d9.md)를 참고한다.

JAR អនុវត្ត_ពាក្យបញ្ជា, 외부 IPv4 TCP/UDP, 별도 នឹង_តំលៃ 부분집합 `jaot`와 게스트 C 컴파일은 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)에 설명한다. 아래 វត្ថុ_តំលៃ·Thread·Swing은 JVM 경로의 기능이며 AOT ទម្រ_តំលៃ 범위와 같지 않다.

이 구현은 **Linux 없이 부팅한 Java AOT 커널의 EL0에서 អនុវត្ត_ពាក្យបញ្ជា**한다. JDK/JRE의 거의 모든 기능을 제공하는 단계는 아직 아니다. HotSpot·OpenJDK ថ្នាក់_តំលៃ បណ្ណាល័យ 전체를 이식하거나 Java SE 인증/TCK를 통과한 구현도 아니다. 이번 확장은 단일 ថ្នាក់_តំលៃ·នឹង_តំលៃ វិធីសាស្រ្ត_តំលៃ 중심이던 실행기를 វត្ថុ_តំលៃ·បណ្ណាល័យ អនុវត្ត_ពាក្យបញ្ជា 기반으로 넓힌 것이다.

## 실행과 ចងក្រង_ប្រភព

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
# 자체 ខឺណេល_តំលៃ 안에서 ប្រភព_មែកធាង ចងក្រង_ប្រភព → class អនុវត្ត_ពាក្យបញ្ជា, 한국어 API 호출
python3 ឧបករណ៍/អនុវត្ត_ឯកសារ.py 시험/자바/한글소스.java

# វត្ថុ_តំលៃ·ការលើកលែង 등은 ហូស JDK로 Java 8 class를 만든 후 자체 커널에서 អនុវត្ត_ពាក្យបញ្ជា
mkdir -p build/my-java
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/my-java 시험/자바/한글시험.java
python3 ឧបករណ៍/អនុវត្ត_ឯកសារ.py build/my-java/한글시험.class

# 의존 class 파일은 --include로 함께 ផ្ទេរ_តំលៃ
javac --release 8 -encoding UTF-8 -d build/my-java 시험/자바/객체시험.java
python3 ឧបករណ៍/អនុវត្ត_ឯកសារ.py build/my-java/객체시험.class \
  --include build/my-java/គំរូដែសថប_តំលៃ.class --include build/my-java/មែក_តំលៃ.class \
  --include build/my-java/계산가능.class

make test-jvm
```

`--include DIR`는 그 디렉터리의 class 파일을 재귀적으로 읽어 `패키지.ថ្នាក់_តំលៃ.class`라는 RAM ឯកសារ 이름으로 전송한다. 주 클래스도 패키지가 있다면 `--class-name 패키지.ថ្នាក់_តំលៃ`를 지정한다. 셸에서는 해당 이름으로 업로드하고 `java 패키지.ថ្នាក់_តំលៃ`로 실행한다. JVM 0.4는 Main-Class가 있는 16 KiB 이하 JAR도 `java -jar ឯកសារ.jar`로 실행한다. JAR 모드에서는 JAR 내부 클래스와 내장 한국어 클래스만 찾는다. 배포 한국어 បណ្ណាល័យ JAR는 ហូស javac의 classpath로 사용하며, 같은 클래스가 អ្នកប្រើ JVM ELF에도 អាន 전용 자료로 포함된다. 일반 class 모드에서는 사용자가 같은 이름으로 올린 RAM class를 먼저 읽는다.

게스트 `javac`는 여전히 នឹង_តំលៃ វិធីសាស្រ្ត_តំលៃ, int/boolean/char/String, លក្ខខណ្ឌ·ការធ្វើឡើងវិញ_តំលៃ, សំនុំអក្សរ_តំលៃ 결합, 일부 ឯកសារ 스트림 등의 **자체 부분집합 컴파일러**다. វត្ថុ_តំលៃ ការប្រកាស·상속·try/catch·Thread 사용 소스를 게스트 javac가 모두 컴파일하는 것은 아니다. 위 기능은 `javac --release 8`로 만든 class를 자체 JVM에서 실행한다. 한국어 API 중 លទ្ធផល·문자 스칼라 អនុគមន៍_តំលៃ·ឯកសារ អាន/쓰기는 게스트 컴파일러에도 연결했다. 다음처럼 전체 이름으로 호출한다.

```java
public class 인사 {
    public static void main(String[] អាគុយម៉ង់) throws Exception {
        한국어.자체.លទ្ធផល.សរសេរ_បណ្ដាញ("안녕하세요😀");
        한국어.자체.លទ្ធផល.수쓰기(한국어.자체.문자.코드포인트수("한글😀"));
        한국어.자체.ឯកសារ.សរសេរ("인사.txt", "한글 ឯកសារ😀");
        한국어.자체.លទ្ធផល.សរសេរ_បណ្ដាញ(한국어.자체.ឯកសារ.អាន("인사.txt"));
    }
}
```

예외는 Throwable/Exception/RuntimeException, ArithmeticException, NullPointerException, IndexOutOfBoundsException/ArrayIndexOutOfBoundsException/StringIndexOutOfBoundsException, IllegalArgumentException/NumberFormatException/IllegalThreadStateException, IOException/FileNotFoundException, IllegalStateException, ClassCastException, NegativeArraySizeException, ArrayStoreException, UnknownHostException, SocketTimeoutException의 제한된 បង្កើត·ប្រភេទ_តំលៃ·처리를 제공한다. អ្នកប្រើ និយមន័យ_តំលៃ Throwable 상속, stack trace/cause/suppressed ការលើកលែង, try-with-resources의 addSuppressed, 완전한 ចាប់ផ្តើម កំហុស 포장은 아직 없다. 잡히지 않은 예외는 현재 전체 Java 실행을 실패로 끝낸다.

## 한국어 API

독립 패키지 **`한국어.자체`**를 사용한다. Linux판 `한국어.자바`가 요구하는 NIO/Swing/HTTP API를 자체 커널에서 실행할 수 있다고 혼동하지 않도록 패키지를 나눴다. 이 라이브러리는 ថ្នាក់_តំលៃ ឈ្មោះ·វិធីសាស្រ្ត_តំលៃ·អាគុយម៉ង់·កន្លែង_បញ្ចូល_តំលៃ·ឯកសារ 이름에 한국어를 사용한다. 표준 Java ថ្នាក់_តំលៃ 이름은 호환성을 위해 보존한다.

| ថ្នាក់_តំលៃ | 공개 기능 | 이름의 의미 |
|---|---|---|
| លទ្ធផល | សរសេរ, សរសេរ_បណ្ដាញ, 수쓰기 | លទ្ធផល(出力): 내용을 바깥으로 내보냄 |
| 문자 | ប្រវែង_តំលៃ, 같음, បិត_អត្ថបទ, កាត់_តំលៃ, ញែក_ចំនួនគត់/សរសេរ_ចំនួនគត់_តំលៃ, 코드포인트수, 부호화/ដោះកូដ_ទិន្នន័យ | 문자(文字), ការបំលែងកូដ_តំលៃ(符號): 글의 단위와 그 값을 바이트로 나타내는 តម្រង_តំលៃ |

| ការបញ្ចូល_បញ្ជី | 더하기, អាន, ជំនួស_តំលៃ, លុប_ការបញ្ចូល, ដាក់ទំហំ, បច្ចេកវិទ្យាព័ត៌មាន_ទទេរ_តំលៃ, លុប_មាតិការ | ការបញ្ចូល_បញ្ជី(目錄): 순서가 있는 ការបញ្ចូល_តំលៃ 모음 |

이 명명은 현재 기능을 설명하는 용어 선택이다. 기존 한국어에 없던 역사적 어원을 만들어 주장하지 않는다. ឯកសារ_ឈ្មោះ_អត្ថបទ·식별자는 UTF-8 소스로 보관한다. `문자.ដោះកូដ_ទិន្នន័យ`는 잘못된 UTF-8에 IllegalArgumentException을 던지며, `부호화`는 짝이 없는 서로게이트를 `?`로 바꾼다. `ឯកសារ.អាន`는 엄격한 UTF-8 복호화를 적용한다. 화면 색은 `빨강 | (초록 << 8) | (파랑 << 16)` 형식이다.

## អនុវត្ត_ពាក្យបញ្ជា 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(한국어 ថ្នាក់_តំលៃ 포함), class당 16 KiB·តំលៃថេរ_តំលៃ 풀 511항목, 전체 វិធីសាស្រ្ត_តំលៃ/កន្លែង_បញ្ចូល_តំលៃ 각각 512개. វិធីសាស្រ្ត_តំលៃ កូដ_តំលៃ 8 KiB, ក្នុងតំបន់_ដែនកំណត់_វិសាលភាព 변수·피연산자 스택 각각 128슬롯, អាគុយម៉ង់ 최대 16개(this 포함).
- VM 가닥은 main 포함 **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 អនុវត្ត_ពាក្យបញ្ជា 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- វត្ថុ_តំលៃ 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 ដែលពិត_ទិន្នន័យ 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 ឯកសារ·대형 សំនុំអក្សរ_តំលៃ·객체가 이 제한을 넘을 수 있다.
- 실행은 50만 바이트코드 ពាក្យ_បញ្ជា 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 입력 대기는 기한을 갱신하고 វីនដូ ប្ដូរ_ម៉ូដ 시 중단·재개한다. 일반 ម៉ាស៊ីនមេ_តំលៃ·계산의 무제한 실행은 아직 없다. 미지원 ពាក្យ_បញ្ជា·ធនធាន_តំលៃ 부족은 명시적인 오류로 종료한다.
- RAM ឯកសារ 최대 64개, 파일당 16384바이트, ផ្លូវ UTF-8 63바이트. RAM 디렉터리와 សិទ្ធស្មើ_តំលៃ/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 한국어 class는 RAM ឯកសារ 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 현재 경로에서 ប្រភព_មែកធាង·ថ្នាក់_តំលៃ·ទិន្នន័យ 파일을 읽는다.
- UDP는 Java 루프백 및 lwIP/SLIP를 통한 외부 IPv4를 제공한다. ដែលពិត_ទិន្នន័យ GENET/Wi-Fi/DNS/TLS/HTTP 전체는 없다. 전문 512바이트, 소켓 8개, 소켓당 큐 4개. receive는 VM 가닥을 양보하며 대기하고 setSoTimeout을 적용하지만 전체 អនុវត្ត_ពាក្យបញ្ជា 기한은 여전히 적용된다.
- long/float/double, invokedynamic/람다, enum/annotation, 다차원 អារេ_តំលៃ, 완전한 អារេ_តំលៃ 공변성·인터페이스 ស្រទាប់_តំលៃ 검사, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/ការបំលែងកូដ_ទិន្នន័យ/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. Swing의 별도 ទម្រ_តំលៃ 부분집합은 아래 및 개발 매뉴얼을 참고한다. ថ្នាក់_តំលៃ ឯកសារ 전체 검증기·ការចូលប្រើ_ការបញ្ចូល ការអនុញ្ញាត_តំលៃ/보호된 멤버 검사는 아직 완전하지 않다. 손상된 입력은 EL0 ការពារ_តំលៃ 경계 내에서 종료되도록 한다.

전체 OpenJDK를 목표로 하려면 다음은 별도의 주요 구현 단계다: 완전한 JVM តំលៃ/ធ្វើអោយមានសុពលភាព/ថ្នាក់_តំលៃ 로더와 ការលើកលែង 모델 → 영속 VFS·mmap·នាឡិកា·원자 ការវះកាត់_តំលៃ·ដែលពិត_ទិន្នន័យ 스레드/សមកាលកម្ម ABI → OpenJDK java.base 및 native បណ្ណាល័យ 이식 → ឧបករណ៍_តំលៃ 네트워크·TCP/IP → វីនដូ 시스템/ពុម្ពអក្សរ_តំលៃ/입력기·java.desktop → Java SE 호환성 시험. 현재 자체 JVM의 일부 메서드를 더하는 것으로 이 작업이 완료되지는 않는다.

## ធ្វើអោយមានសុពលភាព

`ឧបករណ៍/자바가상기계시험.py`는 같은 Java 8 class 파일의 출력을 ហូស OpenJDK `-Xverify:all`과 QEMU raspi4b 자체 커널에서 비교한다. វត្ថុ_តំលៃ/상속/인터페이스·switch·អារេ_តំលៃ, ការលើកលែង/finally, 컬렉션/GC, Thread/잠금, 한국어 UTF-8/ឯកសារ/컬렉션, ដែលពិត_ទិន្នន័យ UDP 루프백/ពេល_វេលា_តំលៃ 초과, 게스트 한글 ប្រភព_មែកធាង ចងក្រង_ប្រភព, អារេ_តំលៃ វាយបញ្ចូល_តំលៃ/ចំលង_តំលៃ/ឯកសារ 경계·한글 패키지의 9개 비교 시험과 잘못된 class 버전/잘린 ឯកសារ បដិសេធ_តំលៃ 시험을 실행한다. UDP បញ្ចាំង_ឬស 실행에는 ហូស 루프백 소켓 권한이 필요하다.

`ឧបករណ៍/부팅시험.py`는 ខឺណេល_តំលៃ ការពារ_តំលៃ/회귀 시험과 별도로 한국어 Java 화면 API가 ដែលពិត_ទិន្នន័យ 픽셀을 그렸는지도 QMP 화면 캡처로 검사한다. 보고서는 `build/verification/jvm/report.json`, `build/verification/report.json`이며 시험한 kernel8.img의 SHA-256을 기록한다. ដែលពិត_ទិន្នន័យ Pi4 하드웨어 부팅 시험과 전체 JDK 호환성 시험 결과는 아니다.


## JVM 0.3: 네트워크와 GUI ម៉ូឌុល_តំលៃ

`Socket`/`ServerSocket` បង្កើត·ភ្ជាប់·accept·양방향 InputStream/OutputStream·close·EOF·ពេល_វេលា_តំលៃ 제한과 UTF-8 `String.getBytes`를 추가했다. JVM 0.4에서는 외부 숫자 IPv4 TCP도 lwIP/SLIP에 연결했다. 연결형 បញ្ចប់_ចំនុច 16개, Java 루프백 버퍼 1024바이트, 외부 TCP 버퍼 4096바이트다. DNS·TLS는 없다.

`JFrame`, `JPanel`, `JLabel`, `JButton`, `JTextField`, `ActionListener`, `ActionEvent`, `SwingUtilities.invokeLater`의 문서화한 부분집합을 네이티브 GUI에 연결했다. `setLayout(null)`과 명시적 좌표를 사용한다. 전체 OpenJDK Swing 또는 Java SE 호환 구현은 아니다. អន្តរកម្ម 이벤트 대기는 អនុវត្ត_ពាក្យបញ្ជា 기한을 갱신하고 ស្ថានីយ ប្ដូរ_ម៉ូដ 시 프로세스 상태를 ផ្ទុក_តំលៃ·복원한다. 이벤트 콜백 자체는 기존 바이트코드/CPU 기한을 따른다.

한국어 `វីនដូ`, `វីដហ្គេត`, `연결통신` 클래스를 배포 JAR와 자체 JVM 내장 자원에 추가했다. 상세 វិធីសាស្រ្ត_តំលៃ·제한·ប្រភព_មែកធាង·업로드 방법: [한글 개발 매뉴얼](개발안내.md).

## 한국어 객체의 직접 អនុវត្ត_ពាក្យបញ្ជា

`វីនដូ`, `ស្លាក`, `អត្ថបទ_កន្លែង_បញ្ចូល`, `ប៊ូតុង`, `ព្រឹត្តិការណ៍_ជួរ`, `동작알림`, `작업가닥`은
표준 GUI/Thread 객체를 보관하는 래퍼가 아니다. 자체 JVM의 វត្ថុ_តំលៃ បង្កើត,
ទំរង់_តំលៃ 검사, 화면 호출, ព្រឹត្តិការណ៍ 큐, ស្រេត_តំលៃ 스케줄러에 한국어 계약을 직접 구현했다.
표준 `javax.swing`·`Thread` 코드의 អនុវត្ត_ពាក្យបញ្ជា 경로도 유지한다.
한국어 단추와 표준 JButton은 서로 다른 형식이며, 해당 instanceof 검사도 검증한다.

자체 실행기의 한국어 진입점은 `public static void រត់()`이다.
표준 `main(String[])`도 지원하며 둘 다 있으면 한국어 진입점을 우선한다.
명령행 인수는 `실행인수.개수()`와 `실행인수.អត្ថបទ(순번)`으로 읽는다.
`example/java`의 다섯 예제는 이 규약을 사용한다. នឹង_តំលៃ ឯកសារ 예제는 게스트
javac로도 컴파일하며, GUI/ស្រេត_តំលៃ 소스는 ហូស `javac --release 8`을 사용한다.
직접 GUI/ស្រេត_តំលៃ API는 자체 JVM 전용이다. 기존 OpenJDK 비교 시험과 별도로
한국어 가닥의 អនុវត្ត_ពាក្យបញ្ជា·រង់ចាំ_តំលៃ·중복 រត់ បដិសេធ_តំលៃ, GUI ព្រឹត្តិការណ៍ 출처·សន្ទស្សន៏·콜백을 검사한다.
전체 JDK 번역이나 모든 API의 jaot 지원을 뜻하지 않는다.

វិធីសាស្រ្ត_តំលៃ 이름은 바이트코드에서도 유지된다. 이름과 참조를 같이 수정하면
한국어 클래스도 실행되지만, សំនុំអក្សរ_តំលៃ 리터럴·표준 បណ្ណាល័យ 재정의·native
ភ្ជាប់·진입점은 각각 컴파일러와 실행기의 계약을 맞춰야 한다.
[상세 계약과 예제](한국어자바/អានខ្ញុំ_eb81d7d9.md)를 참고한다.

## ស្ថានីយ 부분 ផ្ទុក_ឡើង_វិញ

ផ្លាស់ទី_តំលៃ·ដាក់ទំហំ 변경은 새 វីនដូ 영역과 이전 자리에서 드러난 띠만 합성한다.
1920×32 ចំនុចតូចៗ(240 KiB)의 임시 그림에서 배경·겹친 វីនដូ·តួអក្សរ_តំលៃ·GUI를 먼저
완성하고, 현재 បង្ហាញ_តំលៃ 메모리와 비교하여 달라진 화소만 기록한다.
32줄보다 큰 영역은 여러 띠로 처리하므로 전체 프레임을 원자적으로
교체하거나 수직 동기에 맞추는 방식은 아니다. 전체 배경을 먼저 지우는
중간 화면은 표시하지 않는다. 좌표가 같으면 다시 그리지 않는다.

`make test-redraw`는 ដែលពិត_ទិន្នន័យ C 그리기 코드를 호스트의 សតិ_ទិន្នន័យ 화면에 연결해
ផ្លាស់ទី_តំលៃ 80회·ដាក់ទំហំ កែប្រែ_តំលៃ 40회·겹친 វីនដូ 4개를 전체 합성 결과와 ចំនុចតូចៗ 단위로 대조한다.
영역 밖 អ្នកប្រើ ការគូរ_តំលៃ, 동일 ចំនុចតូចៗ 무기록, អង្គ_ចង្អុល_កណ្ដុរ 밑그림, ដែលពិត_ទិន្នន័យ 화면 បន្ទាត់ 간격을
검사한다. 이 시험의 시간은 ហូស CPU 측정이며 Pi 4/QEMU 속도로 해석하지 않는다.
`make test-resize`는 QEMU/VNC의 640×480 및 1920×1080에서 왼쪽 모서리 អូស_តំលៃ,
한글 입력·vi 미저장 មាតិកា_តំលៃ·독립 វីនដូ 크기를 검사한다.
