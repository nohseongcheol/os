# ຜູ້ໃຊ້ 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `ເຄື່ອງຈັກ/ລະບົບປະຕິບັດການ_ໂທ.s`에서 EAX(ດັດຊະນີ), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 인수)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. ແກນກາງ_ຄ່າ 실패는 음수 ຂໍ້ຜິດພາດ ດັດຊະນີ, C ຫໍສະຫມຸດ 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 ຜູ້ໃຊ້ 영역 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C ຂໍ້ມູນ 주소는 ໄບ_ຄ່າ 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java ຟາຍ 흐름의 어셈블리 경계가 별도 ໄບ_ຄ່າ 버퍼를 마련하여 같은 호출을 사용한다.

| 31 | 파일자료읽기 | 서술자, ຂໍ້ມູນ ອີເມວ, ໄບ_ຄ່າ 수 |
| 32 | ຂຽນ_ຟາຍ_ຂໍ້ມູນ | 서술자, ຂໍ້ມູນ ອີເມວ, ໄບ_ຄ່າ 수 |
| 33 | ປິດ_ຟາຍ | 서술자 |
| 34 | ຊອກຫາ_ຟາຍ | 서술자, ເຂົ້າລະຫັດ_ຄ່າ 있는 ອອບເຊັດ_ຄ່າ, ໂຄງ_ການ_ເລກຮາກ |

| 44 | 자료전문받기 | 서술자, ຂໍ້ມູນ ອີເມວ, ຄວາມຍາວ_ຄ່າ, ການຕັ້ງຄ່າ, 요청 ອີເມວ |
| 45 | 통신주소읽기 | 서술자, sockaddr ອີເມວ, socklen_t ອີເມວ |
| 46 | 수신대기정하기 | 서술자, 0~2000 밀리초 |
| 47 | 파일저장확정 | 서술자 |

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 ອີເມວ 두 칸이다. 수신 주소가 NULL이면 ລຸ້ນດຽວກັນ_ຄ່າ ອີເມວ 기록을 생략한다. sockaddr_in은 16바이트이며 ອີເມວ 체계는 ມືຖື_ຄ່າ ໄບ_ຄ່າ 차례, 접속번호와 IP 주소는 네트워크 ໄບ_ຄ່າ 차례다. 축소된 ອີເມວ 버퍼에도 들어가는 앞부분을 쓰고 전체 ອີເມວ ຂະ_ຫນາດ 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 ອອກ_ແອັບ, 2·3은 기존 인수 조회다. 현재 커널의 인수 목록이 ປະ_ຕິ_ບັດ_ຄໍາສັ່ງ 이름을 제외하므로 C 진입기는 argv[0]에 고정 ສະຕຣິງ_ຄ່າ `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX ຂະ_ບວນ_ການ_ຄ່າ ABI와 다른 점이다.

표준 헤더의 ຕົວເລກຈໍານວນເຕັມ ຂະ_ຫນາດ, 플래그 ຄ່າ, stat ຊ່ອງຂໍ້ມູນ_ຄ່າ 순서는 `ແຫຼ່ງທີ່ມາ/포함/`에 정의한다. 동적 ເຊື່ອມຕໍ່·다중 ຂະ_ບວນ_ການ_ຄ່າ·스레드가 추가되면 ຂໍ້ຜິດພາດ ດັດຊະນີ 저장과 ແຫຼ່ງ_ຄ່າ 수명, 호출 경계도 함께 검토해야 한다.
