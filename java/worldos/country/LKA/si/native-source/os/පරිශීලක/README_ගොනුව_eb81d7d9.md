# 셸에서 실행하는 පරිශීලක 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 README_ගොනුව_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 ක්_රියාත්මක_කරන්න_විධානය

ධාරකය අග්_රය 1:

```sh
cd /home/user/jkoros
python3 os/මෙවලම්/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 외부 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

ධාරකය අග්_රය 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 තථ්_ය_දත්ත CPU අවසරය_අගය `ring 3`, විස්තාරක 출력.
- `netcheck`: තොට_අගය 중복, 잘못된 හසුරුව_අගය/පොයින්ටරය/දිග_අගය, 비차단 받기와 시간 초과 තහවුරු_කරන්න.
- `udp`: IPv4 යොමුව·ගමනාන්තය_අගය තොට_අගය·한 단어 메시지를 받아 UDP로 보내고 같은 응답을 තහවුරු_කරන්න. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: ධාරකය `10.0.2.2`의 지정 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 ලූපය_අගය 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 현재 주소는 게스트 `10.0.2.15/24`, වාහල_අගය `10.0.2.2`로 고정돼 있다. QEMU පරිශීලක 네트워크의 ධාරකය ප්_රවේශය_පිවිසුම 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 යෙදු_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java යෙදු_f5044b9b 추가

`예제/내프로그램.java`를 다음 형식으로 만든다. 진입점은 විස්තාරක 없는 `static int` 또는 `static void` 함수다. 인수는 පරිශීලක API로 조회한다.

```java
public final class 내프로그램 {
    public static int ක්_රියාත්මක_කරන්න_2() {
        පරිශීලක.ලිවීම("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/පරිශීලක/යෙදු_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := පරිශීලක/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.ක්_රියාත්මක_කරන්න_2
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `පරිශීලක/선언/පරිශීලක.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 ක්_රියාත්මක_කරන්න_විධානය 중인 VM에는 තැනුම_පද්ධතිය 결과가 자동 반영되지 않는다. යෙදු_f5044b9b 이름은 현재 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java පන්තිය_අගය·ශ්_රිතය_අගය·변수에는 한국어를 쓴다. 최대 32개 යෙදු_f5044b9b, 한 ක්_රියාත්මක_කරන්න_විධානය 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.ක්_රියාත්මක_කරන්න_2 \
    -o os/build/apps/hello.elf os/පරිශීලක/선언/පරිශීලක.java os/පරිශීලක/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 ධාරකය 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 සහාය_අගය පසුර 안에서 실행한다. `.jar`와 일반 Linux ක්_රියාත්මක_කරන්න_විධානය 파일은 지원하지 않는다.

## පරිශීලක 네트워크 API

선언은 `선언/පරිශීලක.java`에 있다. `ඊමේල්_දත්ත`/`자료받기`의 `int[]` අයිතමය_මූලාංගය 한 개는 බයිටය_අගය 하나(0~255)를 나타낸다. 한 데이터그램의 최대 දත්ත 길이는 1,024바이트다.

```java
int හසුරුව_අගය = පරිශීලක.සාදන්න_ජාලය(0); // 0: 임시 ස්ව_විෂය_පථය UDP තොට_අගය 자동 තේරීම_අගය
int[] දත්ත = new int[32];
දත්ත[0] = 'H'; දත්ත[1] = 'i';
int 보낸길이 = පරිශීලක.ඊමේල්_දත්ත(හසුරුව_අගය, 0x0a000202, 9000, දත්ත, 2);
int 받은길이 = පරිශීලක.자료받기(හසුරුව_අගය, දත්ත, 1500);
පරිශීලක.වසන්න_ජාලය(හසුරුව_අගය);
```

තථ්_ය_දත්ත 프로그램에서는 විවෘත_කරන්න·ඊමේල්·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 대기 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 추가 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | හසුරුව_අගය·ක්_රියාවලිය_අගය_පිවිසුම දිග_අගය·성공 등 해당 함수의 결과 |
| -5 | ජංගම_අගය ඊමේල්_අගය අසමත්වීම_අගය |
| -9 | 잘못되었거나 닫힌 통신 හසුරුව_අගය |
| -11 | 비차단 받기에서 도착한 දත්ත 없음 |
| -14 | පරිශීලක පොයින්ටරය/ආරා_ව_අගය පසුර දෝෂය |
| -19 | සහාය_අගය NIC 없음 |
| -22 | තොට_අගය/대기 시간/විස්තාරක අගය දෝෂය |
| -24 | 열린 ජාලය_තොට 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | දත්ත 또는 수신 ආරා_ව_අගය ප්_රමාණය 문제 |
| -98 | ස්ව_විෂය_පථය තොට_අගය සූචිය 중복 |
| -101 | 지원하지 않는 ගමනාන්තය_අගය යොමුව |
| -110 | ARP·ජංගම_අගය·수신 시간 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 සංකේතනය_අගය 있는 Java `int`의 බිටුව_අගය 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## ක්_රියාත්මක_කරන්න_විධානය 경계와 시스템 호출

```text
කවචය run → JKAP에서 ELF වලංගු_කරන්න·적재 → ring 3 පරිශීලක යෙදු_f5044b9b
                                 ↓ int 0x80
                      පොයින්ටරය 검사 → Java කර්නලය_අගය API → RTL8139/UDP
                                 ↓ පිටවීම_යෙදු·예외·시간 초과
                                කවචය 복귀
```

시스템 호출 레지스터는 `EAX=සූචිය`, `EBX,ECX,EDX,ESI,EDI=විස්තාරක`, `EAX=결과`다. Java 호출 스택 ABI는 컴파일러가 පරිශීලක 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| සූචිය | 호출 |
| --- | --- |
| 0 | පිටවීම_යෙදු(තත්වය_අගය 코드) — ක්_රියාත්මක_කරන්න_2/දෝෂය 런타임에서 사용 |
| 1 | අනුලකුණු_වැල_අගය ලිවීම |
| 2 / 3 | විස්තාරක 개수 / විස්තාරක අනුලකුණු_වැල_අගය යොමුව |
| 10 | UDP විවෘත_කරන්න |
| 11 | UDP ඊමේල්(හසුරුව_අගය, IP, ගමනාන්තය_අගය තොට_අගය, ආරා_ව_අගය යොමුව, දිග_අගය) |
| 12 | UDP 받기(හසුරුව_අගය, ආරා_ව_අගය යොමුව, 제한 밀리초) |
| 13 | UDP වසන්න |
| 14 | ස්ව_විෂය_පථය IP යොමුව |
| 15 / 16 | 마지막 සමානයා_අගය IP / UDP තොට_අගය |
| 20 | RAM ගොනු කියවීම(නම int[] යොමුව, 출력 int[] යොමුව) |
| 21 | RAM ගොනු ලිවීම(නම int[] යොමුව, 입력 int[] යොමුව, බයිටය_අගය දිග_අගය) |
| 22 | UTF-16 코드 ඒකක_අගය 문자 출력(0~65535) |

ගොනු API는 `පරිශීලක.파일읽기(int[] නම, int[] දත්ත)`와 `පරිශීලක.ලියන්න_ගොනුව(int[] නම, int[] දත්ත, int දිග_අගය)`다. 이름은 ASCII 코드 ආරා_ව_අගය(최대 64칸, 0 පිටවීම_යෙදු 또는 ආරා_ව_අගය 끝), දත්ත අයිතමය_මූලාංගය 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 ගොනු 없음 `-2`, පොයින්ටරය දෝෂය `-14`, නම/දිග_අගය දෝෂය `-22`, ගොනු විවරය_අගය 부족 `-28`, ප්_රමාණය 초과 `-90`을 반환한다. 쓰기는 වලංගු_කරන්න 후 ගොනු 전체를 대체한다. `පරිශීලක.ලියන්න_අනුලකුණ_අගය(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 පරිශීලක 모드에서 CS의 하위 비트를 직접 읽으므로 තථ්_ය_දත්ත ක්_රියාත්මක_කරන්න_විධානය 권한을 확인한다. කර්නලය_අගය 포트 접근용 `ජංගම_අගය` native 함수는 පරිශීලක ඉලක්කය 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 ක්_රියාත්මක_කරන්න_විධානය, 파이프, 프로세스 간 통신은 없다. ක්_රියාත්මක_කරන්න_විධානය 파일은 커널의 කියවීම 전용 JKAP 묶음에서 적재한다. දත්ත 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- පරිශීලක 가상 යොමුව `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. ක්_රියාත්මක_කරන්න_විධානය 영상은 앞 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. කර්නලය_අගය identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB පරිශීලක 영역을 비우고 ගොනු 구역을 복사해 BSS·ආරා_ව_අගය 영역을 초기화한다. පරිශීලක GC는 없지만 පිටවීම_යෙදු 후 다음 ක්_රියාත්මක_කරන්න_විධානය 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 따옴표/이스케이프 파싱은 없다.
- පරිශීලක 페이지의 코드/දත්ත 분리 කියවීම 전용 සැකසුම්, NX, 스택 guard, ASLR은 아직 없다. 커널과 පරිශීලක මතකය_දත්ත·포트 අවසරය_අගය 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 ක්_රියාත්මක_කරන්න_විධානය 상한을 두며 시간 초과는 `Exit: 124`다. පරිශීලක CPU 예외는 `128 + 예외 සූචිය`(페이지 දෝෂය 142, 특권 위반 141), Java ආරා_ව_අගය/계산 오류는 101~105다. කර්නලය_අගය 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, ස්ථිතික_අගය IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP 검사합 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- පරිශීලක ක්_රියාත්මක_කරන්න_විධානය·네트워크·ආරක්ෂා_කරන්න_අගය 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 ක්_රියාත්මක_කරන්න_විධානය·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## වලංගු_කරන්න 근거

`make test`는 컴파일러 14개 시험, Java 패킷 තත්වය 2,201개 검사, 기존 කවචය ELF/ISO 부팅 시험, පරිශීලක ELF/තථ්_ය_දත්ත UDP/ආරක්ෂා_කරන්න_අගය 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 දිග_අගය·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 විධානය·무한 පුනර්කරණය_අගය 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
