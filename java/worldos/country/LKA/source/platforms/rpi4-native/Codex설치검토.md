# 자체 ARM64 커널의 Codex ස්ථාපනය_කරන්න_අගය 가능성 검토

검토일: 2026-10-05. 소스와 공식 문서를 대조한 설계 검토이며, 게스트에 Codex를 설치하거나
로그인·모델 호출을 실행한 결과는 아니다. 자체 ARM64 커널과 `../rpi4` Linux 실행판은 구분한다.

현재 자체 커널에는 공식 Codex CLI를 그대로 ස්ථාපනය_කරන්න_අගය·실행할 수 없다.
기술적으로 필요한 ක්_රියාත්මක_කරන්න_විධානය 환경을 추가하거나 Codex를 이식하는 경로는 있으나,
다운로드 විධානය 하나를 추가하는 작업으로 해결되지 않는다. JDK/JRE 기능 확장만으로도 해결되지 않는다.

|---|---|---|
| ක්_රියාත්මක_කරන්න_විධානය ගොනු | `යන්ත්_රය/පරිශීලක.c`: AArch64 ET_EXEC만, PT_INTERP/PT_DYNAMIC/PT_TLS 거부, 업로드 ක්_රියාත්මක_කරන්න_විධානය 버퍼 16384바이트 | ඉලක්කය 바이너리에 맞는 ELF 적재·재배치·ක්_රියාත්මක_කරන්න_විධානය මුලපුරන්න, මතකය_දත්ත/ගොනු 제한 දිගුව_අගය |

| 프로세스·스레드 | 일반 fork/clone/execve, pthread/futex, 시그널, mmap, poll/epoll 계열이 미완성 | 비동기 I/O·스레드·දරුවා_අගය විධානය ක්_රියාත්මක_කරන්න_විධානය·පිටවීම_යෙදු/එපා_මෙහෙයුම 기능 |
| ගොනු | `මූලය/මතකය_ගොනු.java`: RAM ගොනු 64개, 파일당 16 KiB, 비영속 | 큰 ක්_රියාත්මක_කරන්න_විධානය ගොනු·프로젝트·සැකසුම්·세션을 위한 영속 VFS, ගොනු අවසරය_අගය·මාර්_ගය·디렉터리 දිගුව_අගය |
| 네트워크 | lwIP TCP/UDP는 있으나 `ජාලය_කැටිය/lwipopts.h`의 LWIP_DNS=0, 일반 HTTPS 클라이언트 없음 | DNS, TLS 인증서 වලංගු_කරන්න·신뢰 저장소·정확한 시각, HTTPS/스트리밍 |
| අග්_රය·මෙවලම් | 자체 셸과 GUI 터미널은 있지만 표준 PTY·일반 프로세스 작업 පාලකය_අගය 없음 | අන්තර්ක්_රියාකාරී CLI용 අග්_රය 기능, කවචය/ගොනු 검색/තැනුම_පද්ධතිය මෙවලම් සම්බන්ද_වන්න |
| ක්_රියාත්මක_කරන්න_විධානය අවසරය_අගය | EL0 보호는 있으나 Codex의 Linux 샌드박스와 같은 정책 집행 환경 없음 | ගොනු·네트워크·විධානය අවසරය_අගය 정책과 승인 기능; 자체 커널에 맞는 격리 구현 |

여기서 ELF의 PT_TLS는 스레드별 ගබඩා_කරන්න_අගය 공간이다. HTTPS의 TLS මුර_පදය_අගය 통신과 서로 다른 기능이다.
ELF ගොනු 형식을 읽을 수 있다는 사실만으로 Linux ක්_රියාත්මක_කරන්න_විධානය 환경을 제공하는 것은 아니다.
SSH/VNC를 위한 මුර_පදය_අගය 라이브러리를 넣은 상태도 HTTPS 구현 완료를 의미하지 않는다.

호스트의 `/home/user/.local/bin/codex`도 확인했다. 이것은 x86-64 ELF ET_DYN이며 약 209 MiB다.
해당 파일을 ARM64 게스트로 복사하여 실행할 수 없다. 이 크기를 ARM64 배포 파일의 크기로
해석하지 않는다. 공식 ARM64 빌드의 තථ්_ය_දත්ත ප්_රමාණය·의존성은 설치할 버전으로 추가 검사해야 한다.

## 가능한 구현 මාර්_ගය

1. **자체 커널에 공식 CLI 직접 이식**
   영속 ගබඩා_කරන්න_අගය/VFS와 පරිශීලක මතකය_දත්ත, 프로세스·스레드·I/O, libc/런타임, DNS/HTTPS,
   අග්_රය·අවසරය_අගය 체계를 갖춘다. 이후 ඉලක්කය 버전의 의존성을 조사하여 크로스 තැනුම_පද්ධතිය·이식한다.
   Linux 커널을 반드시 탑재할 필요는 없지만, 공식 Linux 바이너리를 그대로 쓸 경우
   그 바이너리가 사용하는 Linux ABI까지 호환해야 한다. 큰 මෙහෙයුම්_පද්ධතිය 개발 과제다.

2. **외부 ධාරකය Codex와 자체 කර්නලය_අගය සම්බන්ද_වන්න — 첫 구현으로 권장**
   Linux PC에서 공식 CLI 또는 app-server를 실행하고 jkoros에는 전용 පරිශීලක විධානය/화면을 만든다.
   호스트의 인증된 연결과 게스트 ගොනු කියවීම·수정·업로드·විධානය ක්_රියාත්මක_කරන්න_විධානය 어댑터가 필요하다.
   기존 SSH/TCP 경로를 활용할 수 있으나, ගොනු 동기화나 Codex 전용 어댑터는 현재 구현되어 있지 않다.
   호스트에서 수행한 빌드와 게스트에서 수행한 ක්_රියාත්මක_කරන්න_විධානය 결과를 명확히 구분한다.
   이 구성은 자체 커널을 유지하지만, 공식 CLI 자체는 외부 호스트에서 실행된다.

3. **자체 API 클라이언트 제작**
   자체 ABI의 C 또는 지원되는 Java 부분집합으로 අන්තර්ක්_රියාකාරී_සැසිය UI와 ගොනු/විධානය මෙවලම් 호출 루프를 만든다.
   외부 중계기를 쓰지 않는다면 DNS/වලංගු_කරන්න 가능한 TLS/HTTPS와 인증 දත්ත 저장을 먼저 구현해야 한다.
   이는 OpenAI API를 이용하는 별도 에이전트이며 공식 Codex CLI 전체의 이식으로 표시하지 않는다.

4. **별도 ARM64 Linux 실행판에서 ස්ථාපනය_කරන්න_අගය**
   `../rpi4`는 Linux와 musl 기반이므로 일반 Linux ස්ථාපනය_කරන්න_අගය 경로를 검토할 수 있다.
   사용할 Codex 버전의 ARM64·musl 호환성, 의존성, 커널의 샌드박스 지원을 තථ්_ය_දත්ත 검증해야 한다.
   이번 검토에서 ස්ථාපනය_කරන්න_අගය 성공을 확인하지 않았다. 이 결과를 자체 Java 커널의 지원으로 표시하지 않는다.

## 단계별 완료 기준

- 직접 이식: `--version` ක්_රියාත්මක_කරන්න_2 → 인증/HTTPS → ගොනු කියවීම·수정 → දරුවා_අගය විධානය ක්_රියාත්මක_කරන්න_විධානය →
  අන්තර්ක්_රියාකාරී 입력/스트리밍 → අවසරය_අගය 제한·එපා_මෙහෙයුම → 재부팅 후 සැකසුම්/세션 보존을 각각 තථ්_ය_දත්ත 게스트에서 확인한다.
- ධාරකය සම්බන්ද_වන්න: 게스트에서 요청 입력 → ධාරකය Codex ක්_රියාවලිය_අගය_පිවිසුම → 게스트 ගොනු වෙනස්_කරන්න_අගය තහවුරු_කරන්න →
  게스트 javac/cc ක්_රියාත්මක_කරන්න_විධානය → 결과 표시를 처음부터 끝까지 검증한다.
- COSL 상업 조건을 유지하려면 새로 도입하는 런타임/통신 라이브러리의 라이선스와
  Codex 배포 버전의 제3자 고지를 검토한다. 외부 구성요소를 일괄 COSL로 재라이선스하지 않는다.
