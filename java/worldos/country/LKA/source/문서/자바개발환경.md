# jkoros 안에서 Java සාදන්න_මූලය·ක්_රියාත්මක_කරන්න_විධානය

이 문서의 부팅·කවචය·ගබඩා_කරන්න_අගය 명령은 **x86 අනුවාදය_අගය** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 අනුවාදය_අගය](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 ගොනුව_නම_පෙළ, `edit`의 단독 `.` ගබඩා_කරන්න_අගය, 16개 RAM ගොනු, 약 2초 ක්_රියාත්මක_කරන්න_විධානය 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 තථ්_ය_දත්ත JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. ධාරකය සාදන්න_මූලය 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java යෙදු_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 ක්_රියාත්මක_කරන්න_විධානය

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. ක්_රියාත්මක_කරන්න_විධානය 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox ක්_රියාත්මක_කරන්න_විධානය README_ගොනුව_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 ගොනු 전체를 새 내용으로 작성한다. 기존 내용의 පේළිය සකසන්න_අගය 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 බයිටය_අගය 수 දර්ශනය_අගය.
- `cat FILE`: ගොනු අන්තර්ගතය_අගය දර්ශනය_අගය. 텍스트 소스에 사용한다.
- `rm FILE`: මතකය_දත්ත ගොනු 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·ටයිප්_කරන්න_අගය 검사 අසමත්වීම_අගය 시 기존 `.class`는 유지된다. 소스를 고친 ආපසු_අගය 컴파일이 실패했다면 이전 ක්_රියාත්මක_කරන්න_විධානය 파일이 남아 있으므로 සාදන්න_මූලය 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 ගබඩා_කරන්න_අගය 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 මූලය_රුක·පන්තිය_අගය·දත්ත 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, ගොනු 이름은 ASCII 1~63자다. මූලය_රුක 이름은 `.class` 확장자 공간 때문에 최대 62자다. සකසන්න_අගය 입력은 ASCII이고 한 පේළිය 최대 128자다. පේළිය 또는 ගොනු 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. කර්නලය_අගය/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 පරිශීලක 예제 이름은 ASCII로 작성한다.

## 외부 ගොනු 적재

호스트에서 만든 소스나 සහාය_අගය පසුර 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 තථ්_ය_දත්ත 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# ධාරකය JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 다음 빌드에서는 추가 파일을 포함하지 않는다. ගොනු අන්තර්ගතය_අගය 변경과 පිවිසුම_ලැයිස්තුව 제거도 다음 빌드에 반영된다. 원본 ධාරකය 파일에는 쓰지 않는다. පෙරනිමි_අගය `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 පෙරනිමි_අගය 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 පන්තිය_අගය ගොනු 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 සහාය_අගය පසුර 안에 있어야 한다.

## සහාය_අගය පසුර

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 ස්ව_විෂය_පථය 선언, 오버로드, 임의 ටයිප්_කරන්න_අගය 변환, ආරා_ව_අගය 생성 මූලය, 8/16진 리터럴, Unicode මූලය_රුක 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 නියතය_අගය 축소 변환을 구현하지 않는다. 외부 `.class`의 `int[]` 생성/කියවීම/쓰기는 지원하므로 ධාරකය `javac --release 8`로 만든 ආරා_ව_අගය 예제는 실행할 수 있다.

වස්තුව_අගය ක්_ෂේත්_රය_අගය·일반 වස්තුව_අගය 생성·상속·인터페이스·여러 පන්තිය_අගය සම්බන්ද_වන්න, long/float/double, 예외 ක්_රියාවලිය_අගය_පිවිසුම, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java 예외 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 අනුලකුණු_වැල_අගය ගබඩා_කරන්න_අගය 공간은 ක්_රියාත්මක_කරන්න_විධානය පිටවීම_යෙදු 시 පරිශීලක 영역 전체와 함께 회수한다. 지속 ක්_රියාත්මක_කරන්න_විධානය 중 GC는 없다.

| JVM වස්තුව_අගය ගබඩා_කරන්න_අගය 공간 | 8,192개 32비트 විවරය_පිවිසුම, 헤더 포함 약 32KiB |
| ක්_රියාත්මක_කරන්න_විධානය | 최대 500,000 විධානය, 기존 커널의 약 3초 CPU ක්_රියාත්මක_කරන්න_විධානය 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 සහාය_අගය 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM ශබ්දකෝෂය 검증기를 구현한 것은 아니다. ගොනු/ගුණාංගය_අගය දිග_අගය, නියතය_අගය පරිශීලනය, විධානය·ශාඛාව 경계를 검사하고, ක්_රියාත්මක_කරන්න_විධානය 중 스택 හැඩතලය_අගය·ස්ව_විෂය_පථය මුලපුරන්න·ආරා_ව_අගය යටිලකුණ_අගය·වස්තුව_අගය 참조를 검사한다. පරිශීලක 코드의 페이지·포트 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, සාදන්න_මූලය·JVM 오류는 `Exit: 1`, විධානය විස්තාරක 오류는 `Exit: 2`다. CPU 시간 상한은 기존 `Exit: 124`이며, පරිශීලක ELF 자체의 CPU/런타임 오류는 기존 පිටවීම_යෙදු 코드를 따른다. අසමත්වීම_අගය 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## 구현 위치와 시험

- `os/පරිශීලක/자바/자바컴파일러.java`: 게스트 어휘·구문·ටයිප්_කරන්න_අගය 검사, නියතය_අගය 풀 및 바이트코드 생성.
- `os/පරිශීලක/자바/자바가상기계.java`: පන්තිය_අගය 적재, 스택·프레임·වස්තුව_අගය ගබඩා_කරන්න_අගය, විධානය 해석과 제한된 표준 호출.
- `os/මූලය/මතකය_ගොනු_පද්ධතිය.java`: මතකය_දත්ත ගොනු_පද්ධතිය, සකසන්න_අගය, 부팅 ගොනු 적재.
- `os/මූලය/체계호출.java`, `compiler/ඇරඹුම_පරිශීලක_යෙදු.s`: ගොනු/문자 출력 API와 පරිශීලක පොයින්ටරය 검사.
- `os/මෙවලම්/자바파일묶기.py`: ධාරකය 입력 ගොනු වලංගු_කරන්න·부팅 සමූහය_අගය 생성.

```sh
make test-java
make test
```

`os/시험/자바시험.py`는 ELF/ISO 부팅, 게스트 සාදන්න_මූලය·ක්_රියාත්මක_කරන්න_විධානය, පරිශීලක 입력, 재귀·반복문·පූර්ණාංකය 극값·අනුලකුණු_වැල_අගය 결합·단락 평가, 재실행, මූලය_රුක දෝෂය 후 기존 පන්තිය_අගය 보존, ආරා_ව_අගය/수 해독 දෝෂය, 무한 පුනර්කරණය_අගය 제한, සකසන්න_අගය 넘침과 ගොනු 부족을 검사한다. 게스트 생성 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 ධාරකය OpenJDK의 පන්තිය_අගය, පූර්ණාංකය 배열과 한글 상수를 게스트에 적재하며, 손상된 ගොනු 표식·버전·නියතය_අගය 수·ශාඛාව·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 시험 VM만 생성하고 종료한다.

구현 형식의 참고 දත්ත: Oracle [JVM පන්තිය_අගය ගොනු 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM විධානය 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java ගොනු ආදාන_ප්_රතිදාන

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 පන්තිය_අගය 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 ආපසු_අගය `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. පෙරනිමි_අගය 출력 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. 예외 වස්තුව_අගය·try/catch·try-with-resources는 지원하지 않으며 ගොනු 오류를 진단하고 프로그램을 종료한다. ආරා_ව_අගය ආදාන_ප්_රතිදාන, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 ගොනු 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 කවචය `sync`가 필요하다. 예제의 ගොනු 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 තථ්_ය_දත්ත 게스트 සාදන්න_මූලය 결과를 OpenJDK `-Xverify:all`로 다시 실행해 ගොනු 바이트와 출력을 대조한다. 범위와 ගබඩා_කරන්න_අගය 매체 사용법은 [posix-kor README_ගොනුව_eb81d7d9](../posix-kor/README_ගොනුව_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
