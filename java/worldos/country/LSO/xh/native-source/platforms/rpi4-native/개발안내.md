# 자체 커널에서 vi·여러 i_Terminal·한글 프로그래밍 사용하기

isiXhosa 통신·예외 사용법은 [isiXhosa Java API](한국어자바/i_README_eb81d7d9.md), INKQUBO_ixabiso·변수·iFayili 이름의 변경과 어원 근거는 [명명 i_README_eb81d7d9](명명/i_README_eb81d7d9.md)를 참고한다.

대상은 `platforms/rpi4-native`의 자체 AArch64 Java 커널이다. vi와 Java/Python/C/C++ 프로그램은 EL0에서 실행한다. Linux 실행판과 별도이며 아래 inkxaso_ixabiso 목록은 전체 OpenJDK·Vim·POSIX 구현을 뜻하지 않는다.

게스트 `cc`/`jaot`, JAR 직접 ukwenza_umyalelo, 외부 TCP/UDP와 FTP는 [새 ukwenza_umyalelo 매뉴얼](파일전송과번역.md)을 참고한다.

## GUI와 여러 i_Terminal

```sh
cd /home/user/jkoros/platforms/rpi4-native
make desktop
```

Remmina에서 **VNC**, idilesi **127.0.0.1:5902**로 연결한다. 화면 위 **+ New terminal**, **Ctrl+Shift+T**로 터미널을 추가한다. 최대 네 개다. 위쪽 i_Terminal 버튼 또는 창을 클릭해 선택하고 **F6**으로 순환한다. 제목줄을 끌어서 옮기고 **오른쪽 위 X**를 클릭하면 닫힌다. 마지막 창을 닫아도 위쪽 ukwenza_umyalelo 버튼으로 다시 ikholam_ixabiso 수 있다. 기존 `terminal`, `exit`, F12도 사용할 수 있다.

창마다 현재 디렉터리, isiniki_myalelo 변수, Umyalelo ilog_umqolo, 입력 중인 명령과 inkqubo_f5044b9b ukwenza_umyalelo 상태를 보관한다. iFayili 저장소는 공유한다. vi와 Swing의 이벤트 대기 중에 다른 터미널로 전환하면 umsebenzisi imemori_iingcombolo·레지스터·iFayili/소켓 연결을 보존했다가 돌아올 때 재개한다. **현재 네 프로그램이 동시에 CPU에서 실행되는 선점형 스케줄러는 아니다.** 계산 중인 프로그램은 다음 입력 대기 또는 기존 ukwenza_umyalelo 기한까지 전환이 지연될 수 있다.

X로 터미널을 닫으면 그 터미널의 ukwenza_umyalelo 중인 프로그램도 종료하며 서술자·소켓을 회수한다. 저장하지 않은 hlela_ixabiso 내용은 사라진다. 종료한 슬롯은 새 창에서 재사용한다. 현재 모든 파일은 RAM에 있으며 VM 재시작 후에는 남지 않는다.

화면과 i_window 판단은 게스트 커널이 처리한다. QEMU ukwenza_umyalelo 도구는 VNC 키와 마우스 좌표를 UART 패킷으로 전달한다. eyona_yenzekileyo_iingcombolo Pi4 USB 입력기와 실물 부팅은 아직 검증하지 않았다. 일반 UART 셸은 `make run`, GUI Izixhobo 종료는 umsingathi 터미널의 Ctrl+C다.

`통신규약.h`의 자체 `pk_sockaddr_in`을 사용하며 iphothi_ixabiso·주소는 `망차례짧은수`/`Inethiwekhi_inani_elipheleleyo`로 변환한다. C 소켓 호출은 비차단이며 iingcombolo/연결이 없으면 -1과 `오류번호=11`(EAGAIN)을 반환한다. 양수 i_I_O 결과가 요청보다 작을 수 있으므로 uniko_lomyalelo_omnye_ixabiso 처리한다. ukungaphumeleli_ixabiso 후에만 오류번호를 확인한다.

[Stream_ixabiso.c](예제/한글코딩/Stream_ixabiso.c)는 C에서 isiXhosa 이름으로 Nxulumanisa·accept·부분 Funda/Bhala·큐 포화·EOF를 처리하는 ukwenza_umyalelo 예제다. SDK의 `examples/Stream_ixabiso.c`를 같은 `compile.py`로 컴파일한다.

SDK는 **libposix-kor-user.a**를 링크한다. 호출 흐름은 C/C++ → eyona_yenzekileyo_iingcombolo isiXhosa C INKQUBO_ixabiso 또는 호환용 `pk_*` → `svc #0` → 커널의 소유권·isalathisi 검사 → Java RAM iFayili/루프백 또는 외부 lwIP TCP/UDP 구현이다. `libposix-kor-arm64.a`는 ikheneli_ixabiso 내부용이므로 EL0 프로그램에 링크하지 않는다. Linux 헤더나 Linux ELF와 혼합하지 않는다. 동적 Nxulumanisa, 표준 C printf, libstdc++/STL, 예외·RTTI는 제공하지 않으며 C++의 imi_ndawonye_ixabiso 생성자·eyale_ndawo_umda into_ixabiso 소멸자는 지원한다. 상세 indeksa·imemori_iingcombolo 범위는 [사용자호출규약.md](사용자호출규약.md)를 참고한다.

## isiXhosa 이름으로 직접 작성하는 창과 ithredi_ixabiso

`example/java/창예제.java`는 `실행할일.ukwenza_umsebenzi`,
`동작받이.동작받기(동작알림)`, `iqhosha`, `umcimbi_ityhu.나중에실행`, `Phumeza()`을 쓴다.
자체 JVM에 이 이름들의 into_ixabiso·imethodi_ixabiso·콜백을 직접 구현했으며 영어 Swing 객체를
보관하는 래퍼가 아니다. `작업가닥`도 자체 스케줄러와 직접 연결된다.
세부 메서드와 기존 isiXhosa API에서의 변경은 [isiXhosa API 문서](한국어자바/i_README_eb81d7d9.md)를 본다.

umsingathi javac는 배포 JAR를 iklasi_ixabiso 경로로 사용한다.

```sh
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/한국어사용 ../../example/java/창예제.java
python3 Izixhobo/ukwenza_umyalelo.py --desktop --network --resolution 1920x1080
```

게스트에는 빌드한 예제가 `/example/java`에 설치된다.

```text

java 창예제
```

직접 화면/ithredi_ixabiso API와 `Phumeza()` 진입점은 자체 JVM 전용이다.
전체 OpenJDK·Swing 재구현이나 일반 OpenJDK에서 같은 API의 실행을 보장하지 않는다.
기존 표준 `main(String[])` 프로그램은 계속 실행할 수 있다.
