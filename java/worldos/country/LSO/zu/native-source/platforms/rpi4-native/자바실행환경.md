# 자체 ARM64 JVM 0.4와 Isi_Zulu umtapo

Isi_Zulu 통신·예외 사용법은 [Isi_Zulu Java API](한국어자바/NGIFUNDE_eb81d7d9.md), umsebenzi_inani·변수·Ihele 이름의 변경과 어원 근거는 [명명 NGIFUNDE_eb81d7d9](명명/NGIFUNDE_eb81d7d9.md)를 참고한다.

JAR yenza_umyalo, 외부 IPv4 TCP/UDP, 별도 ngaguquki_inani 부분집합 `jaot`와 게스트 C 컴파일은 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)에 설명한다. 아래 into_inani·Thread·Swing은 JVM 경로의 기능이며 AOT uxhaso_inani 범위와 같지 않다.

이 구현은 **Linux 없이 부팅한 Java AOT 커널의 EL0에서 yenza_umyalo**한다. JDK/JRE의 거의 모든 기능을 제공하는 단계는 아직 아니다. HotSpot·OpenJDK uhlobo_inani umtapo 전체를 이식하거나 Java SE 인증/TCK를 통과한 구현도 아니다. 이번 확장은 단일 uhlobo_inani·ngaguquki_inani indlela_inani 중심이던 실행기를 into_inani·umtapo yenza_umyalo 기반으로 넓힌 것이다.

게스트 `javac`는 여전히 ngaguquki_inani indlela_inani, int/boolean/char/String, isimo·impinda_inani, uchunge_inani 결합, 일부 Ihele 스트림 등의 **자체 부분집합 컴파일러**다. into_inani 선언·상속·try/catch·Thread 사용 소스를 게스트 javac가 모두 컴파일하는 것은 아니다. 위 기능은 `javac --release 8`로 만든 class를 자체 JVM에서 실행한다. ## Isi_Zulu API

독립 패키지 **`Isi_Zulu.자체`**를 사용한다. Linux판 `Isi_Zulu.자바`가 요구하는 NIO/Swing/HTTP API를 자체 커널에서 실행할 수 있다고 혼동하지 않도록 패키지를 나눴다. 이 라이브러리는 uhlobo_inani Igama·indlela_inani·인수·inkundla_indawana_inani·Ihele 이름에 한국어를 사용한다. 표준 Java uhlobo_inani 이름은 호환성을 위해 보존한다.

## yenza_umyalo 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(Isi_Zulu uhlobo_inani 포함), class당 16 KiB·okungaguquki_inani 풀 511항목, 전체 indlela_inani/inkundla_indawana_inani 각각 512개. indlela_inani 코드 8 KiB, endaweni_umklamo 변수·피연산자 스택 각각 128슬롯, 인수 최대 16개(this 포함).
- VM 가닥은 main 포함 **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 yenza_umyalo 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- into_inani 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 ulwazi_ngokwenzekile_imininingwane 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 Ihele·대형 uchunge_inani·객체가 이 제한을 넘을 수 있다.
- 실행은 50만 바이트코드 Umlayelo 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 입력 대기는 기한을 갱신하고 ifasitela guqulela_kokunye_inqubo 시 중단·재개한다. 일반 Iseva_inani·계산의 무제한 실행은 아직 없다. 미지원 Umlayelo·insiza_inani 부족은 명시적인 오류로 종료한다.
- RAM Ihele 최대 64개, 파일당 16384바이트, Indlela_2 UTF-8 63바이트. RAM 디렉터리와 untanga_inani/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 Isi_Zulu class는 RAM Ihele 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 현재 경로에서 umthombo_isihlahla·uhlobo_inani·imininingwane 파일을 읽는다.
- UDP는 Java 루프백 및 lwIP/SLIP를 통한 외부 IPv4를 제공한다. ulwazi_ngokwenzekile_imininingwane GENET/Wi-Fi/DNS/TLS/HTTP 전체는 없다. 전문 512바이트, 소켓 8개, 소켓당 큐 4개. receive는 VM 가닥을 양보하며 대기하고 setSoTimeout을 적용하지만 전체 yenza_umyalo 기한은 여전히 적용된다.
- long/float/double, invokedynamic/람다, enum/annotation, 다차원 AMALUNGU_AFANAYO_inani, 완전한 AMALUNGU_AFANAYO_inani 공변성·인터페이스 ugqinsi_inani 검사, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/bhala_ngokufihla_imininingwane/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. Swing의 별도 uxhaso_inani 부분집합은 아래 및 개발 매뉴얼을 참고한다. uhlobo_inani Ihele 전체 검증기·ungeno_okufakwayo imvume_inani/보호된 멤버 검사는 아직 완전하지 않다. 손상된 입력은 EL0 vikela_inani 경계 내에서 종료되도록 한다.

전체 OpenJDK를 목표로 하려면 다음은 별도의 주요 구현 단계다: 완전한 JVM inani/qinisekisa/uhlobo_inani 로더와 예외 모델 → 영속 VFS·mmap·iwashi·원자 umsebenzi_inani_c96707fb·ulwazi_ngokwenzekile_imininingwane 스레드/i_sync ABI → OpenJDK java.base 및 native umtapo 이식 → idivayisi_inani 네트워크·TCP/IP → ifasitela 시스템/ubuso_bohlamvu_ifonti_inani/입력기·java.desktop → Java SE 호환성 시험. 현재 자체 JVM의 일부 메서드를 더하는 것으로 이 작업이 완료되지는 않는다.

## JVM 0.3: 네트워크와 GUI iselulo_inani

`Socket`/`ServerSocket` 생성·Xhumanisa·accept·양방향 InputStream/OutputStream·close·EOF·시간 제한과 UTF-8 `String.getBytes`를 추가했다. JVM 0.4에서는 외부 idijithi_inani IPv4 TCP도 lwIP/SLIP에 연결했다. 연결형 yekisa_iphoyinti 16개, Java 루프백 버퍼 1024바이트, 외부 TCP 버퍼 4096바이트다. DNS·TLS는 없다.

`JFrame`, `JPanel`, `JLabel`, `JButton`, `JTextField`, `ActionListener`, `ActionEvent`, `SwingUtilities.invokeLater`의 문서화한 부분집합을 네이티브 GUI에 연결했다. `setLayout(null)`과 명시적 좌표를 사용한다. 전체 OpenJDK Swing 또는 Java SE 호환 구현은 아니다. ingxoxo_nekhompiyutha 이벤트 대기는 yenza_umyalo 기한을 갱신하고 터미널 guqulela_kokunye_inqubo 시 프로세스 상태를 Store_inani·복원한다. 이벤트 콜백 자체는 기존 바이트코드/CPU 기한을 따른다.

Isi_Zulu `ifasitela`, `iwijethi`, `연결통신` 클래스를 배포 JAR와 자체 JVM 내장 자원에 추가했다. 상세 indlela_inani·제한·umthombo_isihlahla·업로드 방법: [한글 개발 매뉴얼](개발안내.md).

## Isi_Zulu 객체의 직접 yenza_umyalo

`ifasitela`, `uphawu`, `I_SMS_inkundla_indawana`, `inkinobho`, `isigameko_ujenge`, `동작알림`, `작업가닥`은
표준 GUI/Thread 객체를 보관하는 래퍼가 아니다. 자체 JVM의 into_inani 생성,
misa_inani 검사, 화면 호출, isigameko 큐, uhlu_lwemilayezo_inani 스케줄러에 Isi_Zulu 계약을 직접 구현했다.
표준 `javax.swing`·`Thread` 코드의 yenza_umyalo 경로도 유지한다.
Isi_Zulu 단추와 표준 JButton은 서로 다른 형식이며, 해당 instanceof 검사도 검증한다.

자체 실행기의 Isi_Zulu 진입점은 `public static void Sebenzisa()`이다.
표준 `main(String[])`도 지원하며 둘 다 있으면 Isi_Zulu 진입점을 우선한다.
명령행 인수는 `실행인수.개수()`와 `실행인수.Itekisi(순번)`으로 읽는다.
`example/java`의 다섯 예제는 이 규약을 사용한다. ngaguquki_inani Ihele 예제는 게스트
javac로도 컴파일하며, GUI/uhlu_lwemilayezo_inani 소스는 singatha `javac --release 8`을 사용한다.
직접 GUI/uhlu_lwemilayezo_inani API는 자체 JVM 전용이다. 기존 OpenJDK 비교 시험과 별도로
Isi_Zulu 가닥의 yenza_umyalo·대기·중복 Sebenzisa 거부, GUI isigameko 출처·thola_inkomba·콜백을 검사한다.
전체 JDK 번역이나 모든 API의 jaot 지원을 뜻하지 않는다.

indlela_inani 이름은 바이트코드에서도 유지된다. 이름과 참조를 같이 수정하면
Isi_Zulu 클래스도 실행되지만, uchunge_inani 리터럴·표준 umtapo 재정의·native
Xhumanisa·진입점은 각각 컴파일러와 실행기의 계약을 맞춰야 한다.
[상세 계약과 예제](한국어자바/NGIFUNDE_eb81d7d9.md)를 참고한다.

## 터미널 부분 vuselela

susa_inani·Ubungako 변경은 새 ifasitela 영역과 이전 자리에서 드러난 띠만 합성한다.
1920×32 i_pel(240 KiB)의 임시 그림에서 배경·겹친 ifasitela·uhlamvusimo_inani·GUI를 먼저
완성하고, 현재 khombisa_inani 메모리와 비교하여 달라진 화소만 기록한다.
32줄보다 큰 영역은 여러 띠로 처리하므로 전체 프레임을 원자적으로
교체하거나 수직 동기에 맞추는 방식은 아니다. 전체 배경을 먼저 지우는
중간 화면은 표시하지 않는다. 좌표가 같으면 다시 그리지 않는다.

`make test-redraw`는 ulwazi_ngokwenzekile_imininingwane C 그리기 코드를 호스트의 inkumbulo_imininingwane 화면에 연결해
susa_inani 80회·Ubungako guqula_inani 40회·겹친 ifasitela 4개를 전체 합성 결과와 i_pel 단위로 대조한다.
영역 밖 umsebenzisi umdwebo_inani, 동일 i_pel 무기록, isikhombi 밑그림, ulwazi_ngokwenzekile_imininingwane 화면 umugqa 간격을
검사한다. 이 시험의 시간은 singatha CPU 측정이며 Pi 4/QEMU 속도로 해석하지 않는다.
`make test-resize`는 QEMU/VNC의 640×480 및 1920×1080에서 왼쪽 모서리 donsa_inani,
한글 입력·vi 미저장 Okuqukethwe_inani·독립 ifasitela 크기를 검사한다.
