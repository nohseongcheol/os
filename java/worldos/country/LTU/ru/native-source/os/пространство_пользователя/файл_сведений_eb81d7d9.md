# 셸에서 실행하는 пространство_пользователя 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 среда файл_сведений_eb81d7d9](../../문서/Java_IDE.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 실행

узел терминал 1:

```sh
cd /home/user/jkoros
python3 os/инструменты/вывод_на_экран_данные.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. внешний_ЗНАЧЕН 연결을 받도록 방화벽이나 аппаратный_порт 전달을 변경하지 않는다. Ctrl+C로 종료한다.

узел терминал 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 входные_данные_ЗНАЧЕН:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 фактический_данные CPU Полномочие_ЗНАЧЕН `ring 3`, аргументы текстовыйВывод.
- `netcheck`: порт_ЗНАЧЕН 중복, 잘못된 маркер_ЗНАЧЕН/указатель/длина_ЗНАЧЕН, 비차단 받기와 значение_времени 초과 проверять.
- `udp`: IPv4 АДРЕС·цель_ЗНАЧЕН порт_ЗНАЧЕН·한 Word_ЗНАЧЕН 메시지를 받아 UDP로 보내고 같은 응답을 проверять. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: узел `10.0.2.2`의 Назначить_ЗНАЧЕН 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. получить_ЗНАЧЕН Loop_ЗНАЧЕН 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. текущий_товар 주소는 게스트 `10.0.2.15/24`, шлюз_ЗНАЧЕН `10.0.2.2`로 고정돼 있다. QEMU пространство_пользователя 네트워크의 узел доступ_ввод 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 программа_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java программа_f5044b9b добавить_ввод

`예제/내프로그램.java`를 Далее_товар 형식으로 만든다. 진입점은 аргументы 없는 `static int` 또는 `static void` 함수다. 인수는 пространство_пользователя API로 조회한다.

```java
public final class 내프로그램 {
    public static int запустить() {
        пространство_пользователя.Запись("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/пространство_пользователя/программа_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := пространство_пользователя/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.запустить
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `пространство_пользователя/декларация/пространство_пользователя.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 실행 중인 VM에는 сборка 결과가 자동 반영되지 않는다. программа_f5044b9b 이름은 текущий_товар 셸의 ASCII входные_данные_ЗНАЧЕН 제한에 맞춘 1~15자의 소문자 이름이며 Java Класс_ЗНАЧЕН·ФУНКЦИЯ_ЗНАЧЕН·변수에는 한국어를 쓴다. 최대 32개 программа_f5044b9b, 한 실행 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/компилятор.py --target user --entry приветствие_ae353e94.запустить \
    -o os/build/apps/hello.elf os/пространство_пользователя/декларация/пространство_пользователя.java os/пространство_пользователя/예제/приветствие_ae353e94.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 узел 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 опора_ЗНАЧЕН клип 안에서 실행한다. `.jar`와 일반 Linux 실행 파일은 지원하지 않는다.

## пространство_пользователя 네트워크 API

선언은 `декларация/пространство_пользователя.java`에 있다. `написать_данные`/`получить_данные`의 `int[]` товар_элемент 한 개는 байт_ЗНАЧЕН 하나(0~255)를 나타낸다. 한 데이터그램의 최대 данные 길이는 1,024바이트다.

```java
int маркер_ЗНАЧЕН = пространство_пользователя.открыть_сеть(0); // 0: 임시 локальный_Scope UDP порт_ЗНАЧЕН 자동 выделение_ЗНАЧЕН
int[] данные = new int[32];
данные[0] = 'H'; данные[1] = 'i';
int 보낸길이 = пространство_пользователя.написать_данные(маркер_ЗНАЧЕН, 0x0a000202, 9000, данные, 2);
int ПОЛУЧЕНО_длина = пространство_пользователя.получить_данные(маркер_ЗНАЧЕН, данные, 1500);
пространство_пользователя.Close_сеть(маркер_ЗНАЧЕН);
```

фактический_данные 프로그램에서는 Открыть·написать·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/данные_коммуникация.java`에 있다. `получить_данные`의 минутку_ЗНАЧЕН 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 получить_ЗНАЧЕН 대기열은 한 개뿐이므로 добавить_ввод 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | маркер_ЗНАЧЕН·Процесс_ЗНАЧЕН_ввод длина_ЗНАЧЕН·성공 등 해당 함수의 результат |
| -5 | устройство_ЗНАЧЕН написать_ЗНАЧЕН сбой_ЗНАЧЕН |
| -9 | 잘못되었거나 닫힌 коммуникация маркер_ЗНАЧЕН |
| -11 | 비차단 받기에서 도착한 данные 없음 |
| -14 | пространство_пользователя указатель/МАССИВ_ЗНАЧЕН клип ошибка |
| -19 | опора_ЗНАЧЕН NIC 없음 |
| -22 | порт_ЗНАЧЕН/минутку_ЗНАЧЕН значение_времени/аргументы ЗНАЧЕН ошибка |
| -24 | 열린 сеть_порт 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | данные 또는 получить_ЗНАЧЕН МАССИВ_ЗНАЧЕН Размер 문제 |
| -98 | локальный_Scope порт_ЗНАЧЕН ИНДЕКС 중복 |
| -101 | 지원하지 않는 цель_ЗНАЧЕН АДРЕС |
| -110 | ARP·устройство_ЗНАЧЕН·получить_ЗНАЧЕН значение_времени 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 кодирование_ЗНАЧЕН 있는 Java `int`의 бит_ЗНАЧЕН 패턴을 사용하므로 상위 비트가 1인 ИТ_службы_обычный IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## 실행 경계와 시스템 호출

```text
оболочка run → JKAP에서 ELF проверить·적재 → ring 3 пространство_пользователя программа_f5044b9b
                                 ↓ int 0x80
                      указатель 검사 → Java ядро_ЗНАЧЕН API → RTL8139/UDP
                                 ↓ Выход_программа·исключение·значение_времени 초과
                                оболочка 복귀
```

시스템 호출 레지스터는 `EAX=ИНДЕКС`, `EBX,ECX,EDX,ESI,EDI=аргументы`, `EAX=результат`다. Java 호출 операнд_стек ABI는 컴파일러가 пространство_пользователя 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| ИНДЕКС | 호출 |
| --- | --- |
| 0 | Выход_программа(Состояние_ЗНАЧЕН кодовое_значение) — запустить/ошибка 런타임에서 использовать_ЗНАЧЕН |
| 1 | строка_ЗНАЧЕН Запись |
| 2 / 3 | аргументы товар_СЧЁТ / аргументы строка_ЗНАЧЕН АДРЕС |
| 10 | UDP Открыть |
| 11 | UDP написать(маркер_ЗНАЧЕН, IP, цель_ЗНАЧЕН порт_ЗНАЧЕН, МАССИВ_ЗНАЧЕН АДРЕС, длина_ЗНАЧЕН) |
| 12 | UDP получить(маркер_ЗНАЧЕН, МАССИВ_ЗНАЧЕН АДРЕС, 제한 밀리초) |
| 13 | UDP Закрыть |
| 14 | локальный_Scope IP АДРЕС |
| 15 / 16 | 마지막 одноранговый_ЗНАЧЕН IP / UDP порт_ЗНАЧЕН |
| 20 | RAM файл Чтение(Название int[] АДРЕС, текстовыйВывод int[] АДРЕС) |
| 21 | RAM файл Запись(Название int[] АДРЕС, входные_данные_ЗНАЧЕН int[] АДРЕС, байт_ЗНАЧЕН длина_ЗНАЧЕН) |
| 22 | UTF-16 кодовое_значение урок_ЗНАЧЕН 문자 текстовыйВывод(0~65535) |

файл API는 `пространство_пользователя.чтение_файл(int[] Название, int[] данные)`와 `пространство_пользователя.запись_файл(int[] Название, int[] данные, int длина_ЗНАЧЕН)`다. 이름은 ASCII кодовое_значение МАССИВ_ЗНАЧЕН(최대 64칸, 0 Выход_программа 또는 МАССИВ_ЗНАЧЕН 끝), данные товар_элемент 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 файл 없음 `-2`, указатель ошибка `-14`, Название/длина_ЗНАЧЕН ошибка `-22`, файл слот_ЗНАЧЕН 부족 `-28`, Размер 초과 `-90`을 반환한다. 쓰기는 проверить 후 файл 전체를 대체한다. `пространство_пользователя.запись_знак_ЗНАЧЕН(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`выполнение_Полномочие()`은 시스템 호출이 아니라 пространство_пользователя 모드에서 CS의 하위 비트를 직접 읽으므로 фактический_данные 실행 권한을 확인한다. ядро_ЗНАЧЕН аппаратный_порт 접근용 `устройство_ЗНАЧЕН` native 함수는 пространство_пользователя целевое_значение 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 실행, 파이프, 프로세스 간 통신은 없다. 실행 파일은 커널의 Чтение 전용 JKAP 묶음에서 적재한다. данные 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- пространство_пользователя 가상 АДРЕС `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. 실행 영상은 лицевая_камера_ЗНАЧЕН 2MiB, 인수는 `0x04300000`부터, 스택은 регион_ЗНАЧЕН 끝에서 시작한다. ядро_ЗНАЧЕН identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB пространство_пользователя 영역을 비우고 файл 구역을 복사해 BSS·МАССИВ_ЗНАЧЕН 영역을 초기화한다. пространство_пользователя GC는 없지만 Выход_программа 후 Далее_товар 실행 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 Цитата/이스케이프 파싱은 없다.
- пространство_пользователя 페이지의 кодовое_значение/данные 분리 Чтение 전용 Настройки, NX, операнд_стек guard, ASLR은 아직 없다. 커널과 пространство_пользователя Память_данные·аппаратный_порт Полномочие_ЗНАЧЕН 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 실행 상한을 두며 значение_времени 초과는 `Exit: 124`다. пространство_пользователя CPU 예외는 `128 + исключение ИНДЕКС`(페이지 ошибка 142, 특권 위반 141), Java МАССИВ_ЗНАЧЕН/계산 오류는 101~105다. ядро_ЗНАЧЕН 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, статический_ЗНАЧЕН IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP контрольная_сумма 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- пространство_пользователя 실행·네트워크·защитить_ЗНАЧЕН граница_ЗНАЧЕН 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 실행·ИТ_службы_обычный 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## проверить 근거

`make test`는 компилятор 14개 испытания, Java 패킷 условие 2,201개 검사, 기존 оболочка ELF/ISO запуск_машины испытания, пространство_пользователя ELF/фактический_данные UDP/защитить_ЗНАЧЕН граница_ЗНАЧЕН 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 длина_ЗНАЧЕН·해시까지 `os/build/тест_пользователь_сеть.json`에 기록한다. 시험용 손상된 ELF·특권 команда·무한 спринт_ЗНАЧЕН 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
