`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 aktuell_Daten JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. Host erstellen_Quell 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java App_f5044b9b 실행은 아직 지원하지 않는다.

## 직접 작성

`edit`는 Fichier 전체를 새 내용으로 작성한다. 기존 내용의 Zeil Editéieren_VALUE 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 Byte_VALUE 수 Show_VALUE.
- `cat FILE`: Fichier Inhalt_VALUE Show_VALUE. 텍스트 소스에 사용한다.
- `rm FILE`: Späicher_Daten Fichier 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·TYPE_VALUE 검사 Feeler_VALUE 시 기존 `.class`는 유지된다. 소스를 고친 Zeréck_VALUE 컴파일이 실패했다면 이전 ausféieren_Befeel 파일이 남아 있으므로 erstellen_Quell 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 Store_VALUE 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 Quell_Bamstruktur·Klass_VALUE·Daten 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, Fichier 이름은 ASCII 1~63자다. Quell_Bamstruktur 이름은 `.class` 확장자 공간 때문에 최대 62자다. Editéieren_VALUE 입력은 ASCII이고 한 Zeil 최대 128자다. Zeil 또는 Fichier 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. Kernel_VALUE/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 Benotzer 예제 이름은 ASCII로 작성한다.

## 외부 Fichier 적재

호스트에서 만든 소스나 Support_VALUE Clip 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 aktuell_Daten 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# Host JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 Weider_Element 빌드에서는 추가 파일을 포함하지 않는다. Fichier Inhalt_VALUE 변경과 Agab_Lëscht 제거도 Weider_Element 빌드에 반영된다. 원본 Host 파일에는 쓰지 않는다. Standardwäert `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 Standardwäert 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 Klass_VALUE Fichier 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 Support_VALUE Clip 안에 있어야 한다.

## Java Fichier I_O

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 Klass_VALUE 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 Zeréck_VALUE `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다.
