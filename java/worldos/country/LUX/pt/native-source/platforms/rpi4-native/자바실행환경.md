# nativo ARM64 JVM 0.4와 Português biblioteca

Português comunicação·exceção 사용법은 [Português Java API](한국어자바/LEIAME_eb81d7d9.md), FUNÇÃO_VALOR·variável_VALOR·ficheiro 이름의 변경과 어원 근거는 [명명 LEIAME_eb81d7d9](명명/LEIAME_eb81d7d9.md)를 참고한다.

JAR Executar_comando, externo_VALOR IPv4 TCP/UDP, 별도 estático_VALOR 부분집합 `jaot`와 게스트 C 컴파일은 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)에 설명한다. 아래 objeto_VALOR·Thread·Swing은 JVM 경로의 기능이며 AOT Suporte_VALOR 범위와 같지 않다.

이 구현은 **Linux 없이 부팅한 Java AOT 커널의 EL0에서 Executar_comando**한다. JDK/JRE의 거의 모든 기능을 제공하는 단계는 아직 아니다. HotSpot·OpenJDK aula_VALOR biblioteca 전체를 이식하거나 Java SE 인증/TCK를 통과한 구현도 아니다. 이번 확장은 단일 aula_VALOR·estático_VALOR método_VALOR 중심이던 실행기를 objeto_VALOR·biblioteca Executar_comando 기반으로 넓힌 것이다.

## 실행과 compilar_fonte

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
# nativo kernel_VALOR 안에서 fonte_árvore compilar_fonte → class Executar_comando, Português API 호출
python3 ferramentas/Executar_Arquivo.py testes/자바/한글소스.java

# objeto_VALOR·exceção 등은 host JDK로 Java 8 class를 만든 후 nativo 커널에서 Executar_comando
mkdir -p build/my-java
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/my-java testes/자바/한글시험.java
python3 ferramentas/Executar_Arquivo.py build/my-java/한글시험.class

# 의존 class 파일은 --include로 함께 Transferir_VALOR
javac --release 8 -encoding UTF-8 -d build/my-java testes/자바/객체시험.java
python3 ferramentas/Executar_Arquivo.py build/my-java/객체시험.class \
  --include build/my-java/Tela_de_fundo_VALOR.class --include build/my-java/branch_VALOR.class \
  --include build/my-java/계산가능.class

make test-jvm
```

`--include DIR`는 그 디렉터리의 class 파일을 재귀적으로 읽어 `패키지.aula_VALOR.class`라는 RAM ficheiro 이름으로 전송한다. 주 클래스도 패키지가 있다면 `--class-name 패키지.aula_VALOR`를 지정한다. 셸에서는 해당 이름으로 업로드하고 `java 패키지.aula_VALOR`로 실행한다. JVM 0.4는 Main-Class가 있는 16 KiB 이하 JAR도 `java -jar ficheiro.jar`로 실행한다. JAR 모드에서는 JAR 내부 클래스와 내장 Português 클래스만 찾는다. distribuição_VALOR Português biblioteca JAR는 host javac의 classpath로 사용하며, 같은 클래스가 espaço_do_utilizador JVM ELF에도 Leitura 전용 자료로 포함된다. 일반 class 모드에서는 사용자가 같은 이름으로 올린 RAM class를 먼저 읽는다.

게스트 `javac`는 여전히 estático_VALOR método_VALOR, int/boolean/char/String, doença·sprint_VALOR, cadeia_VALOR 결합, 일부 ficheiro 스트림 등의 **nativo 부분집합 compilador**다. objeto_VALOR declaração·상속·try/catch·Thread uso_VALOR 소스를 게스트 javac가 모두 컴파일하는 것은 아니다. 위 기능은 `javac --release 8`로 만든 class를 nativo JVM에서 실행한다. Português API 중 saídaTexto·문자 스칼라 FUNÇÃO_VALOR·ficheiro Leitura/쓰기는 게스트 컴파일러에도 연결했다. 다음처럼 전체 이름으로 호출한다.

```java
public class saudação_ae353e94 {
    public static void main(String[] argumentos) throws Exception {
        Português.nativo.saídaTexto.gravar_linha("안녕하세요😀");
        Português.nativo.saídaTexto.gravar_número(Português.nativo.문자.ponto_de_código_CONT_NÚM("한글😀"));
        Português.nativo.ficheiro.Escrita("saudação_ae353e94.txt", "한글 ficheiro😀");
        Português.nativo.saídaTexto.gravar_linha(Português.nativo.ficheiro.Leitura("saudação_ae353e94.txt"));
    }
}
```

## Português API

독립 패키지 **`Português.nativo`**를 사용한다. Linux판 `Português.자바`가 요구하는 NIO/Swing/HTTP API를 nativo 커널에서 실행할 número 있다고 혼동하지 않도록 패키지를 나눴다. 이 라이브러리는 aula_VALOR Nome·método_VALOR·argumentos·valor_do_campo·ficheiro 이름에 한국어를 사용한다. 표준 Java aula_VALOR 이름은 호환성을 위해 보존한다.

| aula_VALOR | 공개 기능 | 이름의 의미 |
|---|---|---|
| saídaTexto | Escrita, gravar_linha, gravar_número | saídaTexto(出力): 내용을 바깥으로 내보냄 |
| 문자 | duração_VALOR, 같음, colar_SMS, cortar_VALOR, analisar_inteiro/gravar_inteiro_VALOR, ponto_de_código_CONT_NÚM, codificar/descriptografar_dados | 문자(文字), Codificação_VALOR(符號): 글의 단위와 그 값을 바이트로 나타내는 regra_VALOR |
| ficheiro | Leitura/Escrita(String Nome), leitura_byte_VALOR/gravar_byte_VALOR | 널리 쓰는 espaço_do_utilizador 용어를 보존; RAM 자료의 Nome |
| entrada_Lista_f07b3200 | 더하기, Leitura, MUDAR_VALOR, apagar_entrada, Tamanho, TI_vazio_VALOR, limpar_Sumário | entrada_Lista_f07b3200(目錄): 순서가 있는 entrada_VALOR_962f286b 모음 |

| 작업 | iniciar(실행할일), 기다리기(tarefaSegundoPlano), LUCRO_Tarefa, 살아있는가 | 작업 thread_VALOR: 한 app_f5044b9b 안의 Executar_comando fluxo_VALOR |

## Executar_comando 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(Português aula_VALOR declarações), class당 16 KiB·constante_VALOR 풀 511항목, 전체 método_VALOR/valor_do_campo 각각 512개. método_VALOR valor_do_código 8 KiB, local_Scope variável_VALOR·피연산자 operando_pilha 각각 128슬롯, argumentos 최대 16개(this declarações).
- VM 가닥은 main declarações **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 Executar_comando 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- objeto_VALOR 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 real_dados 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 ficheiro·대형 cadeia_VALOR·객체가 이 제한을 넘을 número 있다.
- 실행은 50만 바이트코드 comando 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 entrada_VALOR 대기는 기한을 갱신하고 Janela mudar_MODO 시 중단·재개한다. 일반 servidor_VALOR·계산의 무제한 실행은 아직 없다. 미지원 comando·recurso_VALOR 부족은 명시적인 오류로 종료한다.
- RAM ficheiro 최대 64개, 파일당 16384바이트, caminho UTF-8 63바이트. RAM 디렉터리와 par_VALOR/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 Português class는 RAM ficheiro 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 em_dia_item 경로에서 fonte_árvore·aula_VALOR·dados 파일을 읽는다.
- UDP는 Java 루프백 및 lwIP/SLIP를 통한 externo_VALOR IPv4를 제공한다. real_dados GENET/Wi-Fi/DNS/TLS/HTTP 전체는 없다. datagrama 512바이트, soquete_VALOR 8개, 소켓당 큐 4개. receive는 VM 가닥을 양보하며 대기하고 setSoTimeout을 적용하지만 전체 Executar_comando 기한은 여전히 적용된다.
- long/float/double, invokedynamic/람다, enum/annotation, 다차원 MATRIZ_VALOR, 완전한 MATRIZ_VALOR 공변성·인터페이스 camada_VALOR 검사, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/Criptografar_dados/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. Swing의 별도 Suporte_VALOR 부분집합은 아래 및 개발 매뉴얼을 참고한다. aula_VALOR ficheiro 전체 검증기·acesso_entrada Permissão_VALOR/보호된 멤버 검사는 아직 완전하지 않다. 손상된 입력은 EL0 proteger_VALOR limite_VALOR 내에서 종료되도록 한다.

전체 OpenJDK를 목표로 하려면 다음은 별도의 주요 implementação 단계다: 완전한 JVM VALOR/validar/aula_VALOR 로더와 exceção 모델 → 영속 VFS·mmap·Relógio·원자 cirurgia_VALOR·real_dados 스레드/sincronizar ABI → OpenJDK java.base 및 native biblioteca 이식 → celular_VALOR 네트워크·TCP/IP → Janela 시스템/fonte_VALOR/입력기·java.desktop → Java SE 호환성 testes. em_dia_item nativo JVM의 일부 메서드를 더하는 것으로 이 작업이 완료되지는 않는다.

## JVM 0.3: 네트워크와 GUI extensão_VALOR

`Socket`/`ServerSocket` gerar·Ligar·accept·양방향 InputStream/OutputStream·close·EOF·valor_temporal 제한과 UTF-8 `String.getBytes`를 추가했다. JVM 0.4에서는 externo_VALOR dígito_VALOR IPv4 TCP도 lwIP/SLIP에 연결했다. 연결형 encerrar_ponto 16개, Java 루프백 버퍼 1024바이트, externo_VALOR TCP 버퍼 4096바이트다. DNS·TLS는 없다.

`JFrame`, `JPanel`, `JLabel`, `JButton`, `JTextField`, `ActionListener`, `ActionEvent`, `SwingUtilities.invokeLater`의 문서화한 부분집합을 네이티브 GUI에 연결했다. `setLayout(null)`과 명시적 좌표를 사용한다. 전체 OpenJDK Swing 또는 Java SE 호환 구현은 아니다. interativo 이벤트 대기는 Executar_comando 기한을 갱신하고 terminal mudar_MODO 시 프로세스 상태를 Store_VALOR·복원한다. 이벤트 콜백 자체는 기존 바이트코드/CPU 기한을 따른다.

Português `Janela`, `elemento_de_ecrã`, `conexão_transporte` 클래스를 distribuição_VALOR JAR와 nativo JVM 내장 자원에 추가했다. 상세 método_VALOR·제한·fonte_árvore·업로드 방법: [한글 개발 매뉴얼](개발안내.md).

## Português 객체의 직접 Executar_comando

`Janela`, `Etiqueta`, `campo_de_texto`, `botão`, `Evento_Fila`, `Ação_aviso`, `tarefaSegundoPlano`은
표준 GUI/Thread 객체를 보관하는 래퍼가 아니다. nativo JVM의 objeto_VALOR gerar,
formato_VALOR 검사, tela 호출, Evento 큐, thread_VALOR 스케줄러에 Português 계약을 직접 구현했다.
표준 `javax.swing`·`Thread` 코드의 Executar_comando 경로도 유지한다.
Português 단추와 표준 JButton은 서로 다른 형식이며, 해당 instanceof 검사도 검증한다.

nativo 실행기의 Português 진입점은 `public static void iniciar()`이다.
표준 `main(String[])`도 지원하며 둘 다 있으면 Português 진입점을 우선한다.
명령행 인수는 `실행인수.item_CONT_NÚM()`와 `실행인수.texto(순번)`으로 읽는다.
`example/java`의 다섯 예제는 이 규약을 사용한다. estático_VALOR ficheiro 예제는 게스트
javac로도 컴파일하며, GUI/thread_VALOR 소스는 host `javac --release 8`을 사용한다.
직접 GUI/thread_VALOR API는 nativo JVM 전용이다. 기존 OpenJDK 비교 시험과 별도로

## terminal 부분 renovar

mover_VALOR·Tamanho 변경은 새 Janela 영역과 Anterior_item 자리에서 드러난 띠만 합성한다.
1920×32 pixel(240 KiB)의 임시 그림에서 배경·겹친 Janela·caractere_VALOR·GUI를 먼저
완성하고, em_dia_item mostrar_VALOR 메모리와 비교하여 달라진 화소만 기록한다.
32줄보다 큰 영역은 여러 띠로 처리하므로 전체 프레임을 원자적으로
교체하거나 수직 동기에 맞추는 방식은 아니다. 전체 배경을 먼저 지우는
중간 화면은 표시하지 않는다. 좌표가 같으면 repetir_VALOR 그리지 않는다.

`make test-redraw`는 real_dados C Paint_tela 코드를 호스트의 Memória_dados 화면에 연결해
mover_VALOR 80회·Tamanho alterar_VALOR 40회·겹친 Janela 4개를 전체 합성 결과와 pixel 단위로 대조한다.
região_VALOR 밖 espaço_do_utilizador desenho_VALOR, 동일 pixel 무기록, ponteiro 밑그림, real_dados tela linha_de_entrada 간격을
검사한다. 이 시험의 시간은 host CPU 측정이며 Pi 4/QEMU 속도로 해석하지 않는다.
`make test-resize`는 QEMU/VNC의 640×480 및 1920×1080에서 왼쪽 모서리 arrastar_VALOR,
한글 entrada_VALOR·vi 미저장 Conteúdo_VALOR·독립 Janela 크기를 검사한다.
