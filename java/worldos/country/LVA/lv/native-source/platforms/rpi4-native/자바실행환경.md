# savs ARM64 JVM 0.4와 Latviešu bibliotēka

Latviešu 통신·izņēmums 사용법은 [Latviešu Java API](한국어자바/fails_Lasi_mani_eb81d7d9.md), FUNCTION_VALUE·mainīgais_VALUE·Fails 이름의 변경과 어원 근거는 [명명 fails_Lasi_mani_eb81d7d9](명명/fails_Lasi_mani_eb81d7d9.md)를 참고한다.

JAR Izpildīt_komanda, ārējs_VALUE IPv4 TCP/UDP, 별도 정적 부분집합 `jaot`와 게스트 C 컴파일은 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)에 설명한다. 아래 objekts_VALUE·Thread·Swing은 JVM 경로의 기능이며 AOT Atbalsts_VALUE 범위와 같지 않다.

이 구현은 **Linux 없이 부팅한 Java AOT 커널의 EL0에서 Izpildīt_komanda**한다. JDK/JRE의 거의 모든 기능을 제공하는 단계는 아직 아니다. HotSpot·OpenJDK klase_VALUE bibliotēka 전체를 이식하거나 Java SE 인증/TCK를 통과한 구현도 아니다. 이번 확장은 단일 klase_VALUE·정적 metode_VALUE 중심이던 실행기를 objekts_VALUE·bibliotēka Izpildīt_komanda 기반으로 넓힌 것이다.

## Izpildīt_komanda 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(Latviešu klase_VALUE 포함), class당 16 KiB·konstante_VALUE 풀 511항목, 전체 metode_VALUE/lauka_vērtība 각각 512개. metode_VALUE CODE_VALUE 8 KiB, vietējs_Tvērums mainīgais_VALUE·피연산자 operands_kopa 각각 128슬롯, Parametri 최대 16개(this 포함).
- VM 가닥은 main 포함 **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 Izpildīt_komanda 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- objekts_VALUE 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 faktisks_dati 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 Fails·대형 virkne_VALUE·객체가 이 제한을 넘을 numurs 있다.
- 실행은 50만 바이트코드 Komanda 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 입력 대기는 기한을 갱신하고 Logs SWITCH_MODE 시 중단·재개한다. 일반 serveris_VALUE·계산의 무제한 실행은 아직 없다. 미지원 Komanda·resurss_VALUE 부족은 명시적인 오류로 종료한다.
- RAM Fails 최대 64개, 파일당 16384바이트, CEĻŠ UTF-8 63바이트. RAM 디렉터리와 vienranga_VALUE/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 Latviešu class는 RAM Fails 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 pašreizējais_krājums 경로에서 avots_koks·klase_VALUE·dati 파일을 읽는다.
- UDP는 Java 루프백 및 lwIP/SLIP를 통한 ārējs_VALUE IPv4를 제공한다. faktisks_dati GENET/Wi-Fi/DNS/TLS/HTTP 전체는 없다. datogramma 512바이트, 소켓 8개, 소켓당 큐 4개. receive는 VM 가닥을 양보하며 대기하고 setSoTimeout을 적용하지만 전체 Izpildīt_komanda 기한은 여전히 적용된다.
- long/float/double, invokedynamic/람다, enum/annotation, 다차원 ARRAY_VALUE, 완전한 ARRAY_VALUE 공변성·인터페이스 slānis_VALUE 검사, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/Šifrēt_dati/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. Swing의 별도 Atbalsts_VALUE 부분집합은 아래 및 개발 매뉴얼을 참고한다. klase_VALUE Fails 전체 검증기·piekļūt_ievade atļauja_VALUE/보호된 멤버 검사는 아직 완전하지 않다. 손상된 입력은 EL0 aizsargāt_VALUE 경계 내에서 종료되도록 한다.

전체 OpenJDK를 목표로 하려면 다음은 별도의 주요 구현 단계다: 완전한 JVM VALUE/validēt/klase_VALUE 로더와 izņēmums 모델 → 영속 VFS·mmap·Pulkstenis·원자 operācija_VALUE·faktisks_dati 스레드/sinhronizēt ABI → OpenJDK java.base 및 native bibliotēka 이식 → ierīce_VALUE 네트워크·TCP/IP → Logs 시스템/fonts_VALUE/입력기·java.desktop → Java SE 호환성 시험. pašreizējais_krājums savs JVM의 일부 메서드를 더하는 것으로 이 작업이 완료되지는 않는다.

## JVM 0.3: 네트워크와 GUI paplašinājums_VALUE

`Socket`/`ServerSocket` ģenerēt·Savienoties·accept·양방향 InputStream/OutputStream·close·EOF·TIME_VALUE 제한과 UTF-8 `String.getBytes`를 추가했다. JVM 0.4에서는 ārējs_VALUE cipars_VALUE IPv4 TCP도 lwIP/SLIP에 연결했다. 연결형 beigt_zvanu_p 16개, Java 루프백 버퍼 1024바이트, ārējs_VALUE TCP 버퍼 4096바이트다. DNS·TLS는 없다.

`JFrame`, `JPanel`, `JLabel`, `JButton`, `JTextField`, `ActionListener`, `ActionEvent`, `SwingUtilities.invokeLater`의 문서화한 부분집합을 네이티브 GUI에 연결했다. `setLayout(null)`과 명시적 좌표를 사용한다. 전체 OpenJDK Swing 또는 Java SE 호환 구현은 아니다. 대화형 이벤트 대기는 Izpildīt_komanda 기한을 갱신하고 Terminālis SWITCH_MODE 시 프로세스 상태를 Store_VALUE·복원한다. 이벤트 콜백 자체는 기존 바이트코드/CPU 기한을 따른다.

Latviešu `Logs`, `logrīks`, `paziņa_transportēšana` 클래스를 sadale_VALUE JAR와 savs JVM 내장 자원에 추가했다. 상세 metode_VALUE·제한·avots_koks·업로드 방법: [한글 개발 매뉴얼](개발안내.md).

## Latviešu 객체의 직접 Izpildīt_komanda

`Logs`, `Etiķete`, `teksta_lauks`, `Pogas`, `notikums_rinda`, `darbība_informēšana`, `nodarbinātais`은
표준 GUI/Thread 객체를 보관하는 래퍼가 아니다. savs JVM의 objekts_VALUE ģenerēt,
formāts_VALUE 검사, 화면 호출, Notikums 큐, saruna_VALUE 스케줄러에 Latviešu 계약을 직접 구현했다.
표준 `javax.swing`·`Thread` 코드의 Izpildīt_komanda 경로도 유지한다.
Latviešu 단추와 표준 JButton은 서로 다른 형식이며, 해당 instanceof 검사도 검증한다.

savs 실행기의 Latviešu 진입점은 `public static void Palaist()`이다.
