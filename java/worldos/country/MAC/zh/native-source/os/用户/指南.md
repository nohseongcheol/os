# 셸에서 실행하는 用户 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 开发 环境 指南](../../文档集/Java开发环境.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 执行命令

宿主 终端 1:

```sh
cd /home/user/jkoros
python3 os/工具集/数据恢复.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 外部值 연결을 받도록 방화벽이나 硬件端口 전달을 변경하지 않는다. Ctrl+C로 종료한다.

宿主 终端 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 输入值:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 实际数据 CPU 权限值 `ring 3`, 实参 输出.
- `netcheck`: 端口值 중복, 잘못된 句柄值/指针/长度, 비차단 받기와 时间值 초과 验证.
- `udp`: IPv4 地址·目的地址值 端口值·한 机器字值 메시지를 받아 UDP로 보내고 같은 응답을 验证. `UDP ECHO PASS`, `Exit: 0`이면 成功值.
- `stress`: 宿主 `10.0.2.2`의 赋值值 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 接收值 循环值 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 当前项目 주소는 게스트 `10.0.2.15/24`, 网关值 `10.0.2.2`로 고정돼 있다. QEMU 用户 네트워크의 宿主 存取条目 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 程序 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java 程序 追加条目

`用例/내프로그램.java`를 下一项目 형식으로 만든다. 진입점은 实参 없는 `static int` 또는 `static void` 함수다. 인수는 用户 API로 조회한다.

```java
public final class 내프로그램 {
    public static int 运行() {
        用户.写入("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/用户/程序.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := 用户/用例/내프로그램.java
APP_ENTRY_mine := 내프로그램.运行
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 构建全部 나열한다. `用户/声明/用户.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 执行命令 중인 VM에는 构建系统 결과가 자동 반영되지 않는다. 程序 이름은 当前项目 셸의 ASCII 输入值 제한에 맞춘 1~15자의 소문자 이름이며 Java 类值·函数·변수에는 한국어를 쓴다. 最大值 32개 程序, 한 执行命令 파일은 最大值 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/编译器.py --target user --entry 问候例.运行 \
    -o os/build/apps/hello.elf os/用户/声明/用户.java os/用户/用例/问候例.java
```

`--target user`는 **jkoros 전용 ABI**第三操作数. Linux 대상과 시스템 调用 번호가 다르므로 宿主 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 支持值 裁剪 안에서 실행한다. `.jar`와 일반 Linux 执行命令 파일은 지원하지 않는다.

## 用户 네트워크 API

선언은 `声明/用户.java`에 있다. `发送数据`/`接收数据`의 `int[]` 项目元素 한 개는 字节值 一值(0~255)를 나타낸다. 한 데이터그램의 最大值 数据 길이는 1,024바이트다.

```java
int 句柄值 = 用户.打开网络(0); // 0: 临时值 局部作用域 UDP 端口值 자동 选中状态值
int[] 数据 = new int[32];
数据[0] = 'H'; 数据[1] = 'i';
int 보낸길이 = 用户.发送数据(句柄值, 0x0a000202, 9000, 数据, 2);
int 已接收长度 = 用户.接收数据(句柄值, 数据, 1500);
用户.关闭网络(句柄值);
```

实际数据 프로그램에서는 打开·发送·받기의 负数值 반환값을 각각 검사한다. 완성된 예제는 `用例/数据通信.java`에 있다. `接收数据`의 等待状态值 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 接收值 대기열은 한 개뿐이므로 追加条目 도착분은 버린다. `已发送地址`와 `已发送端口`로 마지막으로 받은 상대를 조회한다.

| 已返回值 | 의미 |
| --- | --- |
| 0 이상 | 句柄值·进程值条目 长度·成功值 등 해당 함수의 结果 |
| -5 | 设备 发送值 失败值 |
| -9 | 잘못되었거나 닫힌 通信 句柄值 |
| -11 | 비차단 받기에서 도착한 数据 缺失方法 |
| -14 | 用户 指针/数组值 裁剪 错误 |
| -19 | 支持值 NIC 缺失方法 |
| -22 | 端口值/等待状态值 时间值/实参 值 错误 |
| -24 | 열린 网络端口 4개 容量限制 |
| -38 | 알 数 없는 시스템 调用 |
| -90 | 数据 또는 接收值 数组值 大小 문제 |
| -98 | 局部作用域 端口值 编号 중복 |
| -101 | 지원하지 않는 目的地址值 地址 |
| -110 | ARP·设备·接收值 时间值 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 编码状态值 있는 Java `int`의 位值 패턴을 사용하므로 상위 비트가 1인 是否常规 IP 주소가 음수로 보일 数 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## 执行命令 경계와 시스템 调用

```text
命令壳 run → JKAP에서 ELF 有效性校验·적재 → ring 3 用户 程序
                                 ↓ int 0x80
                      指针 检查项 → Java 内核值 API → RTL8139/UDP
                                 ↓ 退出程序·异常·时间值 초과
                                命令壳 복귀
```

시스템 调用 레지스터는 `EAX=编号`, `EBX,ECX,EDX,ESI,EDI=实参`, `EAX=结果`第三操作数. Java 调用 操作数栈 ABI는 컴파일러가 用户 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| 编号 | 调用 |
| --- | --- |
| 0 | 退出程序(状态值 代码值) — 运行/错误 런타임에서 使用值 |
| 1 | 字符串 写入 |
| 2 / 3 | 实参 项目个数 / 实参 字符串 地址 |
| 10 | UDP 打开 |
| 11 | UDP 发送(句柄值, IP, 目的地址值 端口值, 数组值 地址, 长度) |
| 12 | UDP 接收(句柄值, 数组值 地址, 限制值 毫秒) |
| 13 | UDP 关闭 |
| 14 | 局部作用域 IP 地址 |
| 15 / 16 | 最后项目 对端值 IP / UDP 端口值 |
| 20 | RAM 文件 读取(名称 int[] 地址, 输出 int[] 地址) |
| 21 | RAM 文件 写入(名称 int[] 地址, 输入值 int[] 地址, 字节值 长度) |
| 22 | UTF-16 代码值 单位值 字符 输出(0~65535) |

文件 API는 `用户.读取文件(int[] 名称, int[] 数据)`와 `用户.写入文件(int[] 名称, int[] 数据, int 长度)`第三操作数. 이름은 ASCII 代码值 数组值(最大值 64칸, 0 退出程序 또는 数组值 结尾), 数据 项目元素 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 文件 缺失方法 `-2`, 指针 错误 `-14`, 名称/长度 错误 `-22`, 文件 槽值 부족 `-28`, 大小 초과 `-90`을 반환한다. 쓰기는 有效性校验 之后状态 文件 전체를 대체한다. `用户.写入字符值(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`执行状态权限()`은 시스템 호출이 아니라 用户 모드에서 CS의 하위 비트를 직접 읽으므로 实际数据 执行命令 권한을 확인한다. 内核值 硬件端口 접근용 `设备` native 함수는 用户 目标值 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 限制值

- 한 번에 한 프로그램만 실행하며 是否完成 之后状态 셸로 돌아온다. 백그라운드 执行命令, 파이프, 프로세스 간 통신은 없다. 执行命令 파일은 커널의 读取 전용 JKAP 묶음에서 적재한다. 数据 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- 用户 가상 地址 `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. 执行命令 영상은 前端值 2MiB, 인수는 `0x04300000`부터, 스택은 区域值 끝에서 시작한다. 内核值 identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB 用户 영역을 비우고 文件 구역을 복사해 BSS·数组值 영역을 초기화한다. 用户 GC는 없지만 退出程序 之后状态 下一项目 执行命令 때 영역을 재사용한다. 인수는 공백으로 분리한 最大值 16개이며 引号/이스케이프 파싱은 없다.
- 用户 페이지의 代码值/数据 분리 读取 전용 设置, NX, 操作数栈 guard, ASLR은 아직 없다. 커널과 用户 内存数据·硬件端口 权限值 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 执行命令 상한을 두며 时间值 초과는 `Exit: 124`第三操作数. 用户 CPU 예외는 `128 + 异常 编号`(페이지 错误 142, 특권 위반 141), Java 数组值/计算结果 오류는 101~105다. 内核值 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, 静态值 IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP 校验和 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- 用户 执行命令·네트워크·保护值 边界位置值 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 执行命令·是否常规 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## 有效性校验 근거

`make test`는 编译器 14개 测试, Java 패킷 条件 2,201개 检查项, 기존 命令壳 ELF/ISO 启动 测试, 用户 ELF/实际数据 UDP/保护值 边界位置值 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 长度·해시까지 `os/build/测试用户网络.json`에 기록한다. 시험용 손상된 ELF·특권 命令·무한 迭代值 프로그램은 临时值 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
