# 内置 ARM64 커널의 Codex 安装值 가능성 검토

검토일: 2026-10-05. 소스와 공식 문서를 대조한 설계 검토이며, 게스트에 Codex를 설치하거나
로그인·모델 호출을 실행한 결과는 아니다. 内置 ARM64 커널과 `../rpi4` Linux 실행판은 구분한다.

当前项目 内置 커널에는 공식 Codex CLI를 그대로 安装值·실행할 数 없다.
기술적으로 필요한 执行命令 환경을 추가하거나 Codex를 이식하는 경로는 있으나,
다운로드 命令 하나를 추가하는 작업으로 해결되지 않는다. JDK/JRE 기능 확장만으로도 해결되지 않는다.

## 확인한 근거

| 条目值 | 当前项目 소스에서 확인한 状态值 | 직접 실행을 위한 任务 |
|---|---|---|
| 执行命令 文件 | `计算机/用户.c`: AArch64 ET_EXEC만, PT_INTERP/PT_DYNAMIC/PT_TLS 拒绝值, 업로드 执行命令 버퍼 16384바이트 | 目标值 바이너리에 맞는 ELF 적재·재배치·执行命令 初始化, 内存数据/文件 限制值 扩展名值 |
| Linux ABI | `计算机/Linux兼容性.inc`: read/write/openat/brk 등 제한된 번호만 进程值条目, 나머지는 ENOSYS | libc/런타임에 필요한 시스템 호출을 추가하거나 内置 ABI용 런타임 移植 |
| 프로세스·스레드 | 일반 fork/clone/execve, pthread/futex, 시그널, mmap, poll/epoll 계열이 미완성 | 비동기 I/O·스레드·子值 命令 执行命令·退出程序/取消操作 기능 |
| 文件 | `源代码/内存文件集.java`: RAM 文件 64개, 파일당 16 KiB, 비영속 | 큰 执行命令 文件·프로젝트·设置·세션을 위한 영속 VFS, 文件 权限值·路径·디렉터리 扩展名值 |
| 네트워크 | lwIP TCP/UDP는 있으나 `通信网络/lwipopts.h`의 LWIP_DNS=0, 일반 HTTPS 클라이언트 缺失方法 | DNS, TLS 인증서 有效性校验·신뢰 代码库根·정확한 时间戳值, HTTPS/스트리밍 |
| 终端·工具集 | 内置 셸과 GUI 터미널은 있지만 표준 PTY·일반 프로세스 任务 控制值 缺失方法 | 交互式 CLI용 终端 기능, 命令壳/文件 검색/构建系统 工具集 连接 |
| 执行命令 权限值 | EL0 보호는 있으나 Codex의 Linux 샌드박스와 같은 정책 집행 环境 缺失方法 | 文件·네트워크·命令 权限值 정책과 승인 기능; 内置 커널에 맞는 격리 实现 |

여기서 ELF의 PT_TLS는 스레드별 存储值 공간이다. HTTPS의 TLS 密码值 통신과 서로 다른 기능이다.
ELF 文件 형식을 읽을 数 있다는 사실만으로 Linux 执行命令 환경을 제공하는 것은 아니다.
SSH/VNC를 위한 密码值 라이브러리를 넣은 상태도 HTTPS 实现 완료를 의미하지 않는다.

호스트의 `/home/user/.local/bin/codex`도 확인했다. 이것은 x86-64 ELF ET_DYN이며 약 209 MiB다.
해당 파일을 ARM64 게스트로 복사하여 실행할 数 없다. 이 크기를 ARM64 分发值 파일의 크기로
해석하지 않는다. 공식 ARM64 빌드의 实际数据 大小·의존성은 설치할 버전으로 追加条目 검사해야 한다.

## 가능한 实现 路径

1. **内置 커널에 공식 CLI 직접 移植**
   영속 存储值/VFS와 用户 内存数据, 프로세스·스레드·I/O, libc/런타임, DNS/HTTPS,
   终端·权限值 체계를 갖춘다. 之后值 目标值 버전의 의존성을 조사하여 크로스 构建系统·이식한다.
   Linux 커널을 반드시 탑재할 필요는 없지만, 공식 Linux 바이너리를 그대로 쓸 경우
   그 바이너리가 사용하는 Linux ABI까지 호환해야 한다. 큰 操作系统 开发 과제다.

2. **外部值 宿主 Codex와 内置 内核值 连接 — 首位项目 구현으로 권장**
   Linux PC에서 공식 CLI 또는 app-server를 실행하고 jkoros에는 전용 用户 命令/화면을 만든다.
   호스트의 인증된 연결과 게스트 文件 读取·修改值·업로드·命令 执行命令 어댑터가 필요하다.
   기존 SSH/TCP 경로를 활용할 数 있으나, 文件 동기화나 Codex 전용 어댑터는 当前项目 구현되어 있지 않다.
   호스트에서 수행한 빌드와 게스트에서 수행한 执行命令 결과를 명확히 구분한다.
   이 구성은 内置 커널을 유지하지만, 공식 CLI 자체는 外部值 호스트에서 실행된다.

3. **内置 API 클라이언트 제작**
   内置 ABI의 C 또는 지원되는 Java 부분집합으로 交互式会话 UI와 文件/命令 工具集 调用 루프를 만든다.
   外部值 중계기를 쓰지 않는다면 DNS/有效性校验 가능한 TLS/HTTPS와 인증 数据 저장을 먼저 구현해야 한다.
   이는 OpenAI API를 이용하는 별도 에이전트이며 공식 Codex CLI 전체의 이식으로 표시하지 않는다.

4. **별도 ARM64 Linux 실행판에서 安装值**
   `../rpi4`는 Linux와 musl 기반이므로 일반 Linux 安装值 경로를 검토할 数 있다.
   사용할 Codex 버전의 ARM64·musl 호환성, 依赖项列, 커널의 샌드박스 지원을 实际数据 검증해야 한다.
   이번 검토에서 安装值 성공을 확인하지 않았다. 이 결과를 内置 Java 커널의 지원으로 표시하지 않는다.

## 단계별 是否完成 项目根

- 직접 移植: `--version` 运行 → 인증/HTTPS → 文件 读取·修改值 → 子值 命令 执行命令 →
  交互式 输入值/스트리밍 → 权限值 限制值·取消操作 → 재부팅 之后状态 设置/세션 보존을 각각 实际数据 게스트에서 확인한다.
- 宿主 连接: 게스트에서 申请 输入值 → 宿主 Codex 进程值条目 → 게스트 文件 更改值 验证 →
  게스트 javac/cc 执行命令 → 结果 표시를 처음부터 끝까지 검증한다.
- COSL 상업 조건을 유지하려면 새로 도입하는 런타임/通信 라이브러리의 라이선스와
  Codex 分发值 버전의 제3자 고지를 검토한다. 外部值 구성요소를 일괄 COSL로 재라이선스하지 않는다.
