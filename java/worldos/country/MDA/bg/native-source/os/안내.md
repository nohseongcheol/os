# Java 네이티브 операционна_система

이 문서는 기존 **x86 ядро_стойност**을 설명한다. Raspberry Pi 4의 자체 ARM64 първоначално_състояние 이식은 [별도 안내](../platforms/rpi4-native/README.md)를 참고한다. 아래 x86 потребител ELF·네트워크·IDE хранилище_стойност 기능이 ARM64에 모두 이식된 상태는 아니다.

Java 원문을 자체 AOT 후단으로 x86 기계어로 컴파일해 부팅하는 작은 운영체제다. 커널과 별도로 자체 제한형 Java компилатор·JVM ELF를 потребител 모드에 적재할 수 있다. Linux, engos, koros4와 външен_стойност OpenJDK는 게스트에 적재하지 않는다. 부팅 진입과 포트/물리 Памет_област 접근은 어셈블리이며, 문자 단말·입력 Процес_стойност_запис·Команда анализирам_стойност·작업 раздел_стойност 관리는 `ИЗТОЧНИК/*.java`에 있다.

## 게스트 Java 개발

`javac Hello.java`, `java Hello`로 부팅된 операционна_система 안에서 компилирам_източник·실행한다. `edit FILE.java`와 `.save`로 소스를 작성하며 `ls`, `cat`, `rm`을 제공한다. RAM 파일은 최대 8개, 각각 16KiB이다. 전용 IDE 매체를 연결하면 `sync`로 보존할 수 있다. 이 기능은 자체 제한형 구현이며 전체 OpenJDK/JDK 호환은 아니다. 사용법·Поддръжка_стойност 문법·Файл 적재·교차 시험은 [Java 개발 환경](../문서/자바개발환경.md)에 있다. `make test-java`로 검증한다.

## 빌드와 изпълнявам_команда

`compiler/`가 요구하는 도구에 더해 ISO 생성에는 `grub-file`, `grub-mkrescue`, GRUB BIOS модул_стойност, `xorriso`가 필요하다. 실행에는 QEMU 또는 VirtualBox가 필요하다. в_срок_артикул 설치된 도구만 사용한다. `make run-store`는 새 전용 가상 хранилище_стойност 매체를 만들어 연결한다. VirtualBox 실행기는 이 프로젝트가 만든 전용 VM만 설정하고 다른 VM은 변경하지 않는다. 가상 메모리는 стойност_по_подразбиране 64MiB이며 최소 16MiB가 필요하다.

```sh
cd /home/user/jkoros/os
make                 # build/kernel.elf
make iso             # build/kernel.iso (потребител ELF Група_стойност 포함)
make run             # ELF 직접 부팅, 직렬 단말
make run-gui         # GRUB ISO 부팅, VGA 창과 PS/2 자판
make vbox            # 상위 폴더의 실행기로 전용 VirtualBox VM изпълнявам_команда
make vbox-status     # 전용 VirtualBox VM Състояние_стойност проверявам
make test            # ELF와 ISO 두 경로의 действителен_данни 부팅/입력 시험
make apps            # потребител 프로그램만 компилация_система
make test-network    # потребител изпълнявам_команда/UDP/защитавам_стойност 시험
```

`make run`은 QEMU의 직렬 표준 입출력을 쓴다. `Ctrl+A`를 누른 НАЗАД_стойност `X`로 QEMU를 종료할 수 있다. `halt`는 게스트 CPU만 정지시키므로 QEMU Прозорец/프로세스는 별도로 닫는다. 폴링 방식이라 почакай_стойност 중에도 хост CPU를 사용할 수 있다.

VirtualBox는 `make vbox`로 실행한다. 새 전용 VM을 Памет_данни 64MiB, BIOS, 광학 드라이브 부팅으로 자동 설정하며 디스크는 필요 없다. действителен_данни VirtualBox 5.2.42에서 부팅, Java 자체 시험, обвивка 입력, `run hello vbox`의 ring 3 실행과 정상 종료를 확인했다. в_срок_артикул 통신 드라이버는 QEMU의 RTL8139 전용이며 VirtualBox의 PCnet/E1000에서는 네트워크를 사용할 수 없어 네트워크 장치를 비활성화한다. хранилище_стойност Състояние_стойност 재개와 새 компилация_система 반영 방법은 [VirtualBox изпълнявам_команда 안내](../문서/가상상자실행.md)에 있다.

## 셸에서 потребител програма_f5044b9b изпълнявам_команда 및 네트워크 호출

독립 ELF32 изпълнявам_команда 파일을 적재해 **ring 3**에서 실행한다. `int 0x80` 시스템 호출을 통해 단말 Изход, Параметри заявка_стойност, UDP Отваряне·изпращам·получавам·닫기를 제공한다. потребител 코드를 ядро_стойност 함수로 직접 호출하는 구조가 아니다.

```text
jkoros> apps
jkoros> run hello first second
jkoros> net
jkoros> run netcheck
jkoros> run udp 10.0.2.2 9000 hello
```

마지막 명령의 응답을 받으려면 호스트의 별도 터미널에서 `python3 /home/user/jkoros/os/Инструменти/Ехо_данни.py --port 9000`을 먼저 실행한다. 상세 API, програма_f5044b9b добавям_запис, адрес 공간과 제한은 [потребител изпълнявам_команда·네트워크 안내](потребител/안내.md)에 있다.

부팅 проверявам 문구:

```text
JKOROS NATIVE JAVA
자바 기계어 ядро_стойност Стартиране
JAVA SELFTEST PASS
USER ELF: ring 3 / paging / int 0x80
help | info | mem | alloc | free N | echo TEXT | clear | test | halt
apps | run NAME [ARGS] | net
READY
jkoros>
```

## 구현한 기능

- GRUB Multiboot 1 ELF 부팅, x86 защитавам_стойност режим_стойност GDT, BSS 초기화, 64KiB операнд_стек.
- Java функция_стойност действителен_данни 실행과 부팅 Системна_информация маркер_стойност проверявам.
- COM1 직렬 В_И, VGA 문자 화면·курсор_стойност·스크롤·изтривам_запис.
- PS/2 стойност_по_подразбиране 자판, 좌우 Shift, Enter, Backspace. разширение_стойност Ключ_стойност/마우스 자료는 Команда 입력으로 쓰지 않는다.
- 길이 128의 Команда 입력 버퍼, Препълване_стойност 방지, CR/LF Процес_стойност_запис.
- `help`, `info`, `mem`, `alloc`, `free N`, `echo TEXT`, `clear`, `test`, `halt`.
- 4KiB 작업 раздел_стойност 8개의 заделям_Памет·връщам_мярка·재사용과 중복 връщам_мярка 방지.
- Java масив_стойност 256KiB 영역의 Размер·долен_индекс_стойност 검사와 런타임 ГРЕШКА 중단.
- Четене 전용 JKAP изпълнявам_команда Група_стойност, ELF32 раздел_стойност/запис_пункт проверка, потребител режим_стойност·Параметри·Изход_програма код_стойност.
- ядро_стойност/потребител 페이지 разрешение_стойност 분리, TSS, IDT, PIT 100Hz, потребител CPU изключение Процес_стойност_запис 및 изпълнявам_команда час_стойност 상한.
- PCI RTL8139 폴링 드라이버, ARP, 정적 IPv4, UDP контролна_сума·송수신·почакай_стойност 제한.

`mem`의 Upper memory는 Multiboot의 1MiB 위쪽 연속 Памет_данни Размер(KiB)이며, 전체 Памет_данни 지도 분석이나 자유 물리 Памет_данни 수치가 아니다. `alloc`은 이미 확보한 цяло_число масив_стойност 안의 작업 раздел_стойност 번호를 반환한다. 일반 물리 страница_стойност заделям_Памет, адрес адрес_област 또는 потребител Процес_стойност Памет_данни 관리가 아니다.

## 명시적인 한계

이 커널은 **потребител 프로그램을 한 번에 하나 실행하는 първоначално_състояние ядро_стойност**이다. PIT IRQ0만 사용하며 키보드와 NIC는 폴링한다. потребител CPU 예외는 해당 프로그램을 끝내고 셸로 복귀시키지만 ядро_стойност 예외는 중단한다. изпълнявам_команда 시간은 약 3초로 제한한다. 완전한 선점 다중 Процес_стойност 스케줄러, FAT/ext 등 일반 디스크 файлова_система, TCP·DNS·DHCP·IPv6·HTTP, 전체 POSIX, 일반 обект_стойност 모델/GC는 아직 없다. 전용 IDE Файл 보존과 POSIX Файл/UDP 일부 기능은 구현했다. JVM은 RAM 파일의 단일 클래스를 изпълнявам_команда 시 적재하며 일반 ClassLoader나 JAR 로딩은 지원하지 않는다. 네이티브 изпълнявам_команда 파일은 компилация_система 시 Четене 전용 묶음에 넣으며, 일반 Linux ELF를 실행하는 환경이 아니다. 기존 `../наследен_източник/`의 JVM 관리 ядро_стойност 전체를 이식한 것도 아니다.

Java 식별자는 한국어다. 직렬 출력은 이 프로젝트의 한글(BMP 문자)을 UTF-8로 표시한다. VGA는 стойност_по_подразбиране ASCII 글꼴만 사용하므로 한글 자리에 `?`가 나온다. Команда 입력도 в_срок_артикул ASCII만 지원하며 한글 шрифт_стойност·입력기 및 보조 평면 문자 출력은 후속 작업이다. `test`는 작은 배열을 새로 할당하고 GC가 없으므로 무한 반복하지 않는다.

## 자동 시험

`시험/부팅시험.py`는 디스크 없는 독립 QEMU를 생성해 다음을 검증하고 종료한다.

- ELF 직접 부팅 및 GRUB ISO 부팅.
- Java 자체 시험과 UTF-8 직렬 문구.
- Команда показвам_помощ·Системна_информация·Памет_данни·Изход·ГРЕШКА 입력·화면 изтривам_запис.
- 작업 раздел_стойност 8개 заделям_Памет, 부족 Процес_стойност_запис, връщам_мярка/중복 връщам_мярка/재할당.
- 직렬 줄바꿈·백스페이스·긴 입력 Процес_стойност_запис.
- QEMU PS/2 Ключ_стойност 입력으로 `info` изпълнявам_команда, `halt` 정지.

성공 로그는 `build/부팅시험.json`에 남는다. 로컬 Unix 소켓을 금지하는 샌드박스에서는 시험 도구에 해당 권한이 필요하다. 시험 도중 새로 만든 QEMU만 종료하며 기존 VM과 действителен_данни 디스크는 건드리지 않는다.

`시험/사용자통신시험.py`는 ELF/ISO 각각에서 потребител ELF, действителен_данни ring 3, Параметри, хост 루프백 UDP 왕복, 1,023/1,024바이트 24회 연속 왕복, час_стойност 초과, NIC 없음, Памет_данни/포트 достъп_запис 차단, CPU изключение, 무한 спринт_стойност, 잘못된 ELF를 시험한다. `build/사용자통신시험.json`에 게스트 기록과 호스트가 받은 데이터의 길이·해시를 저장한다. `시험/패킷시험.py`는 действителен_данни Java случай_стойност 처리기에 손상된 패킷을 넣어 2,201개 경계/контролна_сума 조건을 검사한다. хост 루프백 외 външен_стойност 서버에는 시험 트래픽을 보내지 않는다.

부트 경계는 GNU의 [Multiboot 명세](https://www.gnu.org/software/grub/manual/multiboot/multiboot.html)를 따른다.

새 파일서술자·C ABI·IDE хранилище_стойност·Java Файл 흐름의 범위와 Български 명명 대응은 [posix-kor 안내](../posix-kor/안내.md)에 있다. `make test-posix`로 ELF/ISO 실행과 재부팅 보존을 검증한다.
