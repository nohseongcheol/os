# jkoros 안에서 Java изгради_извор·Изврши_наредба

이 문서의 부팅·обвивка·Store_VALUE 명령은 **x86 верзија_VALUE** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 верзија_VALUE](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 датотека_име_СМС, `edit`의 단독 `.` Store_VALUE, 16개 RAM Датотека, 약 2초 Изврши_наредба 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 реален_податоци JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. вдоми изгради_извор 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java програма_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 Изврши_наредба

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. Изврши_наредба 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox Изврши_наредба информации_пред_употреба_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 Датотека 전체를 새 내용으로 작성한다. 기존 내용의 ред уреди_VALUE 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 бајт_VALUE 수 прикажи_VALUE.
- `cat FILE`: Датотека Содржина_VALUE прикажи_VALUE. 텍스트 소스에 사용한다.
- `rm FILE`: Меморија_податоци Датотека 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·TYPE_VALUE 검사 неуспех_VALUE 시 기존 `.class`는 유지된다. 소스를 고친 Назад_VALUE 컴파일이 실패했다면 이전 Изврши_наредба 파일이 남아 있으므로 изгради_извор 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 Store_VALUE 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 извор_дрво·класа_VALUE·податоци 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, Датотека 이름은 ASCII 1~63자다. извор_дрво 이름은 `.class` 확장자 공간 때문에 최대 62자다. уреди_VALUE 입력은 ASCII이고 한 ред 최대 128자다. ред 또는 Датотека 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. јадро_VALUE/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 корисник 예제 이름은 ASCII로 작성한다.

## 외부 Датотека 적재

호스트에서 만든 소스나 Поддршка_VALUE клип 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 реален_податоци 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# вдоми JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 Следно_ставка 빌드에서는 추가 파일을 포함하지 않는다. Датотека Содржина_VALUE 변경과 внес_Список 제거도 Следно_ставка 빌드에 반영된다. 원본 вдоми 파일에는 쓰지 않는다. стандардна_вредност `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 стандардна_вредност 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 класа_VALUE Датотека 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 Поддршка_VALUE клип 안에 있어야 한다.

## Поддршка_VALUE клип

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| класа_VALUE | 패키지 없는 단일 класа_VALUE, статичен_VALUE ФУНКЦИЈА_VALUE, 재귀, Аргументи/반환 | 실행마다 단일 класа_VALUE 적재, public static main(String[]) |
| стандардна_вредност VALUE | int, boolean, char, String, main의 String[] Аргументи | цел_број·Референци 스택, String, int[], String[], 내부 StringBuilder |
| изјава_VALUE | 초기값 있는 локален_обем декларација, задача_VALUE, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 цел_број·Референци 바이트코드와 услов гранка |
| израз_VALUE | 십진 цел_број, UTF-8 소스의 низа_VALUE_6ca8363c/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, низа_VALUE_6ca8363c 결합 | цел_број операција_VALUE·бит_VALUE операција_VALUE·TYPE_VALUE CONVERT_VALUE, 단락 평가, низа_VALUE пристап_внес |
| Датотека | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | реален_податоци јадро_VALUE 파일서술자와 Врзи_се, генерира·исчисти_Содржина·이어쓰기·EOF |
| 출력 | System.out.print/println: int/boolean/char/String, println() | 동일 |
| низа_VALUE_6ca8363c/Аргументи | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), низа_VALUE_6ca8363c 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 локален_обем декларација, 오버로드, 임의 TYPE_VALUE CONVERT_VALUE, низа_VALUE генерира ИЗВОР, 8/16진 리터럴, Unicode извор_дрво 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 константа_VALUE 축소 변환을 구현하지 않는다. 외부 `.class`의 `int[]` генерира/Читај/쓰기는 지원하므로 вдоми `javac --release 8`로 만든 низа_VALUE 예제는 실행할 수 있다.

објект_VALUE поле_VALUE·일반 објект_VALUE генерира·상속·인터페이스·여러 класа_VALUE Врзи_се, long/float/double, исклучок Процес_VALUE_внес, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java исклучок 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 низа_VALUE_6ca8363c Store_VALUE 공간은 Изврши_наредба Излез_програма 시 корисник 영역 전체와 함께 회수한다. 지속 Изврши_наредба 중 GC는 없다.

## Изврши_наредба 한도와 ГРЕШКА

| извор_VALUE | 한도 |
| --- | --- |
| извор_дрво/класа_VALUE Датотека | 각각 16KiB |
| 컴파일러 | токен_VALUE 2,047개, генерира CODE_VALUE 4KiB, константа_VALUE 풀 4KiB |
| ФУНКЦИЈА_VALUE/Аргументи | 클래스당 32함수, 함수당 16인수 |
| JVM константа_VALUE | 511개 |
| JVM ФУНКЦИЈА_VALUE CODE_VALUE | 함수당 8KiB |
| JVM 호출/스택/локален_обем 변수 | 32프레임, 프레임당 스택 128칸·локален_обем 128칸 |
| JVM објект_VALUE Store_VALUE 공간 | 8,192개 32비트 отвор_внес, 헤더 포함 약 32KiB |
| Изврши_наредба | 최대 500,000 Команда, 기존 커널의 약 3초 CPU Изврши_наредба 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 Поддршка_VALUE 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM речник 검증기를 구현한 것은 아니다. Датотека/атрибут_VALUE должина_VALUE, константа_VALUE Референци, Команда·гранка 경계를 검사하고, Изврши_наредба 중 스택 формат_VALUE·локален_обем иницијализирај·низа_VALUE индекс_VALUE·објект_VALUE 참조를 검사한다. корисник 코드의 페이지·포트 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, изгради_извор·JVM 오류는 `Exit: 1`, Команда Аргументи 오류는 `Exit: 2`다. CPU TIME_VALUE 상한은 기존 `Exit: 124`이며, корисник ELF 자체의 CPU/런타임 오류는 기존 Излез_програма 코드를 따른다. неуспех_VALUE 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## 구현 위치와 시험

- `os/корисник/자바/자바컴파일러.java`: 게스트 어휘·구문·TYPE_VALUE 검사, константа_VALUE 풀 및 바이트코드 генерира.
- `os/корисник/자바/자바가상기계.java`: класа_VALUE 적재, 스택·프레임·објект_VALUE Store_VALUE, Команда 해석과 제한된 표준 호출.
- `os/ИЗВОР/Меморија_систем_на_датотеки.java`: Меморија_податоци систем_на_датотеки, уреди_VALUE, 부팅 Датотека 적재.
- `os/ИЗВОР/체계호출.java`, `compiler/Start_корисник_програма.s`: Датотека/문자 출력 API와 корисник покажувач 검사.
- `os/Алатки/자바파일묶기.py`: вдоми 입력 Датотека потврди·부팅 Група_VALUE генерира.

```sh
make test-java
make test
```

`os/시험/자바시험.py`는 ELF/ISO 부팅, 게스트 изгради_извор·Изврши_наредба, корисник 입력, 재귀·반복문·цел_број 극값·низа_VALUE_6ca8363c 결합·단락 평가, 재실행, извор_дрво ГРЕШКА 후 기존 класа_VALUE 보존, низа_VALUE/수 해독 ГРЕШКА, 무한 повторување_VALUE 제한, уреди_VALUE 넘침과 Датотека 부족을 검사한다. 게스트 генерира 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 вдоми OpenJDK의 класа_VALUE, цел_број 배열과 한글 상수를 게스트에 적재하며, 손상된 Датотека 표식·버전·константа_VALUE 수·гранка·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 시험 VM만 생성하고 종료한다.

구현 형식의 참고 податоци: Oracle [JVM класа_VALUE Датотека 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM Команда 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java Датотека В_И

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 класа_VALUE 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 Назад_VALUE `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. стандардна_вредност 출력 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. исклучок објект_VALUE·try/catch·try-with-resources는 지원하지 않으며 Датотека 오류를 진단하고 프로그램을 종료한다. низа_VALUE В_И, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 Датотека 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 обвивка `sync`가 필요하다. 예제의 Датотека 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 реален_податоци 게스트 изгради_извор 결과를 OpenJDK `-Xverify:all`로 다시 실행해 Датотека 바이트와 출력을 대조한다. 범위와 Store_VALUE 매체 사용법은 [posix-kor информации_пред_употреба_eb81d7d9](../posix-kor/информации_пред_употреба_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
