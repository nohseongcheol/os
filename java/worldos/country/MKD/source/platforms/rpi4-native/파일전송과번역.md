# 자체 ARM64 јадро_VALUE: FTP, C, JAR와 AOT Изврши_наредба

대상은 **Linux를 적재하지 않는 Raspberry Pi 4용 Java AOT јадро_VALUE**이다. CPU·уред_VALUE 경계는 C/어셈블리, Датотека 체계와 셸은 Java이며, 이번 TCP/IP 스택은 C로 작성된 lwIP 2.2.0을 이식했다. 게스트 TinyCC와 `jaot`도 EL0에서 실행한다. 호스트에 컴파일을 요청하거나 вдоми JVM으로 대신 실행하지 않는다.

JVM은 класа_VALUE 버전 45…52의 문서화한 부분집합이다. `java`는 바이트코드 실행기이고, `jaot`가 별도의 네이티브 Изврши_наредба 파일을 만든다. **JAR Архива_VALUE 해제나 JVM을 함께 묶는 것을 AOT라고 표시하지 않는다.** 지원하지 않는 바이트코드/API는 `jaot`가 진단하고 출력을 만들지 않는다. 기존 출력 ELF도 изгради_извор неуспех_VALUE 때 보존한다.

Android의 Dalvik/ART는 일반 JVM класа_VALUE/JAR가 아닌 **DEX**를 실행한다. ART의 AOT에는 GC, класа_VALUE 로딩, JNI 등 Изврши_наредба 기반도 필요하다. 따라서 ART처럼 기계어로 바꾸는 기능만으로 임의의 OpenJDK JAR 및 Swing이 자동 호환되지는 않는다. [Android 공식 런타임 설명](https://source.android.com/docs/core/runtime)

게스트 `vi 빛.java`로 Следно_ставка 소스를 작성한다.

```java

    public static void main(String[] Аргументи) throws Exception {
        int SUM_VALUE = 0;
        int 수 = 1;
        while (수 <= 10) {
            SUM_VALUE = SUM_VALUE + 수;
```


`jaot`은 클래스의 바이트코드를 C로 변환하고, **게스트 TinyCC**가 ARM64 명령어를 генерира·연결한다. Изврши_наредба 때 JVM 인터프리터를 호출하지 않는다. JAR의 Main-Class가 같은 Поддршка_VALUE 범위이면 다음도 가능하다.

```text

run 빛.elf
```

AOT 지원은 한 애플리케이션 클래스의 статичен_VALUE метод_VALUE/поле_VALUE, int 계열, цел_број 배열과 Референци, Аргументи низа_VALUE, услов·гранка·повторување_VALUE, низа_VALUE_6ca8363c 리터럴, `System.out.print/println`의 int/String, Македонски 출력·Датотека Читај/쓰기로 제한된다. класа_VALUE/метод_VALUE 수와 스택 등에도 고정 상한이 있다. Java исклучок Процес_VALUE_внес, објект_VALUE генерира, 가상 метод_VALUE 일반, switch/wide, long/float/double, invokedynamic, низа_VALUE_6ca8363c 결합용 StringBuilder, 일반 JDK·Socket·Thread·Swing은 이 AOT 백엔드에서 미지원이다. 내장 NUL/고립된 서로게이트 문자열도 거부한다. 잘못된 низа_VALUE пристап_внес/0으로 나누기 등은 네이티브 런타임 오류로 종료하며 Java исклучок 객체로 전달하지 않는다.

입력 클래스뿐 아니라 **생성된 ELF도 16 KiB 이하**여야 한다. 기계어 확장과 ELF 페이지 порамни_VALUE 때문에 짧은 클래스도 이 한도를 넘을 수 있으며, 이 경우 오류를 내고 기존 출력을 보존한다.

게스트 `javac`도 부분집합이다. 일반적인 објект_VALUE·Thread·Swing 소스는 호스트에서 `javac --release 8`로 컴파일하고, **기존 JVM의 Поддршка_VALUE клип 안에서** `java`/`java -jar`로 실행한다. 정확한 API는 [JVM 매뉴얼](자바실행환경.md)과 [한글 개발 매뉴얼](개발안내.md)을 참고한다.

JAR는 하나의 애플리케이션 класа_VALUE 경로다. 내부 Име `пакет/програма_f5044b9b.class`와 점으로 구분한 Main-Class를 지원한다. 내부 클래스는 파일로 풀어 VFS 슬롯을 소비하지 않는다. 내장 Македонски 클래스를 추가로 찾지만 현재 작업 폴더의 다른 클래스는 자동 혼합하지 않는다. ZIP64·кодирај_податоци ZIP·manifest Class-Path·서명 검증은 지원하지 않는다. JAR 하나가 16 KiB 이하이어도 클래스당/적재 수/VM 힙 제한은 그대로 적용된다.

`отвори_датотека` 등은 별도의 모의 호출이 아닌 기존 `pk_open` 등의 Македонски 매크로이며, ELF의 SVC를 통해 реален_податоци Java Датотека 체계에 도달한다. Датотека/소켓 호출 목록은 [корисник ABI](사용자호출규약.md)에 있다. C/C++ вдоми SDK Изврши_наредба 파일도 FTP로 업로드 후 `run` 또는 `./Датотека`로 실행하며 확장자는 필요 없다. Linux ARM64 статичен_VALUE ELF에는 별도의 제한된 호환 ПАТЕКА `run --linux Датотека`을 추가했다. [ELF·Linux ABI 매뉴얼](실행파일규약.md)에 정확한 формат_VALUE·시스템 호출·адреса 제한을 정리했다.

## Македонски 네트워크·작업·화면 API

| класа_VALUE | 호출 예 | Изврши_наредба ПАТЕКА |
|---|---|---|
| `출력` | `запиши_ред("안녕")`, `수쓰기(42)` | JVM 및 제한형 AOT |
| `Датотека` | `Запиши("문서.txt", "Содржина_VALUE")`, `Читај("문서.txt")` | JVM 및 제한형 AOT |
| `통신` | `Отвори(0)`, `испрати(종단, "10.0.2.2", 9000, "한글")`, `받기(종단)` | JVM의 UDP |
| `연결통신` | `Врзи_се("10.0.2.2", 9000)`, `듣기(9000)`, `받기(сервер_VALUE)` | JVM의 Socket/ServerSocket |
| `작업` | `Изврши_2(Runnable)`, `기다리기(Thread)`, `YIELD_задача()` | JVM의 협력식 нишка_VALUE |
| `прозорец`, `графичка_контрола` | прозорец·버튼·знак_VALUE·СМС_поле·настан Врзи_се | JVM의 Swing 부분집합 |

명명에서는 표준 영어 API를 보존하고 Македонски 호출 계층을 추가한다. `통신(通信)`, `Врзи_се(連結)`, `출력(出力)`은 기존 단어의 뜻을 사용한다. `작업 нишка_VALUE`은 한 Изврши_наредба 흐름을 가닥에 빗댄 기술 표현, `порта_VALUE`는 포트의 접점을 설명하는 표현이다. 새 기술 결합어를 고대에 이미 존재한 용어처럼 설명하지 않는다. 전체 JDK의 번역을 완료했다고 표시하지 않는다.

외부 주소는 цифра_VALUE IPv4이며 QEMU 호스트는 `10.0.2.2`, 게스트는 `10.0.2.15`다. UDP 전문은 512바이트까지다. 소켓은 비차단 자체 ABI이며 JVM이 제한된 почекај_VALUE/재시도를 제공한다. TCP connect 대기는 최대 1초, корисник програма_f5044b9b 전체에는 기존 약 2초 CPU 기한이 적용된다. 일반적인 장기 Изврши_наредба корисник 서버와 pthread는 아직 없다. FTP는 корисник програма_f5044b9b 기한과 별개인 јадро_VALUE 서비스다.

게스트의 корисник TCP/UDP 서버로 들어오는 연결은 NAT 포트를 추가한다. 예를 들어 `python3 Алатки/Изврши_наредба.py --network --forward tcp:9300:9300 --forward udp:9301:9301`로 실행하면 호스트의 localhost 9300/TCP·9301/UDP를 게스트의 같은 포트로 전달한다. FTP의 стандардна_вредност контрола_VALUE/데이터 포트와 겹치면 Изврши_наредба 전에 거부한다.
