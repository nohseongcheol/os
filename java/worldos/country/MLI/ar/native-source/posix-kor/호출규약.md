# فضاء_المستخدم 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `جهاز/نظام_تشغيل_المكالمات.s`에서 EAX(فهرس), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 وسائط)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. نواة_قيمة 실패는 음수 خطأ فهرس, C مكتبة 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 فضاء_المستخدم منطقة_قيمة 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C بيانات 주소는 بايت_قيمة 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java ملف 흐름의 어셈블리 경계가 별도 بايت_قيمة 버퍼를 마련하여 같은 호출을 사용한다.

| فهرس | إجراء | وسائط |
|---|---|---|
| 30 | فتح_ملف | NUL 끝 اسم عنوان, إعدادات, 허가 |
| 31 | يقرأ_ملف_بيانات | 서술자, بيانات عنوان, بايت_قيمة رقم |
| 32 | كتابة_ملف_بيانات | 서술자, بيانات عنوان, بايت_قيمة رقم |
| 33 | يغلق_ملف | 서술자 |
| 34 | يبحث_ملف | 서술자, ترميز_قيمة 있는 إزاحة_قيمة, يعرض_جذر |
| 35 | 파일서술자복제 | 서술자 |
| 36 | 파일서술자지정복제 | 서술자, 새 서술자 |
| 37 | يقرأ_ملف_توفر | 서술자, 48바이트 حالة_قيمة عنوان |
| 38 | يزيل_ملف_إدخال_اسم | NUL 끝 اسم عنوان |
| 39 | 파일길이정하기 | 서술자, 새 길이 |
| 40 | 파일서술자제어 | 서술자, أمر, قيمة |

| 42 | يربط_عنوان | 서술자, sockaddr_in عنوان, 길이 |
| 43 | يرسل_مخطط_بيانات_بيانات | 서술자, بيانات عنوان, 길이, إعدادات, طلب عنوان |
| 44 | يستلم_مخطط_بيانات_بيانات | 서술자, بيانات عنوان, 길이, إعدادات, طلب عنوان |
| 45 | يقرأ_مأخذ_التوصيل_عنوان | 서술자, sockaddr عنوان, socklen_t عنوان |
| 46 | 수신대기정하기 | 서술자, 0~2000 밀리초 |
| 47 | تثبيت_تخزين_الملفات | 서술자 |

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 عنوان 두 칸이다. يستلم_قيمة 주소가 NULL이면 نظير_قيمة عنوان 기록을 생략한다. sockaddr_in은 16바이트이며 عنوان 체계는 جهاز_قيمة بايت_قيمة تسلسل_قيمة, 접속번호와 IP 주소는 네트워크 بايت_قيمة 차례다. 축소된 عنوان 버퍼에도 들어가는 앞부분을 쓰고 전체 عنوان حجم 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 خروج_تطبيق, 2·3은 기존 وسائط 조회다. حديث_عنصر 커널의 وسائط 목록이 ينفذ_أمر 이름을 제외하므로 C 진입기는 argv[0]에 고정 سلسلة_قيمة `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX عملية_قيمة ABI와 다른 점이다.

표준 헤더의 عدد_صحيح حجم, 플래그 قيمة, stat قيمة_الحقل 순서는 `مصدر/تصريحات/`에 정의한다. 동적 اتصال·다중 عملية_قيمة·스레드가 추가되면 خطأ فهرس 저장과 مصدر_قيمة 수명, 호출 경계도 함께 검토해야 한다.
