# 셸에서 실행하는 သုံးစွဲသူ 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java ဖွံ့ဖြိုးရေး ဝန်းကျင် လမ်းညွှန်](../../စာတမ်း/Javaဖွံ့ဖြိုးဝန်းကျင်.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 စက်မောင်း

အိမ်ရှင် အဆုံးသုံးမျက်နှာပြင် 1:

```sh
cd /home/user/jkoros
python3 os/ကိရိယာစု/ဒေတာပြန်ယူ.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. ပြင်ပတန်ဖိုး 연결을 받도록 방화벽이나 စက်ပစ္စည်းဆက်သွယ်ပေါက် 전달을 변경하지 않는다. Ctrl+C로 종료한다.

အိမ်ရှင် အဆုံးသုံးမျက်နှာပြင် 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 ဝင်ဒေတာ:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 တကယ့်ဒေတာ CPU ခွင့်ပြုချက်တန်ဖိုး `ring 3`, အချက်များ အထွက်.
- `netcheck`: ဆက်သွယ်ပေါက်တန်ဖိုး 중복, 잘못된 ကိုင်တွယ်ရာတန်ဖိုး/ညွှန်တံ/အလျား, 비차단 받기와 အချိန်တန်ဖိုး 초과 အတည်ပြု.
- `udp`: IPv4 လိပ်စာ·ဦးတည်ရာတန်ဖိုး ဆက်သွယ်ပေါက်တန်ဖိုး·한 စကားလုံးတန်ဖိုး 메시지를 받아 UDP로 보내고 같은 응답을 အတည်ပြု. `UDP ECHO PASS`, `Exit: 0`이면 အောင်မြင်မှုတန်ဖိုး.
- `stress`: အိမ်ရှင် `10.0.2.2`의 သတ်မှတ်ပေးတန်ဖိုး 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. တန်ဖိုးလက်ခံရယူ ထပ်ခါလည်ပတ်မှုတန်ဖိုး 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. လက်ရှိအချက်အလက်တစ်ခု 주소는 게스트 `10.0.2.15/24`, ကွန်ရက်တံခါးပေါက် `10.0.2.2`로 고정돼 있다. QEMU သုံးစွဲသူ 네트워크의 အိမ်ရှင် ဝင်သုံးအချက် 주소를 사용한 예제다. 다른 ကွန်ရက်ဆက် 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 ပရိုဂရမ် 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java ပရိုဂရမ် အချက်နောက်တွဲ

`ဥပမာ/내프로그램.java`를 နောက်တစ်ခုအချက်အလက်တစ်ခု 형식으로 만든다. 진입점은 အချက်များ 없는 `static int` 또는 `static void` 함수다. 인수는 သုံးစွဲသူ API로 조회한다.

```java
public final class 내프로그램 {
    public static int လုပ်ဆောင်() {
        သုံးစွဲသူ.ရေး("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/သုံးစွဲသူ/ပရိုဂရမ်.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := သုံးစွဲသူ/ဥပမာ/내프로그램.java
APP_ENTRY_mine := 내프로그램.လုပ်ဆောင်
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 အားလုံးတည်ဆောက် 나열한다. `သုံးစွဲသူ/ကြေညာချက်/သုံးစွဲသူ.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 စက်မောင်း 중인 VM에는 တည်ဆောက် 결과가 자동 반영되지 않는다. ပရိုဂရမ် 이름은 လက်ရှိအချက်အလက်တစ်ခု 셸의 ASCII ဝင်ဒေတာ 제한에 맞춘 1~15자의 소문자 이름이며 Java အတန်းတန်ဖိုး·လုပ်ဆောင်ချက်·변수에는 한국어를 쓴다. အများဆုံးတန်ဖိုး 32개 ပရိုဂရမ်, 한 စက်မောင်း 파일은 အများဆုံးတန်ဖိုး 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/ဘာသာပြန်စက်.py --target user --entry နှုတ်ဆက်.လုပ်ဆောင် \
    -o os/build/apps/hello.elf os/သုံးစွဲသူ/ကြေညာချက်/သုံးစွဲသူ.java os/သုံးစွဲသူ/ဥပမာ/နှုတ်ဆက်.java
```

`--target user`는 **jkoros 전용 ABI**တတိယအော်ပရန်း. Linux 대상과 시스템 ခေါ်လုပ် 번호가 다르므로 အိမ်ရှင် 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 ထောက်ပံ့မှုတန်ဖိုး ဖြတ်နယ်ပယ် 안에서 실행한다. `.jar`와 일반 Linux စက်မောင်း 파일은 지원하지 않는다.

## သုံးစွဲသူ ကွန်ရက်ဆက် API

선언은 `ကြေညာချက်/သုံးစွဲသူ.java`에 있다. `ဒေတာပို့`/`ဒေတာလက်ခံရယူ`의 `int[]` အချက်အလက်တစ်ခုအင်္ဂါရပ် 한 개는 ဘိုက်တန်ဖိုး တစ်တန်ဖိုး(0~255)를 나타낸다. 한 데이터그램의 အများဆုံးတန်ဖိုး ဒေတာ 길이는 1,024바이트다.

```java
int ကိုင်တွယ်ရာတန်ဖိုး = သုံးစွဲသူ.ကွန်ရက်ဖွင့်(0); // 0: ယာယီတန်ဖိုး ဒေသတွင်းနယ်ပယ်ကန့်သတ် UDP ဆက်သွယ်ပေါက်တန်ဖိုး 자동 ရွေးချယ်မှုတန်ဖိုး
int[] ဒေတာ = new int[32];
ဒေတာ[0] = 'H'; ဒေတာ[1] = 'i';
int 보낸길이 = သုံးစွဲသူ.ဒေတာပို့(ကိုင်တွယ်ရာတန်ဖိုး, 0x0a000202, 9000, ဒေတာ, 2);
int ရရှိအရှည် = သုံးစွဲသူ.ဒေတာလက်ခံရယူ(ကိုင်တွယ်ရာတန်ဖိုး, ဒေတာ, 1500);
သုံးစွဲသူ.ကွန်ရက်ပိတ်(ကိုင်တွယ်ရာတန်ဖိုး);
```

တကယ့်ဒေတာ 프로그램에서는 ဖွင့်·ပို့·받기의 အနုတ်တန်ဖိုး 반환값을 각각 검사한다. 완성된 예제는 `ဥပမာ/ဒေတာဆက်သွယ်.java`에 있다. `ဒေတာလက်ခံရယူ`의 တန်ဖိုးစောင့် 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 တန်ဖိုးလက်ခံရယူ 대기열은 한 개뿐이므로 အချက်နောက်တွဲ 도착분은 버린다. `ပို့ပြီးလိပ်စာ`와 `ပို့ပြီးဆက်သွယ်ပေါက်`로 마지막으로 받은 상대를 조회한다.

| ပြန်ပေးတန်ဖိုး | 의미 |
| --- | --- |
| 0 이상 | ကိုင်တွယ်ရာတန်ဖိုး·လုပ်ငန်းစဉ်တန်ဖိုးအချက် အလျား·အောင်မြင်မှုတန်ဖိုး 등 해당 함수의 ရလဒ် |
| -5 | ကိရိယာ တန်ဖိုးပို့ မအောင်မြင်မှု |
| -9 | 잘못되었거나 닫힌 ဆက်သွယ်မှု ကိုင်တွယ်ရာတန်ဖိုး |
| -11 | 비차단 받기에서 도착한 ဒေတာ 없음 |
| -14 | သုံးစွဲသူ ညွှန်တံ/အခင်းအကျင်းတန်ဖိုး ဖြတ်နယ်ပယ် အမှား |
| -19 | ထောက်ပံ့မှုတန်ဖိုး NIC 없음 |
| -22 | ဆက်သွယ်ပေါက်တန်ဖိုး/တန်ဖိုးစောင့် အချိန်တန်ဖိုး/အချက်များ တန်ဖိုး အမှား |
| -24 | 열린 ကွန်ရက်ဆက်သွယ်ပေါက် 4개 ဆံ့ပမာဏအကန့် |
| -38 | 알 ကိန်းတန်ဖိုး 없는 시스템 ခေါ်လုပ် |
| -90 | ဒေတာ 또는 တန်ဖိုးလက်ခံရယူ အခင်းအကျင်းတန်ဖိုး အရွယ် 문제 |
| -98 | ဒေသတွင်းနယ်ပယ်ကန့်သတ် ဆက်သွယ်ပေါက်တန်ဖိုး နံပါတ် 중복 |
| -101 | 지원하지 않는 ဦးတည်ရာတန်ဖိုး လိပ်စာ |
| -110 | ARP·ကိရိယာ·တန်ဖိုးလက်ခံရယူ အချိန်တန်ဖိုး 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 ကုဒ်သွင်းစနစ်တန်ဖိုး 있는 Java `int`의 ဘစ်တန်ဖိုး 패턴을 사용하므로 상위 비트가 1인 ဖြစ်သောပုံမှန် IP 주소가 음수로 보일 ကိန်းတန်ဖိုး 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## စက်မောင်း 경계와 시스템 ခေါ်လုပ်

```text
အမိန့်ဝင်း run → JKAP에서 ELF မှန်ကန်ကြောင်းစစ်·적재 → ring 3 သုံးစွဲသူ ပရိုဂရမ်
                                 ↓ int 0x80
                      ညွှန်တံ စစ်ဆေးချက် → Java အူတိုင်တန်ဖိုး API → RTL8139/UDP
                                 ↓ ထွက်ပရိုဂရမ်·ခြွင်းချက်·အချိန်တန်ဖိုး 초과
                                အမိန့်ဝင်း 복귀
```

시스템 ခေါ်လုပ် 레지스터는 `EAX=နံပါတ်`, `EBX,ECX,EDX,ESI,EDI=အချက်များ`, `EAX=ရလဒ်`တတိယအော်ပရန်း. Java ခေါ်လုပ် တွက်ချက်ခံထပ်ဆင့်အစု ABI는 컴파일러가 သုံးစွဲသူ 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| နံပါတ် | ခေါ်လုပ် |
| --- | --- |
| 0 | ထွက်ပရိုဂရမ်(အခြေအနေတန်ဖိုး ကုဒ်တန်ဖိုး) — လုပ်ဆောင်/အမှား 런타임에서 သုံးစွဲမှု |
| 1 | အက္ခရာစဉ် ရေး |
| 2 / 3 | အချက်များ အရေအတွက် / အချက်များ အက္ခရာစဉ် လိပ်စာ |
| 10 | UDP ဖွင့် |
| 11 | UDP ပို့(ကိုင်တွယ်ရာတန်ဖိုး, IP, ဦးတည်ရာတန်ဖိုး ဆက်သွယ်ပေါက်တန်ဖိုး, အခင်းအကျင်းတန်ဖိုး လိပ်စာ, အလျား) |
| 12 | UDP လက်ခံ(ကိုင်တွယ်ရာတန်ဖိုး, အခင်းအကျင်းတန်ဖိုး လိပ်စာ, ကန့်သတ်ချက်တန်ဖိုး မီလီစက္ကန့်) |
| 13 | UDP ပိတ် |
| 14 | ဒေသတွင်းနယ်ပယ်ကန့်သတ် IP လိပ်စာ |
| 15 / 16 | နောက်ဆုံးအချက်အလက်တစ်ခု တစ်ဖက်တန်ဖိုး IP / UDP ဆက်သွယ်ပေါက်တန်ဖိုး |
| 20 | RAM ဖိုင် ဖတ်(အမည် int[] လိပ်စာ, အထွက် int[] လိပ်စာ) |
| 21 | RAM ဖိုင် ရေး(အမည် int[] လိပ်စာ, ဝင်ဒေတာ int[] လိပ်စာ, ဘိုက်တန်ဖိုး အလျား) |
| 22 | UTF-16 ကုဒ်တန်ဖိုး ယူနစ်တန်ဖိုး အက္ခရာ အထွက်(0~65535) |

ဖိုင် API는 `သုံးစွဲသူ.ဖိုင်ဖတ်(int[] အမည်, int[] ဒေတာ)`와 `သုံးစွဲသူ.ဖိုင်ရေး(int[] အမည်, int[] ဒေတာ, int အလျား)`တတိယအော်ပရန်း. 이름은 ASCII ကုဒ်တန်ဖိုး အခင်းအကျင်းတန်ဖိုး(အများဆုံးတန်ဖိုး 64칸, 0 ထွက်ပရိုဂရမ် 또는 အခင်းအကျင်းတန်ဖိုး အဆုံး), ဒေတာ အချက်အလက်တစ်ခုအင်္ဂါရပ် 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 ဖိုင် 없음 `-2`, ညွှန်တံ အမှား `-14`, အမည်/အလျား အမှား `-22`, ဖိုင် နေရာကွက်တန်ဖိုး 부족 `-28`, အရွယ် 초과 `-90`을 반환한다. 쓰기는 မှန်ကန်ကြောင်းစစ် 후 ဖိုင် 전체를 대체한다. `သုံးစွဲသူ.အက္ခရာတန်ဖိုးရေး(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`လုပ်ဆောင်မှုခွင့်ပြုချက်()`은 시스템 호출이 아니라 သုံးစွဲသူ 모드에서 CS의 하위 비트를 직접 읽으므로 တကယ့်ဒေတာ စက်မောင်း 권한을 확인한다. အူတိုင်တန်ဖိုး စက်ပစ္စည်းဆက်သွယ်ပေါက် 접근용 `ကိရိယာ` native 함수는 သုံးစွဲသူ ဦးတည်ချက်တန်ဖိုး 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 ကန့်သတ်ချက်တန်ဖိုး

- 한 번에 한 프로그램만 실행하며 ဖြစ်သောအပြည့်အစုံ 후 셸로 돌아온다. 백그라운드 စက်မောင်း, 파이프, 프로세스 간 통신은 없다. စက်မောင်း 파일은 커널의 ဖတ် 전용 JKAP 묶음에서 적재한다. ဒေတာ 파일에는 ပင်မမှတ်ဉာဏ် 파일체계와 전용 IDE 보존 형식이 있다.
- သုံးစွဲသူ 가상 လိပ်စာ `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. စက်မောင်း 영상은 ရှေ့တန်ဖိုး 2MiB, 인수는 `0x04300000`부터, 스택은 နယ်ပယ်တန်ဖိုး 끝에서 시작한다. အူတိုင်တန်ဖိုး identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB သုံးစွဲသူ 영역을 비우고 ဖိုင် 구역을 복사해 BSS·အခင်းအကျင်းတန်ဖိုး 영역을 초기화한다. သုံးစွဲသူ GC는 없지만 ထွက်ပရိုဂရမ် 후 နောက်တစ်ခုအချက်အလက်တစ်ခု စက်မောင်း 때 영역을 재사용한다. 인수는 공백으로 분리한 အများဆုံးတန်ဖိုး 16개이며 ကိုးကားအမှတ်/이스케이프 파싱은 없다.
- သုံးစွဲသူ 페이지의 ကုဒ်တန်ဖိုး/ဒေတာ 분리 ဖတ် 전용 သတ်မှတ်ချက်, NX, တွက်ချက်ခံထပ်ဆင့်အစု guard, ASLR은 아직 없다. 커널과 သုံးစွဲသူ မှတ်ဉာဏ်ဒေတာ·စက်ပစ္စည်းဆက်သွယ်ပေါက် ခွင့်ပြုချက်တန်ဖိုး 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 စက်မောင်း 상한을 두며 အချိန်တန်ဖိုး 초과는 `Exit: 124`တတိယအော်ပရန်း. သုံးစွဲသူ CPU 예외는 `128 + ခြွင်းချက် နံပါတ်`(페이지 အမှား 142, 특권 위반 141), Java အခင်းအကျင်းတန်ဖိုး/တွက်ချက်မှု 오류는 101~105다. အူတိုင်တန်ဖိုး 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, တည်ငြိမ်တန်ဖိုး IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP စစ်ဆေးပေါင်းလဒ် 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- သုံးစွဲသူ စက်မောင်း·ကွန်ရက်ဆက်·တန်ဖိုးကာကွယ် နယ်နိမိတ်တန်ဖိုး 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 စက်မောင်း·ဖြစ်သောပုံမှန် 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## မှန်ကန်ကြောင်းစစ် 근거

`make test`는 ဘာသာပြန်စက် 14개 စမ်းသပ်မှု, Java 패킷 အခြေအနေစည်းကမ်း 2,201개 စစ်ဆေးချက်, 기존 အမိန့်ဝင်း ELF/ISO စက်တင် စမ်းသပ်မှု, သုံးစွဲသူ ELF/တကယ့်ဒေတာ UDP/တန်ဖိုးကာကွယ် နယ်နိမိတ်တန်ဖိုး 시험을 실행한다. ကွန်ရက်ဆက် 시험은 루프백 서버가 받은 자료의 အလျား·해시까지 `os/build/သုံးစွဲဆက်သွယ်စမ်းသပ်.json`에 기록한다. 시험용 손상된 ELF·특권 အမိန့်·무한 반복 프로그램은 ယာယီတန်ဖိုး 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
