# ကိုယ်ပိုင် ARM64 커널의 စက်မောင်း အလွှာတန်ဖိုး·프로세스 တန်ဖိုးပြသ·QEMU ပြင်ပတန်ဖိုး ဆက်သွယ်မှု

2026-10-04 점검. 대상은 `jkoros/platforms/rpi4-native`의 ကိုယ်ပိုင် Java 커널이다.
`platforms/rpi4`의 Linux/OpenJDK 판이나 `os`의 기존 x86 판에 이 결과를 적용하지 않는다.

## စက်မောင်း အလွှာတန်ဖိုး

| ဦးတည်ချက်တန်ဖိုး | စက်မောင်း နေရာ | လက်ရှိအချက်အလက်တစ်ခု အကောင်အထည်ဖော်မှု |
|---|---|---|
| အမိန့်ဝင်း, `sh` အမိန့်စာတမ်းတန်ဖိုး, `ps`, `top`, ဖိုင် 내장 အမိန့် | EL1 အူတိုင်တန်ဖိုး | Java AOT အူတိုင်တန်ဖိုး 함수로 ခေါ်လုပ် |
| အဆုံးသုံးမျက်နှာပြင် 창과 အမိန့်ဝင်း အခြေအနေတန်ဖိုး | အူတိုင်တန်ဖိုး | အများဆုံးတန်ဖိုး 4개의 상태를 တန်ဖိုးထိန်းသိမ်း·복원; 독립 အမိန့်ဝင်း 프로세스가 아님 |
| `java`, `javac` | EL0 သုံးစွဲသူ နယ်ပယ်တန်ဖိုး | `java-tools.elf`를 적재하고 별도 သုံးစွဲသူ တွက်ချက်ခံထပ်ဆင့်အစု·페이지 권한으로 စက်မောင်း |
| `java CLASS`, `java -jar`의 ပရိုဂရမ် | EL0의 ကိုယ်ပိုင် JVM 내부 | ဘိုက်ကုဒ် စက်မောင်း. 전체 OpenJDK가 아님 |
| `jaot` ရလဒ် ELF | EL0 | 지원되는 부분집합을 ARM64 코드로 컴파일한 후 ELF로 စက်မောင်း |
| `python`, `vi`, `cc`, သုံးစွဲသူ ELF | EL0 | သုံးစွဲသူ စက်မောင်း ဖိုင် 적재 လမ်း သုံးစွဲမှု |
| ဖိုင်·ကွန်ရက်ပေါက်တန်ဖိုး·그래픽 시스템 ခေါ်လုပ် | EL1 | EL0에서 SVC로 들어와 처리한 နောက်တန်ဖိုး သုံးစွဲသူ 프로그램으로 복귀 |

근거:

- `မူရင်းကုဒ်/အမိန့်အဓိပ္ပာယ်ဖော်.java`: `ကိရိယာတစ်ခုအချက်()` 및 `java`/`javac` အမိန့် အခွဲ.
- `စက်/သုံးစွဲသူ.c`: `ပရိုဂရမ်စက်မောင်း()`의 ELF 적재, 페이지 ခွင့်ပြုချက်တန်ဖိုး သတ်မှတ်ချက်, PID 배정, `사용자진입()`.
- `စက်တင်/အချက်အမှတ်တစ်ခုတန်ဖိုး.S`: `user_enter`의 `SP_EL0`, `SPSR_EL1=0x340`, `eret`.
- `မူရင်းကုဒ်/ဝင်းအသုံးပြုချိန်ပိုင်း.java`: 네 터미널의 အမိန့်ဝင်း 상태와 သုံးစွဲသူ 세션 တန်ဖိုးထိန်းသိမ်း·လုပ်ဆောင်မှုပြန်စ.

QEMU QMP로 CPU 0을 တကယ့်ဒေတာ 정지하여 읽은 ခွင့်ပြုချက်တန်ဖိုး 상태는 အမိန့်ဝင်း တန်ဖိုးစောင့် 중 `EL1h`, Java တွက်ချက်မှု 중 `EL0t`였다.
이 결과는 소스의 주석이나 အထွက် 문자열만으로 판정한 것이 아니다.

## ps와 top에 기대한 항목이 없는 အကြောင်းရင်း

`မူရင်းကုဒ်/စနစ်ကိရိယာ.java`의 `အလုပ်များပြသ()`ပထမတွက်ချက်ခံ 두 명령의 အများသုံးတန်ဖိုး 출력이다.
`1 ... kernel/shell`은 고정된 အူတိုင်တန်ဖိုး/အမိန့်ဝင်း 집계 행이다. 셸마다 생성한 တကယ့်ဒေတာ PID가 아니다.
그 다음에는 살아 있는 အူတိုင်တန်ဖိုး 협력 작업과 အများဆုံးတန်ဖိုး 4개의 EL0 세션을 조회한다.

1. 셸은 독립 သုံးစွဲသူ 프로세스가 아니므로 터미널을 더 열어도 `shell` 행이 각각 생기지 않는다.
2. 같은 터미널의 `java နှုတ်ဆက်`ပထမတွက်ချက်ခံ 끝난 နောက်တန်ဖိုး `ps`를 실행하면 해당 Java 세션은 이미 정리되어 표시되지 않는다.
3. `vi`ဒုတိယတွက်ချက်ခံ Swing 프로그램은 다른 터미널로 전환할 때 CPU ပတ်ဝန်းကျင်အဓိပ္ပာယ်တန်ဖိုး·메모리를 보관한다. 이 상태가 `SUSPENDED`တတိယအော်ပရန်း.
4. 한 번에 အလုပ်လုပ်နေ EL0 프로그램은 하나다. 다른 창의 프로그램을 동시에 돌리는 일반 선점형 프로세스 스케줄러와 `&` အလုပ် 제어는 없다.
5. Java의 အလုပ် 가닥은 ကိုယ်ပိုင် JVM 내부에서 협력적으로 전환한다. 별도 အူတိုင်တန်ဖိုး 스레드/TID가 아니므로 `ps`에 각각 나타나지 않는다.
6. `ps`·`top` 자체도 အူတိုင်တန်ဖိုး 내장 명령이므로 별도의 သုံးစွဲသူ PID가 생성되지 않는다. `top`은 같은 အလုပ် 목록과 မှတ်ဉာဏ်ဒေတာ 정보를 주기적으로 보여 준다.

`RUN_ms`는 세션이 선택된 동안의 경과 시간이며 시스템 ခေါ်လုပ် 시간도 포함한다.
Linux의 정밀 CPU သုံးစွဲမှု 시간이나 CPU 사용률이 아니다. `MAPPED_KiB`도 သုံးစွဲသူ 페이지 매핑량이다.

실제로 확인하는 방법:

```text
cd /example/java
java ဝင်းဥပမာ
```

GUI에서 `Ctrl+Shift+T`로 새 터미널을 열거나 `F6`으로 다른 터미널을 선택한 နောက်တန်ဖိုး:

```text
ps
top -n 1
```

이번 시험에서 두 명령에 နောက်တစ်ခုအချက်အလက်တစ်ခု သုံးစွဲသူ 행이 나타났다. PID와 시간은 실행마다 달라진다.

```text
PID SLOT STATE MAPPED_KiB RUN_ms AGE_ms COMMAND
1 - RUN - - 25144 kernel/shell
24 0 SUSPENDED 9608 507 3960 java ဝင်းဥပမာ
```

`ဝင်းဥပမာ.class`는 စက်ပုံရိပ်တည်ဆောက် တည်ဆောက် 때 အိမ်ရှင် `javac`로 컴파일되어 소스와 함께 탑재된다.
게스트 `javac ဝင်းဥပမာ.java`는 လက်ရှိအချက်အလက်တစ်ခု ထောက်ပံ့မှုတန်ဖိုး 범위를 넘으며 `unsupported throws type` 오류를 낸다.
이 GUI 점검에는 이미 탑재된 클래스를 실행한다.

셸까지 EL0로 옮기고 프로그램을 동시에 실행하려면 သုံးစွဲသူ အမိန့်ဝင်း စက်မောင်း ဖိုင်, 프로세스별 လိပ်စာ သတ်မှတ်လိပ်စာနယ်·ဖိုင် 기술자·အလုပ် 디렉터리,
프로세스 ထုတ်လုပ်/တန်ဖိုးစောင့်/ထွက်ပရိုဂရမ်, 스케줄러, TTY အဝင်အထွက်, အူတိုင်တန်ဖိုး အလုပ်·သုံးစွဲသူ အလုပ် 구분을 추가해야 한다.
`ps` 출력에 이름만 추가해서는 သုံးစွဲသူ ခွင့်ပြုချက်တန်ဖိုး 분리나 동시 실행이 구현되지 않는다.

## QEMU에서 외부로 통신하기

အိမ်ရှင် 터미널에서 နောက်တစ်ခုအချက်အလက်တစ်ခု 중 하나로 실행한다.

```sh
cd /home/user/jkoros/platforms/rpi4-native
make desktop ARGS="--network"
```

မျက်နှာပြင် 없이 UART 셸만 사용할 때는 `make network`를 사용한다.
이미 VM이 စက်မောင်း 중이면 ထွက်ပရိုဂရမ် 전 RAM 자료를 보관한다. 별도 VM을 띄우려면
`make desktop ARGS="--network --port 5903 --network-host 127.0.0.2"`처럼 VNC와 ဆက်ပို့တန်ဖိုး 주소를 구분한다.

게스트 안에서:

```text
ipconfig
ip route show
ping -c 2 10.0.2.2
```

초깃값은 `sl0`, လိပ်စာ `10.0.2.15`, 넷마스크 `255.255.255.0`, ကွန်ရက်တံခါးပေါက် `10.0.2.2`တတိယအော်ပရန်း.
정상이면 ပြန်ကြိုးစား 설정할 필요가 없다. 주소를 바꿔 둔 경우 ကွန်ရက်ပေါက်တန်ဖိုး/FTP를 닫은 နောက်တန်ဖိုး 기본값으로 돌릴 ကိန်းတန်ဖိုး 있다.

```text
ftpd stop
ipconfig set 10.0.2.15 255.255.255.0 10.0.2.2
```

ဆက်သွယ်မှု လမ်း:

```text
게스트 Java/C/Python → SVC → အူတိုင်တန်ဖိုး lwIP → 보조 UART SLIP
    → အိမ်ရှင် ကွန်ရက်တံတား.py → QEMU user NAT → အိမ်ရှင် TCP/IP → LAN/인터넷
```

QEMU `raspi4b`의 GENET Ethernet Controller는 미구현이다.
လက်ရှိအချက်အလက်တစ်ခု 실행기는 일반 PC용 `-device e1000`이나 `virtio-net-pci` 대신 보조 UART를 사용한다.
따라서 `-nic user`만 추가하거나 게스트 주소만 바꿔서는 이 ဆက်သွယ်မှု 경로를 대신할 ကိန်းတန်ဖိုး 없다.
[QEMU Raspberry Pi ကိရိယာ ထောက်ပံ့မှုတန်ဖိုး](https://www.qemu.org/docs/master/system/arm/raspi.html)

게스트에서 `127.0.0.1`은 게스트 자신이며, `10.0.2.2`ပထမတွက်ချက်ခံ QEMU 호스트에 접근하는 주소다.
그 밖의 တကယ့်ဒေတာ IPv4 주소로 향하는 TCP/UDP는 호스트의 လမ်း·방화벽·ဆက်သွယ်မှု 가능 여부에 따른다.
게스트 DNS와 일반 TLS 소켓은 아직 없다. 도메인 အမည် 대신 ဂဏန်းတန်ဖိုး IPv4를 사용해야 한다. 이후 추가된 GENET·DHCP 및 게스트 SSH·VNC는 [ပြင်ပတန်ဖိုး ချိတ်ဆက်မှု လမ်းညွှန်](ပြင်ပချိတ်ဆက်မှုလမ်းညွှန်.md)를 참고한다.
`ping 10.0.2.2` 성공은 NAT 관문까지의 확인이지 인터넷 통신의 증거는 아니다.
인터넷 ICMP는 QEMU user NAT와 အိမ်ရှင် `ping_group_range` 설정에 영향받으므로,
ပြင်ပတန်ဖိုး ping 실패만으로 TCP/UDP 통신까지 불가능하다고 판단하지 않는다.
[QEMU NAT 및 ICMP ရှင်းလင်းချက်](https://www.qemu.org/docs/master/system/devices/net.html)

## တကယ့်ဒေတာ TCP/UDP 왕복 ဥပမာ

VM을 실행한 상태에서 호스트의 다른 터미널에서:

```sh
cd /home/user/jkoros/platforms/rpi4-native
python3 ကိရိယာစု/ပြန်ပို့စက်ဥပမာ.py --tcp-port 9000 --udp-port 9001
```

게스트 안에서:

```text
cd /example/java
java ကွန်ရက်ဥပမာ 9000 9001
cd /example/python
python ကွန်ရက်ဥပမာ.py 9001
```

Java 예제는 TCP와 UDP, Python 예제는 UDP를 အိမ်ရှင် 응답기로 보내고 တကယ့်ဒေတာ 받은 자료를 비교한다.
Java 예제의 클래스는 이미 탑재되어 있다. 이 예제의 တန်ဖိုးလက်ခံရယူ 제한은 700ms이므로 느린 호스트에서는
ဥပမာ 자체의 အချိန်တန်ဖိုး 제한을 조정해야 할 ကိန်းတန်ဖိုး 있다.

## အိမ်ရှင် 또는 다른 PC에서 게스트로 접속하기

စက်ပစ္စည်းဆက်သွယ်ပေါက် 전달을 စက်မောင်း 시 명시한다.

```sh
make desktop ARGS="--network --forward tcp:18080:8080 --forward udp:19001:9001"
```

- အိမ်ရှင် `127.0.0.1:18080/TCP` → 게스트 `10.0.2.15:8080/TCP`.
- အိမ်ရှင် `127.0.0.1:19001/UDP` → 게스트 `10.0.2.15:9001/UDP`.
- 게스트 프로그램이 그 포트에서 실제로 수신해야 한다. ဆက်ပို့တန်ဖိုး 옵션이 서버를 시작하지는 않는다.
- `ftpd start`는 별도로 게스트 FTP를 시작한다. မူလသတ်မှတ်တန်ဖိုး အိမ်ရှင် ထိန်းချုပ်တန်ဖိုး 포트는 2121, 수동 ဒေတာ 포트는 50000~50007이다.

မူလသတ်မှတ်တန်ဖိုး `--network-host 127.0.0.1`은 루프백에만 연결한다. 이후 추가한 ပြင်ပတန်ဖိုး ချိတ်ဆက်မှု 기능에서는
`--network-host 0.0.0.0` 또는 အိမ်ရှင် LAN 주소를 명시하면 다른 PC의 직접 접속도 허용한다.
[게스트 SSH·VNC စက်မောင်း လမ်းညွှန်](ပြင်ပချိတ်ဆက်မှုလမ်းညွှန်.md)를 참고한다.
루프백 연결을 유지하면서 호스트의 SSH 서버를 이용할 경우 다른 PC에서 다음처럼 TCP 터널을 만든다.
`192.168.0.10`은 QEMU를 실행하는 호스트의 တကယ့်ဒေတာ ဝင်သုံးအချက် 가능한 IP로 바꾼다.

```sh
ssh -N -L 18080:127.0.0.1:18080 user@192.168.0.10
```

다른 PC의 클라이언트는 이제 မိမိကိုးကားချက် `127.0.0.1:18080`에 연결한다.
이것이 SSH를 거쳐 호스트의 QEMU ဆက်ပို့တန်ဖိုး 포트와 게스트 8080에 연결된다.
SSH의 `-L`은 TCP 전용이다. UDP를 LAN에서 직접 받거나 게스트를 LAN의 독립 IP로 쓰려면
အချက်နောက်တွဲ UDP 중계 또는 TAP/브리지 백엔드 연결이 필요하며 လက်ရှိအချက်အလက်တစ်ခု စက်မောင်း 옵션만으로는 제공하지 않는다.
FTP는 ထိန်းချုပ်တန်ဖိုး 포트뿐 아니라 수동 ဒေတာ စက်ပစ္စည်းဆက်သွယ်ပေါက် 전체도 전달해야 한다.

QEMU를 Ubuntu 가상머신 안에서 실행하는 경우 위의 'အိမ်ရှင် IP'는 그 Ubuntu의 주소다.
Ubuntu를 실행하는 바깥 가상화 프로그램도 해당 IP/SSH 포트에 ဝင်သုံးအချက် 가능한 ကွန်ရက်ဆက် 구성이 필요하다.

## 점검 재현과 အတည်ပြု ဖြတ်နယ်ပယ်

```sh
make test-layers
```

- QMP CPU 0 레지스터: အမိန့်ဝင်း `EL1h`, Java တွက်ချက်မှု `EL0t`.
- 종료된 Java 프로그램의 `ps` အချက်တန်ဖိုး အချက်ဖယ်ရှား.
- Java GUI의 다른 အဆုံးသုံးမျက်နှာပြင် အလှည့်ပြောင်းနည်းစနစ် 후 별도 PID 및 `SUSPENDED` 상태를 `ps`와 `top`에서 အတည်ပြု.
- ကွန်ရက်တံခါးပေါက် ICMP 왕복, FTP အတန်းတန်ဖိုး 업로드.
- 독립 အိမ်ရှင် 상대와 TCP/UDP 발신, 명시적 စက်ပစ္စည်းဆက်သွယ်ပေါက် 전달을 통한 TCP/UDP တန်ဖိုးလက်ခံရယူ 및 ဒေတာ 비교.
- ထွက်ပရိုဂရမ် 시 이번 점검이 만든 QEMU만 정리.

결과는 [보고서](build/verification/execution-network-review/report.json)와
[အစဉ်ဆက်တန်ဖိုး မှတ်တမ်းတန်ဖိုး](build/verification/execution-network-review/serial.log)에 저장한다.
보고서에 사용한 အူတိုင်တန်ဖိုး SHA-256과 원시 QMP 레지스터를 남긴다.
최초 시도에서는 지원하지 않는 GUI 소스의 게스트 재컴파일 단계가 실패했고,
`initial-attempt-report.json`/`initial-attempt-serial.log`에 기록을 보관했다.
탑재된 GUI အတန်းတန်ဖိုး 사용으로 점검 절차를 수정한 후 ထိပ်တန်ဖိုး 항목은 အားလုံးတည်ဆောက် 통과했다.

이번 တကယ့်ဒေတာ ဆက်သွယ်မှု 검증의 범위는 **게스트와 QEMU 밖의 독립 အိမ်ရှင် ပရိုဂရမ် 사이**တတိယအော်ပရန်း.
별도 물리 PC, 공인 인터넷 ဦးတည်ရာအဆုံးမှတ်, SSH 터널, တကယ့်ဒေတာ Pi 4 Ethernet에서의 송수신은 시험하지 않았다.
အူတိုင်တန်ဖိုး 셸을 သုံးစွဲသူ 셸로 이식하거나 일반 프로세스 스케줄러를 추가한 변경은 아니다.
