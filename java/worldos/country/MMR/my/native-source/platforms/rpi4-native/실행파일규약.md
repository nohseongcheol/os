# ELF 형식과 Linux စက်မောင်း ဖိုင် 호환성

**ELF는 확장자가 아니다.** Executable and Linkable Format이라는 바이너리
형식이며, Linux 외의 운영체제도 사용한다. ပထမအချက်အလက်တစ်ခု 네 ဘိုက်တန်ဖိုး `7f 45 4c 46`,
ELF အတန်းတန်ဖိုး, CPU အမျိုးအစားတန်ဖိုး, ပရိုဂရမ် 헤더와 အချက်အမှတ်တစ်ခုတန်ဖိုး 주소를 읽어서 해석한다.
[ELF ABI သတ်မှတ်စံ](https://gabi.xinuos.com/elf/02-eheader.html)

기존 jkoros 로더도 တကယ့်ဒေတာ ELF64/AArch64 စက်မောင်း 파일을 읽었다. `.elf`는 예제의
이름일 뿐이었다. 다만 **ELF ပုံစံတန်ဖိုး 지원과 Linux 시스템 ခေါ်လုပ် ABI 지원은 별개**တတိယအော်ပရန်း.
기존에는 `JKOROS` ABI note를 가진 ကိုယ်ပိုင် စက်မောင်း 파일만 허용했고, Linux 바이너리는
호환되지 않았다. ARM64 Linux는 SVC의 x8에 Linux 시스템 ခေါ်လုပ် 번호를 넣는다.
같은 번호를 ကိုယ်ပိုင် ABI로 해석하면 다른 동작이 되므로 두 경로를 구분한다.
[Linux syscall ABI ရှင်းလင်းချက်](https://man7.org/linux/man-pages/man2/syscall.2.html)

## 이번 반영

| ဝင်ဒေတာ | စက်မောင်း 방법 | ထောက်ပံ့မှုတန်ဖိုး ဖြတ်နယ်ပယ် |
|---|---|---|
| ကိုယ်ပိုင် ABI의 ARM64 ELF | `./နှုတ်ဆက်`, `/အလုပ်/နှုတ်ဆက်`, `run နှုတ်ဆက်` | 확장자 없이 စက်မောင်း; 내용이 ELF이면 `.txt`라는 이름도 동일 |
| Linux ARM64 တည်ငြိမ်တန်ဖိုး ELF | `run --linux 리눅스인사 한글인수` | အောက်ဆုံးတန်ဖိုး 시스템 ခေါ်လုပ်·လိပ်စာ·အရွယ် 제한을 만족하는 ပရိုဂရမ် |
| 텍스트를 `.elf`로 이름만 တန်ဖိုးပြောင်း | စက်မောင်း တန်ဖိုးငြင်းပယ် | 확장자로 စက်မောင်း 파일을 인정하지 않음 |
| x86/x86-64, ARM32 စက်မောင်း ဖိုင် | စက်မောင်း တန်ဖိုးငြင်းပယ် | AArch64 전용이며 CPU စက်ညွှန်ကြားချက်တန်ဖိုး ဘာသာပြန်စက်ကိရိယာတစ်ခု 없음 |
| 일반 glibc/musl ပရိုဂရမ်, PIE, 공유 စာကြည့်တိုက် | 아직 미지원 | 동적 로더·재배치·TLS·mmap·시그널 등 အချက်နောက်တွဲ 이식 필요 |

ကိုယ်ပိုင် 바이너리와 JAR의 အမိန့်ဝင်း 직접 실행은 ဖိုင် 헤더로 구분한다. `run`은 ကိုယ်ပိုင် ELF,
`run --linux`는 명시적으로 Linux ABI를 선택한다. Linux 바이너리를 자동으로
ကိုယ်ပိုင် ABI에 넣지 않으며, ကိုယ်ပိုင် ABI note가 있는 파일은 Linux 모드에서 거부한다.
လက်ရှိအချက်အလက်တစ်ခု RAM ဖိုင် 체계에는 စက်မောင်း ခွင့်ပြုချက်တန်ဖိုး 비트와 `chmod`, PATH 검색이 없다.

게스트 C မူရင်းကုဒ်ဘာသာပြန် 예:

```text
cc နှုတ်ဆက်.c -o နှုတ်ဆက်
./နှုတ်ဆက်
run နှုတ်ဆက်
```

`posix-kor`는 이 ကိုယ်ပိုင် ABI 경로로 연결한다. 일반 Linux에서 링크한 프로그램에
မြန်မာ လုပ်ဆောင်ချက် 이름을 붙이는 것만으로 ကိုယ်ပိုင် ABI 호환이 되는 것은 아니다.

## 제한된 Linux ABI

이 기능은 **ကိုယ်ပိုင် Java အူတိုင်တန်ဖိုး 안의 호환 အလွှာတန်ဖိုး**이며 Linux 커널을 적재하지 않는다.

| Linux ခေါ်လုပ် | နံပါတ် | လက်ရှိအချက်အလက်တစ်ခု 제약 |
|---|---:|---|
| read / write / close / lseek | 63 / 64 / 57 / 62 | RAM 파일과 표준 အဝင်အထွက်; ဝင်ဒေတာ 대기는 EAGAIN 가능 |
| openat / unlinkat | 56 / 35 | AT_FDCWD 또는 절대 လမ်း; 파일만, 제한된 အလံများတန်ဖိုး |
| ftruncate / fsync | 46 / 82 | RAM ဖိုင်; fsync가 영속 저장을 의미하지 않음 |
| exit / exit_group | 93 / 94 | လက်ရှိအချက်အလက်တစ်ခု ပရိုဂရမ် ထွက်ပရိုဂရမ် |
| brk | 214 | ကိုယ်ပိုင် သုံးစွဲသူ ပုံတင်မှတ်ဉာဏ်တန်ဖိုး ဖြတ်နယ်ပယ်; မအောင်မြင်မှု 시 ယခင်အချက်အလက်တစ်ခု break ပြန်ပေးရလဒ် |
| clock_gettime | 113 | CLOCK_MONOTONIC만, မီလီစက္ကန့် ကြည်လင်ပြတ်သားမှုတန်ဖိုး |
| getpid / gettid | 172 / 178 | 한 သုံးစွဲသူ စက်မောင်း 흐름의 သတ်မှတ်နံပါတ်တန်ဖိုး |

미지원 번호는 `-ENOSYS`를 반환한다. Linux ABI의 socket, fork/clone/execve,
pthread, mmap, signal, ioctl, fstat, 동적 로더와 일반 libc 초기화는 구현하지
않았다. 기존 ကိုယ်ပိုင် POSIX/Java 소켓은 별도로 TCP/UDP를 지원한다.

အစဦးအခြေအနေ 스택에는 argc, UTF-8 argv, 빈 envp, AT_PAGESZ/AT_ENTRY/AT_NULL을 넣는다.
입력은 ELF64 little-endian AArch64 **ET_EXEC**, ဖိုင် 전체 **16 KiB 이하**,
PT_LOAD 주소는 **0x02000000 이상 0x02c00000 미만**이어야 한다.
ဖိုင် 오프셋과 가상 주소의 페이지 ညှိတန်ဖိုး 관계를 검사하며, 서로 페이지를 공유하는
세그먼트와 ရေး·စက်မောင်း 동시 허용은 거부한다. PT_INTERP/PT_DYNAMIC/PT_TLS와
ET_DYN은 아직 받지 않는다.

일반 Linux 바이너리의 မူလသတ်မှတ်တန်ဖိုး 적재 လိပ်စာ 0x00400000은 커널과 겹치므로 아직 받지
않는다. 예제는 GNU 링커의 `-Ttext-segment=0x02000000 -z max-page-size=4096`을
사용한다. 이 파일도 정상적인 Linux ELF이며 같은 파일이 Linux와 ကိုယ်ပိုင် 커널에서
실행됨을 시험한다. ဖိုင် 이름이나 헤더만 바꿔 기존 Linux ပရိုဂရမ် 전체를 지원할
수는 없다.

## တကယ့်ဒေတာ 동일 바이너리 비교 စမ်းသပ်မှု

```sh
cd /home/user/jkoros/platforms/rpi4-native
make test-elf
```

시험은 `ဥပမာ/리눅스ABI/လုပ်ဆောင်.S`와 `နှုတ်ဆက်.c`를 Linux AArch64 대상으로 컴파일해,
**JKOROS note가 없는 확장자 없는 စက်မောင်း ဖိုင်** `build/verification/elf/리눅스인사`를
만든다. 같은 바이트를 နောက်တစ်ခုအချက်အလက်တစ်ခု 두 경로로 실행한다.

```sh
qemu-aarch64 build/verification/elf/리눅스인사 한글인수
python3 ကိရိယာစု/ဖိုင်လုပ်ဆောင်.py --linux build/verification/elf/리눅스인사 한글인수
```

ပထမအချက်အလက်တစ်ခု 명령은 Linux 시스템 호출을 사용하는 စီမံကိန်းအမြစ် 실행이고, 두 번째는 Linux를
적재하지 않은 raspi4b ကိုယ်ပိုင် အူတိုင်တန်ဖိုး 실행이다. ဟန်ဂုစာသား အချက်များ, ဖိုင် အဝင်အထွက်, နာရီ, ထွက်ပရိုဂရမ်,
အူတိုင်တန်ဖိုး လိပ်စာ ဝင်သုံးအချက် 거부를 비교한다. FTP로 같은 파일을 올려 실행하는 시험도 있다.
မှတ်တမ်းမှတ်တမ်းတစ်ခု: `build/verification/elf/report.json`, `readelf.txt`, `serial.log` 및 FTP 보고서.

일반 Linux 프로그램까지 지원하려면 별도 သုံးစွဲသူ လိပ်စာ သတ်မှတ်လိပ်စာနယ်, 더 큰 영속 VFS,
전체 စက်မောင်း အစပြင်ဆင်/auxv, 동적 링커와 재배치, mmap/TLS/시그널/스레드,
시스템 ခေါ်လုပ် 및 libc 호환성을 확장해야 한다. 이번 구현은 ပထမအချက်အလက်တစ်ခု 제한된 စက်မောင်း 경로다.
