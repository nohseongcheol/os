# ကိုယ်ပိုင် ARM64 커널의 Codex တန်ဖိုးတပ်ဆင် 가능성 검토

검토일: 2026-10-05. 소스와 공식 문서를 대조한 설계 검토이며, 게스트에 Codex를 설치하거나
로그인·모델 호출을 실행한 결과는 아니다. ကိုယ်ပိုင် ARM64 커널과 `../rpi4` Linux 실행판은 구분한다.

လက်ရှိအချက်အလက်တစ်ခု ကိုယ်ပိုင် 커널에는 공식 Codex CLI를 그대로 တန်ဖိုးတပ်ဆင်·실행할 ကိန်းတန်ဖိုး 없다.
기술적으로 필요한 စက်မောင်း 환경을 추가하거나 Codex를 이식하는 경로는 있으나,
다운로드 အမိန့် 하나를 추가하는 작업으로 해결되지 않는다. JDK/JRE 기능 확장만으로도 해결되지 않는다.

## 확인한 근거

| အချက်တန်ဖိုး | လက်ရှိအချက်အလက်တစ်ခု 소스에서 확인한 အခြေအနေတန်ဖိုး | 직접 실행을 위한 အလုပ် |
|---|---|---|
| စက်မောင်း ဖိုင် | `စက်/သုံးစွဲသူ.c`: AArch64 ET_EXEC만, PT_INTERP/PT_DYNAMIC/PT_TLS တန်ဖိုးငြင်းပယ်, 업로드 စက်မောင်း 버퍼 16384바이트 | ဦးတည်ချက်တန်ဖိုး 바이너리에 맞는 ELF 적재·재배치·စက်မောင်း အစပြင်ဆင်, မှတ်ဉာဏ်ဒေတာ/ဖိုင် ကန့်သတ်ချက်တန်ဖိုး တိုးချဲ့မှု |
| Linux ABI | `စက်/리눅스호환.inc`: read/write/openat/brk 등 제한된 번호만 လုပ်ငန်းစဉ်တန်ဖိုးအချက်, 나머지는 ENOSYS | libc/런타임에 필요한 시스템 호출을 추가하거나 ကိုယ်ပိုင် ABI용 런타임 이식 |
| 프로세스·스레드 | 일반 fork/clone/execve, pthread/futex, 시그널, mmap, poll/epoll 계열이 미완성 | 비동기 I/O·스레드·သားသမီးတန်ဖိုး အမိန့် စက်မောင်း·ထွက်ပရိုဂရမ်/ပယ်ဖျက်လုပ်ငန်း 기능 |
| ဖိုင် | `မူရင်းကုဒ်/မှတ်ဉာဏ်ဖိုင်.java`: RAM ဖိုင် 64개, 파일당 16 KiB, 비영속 | 큰 စက်မောင်း ဖိုင်·프로젝트·သတ်မှတ်ချက်·세션을 위한 영속 VFS, ဖိုင် ခွင့်ပြုချက်တန်ဖိုး·လမ်း·디렉터리 တိုးချဲ့မှု |
| ကွန်ရက်ဆက် | lwIP TCP/UDP는 있으나 `ကွန်ရက်အလွှာစု/lwipopts.h`의 LWIP_DNS=0, 일반 HTTPS 클라이언트 없음 | DNS, TLS 인증서 မှန်ကန်ကြောင်းစစ်·신뢰 저장소·정확한 시각, HTTPS/스트리밍 |
| အဆုံးသုံးမျက်နှာပြင်·ကိရိယာစု | ကိုယ်ပိုင် 셸과 GUI 터미널은 있지만 표준 PTY·일반 프로세스 အလုပ် ထိန်းချုပ်တန်ဖိုး 없음 | အပြန်အလှန် CLI용 အဆုံးသုံးမျက်နှာပြင် 기능, အမိန့်ဝင်း/ဖိုင် 검색/တည်ဆောက် ကိရိယာစု ချိတ်ဆက် |
| စက်မောင်း ခွင့်ပြုချက်တန်ဖိုး | EL0 보호는 있으나 Codex의 Linux 샌드박스와 같은 정책 집행 ဝန်းကျင် 없음 | ဖိုင်·ကွန်ရက်ဆက်·အမိန့် ခွင့်ပြုချက်တန်ဖိုး 정책과 승인 기능; ကိုယ်ပိုင် 커널에 맞는 격리 အကောင်အထည်ဖော်မှု |

여기서 ELF의 PT_TLS는 스레드별 သိုလှောင်တန်ဖိုး 공간이다. HTTPS의 TLS စကားဝှက်တန်ဖိုး 통신과 서로 다른 기능이다.
ELF ဖိုင် 형식을 읽을 ကိန်းတန်ဖိုး 있다는 사실만으로 Linux စက်မောင်း 환경을 제공하는 것은 아니다.
SSH/VNC를 위한 စကားဝှက်တန်ဖိုး 라이브러리를 넣은 상태도 HTTPS အကောင်အထည်ဖော်မှု 완료를 의미하지 않는다.

호스트의 `/home/user/.local/bin/codex`도 확인했다. 이것은 x86-64 ELF ET_DYN이며 약 209 MiB다.
해당 파일을 ARM64 게스트로 복사하여 실행할 ကိန်းတန်ဖိုး 없다. 이 크기를 ARM64 ဖြန့်ချိမှုတန်ဖိုး 파일의 크기로
해석하지 않는다. 공식 ARM64 빌드의 တကယ့်ဒေတာ အရွယ်·의존성은 설치할 버전으로 အချက်နောက်တွဲ 검사해야 한다.

## 가능한 အကောင်အထည်ဖော်မှု လမ်း

1. **ကိုယ်ပိုင် 커널에 공식 CLI 직접 이식**
   영속 သိုလှောင်တန်ဖိုး/VFS와 သုံးစွဲသူ မှတ်ဉာဏ်ဒေတာ, 프로세스·스레드·I/O, libc/런타임, DNS/HTTPS,
   အဆုံးသုံးမျက်နှာပြင်·ခွင့်ပြုချက်တန်ဖိုး 체계를 갖춘다. 이후 ဦးတည်ချက်တန်ဖိုး 버전의 의존성을 조사하여 크로스 တည်ဆောက်·이식한다.
   Linux 커널을 반드시 탑재할 필요는 없지만, 공식 Linux 바이너리를 그대로 쓸 경우
   그 바이너리가 사용하는 Linux ABI까지 호환해야 한다. 큰 စက်စနစ် ဖွံ့ဖြိုးရေး 과제다.

2. **ပြင်ပတန်ဖိုး အိမ်ရှင် Codex와 ကိုယ်ပိုင် အူတိုင်တန်ဖိုး ချိတ်ဆက် — ပထမအချက်အလက်တစ်ခု 구현으로 권장**
   Linux PC에서 공식 CLI 또는 app-server를 실행하고 jkoros에는 전용 သုံးစွဲသူ အမိန့်/화면을 만든다.
   호스트의 인증된 연결과 게스트 ဖိုင် ဖတ်·수정·업로드·အမိန့် စက်မောင်း 어댑터가 필요하다.
   기존 SSH/TCP 경로를 활용할 ကိန်းတန်ဖိုး 있으나, ဖိုင် 동기화나 Codex 전용 어댑터는 လက်ရှိအချက်အလက်တစ်ခု 구현되어 있지 않다.
   호스트에서 수행한 빌드와 게스트에서 수행한 စက်မောင်း 결과를 명확히 구분한다.
   이 구성은 ကိုယ်ပိုင် 커널을 유지하지만, 공식 CLI 자체는 ပြင်ပတန်ဖိုး 호스트에서 실행된다.

3. **ကိုယ်ပိုင် API 클라이언트 제작**
   ကိုယ်ပိုင် ABI의 C 또는 지원되는 Java 부분집합으로 အပြန်အလှန်အသုံးပြုချိန်ပိုင်း UI와 ဖိုင်/အမိန့် ကိရိယာစု ခေါ်လုပ် 루프를 만든다.
   ပြင်ပတန်ဖိုး 중계기를 쓰지 않는다면 DNS/မှန်ကန်ကြောင်းစစ် 가능한 TLS/HTTPS와 인증 ဒေတာ 저장을 먼저 구현해야 한다.
   이는 OpenAI API를 이용하는 별도 에이전트이며 공식 Codex CLI 전체의 이식으로 표시하지 않는다.

4. **별도 ARM64 Linux 실행판에서 တန်ဖိုးတပ်ဆင်**
   `../rpi4`는 Linux와 musl 기반이므로 일반 Linux တန်ဖိုးတပ်ဆင် 경로를 검토할 ကိန်းတန်ဖိုး 있다.
   사용할 Codex 버전의 ARM64·musl 호환성, 의존성, 커널의 샌드박스 지원을 တကယ့်ဒေတာ 검증해야 한다.
   이번 검토에서 တန်ဖိုးတပ်ဆင် 성공을 확인하지 않았다. 이 결과를 ကိုယ်ပိုင် Java 커널의 지원으로 표시하지 않는다.

## 단계별 ဖြစ်သောအပြည့်အစုံ စီမံကိန်းအမြစ်

- 직접 이식: `--version` လုပ်ဆောင် → 인증/HTTPS → ဖိုင် ဖတ်·수정 → သားသမီးတန်ဖိုး အမိန့် စက်မောင်း →
  အပြန်အလှန် ဝင်ဒေတာ/스트리밍 → ခွင့်ပြုချက်တန်ဖိုး ကန့်သတ်ချက်တန်ဖိုး·ပယ်ဖျက်လုပ်ငန်း → 재부팅 후 သတ်မှတ်ချက်/세션 보존을 각각 တကယ့်ဒေတာ 게스트에서 확인한다.
- အိမ်ရှင် ချိတ်ဆက်: 게스트에서 တောင်းဆိုချက် ဝင်ဒေတာ → အိမ်ရှင် Codex လုပ်ငန်းစဉ်တန်ဖိုးအချက် → 게스트 ဖိုင် တန်ဖိုးပြောင်း အတည်ပြု →
  게스트 javac/cc စက်မောင်း → ရလဒ် 표시를 처음부터 끝까지 검증한다.
- COSL 상업 조건을 유지하려면 새로 도입하는 런타임/ဆက်သွယ်မှု 라이브러리의 라이선스와
  Codex ဖြန့်ချိမှုတန်ဖိုး 버전의 제3자 고지를 검토한다. ပြင်ပတန်ဖိုး 구성요소를 일괄 COSL로 재라이선스하지 않는다.

## 공식 စာတမ်း

- [Codex CLI တန်ဖိုးတပ်ဆင် 및 လှုပ်ရှားမှု](https://learn.chatgpt.com/docs/codex/cli): 표준 Linux/macOS 독립 တန်ဖိုးတပ်ဆင် 경로와 프로젝트 ဖိုင်·အမိန့် အလုပ်.
- [인증](https://learn.chatgpt.com/docs/auth): ChatGPT/API 인증, 헤드리스 장치의 `codex login --device-auth`, HTTPS 인증서 သတ်မှတ်ချက်.
- [샌드박스](https://learn.chatgpt.com/docs/sandboxing): 운영체제별 집행 နည်းလမ်းနည်းစနစ်, Linux의 bubblewrap 및 သုံးစွဲသူ 네임스페이스 လိုအပ်ချက် 사항.
- [공개 구성요소](https://learn.chatgpt.com/docs/open-source): CLI/SDK/app-server의 공개 မူရင်းကုဒ်အပင်ဖွဲ့စည်းပုံ 위치와 비공개 구성요소 ပိုင်းခြားအမှတ်.

공식 문서에는 jkoros를 ထောက်ပံ့မှုတန်ဖိုး 대상으로 명시한 내용이 없다. ထိပ်တန်ဖိုး အကောင်အထည်ဖော်မှု လမ်း·ဖွံ့ဖြိုးရေး 순서는
လက်ရှိအချက်အလက်တစ်ခု 소스와 လိုအပ်ချက် 기능을 대조한 기술적 판단이다.
