# 内置 ARM64 用户 执行命令 ABI v1

이 ABI는 `platforms/rpi4-native`의 제한된 freestanding 执行命令 환경이다. Linux AArch64 ABI나 POSIX 전체 구현이 아니다. **OpenJDK/JRE, CPython, libc, libstdc++는 아직 이식되지 않았다.**

ELF 로더는 文件 확장자 대신 实际数据 ELF 헤더를 검사한다. 底端值 内置 ABI와 별도로 `run --linux FILE`에 제한된 Linux ARM64 静态值 执行命令 文件 경로를 추가했다. 두 시스템 调用 번호표를 혼합하지 않는다. [ELF·Linux ABI 매뉴얼](可执行文件ABI.md).

## ELF와 执行命令 수명

- ELF64 little endian, ET_EXEC, EM_AARCH64, 버전 1, e_flags=0.
- 程序 헤더 最大值 16개. PT_LOAD는 读取 가능, 4 KiB 对齐值, 페이지 간 嵌套值 缺失方法, filesz≤memsz, 构建映像 地址 裁剪 안이어야 한다. W+X는 거부한다.
- 진입점은 文件 내용이 있는 执行命令 세그먼트 안의 4바이트 对齐值 주소다.
- PT_NOTE에 名称 `JKOROS\0`(namesz=7), type=1, descsz=4, 버전 1의 little endian uint32가 필요하다. SDK의 `start.o`首位操作数 넣는다.
- PT_DYNAMIC/PT_INTERP/PT_TLS 등은 거부한다. 동적 재배치·공유 库·TLS 로더가 없다.
- 커널에 포함한 ELF 묶음을 검증하고 별도 用户 메모리에 복사한 后端值 EL0로 진입한다. 커널에 함수로 静态值 링크해 호출하는 上一个项目 `cpp_test`와 다르다.
- 내장 프로그램은 `demo.elf`, `fault.elf`의 8개 保护值 测试 模式值, `network.elf`, 内置 Java 工具集, MicroPython이다. 셸의 `load`/`run FILE`로 RAM의 16KiB 이하 ELF도 같은 有效性校验 경로로 실행한다.
- `_start`首位操作数 `user_start`를 호출하고 `.init_array` → `开始用户程序(int)` → `.fini_array` 순서로 실행한 后端值 exit 호출을 수행한다. 인수는 调用 15로 읽으며 표준 argc/argv/envp 操作数栈 배치는 없다.
- 한 번에 한 用户 프로그램이 CPU에서 실행된다. 네 터미널에 각 하나씩 交互式 프로그램을 일시 정지해 보관할 数 있다. 是否常规 退出程序·异常·时间值 초과 시 커널에 복귀하고 열린 文件/소켓을 닫으며 用户 페이지 권한을 제거한다.
- 静态值 생성자와 자동 객체의 RAII 소멸자를 시험했다. `__cxa_atexit`, 표준 C++ 异常/RTTI/STL, 일반적인 전역 对象值 退出程序 등록은 제공하지 않는다.

## 주소와 保护值

| 가상 地址 裁剪 | 용도 |
|---|---|
| 0x02000000–0x02bfffff | ELF 构建映像, 最大值 12 MiB |
| 0x02c00000–0x02ecffff | brk 堆值, 最大值 2880 KiB |
| 0x02ed0000–0x02efffff | 미매핑 文本范围/操作数栈 底端值 保护值 文本范围 |
| 0x02f00000–0x02ffffff | 1 MiB 用户 操作数栈 |

内置 JVM의 类值·对象值 자료를 수용하도록 用户 창을 16 MiB로 확장했다. 程序 헤더의 允许值 裁剪, 페이지 权限值 检查项, SDK 링커 脚本值 및 保护值 시험이 같은 배치를 사용한다. 기존에 brk 运行 주소를 상수로 가정한 프로그램은 새 SDK로 重试值 빌드한다. 일반 프로그램은 调用 8로 当前项目 brk를 조회한다.

执行命令 코드는 EL0 读取/실행만, 数据·堆值·스택은 EL0 读取/쓰기만 허용한다. 余数值 内核值 RAM·设备 MMIO에는 EL0 권한을 주지 않는다. 이번 W^X 보장은 **用户 페이지에 대한 것**이다. kernel identity map의 전체 权限值 분할이나 다중 프로세스 地址 地址区域 전환을 구현했다고 의미하지 않는다.

커널은 `-mgeneral-regs-only`로 빌드한다. 用户 C/C++는 FP/SIMD를 허용하고, 用户 条目分值 시 向量值 레지스터와 FPCR/FPSR를 초기화한다. 内核值 복귀용 callee-saved FP 상태를 보관한다. syscall/IRQ의 C 처리부는 FP 레지스터를 사용하지 않는다. 향후 여러 用户 스레드를 전환할 때에는 각 스레드의 전체 FP 上下文值 보존을 별도로 구현해야 한다.

GIC-400의 물리 타이머 IRQ로 약 2초의 执行命令 기한을 적용한다. SVC 없는 무한 반복도 종료한다. 시스템 调用 运行 시 기한을 검사하지만 EL1 进程值条目 중에는 IRQ를 마스킹하므로 긴 输出/画图屏幕 호출의 종료는 지연될 数 있다. 이것은 程序 执行命令 기한이며 일반 선점 스케줄러가 아니다.

## 시스템 调用

`svc #0`, 编号 x8, 实参 x0…x5, 结果 x0. 실패는 负数值 错误 번호다. `libposix-kor-user.a`는 이를 -1과 `错误编号`로 바꾼다. 用户 프로그램의 errno는 当前项目 단일 执行命令 흐름용이며 pthread TLS가 아니다.

| 编号 | 调用 | 实参 |
|---:|---|---|
| 0 | ABI 버전 | 缺失方法, 1 发回结果 |
| 1 | write | fd, buffer, count |
| 2 | read | fd, buffer, count |
| 3 | open | NUL 退出程序 路径, flags; mode는 저장하지 않음 |
| 4 | close | 文件 또는 루프백 套接字值 fd |
| 5 | lseek | fd, signed offset, origin |
| 6 | exit | 하위 8비트 退出程序 状态值 |
| 7 | 毫秒 | 启动 之后状态 32비트 카운터; wrap 가능, POSIX clock_gettime 아님 |
| 8 | brk | 0이면 当前项目 结尾, 그 외 새 结尾; 已映射值 扩展名值 시 새 페이지 初始化 |
| 9 | 文件 大小 | fd; fstat ABI 아님 |
| 10 | ftruncate | fd, length |
| 11 | unlink | NUL 退出程序 路径 |
| 12 | fsync | fd; RAM 파일은 ENOSYS |
| 13 | 矩形 | x, y, RGB32 值, width, height |
| 14 | UART 字节值 | 输入值 없음은 -1, POSIX read와 별도 辅助值 调用 |
| 15 | 执行命令 实参 | index, buffer, capacity; index=UINTPTR_MAX이면 项目个数, 나머지는 UTF-8 长度 发回结果 및 NUL 退出程序 复制值 |
| 16 | 交互式 tty | 0: 运行/当前项目 行值·列值 发回结果, 1: 输入值 等待状态值(数据 缺失方法 -11), 2: 退出程序, 3: 当前项目 大小 查询值(상위 16비트 行值, 하위 16비트 列值) |
| 17 | 협력 等待状态值 | 毫秒(0~100); 通信·FTP를 처리하며 CPU 기한 刷新 |
| 18 | 路径 任务 | NUL 退出程序 路径, 动作(0: 种类值, 1: mkdir, 2: rmdir); 种类值 0: 缺失方法, 1: 文件, 2: 目录值 |
| 20 | GUI 元素值 | 动作, 元素值 编号, 值 4개; 内置 Swing peer 전용 |
| 21 | GUI 文本 | 元素值 编号, uint32 코드포인트 数组值, 长度(≤127) |
| 22 | 屏幕 大小 | x0=0: 实际数据 宽度值, x0=1: 实际数据 高度值; 다른 값은 -EINVAL, 屏幕 없음은 -ENODEV |
| 32 | socket | domain, type, protocol |
| 33 | bind | fd, sockaddr, address length |
| 34 | sendto | fd, buffer, count, flags, sockaddr, address length |
| 35 | recvfrom | fd, buffer, count, flags, peer sockaddr, length pointer |
| 36 | getsockname | fd, sockaddr, length pointer |
| 37 | connect | 연결형 fd, sockaddr, address length |
| 38 | listen | 연결형 fd, backlog; 实际数据 等待状态值 最大值 4개 |
| 39 | accept | 연결형 fd, 0, 0; peer 地址 반환은 아직 缺失方法 |

是否不支持 호출은 -ENOSYS이다. 모든 用户 포인터와 해당 페이지의 读取/写入 권한을 확인한다. 파일은 3…18의 프로세스별 서술자를 内核值 서술자로 변환한다. 0은 当前项目 셸의 표준 输入值(UART 또는 리다이렉션/파이프), 1은 표준 输出(UART/GUI 또는 리다이렉션/파이프), 2는 UART/GUI 诊断值 출력이다. UART에 읽을 자료가 없으면 -EAGAIN, 文件/파이프 输入值 끝이면 read가 0을 반환한다. 출력은 文件/파이프에서 LF를 그대로 유지하고 UART에서만 CRLF로 표시한다. 파이프는 16 KiB 순차 버퍼이며 프로세스 간 동시 파이프/PTY는 아니다. read/write 요청은 65536바이트 이하이며, RAM 파일은 最大值 64개, 각각 16384바이트다. 文件 경로는 当前项目 命令壳 경로에 대한 对端值 路径 또는 `/`로 시작하는 절대 경로이며 UTF-8 63바이트까지다. 디렉터리 生成·빈 目录值 移除条目·种类值 조회는 调用 18로도 제공한다. 当前项目 路径 변경은 命令壳 내장 cd가 담당한다. 그래픽 요청은 调用 22로 조회한 实际数据 屏幕 大小 안의 직사각형만 허용한다. 프레임버퍼 地址 자체는 사용자에게 노출하지 않는다.

힙의 페이지 单位值 축소·재확장에서 重试值 노출하는 페이지는 0으로 만든다. 같은 페이지 안에서 brk만 줄였다 늘리는 경우에는 해당 페이지 내용이 남을 数 있다. malloc/free나 mmap/mprotect의 구현은 아니다.

인수는 最大值 8개·각 255바이트다. 잘못된 번호는 -EINVAL, 작은 버퍼는 -ENAMETOOLONG, 写入 불가능한 포인터는 -EFAULT다. `run FILE [ARGS]`는 파일명을 实参 0으로 포함한다. `javac`/`java`/`python`은 指令值 자체를 제외한 토큰을 전달한다. 인수는 内核值 保留值 자료를 用户 버퍼로 복사하며 内核值 포인터를 반환하지 않는다.

## UDP 루프백의 계약

바깥 IPv4는 lwIP/SLIP로 확장했다. 기존 fd/구조체/指针 检查项 규약을 유지하며 0.0.0.0 또는 10.0.2.15에 bind한 끝점을 바깥 통신에 연결한다. 127.0.0.1에 명시적으로 bind한 UDP는 루프백에 한정한다. 外部值 TCP connect는 비차단 -EINPROGRESS(-115)를 반환할 数 있으므로 같은 주소로 재시도하여 완료를 확인한다. [执行命令/限制值](文件传送与编译过程.md).

`互联网族`, `数据报套接字`, 传送协议 0/`数据报协议`을 허용한다. `struct 互联网套接字地址`는 16바이트이며 주소갈래는 设备 序列值, 접속번호와 互联网地址.주소값은 网络值 차례다. 호환용 pk_sockaddr_in도 같은 배치지만 독립 자료형이다. 中文 함수는 직접 SVC를 호출하는 实际数据 함수이며 표준 이름으로 치환하는 매크로가 아니다. 宿主 Linux 헤더를 섞지 않는다.

- 목적지는 127.0.0.1만 允许值. bind는 0.0.0.0 또는 127.0.0.1, port=0이면 49152…65535에서 빈 창구를 고른다.
- 미바인드 소켓의 首位项目 전송은 临时值 창구를 바인드한다. 같은 창구의 중복 bind는 EADDRINUSE.
- 最大值 8개 套接字值, 각 큐 4개, 전문은 0…512바이트. 빈 전문도 소비된다.
- 接收值 버퍼가 작으면 복사할 부분만 반환하고 전문의 나머지는 버린다. peer 地址/창구를 반환한다.
- flags는 当前项目 0만 支持值. 비차단 수신의 빈 큐 및 发送值 目标值 큐 포화는 EAGAIN이다.
- 目标值 端口值 없음은 ECONNREFUSED, 512바이트 초과는 EMSGSIZE, 루프백에 명시적으로 바인드한 UDP의 外部值 IP는 ENETUNREACH, UDP 소켓에 잘못된 규약을 지정하면 EPROTONOSUPPORT. SOCK_STREAM은 별도 연결형 루프백에서 제공한다.
- 外部值 IPv4 TCP/UDP 헤더·체크섬·재전송은 lwIP가 처리한다. 实际数据 GENET/Wi-Fi NIC, poll/select, setsockopt는 아직 없다. 연결형 루프백의 connect/listen/accept는 底端值 扩展名值 ABI로 제공한다.

## 커널로 돌아오는 结果

Java의 `板.运行用户程序(index)`는 是否常规 exit 状态值 0…255 또는 下一项目 값을 받는다. GUI는 실패를 표시하고 셸을 유지한다.

| 值 | 의미 |
|---:|---|
| -8 | ELF/ABI/地址/权限值 有效性校验 失败值 |
| -16 | 用户 程序 嵌套值 执行命令 拒绝值 |
| -22 | 등록되지 않은 程序 编号 |
| -1001 | 用户 数据 存取条目 异常 |
| -1002 | 用户 指令值 存取条目 异常 |
| -1003 | 특권/是否不支持 命令 등 用户 异常 |
| -1004 | 用户 执行命令 기한 초과 |
| -1005 | 交互式 用户 程序 일시 停机执行状态; 内核值 命令壳 전용 结果 |

이는 완성된 POSIX signal/wait 상태가 아닌 当前项目 内置 실행기의 诊断值 규약이다.


## 여러 터미널의 用户 上下文值

交互式 tty/GUI 대기를 명시적으로 시작한 프로그램은 输入值 대기에서 약 2초 기한을 갱신한다. 等待状态值 없이 무한 반복하면 타이머로 종료한다. 파이프/리다이렉션/복합 命令/스크립트에서 交互式 시작은 -ENOTSUP로 거부한다. vi와 Swing의 이벤트 루프가 이 API를 사용한다.

다른 창으로 전환하면 下一项目 等待状态值 SVC에서 EL0 문맥을 저장하고 해당 SVC를 재실행할 위치에서 재개한다. x0…x30, SP/PC/PSTATE, v0…v31, FPCR/FPSR, 已映射值·堆值·执行命令 实参·文件/套接字值 소유권을 보관한다. 스냅샷은 内核值 전용 물리 地址 0x04000000…0x07ffffff(네 槽值 ×16 MiB)에 저장한다. 当前项目 活跃 EL0 地址 창은 종전 0x02000000…0x02ffffff를 사용한다. 스냅샷 저장소는 EL0에서 접근할 数 없다. fork/exec/wait, SMP 또는 일반 선점형 프로세스 스케줄러의 구현은 아니다.

SVC 40은 소유한 연결형 소켓의 对端值 硬件端口 번호를 반환한다(内置 JVM용 整数 查询值).

연결형 루프백 fd는 40…55, UDP fd는 32…39다. 退出程序/终端 X 닫기에서 해당 프로그램의 文件·소켓을 회수한다. 연결형 읽기의 数据 없음은 -EAGAIN, 상대가 닫고 버퍼도 비면 0, 상대가 닫힌 后端值 쓰기는 -EPIPE다. 쓰기는 짧게 완료될 数 있다. 큐 용량은 끝점마다 1024바이트이고 한 시스템 호출은 最大值 512바이트를 옮긴다. 父值 리스너를 닫으면 아직 accept하지 않은 연결도 회수한다. 外部值 연결은 lwIP TCP를 사용하며 外部值 接收值 버퍼는 4096바이트다. 实际数据 GENET NIC 드라이버는 없다.

협력 等待状态值(17)는 일반 선점형 sleep/scheduler 구현이 아니다. 호출마다 最大值 100 ms 동안 통신을 처리하고 用户 执行命令 기한을 갱신한다. 软件包 설치기의 비차단 TCP 대기에 사용한다.
