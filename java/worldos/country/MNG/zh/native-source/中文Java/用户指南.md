# jkoros 中文 库 用户指南

확인일: 2026-09-27. 대상은 `platforms/rpi4`의 **ARM64 Linux + OpenJDK 실행판**이며, QEMU에서도 같은 Java 라이브러리를 사용한다. `os/`의 内置 x86 内核值 및 `基础源代码/`의 관리 内核值 모형과 구분한다.

## 1. 当前项目 제공하는 库

패키지는 `中文.Java`, 操作系统 안의 JAR 경로는 `/opt/jkoros/lib/中文Java.jar`第三操作数. **辅助器值 类值 5개, 공개 静态值 方法值 22개, 별도 GUI 프로그램인 工作区 1개**首位操作数 있다. JAR는 Java 11 이상을 대상으로 빌드하며 当前项目 ARM64 배포판에는 OpenJDK 25가 포함돼 있다.

| 类值 | 方法值 数 | 기능 | 源代码 |
|---|---:|---|---|
| `文件` | 9 | UTF-8 텍스트·字节值 文件, 目录值, 条目列表 | [文件.java](源代码/中文/Java/文件.java) |
| `字符` | 5 | UTF-8 转换值, NFC 正规化值, 代码值 포인트, 字符串 边界位置值 | [字符.java](源代码/中文/Java/字符.java) |
| `通信` | 2 | HTTP(S) GET, TCP 连接 | [通信.java](源代码/中文/Java/通信.java) |
| `任务` | 4 | 스레드 执行命令·等待状态值, 고정 大小 任务 运行器 | [任务.java](源代码/中文/Java/任务.java) |
| `屏幕` | 2 | Swing 이벤트 进程值条目 가닥에 任务 예약, 窗口 生成 | [屏幕.java](源代码/中文/Java/屏幕.java) |
| `工作区` | 条目分 `main` | Java 源代码 编辑值·存储值·编译源代码·执行命令 | [工作区.java](源代码/中文/Java/工作区.java) |

표준 JDK 전체를 한국어로 번역한 라이브러리는 아니다. Java 키워드와 `String`, `Path`, `Socket`, `JFrame`, `IOException` 같은 표준 数据类型·예외를 함께 사용한다. 이 도우미에 없는 기능은 OpenJDK의 표준 API 또는 별도 라이브러리로 구현한다. 예를 들어 HTTP POST, UDP, Swing 按钮·메뉴에는 각각 표준 Java API를 사용한다.

## 2. Java에서 开始任务

게스트 운영체제의 任务 폴더에서 `사용예.java`를 작성한다.

```java
import 中文.Java.*;
import java.nio.file.Path;

public class 사용예 {
    public static void main(String[] 实参) throws Exception {
        Path 目录值 = 文件.创建目录(文件.路径("사용예자료"));
        Path 文档集 = 目录值.resolve("问候例.txt");
        文件.写入(文档集, "韩文文本 😀");
        String 内容值 = 文件.读取(文档集);
        System.out.println(内容值);
        System.out.println(字符.代码分个数(内容值)); // 한, 文本, 공백, 😀 → 4
        Thread 工作值 = 任务.运行("问候例 任务", () -> System.out.println("任务 执行命令"));
        任务.等待(工作值);
    }
}
```

```sh
javac -encoding UTF-8 -cp /opt/jkoros/lib/中文Java.jar 사용예.java
java -cp .:/opt/jkoros/lib/中文Java.jar 사용예
```

로그인 환경에 默认值 `CLASSPATH`도 설정돼 있지만, 명시적인 `-cp`는 다른 执行命令 환경에서도 경로를 분명하게 한다. 사용자가 `-cp`를 지정하면 필요한 JAR와 类值 폴더를 构建全部 그 값에 포함해야 한다.

宿主 저장소에서는 다음처럼 构建系统·실행한다. 宿主 경로와 게스트의 `/opt/...` 경로는 서로 다르다.

```sh
cd /home/user/jkoros/中文Java
make
javac -encoding UTF-8 -cp build/中文Java.jar 用例/问候例.java
java -cp build/中文Java.jar:用例 问候例
```

## 3. 전체 辅助器值 API

底端值 메서드는 构建全部 `public static`이며, 객체를 만들지 않고 `文件.读取(...)`처럼 호출한다. 표의 이름은 实际数据 源代码树 및 JAR의 `javap -public` 결과와 대조했다. 선언된 检查项 异常 외에도 잘못된 实参 등에 대한 표준 Java 执行命令 시 예외가 발생할 数 있다.

### 文件: `中文.Java.文件`

`Path`는 `java.nio.file.Path`, `List`는 `java.util.List`第三操作数.

| 方法值 | 发回类型 | 动作·条件 |
|---|---|---|
| `路径(String 名称)` | `Path` | 이름을 路径 객체로 转换值. 实际数据 파일을 만들지는 않음 |
| `读取(Path 路径)` | `String` | 文件 전체를 UTF-8 텍스트로 读取结果 |
| `写入(Path 路径, String 内容值)` | `Path` | UTF-8 存储值. 파일이 없으면 생성하고, 있으면 기존 내용을 비움 |
| `读取字节值(Path 路径)` | `byte[]` | 文件 전체를 字节值 배열로 读取结果 |
| `写入字节值(Path 路径, byte[] 内容值)` | `Path` | 字节值 存储值. 없으면 생성하고, 있으면 기존 내용을 비움 |
| `创建目录(Path 路径)` | `Path` | 필요한 상위 폴더까지 生成 |
| `是否执行存在(Path 路径)` | `boolean` | 존재 여부 验证. 확인할 数 없는 경우도 `false`工作值 数 있음 |
| `擦除条目(Path 路径)` | `boolean` | 삭제했으면 `true`, 없으면 `false`. 폴더의 재귀 삭제는 아님 |
| `条目列表(Path 路径)` | `List<Path>` | 바로 底端值 항목을 路径 对齐值 순서로 发回结果. 재귀 탐색은 아님 |

`路径`, `是否执行存在`를 제외한 顶端值 메서드는 `IOException`을 선언한다. `写入`와 `写入字节值`는 상위 폴더를 자동으로 만들거나 내용을 继续状态值 쓰지 않는다. 필요한 폴더는 먼저 생성한다. 큰 파일은 전체 내용을 메모리에 담는 대신 표준 Java 스트림·信道值 API를 사용하는 방식으로 작성할 数 있다.

### 字符: `中文.Java.字符`

| 方法值 | 发回类型 | 动作·条件 |
|---|---|---|
| `编码(String 内容值)` | `byte[]` | 문자열을 UTF-8 바이트로 转换值 |
| `解密数据(byte[] 内容值)` | `String` | UTF-8 바이트를 문자열로 转换值. 잘못된 입력은 대체 문자로 进程值条目 |
| `正规化值(String 内容值)` | `String` | Unicode值 NFC 正规化值. 예: 组合 字母构件值 `ᄀ` + `ᅡ` → `首位操作数` |
| `代码分个数(String 内容值)` | `int` | UTF-16 代码值 단위가 아닌 Unicode值 代码值 포인트 数 |
| `词法用机器字(String 内容值, Locale 语言)` | `List<String>` | 赋值值 언어의 `BreakIterator` 词法用机器字 경계로 나눈 文本范围 |

`词法用机器字`은 공백·문장부호 구간도 반환한다. 자연어 형태소 분석기나 공백을 제거한 机器字值 条目列表 API는 아니다. `正规化值`는 입력기나 翻译源代码 기능이 아니다. 代码值 포인트 数 역시 사람이 보는 字符值 수와 항상 같지는 않다. 여러 代码值 포인트로 이루어진 合并值列 字符·가족 이모지 등을 구분해야 한다.

### 通信: `中文.Java.通信`

| 方法值 | 发回类型 | 动作·条件 |
|---|---|---|
| `取用值(URI 地址, Duration 时间限制)` | `HttpResponse<String>` | HTTP(S) GET. 连接 및 申请 时间限制 设置. 回复 본문을 UTF-8로 解析值 |
| `连接端点(String 地址, int 硬件端口, int 限制毫秒)` | `Socket` | TCP 连接 之后状态 같은 값으로 读取 제한시간도 设置 |

`取用值`는 `IOException`, `InterruptedException`을 선언한다. 제한시간은 양수다. 404·500 같은 HTTP 错误 상태도 응답으로 반환하므로 `statusCode()`로 판단하고 `body()`로 본문을 읽는다. 当前项目 구현은 호출마다 HTTP 클라이언트를 만들며 자동 리다이렉트 설정을 추가하지 않는다.

`连接端点`는 `IOException`을 선언한다. 연결된 소켓은 호출자가 `close()` 또는 try-with-resources로 닫아야 한다. 제한밀리초의 0은 限制值 없음이며, 写入 전체의 截止时间值 시간을 보장하는 옵션은 아니다.

```java
var 回复 = 通信.取用值(
    java.net.URI.create("http://127.0.0.1:8000/"),
    java.time.Duration.ofSeconds(5));
System.out.println(回复.statusCode());
System.out.println(回复.body());
```

顶端值 조각은 方法值 안에서 실행하며 별도로 해당 주소의 서버를 실행해야 한다. Java 异常 처리가 필요하다.

### 任务: `中文.Java.任务`

| 方法值 | 发回类型 | 动作·条件 |
|---|---|---|
| `运行(String 名称, Runnable 动作)` | `Thread` | 이름을 지정한 스레드를 만들고 즉시 运行 |
| `等待(Thread 线程值)` | `void` | 해당 스레드가 종료할 때까지 `join()` |
| `剩余部分短暂地(long 毫秒)` | `void` | 호출한 스레드를 赋值值 时间值 동안 `sleep()` |
| `工作台值(int 线程个数)` | `ExecutorService` | 고정 大小 任务 运行器 生成. 가닥수는 양수 |

`等待`, `剩余部分短暂地`는 `InterruptedException`을 선언한다. 任务 실행기는 使用值 之后状态 `shutdown()`으로 종료하고 필요하면 `awaitTermination(...)`으로 완료를 기다린다. Swing 이벤트 进程值条目 가닥에서 긴 작업이나 `等待`를 실행하면 화면이 멈출 数 있다.

### 屏幕: `中文.Java.屏幕`

| 方法值 | 发回类型 | 动作·条件 |
|---|---|---|
| `稍后值(Runnable 动作)` | `void` | Swing 이벤트 进程值条目 가닥에 실행을 예약하고 发回结果 |
| `窗口(String 窗口标题, JComponent 内容值, int 宽度值, int 高度值)` | `JFrame` | 内容值·크기를 지정한 창을 생성해 显示值 |

`窗口`을 Swing 이벤트 进程值条目 线程值 밖에서 부르면 `IllegalStateException`이 발생한다. 그래픽 세션도 필요하다. QEMU에서는 VNC 데스크톱의 터미널에서 실행한다.

```java
屏幕.稍后值(() -> 屏幕.窗口(
    "中文 屏幕", new javax.swing.JLabel("안녕하세요"), 500, 180));
```

반환된 `JFrame`에 표준 Swing API를 추가로 사용할 数 있다. 창의 关闭 동작은 `DISPOSE_ON_CLOSE`第三操作数. `屏幕.稍后值`首位操作数 반환됐다고 窗口 생성이 이미 끝난 것은 아니다.

### 工作区: 编辑值·编译源代码 GUI

```sh
java -cp /opt/jkoros/lib/中文Java.jar 中文.Java.工作区
```

`~/workspace`의 원문을 打开·저장하고, `javac`로 컴파일해 `java`로 실행한다. 执行命令 文件 만들기는 `jclassc --target openjdk` 경로를 사용한다. 작업마당은 개발용 프로그램이며 별도의 文件·字符 API 클래스가 아니다. 생성하는 执行命令 文件 방식은 [编译器 说明](../compiler/OpenJDK-可执行文件文件.md)을 따른다.

## 4. Python과 C++에서 사용할 数 是否执行存在?

| 方法模式 | 当前项目 头文件 状态值 | 调用 가능 裁剪 |
|---|---|---|
| Java → 中文 JAR | 默认值 头文件 | 顶端值 22개 메서드와 工作区 |
| Python → `java` 子值 프로세스 | Python·Java 默认值 头文件 | 작은 Java 진입점을 통해 호출하고 표준 输出·文件 등으로 结果 前向值 |
| Python → JPype → JVM | JPype는 默认值 배포에 缺失方法 | 별도 安装值 之后状态 Java 类值·方法值 调用 가능. 이 배포판의 ARM64/musl/Python 3.14 조합은 追加条目 有效性校验 所需条件值 |
| C++ → JNI → JVM | `g++`, JNI 헤더, `libjvm.so` 头文件 | JVM을 생성하고 中文 类值·메서드를 직접 호출할 数 있음 |
| Python용 독립 中文 库 | 当前项目 默认值 제공 缺失方法 | 필요하면 Python 표준 라이브러리를 감싸는 中文 모듈을 별도로 작성 |
| C/C++용 독립 中文 库 | 内置 x86 `posix-kor`와 内置 ARM64 커널용 初始状态 RAM 文件 연결이 별도로 존재 | 二值 第三操作数 이 Linux/OpenJDK 실행판의 libc 라이브러리는 아님 |

Python의 일반 `import`第二操作数 `ctypes.CDLL`로 JAR를 바로 읽을 수는 없다. C++의 `#include`第二操作数 일반 네이티브 링커만으로 Java 메서드를 연결할 수도 없다. JVM 프로세스 또는 JVM 连接 계층을 거쳐야 한다.

### Python: 追加条目 패키지 없이 调用

执行命令 가능한 用例 원문은 [字符命令.java](用例/其他语言/字符命令.java), [Python调用.py](用例/其他语言/Python调用.py)第三操作数. Python이 Java 진입점을 실행하고 `字符.代码分个数`의 整数 결과를 받는다. 实参 목록을 사용하며 命令壳 命令 문자열을 조립하지 않는다. `subprocess.run`의 프로세스 执行命令·退出程序 代码值·输出 进程值条目 방식은 [Python 공식 文档集](https://docs.python.org/3/library/subprocess.html)를 따른다.

두 用例 파일을 게스트의 같은 폴더에 복사한 后端值 그 폴더에서 실행한다. 用例 文件 자체는 默认值 시스템 이미지에 자동 설치돼 있지 않다.

```sh
mkdir -p classes
javac -encoding UTF-8 -cp /opt/jkoros/lib/中文Java.jar -d classes 字符命令.java
python3 Python调用.py --text '韩文文本 😀'
```

输出: `Python → 中文.Java.字符.代码分个数: 4`

이 예제의 Python 函数 `代码分个数`는 이번 문서의 连接 예제이며 기존에 설치된 Python 라이브러리는 아니다. 当前项目 예제는 호출할 때마다 JVM 프로세스를 시작한다. Java 对象值 자체를 Python으로 가져오는 방식은 아니며, 다른 메서드를 사용하려면 진입점의 实参·结果 형식을 확장한다.

### Python: JPype로 같은 프로세스에서 调用

JPype를 별도 설치한 환경에서는 下一项目 형태로 연결할 数 있다. **아래는 选中状态值 가능한 连接 방법이며, 当前项目 배포판에 JPype가 설치돼 있거나 执行命令 검증됐다는 뜻은 아니다.** JVM 시작과 `JClass`를 통한 类值 접근은 [JPype 공식 说明](https://jpype.readthedocs.io/en/latest/userguide.html)을 참고한다.

```python
import jpype

jpype.startJVM(
    "/usr/lib/jvm/java-25-openjdk/lib/server/libjvm.so",
    classpath=["/opt/jkoros/lib/中文Java.jar"])
try:
    字符 = jpype.JClass("中文.Java.字符")
    print(字符.代码分个数(jpype.JString("韩文文本 😀")))
finally:
    jpype.shutdownJVM()
```

Python·JVM·连接 모듈의 CPU 아키텍처가 맞아야 한다. 이 실행판은 ARM64 + musl이므로 일반 x86_64/glibc용 바이너리를 그대로 설치하는 방식은 맞지 않는다. JPype 安装值·패키지 빌드는 이번 文档集 작업에서 수행하지 않았다.

### C++: JNI로 직접 调用

[Java调用.cpp](用例/其他语言/Java调用.cpp)는 实际数据 执行命令 가능한 예제다. JVM을 任务 스레드에서 생성하고 下一项目 메서드를 찾는다.

```cpp
jclass type = env->FindClass("中文/Java/字符");
jmethodID method = env->GetStaticMethodID(
    type, "代码分个数", "(Ljava/lang/String;)I");
```

JVM 生成·종료와 스레드 연결은 [JNI Invocation API](https://docs.oracle.com/en/java/javase/25/docs/specs/jni/invocation.html)의 방식이다. `JNIEnv*`는 生成·연결된 스레드에서 사용해야 한다. 예제는 Java 예외를 확인하고 JVM 종료까지 처리한다.

게스트에 `Java调用.cpp`를 복사한 后端值 컴파일한다. 로그인 환경의 `JAVA_HOME`은 `/usr/lib/jvm/java-25-openjdk`第三操作数.

```sh
g++ -std=c++11 -Wall -Wextra -pthread \
  -I"$JAVA_HOME/include" -I"$JAVA_HOME/include/linux" \
  Java调用.cpp -L"$JAVA_HOME/lib/server" \
  -Wl,-rpath,"$JAVA_HOME/lib/server" -ljvm -o Java调用
./Java调用 /opt/jkoros/lib/中文Java.jar
```

输出: `C++ → 中文.Java.字符.代码分个数: 4`

예제는 `韩文文本 😀`을 UTF-16으로 만들어 `NewString`에 전달한다. `NewStringUTF`首位操作数 받는 modified UTF-8은 일반 UTF-8과 차이가 있으므로, 일반 UTF-8 이모지 바이트를 그대로 넘기는 예제로 작성하지 않았다. [JNI 字符串 格式值](https://docs.oracle.com/en/java/javase/25/docs/specs/jni/types.html#modified-utf-8-strings)

다른 中文 메서드도 JNI 서명과 实参 자료형을 맞춰 호출할 数 있다. 예를 들어 `Path`를 받는 文件 API는 먼저 `文件.路径`로 Java 路径 객체를 얻어 전달한다. Swing 호출에는 그래픽 세션과 이벤트 进程值条目 线程值 규칙도 그대로 적용된다. JNI는 Java 실행을 기계어로 대체하는 기능이 아니며 JVM이 继续处理 필요하다.

### 기존 posix-kor와의 관계

추가된 [内置 ARM64 连接](../posix-kor/arm64-native/指南.md)은 C++에서 AOT Java 커널의 RAM 文件 API를 직접 호출하며, 별도 EL0 用户 라이브러리로 文件/UDP 루프백 SVC 호출도 제공한다. JNI를 사용하지 않는다. 이 문서의 ARM64 **Linux** 및 中文 Java JAR와는 다른 执行命令 기반이며 内置 커널은 별도 제한형 Java 编译器/JVM과 MicroPython 1.24.1을 실행한다. MicroPython의 `import jkoros`로 Java 内核值 文件·UDP 루프백·矩形 호출이 가능하지만 이 문서의 JAR를 가져오는 기능은 아니다. 内置 커널의 전체 OpenJDK/JRE/CPython 이식은 아직 미완성이다.

[posix-kor](../posix-kor/指南.md)에는 `打开文件`, `读取文件数据`, `写入文件数据`, `关闭文件`, `创建端点`, `发送数据报数据` 등의 中文 C 별칭이 있다. 그러나 구현은 **内置 jkoros i386 커널의 `int 0x80` 调用 규약용**이다.

이 `libposix-kor.a`와 内置 `sys/stat.h` 등의 헤더는 当前项目 ARM64 Linux 실행판의 libc/C++용 라이브러리가 아니다. 해당 헤더·바이너리를 ARM64 Linux 프로그램에 그대로 연결해서는 ABI가 맞지 않는다. C++용 中文 类值 라이브러리나 Python용 바인딩을 默认值 제공하는 상태도 아니다. 当前项目 Linux 실행판에서 그와 같은 독립 API를 제공하려면 Linux 표준 라이브러리를 대상으로 별도로 实现·빌드해야 한다.

## 5. 验证 범위와 재현

패키지 头文件 여부는 [分发值 패키지 条目列表](../platforms/rpi4/dist/packages.lock.json) 및 构建系统 루트의 实际数据 파일로 확인했다. JNI 헤더는 JDK의 `include/jni.h`, `include/linux/jni_md.h`, JVM 라이브러리는 `lib/server/libjvm.so`에 있다. 사용자가 之后值 별도로 설치한 패키지는 이 默认值 分发值 목록과 다를 数 있다.

이번에 **宿主 x86_64/OpenJDK 11에서** Python 子值 프로세스 호출과 C++ JNI 직접 호출을 编译源代码·실행해 각각 结果 4를 확인했다. JAR 공개 메서드도 소스와 대조했다. Python 连接 예제는 追加条目 패키지를 설치하지 않는다.

문서의 Java 使用值 예제도 编译源代码·실행했고, 22개 메서드의 文档集 头文件 여부와 로컬 文档集 링크를 확인했다. [用例 有效性校验 日志记录](build/其他语言/有效性验证报告.json)

기존 ARM64 QEMU에서는 Java의 文件·Unicode值·스레드·HTTP 및 Swing 测试 결과가 있다. 이번 Python/C++ 连接 예제의 **ARM64 게스트 실행과 JPype 설치는 별도 검증하지 않았다.** 이미지와 执行命令 중인 用户 환경은 이 文档集 작업에서 변경하지 않았다. [기존 操作系统 有效性校验 日志记录](../platforms/rpi4/VERIFICATION.md)

호스트에서 Python 예제를 재현하려면:

```sh
cd /home/user/jkoros/中文Java
make
mkdir -p build/其他语言
javac -encoding UTF-8 --release 11 -cp build/中文Java.jar \
  -d build/其他语言 用例/其他语言/字符命令.java
python3 用例/其他语言/Python调用.py \
  --jar build/中文Java.jar --classes build/其他语言
```

宿主 C++ 예제는 顶端值 JNI 编译源代码 명령의 JDK 경로를 **宿主 JDK 路径**로 바꾸고, 源代码 `用例/其他语言/Java调用.cpp`와 JAR `build/中文Java.jar`를 지정한다. ARM64 게스트 JDK의 헤더·库 경로를 宿主 x86_64 링크 명령에 섞지 않는다.
