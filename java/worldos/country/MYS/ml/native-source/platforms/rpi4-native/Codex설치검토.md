# 자체 ARM64 커널의 Codex ഇന്_സ്റ്റാള്_ചെയ്യുക_മൂല്യം 가능성 검토

검토일: 2026-10-05. 소스와 공식 문서를 대조한 설계 검토이며, 게스트에 Codex를 설치하거나
로그인·모델 호출을 실행한 결과는 아니다. 자체 ARM64 커널과 `../rpi4` Linux 실행판은 구분한다.

현재 자체 커널에는 공식 Codex CLI를 그대로 ഇന്_സ്റ്റാള്_ചെയ്യുക_മൂല്യം·실행할 수 없다.
기술적으로 필요한 നടപ്പാക്കുക_കമാന്_ഡ് 환경을 추가하거나 Codex를 이식하는 경로는 있으나,
다운로드 ആജ്ഞ 하나를 추가하는 작업으로 해결되지 않는다. JDK/JRE 기능 확장만으로도 해결되지 않는다.

## 확인한 근거

| എന്_ട്രി_മൂല്യം | 현재 소스에서 확인한 അവസ്ഥ_മൂല്യം | 직접 실행을 위한 작업 |
|---|---|---|
| നടപ്പാക്കുക_കമാന്_ഡ് ഫയല് | `മെഷീൻ/ഉപയോക്താവ്.c`: AArch64 ET_EXEC만, PT_INTERP/PT_DYNAMIC/PT_TLS നിരസിക്കുക_മൂല്യം, 업로드 നടപ്പാക്കുക_കമാന്_ഡ് 버퍼 16384바이트 | ലക്_ഷ്യം 바이너리에 맞는 ELF 적재·재배치·നടപ്പാക്കുക_കമാന്_ഡ് തുടക്കമിടുക, മെമ്മറി_ഡാറ്റാ/ഫയല് 제한 വിപുലീകരണം_മൂല്യം |
| Linux ABI | `മെഷീൻ/리눅스호환.inc`: read/write/openat/brk 등 제한된 번호만 പ്രോസസ്_മൂല്യം_എന്_ട്രി, 나머지는 ENOSYS | libc/런타임에 필요한 시스템 호출을 추가하거나 자체 ABI용 런타임 이식 |
| 프로세스·스레드 | 일반 fork/clone/execve, pthread/futex, 시그널, mmap, poll/epoll 계열이 미완성 | 비동기 I/O·스레드·കുട്ടി_മൂല്യം ആജ്ഞ നടപ്പാക്കുക_കമാന്_ഡ്·പുറത്തുകടക്കൽ_പ്രോഗ്രാം/റദ്ദാക്കുക_ഓപ്പറേഷൻ 기능 |
| ഫയല് | `ഉറവിടം/മെമ്മറി_ഫയലുകൾ.java`: RAM ഫയല് 64개, 파일당 16 KiB, 비영속 | 큰 നടപ്പാക്കുക_കമാന്_ഡ് ഫയല്·프로젝트·സജ്ജീകരണം·세션을 위한 영속 VFS, ഫയല് അനുമതി_മൂല്യം·വഴി·디렉터리 വിപുലീകരണം_മൂല്യം |
| 네트워크 | lwIP TCP/UDP는 있으나 `നെറ്റ്_വർക്ക്_സ്റ്റാക്ക്_ചെയ്യുക/lwipopts.h`의 LWIP_DNS=0, 일반 HTTPS 클라이언트 없음 | DNS, TLS 인증서 സാധൂകരിക്കുക·신뢰 കലവറ_വർഗ്ഗമൂലം·정확한 시각, HTTPS/스트리밍 |
| ടെ_ര്മിനല്·ഉപകരണങ്ങൾ | 자체 셸과 GUI 터미널은 있지만 표준 PTY·일반 프로세스 작업 നിയന്ത്രണം_മൂല്യം 없음 | ഇടപെടാനുതകുന്ന CLI용 ടെ_ര്മിനല് 기능, ഷെല്/ഫയല് 검색/ബിൽഡ്_సిస్టమ్ ഉപകരണങ്ങൾ കണക്ടു്_ചെയ്യുക |
| നടപ്പാക്കുക_കമാന്_ഡ് അനുമതി_മൂല്യം | EL0 보호는 있으나 Codex의 Linux 샌드박스와 같은 정책 집행 환경 없음 | ഫയല്·네트워크·ആജ്ഞ അനുമതി_മൂല്യം 정책과 승인 기능; 자체 커널에 맞는 격리 구현 |

여기서 ELF의 PT_TLS는 스레드별 സ്_റ്റോർ_മൂല്യം 공간이다. HTTPS의 TLS പാസ്_വേഡ്_മൂല്യം 통신과 서로 다른 기능이다.
ELF ഫയല് 형식을 읽을 수 있다는 사실만으로 Linux നടപ്പാക്കുക_കമാന്_ഡ് 환경을 제공하는 것은 아니다.
SSH/VNC를 위한 പാസ്_വേഡ്_മൂല്യം 라이브러리를 넣은 상태도 HTTPS 구현 완료를 의미하지 않는다.

호스트의 `/home/user/.local/bin/codex`도 확인했다. 이것은 x86-64 ELF ET_DYN이며 약 209 MiB다.
해당 파일을 ARM64 게스트로 복사하여 실행할 수 없다. 이 크기를 ARM64 배포 파일의 크기로
해석하지 않는다. 공식 ARM64 빌드의 വാസ്തവമായ_ഡാറ്റാ വലിപ്പം·의존성은 설치할 버전으로 추가 검사해야 한다.

## 가능한 구현 വഴി

1. **자체 커널에 공식 CLI 직접 이식**
   영속 സ്_റ്റോർ_മൂല്യം/VFS와 ഉപയോക്താവ് മെമ്മറി_ഡാറ്റാ, 프로세스·스레드·I/O, libc/런타임, DNS/HTTPS,
   ടെ_ര്മിനല്·അനുമതി_മൂല്യം 체계를 갖춘다. 이후 ലക്_ഷ്യം 버전의 의존성을 조사하여 크로스 ബിൽഡ്_సిస్టమ్·이식한다.
   Linux 커널을 반드시 탑재할 필요는 없지만, 공식 Linux 바이너리를 그대로 쓸 경우
   그 바이너리가 사용하는 Linux ABI까지 호환해야 한다. 큰 ഓപ്പറേറ്റിംഗ്_സിസ്റ്റം 개발 과제다.

2. **외부 ഹോസ്റ്റ് Codex와 자체 കെര്_ണല്_മൂല്യം കണക്ടു്_ചെയ്യുക — 첫 구현으로 권장**
   Linux PC에서 공식 CLI 또는 app-server를 실행하고 jkoros에는 전용 ഉപയോക്താവ് ആജ്ഞ/화면을 만든다.
   호스트의 인증된 연결과 게스트 ഫയല് വായന·수정·업로드·ആജ്ഞ നടപ്പാക്കുക_കമാന്_ഡ് 어댑터가 필요하다.
   기존 SSH/TCP 경로를 활용할 수 있으나, ഫയല് 동기화나 Codex 전용 어댑터는 현재 구현되어 있지 않다.
   호스트에서 수행한 빌드와 게스트에서 수행한 നടപ്പാക്കുക_കമാന്_ഡ് 결과를 명확히 구분한다.
   이 구성은 자체 커널을 유지하지만, 공식 CLI 자체는 외부 호스트에서 실행된다.

3. **자체 API 클라이언트 제작**
   자체 ABI의 C 또는 지원되는 Java 부분집합으로 ഇടപെടാനുതകുന്ന_സെഷൻ UI와 ഫയല്/ആജ്ഞ ഉപകരണങ്ങൾ 호출 루프를 만든다.
   외부 중계기를 쓰지 않는다면 DNS/സാധൂകരിക്കുക 가능한 TLS/HTTPS와 인증 ഡാറ്റാ 저장을 먼저 구현해야 한다.
   이는 OpenAI API를 이용하는 별도 에이전트이며 공식 Codex CLI 전체의 이식으로 표시하지 않는다.

4. **별도 ARM64 Linux 실행판에서 ഇന്_സ്റ്റാള്_ചെയ്യുക_മൂല്യം**
   `../rpi4`는 Linux와 musl 기반이므로 일반 Linux ഇന്_സ്റ്റാള്_ചെയ്യുക_മൂല്യം 경로를 검토할 수 있다.
   사용할 Codex 버전의 ARM64·musl 호환성, 의존성, 커널의 샌드박스 지원을 വാസ്തവമായ_ഡാറ്റാ 검증해야 한다.
   이번 검토에서 ഇന്_സ്റ്റാള്_ചെയ്യുക_മൂല്യം 성공을 확인하지 않았다. 이 결과를 자체 Java 커널의 지원으로 표시하지 않는다.

## 단계별 완료 പ്രൊജക്റ്റ്_ചെയ്യുക_വർഗ്ഗമൂലം

- 직접 이식: `--version` നടപ്പിലാക്കുക → 인증/HTTPS → ഫയല് വായന·수정 → കുട്ടി_മൂല്യം ആജ്ഞ നടപ്പാക്കുക_കമാന്_ഡ് →
  ഇടപെടാനുതകുന്ന 입력/스트리밍 → അനുമതി_മൂല്യം 제한·റദ്ദാക്കുക_ഓപ്പറേഷൻ → 재부팅 후 സജ്ജീകരണം/세션 보존을 각각 വാസ്തവമായ_ഡാറ്റാ 게스트에서 확인한다.
- ഹോസ്റ്റ് കണക്ടു്_ചെയ്യുക: 게스트에서 HTTP_അപേക്ഷ 입력 → ഹോസ്റ്റ് Codex പ്രോസസ്_മൂല്യം_എന്_ട്രി → 게스트 ഫയല് മാറ്റികൊടുക്കുക_മൂല്യം പരിശോധിക്കുക →
  게스트 javac/cc നടപ്പാക്കുക_കമാന്_ഡ് → അളവ് 표시를 처음부터 끝까지 검증한다.
- COSL 상업 조건을 유지하려면 새로 도입하는 런타임/통신 라이브러리의 라이선스와
  Codex 배포 버전의 제3자 고지를 검토한다. 외부 구성요소를 일괄 COSL로 재라이선스하지 않는다.
