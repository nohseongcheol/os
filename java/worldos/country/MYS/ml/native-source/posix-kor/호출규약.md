# ഉപയോക്താവ് 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `മെഷീൻ/ഓപ്പറേറ്റിംഗ്_സിസ്റ്റം_കോളുകൾ.s`에서 EAX(സൂചിക), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 인수)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. കെര്_ണല്_മൂല്യം 실패는 음수 പിശക് സൂചിക, C లైబ్రరీ 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 ഉപയോക്താവ് 영역 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C ഡാറ്റാ 주소는 బైట్_മൂല്യം 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java ഫയല് 흐름의 어셈블리 경계가 별도 బైట్_മൂല്യം 버퍼를 마련하여 같은 호출을 사용한다.

|---|---|---|

| 31 | 파일자료읽기 | 서술자, ഡാറ്റാ ഇമെയിൽ, బైట్_മൂല്യം 수 |
| 32 | റൈറ്റ്_ചെയ്യുക_ഫയല്_ഡാറ്റാ | 서술자, ഡാറ്റാ ഇമെയിൽ, బైట్_മൂല്യം 수 |
| 33 | അടയ്ക്കുക_ഫയല് | 서술자 |
| 34 | തിരയുക_ഫയല് | 서술자, എന്_കോഡുചെയ്യല്_മൂല്യം 있는 ഓഫ്_സെറ്റ്_മൂല്യം, പ്രൊജക്റ്റ്_ചെയ്യുക_വർഗ്ഗമൂലം |

| 44 | 자료전문받기 | 서술자, ഡാറ്റാ ഇമെയിൽ, ദൈര്_ഘ്യം_മൂല്യം, സജ്ജീകരണം, HTTP_അപേക്ഷ ഇമെയിൽ |
| 45 | 통신주소읽기 | 서술자, sockaddr ഇമെയിൽ, socklen_t ഇമെയിൽ |
| 46 | 수신대기정하기 | 서술자, 0~2000 밀리초 |
| 47 | 파일저장확정 | 서술자 |

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 ഇമെയിൽ 두 칸이다. 수신 주소가 NULL이면 പീര്_മൂല്യം ഇമെയിൽ 기록을 생략한다. sockaddr_in은 16바이트이며 ഇമെയിൽ 체계는 മൊബൈൽ_മൂല്യം బైట్_മൂല്യം 차례, 접속번호와 IP 주소는 네트워크 బైట్_മൂല്യം 차례다. 축소된 ഇമെയിൽ 버퍼에도 들어가는 앞부분을 쓰고 전체 ഇമെയിൽ വലിപ്പം 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 പുറത്തുകടക്കൽ_പ്രോഗ്രാം, 2·3은 기존 인수 조회다. 현재 커널의 인수 목록이 നടപ്പാക്കുക_കമാന്_ഡ് 이름을 제외하므로 C 진입기는 argv[0]에 고정 സ്ട്രിംഗ്_മൂല്യം `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX പ്രോസസ്_മൂല്യം ABI와 다른 점이다.

표준 헤더의 പൂര്_ണ്ണസംഖ്യ വലിപ്പം, 플래그 മൂല്യം, stat മണ്ഡലം_മൂല്യം 순서는 `ഉറവിടം/포함/`에 정의한다. 동적 കണക്ടു്_ചെയ്യുക·다중 പ്രോസസ്_മൂല്യം·스레드가 추가되면 പിശക് സൂചിക 저장과 ഉറവിടം_മൂല്യം 수명, 호출 경계도 함께 검토해야 한다.
