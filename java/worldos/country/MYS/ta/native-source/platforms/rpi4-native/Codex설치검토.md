# 자체 ARM64 커널의 Codex நிறுவு_மதிப்பு 가능성 검토

검토일: 2026-10-05. 소스와 공식 문서를 대조한 설계 검토이며, 게스트에 Codex를 설치하거나
로그인·모델 호출을 실행한 결과는 아니다. 자체 ARM64 커널과 `../rpi4` Linux 실행판은 구분한다.

현재 자체 커널에는 공식 Codex CLI를 그대로 நிறுவு_மதிப்பு·실행할 수 없다.
기술적으로 필요한 இயக்கு_கட்டளை 환경을 추가하거나 Codex를 이식하는 경로는 있으나,
다운로드 கட்டளை 하나를 추가하는 작업으로 해결되지 않는다. JDK/JRE 기능 확장만으로도 해결되지 않는다.

## 확인한 근거

| உள்ளீடு_மதிப்பு | 현재 소스에서 확인한 நிலை_மதிப்பு_e10195a1 | 직접 실행을 위한 작업 |
|---|---|---|

| 프로세스·스레드 | 일반 fork/clone/execve, pthread/futex, 시그널, mmap, poll/epoll 계열이 미완성 | 비동기 I/O·스레드·குழந்தை_மதிப்பு கட்டளை இயக்கு_கட்டளை·முடிவு_நிரல்/ரத்து_இயக்கம் 기능 |
| கோப்பின்_பெயர் | `மூலக்_கோப்பு/நினைவகம்_கோப்புகள்.java`: RAM கோப்பின்_பெயர் 64개, 파일당 16 KiB, 비영속 | 큰 இயக்கு_கட்டளை கோப்பின்_பெயர்·프로젝트·அமைப்புகள்·세션을 위한 영속 VFS, கோப்பின்_பெயர் அனுமதி_மதிப்பு·பாதை_2·디렉터리 நீட்டிப்பு_மதிப்பு |
| 네트워크 | lwIP TCP/UDP는 있으나 `பிணையம்_அடுக்கு_49fba3da/lwipopts.h`의 LWIP_DNS=0, 일반 HTTPS 클라이언트 없음 | DNS, TLS 인증서 சரிபார்_5fb2b747·신뢰 தொகுபதிவகம்_மூலம்·정확한 시각, HTTPS/스트리밍 |
| கட்டளை_விளக்கி·கருவிகள் | 자체 셸과 GUI 터미널은 있지만 표준 PTY·일반 프로세스 작업 கட்டுப்பாடு_மதிப்பு 없음 | ஊடாடு CLI용 கட்டளை_விளக்கி 기능, கூடு/கோப்பின்_பெயர் 검색/தொகு_முறைமை கருவிகள் இணைக்க |
| இயக்கு_கட்டளை அனுமதி_மதிப்பு | EL0 보호는 있으나 Codex의 Linux 샌드박스와 같은 정책 집행 환경 없음 | கோப்பின்_பெயர்·네트워크·கட்டளை அனுமதி_மதிப்பு 정책과 승인 기능; 자체 커널에 맞는 격리 구현 |

여기서 ELF의 PT_TLS는 스레드별 சேகரி_மதிப்பு 공간이다. HTTPS의 TLS கடவுச்சொல்_மதிப்பு 통신과 서로 다른 기능이다.
ELF கோப்பின்_பெயர் 형식을 읽을 수 있다는 사실만으로 Linux இயக்கு_கட்டளை 환경을 제공하는 것은 아니다.
SSH/VNC를 위한 கடவுச்சொல்_மதிப்பு 라이브러리를 넣은 상태도 HTTPS 구현 완료를 의미하지 않는다.

호스트의 `/home/user/.local/bin/codex`도 확인했다. 이것은 x86-64 ELF ET_DYN이며 약 209 MiB다.
해당 파일을 ARM64 게스트로 복사하여 실행할 수 없다. 이 크기를 ARM64 배포 파일의 크기로
해석하지 않는다. 공식 ARM64 빌드의 அசல்_தரவு அளவு·의존성은 설치할 버전으로 추가 검사해야 한다.

## 가능한 구현 பாதை_2

1. **자체 커널에 공식 CLI 직접 이식**
   영속 சேகரி_மதிப்பு/VFS와 பயனர் நினைவகம்_தரவு, 프로세스·스레드·I/O, libc/런타임, DNS/HTTPS,
   கட்டளை_விளக்கி·அனுமதி_மதிப்பு 체계를 갖춘다. 이후 இலக்கு 버전의 의존성을 조사하여 크로스 தொகு_முறைமை·이식한다.
   Linux 커널을 반드시 탑재할 필요는 없지만, 공식 Linux 바이너리를 그대로 쓸 경우
   그 바이너리가 사용하는 Linux ABI까지 호환해야 한다. 큰 இயக்க_முறைமை 개발 과제다.

2. **외부 ஓம்பு Codex와 자체 கரு_மதிப்பு இணைக்க — 첫 구현으로 권장**
   Linux PC에서 공식 CLI 또는 app-server를 실행하고 jkoros에는 전용 பயனர் கட்டளை/화면을 만든다.
   호스트의 인증된 연결과 게스트 கோப்பின்_பெயர் படி·수정·업로드·கட்டளை இயக்கு_கட்டளை 어댑터가 필요하다.
   기존 SSH/TCP 경로를 활용할 수 있으나, கோப்பின்_பெயர் 동기화나 Codex 전용 어댑터는 현재 구현되어 있지 않다.
   호스트에서 수행한 빌드와 게스트에서 수행한 இயக்கு_கட்டளை 결과를 명확히 구분한다.
   이 구성은 자체 커널을 유지하지만, 공식 CLI 자체는 외부 호스트에서 실행된다.

3. **자체 API 클라이언트 제작**
   자체 ABI의 C 또는 지원되는 Java 부분집합으로 ஊடாடு_அமர்வு UI와 கோப்பின்_பெயர்/கட்டளை கருவிகள் 호출 루프를 만든다.
   외부 중계기를 쓰지 않는다면 DNS/சரிபார்_5fb2b747 가능한 TLS/HTTPS와 인증 தரவு 저장을 먼저 구현해야 한다.
   이는 OpenAI API를 이용하는 별도 에이전트이며 공식 Codex CLI 전체의 이식으로 표시하지 않는다.

4. **별도 ARM64 Linux 실행판에서 நிறுவு_மதிப்பு**
   `../rpi4`는 Linux와 musl 기반이므로 일반 Linux நிறுவு_மதிப்பு 경로를 검토할 수 있다.
   사용할 Codex 버전의 ARM64·musl 호환성, 의존성, 커널의 샌드박스 지원을 அசல்_தரவு 검증해야 한다.
   이번 검토에서 நிறுவு_மதிப்பு 성공을 확인하지 않았다. 이 결과를 자체 Java 커널의 지원으로 표시하지 않는다.

## 단계별 완료 திட்டப்பணி_மூலம்

- 직접 이식: `--version` செயல்படுத்துக → 인증/HTTPS → கோப்பின்_பெயர் படி·수정 → குழந்தை_மதிப்பு கட்டளை இயக்கு_கட்டளை →
  ஊடாடு 입력/스트리밍 → அனுமதி_மதிப்பு 제한·ரத்து_இயக்கம் → 재부팅 후 அமைப்புகள்/세션 보존을 각각 அசல்_தரவு 게스트에서 확인한다.
- ஓம்பு இணைக்க: 게스트에서 HTTP_வேண்டுதல் 입력 → ஓம்பு Codex செயலகம்_மதிப்பு_உள்ளீடு → 게스트 கோப்பின்_பெயர் மாற்று_மதிப்பு_16f64fe4 சரிபார் →
  게스트 javac/cc இயக்கு_கட்டளை → அளவிடக்கூடியது 표시를 처음부터 끝까지 검증한다.
- COSL 상업 조건을 유지하려면 새로 도입하는 런타임/통신 라이브러리의 라이선스와
  Codex 배포 버전의 제3자 고지를 검토한다. 외부 구성요소를 일괄 COSL로 재라이선스하지 않는다.
