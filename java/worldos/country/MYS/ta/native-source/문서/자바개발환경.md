# jkoros 안에서 Java தொகு_மூலம்·இயக்கு_கட்டளை

이 문서의 부팅·கூடு·சேகரி_மதிப்பு 명령은 **x86 பதிப்பு_மதிப்பு** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 பதிப்பு_மதிப்பு](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 கோப்பு_பெயர்_உரை, `edit`의 단독 `.` சேகரி_மதிப்பு, 16개 RAM கோப்பின்_பெயர், 약 2초 இயக்கு_கட்டளை 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 அசல்_தரவு JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. ஓம்பு தொகு_மூலம் 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java நிரல்_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 இயக்கு_கட்டளை

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. இயக்கு_கட்டளை 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox இயக்கு_கட்டளை பயனர்_உதவிக்_கோப்பு_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 கோப்பின்_பெயர் 전체를 새 내용으로 작성한다. 기존 내용의 உள்ளீட்டு_வரி திருத்து_மதிப்பு 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 பைட்_மதிப்பு 수 காட்சி_மதிப்பு_487749b8.
- `cat FILE`: கோப்பின்_பெயர் உள்ளடக்கம்_மதிப்பு காட்சி_மதிப்பு_487749b8. 텍스트 소스에 사용한다.
- `rm FILE`: நினைவகம்_தரவு கோப்பின்_பெயர் 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·வகை_மதிப்பு 검사 செயலிழப்பு_மதிப்பு 시 기존 `.class`는 유지된다. 소스를 고친 பின்_மதிப்பு 컴파일이 실패했다면 이전 இயக்கு_கட்டளை 파일이 남아 있으므로 தொகு_மூலம் 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 சேகரி_மதிப்பு 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 மூலம்_மரம்·பிரிவு_மதிப்பு_55654bf1·தரவு 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, கோப்பின்_பெயர் 이름은 ASCII 1~63자다. மூலம்_மரம் 이름은 `.class` 확장자 공간 때문에 최대 62자다. திருத்து_மதிப்பு 입력은 ASCII이고 한 உள்ளீட்டு_வரி 최대 128자다. உள்ளீட்டு_வரி 또는 கோப்பின்_பெயர் 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. கரு_மதிப்பு/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 பயனர் 예제 이름은 ASCII로 작성한다.

## 외부 கோப்பின்_பெயர் 적재

호스트에서 만든 소스나 ஆதரவு_மதிப்பு கிளிப் 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 அசல்_தரவு 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# ஓம்பு JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 அடுத்து_உருப்படி 빌드에서는 추가 파일을 포함하지 않는다. கோப்பின்_பெயர் உள்ளடக்கம்_மதிப்பு 변경과 உள்ளீடு_பட்டியல் 제거도 அடுத்து_உருப்படி 빌드에 반영된다. 원본 ஓம்பு 파일에는 쓰지 않는다. இயல்புநிலை_மதிப்பு `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 இயல்புநிலை_மதிப்பு 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 பிரிவு_மதிப்பு_55654bf1 கோப்பின்_பெயர் 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 ஆதரவு_மதிப்பு கிளிப் 안에 있어야 한다.

## ஆதரவு_மதிப்பு கிளிப்

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| பிரிவு_மதிப்பு_55654bf1 | 패키지 없는 단일 பிரிவு_மதிப்பு_55654bf1, மாறா_மதிப்பு செயல்பாடு_மதிப்பு, 재귀, செயலுருபுகள்/반환 | 실행마다 단일 பிரிவு_மதிப்பு_55654bf1 적재, public static main(String[]) |
| இயல்புநிலை_மதிப்பு மதிப்பு | int, boolean, char, String, main의 String[] செயலுருபுகள் | முழு_எண்·மேற்கோள் 스택, String, int[], String[], 내부 StringBuilder |
| கூற்று_மதிப்பு | 초기값 있는 தனி_நோக்கி அறிவிப்பு, வேலை_மதிப்பு, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 முழு_எண்·மேற்கோள் 바이트코드와 நிபந்தனை கிளை |
| கோவை_மதிப்பு | 십진 முழு_எண், UTF-8 소스의 சரம்_மதிப்பு/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, சரம்_மதிப்பு 결합 | முழு_எண் இயக்கம்_மதிப்பு·பிட்_மதிப்பு இயக்கம்_மதிப்பு·வகை_மதிப்பு 변환, 단락 평가, கோவை_மதிப்பு_ed437109 அணுகு_உள்ளீடு |
| கோப்பின்_பெயர் | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | அசல்_தரவு கரு_மதிப்பு 파일서술자와 இணைக்க, உருவாக்குக·அழி_உள்ளடக்கங்கள்·이어쓰기·EOF |
| வெளியீட்டு_இடம் | System.out.print/println: int/boolean/char/String, println() | 동일 |
| சரம்_மதிப்பு/செயலுருபுகள் | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), சரம்_மதிப்பு 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 தனி_நோக்கி அறிவிப்பு, 오버로드, 임의 வகை_மதிப்பு 변환, கோவை_மதிப்பு_ed437109 உருவாக்குக மூலக்_கோப்பு, 8/16진 리터럴, Unicode மூலம்_மரம் 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 மாறிலி_மதிப்பு 축소 변환을 구현하지 않는다. 외부 `.class`의 `int[]` உருவாக்குக/படி/쓰기는 지원하므로 ஓம்பு `javac --release 8`로 만든 கோவை_மதிப்பு_ed437109 예제는 실행할 수 있다.

பொருள்_மதிப்பு புலம்_மதிப்பு·일반 பொருள்_மதிப்பு உருவாக்குக·상속·인터페이스·여러 பிரிவு_மதிப்பு_55654bf1 இணைக்க, long/float/double, விதிவிலக்கு செயலகம்_மதிப்பு_உள்ளீடு, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java விதிவிலக்கு 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 சரம்_மதிப்பு சேகரி_மதிப்பு 공간은 இயக்கு_கட்டளை முடிவு_நிரல் 시 பயனர் 영역 전체와 함께 회수한다. 지속 இயக்கு_கட்டளை 중 GC는 없다.

## இயக்கு_கட்டளை 한도와 பிழை

| வளம்_மதிப்பு | 한도 |
| --- | --- |
| மூலம்_மரம்/பிரிவு_மதிப்பு_55654bf1 கோப்பின்_பெயர் | 각각 16KiB |
| 컴파일러 | டோக்கன்_மதிப்பு 2,047개, உருவாக்குக குறியீடு_மதிப்பு 4KiB, மாறிலி_மதிப்பு 풀 4KiB |
| செயல்பாடு_மதிப்பு/செயலுருபுகள் | 클래스당 32함수, 함수당 16인수 |
| JVM மாறிலி_மதிப்பு | 511개 |
| JVM செயல்பாடு_மதிப்பு குறியீடு_மதிப்பு | 함수당 8KiB |
| JVM 호출/스택/தனி_நோக்கி 변수 | 32프레임, 프레임당 스택 128칸·தனி_நோக்கி 128칸 |
| JVM பொருள்_மதிப்பு சேகரி_மதிப்பு 공간 | 8,192개 32비트 ஸ்லாட்_உள்ளீடு, 헤더 포함 약 32KiB |
| இயக்கு_கட்டளை | 최대 500,000 கட்டளை, 기존 커널의 약 3초 CPU இயக்கு_கட்டளை 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 ஆதரவு_மதிப்பு 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM அகராதி 검증기를 구현한 것은 아니다. கோப்பின்_பெயர்/பண்புக்கூறு_மதிப்பு நீளம்_மதிப்பு, மாறிலி_மதிப்பு மேற்கோள், கட்டளை·கிளை 경계를 검사하고, இயக்கு_கட்டளை 중 스택 வடிவமை_மதிப்பு·தனி_நோக்கி தயார்படுத்து·கோவை_மதிப்பு_ed437109 கீழ்_ஒட்டு_மதிப்பு·பொருள்_மதிப்பு 참조를 검사한다. பயனர் 코드의 페이지·포트 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, தொகு_மூலம்·JVM 오류는 `Exit: 1`, கட்டளை செயலுருபுகள் 오류는 `Exit: 2`다. CPU நேர_மதிப்பு 상한은 기존 `Exit: 124`이며, பயனர் ELF 자체의 CPU/런타임 오류는 기존 முடிவு_நிரல் 코드를 따른다. செயலிழப்பு_மதிப்பு 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

- `os/பயனர்/자바/자바컴파일러.java`: 게스트 어휘·구문·வகை_மதிப்பு 검사, மாறிலி_மதிப்பு 풀 및 바이트코드 உருவாக்குக.

## Java கோப்பின்_பெயர் உள்ளீடு_வெளியீடு

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 பிரிவு_மதிப்பு_55654bf1 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 பின்_மதிப்பு `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. இயல்புநிலை_மதிப்பு வெளியீட்டு_இடம் 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. விதிவிலக்கு பொருள்_மதிப்பு·try/catch·try-with-resources는 지원하지 않으며 கோப்பின்_பெயர் 오류를 진단하고 프로그램을 종료한다. கோவை_மதிப்பு_ed437109 உள்ளீடு_வெளியீடு, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 கோப்பின்_பெயர் 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 கூடு `sync`가 필요하다. 예제의 கோப்பின்_பெயர் 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 அசல்_தரவு 게스트 தொகு_மூலம் 결과를 OpenJDK `-Xverify:all`로 다시 실행해 கோப்பின்_பெயர் 바이트와 출력을 대조한다. 범위와 சேகரி_மதிப்பு 매체 사용법은 [posix-kor பயனர்_உதவிக்_கோப்பு_eb81d7d9](../posix-kor/பயனர்_உதவிக்_கோப்பு_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
