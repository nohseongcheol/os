# Java 네이티브 操作系统

이 문서는 기존 **x86 内核值**을 설명한다. Raspberry Pi 4의 内置 ARM64 初始状态 이식은 [별도 指南](../platforms/rpi4-native/README.md)를 참고한다. 底端值 x86 用户 ELF·네트워크·IDE 存储值 기능이 ARM64에 构建全部 이식된 상태는 아니다.

Java 원문을 内置 AOT 후단으로 x86 기계어로 컴파일해 부팅하는 작은 운영체제다. 커널과 별도로 内置 제한형 Java 编译器·JVM ELF를 用户 모드에 적재할 数 있다. Linux, engos, koros4와 外部值 OpenJDK는 게스트에 적재하지 않는다. 启动 진입과 硬件端口/물리 内存空间 접근은 어셈블리이며, 字符 终端输入输出·输入值 进程值条目·命令 解析值·任务 区段值 관리는 `源代码/*.java`에 있다.

## 게스트 Java 开发

`javac Hello.java`, `java Hello`로 부팅된 操作系统 안에서 编译源代码·실행한다. `edit FILE.java`와 `.save`로 소스를 작성하며 `ls`, `cat`, `rm`을 제공한다. RAM 파일은 最大值 8개, 각각 16KiB이다. 전용 IDE 매체를 연결하면 `sync`로 보존할 数 있다. 이 기능은 内置 제한형 구현이며 전체 OpenJDK/JDK 호환은 아니다. 사용법·支持值 문법·文件 적재·교차 시험은 [Java 开发 环境](../文档集/Java开发环境.md)에 있다. `make test-java`로 검증한다.

## 빌드와 执行命令

`compiler/`首位操作数 요구하는 도구에 더해 ISO 생성에는 `grub-file`, `grub-mkrescue`, GRUB BIOS 模块值, `xorriso`首位操作数 필요하다. 실행에는 QEMU 또는 VirtualBox가 필요하다. 当前项目 설치된 도구만 사용한다. `make run-store`는 새 전용 가상 存储值 매체를 만들어 연결한다. VirtualBox 실행기는 이 프로젝트가 만든 전용 VM만 설정하고 다른 VM은 변경하지 않는다. 가상 메모리는 默认值 64MiB이며 最小值 16MiB가 필요하다.

```sh
cd /home/user/jkoros/os
make                 # build/kernel.elf
make iso             # build/kernel.iso (用户 ELF 组值 头文件)
make run             # ELF 직접 启动, 串行值 终端输入输出
make run-gui         # GRUB ISO 启动, VGA 창과 PS/2 자판
make vbox            # 상위 폴더의 실행기로 전용 VirtualBox VM 执行命令
make vbox-status     # 전용 VirtualBox VM 状态值 验证
make test            # ELF와 ISO 두 경로의 实际数据 启动/输入值 测试
make apps            # 用户 프로그램만 构建系统
make test-network    # 用户 执行命令/UDP/保护值 测试
```

`make run`은 QEMU의 串行值 표준 입출력을 쓴다. `Ctrl+A`를 누른 后端值 `X`로 QEMU를 종료할 数 있다. `halt`는 게스트 CPU만 정지시키므로 QEMU 窗口/프로세스는 별도로 닫는다. 폴링 방식이라 等待状态值 중에도 宿主 CPU를 사용할 数 있다.

VirtualBox는 `make vbox`로 실행한다. 새 전용 VM을 内存数据 64MiB, BIOS, 광학 드라이브 부팅으로 자동 설정하며 디스크는 所需条件值 없다. 实际数据 VirtualBox 5.2.42에서 启动, Java 内置 测试, 命令壳 输入值, `run hello vbox`의 ring 3 실행과 是否常规 종료를 확인했다. 当前项目 通信 드라이버는 QEMU의 RTL8139 전용이며 VirtualBox의 PCnet/E1000에서는 네트워크를 사용할 数 없어 네트워크 장치를 비활성화한다. 存储值 状态值 재개와 새 构建系统 반영 방법은 [VirtualBox 执行命令 指南](../文档集/VirtualBox运行.md)에 있다.

## 셸에서 用户 程序 执行命令 및 네트워크 调用

독립 ELF32 执行命令 파일을 적재해 **ring 3**에서 실행한다. `int 0x80` 시스템 호출을 통해 终端输入输出 输出, 实参 查询值, UDP 打开·发送·接收·닫기를 제공한다. 用户 코드를 内核值 함수로 직접 호출하는 구조가 아니다.

```text
jkoros> apps
jkoros> run hello first second
jkoros> net
jkoros> run netcheck
jkoros> run udp 10.0.2.2 9000 hello
```

最后项目 명령의 응답을 받으려면 호스트의 별도 터미널에서 `python3 /home/user/jkoros/os/工具集/数据恢复.py --port 9000`을 먼저 실행한다. 상세 API, 程序 追加条目, 地址 공간과 제한은 [用户 执行命令·네트워크 指南](用户/指南.md)에 있다.

启动 验证 短语值:

```text
JKOROS NATIVE JAVA
Java 기계어 内核值 运行
JAVA SELFTEST PASS
USER ELF: ring 3 / paging / int 0x80
help | info | mem | alloc | free N | echo TEXT | clear | test | halt
apps | run NAME [ARGS] | net
READY
jkoros>
```

## 구현한 기능

- GRUB Multiboot 1 ELF 启动, x86 保护值 模式值 GDT, BSS 初始化, 64KiB 操作数栈.
- Java 函数 实际数据 실행과 启动 系统信息 标记值 验证.
- COM1 串行值 输入输出, VGA 字符 屏幕·光标值·스크롤·擦除条目.
- PS/2 默认值 자판, 좌우 Shift, Enter, Backspace. 扩展名值 键值/마우스 자료는 命令 입력으로 쓰지 않는다.
- 长度 128의 命令 输入值 버퍼, 溢出值 방지, CR/LF 进程值条目.
- `help`, `info`, `mem`, `alloc`, `free N`, `echo TEXT`, `clear`, `test`, `halt`.
- 4KiB 任务 区段值 8개의 分配存储装置·发回结果·재사용과 중복 发回结果 방지.
- Java 数组值 256KiB 영역의 大小·下标值 검사와 런타임 错误 중단.
- 读取 전용 JKAP 执行命令 组值, ELF32 区段值/条目分 有效性校验, 用户 模式值·实参·退出程序 代码值.
- 内核值/用户 페이지 权限值 분리, TSS, IDT, PIT 100Hz, 用户 CPU 异常 进程值条目 및 执行命令 时间值 상한.
- PCI RTL8139 폴링 드라이버, ARP, 静态值 IPv4, UDP 校验和·송수신·等待状态值 限制值.

`mem`의 Upper memory는 Multiboot의 1MiB 上位侧侧 稠密切换分支项集 内存数据 大小(KiB)이며, 전체 内存数据 지도 분석이나 자유 물리 内存数据 수치가 아니다. `alloc`은 이미 확보한 整数 数组值 안의 任务 区段值 번호를 반환한다. 일반 물리 页值 分配存储装置, 地址 地址区域 또는 用户 进程值 内存数据 관리가 아니다.

## 명시적인 边界位置限制

이 커널은 **用户 프로그램을 한 번에 一值 실행하는 初始状态 内核值**이다. PIT IRQ0만 사용하며 키보드와 NIC는 폴링한다. 用户 CPU 예외는 해당 프로그램을 끝내고 셸로 복귀시키지만 内核值 예외는 중단한다. 执行命令 시간은 약 3초로 제한한다. 완전한 선점 다중 进程值 스케줄러, FAT/ext 등 일반 디스크 文件系统, TCP·DNS·DHCP·IPv6·HTTP, 전체 POSIX, 일반 对象值 모델/GC는 아직 없다. 전용 IDE 文件 보존과 POSIX 文件/UDP 일부 기능은 구현했다. JVM은 RAM 파일의 단일 클래스를 执行命令 시 적재하며 일반 ClassLoader나 JAR 로딩은 지원하지 않는다. 네이티브 执行命令 파일은 构建系统 시 读取 전용 묶음에 넣으며, 일반 Linux ELF를 실행하는 환경이 아니다. 기존 `../基础源代码/`의 JVM 관리 内核值 전체를 이식한 것도 아니다.

Java 식별자는 한국어다. 串行值 출력은 이 프로젝트의 韩文文本(BMP 字符)을 UTF-8로 표시한다. VGA는 默认值 ASCII 글꼴만 사용하므로 韩文文本 자리에 `?`首位操作数 나온다. 命令 입력도 当前项目 ASCII만 지원하며 韩文文本 字体值·입력기 및 辅助值 평면 字符 출력은 후속 작업이다. `test`는 작은 배열을 새로 할당하고 GC가 없으므로 무한 반복하지 않는다.

## 자동 测试

`测试/启动测试.py`는 디스크 없는 독립 QEMU를 생성해 다음을 검증하고 종료한다.

- ELF 직접 启动 및 GRUB ISO 启动.
- Java 内置 시험과 UTF-8 串行值 短语值.
- 命令 显示帮助·系统信息·内存数据·输出·错误 输入值·屏幕 擦除条目.
- 任务 区段值 8개 分配存储装置, 부족 进程值条目, 发回结果/중복 发回结果/재할당.
- 串行值 换行·백스페이스·긴 输入值 进程值条目.
- QEMU PS/2 键值 입력으로 `info` 执行命令, `halt` 停机执行状态.

成功值 로그는 `build/启动测试.json`에 남는다. 로컬 Unix 소켓을 금지하는 샌드박스에서는 测试 도구에 해당 권한이 필요하다. 测试 도중 새로 만든 QEMU만 종료하며 기존 VM과 实际数据 디스크는 건드리지 않는다.

`测试/测试用户网络.py`는 ELF/ISO 각각에서 用户 ELF, 实际数据 ring 3, 实参, 宿主 루프백 UDP 왕복, 1,023/1,024바이트 24회 稠密切换分支项集 왕복, 时间值 초과, NIC 缺失方法, 内存数据/硬件端口 存取条目 차단, CPU 异常, 무한 迭代值, 잘못된 ELF를 시험한다. `build/测试用户网络.json`에 게스트 기록과 호스트가 받은 데이터의 长度·해시를 저장한다. `测试/数据包测试.py`는 实际数据 Java 契约值 처리기에 손상된 패킷을 넣어 2,201개 边界位置值/校验和 조건을 검사한다. 宿主 루프백 외 外部值 서버에는 测试 트래픽을 보내지 않는다.

부트 경계는 GNU의 [Multiboot 规格](https://www.gnu.org/software/grub/manual/multiboot/multiboot.html)를 따른다.

새 文件描述符·C ABI·IDE 存储值·Java 文件 흐름의 범위와 中文 命名 대응은 [posix-kor 指南](../posix-kor/指南.md)에 있다. `make test-posix`로 ELF/ISO 실행과 재부팅 보존을 검증한다.
