# jkoros posix-kor

**内置 ARM64 Java 커널용 C++ 连接**은 [arm64-native](arm64-native/指南.md)에 있다. 内核值 내부 직접 文件 호출과 EL0 用户 프로그램의 文件/UDP 루프백 SVC 호출을 별도 라이브러리로 제공한다. 底端值 i386 库 및 ARM64 Linux libc와는 目标值·ABI가 다르다.

内置 jkoros 커널에서 실행되는 i386 C 라이브러리와 中文 API다. 宿主 libc를 연결하지 않고 `int 0x80`으로 实际数据 커널의 文件描述符·终端输入输出·UDP·存储值 계층을 호출한다. `基础源代码/`의 宿主 JVM 모형과 별개다.

**현재는 POSIX의 일부 기능을 제공하는 호환 계층이며, POSIX 인증·전체 libc·전체 OpenJDK를 뜻하지 않는다.** 实现 범위와 제한을 아래에 명시한다. 한국어를 먼저 적용했다. 다른 국가·언어의 번역판은 아직 만들지 않았다.

## 빌드와 执行命令

```sh
cd /home/user/jkoros
make posix-kor
make iso
make test-posix
make -C os run-store
```

`run-store`는 `os/build/files.img`首位操作数 없을 때만 새 전용 파일을 만들고 QEMU IDE 首位项目 장치로 연결한다. 기존 파일을 덮어써서 초기화하지 않는다. 일반 `make run`은 디스크 없이 실행된다. VirtualBox 실행기의 디스크 연결은 변경하지 않았다.

부팅된 jkoros에서:

```text
run posixcheck check
run posixstore
cat stored.txt
edit note.txt
hello from jkoros
.save
sync
```

`Sync: 0`은 연결된 전용 매체에 저장했다는 뜻이다. 디스크가 없거나 赋值值 형식이 아니면 `Sync: -19`第三操作数. 같은 `files.img`로 重试值 부팅하면 最后项目 同步化 상태를 복원한다. Java 소스와 `.class`도 같은 存储值 대상이다. `close`第二操作数 편집기의 `.save`만으로 재부팅 보존을 보장하지 않으므로 退出程序 전에 `sync`를 실행한다.

## 한국어로 C 程序 작성

```c
#include <文件ABI.h>

int main(int 参数列个数, char **参数列表) {
    (void)参数列个数;
    (void)参数列表;
    int 文件描述符 = 打开文件("note.txt", 读取写入 | 创建条件缺失, 0600);
    if (文件描述符 < 0) return 错误编号;
    if (写入文件数据(文件描述符, "hello\n", 6) != 6) return 1;
    if (提交文件存储装置(文件描述符) < 0) return 错误编号;
    return 关闭文件(文件描述符);
}
```

작성 원문은 한글을 그대로 유지한다. `工具集/标识符转换结果.py`首位操作数 构建系统 복사본의 식별자만 C 표준 UCN 표기로 바꾸어 GCC 7에서도 컴파일되게 한다. 字符串, 주석, `#include` 경로는 변환하지 않는다. 이 도구는 C의 모든 预处理源代码 표기법을 해석하는 전처리기가 아니며, 프로젝트가 사용하는 일반 토큰과 include 문법을 대상으로 한다.

라이브러리는 `build/libposix-kor.a`, 运行 코드는 `build/开始用户程序.o`, 生成 헤더는 `build/源代码/头文件/`이다. 构建系统 옵션과 连接 명령은 [Makefile](Makefile), 实际数据 예제는 [文件ABI测试.c](源代码/测试/文件ABI测试.c)와 [数据报测试.c](源代码/测试/数据报测试.c)에 있다. 새 ELF를 OS에 포함하려면 `os/Makefile`의 用户 执行命令 묶음에 명시적으로 등록한다. 게스트 안에서 C를 컴파일하는 도구는 제공하지 않는다.

표준 C/POSIX 外部值 名称 `open`, `read`, `write`, `socket`, `errno`, `main`과 헤더 경로는 유지한다. 中文 별칭은 같은 함수를 가리킨다. 변수와 实现 파일에는 의미를 드러내는 中文 이름을 사용한다. 翻译源代码 근거는 [命名 원칙](命名原则.md), 实际数据 대응은 [용어 대응표](术语映射.tsv)에 기록했다.

## 제공하는 기능

| 裁剪 | 实现 | 当前项目 限制值 |
|---|---|---|
| 文件 | open/creat/read/write/close/lseek/unlink/ftruncate/fstat/fsync | 루트의 단일 名称, ASCII 63바이트, 8개 文件, 파일당 16KiB |
| 描述符条目 | dup/dup2, F_DUPFD/F_DUPFD_CLOEXEC/F_GETFD/F_SETFD/F_GETFL/F_SETFL | 进程值 一值, 最大值 32개; 锁值·exec 미구현 |
| 输入输出 设置 | O_RDONLY/O_WRONLY/O_RDWR/O_CREAT/O_EXCL/O_TRUNC/O_APPEND/O_NONBLOCK/O_CLOEXEC | 그 밖의 비트는 ENOTSUP; 实际数据 用户·그룹 存取条目 权限值 검사는 缺失方法 |
| 표준 终端输入输出 | 0 读取, 1·2 写入, 字节值 单位值 输入值 | 终端 编辑值·termios·시그널 缺失方法, 韩文文本 字体值/입력기 缺失方法 |
| UDP | socket/bind/sendto/recvfrom/getsockname, SO_RCVTIMEO | IPv4 UDP만, 묶인 端点值 4개, 전문당 1,024바이트, 接收值 等待状态值 设置 最大值 2초 |
| 地址 | htons/ntohs/htonl/ntohl/inet_pton/inet_ntop | IPv4 数字值 주소만; DNS/IPv6 缺失方法 |
| 작은 C 支持值 | strlen/strcmp/memcpy/memset/memcmp/puts/putchar | 전체 libc·stdio FILE·malloc 缺失方法 |
| 存储值 | JKSTORE1 전용 IDE 存储值, 두 보존본과 校验和 | FAT/ext 文件系统·디렉터리·하드 링크·심볼릭 링크 缺失方法 |
| 게스트 Java | FileInputStream(String).read()/close(), FileOutputStream(String[, boolean]).write(int)/close() | 数组值 输入输出·일반 java.io·异常 进程值条目 缺失方法 |

`dup`으로 복제한 서술자는 文件 위치와 追加继续状态 설정을 공유한다. `FD_CLOEXEC`는 서술자마다 저장한다. `unlink`는 이름만 제거하며, 열린 파일의 내용은 最后项目 참조가 닫힐 때까지 접근할 数 있다. 빈 위치를 건너뛰어 쓰거나 길이를 늘린 영역은 0으로 읽힌다. 文件描述符 부족으로 실패한 `open`은 파일을 생성하거나 비우지 않는다. C 调用 실패는 `-1`과 `errno`, 내부 内核值 호출은 负数值 错误 번호를 반환한다.

`fstat`는 이 프로젝트 전용 48바이트 구조체에 种类值·大小·링크 数·授权权限 位值 등을 반환한다. POSIX의 전체 时间值 속성은 아직 제공하지 않는다. 다른 운영체제의 `struct stat` 또는 Linux 바이너리 ABI와 호환되지 않는다. `O_CLOEXEC`는 기록할 数 있지만 当前项目 exec 기능은 없다. 성공하는 函数 이름만으로 전체 POSIX 의미가 구현되었다고 간주하면 안 된다.

UDP는 QEMU RTL8139의 实际数据 宿主 왕복을 지원한다. 짧은 接收值 버퍼에는 앞부분을 복사하고 余数值 전문을 버린다. 빈 전문도 송수신한다. `SO_RCVTIMEO` 또는 비차단 수신의 数据 없음은 `EAGAIN`이다. TCP를 요청하면 `EPROTONOSUPPORT`를 반환한다. 루프백·브로드캐스트·멀티캐스트·연결형 套接字值·listen/accept는 아직 없다. 기존 AOT Java UDP 손잡이는 이 POSIX 서술자와 별개이므로 서로 섞어 닫지 않는다.

모든 用户 프로그램에는 기존 약 3초 执行命令 상한이 적용된다. `errno`는 当前项目 단일 进程值·단일 스레드 변수다. JDK 전체, Swing/AWT/JavaFX, TCP/DNS/HTTP/TLS, 스레드·GC·JIT·동적 연결은 아직 구현하지 않았다. 전체 Java SE 执行命令 환경을 만들려면 해당 内核值 기반과 런타임 이식을 继续处理 진행하거나 별도 Linux 基础 执行命令 방식을 결정해야 한다.

## 存储值 형식과 有效性校验

매체는 512바이트 区段值 2,048개(1MiB)第三操作数. 区段值 0의 `JKSTORE1` 标识符值·大小·格式值 번호가 构建全部 맞는 장치만 写入 대상으로 삼는다. 区段值 1과 260에서 각각 259구역짜리 보존본이 시작한다. 각 보존본은 是否完成 头值 1구역, 文件 表 2구역, 文件 数据 256구역으로 구성된다.

`fsync`와 `sync`는 이름이 남아 있는 모든 파일의 当前项目 상태를 저장한다. 반대편 보존본을 무효화한 后端值 文件 표와 자료를 쓰고 ATA 캐시 비우기를 실행한다. 마지막에 代次值 번호와 FNV-1a 검사합을 가진 是否完成 머리를 기록하고 重试值 캐시를 비운다. 启动 시 검사합과 표가 유효한 가장 最近值 세대를 선택한다. 검사합은 우발적인 손상을 查找条目 위한 것이며 암호학적 무결성 검증은 아니다. 实际数据 设备 전원 차단 시험은 하지 않았다.

복원된 文件 목록은 启动 이미지의 默认值 用例/`JAVA_FILES` 목록을 대체한다. 새 예제를 이미지에 추가해도 기존 存储值 매체를 연결하면 저장된 목록이 우선한다. 동기화하지 않은 변경은 재부팅 之后状态 사라진다.

`make test-posix`는 中文 标识符值 转换值, ELF/ISO의 实际数据 C ABI 调用, 공유 位置, 삭제된 파일의 수명, 文件/描述符条目 고갈, 指针 错误, 표준 输入值, UDP, `fsync`, 재부팅, 손상된 最新值 보존본의 회피, 다른 형식의 介质值 비변경, 게스트 Java 文件 처리와 OpenJDK 교차 실행을 확인한다. 기록은 `os/build/契约测试.json`, `持久化测试.json`, `Java文件测试.json`이다.
