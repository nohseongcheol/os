# jkoros 안에서 Java bou_bron·uitvoer_bevel

이 문서의 부팅·dop·bêre_VALUE 명령은 **x86 weergawe_VALUE** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 weergawe_VALUE](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 lêer_naam_SMS, `edit`의 단독 `.` bêre_VALUE, 16개 RAM Lêer, 약 2초 uitvoer_bevel 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 werklik_data JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. hou bou_bron 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java program_f5044b9b 실행은 아직 지원하지 않는다.

## 직접 작성

`edit`는 Lêer 전체를 새 내용으로 작성한다. 기존 내용의 lyn redigeer_VALUE 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 greep_VALUE 수 wys_VALUE.
- `cat FILE`: Lêer Inhoud_VALUE wys_VALUE. 텍스트 소스에 사용한다.
- `rm FILE`: Geheue_data Lêer 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·TYPE_VALUE 검사 faling_VALUE 시 기존 `.class`는 유지된다. 소스를 고친 TERUG_VALUE 컴파일이 실패했다면 이전 uitvoer_bevel 파일이 남아 있으므로 bou_bron 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 bêre_VALUE 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 bron_boom·Klas_VALUE·data 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, Lêer 이름은 ASCII 1~63자다. bron_boom 이름은 `.class` 확장자 공간 때문에 최대 62자다. redigeer_VALUE 입력은 ASCII이고 한 lyn 최대 128자다. lyn 또는 Lêer 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. kern_VALUE/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 gebruiker 예제 이름은 ASCII로 작성한다.

## 외부 Lêer 적재

호스트에서 만든 소스나 Bystand_VALUE snit 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 werklik_data 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# hou JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 Volgende_item 빌드에서는 추가 파일을 포함하지 않는다. Lêer Inhoud_VALUE 변경과 inskrywing_Lys 제거도 Volgende_item 빌드에 반영된다. 원본 hou 파일에는 쓰지 않는다. verstekwaarde `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 verstekwaarde 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 Klas_VALUE Lêer 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 Bystand_VALUE snit 안에 있어야 한다.

## Bystand_VALUE snit

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| Klas_VALUE | 패키지 없는 단일 Klas_VALUE, staties_VALUE funksie_VALUE, 재귀, 인수/teruggee_maatreël | 실행마다 단일 Klas_VALUE 적재, public static main(String[]) |
| verstekwaarde VALUE | int, boolean, char, String, main의 String[] 인수 | heelgetal·Naslaan 스택, String, int[], String[], 내부 StringBuilder |
| stelling_VALUE | 초기값 있는 lokaal_bestek verklaring, opdrag_VALUE, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 heelgetal·Naslaan 바이트코드와 toestand tak |
| uitdrukking_VALUE | 십진 heelgetal, UTF-8 소스의 string_VALUE/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, string_VALUE 결합 | heelgetal werking_VALUE·bis_VALUE werking_VALUE·TYPE_VALUE CONVERT_VALUE, 단락 평가, ARRAY_VALUE toegang_inskrywing |
| Lêer | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | werklik_data kern_VALUE 파일서술자와 Koppel, genereer·vee_uit_inhoud·이어쓰기·EOF |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 lokaal_bestek verklaring, 오버로드, 임의 TYPE_VALUE CONVERT_VALUE, ARRAY_VALUE genereer Bron, 8/16진 리터럴, Unicode bron_boom 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 konstante_VALUE 축소 변환을 구현하지 않는다. 외부 `.class`의 `int[]` genereer/Lees/쓰기는 지원하므로 hou `javac --release 8`로 만든 ARRAY_VALUE 예제는 실행할 수 있다.

objek_VALUE veld_VALUE·일반 objek_VALUE genereer·상속·인터페이스·여러 Klas_VALUE Koppel, long/float/double, uitsondering Proses_VALUE_inskrywing, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java uitsondering 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 string_VALUE bêre_VALUE 공간은 uitvoer_bevel Verlaat_program 시 gebruiker 영역 전체와 함께 회수한다. 지속 uitvoer_bevel 중 GC는 없다.

## uitvoer_bevel 한도와 Fout

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 Bystand_VALUE 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM woordeboek 검증기를 구현한 것은 아니다. Lêer/kenmerk_VALUE lengte_VALUE, konstante_VALUE Naslaan, Opdrag·tak 경계를 검사하고, uitvoer_bevel 중 스택 formaat_VALUE·lokaal_bestek inisialiseer·ARRAY_VALUE voetskrif_VALUE·objek_VALUE 참조를 검사한다. gebruiker 코드의 페이지·hardeware_ombou 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, bou_bron·JVM 오류는 `Exit: 1`, Opdrag 인수 오류는 `Exit: 2`다. CPU tyd_VALUE 상한은 기존 `Exit: 124`이며, gebruiker ELF 자체의 CPU/런타임 오류는 기존 Verlaat_program 코드를 따른다. faling_VALUE 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## Java Lêer I_O

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 Klas_VALUE 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 TERUG_VALUE `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. verstekwaarde Afvoer 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. uitsondering objek_VALUE·try/catch·try-with-resources는 지원하지 않으며 Lêer 오류를 진단하고 프로그램을 종료한다. ARRAY_VALUE I_O, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 Lêer 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 dop `sync`가 필요하다. 예제의 Lêer 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 werklik_data 게스트 bou_bron 결과를 OpenJDK `-Xverify:all`로 다시 실행해 Lêer 바이트와 출력을 대조한다. 범위와 bêre_VALUE media_VALUE 사용법은 [posix-kor README_eb81d7d9](../posix-kor/README_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
