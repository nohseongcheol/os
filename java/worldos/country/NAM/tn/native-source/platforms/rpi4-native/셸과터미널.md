이 터미널은 자체 Java 커널의 셸을 프레임버퍼 창과 UART에서 사용한다. Taelo Thulaganyo_Boleng_tsenyo·RAM faele·파이프는 Java Khenele_Boleng, 화면의 Letshwao_Boleng 그리기는 freestanding C에서 수행한다. Linux·X11·Bash 없이 동작하며, 자체 JVM의 Swing Thuso_Boleng 부분집합도 같은 fensetere 시스템을 이용한다. 자세한 vi·다중 fensetere·코딩 사용법은 [개발 매뉴얼](개발안내.md)을 참고한다.

FTP와 외부 네트워크도 함께 쓰려면 `python3 Thuluse/diragatsa_Taelo.py --desktop --network`로
실행한다. Remmina VNC는 `127.0.0.1:5902`, 게스트에서 `ftpd start` 후 FTP는
`127.0.0.1:2121`이다. `--port`, `--ftp-port`, `--forward`를 함께 지정할 수 있다.
한 VM의 보조 UART로 SLIP를 전송하고 주 UART로 GUI 입력을 전달한다.

## 문법과 제한

작은따옴표·큰따옴표·백슬래시, `$NAME`/`${NAME}`/`$?`, Lefoko_Boleng 앞 `~`, Mola 주석 `#`, 순차 diragatsa_Taelo `;`, boemo diragatsa_Taelo `&&`/`||`, 파이프 `|`, 입력 `<`, 새 출력 `>`, 추가 출력 `>>`를 제공한다. 변수 확장은 인수 안에서 수행하며 katoloso_Boleng 결과를 공백으로 다시 나누지 않는다. `export`의 값은 setlhalosataelo 안에서만 공유하며 modirisi ELF의 envp/getenv 환경은 아직 없다.

파이프는 각 단계를 순서대로 실행하고 최대 **16384바이트**를 다음 단계로 넘긴다. 여러 프로세스가 동시에 읽고 쓰는 POSIX 파이프가 아니다. 용량 초과는 phoso 28과 palelo_Boleng 상태를 반환하고 해당 실행을 중단한다. `<`는 EOF를 제공하며 `>`/`>>`는 stdout만 바꾼다. EL0 fd 2는 화면/UART로 출력된다. `2>` 등 번호를 붙인 리다이렉션은 거부한다. 일부 내장 명령의 진단은 stdout을 사용한다. 연결한 프로그램의 `exit N` 진단은 데이터에 섞이지 않도록 생략한다.

`vi`, `edit`, `load`, `gui`, `terminal`, `sh`, `source`에는 파이프와 리다이렉션을 적용할 수 없다. 리다이렉션 파일을 열지 못하거나 파이프 용량을 초과하면 ga_jaana_selwana 명령줄을 중단하며, 그 줄의 뒤쪽 `||` 명령도 실행하지 않는다. Sekeripiti_Boleng 파일을 입력할 때 멀티라인 따옴표·이어 쓰기는 제공하지 않는다. `if`/`for`/`while`, TIRISO_Boleng, Taelo 치환, glob, 별칭, 백그라운드 `&`, jobs/fg/bg, 일반 프로세스·신호·PTY는 아직 없다. Bash/POSIX sh 전체 호환으로 표시하지 않는다.

faele 64개 × 각 16384바이트, 루트 외 디렉터리 15개, faele 서술자 16개, tsela 최대 UTF-8 63바이트다. semphato_Boleng/절대 경로와 `.`/`..`를 정규화하지만 tetla_Boleng·심볼릭 링크·마운트·디스크 영속 저장은 없다. **faele·디렉터리·변수·기록의 수정 내용은 재부팅하면 사라진다.** modirisi 실행도 ga_jaana_selwana setlhalosataelo 경로를 사용한다.
