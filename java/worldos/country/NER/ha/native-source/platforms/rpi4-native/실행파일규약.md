# ELF 형식과 Linux gudanar_Umarni Fayil 호환성

**ELF는 확장자가 아니다.** Executable and Linkable Format이라는 바이너리
형식이며, Linux 외의 운영체제도 사용한다. 첫 네 bayit_Daraja `7f 45 4c 46`,
ELF Aji_Daraja, CPU 종류, Shiri_f5044b9b 헤더와 Mashigar_bayanai_maki_Daraja 주소를 읽어서 해석한다.
[ELF ABI 명세](https://gabi.xinuos.com/elf/02-eheader.html)

기존 jkoros 로더도 Na_hakika_Tarin_bayani ELF64/AArch64 gudanar_Umarni 파일을 읽었다. `.elf`는 예제의
이름일 뿐이었다. 다만 **ELF zubi_Daraja 지원과 Linux 시스템 호출 ABI 지원은 별개**다.
기존에는 `JKOROS` ABI note를 가진 자체 gudanar_Umarni 파일만 허용했고, Linux 바이너리는
호환되지 않았다. ARM64 Linux는 SVC의 x8에 Linux 시스템 호출 번호를 넣는다.
같은 번호를 자체 ABI로 해석하면 다른 동작이 되므로 두 경로를 구분한다.
[Linux syscall ABI 설명](https://man7.org/linux/man-pages/man2/syscall.2.html)

자체 바이너리와 JAR의 Mai_fayyace_umani 직접 실행은 Fayil 헤더로 구분한다. `run`은 자체 ELF,

자체 ABI에 넣지 않으며, 자체 ABI note가 있는 파일은 Linux 모드에서 거부한다.
현재 RAM Fayil 체계에는 gudanar_Umarni izini_Daraja 비트와 `chmod`, PATH 검색이 없다.

## 제한된 Linux ABI

이 기능은 **자체 Java Kwara_Daraja 안의 호환 Tsarkiya_Daraja**이며 Linux 커널을 적재하지 않는다.

| Linux 호출 | Indes | 현재 제약 |
|---|---:|---|
| read / write / close / lseek | 63 / 64 / 57 / 62 | RAM 파일과 표준 I_O; 입력 대기는 EAGAIN 가능 |
| openat / unlinkat | 56 / 35 | AT_FDCWD 또는 절대 Hanyar_shiga; 파일만, 제한된 플래그 |
| ftruncate / fsync | 46 / 82 | RAM Fayil; fsync가 영속 저장을 의미하지 않음 |
| exit / exit_group | 93 / 94 | 현재 Shiri_f5044b9b Mafita_Shiri |
| brk | 214 | 자체 Mai_anfani_da_kwamfuta 힙 darfi; Kasa_aiki_Daraja 시 이전 break 반환 |
| clock_gettime | 113 | CLOCK_MONOTONIC만, 밀리초 Kyawon_tarkacen_hoto_Daraja |
| getpid / gettid | 172 / 178 | 한 Mai_anfani_da_kwamfuta gudanar_Umarni 흐름의 mai_ganewa_Daraja |

미지원 번호는 `-ENOSYS`를 반환한다. Linux ABI의 socket, fork/clone/execve,
pthread, mmap, signal, ioctl, fstat, 동적 로더와 일반 libc 초기화는 구현하지
않았다. 기존 자체 POSIX/Java 소켓은 별도로 TCP/UDP를 지원한다.

초기 스택에는 argc, UTF-8 argv, 빈 envp, AT_PAGESZ/AT_ENTRY/AT_NULL을 넣는다.
입력은 ELF64 little-endian AArch64 **ET_EXEC**, Fayil 전체 **16 KiB 이하**,
PT_LOAD 주소는 **0x02000000 이상 0x02c00000 미만**이어야 한다.
Fayil 오프셋과 가상 주소의 페이지 Daidaita_Daraja 관계를 검사하며, 서로 페이지를 공유하는
세그먼트와 Yi_Rubutu·gudanar_Umarni 동시 허용은 거부한다. PT_INTERP/PT_DYNAMIC/PT_TLS와
ET_DYN은 아직 받지 않는다.

일반 Linux 바이너리의 Tanadaddiyar_daraja 적재 imel 0x00400000은 커널과 겹치므로 아직 받지
않는다. 예제는 GNU 링커의 `-Ttext-segment=0x02000000 -z max-page-size=4096`을
사용한다. 이 파일도 정상적인 Linux ELF이며 같은 파일이 Linux와 자체 커널에서
실행됨을 시험한다. Fayil 이름이나 헤더만 바꿔 기존 Linux Shiri_f5044b9b 전체를 지원할
수는 없다.
