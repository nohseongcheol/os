# jkoros 안에서 Java يحول_برمجياً_مصدر·ينفذ_أمر

이 문서의 إقلاع_الآلة·셸·مخزن_قيمة 명령은 **x86 إصدار_قيمة** 기준이다. 공유 Java محول_برمجي/JVM은 [ذاتي ARM64 Pi4 إصدار_قيمة](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART إدخال_قيمة·한글 اسم_الملف_نص, `edit`의 단독 `.` مخزن_قيمة, 16개 RAM ملف, 약 2초 ينفذ_أمر 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 الفعلي_بيانات JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. مضيف يحول_برمجياً_مصدر 서버나 Linux 게스트는 사용하지 않는다.

**حديث_عنصر 구현은 ذاتي 제한형 محول_برمجي·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java تطبيق_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 ينفذ_أمر

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. ينفذ_أمر 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 إقلاع_الآلة 절차는 [VirtualBox ينفذ_أمر 안내](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 ملف 전체를 새 내용으로 작성한다. 기존 내용의 سطر يحرر_قيمة 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 بايت_قيمة رقم عرض_قيمة_487749b8.
- `cat FILE`: ملف محتوى_قيمة عرض_قيمة_487749b8. 텍스트 소스에 사용한다.
- `rm FILE`: ذاكرة_بيانات ملف 삭제.
- `edit FILE`: 전체 내용을 새로 إدخال_قيمة. 빈 파일도 저장할 رقم 있다.
- 구문·نوع_قيمة 검사 فشل_قيمة 시 기존 `.class`는 유지된다. 소스를 고친 عودة_قيمة 컴파일이 실패했다면 이전 ينفذ_أمر 파일이 남아 있으므로 يحول_برمجياً_مصدر 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 مخزن_قيمة 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 مصدر_شجرة·فئة_قيمة_55654bf1·بيانات 파일을 보존할 رقم 있다. 최대 8개, 파일마다 16KiB, ملف 이름은 ASCII 1~63자다. مصدر_شجرة 이름은 `.class` 확장자 عنوان_منطقة 때문에 최대 62자다. يحرر_قيمة 입력은 ASCII이고 한 سطر 최대 128자다. سطر 또는 ملف 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. نواة_قيمة/محول_برمجي/JVM 구현의 Java 식별자는 한국어이며, حديث_عنصر 게스트 إدخال_قيمة 제한 때문에 فضاء_المستخدم 예제 이름은 ASCII로 작성한다.

## خارجي_قيمة ملف 적재

호스트에서 만든 소스나 دعم_قيمة يقص 안의 `.class`를 إقلاع_الآلة 이미지에 포함할 رقم 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 الفعلي_بيانات 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# مضيف JDK로 컴파일한 클래스도 사용할 رقم 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 إقلاع_الآلة 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 التالي_عنصر 빌드에서는 إلحاق_إدخال 파일을 포함하지 않는다. ملف محتوى_قيمة 변경과 إدخال_قائمة_f07b3200 제거도 التالي_عنصر 빌드에 반영된다. 원본 مضيف 파일에는 쓰지 않는다. قيمة_افتراضية `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 قيمة_افتراضية 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 فئة_قيمة_55654bf1 ملف 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 دعم_قيمة يقص 안에 있어야 한다.

## دعم_قيمة يقص

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| فئة_قيمة_55654bf1 | 패키지 없는 단일 فئة_قيمة_55654bf1, ثابت_قيمة_f430d3f5 دالة_قيمة, 재귀, وسائط/إرجاع_مقياس | 실행마다 단일 فئة_قيمة_55654bf1 적재, public static main(String[]) |
| قيمة_افتراضية قيمة | int, boolean, char, String, main의 String[] وسائط | عدد_صحيح·مرجع مُعامل_رمز, String, int[], String[], 내부 StringBuilder |
| كشف_قيمة | 초기값 있는 محلي_نطاق إعلان, مهمة_قيمة, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 عدد_صحيح·مرجع 바이트코드와 شرط فرع |
| تعبير_قيمة | 십진 عدد_صحيح, UTF-8 소스의 سلسلة_قيمة/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, سلسلة_قيمة 결합 | عدد_صحيح تشغيل_قيمة·بت_قيمة تشغيل_قيمة·نوع_قيمة تحويل_قيمة, 단락 평가, صفيف_قيمة يصل_إدخال |
| ملف | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | الفعلي_بيانات نواة_قيمة 파일서술자와 اتصال, إنشاء·مسح_المحتويات·이어쓰기·EOF |
| مخرجات | System.out.print/println: int/boolean/char/String, println() | 동일 |
| سلسلة_قيمة/وسائط | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), سلسلة_قيمة 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 محلي_نطاق إعلان, 오버로드, 임의 نوع_قيمة تحويل_قيمة, صفيف_قيمة إنشاء مصدر, 8/16진 리터럴, Unicode مصدر_شجرة 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 ثابت_قيمة 축소 변환을 구현하지 않는다. خارجي_قيمة `.class`의 `int[]` إنشاء/قراءة/쓰기는 지원하므로 مضيف `javac --release 8`로 만든 صفيف_قيمة 예제는 실행할 رقم 있다.

عنصر_قيمة_2ed200e9 قيمة_الحقل·일반 عنصر_قيمة_2ed200e9 إنشاء·상속·인터페이스·여러 فئة_قيمة_55654bf1 اتصال, long/float/double, استثناء عملية_قيمة_إدخال, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java استثناء 객체를 던지지 않고 진단 후 حديث_عنصر 프로그램을 종료한다. 객체와 سلسلة_قيمة مخزن_قيمة 공간은 ينفذ_أمر خروج_تطبيق 시 فضاء_المستخدم منطقة_قيمة 전체와 함께 회수한다. 지속 ينفذ_أمر 중 GC는 없다.

## ينفذ_أمر 한도와 خطأ

| مصدر_قيمة | 한도 |
| --- | --- |
| مصدر_شجرة/فئة_قيمة_55654bf1 ملف | 각각 16KiB |
| محول_برمجي | رمز_مميز_قيمة 2,047개, إنشاء رمز_قيمة_f3cd31ee 4KiB, ثابت_قيمة 풀 4KiB |
| دالة_قيمة/وسائط | 클래스당 32함수, 함수당 16인수 |
| JVM ثابت_قيمة | 511개 |
| JVM دالة_قيمة رمز_قيمة_f3cd31ee | 함수당 8KiB |
| JVM 호출/مُعامل_رمز/محلي_نطاق متغيّر_قيمة | 32프레임, 프레임당 مُعامل_رمز 128칸·محلي_نطاق 128칸 |
| JVM عنصر_قيمة_2ed200e9 مخزن_قيمة عنوان_منطقة | 8,192개 32비트 فتحة_إدخال, 헤더 تصريحات 약 32KiB |
| ينفذ_أمر | 최대 500,000 أمر, 기존 커널의 약 3초 CPU ينفذ_أمر 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 دعم_قيمة 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM قاموس 검증기를 구현한 것은 아니다. ملف/قيمة_السمة 길이, ثابت_قيمة مرجع, أمر·فرع 경계를 검사하고, ينفذ_أمر 중 مُعامل_رمز ينسق_قيمة·محلي_نطاق تهيئة·صفيف_قيمة منخفض_قيمة·عنصر_قيمة_2ed200e9 참조를 검사한다. فضاء_المستخدم 코드의 페이지·أجهزة_منفذ 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, يحول_برمجياً_مصدر·JVM 오류는 `Exit: 1`, أمر وسائط 오류는 `Exit: 2`다. CPU قيمة_الوقت 상한은 기존 `Exit: 124`이며, فضاء_المستخدم ELF 자체의 CPU/런타임 오류는 기존 خروج_تطبيق 코드를 따른다. فشل_قيمة 후 셸에서 다른 프로그램을 계속 실행할 رقم 있다.

## 구현 위치와 اختبارات

- `os/فضاء_المستخدم/자바/자바컴파일러.java`: 게스트 어휘·구문·نوع_قيمة 검사, ثابت_قيمة 풀 및 바이트코드 إنشاء.
- `os/فضاء_المستخدم/자바/자바가상기계.java`: فئة_قيمة_55654bf1 적재, مُعامل_رمز·프레임·عنصر_قيمة_2ed200e9 مخزن_قيمة, أمر 해석과 제한된 표준 호출.
- `os/مصدر/ذاكرة_نظام_الملفات.java`: ذاكرة_بيانات نظام_الملفات, يحرر_قيمة, إقلاع_الآلة ملف 적재.
- `os/مصدر/نداء_النظام.java`, `compiler/بدء_مستخدم_تطبيق.s`: ملف/문자 مخرجات API와 فضاء_المستخدم مؤشر 검사.
- `os/أدوات/자바파일묶기.py`: مضيف إدخال_قيمة ملف التحقق_من_صحة·إقلاع_الآلة يجمع_قيمة إنشاء.

```sh
make test-java
make test
```

`os/اختبارات/자바시험.py`는 ELF/ISO إقلاع_الآلة, 게스트 يحول_برمجياً_مصدر·ينفذ_أمر, فضاء_المستخدم إدخال_قيمة, 재귀·반복문·عدد_صحيح 극값·سلسلة_قيمة 결합·단락 평가, 재실행, مصدر_شجرة خطأ 후 기존 فئة_قيمة_55654bf1 보존, صفيف_قيمة/رقم 해독 خطأ, 무한 تكرار_قيمة 제한, يحرر_قيمة 넘침과 ملف 부족을 검사한다. 게스트 إنشاء 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 مضيف OpenJDK의 فئة_قيمة_55654bf1, عدد_صحيح 배열과 한글 상수를 게스트에 적재하며, 손상된 ملف علامة_قيمة_7e8f90bd·버전·ثابت_قيمة رقم·فرع·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 اختبارات VM만 생성하고 종료한다.

구현 형식의 참고 بيانات: Oracle [JVM فئة_قيمة_55654bf1 ملف المواصفات](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM أمر المواصفات](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java ملف إدخال_إخراج

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 فئة_قيمة_55654bf1 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 إقلاع_الآلة 이미지에 넣은 عودة_قيمة `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. قيمة_افتراضية مخرجات 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. استثناء عنصر_قيمة_2ed200e9·try/catch·try-with-resources는 지원하지 않으며 ملف 오류를 진단하고 프로그램을 종료한다. صفيف_قيمة إدخال_إخراج, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 ملف 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 셸 `sync`가 필요하다. 예제의 ملف 이름은 حديث_عنصر 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/اختبارات/자바파일시험.py`는 الفعلي_بيانات 게스트 يحول_برمجياً_مصدر 결과를 OpenJDK `-Xverify:all`로 إعادة_محاولة_قيمة 실행해 ملف 바이트와 출력을 대조한다. 범위와 مخزن_قيمة وسائط_قيمة 사용법은 [posix-kor 안내](../posix-kor/안내.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
