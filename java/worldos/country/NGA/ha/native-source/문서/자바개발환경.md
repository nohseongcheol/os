# jkoros 안에서 Java Gina_tushe·gudanar_Umarni

이 문서의 부팅·Mai_fayyace_umani·Ajiye_Daraja 명령은 **x86 siga_Daraja** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 siga_Daraja](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 Fayil_Suna_SMS, `edit`의 단독 `.` Ajiye_Daraja, 16개 RAM Fayil, 약 2초 gudanar_Umarni 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 Na_hakika_Tarin_bayani JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. sauka Gina_tushe 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java Shiri_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 gudanar_Umarni

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)

55
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. gudanar_Umarni 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox gudanar_Umarni README_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 Fayil 전체를 새 내용으로 작성한다. 기존 내용의 Layi gyaran_Daraja 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 bayit_Daraja 수 Nuna_Daraja.
- `cat FILE`: Fayil kunshiya_Daraja Nuna_Daraja. 텍스트 소스에 사용한다.
- `rm FILE`: Mahardatar_kwamfuta_Tarin_bayani Fayil 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·rubuta_Daraja 검사 Kasa_aiki_Daraja 시 기존 `.class`는 유지된다. 소스를 고친 Baya_Daraja 컴파일이 실패했다면 이전 gudanar_Umarni 파일이 남아 있으므로 Gina_tushe 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 Ajiye_Daraja 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 tushe_Li_irabin_tarin_bayanai·Aji_Daraja·Tarin_bayani 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, Fayil 이름은 ASCII 1~63자다. tushe_Li_irabin_tarin_bayanai 이름은 `.class` 확장자 공간 때문에 최대 62자다. gyaran_Daraja 입력은 ASCII이고 한 Layi 최대 128자다. Layi 또는 Fayil 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. Kwara_Daraja/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 Mai_anfani_da_kwamfuta 예제 이름은 ASCII로 작성한다.

## 외부 Fayil 적재

호스트에서 만든 소스나 taimako_Daraja darfi 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 Na_hakika_Tarin_bayani 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# sauka JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 다음 빌드에서는 추가 파일을 포함하지 않는다. Fayil kunshiya_Daraja 변경과 Mashigar_bayanai_Jeri 제거도 다음 빌드에 반영된다. 원본 sauka 파일에는 쓰지 않는다. Tanadaddiyar_daraja `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 Tanadaddiyar_daraja 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 Aji_Daraja Fayil 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 taimako_Daraja darfi 안에 있어야 한다.

abu_Daraja Fili_Daraja·일반 abu_Daraja 생성·상속·인터페이스·여러 Aji_Daraja Haɗi, long/float/double, banbanchi haryar_aikin_na_ura_Daraja_Mashigar_bayanai, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java banbanchi 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 Zare_Daraja Ajiye_Daraja 공간은 gudanar_Umarni Mafita_Shiri 시 Mai_anfani_da_kwamfuta 영역 전체와 함께 회수한다. 지속 gudanar_Umarni 중 GC는 없다.

## Java Fayil I_O

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 Aji_Daraja 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 Baya_Daraja `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. Tanadaddiyar_daraja 출력 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. banbanchi abu_Daraja·try/catch·try-with-resources는 지원하지 않으며 Fayil 오류를 진단하고 프로그램을 종료한다. TSARI_Daraja I_O, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 Fayil 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 Mai_fayyace_umani `sync`가 필요하다. 예제의 Fayil 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 Na_hakika_Tarin_bayani 게스트 Gina_tushe 결과를 OpenJDK `-Xverify:all`로 다시 실행해 Fayil 바이트와 출력을 대조한다. 범위와 Ajiye_Daraja Midiya_Daraja 사용법은 [posix-kor README_eb81d7d9](../posix-kor/README_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
