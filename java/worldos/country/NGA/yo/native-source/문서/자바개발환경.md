# jkoros 안에서 Java ṣàkójọ_ìtumò_èdè_kọ̀ǹpútà_orísun·ṣiṣẹ́_àṣẹ

이 문서의 부팅·ṣẹ́ẹ̀lì·Store_iye 명령은 **x86 ẹ̀yà_iye** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 ẹ̀yà_iye](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 fáìlì_orúkọ_SMS, `edit`의 단독 `.` Store_iye, 16개 RAM Fáìlì, 약 2초 ṣiṣẹ́_àṣẹ 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 gangan_détà JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. olùpèsè ṣàkójọ_ìtumò_èdè_kọ̀ǹpútà_orísun 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java àtòjọ_ètò_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 ṣiṣẹ́_àṣẹ

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. ṣiṣẹ́_àṣẹ 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox ṣiṣẹ́_àṣẹ KÀ_MÍ_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 Fáìlì 전체를 새 내용으로 작성한다. 기존 내용의 ìlà ṣàtúnṣe_iye 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 báìtì_iye 수 ṣàfihàn_iye.
- `cat FILE`: Fáìlì Àkóónú_iye ṣàfihàn_iye. 텍스트 소스에 사용한다.
- `rm FILE`: ibi_ìpamọ́_détà Fáìlì 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·irú_iye 검사 ìkùnà_iye 시 기존 `.class`는 유지된다. 소스를 고친 Padà_sẹ́yìn_iye 컴파일이 실패했다면 이전 ṣiṣẹ́_àṣẹ 파일이 남아 있으므로 ṣàkójọ_ìtumò_èdè_kọ̀ǹpútà_orísun 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 Store_iye 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 orísun_ètò_afigijúwe·ọ̀wọ́_iye·détà 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, Fáìlì 이름은 ASCII 1~63자다. orísun_ètò_afigijúwe 이름은 `.class` 확장자 공간 때문에 최대 62자다. ṣàtúnṣe_iye 입력은 ASCII이고 한 ìlà 최대 128자다. ìlà 또는 Fáìlì 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. kánẹ́ẹ̀lì_iye/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 aṣàmúlò 예제 이름은 ASCII로 작성한다.

## 외부 Fáìlì 적재

호스트에서 만든 소스나 àtìlẹ́yìn_iye ní_ṣókí 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 gangan_détà 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# olùpèsè JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 다음 빌드에서는 추가 파일을 포함하지 않는다. Fáìlì Àkóónú_iye 변경과 ìgbéwọlé_Àtòkọ 제거도 다음 빌드에 반영된다. 원본 olùpèsè 파일에는 쓰지 않는다. àdáwọ̀ `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 àdáwọ̀ 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 ọ̀wọ́_iye Fáìlì 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 àtìlẹ́yìn_iye ní_ṣókí 안에 있어야 한다.

## àtìlẹ́yìn_iye ní_ṣókí

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| ọ̀wọ́_iye | 패키지 없는 단일 ọ̀wọ́_iye, ìdágún_iye ÀKÀNṢEFỌMÚLÀ_iye, 재귀, 인수/반환 | 실행마다 단일 ọ̀wọ́_iye 적재, public static main(String[]) |
| àdáwọ̀ iye | int, boolean, char, String, main의 String[] 인수 | nọ́ńbà_odindi·Ìtọ́ka 스택, String, int[], String[], 내부 StringBuilder |
| àlàyé_iye | 초기값 있는 agbègbè_sàkání 선언, aṣetiléwá_iye, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 nọ́ńbà_odindi·Ìtọ́ka 바이트코드와 kání ẹ̀ka |
| ìsọ̀rọ̀sí_iye | 십진 nọ́ńbà_odindi, UTF-8 소스의 fọ́nrán_iye/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, fọ́nrán_iye 결합 | nọ́ńbà_odindi ìmú_ṣiṣẹ́_iye·bíìtì_iye ìmú_ṣiṣẹ́_iye·irú_iye 변환, 단락 평가, ÀRÉÈ_iye wáyè_sí_ìgbéwọlé |
| Fáìlì | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | gangan_détà kánẹ́ẹ̀lì_iye 파일서술자와 Darapọ̀, 생성·mú_kúrò_TOC·이어쓰기·EOF |
| 출력 | System.out.print/println: int/boolean/char/String, println() | 동일 |
| fọ́nrán_iye/인수 | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), fọ́nrán_iye 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 agbègbè_sàkání 선언, 오버로드, 임의 irú_iye 변환, ÀRÉÈ_iye 생성 orísun, 8/16진 리터럴, Unicode orísun_ètò_afigijúwe 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 aláìṣeéyípadà_iye 축소 변환을 구현하지 않는다. 외부 `.class`의 `int[]` 생성/Kàá/쓰기는 지원하므로 olùpèsè `javac --release 8`로 만든 ÀRÉÈ_iye 예제는 실행할 수 있다.

nǹkan_iye àayè_wúnrẹ̀n_iye·일반 nǹkan_iye 생성·상속·인터페이스·여러 ọ̀wọ́_iye Darapọ̀, long/float/double, 예외 Ìlànà_iye_ìgbéwọlé, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java 예외 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 fọ́nrán_iye Store_iye 공간은 ṣiṣẹ́_àṣẹ jáde_àtòjọ_ètò 시 aṣàmúlò 영역 전체와 함께 회수한다. 지속 ṣiṣẹ́_àṣẹ 중 GC는 없다.

## ṣiṣẹ́_àṣẹ 한도와 àṣìṣe

| ohun_àmúlò_iye | 한도 |
| --- | --- |
| orísun_ètò_afigijúwe/ọ̀wọ́_iye Fáìlì | 각각 16KiB |
| 컴파일러 | kóòdù_káàdì_àsansílẹ̀_iye 2,047개, 생성 코드 4KiB, aláìṣeéyípadà_iye 풀 4KiB |
| ÀKÀNṢEFỌMÚLÀ_iye/인수 | 클래스당 32함수, 함수당 16인수 |
| JVM aláìṣeéyípadà_iye | 511개 |
| JVM ÀKÀNṢEFỌMÚLÀ_iye 코드 | 함수당 8KiB |
| JVM 호출/스택/agbègbè_sàkání 변수 | 32프레임, 프레임당 스택 128칸·agbègbè_sàkání 128칸 |
| JVM nǹkan_iye Store_iye 공간 | 8,192개 32비트 ààyè_ìfàyọkàsí_ìgbéwọlé, 헤더 포함 약 32KiB |
| ṣiṣẹ́_àṣẹ | 최대 500,000 Àṣẹ, 기존 커널의 약 3초 CPU ṣiṣẹ́_àṣẹ 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 àtìlẹ́yìn_iye 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM àtumọ̀èdè 검증기를 구현한 것은 아니다. Fáìlì/àwòmọ́_iye gígùn_iye, aláìṣeéyípadà_iye Ìtọ́ka, Àṣẹ·ẹ̀ka 경계를 검사하고, ṣiṣẹ́_àṣẹ 중 스택 ìgúnrégé_iye·agbègbè_sàkání pàjùbà·ÀRÉÈ_iye òǹtẹ̀_ìsàlẹ̀_iye·nǹkan_iye 참조를 검사한다. aṣàmúlò 코드의 페이지·ohun_èlò_alárídìmú_ojú 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, ṣàkójọ_ìtumò_èdè_kọ̀ǹpútà_orísun·JVM 오류는 `Exit: 1`, Àṣẹ 인수 오류는 `Exit: 2`다. CPU 시간 상한은 기존 `Exit: 124`이며, aṣàmúlò ELF 자체의 CPU/런타임 오류는 기존 jáde_àtòjọ_ètò 코드를 따른다. ìkùnà_iye 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## 구현 위치와 시험

- `os/aṣàmúlò/자바/자바컴파일러.java`: 게스트 어휘·구문·irú_iye 검사, aláìṣeéyípadà_iye 풀 및 바이트코드 생성.
- `os/aṣàmúlò/자바/자바가상기계.java`: ọ̀wọ́_iye 적재, 스택·프레임·nǹkan_iye Store_iye, Àṣẹ 해석과 제한된 표준 호출.
- `os/orísun/ibi_ìpamọ́_ìlànà_ètò_fáìlì.java`: ibi_ìpamọ́_détà ìlànà_ètò_fáìlì, ṣàtúnṣe_iye, 부팅 Fáìlì 적재.
- `os/orísun/체계호출.java`, `compiler/bẹ̀rẹ̀_aṣàmúlò_àtòjọ_ètò.s`: Fáìlì/문자 출력 API와 aṣàmúlò ìtọ́ka 검사.
- `os/Àwọn_irinṣẹ́/자바파일묶기.py`: olùpèsè 입력 Fáìlì ìfọwọ́síìwé·부팅 Àjọṣe_iye 생성.

```sh
make test-java
make test
```

`os/시험/자바시험.py`는 ELF/ISO 부팅, 게스트 ṣàkójọ_ìtumò_èdè_kọ̀ǹpútà_orísun·ṣiṣẹ́_àṣẹ, aṣàmúlò 입력, 재귀·반복문·nọ́ńbà_odindi 극값·fọ́nrán_iye 결합·단락 평가, 재실행, orísun_ètò_afigijúwe àṣìṣe 후 기존 ọ̀wọ́_iye 보존, ÀRÉÈ_iye/수 해독 àṣìṣe, 무한 àṣetúnṣe_iye 제한, ṣàtúnṣe_iye 넘침과 Fáìlì 부족을 검사한다. 게스트 생성 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 olùpèsè OpenJDK의 ọ̀wọ́_iye, nọ́ńbà_odindi 배열과 한글 상수를 게스트에 적재하며, 손상된 Fáìlì 표식·버전·aláìṣeéyípadà_iye 수·ẹ̀ka·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 시험 VM만 생성하고 종료한다.

구현 형식의 참고 détà: Oracle [JVM ọ̀wọ́_iye Fáìlì 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM Àṣẹ 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java Fáìlì I_O

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 ọ̀wọ́_iye 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 Padà_sẹ́yìn_iye `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. àdáwọ̀ 출력 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. 예외 nǹkan_iye·try/catch·try-with-resources는 지원하지 않으며 Fáìlì 오류를 진단하고 프로그램을 종료한다. ÀRÉÈ_iye I_O, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 Fáìlì 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 ṣẹ́ẹ̀lì `sync`가 필요하다. 예제의 Fáìlì 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 gangan_détà 게스트 ṣàkójọ_ìtumò_èdè_kọ̀ǹpútà_orísun 결과를 OpenJDK `-Xverify:all`로 다시 실행해 Fáìlì 바이트와 출력을 대조한다. 범위와 Store_iye 매체 사용법은 [posix-kor KÀ_MÍ_eb81d7d9](../posix-kor/KÀ_MÍ_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
