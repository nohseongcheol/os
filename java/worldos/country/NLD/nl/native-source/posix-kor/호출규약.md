# gebruikersruimte 호출 grens_WAARDE

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `machine/besturingssysteem_Oproepen.s`에서 EAX(INDEX), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 argumenten)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. kernel_WAARDE 실패는 음수 fout INDEX, C bibliotheek 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 gebruikersruimte regio_WAARDE 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C gegevens 주소는 byte_WAARDE 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java bestand 흐름의 어셈블리 경계가 별도 byte_WAARDE 버퍼를 마련하여 같은 호출을 사용한다.

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 ADRES 두 칸이다. ontvangen_WAARDE 주소가 NULL이면 peer_WAARDE ADRES 기록을 생략한다. sockaddr_in은 16바이트이며 ADRES 체계는 mobiel_WAARDE byte_WAARDE REEKS_WAARDE, 접속번호와 IP 주소는 네트워크 byte_WAARDE 차례다. 축소된 ADRES 버퍼에도 들어가는 앞부분을 쓰고 전체 ADRES Grootte 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 Einde_app, 2·3은 기존 argumenten 조회다. actueel_item 커널의 argumenten 목록이 Uitvoeren_opdracht 이름을 제외하므로 C 진입기는 argv[0]에 고정 tekenreeks_WAARDE `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX Proces_WAARDE ABI와 다른 점이다.

표준 헤더의 geheel_getal Grootte, 플래그 WAARDE, stat veldwaarde 순서는 `broncode/declaraties/`에 정의한다. 동적 Verbinden·다중 Proces_WAARDE·스레드가 추가되면 fout INDEX 저장과 bron_WAARDE 수명, 호출 경계도 함께 검토해야 한다.
