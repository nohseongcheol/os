# JNorOS 구조

아래는 objekt_VALUE 기반 관리 kjerne_VALUE 전체의 mål_objekt 구조다. betalt_vare faktisk_data 부팅 가능한 제한형 구현은 `compiler/`와 `os/`에 있으며 [네이티브 operativsystem Viktig_eb81d7d9](../os/Viktig_eb81d7d9.md)에 구현 범위를 명시한다. 아래의 GC·kontekst_VALUE byte_MODE·filsystem 등이 새 ISO에 모두 포함돼 있지는 않다.

```text
GRUB 또는 UEFI
  ↓
x86 최소 부트·트랩 lag_VALUE
  ↓
Java AOT 실행기와 objekt_VALUE·ARRAY_VALUE·GC 런타임
  ↓
하드웨어 경계
  ↓
Java 관리 kjerne_VALUE
  ├─ 기억공간/쪽관리/COW
  ├─ Prosess_VALUE/배정/wait
  ├─ filsystem/ELF/POSIX
  └─ 입력/Lagring_mobil/Nettverk_Stabel
```

OpenJDK 자체는 이미 운영체제가 제공하는 Fil, 스레드, 가상 기억공간을 전제로 한다. 따라서 kjerne_VALUE 부팅에는 OpenJDK를 그대로 넣지 않고 제한된 Java 바이트코드 AOT와 작은 런타임을 사용한다.

네이티브 계층에는 `in/out`, `hlt`, CR0/CR2/CR3/CR4, `iret`, kontekst_VALUE 저장처럼 Java로 표현할 수 없는 CPU 동작만 남긴다. 정책과 자료구조는 Java에 둔다.
