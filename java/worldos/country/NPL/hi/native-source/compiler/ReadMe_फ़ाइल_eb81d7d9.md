# Java 네이티브 कंपाइलर

OpenJDK निज 소스를 빌드하는 **`--target openjdk-build`**와 निज कर्नेल_मान ABI 검사 도구를 추가했다.
이는 공식 javac/C/C++ 도구를 연결하는 별도 경로다. [बिल्ड_सिस्टम 방법·वास्तविक_डेटा मान्य_करें·कर्नेल_मान 이식 क्लिप](OpenJDK-소스빌드와-자체커널-이식.md)를 참고한다.

x86 직접 변환과 ARM64 C जनरेट_करें 후단은 모두 [पूर्वसंकलक.java](जावासाधन/पूर्वसंकलक.java)로 구현한다. `sh 미리번역.sh`로 직접 실행하며, [पूर्वसंकलक.py](पूर्वसंकलक.py)와 `कंपाइलर.py`는 이전 आदेश·API 및 OpenJDK 도구를 위한 호환 진입점이다. निज Pi4 후단은 freestanding C를 거쳐 AArch64로 만든다. [arm64.py](arm64.py)는 이전 경로와 Python 호출을 위한 호환 진입점이다. फ़ंक्_शन_मान·चर_मान·जनरेट_करें C 이름의 뜻과 예외는 [हिंदी 명명 ReadMe_फ़ाइल_eb81d7d9](../platforms/rpi4-native/명명/ReadMe_फ़ाइल_eb81d7d9.md)를 참고한다. [ARM64 बिल्ड_सिस्टम·समर्थन_मान क्लिप](../platforms/rpi4-native/ReadMe_फ़ाइल_eb81d7d9.md)에 निष्पादित_करें_आदेश 조건이 있다. 전체 OpenJDK나 일반 कक्षा_मान 실행기는 아니다.

निष्पादित_करें_आदेश 시 JVM이 필요 없는 x86 32비트 ELF를 만든다. JDK 11 이상으로 실행하는 Java निज AOT 후단이며, Java 전체를 새로 구현한 컴파일러는 아니다. Java 문법·पहुँच_एन्ट्री नियंत्रण_मान·लिखें_मान 검사는 JDK의 `javac`에 맡기고, Java 8 कक्षा_मान 파일을 읽어 각 바이트코드를 x86 명령으로 직접 변환한다. C 코드로 우회하거나 바이트코드 해석기를 커널에 넣지 않는다.

```text
Java स्रोत → javac의 문법·लिखें_मान 검사 → 임시 .class
          → निज x86 변환기 → GNU as/ld → 네이티브 ELF32
```

## 준비와 निष्पादित_करें_आदेश

बिल्ड_सिस्टम आयोजक: Linux, Python 3.6 이상, JDK 11 이상(`javac --release 8`), GNU binutils(`as`, `ld`), Make. अद्यतित_आइटम 환경의 OpenJDK 11, Python 3.6, binutils 2.30으로 검증했다. बाहरी_मान Python 패키지와 네트워크 다운로드는 사용하지 않는다.

```sh
cd /home/user/jkoros/compiler
make
./build/계산
echo $?                  # 0이면 예제 시험 성공

python3 कंपाइलर.py --target linux --entry 계산.चलाएँ \
    -o build/계산 예제/계산.java

make test
```

`linux` 대상은 Linux의 32비트 निष्पादित_करें_आदेश 호환 기능이 필요하다. `int 0x80`을 차단하는 샌드박스에서는 `Bad system call`이 발생할 수 있다. 정상 Linux आयोजक 또는 해당 실행을 허용한 시험 환경에서 실행한다. 시험의 비정상 종료를 통과로 처리하지 않는다.

진입점은 `static int चलाएँ()` 또는 `static void चलाएँ()`처럼 인수가 없어야 한다. `--entry 패키지.कक्षा_मान.फ़ंक्_शन_मान`로 선택한다. `int` 반환값은 Linux 프로세스 निर्गमन_ऐप 코드가 되며 셸에는 하위 8비트가 보인다. 일반 `main(String[] args)` निष्पादित_करें_आदेश 환경이나 표준 इनपुट_आउटपुट 라이브러리는 제공하지 않는다.

`--target kernel`은 부팅 코드와 연결할 재배치 ELF 오브젝트를 생성한다.

```sh
cd /home/user/jkoros
python3 compiler/कंपाइलर.py --target kernel --entry कर्नेल.चलाएँ \
    --export kernel_dispatch=체계호출.प्रक्रिया_मान_एन्ट्री \
    -o os/build/java.o os/स्रोत/*.java
```

`--target user`는 jkoros 셸에서 실행할 독립 ELF를 생성한다. `उपयोगकर्ता` 클래스의 제한된 native API는 `int 0x80` 시스템 호출로 연결하며 `उपकरण_मान` 클래스의 하드웨어 직접 접근은 거부한다. उपयोगकर्ता ELF는 Linux निष्पादित_करें_आदेश संचिका ABI와 다르므로 호스트에서 실행하지 않는다. जनरेट_करें·रजिस्टर_एन्ट्री 방법은 [उपयोगकर्ता निष्पादित_करें_आदेश ReadMe_फ़ाइल_eb81d7d9](../os/उपयोगकर्ता/ReadMe_फ़ाइल_eb81d7d9.md)에 있다. `--export 외부기호=कक्षा_मान.फ़ंक्_शन_मान`는 오버로드되지 않은 정적 함수를 निज ऑपरेंड_स्टैक ABI로 노출한다. 커널의 시스템 호출 진입점에 사용한다.

Java 파일은 필요한 클래스들을 한꺼번에 전달한다. निर्गम 옆의 `.s`는 생성된 어셈블리, `.json`은 स्रोत SHA-256 및 네이티브 प्रतीक↔Java फ़ंक्_शन_मान 대응표다. हिंदी 함수명은 원문과 대응표에 보존하고 ELF 내부에는 충돌 방지용 यंत्र 기호를 쓴다. कंपाइल_स्रोत·조립·जोड़ना 중 실패하면 기존 परिणाम 파일을 덮어쓰지 않는다.

## समर्थन_मान क्लिप

- `int`, `boolean`, `byte`, `short`, `char`의 32비트 계산 및 लिखें_मान रूपांतरित_करें_मान.
- 정적 필드와 정적 फ़ंक्_शन_मान, 매개변수·반환값, 재귀, 클래스별 지연 초기화와 आरंभ चक्र_मान.
- 조건문, 반복문, 단락 평가, 삼항식, पूर्णांक `switch`, 넓은 स्थानीय_दायरा चर_मान 인덱스.
- 덧셈·뺄셈·곱셈·나눗셈·나머지·बिट_मान 연산과 ले_जाएँ_मान. Java의 오버플로 및 `MIN_VALUE / -1` 동작을 유지한다.
- `int[]` जनरेट_करें·초기값 0·길이·पढ़ें·लिखें·संदर्भ 비교. 256KiB 고정 सरणी_मान क्षेत्र_मान, 널/सबस्क्रिप्ट_मान/आकार/पता_क्षेत्र 검사.
- स्ट्रिंग_मान 리터럴과 `String` संदर्भ, `length()` 및 `charAt()`. 문자열은 UTF-16 कोड_मान 단위로 저장하고 같은 리터럴은 공유한다. NUL 및 대리쌍도 시험한다.
- हिंदी कक्षा_मान·फ़ंक्_शन_मान·चर_मान·संचिका नाम.

`new Object`, 인스턴스 फ़ील्ड_मान/फ़ंक्_शन_मान, 상속/인터페이스, `long/float/double` निष्पादित_करें_आदेश ऑपरेशन_मान, `int[]` 이외 सरणी_मान, स्ट्रिंग_मान 동적 결합, Java 표준 लाइब्रेरी, अपवाद प्रक्रिया_मान_एन्ट्री, 스레드·सिंक्रनाइज़_करें·GC는 미지원이다. 실행에 필요한 미지원 바이트코드나 बाहरी_मान 호출을 발견하면 실패한다. 사용되지 않는 डिफ़ॉल्ट_मान 생성자는 निष्पादित_करें_आदेश 코드로 만들지 않는다. Java 8 문법이어도 모든 프로그램을 컴파일할 수 있다는 뜻은 아니다.

अपवाद ऑब्जेक्ट_मान 대신 런타임 त्रुटि 번호로 중단한다. Linux와 jkoros उपयोगकर्ता 대상에서는 `100 + इंडेक्स`로 종료하고 कर्नेल_मान 대상에서는 `JKOROS PANIC इंडेक्स`를 출력하고 정지한다. उपयोगकर्ता 프로그램만 종료한 경우 셸은 계속 실행된다.

| इंडेक्स | 원인 |
| --- | --- |
| 1 | 0으로 विभाग_परिणाम |
| 2 | 널 संदर्भ |
| 3 | सरणी_मान/स्ट्रिंग_मान सबस्क्रिप्ट_मान क्लिप 초과 |
| 4 | 음수 सरणी_मान आकार |
| 5 | सरणी_मान क्षेत्र_मान 부족 |

सरणी_मान 영역은 증가식 할당이며 회수하지 않는다. 재귀 스택의 경계 검사도 아직 없으므로 무제한 재귀를 안전하게 처리하는 런타임은 아니다. 특권 कर्नेल_मान 및 신뢰할 수 있는 작은 프로그램용 प्रारंभिक_स्थिति 구현이다.

## native 경계와 ABI

कर्नेल_मान 대상에서는 `os/स्रोत/उपकरण_मान.java`, उपयोगकर्ता 대상에서는 `os/उपयोगकर्ता/घोषणा/उपयोगकर्ता.java`의 정확한 विधि_नाम_पाठ·서술만 허용한다. 임의의 `native` 함수와 Linux/उपयोगकर्ता 대상의 하드웨어 접근은 거부한다. Java 인수를 왼쪽부터 32비트 한 칸씩 스택에 놓으며, 반환값은 EAX, EBP/ESP 이외 레지스터는 호출자가 보존한다고 가정하지 않는다. C의 cdecl/JNI ABI가 아니므로 C 함수와 바로 연결하면 안 된다.

Java स्रोत 또는 `.class` 입력을 받는다. 전체 JVM 바이트코드 검증기는 제공하지 않는다. 어노테이션 처리는 비활성화하고 비어 있는 कक्षा_मान पथ/स्रोत 경로에서 명시한 소스만 컴파일한다.

## 검증과 구현 근거

`시험/test_compiler.py`의 14개 시험에는 네이티브 ELF와 OpenJDK의 ऑपरेशन_मान परिणाम 대조, कक्षा_मान आरंभ, पूर्णांक 극값, स्ट्रिंग_मान/सरणी_मान, 재귀·switch·wide, 런타임 오류와 미지원 기능 अस्वीकृत_करें_मान, विफलता_मान 시 निर्गम 보존, उपयोगकर्ता ELF/अनुमति_मान 경계 및 내보내기 검증이 포함된다. 이것은 Java 전체 적합성 시험은 아니다.

आदेश 의미와 कक्षा_मान संचिका 형식은 Oracle의 [JVM आदेश 명세](https://docs.oracle.com/javase/specs/jvms/se11/html/jvms-6.html), [कक्षा_मान संचिका 명세](https://docs.oracle.com/javase/specs/jvms/se11/html/jvms-4.html)를 참고했다.
