# निज ARM64 커널의 Codex इंस्टॉल_करें_मान 가능성 검토

검토일: 2026-10-05. 소스와 공식 문서를 대조한 설계 검토이며, 게스트에 Codex를 설치하거나
로그인·모델 호출을 실행한 결과는 아니다. निज ARM64 커널과 `../rpi4` Linux 실행판은 구분한다.

अद्यतित_आइटम निज 커널에는 공식 Codex CLI를 그대로 इंस्टॉल_करें_मान·실행할 수 없다.
기술적으로 필요한 निष्पादित_करें_आदेश 환경을 추가하거나 Codex를 이식하는 경로는 있으나,
다운로드 आदेश 하나를 추가하는 작업으로 해결되지 않는다. JDK/JRE 기능 확장만으로도 해결되지 않는다.

## 확인한 근거

| एन्ट्री_मान | अद्यतित_आइटम 소스에서 확인한 अवस्था_मान | 직접 실행을 위한 작업 |
|---|---|---|
| निष्पादित_करें_आदेश संचिका | `यंत्र/उपयोगकर्ता.c`: AArch64 ET_EXEC만, PT_INTERP/PT_DYNAMIC/PT_TLS अस्वीकृत_करें_मान, 업로드 निष्पादित_करें_आदेश 버퍼 16384바이트 | लक्ष्य 바이너리에 맞는 ELF 적재·재배치·निष्पादित_करें_आदेश आरंभ, मेमोरी_डेटा/संचिका 제한 एक्सटेंशन_मान |
| Linux ABI | `यंत्र/리눅스호환.inc`: read/write/openat/brk 등 제한된 번호만 प्रक्रिया_मान_एन्ट्री, 나머지는 ENOSYS | libc/런타임에 필요한 시스템 호출을 추가하거나 निज ABI용 런타임 이식 |
| 프로세스·스레드 | 일반 fork/clone/execve, pthread/futex, 시그널, mmap, poll/epoll 계열이 미완성 | 비동기 I/O·스레드·बच्चा_मान आदेश निष्पादित_करें_आदेश·निर्गमन_ऐप/रद्द_करें_ऑपरेशन 기능 |
| संचिका | `स्रोत/मेमोरी_फ़ाइलें.java`: RAM संचिका 64개, 파일당 16 KiB, 비영속 | 큰 निष्पादित_करें_आदेश संचिका·프로젝트·विन्यास·세션을 위한 영속 VFS, संचिका अनुमति_मान·पथ·디렉터리 एक्सटेंशन_मान |
| 네트워크 | lwIP TCP/UDP는 있으나 `नेटवर्क_स्टैक/lwipopts.h`의 LWIP_DNS=0, 일반 HTTPS 클라이언트 없음 | DNS, TLS 인증서 मान्य_करें·신뢰 संग्रह_मूल·정확한 시각, HTTPS/스트리밍 |
| आदेशपटल·उपकरण | निज 셸과 GUI 터미널은 있지만 표준 PTY·일반 프로세스 작업 नियंत्रण_मान 없음 | 대화형 CLI용 आदेशपटल 기능, शेल/संचिका 검색/बिल्ड_सिस्टम उपकरण जोड़ना |
| निष्पादित_करें_आदेश अनुमति_मान | EL0 보호는 있으나 Codex의 Linux 샌드박스와 같은 정책 집행 환경 없음 | संचिका·네트워크·आदेश अनुमति_मान 정책과 승인 기능; निज 커널에 맞는 격리 구현 |

여기서 ELF의 PT_TLS는 스레드별 स्टोर_मान 공간이다. HTTPS의 TLS पासवर्ड_मान 통신과 서로 다른 기능이다.
ELF संचिका 형식을 읽을 수 있다는 사실만으로 Linux निष्पादित_करें_आदेश 환경을 제공하는 것은 아니다.
SSH/VNC를 위한 पासवर्ड_मान 라이브러리를 넣은 상태도 HTTPS 구현 완료를 의미하지 않는다.

호스트의 `/home/user/.local/bin/codex`도 확인했다. 이것은 x86-64 ELF ET_DYN이며 약 209 MiB다.
해당 파일을 ARM64 게스트로 복사하여 실행할 수 없다. 이 크기를 ARM64 배포 파일의 크기로
해석하지 않는다. 공식 ARM64 빌드의 वास्तविक_डेटा आकार·의존성은 설치할 버전으로 जोड़ें_एन्ट्री 검사해야 한다.

## 가능한 구현 पथ

1. **निज 커널에 공식 CLI 직접 이식**
   영속 स्टोर_मान/VFS와 उपयोगकर्ता मेमोरी_डेटा, 프로세스·스레드·I/O, libc/런타임, DNS/HTTPS,
   आदेशपटल·अनुमति_मान 체계를 갖춘다. 이후 लक्ष्य 버전의 의존성을 조사하여 크로스 बिल्ड_सिस्टम·이식한다.
   Linux 커널을 반드시 탑재할 필요는 없지만, 공식 Linux 바이너리를 그대로 쓸 경우
   그 바이너리가 사용하는 Linux ABI까지 호환해야 한다. 큰 ऑपरेटिंग_सिस्टम 개발 과제다.

2. **बाहरी_मान आयोजक Codex와 निज कर्नेल_मान जोड़ना — 첫 구현으로 권장**
   Linux PC에서 공식 CLI 또는 app-server를 실행하고 jkoros에는 전용 उपयोगकर्ता आदेश/화면을 만든다.
   호스트의 인증된 연결과 게스트 संचिका पढ़ें·수정·업로드·आदेश निष्पादित_करें_आदेश 어댑터가 필요하다.
   기존 SSH/TCP 경로를 활용할 수 있으나, संचिका 동기화나 Codex 전용 어댑터는 अद्यतित_आइटम 구현되어 있지 않다.
   호스트에서 수행한 빌드와 게스트에서 수행한 निष्पादित_करें_आदेश 결과를 명확히 구분한다.
   이 구성은 निज 커널을 유지하지만, 공식 CLI 자체는 बाहरी_मान 호스트에서 실행된다.

3. **निज API 클라이언트 제작**
   निज ABI의 C 또는 지원되는 Java 부분집합으로 대화 UI와 संचिका/आदेश उपकरण 호출 루프를 만든다.
   बाहरी_मान 중계기를 쓰지 않는다면 DNS/मान्य_करें 가능한 TLS/HTTPS와 인증 आँकड़े 저장을 먼저 구현해야 한다.
   이는 OpenAI API를 이용하는 별도 에이전트이며 공식 Codex CLI 전체의 이식으로 표시하지 않는다.

4. **별도 ARM64 Linux 실행판에서 इंस्टॉल_करें_मान**
   `../rpi4`는 Linux와 musl 기반이므로 일반 Linux इंस्टॉल_करें_मान 경로를 검토할 수 있다.
   사용할 Codex 버전의 ARM64·musl 호환성, 의존성, 커널의 샌드박스 지원을 वास्तविक_डेटा 검증해야 한다.
   이번 검토에서 इंस्टॉल_करें_मान 성공을 확인하지 않았다. 이 결과를 निज Java 커널의 지원으로 표시하지 않는다.

## 단계별 완료 प्रोजेक्ट_करें_मूल

- 직접 이식: `--version` चलाएँ → 인증/HTTPS → संचिका पढ़ें·수정 → बच्चा_मान आदेश निष्पादित_करें_आदेश →
  대화형 입력/스트리밍 → अनुमति_मान 제한·रद्द_करें_ऑपरेशन → 재부팅 후 विन्यास/세션 보존을 각각 वास्तविक_डेटा 게스트에서 확인한다.
- आयोजक जोड़ना: 게스트에서 अनुरोध 입력 → आयोजक Codex प्रक्रिया_मान_एन्ट्री → 게스트 संचिका परिवर्तित_करें_मान सत्यापित_करें →
  게스트 javac/cc निष्पादित_करें_आदेश → परिणाम 표시를 처음부터 끝까지 검증한다.
- COSL 상업 조건을 유지하려면 새로 도입하는 런타임/통신 라이브러리의 라이선스와
  Codex 배포 버전의 제3자 고지를 검토한다. बाहरी_मान 구성요소를 일괄 COSL로 재라이선스하지 않는다.

## 공식 문서

- [Codex CLI इंस्टॉल_करें_मान 및 क्रिया](https://learn.chatgpt.com/docs/codex/cli): 표준 Linux/macOS 독립 इंस्टॉल_करें_मान 경로와 프로젝트 संचिका·आदेश 작업.
- [인증](https://learn.chatgpt.com/docs/auth): ChatGPT/API 인증, 헤드리스 장치의 `codex login --device-auth`, HTTPS 인증서 विन्यास.
- [샌드박스](https://learn.chatgpt.com/docs/sandboxing): 운영체제별 집행 विधि_मोड, Linux의 bubblewrap 및 उपयोगकर्ता 네임스페이스 요구 사항.
- [공개 구성요소](https://learn.chatgpt.com/docs/open-source): CLI/SDK/app-server의 공개 स्रोत_ट्री 위치와 비공개 구성요소 डिलिमिटर_मान.

공식 문서에는 jkoros를 समर्थन_मान 대상으로 명시한 내용이 없다. 위 구현 पथ·개발 순서는
अद्यतित_आइटम 소스와 요구 기능을 대조한 기술적 판단이다.
