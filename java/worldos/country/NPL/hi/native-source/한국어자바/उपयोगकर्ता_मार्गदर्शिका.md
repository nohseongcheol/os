# jkoros हिंदी लाइब्रेरी उपयोगकर्ता_मार्गदर्शिका

확인일: 2026-09-27. 대상은 `platforms/rpi4`의 **ARM64 Linux + OpenJDK 실행판**이며, QEMU에서도 같은 Java 라이브러리를 사용한다. `os/`의 निज x86 कर्नेल_मान 및 `लिगेसी_स्रोत/`의 관리 कर्नेल_मान 모형과 구분한다.

## 1. अद्यतित_आइटम 제공하는 लाइब्रेरी

패키지는 `हिंदी.자바`, ऑपरेटिंग_सिस्टम 안의 JAR 경로는 `/opt/jkoros/lib/한국어자바.jar`다. **도우미 कक्षा_मान 5개, 공개 정적 विधि_मान 22개, 별도 GUI 프로그램인 कार्यस्थान 1개**가 있다. JAR는 Java 11 이상을 대상으로 빌드하며 अद्यतित_आइटम ARM64 배포판에는 OpenJDK 25가 포함돼 있다.

| कक्षा_मान | विधि_मान 수 | 기능 | स्रोत |
|---|---:|---|---|
| `संचिका` | 9 | UTF-8 텍스트·बाइट_मान संचिका, डायरेक्टरी_मान, एन्ट्री_सूची | [संचिका.java](स्रोत/हिंदी/자바/संचिका.java) |
| `문자` | 5 | UTF-8 रूपांतरित_करें_मान, NFC सामान्य_करें_मान, कोड_मान 포인트, स्ट्रिंग_मान 경계 | [문자.java](स्रोत/हिंदी/자바/문자.java) |
| `통신` | 2 | HTTP(S) GET, TCP जोड़ना | [통신.java](स्रोत/हिंदी/자바/통신.java) |
| `작업` | 4 | 스레드 निष्पादित_करें_आदेश·प्रतीक्षा_करें_मान, 고정 आकार 작업 ऐप_लॉन्चर | [작업.java](स्रोत/हिंदी/자바/작업.java) |
| `화면` | 2 | Swing 이벤트 प्रक्रिया_मान_एन्ट्री 가닥에 작업 예약, खिड़की जनरेट_करें | [화면.java](स्रोत/हिंदी/자바/화면.java) |
| `कार्यस्थान` | प्रवेश_बिदुं `main` | Java स्रोत संपादन_मान·स्टोर_मान·कंपाइल_स्रोत·निष्पादित_करें_आदेश | [कार्यस्थान.java](स्रोत/हिंदी/자바/कार्यस्थान.java) |

표준 JDK 전체를 한국어로 번역한 라이브러리는 아니다. Java 키워드와 `String`, `Path`, `Socket`, `JFrame`, `IOException` 같은 표준 डेटा_प्रकार·예외를 함께 사용한다. 이 도우미에 없는 기능은 OpenJDK의 표준 API 또는 별도 라이브러리로 구현한다. 예를 들어 HTTP POST, UDP, Swing बटन·메뉴에는 각각 표준 Java API를 사용한다.

## 2. Java에서 प्रारंभ_कार्य

게스트 운영체제의 작업 폴더에서 `사용예.java`를 작성한다.

```java
import हिंदी.자바.*;
import java.nio.file.Path;

public class 사용예 {
    public static void main(String[] तर्क) throws Exception {
        Path डायरेक्टरी_मान = संचिका.बनाएँ_डायरेक्टरी(संचिका.पथ("사용예자료"));
        Path 문서 = डायरेक्टरी_मान.resolve("अभिनन्दन_ae353e94.txt");
        संचिका.लिखें(문서, "한글 😀");
        String सामग्री_मान = संचिका.पढ़ें(문서);
        System.out.println(सामग्री_मान);
        System.out.println(문자.코드포인트수(सामग्री_मान)); // 한, पाठ, 공백, 😀 → 4
        Thread काम_मान = 작업.चलाएँ("अभिनन्दन_ae353e94 작업", () -> System.out.println("작업 निष्पादित_करें_आदेश"));
        작업.기다리기(काम_मान);
    }
}
```

```sh
javac -encoding UTF-8 -cp /opt/jkoros/lib/한국어자바.jar 사용예.java
java -cp .:/opt/jkoros/lib/한국어자바.jar 사용예
```

로그인 환경에 डिफ़ॉल्ट_मान `CLASSPATH`도 설정돼 있지만, 명시적인 `-cp`는 다른 निष्पादित_करें_आदेश 환경에서도 경로를 분명하게 한다. 사용자가 `-cp`를 지정하면 필요한 JAR와 कक्षा_मान 폴더를 모두 그 값에 포함해야 한다.

आयोजक 저장소에서는 다음처럼 बिल्ड_सिस्टम·실행한다. आयोजक 경로와 게스트의 `/opt/...` 경로는 서로 다르다.

```sh
cd /home/user/jkoros/한국어자바
make
javac -encoding UTF-8 -cp build/한국어자바.jar 예제/अभिनन्दन_ae353e94.java
java -cp build/한국어자바.jar:예제 अभिनन्दन_ae353e94
```

## 3. 전체 도우미 API

아래 메서드는 모두 `public static`이며, 객체를 만들지 않고 `संचिका.पढ़ें(...)`처럼 호출한다. 표의 이름은 वास्तविक_डेटा स्रोत_ट्री 및 JAR의 `javap -public` 결과와 대조했다. 선언된 검사 अपवाद 외에도 잘못된 तर्क 등에 대한 표준 Java निष्पादित_करें_आदेश 시 예외가 발생할 수 있다.

### संचिका: `हिंदी.자바.संचिका`

`Path`는 `java.nio.file.Path`, `List`는 `java.util.List`다.

| विधि_मान | वापस_करें_लिखें | क्रिया·शर्त |
|---|---|---|
| `पथ(String नाम)` | `Path` | 이름을 पथ 객체로 रूपांतरित_करें_मान. वास्तविक_डेटा 파일을 만들지는 않음 |
| `पढ़ें(Path पथ)` | `String` | संचिका 전체를 UTF-8 텍스트로 पढें_परिणाम |
| `लिखें(Path पथ, String सामग्री_मान)` | `Path` | UTF-8 स्टोर_मान. 파일이 없으면 생성하고, 있으면 기존 내용을 비움 |
| `पढें_बाइट_मान(Path पथ)` | `byte[]` | संचिका 전체를 बाइट_मान 배열로 पढें_परिणाम |
| `लिखना_बाइट_मान(Path पथ, byte[] सामग्री_मान)` | `Path` | बाइट_मान स्टोर_मान. 없으면 생성하고, 있으면 기존 내용을 비움 |
| `बनाएँ_डायरेक्टरी(Path पथ)` | `Path` | 필요한 상위 폴더까지 जनरेट_करें |
| `있는가(Path पथ)` | `boolean` | 존재 여부 सत्यापित_करें. 확인할 수 없는 경우도 `false`काम_मान 수 있음 |
| `मिटाएँ_एन्ट्री(Path पथ)` | `boolean` | 삭제했으면 `true`, 없으면 `false`. 폴더의 재귀 삭제는 아님 |
| `एन्ट्री_सूची(Path पथ)` | `List<Path>` | 바로 아래 항목을 पथ संरेखित_करें_मान 순서로 वापस_करें_परिणाम. 재귀 탐색은 아님 |

`पथ`, `있는가`를 제외한 위 메서드는 `IOException`을 선언한다. `लिखें`와 `लिखना_बाइट_मान`는 상위 폴더를 자동으로 만들거나 내용을 이어 쓰지 않는다. 필요한 폴더는 먼저 생성한다. 큰 파일은 전체 내용을 메모리에 담는 대신 표준 Java 스트림·चैनल_मान API를 사용하는 방식으로 작성할 수 있다.

### 문자: `हिंदी.자바.문자`

| विधि_मान | वापस_करें_लिखें | क्रिया·शर्त |
|---|---|---|
| `부호화(String सामग्री_मान)` | `byte[]` | 문자열을 UTF-8 바이트로 रूपांतरित_करें_मान |
| `डिक्रिप्ट_करें_डेटा(byte[] सामग्री_मान)` | `String` | UTF-8 바이트를 문자열로 रूपांतरित_करें_मान. 잘못된 입력은 대체 문자로 प्रक्रिया_मान_एन्ट्री |
| `सामान्य_करें_मान(String सामग्री_मान)` | `String` | यूनिकोड_मान NFC सामान्य_करें_मान. 예: 조합 자모 `ᄀ` + `ᅡ` → `가` |
| `코드포인트수(String सामग्री_मान)` | `int` | UTF-16 कोड_मान 단위가 아닌 यूनिकोड_मान कोड_मान 포인트 수 |
| `낱말(String सामग्री_मान, Locale भाषा)` | `List<String>` | असाइन_करें_मान 언어의 `BreakIterator` 낱말 경계로 나눈 पाठ_श्रेणी |

`낱말`은 공백·문장부호 구간도 반환한다. 자연어 형태소 분석기나 공백을 제거한 शब्द_मान एन्ट्री_सूची API는 아니다. `सामान्य_करें_मान`는 입력기나 अनुवाद_स्रोत 기능이 아니다. कोड_मान 포인트 수 역시 사람이 보는 कैरेक्टर_मान 수와 항상 같지는 않다. 여러 कोड_मान 포인트로 이루어진 결합 문자·가족 이모지 등을 구분해야 한다.

### 통신: `हिंदी.자바.통신`

| विधि_मान | वापस_करें_लिखें | क्रिया·शर्त |
|---|---|---|
| `가져오기(URI पता, Duration समय_सीमा)` | `HttpResponse<String>` | HTTP(S) GET. जोड़ना 및 अनुरोध समय_सीमा विन्यास. उत्तर 본문을 UTF-8로 पार्स_करें_मान |
| `कनेक्ट_एंडपॉइंट(String पता, int 포트, int 제한밀리초)` | `Socket` | TCP जोड़ना 후 같은 값으로 पढ़ें 제한시간도 विन्यास |

`가져오기`는 `IOException`, `InterruptedException`을 선언한다. 제한시간은 양수다. 404·500 같은 HTTP त्रुटि 상태도 응답으로 반환하므로 `statusCode()`로 판단하고 `body()`로 본문을 읽는다. अद्यतित_आइटम 구현은 호출마다 HTTP 클라이언트를 만들며 자동 리다이렉트 설정을 추가하지 않는다.

`कनेक्ट_एंडपॉइंट`는 `IOException`을 선언한다. 연결된 소켓은 호출자가 `close()` 또는 try-with-resources로 닫아야 한다. 제한밀리초의 0은 제한 없음이며, लिखें 전체의 अंति_म_समय_सीमा_मान 시간을 보장하는 옵션은 아니다.

```java
var उत्तर = 통신.가져오기(
    java.net.URI.create("http://127.0.0.1:8000/"),
    java.time.Duration.ofSeconds(5));
System.out.println(उत्तर.statusCode());
System.out.println(उत्तर.body());
```

위 조각은 विधि_मान 안에서 실행하며 별도로 해당 주소의 서버를 실행해야 한다. Java अपवाद 처리가 필요하다.

### 작업: `हिंदी.자바.작업`

| विधि_मान | वापस_करें_लिखें | क्रिया·शर्त |
|---|---|---|
| `चलाएँ(String नाम, Runnable क्रिया)` | `Thread` | 이름을 지정한 스레드를 만들고 즉시 चलाएँ |
| `기다리기(Thread थ्रेड_मान)` | `void` | 해당 스레드가 종료할 때까지 `join()` |
| `쉬기(long 밀리초)` | `void` | 호출한 스레드를 असाइन_करें_मान समय_उपयोगिता 동안 `sleep()` |
| `작업대(int 가닥수)` | `ExecutorService` | 고정 आकार 작업 ऐप_लॉन्चर जनरेट_करें. 가닥수는 양수 |

`기다리기`, `쉬기`는 `InterruptedException`을 선언한다. 작업 실행기는 사용 후 `shutdown()`으로 종료하고 필요하면 `awaitTermination(...)`으로 완료를 기다린다. Swing 이벤트 प्रक्रिया_मान_एन्ट्री 가닥에서 긴 작업이나 `기다리기`를 실행하면 화면이 멈출 수 있다.

### 화면: `हिंदी.자바.화면`

| विधि_मान | वापस_करें_लिखें | क्रिया·शर्त |
|---|---|---|
| `나중에(Runnable क्रिया)` | `void` | Swing 이벤트 प्रक्रिया_मान_एन्ट्री 가닥에 실행을 예약하고 वापस_करें_परिणाम |
| `खिड़की(String विंडो_शीर्षक, JComponent सामग्री_मान, int 너비, int 높이)` | `JFrame` | सामग्री_मान·크기를 지정한 창을 생성해 शो_मान |

`खिड़की`을 Swing 이벤트 प्रक्रिया_मान_एन्ट्री थ्रेड_मान 밖에서 부르면 `IllegalStateException`이 발생한다. 그래픽 세션도 필요하다. QEMU에서는 VNC 데스크톱의 터미널에서 실행한다.

```java
화면.나중에(() -> 화면.खिड़की(
    "हिंदी 화면", new javax.swing.JLabel("안녕하세요"), 500, 180));
```

반환된 `JFrame`에 표준 Swing API를 추가로 사용할 수 있다. 창의 बंदकरें 동작은 `DISPOSE_ON_CLOSE`다. `화면.나중에`가 반환됐다고 खिड़की 생성이 이미 끝난 것은 아니다.

### कार्यस्थान: संपादन_मान·कंपाइल_स्रोत GUI

```sh
java -cp /opt/jkoros/lib/한국어자바.jar हिंदी.자바.कार्यस्थान
```

`~/workspace`의 원문을 खोलें·저장하고, `javac`로 컴파일해 `java`로 실행한다. निष्पादित_करें_आदेश संचिका 만들기는 `jclassc --target openjdk` 경로를 사용한다. 작업마당은 개발용 프로그램이며 별도의 संचिका·문자 API 클래스가 아니다. 생성하는 निष्पादित_करें_आदेश संचिका 방식은 [कंपाइलर 설명](../compiler/OpenJDK-निष्पादन_योग्य_फ़ाइल.md)을 따른다.

## 4. Python과 C++에서 사용할 수 있는가?

| विधि_मोड | अद्यतित_आइटम 포함 अवस्था_मान | 호출 가능 क्लिप |
|---|---|---|
| Java → हिंदी JAR | डिफ़ॉल्ट_मान 포함 | 위 22개 메서드와 कार्यस्थान |
| Python → `java` बच्चा_मान 프로세스 | Python·Java डिफ़ॉल्ट_मान 포함 | 작은 Java 진입점을 통해 호출하고 표준 निर्गम·संचिका 등으로 परिणाम आगे_मान |
| Python → JPype → JVM | JPype는 डिफ़ॉल्ट_मान 배포에 없음 | 별도 इंस्टॉल_करें_मान 후 Java कक्षा_मान·विधि_मान 호출 가능. 이 배포판의 ARM64/musl/Python 3.14 조합은 जोड़ें_एन्ट्री मान्य_करें 필요 |
| C++ → JNI → JVM | `g++`, JNI 헤더, `libjvm.so` 포함 | JVM을 생성하고 हिंदी कक्षा_मान·메서드를 직접 호출할 수 있음 |
| Python용 독립 हिंदी लाइब्रेरी | अद्यतित_आइटम डिफ़ॉल्ट_मान 제공 없음 | 필요하면 Python 표준 라이브러리를 감싸는 हिंदी 모듈을 별도로 작성 |
| C/C++용 독립 हिंदी लाइब्रेरी | निज x86 `posix-kor`와 निज ARM64 커널용 प्रारंभिक_स्थिति RAM संचिका 연결이 별도로 존재 | 둘 다 이 Linux/OpenJDK 실행판의 libc 라이브러리는 아님 |

Python의 일반 `import`나 `ctypes.CDLL`로 JAR를 바로 읽을 수는 없다. C++의 `#include`나 일반 네이티브 링커만으로 Java 메서드를 연결할 수도 없다. JVM 프로세스 또는 JVM जोड़ना 계층을 거쳐야 한다.

### Python: जोड़ें_एन्ट्री 패키지 없이 호출

निष्पादित_करें_आदेश 가능한 예제 원문은 [문자명령.java](예제/다른언어/문자명령.java), [파이썬호출.py](예제/다른언어/파이썬호출.py)다. Python이 Java 진입점을 실행하고 `문자.코드포인트수`의 पूर्णांक 결과를 받는다. तर्क 목록을 사용하며 शेल आदेश 문자열을 조립하지 않는다. `subprocess.run`의 프로세스 निष्पादित_करें_आदेश·निर्गमन_ऐप कोड_मान·निर्गम प्रक्रिया_मान_एन्ट्री 방식은 [Python 공식 문서](https://docs.python.org/3/library/subprocess.html)를 따른다.

두 예제 파일을 게스트의 같은 폴더에 복사한 वापस_मान 그 폴더에서 실행한다. 예제 संचिका 자체는 डिफ़ॉल्ट_मान 시스템 이미지에 자동 설치돼 있지 않다.

```sh
mkdir -p classes
javac -encoding UTF-8 -cp /opt/jkoros/lib/한국어자바.jar -d classes 문자명령.java
python3 파이썬호출.py --text '한글 😀'
```

निर्गम: `Python → हिंदी.자바.문자.코드포인트수: 4`

이 예제의 Python फ़ंक्_शन_मान `코드포인트수`는 이번 문서의 जोड़ना 예제이며 기존에 설치된 Python 라이브러리는 아니다. अद्यतित_आइटम 예제는 호출할 때마다 JVM 프로세스를 시작한다. Java ऑब्जेक्ट_मान 자체를 Python으로 가져오는 방식은 아니며, 다른 메서드를 사용하려면 진입점의 तर्क·परिणाम 형식을 확장한다.

### Python: JPype로 같은 프로세스에서 호출

JPype를 별도 설치한 환경에서는 अगला_आइटम 형태로 연결할 수 있다. **아래는 चयन_मान 가능한 जोड़ना 방법이며, अद्यतित_आइटम 배포판에 JPype가 설치돼 있거나 निष्पादित_करें_आदेश 검증됐다는 뜻은 아니다.** JVM 시작과 `JClass`를 통한 कक्षा_मान 접근은 [JPype 공식 설명](https://jpype.readthedocs.io/en/latest/userguide.html)을 참고한다.

```python
import jpype

jpype.startJVM(
    "/usr/lib/jvm/java-25-openjdk/lib/server/libjvm.so",
    classpath=["/opt/jkoros/lib/한국어자바.jar"])
try:
    문자 = jpype.JClass("हिंदी.자바.문자")
    print(문자.코드포인트수(jpype.JString("한글 😀")))
finally:
    jpype.shutdownJVM()
```

Python·JVM·जोड़ना 모듈의 CPU 아키텍처가 맞아야 한다. 이 실행판은 ARM64 + musl이므로 일반 x86_64/glibc용 바이너리를 그대로 설치하는 방식은 맞지 않는다. JPype इंस्टॉल_करें_मान·패키지 빌드는 이번 문서 작업에서 수행하지 않았다.

### C++: JNI로 직접 호출

[자바호출.cpp](예제/다른언어/자바호출.cpp)는 वास्तविक_डेटा निष्पादित_करें_आदेश 가능한 예제다. JVM을 작업 스레드에서 생성하고 अगला_आइटम 메서드를 찾는다.

```cpp
jclass type = env->FindClass("हिंदी/자바/문자");
jmethodID method = env->GetStaticMethodID(
    type, "코드포인트수", "(Ljava/lang/String;)I");
```

JVM जनरेट_करें·종료와 스레드 연결은 [JNI Invocation API](https://docs.oracle.com/en/java/javase/25/docs/specs/jni/invocation.html)의 방식이다. `JNIEnv*`는 जनरेट_करें·연결된 스레드에서 사용해야 한다. 예제는 Java 예외를 확인하고 JVM 종료까지 처리한다.

게스트에 `자바호출.cpp`를 복사한 वापस_मान 컴파일한다. 로그인 환경의 `JAVA_HOME`은 `/usr/lib/jvm/java-25-openjdk`다.

```sh
g++ -std=c++11 -Wall -Wextra -pthread \
  -I"$JAVA_HOME/include" -I"$JAVA_HOME/include/linux" \
  자바호출.cpp -L"$JAVA_HOME/lib/server" \
  -Wl,-rpath,"$JAVA_HOME/lib/server" -ljvm -o 자바호출
./자바호출 /opt/jkoros/lib/한국어자바.jar
```

निर्गम: `C++ → हिंदी.자바.문자.코드포인트수: 4`

예제는 `한글 😀`을 UTF-16으로 만들어 `NewString`에 전달한다. `NewStringUTF`가 받는 modified UTF-8은 일반 UTF-8과 차이가 있으므로, 일반 UTF-8 이모지 바이트를 그대로 넘기는 예제로 작성하지 않았다. [JNI स्ट्रिंग_मान फॉर्मैट_मान](https://docs.oracle.com/en/java/javase/25/docs/specs/jni/types.html#modified-utf-8-strings)

다른 हिंदी 메서드도 JNI 서명과 तर्क 자료형을 맞춰 호출할 수 있다. 예를 들어 `Path`를 받는 संचिका API는 먼저 `संचिका.पथ`로 Java पथ 객체를 얻어 전달한다. Swing 호출에는 그래픽 세션과 이벤트 प्रक्रिया_मान_एन्ट्री थ्रेड_मान 규칙도 그대로 적용된다. JNI는 Java 실행을 기계어로 대체하는 기능이 아니며 JVM이 계속 필요하다.

### 기존 posix-kor와의 관계

추가된 [निज ARM64 जोड़ना](../posix-kor/arm64-native/ReadMe_फ़ाइल_eb81d7d9.md)은 C++에서 AOT Java 커널의 RAM संचिका API를 직접 호출하며, 별도 EL0 उपयोगकर्ता 라이브러리로 संचिका/UDP 루프백 SVC 호출도 제공한다. JNI를 사용하지 않는다. 이 문서의 ARM64 **Linux** 및 हिंदी Java JAR와는 다른 निष्पादित_करें_आदेश 기반이며 निज 커널은 별도 제한형 Java कंपाइलर/JVM과 MicroPython 1.24.1을 실행한다. MicroPython의 `import jkoros`로 Java कर्नेल_मान संचिका·UDP 루프백·रेक्_टेंगल 호출이 가능하지만 이 문서의 JAR를 가져오는 기능은 아니다. निज 커널의 전체 OpenJDK/JRE/CPython 이식은 아직 미완성이다.

[posix-kor](../posix-kor/ReadMe_फ़ाइल_eb81d7d9.md)에는 `जारी_फ़ाइल`, `पढें_फ़ाइल_डेटा`, `लिखना_फ़ाइल_डेटा`, `बंद_फ़ाइल`, `बनाएँ_एंडपॉइंट`, `자료전문보내기` 등의 हिंदी C 별칭이 있다. 그러나 구현은 **निज jkoros i386 커널의 `int 0x80` 호출 규약용**이다.

이 `libposix-kor.a`와 निज `sys/stat.h` 등의 헤더는 अद्यतित_आइटम ARM64 Linux 실행판의 libc/C++용 라이브러리가 아니다. 해당 헤더·바이너리를 ARM64 Linux 프로그램에 그대로 연결해서는 ABI가 맞지 않는다. C++용 हिंदी कक्षा_मान 라이브러리나 Python용 바인딩을 डिफ़ॉल्ट_मान 제공하는 상태도 아니다. अद्यतित_आइटम Linux 실행판에서 그와 같은 독립 API를 제공하려면 Linux 표준 라이브러리를 대상으로 별도로 구현·빌드해야 한다.

## 5. सत्यापित_करें 범위와 재현

패키지 포함 여부는 [배포 패키지 एन्ट्री_सूची](../platforms/rpi4/dist/packages.lock.json) 및 बिल्ड_सिस्टम 루트의 वास्तविक_डेटा 파일로 확인했다. JNI 헤더는 JDK의 `include/jni.h`, `include/linux/jni_md.h`, JVM 라이브러리는 `lib/server/libjvm.so`에 있다. 사용자가 이후 별도로 설치한 패키지는 이 डिफ़ॉल्ट_मान 배포 목록과 다를 수 있다.

이번에 **आयोजक x86_64/OpenJDK 11에서** Python बच्चा_मान 프로세스 호출과 C++ JNI 직접 호출을 कंपाइल_स्रोत·실행해 각각 परिणाम 4를 확인했다. JAR 공개 메서드도 소스와 대조했다. Python जोड़ना 예제는 जोड़ें_एन्ट्री 패키지를 설치하지 않는다.

문서의 Java 사용 예제도 कंपाइल_स्रोत·실행했고, 22개 메서드의 문서 포함 여부와 로컬 문서 링크를 확인했다. [예제 मान्य_करें लॉग_रिकॉर्ड](build/다른언어/प्रमाणीकरण_रिपोर्ट.json)

기존 ARM64 QEMU에서는 Java의 संचिका·यूनिकोड_मान·스레드·HTTP 및 Swing 시험 결과가 있다. 이번 Python/C++ जोड़ना 예제의 **ARM64 게스트 실행과 JPype 설치는 별도 검증하지 않았다.** 이미지와 निष्पादित_करें_आदेश 중인 उपयोगकर्ता 환경은 이 문서 작업에서 변경하지 않았다. [기존 ऑपरेटिंग_सिस्टम मान्य_करें लॉग_रिकॉर्ड](../platforms/rpi4/VERIFICATION.md)

호스트에서 Python 예제를 재현하려면:

```sh
cd /home/user/jkoros/한국어자바
make
mkdir -p build/다른언어
javac -encoding UTF-8 --release 11 -cp build/한국어자바.jar \
  -d build/다른언어 예제/다른언어/문자명령.java
python3 예제/다른언어/파이썬호출.py \
  --jar build/한국어자바.jar --classes build/다른언어
```

आयोजक C++ 예제는 위 JNI कंपाइल_स्रोत 명령의 JDK 경로를 **आयोजक JDK पथ**로 바꾸고, स्रोत `예제/다른언어/자바호출.cpp`와 JAR `build/한국어자바.jar`를 지정한다. ARM64 게스트 JDK의 헤더·लाइब्रेरी 경로를 आयोजक x86_64 링크 명령에 섞지 않는다.
