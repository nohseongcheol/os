# 셸에서 실행하는 प्रयोगकर्ता 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 readme_फाइल_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 कार्यान्वयन_गर्नुहोस्_आदेश

होस्ट टर्मिनल 1:

```sh
cd /home/user/jkoros
python3 os/उपकरणहरू/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 외부 연결을 받도록 방화벽이나 हार्डवेयर_पोर्ट 전달을 변경하지 않는다. Ctrl+C로 종료한다.

होस्ट टर्मिनल 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 वास्तविक_लगत CPU अनुमति_मान `ring 3`, तर्क 출력.
- `netcheck`: पोर्ट_मान 중복, 잘못된 ह्यान्डल_मान/पोइन्टर/लम्बाइ_मान, 비차단 받기와 시간 초과 रुजू_गर्नुहोस्.
- `udp`: IPv4 ठेगाना·गन्तव्य_मान पोर्ट_मान·한 शब्द_मान 메시지를 받아 UDP로 보내고 같은 응답을 रुजू_गर्नुहोस्. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: होस्ट `10.0.2.2`의 지정 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 लुप_मान 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 현재 주소는 게스트 `10.0.2.15/24`, गेटवे_मान `10.0.2.2`로 고정돼 있다. QEMU प्रयोगकर्ता 네트워크의 होस्ट पहुँच_प्रविष्टि 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 अनुप्रयोग_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java अनुप्रयोग_f5044b9b 추가

`예제/내프로그램.java`를 अर्को_वस्तु 형식으로 만든다. 진입점은 तर्क 없는 `static int` 또는 `static void` 함수다. 인수는 प्रयोगकर्ता API로 조회한다.

```java
public final class 내프로그램 {
    public static int चलाउनुहोस्() {
        प्रयोगकर्ता.लेख्नुहोस्("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/प्रयोगकर्ता/अनुप्रयोग_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := प्रयोगकर्ता/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.चलाउनुहोस्
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `प्रयोगकर्ता/선언/प्रयोगकर्ता.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 कार्यान्वयन_गर्नुहोस्_आदेश 중인 VM에는 बनाउनुहोस्_प्रणाली 결과가 자동 반영되지 않는다. अनुप्रयोग_f5044b9b 이름은 현재 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java वर्ग_मान·प्रकार्य_मान·변수에는 한국어를 쓴다. 최대 32개 अनुप्रयोग_f5044b9b, 한 कार्यान्वयन_गर्नुहोस्_आदेश 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.चलाउनुहोस् \
    -o os/build/apps/hello.elf os/प्रयोगकर्ता/선언/प्रयोगकर्ता.java os/प्रयोगकर्ता/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 होस्ट 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 समर्थन_मान क्लिप 안에서 실행한다. `.jar`와 일반 Linux कार्यान्वयन_गर्नुहोस्_आदेश 파일은 지원하지 않는다.

## प्रयोगकर्ता 네트워크 API

선언은 `선언/प्रयोगकर्ता.java`에 있다. `पठाउनुहोस्_लगत`/`자료받기`의 `int[]` वस्तु_तत्त्व 한 개는 बाइट_मान 하나(0~255)를 나타낸다. 한 데이터그램의 최대 लगत 길이는 1,024바이트다.

```java
int ह्यान्डल_मान = प्रयोगकर्ता.सिर्जना_सञ्जाल(0); // 0: 임시 स्थानीय_क्षेत्र UDP पोर्ट_मान 자동 चयन_मान
int[] लगत = new int[32];
लगत[0] = 'H'; लगत[1] = 'i';
int 보낸길이 = प्रयोगकर्ता.पठाउनुहोस्_लगत(ह्यान्डल_मान, 0x0a000202, 9000, लगत, 2);
int 받은길이 = प्रयोगकर्ता.자료받기(ह्यान्डल_मान, लगत, 1500);
प्रयोगकर्ता.बन्द_गर्नुहोस्_सञ्जाल(ह्यान्डल_मान);
```

वास्तविक_लगत 프로그램에서는 खोल्नुहोस्·पठाउनुहोस्·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 대기 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 추가 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | ह्यान्डल_मान·प्रक्रिया_मान_प्रविष्टि लम्बाइ_मान·성공 등 해당 함수의 मापन |
| -5 | मोबाइल_मान पठाउनुहोस्_मान विफल_मान |
| -9 | 잘못되었거나 닫힌 통신 ह्यान्डल_मान |
| -11 | 비차단 받기에서 도착한 लगत 없음 |
| -14 | प्रयोगकर्ता पोइन्टर/विन्यास_मान क्लिप त्रुटि |
| -19 | समर्थन_मान NIC 없음 |
| -22 | पोर्ट_मान/대기 시간/तर्क मान त्रुटि |
| -24 | 열린 सञ्जाल_पोर्ट 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | लगत 또는 수신 विन्यास_मान आकार 문제 |
| -98 | स्थानीय_क्षेत्र पोर्ट_मान अनुक्रमणिका 중복 |
| -101 | 지원하지 않는 गन्तव्य_मान ठेगाना |
| -110 | ARP·मोबाइल_मान·수신 시간 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 एनकोडिङ_मान 있는 Java `int`의 बिट_मान 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## कार्यान्वयन_गर्नुहोस्_आदेश 경계와 시스템 호출

```text
शेल run → JKAP에서 ELF वैध_गर्नुहोस्·적재 → ring 3 प्रयोगकर्ता अनुप्रयोग_f5044b9b
                                 ↓ int 0x80
                      पोइन्टर 검사 → Java कर्णेल_मान API → RTL8139/UDP
                                 ↓ बाहिर_जानुहोस्_अनुप्रयोग·예외·시간 초과
                                शेल 복귀
```

시스템 호출 레지스터는 `EAX=अनुक्रमणिका`, `EBX,ECX,EDX,ESI,EDI=तर्क`, `EAX=मापन`다. Java 호출 스택 ABI는 컴파일러가 प्रयोगकर्ता 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| अनुक्रमणिका | 호출 |
| --- | --- |
| 0 | बाहिर_जानुहोस्_अनुप्रयोग(स्थिति_मान 코드) — चलाउनुहोस्/त्रुटि 런타임에서 사용 |
| 1 | स्ट्रिङ_मान लेख्नुहोस् |
| 2 / 3 | तर्क 개수 / तर्क स्ट्रिङ_मान ठेगाना |
| 10 | UDP खोल्नुहोस् |
| 11 | UDP पठाउनुहोस्(ह्यान्डल_मान, IP, गन्तव्य_मान पोर्ट_मान, विन्यास_मान ठेगाना, लम्बाइ_मान) |
| 12 | UDP 받기(ह्यान्डल_मान, विन्यास_मान ठेगाना, 제한 밀리초) |
| 13 | UDP बन्दगर्नुहोस् |
| 14 | स्थानीय_क्षेत्र IP ठेगाना |
| 15 / 16 | 마지막 समान_मान IP / UDP पोर्ट_मान |
| 20 | RAM फाइल पढनुहोस्(नाम int[] ठेगाना, 출력 int[] ठेगाना) |
| 21 | RAM फाइल लेख्नुहोस्(नाम int[] ठेगाना, 입력 int[] ठेगाना, बाइट_मान लम्बाइ_मान) |
| 22 | UTF-16 코드 शिक्षा_मान 문자 출력(0~65535) |

फाइल API는 `प्रयोगकर्ता.파일읽기(int[] नाम, int[] लगत)`와 `प्रयोगकर्ता.लेख्नुहोस्_फाइल(int[] नाम, int[] लगत, int लम्बाइ_मान)`다. 이름은 ASCII 코드 विन्यास_मान(최대 64칸, 0 बाहिर_जानुहोस्_अनुप्रयोग 또는 विन्यास_मान 끝), लगत वस्तु_तत्त्व 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 फाइल 없음 `-2`, पोइन्टर त्रुटि `-14`, नाम/लम्बाइ_मान त्रुटि `-22`, फाइल स्लट_मान 부족 `-28`, आकार 초과 `-90`을 반환한다. 쓰기는 वैध_गर्नुहोस् 후 फाइल 전체를 대체한다. `प्रयोगकर्ता.लेख्नुहोस्_वर्ण_मान(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 प्रयोगकर्ता 모드에서 CS의 하위 비트를 직접 읽으므로 वास्तविक_लगत कार्यान्वयन_गर्नुहोस्_आदेश 권한을 확인한다. कर्णेल_मान हार्डवेयर_पोर्ट 접근용 `मोबाइल_मान` native 함수는 प्रयोगकर्ता लक्ष्य 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 कार्यान्वयन_गर्नुहोस्_आदेश, 파이프, 프로세스 간 통신은 없다. कार्यान्वयन_गर्नुहोस्_आदेश 파일은 커널의 पढनुहोस् 전용 JKAP 묶음에서 적재한다. लगत 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- प्रयोगकर्ता 가상 ठेगाना `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. कार्यान्वयन_गर्नुहोस्_आदेश 영상은 앞 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. कर्णेल_मान identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB प्रयोगकर्ता 영역을 비우고 फाइल 구역을 복사해 BSS·विन्यास_मान 영역을 초기화한다. प्रयोगकर्ता GC는 없지만 बाहिर_जानुहोस्_अनुप्रयोग 후 अर्को_वस्तु कार्यान्वयन_गर्नुहोस्_आदेश 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 उद्धरण/이스케이프 파싱은 없다.
- प्रयोगकर्ता 페이지의 코드/लगत 분리 पढनुहोस् 전용 सेटिङ, NX, 스택 guard, ASLR은 아직 없다. 커널과 प्रयोगकर्ता मेमोरी_लगत·हार्डवेयर_पोर्ट अनुमति_मान 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 कार्यान्वयन_गर्नुहोस्_आदेश 상한을 두며 시간 초과는 `Exit: 124`다. प्रयोगकर्ता CPU 예외는 `128 + 예외 अनुक्रमणिका`(페이지 त्रुटि 142, 특권 위반 141), Java विन्यास_मान/계산 오류는 101~105다. कर्णेल_मान 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, तथ्याङ्कित_मान IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP 검사합 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- प्रयोगकर्ता कार्यान्वयन_गर्नुहोस्_आदेश·네트워크·सुरक्षित_गर्नुहोस्_मान 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 कार्यान्वयन_गर्नुहोस्_आदेश·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## वैध_गर्नुहोस् 근거

`make test`는 컴파일러 14개 시험, Java 패킷 सर्त 2,201개 검사, 기존 शेल ELF/ISO 부팅 시험, प्रयोगकर्ता ELF/वास्तविक_लगत UDP/सुरक्षित_गर्नुहोस्_मान 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 लम्बाइ_मान·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 आदेश·무한 दोहर्_याउनु_मान 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.

참고한 일차 लगत: [Intel 시스템 프로그래밍 명세](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html), [QEMU RTL8139 구현](https://github.com/qemu/qemu/blob/master/hw/net/rtl8139.c), [QEMU 네트워크 readme_फाइल_eb81d7d9](https://www.qemu.org/docs/master/system/devices/net.html), [IPv4 RFC 791](https://www.rfc-editor.org/rfc/rfc791), [ARP RFC 826](https://www.rfc-editor.org/rfc/rfc826), [UDP RFC 768](https://www.rfc-editor.org/rfc/rfc768).
