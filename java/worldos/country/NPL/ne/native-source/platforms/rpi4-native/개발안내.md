# निज 커널에서 vi·여러 टर्मिनल·한글 프로그래밍 사용하기

नेपाली 통신·예외 사용법은 [नेपाली Java API](한국어자바/readme_फाइल_eb81d7d9.md), प्रकार्य_मान·변수·फाइल 이름의 변경과 어원 근거는 [명명 readme_फाइल_eb81d7d9](명명/readme_फाइल_eb81d7d9.md)를 참고한다.

대상은 `platforms/rpi4-native`의 निज AArch64 Java 커널이다. vi와 Java/Python/C/C++ 프로그램은 EL0에서 실행한다. Linux 실행판과 별도이며 아래 समर्थन_मान 목록은 전체 OpenJDK·Vim·POSIX 구현을 뜻하지 않는다.

게스트 `cc`/`jaot`, JAR 직접 कार्यान्वयन_गर्नुहोस्_आदेश, 외부 TCP/UDP와 FTP는 [새 कार्यान्वयन_गर्नुहोस्_आदेश 매뉴얼](파일전송과번역.md)을 참고한다.

## GUI와 여러 टर्मिनल

```sh
cd /home/user/jkoros/platforms/rpi4-native
make desktop
```

Remmina에서 **VNC**, ठेगाना **127.0.0.1:5902**로 연결한다. 화면 위 **+ New terminal**, **Ctrl+Shift+T**로 터미널을 추가한다. 최대 네 개다. 위쪽 टर्मिनल 버튼 또는 창을 클릭해 선택하고 **F6**으로 순환한다. 제목줄을 끌어서 옮기고 **오른쪽 위 X**를 클릭하면 닫힌다. 마지막 창을 닫아도 위쪽 कार्यान्वयन_गर्नुहोस्_आदेश 버튼으로 다시 स्तम्भ_मान 수 있다. 기존 `terminal`, `exit`, F12도 사용할 수 있다.

창마다 현재 디렉터리, शेल 변수, आदेश लग_रेकर्ड, 입력 중인 명령과 अनुप्रयोग_f5044b9b कार्यान्वयन_गर्नुहोस्_आदेश 상태를 보관한다. फाइल 저장소는 공유한다. vi와 Swing의 이벤트 대기 중에 다른 터미널로 전환하면 प्रयोगकर्ता मेमोरी_लगत·레지스터·फाइल/소켓 연결을 보존했다가 돌아올 때 재개한다. **현재 네 프로그램이 동시에 CPU에서 실행되는 선점형 스케줄러는 아니다.** 계산 중인 프로그램은 अर्को_वस्तु 입력 대기 또는 기존 कार्यान्वयन_गर्नुहोस्_आदेश 기한까지 전환이 지연될 수 있다.

X로 터미널을 닫으면 그 터미널의 कार्यान्वयन_गर्नुहोस्_आदेश 중인 프로그램도 종료하며 서술자·소켓을 회수한다. 저장하지 않은 सम्पादन_गर्नुहोस्_मान 내용은 사라진다. 종료한 슬롯은 새 창에서 재사용한다. 현재 모든 파일은 RAM에 있으며 VM 재시작 후에는 남지 않는다.

화면과 सन्झ्याल 판단은 게스트 커널이 처리한다. QEMU कार्यान्वयन_गर्नुहोस्_आदेश 도구는 VNC 키와 마우스 좌표를 UART 패킷으로 전달한다. वास्तविक_लगत Pi4 USB 입력기와 실물 부팅은 아직 검증하지 않았다. 일반 UART 셸은 `make run`, GUI उपकरणहरू 종료는 होस्ट 터미널의 Ctrl+C다.

## vi 사용

```text
mkdir 작업
cd 작업
vi 인사.py
```

`vi`는 새로 구현한 **vi आदेश 부분집합** 편집기다. 내장 `build/user/vi.elf`를 보호된 प्रयोगकर्ता 영역에 적재한다. फाइल 크기는 UTF-8 बाइट_मान परियोजना_रूट 16 KiB, 경로는 63바이트까지다. 디스크에 설치한 Vim/Neovim 바이너리를 실행하는 것이 아니다.

| कुञ्जी_मान/आदेश | कार्य |
|---|---|
| `i`, `a`, `I`, `A` | 현재/अर्को_वस्तु स्थिति 또는 रेखा 처음/끝에서 입력 |
| `o`, `O` | 아래/위에 새 줄을 만들고 입력 |
| Esc | 일반 मोड_मान |
| `h j k l`, 방향키 | UTF-8 문자/रेखा लैजानुहोस्_मान |
| `0`, `$`, Home, End | रेखा 처음/끝 |
| `gg`, `G`, `:अनुक्रमणिका` | फाइल 처음/마지막 रेखा/지정 रेखा |
| PgUp, PgDn | 화면 शिक्षा_मान लैजानुहोस्_मान |
| `x`, Delete | 현재 문자 삭제 |
| `dd`, `yy`, `p` | रेखा 삭제/उद्धरण_मान_37b3d3b1/टाँस्नुहोस्_पाठ |
| `u` | 마지막 편집을 되돌림; 한 चरण_मान 토글 |
| `/स्ट्रिङ_मान`, `n` | 단순 स्ट्रिङ_मान 검색/अर्को_वस्तु 일치; 정규식 없음 |
| `:w`, `:w 다른이름` | RAM फाइल भण्डार_गर्नुहोस्_मान/다른 경로로 भण्डार_गर्नुहोस्_मान |
| `:q` | 변경이 없을 때 बाहिर_जानुहोस्_अनुप्रयोग |
| `:q!` | 변경을 버리고 बाहिर_जानुहोस्_अनुप्रयोग |
| `:wq`, `ZZ` | 저장하고 बाहिर_जानुहोस्_अनुप्रयोग |

붙여 넣은 한글을 문자 경계에 맞춰 लैजानुहोस्_मान·삭제한다. 일반 vi의 수량 접두사, म्याक्रो_मान, सेटिङ फाइल, 플러그인, 정규식, 여러 버퍼/분할 सन्झ्याल, 문법 강조 등은 아직 없다. `--desktop`에서는 F9·Shift+Space·한/영 키로 두벌식 조합을 전환한다. PC 입력기를 영어로 두고 सन्झ्याल सन्झ्याल_शिर्षक `[KO]`에서 입력하며, `help ko`에 단축키를 표시한다. 완성된 Unicode 문자와 VNC의 명시적 붙여넣기도 전달한다.

vi와 Swing 프로그램은 **단독 आदेश**으로 실행한다. 파이프·리다이렉션·स्क्रिप्ट_मान·`;`/`&&`/`||`로 연결한 실행에서 अन्तरक्रियाशील 대기를 시작하면 거부한다. 입력 대기는 약 2초 CPU 기한을 갱신하지만 입력 대기 없이 무한 반복하는 프로그램은 기존처럼 종료한다.

## 한글 Java

vi에서 다음을 `인사.java`에 입력하고 Esc → `:wq`로 저장한다.

```java
public class 인사 {
    static int 더하기(int 첫째, int 둘째) { return 첫째 + 둘째; }
    public static void main(String[] तर्क) {
        int 합계 = 더하기(20, 22);
        System.out.println("안녕하세요 · 합계=" + 합계);
    }
}
```

게스트 셸에서 실행한다.

```text
javac 인사.java
java 인사
```

한글 फाइल_नाम_पाठ·वर्ग_नाम·तरिका_नाम_पाठ·변수명·문자열을 사용할 수 있다. **게스트 javac는 तथ्याङ्कित_मान Java 부분집합**이다. वस्तु_मान·리스너·Swing·소켓을 사용하는 소스는 현재 होस्ट JDK에서 `javac --release 8 -encoding UTF-8`로 컴파일하고 निज JVM에 class를 올린다. निज JVM에서 지원하는 바이트코드/API 범위는 [자바실행환경.md](자바실행환경.md)를 따른다.

```sh
# होस्ट
mkdir -p build/my-java
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/my-java 시험/자바/스윙시험.java
python3 उपकरणहरू/अपलोड_गर्नुहोस्_फाइलहरू.py build/my-java/스윙시험.class
```

`upload.py`는 게스트 `load`에 붙여 넣을 16진수 명령을 생성한다. 출력 전체를 GUI 터미널에 보내면 업로드한다. 업로드 후 **별도로** `java 스윙시험`을 실행한다. 종속 class가 있으면 각각 업로드한다. 패키지 class의 파일명은 `패키지.वर्ग_मान.class` 형식이다. 내장 नेपाली 라이브러리는 별도 업로드가 필요 없다. नेपाली सन्झ्याल API의 예제는 [한글창시험.java](시험/자바/한글창시험.java)이며 같은 방법으로 बनाउनुहोस्_स्रोत·업로드해 `java 한글창시험`으로 실행한다.

GUI가 필요 없는 단일 स्रोत_वृक्ष/클래스는 호스트의 `python3 उपकरणहरू/कार्यान्वयन_गर्नुहोस्_फाइल.py मार्ग/인사.java`로 별도 QEMU에 업로드·कार्यान्वयन_गर्नुहोस्_आदेश·종료할 수 있다. अन्तरक्रियाशील Swing에는 कार्यान्वयन_गर्नुहोस्_आदेश 후 प्रयोगकर्ता 입력을 유지하는 `make desktop`을 사용한다.

## निज JVM의 Swing क्लिप

실제로 제공하는 것은 **표준 패키지 이름으로 호출하는 निज Swing API 부분집합**이다. OpenJDK `java.desktop` 모듈이나 AWT 전체를 이식한 것은 아니다.

| API | कार्य |
|---|---|
| `JFrame` | सन्झ्याल_शिर्षक, आकार·स्थिति, शो_सन्झ्याल, बन्दगर्नुहोस् 정책, dispose |
| `JPanel` | बच्चा_मान 요소를 담는 패널 |
| `JLabel` | 한글을 포함한 स्ट्रिङ_मान शो_मान·परिवर्तन_मान |
| `JButton` | 버튼과 ActionListener क्लिक_गर्नुहोस्_मान प्रक्रिया_मान_प्रविष्टि |
| `JTextField` | 한 रेखा UTF-8 입력, 삭제, getText/setText, Enter 이벤트 |
| 공통 | setBounds, setSize, add, getContentPane, repaint, validate |
| `SwingUtilities` | invokeLater, isEventDispatchThread |
| `ActionEvent` | getSource, getActionCommand, getID |

`setLayout(null)`과 `setBounds`로 배치한다. FlowLayout/BorderLayout/GridLayout, pack, 폰트·스타일 전체, 메뉴·테이블·트리·스크롤 패널, Java2D, 네이티브 AWT peer/JNI, 복잡한 문자 조판은 아직 없다. 이벤트 콜백은 निज JVM의 단일 이벤트 कार्यान्वयन_गर्नुहोस्_आदेश 흐름에서 처리하며 OpenJDK EDT 구현과 동일하지 않다. सन्झ्याल·요소는 कार्यान्वयन_गर्नुहोस्_आदेश 하나당 합계 32개, तत्त्व_मान 글자는 최대 127 코드포인트다. पूर्वनिर्धारित_मान 서체와 색은 커널이 제공한다.

[스윙시험.java](시험/자바/스윙시험.java)는 सन्झ्याल·한글 ट्याग_मान·पाठ_क्षेत्र·버튼·이벤트 처리의 कार्यान्वयन_गर्नुहोस्_आदेश 가능한 예제다. [निज Swing 화면](build/verification/swing/native-swing.png)을 참고한다.

नेपाली 라이브러리에는 다음을 추가했다. होस्ट बनाउनुहोस्_स्रोत 시 `dist/jkoros-native-korean.jar`를 classpath에 넣는다.

- `नेपाली.निज.सन्झ्याल`: `थप्नुहोस्_तत्त्व`, `शो_सन्झ्याल`, `बन्दगर्नुहोस्`.
- `नेपाली.निज.विजेट`: `ट्याग_मान`, `बटन`, `पाठ_क्षेत्र` सिर्जना_गर्नुहोस्.
- `नेपाली.निज.연결통신`: `जडान`, `듣기`, `받기`.
- 기존 `출력`, `문자`, `फाइल`, `작업`, `प्रविष्टि_सूची`, `शब्दकोष`, `통신`, `화면`, `कर्णेल_मान`도 유지한다.

## Java 네트워크

기존 `DatagramSocket`/`DatagramPacket`의 UDP 루프백에 `Socket`/`ServerSocket`의 **कर्णेल_मान 내부 연결형 बाइट_मान प्रवाह_मान**을 추가했다. फाइल/소켓과 마찬가지로 SVC를 통해 Java 커널이 전송한다. 물리 NIC의 TCP/IP 패킷 스택은 아니다.

```java
java.net.ServerSocket सर्भर_मान = new java.net.ServerSocket(9250);
java.net.Socket अतिथि_मान = new java.net.Socket("localhost", 9250);
java.net.Socket जडान = सर्भर_मान.accept();
अतिथि_मान.getOutputStream().write("안녕하세요".getBytes("UTF-8"));
byte[] 받은것 = new byte[64];
int लम्बाइ_मान = जडान.getInputStream().read(받은것);
जडान.close(); अतिथि_मान.close(); सर्भर_मान.close();
```

सिर्जना_गर्नुहोस्·जडान·accept·양방향 बाइट_मान/विन्यास_मान आगत_लगत·close·EOF·setSoTimeout을 지원한다. `String.getBytes()`와 UTF-8 이름을 지정한 getBytes도 제공한다. 루프백 주소는 `localhost`/`127.0.0.1`이다. 연결형 समाप्त_गर्नुहोस्_अंक 16개, 수신 버퍼당 1024바이트, 대기 जडान 최대 4개이며 Java의 대기는 내부 가닥에 실행을 양보한다. पूर्वनिर्धारित_मान 시간 제한 0은 별도 소켓 기한을 설정하지 않지만 JVM आदेश 수/कर्णेल_मान कार्यान्वयन_गर्नुहोस्_आदेश 기한은 여전히 적용된다.

외부 अङ्क_मान IPv4 TCP/UDP는 lwIP/SLIP로 지원한다. वास्तविक_लगत Ethernet/Wi-Fi 드라이버, DNS·TLS·HTTP पुस्तकालय 전체는 미지원이다. `java.net`의 모든 메서드와 옵션, `SocketChannel`/select, SSL, shutdownInput/Output는 아직 없다. [흐름시험.java](시험/자바/흐름시험.java)는 वास्तविक_लगत 송수신·EOF·기한·जडान 회수의 시험 예제다.

## 한글 Python

게스트 vi에서 한글 이름을 사용해 작성한다.

```python
मान = 21

def 두배(अङ्क_मान):
    return अङ्क_मान * 2

print("मापन:", 두배(मान))
```

भण्डार_गर्नुहोस्_मान 후 `python 인사.py`로 실행한다. 실행기는 MicroPython 1.24.1이다. Python 문법 키워드는 그대로 사용하며 प्रकार्य_मान·변수·फाइल 이름과 문자열을 한글로 쓴다.

[नेपाली.py](예제/한글코딩/नेपाली.py)를 같은 디렉터리에 두면 अर्को_वस्तु 별칭을 사용할 수 있다.

```python
import नेपाली
नेपाली.लेख्नुहोस्_फाइल("인사.txt", "안녕하세요")
नेपाली.출력(नेपाली.파일읽기("인사.txt").decode())
```

출력·फाइल पढनुहोस्/लेख्नुहोस्/삭제·표준 입력·사각형·시간·UDP를 연결한다. 기존 `udp_send`는 루프백, 새 `udp_sendto(fd, "10.0.2.2", port, data)`는 अङ्क_मान IPv4 ठेगाना 전송이다. `wait_key()`는 화면을 확인할 때 अन्तरक्रियाशील 입력을 기다린다. Python 함수는 `jkoros` 내장 모듈을 통해 SVC를 사용한다. C ABI인 posix-kor तथ्याङ्कित_मान 라이브러리를 Python이 직접 링크하는 구성은 아니다. CPython과 일반 विस्तार_मान 모듈은 아직 없다. 제한형 `pip`의 स्रोत_वृक्ष 설치는 [Python पोको readme_फाइल_eb81d7d9](파이썬꾸러미.md)를 따른다. [세 언어의 वास्तविक_लगत 예제](../../example/README.md).

## C·C++에서 posix-kor 호출

두 भाषा 모두 नेपाली 헤더와 प्रकार्य_मान 이름을 직접 사용한다. [인사.c](예제/한글코딩/인사.c), [인사.cpp](예제/한글코딩/인사.cpp)가 वास्तविक_लगत EL0 कार्यान्वयन_गर्नुहोस्_आदेश 시험 대상이다.

```c
#include "파일규약.h"
#ifdef __cplusplus
extern "C"
#endif
int सुरु_प्रयोगकर्ता_अनुप्रयोग(int तर्क) {
    (void)तर्क;
    const char 인사말[] = "안녕하세요\n";
    int 문서 = सिर्जना_फाइल("인사.txt", पढ्न_लेख्_न | 없으면만들기 | 내용비우기, 0600);
    if (문서 < 0) return 1;
    입출력결과형 기록한수 = लेख्नुहोस्_फाइल_लगत(문서, 인사말, sizeof(인사말) - 1);
    बन्द_गर्नुहोस्_फाइल(문서);
    लेख्नुहोस्_फाइल_लगत(1, 인사말, sizeof(인사말) - 1); /* 현재 टर्मिनल stdout */
    return 기록한수 == sizeof(인사말) - 1 ? 0 : 2;
}
```

파일은 게스트 vi로 작성할 수 있다. C는 게스트 `cc` 또는 होस्ट SDK, C++는 होस्ट SDK의 Clang++로 컴파일한다. 아래 예제는 기존 होस्ट SDK 경로다. 게스트 내부 GCC/Clang·libc/libstdc++ 전체를 탑재한 것은 아니다. SDK가 `.c`에는 C11, `.cpp`에는 C++11을 선택한다.

```sh
# 호스트에서 SDK सिर्जना_गर्नुहोस्·झिक्नुहोस्
make sdk
mkdir -p build/sdk-work
tar -xzf dist/jkoros-native-aarch64-sdk.tar.gz -C build/sdk-work
cd build/sdk-work/jkoros-native-sdk
python3 compile.py examples/인사.c -o 인사-c.elf
python3 compile.py examples/인사.cpp -o 인사-cpp.elf

# 프로젝트로 돌아와 별도 QEMU에서 वास्तविक_लगत कार्यान्वयन_गर्नुहोस्_आदेश
cd /home/user/jkoros/platforms/rpi4-native
python3 उपकरणहरू/कार्यान्वयन_गर्नुहोस्_फाइल.py build/sdk-work/jkoros-native-sdk/인사-c.elf
python3 उपकरणहरू/कार्यान्वयन_गर्नुहोस्_फाइल.py build/sdk-work/jkoros-native-sdk/인사-cpp.elf
```

현재 GUI VM에서 실행하려면 `python3 उपकरणहरू/अपलोड_गर्नुहोस्_फाइलहरू.py मार्ग/인사-c.elf`의 출력을 게스트에 보내고 `run 인사-c.elf`를 입력한다. 게스트에서 작성한 소스의 전송은 `hex फाइल_नाम_पाठ`으로 내용을 얻어 호스트에서 `bytes.fromhex(...)`로 복원할 수 있다. 호스트와 게스트의 फाइल 시스템은 별개다.

| नेपाली नाम | C चिन्ह | क्लिप |
|---|---|---|
| सिर्जना_फाइल/बन्द_गर्नुहोस्_फाइल | pk_open/pk_close | RAM फाइल, समान_मान/절대 मार्ग |
| 파일자료읽기/लेख्नुहोस्_फाइल_लगत | pk_read/pk_write | फाइल, fd 0/1/2 표준 आगत_लगत, 연결형 소켓 |
| खोज्नुहोस्_फाइल | pk_lseek | 처음기준/현재기준/끝기준 |
| फाइल_साइज/सेट_फाइल_लम्बाइ | pk_size/pk_ftruncate | लम्बाइ_मान क्वेरी_मान/परिवर्तन_मान |
| हटाउनुहोस्_फाइल_प्रविष्टि_नाम | pk_unlink | फाइल नाम 삭제 |
| 파일저장확정 | pk_fsync | RAM이므로 -1, 오류번호=ENOSYS |
| 통신종단점만들기/बाँध्नु_ठेगाना | pk_socket/pk_bind | AF_INET, SOCK_DGRAM 또는 SOCK_STREAM |
| 자료전문보내기/자료전문받기 | pk_sendto/pk_recvfrom | UDP 루프백 |
| कनेक्ट_सञ्जाल | pk_connect | 연결형 루프백 |
| 통신연결기다리기 | pk_listen | 대기 जडान 최대 4개 |
| स्वीकार्नुहोस्_नेटवर्क_जडान | pk_accept | 현재 ठेगाना 인수는 NULL/NULL만 समर्थन_मान |
| 통신주소읽기 | pk_getsockname | 로컬 ठेगाना/पोर्ट_मान |

`통신규약.h`의 निज `pk_sockaddr_in`을 사용하며 पोर्ट_मान·주소는 `망차례짧은수`/`सञ्जाल_पूर्ण_सङ्ख्या`로 변환한다. C 소켓 호출은 비차단이며 लगत/연결이 없으면 -1과 `오류번호=11`(EAGAIN)을 반환한다. 양수 आगत_लगत 결과가 요청보다 작을 수 있으므로 दोहर्_याउनु_मान 처리한다. विफल_मान 후에만 오류번호를 확인한다.

[प्रवाह_मान.c](예제/한글코딩/प्रवाह_मान.c)는 C에서 नेपाली 이름으로 जडान·accept·부분 पढनुहोस्/लेख्नुहोस्·큐 포화·EOF를 처리하는 कार्यान्वयन_गर्नुहोस्_आदेश 예제다. SDK의 `examples/प्रवाह_मान.c`를 같은 `compile.py`로 컴파일한다.

SDK는 **libposix-kor-user.a**를 링크한다. 호출 흐름은 C/C++ → वास्तविक_लगत नेपाली C प्रकार्य_मान 또는 호환용 `pk_*` → `svc #0` → 커널의 소유권·पोइन्टर 검사 → Java RAM फाइल/루프백 또는 외부 lwIP TCP/UDP 구현이다. `libposix-kor-arm64.a`는 कर्णेल_मान 내부용이므로 EL0 프로그램에 링크하지 않는다. Linux 헤더나 Linux ELF와 혼합하지 않는다. 동적 जडान, 표준 C printf, libstdc++/STL, 예외·RTTI는 제공하지 않으며 C++의 तथ्याङ्कित_मान 생성자·स्थानीय_क्षेत्र वस्तु_मान 소멸자는 지원한다. 상세 अनुक्रमणिका·मेमोरी_लगत 범위는 [사용자호출규약.md](사용자호출규약.md)를 참고한다.

## वैध_गर्नुहोस्

`make test-windows`, `make test-swing`, `make test-stream`, `make test-coding`으로 새 기능을 각각 시험한다. `make test`는 기존 शेल·VNC·JVM·AOT·कर्णेल_मान सुरक्षित_गर्नुहोस्_मान 시험까지 포함한다. वास्तविक_लगत बोर्ड 대신 QEMU raspi4b에서 수행한다. 결과는 [이전 GUI विस्तार_मान वैध_गर्नुहोस् लग_रेकर्ड](build/verification/release.json)과 [현재 सामान्य_भाषा_चालु_समय वैध_गर्नुहोस् लग_रेकर्ड](build/verification/native-runtime-summary.json), [여러 टर्मिनल 화면](build/verification/windows/four-terminals.png), [Swing 화면](build/verification/swing/native-swing.png)을 참고한다.

구현 시 참고한 표준 API: [Socket](https://docs.oracle.com/javase/8/docs/api/java/net/Socket.html), [JFrame](https://docs.oracle.com/javase/8/docs/api/javax/swing/JFrame.html), [JButton](https://docs.oracle.com/javase/8/docs/api/javax/swing/JButton.html). 이 문서의 구현 범위가 위 표준 전체를 지원한다는 뜻은 아니다.

## नेपाली 이름으로 직접 작성하는 창과 धागो_मान

`example/java/झ्यालउदाहरण.java`는 `실행할일.कार्यान्वयन_गर्नुहोस्`,
`동작받이.동작받기(동작알림)`, `बटन`, `घटना_लाइन.나중에실행`, `चलाउनुहोस्()`을 쓴다.
निज JVM에 이 이름들의 वस्तु_मान·तरिका_मान·콜백을 직접 구현했으며 영어 Swing 객체를
보관하는 래퍼가 아니다. `작업가닥`도 निज 스케줄러와 직접 연결된다.
세부 메서드와 기존 नेपाली API에서의 변경은 [नेपाली API 문서](한국어자바/readme_फाइल_eb81d7d9.md)를 본다.

होस्ट javac는 배포 JAR를 वर्ग_मान 경로로 사용한다.

```sh
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/한국어사용 ../../example/java/झ्यालउदाहरण.java
python3 उपकरणहरू/कार्यान्वयन_गर्नुहोस्_आदेश.py --desktop --network --resolution 1920x1080
```

게스트에는 빌드한 예제가 `/example/java`에 설치된다.

```text
cd /example/java
java झ्यालउदाहरण
```

직접 화면/धागो_मान API와 `चलाउनुहोस्()` 진입점은 निज JVM 전용이다.
전체 OpenJDK·Swing 재구현이나 일반 OpenJDK에서 같은 API의 실행을 보장하지 않는다.
기존 표준 `main(String[])` 프로그램은 계속 실행할 수 있다.
