# JNplOS

현재 निज ARM64 배포판은 [LICENSE](LICENSE)의 COSL 상업 조건을 유지한다. 제3자 라이선스의 권리는 별도로 보장하며, 배포 시 स्रोत_वृक्ष·재연결 자료를 포함하는 절차는 [COSL 배포 readme_फाइल_eb81d7d9](platforms/rpi4-native/COSL배포안내.md)에 있다.

निज ARM64 판의 `ipconfig`/`ip`, `ping`, `ps`/`top`, `free`/`df`, `poweroff`와 नेपाली 명령은 [네트워크·सञ्चालनप्रणाली_मान आदेश readme_फाइल_eb81d7d9](platforms/rpi4-native/네트워크와체계명령.md)를 참고한다. 새 커널을 부팅한 पछाडि_मान `help system`으로 볼 수 있다.

Raspberry Pi 4 **निज Java ARM64 कर्णेल_मान**은 [निज Pi4 readme_फाइल_eb81d7d9](platforms/rpi4-native/readme_फाइल_eb81d7d9.md)에 있다. Linux 없이 부팅하며 GUI टर्मिनल·vi, निज JVM의 Swing 일부 API, TCP/UDP·FTP, 게스트 TinyCC·MicroPython, C/C++의 posix-kor 호출을 제공한다. [नेपाली Java 통신·예외 API](platforms/rpi4-native/한국어자바/readme_फाइल_eb81d7d9.md)와 [नेपाली स्रोत_वृक्ष 명명](platforms/rpi4-native/명명/readme_फाइल_eb81d7d9.md)을 지원한다. [निज SSH·VNC 및 GENET 드라이버](platforms/rpi4-native/외부접속안내.md)를 포함하며, 네트워크는 QEMU의 UART SLIP 경로로 검증했다. वास्तविक_लगत Pi 4 GENET 동작은 미검증이고, USB 입력·영속 저장과 전체 OpenJDK·Swing은 아직 समर्थन_मान क्लिप 밖이다.

Raspberry Pi 4용 Linux·OpenJDK 실행판과 प्रयोगकर्ता 환경 लैजानुहोस्_मान 기능은 [라즈베리파이 실행판](platforms/rpi4/README.md)에 있다. वास्तविक_लगत ARM64 JDK/JRE와 시스템·प्रयोगकर्ता बनाउनुहोस्_छवि बनाउनुहोस्_प्रणाली 경로를 제공한다. 기존 निज x86 커널과는 별도 कार्यान्वयन_गर्नुहोस्_आदेश 기반이다. 일반 Java `.class`/JAR의 कार्यान्वयन_गर्नुहोस्_आदेश फाइल 생성은 [OpenJDK कार्यान्वयन_गर्नुहोस्_आदेश फाइल](compiler/OpenJDK-실행파일.md), नेपाली API는 [नेपाली Java पुस्तकालय](한국어자바/readme_फाइल_eb81d7d9.md)를 참고한다.

`jkoros`는 `engos`의 기능을 Java 관리 커널로 옮기는 프로젝트다. 프로젝트가 소유하는 Java प्रकार्य_मान, 변수, ढाँचा_मान 및 Java फाइल 이름은 한국어로 작성한다. 표준 Java 실행기의 `main`, Java 표준 पुस्तकालय ढाँचा_मान, x86 부트 ABI 등 외부 계약은 보존한다. निज ARM64 실행기는 नेपाली `चलाउनुहोस्()`도 진입점으로 지원하며, नेपाली GUI·작업 가닥을 JVM에 직접 구현했다. निज ARM64 C 연결부·Python 도구와 공용 x86·ARM64 AOT 번역기의 निज 이름도 한국어로 작성한다. 이전 경로의 호환 प्रविष्टि_अंक, OpenJDK 보조 도구와 Linux संस्करण_मान 도구에는 영어 이름이 남아 있고 [명명 원칙·말의 근거·전체 स्रोत 검토 क्लिप](platforms/rpi4-native/명명/readme_फाइल_eb81d7d9.md)를 별도로 기록한다.

## 현재 구현

아래 목록은 기존 `बिरासत_स्रोत/`의 JVM 관리 커널에 대한 것이다. वास्तविक_लगत 네이티브 커널의 범위는 `os/readme_फाइल_eb81d7d9.md`에서 별도로 설명한다.

- पङ्_क्तिबद्ध_गर्नुहोस्_मान 할당과 해제를 지원하는 기억공간 प्रबन्धक_मान
- ठेगाना 공간, पृष्ठ_मान जडान, लेख्नुहोस् 시 उद्धरण_मान_37b3d3b1(COW)
- प्रक्रिया_मान परिचायक_मान, तयार_गर्नुहोस् 대기열, fork/wait स्थिति_मान
- 과정별 फाइल 서술자, open/read/seek/dup/close
- ELF32 식별 및 सेक्सन_मान 검사
- 키보드·마우스 입력 घटना 대기열
- 직렬 단말과 네이티브 हार्डवेयर_मान 경계
- 관리 कर्णेल_मान 전체 자동 시험

세부 대응 범위와 아직 필요한 네이티브 연결은 [기능 대응표](문서/기능대응.md)에 기록한다.

## 빌드와 시험

새 네이티브 구현은 `compiler/`와 `os/`에 있다. 기존 `बिरासत_स्रोत/`의 JVM 관리 커널은 그대로 보존하며, 두 구현의 시험과 기능 범위는 서로 다르다.

```sh
cd /home/user/jkoros
make                 # 네이티브 계산 예제 + Java कर्णेल_मान ELF
make iso             # os/build/kernel.iso
make run             # QEMU 직렬 단말; help 입력 (종료는 Ctrl+A, X)
make run-gui         # ISO를 QEMU 화면/PS2 키보드로 कार्यान्वयन_गर्नुहोस्_आदेश
make vbox            # 전용 VirtualBox VM 자동 सिर्जना_गर्नुहोस्·कार्यान्वयन_गर्नुहोस्_आदेश (GUI)
make vbox-status     # VirtualBox स्थिति_मान·ISO·직렬 लग_रेकर्ड मार्ग रुजू_गर्नुहोस्
make test-vbox       # VirtualBox अनुप्रयोग_कर्मचारी_अगुवा स्थिति_मान प्रक्रिया_मान_प्रविष्टि 시험 (वास्तविक_लगत VM परिवर्तन_मान 없음)
make test            # 컴파일러 시험 + ELF/ISO 부팅 및 आदेश 입력 시험
make apps            # 독립 प्रयोगकर्ता ELF अनुप्रयोग_f5044b9b बनाउनुहोस्_प्रणाली
make test-network    # प्रयोगकर्ता मोड_मान·UDP 왕복·मेमोरी_लगत सुरक्षित_गर्नुहोस्_मान 시험
make test-java       # 게스트 javac/JVM + OpenJDK 양방향 교차 कार्यान्वयन_गर्नुहोस्_आदेश 시험
make posix-kor       # नेपाली C 헤더와 वास्तविक_लगत कर्णेल_मान 호출 पुस्तकालय
make test-posix      # फाइल/UDP/भण्डार_गर्नुहोस्_मान/Java फाइल आगत_लगत 시험
make -C os run-store # 전용 भण्डार_गर्नुहोस्_मान 매체로 QEMU 부팅
make legacy-test     # 아래 기존 JVM 관리 커널의 47개 시험
```

`compiler/`는 호스트의 `javac`를 문법·प्रकार_मान 검사 전단으로 사용하고 निज 바이트코드→x86 변환기로 ELF32 기계어를 만든다. 빌드할 때는 JDK가 필요하지만 생성된 커널과 ELF는 외부 JVM 없이 실행된다. 전체 Java, वस्तु_मान 모델, 표준 라이브러리와 기존 관리 कर्णेल_मान 전체의 AOT 변환은 아직 지원하지 않는다. 자세한 समर्थन_मान 문법과 명령은 [컴파일러 readme_फाइल_eb81d7d9](compiler/readme_फाइल_eb81d7d9.md), वास्तविक_लगत 부팅 기능과 한계는 [네이티브 सञ्चालनप्रणाली readme_फाइल_eb81d7d9](os/readme_फाइल_eb81d7d9.md)를 참고한다.

네이티브 셸에 निज 제한형 `javac`와 `java`를 추가했다. `edit Demo.java`로 소스를 입력하고 `.save`로 저장한 पछाडि_मान `javac Demo.java`, `java Demo`로 **게스트 내부에서 컴파일하고 कार्यान्वयन_गर्नुहोस्_आदेश**할 수 있다. पूर्वनिर्धारित_मान 예제는 `javac Hello.java`, `java Hello`다. 파일은 RAM에서 동작하며, 전용 भण्डार_गर्नुहोस्_मान 매체를 연결하면 `sync`로 재부팅 후에도 보존할 수 있다. **OpenJDK/JDK 전체 이식은 아니며**, 단일 वर्ग_मान·तथ्याङ्कित_मान प्रकार्य_मान·पूर्ण_सङ्ख्या·स्ट्रिङ_मान·सर्त/반복문과 일부 표준 호출을 지원한다. समर्थन_मान क्लिप, 외부 फाइल 적재와 시험은 [Java 개발 환경 readme_फाइल_eb81d7d9](문서/자바개발환경.md)에 있다.

네이티브 셸에서 `apps`, `run hello first second`, `net`, `run netcheck`를 사용할 수 있다. 독립 ELF를 ring 3에 적재하고 `int 0x80` 호출을 통해 출력·तर्क·UDP 네트워크를 제공한다. 별도 होस्ट 터미널에서 `python3 os/उपकरणहरू/자료되돌리기.py --port 9000`을 실행한 पछाडि_मान 게스트에서 `run udp 10.0.2.2 9000 hello`로 वास्तविक_लगत 왕복을 확인한다. 새 अनुप्रयोग_f5044b9b दर्ता_प्रविष्टि, API 및 제한은 [प्रयोगकर्ता कार्यान्वयन_गर्नुहोस्_आदेश·네트워크 readme_फाइल_eb81d7d9](os/प्रयोगकर्ता/readme_फाइल_eb81d7d9.md)를 참고한다. 현재 QEMU RTL8139·तथ्याङ्कित_मान IPv4·UDP 전용이며 TCP/DNS는 미지원이며, 전용 IDE भण्डार_गर्नुहोस्_मान 형식과 POSIX फाइल/UDP 일부 기능을 추가했다.

`make vbox`는 `jkoros operating system` 전용 VM을 만들고 디스크 없이 ISO로 부팅한다. कार्यान्वयन_गर्नुहोस्_आदेश 중이면 유지하고, भण्डार_गर्नुहोस्_मान·일시정지 상태이면 재개하며, 꺼져 있을 때만 새 ISO를 빌드해 연결한다. VirtualBox에서 부팅과 셸의 प्रयोगकर्ता अनुप्रयोग_f5044b9b 실행을 확인했다. 다만 현재 VirtualBox용 네트워크 드라이버는 없어 네트워크 장치를 비활성화한다. UDP 시험에는 `make run`을 사용한다. 상태별 동작과 새 बनाउनुहोस्_प्रणाली 반영 방법은 [VirtualBox कार्यान्वयन_गर्नुहोस्_आदेश readme_फाइल_eb81d7d9](문서/가상상자실행.md)에 있다.

기존 관리 커널만 시험하려면:

```sh
cd /home/user/jkoros
make -f सिर्जना_प्रविष्टि.mk 검사
make -f सिर्जना_प्रविष्टि.mk होस्ट
```

`होस्ट`는 여전히 JVM 관리 계층의 कार्य 시험이다. `make -f सिर्जना_प्रविष्टि.mk बनाउनुहोस्_छवि`는 새 `os/`의 제한형 네이티브 कर्णेल_मान ISO를 만든다. 기존 `बिरासत_स्रोत/`의 फाइल_प्रणाली·प्रक्रिया_मान·सञ्जाल_चाङ 구현 전체를 이 ISO에 이식했다는 의미는 아니다.

नेपाली प्रकार्य_मान·변수·फाइल 이름과 वास्तविक_लगत C API는 [posix-kor](posix-kor/readme_फाइल_eb81d7d9.md)에 있다. 게스트 Java에서는 `FileInputStream`·`FileOutputStream`의 단일 बाइट_मान 입출력도 지원한다. 전체 POSIX·OpenJDK·Swing 지원으로 확대된 것은 아니다.

외부 배포용 `pack.sh` / `unpack.sh`와 자동 의존성 복원은 [배포 readme_फाइल_eb81d7d9](distribution/README.md)를 참고하세요.
