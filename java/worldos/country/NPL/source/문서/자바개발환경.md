# jkoros 안에서 Java बनाउनुहोस्_स्रोत·कार्यान्वयन_गर्नुहोस्_आदेश

이 문서의 부팅·शेल·भण्डार_गर्नुहोस्_मान 명령은 **x86 संस्करण_मान** 기준이다. 공유 Java 컴파일러/JVM은 [निज ARM64 Pi4 संस्करण_मान](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 फाइल_नाम_पाठ, `edit`의 단독 `.` भण्डार_गर्नुहोस्_मान, 16개 RAM फाइल, 약 2초 कार्यान्वयन_गर्नुहोस्_आदेश 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 वास्तविक_लगत JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. होस्ट बनाउनुहोस्_स्रोत 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 निज 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java अनुप्रयोग_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 कार्यान्वयन_गर्नुहोस्_आदेश

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. कार्यान्वयन_गर्नुहोस्_आदेश 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox कार्यान्वयन_गर्नुहोस्_आदेश readme_फाइल_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 फाइल 전체를 새 내용으로 작성한다. 기존 내용의 रेखा सम्पादन_गर्नुहोस्_मान 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 बाइट_मान 수 शो_मान.
- `cat FILE`: फाइल सामग्री_मान शो_मान. 텍스트 소스에 사용한다.
- `rm FILE`: मेमोरी_लगत फाइल 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·प्रकार_मान 검사 विफल_मान 시 기존 `.class`는 유지된다. 소스를 고친 पछाडि_मान 컴파일이 실패했다면 이전 कार्यान्वयन_गर्नुहोस्_आदेश 파일이 남아 있으므로 बनाउनुहोस्_स्रोत 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 भण्डार_गर्नुहोस्_मान 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 स्रोत_वृक्ष·वर्ग_मान·लगत 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, फाइल 이름은 ASCII 1~63자다. स्रोत_वृक्ष 이름은 `.class` 확장자 공간 때문에 최대 62자다. सम्पादन_गर्नुहोस्_मान 입력은 ASCII이고 한 रेखा 최대 128자다. रेखा 또는 फाइल 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. कर्णेल_मान/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 प्रयोगकर्ता 예제 이름은 ASCII로 작성한다.

## 외부 फाइल 적재

호스트에서 만든 소스나 समर्थन_मान क्लिप 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 वास्तविक_लगत 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# होस्ट JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 अर्को_वस्तु 빌드에서는 추가 파일을 포함하지 않는다. फाइल सामग्री_मान 변경과 प्रविष्टि_सूची 제거도 अर्को_वस्तु 빌드에 반영된다. 원본 होस्ट 파일에는 쓰지 않는다. पूर्वनिर्धारित_मान `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 पूर्वनिर्धारित_मान 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 वर्ग_मान फाइल 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 समर्थन_मान क्लिप 안에 있어야 한다.

## समर्थन_मान क्लिप

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| वर्ग_मान | 패키지 없는 단일 वर्ग_मान, तथ्याङ्कित_मान प्रकार्य_मान, 재귀, तर्क/반환 | 실행마다 단일 वर्ग_मान 적재, public static main(String[]) |
| पूर्वनिर्धारित_मान मान | int, boolean, char, String, main의 String[] तर्क | पूर्ण_सङ्ख्या·निर्देश 스택, String, int[], String[], 내부 StringBuilder |
| कथन_मान | 초기값 있는 स्थानीय_क्षेत्र 선언, अधिन्यास_मान, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 पूर्ण_सङ्ख्या·निर्देश 바이트코드와 सर्त शाखा |
| अभिव्यक्ति_मान | 십진 पूर्ण_सङ्ख्या, UTF-8 소스의 स्ट्रिङ_मान/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, स्ट्रिङ_मान 결합 | पूर्ण_सङ्ख्या सञ्चालन_मान·बिट_मान सञ्चालन_मान·प्रकार_मान 변환, 단락 평가, विन्यास_मान पहुँच_प्रविष्टि |
| फाइल | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | वास्तविक_लगत कर्णेल_मान 파일서술자와 जडान, सिर्जना_गर्नुहोस्·खाली_गर्नुहोस्_टिओसी·이어쓰기·EOF |
| 출력 | System.out.print/println: int/boolean/char/String, println() | 동일 |
| स्ट्रिङ_मान/तर्क | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), स्ट्रिङ_मान 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 स्थानीय_क्षेत्र 선언, 오버로드, 임의 प्रकार_मान 변환, विन्यास_मान सिर्जना_गर्नुहोस् स्रोत, 8/16진 리터럴, Unicode स्रोत_वृक्ष 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 अचल_मान 축소 변환을 구현하지 않는다. 외부 `.class`의 `int[]` सिर्जना_गर्नुहोस्/पढनुहोस्/쓰기는 지원하므로 होस्ट `javac --release 8`로 만든 विन्यास_मान 예제는 실행할 수 있다.

वस्तु_मान फाँट_मान·일반 वस्तु_मान सिर्जना_गर्नुहोस्·상속·인터페이스·여러 वर्ग_मान जडान, long/float/double, 예외 प्रक्रिया_मान_प्रविष्टि, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java 예외 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 स्ट्रिङ_मान भण्डार_गर्नुहोस्_मान 공간은 कार्यान्वयन_गर्नुहोस्_आदेश बाहिर_जानुहोस्_अनुप्रयोग 시 प्रयोगकर्ता 영역 전체와 함께 회수한다. 지속 कार्यान्वयन_गर्नुहोस्_आदेश 중 GC는 없다.

## कार्यान्वयन_गर्नुहोस्_आदेश 한도와 त्रुटि

| स्रोत_मान | 한도 |
| --- | --- |
| स्रोत_वृक्ष/वर्ग_मान फाइल | 각각 16KiB |
| 컴파일러 | टोकन_मान 2,047개, सिर्जना_गर्नुहोस् 코드 4KiB, अचल_मान 풀 4KiB |
| प्रकार्य_मान/तर्क | 클래스당 32함수, 함수당 16인수 |
| JVM अचल_मान | 511개 |
| JVM प्रकार्य_मान 코드 | 함수당 8KiB |
| JVM 호출/스택/स्थानीय_क्षेत्र 변수 | 32프레임, 프레임당 스택 128칸·स्थानीय_क्षेत्र 128칸 |
| JVM वस्तु_मान भण्डार_गर्नुहोस्_मान 공간 | 8,192개 32비트 स्लट_प्रविष्टि, 헤더 포함 약 32KiB |
| कार्यान्वयन_गर्नुहोस्_आदेश | 최대 500,000 आदेश, 기존 커널의 약 3초 CPU कार्यान्वयन_गर्नुहोस्_आदेश 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 समर्थन_मान 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM शब्दकोष 검증기를 구현한 것은 아니다. फाइल/विशेषण_मान लम्बाइ_मान, अचल_मान निर्देश, आदेश·शाखा 경계를 검사하고, कार्यान्वयन_गर्नुहोस्_आदेश 중 스택 ढाँचा_मान·स्थानीय_क्षेत्र आरम्भिक·विन्यास_मान सबस्क्रिप्ट_मान·वस्तु_मान 참조를 검사한다. प्रयोगकर्ता 코드의 페이지·हार्डवेयर_पोर्ट 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, बनाउनुहोस्_स्रोत·JVM 오류는 `Exit: 1`, आदेश तर्क 오류는 `Exit: 2`다. CPU 시간 상한은 기존 `Exit: 124`이며, प्रयोगकर्ता ELF 자체의 CPU/런타임 오류는 기존 बाहिर_जानुहोस्_अनुप्रयोग 코드를 따른다. विफल_मान 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## 구현 위치와 시험

- `os/प्रयोगकर्ता/자바/자바컴파일러.java`: 게스트 어휘·구문·प्रकार_मान 검사, अचल_मान 풀 및 바이트코드 सिर्जना_गर्नुहोस्.
- `os/प्रयोगकर्ता/자바/자바가상기계.java`: वर्ग_मान 적재, 스택·프레임·वस्तु_मान भण्डार_गर्नुहोस्_मान, आदेश 해석과 제한된 표준 호출.
- `os/स्रोत/मेमोरी_फाइल_प्रणाली.java`: मेमोरी_लगत फाइल_प्रणाली, सम्पादन_गर्नुहोस्_मान, 부팅 फाइल 적재.
- `os/स्रोत/체계호출.java`, `compiler/सुरु_प्रयोगकर्ता_अनुप्रयोग.s`: फाइल/문자 출력 API와 प्रयोगकर्ता पोइन्टर 검사.
- `os/उपकरणहरू/자바파일묶기.py`: होस्ट 입력 फाइल वैध_गर्नुहोस्·부팅 समूह_मान सिर्जना_गर्नुहोस्.

```sh
make test-java
make test
```

`os/시험/자바시험.py`는 ELF/ISO 부팅, 게스트 बनाउनुहोस्_स्रोत·कार्यान्वयन_गर्नुहोस्_आदेश, प्रयोगकर्ता 입력, 재귀·반복문·पूर्ण_सङ्ख्या 극값·स्ट्रिङ_मान 결합·단락 평가, 재실행, स्रोत_वृक्ष त्रुटि 후 기존 वर्ग_मान 보존, विन्यास_मान/수 해독 त्रुटि, 무한 दोहर्_याउनु_मान 제한, सम्पादन_गर्नुहोस्_मान 넘침과 फाइल 부족을 검사한다. 게스트 सिर्जना_गर्नुहोस् 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 होस्ट OpenJDK의 वर्ग_मान, पूर्ण_सङ्ख्या 배열과 한글 상수를 게스트에 적재하며, 손상된 फाइल 표식·버전·अचल_मान 수·शाखा·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 시험 VM만 생성하고 종료한다.

구현 형식의 참고 लगत: Oracle [JVM वर्ग_मान फाइल 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM आदेश 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java फाइल आगत_लगत

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 वर्ग_मान 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 पछाडि_मान `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. पूर्वनिर्धारित_मान 출력 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. 예외 वस्तु_मान·try/catch·try-with-resources는 지원하지 않으며 फाइल 오류를 진단하고 프로그램을 종료한다. विन्यास_मान आगत_लगत, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 फाइल 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 शेल `sync`가 필요하다. 예제의 फाइल 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 वास्तविक_लगत 게스트 बनाउनुहोस्_स्रोत 결과를 OpenJDK `-Xverify:all`로 다시 실행해 फाइल 바이트와 출력을 대조한다. 범위와 भण्डार_गर्नुहोस्_मान 매체 사용법은 [posix-kor readme_फाइल_eb81d7d9](../posix-kor/readme_फाइल_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
