# 자체 커널에서 vi·여러 Tauranga·한글 프로그래밍 사용하기

Reo_Māori 통신·예외 사용법은 [Reo_Māori Java API](한국어자바/PĀNUIMAI_eb81d7d9.md), TAUMAHI_uara·변수·Kōnae 이름의 변경과 어원 근거는 [명명 PĀNUIMAI_eb81d7d9](명명/PĀNUIMAI_eb81d7d9.md)를 참고한다.

대상은 `platforms/rpi4-native`의 자체 AArch64 Java 커널이다. vi와 Java/Python/C/C++ 프로그램은 EL0에서 실행한다. Linux 실행판과 별도이며 아래 Tautoko_uara 목록은 전체 OpenJDK·Vim·POSIX 구현을 뜻하지 않는다.

게스트 `cc`/`jaot`, JAR 직접 kawe_tono, 외부 TCP/UDP와 FTP는 [새 kawe_tono 매뉴얼](파일전송과번역.md)을 참고한다.

## GUI와 여러 Tauranga

```sh
cd /home/user/jkoros/platforms/rpi4-native
make desktop
```

Remmina에서 **VNC**, ADDRESS **127.0.0.1:5902**로 연결한다. 화면 위 **+ New terminal**, **Ctrl+Shift+T**로 터미널을 추가한다. 최대 네 개다. 위쪽 Tauranga 버튼 또는 창을 클릭해 선택하고 **F6**으로 순환한다. 제목줄을 끌어서 옮기고 **RIGHT 위 X**를 클릭하면 닫힌다. 마지막 창을 닫아도 위쪽 kawe_tono 버튼으로 다시 tīwae_uara 수 있다. 기존 `terminal`, `exit`, F12도 사용할 수 있다.

창마다 현재 디렉터리, anga 변수, tono LOG_RECORD, 입력 중인 명령과 kaupapa_f5044b9b kawe_tono 상태를 보관한다. Kōnae 저장소는 공유한다. vi와 Swing의 이벤트 대기 중에 다른 터미널로 전환하면 kaiwhakamahi Pūmahara_raraunga·레지스터·Kōnae/소켓 연결을 보존했다가 돌아올 때 재개한다. **현재 네 프로그램이 동시에 CPU에서 실행되는 선점형 스케줄러는 아니다.** 계산 중인 프로그램은 Panuku_tuemi 입력 대기 또는 기존 kawe_tono 기한까지 전환이 지연될 수 있다.

X로 터미널을 닫으면 그 터미널의 kawe_tono 중인 프로그램도 종료하며 서술자·소켓을 회수한다. 저장하지 않은 whakatika_uara 내용은 사라진다. 종료한 슬롯은 새 창에서 재사용한다. 현재 모든 파일은 RAM에 있으며 VM 재시작 후에는 남지 않는다.

화면과 matapihi 판단은 게스트 커널이 처리한다. QEMU kawe_tono 도구는 VNC 키와 마우스 좌표를 UART 패킷으로 전달한다. tūturu_raraunga Pi4 USB 입력기와 실물 부팅은 아직 검증하지 않았다. 일반 UART 셸은 `make run`, GUI Ngā_Utauta 종료는 taurima 터미널의 Ctrl+C다.

## vi 사용

```text
mkdir 작업
cd 작업
vi 인사.py
```

`vi`는 새로 구현한 **vi tono 부분집합** 편집기다. 내장 `build/user/vi.elf`를 보호된 kaiwhakamahi 영역에 적재한다. Kōnae 크기는 UTF-8 paita_uara whakaatu_pūtake 16 KiB, 경로는 63바이트까지다. 디스크에 설치한 Vim/Neovim 바이너리를 실행하는 것이 아니다.

| `o`, `O` | 아래/위에 새 줄을 만들고 입력 |
| Esc | 일반 MODE_uara |

| `gg`, `G`, `:INDEX` | Kōnae 처음/마지막 hononga/tautapa_uara hononga |
| PgUp, PgDn | 화면 ngā_wae_uara nuku_uara |
| `x`, Delete | 현재 문자 삭제 |

붙여 넣은 한글을 문자 경계에 맞춰 nuku_uara·삭제한다. 일반 vi의 수량 접두사, tonotono_uara, Ngā_Tautuhinga Kōnae, 플러그인, 정규식, 여러 버퍼/분할 matapihi, 문법 강조 등은 아직 없다. `--desktop`에서는 F9·Shift+Space·한/영 키로 두벌식 조합을 전환한다. PC 입력기를 영어로 두고 matapihi matapihi_Taitara `[KO]`에서 입력하며, `help ko`에 단축키를 표시한다. 완성된 Unicode 문자와 VNC의 명시적 붙여넣기도 전달한다.

vi와 Swing 프로그램은 **단독 tono**으로 실행한다. 파이프·리다이렉션·hōtuhi_uara·`;`/`&&`/`||`로 연결한 실행에서 pāhekoheko 대기를 시작하면 거부한다. 입력 대기는 약 2초 CPU 기한을 갱신하지만 입력 대기 없이 무한 반복하는 프로그램은 기존처럼 종료한다.

## 한글 Java

vi에서 다음을 `인사.java`에 입력하고 Esc → `:wq`로 저장한다.

```java
public class 인사 {
    static int 더하기(int 첫째, int 둘째) { return 첫째 + 둘째; }
    public static void main(String[] 인수) {
        int 합계 = 더하기(20, 22);
        System.out.println("안녕하세요 · 합계=" + 합계);
    }
}
```

게스트 셸에서 실행한다.

```text
javac 인사.java
java 인사
```

한글 kōnae_ingoa_TEXT·tauaha_ingoa·aratuka_ingoa_TEXT·변수명·문자열을 사용할 수 있다. **게스트 javac는 pateko_uara Java 부분집합**이다. ahanoa_uara·리스너·Swing·소켓을 사용하는 소스는 현재 taurima JDK에서 `javac --release 8 -encoding UTF-8`로 컴파일하고 자체 JVM에 class를 올린다. 자체 JVM에서 지원하는 바이트코드/API 범위는 [자바실행환경.md](자바실행환경.md)를 따른다.

```sh
# taurima
mkdir -p build/my-java
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/my-java 시험/자바/스윙시험.java
python3 Ngā_Utauta/tukuatu_Ngā_Kōnae.py build/my-java/스윙시험.class
```

`upload.py`는 게스트 `load`에 붙여 넣을 16진수 명령을 생성한다. 출력 전체를 GUI 터미널에 보내면 업로드한다. 업로드 후 **별도로** `java 스윙시험`을 실행한다. 종속 class가 있으면 각각 업로드한다. 패키지 class의 파일명은 `패키지.tauaha_uara.class` 형식이다. 내장 Reo_Māori 라이브러리는 별도 업로드가 필요 없다. Reo_Māori matapihi API의 예제는 [한글창시험.java](시험/자바/한글창시험.java)이며 같은 방법으로 hanga_pūtake·업로드해 `java 한글창시험`으로 실행한다.

GUI가 필요 없는 단일 pūtake_rākau/클래스는 호스트의 `python3 Ngā_Utauta/kawe_kōnae.py ara/인사.java`로 별도 QEMU에 업로드·kawe_tono·종료할 수 있다. pāhekoheko Swing에는 kawe_tono 후 kaiwhakamahi 입력을 유지하는 `make desktop`을 사용한다.

## 자체 JVM의 Swing topenga

실제로 제공하는 것은 **표준 패키지 이름으로 호출하는 자체 Swing API 부분집합**이다. OpenJDK `java.desktop` 모듈이나 AWT 전체를 이식한 것은 아니다.

| API | hohenga |
|---|---|
| `JFrame` | matapihi_Taitara, rahi·tūranga, whakaatu_matapihi, Kati 정책, dispose |
| `JPanel` | tamaiti_uara 요소를 담는 패널 |
| `JLabel` | 한글을 포함한 aho_uara whakaatu_uara·huri_uara |
| `JButton` | 버튼과 ActionListener pāwhiri_uara Hātepe_uara_tāurunga |
| `JTextField` | 한 hononga UTF-8 입력, 삭제, getText/setText, Enter 이벤트 |
| 공통 | setBounds, setSize, add, getContentPane, repaint, validate |
| `SwingUtilities` | invokeLater, isEventDispatchThread |
| `ActionEvent` | getSource, getActionCommand, getID |

`setLayout(null)`과 `setBounds`로 배치한다. FlowLayout/BorderLayout/GridLayout, pack, 폰트·스타일 전체, 메뉴·테이블·트리·스크롤 패널, Java2D, 네이티브 AWT peer/JNI, 복잡한 문자 조판은 아직 없다. 이벤트 콜백은 자체 JVM의 단일 이벤트 kawe_tono 흐름에서 처리하며 OpenJDK EDT 구현과 동일하지 않다. matapihi·요소는 kawe_tono 하나당 합계 32개, huānga_uara 글자는 최대 127 코드포인트다. uara_taunoa 서체와 색은 커널이 제공한다.

[스윙시험.java](시험/자바/스윙시험.java)는 matapihi·한글 tūtohu_uara·āpure_kuputuhi·버튼·이벤트 처리의 kawe_tono 가능한 예제다. [자체 Swing 화면](build/verification/swing/native-swing.png)을 참고한다.

Reo_Māori 라이브러리에는 다음을 추가했다. taurima hanga_pūtake 시 `dist/jkoros-native-korean.jar`를 classpath에 넣는다.

- `Reo_Māori.자체.matapihi`: `tāpiri_huānga`, `whakaatu_matapihi`, `Kati`.
- `Reo_Māori.자체.taputapu`: `tūtohu_uara`, `pātene`, `āpure_kuputuhi` waihanga.
- `Reo_Māori.자체.연결통신`: `TŪHONO`, `듣기`, `받기`.
- 기존 `출력`, `문자`, `Kōnae`, `작업`, `tāurunga_Rārangi`, `papakupu`, `통신`, `화면`, `kākano_uara_0611a8a8`도 유지한다.

## Java 네트워크

기존 `DatagramSocket`/`DatagramPacket`의 UDP 루프백에 `Socket`/`ServerSocket`의 **kākano_uara_0611a8a8 내부 연결형 paita_uara roma_uara**을 추가했다. Kōnae/소켓과 마찬가지로 SVC를 통해 Java 커널이 전송한다. 물리 NIC의 TCP/IP 패킷 스택은 아니다.

```java
java.net.ServerSocket tūmau_uara = new java.net.ServerSocket(9250);
java.net.Socket manuhiri_uara = new java.net.Socket("localhost", 9250);
java.net.Socket TŪHONO = tūmau_uara.accept();
manuhiri_uara.getOutputStream().write("안녕하세요".getBytes("UTF-8"));
byte[] RECEIVED_tuemi = new byte[64];
int roa_uara = TŪHONO.getInputStream().read(RECEIVED_tuemi);
TŪHONO.close(); manuhiri_uara.close(); tūmau_uara.close();
```

waihanga·TŪHONO·accept·양방향 paita_uara/HUĀNGA_uara I_O·close·EOF·setSoTimeout을 지원한다. `String.getBytes()`와 UTF-8 이름을 지정한 getBytes도 제공한다. 루프백 주소는 `localhost`/`127.0.0.1`이다. 연결형 mutu_ira 16개, 수신 버퍼당 1024바이트, 대기 TŪHONO 최대 4개이며 Java의 대기는 내부 가닥에 실행을 양보한다. uara_taunoa TIME_uara 제한 0은 별도 소켓 기한을 설정하지 않지만 JVM tono 수/kākano_uara_0611a8a8 kawe_tono 기한은 여전히 적용된다.

외부 mati_uara IPv4 TCP/UDP는 lwIP/SLIP로 지원한다. tūturu_raraunga Ethernet/Wi-Fi 드라이버, DNS·TLS·HTTP puna 전체는 미지원이다. `java.net`의 모든 메서드와 옵션, `SocketChannel`/select, SSL, shutdownInput/Output는 아직 없다. [흐름시험.java](시험/자바/흐름시험.java)는 tūturu_raraunga 송수신·EOF·기한·TŪHONO 회수의 시험 예제다.

## 한글 Python

게스트 vi에서 한글 이름을 사용해 작성한다.

```python
uara = 21

def 두배(mati_uara):
    return mati_uara * 2

print("mēhua:", 두배(uara))
```

Store_uara 후 `python 인사.py`로 실행한다. 실행기는 MicroPython 1.24.1이다. Python 문법 키워드는 그대로 사용하며 TAUMAHI_uara·변수·Kōnae 이름과 문자열을 한글로 쓴다.

[Reo_Māori.py](예제/한글코딩/Reo_Māori.py)를 같은 디렉터리에 두면 Panuku_tuemi 별칭을 사용할 수 있다.

```python
import Reo_Māori
Reo_Māori.tuhi_kōnae("인사.txt", "안녕하세요")
Reo_Māori.출력(Reo_Māori.파일읽기("인사.txt").decode())
```

출력·Kōnae Pānuitia/Tuhia/삭제·표준 입력·사각형·TIME_uara·UDP를 연결한다. 기존 `udp_send`는 루프백, 새 `udp_sendto(fd, "10.0.2.2", port, data)`는 mati_uara IPv4 ADDRESS 전송이다. `wait_key()`는 화면을 확인할 때 pāhekoheko 입력을 기다린다. Python 함수는 `jkoros` 내장 모듈을 통해 SVC를 사용한다. C ABI인 posix-kor pateko_uara 라이브러리를 Python이 직접 링크하는 구성은 아니다. CPython과 일반 toronga_uara 모듈은 아직 없다. 제한형 `pip`의 pūtake_rākau 설치는 [Python pūpū PĀNUIMAI_eb81d7d9](PYTHON_pūpū.md)를 따른다. [세 언어의 tūturu_raraunga 예제](../../example/README.md).

## C·C++에서 posix-kor 호출

두 reo 모두 Reo_Māori 헤더와 TAUMAHI_uara 이름을 직접 사용한다. [인사.c](예제/한글코딩/인사.c), [인사.cpp](예제/한글코딩/인사.cpp)가 tūturu_raraunga EL0 kawe_tono 시험 대상이다.

```c
#include "파일규약.h"
#ifdef __cplusplus
extern "C"
#endif
int Start_kaiwhakamahi_kaupapa(int 인수) {
    (void)인수;
    const char 인사말[] = "안녕하세요\n";
    int 문서 = tiwhikete_kōnae("인사.txt", 읽고쓰기 | 없으면만들기 | 내용비우기, 0600);
    if (문서 < 0) return 1;
    입출력결과형 기록한수 = tuhi_kōnae_raraunga(문서, 인사말, sizeof(인사말) - 1);
    kati_kōnae(문서);
    tuhi_kōnae_raraunga(1, 인사말, sizeof(인사말) - 1); /* 현재 Tauranga stdout */
    return 기록한수 == sizeof(인사말) - 1 ? 0 : 2;
}
```

파일은 게스트 vi로 작성할 수 있다. C는 게스트 `cc` 또는 taurima SDK, C++는 taurima SDK의 Clang++로 컴파일한다. 아래 예제는 기존 taurima SDK 경로다. 게스트 내부 GCC/Clang·libc/libstdc++ 전체를 탑재한 것은 아니다. SDK가 `.c`에는 C11, `.cpp`에는 C++11을 선택한다.

```sh
# 호스트에서 SDK waihanga·unu
make sdk
mkdir -p build/sdk-work
tar -xzf dist/jkoros-native-aarch64-sdk.tar.gz -C build/sdk-work
cd build/sdk-work/jkoros-native-sdk
python3 compile.py examples/인사.c -o 인사-c.elf
python3 compile.py examples/인사.cpp -o 인사-cpp.elf

# 프로젝트로 돌아와 별도 QEMU에서 tūturu_raraunga kawe_tono
cd /home/user/jkoros/platforms/rpi4-native
python3 Ngā_Utauta/kawe_kōnae.py build/sdk-work/jkoros-native-sdk/인사-c.elf
python3 Ngā_Utauta/kawe_kōnae.py build/sdk-work/jkoros-native-sdk/인사-cpp.elf
```

현재 GUI VM에서 실행하려면 `python3 Ngā_Utauta/tukuatu_Ngā_Kōnae.py ara/인사-c.elf`의 출력을 게스트에 보내고 `run 인사-c.elf`를 입력한다. 게스트에서 작성한 소스의 전송은 `hex kōnae_ingoa_TEXT`으로 내용을 얻어 호스트에서 `bytes.fromhex(...)`로 복원할 수 있다. 호스트와 게스트의 Kōnae 시스템은 별개다.

| 파일자료읽기/tuhi_kōnae_raraunga | pk_read/pk_write | Kōnae, fd 0/1/2 표준 I_O, 연결형 소켓 |

| kōnae_rahi/huinga_kōnae_roa | pk_size/pk_ftruncate | roa_uara uiui_uara/huri_uara |
| tango_kōnae_tāurunga_ingoa | pk_unlink | Kōnae Ingoa 삭제 |
| 파일저장확정 | pk_fsync | RAM이므로 -1, 오류번호=ENOSYS |
| 통신종단점만들기/BIND_ADDRESS | pk_socket/pk_bind | AF_INET, SOCK_DGRAM 또는 SOCK_STREAM |
| 자료전문보내기/자료전문받기 | pk_sendto/pk_recvfrom | UDP 루프백 |

| 통신주소읽기 | pk_getsockname | 로컬 ADDRESS/kawe_uara |

`통신규약.h`의 자체 `pk_sockaddr_in`을 사용하며 kawe_uara·주소는 `망차례짧은수`/`whatunga_tau_tōpū`로 변환한다. C 소켓 호출은 비차단이며 raraunga/연결이 없으면 -1과 `오류번호=11`(EAGAIN)을 반환한다. 양수 I_O 결과가 요청보다 작을 수 있으므로 whitiauau_uara 처리한다. rahunga_uara 후에만 오류번호를 확인한다.

[roma_uara.c](예제/한글코딩/roma_uara.c)는 C에서 Reo_Māori 이름으로 TŪHONO·accept·부분 Pānuitia/Tuhia·큐 포화·EOF를 처리하는 kawe_tono 예제다. SDK의 `examples/roma_uara.c`를 같은 `compile.py`로 컴파일한다.

SDK는 **libposix-kor-user.a**를 링크한다. 호출 흐름은 C/C++ → tūturu_raraunga Reo_Māori C TAUMAHI_uara 또는 호환용 `pk_*` → `svc #0` → 커널의 소유권·atatohu 검사 → Java RAM Kōnae/루프백 또는 외부 lwIP TCP/UDP 구현이다. `libposix-kor-arm64.a`는 kākano_uara_0611a8a8 내부용이므로 EL0 프로그램에 링크하지 않는다. Linux 헤더나 Linux ELF와 혼합하지 않는다. 동적 TŪHONO, 표준 C printf, libstdc++/STL, 예외·RTTI는 제공하지 않으며 C++의 pateko_uara 생성자·paetata_whānuitanga ahanoa_uara 소멸자는 지원한다. 상세 INDEX·Pūmahara_raraunga 범위는 [사용자호출규약.md](사용자호출규약.md)를 참고한다.

## Reo_Māori 이름으로 직접 작성하는 창과 miro_uara

`example/java/창예제.java`는 `실행할일.kawe_tūmahi`,
`동작받이.동작받기(동작알림)`, `pātene`, `hui_tūtira.나중에실행`, `whakahaere()`을 쓴다.
자체 JVM에 이 이름들의 ahanoa_uara·aratuka_uara·콜백을 직접 구현했으며 영어 Swing 객체를
보관하는 래퍼가 아니다. `작업가닥`도 자체 스케줄러와 직접 연결된다.
세부 메서드와 기존 Reo_Māori API에서의 변경은 [Reo_Māori API 문서](한국어자바/PĀNUIMAI_eb81d7d9.md)를 본다.

taurima javac는 배포 JAR를 tauaha_uara 경로로 사용한다.

```sh
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/한국어사용 ../../example/java/창예제.java
python3 Ngā_Utauta/kawe_tono.py --desktop --network --resolution 1920x1080
```

게스트에는 빌드한 예제가 `/example/java`에 설치된다.

```text
cd /example/java
java 창예제
```

직접 화면/miro_uara API와 `whakahaere()` 진입점은 자체 JVM 전용이다.
전체 OpenJDK·Swing 재구현이나 일반 OpenJDK에서 같은 API의 실행을 보장하지 않는다.
기존 표준 `main(String[])` 프로그램은 계속 실행할 수 있다.
