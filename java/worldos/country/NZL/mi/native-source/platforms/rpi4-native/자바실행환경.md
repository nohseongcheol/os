# 자체 ARM64 JVM 0.4와 Reo_Māori puna

Reo_Māori 통신·예외 사용법은 [Reo_Māori Java API](한국어자바/PĀNUIMAI_eb81d7d9.md), TAUMAHI_uara·변수·Kōnae 이름의 변경과 어원 근거는 [명명 PĀNUIMAI_eb81d7d9](명명/PĀNUIMAI_eb81d7d9.md)를 참고한다.

JAR kawe_tono, 외부 IPv4 TCP/UDP, 별도 pateko_uara 부분집합 `jaot`와 게스트 C 컴파일은 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)에 설명한다. 아래 ahanoa_uara·Thread·Swing은 JVM 경로의 기능이며 AOT Tautoko_uara 범위와 같지 않다.

이 구현은 **Linux 없이 부팅한 Java AOT 커널의 EL0에서 kawe_tono**한다. JDK/JRE의 거의 모든 기능을 제공하는 단계는 아직 아니다. HotSpot·OpenJDK tauaha_uara puna 전체를 이식하거나 Java SE 인증/TCK를 통과한 구현도 아니다. 이번 확장은 단일 tauaha_uara·pateko_uara aratuka_uara 중심이던 실행기를 ahanoa_uara·puna kawe_tono 기반으로 넓힌 것이다.

## 실행과 hanga_pūtake

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
# 자체 kākano_uara_0611a8a8 안에서 pūtake_rākau hanga_pūtake → class kawe_tono, Reo_Māori API 호출
python3 Ngā_Utauta/kawe_kōnae.py 시험/자바/한글소스.java

# ahanoa_uara·예외 등은 taurima JDK로 Java 8 class를 만든 후 자체 커널에서 kawe_tono
mkdir -p build/my-java
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/my-java 시험/자바/한글시험.java
python3 Ngā_Utauta/kawe_kōnae.py build/my-java/한글시험.class

# 의존 class 파일은 --include로 함께 whakawhiti_uara_630ba093
javac --release 8 -encoding UTF-8 -d build/my-java 시험/자바/객체시험.java
python3 Ngā_Utauta/kawe_kōnae.py build/my-java/객체시험.class \
  --include build/my-java/Papamuri_uara.class --include build/my-java/peka_uara.class \
  --include build/my-java/계산가능.class

make test-jvm
```

`--include DIR`는 그 디렉터리의 class 파일을 재귀적으로 읽어 `패키지.tauaha_uara.class`라는 RAM Kōnae 이름으로 전송한다. 주 클래스도 패키지가 있다면 `--class-name 패키지.tauaha_uara`를 지정한다. 셸에서는 해당 이름으로 업로드하고 `java 패키지.tauaha_uara`로 실행한다. JVM 0.4는 Main-Class가 있는 16 KiB 이하 JAR도 `java -jar Kōnae.jar`로 실행한다. JAR 모드에서는 JAR 내부 클래스와 내장 Reo_Māori 클래스만 찾는다. 배포 Reo_Māori puna JAR는 taurima javac의 classpath로 사용하며, 같은 클래스가 kaiwhakamahi JVM ELF에도 Pānuitia 전용 자료로 포함된다. 일반 class 모드에서는 사용자가 같은 이름으로 올린 RAM class를 먼저 읽는다.

게스트 `javac`는 여전히 pateko_uara aratuka_uara, int/boolean/char/String, here·whitiauau_uara, aho_uara 결합, 일부 Kōnae 스트림 등의 **자체 부분집합 컴파일러**다. ahanoa_uara 선언·상속·try/catch·Thread 사용 소스를 게스트 javac가 모두 컴파일하는 것은 아니다. 위 기능은 `javac --release 8`로 만든 class를 자체 JVM에서 실행한다. Reo_Māori API 중 출력·문자 스칼라 TAUMAHI_uara·Kōnae Pānuitia/쓰기는 게스트 컴파일러에도 연결했다. 다음처럼 전체 이름으로 호출한다.

```java
public class 인사 {
    public static void main(String[] 인수) throws Exception {
        Reo_Māori.자체.출력.tuhi_hononga("안녕하세요😀");
        Reo_Māori.자체.출력.수쓰기(Reo_Māori.자체.문자.waehere_pūāhua_COUNT("한글😀"));
        Reo_Māori.자체.Kōnae.Tuhia("인사.txt", "한글 Kōnae😀");
        Reo_Māori.자체.출력.tuhi_hononga(Reo_Māori.자체.Kōnae.Pānuitia("인사.txt"));
    }
}
```

## Reo_Māori API

독립 패키지 **`Reo_Māori.자체`**를 사용한다. Linux판 `Reo_Māori.자바`가 요구하는 NIO/Swing/HTTP API를 자체 커널에서 실행할 수 있다고 혼동하지 않도록 패키지를 나눴다. 이 라이브러리는 tauaha_uara Ingoa·aratuka_uara·인수·āpure_uara·Kōnae 이름에 한국어를 사용한다. 표준 Java tauaha_uara 이름은 호환성을 위해 보존한다.

## kawe_tono 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(Reo_Māori tauaha_uara 포함), class당 16 KiB·taimau_uara 풀 511항목, 전체 aratuka_uara/āpure_uara 각각 512개. aratuka_uara CODE_uara 8 KiB, paetata_whānuitanga 변수·피연산자 스택 각각 128슬롯, 인수 최대 16개(this 포함).
- VM 가닥은 main 포함 **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 kawe_tono 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- ahanoa_uara 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 tūturu_raraunga 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 Kōnae·대형 aho_uara·객체가 이 제한을 넘을 수 있다.
- 실행은 50만 바이트코드 tono 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 입력 대기는 기한을 갱신하고 matapihi SWITCH_MODE 시 중단·재개한다. 일반 tūmau_uara·계산의 무제한 실행은 아직 없다. 미지원 tono·rauemi_uara 부족은 명시적인 오류로 종료한다.
- RAM Kōnae 최대 64개, 파일당 16384바이트, ara UTF-8 63바이트. RAM 디렉터리와 hoa_uara/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 Reo_Māori class는 RAM Kōnae 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 현재 경로에서 pūtake_rākau·tauaha_uara·raraunga 파일을 읽는다.
- UDP는 Java 루프백 및 lwIP/SLIP를 통한 외부 IPv4를 제공한다. tūturu_raraunga GENET/Wi-Fi/DNS/TLS/HTTP 전체는 없다. 전문 512바이트, 소켓 8개, 소켓당 큐 4개. receive는 VM 가닥을 양보하며 대기하고 setSoTimeout을 적용하지만 전체 kawe_tono 기한은 여전히 적용된다.
- long/float/double, invokedynamic/람다, enum/annotation, 다차원 HUĀNGA_uara, 완전한 HUĀNGA_uara 공변성·인터페이스 apa_uara 검사, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/whakamuna_raraunga/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. Swing의 별도 Tautoko_uara 부분집합은 아래 및 개발 매뉴얼을 참고한다. tauaha_uara Kōnae 전체 검증기·uru_tāurunga mana_uru_uara/보호된 멤버 검사는 아직 완전하지 않다. 손상된 입력은 EL0 pare_uara 경계 내에서 종료되도록 한다.

전체 OpenJDK를 목표로 하려면 다음은 별도의 주요 구현 단계다: 완전한 JVM uara/whakamana/tauaha_uara 로더와 예외 모델 → 영속 VFS·mmap·Karaka·원자 mahi_uara·tūturu_raraunga 스레드/tukutahi ABI → OpenJDK java.base 및 native puna 이식 → pūkoro_uara 네트워크·TCP/IP → matapihi 시스템/momotuhi_uara/입력기·java.desktop → Java SE 호환성 시험. 현재 자체 JVM의 일부 메서드를 더하는 것으로 이 작업이 완료되지는 않는다.

## whakamana

`Ngā_Utauta/자바가상기계시험.py`는 같은 Java 8 class 파일의 출력을 taurima OpenJDK `-Xverify:all`과 QEMU raspi4b 자체 커널에서 비교한다. ahanoa_uara/상속/인터페이스·switch·HUĀNGA_uara, 예외/finally, 컬렉션/GC, Thread/잠금, Reo_Māori UTF-8/Kōnae/컬렉션, tūturu_raraunga UDP 루프백/TIME_uara 초과, 게스트 한글 pūtake_rākau hanga_pūtake, HUĀNGA_uara TYPE_uara/tārua_uara/Kōnae 경계·한글 패키지의 9개 비교 시험과 잘못된 class 버전/잘린 Kōnae 거부 시험을 실행한다. ## JVM 0.3: 네트워크와 GUI toronga_uara

`Socket`/`ServerSocket` waihanga·TŪHONO·accept·양방향 InputStream/OutputStream·close·EOF·TIME_uara 제한과 UTF-8 `String.getBytes`를 추가했다. JVM 0.4에서는 외부 mati_uara IPv4 TCP도 lwIP/SLIP에 연결했다. 연결형 mutu_ira 16개, Java 루프백 버퍼 1024바이트, 외부 TCP 버퍼 4096바이트다. DNS·TLS는 없다.

`JFrame`, `JPanel`, `JLabel`, `JButton`, `JTextField`, `ActionListener`, `ActionEvent`, `SwingUtilities.invokeLater`의 문서화한 부분집합을 네이티브 GUI에 연결했다. `setLayout(null)`과 명시적 좌표를 사용한다. 전체 OpenJDK Swing 또는 Java SE 호환 구현은 아니다. pāhekoheko 이벤트 대기는 kawe_tono 기한을 갱신하고 Tauranga SWITCH_MODE 시 프로세스 상태를 Store_uara·복원한다. 이벤트 콜백 자체는 기존 바이트코드/CPU 기한을 따른다.

Reo_Māori `matapihi`, `taputapu`, `연결통신` 클래스를 배포 JAR와 자체 JVM 내장 자원에 추가했다. 상세 aratuka_uara·제한·pūtake_rākau·업로드 방법: [한글 개발 매뉴얼](개발안내.md).

## Reo_Māori 객체의 직접 kawe_tono

`matapihi`, `tapanga`, `āpure_kuputuhi`, `pātene`, `hui_tūtira`, `동작알림`, `작업가닥`은
표준 GUI/Thread 객체를 보관하는 래퍼가 아니다. 자체 JVM의 ahanoa_uara waihanga,
hōputu_uara 검사, 화면 호출, hui 큐, miro_uara 스케줄러에 Reo_Māori 계약을 직접 구현했다.
표준 `javax.swing`·`Thread` 코드의 kawe_tono 경로도 유지한다.
Reo_Māori 단추와 표준 JButton은 서로 다른 형식이며, 해당 instanceof 검사도 검증한다.

자체 실행기의 Reo_Māori 진입점은 `public static void whakahaere()`이다.
표준 `main(String[])`도 지원하며 둘 다 있으면 Reo_Māori 진입점을 우선한다.
명령행 인수는 `실행인수.tuemi_COUNT()`와 `실행인수.Ngā_kupu(순번)`으로 읽는다.
`example/java`의 다섯 예제는 이 규약을 사용한다. pateko_uara Kōnae 예제는 게스트
javac로도 컴파일하며, GUI/miro_uara 소스는 taurima `javac --release 8`을 사용한다.
직접 GUI/miro_uara API는 자체 JVM 전용이다. 기존 OpenJDK 비교 시험과 별도로
Reo_Māori 가닥의 kawe_tono·대기·중복 whakahaere 거부, GUI hui 출처·INDEX·콜백을 검사한다.
전체 JDK 번역이나 모든 API의 jaot 지원을 뜻하지 않는다.

aratuka_uara 이름은 바이트코드에서도 유지된다. 이름과 참조를 같이 수정하면
Reo_Māori 클래스도 실행되지만, aho_uara 리터럴·표준 puna 재정의·native
TŪHONO·진입점은 각각 컴파일러와 실행기의 계약을 맞춰야 한다.

## Tauranga 부분 tāmata

nuku_uara·rahi 변경은 새 matapihi 영역과 이전 자리에서 드러난 띠만 합성한다.
1920×32 pika(240 KiB)의 임시 그림에서 배경·겹친 matapihi·pūāhua_uara·GUI를 먼저
완성하고, 현재 whakaatu_uara 메모리와 비교하여 달라진 화소만 기록한다.
32줄보다 큰 영역은 여러 띠로 처리하므로 전체 프레임을 원자적으로
교체하거나 수직 동기에 맞추는 방식은 아니다. 전체 배경을 먼저 지우는
중간 화면은 표시하지 않는다. 좌표가 같으면 다시 그리지 않는다.

`make test-redraw`는 tūturu_raraunga C 그리기 코드를 호스트의 Pūmahara_raraunga 화면에 연결해
nuku_uara 80회·rahi huri_uara 40회·겹친 matapihi 4개를 전체 합성 결과와 pika 단위로 대조한다.
영역 밖 kaiwhakamahi tātuhi_uara, 동일 pika 무기록, atatohu 밑그림, tūturu_raraunga 화면 hononga 간격을
검사한다. 이 시험의 시간은 taurima CPU 측정이며 Pi 4/QEMU 속도로 해석하지 않는다.
`make test-resize`는 QEMU/VNC의 640×480 및 1920×1080에서 왼쪽 모서리 tō_uara,
한글 입력·vi 미저장 Ihirangi_uara·독립 matapihi 크기를 검사한다.
