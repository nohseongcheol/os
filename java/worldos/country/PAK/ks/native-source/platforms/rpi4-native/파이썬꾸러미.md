# 자체 커널의 Python 꾸러미 설치

자체 ARM64 커널의 `python`은 **MicroPython 1.24.1 정수 빌드**다.
`pip`와 `python -m pip`는 이 환경을 위한 제한형 소스 설치 명령이다.
PyPA pip 전체나 CPython을 이식한 것은 아니다.

호스트에서 실행한다.

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
python3 도구/실행.py --desktop --network --pip
```

게스트 셸에서 설치하고 사용한다.

```text
pip install micropython-bisect==3.3.3
pip list
python -c 'from bisect import insort as 순서대로넣기; 값=[1,5]; 순서대로넣기(값,3); print(값)'
python -m pip list
pip uninstall micropython-bisect
```

정상 실행 결과는 `[1, 3, 5]`다. 예시 배포 파일은
[PyPI의 micropython-bisect 3.3.3](https://pypi.org/project/micropython-bisect/3.3.3/)이며
SHA-256은 `b8d09d0bb4b2add706078dfa3f306e22fad1f4b5340b87d13f2c852507d720c8`이다.
`bisect`는 설치 전 내장되어 있지 않다. 내려받은 `.py`를 자체 커널의 EL0
MicroPython이 import하여 실행한다.

## 설치 경로와 역할

호스트의 [꾸러미중계.py](도구/꾸러미중계.py)는 PyPI HTTPS 다운로드, 인증서 확인,
배포 फ़ाइल SHA-256 검증과 압축 해제를 맡는다. 호스트에서 `setup.py`나 내려받은
Python 코드를 실행하지 않는다. 호스트 pip 설치도 필요 없다.
중계는 `127.0.0.1:8027`에만 열리며 게스트는 QEMU NAT의 `10.0.2.2:8027`로 연결한다.
게스트 자체에 DNS·TLS·PyPI 압축 해제 기능을 추가했다는 뜻은 아니다.

게스트의 [꾸러미.py](파이썬연결/라이브러리/꾸러미.py)는 TCP로 받은 파일의 SHA-256과
경로·नाप·문법을 검사한 뒤 `/lib`에 설치하고 `/lib/.pip.json`에 목록을 기록한다.
`/lib`와 실행 스크립트 폴더를 모듈 검색 경로에 추가했으므로 작업 폴더가 달라도
설치한 모듈을 import할 수 있다. 패키지 폴더와 상대 import도 지원한다.

설치 도중 공간 부족 등 오류가 발생하면 새 파일과 폴더를 지우고 기존 목록을
복원한다. 이미 있는 사용자 파일을 덮어쓰지 않는다. 동일 버전 재설치 요청은
फ़ाइल 지문을 확인하고 유지한다. 다른 버전은 제거 후 설치한다. 제거 시 사용자가
수정한 파일이 발견되면 보존하고 오류를 알린다. 빈 패키지 폴더는 남을 수 있다.

**`/lib`도 RAM 파일이다. 재부팅하면 설치한 패키지가 사라진다.**
호스트 `build/pip-cache`에는 배포 파일과 출처·지문이 남으므로 다음 부팅에서 다시
설치할 수 있다. 버전을 지정하면 같은 배포 파일을 재사용한다.

```sh
# 호스트: 인터넷이 있을 때 배포 파일만 준비
python3 도구/꾸러미중계.py --fetch micropython-bisect==3.3.3
# 다음 실행: PyPI 연결 없이 캐시 사용
python3 도구/실행.py --network --pip --pip-offline
```

다른 포트는 호스트 `--pip-port 8028`, 게스트
`pip install micropython-bisect==3.3.3 --port 8028`로 맞춘다.
호스트 중계는 `python3 도구/꾸러미중계.py --port 8027`로 별도 실행할 수도 있다.
QEMU를 종료하거나 중계 실행을 끝내면 이 서비스도 닫힌다.

## 지원 범위

- 의존성 없는 순수 Python wheel(`*-none-any.whl`, `Root-Is-Purelib: true`).
- 구형 `micropython-*` 소스 배포형의 `.py`와 `PKG-INFO`.
- 꾸러미당 소스 16개, 합계 64 KiB, 파일당 16 KiB, 절대 경로 UTF-8 63바이트 이하.
  전체 RAM फ़ाइल 64개·폴더 16개의 남은 공간과 Python 힙 256 KiB 한도도 적용된다.
- `install`, `list`, `uninstall`, `--help`, `--version`.
- SHA-256, JSON, 메모리 `io.StringIO`/`BytesIO`를 실행기에 추가했다.
  일반 फ़ाइल 객체 `open()`은 미지원이며 `한국어.파일읽기/파일쓰기` 또는
  `jkoros.read/write`를 사용한다.

C 확장·플랫폼 전용 wheel, 일반 sdist 빌드, 자동 의존성 해결, extras, VCS/임의 URL,
NumPy 같은 CPython 전용 패키지는 지원하지 않는다. 순수 Python 패키지도
MicroPython의 문법·표준 모듈·정수 전용 환경과 맞아야 실제로 실행할 수 있다.
설치 시 문법을 검사하지만 모든 실행 경로의 호환성을 증명하지는 않는다.
실제 Raspberry Pi 4의 LAN을 통한 설치는 검증하지 않았으며 현재 중계는 QEMU용이다.

MicroPython 자체의 패키지 체계와 CPython pip의 차이는
[MicroPython 패키지 문서](https://docs.micropython.org/en/v1.24.0/reference/packages.html),
wheel 형식은 [PyPA 배포 형식 규격](https://packaging.python.org/en/latest/specifications/binary-distribution-format/)을 참고한다.

```sh
make test-pip
```

검증 기록은 `build/verification/pip/report.json`과 `serial.log`에 저장한다.
실제 PyPI 꾸러미 시험과 별도로 시험용 wheel로 패키지 폴더, 구문 오류,
공간 부족 되돌림을 확인한다.
