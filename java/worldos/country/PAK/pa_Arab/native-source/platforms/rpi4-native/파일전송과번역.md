# 자체 ARM64 کرنل_قدر: FTP, C, JAR와 AOT نفاذ_کرو_حکم

대상은 **Linux를 적재하지 않는 Raspberry Pi 4용 Java AOT کرنل_قدر**이다. CPU·آلہ_قدر 경계는 C/어셈블리, فائل 체계와 셸은 Java이며, 이번 TCP/IP 스택은 C로 작성된 lwIP 2.2.0을 이식했다. 게스트 TinyCC와 `jaot`도 EL0에서 실행한다. 호스트에 컴파일을 요청하거나 مہمان_b78e430d JVM으로 대신 실행하지 않는다.

## 먼저 알아둘 مدد_قدر 경계

| 요청 | 이번 구현 | 남은 تراشہ |
|---|---|---|
| JAR를 نفاذ_کرو_حکم 파일처럼 نفاذ_کرو_حکم | `java -jar فائل.jar`, `./فائل.jar 인수`; Main-Class와 ذخیرہ_کرو_قدر/DEFLATE ZIP, CRC 검사 | 전체 Java SE, 임의의 모든 JAR 호환성 |
| 게스트 AOT | `jaot فائل.class -o فائل.elf`, `jaot فائل.jar -o فائل.elf`; اصلی_کوائف ARM64 기계어 생성 | آبجیکٹ_قدر·예외·Thread·Swing·Socket의 AOT 변환, 여러 애플리케이션 درجہ_قدر جڑو |
| C تیار_کرو_ماخذ | 게스트 `cc`/`tcc`, TinyCC C 전처리기·ARM64 생성기·링커; 한국어 식별자와 posix-kor | 전체 libc, 일반 Linux نفاذ_کرو_حکم فائل, 게스트 C++ 컴파일러 |
| 업로드한 ELF نفاذ_کرو_حکم | ELF64/AArch64 헤더 검사, 확장자 없는 `./فائل`; 자체 ABI 및 명시적인 제한형 Linux ABI | 일반 Linux 바이너리 호환, 동적 링커, 공유 لائبریری |
| 외부 TCP/UDP | 게스트 lwIP IPv4 스택, POSIX 소켓과 JVM의 عدد_قدر IPv4 پتا | GENET/Wi-Fi 드라이버, DHCP·DNS·TLS, 실물 보드 네트워크 시험 |
| FTP | 게스트 서비스, 패시브 منتقلی_قدر, UTF-8 ناں, STOR/RETR/SIZE/LIST/NLST/MLSD/DELE | TLS·사용자별 اجازت_قدر·하위 디렉터리·영속 ذخیرہ_کرو_قدر |
| 한글 Java | 기존 `한국어.자체` 클래스와 외부 پتا UDP 오버로드 | 전체 JDK의 일대일 한국어 대응 API |

JVM은 درجہ_قدر 버전 45…52의 문서화한 부분집합이다. `java`는 바이트코드 실행기이고, `jaot`가 별도의 네이티브 نفاذ_کرو_حکم 파일을 만든다. **JAR محفوظہ_قدر 해제나 JVM을 함께 묶는 것을 AOT라고 표시하지 않는다.** 지원하지 않는 바이트코드/API는 `jaot`가 진단하고 출력을 만들지 않는다. 기존 출력 ELF도 تیار_کرو_ماخذ ناکامی_قدر 때 보존한다.

Android의 Dalvik/ART는 일반 JVM درجہ_قدر/JAR가 아닌 **DEX**를 실행한다. ART의 AOT에는 GC, درجہ_قدر 로딩, JNI 등 نفاذ_کرو_حکم 기반도 필요하다. 따라서 ART처럼 기계어로 바꾸는 기능만으로 임의의 OpenJDK JAR 및 Swing이 자동 호환되지는 않는다. [Android 공식 런타임 설명](https://source.android.com/docs/core/runtime)

## 한국어 Java를 게스트에서 컴파일하고 AOT نفاذ_کرو_حکم

게스트 `vi 빛.java`로 다음 소스를 작성한다.

```java
public class 빛 {
    public static void main(String[] 인수) throws Exception {
        int 합 = 0;
        int 수 = 1;
        while (수 <= 10) {
            합 = 합 + 수;
            수 = 수 + 1;
        }
        한국어.자체.출력.수쓰기(합);
        한국어.자체.فائل.لکھو("aot.txt", "한글 AOT فائل 😀");
        한국어.자체.출력.لکھو_لائن(한국어.자체.فائل.읽기("aot.txt"));
    }
}
```

```text
javac 빛.java
java 빛
jaot 빛.class -o 빛.elf
run 빛.elf
```

`jaot`은 클래스의 바이트코드를 C로 변환하고, **게스트 TinyCC**가 ARM64 명령어를 생성·연결한다. نفاذ_کرو_حکم 때 JVM 인터프리터를 호출하지 않는다. JAR의 Main-Class가 같은 مدد_قدر 범위이면 다음도 가능하다.

```text
jaot 빛.jar -o 빛.elf
run 빛.elf
```

AOT 지원은 한 애플리케이션 클래스의 ساقط_قدر طریقہ_قدر/قطعہ_قدر, int 계열, عدد 배열과 حوالہ, 인수 ایرے_قدر, حالت·شاخ·تکرار_قدر, سٹرنگ_قدر 리터럴, `System.out.print/println`의 int/String, 한국어 출력·فائل 읽기/쓰기로 제한된다. درجہ_قدر/طریقہ_قدر 수와 스택 등에도 고정 상한이 있다. Java 예외 عمل_قدر_داخلہ, آبجیکٹ_قدر 생성, 가상 طریقہ_قدر 일반, switch/wide, long/float/double, invokedynamic, سٹرنگ_قدر 결합용 StringBuilder, 일반 JDK·Socket·Thread·Swing은 이 AOT 백엔드에서 미지원이다. 내장 NUL/고립된 서로게이트 문자열도 거부한다. 잘못된 ایرے_قدر پہنچ_داخلہ/0으로 나누기 등은 네이티브 런타임 오류로 종료하며 Java 예외 객체로 전달하지 않는다.

입력 클래스뿐 아니라 **생성된 ELF도 16 KiB 이하**여야 한다. 기계어 확장과 ELF 페이지 سیدھا_قدر 때문에 짧은 클래스도 이 한도를 넘을 수 있으며, 이 경우 오류를 내고 기존 출력을 보존한다.

게스트 `javac`도 부분집합이다. 일반적인 آبجیکٹ_قدر·Thread·Swing 소스는 호스트에서 `javac --release 8`로 컴파일하고, **기존 JVM의 مدد_قدر تراشہ 안에서** `java`/`java -jar`로 실행한다. 정확한 API는 [JVM 매뉴얼](자바실행환경.md)과 [한글 개발 매뉴얼](개발안내.md)을 참고한다.

JAR는 하나의 애플리케이션 درجہ_قدر 경로다. 내부 ناں `گٹھ/ایپ_f5044b9b.class`와 점으로 구분한 Main-Class를 지원한다. 내부 클래스는 파일로 풀어 VFS 슬롯을 소비하지 않는다. 내장 한국어 클래스를 추가로 찾지만 현재 작업 폴더의 다른 클래스는 자동 혼합하지 않는다. ZIP64·ضابطہ_کشائی_کوائف ZIP·manifest Class-Path·서명 검증은 지원하지 않는다. JAR 하나가 16 KiB 이하이어도 클래스당/적재 수/VM 힙 제한은 그대로 적용된다.

## C에서 한국어 POSIX 호출

게스트에서 `vi 인사.c`로 작성하거나 FTP로 소스를 업로드한다.

```c
#include <파일규약.h>

int main(void) {
    const char 인사말[] = "자체 ARM64 C에서 한글 POSIX 호출\n";
    int 문서 = بنڑاؤ_فائل("인사.txt", پڑھو_لکھو | 없으면만들기 | 내용비우기, 0600);
    if (문서 < 0) return 1;
    입출력결과형 기록한수 = لکھو_فائل_کوائف(문서, 인사말, sizeof(인사말) - 1);
    بند_کرو_فائل(문서);
    لکھو_فائل_کوائف(1, 인사말, sizeof(인사말) - 1);
    return 기록한수 == sizeof(인사말) - 1 ? 0 : 2;

```

```text

run 인사.elf
cat 인사.txt
```

TinyCC의 표준 C داخلہ_مقام `main`을 사용한다. 기존 مہمان_b78e430d C/C++ SDK의 `مکھ_صارف_ایپ(int)` 진입점과 구분한다. 포함 فائل·چلاؤ آبجیکٹ_قدر·`libposix-kor-user.a`는 컴파일러 내부의 읽기 전용 SDK에 들어 있다. C 전처리기/구조체/فعل_قدر/재귀/پوائنٹر/부동소수점 생성 등을 사용하되 **일반 libc/libstdc++를 제공한다는 뜻은 아니다**. 제공하지 않는 함수는 جڑو 오류가 난다. 컴파일러 자체의 문자/عدد_قدر 변환 지원도 완전한 libc 대체품이 아니다.

`بنڑاؤ_فائل` 등은 별도의 모의 호출이 아닌 기존 `pk_open` 등의 한국어 매크로이며, ELF의 SVC를 통해 اصلی_کوائف Java فائل 체계에 도달한다. فائل/소켓 호출 목록은 [صارف ABI](사용자호출규약.md)에 있다. C/C++ مہمان_b78e430d SDK نفاذ_کرو_حکم 파일도 FTP로 업로드 후 `run` 또는 `./فائل`로 실행하며 확장자는 필요 없다. Linux ARM64 ساقط_قدر ELF에는 별도의 제한된 호환 راہ `run --linux فائل`을 추가했다. [ELF·Linux ABI 매뉴얼](실행파일규약.md)에 정확한 وضع_قدر·시스템 호출·پتا 제한을 정리했다.

## 한국어 네트워크·작업·화면 API

| درجہ_قدر | 호출 예 | نفاذ_کرو_حکم راہ |
|---|---|---|
| `출력` | `لکھو_لائن("안녕")`, `수쓰기(42)` | JVM 및 제한형 AOT |
| `فائل` | `لکھو("문서.txt", "اجزاء_قدر")`, `읽기("문서.txt")` | JVM 및 제한형 AOT |
| `통신` | `بنڑاؤ(0)`, `بھیجو(종단, "10.0.2.2", 9000, "한글")`, `받기(종단)` | JVM의 UDP |
| `연결통신` | `جڑو("10.0.2.2", 9000)`, `듣기(9000)`, `받기(سرور_قدر)` | JVM의 Socket/ServerSocket |
| `작업` | `چلاؤ(Runnable)`, `기다리기(Thread)`, `معطل_کیتا_گیا_ٹاسک()` | JVM의 협력식 لڑی_قدر |
| `کھڑکی`, `ویجٹ` | کھڑکی·버튼·کریکٹر_قدر·متن_قطعہ·واقعہ جڑو | JVM의 Swing 부분집합 |

명명에서는 표준 영어 API를 보존하고 한국어 호출 계층을 추가한다. `통신(通信)`, `جڑو(連結)`, `출력(出力)`은 기존 단어의 뜻을 사용한다. `작업 لڑی_قدر`은 한 نفاذ_کرو_حکم 흐름을 가닥에 빗댄 기술 표현, `دہانہ_قدر`는 포트의 접점을 설명하는 표현이다. 새 기술 결합어를 고대에 이미 존재한 용어처럼 설명하지 않는다. 전체 JDK의 번역을 완료했다고 표시하지 않는다.

외부 주소는 عدد_قدر IPv4이며 QEMU 호스트는 `10.0.2.2`, 게스트는 `10.0.2.15`다. UDP 전문은 512바이트까지다. 소켓은 비차단 자체 ABI이며 JVM이 제한된 대기/재시도를 제공한다. TCP connect 대기는 최대 1초, صارف ایپ_f5044b9b 전체에는 기존 약 2초 CPU 기한이 적용된다. 일반적인 장기 نفاذ_کرو_حکم صارف 서버와 pthread는 아직 없다. FTP는 صارف ایپ_f5044b9b 기한과 별개인 کرنل_قدر 서비스다.

게스트의 صارف TCP/UDP 서버로 들어오는 연결은 NAT 포트를 추가한다. 예를 들어 `python3 اوزار/نفاذ_کرو_حکم.py --network --forward tcp:9300:9300 --forward udp:9301:9301`로 실행하면 호스트의 localhost 9300/TCP·9301/UDP를 게스트의 같은 포트로 전달한다. FTP의 طےشدہ_قدر کنٹرول_قدر/데이터 포트와 겹치면 نفاذ_کرو_حکم 전에 거부한다.

`build/verification/ftp/report.json`은 اصلی_کوائف FTP منتقلی_قدر, 한글 فائل, سائز 초과 보존, محفوظہ_قدر JAR نفاذ_کرو_حکم, 게스트 C تیار_کرو_ماخذ/ELF 재업로드, 외부 Java TCP/UDP, 게스트 javac/AOT 실행을 기록한다. `serial.log`에서 게스트 명령과 결과를 확인할 수 있다. 보고서의 کرنل_قدر SHA-256과 배포 이미지의 커널을 비교한다.

빌드는 기존 JDK/Clang/AArch64 binutils와 함께 `../rpi4/build/rootfs`의 ARM64 SDK 선언 헤더와 libgcc 산술 보조 함수를 사용한다(`make rpi-prepare`). **musl libc, Linux کرنل_قدر, 동적 로더를 게스트에 링크하지 않는다.** TinyCC/lwIP/uzlib 원본과 라이선스·버전 정보는 `vendor/`, 이식 코드는 `ccompiler/`, `network/`, `صارف/گٹھ.c`에 있다.

전체 JDK/AOT JVM으로 확장하려면 타입 تریخ_دے_مطابق_کرو·آبجیکٹ_قدر/예외/GC·동적 로딩·JNI, 영속 فائل آپریٹنگ_سسٹم_قدر·mmap/TLS/시그널·스레드 ABI, OpenJDK native لائبریری, GUI peer/폰트/입력기, GENET 및 실물 آلہ_قدر 검증이 더 필요하다. 이 문서의 نفاذ_کرو_حکم 시험은 그 전체 이식을 대신하지 않는다.
