# Java 네이티브 編譯器

OpenJDK 內建 소스를 빌드하는 **`--target openjdk-build`**와 內建 內核值 ABI 檢查項 도구를 추가했다.
이는 공식 javac/C/C++ 도구를 연결하는 별도 경로다. [構建系統 방법·實際資料 有效性校驗·內核值 移植 裁剪](OpenJDK原始碼建置與核心移植.md)를 참고한다.

x86 직접 변환과 ARM64 C 生成 후단은 構建全部 [提前所屬時間編譯器.java](Java工具/提前所屬時間編譯器.java)로 구현한다. `sh 提前所屬時間.sh`로 직접 실행하며, [提前所屬時間編譯器.py](提前所屬時間編譯器.py)와 `編譯器.py`는 上一個項目 命令·API 및 OpenJDK 도구를 위한 호환 진입점이다. 內建 Pi4 후단은 freestanding C를 거쳐 AArch64로 만든다. [arm64.py](arm64.py)는 上一個項目 경로와 Python 호출을 위한 호환 진입점이다. 函數·變量值·生成 C 이름의 뜻과 예외는 [中文 命名 指南](../platforms/rpi4-native/命名/指南.md)를 참고한다. [ARM64 構建系統·支持值 裁剪](../platforms/rpi4-native/指南.md)에 執行命令 조건이 있다. 전체 OpenJDK나 일반 類別值 실행기는 아니다.

執行命令 시 JVM이 所需條件值 없는 x86 32비트 ELF를 만든다. JDK 11 이상으로 실행하는 Java 內建 AOT 후단이며, Java 전체를 새로 구현한 컴파일러는 아니다. Java 문법·存取條目 控制值·類型值 검사는 JDK의 `javac`에 맡기고, Java 8 類別值 파일을 읽어 각 바이트코드를 x86 명령으로 직접 변환한다. C 코드로 우회하거나 字節碼 해석기를 커널에 넣지 않는다.

```text
Java 原始碼 → javac의 문법·類型值 檢查項 → 臨時值 .class
          → 內建 x86 변환기 → GNU as/ld → 네이티브 ELF32
```

## 준비와 執行命令

構建系統 宿主: Linux, Python 3.6 이상, JDK 11 이상(`javac --release 8`), GNU binutils(`as`, `ld`), Make. 當前項目 환경의 OpenJDK 11, Python 3.6, binutils 2.30으로 검증했다. 外部值 Python 패키지와 네트워크 다운로드는 사용하지 않는다.

```sh
cd /home/user/jkoros/compiler
make
./build/計算結果
echo $?                  # 0이면 範例 測試 成功值

python3 編譯器.py --target linux --entry 計算結果.運行 \
    -o build/計算結果 範例/計算結果.java

make test
```

`linux` 대상은 Linux의 32비트 執行命令 호환 기능이 필요하다. `int 0x80`을 차단하는 샌드박스에서는 `Bad system call`이 발생할 數 있다. 是否常規 Linux 宿主 또는 해당 실행을 허용한 測試 환경에서 실행한다. 시험의 비정상 종료를 통과로 처리하지 않는다.

진입점은 `static int 運行()` 또는 `static void 運行()`처럼 인수가 없어야 한다. `--entry 패키지.類別值.函數`로 선택한다. `int` 반환값은 Linux 프로세스 退出程式 코드가 되며 셸에는 하위 8비트가 보인다. 일반 `main(String[] args)` 執行命令 환경이나 표준 輸入輸出 라이브러리는 제공하지 않는다.

`--target kernel`은 啓動 코드와 연결할 재배치 ELF 오브젝트를 생성한다.

```sh
cd /home/user/jkoros
python3 compiler/編譯器.py --target kernel --entry 內核.運行 \
    --export kernel_dispatch=系統呼叫.程序值條目 \
    -o os/build/java.o os/原始碼/*.java
```

`--target user`는 jkoros 셸에서 실행할 독립 ELF를 생성한다. `使用者` 클래스의 제한된 native API는 `int 0x80` 시스템 호출로 연결하며 `設備` 클래스의 硬件值 직접 접근은 거부한다. 使用者 ELF는 Linux 執行命令 檔案 ABI와 다르므로 호스트에서 실행하지 않는다. 生成·登記 방법은 [使用者 執行命令 指南](../os/使用者/指南.md)에 있다. `--export 외부기호=類別值.函數`는 오버로드되지 않은 靜態值 함수를 內建 操作數棧 ABI로 노출한다. 커널의 시스템 調用 진입점에 사용한다.

Java 파일은 필요한 클래스들을 한꺼번에 전달한다. 輸出 옆의 `.s`는 생성된 어셈블리, `.json`은 原始碼 SHA-256 및 네이티브 符號↔Java 函數 대응표다. 中文 함수명은 원문과 대응표에 보존하고 ELF 내부에는 충돌 방지용 計算機 기호를 쓴다. 編譯原始碼·組裝值·連接 중 실패하면 기존 結果 파일을 덮어쓰지 않는다.

## 支持值 裁剪

- `int`, `boolean`, `byte`, `short`, `char`의 32비트 計算結果 및 類型值 轉換值.
- 靜態值 필드와 靜態值 函數, 매개변수·已返回值, 재귀, 클래스별 지연 초기화와 初始化 週期值.
- 조건문, 반복문, 단락 평가, 삼항식, 整數 `switch`, 넓은 局部作用域 變量值 인덱스.
- 加法結果結果·減法結果結果·곱셈·나눗셈·餘數值·位元值 연산과 移動值. Java의 오버플로 및 `MIN_VALUE / -1` 동작을 유지한다.
- `int[]` 生成·初始值 0·長度·讀取·寫入·引用 비교. 256KiB 고정 陣列值 區域值, 널/下標值/大小/地址區域 檢查項.
- 字符串 리터럴과 `String` 引用, `length()` 및 `charAt()`. 문자열은 UTF-16 程式碼值 단위로 저장하고 같은 리터럴은 공유한다. NUL 및 대리쌍도 시험한다.
- 中文 類別值·函數·變量值·檔案 名稱.

`new Object`, 인스턴스 字段值/函數, 상속/인터페이스, `long/float/double` 執行命令 操作值, `int[]` 이외 陣列值, 字符串 동적 合併值列, Java 표준 庫, 異常 程序值條目, 스레드·同步化·GC는 미지원이다. 실행에 필요한 是否不支持 바이트코드나 外部值 호출을 발견하면 실패한다. 사용되지 않는 默認值 생성자는 執行命令 코드로 만들지 않는다. Java 8 문법이어도 모든 프로그램을 컴파일할 數 있다는 뜻은 아니다.

異常 物件值 대신 런타임 錯誤 번호로 중단한다. Linux와 jkoros 使用者 대상에서는 `100 + 編號`로 종료하고 內核值 대상에서는 `JKOROS PANIC 編號`를 출력하고 정지한다. 使用者 프로그램만 종료한 경우 셸은 繼續處理 실행된다.

| 編號 | 원인 |
| --- | --- |
| 1 | 0으로 除法結果 |
| 2 | 널 引用 |
| 3 | 陣列值/字符串 下標值 裁剪 초과 |
| 4 | 負數值 陣列值 大小 |
| 5 | 陣列值 區域值 부족 |

陣列值 영역은 증가식 할당이며 회수하지 않는다. 재귀 스택의 邊界位置值 검사도 아직 없으므로 무제한 재귀를 안전하게 처리하는 런타임은 아니다. 특권 內核值 및 신뢰할 數 있는 작은 프로그램용 初始狀態 구현이다.

## native 경계와 ABI

內核值 대상에서는 `os/原始碼/設備.java`, 使用者 대상에서는 `os/使用者/聲明/使用者.java`의 정확한 方法名稱文本·서술만 허용한다. 임의의 `native` 함수와 Linux/使用者 대상의 硬件值 접근은 거부한다. Java 인수를 왼쪽부터 32비트 한 칸씩 스택에 놓으며, 반환값은 EAX, EBP/ESP 이외 레지스터는 호출자가 보존한다고 가정하지 않는다. C의 cdecl/JNI ABI가 아니므로 C 함수와 바로 연결하면 안 된다.

Java 原始碼 또는 `.class` 입력을 받는다. 전체 JVM 字節碼 검증기는 제공하지 않는다. 어노테이션 처리는 비활성화하고 비어 있는 類別值 路徑/原始碼 경로에서 명시한 소스만 컴파일한다.

## 검증과 實現 근거

`測試/test_compiler.py`의 14개 시험에는 네이티브 ELF와 OpenJDK의 操作值 結果 대조, 類別值 初始化, 整數 극값, 字符串/陣列值, 재귀·switch·wide, 런타임 오류와 是否不支持 기능 拒絕值, 失敗值 시 輸出 보존, 使用者 ELF/權限值 邊界位置值 및 發射值 검증이 포함된다. 이것은 Java 전체 적합성 시험은 아니다.

命令 의미와 類別值 檔案 형식은 Oracle의 [JVM 命令 規格](https://docs.oracle.com/javase/specs/jvms/se11/html/jvms-6.html), [類別值 檔案 規格](https://docs.oracle.com/javase/specs/jvms/se11/html/jvms-4.html)를 참고했다.
