# 자체 ARM64 JVM 0.4와 한국어 бібліятэка

한국어 통신·выключэнне 사용법은 [한국어 Java API](한국어자바/файл_звестак_eb81d7d9.md), функцыя_значэнне·변수·Файл 이름의 변경과 어원 근거는 [명명 файл_звестак_eb81d7d9](명명/файл_звестак_eb81d7d9.md)를 참고한다.

JAR выканаць_каманда, 외부 IPv4 TCP/UDP, 별도 статычны_значэнне 부분집합 `jaot`와 게스트 C 컴파일은 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)에 설명한다. 아래 аб_ект_значэнне·Thread·Swing은 JVM 경로의 기능이며 AOT апора_значэнне 범위와 같지 않다.

이 구현은 **Linux 없이 부팅한 Java AOT 커널의 EL0에서 выканаць_каманда**한다. JDK/JRE의 거의 모든 기능을 제공하는 단계는 아직 아니다. HotSpot·OpenJDK клас_значэнне бібліятэка 전체를 이식하거나 Java SE 인증/TCK를 통과한 구현도 아니다. 이번 확장은 단일 клас_значэнне·статычны_значэнне спосаб_значэнне 중심이던 실행기를 аб_ект_значэнне·бібліятэка выканаць_каманда 기반으로 넓힌 것이다.

## 실행과 будаваць_крыніца

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
# 자체 ядро_значэнне 안에서 крыніца_дрэва будаваць_крыніца → class выканаць_каманда, 한국어 API 호출
python3 Інструменты/выканаць_файл.py 시험/자바/한글소스.java

# аб_ект_значэнне·выключэнне 등은 вузел JDK로 Java 8 class를 만든 후 자체 커널에서 выканаць_каманда
mkdir -p build/my-java
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/my-java 시험/자바/한글시험.java
python3 Інструменты/выканаць_файл.py build/my-java/한글시험.class

# 의존 class 파일은 --include로 함께 перанос_значэнне
javac --release 8 -encoding UTF-8 -d build/my-java 시험/자바/객체시험.java
python3 Інструменты/выканаць_файл.py build/my-java/객체시험.class \
  --include build/my-java/Фон_значэнне.class --include build/my-java/галіна_значэнне.class \
  --include build/my-java/계산가능.class

make test-jvm
```

`--include DIR`는 그 디렉터리의 class 파일을 재귀적으로 읽어 `패키지.клас_значэнне.class`라는 RAM Файл 이름으로 전송한다. 주 클래스도 패키지가 있다면 `--class-name 패키지.клас_значэнне`를 지정한다. 셸에서는 해당 이름으로 업로드하고 `java 패키지.клас_значэнне`로 실행한다. JVM 0.4는 Main-Class가 있는 16 KiB 이하 JAR도 `java -jar Файл.jar`로 실행한다. JAR 모드에서는 JAR 내부 클래스와 내장 한국어 클래스만 찾는다. 배포 한국어 бібліятэка JAR는 вузел javac의 classpath로 사용하며, 같은 클래스가 карыстальнік JVM ELF에도 Чытанне 전용 자료로 포함된다. 일반 class 모드에서는 사용자가 같은 이름으로 올린 RAM class를 먼저 읽는다.

게스트 `javac`는 여전히 статычны_значэнне спосаб_значэнне, int/boolean/char/String, умова·спрынт_значэнне, радок_значэнне 결합, 일부 Файл 스트림 등의 **자체 부분집합 컴파일러**다. аб_ект_значэнне абвяшчэнне·상속·try/catch·Thread 사용 소스를 게스트 javac가 모두 컴파일하는 것은 아니다. 위 기능은 `javac --release 8`로 만든 class를 자체 JVM에서 실행한다. 한국어 API 중 Выхад·문자 스칼라 функцыя_значэнне·Файл Чытанне/쓰기는 게스트 컴파일러에도 연결했다. 다음처럼 전체 이름으로 호출한다.

```java
public class 인사 {
    public static void main(String[] 인수) throws Exception {
        한국어.자체.Выхад.напісаць_лінія("안녕하세요😀");
        한국어.자체.Выхад.수쓰기(한국어.자체.문자.코드포인트수("한글😀"));

```

## выканаць_каманда 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(한국어 клас_значэнне 포함), class당 16 KiB·канстанта_значэнне 풀 511항목, 전체 спосаб_значэнне/поле_значэнне 각각 512개. спосаб_значэнне код_значэнне 8 KiB, мясцовы_маштаб 변수·피연산자 스택 각각 128슬롯, 인수 최대 16개(this 포함).
- VM 가닥은 main 포함 **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 выканаць_каманда 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- аб_ект_значэнне 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 фактычны_дадзеныя 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 Файл·대형 радок_значэнне·객체가 이 제한을 넘을 수 있다.
- 실행은 50만 바이트코드 Загад 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 입력 대기는 기한을 갱신하고 акно пераход_рэжым 시 중단·재개한다. 일반 сервер_значэнне·계산의 무제한 실행은 아직 없다. 미지원 Загад·рэсурс_значэнне 부족은 명시적인 오류로 종료한다.
- RAM Файл 최대 64개, 파일당 16384바이트, ШЛЯХ UTF-8 63바이트. RAM 디렉터리와 аднарангавы_значэнне/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 한국어 class는 RAM Файл 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 현재 경로에서 крыніца_дрэва·клас_значэнне·дадзеныя 파일을 읽는다.
- UDP는 Java 루프백 및 lwIP/SLIP를 통한 외부 IPv4를 제공한다. фактычны_дадзеныя GENET/Wi-Fi/DNS/TLS/HTTP 전체는 없다. 전문 512바이트, 소켓 8개, 소켓당 큐 4개. receive는 VM 가닥을 양보하며 대기하고 setSoTimeout을 적용하지만 전체 выканаць_каманда 기한은 여전히 적용된다.
- long/float/double, invokedynamic/람다, enum/annotation, 다차원 масіў_значэнне, 완전한 масіў_значэнне 공변성·인터페이스 слой_значэнне 검사, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/зашыфраваць_дадзеныя/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. Swing의 별도 апора_значэнне 부분집합은 아래 및 개발 매뉴얼을 참고한다. клас_значэнне Файл 전체 검증기·доступ_увядзенне дазвол_значэнне/보호된 멤버 검사는 아직 완전하지 않다. 손상된 입력은 EL0 ахоўваць_значэнне 경계 내에서 종료되도록 한다.

전체 OpenJDK를 목표로 하려면 다음은 별도의 주요 구현 단계다: 완전한 JVM значэнне/праверыць_5fb2b747/клас_значэнне 로더와 выключэнне 모델 → 영속 VFS·mmap·гадзіннік·원자 аперацыя_значэнне·фактычны_дадзеныя 스레드/сінхранізаваць ABI → OpenJDK java.base 및 native бібліятэка 이식 → прылада_значэнне 네트워크·TCP/IP → акно 시스템/шрыфт_значэнне/입력기·java.desktop → Java SE 호환성 시험. 현재 자체 JVM의 일부 메서드를 더하는 것으로 이 작업이 완료되지는 않는다.

## праверыць_5fb2b747
