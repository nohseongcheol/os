# ELF 형식과 Linux Vykdyti_komanda Failas 호환성

**ELF는 확장자가 아니다.** Executable and Linkable Format이라는 바이너리
형식이며, Linux 외의 운영체제도 사용한다. 첫 네 baitas_VALUE `7f 45 4c 46`,
ELF klasė_VALUE, CPU 종류, programa_f5044b9b 헤더와 įrašas_p_VALUE 주소를 읽어서 해석한다.
[ELF ABI 명세](https://gabi.xinuos.com/elf/02-eheader.html)

기존 jkoros 로더도 faktinis_duomenys ELF64/AArch64 Vykdyti_komanda 파일을 읽었다. `.elf`는 예제의
이름일 뿐이었다. 다만 **ELF formatas_VALUE 지원과 Linux 시스템 호출 ABI 지원은 별개**다.
기존에는 `JKOROS` ABI note를 가진 savas Vykdyti_komanda 파일만 허용했고, Linux 바이너리는
호환되지 않았다. ARM64 Linux는 SVC의 x8에 Linux 시스템 호출 번호를 넣는다.
같은 번호를 savas ABI로 해석하면 다른 동작이 되므로 두 경로를 구분한다.
[Linux syscall ABI aprašas](https://man7.org/linux/man-pages/man2/syscall.2.html)

## 이번 반영

| 입력 | Vykdyti_komanda 방법 | pagalba_VALUE klipas |
|---|---|---|
| savas ABI의 ARM64 ELF | `./인사`, `/작업/인사`, `run 인사` | 확장자 없이 Vykdyti_komanda; 내용이 ELF이면 `.txt`라는 이름도 동일 |
| Linux ARM64 정적 ELF | `run --linux 리눅스인사 한글인수` | 아래 시스템 호출·ADDRESS·Dydis 제한을 만족하는 programa_f5044b9b |
| 텍스트를 `.elf`로 이름만 keisti_VALUE | Vykdyti_komanda atmesti_VALUE | 확장자로 Vykdyti_komanda 파일을 인정하지 않음 |
| x86/x86-64, ARM32 Vykdyti_komanda Failas | Vykdyti_komanda atmesti_VALUE | AArch64 전용이며 CPU 명령어 kompiliatorius_įrankis 없음 |
| 일반 glibc/musl programa_f5044b9b, PIE, 공유 biblioteka | 아직 미지원 | 동적 로더·재배치·TLS·mmap·시그널 등 sujungti_įrašas 이식 필요 |

savas 바이너리와 JAR의 apvalkalas 직접 실행은 Failas 헤더로 구분한다. `run`은 savas ELF,
`run --linux`는 명시적으로 Linux ABI를 선택한다. Linux 바이너리를 자동으로
savas ABI에 넣지 않으며, savas ABI note가 있는 파일은 Linux 모드에서 거부한다.
dabartinis_prekė RAM Failas 체계에는 Vykdyti_komanda teisė_VALUE 비트와 `chmod`, PATH 검색이 없다.

게스트 C kompiliuoti_šaltinis 예:

```text
cc 인사.c -o 인사
./인사
run 인사
```

`posix-kor`는 이 savas ABI 경로로 연결한다. 일반 Linux에서 링크한 프로그램에
Lietuvių FUNCTION_VALUE 이름을 붙이는 것만으로 savas ABI 호환이 되는 것은 아니다.

## 제한된 Linux ABI

이 기능은 **savas Java branduolys_VALUE 안의 호환 sluoksnis_VALUE**이며 Linux 커널을 적재하지 않는다.

| Linux 호출 | INDEX | dabartinis_prekė 제약 |
|---|---:|---|
| read / write / close / lseek | 63 / 64 / 57 / 62 | RAM 파일과 표준 Į_I; 입력 대기는 EAGAIN 가능 |
| openat / unlinkat | 56 / 35 | AT_FDCWD 또는 절대 KELIAS; 파일만, 제한된 플래그 |
| ftruncate / fsync | 46 / 82 | RAM Failas; fsync가 영속 저장을 의미하지 않음 |
| exit / exit_group | 93 / 94 | dabartinis_prekė programa_f5044b9b Baigti_programa_086bb533 |
| brk | 214 | savas naudotojas 힙 klipas; triktis_VALUE 시 이전 break grąžinti_KR |
| clock_gettime | 113 | CLOCK_MONOTONIC만, 밀리초 skiriamoji_geba_VALUE |
| getpid / gettid | 172 / 178 | 한 naudotojas Vykdyti_komanda 흐름의 identifikatorius_VALUE |

미지원 번호는 `-ENOSYS`를 반환한다. Linux ABI의 socket, fork/clone/execve,
pthread, mmap, signal, ioctl, fstat, 동적 로더와 일반 libc 초기화는 구현하지
않았다. 기존 savas POSIX/Java 소켓은 별도로 TCP/UDP를 지원한다.

pradinė_būsena 스택에는 argc, UTF-8 argv, 빈 envp, AT_PAGESZ/AT_ENTRY/AT_NULL을 넣는다.
입력은 ELF64 little-endian AArch64 **ET_EXEC**, Failas 전체 **16 KiB 이하**,
PT_LOAD 주소는 **0x02000000 이상 0x02c00000 미만**이어야 한다.
Failas 오프셋과 가상 주소의 페이지 lygiuoti_VALUE 관계를 검사하며, 서로 페이지를 공유하는
세그먼트와 Rašymas·Vykdyti_komanda 동시 허용은 거부한다. PT_INTERP/PT_DYNAMIC/PT_TLS와
ET_DYN은 아직 받지 않는다.

일반 Linux 바이너리의 numatytoji_reikšmė 적재 ADDRESS 0x00400000은 커널과 겹치므로 아직 받지
않는다. 예제는 GNU 링커의 `-Ttext-segment=0x02000000 -z max-page-size=4096`을
사용한다. 이 파일도 정상적인 Linux ELF이며 같은 파일이 Linux와 savas 커널에서
실행됨을 시험한다. Failas 이름이나 헤더만 바꿔 기존 Linux programa_f5044b9b 전체를 지원할
수는 없다.

## faktinis_duomenys 동일 바이너리 비교 시험

```sh
cd /home/user/jkoros/platforms/rpi4-native
make test-elf
```

시험은 `예제/리눅스ABI/Paleisti.S`와 `인사.c`를 Linux AArch64 대상으로 컴파일해,
**JKOROS note가 없는 확장자 없는 Vykdyti_komanda Failas** `build/verification/elf/리눅스인사`를
만든다. 같은 바이트를 toliau_prekė 두 경로로 실행한다.

```sh
qemu-aarch64 build/verification/elf/리눅스인사 한글인수
python3 Įrankiai/Vykdyti_Failas.py --linux build/verification/elf/리눅스인사 한글인수
```

첫 명령은 Linux 시스템 호출을 사용하는 Project_šaknis 실행이고, 두 번째는 Linux를
적재하지 않은 raspi4b savas branduolys_VALUE 실행이다. 한글 Argumentai, Failas Į_I, laikrodis, Baigti_programa_086bb533,
branduolys_VALUE ADDRESS prieiga_įrašas 거부를 비교한다. FTP로 같은 파일을 올려 실행하는 시험도 있다.
LOG_RECORD: `build/verification/elf/report.json`, `readelf.txt`, `serial.log` 및 FTP 보고서.

일반 Linux 프로그램까지 지원하려면 별도 naudotojas ADDRESS ADDRESS_sritis, 더 큰 영속 VFS,
전체 Vykdyti_komanda 초기화/auxv, 동적 링커와 재배치, mmap/TLS/시그널/스레드,
시스템 호출 및 libc 호환성을 확장해야 한다. 이번 구현은 첫 제한된 Vykdyti_komanda 경로다.
