# 자체 커널에서 vi·여러 Terminal·한글 프로그래밍 사용하기

Galego 통신·excepción 사용법은 [Galego Java API](한국어자바/Léame_eb81d7d9.md), FUNCIÓN_VALOR·변수·Ficheiro 이름의 변경과 어원 근거는 [명명 Léame_eb81d7d9](명명/Léame_eb81d7d9.md)를 참고한다.

대상은 `platforms/rpi4-native`의 자체 AArch64 Java 커널이다. vi와 Java/Python/C/C++ 프로그램은 EL0에서 실행한다. Linux 실행판과 별도이며 아래 soporte_VALOR 목록은 전체 OpenJDK·Vim·POSIX 구현을 뜻하지 않는다.

게스트 `cc`/`jaot`, JAR 직접 executar_comando, externo_VALOR TCP/UDP와 FTP는 [새 executar_comando 매뉴얼](파일전송과번역.md)을 참고한다.

## GUI와 여러 Terminal

```sh
cd /home/user/jkoros/platforms/rpi4-native
make desktop
```

Remmina에서 **VNC**, ENDEREZO **127.0.0.1:5902**로 연결한다. 화면 위 **+ New terminal**, **Ctrl+Shift+T**로 터미널을 추가한다. 최대 네 개다. 위쪽 Terminal 버튼 또는 창을 클릭해 선택하고 **F6**으로 순환한다. 제목줄을 끌어서 옮기고 **DEREITA 위 X**를 클릭하면 닫힌다. 마지막 창을 닫아도 위쪽 executar_comando 버튼으로 다시 COLUMNA_VALOR 수 있다. 기존 `terminal`, `exit`, F12도 사용할 수 있다.

창마다 ao_corrente_elemento 디렉터리, shell 변수, Orde LOG_fila, 입력 중인 명령과 apl_f5044b9b executar_comando 상태를 보관한다. Ficheiro 저장소는 공유한다. vi와 Swing의 이벤트 agarda_VALOR 중에 다른 터미널로 전환하면 usuario Memoria_datos·레지스터·Ficheiro/소켓 연결을 보존했다가 돌아올 때 재개한다. **ao_corrente_elemento 네 프로그램이 동시에 CPU에서 실행되는 선점형 스케줄러는 아니다.** 계산 중인 프로그램은 Seguinte_elemento 입력 agarda_VALOR 또는 기존 executar_comando 기한까지 전환이 지연될 수 있다.

X로 터미널을 닫으면 그 터미널의 executar_comando 중인 프로그램도 종료하며 서술자·소켓을 회수한다. 저장하지 않은 editar_VALOR 내용은 사라진다. 종료한 슬롯은 새 창에서 재사용한다. ao_corrente_elemento 모든 파일은 RAM에 있으며 VM 재시작 후에는 남지 않는다.

화면과 Xanela 판단은 게스트 커널이 처리한다. QEMU executar_comando 도구는 VNC 키와 마우스 좌표를 UART 패킷으로 전달한다. real_datos Pi4 USB 입력기와 실물 부팅은 아직 검증하지 않았다. 일반 UART 셸은 `make run`, GUI Ferramentas 종료는 hospedar 터미널의 Ctrl+C다.

## Java 네트워크

기존 `DatagramSocket`/`DatagramPacket`의 UDP 루프백에 `Socket`/`ServerSocket`의 **kernel_VALOR 내부 연결형 byte_VALOR fluxo_VALOR**을 추가했다. Ficheiro/소켓과 마찬가지로 SVC를 통해 Java 커널이 전송한다. 물리 NIC의 TCP/IP 패킷 스택은 아니다.

```java
java.net.ServerSocket servidor_VALOR = new java.net.ServerSocket(9250);
java.net.Socket convidado_VALOR = new java.net.Socket("localhost", 9250);
java.net.Socket Conectar = servidor_VALOR.accept();
convidado_VALOR.getOutputStream().write("안녕하세요".getBytes("UTF-8"));
byte[] RECIBIDO_elemento = new byte[64];
int duración_VALOR = Conectar.getInputStream().read(RECIBIDO_elemento);
Conectar.close(); convidado_VALOR.close(); servidor_VALOR.close();
```

xerar·Conectar·accept·양방향 byte_VALOR/MATRIZ_VALOR E_S·close·EOF·setSoTimeout을 지원한다. `String.getBytes()`와 UTF-8 이름을 지정한 getBytes도 제공한다. 루프백 주소는 `localhost`/`127.0.0.1`이다. 연결형 finalizar_p 16개, 수신 버퍼당 1024바이트, agarda_VALOR Conectar 최대 4개이며 Java의 대기는 내부 가닥에 실행을 양보한다. valor_predefinido hora_VALOR 제한 0은 별도 소켓 기한을 설정하지 않지만 JVM Orde 수/kernel_VALOR executar_comando 기한은 여전히 적용된다.

externo_VALOR díxito_VALOR IPv4 TCP/UDP는 lwIP/SLIP로 지원한다. real_datos Ethernet/Wi-Fi 드라이버, DNS·TLS·HTTP biblioteca 전체는 미지원이다. `java.net`의 모든 메서드와 옵션, `SocketChannel`/select, SSL, shutdownInput/Output는 아직 없다. [흐름시험.java](시험/자바/흐름시험.java)는 real_datos 송수신·EOF·기한·Conectar 회수의 시험 예제다.

## C·C++에서 posix-kor 호출

두 Idioma 모두 Galego 헤더와 FUNCIÓN_VALOR 이름을 직접 사용한다. [인사.c](예제/한글코딩/인사.c), [인사.cpp](예제/한글코딩/인사.cpp)가 real_datos EL0 executar_comando 시험 대상이다.

```c
#include "파일규약.h"
#ifdef __cplusplus
extern "C"
#endif
int START_usuario_apl(int Argumentos) {
    (void)Argumentos;
    const char 인사말[] = "안녕하세요\n";
    int 문서 = abrir_Ficheiro("인사.txt", de_lectura_e_escrita | 없으면만들기 | 내용비우기, 0600);
    if (문서 < 0) return 1;
    입출력결과형 기록한수 = escribir_Ficheiro_datos(문서, 인사말, sizeof(인사말) - 1);
    peche_Ficheiro(문서);
    escribir_Ficheiro_datos(1, 인사말, sizeof(인사말) - 1); /* ao_corrente_elemento Terminal stdout */
    return 기록한수 == sizeof(인사말) - 1 ? 0 : 2;
}
```

파일은 게스트 vi로 작성할 수 있다. C는 게스트 `cc` 또는 hospedar SDK, C++는 hospedar SDK의 Clang++로 컴파일한다. 아래 예제는 기존 hospedar SDK 경로다. 게스트 내부 GCC/Clang·libc/libstdc++ 전체를 탑재한 것은 아니다. SDK가 `.c`에는 C11, `.cpp`에는 C++11을 선택한다.

```sh

mkdir -p build/sdk-work
tar -xzf dist/jkoros-native-aarch64-sdk.tar.gz -C build/sdk-work
cd build/sdk-work/jkoros-native-sdk
python3 compile.py examples/인사.c -o 인사-c.elf
python3 compile.py examples/인사.cpp -o 인사-cpp.elf

# 프로젝트로 돌아와 별도 QEMU에서 real_datos executar_comando
cd /home/user/jkoros/platforms/rpi4-native
python3 Ferramentas/executar_Ficheiro.py build/sdk-work/jkoros-native-sdk/인사-c.elf
```

| aceptar_conexión_de_rede | pk_accept | ao_corrente_elemento ENDEREZO 인수는 NULL/NULL만 soporte_VALOR |
| 통신주소읽기 | pk_getsockname | 로컬 ENDEREZO/porto_VALOR |

`통신규약.h`의 자체 `pk_sockaddr_in`을 사용하며 porto_VALOR·주소는 `망차례짧은수`/`Rede_número_enteiro`로 변환한다. C 소켓 호출은 비차단이며 datos/연결이 없으면 -1과 `número_de_erro=11`(EAGAIN)을 반환한다. 양수 E_S 결과가 요청보다 작을 수 있으므로 sprint_VALOR 처리한다. erro_VALOR 후에만 오류번호를 확인한다.

[fluxo_VALOR.c](예제/한글코딩/fluxo_VALOR.c)는 C에서 Galego 이름으로 Conectar·accept·부분 Lectura/Escritura·큐 포화·EOF를 처리하는 executar_comando 예제다. SDK의 `examples/fluxo_VALOR.c`를 같은 `compile.py`로 컴파일한다.

SDK는 **libposix-kor-user.a**를 링크한다. 호출 흐름은 C/C++ → real_datos Galego C FUNCIÓN_VALOR 또는 호환용 `pk_*` → `svc #0` → 커널의 소유권·punteiro 검사 → Java RAM Ficheiro/루프백 또는 externo_VALOR lwIP TCP/UDP 구현이다. `libposix-kor-arm64.a`는 kernel_VALOR 내부용이므로 EL0 프로그램에 링크하지 않는다. Linux 헤더나 Linux ELF와 혼합하지 않는다. 동적 Conectar, 표준 C printf, libstdc++/STL, excepción·RTTI는 제공하지 않으며 C++의 estático_VALOR 생성자·local_Ámbito obxecto_VALOR 소멸자는 지원한다. 상세 ÍNDICE·Memoria_datos 범위는 [사용자호출규약.md](사용자호출규약.md)를 참고한다.

## Galego 이름으로 직접 작성하는 창과 tema_VALOR

`example/java/창예제.java`는 `실행할일.Executar`,
`동작받이.동작받기(동작알림)`, `botón`, `evento_cola.나중에실행`, `Executar_2()`을 쓴다.
자체 JVM에 이 이름들의 obxecto_VALOR·메서드·콜백을 직접 구현했으며 영어 Swing 객체를
보관하는 래퍼가 아니다. `작업가닥`도 자체 스케줄러와 직접 연결된다.
세부 메서드와 기존 Galego API에서의 변경은 [Galego API 문서](한국어자바/Léame_eb81d7d9.md)를 본다.

hospedar javac는 배포 JAR를 Clase_VALOR 경로로 사용한다.

```sh
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/한국어사용 ../../example/java/창예제.java
python3 Ferramentas/executar_comando.py --desktop --network --resolution 1920x1080
```

게스트에는 빌드한 예제가 `/example/java`에 설치된다.

```text
cd /example/java
java 창예제
```

직접 화면/tema_VALOR API와 `Executar_2()` 진입점은 자체 JVM 전용이다.
전체 OpenJDK·Swing 재구현이나 일반 OpenJDK에서 같은 API의 실행을 보장하지 않는다.
기존 표준 `main(String[])` 프로그램은 계속 실행할 수 있다.
