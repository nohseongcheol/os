# 內建 ARM64 커널의 Codex 安裝值 가능성 검토

검토일: 2026-10-05. 소스와 공식 문서를 대조한 설계 검토이며, 게스트에 Codex를 설치하거나
로그인·모델 호출을 실행한 결과는 아니다. 內建 ARM64 커널과 `../rpi4` Linux 실행판은 구분한다.

當前項目 內建 커널에는 공식 Codex CLI를 그대로 安裝值·실행할 數 없다.
기술적으로 필요한 執行命令 환경을 추가하거나 Codex를 이식하는 경로는 있으나,
다운로드 命令 하나를 추가하는 작업으로 해결되지 않는다. JDK/JRE 기능 확장만으로도 해결되지 않는다.

## 확인한 근거

| 條目值 | 當前項目 소스에서 확인한 狀態值 | 직접 실행을 위한 任務 |
|---|---|---|
| 執行命令 檔案 | `計算機/使用者.c`: AArch64 ET_EXEC만, PT_INTERP/PT_DYNAMIC/PT_TLS 拒絕值, 업로드 執行命令 버퍼 16384바이트 | 目標值 바이너리에 맞는 ELF 적재·재배치·執行命令 初始化, 記憶體資料/檔案 限制值 擴展名值 |
| Linux ABI | `計算機/Linux兼容性.inc`: read/write/openat/brk 등 제한된 번호만 程序值條目, 나머지는 ENOSYS | libc/런타임에 필요한 시스템 호출을 추가하거나 內建 ABI용 런타임 移植 |
| 프로세스·스레드 | 일반 fork/clone/execve, pthread/futex, 시그널, mmap, poll/epoll 계열이 미완성 | 비동기 I/O·스레드·子值 命令 執行命令·退出程式/取消操作 기능 |
| 檔案 | `原始碼/記憶體檔案集.java`: RAM 檔案 64개, 파일당 16 KiB, 비영속 | 큰 執行命令 檔案·프로젝트·設置·세션을 위한 영속 VFS, 檔案 權限值·路徑·디렉터리 擴展名值 |
| 네트워크 | lwIP TCP/UDP는 있으나 `通信網絡/lwipopts.h`의 LWIP_DNS=0, 일반 HTTPS 클라이언트 缺失方法 | DNS, TLS 인증서 有效性校驗·신뢰 代碼庫根·정확한 時間戳值, HTTPS/스트리밍 |
| 終端·工具集 | 內建 셸과 GUI 터미널은 있지만 표준 PTY·일반 프로세스 任務 控制值 缺失方法 | 交互式 CLI용 終端 기능, 命令殼/檔案 검색/構建系統 工具集 連接 |
| 執行命令 權限值 | EL0 보호는 있으나 Codex의 Linux 샌드박스와 같은 정책 집행 環境 缺失方法 | 檔案·네트워크·命令 權限值 정책과 승인 기능; 內建 커널에 맞는 격리 實現 |

여기서 ELF의 PT_TLS는 스레드별 存儲值 공간이다. HTTPS의 TLS 密碼值 통신과 서로 다른 기능이다.
ELF 檔案 형식을 읽을 數 있다는 사실만으로 Linux 執行命令 환경을 제공하는 것은 아니다.
SSH/VNC를 위한 密碼值 라이브러리를 넣은 상태도 HTTPS 實現 완료를 의미하지 않는다.

호스트의 `/home/user/.local/bin/codex`도 확인했다. 이것은 x86-64 ELF ET_DYN이며 약 209 MiB다.
해당 파일을 ARM64 게스트로 복사하여 실행할 數 없다. 이 크기를 ARM64 分發值 파일의 크기로
해석하지 않는다. 공식 ARM64 빌드의 實際資料 大小·의존성은 설치할 버전으로 追加條目 검사해야 한다.

## 가능한 實現 路徑

1. **內建 커널에 공식 CLI 직접 移植**
   영속 存儲值/VFS와 使用者 記憶體資料, 프로세스·스레드·I/O, libc/런타임, DNS/HTTPS,
   終端·權限值 체계를 갖춘다. 之後值 目標值 버전의 의존성을 조사하여 크로스 構建系統·이식한다.
   Linux 커널을 반드시 탑재할 필요는 없지만, 공식 Linux 바이너리를 그대로 쓸 경우
   그 바이너리가 사용하는 Linux ABI까지 호환해야 한다. 큰 操作系統 開發 과제다.

2. **外部值 宿主 Codex와 內建 內核值 連接 — 首位項目 구현으로 권장**
   Linux PC에서 공식 CLI 또는 app-server를 실행하고 jkoros에는 전용 使用者 命令/화면을 만든다.
   호스트의 인증된 연결과 게스트 檔案 讀取·修改值·업로드·命令 執行命令 어댑터가 필요하다.
   기존 SSH/TCP 경로를 활용할 數 있으나, 檔案 동기화나 Codex 전용 어댑터는 當前項目 구현되어 있지 않다.
   호스트에서 수행한 빌드와 게스트에서 수행한 執行命令 결과를 명확히 구분한다.
   이 구성은 內建 커널을 유지하지만, 공식 CLI 자체는 外部值 호스트에서 실행된다.

3. **內建 API 클라이언트 제작**
   內建 ABI의 C 또는 지원되는 Java 부분집합으로 交互式會話 UI와 檔案/命令 工具集 調用 루프를 만든다.
   外部值 중계기를 쓰지 않는다면 DNS/有效性校驗 가능한 TLS/HTTPS와 인증 資料 저장을 먼저 구현해야 한다.
   이는 OpenAI API를 이용하는 별도 에이전트이며 공식 Codex CLI 전체의 이식으로 표시하지 않는다.

4. **별도 ARM64 Linux 실행판에서 安裝值**
   `../rpi4`는 Linux와 musl 기반이므로 일반 Linux 安裝值 경로를 검토할 數 있다.
   사용할 Codex 버전의 ARM64·musl 호환성, 依賴項列, 커널의 샌드박스 지원을 實際資料 검증해야 한다.
   이번 검토에서 安裝值 성공을 확인하지 않았다. 이 결과를 內建 Java 커널의 지원으로 표시하지 않는다.

## 단계별 是否完成 項目根

- 직접 移植: `--version` 運行 → 인증/HTTPS → 檔案 讀取·修改值 → 子值 命令 執行命令 →
  交互式 輸入值/스트리밍 → 權限值 限制值·取消操作 → 재부팅 之後狀態 設置/세션 보존을 각각 實際資料 게스트에서 확인한다.
- 宿主 連接: 게스트에서 申請 輸入值 → 宿主 Codex 程序值條目 → 게스트 檔案 更改值 驗證 →
  게스트 javac/cc 執行命令 → 結果 표시를 처음부터 끝까지 검증한다.
- COSL 상업 조건을 유지하려면 새로 도입하는 런타임/通信 라이브러리의 라이선스와
  Codex 分發值 버전의 제3자 고지를 검토한다. 外部值 구성요소를 일괄 COSL로 재라이선스하지 않는다.
