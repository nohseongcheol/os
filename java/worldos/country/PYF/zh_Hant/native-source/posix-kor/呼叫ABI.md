# 使用者 調用 邊界位置值

대상은 jkoros i386 ELF32다. Linux i386의 調用 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `計算機/運行系統調用列.s`에서 EAX(編號), EBX·ECX·EDX·ESI·EDI(首位序數~第五序數 實參)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. 內核值 실패는 負數值 錯誤 編號, C 庫 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 使用者 區域值 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C 資料 주소는 位元組值 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java 檔案 흐름의 어셈블리 경계가 별도 位元組值 버퍼를 마련하여 같은 호출을 사용한다.

| 編號 | 動作 | 實參 |
|---|---|---|
| 30 | 打開檔案 | NUL 結尾 名稱 地址, 設置, 授權權限 |
| 31 | 讀取檔案資料 | 描述符條目, 資料 地址, 位元組值 數 |
| 32 | 寫入檔案資料 | 描述符條目, 資料 地址, 位元組值 數 |
| 33 | 關閉檔案 | 描述符條目 |
| 34 | 尋道檔案 | 描述符條目, 編碼狀態值 있는 偏移值, 項目根 |
| 35 | 複製副本檔案描述符 | 描述符條目 |
| 36 | 複製副本檔案描述符位置 | 描述符條目, 새 描述符條目 |
| 37 | 讀取檔案運行狀態 | 描述符條目, 48바이트 狀態值 地址 |
| 38 | 移除檔案條目名稱 | NUL 結尾 名稱 地址 |
| 39 | 設定檔案長度 | 描述符條目, 새 長度 |
| 40 | 控制檔案描述符 | 描述符條目, 命令, 值 |
| 41 | 創建端點 | 地址 運行系統值, 種類值, 契約值 編號 |
| 42 | 綁定地址 | 描述符條目, sockaddr_in 地址, 長度 |
| 43 | 發送數據報資料 | 描述符條目, 資料 地址, 長度, 設置, 申請 地址 |
| 44 | 接收數據報資料 | 描述符條目, 資料 地址, 長度, 設置, 申請 地址 |
| 45 | 讀取通訊端地址 | 描述符條目, sockaddr 地址, socklen_t 地址 |
| 46 | 設定接收超時 | 描述符條目, 0~2000 毫秒 |
| 47 | 提交檔案存儲裝置 | 描述符條目 |

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 地址 두 칸이다. 接收值 주소가 NULL이면 對端值 地址 기록을 생략한다. sockaddr_in은 16바이트이며 地址 체계는 設備 位元組值 序列值, 접속번호와 IP 주소는 네트워크 位元組值 차례다. 축소된 地址 버퍼에도 들어가는 앞부분을 쓰고 전체 地址 大小 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 退出程式, 2·3은 기존 實參 조회다. 當前項目 커널의 實參 목록이 執行命令 이름을 제외하므로 C 진입기는 argv[0]에 고정 字符串 `jkoros-app`을 넣고 之後值 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX 程序值 ABI와 다른 점이다.

표준 헤더의 整數 大小, 標誌列值 值, stat 字段值 순서는 `原始碼/頭文件/`에 정의한다. 동적 連接·다중 程序值·스레드가 추가되면 錯誤 編號 저장과 資源值 수명, 調用 경계도 함께 검토해야 한다.
