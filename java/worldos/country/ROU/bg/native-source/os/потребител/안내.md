# 셸에서 실행하는 потребител 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 안내](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 изпълнявам_команда

хост Терминал 1:

```sh
cd /home/user/jkoros
python3 os/Инструменти/Ехо_данни.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. външен_стойност 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

хост Терминал 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 действителен_данни CPU разрешение_стойност `ring 3`, Параметри Изход.
- `netcheck`: порт_стойност 중복, 잘못된 манипулатор_стойност/показалец/길이, 비차단 받기와 час_стойност 초과 проверявам.
- `udp`: IPv4 адрес·местоназначение_стойност порт_стойност·한 Игри_с_думи_стойност 메시지를 받아 UDP로 보내고 같은 응답을 проверявам. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: хост `10.0.2.2`의 Възложи_стойност 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. получавам_стойност_cef4d8ab цикъл_стойност 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. в_срок_артикул 주소는 게스트 `10.0.2.15/24`, шлюз_стойност `10.0.2.2`로 고정돼 있다. QEMU потребител 네트워크의 хост достъп_запис 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 програма_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java програма_f5044b9b добавям_запис

`예제/내프로그램.java`를 Следваща_артикул 형식으로 만든다. 진입점은 Параметри 없는 `static int` 또는 `static void` 함수다. 인수는 потребител API로 조회한다.

```java
public final class 내프로그램 {
    public static int Стартиране() {
        потребител.Писане("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/потребител/програма_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := потребител/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.Стартиране
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `потребител/декларация/потребител.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 изпълнявам_команда 중인 VM에는 компилация_система 결과가 자동 반영되지 않는다. програма_f5044b9b 이름은 в_срок_артикул 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java Клас_стойност·функция_стойност·변수에는 한국어를 쓴다. 최대 32개 програма_f5044b9b, 한 изпълнявам_команда 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/компилатор.py --target user --entry 인사.Стартиране \
    -o os/build/apps/hello.elf os/потребител/декларация/потребител.java os/потребител/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 хост 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 Поддръжка_стойност клип 안에서 실행한다. `.jar`와 일반 Linux изпълнявам_команда 파일은 지원하지 않는다.

## потребител 네트워크 API

선언은 `декларация/потребител.java`에 있다. `изпращам_данни`/`получавам_данни`의 `int[]` артикул_елемент 한 개는 байт_стойност 하나(0~255)를 나타낸다. 한 데이터그램의 최대 данни 길이는 1,024바이트다.

```java
int манипулатор_стойност = потребител.отварям_мрежа(0); // 0: 임시 локален_Обхват UDP порт_стойност 자동 избор_стойност
int[] данни = new int[32];
данни[0] = 'H'; данни[1] = 'i';
int 보낸길이 = потребител.изпращам_данни(манипулатор_стойност, 0x0a000202, 9000, данни, 2);
int 받은길이 = потребител.получавам_данни(манипулатор_стойност, данни, 1500);
потребител.затварям_мрежа(манипулатор_стойност);
```

действителен_данни 프로그램에서는 Отваряне·изпращам·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `получавам_данни`의 почакай_стойност 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 получавам_стойност_cef4d8ab 대기열은 한 개뿐이므로 добавям_запис 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | манипулатор_стойност·Процес_стойност_запис 길이·성공 등 해당 함수의 РЕЗУЛТАТ |
| -5 | устройство_стойност изпращам_стойност отказ_стойност |
| -9 | 잘못되었거나 닫힌 통신 манипулатор_стойност |
| -11 | 비차단 받기에서 도착한 данни 없음 |
| -14 | потребител показалец/масив_стойност клип ГРЕШКА |
| -19 | Поддръжка_стойност NIC 없음 |
| -22 | порт_стойност/почакай_стойност час_стойност/Параметри стойност ГРЕШКА |
| -24 | 열린 мрежа_порт 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | данни 또는 получавам_стойност_cef4d8ab масив_стойност Размер 문제 |
| -98 | локален_Обхват порт_стойност индекс 중복 |
| -101 | 지원하지 않는 местоназначение_стойност адрес |
| -110 | ARP·устройство_стойност·получавам_стойност_cef4d8ab час_стойност 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 кодиране_стойност 있는 Java `int`의 бит_стойност 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## изпълнявам_команда 경계와 시스템 호출

```text
обвивка run → JKAP에서 ELF проверка·적재 → ring 3 потребител програма_f5044b9b
                                 ↓ int 0x80
                      показалец 검사 → Java ядро_стойност API → RTL8139/UDP
                                 ↓ Изход_програма·изключение·час_стойност 초과
                                обвивка 복귀
```

시스템 호출 레지스터는 `EAX=индекс`, `EBX,ECX,EDX,ESI,EDI=Параметри`, `EAX=РЕЗУЛТАТ`다. Java 호출 операнд_стек ABI는 컴파일러가 потребител 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| индекс | 호출 |
| --- | --- |
| 0 | Изход_програма(Състояние_стойност код_стойност) — Стартиране/ГРЕШКА 런타임에서 използвам_стойност |
| 1 | низ_стойност Писане |
| 2 / 3 | Параметри 개수 / Параметри низ_стойност адрес |
| 10 | UDP Отваряне |
| 11 | UDP изпращам(манипулатор_стойност, IP, местоназначение_стойност порт_стойност, масив_стойност адрес, 길이) |
| 12 | UDP получавам(манипулатор_стойност, масив_стойност адрес, 제한 밀리초) |
| 13 | UDP Затворен |
| 14 | локален_Обхват IP адрес |
| 15 / 16 | 마지막 крайно_устройство_стойност IP / UDP порт_стойност |
| 20 | RAM Файл Четене(Име int[] адрес, Изход int[] адрес) |
| 21 | RAM Файл Писане(Име int[] адрес, 입력 int[] адрес, байт_стойност 길이) |
| 22 | UTF-16 код_стойност урок_стойност 문자 Изход(0~65535) |

Файл API는 `потребител.파일읽기(int[] Име, int[] данни)`와 `потребител.записване_Файл(int[] Име, int[] данни, int 길이)`다. 이름은 ASCII код_стойност масив_стойност(최대 64칸, 0 Изход_програма 또는 масив_стойност 끝), данни артикул_елемент 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 Файл 없음 `-2`, показалец ГРЕШКА `-14`, Име/길이 ГРЕШКА `-22`, Файл 슬롯 부족 `-28`, Размер 초과 `-90`을 반환한다. 쓰기는 проверка 후 Файл 전체를 대체한다. `потребител.записване_знак_стойност(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 потребител 모드에서 CS의 하위 비트를 직접 읽으므로 действителен_данни изпълнявам_команда 권한을 확인한다. ядро_стойност 포트 접근용 `устройство_стойност` native 함수는 потребител цел 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 изпълнявам_команда, 파이프, 프로세스 간 통신은 없다. изпълнявам_команда 파일은 커널의 Четене 전용 JKAP 묶음에서 적재한다. данни 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- потребител 가상 адрес `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. изпълнявам_команда 영상은 предна_стойност 2MiB, 인수는 `0x04300000`부터, 스택은 област_стойност_0e9a97ab 끝에서 시작한다. ядро_стойност identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB потребител 영역을 비우고 Файл 구역을 복사해 BSS·масив_стойност 영역을 초기화한다. потребител GC는 없지만 Изход_програма 후 Следваща_артикул изпълнявам_команда 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 Цитат/이스케이프 파싱은 없다.
- потребител 페이지의 код_стойност/данни 분리 Четене 전용 Настройки, NX, операнд_стек guard, ASLR은 아직 없다. 커널과 потребител Памет_данни·포트 разрешение_стойност 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 изпълнявам_команда 상한을 두며 час_стойност 초과는 `Exit: 124`다. потребител CPU 예외는 `128 + изключение индекс`(페이지 ГРЕШКА 142, 특권 위반 141), Java масив_стойност/계산 오류는 101~105다. ядро_стойност 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, 정적 IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP контролна_сума 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- потребител изпълнявам_команда·네트워크·защитавам_стойност 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 изпълнявам_команда·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## проверка 근거

`make test`는 компилатор 14개 시험, Java 패킷 условие 2,201개 검사, 기존 обвивка ELF/ISO 부팅 시험, потребител ELF/действителен_данни UDP/защитавам_стойност 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 길이·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 Команда·무한 спринт_стойност 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
