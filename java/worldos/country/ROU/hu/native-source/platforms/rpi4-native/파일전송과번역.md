## magyar Java를 게스트에서 컴파일하고 AOT végrehajt_parancs

게스트 `vi 빛.java`로 Tovább_cikk 소스를 작성한다.

```java

```

`jaot`은 클래스의 바이트코드를 C로 변환하고, **게스트 TinyCC**가 ARM64 명령어를 generálás·연결한다. végrehajt_parancs 때 JVM 인터프리터를 호출하지 않는다. JAR의 Main-Class가 같은 támogat_ÉRTÉK 범위이면 다음도 가능하다.

```text

run 빛.elf
```

AOT 지원은 한 애플리케이션 클래스의 statikus_ÉRTÉK metódus_ÉRTÉK/mezőérték, int 계열, egész_szám 배열과 hivatkozik, Argumentumok TÖMB_ÉRTÉK, állapot·ág·futam_ÉRTÉK, sztring_ÉRTÉK 리터럴, `System.out.print/println`의 int/String, magyar Kimenet·Fájl Olvasás/쓰기로 제한된다. tanóra_ÉRTÉK/metódus_ÉRTÉK 수와 operandus_Sor 등에도 고정 상한이 있다. Java kivétel folyamat_ÉRTÉK_bejegyzés, objektum_ÉRTÉK generálás, 가상 metódus_ÉRTÉK 일반, switch/wide, long/float/double, invokedynamic, sztring_ÉRTÉK 결합용 StringBuilder, 일반 JDK·Socket·Thread·Swing은 이 AOT 백엔드에서 미지원이다. 내장 NUL/고립된 서로게이트 문자열도 거부한다. 잘못된 TÖMB_ÉRTÉK hozzáfér_bejegyzés/0으로 나누기 등은 네이티브 런타임 오류로 종료하며 Java kivétel 객체로 전달하지 않는다.

bevitel_ÉRTÉK 클래스뿐 아니라 **생성된 ELF도 16 KiB 이하**여야 한다. 기계어 확장과 ELF 페이지 igazít_ÉRTÉK 때문에 짧은 클래스도 이 한도를 넘을 szám 있으며, 이 경우 오류를 내고 기존 출력을 보존한다.

JAR는 하나의 애플리케이션 tanóra_ÉRTÉK 경로다. 내부 Név `köteg/app_f5044b9b.class`와 점으로 구분한 Main-Class를 지원한다. 내부 클래스는 파일로 풀어 VFS 슬롯을 소비하지 않는다. 내장 magyar 클래스를 추가로 찾지만 aktuális_cikk 작업 폴더의 다른 클래스는 자동 혼합하지 않는다. ZIP64·titkosít_adat ZIP·manifest Class-Path·서명 검증은 지원하지 않는다. JAR 하나가 16 KiB 이하이어도 클래스당/적재 szám/VM halommemória_ÉRTÉK 제한은 그대로 적용된다.

`készít_Fájl` 등은 별도의 모의 호출이 아닌 기존 `pk_open` 등의 magyar 매크로이며, ELF의 SVC를 통해 tényleges_adat Java Fájl 체계에 도달한다. Fájl/szoftvercsatorna_ÉRTÉK 호출 목록은 [felhasználó ABI](사용자호출규약.md)에 있다. C/C++ gazda SDK végrehajt_parancs 파일도 FTP로 업로드 후 `run` 또는 `./Fájl`로 실행하며 확장자는 필요 없다. Linux ARM64 statikus_ÉRTÉK ELF에는 별도의 제한된 호환 ÚTVONAL `run --linux Fájl`을 추가했다. ## magyar 네트워크·작업·화면 API

| tanóra_ÉRTÉK | 호출 예 | végrehajt_parancs ÚTVONAL |
|---|---|---|
| `Kimenet` | `ír_sor("안녕")`, `ír_szám(42)` | JVM 및 제한형 AOT |
| `Fájl` | `Írás("문서.txt", "Tartalom_ÉRTÉK")`, `Olvasás("문서.txt")` | JVM 및 제한형 AOT |
| `kommunikáció` | `Megnyitás(0)`, `küld(végpont, "10.0.2.2", 9000, "한글")`, `fogad(végpont)` | JVM의 UDP |
| `ismerős_szállítás` | `Kapcsolódás("10.0.2.2", 9000)`, `figyelés_végpont(9000)`, `fogad(kiszolgáló_ÉRTÉK)` | JVM의 Socket/ServerSocket |
| `작업` | `Futtatás(Runnable)`, `기다리기(Thread)`, `HOZAM_teendő()` | JVM의 협력식 szál_ÉRTÉK |
| `Ablak`, `widget` | Ablak·버튼·karakter_ÉRTÉK·szövegmező·Esemény Kapcsolódás | JVM의 Swing 부분집합 |

명명에서는 표준 영어 API를 보존하고 magyar 호출 계층을 추가한다. `kommunikáció(通信)`, `Kapcsolódás(連結)`, `Kimenet(出力)`은 기존 단어의 뜻을 사용한다. `작업 szál_ÉRTÉK`은 한 végrehajt_parancs 흐름을 가닥에 빗댄 기술 표현, `port_ÉRTÉK`는 포트의 접점을 설명하는 표현이다. 새 기술 결합어를 고대에 이미 존재한 용어처럼 설명하지 않는다. 전체 JDK의 번역을 완료했다고 표시하지 않는다.

külső_ÉRTÉK 주소는 számjegy_ÉRTÉK IPv4이며 QEMU 호스트는 `10.0.2.2`, 게스트는 `10.0.2.15`다. UDP 전문은 512바이트까지다. 소켓은 비차단 saját ABI이며 JVM이 제한된 várj_ÉRTÉK/재시도를 제공한다. TCP connect 대기는 최대 1초, felhasználó app_f5044b9b 전체에는 기존 약 2초 CPU 기한이 적용된다. 일반적인 장기 végrehajt_parancs felhasználó 서버와 pthread는 아직 없다. FTP는 felhasználó app_f5044b9b 기한과 별개인 kernel_ÉRTÉK 서비스다.

게스트의 felhasználó TCP/UDP 서버로 들어오는 연결은 NAT 포트를 추가한다. 예를 들어 `python3 Eszközök/végrehajt_parancs.py --network --forward tcp:9300:9300 --forward udp:9301:9301`로 실행하면 호스트의 localhost 9300/TCP·9301/UDP를 게스트의 같은 포트로 전달한다. FTP의 alapértelmezett_érték vezérlő_ÉRTÉK/데이터 포트와 겹치면 végrehajt_parancs 전에 거부한다.
