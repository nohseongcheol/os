# käyttäjätila 호출 rajattu_alue_ARVO

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `kone/käyttöjärjestelmä_Puhelut.s`에서 EAX(INDEKSI), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 argumentit)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. ydin_ARVO 실패는 음수 VIRHE INDEKSI, C kirjasto 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 käyttäjätila alue_ARVO_0e9a97ab 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C data 주소는 tavu_ARVO 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java tiedoston_nimi 흐름의 어셈블리 경계가 별도 tavu_ARVO 버퍼를 마련하여 같은 호출을 사용한다.

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 OSOITE 두 칸이다. saada_ARVO 주소가 NULL이면 vertaissolmu_ARVO OSOITE 기록을 생략한다. sockaddr_in은 16바이트이며 OSOITE 체계는 laite_ARVO tavu_ARVO JONO_ARVO, 접속번호와 IP 주소는 네트워크 tavu_ARVO 차례다. 축소된 OSOITE 버퍼에도 들어가는 앞부분을 쓰고 전체 OSOITE Koko 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 Lopeta_ohjelma, 2·3은 기존 argumentit 조회다. nykyinen_kohde 커널의 argumentit 목록이 Suorita_komento 이름을 제외하므로 C 진입기는 argv[0]에 고정 merkkijono_ARVO `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX prosessi_ARVO ABI와 다른 점이다.

표준 헤더의 kokonaisluku Koko, 플래그 ARVO, stat kentän_arvo 순서는 `lähdetiedosto/esittelyt/`에 정의한다. 동적 Yhdistä·다중 prosessi_ARVO·스레드가 추가되면 VIRHE INDEKSI 저장과 resurssi_ARVO 수명, 호출 경계도 함께 검토해야 한다.
