# Raspberry Pi 4 자체 Java төш_VALUE — кулланучы үтәргә_команда 기반

현재 자체 코드의 COSL 상업 шарт, 제3자 고지 및 LGPL 재연결 자료는 [COSL 배포 Белешмә_файлы_eb81d7d9](COSL배포안내.md)를 참고한다. SWITCH_MODE 전 GPL 구성의 판단은 [이전 라이선스 검토](라이선스검토.md)에 기록했다.

Татарча 통신·예외 사용법은 [Татарча Java API](한국어자바/Белешмә_файлы_eb81d7d9.md), ФУНКЦИЯ_VALUE·변수·Birem 이름의 변경과 어원 근거는 [명명 Белешмә_файлы_eb81d7d9](명명/Белешмә_файлы_eb81d7d9.md)를 참고한다.

Linux 없이 부팅하는 자체 AArch64 커널이다. Java AOT төш_VALUE 위에 **команда_юлы тышча, 게스트 Java 컴파일러·JVM, MicroPython, EL0 C++ үтәргә_команда, Birem·UDP 루프백 시스템 호출, 여러 한글 GUI Терминал·vi Редактор·Swing 부분집합**을 제공한다. 커널의 Birem мәгълүмат/정책·루프백 күчерү_VALUE_630ba093·тышча 상태는 Java, 화면 합성·нокта үзгәртү_VALUE·күрсәткеч·클리핑도 Java로 구현하며, CPU/MMU/мобиль_VALUE 경계와 Терминал·символ_VALUE_068c2631 그리기 연결은 C와 어셈블리다.

**전체 JDK/JRE·CPython·표준 C++ 런타임·Swing 이식은 아직 완료되지 않았다.** 기존 [ARM64 Linux 실행판](../rpi4/README.md)의 OpenJDK/Python 패키지를 이 자체 커널에 탑재했다고 표시하지 않는다.

새로운 게스트 `cc`/`jaot`, JAR 직접 үтәргә_команда, lwIP TCP/UDP와 FTP는 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)을 참고한다. 게스트 SSH·VNC와 Pi4 GENET/PHY·DHCP 드라이버를 추가했다. **SSH·VNC는 QEMU에서 검증하며, 실물 Pi4의 чыбыклы_VALUE 송수신은 아직 미검증이다.** үтәргә_команда·тоташу_e05f319b·серсүз_VALUE 확인은 [외부 тоташу_e05f319b Белешмә_файлы_eb81d7d9](외부접속안내.md)에 정리했다.

셸은 EL1 төш_VALUE, `java` 등 кулланучы үтәргә_команда 파일은 EL0에서 실행한다.
`ps`·`top`의 표시와 제한, QEMU 네트워크 үтәргә_команда·тоташу_e05f319b 방법 및 фактик_мәгълүмат 검증은
[үтәргә_команда 계층과 외부 통신 점검](실행계층과외부통신점검.md)을 참고한다.

ELF는 확장자가 아닌 фактик_мәгълүмат үтәргә_команда 형식으로 검사한다. `./인사`처럼 확장자 없이 실행하며, 제한된 Linux ARM64 статик_VALUE ELF는 `run --linux файл_исем_СМС`으로 실행한다. [ELF·Linux ABI ярдәм_VALUE 범위와 동일 바이너리 시험](실행파일규약.md).

GUI와 네트워크는 `python3 Кораллар/үтәргә_команда.py --desktop --network`로 함께 사용한다. Java·C·Python의 Татарча 예제 13개는 [jkoros/example](../../example/README.md)에 있으며, **게스트 부팅 시 `/example/java`, `/example/c`, `/example/python`에 자동으로 준비된다.** `example java|c|python`으로 지운 예제를 복원할 수 있다. Remmina에서 **F9/Shift+Space/한·영 ачкыч_VALUE**로 `[EN]`↔`[KO]` 두벌식을 전환한다(`help ko`). `make test-examples`는 같은 GUI VM에서 FTP·фактик_мәгълүмат TCP/UDP·Birem байт_VALUE·그래픽 픽셀을 검증한다.

게스트에서 `cd /example/java` 후 `java 창예제`로 Татарча Swing 예제를 실행한다. Терминал 모서리에 마우스를 대고 **왼쪽 버튼으로 끌면 크기가 바뀐다**. `terminal size`는 현재 COLUMN_VALUE·юл_VALUE_fc48bc81 수를 보여 준다.

## 현재 컴퓨터에서 үтәргә_команда

```sh
cd /home/user/jkoros/platforms/rpi4-native
make test
make run
```

Чыгу_кушымта: **Ctrl+A Киләсе_элемент X**. 게스트 C/AOT Кораллар 빌드에는 `make rpi-prepare`로 준비한 ARM64 SDK 헤더와 libgcc 산술 보조 함수도 필요하다. libc나 Linux 커널을 게스트에 넣는 것은 아니다. хост 도구는 JDK 11 이상, Python 3.6 이상, Clang/Clang++, AArch64 GNU binutils, Make, `libnewlib-dev` 헤더다. MicroPython은 `/usr/include/newlib` 헤더를 사용하며 다른 위치는 `NEWLIB_INCLUDE`로 지정한다. newlib 런타임을 이식·링크한 것은 아니다. 컴파일러 의미 비교에는 GCC/UBSan도 사용한다. 기존 `../rpi4/build/host`의 QEMU 11.0.3이 있으면 이용하며, 그렇지 않으면 PATH의 QEMU를 사용한다. `QEMU_AARCH64=/절대/Yul/qemu-system-aarch64`로 지정할 수도 있다. `raspi4b` ярдәм_VALUE 여부를 확인한 후 실행한다.

명령은 **Enter를 눌러 үтәргә_команда**한다. 기존 한 символ_VALUE_068c2631 명령도 Enter가 필요하다.

```text
javac Hello.java
java Hello "한글 인수 😀"
python hello.py
python -c 'print(2**100)'
ls
cat python.txt
run cpp
net test
gui
```

예를 들어 `edit 인사.java`를 입력한 Киләсе_элемент 아래 소스를 입력한다.

```java
public class 인사 { public static void main(String[] args) { int VALUE = 7; System.out.println("한글=" + VALUE); } }
```

그다음 단독 `.` 줄로 저장하고 `javac 인사.java`, `java 인사`를 실행한다. 편집기는 기존 파일에 커서를 이동하는 방식이 아니라 전체 교체 방식이다. баш_тарту_гамәл·잘못된 16진수·용량 초과는 원본을 보존한다. 줄은 4096바이트, 파일은 16384바이트, үтәргә_команда 인수는 최대 8개·각각 UTF-8 255바이트다. 일반 команда 인수는 최대 32개다. Куштырнаклар·백슬래시·тышча 변수·파이프·리다이렉션 범위는 [тышча 설명](тышча_AND_Терминал.md)을 참고한다.

GUI 터미널은 다음과 같이 실행하고 Remmina에서 **VNC**, адрес **127.0.0.1:5902**로 연결한다. 키보드·한글 Unicode 입력·명시적 өстәү_VALUE·үтәргә_команда 버튼의 마우스 클릭을 QEMU 도구가 UART에 전달한다.

```sh
make desktop
# GUI + 네트워크: python3 Кораллар/үтәргә_команда.py --desktop --network
# 다른 포트: python3 Кораллар/үтәргә_команда.py --desktop --port 5903
```

종료는 실행한 хост 터미널에서 Ctrl+C다. 기존 `python3 Кораллар/үтәргә_команда.py --vnc 127.0.0.1:2`는 화면 보기와 별도 UART 입력을 유지한다. `make run`은 일반 UART 셸이다. фактик_мәгълүмат Pi4 USB 입력기는 아직 없으며, VNC ялгау 도구는 QEMU 시험용이다.

GUI의 다섯 버튼은 фактик_мәгълүмат C++/UDP ELF үтәргә_команда, `Hello.java` төзү_чыганак 후 JVM үтәргә_команда, `hello.py` үтәргә_команда, GUI Терминал 열기를 수행한다. 한 번에 한 프로그램이 CPU에서 실행되며 일반 실행에는 약 2초 기한이 있다. vi·Swing은 интерактив 대기에서 기한을 갱신하고 다른 터미널로 전환할 때 Хәтер_мәгълүмат·CPU 문맥을 보관한다. тышча·편집기에서 입력을 기다리는 시간에는 이 제한이 적용되지 않는다.

| `dist/manifest.json`, `build/build.json` | SHA256과 фактик_мәгълүмат ярдәм_VALUE халәт_VALUE |

이미지는 확인된 공식 Pi 부팅 묶음에서 `start4.elf`, `fixup4.dat`, Pi4 DTB와 disable-bt overlay를 가져온다. Linux kernel/initramfs/rootfs는 넣지 않는다. 펌웨어·MicroPython·Терминал шрифт_VALUE 라이선스와 шрифт_VALUE 출처 해시도 동봉한다. Birem булдыру 스크립트는 물리 디스크에 기록하지 않는다.

예비 microSD에 төзү_IMAGE LOG_юл 도구로 `.img`를 기록하거나 FAT32 부팅 파티션 최상위에 ZIP 내용을 푼다. төзү_IMAGE 기록은 선택한 카드의 기존 내용을 지우므로 대상을 확인한다. Pi4 килешенгәнчә_кыйммәт EEPROM SD 부팅을 전제로 한다. UART는 **3.3V TTL, 115200 8N1**, GPIO14/TXD(8번)→어댑터 RX, GPIO15/RXD(10번)→TX, GND(6번) 연결이다. GPIO에 5V 신호를 연결하지 않는다.

**실물 Pi4 부팅은 미검증이다.** QEMU `-kernel`은 SD의 VideoCore 펌웨어를 실행하지 않고 커널을 직접 적재한다. SD Birem 구성·төш_VALUE 체크섬 검사와 물리 такта 부팅 검증은 별개다. MMU 사용 전에는 펌웨어의 캐시/MMU가 꺼져 있고 EL1 또는 EL2로 진입하는 통상 부팅 조건을 전제로 한다. 세 보조 코어는 대기시키며 한 코어만 사용한다.

## C++와 Татарча API 사용

SDK를 풀고 호스트에서 컴파일한다.

```sh
tar -xzf dist/jkoros-native-aarch64-sdk.tar.gz -C build
cd build/jkoros-native-sdk
python3 compile.py examples/파일예제.cpp -o demo.elf
```

진입점은 `extern "C" int Start_кулланучы_кушымта(int)`이다. кулланучы C++는 FP/SIMD를 사용할 수 있다. төш_VALUE C/Java AOT는 일반 레지스터만 사용하므로 예외 Процесс_VALUE_кертү 중 кулланучы FP 상태를 건드리지 않는다. кулланучы кертү_балл_VALUE 시 FP 상태를 초기화하고 төш_VALUE 복귀에 필요한 상태를 보존한다.

```cpp
#include "파일규약.h"
extern "C" int Start_кулланучы_кушымта(int) {
    int Birem = ачу_файл("인사.txt", укымалы_язмалы | 없으면만들기 | 내용비우기, 0600);
    if (Birem < 0) return 1;
    const char Эчтәлек_VALUE[] = "안녕하세요";
    int үлчәм = язу_файл_мәгълүмат(Birem, Эчтәлек_VALUE, sizeof(Эчтәлек_VALUE) - 1);
    чик_файл(Birem);
    return үлчәм == sizeof(Эчтәлек_VALUE) - 1 ? 0 : 2;
}
```

[Birem 예제](кулланучы/파일예제.cpp)와 [통신 예제](кулланучы/통신예제.cpp)가 фактик_мәгълүмат 부팅 시험 대상이다. `파일규약.h`의 이름은 커널용/사용자용 모두 같지만 **링크하는 라이브러리가 다르다**. 사용자용은 `svc #0`으로 호출하고 Birem Процесс_VALUE_кертү 및 루프백 전달은 Java 커널에서 실행한다. `통신규약.h`의 소켓 함수는 현재 사용자용 라이브러리에 구현돼 있다.

새 프로그램은 төш_VALUE 재빌드 없이 `load FILE.elf`와 `run FILE.elf`로 실행한다. 호스트에서 Киләсе_элемент 도구를 사용하면 **새 QEMU를 부팅해 업로드한 фактик_мәгълүмат 바이트를 재확인한 Артка_VALUE 게스트에서 үтәргә_команда**하고 종료한다. 이 도구의 새 VM에서 만든 RAM 자료는 종료할 때 사라진다.

```sh
cd /home/user/jkoros/platforms/rpi4-native
python3 Кораллар/үтәргә_файл.py build/jkoros-native-sdk/demo.elf
python3 Кораллар/үтәргә_файл.py 예제/Hello.java "한글 인수"
python3 Кораллар/үтәргә_файл.py 예제/hello.py
```

이 경로는 16KiB 이하의 `.elf`, `.java`, `.class`, `.py`를 지원한다. 큰 내장 Java/MicroPython ELF 자체는 төш_VALUE 묶음에 포함되어 이 Birem 한도를 적용받지 않는다. **C++ 컴파일러는 хост SDK의 Clang++**이며 게스트 내부 GCC/Clang 컴파일러는 아직 없다. SDK만으로 일반 Linux 프로그램을 실행할 수는 없다. Linux ELF, 동적 библиотека, PT_TLS, PT_INTERP, PT_DYNAMIC, үтәргә_команда·язу 겸용 세그먼트는 로더가 거부한다. 구체적인 호출 INDEX·адрес клип·오류는 [кулланучы ABI](사용자호출규약.md)를 참고한다.

RAM 파일은 재부팅 시 사라진다. `파일저장확정`은 -1과 ENOSYS를 반환한다. 파일의 mode 인수를 저장하지 않으며 рөхсәт_VALUE·dup/fcntl은 없다. 디렉터리와 тиңдәш_VALUE/절대 경로는 같은 RAM 저장소에서 처리한다. UDP 전문은 최대 512바이트, 소켓은 8개, 수신 큐는 소켓당 4개다. 수신할 자료가 없거나 큐가 가득 차면 EAGAIN을 반환한다. кулланучы Чыгу_кушымта 시 열린 Birem 서술자와 소켓을 회수한다.

## Java와 Python의 정확한 клип

자체 `javac`는 버전 49 `.class`를 생성하며 JVM은 ярдәм_VALUE 명령으로 구성된 버전 45–52 클래스를 실행한다. статик_VALUE ФУНКЦИЯ_VALUE·재귀·int/boolean/char/String·шарт/итерация_VALUE·юл_VALUE_6ca8363c 결합과 일부 Birem 스트림을 지원한다. UTF-8 문자열과 문자 리터럴, ASCII 및 현대 한글 음절/조합 자모 식별자를 처리한다. Unicode күрсәткеч_VALUE 전체 Эзләү_таблица·Unicode чыганак_агач 이스케이프는 구현하지 않았다. 게스트 чыганак_агач 컴파일러는 일반 объект_VALUE·예외·Thread 구문을 아직 컴파일하지 못한다. хост `javac --release 8`로 만든 ярдәм_VALUE 부분집합 클래스는 자체 JVM 0.4의 объект_VALUE·예외·Thread·UDP와 Татарча API를 사용할 수 있다. Swing은 문서화한 자체 API 부분집합을 제공하며 JAR 로더는 제공하지만 전체 AWT/Swing·JDK 표준 라이브러리는 없다. 정확한 범위는 [자체 JVM 설명](자바실행환경.md)이 기준이다. 상세 тел 범위는 [공유 Java Кораллар 설명](../../문서/자바개발환경.md)을 참고하되, 그 문서의 x86 тышча/Store_VALUE/실행시간과 이 ARM64 판의 차이에 유의한다.

MicroPython은 공식 **1.24.1 чыганак_агач**를 자체 AArch64 EL0/SVC 대상으로 빌드했다. Python 문법의 ФУНКЦИЯ_VALUE·класс_VALUE·예외·리스트/сүзлек·Unicode·GC·가변 정밀도 정수를 제공한다. 현재 구성은 бөтен_сан 빌드로 `float`, `complex`, `math`가 없으며 CPython 전체 표준 библиотека, pip, subprocess, threading, 일반 socket과 килешенгәнчә_кыйммәт `open()` Birem 객체는 제공하지 않는다. `python FILE.py` 및 `-c` 실행만 제공하며 REPL은 아직 없다. 각 실행의 объект_VALUE·모듈은 Чыгу_кушымта 시 회수되고 RAM 파일만 Киләсе_элемент 실행에 남는다.

## Татарча 직접 API와 화면 яңарту
