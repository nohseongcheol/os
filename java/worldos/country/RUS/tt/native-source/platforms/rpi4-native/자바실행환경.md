# 자체 ARM64 JVM 0.4와 Татарча библиотека

Татарча 통신·예외 사용법은 [Татарча Java API](한국어자바/Белешмә_файлы_eb81d7d9.md), ФУНКЦИЯ_VALUE·변수·Birem 이름의 변경과 어원 근거는 [명명 Белешмә_файлы_eb81d7d9](명명/Белешмә_файлы_eb81d7d9.md)를 참고한다.

JAR үтәргә_команда, 외부 IPv4 TCP/UDP, 별도 статик_VALUE 부분집합 `jaot`와 게스트 C 컴파일은 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)에 설명한다. 아래 объект_VALUE·Thread·Swing은 JVM 경로의 기능이며 AOT ярдәм_VALUE 범위와 같지 않다.

이 구현은 **Linux 없이 부팅한 Java AOT 커널의 EL0에서 үтәргә_команда**한다. JDK/JRE의 거의 모든 기능을 제공하는 단계는 아직 아니다. HotSpot·OpenJDK класс_VALUE библиотека 전체를 이식하거나 Java SE 인증/TCK를 통과한 구현도 아니다. 이번 확장은 단일 класс_VALUE·статик_VALUE ысул_VALUE 중심이던 실행기를 объект_VALUE·библиотека үтәргә_команда 기반으로 넓힌 것이다.

## 실행과 төзү_чыганак

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
# 자체 төш_VALUE 안에서 чыганак_агач төзү_чыганак → class үтәргә_команда, Татарча API 호출
python3 Кораллар/үтәргә_файл.py 시험/자바/한글소스.java

mkdir -p build/my-java
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/my-java 시험/자바/한글시험.java
python3 Кораллар/үтәргә_файл.py build/my-java/한글시험.class

# 의존 class 파일은 --include로 함께 күчерү_VALUE_630ba093

python3 Кораллар/үтәргә_файл.py build/my-java/객체시험.class \
  --include build/my-java/Фон_VALUE.class --include build/my-java/тармак_VALUE.class \
```

`--include DIR`는 그 디렉터리의 class 파일을 재귀적으로 읽어 `패키지.класс_VALUE.class`라는 RAM Birem 이름으로 전송한다. 주 클래스도 패키지가 있다면 `--class-name 패키지.класс_VALUE`를 지정한다. 셸에서는 해당 이름으로 업로드하고 `java 패키지.класс_VALUE`로 실행한다. JVM 0.4는 Main-Class가 있는 16 KiB 이하 JAR도 `java -jar Birem.jar`로 실행한다. JAR 모드에서는 JAR 내부 클래스와 내장 Татарча 클래스만 찾는다. 배포 Татарча библиотека JAR는 хост javac의 classpath로 사용하며, 같은 클래스가 кулланучы JVM ELF에도 읽기 전용 자료로 포함된다. 일반 class 모드에서는 사용자가 같은 이름으로 올린 RAM class를 먼저 읽는다.

게스트 `javac`는 여전히 статик_VALUE ысул_VALUE, int/boolean/char/String, шарт·итерация_VALUE, юл_VALUE_6ca8363c 결합, 일부 Birem 스트림 등의 **자체 부분집합 컴파일러**다. объект_VALUE 선언·상속·try/catch·Thread 사용 소스를 게스트 javac가 모두 컴파일하는 것은 아니다. 위 기능은 `javac --release 8`로 만든 class를 자체 JVM에서 실행한다. Татарча API 중 출력·문자 스칼라 ФУНКЦИЯ_VALUE·Birem 읽기/쓰기는 게스트 컴파일러에도 연결했다. 다음처럼 전체 이름으로 호출한다.

```java
public class 인사 {
    public static void main(String[] 인수) throws Exception {
        Татарча.자체.출력.язу_юл("안녕하세요😀");
        Татарча.자체.출력.수쓰기(Татарча.자체.문자.символ_коды_COUNT("한글😀"));
        Татарча.자체.Birem.язу("인사.txt", "한글 Birem😀");
        Татарча.자체.출력.язу_юл(Татарча.자체.Birem.읽기("인사.txt"));
    }
}
```

## Татарча API

독립 패키지 **`Татарча.자체`**를 사용한다. Linux판 `Татарча.자바`가 요구하는 NIO/Swing/HTTP API를 자체 커널에서 실행할 수 있다고 혼동하지 않도록 패키지를 나눴다. 이 라이브러리는 класс_VALUE исем·ысул_VALUE·인수·кыр_VALUE·Birem 이름에 한국어를 사용한다. 표준 Java класс_VALUE 이름은 호환성을 위해 보존한다.

| 출력 | язу, язу_юл, 수쓰기 | 출력(出力): 내용을 바깥으로 내보냄 |

## үтәргә_команда 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(Татарча класс_VALUE 포함), class당 16 KiB·константа_VALUE 풀 511항목, 전체 ысул_VALUE/кыр_VALUE 각각 512개. ысул_VALUE CODE_VALUE 8 KiB, локаль_даирә 변수·피연산자 스택 각각 128슬롯, 인수 최대 16개(this 포함).
- VM 가닥은 main 포함 **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 үтәргә_команда 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- объект_VALUE 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 фактик_мәгълүмат 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 Birem·대형 юл_VALUE_6ca8363c·객체가 이 제한을 넘을 수 있다.
- 실행은 50만 바이트코드 команда 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 입력 대기는 기한을 갱신하고 тәрәз SWITCH_MODE 시 중단·재개한다. 일반 сервер_VALUE·계산의 무제한 실행은 아직 없다. 미지원 команда·ресурс_VALUE 부족은 명시적인 오류로 종료한다.
- RAM Birem 최대 64개, 파일당 16384바이트, Yul UTF-8 63바이트. RAM 디렉터리와 тиңдәш_VALUE/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 Татарча class는 RAM Birem 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 현재 경로에서 чыганак_агач·класс_VALUE·мәгълүмат 파일을 읽는다.
- UDP는 Java 루프백 및 lwIP/SLIP를 통한 외부 IPv4를 제공한다. фактик_мәгълүмат GENET/Wi-Fi/DNS/TLS/HTTP 전체는 없다. 전문 512바이트, 소켓 8개, 소켓당 큐 4개. receive는 VM 가닥을 양보하며 대기하고 setSoTimeout을 적용하지만 전체 үтәргә_команда 기한은 여전히 적용된다.
- long/float/double, invokedynamic/람다, enum/annotation, 다차원 МАССИВ_VALUE, 완전한 МАССИВ_VALUE 공변성·인터페이스 дәрәҗә_VALUE 검사, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/шифрлау_мәгълүмат/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. Swing의 별도 ярдәм_VALUE 부분집합은 아래 및 개발 매뉴얼을 참고한다. класс_VALUE Birem 전체 검증기·керү_кертү рөхсәт_VALUE/보호된 멤버 검사는 아직 완전하지 않다. 손상된 입력은 EL0 саклау_VALUE 경계 내에서 종료되도록 한다.

전체 OpenJDK를 목표로 하려면 다음은 별도의 주요 구현 단계다: 완전한 JVM VALUE/тикшерү/класс_VALUE 로더와 예외 모델 → 영속 VFS·mmap·Сәгать·원자 гамәл_VALUE·фактик_мәгълүмат 스레드/синхронлаштыру ABI → OpenJDK java.base 및 native библиотека 이식 → мобиль_VALUE 네트워크·TCP/IP → тәрәз 시스템/шрифт_VALUE/입력기·java.desktop → Java SE 호환성 시험. 현재 자체 JVM의 일부 메서드를 더하는 것으로 이 작업이 완료되지는 않는다.
