# 자체 ARM64 төш_VALUE: FTP, C, JAR와 AOT үтәргә_команда

대상은 **Linux를 적재하지 않는 Raspberry Pi 4용 Java AOT төш_VALUE**이다. CPU·мобиль_VALUE 경계는 C/어셈블리, Birem 체계와 셸은 Java이며, 이번 TCP/IP 스택은 C로 작성된 lwIP 2.2.0을 이식했다. 게스트 TinyCC와 `jaot`도 EL0에서 실행한다. 호스트에 컴파일을 요청하거나 хост JVM으로 대신 실행하지 않는다.

JVM은 класс_VALUE 버전 45…52의 문서화한 부분집합이다. `java`는 바이트코드 실행기이고, `jaot`가 별도의 네이티브 үтәргә_команда 파일을 만든다. **JAR Архив_VALUE 해제나 JVM을 함께 묶는 것을 AOT라고 표시하지 않는다.** 지원하지 않는 바이트코드/API는 `jaot`가 진단하고 출력을 만들지 않는다. 기존 출력 ELF도 төзү_чыганак эштән_туктау_VALUE 때 보존한다.

Android의 Dalvik/ART는 일반 JVM класс_VALUE/JAR가 아닌 **DEX**를 실행한다. ART의 AOT에는 GC, класс_VALUE 로딩, JNI 등 үтәргә_команда 기반도 필요하다. 따라서 ART처럼 기계어로 바꾸는 기능만으로 임의의 OpenJDK JAR 및 Swing이 자동 호환되지는 않는다. [Android 공식 런타임 설명](https://source.android.com/docs/core/runtime)

## Татарча Java를 게스트에서 컴파일하고 AOT үтәргә_команда

게스트 `vi 빛.java`로 Киләсе_элемент 소스를 작성한다.

```java
public class 빛 {
    public static void main(String[] 인수) throws Exception {
        int SUM_VALUE = 0;
        int 수 = 1;
        while (수 <= 10) {
            SUM_VALUE = SUM_VALUE + 수;
            수 = 수 + 1;
        }
        Татарча.자체.출력.수쓰기(SUM_VALUE);
        Татарча.자체.Birem.язу("aot.txt", "한글 AOT Birem 😀");
        Татарча.자체.출력.язу_юл(Татарча.자체.Birem.읽기("aot.txt"));
```


`jaot`은 클래스의 바이트코드를 C로 변환하고, **게스트 TinyCC**가 ARM64 명령어를 булдыру·연결한다. үтәргә_команда 때 JVM 인터프리터를 호출하지 않는다. JAR의 Main-Class가 같은 ярдәм_VALUE 범위이면 다음도 가능하다.

```text
jaot 빛.jar -o 빛.elf
run 빛.elf
```

AOT 지원은 한 애플리케이션 클래스의 статик_VALUE ысул_VALUE/кыр_VALUE, int 계열, бөтен_сан 배열과 Белешмәлекләр, 인수 МАССИВ_VALUE, шарт·тармак·итерация_VALUE, юл_VALUE_6ca8363c 리터럴, `System.out.print/println`의 int/String, Татарча 출력·Birem 읽기/쓰기로 제한된다. класс_VALUE/ысул_VALUE 수와 스택 등에도 고정 상한이 있다. Java 예외 Процесс_VALUE_кертү, объект_VALUE булдыру, 가상 ысул_VALUE 일반, switch/wide, long/float/double, invokedynamic, юл_VALUE_6ca8363c 결합용 StringBuilder, 일반 JDK·Socket·Thread·Swing은 이 AOT 백엔드에서 미지원이다. 내장 NUL/고립된 서로게이트 문자열도 거부한다. 잘못된 МАССИВ_VALUE керү_кертү/0으로 나누기 등은 네이티브 런타임 오류로 종료하며 Java 예외 객체로 전달하지 않는다.

입력 클래스뿐 아니라 **생성된 ELF도 16 KiB 이하**여야 한다. 기계어 확장과 ELF 페이지 тигезләү_VALUE 때문에 짧은 클래스도 이 한도를 넘을 수 있으며, 이 경우 오류를 내고 기존 출력을 보존한다.

게스트 `javac`도 부분집합이다. 일반적인 объект_VALUE·Thread·Swing 소스는 호스트에서 `javac --release 8`로 컴파일하고, **기존 JVM의 ярдәм_VALUE клип 안에서** `java`/`java -jar`로 실행한다. 정확한 API는 [JVM 매뉴얼](자바실행환경.md)과 [한글 개발 매뉴얼](개발안내.md)을 참고한다.

JAR는 하나의 애플리케이션 класс_VALUE 경로다. 내부 исем `пакет/кушымта_f5044b9b.class`와 점으로 구분한 Main-Class를 지원한다. 내부 클래스는 파일로 풀어 VFS 슬롯을 소비하지 않는다. 내장 Татарча 클래스를 추가로 찾지만 현재 작업 폴더의 다른 클래스는 자동 혼합하지 않는다. ZIP64·шифрлау_мәгълүмат ZIP·manifest Class-Path·서명 검증은 지원하지 않는다. JAR 하나가 16 KiB 이하이어도 클래스당/적재 수/VM 힙 제한은 그대로 적용된다.

TinyCC의 표준 C кертү_балл `main`을 사용한다. 기존 хост C/C++ SDK의 `Start_кулланучы_кушымта(int)` 진입점과 구분한다. 포함 Birem·эшләтү объект_VALUE·`libposix-kor-user.a`는 컴파일러 내부의 읽기 전용 SDK에 들어 있다. C 전처리기/구조체/ФУНКЦИЯ_VALUE/재귀/күрсәткеч/부동소수점 булдыру 등을 사용하되 **일반 libc/libstdc++를 제공한다는 뜻은 아니다**. 제공하지 않는 함수는 ялгау 오류가 난다. 컴파일러 자체의 문자/сан_VALUE CONVERT_VALUE 지원도 완전한 libc 대체품이 아니다.

`ачу_файл` 등은 별도의 모의 호출이 아닌 기존 `pk_open` 등의 Татарча 매크로이며, ELF의 SVC를 통해 фактик_мәгълүмат Java Birem 체계에 도달한다. Birem/소켓 호출 목록은 [кулланучы ABI](사용자호출규약.md)에 있다. C/C++ хост SDK үтәргә_команда 파일도 FTP로 업로드 후 `run` 또는 `./Birem`로 실행하며 확장자는 필요 없다. Linux ARM64 статик_VALUE ELF에는 별도의 제한된 호환 Yul `run --linux Birem`을 추가했다. [ELF·Linux ABI 매뉴얼](실행파일규약.md)에 정확한 формат_VALUE·시스템 호출·адрес 제한을 정리했다.

## Татарча 네트워크·작업·화면 API

| класс_VALUE | 호출 예 | үтәргә_команда Yul |
|---|---|---|
| `출력` | `язу_юл("안녕")`, `수쓰기(42)` | JVM 및 제한형 AOT |
| `Birem` | `язу("문서.txt", "Эчтәлек_VALUE")`, `읽기("문서.txt")` | JVM 및 제한형 AOT |
| `통신` | `ачу(0)`, `җибәрү(종단, "10.0.2.2", 9000, "한글")`, `받기(종단)` | JVM의 UDP |
| `연결통신` | `ялгау("10.0.2.2", 9000)`, `듣기(9000)`, `받기(сервер_VALUE)` | JVM의 Socket/ServerSocket |
| `작업` | `эшләтү(Runnable)`, `기다리기(Thread)`, `YIELD_мәсьәлә()` | JVM의 협력식 агым_VALUE_5b72a632 |
| `тәрәз`, `виджет` | тәрәз·버튼·символ_VALUE_068c2631·текст_кыры·вакыйга ялгау | JVM의 Swing 부분집합 |

명명에서는 표준 영어 API를 보존하고 Татарча 호출 계층을 추가한다. `통신(通信)`, `ялгау(連結)`, `출력(出力)`은 기존 단어의 뜻을 사용한다. `작업 агым_VALUE_5b72a632`은 한 үтәргә_команда 흐름을 가닥에 빗댄 기술 표현, `порт_VALUE`는 포트의 접점을 설명하는 표현이다. 새 기술 결합어를 고대에 이미 존재한 용어처럼 설명하지 않는다. 전체 JDK의 번역을 완료했다고 표시하지 않는다.

외부 주소는 сан_VALUE IPv4이며 QEMU 호스트는 `10.0.2.2`, 게스트는 `10.0.2.15`다. UDP 전문은 512바이트까지다. 소켓은 비차단 자체 ABI이며 JVM이 제한된 대기/재시도를 제공한다. TCP connect 대기는 최대 1초, кулланучы кушымта_f5044b9b 전체에는 기존 약 2초 CPU 기한이 적용된다. 일반적인 장기 үтәргә_команда кулланучы 서버와 pthread는 아직 없다. FTP는 кулланучы кушымта_f5044b9b 기한과 별개인 төш_VALUE 서비스다.

게스트의 кулланучы TCP/UDP 서버로 들어오는 연결은 NAT 포트를 추가한다. 예를 들어 `python3 Кораллар/үтәргә_команда.py --network --forward tcp:9300:9300 --forward udp:9301:9301`로 실행하면 호스트의 localhost 9300/TCP·9301/UDP를 게스트의 같은 포트로 전달한다. FTP의 килешенгәнчә_кыйммәт идарә_VALUE/데이터 포트와 겹치면 үтәргә_команда 전에 거부한다.
