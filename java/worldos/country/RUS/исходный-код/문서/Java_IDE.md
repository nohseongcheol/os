# jkoros 안에서 Java компилировать_источник·실행

이 문서의 запуск_машины·оболочка·Store_ЗНАЧЕН 명령은 **x86 версия_ЗНАЧЕН_65c6ecdc** 기준이다. 공유 Java компилятор/JVM은 [свой ARM64 Pi4 версия_ЗНАЧЕН_65c6ecdc](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART входные_данные_ЗНАЧЕН·한글 имя_файла_SMS, `edit`의 단독 `.` Store_ЗНАЧЕН, 16개 RAM файл, 약 2초 실행 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 фактический_данные JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. узел компилировать_источник 서버나 Linux 게스트는 사용하지 않는다.

**текущий_товар 구현은 свой 제한형 компилятор·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java программа_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 실행

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. 실행 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 запуск_машины 절차는 [VirtualBox 실행 файл_сведений_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 файл 전체를 새 내용으로 작성한다. 기존 내용의 строка_ввода правка_ЗНАЧЕН 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 байт_ЗНАЧЕН 수 выпуск_ЗНАЧЕН.
- `cat FILE`: файл контент_ЗНАЧЕН выпуск_ЗНАЧЕН. 텍스트 소스에 사용한다.
- `rm FILE`: Память_данные файл 삭제.
- `edit FILE`: 전체 내용을 새로 входные_данные_ЗНАЧЕН. 빈 파일도 저장할 수 있다.
- 구문·ТИП_ЗНАЧЕН 검사 сбой_ЗНАЧЕН 시 기존 `.class`는 유지된다. 소스를 고친 BACK_ЗНАЧЕН 컴파일이 실패했다면 Назад_товар 실행 파일이 남아 있으므로 компилировать_источник 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 Store_ЗНАЧЕН 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 источник_дерево·Класс_ЗНАЧЕН·данные 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, файл 이름은 ASCII 1~63자다. источник_дерево 이름은 `.class` 확장자 АДРЕС_регион 때문에 최대 62자다. правка_ЗНАЧЕН 입력은 ASCII이고 한 строка_ввода 최대 128자다. строка_ввода 또는 файл 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. ядро_ЗНАЧЕН/компилятор/JVM 구현의 Java 식별자는 한국어이며, текущий_товар 게스트 входные_данные_ЗНАЧЕН 제한 때문에 пространство_пользователя 예제 이름은 ASCII로 작성한다.

## внешний_ЗНАЧЕН файл 적재

호스트에서 만든 소스나 опора_ЗНАЧЕН клип 안의 `.class`를 запуск_машины 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 фактический_данные 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# узел JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 запуск_машины 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 Далее_товар 빌드에서는 добавить_ввод 파일을 포함하지 않는다. файл контент_ЗНАЧЕН 변경과 ввод_Список 제거도 Далее_товар 빌드에 반영된다. 원본 узел 파일에는 쓰지 않는다. значение_по_умолчанию `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 значение_по_умолчанию 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 Класс_ЗНАЧЕН файл 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 опора_ЗНАЧЕН клип 안에 있어야 한다.

## 실행 한도와 ошибка

| ресурс_ЗНАЧЕН | 한도 |
| --- | --- |
| источник_дерево/Класс_ЗНАЧЕН файл | 각각 16KiB |
| компилятор | токен_ЗНАЧЕН 2,047개, генерировать кодовое_значение 4KiB, константа_ЗНАЧЕН 풀 4KiB |
| ФУНКЦИЯ_ЗНАЧЕН/аргументы | 클래스당 32함수, 함수당 16인수 |
| JVM константа_ЗНАЧЕН | 511개 |
| JVM ФУНКЦИЯ_ЗНАЧЕН кодовое_значение | 함수당 8KiB |
| JVM 호출/операнд_стек/локальный_Scope переменная_ЗНАЧЕН | 32프레임, 프레임당 операнд_стек 128칸·локальный_Scope 128칸 |
| JVM объект_ЗНАЧЕН Store_ЗНАЧЕН АДРЕС_регион | 8,192개 32비트 слот_ввод, 헤더 объявления 약 32KiB |
| 실행 | 최대 500,000 команда, 기존 커널의 약 3초 CPU 실행 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 опора_ЗНАЧЕН 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM словарь 검증기를 구현한 것은 아니다. файл/значение_атрибута длина_ЗНАЧЕН, константа_ЗНАЧЕН ссылка, команда·ветвь 경계를 검사하고, 실행 중 операнд_стек формат_ЗНАЧЕН·локальный_Scope инициализировать·МАССИВ_ЗНАЧЕН подстрочный_ЗНАЧЕН·объект_ЗНАЧЕН 참조를 검사한다. пространство_пользователя 코드의 페이지·аппаратный_порт 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, компилировать_источник·JVM 오류는 `Exit: 1`, команда аргументы 오류는 `Exit: 2`다. CPU значение_времени 상한은 기존 `Exit: 124`이며, пространство_пользователя ELF 자체의 CPU/런타임 오류는 기존 Выход_программа 코드를 따른다. сбой_ЗНАЧЕН 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## Java файл входные_данные_выход

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 Класс_ЗНАЧЕН 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 запуск_машины 이미지에 넣은 BACK_ЗНАЧЕН `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. значение_по_умолчанию текстовыйВывод 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. исключение объект_ЗНАЧЕН·try/catch·try-with-resources는 지원하지 않으며 файл 오류를 진단하고 프로그램을 종료한다. МАССИВ_ЗНАЧЕН входные_данные_выход, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 файл 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 оболочка `sync`가 필요하다. 예제의 файл 이름은 текущий_товар 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/испытания/자바파일시험.py`는 фактический_данные 게스트 компилировать_источник 결과를 OpenJDK `-Xverify:all`로 повторить_попытку_ЗНАЧЕН 실행해 файл 바이트와 출력을 대조한다. 범위와 Store_ЗНАЧЕН носители_ЗНАЧЕН 사용법은 [posix-kor файл_сведений_eb81d7d9](../posix-kor/файл_сведений_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
