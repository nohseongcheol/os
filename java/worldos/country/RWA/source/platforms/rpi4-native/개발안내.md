# 자체 커널에서 vi·여러 터미널·한글 프로그래밍 사용하기

Ikinyarwanda 통신·예외 사용법은 [Ikinyarwanda Java API](한국어자바/NSOMA_eb81d7d9.md), FUNCTION_agaciro·변수·Idosiye 이름의 변경과 어원 근거는 [명명 NSOMA_eb81d7d9](명명/NSOMA_eb81d7d9.md)를 참고한다.

대상은 `platforms/rpi4-native`의 자체 AArch64 Java 커널이다. vi와 Java/Python/C/C++ 프로그램은 EL0에서 실행한다. Linux 실행판과 별도이며 아래 Ubufasha_agaciro 목록은 전체 OpenJDK·Vim·POSIX 구현을 뜻하지 않는다.

게스트 `cc`/`jaot`, JAR 직접 gukora_ibwiriza, 외부 TCP/UDP와 FTP는 [새 gukora_ibwiriza 매뉴얼](파일전송과번역.md)을 참고한다.

## GUI와 여러 터미널

```sh
cd /home/user/jkoros/platforms/rpi4-native
make desktop
```

Remmina에서 **VNC**, aderesi **127.0.0.1:5902**로 연결한다. 화면 위 **+ New terminal**, **Ctrl+Shift+T**로 터미널을 추가한다. 최대 네 개다. 위쪽 터미널 버튼 또는 창을 클릭해 선택하고 **F6**으로 순환한다. 제목줄을 끌어서 옮기고 **오른쪽 위 X**를 클릭하면 닫힌다. 마지막 창을 닫아도 위쪽 gukora_ibwiriza 버튼으로 다시 inkingi_agaciro 수 있다. 기존 `terminal`, `exit`, F12도 사용할 수 있다.

창마다 현재 디렉터리, insomamabwiriza 변수, Icyo_wifuza kubika_umurongo, 입력 중인 명령과 porogaramu_f5044b9b gukora_ibwiriza 상태를 보관한다. Idosiye 저장소는 공유한다. vi와 Swing의 이벤트 대기 중에 다른 터미널로 전환하면 ukoresha ububiko_amakurushingiro·레지스터·Idosiye/소켓 연결을 보존했다가 돌아올 때 재개한다. **현재 네 프로그램이 동시에 CPU에서 실행되는 선점형 스케줄러는 아니다.** 계산 중인 프로그램은 다음 입력 대기 또는 기존 gukora_ibwiriza 기한까지 전환이 지연될 수 있다.

X로 터미널을 닫으면 그 터미널의 gukora_ibwiriza 중인 프로그램도 종료하며 서술자·소켓을 회수한다. 저장하지 않은 guhindura_agaciro 내용은 사라진다. 종료한 슬롯은 새 창에서 재사용한다. 현재 모든 파일은 RAM에 있으며 VM 재시작 후에는 남지 않는다.

화면과 idirishya 판단은 게스트 커널이 처리한다. QEMU gukora_ibwiriza 도구는 VNC 키와 마우스 좌표를 UART 패킷으로 전달한다. nyakuri_amakurushingiro Pi4 USB 입력기와 실물 부팅은 아직 검증하지 않았다. 일반 UART 셸은 `make run`, GUI Ibikoresho 종료는 gucumbikira 터미널의 Ctrl+C다.

## Java 네트워크

기존 `DatagramSocket`/`DatagramPacket`의 UDP 루프백에 `Socket`/`ServerSocket`의 **intima_agaciro 내부 연결형 bayiti_agaciro Stream_agaciro**을 추가했다. Idosiye/소켓과 마찬가지로 SVC를 통해 Java 커널이 전송한다. 물리 NIC의 TCP/IP 패킷 스택은 아니다.

```java

java.net.Socket 손님 = new java.net.Socket("localhost", 9250);
java.net.Socket Guhuza = seriveri_agaciro.accept();
손님.getOutputStream().write("안녕하세요".getBytes("UTF-8"));
byte[] 받은것 = new byte[64];
int uburebure_agaciro = Guhuza.getInputStream().read(받은것);
Guhuza.close(); 손님.close(); seriveri_agaciro.close();
```

생성·Guhuza·accept·양방향 bayiti_agaciro/ARRAY_agaciro I_O·close·EOF·setSoTimeout을 지원한다. `String.getBytes()`와 UTF-8 이름을 지정한 getBytes도 제공한다. 루프백 주소는 `localhost`/`127.0.0.1`이다. 연결형 kurangiza_inota 16개, 수신 버퍼당 1024바이트, 대기 Guhuza 최대 4개이며 Java의 대기는 내부 가닥에 실행을 양보한다. agaciro_gasanzweho 시간 제한 0은 별도 소켓 기한을 설정하지 않지만 JVM Icyo_wifuza 수/intima_agaciro gukora_ibwiriza 기한은 여전히 적용된다.

외부 umubare_agaciro IPv4 TCP/UDP는 lwIP/SLIP로 지원한다. nyakuri_amakurushingiro Ethernet/Wi-Fi 드라이버, DNS·TLS·HTTP isomero 전체는 미지원이다. `java.net`의 모든 메서드와 옵션, `SocketChannel`/select, SSL, shutdownInput/Output는 아직 없다. [흐름시험.java](시험/자바/흐름시험.java)는 nyakuri_amakurushingiro 송수신·EOF·기한·Guhuza 회수의 시험 예제다.

`통신규약.h`의 자체 `pk_sockaddr_in`을 사용하며 poti_agaciro·주소는 `망차례짧은수`/`Urusobemiyoboro_umubare_wuzuye`로 변환한다. C 소켓 호출은 비차단이며 amakurushingiro/연결이 없으면 -1과 `오류번호=11`(EAGAIN)을 반환한다. 양수 I_O 결과가 요청보다 작을 수 있으므로 isubiramo_agaciro 처리한다. kudakora_agaciro 후에만 오류번호를 확인한다.

[Stream_agaciro.c](예제/한글코딩/Stream_agaciro.c)는 C에서 Ikinyarwanda 이름으로 Guhuza·accept·부분 읽기/kwandika·큐 포화·EOF를 처리하는 gukora_ibwiriza 예제다. SDK의 `examples/Stream_agaciro.c`를 같은 `compile.py`로 컴파일한다.

SDK는 **libposix-kor-user.a**를 링크한다. 호출 흐름은 C/C++ → nyakuri_amakurushingiro Ikinyarwanda C FUNCTION_agaciro 또는 호환용 `pk_*` → `svc #0` → 커널의 소유권·mwerekana 검사 → Java RAM Idosiye/루프백 또는 외부 lwIP TCP/UDP 구현이다. `libposix-kor-arm64.a`는 intima_agaciro 내부용이므로 EL0 프로그램에 링크하지 않는다. Linux 헤더나 Linux ELF와 혼합하지 않는다. 동적 Guhuza, 표준 C printf, libstdc++/STL, 예외·RTTI는 제공하지 않으며 C++의 kitayega_agaciro 생성자·mu_gace_urwego ikintu_agaciro_2ed200e9 소멸자는 지원한다. 상세 umugerekashakiro·ububiko_amakurushingiro 범위는 [사용자호출규약.md](사용자호출규약.md)를 참고한다.

## Ikinyarwanda 이름으로 직접 작성하는 창과 mugenaporogaramu_agaciro

`example/java/창예제.java`는 `실행할일.gukora_umukoro`,
`동작받이.동작받기(동작알림)`, `buto`, `icyabaye_umurongo_utegererezwaho.나중에실행`, `ihuriro()`을 쓴다.
자체 JVM에 이 이름들의 ikintu_agaciro_2ed200e9·uburyo_agaciro·콜백을 직접 구현했으며 영어 Swing 객체를
보관하는 래퍼가 아니다. `작업가닥`도 자체 스케줄러와 직접 연결된다.
세부 메서드와 기존 Ikinyarwanda API에서의 변경은 [Ikinyarwanda API 문서](한국어자바/NSOMA_eb81d7d9.md)를 본다.

gucumbikira javac는 배포 JAR를 icyiciro_agaciro_55654bf1 경로로 사용한다.

```sh
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/한국어사용 ../../example/java/창예제.java
python3 Ibikoresho/gukora_ibwiriza.py --desktop --network --resolution 1920x1080
```

게스트에는 빌드한 예제가 `/example/java`에 설치된다.

```text

```

직접 화면/mugenaporogaramu_agaciro API와 `ihuriro()` 진입점은 자체 JVM 전용이다.
전체 OpenJDK·Swing 재구현이나 일반 OpenJDK에서 같은 API의 실행을 보장하지 않는다.
기존 표준 `main(String[])` 프로그램은 계속 실행할 수 있다.
