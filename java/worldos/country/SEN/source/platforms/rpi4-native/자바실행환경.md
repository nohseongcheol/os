## def_ndigel 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(한국어 maas_xëyma 포함), class당 16 KiB·Lees_dul_soppi_xëyma 풀 511항목, 전체 doxalin_xëyma/barabu_denc_ab_joxe_xëyma 각각 512개. doxalin_xëyma 코드 8 KiB, dënnd_nameef 변수·피연산자 스택 각각 128슬롯, 인수 최대 16개(this 포함).
- VM 가닥은 main 포함 **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 def_ndigel 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- yëf_xëyma 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 liteew_mbir 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 bara_denc·대형 araf_yu_bennoo_xëyma·객체가 이 제한을 넘을 수 있다.
- 실행은 50만 바이트코드 ndigel 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 입력 대기는 기한을 갱신하고 palanteer jalantu_anam 시 중단·재개한다. 일반 dëggu_xëyma·계산의 무제한 실행은 아직 없다. 미지원 ndigel·Kàttan_xëyma 부족은 명시적인 오류로 종료한다.
- RAM bara_denc 최대 64개, 파일당 16384바이트, Yoonu_jëmale UTF-8 63바이트. RAM 디렉터리와 Nàttangoo_xëyma/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 한국어 class는 RAM bara_denc 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 현재 경로에서 Cosaan_tëralinuy_pàcc·maas_xëyma·mbir 파일을 읽는다.
