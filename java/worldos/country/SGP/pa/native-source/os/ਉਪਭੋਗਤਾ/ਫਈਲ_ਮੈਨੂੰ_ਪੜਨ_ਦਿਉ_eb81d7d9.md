# 셸에서 실행하는 ਉਪਭੋਗਤਾ 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 ਫਈਲ_ਮੈਨੂੰ_ਪੜਨ_ਦਿਉ_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼

ਹੋਸਟ ਟਰਮੀਨਲ 1:

```sh
cd /home/user/jkoros
python3 os/ਸਾਧਨ/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 외부 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

ਹੋਸਟ ਟਰਮੀਨਲ 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 ਅਸਲ_ਸਮੱਗਰੀ CPU ਆਗਿਆ_ਕੀਮਤ `ring 3`, ਆਰਗੂਮੈਂਟ ਆਉਟਪੁੱਟ.
- `netcheck`: ਪੋਰਟ_ਕੀਮਤ 중복, 잘못된 ਸੰਭਾਲਣਾ_ਕੀਮਤ/ਪੌਇੰਟਰ/ਲੰਬਾਈ_ਕੀਮਤ, 비차단 받기와 시간 초과 ਤਸਦੀਕ.
- `udp`: IPv4 ਪਤਾ·ਮੰਜਿਲ_ਕੀਮਤ ਪੋਰਟ_ਕੀਮਤ·한 ਸ਼ਬਦ_ਕੀਮਤ 메시지를 받아 UDP로 보내고 같은 응답을 ਤਸਦੀਕ. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: ਹੋਸਟ `10.0.2.2`의 ਅਸਾਈਨ_ਕਰੋ_ਕੀਮਤ 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 ਲੂਪ_ਕੀਮਤ 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 현재 주소는 게스트 `10.0.2.15/24`, ਗੇਟਵੇ_ਕੀਮਤ `10.0.2.2`로 고정돼 있다. QEMU ਉਪਭੋਗਤਾ 네트워크의 ਹੋਸਟ ਐਕਸੈਸ_ਦਾਖਲਾ 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 ਐਪਲੀਕੇਸ਼_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java ਐਪਲੀਕੇਸ਼_f5044b9b 추가

`예제/내프로그램.java`를 ਅਗਲਾ_ਆਇਟਮ 형식으로 만든다. 진입점은 ਆਰਗੂਮੈਂਟ 없는 `static int` 또는 `static void` 함수다. 인수는 ਉਪਭੋਗਤਾ API로 조회한다.

```java
public final class 내프로그램 {
    public static int ਚਲਾਓ_2() {
        ਉਪਭੋਗਤਾ.ਲਿਖਣ("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/ਉਪਭੋਗਤਾ/ਐਪਲੀਕੇਸ਼_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := ਉਪਭੋਗਤਾ/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.ਚਲਾਓ_2
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `ਉਪਭੋਗਤਾ/선언/ਉਪਭੋਗਤਾ.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 중인 VM에는 ਬਿਲਡ_ਪਰਬੰਧ 결과가 자동 반영되지 않는다. ਐਪਲੀਕੇਸ਼_f5044b9b 이름은 현재 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java ਸ੍ਰੇਣੀ_ਕੀਮਤ·ਫੰਗਸ਼ਨ_ਕੀਮਤ·변수에는 한국어를 쓴다. 최대 32개 ਐਪਲੀਕੇਸ਼_f5044b9b, 한 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.ਚਲਾਓ_2 \
    -o os/build/apps/hello.elf os/ਉਪਭੋਗਤਾ/선언/ਉਪਭੋਗਤਾ.java os/ਉਪਭੋਗਤਾ/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 ਹੋਸਟ 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 ਸਮਰਥਨ_ਕੀਮਤ ਕਲਿਪ 안에서 실행한다. `.jar`와 일반 Linux ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 파일은 지원하지 않는다.

## ਉਪਭੋਗਤਾ 네트워크 API

선언은 `선언/ਉਪਭੋਗਤਾ.java`에 있다. `ਈਮੇਲ_ਸਮੱਗਰੀ`/`자료받기`의 `int[]` ਆਇਟਮ_ਤੱਤ 한 개는 ਬਾਈਟ_ਕੀਮਤ 하나(0~255)를 나타낸다. 한 데이터그램의 최대 ਸਮੱਗਰੀ 길이는 1,024바이트다.

```java
int ਸੰਭਾਲਣਾ_ਕੀਮਤ = ਉਪਭੋਗਤਾ.ਖੋਲੋ_ਨੈਟਵਰਕ(0); // 0: 임시 ਲੋਕਲ_ਗੁੰਜਾਇਸ਼ UDP ਪੋਰਟ_ਕੀਮਤ 자동 ਚੋਣ_ਕੀਮਤ
int[] ਸਮੱਗਰੀ = new int[32];
ਸਮੱਗਰੀ[0] = 'H'; ਸਮੱਗਰੀ[1] = 'i';
int 보낸길이 = ਉਪਭੋਗਤਾ.ਈਮੇਲ_ਸਮੱਗਰੀ(ਸੰਭਾਲਣਾ_ਕੀਮਤ, 0x0a000202, 9000, ਸਮੱਗਰੀ, 2);
int 받은길이 = ਉਪਭੋਗਤਾ.자료받기(ਸੰਭਾਲਣਾ_ਕੀਮਤ, ਸਮੱਗਰੀ, 1500);
ਉਪਭੋਗਤਾ.ਬੰਦ_ਕਰੋ_ਨੈਟਵਰਕ(ਸੰਭਾਲਣਾ_ਕੀਮਤ);
```

ਅਸਲ_ਸਮੱਗਰੀ 프로그램에서는 ਖੋਲ੍ਹੋ·ਈਮੇਲ·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 대기 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 추가 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | ਸੰਭਾਲਣਾ_ਕੀਮਤ·ਕਾਰਵਾਈ_ਕੀਮਤ_ਦਾਖਲਾ ਲੰਬਾਈ_ਕੀਮਤ·성공 등 해당 함수의 ਮਾਪ |
| -5 | ਤਜਵੀਜ_ਕੀਮਤ ਈਮੇਲ_ਕੀਮਤ ਅਸਫਲ_ਕੀਮਤ |
| -9 | 잘못되었거나 닫힌 통신 ਸੰਭਾਲਣਾ_ਕੀਮਤ |
| -11 | 비차단 받기에서 도착한 ਸਮੱਗਰੀ 없음 |
| -14 | ਉਪਭੋਗਤਾ ਪੌਇੰਟਰ/ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ ਕਲਿਪ ਗਲਤੀ |
| -19 | ਸਮਰਥਨ_ਕੀਮਤ NIC 없음 |
| -22 | ਪੋਰਟ_ਕੀਮਤ/대기 시간/ਆਰਗੂਮੈਂਟ ਕੀਮਤ ਗਲਤੀ |
| -24 | 열린 ਨੈਟਵਰਕ_ਪੋਰਟ 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | ਸਮੱਗਰੀ 또는 수신 ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ ਆਕਾਰ 문제 |
| -98 | ਲੋਕਲ_ਗੁੰਜਾਇਸ਼ ਪੋਰਟ_ਕੀਮਤ ਅਨੁਕ੍ਰਮਣਿਕਾ 중복 |
| -101 | 지원하지 않는 ਮੰਜਿਲ_ਕੀਮਤ ਪਤਾ |
| -110 | ARP·ਤਜਵੀਜ_ਕੀਮਤ·수신 시간 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 ਸੁਰੂ_ਤੋਂ_ਗਿਣਨਾ_ਕੀਮਤ 있는 Java `int`의 ਬਿਟ_ਕੀਮਤ 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 경계와 시스템 호출

```text
ਸ਼ੈਲ run → JKAP에서 ELF ਪ੍ਰਮਾਣਿਤ·적재 → ring 3 ਉਪਭੋਗਤਾ ਐਪਲੀਕੇਸ਼_f5044b9b
                                 ↓ int 0x80
                      ਪੌਇੰਟਰ 검사 → Java ਪੱਕੇ_ਹੋਣਾ_ਕੀਮਤ API → RTL8139/UDP
                                 ↓ ਨਿਕਾਸ_ਐਪਲੀਕੇਸ਼·예외·시간 초과
                                ਸ਼ੈਲ 복귀
```

시스템 호출 레지스터는 `EAX=ਅਨੁਕ੍ਰਮਣਿਕਾ`, `EBX,ECX,EDX,ESI,EDI=ਆਰਗੂਮੈਂਟ`, `EAX=ਮਾਪ`다. Java 호출 스택 ABI는 컴파일러가 ਉਪਭੋਗਤਾ 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| ਅਨੁਕ੍ਰਮਣਿਕਾ | 호출 |
| --- | --- |
| 0 | ਨਿਕਾਸ_ਐਪਲੀਕੇਸ਼(ਸਥਿਤੀ_ਕੀਮਤ 코드) — ਚਲਾਓ_2/ਗਲਤੀ 런타임에서 사용 |
| 1 | ਨਿਰਭਰ_ਰਹਿਣ_ਵਾਲਾ_ਕੀਮਤ ਲਿਖਣ |
| 2 / 3 | ਆਰਗੂਮੈਂਟ 개수 / ਆਰਗੂਮੈਂਟ ਨਿਰਭਰ_ਰਹਿਣ_ਵਾਲਾ_ਕੀਮਤ ਪਤਾ |
| 10 | UDP ਖੋਲ੍ਹੋ |
| 11 | UDP ਈਮੇਲ(ਸੰਭਾਲਣਾ_ਕੀਮਤ, IP, ਮੰਜਿਲ_ਕੀਮਤ ਪੋਰਟ_ਕੀਮਤ, ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ ਪਤਾ, ਲੰਬਾਈ_ਕੀਮਤ) |
| 12 | UDP 받기(ਸੰਭਾਲਣਾ_ਕੀਮਤ, ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ ਪਤਾ, 제한 밀리초) |
| 13 | UDP ਬੰਦ_ਕਰੋ |
| 14 | ਲੋਕਲ_ਗੁੰਜਾਇਸ਼ IP ਪਤਾ |
| 15 / 16 | 마지막 ਪਿਅਰ_ਕੀਮਤ IP / UDP ਪੋਰਟ_ਕੀਮਤ |
| 20 | RAM ਫਾਇਲ ਪੜ੍ਹਨ(ਨਾਂ int[] ਪਤਾ, ਆਉਟਪੁੱਟ int[] ਪਤਾ) |
| 21 | RAM ਫਾਇਲ ਲਿਖਣ(ਨਾਂ int[] ਪਤਾ, 입력 int[] ਪਤਾ, ਬਾਈਟ_ਕੀਮਤ ਲੰਬਾਈ_ਕੀਮਤ) |
| 22 | UTF-16 코드 ਪਾਠ_ਕੀਮਤ 문자 ਆਉਟਪੁੱਟ(0~65535) |

ਫਾਇਲ API는 `ਉਪਭੋਗਤਾ.파일읽기(int[] ਨਾਂ, int[] ਸਮੱਗਰੀ)`와 `ਉਪਭੋਗਤਾ.ਲਿੱਖੋ_ਲਿਖਤ_ਪੱਤਰ(int[] ਨਾਂ, int[] ਸਮੱਗਰੀ, int ਲੰਬਾਈ_ਕੀਮਤ)`다. 이름은 ASCII 코드 ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ(최대 64칸, 0 ਨਿਕਾਸ_ਐਪਲੀਕੇਸ਼ 또는 ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ 끝), ਸਮੱਗਰੀ ਆਇਟਮ_ਤੱਤ 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 ਫਾਇਲ 없음 `-2`, ਪੌਇੰਟਰ ਗਲਤੀ `-14`, ਨਾਂ/ਲੰਬਾਈ_ਕੀਮਤ ਗਲਤੀ `-22`, ਫਾਇਲ ਸਲੌਟ_ਕੀਮਤ 부족 `-28`, ਆਕਾਰ 초과 `-90`을 반환한다. 쓰기는 ਪ੍ਰਮਾਣਿਤ 후 ਫਾਇਲ 전체를 대체한다. `ਉਪਭੋਗਤਾ.ਲਿੱਖੋ_ਵਰਣ_ਕੀਮਤ(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 ਉਪਭੋਗਤਾ 모드에서 CS의 하위 비트를 직접 읽으므로 ਅਸਲ_ਸਮੱਗਰੀ ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 권한을 확인한다. ਪੱਕੇ_ਹੋਣਾ_ਕੀਮਤ 포트 접근용 `ਤਜਵੀਜ_ਕੀਮਤ` native 함수는 ਉਪਭੋਗਤਾ ਟੀਚਾ 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼, 파이프, 프로세스 간 통신은 없다. ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 파일은 커널의 ਪੜ੍ਹਨ 전용 JKAP 묶음에서 적재한다. ਸਮੱਗਰੀ 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- ਉਪਭੋਗਤਾ 가상 ਪਤਾ `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 영상은 앞 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. ਪੱਕੇ_ਹੋਣਾ_ਕੀਮਤ identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB ਉਪਭੋਗਤਾ 영역을 비우고 ਫਾਇਲ 구역을 복사해 BSS·ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ 영역을 초기화한다. ਉਪਭੋਗਤਾ GC는 없지만 ਨਿਕਾਸ_ਐਪਲੀਕੇਸ਼ 후 ਅਗਲਾ_ਆਇਟਮ ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 ਹਵਾਲਾ/이스케이프 파싱은 없다.
- ਉਪਭੋਗਤਾ 페이지의 코드/ਸਮੱਗਰੀ 분리 ਪੜ੍ਹਨ 전용 ਸੈਟਿੰਗ, NX, 스택 guard, ASLR은 아직 없다. 커널과 ਉਪਭੋਗਤਾ ਮੈਮਰੀ_ਸਮੱਗਰੀ·포트 ਆਗਿਆ_ਕੀਮਤ 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 상한을 두며 시간 초과는 `Exit: 124`다. ਉਪਭੋਗਤਾ CPU 예외는 `128 + 예외 ਅਨੁਕ੍ਰਮਣਿਕਾ`(페이지 ਗਲਤੀ 142, 특권 위반 141), Java ਤਰਤੀਬ_ਦੇਣਾ_ਕੀਮਤ/계산 오류는 101~105다. ਪੱਕੇ_ਹੋਣਾ_ਕੀਮਤ 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, ਸਥਾਈ_ਕੀਮਤ IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP 검사합 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- ਉਪਭੋਗਤਾ ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼·네트워크·ਰੱਖਿਆ_ਕਰਨੀ_ਕੀਮਤ 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## ਪ੍ਰਮਾਣਿਤ 근거

`make test`는 컴파일러 14개 시험, Java 패킷 ਸ਼ਰਤ 2,201개 검사, 기존 ਸ਼ੈਲ ELF/ISO 부팅 시험, ਉਪਭੋਗਤਾ ELF/ਅਸਲ_ਸਮੱਗਰੀ UDP/ਰੱਖਿਆ_ਕਰਨੀ_ਕੀਮਤ 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 ਲੰਬਾਈ_ਕੀਮਤ·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 ਕਮਾਂਡ·무한 ਦੋਹਰਾਵ_ਕੀਮਤ 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
