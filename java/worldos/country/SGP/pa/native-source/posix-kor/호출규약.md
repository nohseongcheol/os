# ਉਪਭੋਗਤਾ 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `ਮਸ਼ੀਨ/ਸਿਸਟਮ_ਚਲਾਉਣਾ_ਕਾਲਾਂ.s`에서 EAX(ਅਨੁਕ੍ਰਮਣਿਕਾ), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 ਆਰਗੂਮੈਂਟ)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. ਪੱਕੇ_ਹੋਣਾ_ਕੀਮਤ 실패는 음수 ਗਲਤੀ ਅਨੁਕ੍ਰਮਣਿਕਾ, C ਪੁਸਤਕਾਲਾ 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 ਉਪਭੋਗਤਾ 영역 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C ਸਮੱਗਰੀ 주소는 ਬਾਈਟ_ਕੀਮਤ 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java ਫਾਇਲ 흐름의 어셈블리 경계가 별도 ਬਾਈਟ_ਕੀਮਤ 버퍼를 마련하여 같은 호출을 사용한다.

|---|---|---|
| 30 | ਖੋਲੋ_ਲਿਖਤ_ਪੱਤਰ | NUL 끝 ਨਾਂ ਪਤਾ, ਸੈਟਿੰਗ, 허가 |
| 31 | 파일자료읽기 | 서술자, ਸਮੱਗਰੀ ਪਤਾ, ਬਾਈਟ_ਕੀਮਤ 수 |
| 32 | ਲਿੱਖੋ_ਲਿਖਤ_ਪੱਤਰ_ਸਮੱਗਰੀ | 서술자, ਸਮੱਗਰੀ ਪਤਾ, ਬਾਈਟ_ਕੀਮਤ 수 |
| 33 | ਬੰਦ_ਕਰੋ_ਲਿਖਤ_ਪੱਤਰ | 서술자 |

| 39 | ਸੈਟ_ਲਿਖਤ_ਪੱਤਰ_ਲੰਬਾਈ | 서술자, 새 ਲੰਬਾਈ_ਕੀਮਤ |

| 44 | 자료전문받기 | 서술자, ਸਮੱਗਰੀ ਪਤਾ, ਲੰਬਾਈ_ਕੀਮਤ, ਸੈਟਿੰਗ, 요청 ਪਤਾ |
| 45 | 통신주소읽기 | 서술자, sockaddr ਪਤਾ, socklen_t ਪਤਾ |
| 46 | 수신대기정하기 | 서술자, 0~2000 밀리초 |
| 47 | 파일저장확정 | 서술자 |

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 ਪਤਾ 두 칸이다. 수신 주소가 NULL이면 ਪਿਅਰ_ਕੀਮਤ ਪਤਾ 기록을 생략한다. sockaddr_in은 16바이트이며 ਪਤਾ 체계는 ਤਜਵੀਜ_ਕੀਮਤ ਬਾਈਟ_ਕੀਮਤ 차례, 접속번호와 IP 주소는 네트워크 ਬਾਈਟ_ਕੀਮਤ 차례다. 축소된 ਪਤਾ 버퍼에도 들어가는 앞부분을 쓰고 전체 ਪਤਾ ਆਕਾਰ 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 ਨਿਕਾਸ_ਐਪਲੀਕੇਸ਼, 2·3은 기존 ਆਰਗੂਮੈਂਟ 조회다. 현재 커널의 ਆਰਗੂਮੈਂਟ 목록이 ਅਮਲ_ਕਰੋ_ਆਦੇਸ਼ 이름을 제외하므로 C 진입기는 argv[0]에 고정 ਨਿਰਭਰ_ਰਹਿਣ_ਵਾਲਾ_ਕੀਮਤ `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX ਕਾਰਵਾਈ_ਕੀਮਤ ABI와 다른 점이다.

표준 헤더의 ਪੂਰਣ_ਅੰਕ ਆਕਾਰ, 플래그 ਕੀਮਤ, stat ਫਿਲਡ_ਕੀਮਤ 순서는 `ਸਰੋਤ/포함/`에 정의한다. 동적 ਕੁਨੈਕਸ਼ਨ_ਕਰੋ·다중 ਕਾਰਵਾਈ_ਕੀਮਤ·스레드가 추가되면 ਗਲਤੀ ਅਨੁਕ੍ਰਮਣਿਕਾ 저장과 ਸੰਸਾਧਨ_ਕੀਮਤ 수명, 호출 경계도 함께 검토해야 한다.
