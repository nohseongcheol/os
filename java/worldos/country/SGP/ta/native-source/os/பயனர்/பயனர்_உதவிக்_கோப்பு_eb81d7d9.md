# 셸에서 실행하는 பயனர் 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 பயனர்_உதவிக்_கோப்பு_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 இயக்கு_கட்டளை

ஓம்பு கட்டளை_விளக்கி 1:

```sh
cd /home/user/jkoros
python3 os/கருவிகள்/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 외부 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

ஓம்பு கட்டளை_விளக்கி 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 அசல்_தரவு CPU அனுமதி_மதிப்பு `ring 3`, செயலுருபுகள் வெளியீட்டு_இடம்.
- `netcheck`: முணையம்_மதிப்பு 중복, 잘못된 நடத்தி_மதிப்பு/குறிப்பான்/நீளம்_மதிப்பு, 비차단 받기와 நேர_மதிப்பு 초과 சரிபார்.
- `udp`: IPv4 முகவரி·இலக்கு_மதிப்பு முணையம்_மதிப்பு·한 சொல்_மதிப்பு 메시지를 받아 UDP로 보내고 같은 응답을 சரிபார். `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: ஓம்பு `10.0.2.2`의 ஒதுக்கு_மதிப்பு 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 சுழற்சி_மதிப்பு 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 현재 주소는 게스트 `10.0.2.15/24`, நுழைவாயில்_மதிப்பு `10.0.2.2`로 고정돼 있다. QEMU பயனர் 네트워크의 ஓம்பு அணுகு_உள்ளீடு 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 நிரல்_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java நிரல்_f5044b9b 추가

`예제/내프로그램.java`를 அடுத்து_உருப்படி 형식으로 만든다. 진입점은 செயலுருபுகள் 없는 `static int` 또는 `static void` 함수다. 인수는 பயனர் API로 조회한다.

```java
public final class 내프로그램 {
    public static int செயல்படுத்துக() {
        பயனர்.எழுது("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/பயனர்/நிரல்_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := பயனர்/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.செயல்படுத்துக
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `பயனர்/அறிவிப்பு/பயனர்.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 இயக்கு_கட்டளை 중인 VM에는 தொகு_முறைமை 결과가 자동 반영되지 않는다. நிரல்_f5044b9b 이름은 현재 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java பிரிவு_மதிப்பு_55654bf1·செயல்பாடு_மதிப்பு·변수에는 한국어를 쓴다. 최대 32개 நிரல்_f5044b9b, 한 இயக்கு_கட்டளை 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.செயல்படுத்துக \
    -o os/build/apps/hello.elf os/பயனர்/அறிவிப்பு/பயனர்.java os/பயனர்/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 ஓம்பு 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 ஆதரவு_மதிப்பு கிளிப் 안에서 실행한다. `.jar`와 일반 Linux இயக்கு_கட்டளை 파일은 지원하지 않는다.

## பயனர் 네트워크 API

선언은 `அறிவிப்பு/பயனர்.java`에 있다. `அனுப்பு_தரவு`/`자료받기`의 `int[]` உருப்படி_உறுப்பு 한 개는 பைட்_மதிப்பு 하나(0~255)를 나타낸다. 한 데이터그램의 최대 தரவு 길이는 1,024바이트다.

```java
int நடத்தி_மதிப்பு = பயனர்.திற_பிணையம்(0); // 0: 임시 தனி_நோக்கி UDP முணையம்_மதிப்பு 자동 தேர்வு_மதிப்பு
int[] தரவு = new int[32];
தரவு[0] = 'H'; தரவு[1] = 'i';
int 보낸길이 = பயனர்.அனுப்பு_தரவு(நடத்தி_மதிப்பு, 0x0a000202, 9000, தரவு, 2);
int 받은길이 = பயனர்.자료받기(நடத்தி_மதிப்பு, தரவு, 1500);
பயனர்.மூடு_பிணையம்(நடத்தி_மதிப்பு);
```

அசல்_தரவு 프로그램에서는 திற·அனுப்பு·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 காத்திரு_மதிப்பு 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 추가 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | நடத்தி_மதிப்பு·செயலகம்_மதிப்பு_உள்ளீடு நீளம்_மதிப்பு·성공 등 해당 함수의 அளவிடக்கூடியது |
| -5 | சாதனம்_மதிப்பு அனுப்பு_மதிப்பு_f993dacd செயலிழப்பு_மதிப்பு |
| -9 | 잘못되었거나 닫힌 통신 நடத்தி_மதிப்பு |
| -11 | 비차단 받기에서 도착한 தரவு 없음 |
| -14 | பயனர் குறிப்பான்/கோவை_மதிப்பு_ed437109 கிளிப் பிழை |
| -19 | ஆதரவு_மதிப்பு NIC 없음 |
| -22 | முணையம்_மதிப்பு/காத்திரு_மதிப்பு நேர_மதிப்பு/செயலுருபுகள் மதிப்பு பிழை |
| -24 | 열린 பிணையம்_முணையம் 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | தரவு 또는 수신 கோவை_மதிப்பு_ed437109 அளவு 문제 |
| -98 | தனி_நோக்கி முணையம்_மதிப்பு அடைவு 중복 |
| -101 | 지원하지 않는 இலக்கு_மதிப்பு முகவரி |
| -110 | ARP·சாதனம்_மதிப்பு·수신 நேர_மதிப்பு 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 குறியீட்டு_முறை_மதிப்பு 있는 Java `int`의 பிட்_மதிப்பு 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## இயக்கு_கட்டளை 경계와 시스템 호출

```text
கூடு run → JKAP에서 ELF சரிபார்_5fb2b747·적재 → ring 3 பயனர் நிரல்_f5044b9b
                                 ↓ int 0x80
                      குறிப்பான் 검사 → Java கரு_மதிப்பு API → RTL8139/UDP
                                 ↓ முடிவு_நிரல்·விதிவிலக்கு·நேர_மதிப்பு 초과
                                கூடு 복귀
```

시스템 호출 레지스터는 `EAX=அடைவு`, `EBX,ECX,EDX,ESI,EDI=செயலுருபுகள்`, `EAX=அளவிடக்கூடியது`다. Java 호출 스택 ABI는 컴파일러가 பயனர் 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| அடைவு | 호출 |
| --- | --- |
| 0 | முடிவு_நிரல்(நிலை_மதிப்பு_e10195a1 குறியீடு_மதிப்பு) — செயல்படுத்துக/பிழை 런타임에서 사용 |
| 1 | சரம்_மதிப்பு எழுது |
| 2 / 3 | செயலுருபுகள் 개수 / செயலுருபுகள் சரம்_மதிப்பு முகவரி |
| 10 | UDP திற |
| 11 | UDP அனுப்பு(நடத்தி_மதிப்பு, IP, இலக்கு_மதிப்பு முணையம்_மதிப்பு, கோவை_மதிப்பு_ed437109 முகவரி, நீளம்_மதிப்பு) |
| 12 | UDP 받기(நடத்தி_மதிப்பு, கோவை_மதிப்பு_ed437109 முகவரி, 제한 밀리초) |
| 13 | UDP மூடு |
| 14 | தனி_நோக்கி IP முகவரி |
| 15 / 16 | 마지막 பியர்_மதிப்பு IP / UDP முணையம்_மதிப்பு |
| 20 | RAM கோப்பின்_பெயர் படி(பெயர் int[] முகவரி, வெளியீட்டு_இடம் int[] முகவரி) |
| 21 | RAM கோப்பின்_பெயர் எழுது(பெயர் int[] முகவரி, 입력 int[] முகவரி, பைட்_மதிப்பு நீளம்_மதிப்பு) |
| 22 | UTF-16 குறியீடு_மதிப்பு பாடம்_மதிப்பு 문자 வெளியீட்டு_இடம்(0~65535) |

கோப்பின்_பெயர் API는 `பயனர்.파일읽기(int[] பெயர், int[] தரவு)`와 `பயனர்.எழுது_கோப்பு(int[] பெயர், int[] தரவு, int நீளம்_மதிப்பு)`다. 이름은 ASCII குறியீடு_மதிப்பு கோவை_மதிப்பு_ed437109(최대 64칸, 0 முடிவு_நிரல் 또는 கோவை_மதிப்பு_ed437109 끝), தரவு உருப்படி_உறுப்பு 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 கோப்பின்_பெயர் 없음 `-2`, குறிப்பான் பிழை `-14`, பெயர்/நீளம்_மதிப்பு பிழை `-22`, கோப்பின்_பெயர் ஸ்லாட்_மதிப்பு 부족 `-28`, அளவு 초과 `-90`을 반환한다. 쓰기는 சரிபார்_5fb2b747 후 கோப்பின்_பெயர் 전체를 대체한다. `பயனர்.எழுது_எழுத்துக்குறி_மதிப்பு(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 பயனர் 모드에서 CS의 하위 비트를 직접 읽으므로 அசல்_தரவு இயக்கு_கட்டளை 권한을 확인한다. கரு_மதிப்பு 포트 접근용 `சாதனம்_மதிப்பு` native 함수는 பயனர் இலக்கு 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 இயக்கு_கட்டளை, 파이프, 프로세스 간 통신은 없다. இயக்கு_கட்டளை 파일은 커널의 படி 전용 JKAP 묶음에서 적재한다. தரவு 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- பயனர் 가상 முகவரி `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. இயக்கு_கட்டளை 영상은 முன்_மதிப்பு 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. கரு_மதிப்பு identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB பயனர் 영역을 비우고 கோப்பின்_பெயர் 구역을 복사해 BSS·கோவை_மதிப்பு_ed437109 영역을 초기화한다. பயனர் GC는 없지만 முடிவு_நிரல் 후 அடுத்து_உருப்படி இயக்கு_கட்டளை 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 மேற்கோள்_cbe2c532/이스케이프 파싱은 없다.
- பயனர் 페이지의 குறியீடு_மதிப்பு/தரவு 분리 படி 전용 அமைப்புகள், NX, 스택 guard, ASLR은 아직 없다. 커널과 பயனர் நினைவகம்_தரவு·포트 அனுமதி_மதிப்பு 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 இயக்கு_கட்டளை 상한을 두며 நேர_மதிப்பு 초과는 `Exit: 124`다. பயனர் CPU 예외는 `128 + விதிவிலக்கு அடைவு`(페이지 பிழை 142, 특권 위반 141), Java கோவை_மதிப்பு_ed437109/계산 오류는 101~105다. கரு_மதிப்பு 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, மாறா_மதிப்பு IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP சொதனைக்_கணக்கு 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- பயனர் இயக்கு_கட்டளை·네트워크·பாதுகாப்பளி_மதிப்பு 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 இயக்கு_கட்டளை·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## சரிபார்_5fb2b747 근거

`make test`는 컴파일러 14개 시험, Java 패킷 நிபந்தனை 2,201개 검사, 기존 கூடு ELF/ISO 부팅 시험, பயனர் ELF/அசல்_தரவு UDP/பாதுகாப்பளி_மதிப்பு 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 நீளம்_மதிப்பு·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 கட்டளை·무한 மீள்செயல்_மதிப்பு 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
