# 内置 커널의 GUI 터미널과 命令壳

이 터미널은 内置 Java 커널의 셸을 프레임버퍼 창과 UART에서 사용한다. 命令 进程值条目·RAM 文件·파이프는 Java 内核值, 화면의 字符值 그리기는 freestanding C에서 수행한다. Linux·X11·Bash 없이 동작하며, 内置 JVM의 Swing 支持值 부분집합도 같은 窗口 시스템을 이용한다. 자세한 vi·다중 窗口·코딩 사용법은 [开发 매뉴얼](开发指南.md)을 참고한다.

## 当前项目 컴퓨터에서 执行命令

```sh
cd /home/user/jkoros/platforms/rpi4-native
make desktop
```

Remmina에서 **VNC**, 地址 **127.0.0.1:5902**로 연결한다. 终端 창은 자동으로 열린다. 연결한 VNC 창에 키를 입력하면 内置 커널의 셸로 전달된다. 종료하려면 `make desktop`을 실행한 宿主 터미널에서 Ctrl+C를 누른다. 포트를 바꾸려면 构建系统 之后状态 `python3 工具集/执行命令.py --desktop --port 5903`을 사용한다. 서버는 localhost에만 바인드하며 동시에 한 클라이언트가 제어한다.

일반 UART 셸은 `make run`으로 시작한다. QEMU 종료는 Ctrl+A 下一项目 X이다. 같은 VM의 UART에서 `terminal` 또는 F12로 GUI 터미널을 列值 数 있다. `gui` 执行命令 화면에서는 다섯 번째 **OPEN TERMINAL** 버튼, 数字值 5 또는 T로 연다. `--vnc 127.0.0.1:2`만 사용한 기존 执行命令 방식은 屏幕 보기용이며, VNC 키보드를 연결하려면 `--desktop`을 사용한다.

FTP와 外部值 네트워크도 함께 쓰려면 `python3 工具集/执行命令.py --desktop --network`로
실행한다. Remmina VNC는 `127.0.0.1:5902`, 게스트에서 `ftpd start` 之后状态 FTP는
`127.0.0.1:2121`이다. `--port`, `--ftp-port`, `--forward`를 함께 지정할 数 있다.
한 VM의 辅助值 UART로 SLIP를 전송하고 주 UART로 GUI 입력을 전달한다.

QEMU 执行命令 도구가 VNC 키보드/마우스를 UART 입력으로 변환한다. 实际数据 Pi4의 USB 키보드·마우스 드라이버를 구현한 것은 아니다. 实际数据 보드에서는 当前项目 UART 입력이 필요하며 物理硬件 부팅은 아직 미검증이다.

## 창과 输入值

- 640×480~1920×1080 화면에서 最大值 네 개 终端 窗口, 默认值 568×360(68열 × 19행)과 最近值 160행 保留值, 默认值 ANSI 像素颜色·光标值·擦除条目 进程值条目.
- 상단 **+ New terminal** 또는 Ctrl+Shift+T로 새 창을 연다. 제목줄을 끌어 이동하고 窗口/상단 버튼을 클릭하거나 F6으로 전환한다. 각 창의 任务 路径·变量值·命令 日志记录·输入值 중인 줄은 독립적이다.
- UTF-8 韩文文本·CJK·라틴 문자와 일부 이모지 비트맵 字体值. 복잡한 字符 조판·合并值列 字符·양방향 链接布局·모든 Unicode 글리프를 보장하지 않는다.
- 좌우 방향키/Home/End/Delete/Backspace로 명령을 편집하고 위아래 방향키로 最近值 16개 명령을 찾는다. 긴 명령은 输入值 줄을 가로로 이동해 보여 주며 `<`, `>`首位操作数 숨겨진 부분을 나타낸다.
- Tab은 命令 名称 또는 当前项目 디렉터리의 파일명에서 후보가 하나일 때 완성한다. 디렉터리를 포함한 路径 접두사·引号 안의 완성은 아직 없다.
- Ctrl+A/E: 初始项目/结尾, Ctrl+U/K: 光标值 前端值/后端值 삭제, Ctrl+C: 输入值 取消操作. 执行命令 중인 임의 프로그램에 SIGINT를 보내는 기능은 없다. vi와 Swing의 输入值 대기는 执行命令 기한을 갱신하지만 일반 계산의 약 2초 제한은 유지한다.
- PgUp/PgDn 또는 마우스 휠: 上一个项目 输出. 새 출력이 오면 最新值 위치로 돌아온다.
- F12/标题栏 右 버튼/`exit`: 窗口 关闭. 빈 입력에서 Ctrl+D도 창을 닫는다. VM을 종료하는 명령은 아니다.

`--desktop`의 VNC 输入值 연결에 **두벌식 韩文文本 组合**을 제공한다. 접속한 PC의
입력기를 영어로 두고 **F9**, **Shift+Space**, **한/零操作数 键值** 중 하나를 누르면
窗口 제목이 `[EN]`에서 `[KO]`로 바뀐다. `gksrmf` → `韩文文本`,
`dkssudgktpdy` → `안녕하세요`. 같은 키로 영어로 돌아간다.
겹받침·복합 모음과 组合 단계별 Backspace를 지원한다. 光标值 移动值·마우스 单击值·
단축키·粘贴值·Enter 때 조합을 확정한다. PC가 Shift+Space나 한/零操作数 키를
内置 처리하면 **F9**를 사용한다. Alt 단독은 切换模式 키가 아니다.

이 조합기는 QEMU의 VNC→UART 输入值 연결에서 실행된다. 일반 串行值 접속과
物理硬件 Pi의 USB 키보드 입력기에 추가된 기능은 아니다. 이미 완성된 Unicode
韩文文本 키도 그대로 전달한다. 클립보드 공유가 활성화되어 표준 VNC ClientCutText가
도착하면 Ctrl+Shift+V로 붙여 넣는다. 클립보드 동기화만으로 명령을 실행하지 않는다.
줄바꿈을 포함해 명시적으로 붙여 넣으면 해당 줄이 실행된다.

게스트에서 `help` 또는 `help ko`를 입력하면 韩文文本 输入值 안내를 볼 数 있다.
`help`와 `help ko`에는 한/零操作数 键值·Shift+Space·F9 및 `[EN]`/`[KO]` 안내를 표시한다.
긴 도움말은 PgUp/PgDn으로 스크롤한다.

터미널에서 Java·Python·C++ 执行命令 결과를 바로 볼 数 있다. 프로그램이 직접 프레임버퍼에 그림을 그린 경우 退出程序 之后状态 终端 창을 복원한다. vi/Swing 等待状态值 중 다른 창으로 전환하면 해당 EL0 프로그램의 内存数据·레지스터를 보관하고 돌아올 때 재개한다. 选中状态值 复制值·PTY·전체 VT100/xterm 호환과 임의 프로그램의 동시 병렬 실행은 제공하지 않는다. X로 닫으면 해당 창의 프로그램도 종료되므로 vi에서 저장하지 않은 내용은 사라진다.

## 문법과 限制值

작은따옴표·큰따옴표·백슬래시, `$NAME`/`${NAME}`/`$?`, 机器字值 前端值 `~`, 行 주석 `#`, 순차 执行命令 `;`, 条件 执行命令 `&&`/`||`, 파이프 `|`, 输入值 `<`, 새 输出 `>`, 追加条目 输出 `>>`를 제공한다. 变量值 확장은 实参 안에서 수행하며 扩展名值 결과를 공백으로 重试值 나누지 않는다. `export`의 값은 命令壳 안에서만 공유하며 用户 ELF의 envp/getenv 환경은 아직 없다.

파이프는 각 단계를 순서대로 실행하고 最大值 **16384바이트**를 下一项目 단계로 넘긴다. 여러 프로세스가 동시에 읽고 쓰는 POSIX 파이프가 아니다. 容量值 초과는 错误 28과 失败值 상태를 반환하고 해당 실행을 중단한다. `<`는 EOF를 제공하며 `>`/`>>`는 stdout만 바꾼다. EL0 fd 2는 屏幕/UART로 출력된다. `2>` 등 번호를 붙인 리다이렉션은 거부한다. 일부 내장 명령의 진단은 stdout을 사용한다. 연결한 프로그램의 `exit N` 진단은 데이터에 섞이지 않도록 생략한다.

`vi`, `edit`, `load`, `gui`, `terminal`, `sh`, `source`에는 파이프와 리다이렉션을 적용할 数 없다. 리다이렉션 파일을 열지 못하거나 파이프 용량을 초과하면 当前项目 명령줄을 중단하며, 그 줄의 뒤쪽 `||` 명령도 실행하지 않는다. 脚本值 파일을 입력할 때 멀티라인 引号·继续状态值 쓰기는 제공하지 않는다. `if`/`for`/`while`, 函数, 命令 치환, glob, 备用名称, 백그라운드 `&`, jobs/fg/bg, 일반 프로세스·신호·PTY는 아직 없다. Bash/POSIX sh 전체 호환으로 표시하지 않는다.

文件 64개 × 각 16384바이트, 루트 외 디렉터리 15개, 文件 描述符条目 16개, 路径 最大值 UTF-8 63바이트다. 对端值/절대 경로와 `.`/`..`를 정규화하지만 权限值·심볼릭 링크·마운트·디스크 영속 저장은 없다. **文件·디렉터리·变量值·기록의 修改值 내용은 재부팅하면 사라진다.** 用户 실행도 当前项目 命令壳 경로를 사용한다. Java/Python/C++의 文件 API는 같은 RAM 저장소를 본다. `/example`의 三值 语言 예제와 설명서는 부팅할 때 원본으로 준비된다.

한 명령줄은 4096바이트, 구문 词元值 128개, 执行命令 实参 32개, 변수는 16개(名称 31바이트·值 255바이트)까지다. 用户 프로그램에 전달하는 인수는 기존 ABI대로 最大值 8개·각 255바이트다. 命令 기록은 1024바이트 이하 줄을 最近值 16개까지 저장한다.

## 마우스로 大小 更改值

네 모서리의 안쪽 8픽셀에 마우스를 대면 방향에 맞는 대각선 양방향 포인터가
나타난다. **左侧 버튼을 누른 채 끌고 놓는다.** 右 버튼으로는 크기가 바뀌지 않는다.
窗口标题 표시줄의 余数值 부분은 移动值, 右 顶端值 X는 닫기다.
最小值 크기는 360×216이며 最大值 크기는 当前项目 屏幕 안에 제한된다.
각 창의 字符值 칸은 `(宽度跨度-24)/8`列值, `(高度值-56)/16`행이다. `terminal size`로 조회한다.

명령줄의 输入值·光标值·기록과 vi의 미저장 문서를 유지하며 보이는 영역을 갱신한다.
지난 출력은 저장된 行 단위를 유지하고, 좁아진 창에서 가려진 열은 重试值 넓히면
볼 数 있다. 과거 输出 전체를 새 너비에 맞춰 재배열하는 기능은 아니다.
크기를 바꾼 后端值 출력되는 글은 새 列值 수로 줄바꿈한다. vi는 输入值 等待状态值 중에도
SVC 16의 动作 3으로 当前项目 大小(상위 16비트 行值, 하위 16비트 列值)를 조회한다.
交互式 tty의 内核值 屏幕 输出 시간은 用户 计算结果 기한에서 제외하며, 输入值 等待状态值 없이
계산만 반복하는 用户 프로그램의 时间值 제한은 유지한다.
커널이 프레임버퍼에 포인터를 그리며, Remmina 중계는 远程值 포인터를 숨겨 중복을 피한다.
로컬 VNC 중계는 默认值 Raw 인코딩을 사용한다.

有效性校验: `make test-resize` — 640×480·1920×1080에서 네 角值, 左侧/右 버튼,
最小值·最大值 大小, 指针 복원, 输入值 보존, vi 存储值·继续处理 输入值, 창별 크기를 확인한다.
