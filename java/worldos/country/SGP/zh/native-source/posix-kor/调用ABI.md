# 用户 调用 边界位置值

대상은 jkoros i386 ELF32다. Linux i386의 调用 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `计算机/运行系统调用列.s`에서 EAX(编号), EBX·ECX·EDX·ESI·EDI(首位序数~第五序数 实参)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. 内核值 실패는 负数值 错误 编号, C 库 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 用户 区域值 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C 数据 주소는 字节值 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java 文件 흐름의 어셈블리 경계가 별도 字节值 버퍼를 마련하여 같은 호출을 사용한다.

| 编号 | 动作 | 实参 |
|---|---|---|
| 30 | 打开文件 | NUL 结尾 名称 地址, 设置, 授权权限 |
| 31 | 读取文件数据 | 描述符条目, 数据 地址, 字节值 数 |
| 32 | 写入文件数据 | 描述符条目, 数据 地址, 字节值 数 |
| 33 | 关闭文件 | 描述符条目 |
| 34 | 寻道文件 | 描述符条目, 编码状态值 있는 偏移值, 项目根 |
| 35 | 复制副本文件描述符 | 描述符条目 |
| 36 | 复制副本文件描述符位置 | 描述符条目, 새 描述符条目 |
| 37 | 读取文件运行状态 | 描述符条目, 48바이트 状态值 地址 |
| 38 | 移除文件条目名称 | NUL 结尾 名称 地址 |
| 39 | 设定文件长度 | 描述符条目, 새 长度 |
| 40 | 控制文件描述符 | 描述符条目, 命令, 值 |
| 41 | 创建端点 | 地址 运行系统值, 种类值, 契约值 编号 |
| 42 | 绑定地址 | 描述符条目, sockaddr_in 地址, 长度 |
| 43 | 发送数据报数据 | 描述符条目, 数据 地址, 长度, 设置, 申请 地址 |

| 47 | 提交文件存储装置 | 描述符条目 |

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 地址 두 칸이다. 接收值 주소가 NULL이면 对端值 地址 기록을 생략한다. sockaddr_in은 16바이트이며 地址 체계는 设备 字节值 序列值, 접속번호와 IP 주소는 네트워크 字节值 차례다. 축소된 地址 버퍼에도 들어가는 앞부분을 쓰고 전체 地址 大小 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 退出程序, 2·3은 기존 实参 조회다. 当前项目 커널의 实参 목록이 执行命令 이름을 제외하므로 C 진입기는 argv[0]에 고정 字符串 `jkoros-app`을 넣고 之后值 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX 进程值 ABI와 다른 점이다.

표준 헤더의 整数 大小, 标志列值 值, stat 字段值 순서는 `源代码/头文件/`에 정의한다. 동적 连接·다중 进程值·스레드가 추가되면 错误 编号 저장과 资源值 수명, 调用 경계도 함께 검토해야 한다.
