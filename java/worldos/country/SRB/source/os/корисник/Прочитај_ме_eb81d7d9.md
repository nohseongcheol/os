# 셸에서 실행하는 корисник 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 радно_окружење Прочитај_ме_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 Изврши_команда

хост Терминал 1:

```sh
cd /home/user/jkoros
python3 os/Алатке/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. екстерни_вриједност 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

хост Терминал 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 стваран_подаци CPU дозвола_вриједност `ring 3`, Аргументи Излаз.
- `netcheck`: порт_вриједност 중복, 잘못된 хватиште_вриједност/показивач/дужина_вриједност, 비차단 받기와 време_вриједност 초과 потврдити.
- `udp`: IPv4 адреса·одредиште_вриједност порт_вриједност·한 Укрштенице_вриједност 메시지를 받아 UDP로 보내고 같은 응답을 потврдити. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: хост `10.0.2.2`의 Додели_вриједност 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 петља_вриједност 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. актуелно_ставка 주소는 게스트 `10.0.2.15/24`, мрежни_пролаз_вриједност `10.0.2.2`로 고정돼 있다. QEMU корисник 네트워크의 хост приступ_унос 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 програм_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java програм_f5044b9b додати_унос

`예제/내프로그램.java`를 Даље_ставка 형식으로 만든다. 진입점은 Аргументи 없는 `static int` 또는 `static void` 함수다. 인수는 корисник API로 조회한다.

```java
public final class 내프로그램 {
    public static int Покрени() {
        корисник.Пише("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/корисник/програм_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := корисник/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.Покрени
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `корисник/декларација/корисник.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 Изврши_команда 중인 VM에는 градити_систем 결과가 자동 반영되지 않는다. програм_f5044b9b 이름은 актуелно_ставка 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java класа_вриједност·функција_вриједност·변수에는 한국어를 쓴다. 최대 32개 програм_f5044b9b, 한 Изврши_команда 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.Покрени \
    -o os/build/apps/hello.elf os/корисник/декларација/корисник.java os/корисник/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 хост 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 Подршка_вриједност клип 안에서 실행한다. `.jar`와 일반 Linux Изврши_команда 파일은 지원하지 않는다.

## корисник 네트워크 API

선언은 `декларација/корисник.java`에 있다. `послати_подаци`/`자료받기`의 `int[]` ставка_елемент 한 개는 бајт_вриједност 하나(0~255)를 나타낸다. 한 데이터그램의 최대 подаци 길이는 1,024바이트다.

```java
int хватиште_вриједност = корисник.креирати_Мрежа(0); // 0: 임시 локални_обим UDP порт_вриједност 자동 избор_вриједност
int[] подаци = new int[32];
подаци[0] = 'H'; подаци[1] = 'i';
int 보낸길이 = корисник.послати_подаци(хватиште_вриједност, 0x0a000202, 9000, подаци, 2);
int 받은길이 = корисник.자료받기(хватиште_вриједност, подаци, 1500);
корисник.затварање_Мрежа(хватиште_вриједност);
```

стваран_подаци 프로그램에서는 Отвори·послати·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 чекај_вриједност 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 додати_унос 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | хватиште_вриједност·Процес_вриједност_унос дужина_вриједност·성공 등 해당 함수의 ИСХОД |
| -5 | уређај_вриједност послати_вриједност неуспјех_вриједност |
| -9 | 잘못되었거나 닫힌 통신 хватиште_вриједност |
| -11 | 비차단 받기에서 도착한 подаци 없음 |
| -14 | корисник показивач/низ_вриједност клип ГРЕШКА |
| -19 | Подршка_вриједност NIC 없음 |
| -22 | порт_вриједност/чекај_вриједност време_вриједност/Аргументи вриједност ГРЕШКА |
| -24 | 열린 Мрежа_порт 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | подаци 또는 수신 низ_вриједност Величина 문제 |
| -98 | локални_обим порт_вриједност индекс 중복 |
| -101 | 지원하지 않는 одредиште_вриједност адреса |
| -110 | ARP·уређај_вриједност·수신 време_вриједност 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 кодирање_вриједност 있는 Java `int`의 бит_вриједност 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## Изврши_команда 경계와 시스템 호출

```text
љуска run → JKAP에서 ELF потврдити_5fb2b747·적재 → ring 3 корисник програм_f5044b9b
                                 ↓ int 0x80
                      показивач 검사 → Java језгро_вриједност API → RTL8139/UDP
                                 ↓ Излаз_програм·изузетак·време_вриједност 초과
                                љуска 복귀
```

시스템 호출 레지스터는 `EAX=индекс`, `EBX,ECX,EDX,ESI,EDI=Аргументи`, `EAX=ИСХОД`다. Java 호출 операнд_комплет ABI는 컴파일러가 корисник 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| индекс | 호출 |
| --- | --- |
| 0 | Излаз_програм(стање_вриједност шифра_вриједност) — Покрени/ГРЕШКА 런타임에서 사용 |
| 1 | ниска_вриједност Пише |
| 2 / 3 | Аргументи 개수 / Аргументи ниска_вриједност адреса |
| 10 | UDP Отвори |
| 11 | UDP послати(хватиште_вриједност, IP, одредиште_вриједност порт_вриједност, низ_вриједност адреса, дужина_вриједност) |
| 12 | UDP 받기(хватиште_вриједност, низ_вриједност адреса, 제한 밀리초) |
| 13 | UDP Затворен |
| 14 | локални_обим IP адреса |
| 15 / 16 | 마지막 상대 IP / UDP порт_вриједност |
| 20 | RAM Датотека Чита(Назив int[] адреса, Излаз int[] адреса) |
| 21 | RAM Датотека Пише(Назив int[] адреса, 입력 int[] адреса, бајт_вриједност дужина_вриједност) |
| 22 | UTF-16 шифра_вриједност лекција_вриједност 문자 Излаз(0~65535) |

Датотека API는 `корисник.파일읽기(int[] Назив, int[] подаци)`와 `корисник.писати_фајл(int[] Назив, int[] подаци, int дужина_вриједност)`다. 이름은 ASCII шифра_вриједност низ_вриједност(최대 64칸, 0 Излаз_програм 또는 низ_вриједност 끝), подаци ставка_елемент 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 Датотека 없음 `-2`, показивач ГРЕШКА `-14`, Назив/дужина_вриједност ГРЕШКА `-22`, Датотека простор_за_унос_вриједност 부족 `-28`, Величина 초과 `-90`을 반환한다. 쓰기는 потврдити_5fb2b747 후 Датотека 전체를 대체한다. `корисник.писати_знак_вриједност(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 корисник 모드에서 CS의 하위 비트를 직접 읽으므로 стваран_подаци Изврши_команда 권한을 확인한다. језгро_вриједност 포트 접근용 `уређај_вриједност` native 함수는 корисник циљ 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 Изврши_команда, 파이프, 프로세스 간 통신은 없다. Изврши_команда 파일은 커널의 Чита 전용 JKAP 묶음에서 적재한다. подаци 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- корисник 가상 адреса `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. Изврши_команда 영상은 앞 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. језгро_вриједност identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB корисник 영역을 비우고 Датотека 구역을 복사해 BSS·низ_вриједност 영역을 초기화한다. корисник GC는 없지만 Излаз_програм 후 Даље_ставка Изврши_команда 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 Цитат/이스케이프 파싱은 없다.
- корисник 페이지의 шифра_вриједност/подаци 분리 Чита 전용 Поставке, NX, операнд_комплет guard, ASLR은 아직 없다. 커널과 корисник Меморија_подаци·포트 дозвола_вриједност 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 Изврши_команда 상한을 두며 време_вриједност 초과는 `Exit: 124`다. корисник CPU 예외는 `128 + изузетак индекс`(페이지 ГРЕШКА 142, 특권 위반 141), Java низ_вриједност/계산 오류는 101~105다. језгро_вриједност 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, статични_вриједност IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP контролни_збир 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- корисник Изврши_команда·네트워크·заштитити_вриједност 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 Изврши_команда·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## потврдити_5fb2b747 근거

`make test`는 컴파일러 14개 시험, Java 패킷 стање 2,201개 검사, 기존 љуска ELF/ISO 부팅 시험, корисник ELF/стваран_подаци UDP/заштитити_вриједност 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 дужина_вриједност·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 Наредба·무한 спринт_вриједност 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
