# jkoros 안에서 Java направити_извор·Изврши_команда

이 문서의 부팅·љуска·похранити_вриједност 명령은 **x86 верзија_вриједност** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 верзија_вриједност](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 фајл_име_Текст, `edit`의 단독 `.` похранити_вриједност, 16개 RAM Датотека, 약 2초 Изврши_команда 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 стваран_подаци JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. хост направити_извор 서버나 Linux 게스트는 사용하지 않는다.

**актуелно_ставка 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java програм_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 Изврши_команда

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. Изврши_команда 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox Изврши_команда Прочитај_ме_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 Датотека 전체를 새 내용으로 작성한다. 기존 내용의 Ред Уреди_вриједност 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 бајт_вриједност 수 емисија_вриједност.
- `cat FILE`: Датотека Садржај_вриједност емисија_вриједност. 텍스트 소스에 사용한다.
- `rm FILE`: Меморија_подаци Датотека 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·тип_вриједност 검사 неуспјех_вриједност 시 기존 `.class`는 유지된다. 소스를 고친 НАЗАД_вриједност 컴파일이 실패했다면 이전 Изврши_команда 파일이 남아 있으므로 направити_извор 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 похранити_вриједност 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 извор_стабло·класа_вриједност·подаци 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, Датотека 이름은 ASCII 1~63자다. извор_стабло 이름은 `.class` 확장자 공간 때문에 최대 62자다. Уреди_вриједност 입력은 ASCII이고 한 Ред 최대 128자다. Ред 또는 Датотека 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. језгро_вриједност/컴파일러/JVM 구현의 Java 식별자는 한국어이며, актуелно_ставка 게스트 입력 제한 때문에 корисник 예제 이름은 ASCII로 작성한다.

## екстерни_вриједност Датотека 적재

호스트에서 만든 소스나 Подршка_вриједност клип 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 стваран_подаци 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# хост JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 Даље_ставка 빌드에서는 додати_унос 파일을 포함하지 않는다. Датотека Садржај_вриједност 변경과 унос_Листа 제거도 Даље_ставка 빌드에 반영된다. 원본 хост 파일에는 쓰지 않는다. задана_вриједност `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 задана_вриједност 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 класа_вриједност Датотека 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 Подршка_вриједност клип 안에 있어야 한다.

## Подршка_вриједност клип

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| класа_вриједност | 패키지 없는 단일 класа_вриједност, статични_вриједност функција_вриједност, 재귀, Аргументи/вратити_мера | 실행마다 단일 класа_вриједност 적재, public static main(String[]) |
| задана_вриједност вриједност | int, boolean, char, String, main의 String[] Аргументи | цијели_број·Литература операнд_комплет, String, int[], String[], 내부 StringBuilder |
| изјава_вриједност | 초기값 있는 локални_обим декларација, додела_вриједност, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 цијели_број·Литература 바이트코드와 стање грана |
| израз_вриједност | 십진 цијели_број, UTF-8 소스의 ниска_вриједност/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, ниска_вриједност 결합 | цијели_број операција_вриједност·бит_вриједност операција_вриједност·тип_вриједност конвертовати_вриједност, 단락 평가, низ_вриједност приступ_унос |
| Датотека | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | стваран_подаци језгро_вриједност 파일서술자와 Повежи_се, генерисати·обрисати_Садржај·이어쓰기·EOF |
| Излаз | System.out.print/println: int/boolean/char/String, println() | 동일 |
| ниска_вриједност/Аргументи | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), ниска_вриједност 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 локални_обим декларација, 오버로드, 임의 тип_вриједност конвертовати_вриједност, низ_вриједност генерисати ИЗВОР, 8/16진 리터럴, Unicode извор_стабло 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 константа_вриједност 축소 변환을 구현하지 않는다. екстерни_вриједност `.class`의 `int[]` генерисати/Чита/쓰기는 지원하므로 хост `javac --release 8`로 만든 низ_вриједност 예제는 실행할 수 있다.

објекат_вриједност поље_вриједност·일반 објекат_вриједност генерисати·상속·인터페이스·여러 класа_вриједност Повежи_се, long/float/double, изузетак Процес_вриједност_унос, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java изузетак 객체를 던지지 않고 진단 후 актуелно_ставка 프로그램을 종료한다. 객체와 ниска_вриједност похранити_вриједност 공간은 Изврши_команда Излаз_програм 시 корисник 영역 전체와 함께 회수한다. 지속 Изврши_команда 중 GC는 없다.

## Изврши_команда 한도와 ГРЕШКА

| ресурс_вриједност | 한도 |
| --- | --- |
| извор_стабло/класа_вриједност Датотека | 각각 16KiB |
| 컴파일러 | токен_вриједност 2,047개, генерисати шифра_вриједност 4KiB, константа_вриједност 풀 4KiB |
| функција_вриједност/Аргументи | 클래스당 32함수, 함수당 16인수 |
| JVM константа_вриједност | 511개 |
| JVM функција_вриједност шифра_вриједност | 함수당 8KiB |
| JVM 호출/операнд_комплет/локални_обим променљива_вриједност | 32프레임, 프레임당 операнд_комплет 128칸·локални_обим 128칸 |
| JVM објекат_вриједност похранити_вриједност 공간 | 8,192개 32비트 простор_за_унос_унос, 헤더 포함 약 32KiB |
| Изврши_команда | 최대 500,000 Наредба, 기존 커널의 약 3초 CPU Изврши_команда 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 Подршка_вриједност 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM речник 검증기를 구현한 것은 아니다. Датотека/атрибут_вриједност дужина_вриједност, константа_вриједност Литература, Наредба·грана 경계를 검사하고, Изврши_команда 중 операнд_комплет формат_вриједност·локални_обим иницијализовати·низ_вриједност субскрипт_вриједност·објекат_вриједност 참조를 검사한다. корисник 코드의 페이지·포트 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, направити_извор·JVM 오류는 `Exit: 1`, Наредба Аргументи 오류는 `Exit: 2`다. CPU време_вриједност 상한은 기존 `Exit: 124`이며, корисник ELF 자체의 CPU/런타임 오류는 기존 Излаз_програм 코드를 따른다. неуспјех_вриједност 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

- `os/ИЗВОР/Меморија_фајл_систем.java`: Меморија_подаци фајл_систем, Уреди_вриједност, 부팅 Датотека 적재.
- `os/ИЗВОР/체계호출.java`, `compiler/Старт_корисник_програм.s`: Датотека/문자 Излаз API와 корисник показивач 검사.
- `os/Алатке/자바파일묶기.py`: хост 입력 Датотека потврдити_5fb2b747·부팅 Група_вриједност генерисати.


`os/시험/자바시험.py`는 ELF/ISO 부팅, 게스트 направити_извор·Изврши_команда, корисник 입력, 재귀·반복문·цијели_број 극값·ниска_вриједност 결합·단락 평가, 재실행, извор_стабло ГРЕШКА 후 기존 класа_вриједност 보존, низ_вриједност/수 해독 ГРЕШКА, 무한 спринт_вриједност 제한, Уреди_вриједност 넘침과 Датотека 부족을 검사한다. 게스트 генерисати 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 хост OpenJDK의 класа_вриједност, цијели_број 배열과 한글 상수를 게스트에 적재하며, 손상된 Датотека 표식·버전·константа_вриједност 수·грана·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 시험 VM만 생성하고 종료한다.

구현 형식의 참고 подаци: Oracle [JVM класа_вриједност Датотека 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM Наредба 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java Датотека У_И

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 класа_вриједност 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 НАЗАД_вриједност `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. задана_вриједност Излаз 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. изузетак објекат_вриједност·try/catch·try-with-resources는 지원하지 않으며 Датотека 오류를 진단하고 프로그램을 종료한다. низ_вриједност У_И, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 Датотека 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 љуска `sync`가 필요하다. 예제의 Датотека 이름은 актуелно_ставка 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 стваран_подаци 게스트 направити_извор 결과를 OpenJDK `-Xverify:all`로 다시 실행해 Датотека 바이트와 출력을 대조한다. 범위와 похранити_вриједност 매체 사용법은 [posix-kor Прочитај_ме_eb81d7d9](../posix-kor/Прочитај_ме_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
