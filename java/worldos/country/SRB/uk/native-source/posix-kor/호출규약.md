# простір_користувача 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `комп_ютер/операційна_система_ОС_Виклики.s`에서 EAX(індекс), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 аргументи)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. ядро_значення 실패는 음수 ПОМИЛКА індекс, C бібліотека 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 простір_користувача область_значення_0e9a97ab 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C дані 주소는 байт_значення 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java файл 흐름의 어셈블리 경계가 별도 байт_значення 버퍼를 마련하여 같은 호출을 사용한다.

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 Адреса 두 칸이다. отримувати_значення_cef4d8ab 주소가 NULL이면 точка_значення Адреса 기록을 생략한다. sockaddr_in은 16바이트이며 Адреса 체계는 пристрій_значення байт_значення 차례, 접속번호와 IP 주소는 네트워크 байт_значення 차례다. 축소된 Адреса 버퍼에도 들어가는 앞부분을 쓰고 전체 Адреса Розмір 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 Вийти_програма, 2·3은 기존 аргументи 조회다. чинний_елемент 커널의 аргументи 목록이 Виконати_команда 이름을 제외하므로 C 진입기는 argv[0]에 고정 рядок_значення `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX процес_значення ABI와 다른 점이다.

표준 헤더의 ціле_число Розмір, 플래그 значення, stat значення_поля 순서는 `вихіднийКод/оголошення/`에 정의한다. 동적 З_єднання·다중 процес_значення·스레드가 추가되면 ПОМИЛКА індекс 저장과 ресурс_значення 수명, 호출 경계도 함께 검토해야 한다.
