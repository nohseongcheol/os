# 中文 Java 通信·輸入輸出·異常 API

패키지는 `中文.內建`第三操作數. 宿主 `javac --release 8`로 컴파일한 class를
內建 ARM64 커널의 JVM에서 실행한다. 通信·檔案·異常 API는 OpenJDK와 대조한다. 아래의 직접 구현한 屏幕·任務 執行緒值 API는 內建 JVM 전용이다.
기존 표준 Java 庫 전체의 中文 번역판은 아니다.

```java
import 中文.內建.*;

public class 使用網路 {
    public static void main(String[] 實參) throws 輸入輸出異常 {
        連接通道 連接 = 連接通道.打開("10.0.2.2", 9000);
        try {
            連接.超時(700);
            連接.輸出().寫入(字元.編碼("안녕하세요\n"));
            輸入流 輸入值 = 連接.輸入值();
            輸出.寫入編號(輸入值.讀取());
        } catch (等待狀態超時異常 錯誤) {
            輸出.寫入行(錯誤.說明());
        } finally {
            連接.關閉();
        }
    }
}
```

`Socket`, `getOutputStream`, `write`, `getInputStream`, `read`, `close`를
使用者 예제에서 직접 호출할 필요가 없다. `try/catch/throws` 등 Java 문법은 유지한다. `String`은 예약어가 아니라 javac가 字符串 리터럴에 사용하는 표준 클래스다. 內建 실행기는 `public static void 運行()`도 진입점으로 받는다.

## 통신과 流值

| 類別值 | 中文 調用 |
|---|---|
| 連接通道 | `打開(地址, 埠編號)`, `輸入值()`, `輸出()`, `超時(毫秒)`, `埠編號()`, `局部埠編號()`, `已連接()`, `是否已關閉()`, `關閉()` |
| 接收埠 | `打開(埠編號)`, `接收()`, `埠編號()`, `超時(毫秒)`, `是否已關閉()`, `關閉()` |
| 輸入流 | `讀取()`, `讀取(byte[])`, `讀取(byte[], 運行, 長度)`, `關閉()` |
| 輸出流 | `寫入(int)`, `寫入(byte[])`, `寫入(byte[], 運行, 長度)`, `發射值()`, `關閉()` |
| 數據報信道 | `打開(埠編號)`, `發送(地址, 埠編號, 文本)`, `接收()`, `超時(毫秒)`, `埠編號()`, `是否已關閉()`, `關閉()` |
| 連接狀態傳輸 | `打開(...)`, `打開接收者(...)`는 頂端值 中文 객체를 發回結果 |
| 檢查項 | `確認真值(條件, 原因值)` |

TCP 입력은 한 번에 요청한 모든 바이트가 도착한다고 가정하지 않는다.
`讀取()`의 檔案 끝은 -1, 陣列值 읽기의 반환값은 實際資料 읽은 길이다.
네트워크 흐름을 닫으면 연결도 닫힌다. 埠編號 0은 빈 번호를 자동 배정한다.
UDP 전문은 當前項目 內建 커널에서 512바이트까지 받으며, 주소는 數字值 IPv4를 사용한다.
`localhost` 루프백 외의 名稱 풀이(DNS)는 內建 커널에 아직 없다.

기존 `連接狀態傳輸.連接/偵聽端點/接收`, `通信.打開/發送/接收`는 표준 Java 객체를
사용하던 코드와의 연결용이다. 새 코드는 `連接通道`, `接收埠`, `數據報信道`를 쓴다.

## 中文 異常

모든 底端值 클래스는 默認值 생성자, `새예외("說明")` 형태의 字符串 생성자와
`說明()`을 제공한다. 實際資料 生成 문법은 `new 等待狀態超時異常("等待狀態狀態 結尾")`이다.

| 中文 異常 | 상위 類別值 / 용도 |
|---|---|
| 異常 | `java.lang.Exception`, 직접 던지는 일반 檢查項 異常 |
| 執行狀態異常 | `java.lang.RuntimeException` |
| 輸入輸出異常 | `java.io.IOException`, 中文 檔案·通信 API의 檢查項 異常 |
| 等待狀態超時異常 | `輸入輸出異常`, 通信 超時 초과 |
| 地址查找異常 | `輸入輸出異常`, 地址 驗證 失敗值 |
| 缺失檔案異常 | `輸入輸出異常`, 檔案 打開 失敗值 |
| 通信異常 | `輸入輸出異常`, 표준 SocketException 轉換值 |
| 無效實際參數異常 | `java.lang.IllegalArgumentException` |
| 編號格式失敗 | `無效實際參數異常` |
| 邊界異常 | `java.lang.IndexOutOfBoundsException` |
| 陣列邊界異常 / 字符串邊界異常 | `邊界異常` |
| 空引用引用異常 | `java.lang.NullPointerException` |
| 算術失敗 | `java.lang.ArithmeticException` |
| 狀態異常 | `java.lang.IllegalStateException` |
| 類型類型轉換異常 | `java.lang.ClassCastException` |
| 負數陣列大小失敗 | `java.lang.NegativeArraySizeException` |
| 陣列存儲失敗 | `java.lang.ArrayStoreException` |
| 執行緒狀態異常 | `java.lang.IllegalThreadStateException` |
| 等待狀態已中斷異常 | `java.lang.InterruptedException`, `任務.等待`의 等待狀態值 중단 |

`異常`와 `執行狀態異常`는 모든 中文 예외의 公用值 부모가 아니다. 頂端值 상속 관계를
사용하며, 檔案·通信 전체를 잡으려면 `catch (輸入輸出異常 錯誤)`를 쓴다.
中文 API가 표준 輸入輸出 오류를 中文 예외로 변환한다.
기존 中文 通信 호출에서 `SocketTimeoutException`을 잡던 코드는
`等待狀態超時異常`를 잡도록 옮긴다. 표준 `java.net`을 직접 사용하는 코드의
異常 유형은 기존 Java 규약을 따른다.
일반 Java 연산이 자동으로 던지는 표준 예외까지 이름을 바꾸지는 않는다.
예를 들어 `1 / 0`의 ArithmeticException과 직접 만든 산술예외는 서로 다른 형식이다.
當前項目 內建 JVM에 이 20종을 추가했다. 임의의 使用者 Throwable 하위 類別值 전체를
지원하도록 확장했다는 뜻은 아니다.

## 編譯原始碼·執行命令

```sh
cd /home/user/jkoros/platforms/rpi4-native
make 構建系統
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/한국어사용 測試/Java/測試韓語聯網.java
python3 工具集/執行檔案.py build/한국어사용/測試韓語聯網.class
make test-jvm
```

내장 라이브러리는 使用者 JVM ELF 안에 탑재된다. `.jar`는 宿主 javac의
類別值 경로로 사용한다. 原始碼樹 묶음은 `dist/jkoros-native-korean-sources.zip`이다.
게스트의 제한형 `javac`는 中文 예외의 `throws` 선언과 그 import를 인식한다.
內建 JVM의 Thread.interrupt 동작을 새로 구현한 것은 아니다.
try/catch·物件值·通訊端值 範例 전체의 原始碼樹 컴파일은 宿主 javac를 사용한다.
`/example/java/檔案例.java`는 게스트 javac로도 컴파일할 數 있다.

實際資料 TCP/UDP 예제는 [網路例.java](../../../example/java/網路例.java),
執行命令 절차는 [example 指南](../../../example/README.md),
原始碼樹 命名 원칙은 [命名 指南](../命名/指南.md)에 있다.

## Swing 窗口 範例

`/example/java/窗口例.java`와 컴파일된 `.class`首位操作數 啓動 시 준비된다.
`cd /example/java` 下一項目 `java 窗口例`로 연다. 名稱 輸入值, 問候 버튼,
인사말과 單擊值 重複狀態個數 刷新, X 닫기를 지원한다.

| 기능 | 中文 직접 API |
|---|---|
| Runnable / run | `可運行任務任務.執行任務()` |
| ActionListener / actionPerformed | `動作接收者.接收動作(動作通知 通知)` |
| ActionEvent | `動作通知.命令文本()`, `事件原始碼()`, `編號()` |
| JFrame | `窗口(窗口標題, 寬度跨度, 高度值)`, `添加元素(屏幕元素)`, `顯示窗口()`, `關閉()`, `是否可見()` |
| JButton | `按鈕(文本, 水平位置, 垂直位置, 寬度跨度, 高度值, 接收者值)`, `設定動作接收者(接收者值)` |
| JLabel / JTextField | `標籤(...)`, `文本字段(...)` |
| 公用值 屏幕 元素值 | `屏幕元素.讀取文本()`, `寫入文本(文本)`, `設定邊界(水平位置, 垂直位置, 寬度跨度, 高度值)` |
| SwingUtilities.invokeLater | `事件排隊.調用稍後(可運行任務任務)`, `是否事件分派中()` |
| Thread | `後臺任務(可運行任務任務)`, `開始任務()`, `等待()`, `是否存活()`, `掛起任務()` |
| 명령행 | `運行()`, `運行參數.項目個數()`, `運行參數.文本(序數索引)` |

頂端值 클래스들은 `JButton`·`Thread` 등의 객체를 만들거나 보관하지 않는다.
內建 JVM의 `調用韓語屏幕`, `程序執行緒`首位操作數 中文 類別值·方法值·서술자를
해석해 屏幕 요소와 執行命令 가닥을 직접 만든다. 動作 알림도 內建 객체이며
콜백으로 `執行任務`와 `接收動作`를 직접 찾는다. 표준 Swing/Thread를
사용하는 기존 프로그램의 執行命令 경로는 별도로 남아 있다.

Java 소스의 `native` 선언은 內建 JVM에 구현한 계약이다. 생성자의 예외는
이 계약이 없는 宿主 JVM에서 무동작 객체가 생기지 않도록 하는 拒絕值 경로다.
內建 JVM은 생성자를 직접 처리한다. 일반 OpenJDK에서는 이 직접 實現 API를
실행할 數 없다. 宿主 javac로 컴파일한 後端值 內建 JVM에서 실행한다.
`StringUtilities`라는 표준 Swing 클래스는 없으며, 屏幕 큐 기능은 `SwingUtilities`에 해당한다.

```java
import 中文.內建.*;
public class 가닥예제 implements 可運行任務任務 {
    public void 執行任務() { 輸出.寫入行("中文 任務 執行命令"); }
    public static void 運行() throws 等待狀態已中斷異常 {
        後臺任務 執行緒值 = 任務.運行(new 가닥예제());
        任務.等待(執行緒值);
    }
}
```

`example/java`의 다섯 소스는 已保留位單詞列·리터럴 외 식별자를 한국어로 작성한다.
陣列值 實參 대신 `運行參數`, 길이는 `字元.位元組個數`를 사용한다.
표준 Java의 `main(String[])`도 繼續處理 지원한다. 二值 第三操作數 정의되어 있으면
內建 실행기는 實參 없는 `運行()`을 우선한다.
기존 中文 屏幕 래퍼의 표준 `Component`/`Runnable`/`ActionListener` 인수와
`任務.運行(Runnable)`을 사용하던 코드는 새 中文 계약으로 수정하고 재컴파일한다.
이는 전체 AWT/Swing·Thread API 支持值 또는 모든 JDK 소스의 번역을 뜻하지 않는다.

바이트코드에도 類別值·方法值 이름과 서술자가 남는다.
中文 名稱 자체는 합법이지만, 다른 클래스에서 그 이름을 참조하는 子部分值,
상속·方法值 재정의, native 連接, 런처의 진입점도 함께 맞춰야 한다.
근거는 [JLS 標識符值](https://docs.oracle.com/javase/specs/jls/se25/html/jls-3.html#jls-3.8)와
[JVMS 方法值 引用](https://docs.oracle.com/javase/specs/jvms/se25/html/jvms-4.html#jvms-4.4.2)第三操作數.
