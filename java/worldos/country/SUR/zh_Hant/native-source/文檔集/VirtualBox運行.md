# VirtualBox 執行命令

```sh
cd ~/jkoros
make vbox
```

별도로 VM을 만들거나 ISO를 연결할 필요가 없다. 初始項目 실행하면 `os/build/kernel.iso`를 빌드하고 `jkoros operating system`이라는 전용 VM을 만들어 VirtualBox 창으로 부팅한다. `jkoros/os` 안에서도 `make vbox`를 사용할 數 있다.

게스트의 `jkoros>` 프롬프트에서 下一項目 명령을 입력한다.

```text
help
apps
run hello vbox
```

最後項目 명령은 별도 Java ELF를 실행한다. `USER MODE ring 3`, `arg: vbox`, `Exit: 0` 輸出 之後狀態 셸로 돌아오면 정상이다. VGA 화면은 當前項目 ASCII 글꼴만 지원하므로 한글은 `?`로 보이며, 韓文文本 원문은 串行值 기록에서 확인할 數 있다.

## 狀態值 확인과 重試值 執行命令

```sh
make vbox-status
```

이 명령은 VM 狀態值, ISO와 串行值 기록의 절대 경로를 JSON으로 출력한다.

| 當前項目 狀態值 | `make vbox` 動作 |
| --- | --- |
| 아직 생성하지 않음 | ISO 構建系統 → 전용 VM 生成 → 啓動 |
| 擁有已退出 (`poweroff`, `aborted`) | ISO 構建系統 → 광학 介質值 刷新 → 새로 啓動 |
| 執行命令 중 (`running`) | 재빌드·재부팅 없이 當前項目 VM 保持值 |
| 일시정지 (`paused`) | 기존 VM 恢復執行執行狀態 |
| 저장됨 (`saved`) | 上一個項目 串行值 기록을 복사해 보관하고 存儲值 狀態值 恢復執行執行狀態 |
| 存儲值·運行 등 切換模式 중 | 변경하지 않고 任務 是否完成 之後狀態 재실행하도록 指南 |

原始碼樹 변경을 반영하려면 VM을 종료한 下一項目 重試值 `make vbox`를 실행한다. **存儲值 상태를 재개하면 上一個項目 커널이 繼續處理 실행되므로 새 빌드를 반영하지 않는다.** 실행기는 강제 종료하거나 存儲值 상태를 폐기하지 않는다. VirtualBox 창을 닫을 때 사용자가 전원 끄기를 선택하면 記憶體資料 상태가 사라지므로 보존할 작업이 없는지 먼저 확인한다. 게스트의 `halt`는 CPU만 멈추며 VirtualBox의 전원을 끄는 명령은 아니다.

窗口 없는 실행이 필요하면 VM이 꺼져 있을 때 사용한다.

```sh
make vbox VBOX_TYPE=headless
```

執行命令 중인 VM에 重試值 명령을 내려도 GUI/headless 방식은 바뀌지 않는다. 默認值 名稱 대신 다른 이름이 필요하면 **최초 生成 시에만** `VBOX_NAME="원하는 名稱"`을 지정하고 이후에도 같은 값을 사용한다.

## 설정과 資料 보존

- 默認值 설정은 BIOS, 記憶體資料 64MiB, CPU 1개, VGA 記憶體資料 16MiB, IDE 광학 부팅이다. 가상 하드디스크를 만들지 않는다.
- VM 설정은 `.vbox/machines/`, 內容值 검사합별 ISO 사본은 `.vbox/media/`, 串行值 기록은 `.vbox/logs/`에 보관한다. `.vbox/state.json`은 전용 VM의 UUID와 所有者值 표식을 저장한다.
- 꺼진 VM을 부팅할 때 새 串行值 기록을 만든다. 存儲值 狀態值 恢復執行執行狀態 전의 기록은 `before-resume-*.log`로 복사한다. 存儲值 狀態值 자체는 삭제하지 않고 VirtualBox가 그대로 재개한다.
- 같은 이름의 다른 VM을 인수하지 않는다. UUID·設置 路徑·所有者值 표식을 검사하며, 사용자가 별도로 연결한 디스크나 광학 매체를 자동 교체하지 않는다.
- 기존 ISO 사본과 기록은 자동 삭제하지 않는다. `.vbox`는 Git 排除值 대상이다. 용량을 정리할 때도 執行命令·存儲值 상태의 VM이 참조하는 파일과 관리 정보를 임의로 삭제하지 않는다.
- VirtualBox 또는 宿主 드라이버가 없으면 오류를 안내한다. 자동 安裝值, 管理器值 權限值 執行命令, 設備 權限值 변경은 하지 않는다.

## 네트워크 限制值

當前項目 커널의 RTL8139 드라이버는 QEMU에서 사용한다. VirtualBox의 PCnet/E1000 드라이버는 아직 구현하지 않아 이 실행기는 네트워크 장치를 비활성화한다. 셸과 使用者 프로그램은 실행되지만 UDP 열기는 `-19`로 실패한다. UDP 왕복은 `make run`과 [使用者 執行命令·네트워크 指南](../os/使用者/指南.md)의 절차로 시험한다.

## 有效性校驗

`make test-vbox`는 가짜 VirtualBox 응답을 사용하여 새 VM 生成, 執行命令·存儲值·일시정지·切換模式 狀態值, 名稱 충돌, 소유권 불일치, 使用者 介質值 保護值, 構建系統 失敗值, 중단된 生成 恢復狀態, ISO 更改值 감지, 路徑 保護值 등을 검사한다. 實際資料 VM을 만들거나 변경하지 않는다.

2026-09-13에 運行器 單位值 測試 16개가 통과했다. 별도로 實際資料 VirtualBox 5.2.42에서 `make vbox`의 VM 生成·GUI 啓動, `JAVA SELFTEST PASS`, 셸의 `run hello vbox` 실행과 `Exit: 0`, 執行命令 중 재호출 시 재부팅하지 않는 動作 및 `make vbox-status`를 확인했다. 存儲值·일시정지 분기는 單位值 시험으로 검증했다.
