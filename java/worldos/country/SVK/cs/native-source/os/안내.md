# Java 네이티브 operační_systém

이 문서는 기존 **x86 jádro_HODNOTA**을 설명한다. Raspberry Pi 4의 vlastní ARM64 počáteční_stav 이식은 [별도 안내](../platforms/rpi4-native/README.md)를 참고한다. 아래 x86 uživatelský_prostor ELF·네트워크·IDE Store_HODNOTA 기능이 ARM64에 모두 이식된 상태는 아니다.

Java 원문을 vlastní AOT 후단으로 x86 기계어로 컴파일해 부팅하는 작은 운영체제다. 커널과 별도로 vlastní 제한형 Java kompilátor·JVM ELF를 uživatelský_prostor 모드에 적재할 číslo 있다. Linux, engos, koros4와 externí_HODNOTA OpenJDK는 게스트에 적재하지 않는다. spuštění_stroje 진입과 hardware_port/물리 Paměť_oblast 접근은 어셈블리이며, 문자 단말·vstup_HODNOTA Proces_HODNOTA_položka·příkaz parsovat_HODNOTA·작업 oddíl_HODNOTA_366e0bfa 관리는 `zdrojový_soubor/*.java`에 있다.

## 게스트 Java 개발

`javac Hello.java`, `java Hello`로 부팅된 operační_systém 안에서 kompilovat_zdroj·실행한다. `edit FILE.java`와 `.save`로 소스를 작성하며 `ls`, `cat`, `rm`을 제공한다. RAM 파일은 최대 8개, 각각 16KiB이다. 전용 IDE 매체를 연결하면 `sync`로 보존할 číslo 있다. 이 기능은 vlastní 제한형 구현이며 전체 OpenJDK/JDK 호환은 아니다. 사용법·vzpěra_HODNOTA 문법·název_souboru 적재·교차 시험은 [Java 개발 prostředí_5d36e09c](../문서/Java_IDE.md)에 있다. `make test-java`로 검증한다.

## 빌드와 Provést_příkaz

`compiler/`가 요구하는 도구에 더해 ISO 생성에는 `grub-file`, `grub-mkrescue`, GRUB BIOS modul_HODNOTA, `xorriso`가 필요하다. 실행에는 QEMU 또는 VirtualBox가 필요하다. dobrá_zboží 설치된 도구만 사용한다. `make run-store`는 새 전용 가상 Store_HODNOTA 매체를 만들어 연결한다. VirtualBox 실행기는 이 프로젝트가 만든 전용 VM만 설정하고 다른 VM은 변경하지 않는다. 가상 메모리는 výchozí_hodnota 64MiB이며 최소 16MiB가 필요하다.

```sh
cd /home/user/jkoros/os
make                 # build/kernel.elf
make iso             # build/kernel.iso (uživatelský_prostor ELF Skupina_HODNOTA deklarace)
make run             # ELF 직접 spuštění_stroje, 직렬 단말
make run-gui         # GRUB ISO spuštění_stroje, VGA 창과 PS/2 자판
make vbox            # 상위 폴더의 실행기로 전용 VirtualBox VM Provést_příkaz
make vbox-status     # 전용 VirtualBox VM Stav_HODNOTA ověřit
make test            # ELF와 ISO 두 경로의 skutečný_data spuštění_stroje/vstup_HODNOTA zkoušky
make apps            # uživatelský_prostor 프로그램만 BLD_Systém
make test-network    # uživatelský_prostor Provést_příkaz/UDP/chránit_HODNOTA zkoušky
```

`make run`은 QEMU의 직렬 표준 입출력을 쓴다. `Ctrl+A`를 누른 BACK_HODNOTA `X`로 QEMU를 종료할 číslo 있다. `halt`는 게스트 CPU만 정지시키므로 QEMU Okno/프로세스는 별도로 닫는다. 폴링 방식이라 počkej_HODNOTA 중에도 hostit CPU를 사용할 číslo 있다.

VirtualBox는 `make vbox`로 실행한다. 새 전용 VM을 Paměť_data 64MiB, BIOS, 광학 드라이브 부팅으로 자동 설정하며 디스크는 필요 없다. skutečný_data VirtualBox 5.2.42에서 spuštění_stroje, Java vlastní zkoušky, prostředí vstup_HODNOTA, `run hello vbox`의 ring 3 실행과 informační_systémy_normální 종료를 확인했다. dobrá_zboží komunikace 드라이버는 QEMU의 RTL8139 전용이며 VirtualBox의 PCnet/E1000에서는 네트워크를 사용할 číslo 없어 네트워크 장치를 비활성화한다. Store_HODNOTA Stav_HODNOTA 재개와 새 BLD_Systém 반영 방법은 [VirtualBox Provést_příkaz 안내](../문서/가상상자실행.md)에 있다.

## 명시적인 한계

이 커널은 **uživatelský_prostor 프로그램을 한 번에 하나 실행하는 počáteční_stav jádro_HODNOTA**이다. PIT IRQ0만 사용하며 키보드와 NIC는 폴링한다. uživatelský_prostor CPU 예외는 해당 프로그램을 끝내고 셸로 복귀시키지만 jádro_HODNOTA 예외는 중단한다. Provést_příkaz 시간은 약 3초로 제한한다. 완전한 선점 다중 Proces_HODNOTA 스케줄러, FAT/ext 등 일반 디스크 systém_souborů, TCP·DNS·DHCP·IPv6·HTTP, 전체 POSIX, 일반 objekt_HODNOTA 모델/GC는 아직 없다. 전용 IDE název_souboru 보존과 POSIX název_souboru/UDP 일부 기능은 구현했다. JVM은 RAM 파일의 단일 클래스를 Provést_příkaz 시 적재하며 일반 ClassLoader나 JAR 로딩은 지원하지 않는다. 네이티브 Provést_příkaz 파일은 BLD_Systém 시 Čtení 전용 묶음에 넣으며, 일반 Linux ELF를 실행하는 환경이 아니다. 기존 `../starší_verze_zdroj/`의 JVM 관리 jádro_HODNOTA 전체를 이식한 것도 아니다.

Java 식별자는 한국어다. 직렬 출력은 이 프로젝트의 한글(BMP 문자)을 UTF-8로 표시한다. VGA는 výchozí_hodnota ASCII 글꼴만 사용하므로 한글 자리에 `?`가 나온다. příkaz 입력도 dobrá_zboží ASCII만 지원하며 한글 písmo_HODNOTA·입력기 및 보조 평면 문자 출력은 후속 작업이다. `test`는 작은 배열을 새로 할당하고 GC가 없으므로 무한 반복하지 않는다.

## 자동 zkoušky

`zkoušky/부팅시험.py`는 디스크 없는 독립 QEMU를 생성해 다음을 검증하고 종료한다.

- ELF 직접 spuštění_stroje 및 GRUB ISO spuštění_stroje.
- Java vlastní 시험과 UTF-8 직렬 문구.
- příkaz zobrazit_nápovědu·Informace_o_systému·Paměť_data·výstupní_pozice·chyba vstup_HODNOTA·화면 vymazat_položka.
- 작업 oddíl_HODNOTA_366e0bfa 8개 přidělit_Storage, 부족 Proces_HODNOTA_položka, Vratka_KV/중복 Vratka_KV/재할당.
- 직렬 줄바꿈·백스페이스·긴 vstup_HODNOTA Proces_HODNOTA_položka.
- QEMU PS/2 Klíč_HODNOTA 입력으로 `info` Provést_příkaz, `halt` 정지.

성공 로그는 `build/부팅시험.json`에 남는다. 로컬 Unix 소켓을 금지하는 샌드박스에서는 zkoušky 도구에 해당 권한이 필요하다. zkoušky 도중 새로 만든 QEMU만 종료하며 기존 VM과 skutečný_data 디스크는 건드리지 않는다.

`zkoušky/test_uživatel_síť.py`는 ELF/ISO 각각에서 uživatelský_prostor ELF, skutečný_data ring 3, argumenty, hostit 루프백 UDP 왕복, 1,023/1,024바이트 24회 연속 왕복, časová_hodnota 초과, NIC 없음, Paměť_data/hardware_port přístup_položka 차단, CPU výjimka, 무한 sprint_HODNOTA, 잘못된 ELF를 시험한다. `build/test_uživatel_síť.json`에 게스트 기록과 호스트가 받은 데이터의 délka_HODNOTA·해시를 저장한다. `zkoušky/paket_test.py`는 skutečný_data Java hodnota_smlouvy 처리기에 손상된 패킷을 넣어 2,201개 mez_HODNOTA/kontrolní_součet 조건을 검사한다. hostit 루프백 외 externí_HODNOTA 서버에는 zkoušky 트래픽을 보내지 않는다.

부트 경계는 GNU의 [Multiboot 명세](https://www.gnu.org/software/grub/manual/multiboot/multiboot.html)를 따른다.

새 Soubor_popisovač·C ABI·IDE Store_HODNOTA·Java název_souboru 흐름의 범위와 čeština 명명 대응은 [posix-kor 안내](../posix-kor/안내.md)에 있다. `make test-posix`로 ELF/ISO 실행과 재부팅 보존을 검증한다.
