# Java 네이티브 operačný_systém

이 문서는 기존 **x86 jadro_VALUE**을 설명한다. Raspberry Pi 4의 vlastné ARM64 počiatočný_stav 이식은 [별도 안내](../platforms/rpi4-native/README.md)를 참고한다. 아래 x86 používateľ ELF·네트워크·IDE Store_VALUE 기능이 ARM64에 모두 이식된 상태는 아니다.

Java 원문을 vlastné AOT 후단으로 x86 기계어로 컴파일해 부팅하는 작은 운영체제다. 커널과 별도로 vlastné 제한형 Java kompilátor·JVM ELF를 používateľ 모드에 적재할 수 있다. Linux, engos, koros4와 externý_VALUE OpenJDK는 게스트에 적재하지 않는다. 부팅 진입과 hardvér_port/물리 Pamäť_oblasť 접근은 어셈블리이며, 문자 단말·vstup_VALUE Proces_VALUE_položka·Príkaz analyzovať_VALUE·작업 sekcia_VALUE 관리는 `ZDROJ/*.java`에 있다.

## 게스트 Java 개발

`javac Hello.java`, `java Hello`로 부팅된 operačný_systém 안에서 kompilovať_zdroj·실행한다. `edit FILE.java`와 `.save`로 소스를 작성하며 `ls`, `cat`, `rm`을 제공한다. RAM 파일은 최대 8개, 각각 16KiB이다. 전용 IDE 매체를 연결하면 `sync`로 보존할 수 있다. 이 기능은 vlastné 제한형 구현이며 전체 OpenJDK/JDK 호환은 아니다. 사용법·Podpora_VALUE 문법·Súbor 적재·교차 시험은 [Java 개발 환경](../문서/자바개발환경.md)에 있다. `make test-java`로 검증한다.

## 빌드와 Vykonať_príkaz

`compiler/`가 요구하는 도구에 더해 ISO 생성에는 `grub-file`, `grub-mkrescue`, GRUB BIOS modul_VALUE, `xorriso`가 필요하다. 실행에는 QEMU 또는 VirtualBox가 필요하다. v_termíne_splatnosti_položka 설치된 도구만 사용한다. `make run-store`는 새 전용 가상 Store_VALUE 매체를 만들어 연결한다. VirtualBox 실행기는 이 프로젝트가 만든 전용 VM만 설정하고 다른 VM은 변경하지 않는다. 가상 메모리는 predvolená_hodnota 64MiB이며 최소 16MiB가 필요하다.

```sh
cd /home/user/jkoros/os
make                 # build/kernel.elf
make iso             # build/kernel.iso (používateľ ELF Skupina_VALUE 포함)
make run             # ELF 직접 부팅, 직렬 단말
make run-gui         # GRUB ISO 부팅, VGA 창과 PS/2 자판
make vbox            # 상위 폴더의 실행기로 전용 VirtualBox VM Vykonať_príkaz
make vbox-status     # 전용 VirtualBox VM Stav_VALUE overiť
make test            # ELF와 ISO 두 경로의 skutočný_údaje 부팅/vstup_VALUE 시험
make apps            # používateľ 프로그램만 zostava_systém
make test-network    # používateľ Vykonať_príkaz/UDP/chrániť_VALUE 시험
```

`make run`은 QEMU의 직렬 표준 입출력을 쓴다. `Ctrl+A`를 누른 BACK_VALUE `X`로 QEMU를 종료할 수 있다. `halt`는 게스트 CPU만 정지시키므로 QEMU Okno/프로세스는 별도로 닫는다. 폴링 방식이라 počkaj_VALUE 중에도 hostiteľ CPU를 사용할 수 있다.

VirtualBox는 `make vbox`로 실행한다. 새 전용 VM을 Pamäť_údaje 64MiB, BIOS, 광학 드라이브 부팅으로 자동 설정하며 디스크는 필요 없다. skutočný_údaje VirtualBox 5.2.42에서 부팅, Java vlastné 시험, 셸 vstup_VALUE, `run hello vbox`의 ring 3 실행과 정상 종료를 확인했다. v_termíne_splatnosti_položka 통신 드라이버는 QEMU의 RTL8139 전용이며 VirtualBox의 PCnet/E1000에서는 네트워크를 사용할 수 없어 네트워크 장치를 비활성화한다. Store_VALUE Stav_VALUE 재개와 새 zostava_systém 반영 방법은 [VirtualBox Vykonať_príkaz 안내](../문서/가상상자실행.md)에 있다.

## 명시적인 한계

이 커널은 **používateľ 프로그램을 한 번에 하나 실행하는 počiatočný_stav jadro_VALUE**이다. PIT IRQ0만 사용하며 키보드와 NIC는 폴링한다. používateľ CPU 예외는 해당 프로그램을 끝내고 셸로 복귀시키지만 jadro_VALUE 예외는 중단한다. Vykonať_príkaz 시간은 약 3초로 제한한다. 완전한 선점 다중 Proces_VALUE 스케줄러, FAT/ext 등 일반 디스크 systém_súborov, TCP·DNS·DHCP·IPv6·HTTP, 전체 POSIX, 일반 objekt_VALUE 모델/GC는 아직 없다. 전용 IDE Súbor 보존과 POSIX Súbor/UDP 일부 기능은 구현했다. JVM은 RAM 파일의 단일 클래스를 Vykonať_príkaz 시 적재하며 일반 ClassLoader나 JAR 로딩은 지원하지 않는다. 네이티브 Vykonať_príkaz 파일은 zostava_systém 시 Čítanie 전용 묶음에 넣으며, 일반 Linux ELF를 실행하는 환경이 아니다. 기존 `../starší_zdroj/`의 JVM 관리 jadro_VALUE 전체를 이식한 것도 아니다.

Java 식별자는 한국어다. 직렬 출력은 이 프로젝트의 한글(BMP 문자)을 UTF-8로 표시한다. VGA는 predvolená_hodnota ASCII 글꼴만 사용하므로 한글 자리에 `?`가 나온다. Príkaz 입력도 v_termíne_splatnosti_položka ASCII만 지원하며 한글 písmo_VALUE·입력기 및 보조 평면 문자 출력은 후속 작업이다. `test`는 작은 배열을 새로 할당하고 GC가 없으므로 무한 반복하지 않는다.

## 자동 시험

`시험/부팅시험.py`는 디스크 없는 독립 QEMU를 생성해 다음을 검증하고 종료한다.

- ELF 직접 부팅 및 GRUB ISO 부팅.
- Java vlastné 시험과 UTF-8 직렬 문구.
- Príkaz zobraziť_Pomocník·Systémové_informácie·Pamäť_údaje·Výstup·chyba vstup_VALUE·화면 vymazať_položka.
- 작업 sekcia_VALUE 8개 vyhradiť_Úložisko, 부족 Proces_VALUE_položka, vrátiť_KR/중복 vrátiť_KR/재할당.
- 직렬 줄바꿈·백스페이스·긴 vstup_VALUE Proces_VALUE_položka.
- QEMU PS/2 Kľúč_VALUE 입력으로 `info` Vykonať_príkaz, `halt` 정지.

성공 로그는 `build/부팅시험.json`에 남는다. 로컬 Unix 소켓을 금지하는 샌드박스에서는 시험 도구에 해당 권한이 필요하다. 시험 도중 새로 만든 QEMU만 종료하며 기존 VM과 skutočný_údaje 디스크는 건드리지 않는다.

`시험/test_používateľ_sieť.py`는 ELF/ISO 각각에서 používateľ ELF, skutočný_údaje ring 3, Argumenty, hostiteľ 루프백 UDP 왕복, 1,023/1,024바이트 24회 연속 왕복, čas_VALUE 초과, NIC 없음, Pamäť_údaje/hardvér_port prístup_položka 차단, CPU výnimka, 무한 šprint_VALUE, 잘못된 ELF를 시험한다. `build/test_používateľ_sieť.json`에 게스트 기록과 호스트가 받은 데이터의 dĺžka_VALUE·해시를 저장한다. `시험/paket_test.py`는 skutočný_údaje Java prípad_VALUE 처리기에 손상된 패킷을 넣어 2,201개 경계/kontrolný_súčet 조건을 검사한다. hostiteľ 루프백 외 externý_VALUE 서버에는 시험 트래픽을 보내지 않는다.

부트 경계는 GNU의 [Multiboot 명세](https://www.gnu.org/software/grub/manual/multiboot/multiboot.html)를 따른다.

새 파일서술자·C ABI·IDE Store_VALUE·Java Súbor 흐름의 범위와 Slovenský 명명 대응은 [posix-kor 안내](../posix-kor/안내.md)에 있다. `make test-posix`로 ELF/ISO 실행과 재부팅 보존을 검증한다.
