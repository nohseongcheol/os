# ELF 형식과 Linux Vykonať_príkaz Súbor 호환성

**ELF는 확장자가 아니다.** Executable and Linkable Format이라는 바이너리
형식이며, Linux 외의 운영체제도 사용한다. 첫 네 Byte_VALUE `7f 45 4c 46`,
ELF lekcia_VALUE, CPU 종류, program_f5044b9b 헤더와 položka_bod_VALUE 주소를 읽어서 해석한다.
[ELF ABI 명세](https://gabi.xinuos.com/elf/02-eheader.html)

기존 jkoros 로더도 skutočný_údaje ELF64/AArch64 Vykonať_príkaz 파일을 읽었다. `.elf`는 예제의
이름일 뿐이었다. 다만 **ELF formát_VALUE 지원과 Linux 시스템 호출 ABI 지원은 별개**다.
기존에는 `JKOROS` ABI note를 가진 vlastné Vykonať_príkaz 파일만 허용했고, Linux 바이너리는
호환되지 않았다. ARM64 Linux는 SVC의 x8에 Linux 시스템 호출 번호를 넣는다.
같은 번호를 vlastné ABI로 해석하면 다른 동작이 되므로 두 경로를 구분한다.
[Linux syscall ABI 설명](https://man7.org/linux/man-pages/man2/syscall.2.html)

## 이번 반영

| vstup_VALUE | Vykonať_príkaz 방법 | Podpora_VALUE klip |
|---|---|---|
| vlastné ABI의 ARM64 ELF | `./인사`, `/작업/인사`, `run 인사` | 확장자 없이 Vykonať_príkaz; 내용이 ELF이면 `.txt`라는 이름도 동일 |
| Linux ARM64 정적 ELF | `run --linux 리눅스인사 한글인수` | 아래 시스템 호출·adresa·Veľkosť 제한을 만족하는 program_f5044b9b |
| 텍스트를 `.elf`로 이름만 zmeniť_VALUE | Vykonať_príkaz odmietnuť_VALUE | 확장자로 Vykonať_príkaz 파일을 인정하지 않음 |
| x86/x86-64, ARM32 Vykonať_príkaz Súbor | Vykonať_príkaz odmietnuť_VALUE | AArch64 전용이며 CPU inštrukcia_VALUE kompilátor_nástroj 없음 |
| 일반 glibc/musl program_f5044b9b, PIE, 공유 knižnica | 아직 미지원 | 동적 로더·재배치·TLS·mmap·시그널 등 Pripojiť_položka 이식 필요 |

vlastné 바이너리와 JAR의 셸 직접 실행은 Súbor 헤더로 구분한다. `run`은 vlastné ELF,
`run --linux`는 명시적으로 Linux ABI를 선택한다. Linux 바이너리를 자동으로
vlastné ABI에 넣지 않으며, vlastné ABI note가 있는 파일은 Linux 모드에서 거부한다.
v_termíne_splatnosti_položka RAM Súbor 체계에는 Vykonať_príkaz povolenie_VALUE 비트와 `chmod`, PATH 검색이 없다.

게스트 C kompilovať_zdroj 예:

```text
cc 인사.c -o 인사
./인사
run 인사
```

`posix-kor`는 이 vlastné ABI 경로로 연결한다. 일반 Linux에서 링크한 프로그램에
Slovenský funkcia_VALUE 이름을 붙이는 것만으로 vlastné ABI 호환이 되는 것은 아니다.

## 제한된 Linux ABI

이 기능은 **vlastné Java jadro_VALUE 안의 호환 vrstva_VALUE**이며 Linux 커널을 적재하지 않는다.

| Linux 호출 | INDEX | v_termíne_splatnosti_položka 제약 |
|---|---:|---|
| read / write / close / lseek | 63 / 64 / 57 / 62 | RAM 파일과 표준 vstup_a_výstup; vstup_VALUE 대기는 EAGAIN 가능 |
| openat / unlinkat | 56 / 35 | AT_FDCWD 또는 절대 Cesta; 파일만, 제한된 플래그 |
| ftruncate / fsync | 46 / 82 | RAM Súbor; fsync가 영속 저장을 의미하지 않음 |
| exit / exit_group | 93 / 94 | v_termíne_splatnosti_položka program_f5044b9b Skončiť_program |
| brk | 214 | vlastné používateľ halda_VALUE klip; zlyhanie_VALUE 시 이전 break vrátiť_KR |
| clock_gettime | 113 | CLOCK_MONOTONIC만, 밀리초 rozlíšenie_VALUE |
| getpid / gettid | 172 / 178 | 한 používateľ Vykonať_príkaz 흐름의 identifikátor_VALUE |

미지원 번호는 `-ENOSYS`를 반환한다. Linux ABI의 socket, fork/clone/execve,
pthread, mmap, signal, ioctl, fstat, 동적 로더와 일반 libc 초기화는 구현하지
않았다. 기존 vlastné POSIX/Java 소켓은 별도로 TCP/UDP를 지원한다.

počiatočný_stav 스택에는 argc, UTF-8 argv, 빈 envp, AT_PAGESZ/AT_ENTRY/AT_NULL을 넣는다.
입력은 ELF64 little-endian AArch64 **ET_EXEC**, Súbor 전체 **16 KiB 이하**,
PT_LOAD 주소는 **0x02000000 이상 0x02c00000 미만**이어야 한다.
Súbor 오프셋과 가상 주소의 페이지 zarovnať_VALUE 관계를 검사하며, 서로 페이지를 공유하는
세그먼트와 Zápis·Vykonať_príkaz 동시 허용은 거부한다. PT_INTERP/PT_DYNAMIC/PT_TLS와
ET_DYN은 아직 받지 않는다.

일반 Linux 바이너리의 predvolená_hodnota 적재 adresa 0x00400000은 커널과 겹치므로 아직 받지
않는다. 예제는 GNU 링커의 `-Ttext-segment=0x02000000 -z max-page-size=4096`을
사용한다. 이 파일도 정상적인 Linux ELF이며 같은 파일이 Linux와 vlastné 커널에서
실행됨을 시험한다. Súbor 이름이나 헤더만 바꿔 기존 Linux program_f5044b9b 전체를 지원할
수는 없다.

## skutočný_údaje 동일 바이너리 비교 시험

```sh
cd /home/user/jkoros/platforms/rpi4-native
make test-elf
```

시험은 `예제/리눅스ABI/Spustiť_2.S`와 `인사.c`를 Linux AArch64 대상으로 컴파일해,
**JKOROS note가 없는 확장자 없는 Vykonať_príkaz Súbor** `build/verification/elf/리눅스인사`를
만든다. 같은 바이트를 Ďalej_položka 두 경로로 실행한다.

```sh
qemu-aarch64 build/verification/elf/리눅스인사 한글인수
python3 Nástroje/Vykonať_Súbor.py --linux build/verification/elf/리눅스인사 한글인수
```

첫 명령은 Linux 시스템 호출을 사용하는 akcia_koreň 실행이고, 두 번째는 Linux를
적재하지 않은 raspi4b vlastné jadro_VALUE 실행이다. 한글 Argumenty, Súbor vstup_a_výstup, Hodiny, Skončiť_program,
jadro_VALUE adresa prístup_položka 거부를 비교한다. FTP로 같은 파일을 올려 실행하는 시험도 있다.
LOG_RECORD: `build/verification/elf/report.json`, `readelf.txt`, `serial.log` 및 FTP 보고서.

일반 Linux 프로그램까지 지원하려면 별도 používateľ adresa adresa_oblasť, 더 큰 영속 VFS,
전체 Vykonať_príkaz incializovať/auxv, 동적 링커와 재배치, mmap/TLS/시그널/스레드,
시스템 호출 및 libc 호환성을 확장해야 한다. 이번 구현은 첫 제한된 Vykonať_príkaz 경로다.
