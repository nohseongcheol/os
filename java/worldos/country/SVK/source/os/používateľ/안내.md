# 셸에서 실행하는 používateľ 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 안내](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 Vykonať_príkaz

hostiteľ Terminál 1:

```sh
cd /home/user/jkoros
python3 os/Nástroje/ozvena_údaje.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. externý_VALUE 연결을 받도록 방화벽이나 hardvér_port 전달을 변경하지 않는다. Ctrl+C로 종료한다.

hostiteľ Terminál 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 vstup_VALUE:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 skutočný_údaje CPU povolenie_VALUE `ring 3`, Argumenty Výstup.
- `netcheck`: port_VALUE 중복, 잘못된 rukoväť_VALUE/ukazovateľ/dĺžka_VALUE, 비차단 받기와 čas_VALUE 초과 overiť.
- `udp`: IPv4 adresa·cieľ_VALUE port_VALUE·한 Word_VALUE 메시지를 받아 UDP로 보내고 같은 응답을 overiť. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: hostiteľ `10.0.2.2`의 Priradiť_VALUE 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. dostať_VALUE Loop_VALUE 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. v_termíne_splatnosti_položka 주소는 게스트 `10.0.2.15/24`, brána_VALUE `10.0.2.2`로 고정돼 있다. QEMU používateľ 네트워크의 hostiteľ prístup_položka 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 program_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java program_f5044b9b Pripojiť_položka

`예제/내프로그램.java`를 Ďalej_položka 형식으로 만든다. 진입점은 Argumenty 없는 `static int` 또는 `static void` 함수다. 인수는 používateľ API로 조회한다.

```java
public final class 내프로그램 {
    public static int Spustiť_2() {
        používateľ.Zápis("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/používateľ/program_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := používateľ/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.Spustiť_2
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `používateľ/deklarácia/používateľ.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 Vykonať_príkaz 중인 VM에는 zostava_systém 결과가 자동 반영되지 않는다. program_f5044b9b 이름은 v_termíne_splatnosti_položka 셸의 ASCII vstup_VALUE 제한에 맞춘 1~15자의 소문자 이름이며 Java lekcia_VALUE·funkcia_VALUE·변수에는 한국어를 쓴다. 최대 32개 program_f5044b9b, 한 Vykonať_príkaz 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/kompilátor.py --target user --entry 인사.Spustiť_2 \
    -o os/build/apps/hello.elf os/používateľ/deklarácia/používateľ.java os/používateľ/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 hostiteľ 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 Podpora_VALUE klip 안에서 실행한다. `.jar`와 일반 Linux Vykonať_príkaz 파일은 지원하지 않는다.

## používateľ 네트워크 API

선언은 `deklarácia/používateľ.java`에 있다. `odoslať_údaje`/`dostať_údaje`의 `int[]` položka_prvok 한 개는 Byte_VALUE 하나(0~255)를 나타낸다. 한 데이터그램의 최대 údaje 길이는 1,024바이트다.

```java
int rukoväť_VALUE = používateľ.otvoriť_sieť(0); // 0: 임시 miestny_Rozsah UDP port_VALUE 자동 výber_VALUE
int[] údaje = new int[32];
údaje[0] = 'H'; údaje[1] = 'i';
int 보낸길이 = používateľ.odoslať_údaje(rukoväť_VALUE, 0x0a000202, 9000, údaje, 2);
int RECEIVED_dĺžka = používateľ.dostať_údaje(rukoväť_VALUE, údaje, 1500);
používateľ.Zavrieť_sieť(rukoväť_VALUE);
```

skutočný_údaje 프로그램에서는 Otvoriť·odoslať·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `dostať_údaje`의 počkaj_VALUE 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 dostať_VALUE 대기열은 한 개뿐이므로 Pripojiť_položka 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | rukoväť_VALUE·Proces_VALUE_položka dĺžka_VALUE·성공 등 해당 함수의 KR |
| -5 | telefón_VALUE odoslať_VALUE zlyhanie_VALUE |
| -9 | 잘못되었거나 닫힌 통신 rukoväť_VALUE |
| -11 | 비차단 받기에서 도착한 údaje 없음 |
| -14 | používateľ ukazovateľ/pole_VALUE klip chyba |
| -19 | Podpora_VALUE NIC 없음 |
| -22 | port_VALUE/počkaj_VALUE čas_VALUE/Argumenty VALUE chyba |
| -24 | 열린 sieť_port 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | údaje 또는 dostať_VALUE pole_VALUE Veľkosť 문제 |
| -98 | miestny_Rozsah port_VALUE INDEX 중복 |
| -101 | 지원하지 않는 cieľ_VALUE adresa |
| -110 | ARP·telefón_VALUE·dostať_VALUE čas_VALUE 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 kódovanie_VALUE 있는 Java `int`의 Bit_VALUE 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## Vykonať_príkaz 경계와 시스템 호출

```text
셸 run → JKAP에서 ELF overiť_5fb2b747·적재 → ring 3 používateľ program_f5044b9b
                                 ↓ int 0x80
                      ukazovateľ 검사 → Java jadro_VALUE API → RTL8139/UDP
                                 ↓ Skončiť_program·výnimka·čas_VALUE 초과
                                셸 복귀
```

시스템 호출 레지스터는 `EAX=INDEX`, `EBX,ECX,EDX,ESI,EDI=Argumenty`, `EAX=KR`다. Java 호출 operand_Vrstvy ABI는 컴파일러가 používateľ 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| INDEX | 호출 |
| --- | --- |
| 0 | Skončiť_program(Stav_VALUE kód_VALUE) — Spustiť_2/chyba 런타임에서 používať_VALUE |
| 1 | reťazec_VALUE Zápis |
| 2 / 3 | Argumenty položka_COUNT / Argumenty reťazec_VALUE adresa |
| 10 | UDP Otvoriť |
| 11 | UDP odoslať(rukoväť_VALUE, IP, cieľ_VALUE port_VALUE, pole_VALUE adresa, dĺžka_VALUE) |
| 12 | UDP dostať(rukoväť_VALUE, pole_VALUE adresa, 제한 밀리초) |
| 13 | UDP Zatvoriť |
| 14 | miestny_Rozsah IP adresa |
| 15 / 16 | 마지막 partnerský_uzol_VALUE IP / UDP port_VALUE |
| 20 | RAM Súbor Čítanie(Názov int[] adresa, Výstup int[] adresa) |
| 21 | RAM Súbor Zápis(Názov int[] adresa, vstup_VALUE int[] adresa, Byte_VALUE dĺžka_VALUE) |
| 22 | UTF-16 kód_VALUE lekcia_VALUE_7c611f50 문자 Výstup(0~65535) |

Súbor API는 `používateľ.파일읽기(int[] Názov, int[] údaje)`와 `používateľ.zapísať_Súbor(int[] Názov, int[] údaje, int dĺžka_VALUE)`다. 이름은 ASCII kód_VALUE pole_VALUE(최대 64칸, 0 Skončiť_program 또는 pole_VALUE 끝), údaje položka_prvok 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 Súbor 없음 `-2`, ukazovateľ chyba `-14`, Názov/dĺžka_VALUE chyba `-22`, Súbor 슬롯 부족 `-28`, Veľkosť 초과 `-90`을 반환한다. 쓰기는 overiť_5fb2b747 후 Súbor 전체를 대체한다. `používateľ.zapísať_znak_VALUE(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 používateľ 모드에서 CS의 하위 비트를 직접 읽으므로 skutočný_údaje Vykonať_príkaz 권한을 확인한다. jadro_VALUE hardvér_port 접근용 `telefón_VALUE` native 함수는 používateľ cieľová_hodnota 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 Vykonať_príkaz, 파이프, 프로세스 간 통신은 없다. Vykonať_príkaz 파일은 커널의 Čítanie 전용 JKAP 묶음에서 적재한다. údaje 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- používateľ 가상 adresa `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. Vykonať_príkaz 영상은 predný_VALUE 2MiB, 인수는 `0x04300000`부터, 스택은 oblasť_VALUE_0e9a97ab 끝에서 시작한다. jadro_VALUE identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB používateľ 영역을 비우고 Súbor 구역을 복사해 BSS·pole_VALUE 영역을 초기화한다. používateľ GC는 없지만 Skončiť_program 후 Ďalej_položka Vykonať_príkaz 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 Citát/이스케이프 파싱은 없다.
- používateľ 페이지의 kód_VALUE/údaje 분리 Čítanie 전용 Nastavenia, NX, operand_Vrstvy guard, ASLR은 아직 없다. 커널과 používateľ Pamäť_údaje·hardvér_port povolenie_VALUE 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 Vykonať_príkaz 상한을 두며 čas_VALUE 초과는 `Exit: 124`다. používateľ CPU 예외는 `128 + výnimka INDEX`(페이지 chyba 142, 특권 위반 141), Java pole_VALUE/계산 오류는 101~105다. jadro_VALUE 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, 정적 IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP kontrolný_súčet 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- používateľ Vykonať_príkaz·네트워크·chrániť_VALUE 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 Vykonať_príkaz·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.
