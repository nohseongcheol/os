# vlastné 커널의 GUI 터미널과 셸

이 터미널은 vlastné Java 커널의 셸을 프레임버퍼 창과 UART에서 사용한다. Príkaz Proces_VALUE_položka·RAM Súbor·파이프는 Java jadro_VALUE, 화면의 znak_VALUE 그리기는 freestanding C에서 수행한다. Linux·X11·Bash 없이 동작하며, vlastné JVM의 Swing Podpora_VALUE 부분집합도 같은 Okno 시스템을 이용한다. 자세한 vi·다중 Okno·코딩 사용법은 [개발 매뉴얼](개발안내.md)을 참고한다.

## v_termíne_splatnosti_položka 컴퓨터에서 Vykonať_príkaz

```sh
cd /home/user/jkoros/platforms/rpi4-native
make desktop
```

Remmina에서 **VNC**, adresa **127.0.0.1:5902**로 연결한다. Terminál 창은 자동으로 열린다. 연결한 VNC 창에 키를 입력하면 vlastné 커널의 셸로 전달된다. 종료하려면 `make desktop`을 실행한 hostiteľ 터미널에서 Ctrl+C를 누른다. 포트를 바꾸려면 zostava_systém 후 `python3 Nástroje/Vykonať_príkaz.py --desktop --port 5903`을 사용한다. 서버는 localhost에만 바인드하며 동시에 한 클라이언트가 제어한다.

일반 UART 셸은 `make run`으로 시작한다. QEMU 종료는 Ctrl+A Ďalej_položka X이다. 같은 VM의 UART에서 `terminal` 또는 F12로 GUI 터미널을 COLUMN_VALUE 수 있다. `gui` Vykonať_príkaz 화면에서는 다섯 번째 **OPEN TERMINAL** 버튼, číslica_VALUE 5 또는 T로 연다. `--vnc 127.0.0.1:2`만 사용한 기존 Vykonať_príkaz 방식은 화면 보기용이며, VNC 키보드를 연결하려면 `--desktop`을 사용한다.

FTP와 externý_VALUE 네트워크도 함께 쓰려면 `python3 Nástroje/Vykonať_príkaz.py --desktop --network`로
실행한다. Remmina VNC는 `127.0.0.1:5902`, 게스트에서 `ftpd start` 후 FTP는
`127.0.0.1:2121`이다. `--port`, `--ftp-port`, `--forward`를 함께 지정할 수 있다.
한 VM의 보조 UART로 SLIP를 전송하고 주 UART로 GUI 입력을 전달한다.

QEMU Vykonať_príkaz 도구가 VNC 키보드/마우스를 UART 입력으로 변환한다. skutočný_údaje Pi4의 USB 키보드·마우스 드라이버를 구현한 것은 아니다. skutočný_údaje 보드에서는 v_termíne_splatnosti_položka UART 입력이 필요하며 실물 부팅은 아직 미검증이다.

`--desktop`의 VNC vstup_VALUE 연결에 **두벌식 한글 조합**을 제공한다. 접속한 PC의
입력기를 영어로 두고 **F9**, **Shift+Space**, **한/영 Kľúč_VALUE** 중 하나를 누르면

vlastné 처리하면 **F9**를 사용한다. Alt 단독은 SWITCH_MODE 키가 아니다.

이 조합기는 QEMU의 VNC→UART vstup_VALUE 연결에서 실행된다. 일반 직렬 접속과
실물 Pi의 USB 키보드 입력기에 추가된 기능은 아니다. 이미 완성된 Unicode

줄바꿈을 포함해 명시적으로 붙여 넣으면 해당 줄이 실행된다.

게스트에서 `help` 또는 `help ko`를 입력하면 한글 vstup_VALUE 안내를 볼 수 있다.
`help`와 `help ko`에는 한/영 Kľúč_VALUE·Shift+Space·F9 및 `[EN]`/`[KO]` 안내를 표시한다.

## 문법과 제한

작은따옴표·큰따옴표·백슬래시, `$NAME`/`${NAME}`/`$?`, Word_VALUE predný_VALUE `~`, riadok 주석 `#`, 순차 Vykonať_príkaz `;`, podmienka Vykonať_príkaz `&&`/`||`, 파이프 `|`, vstup_VALUE `<`, 새 Výstup `>`, Pripojiť_položka Výstup `>>`를 제공한다. 변수 확장은 Argumenty 안에서 수행하며 prípona_VALUE 결과를 공백으로 skúsiť_znova_VALUE 나누지 않는다. `export`의 값은 셸 안에서만 공유하며 používateľ ELF의 envp/getenv 환경은 아직 없다.

파이프는 각 단계를 순서대로 실행하고 최대 **16384바이트**를 Ďalej_položka 단계로 넘긴다. 여러 프로세스가 동시에 읽고 쓰는 POSIX 파이프가 아니다. kapacita_VALUE 초과는 chyba 28과 zlyhanie_VALUE 상태를 반환하고 해당 실행을 중단한다. `<`는 EOF를 제공하며 `>`/`>>`는 stdout만 바꾼다. EL0 fd 2는 화면/UART로 출력된다. `2>` 등 번호를 붙인 리다이렉션은 거부한다. 일부 내장 명령의 진단은 stdout을 사용한다. 연결한 프로그램의 `exit N` 진단은 데이터에 섞이지 않도록 생략한다.

`vi`, `edit`, `load`, `gui`, `terminal`, `sh`, `source`에는 파이프와 리다이렉션을 적용할 수 없다. 리다이렉션 파일을 열지 못하거나 파이프 용량을 초과하면 v_termíne_splatnosti_položka 명령줄을 중단하며, 그 줄의 뒤쪽 `||` 명령도 실행하지 않는다. skript_VALUE 파일을 입력할 때 멀티라인 Citát·이어 쓰기는 제공하지 않는다. `if`/`for`/`while`, funkcia_VALUE, Príkaz 치환, glob, 별칭, 백그라운드 `&`, jobs/fg/bg, 일반 프로세스·신호·PTY는 아직 없다. Bash/POSIX sh 전체 호환으로 표시하지 않는다.

Súbor 64개 × 각 16384바이트, 루트 외 디렉터리 15개, Súbor 서술자 16개, Cesta 최대 UTF-8 63바이트다. partnerský_uzol_VALUE/절대 경로와 `.`/`..`를 정규화하지만 povolenie_VALUE·심볼릭 링크·마운트·디스크 영속 저장은 없다. **Súbor·디렉터리·변수·기록의 수정 내용은 재부팅하면 사라진다.** používateľ 실행도 v_termíne_splatnosti_položka 셸 경로를 사용한다. Java/Python/C++의 Súbor API는 같은 RAM 저장소를 본다. `/example`의 세 Jazyky 예제와 설명서는 부팅할 때 원본으로 준비된다.

한 명령줄은 4096바이트, 구문 token_VALUE 128개, Vykonať_príkaz Argumenty 32개, 변수는 16개(Názov 31바이트·VALUE 255바이트)까지다. používateľ 프로그램에 전달하는 인수는 기존 ABI대로 최대 8개·각 255바이트다. Príkaz 기록은 1024바이트 이하 줄을 Nedávne_VALUE 16개까지 저장한다.
