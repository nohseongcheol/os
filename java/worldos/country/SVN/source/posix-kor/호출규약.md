# uporabnik 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `računalnik/operacijski_sistem_Klici.s`에서 EAX(INDEX), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 Argumenti)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. jedro_VALUE 실패는 음수 NAPAKA INDEX, C knjižnica 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 uporabnik območje_VALUE_0e9a97ab 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C podatki 주소는 bajt_VALUE 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java Datoteka 흐름의 어셈블리 경계가 별도 bajt_VALUE 버퍼를 마련하여 같은 호출을 사용한다.

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 naslov 두 칸이다. sprejeti_sprejemati_prejeti_prejemati_VALUE 주소가 NULL이면 enakovreden_VALUE naslov 기록을 생략한다. sockaddr_in은 16바이트이며 naslov 체계는 naprava_VALUE bajt_VALUE SEQUENCE_VALUE, 접속번호와 IP 주소는 네트워크 bajt_VALUE 차례다. 축소된 naslov 버퍼에도 들어가는 앞부분을 쓰고 전체 naslov Velikost 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 Izhod_aplikacija, 2·3은 기존 Argumenti 조회다. sprotno_element 커널의 Argumenti 목록이 Izvedi_ukaz 이름을 제외하므로 C 진입기는 argv[0]에 고정 niz_VALUE `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX Proces_VALUE ABI와 다른 점이다.

표준 헤더의 celo_število Velikost, 플래그 VALUE, stat polje_VALUE 순서는 `VIR/포함/`에 정의한다. 동적 Poveži·다중 Proces_VALUE·스레드가 추가되면 NAPAKA INDEX 저장과 vir_VALUE 수명, 호출 경계도 함께 검토해야 한다.
