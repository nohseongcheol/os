# eget ARM64 användarutrymme köra_kommando ABI v1

이 ABI는 `platforms/rpi4-native`의 제한된 freestanding köra_kommando 환경이다. Linux AArch64 ABI나 POSIX 전체 구현이 아니다. **OpenJDK/JRE, CPython, libc, libstdc++는 아직 이식되지 않았다.**

ELF 로더는 filnamn 확장자 대신 verklig_data ELF 헤더를 검사한다. 아래 eget ABI와 별도로 `run --linux FILE`에 제한된 Linux ARM64 statisk_värde köra_kommando filnamn 경로를 추가했다. 두 시스템 호출 번호표를 혼합하지 않는다. [ELF·Linux ABI 매뉴얼](실행파일규약.md).

## ELF와 köra_kommando 수명

- ELF64 little endian, ET_EXEC, EM_AARCH64, 버전 1, e_flags=0.
- app_f5044b9b 헤더 최대 16개. PT_LOAD는 Läs 가능, 4 KiB justera_värde, 페이지 간 kapsling_värde 없음, filesz≤memsz, version_BILD Adress klipp 안이어야 한다. W+X는 거부한다.
- 진입점은 filnamn 내용이 있는 köra_kommando 세그먼트 안의 4바이트 justera_värde 주소다.
- PT_NOTE에 Namn `JKOROS\0`(namesz=7), type=1, descsz=4, 버전 1의 little endian uint32가 필요하다. SDK의 `start.o`가 넣는다.
- PT_DYNAMIC/PT_INTERP/PT_TLS 등은 거부한다. 동적 재배치·공유 bibliotek·TLS 로더가 없다.
- 커널에 포함한 ELF 묶음을 검증하고 별도 användarutrymme 메모리에 복사한 BACK_värde EL0로 진입한다. 커널에 함수로 statisk_värde 링크해 호출하는 Föregående_objekt `cpp_test`와 다르다.
- 내장 프로그램은 `demo.elf`, `fault.elf`의 8개 skydda_värde tester läge_värde, `network.elf`, eget Java verktyg, MicroPython이다. 셸의 `load`/`run FILE`로 RAM의 16KiB 이하 ELF도 같은 validera 경로로 실행한다.
- `_start`가 `user_start`를 호출하고 `.init_array` → `START_användare_app(int)` → `.fini_array` 순서로 실행한 BACK_värde exit 호출을 수행한다. 인수는 호출 15로 읽으며 표준 argc/argv/envp operand_Stack 배치는 없다.
- 한 번에 한 användarutrymme 프로그램이 CPU에서 실행된다. 네 터미널에 각 하나씩 interaktiv 프로그램을 일시 정지해 보관할 nummer 있다. informationsteknik_normal Utgång_app·fel_31f743d2·tid_värde 초과 시 커널에 복귀하고 열린 filnamn/소켓을 닫으며 användarutrymme 페이지 권한을 제거한다.
- statisk_värde 생성자와 자동 객체의 RAII 소멸자를 시험했다. `__cxa_atexit`, 표준 C++ fel_31f743d2/RTTI/STL, 일반적인 전역 objekt_värde Utgång_app 등록은 제공하지 않는다.

eget JVM의 Kurs_värde·objekt_värde 자료를 수용하도록 användarutrymme 창을 16 MiB로 확장했다. app_f5044b9b 헤더의 Tillåt_värde klipp, 페이지 behörighet_värde 검사, SDK 링커 skript_värde 및 skydda_värde 시험이 같은 배치를 사용한다. 기존에 brk Kör 주소를 상수로 가정한 프로그램은 새 SDK로 försöka_igen_värde 빌드한다. 일반 프로그램은 호출 8로 aktuellt_objekt brk를 조회한다.

köra_kommando 코드는 EL0 Läs/실행만, data·heap_värde·스택은 EL0 Läs/쓰기만 허용한다. 나머지 kärna_värde RAM·enhet_värde MMIO에는 EL0 권한을 주지 않는다. 이번 W^X 보장은 **användarutrymme 페이지에 대한 것**이다. kernel identity map의 전체 behörighet_värde 분할이나 다중 프로세스 Adress ADRESS_område 전환을 구현했다고 의미하지 않는다.

커널은 `-mgeneral-regs-only`로 빌드한다. användarutrymme C/C++는 FP/SIMD를 허용하고, användarutrymme startpunkt_värde 시 vektor_värde 레지스터와 FPCR/FPSR를 초기화한다. kärna_värde 복귀용 callee-saved FP 상태를 보관한다. syscall/IRQ의 C 처리부는 FP 레지스터를 사용하지 않는다. 향후 여러 användarutrymme 스레드를 전환할 때에는 각 스레드의 전체 FP sammanhang_värde 보존을 별도로 구현해야 한다.

GIC-400의 물리 타이머 IRQ로 약 2초의 köra_kommando 기한을 적용한다. SVC 없는 무한 반복도 종료한다. 시스템 호출 Kör 시 기한을 검사하지만 EL1 Process_värde_post 중에는 IRQ를 마스킹하므로 긴 utmatningsposition/Paint_skärmbild 호출의 종료는 지연될 nummer 있다. 이것은 app_f5044b9b köra_kommando 기한이며 일반 선점 스케줄러가 아니다.

## UDP 루프백의 계약

바깥 IPv4는 lwIP/SLIP로 확장했다. 기존 fd/구조체/markör 검사 규약을 유지하며 0.0.0.0 또는 10.0.2.15에 bind한 끝점을 바깥 통신에 연결한다. 127.0.0.1에 명시적으로 bind한 UDP는 루프백에 한정한다. extern_värde TCP connect는 비차단 -EINPROGRESS(-115)를 반환할 nummer 있으므로 같은 주소로 재시도하여 완료를 확인한다. [köra_kommando/제한](파일전송과번역.md).

`nät_serie`, `datagramsocket`, Överför_protokoll 0/`datagram_protokoll`을 허용한다. `struct nät_socket_ADRESS`는 16바이트이며 주소갈래는 enhet_värde SEKVENS_värde, 접속번호와 Internetadress.주소값은 nätverk_värde 차례다. 호환용 pk_sockaddr_in도 같은 배치지만 독립 자료형이다. Svenska 함수는 직접 SVC를 호출하는 verklig_data 함수이며 표준 이름으로 치환하는 매크로가 아니다. värd Linux 헤더를 섞지 않는다.

- 목적지는 127.0.0.1만 Tillåt_värde. bind는 0.0.0.0 또는 127.0.0.1, port=0이면 49152…65535에서 빈 창구를 고른다.
- 미바인드 소켓의 첫 전송은 임시 창구를 바인드한다. 같은 창구의 중복 bind는 EADDRINUSE.
- 최대 8개 socket_värde, 각 큐 4개, 전문은 0…512바이트. 빈 전문도 소비된다.
- få_värde 버퍼가 작으면 복사할 부분만 반환하고 전문의 나머지는 버린다. peer Adress/창구를 반환한다.
- flags는 aktuellt_objekt 0만 stöd_värde. 비차단 수신의 빈 큐 및 skicka_värde_f993dacd mål 큐 포화는 EAGAIN이다.
- mål port_värde 없음은 ECONNREFUSED, 512바이트 초과는 EMSGSIZE, 루프백에 명시적으로 바인드한 UDP의 extern_värde IP는 ENETUNREACH, UDP 소켓에 잘못된 규약을 지정하면 EPROTONOSUPPORT. SOCK_STREAM은 별도 연결형 루프백에서 제공한다.
- extern_värde IPv4 TCP/UDP 헤더·체크섬·재전송은 lwIP가 처리한다. verklig_data GENET/Wi-Fi NIC, poll/select, setsockopt는 아직 없다. 연결형 루프백의 connect/listen/accept는 아래 tillägg_värde ABI로 제공한다.

## 여러 터미널의 användarutrymme sammanhang_värde

interaktiv tty/GUI 대기를 명시적으로 시작한 프로그램은 indata_värde 대기에서 약 2초 기한을 갱신한다. vänta_värde 없이 무한 반복하면 타이머로 종료한다. 파이프/리다이렉션/복합 kommando/스크립트에서 interaktiv 시작은 -ENOTSUP로 거부한다. vi와 Swing의 이벤트 루프가 이 API를 사용한다.

다른 창으로 전환하면 Nästa_objekt vänta_värde SVC에서 EL0 문맥을 저장하고 해당 SVC를 재실행할 위치에서 재개한다. x0…x30, SP/PC/PSTATE, v0…v31, FPCR/FPSR, 매핑·heap_värde·köra_kommando argument·filnamn/socket_värde 소유권을 보관한다. 스냅샷은 kärna_värde 전용 물리 Adress 0x04000000…0x07ffffff(네 fack_värde ×16 MiB)에 저장한다. aktuellt_objekt Aktiv EL0 Adress 창은 종전 0x02000000…0x02ffffff를 사용한다. 스냅샷 저장소는 EL0에서 접근할 nummer 없다. fork/exec/wait, SMP 또는 일반 선점형 프로세스 스케줄러의 구현은 아니다.

SVC 40은 소유한 연결형 소켓의 peer_värde maskinvara_port 번호를 반환한다(eget JVM용 heltal fråga_värde).

연결형 루프백 fd는 40…55, UDP fd는 32…39다. Utgång_app/kommandotolk X 닫기에서 해당 프로그램의 filnamn·소켓을 회수한다. 연결형 읽기의 data 없음은 -EAGAIN, 상대가 닫고 버퍼도 비면 0, 상대가 닫힌 BACK_värde 쓰기는 -EPIPE다. 쓰기는 짧게 완료될 nummer 있다. 큐 용량은 끝점마다 1024바이트이고 한 시스템 호출은 최대 512바이트를 옮긴다. överordnad_värde 리스너를 닫으면 아직 accept하지 않은 연결도 회수한다. extern_värde 연결은 lwIP TCP를 사용하며 extern_värde få_värde 버퍼는 4096바이트다. verklig_data GENET NIC 드라이버는 없다.

협력 vänta_värde(17)는 일반 선점형 sleep/scheduler 구현이 아니다. 호출마다 최대 100 ms 동안 통신을 처리하고 användarutrymme köra_kommando 기한을 갱신한다. bunt 설치기의 비차단 TCP 대기에 사용한다.
