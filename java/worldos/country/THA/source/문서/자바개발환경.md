# jkoros 안에서 Java คอมไพล์_แหล่ง·ดําเนินการ_คําสั่ง

이 문서의 부팅·เชลล์·เก็บ_ค่า 명령은 **x86 รุ่น_ค่า** 기준이다. 공유 Java คอมไพเลอร์/JVM은 [เอง ARM64 Pi4 รุ่น_ค่า](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 ชื่อแฟ้ม_ข้อความ, `edit`의 단독 `.` เก็บ_ค่า, 16개 RAM แฟ้ม, 약 2초 ดําเนินการ_คําสั่ง 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 ค่าจริง_ข้อมูล JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. โฮสต์ คอมไพล์_แหล่ง 서버나 Linux 게스트는 사용하지 않는다.

**ปัจจุบัน_รายการ 구현은 เอง 제한형 คอมไพเลอร์·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java แอป_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 ดําเนินการ_คําสั่ง

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. ดําเนินการ_คําสั่ง 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox ดําเนินการ_คําสั่ง 안내](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 แฟ้ม 전체를 새 내용으로 작성한다. 기존 내용의 บรรทัด แก้ไข_ค่า 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 ไบต์_ค่า หมายเลข แสดง_ค่า.
- `cat FILE`: แฟ้ม เนื้อหา_ค่า แสดง_ค่า. 텍스트 소스에 사용한다.
- `rm FILE`: ความจํา_ข้อมูล แฟ้ม 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 หมายเลข 있다.
- 구문·ชนิด_ค่า 검사 ความล้มเหลว_ค่า 시 기존 `.class`는 유지된다. 소스를 고친 ย้อนกลับ_ค่า 컴파일이 실패했다면 이전 ดําเนินการ_คําสั่ง 파일이 남아 있으므로 คอมไพล์_แหล่ง 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 เก็บ_ค่า 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 แหล่ง_ทรี·คลาส_ค่า·ข้อมูล 파일을 보존할 หมายเลข 있다. 최대 8개, 파일마다 16KiB, แฟ้ม 이름은 ASCII 1~63자다. แหล่ง_ทรี 이름은 `.class` 확장자 อีเมล_ขอบเขต 때문에 최대 62자다. แก้ไข_ค่า 입력은 ASCII이고 한 บรรทัด 최대 128자다. บรรทัด 또는 แฟ้ม 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. เคอร์เนล_ค่า/คอมไพเลอร์/JVM 구현의 Java 식별자는 한국어이며, ปัจจุบัน_รายการ 게스트 입력 제한 때문에 ผู้ใช้ 예제 이름은 ASCII로 작성한다.

## ภายนอก_ค่า แฟ้ม 적재

호스트에서 만든 소스나 สนับสนุน_ค่า คลิป 안의 `.class`를 부팅 이미지에 포함할 หมายเลข 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 ค่าจริง_ข้อมูล 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# โฮสต์ JDK로 컴파일한 클래스도 사용할 หมายเลข 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 ถัดไป_รายการ 빌드에서는 ผนวก_รายการ 파일을 포함하지 않는다. แฟ้ม เนื้อหา_ค่า 변경과 รายการ_รายการ 제거도 ถัดไป_รายการ 빌드에 반영된다. 원본 โฮสต์ 파일에는 쓰지 않는다. ค่าเริ่มต้น `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 ค่าเริ่มต้น 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 คลาส_ค่า แฟ้ม 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 สนับสนุน_ค่า คลิป 안에 있어야 한다.

## สนับสนุน_ค่า คลิป

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| คลาส_ค่า | 패키지 없는 단일 คลาส_ค่า, คงที่_ค่า ฟังก์ชัน_ค่า, 재귀, อาร์กิวเมนต์/ส่งคืน_เมตริก | 실행마다 단일 คลาส_ค่า 적재, public static main(String[]) |
| ค่าเริ่มต้น ค่า | int, boolean, char, String, main의 String[] อาร์กิวเมนต์ | จํานวนเต็ม·อ้างอิง ตัวถูกดําเนินการ_สแตก, String, int[], String[], 내부 StringBuilder |
| คําสั่ง_ค่า | 초기값 있는 ท้องถิ่น_ขอบเขต การประกาศ, แล็บ_ค่า, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 จํานวนเต็ม·อ้างอิง 바이트코드와 โรค สาขา |
| นิพจน์_ค่า | 십진 จํานวนเต็ม, UTF-8 소스의 สตริง_ค่า/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, สตริง_ค่า 결합 | จํานวนเต็ม ศัลยกรรม_ค่า·บิต_ค่า ศัลยกรรม_ค่า·ชนิด_ค่า แปลง_ค่า_4633b7f3, 단락 평가, อาร์เรย์_ค่า เข้าถึง_รายการ |
| แฟ้ม | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | ค่าจริง_ข้อมูล เคอร์เนล_ค่า 파일서술자와 เชื่อมต่อ, สร้าง_167eff27·ล้าง_สารบัญ·이어쓰기·EOF |
| ข้อความออก | System.out.print/println: int/boolean/char/String, println() | 동일 |
| สตริง_ค่า/อาร์กิวเมนต์ | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), สตริง_ค่า 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 ท้องถิ่น_ขอบเขต การประกาศ, 오버로드, 임의 ชนิด_ค่า แปลง_ค่า_4633b7f3, อาร์เรย์_ค่า สร้าง_167eff27 รหัสต้นฉบับ, 8/16진 리터럴, Unicode แหล่ง_ทรี 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 ค่าคงที่_ค่า 축소 변환을 구현하지 않는다. ภายนอก_ค่า `.class`의 `int[]` สร้าง_167eff27/อ่าน/쓰기는 지원하므로 โฮสต์ `javac --release 8`로 만든 อาร์เรย์_ค่า 예제는 실행할 หมายเลข 있다.

วัตถุ_ค่า ค่าเขตข้อมูล·일반 วัตถุ_ค่า สร้าง_167eff27·상속·인터페이스·여러 คลาส_ค่า เชื่อมต่อ, long/float/double, ข้อยกเว้น กระบวนการ_ค่า_รายการ, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java ข้อยกเว้น 객체를 던지지 않고 진단 후 ปัจจุบัน_รายการ 프로그램을 종료한다. 객체와 สตริง_ค่า เก็บ_ค่า 공간은 ดําเนินการ_คําสั่ง ออก_แอป 시 ผู้ใช้ ขอบเขต_ค่า 전체와 함께 회수한다. 지속 ดําเนินการ_คําสั่ง 중 GC는 없다.

## ดําเนินการ_คําสั่ง 한도와 ข้อผิดพลาด

| ทรัพยากร_ค่า | 한도 |
| --- | --- |
| แหล่ง_ทรี/คลาส_ค่า แฟ้ม | 각각 16KiB |
| คอมไพเลอร์ | โทเค็น_ค่า 2,047개, สร้าง_167eff27 รหัส_ค่า 4KiB, ค่าคงที่_ค่า 풀 4KiB |
| ฟังก์ชัน_ค่า/อาร์กิวเมนต์ | 클래스당 32함수, 함수당 16인수 |
| JVM ค่าคงที่_ค่า | 511개 |
| JVM ฟังก์ชัน_ค่า รหัส_ค่า | 함수당 8KiB |
| JVM 호출/ตัวถูกดําเนินการ_สแตก/ท้องถิ่น_ขอบเขต ตัวแปร_ค่า_541034c4 | 32프레임, 프레임당 ตัวถูกดําเนินการ_สแตก 128칸·ท้องถิ่น_ขอบเขต 128칸 |
| JVM วัตถุ_ค่า เก็บ_ค่า อีเมล_ขอบเขต | 8,192개 32비트 칸, 헤더 포함 약 32KiB |
| ดําเนินการ_คําสั่ง | 최대 500,000 คําสั่ง, 기존 커널의 약 3초 CPU ดําเนินการ_คําสั่ง 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 สนับสนุน_ค่า 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM พจนานุกรม 검증기를 구현한 것은 아니다. แฟ้ม/แอตทริบิวต์_ค่า 길이, ค่าคงที่_ค่า อ้างอิง, คําสั่ง·สาขา 경계를 검사하고, ดําเนินการ_คําสั่ง 중 ตัวถูกดําเนินการ_สแตก รูปแบบ_ค่า_d1a42ea5·ท้องถิ่น_ขอบเขต เริ่มต้น·อาร์เรย์_ค่า ตัวห้อย_ค่า·วัตถุ_ค่า 참조를 검사한다. ผู้ใช้ 코드의 페이지·ฮาร์ดแวร์_แปลง 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, คอมไพล์_แหล่ง·JVM 오류는 `Exit: 1`, คําสั่ง อาร์กิวเมนต์ 오류는 `Exit: 2`다. CPU ค่าเวลา 상한은 기존 `Exit: 124`이며, ผู้ใช้ ELF 자체의 CPU/런타임 오류는 기존 ออก_แอป 코드를 따른다. ความล้มเหลว_ค่า 후 셸에서 다른 프로그램을 계속 실행할 หมายเลข 있다.

## 구현 위치와 시험

- `os/ผู้ใช้/자바/자바컴파일러.java`: 게스트 어휘·구문·ชนิด_ค่า 검사, ค่าคงที่_ค่า 풀 및 바이트코드 สร้าง_167eff27.
- `os/ผู้ใช้/자바/자바가상기계.java`: คลาส_ค่า 적재, ตัวถูกดําเนินการ_สแตก·프레임·วัตถุ_ค่า เก็บ_ค่า, คําสั่ง 해석과 제한된 표준 호출.
- `os/รหัสต้นฉบับ/ความจํา_ระบบแฟ้ม.java`: ความจํา_ข้อมูล ระบบแฟ้ม, แก้ไข_ค่า, 부팅 แฟ้ม 적재.
- `os/รหัสต้นฉบับ/체계호출.java`, `compiler/เริ่ม_ผู้ใช้_แอป.s`: แฟ้ม/문자 ข้อความออก API와 ผู้ใช้ ตัวชี้ 검사.
- `os/เครื่องมือ/자바파일묶기.py`: โฮสต์ 입력 แฟ้ม ตรวจสอบความถูกต้อง·부팅 กลุ่ม_ค่า สร้าง_167eff27.

```sh
make test-java
make test
```

`os/시험/자바시험.py`는 ELF/ISO 부팅, 게스트 คอมไพล์_แหล่ง·ดําเนินการ_คําสั่ง, ผู้ใช้ 입력, 재귀·반복문·จํานวนเต็ม 극값·สตริง_ค่า 결합·단락 평가, 재실행, แหล่ง_ทรี ข้อผิดพลาด 후 기존 คลาส_ค่า 보존, อาร์เรย์_ค่า/หมายเลข 해독 ข้อผิดพลาด, 무한 สปรินต์_ค่า 제한, แก้ไข_ค่า 넘침과 แฟ้ม 부족을 검사한다. 게스트 สร้าง_167eff27 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 โฮสต์ OpenJDK의 คลาส_ค่า, จํานวนเต็ม 배열과 한글 상수를 게스트에 적재하며, 손상된 แฟ้ม มาร์กเกอร์_ค่า·버전·ค่าคงที่_ค่า หมายเลข·สาขา·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 시험 VM만 생성하고 종료한다.

구현 형식의 참고 ข้อมูล: Oracle [JVM คลาส_ค่า แฟ้ม 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM คําสั่ง 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java แฟ้ม รับเข้า_ส่งออก

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 คลาส_ค่า 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 ย้อนกลับ_ค่า `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. ค่าเริ่มต้น ข้อความออก 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. ข้อยกเว้น วัตถุ_ค่า·try/catch·try-with-resources는 지원하지 않으며 แฟ้ม 오류를 진단하고 프로그램을 종료한다. อาร์เรย์_ค่า รับเข้า_ส่งออก, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 แฟ้ม 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 เชลล์ `sync`가 필요하다. 예제의 แฟ้ม 이름은 ปัจจุบัน_รายการ 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 ค่าจริง_ข้อมูล 게스트 คอมไพล์_แหล่ง 결과를 OpenJDK `-Xverify:all`로 ลองอีกครั้ง_ค่า 실행해 แฟ้ม 바이트와 출력을 대조한다. 범위와 เก็บ_ค่า สื่อข้อมูล_ค่า 사용법은 [posix-kor 안내](../posix-kor/안내.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
