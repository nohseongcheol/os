# 셸에서 실행하는 ผู้ใช้ 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 สภาพแวดล้อม 안내](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 ดําเนินการ_คําสั่ง

โฮสต์ เทอร์มินัล 1:

```sh
cd /home/user/jkoros
python3 os/เครื่องมือ/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. ภายนอก_ค่า 연결을 받도록 방화벽이나 ฮาร์ดแวร์_แปลง 전달을 변경하지 않는다. Ctrl+C로 종료한다.

โฮสต์ เทอร์มินัล 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 ค่าจริง_ข้อมูล CPU สิทธิ์_ค่า `ring 3`, อาร์กิวเมนต์ ข้อความออก.
- `netcheck`: แปลง_ค่า 중복, 잘못된 จุดจับ_ค่า/ตัวชี้/길이, 비차단 받기와 ค่าเวลา 초과 ยืนยัน.
- `udp`: IPv4 อีเมล·ปลายทาง_ค่า_a0fbc067 แปลง_ค่า·한 คํา_ค่า 메시지를 받아 UDP로 보내고 같은 응답을 ยืนยัน. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: โฮสต์ `10.0.2.2`의 กําหนด_ค่า 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. รับ_ค่า วน_ค่า 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. ปัจจุบัน_รายการ 주소는 게스트 `10.0.2.15/24`, เกตเวย์_ค่า `10.0.2.2`로 고정돼 있다. QEMU ผู้ใช้ 네트워크의 โฮสต์ เข้าถึง_รายการ 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 แอป_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java แอป_f5044b9b ผนวก_รายการ

`예제/내프로그램.java`를 ถัดไป_รายการ 형식으로 만든다. 진입점은 อาร์กิวเมนต์ 없는 `static int` 또는 `static void` 함수다. 인수는 ผู้ใช้ API로 조회한다.

```java
public final class 내프로그램 {
    public static int เรียกใช้งาน() {
        ผู้ใช้.เขียน("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/ผู้ใช้/แอป_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := ผู้ใช้/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.เรียกใช้งาน
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `ผู้ใช้/การประกาศ/ผู้ใช้.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 ดําเนินการ_คําสั่ง 중인 VM에는 สร้าง 결과가 자동 반영되지 않는다. แอป_f5044b9b 이름은 ปัจจุบัน_รายการ 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java คลาส_ค่า·ฟังก์ชัน_ค่า·변수에는 한국어를 쓴다. 최대 32개 แอป_f5044b9b, 한 ดําเนินการ_คําสั่ง 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/คอมไพเลอร์.py --target user --entry 인사.เรียกใช้งาน \
    -o os/build/apps/hello.elf os/ผู้ใช้/การประกาศ/ผู้ใช้.java os/ผู้ใช้/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 โฮสต์ 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 สนับสนุน_ค่า คลิป 안에서 실행한다. `.jar`와 일반 Linux ดําเนินการ_คําสั่ง 파일은 지원하지 않는다.

## ผู้ใช้ 네트워크 API

선언은 `การประกาศ/ผู้ใช้.java`에 있다. `ส่ง_ข้อมูล`/`รับ_ข้อมูล`의 `int[]` รายการ_องค์ประกอบ 한 개는 ไบต์_ค่า 하나(0~255)를 나타낸다. 한 데이터그램의 최대 ข้อมูล 길이는 1,024바이트다.

```java
int จุดจับ_ค่า = ผู้ใช้.เปิด_เครือข่าย(0); // 0: 임시 ท้องถิ่น_ขอบเขต UDP แปลง_ค่า 자동 การเลือก_ค่า
int[] ข้อมูล = new int[32];
ข้อมูล[0] = 'H'; ข้อมูล[1] = 'i';
int 보낸길이 = ผู้ใช้.ส่ง_ข้อมูล(จุดจับ_ค่า, 0x0a000202, 9000, ข้อมูล, 2);
int 받은길이 = ผู้ใช้.รับ_ข้อมูล(จุดจับ_ค่า, ข้อมูล, 1500);
ผู้ใช้.ปิด_เครือข่าย(จุดจับ_ค่า);
```

ค่าจริง_ข้อมูล 프로그램에서는 เปิด·ส่ง·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `รับ_ข้อมูล`의 รอเดี๋ยว_ค่า 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 รับ_ค่า 대기열은 한 개뿐이므로 ผนวก_รายการ 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | จุดจับ_ค่า·กระบวนการ_ค่า_รายการ 길이·성공 등 해당 함수의 ผลลัพธ์ |
| -5 | อุปกรณ์_ค่า ส่ง_ค่า ความล้มเหลว_ค่า |
| -9 | 잘못되었거나 닫힌 통신 จุดจับ_ค่า |
| -11 | 비차단 받기에서 도착한 ข้อมูล 없음 |
| -14 | ผู้ใช้ ตัวชี้/อาร์เรย์_ค่า คลิป ข้อผิดพลาด |
| -19 | สนับสนุน_ค่า NIC 없음 |
| -22 | แปลง_ค่า/รอเดี๋ยว_ค่า ค่าเวลา/อาร์กิวเมนต์ ค่า ข้อผิดพลาด |
| -24 | 열린 เครือข่าย_แปลง 4개 한도 |
| -38 | 알 หมายเลข 없는 시스템 호출 |
| -90 | ข้อมูล 또는 รับ_ค่า อาร์เรย์_ค่า ขนาด 문제 |
| -98 | ท้องถิ่น_ขอบเขต แปลง_ค่า ดัชนี 중복 |
| -101 | 지원하지 않는 ปลายทาง_ค่า_a0fbc067 อีเมล |
| -110 | ARP·อุปกรณ์_ค่า·รับ_ค่า ค่าเวลา 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 การเข้ารหัส_ค่า 있는 Java `int`의 บิต_ค่า 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 หมายเลข 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## ดําเนินการ_คําสั่ง 경계와 시스템 호출

```text
เชลล์ run → JKAP에서 ELF ตรวจสอบความถูกต้อง·적재 → ring 3 ผู้ใช้ แอป_f5044b9b
                                 ↓ int 0x80
                      ตัวชี้ 검사 → Java เคอร์เนล_ค่า API → RTL8139/UDP
                                 ↓ ออก_แอป·ข้อยกเว้น·ค่าเวลา 초과
                                เชลล์ 복귀
```

시스템 호출 레지스터는 `EAX=ดัชนี`, `EBX,ECX,EDX,ESI,EDI=อาร์กิวเมนต์`, `EAX=ผลลัพธ์`다. Java 호출 ตัวถูกดําเนินการ_สแตก ABI는 컴파일러가 ผู้ใช้ 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| ดัชนี | 호출 |
| --- | --- |
| 0 | ออก_แอป(สถานะ_ค่า รหัส_ค่า) — เรียกใช้งาน/ข้อผิดพลาด 런타임에서 ใช้_ค่า |
| 1 | สตริง_ค่า เขียน |
| 2 / 3 | อาร์กิวเมนต์ 개수 / อาร์กิวเมนต์ สตริง_ค่า อีเมล |
| 10 | UDP เปิด |
| 11 | UDP ส่ง(จุดจับ_ค่า, IP, ปลายทาง_ค่า_a0fbc067 แปลง_ค่า, อาร์เรย์_ค่า อีเมล, 길이) |
| 12 | UDP รับ(จุดจับ_ค่า, อาร์เรย์_ค่า อีเมล, 제한 밀리초) |
| 13 | UDP ปิด |
| 14 | ท้องถิ่น_ขอบเขต IP อีเมล |
| 15 / 16 | 마지막 ชั้น_ค่า IP / UDP แปลง_ค่า |
| 20 | RAM แฟ้ม อ่าน(ชื่อ int[] อีเมล, ข้อความออก int[] อีเมล) |
| 21 | RAM แฟ้ม เขียน(ชื่อ int[] อีเมล, 입력 int[] อีเมล, ไบต์_ค่า 길이) |
| 22 | UTF-16 รหัส_ค่า หน่วย_ค่า 문자 ข้อความออก(0~65535) |

แฟ้ม API는 `ผู้ใช้.파일읽기(int[] ชื่อ, int[] ข้อมูล)`와 `ผู้ใช้.파일쓰기(int[] ชื่อ, int[] ข้อมูล, int 길이)`다. 이름은 ASCII รหัส_ค่า อาร์เรย์_ค่า(최대 64칸, 0 ออก_แอป 또는 อาร์เรย์_ค่า 끝), ข้อมูล รายการ_องค์ประกอบ 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 แฟ้ม 없음 `-2`, ตัวชี้ ข้อผิดพลาด `-14`, ชื่อ/길이 ข้อผิดพลาด `-22`, แฟ้ม 슬롯 부족 `-28`, ขนาด 초과 `-90`을 반환한다. 쓰기는 ตรวจสอบความถูกต้อง 후 แฟ้ม 전체를 대체한다. `ผู้ใช้.문자쓰기(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 ผู้ใช้ 모드에서 CS의 하위 비트를 직접 읽으므로 ค่าจริง_ข้อมูล ดําเนินการ_คําสั่ง 권한을 확인한다. เคอร์เนล_ค่า ฮาร์ดแวร์_แปลง 접근용 `อุปกรณ์_ค่า` native 함수는 ผู้ใช้ เป้าหมาย 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 ดําเนินการ_คําสั่ง, 파이프, 프로세스 간 통신은 없다. ดําเนินการ_คําสั่ง 파일은 커널의 อ่าน 전용 JKAP 묶음에서 적재한다. ข้อมูล 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- ผู้ใช้ 가상 อีเมล `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. ดําเนินการ_คําสั่ง 영상은 กล้องหน้า_ค่า 2MiB, 인수는 `0x04300000`부터, 스택은 ขอบเขต_ค่า 끝에서 시작한다. เคอร์เนล_ค่า identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB ผู้ใช้ 영역을 비우고 แฟ้ม 구역을 복사해 BSS·อาร์เรย์_ค่า 영역을 초기화한다. ผู้ใช้ GC는 없지만 ออก_แอป 후 ถัดไป_รายการ ดําเนินการ_คําสั่ง 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 ยกคําพูด/이스케이프 파싱은 없다.
- ผู้ใช้ 페이지의 รหัส_ค่า/ข้อมูล 분리 อ่าน 전용 ตั้งค่า, NX, ตัวถูกดําเนินการ_สแตก guard, ASLR은 아직 없다. 커널과 ผู้ใช้ ความจํา_ข้อมูล·ฮาร์ดแวร์_แปลง สิทธิ์_ค่า 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 ดําเนินการ_คําสั่ง 상한을 두며 ค่าเวลา 초과는 `Exit: 124`다. ผู้ใช้ CPU 예외는 `128 + ข้อยกเว้น ดัชนี`(페이지 ข้อผิดพลาด 142, 특권 위반 141), Java อาร์เรย์_ค่า/계산 오류는 101~105다. เคอร์เนล_ค่า 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, คงที่_ค่า IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP 검사합 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- ผู้ใช้ ดําเนินการ_คําสั่ง·네트워크·ป้องกัน_ค่า 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 ดําเนินการ_คําสั่ง·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## ตรวจสอบความถูกต้อง 근거

`make test`는 คอมไพเลอร์ 14개 시험, Java 패킷 โรค 2,201개 검사, 기존 เชลล์ ELF/ISO 부팅 시험, ผู้ใช้ ELF/ค่าจริง_ข้อมูล UDP/ป้องกัน_ค่า 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 길이·해시까지 `os/build/การทดสอบ_ผู้ใช้_เครือข่าย.json`에 기록한다. 시험용 손상된 ELF·특권 คําสั่ง·무한 สปรินต์_ค่า 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
