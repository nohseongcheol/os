# ผู้ใช้ 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `เครื่อง/ระบบปฏิบัติการ_การโทร.s`에서 EAX(ดัชนี), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 อาร์กิวเมนต์)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. เคอร์เนล_ค่า 실패는 음수 ข้อผิดพลาด ดัชนี, C ไลบรารี 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 ผู้ใช้ ขอบเขต_ค่า 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C ข้อมูล 주소는 ไบต์_ค่า 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java แฟ้ม 흐름의 어셈블리 경계가 별도 ไบต์_ค่า 버퍼를 마련하여 같은 호출을 사용한다.

| 33 | ปิด_แฟ้ม | 서술자 |

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 อีเมล 두 칸이다. รับ_ค่า 주소가 NULL이면 ชั้น_ค่า อีเมล 기록을 생략한다. sockaddr_in은 16바이트이며 อีเมล 체계는 อุปกรณ์_ค่า ไบต์_ค่า ลําดับ_ค่า_e9fa7815, 접속번호와 IP 주소는 네트워크 ไบต์_ค่า 차례다. 축소된 อีเมล 버퍼에도 들어가는 앞부분을 쓰고 전체 อีเมล ขนาด 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 ออก_แอป, 2·3은 기존 อาร์กิวเมนต์ 조회다. ปัจจุบัน_รายการ 커널의 อาร์กิวเมนต์ 목록이 ดําเนินการ_คําสั่ง 이름을 제외하므로 C 진입기는 argv[0]에 고정 สตริง_ค่า `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX กระบวนการ_ค่า ABI와 다른 점이다.

표준 헤더의 จํานวนเต็ม ขนาด, 플래그 ค่า, stat ค่าเขตข้อมูล 순서는 `รหัสต้นฉบับ/포함/`에 정의한다. 동적 เชื่อมต่อ·다중 กระบวนการ_ค่า·스레드가 추가되면 ข้อผิดพลาด ดัชนี 저장과 ทรัพยากร_ค่า 수명, 호출 경계도 함께 검토해야 한다.
