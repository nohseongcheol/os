# کاربر 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `دستگاه/سیستم_عامل_تماس_ها.s`에서 EAX(فهرست), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 نشانوندها)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. هسته_مقدار 실패는 음수 خطا فهرست, C کتابخانه 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 کاربر 영역 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C داده_ها 주소는 بایت_مقدار 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java پرونده 흐름의 어셈블리 경계가 별도 بایت_مقدار 버퍼를 마련하여 같은 호출을 사용한다.

| فهرست | کنش | نشانوندها |
|---|---|---|
| 30 | ایجاد_فایل | NUL 끝 نام آدرس, تنظیمات, 허가 |
| 31 | 파일자료읽기 | 서술자, داده_ها آدرس, بایت_مقدار 수 |
| 32 | نوشتن_فایل_داده_ها | 서술자, داده_ها آدرس, بایت_مقدار 수 |
| 33 | بستن_فایل | 서술자 |
| 34 | جستجو_کردن_فایل | 서술자, رمزگذاری_مقدار 있는 جابجایی_لایه_ای_مقدار, نمایش_دادن_جذر |
| 35 | 파일서술자복제 | 서술자 |
| 36 | 파일서술자지정복제 | 서술자, 새 서술자 |
| 37 | 파일상태읽기 | 서술자, 48바이트 وضعیت_مقدار آدرس |
| 38 | حذف_فایل_ورودی_نام | NUL 끝 نام آدرس |
| 39 | مجموعه_فایل_طول | 서술자, 새 طول_مقدار |
| 40 | 파일서술자제어 | 서술자, فرمان, مقدار |
| 41 | 통신종단점만들기 | آدرس سیستم_عامل_مقدار, 종류, شغل_مقدار فهرست |
| 42 | مرتبط_سازی_آدرس | 서술자, sockaddr_in آدرس, طول_مقدار |
| 43 | 자료전문보내기 | 서술자, داده_ها آدرس, طول_مقدار, تنظیمات, 요청 آدرس |
| 44 | 자료전문받기 | 서술자, داده_ها آدرس, طول_مقدار, تنظیمات, 요청 آدرس |
| 45 | 통신주소읽기 | 서술자, sockaddr آدرس, socklen_t آدرس |
| 46 | 수신대기정하기 | 서술자, 0~2000 밀리초 |
| 47 | 파일저장확정 | 서술자 |

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 آدرس 두 칸이다. 수신 주소가 NULL이면 مشابه_مقدار آدرس 기록을 생략한다. sockaddr_in은 16바이트이며 آدرس 체계는 دستگاه_مقدار بایت_مقدار 차례, 접속번호와 IP 주소는 네트워크 بایت_مقدار 차례다. 축소된 آدرس 버퍼에도 들어가는 앞부분을 쓰고 전체 آدرس اندازه 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 خروج_برنامه, 2·3은 기존 نشانوندها 조회다. 현재 커널의 نشانوندها 목록이 اجرا_فرمان 이름을 제외하므로 C 진입기는 argv[0]에 고정 رشته_مقدار_6ca8363c `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX فرآیند_مقدار ABI와 다른 점이다.

표준 헤더의 عدد_صحیح اندازه, 플래그 مقدار, stat فیلد_مقدار 순서는 `مبداء/포함/`에 정의한다. 동적 اتصال·다중 فرآیند_مقدار·스레드가 추가되면 خطا فهرست 저장과 منبع_مقدار 수명, 호출 경계도 함께 검토해야 한다.
