# JTjkOS

현재 بومی ARM64 배포판은 [LICENSE](LICENSE)의 COSL 상업 조건을 유지한다. 제3자 라이선스의 권리는 별도로 보장하며, 배포 시 منبع_درخت·재연결 자료를 포함하는 절차는 [COSL 배포 مرا_بخوان_eb81d7d9](platforms/rpi4-native/COSL배포안내.md)에 있다.

بومی ARM64 판의 `ipconfig`/`ip`, `ping`, `ps`/`top`, `free`/`df`, `poweroff`와 فارسی 명령은 [네트워크·سیستم_عامل_مقدار فرمان مرا_بخوان_eb81d7d9](platforms/rpi4-native/네트워크와체계명령.md)를 참고한다. 새 커널을 부팅한 برگشت_مقدار `help system`으로 볼 수 있다.

Raspberry Pi 4 **بومی Java ARM64 هسته_مقدار**은 [بومی Pi4 مرا_بخوان_eb81d7d9](platforms/rpi4-native/مرا_بخوان_eb81d7d9.md)에 있다. Linux 없이 부팅하며 GUI پایانه·vi, بومی JVM의 Swing 일부 API, TCP/UDP·FTP, 게스트 TinyCC·MicroPython, C/C++의 posix-kor 호출을 제공한다. [فارسی Java 통신·استثنا API](platforms/rpi4-native/한국어자바/مرا_بخوان_eb81d7d9.md)와 [فارسی منبع_درخت 명명](platforms/rpi4-native/명명/مرا_بخوان_eb81d7d9.md)을 지원한다. [بومی SSH·VNC 및 GENET 드라이버](platforms/rpi4-native/외부접속안내.md)를 포함하며, 네트워크는 QEMU의 UART SLIP 경로로 검증했다. واقعی_داده_ها Pi 4 GENET 동작은 미검증이고, USB 입력·영속 저장과 전체 OpenJDK·Swing은 아직 پشتیبان_مقدار کلیپ 밖이다.

Raspberry Pi 4용 Linux·OpenJDK 실행판과 کاربر 환경 انتقال_مقدار 기능은 [라즈베리파이 실행판](platforms/rpi4/README.md)에 있다. واقعی_داده_ها ARM64 JDK/JRE와 시스템·کاربر ساخت_عکس ساخت_سیستم 경로를 제공한다. 기존 بومی x86 커널과는 별도 اجرا_فرمان 기반이다. 일반 Java `.class`/JAR의 اجرا_فرمان پرونده 생성은 [OpenJDK اجرا_فرمان پرونده](compiler/OpenJDK-실행파일.md), فارسی API는 [فارسی Java کتابخانه](한국어자바/مرا_بخوان_eb81d7d9.md)를 참고한다.

`jkoros`는 `engos`의 기능을 Java 관리 커널로 옮기는 프로젝트다. 프로젝트가 소유하는 Java عملکرد_مقدار, 변수, قالب_مقدار 및 Java پرونده 이름은 한국어로 작성한다. 표준 Java 실행기의 `main`, Java 표준 کتابخانه قالب_مقدار, x86 부트 ABI 등 외부 계약은 보존한다. بومی ARM64 실행기는 فارسی `اجرا_2()`도 진입점으로 지원하며, فارسی GUI·작업 가닥을 JVM에 직접 구현했다. بومی ARM64 C 연결부·Python 도구와 공용 x86·ARM64 AOT 번역기의 بومی 이름도 한국어로 작성한다. 이전 경로의 호환 ورودی_نقطه, OpenJDK 보조 도구와 Linux نسخه_مقدار 도구에는 영어 이름이 남아 있고 [명명 원칙·말의 근거·전체 مبداء 검토 کلیپ](platforms/rpi4-native/명명/مرا_بخوان_eb81d7d9.md)를 별도로 기록한다.

## 현재 구현

아래 목록은 기존 `موروثی_منبع/`의 JVM 관리 커널에 대한 것이다. واقعی_داده_ها 네이티브 커널의 범위는 `os/مرا_بخوان_eb81d7d9.md`에서 별도로 설명한다.

- تراز_کردن_مقدار 할당과 해제를 지원하는 기억공간 مدیر_مقدار
- آدرس 공간, صفحه_مقدار اتصال, نوشتن 시 کپی_مقدار(COW)
- فرآیند_مقدار شناسه_مقدار, آماده_کردن 대기열, fork/wait وضعیت_مقدار
- 과정별 پرونده 서술자, open/read/seek/dup/close
- ELF32 식별 및 قسمت_مقدار 검사
- 키보드·마우스 입력 رویداد 대기열
- 직렬 단말과 네이티브 하드웨어 경계
- 관리 هسته_مقدار 전체 자동 시험

세부 대응 범위와 아직 필요한 네이티브 연결은 [기능 대응표](문서/기능대응.md)에 기록한다.

## 빌드와 시험

새 네이티브 구현은 `compiler/`와 `os/`에 있다. 기존 `موروثی_منبع/`의 JVM 관리 커널은 그대로 보존하며, 두 구현의 시험과 기능 범위는 서로 다르다.

```sh
cd /home/user/jkoros
make                 # 네이티브 계산 예제 + Java هسته_مقدار ELF
make iso             # os/build/kernel.iso
make run             # QEMU 직렬 단말; help 입력 (종료는 Ctrl+A, X)
make run-gui         # ISO를 QEMU 화면/PS2 키보드로 اجرا_فرمان
make vbox            # 전용 VirtualBox VM 자동 ایجاد·اجرا_فرمان (GUI)
make vbox-status     # VirtualBox وضعیت_مقدار·ISO·직렬 واقعه_نگار_ردیف مسیر تأیید_صحت
make test-vbox       # VirtualBox برنامه_راه_انداز وضعیت_مقدار فرآیند_مقدار_ورودی 시험 (واقعی_داده_ها VM تغییر_مقدار 없음)
make test            # 컴파일러 시험 + ELF/ISO 부팅 및 فرمان 입력 시험
make apps            # 독립 کاربر ELF برنامه_f5044b9b ساخت_سیستم
make test-network    # کاربر حالت_مقدار·UDP 왕복·حافظه_داده_ها حفاظت_کردن_مقدار 시험
make test-java       # 게스트 javac/JVM + OpenJDK 양방향 교차 اجرا_فرمان 시험
make posix-kor       # فارسی C 헤더와 واقعی_داده_ها هسته_مقدار 호출 کتابخانه
make test-posix      # پرونده/UDP/ذخیره_مقدار/Java پرونده ورودی_خروجی 시험
make -C os run-store # 전용 ذخیره_مقدار 매체로 QEMU 부팅
make legacy-test     # 아래 기존 JVM 관리 커널의 47개 시험
```

`compiler/`는 호스트의 `javac`를 문법·تایپ_کردن_مقدار 검사 전단으로 사용하고 بومی 바이트코드→x86 변환기로 ELF32 기계어를 만든다. 빌드할 때는 JDK가 필요하지만 생성된 커널과 ELF는 외부 JVM 없이 실행된다. 전체 Java, شئ_مقدار 모델, 표준 라이브러리와 기존 관리 هسته_مقدار 전체의 AOT 변환은 아직 지원하지 않는다. 자세한 پشتیبان_مقدار 문법과 명령은 [컴파일러 مرا_بخوان_eb81d7d9](compiler/مرا_بخوان_eb81d7d9.md), واقعی_داده_ها 부팅 기능과 한계는 [네이티브 سیستم_عامل مرا_بخوان_eb81d7d9](os/مرا_بخوان_eb81d7d9.md)를 참고한다.

네이티브 셸에 بومی 제한형 `javac`와 `java`를 추가했다. `edit Demo.java`로 소스를 입력하고 `.save`로 저장한 برگشت_مقدار `javac Demo.java`, `java Demo`로 **게스트 내부에서 컴파일하고 اجرا_فرمان**할 수 있다. مقدار_پیش_فرض 예제는 `javac Hello.java`, `java Hello`다. 파일은 RAM에서 동작하며, 전용 ذخیره_مقدار 매체를 연결하면 `sync`로 재부팅 후에도 보존할 수 있다. **OpenJDK/JDK 전체 이식은 아니며**, 단일 کلاس_مقدار·ایستا_مقدار عملکرد_مقدار·عدد_صحیح·رشته_مقدار_6ca8363c·شرط/반복문과 일부 표준 호출을 지원한다. پشتیبان_مقدار کلیپ, 외부 پرونده 적재와 시험은 [Java 개발 환경 مرا_بخوان_eb81d7d9](문서/자바개발환경.md)에 있다.

네이티브 셸에서 `apps`, `run hello first second`, `net`, `run netcheck`를 사용할 수 있다. 독립 ELF를 ring 3에 적재하고 `int 0x80` 호출을 통해 خروجی·نشانوندها·UDP 네트워크를 제공한다. 별도 میزبان 터미널에서 `python3 os/ابزارها/자료되돌리기.py --port 9000`을 실행한 برگشت_مقدار 게스트에서 `run udp 10.0.2.2 9000 hello`로 واقعی_داده_ها 왕복을 확인한다. 새 برنامه_f5044b9b ثبت_نام_ورودی, API 및 제한은 [کاربر اجرا_فرمان·네트워크 مرا_بخوان_eb81d7d9](os/کاربر/مرا_بخوان_eb81d7d9.md)를 참고한다. 현재 QEMU RTL8139·ایستا_مقدار IPv4·UDP 전용이며 TCP/DNS는 미지원이며, 전용 IDE ذخیره_مقدار 형식과 POSIX پرونده/UDP 일부 기능을 추가했다.

`make vbox`는 `jkoros operating system` 전용 VM을 만들고 디스크 없이 ISO로 부팅한다. اجرا_فرمان 중이면 유지하고, ذخیره_مقدار·일시정지 상태이면 재개하며, 꺼져 있을 때만 새 ISO를 빌드해 연결한다. VirtualBox에서 부팅과 셸의 کاربر برنامه_f5044b9b 실행을 확인했다. 다만 현재 VirtualBox용 네트워크 드라이버는 없어 네트워크 장치를 비활성화한다. UDP 시험에는 `make run`을 사용한다. 상태별 동작과 새 ساخت_سیستم 반영 방법은 [VirtualBox اجرا_فرمان مرا_بخوان_eb81d7d9](문서/가상상자실행.md)에 있다.

기존 관리 커널만 시험하려면:

```sh
cd /home/user/jkoros
make -f ایجاد_ورودی.mk 검사
make -f ایجاد_ورودی.mk میزبان
```

`میزبان`는 여전히 JVM 관리 계층의 کنش 시험이다. `make -f ایجاد_ورودی.mk ساخت_عکس`는 새 `os/`의 제한형 네이티브 هسته_مقدار ISO를 만든다. 기존 `موروثی_منبع/`의 سیستم_پرونده·فرآیند_مقدار·شبکه_پشته 구현 전체를 이 ISO에 이식했다는 의미는 아니다.

فارسی عملکرد_مقدار·변수·پرونده 이름과 واقعی_داده_ها C API는 [posix-kor](posix-kor/مرا_بخوان_eb81d7d9.md)에 있다. 게스트 Java에서는 `FileInputStream`·`FileOutputStream`의 단일 بایت_مقدار 입출력도 지원한다. 전체 POSIX·OpenJDK·Swing 지원으로 확대된 것은 아니다.

외부 배포용 `pack.sh` / `unpack.sh`와 자동 의존성 복원은 [배포 مرا_بخوان_eb81d7d9](distribution/README.md)를 참고하세요.
