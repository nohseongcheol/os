## 가능한 реализация путь

1. **свой 커널에 공식 CLI 직접 이식**
   영속 Store_ЗНАЧЕН/VFS와 пространство_пользователя Память_данные, 프로세스·스레드·I/O, libc/런타임, DNS/HTTPS,
   терминал·Полномочие_ЗНАЧЕН 체계를 갖춘다. 이후 целевое_значение 버전의 의존성을 조사하여 크로스 сборка·이식한다.
   Linux 커널을 반드시 탑재할 필요는 없지만, 공식 Linux 바이너리를 그대로 쓸 경우
   그 바이너리가 사용하는 Linux ABI까지 호환해야 한다. 큰 операционная_система 개발 과제다.

2. **внешний_ЗНАЧЕН узел Codex와 свой ядро_ЗНАЧЕН Подключить — 첫 구현으로 권장**
   Linux PC에서 공식 CLI 또는 app-server를 실행하고 jkoros에는 전용 пространство_пользователя команда/화면을 만든다.
   호스트의 인증된 연결과 게스트 файл Чтение·수정·업로드·команда 실행 어댑터가 필요하다.
   기존 SSH/TCP 경로를 활용할 수 있으나, файл 동기화나 Codex 전용 어댑터는 текущий_товар 구현되어 있지 않다.
   호스트에서 수행한 빌드와 게스트에서 수행한 실행 결과를 명확히 구분한다.
   이 구성은 свой 커널을 유지하지만, 공식 CLI 자체는 внешний_ЗНАЧЕН 호스트에서 실행된다.

3. **свой API 클라이언트 제작**
   свой ABI의 C 또는 지원되는 Java 부분집합으로 интерактивный_сеанс UI와 файл/команда инструменты 호출 루프를 만든다.
   внешний_ЗНАЧЕН 중계기를 쓰지 않는다면 DNS/проверить 가능한 TLS/HTTPS와 인증 данные 저장을 먼저 구현해야 한다.
   이는 OpenAI API를 이용하는 별도 에이전트이며 공식 Codex CLI 전체의 이식으로 표시하지 않는다.

4. **별도 ARM64 Linux 실행판에서 установить_ЗНАЧЕН**
   `../rpi4`는 Linux와 musl 기반이므로 일반 Linux установить_ЗНАЧЕН 경로를 검토할 수 있다.
   사용할 Codex 버전의 ARM64·musl 호환성, 의존성, 커널의 샌드박스 지원을 фактический_данные 검증해야 한다.
   이번 검토에서 установить_ЗНАЧЕН 성공을 확인하지 않았다. 이 결과를 свой Java 커널의 지원으로 표시하지 않는다.
