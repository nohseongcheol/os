# 셸에서 실행하는 корбар 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 файли_тафсилот_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 иҷро_кардан_фармон

мизбон 터미널 1:

```sh
cd /home/user/jkoros
python3 os/Абзорҳо/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 외부 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

мизбон 터미널 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 воқеӣ_иттилоот CPU иҷозат_қимат `ring 3`, 인수 출력.
- `netcheck`: порт_қимат 중복, 잘못된 дастак_қимат/курсор/дарозӣ_қимат, 비차단 받기와 시간 초과 тасдиқ_кардан.
- `udp`: IPv4 суроға·ҷои_таъинот_қимат порт_қимат·한 Калимабозӣ_қимат 메시지를 받아 UDP로 보내고 같은 응답을 тасдиқ_кардан. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: мизбон `10.0.2.2`의 지정 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 ҳалқа_қимат 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 현재 주소는 게스트 `10.0.2.15/24`, 관문 `10.0.2.2`로 고정돼 있다. QEMU корбар 네트워크의 мизбон дастрасӣ_ворида 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 барнома_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java барнома_f5044b9b 추가

`예제/내프로그램.java`를 다음 형식으로 만든다. 진입점은 인수 없는 `static int` 또는 `static void` 함수다. 인수는 корбар API로 조회한다.

```java
public final class 내프로그램 {
    public static int порча() {
        корбар.Навиштан("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/корбар/барнома_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := корбар/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.порча
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `корбар/선언/корбар.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 иҷро_кардан_фармон 중인 VM에는 сохт_система 결과가 자동 반영되지 않는다. барнома_f5044b9b 이름은 현재 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java синф_қимат·функсия_қимат·변수에는 한국어를 쓴다. 최대 32개 барнома_f5044b9b, 한 иҷро_кардан_фармон 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.порча \
    -o os/build/apps/hello.elf os/корбар/선언/корбар.java os/корбар/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 мизбон 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 Дастгирӣ_қимат клип 안에서 실행한다. `.jar`와 일반 Linux иҷро_кардан_фармон 파일은 지원하지 않는다.

## корбар 네트워크 API

선언은 `선언/корбар.java`에 있다. `фиристодан_иттилоот`/`자료받기`의 `int[]` объект_унсур 한 개는 байт_қимат 하나(0~255)를 나타낸다. 한 데이터그램의 최대 иттилоот 길이는 1,024바이트다.

```java
int дастак_қимат = корбар.кушодан_Шабака(0); // 0: 임시 маҳаллӣ_ҳаҷм UDP порт_қимат 자동 интихоб_қимат
int[] иттилоот = new int[32];
иттилоот[0] = 'H'; иттилоот[1] = 'i';
int 보낸길이 = корбар.фиристодан_иттилоот(дастак_қимат, 0x0a000202, 9000, иттилоот, 2);
int 받은길이 = корбар.자료받기(дастак_қимат, иттилоот, 1500);
корбар.пӯшидан_Шабака(дастак_қимат);
```

воқеӣ_иттилоот 프로그램에서는 кушодан·фиристодан·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 대기 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 추가 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | дастак_қимат·Раванд_қимат_ворида дарозӣ_қимат·성공 등 해당 함수의 결과 |
| -5 | мобилӣ_қимат фиристодан_қимат нокомӣ_қимат |
| -9 | 잘못되었거나 닫힌 통신 дастак_қимат |
| -11 | 비차단 받기에서 도착한 иттилоот 없음 |
| -14 | корбар курсор/қатор_қимат клип Хато |
| -19 | Дастгирӣ_қимат NIC 없음 |
| -22 | порт_қимат/대기 시간/인수 қимат Хато |
| -24 | 열린 Шабака_порт 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | иттилоот 또는 수신 қатор_қимат андоза_кардан 문제 |
| -98 | маҳаллӣ_ҳаҷм порт_қимат индекс 중복 |
| -101 | 지원하지 않는 ҷои_таъинот_қимат суроға |
| -110 | ARP·мобилӣ_қимат·수신 시간 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 рамзгузорӣ_қимат 있는 Java `int`의 бит_қимат 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## иҷро_кардан_фармон 경계와 시스템 호출

```text
восит run → JKAP에서 ELF санҷидани_эътибор·적재 → ring 3 корбар барнома_f5044b9b
                                 ↓ int 0x80
                      курсор 검사 → Java ҳаста_қимат API → RTL8139/UDP
                                 ↓ Баромад_барнома·예외·시간 초과
                                восит 복귀
```

시스템 호출 레지스터는 `EAX=индекс`, `EBX,ECX,EDX,ESI,EDI=인수`, `EAX=결과`다. Java 호출 스택 ABI는 컴파일러가 корбар 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| индекс | 호출 |
| --- | --- |
| 0 | Баромад_барнома(вазъият_қимат 코드) — порча/Хато 런타임에서 사용 |
| 1 | сатр_қимат_6ca8363c Навиштан |
| 2 / 3 | 인수 개수 / 인수 сатр_қимат_6ca8363c суроға |
| 10 | UDP кушодан |
| 11 | UDP фиристодан(дастак_қимат, IP, ҷои_таъинот_қимат порт_қимат, қатор_қимат суроға, дарозӣ_қимат) |
| 12 | UDP 받기(дастак_қимат, қатор_қимат суроға, 제한 밀리초) |
| 13 | UDP Пӯшидан |
| 14 | маҳаллӣ_ҳаҷм IP суроға |
| 15 / 16 | 마지막 ҳамсон_қимат IP / UDP порт_қимат |
| 20 | RAM Файл Хондан(Ном int[] суроға, 출력 int[] суроға) |
| 21 | RAM Файл Навиштан(Ном int[] суроға, 입력 int[] суроға, байт_қимат дарозӣ_қимат) |
| 22 | UTF-16 코드 дарс_қимат 문자 출력(0~65535) |

Файл API는 `корбар.파일읽기(int[] Ном, int[] иттилоот)`와 `корбар.навиштан_файл(int[] Ном, int[] иттилоот, int дарозӣ_қимат)`다. 이름은 ASCII 코드 қатор_қимат(최대 64칸, 0 Баромад_барнома 또는 қатор_қимат 끝), иттилоот объект_унсур 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 Файл 없음 `-2`, курсор Хато `-14`, Ном/дарозӣ_қимат Хато `-22`, Файл ковокӣ_қимат 부족 `-28`, андоза_кардан 초과 `-90`을 반환한다. 쓰기는 санҷидани_эътибор 후 Файл 전체를 대체한다. `корбар.навиштан_аломат_қимат(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 корбар 모드에서 CS의 하위 비트를 직접 읽으므로 воқеӣ_иттилоот иҷро_кардан_фармон 권한을 확인한다. ҳаста_қимат 포트 접근용 `мобилӣ_қимат` native 함수는 корбар ҳадаф 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 иҷро_кардан_фармон, 파이프, 프로세스 간 통신은 없다. иҷро_кардан_фармон 파일은 커널의 Хондан 전용 JKAP 묶음에서 적재한다. иттилоот 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- корбар 가상 суроға `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. иҷро_кардан_фармон 영상은 앞 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. ҳаста_қимат identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB корбар 영역을 비우고 Файл 구역을 복사해 BSS·қатор_қимат 영역을 초기화한다. корбар GC는 없지만 Баромад_барнома 후 다음 иҷро_кардан_фармон 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 따옴표/이스케이프 파싱은 없다.
- корбар 페이지의 코드/иттилоот 분리 Хондан 전용 Танзимот, NX, 스택 guard, ASLR은 아직 없다. 커널과 корбар ҳофиза_иттилоот·포트 иҷозат_қимат 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 иҷро_кардан_фармон 상한을 두며 시간 초과는 `Exit: 124`다. корбар CPU 예외는 `128 + 예외 индекс`(페이지 Хато 142, 특권 위반 141), Java қатор_қимат/계산 오류는 101~105다. ҳаста_қимат 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, собит_қимат IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP 검사합 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- корбар иҷро_кардан_фармон·네트워크·муҳофизат_кардан_қимат 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 иҷро_кардан_фармон·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## санҷидани_эътибор 근거

`make test`는 컴파일러 14개 시험, Java 패킷 шарт 2,201개 검사, 기존 восит ELF/ISO 부팅 시험, корбар ELF/воқеӣ_иттилоот UDP/муҳофизат_кардан_қимат 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 дарозӣ_қимат·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 фармон·무한 такрор_қимат 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
