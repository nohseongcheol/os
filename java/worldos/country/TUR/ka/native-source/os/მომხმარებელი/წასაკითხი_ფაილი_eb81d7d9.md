# 셸에서 실행하는 მომხმარებელი 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 환경 წასაკითხი_ფაილი_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 შესრულება_ბრძანება

მასპინძელი ტერმინალი 1:

```sh
cd /home/user/jkoros
python3 os/ხელსაწყოები/자료되돌리기.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. 외부 연결을 받도록 방화벽이나 포트 전달을 변경하지 않는다. Ctrl+C로 종료한다.

მასპინძელი ტერმინალი 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 რეალური_მონაცემები CPU ნებართვა_მნიშვნელობა `ring 3`, 인수 출력.
- `netcheck`: პორტი_მნიშვნელობა 중복, 잘못된 სახელური_მნიშვნელობა/კურსორი/სიგრძე_მნიშვნელობა, 비차단 받기와 დრო_მნიშვნელობა 초과 გადამოწმება.
- `udp`: IPv4 მისამართი·მიმართულება_მნიშვნელობა პორტი_მნიშვნელობა·한 სიტყვები_მნიშვნელობა 메시지를 받아 UDP로 보내고 같은 응답을 გადამოწმება. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: მასპინძელი `10.0.2.2`의 지정 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. 수신 ციკლი_მნიშვნელობა_201e2521 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. 현재 주소는 게스트 `10.0.2.15/24`, კარიბჭე_მნიშვნელობა `10.0.2.2`로 고정돼 있다. QEMU მომხმარებელი 네트워크의 მასპინძელი წვდომა_შენატანი 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 აპი_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java აპი_f5044b9b 추가

`예제/내프로그램.java`를 შემდეგი_ელემენტი 형식으로 만든다. 진입점은 인수 없는 `static int` 또는 `static void` 함수다. 인수는 მომხმარებელი API로 조회한다.

```java
public final class 내프로그램 {
    public static int გაშვება() {
        მომხმარებელი.ჩაწერა("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/მომხმარებელი/აპი_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := მომხმარებელი/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.გაშვება
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `მომხმარებელი/선언/მომხმარებელი.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 შესრულება_ბრძანება 중인 VM에는 აწყობა_სისტემა 결과가 자동 반영되지 않는다. აპი_f5044b9b 이름은 현재 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java კლასი_მნიშვნელობა·ფუნქცია_მნიშვნელობა·변수에는 한국어를 쓴다. 최대 32개 აპი_f5044b9b, 한 შესრულება_ბრძანება 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/컴파일러.py --target user --entry 인사.გაშვება \
    -o os/build/apps/hello.elf os/მომხმარებელი/선언/მომხმარებელი.java os/მომხმარებელი/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 მასპინძელი 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 მხარდაჭერა_მნიშვნელობა კლიპი 안에서 실행한다. `.jar`와 일반 Linux შესრულება_ბრძანება 파일은 지원하지 않는다.

## მომხმარებელი 네트워크 API

선언은 `선언/მომხმარებელი.java`에 있다. `გაგზავნა_მონაცემები`/`자료받기`의 `int[]` ელემენტი_ელემენტი 한 개는 ბაიტი_მნიშვნელობა 하나(0~255)를 나타낸다. 한 데이터그램의 최대 მონაცემები 길이는 1,024바이트다.

```java
int სახელური_მნიშვნელობა = მომხმარებელი.გახსნა_ქსელი(0); // 0: 임시 ლოკალური_არეალი UDP პორტი_მნიშვნელობა 자동 მონიშნული_ობიექტი_მნიშვნელობა
int[] მონაცემები = new int[32];
მონაცემები[0] = 'H'; მონაცემები[1] = 'i';
int 보낸길이 = მომხმარებელი.გაგზავნა_მონაცემები(სახელური_მნიშვნელობა, 0x0a000202, 9000, მონაცემები, 2);
int 받은길이 = მომხმარებელი.자료받기(სახელური_მნიშვნელობა, მონაცემები, 1500);
მომხმარებელი.დახურვა_ქსელი(სახელური_მნიშვნელობა);
```

რეალური_მონაცემები 프로그램에서는 გახსნა·გაგზავნა·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `자료받기`의 მოლოდინი_მნიშვნელობა 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 수신 대기열은 한 개뿐이므로 추가 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | სახელური_მნიშვნელობა·პროცესი_მნიშვნელობა_შენატანი სიგრძე_მნიშვნელობა·성공 등 해당 함수의 გაზომვა |
| -5 | მობილური_მნიშვნელობა გაგზავნა_მნიშვნელობა მარცხი_მნიშვნელობა |
| -9 | 잘못되었거나 닫힌 통신 სახელური_მნიშვნელობა |
| -11 | 비차단 받기에서 도착한 მონაცემები 없음 |
| -14 | მომხმარებელი კურსორი/მასივი_მნიშვნელობა კლიპი შეცდომა |
| -19 | მხარდაჭერა_მნიშვნელობა NIC 없음 |
| -22 | პორტი_მნიშვნელობა/მოლოდინი_მნიშვნელობა დრო_მნიშვნელობა/인수 მნიშვნელობა შეცდომა |
| -24 | 열린 ქსელი_პორტი 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | მონაცემები 또는 수신 მასივი_მნიშვნელობა ზომა 문제 |
| -98 | ლოკალური_არეალი პორტი_მნიშვნელობა ინდექსი 중복 |
| -101 | 지원하지 않는 მიმართულება_მნიშვნელობა მისამართი |
| -110 | ARP·მობილური_მნიშვნელობა·수신 დრო_მნიშვნელობა 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 კოდირება_მნიშვნელობა 있는 Java `int`의 ბიტი_მნიშვნელობა 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## შესრულება_ბრძანება 경계와 시스템 호출

```text
გარემო run → JKAP에서 ELF შემოწმება·적재 → ring 3 მომხმარებელი აპი_f5044b9b
                                 ↓ int 0x80
                      კურსორი 검사 → Java ბირთვი_მნიშვნელობა API → RTL8139/UDP
                                 ↓ გასვლა_აპი·예외·დრო_მნიშვნელობა 초과
                                გარემო 복귀
```

시스템 호출 레지스터는 `EAX=ინდექსი`, `EBX,ECX,EDX,ESI,EDI=인수`, `EAX=გაზომვა`다. Java 호출 스택 ABI는 컴파일러가 მომხმარებელი 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| ინდექსი | 호출 |
| --- | --- |
| 0 | გასვლა_აპი(სტატუსი_მნიშვნელობა კოდექსი_მნიშვნელობა) — გაშვება/შეცდომა 런타임에서 사용 |
| 1 | სტრიქონი_მნიშვნელობა ჩაწერა |
| 2 / 3 | 인수 개수 / 인수 სტრიქონი_მნიშვნელობა მისამართი |
| 10 | UDP გახსნა |
| 11 | UDP გაგზავნა(სახელური_მნიშვნელობა, IP, მიმართულება_მნიშვნელობა პორტი_მნიშვნელობა, მასივი_მნიშვნელობა მისამართი, სიგრძე_მნიშვნელობა) |
| 12 | UDP 받기(სახელური_მნიშვნელობა, მასივი_მნიშვნელობა მისამართი, 제한 밀리초) |
| 13 | UDP დახურვა |
| 14 | ლოკალური_არეალი IP მისამართი |
| 15 / 16 | 마지막 კვანძი_მნიშვნელობა_6a3b6fa7 IP / UDP პორტი_მნიშვნელობა |
| 20 | RAM ფაილი კითხვა(სახელი int[] მისამართი, 출력 int[] მისამართი) |
| 21 | RAM ფაილი ჩაწერა(სახელი int[] მისამართი, 입력 int[] მისამართი, ბაიტი_მნიშვნელობა სიგრძე_მნიშვნელობა) |
| 22 | UTF-16 კოდექსი_მნიშვნელობა გაკვეთილი_მნიშვნელობა 문자 출력(0~65535) |

ფაილი API는 `მომხმარებელი.파일읽기(int[] სახელი, int[] მონაცემები)`와 `მომხმარებელი.ჩაწერა_ფაილი(int[] სახელი, int[] მონაცემები, int სიგრძე_მნიშვნელობა)`다. 이름은 ASCII კოდექსი_მნიშვნელობა მასივი_მნიშვნელობა(최대 64칸, 0 გასვლა_აპი 또는 მასივი_მნიშვნელობა 끝), მონაცემები ელემენტი_ელემენტი 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 ფაილი 없음 `-2`, კურსორი შეცდომა `-14`, სახელი/სიგრძე_მნიშვნელობა შეცდომა `-22`, ფაილი სლოტი_მნიშვნელობა 부족 `-28`, ზომა 초과 `-90`을 반환한다. 쓰기는 შემოწმება 후 ფაილი 전체를 대체한다. `მომხმარებელი.ჩაწერა_სიმბოლო_მნიშვნელობა(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 მომხმარებელი 모드에서 CS의 하위 비트를 직접 읽으므로 რეალური_მონაცემები შესრულება_ბრძანება 권한을 확인한다. ბირთვი_მნიშვნელობა 포트 접근용 `მობილური_მნიშვნელობა` native 함수는 მომხმარებელი მიზანი 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 შესრულება_ბრძანება, 파이프, 프로세스 간 통신은 없다. შესრულება_ბრძანება 파일은 커널의 კითხვა 전용 JKAP 묶음에서 적재한다. მონაცემები 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- მომხმარებელი 가상 მისამართი `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. შესრულება_ბრძანება 영상은 앞 2MiB, 인수는 `0x04300000`부터, 스택은 영역 끝에서 시작한다. ბირთვი_მნიშვნელობა identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB მომხმარებელი 영역을 비우고 ფაილი 구역을 복사해 BSS·მასივი_მნიშვნელობა 영역을 초기화한다. მომხმარებელი GC는 없지만 გასვლა_აპი 후 შემდეგი_ელემენტი შესრულება_ბრძანება 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 ციტატა/이스케이프 파싱은 없다.
- მომხმარებელი 페이지의 კოდექსი_მნიშვნელობა/მონაცემები 분리 კითხვა 전용 პარამეტრები, NX, 스택 guard, ASLR은 아직 없다. 커널과 მომხმარებელი მეხსიერება_მონაცემები·포트 ნებართვა_მნიშვნელობა 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 შესრულება_ბრძანება 상한을 두며 დრო_მნიშვნელობა 초과는 `Exit: 124`다. მომხმარებელი CPU 예외는 `128 + 예외 ინდექსი`(페이지 შეცდომა 142, 특권 위반 141), Java მასივი_მნიშვნელობა/계산 오류는 101~105다. ბირთვი_მნიშვნელობა 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, სტატიკური_მნიშვნელობა IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP 검사합 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- მომხმარებელი შესრულება_ბრძანება·네트워크·დაცვა_მნიშვნელობა 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 შესრულება_ბრძანება·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## შემოწმება 근거

`make test`는 컴파일러 14개 시험, Java 패킷 პირობა 2,201개 검사, 기존 გარემო ELF/ISO 부팅 시험, მომხმარებელი ELF/რეალური_მონაცემები UDP/დაცვა_მნიშვნელობა 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 სიგრძე_მნიშვნელობა·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 ბრძანება·무한 იტერაცია_მნიშვნელობა 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
