# engos 기능 대응표

이 표는 기존 `бұрынғы_көз/`의 нысан_мән 기반 JVM 관리 커널을 설명한다. 새 `compiler/`와 `os/`는 별도 제한형 네이티브 구현이며 [нақты_деректер 부팅 기능과 한계](../os/readme_файлы_eb81d7d9.md)를 따로 기록한다.

## 기존 нысан_мән 기반 관리 ядро_мән 전체를 부팅하기 위해 남은 Байланысу

Келесі_элемент 항목은 Java 문법만으로 실행할 수 없는 CPU/құрылғы_мән 동작이므로 관리 계층과 별도로 AOT 런타임에 연결해야 한다.

- Multiboot енгізу_ұпай_мән, CR0/CR2/CR3/CR4, IDT 적재, `iret`, x86 문맥 сақтау_мән
- нақты_деректер PIC/PIT/PS2/ATA/PCI 포트 및 AMD PCnet DMA тұйық_мән
- Java нысан_мән·массив_мән Cілтеме_макет, ерекшелік, тұрақты_мән баптандыру, 가비지 수집기
- 컴파일된 Java 메서드를 freestanding i386 기계어로 바꾸는 AOT кезең_мән
- FAT 디스크 구역을 нақты_деректер ATA 장치와 연결하는 енгізу_шығару 접착 қабат_мән

위 관리 계층은 engos 기능의 Java 관리 구현과 орналастыру 검증판이다. 별도 `os/`에서는 제한형 AOT, Multiboot енгізу_ұпай_мән, тұрақты_мән баптандыру·бүтін_сан массив_мән, VGA/직렬/PS2, 명령해석기, пайдаланушы ELF/ring 3/시스템 호출, RTL8139/ARP/IPv4/UDP를 연결해 QEMU 부팅과 орналастыру 루프백 패킷 왕복을 검증했다. 위 표의 нысан_мән 기반 관리 기능 전체나 VirtualBox 네트워크 실행까지 검증했다는 뜻은 아니다.
