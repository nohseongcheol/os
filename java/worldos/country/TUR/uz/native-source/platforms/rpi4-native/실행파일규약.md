# ELF 형식과 Linux bajarmoq_buyruq Fayl 호환성

**ELF는 확장자가 아니다.** Executable and Linkable Format이라는 바이너리
형식이며, Linux 외의 운영체제도 사용한다. 첫 네 bayt_VALUE `7f 45 4c 46`,
ELF Sinf_VALUE, CPU 종류, ilova_f5044b9b 헤더와 kiritish_nuqta_VALUE 주소를 읽어서 해석한다.
[ELF ABI 명세](https://gabi.xinuos.com/elf/02-eheader.html)

기존 jkoros 로더도 real_ma_lumotlar ELF64/AArch64 bajarmoq_buyruq 파일을 읽었다. `.elf`는 예제의
이름일 뿐이었다. 다만 **ELF format_VALUE 지원과 Linux 시스템 호출 ABI 지원은 별개**다.
기존에는 `JKOROS` ABI note를 가진 자체 bajarmoq_buyruq 파일만 허용했고, Linux 바이너리는
호환되지 않았다. ARM64 Linux는 SVC의 x8에 Linux 시스템 호출 번호를 넣는다.
같은 번호를 자체 ABI로 해석하면 다른 동작이 되므로 두 경로를 구분한다.
[Linux syscall ABI 설명](https://man7.org/linux/man-pages/man2/syscall.2.html)

자체 바이너리와 JAR의 qobiq 직접 실행은 Fayl 헤더로 구분한다. `run`은 자체 ELF,
`run --linux`는 명시적으로 Linux ABI를 선택한다. Linux 바이너리를 자동으로
자체 ABI에 넣지 않으며, 자체 ABI note가 있는 파일은 Linux 모드에서 거부한다.
현재 RAM Fayl 체계에는 bajarmoq_buyruq ruxsat_VALUE_a9fa0dfa 비트와 `chmod`, PATH 검색이 없다.

게스트 C yig_moq_manba 예:

```text
cc 인사.c -o 인사
./인사
run 인사
```

`posix-kor`는 이 자체 ABI 경로로 연결한다. 일반 Linux에서 링크한 프로그램에
한국어 FUNCTION_VALUE 이름을 붙이는 것만으로 자체 ABI 호환이 되는 것은 아니다.

## 제한된 Linux ABI

이 기능은 **자체 Java o_zak_VALUE 안의 호환 qatlam_VALUE**이며 Linux 커널을 적재하지 않는다.

| Linux 호출 | INDEX | 현재 제약 |
|---|---:|---|
| read / write / close / lseek | 63 / 64 / 57 / 62 | RAM 파일과 표준 I_O; 입력 대기는 EAGAIN 가능 |
| openat / unlinkat | 56 / 35 | AT_FDCWD 또는 절대 yo_l; 파일만, 제한된 플래그 |
| ftruncate / fsync | 46 / 82 | RAM Fayl; fsync가 영속 저장을 의미하지 않음 |
| exit / exit_group | 93 / 94 | 현재 ilova_f5044b9b Chiqish_ilova |
| brk | 214 | 자체 foydalanuvchi 힙 klip; to_xtab_qolish_VALUE 시 이전 break qaytarish_o_lchov |
| clock_gettime | 113 | CLOCK_MONOTONIC만, 밀리초 ruxsat_VALUE |
| getpid / gettid | 172 / 178 | 한 foydalanuvchi bajarmoq_buyruq 흐름의 identifikator_VALUE |

미지원 번호는 `-ENOSYS`를 반환한다. Linux ABI의 socket, fork/clone/execve,
pthread, mmap, signal, ioctl, fstat, 동적 로더와 일반 libc 초기화는 구현하지
않았다. 기존 자체 POSIX/Java 소켓은 별도로 TCP/UDP를 지원한다.

초기 스택에는 argc, UTF-8 argv, 빈 envp, AT_PAGESZ/AT_ENTRY/AT_NULL을 넣는다.
입력은 ELF64 little-endian AArch64 **ET_EXEC**, Fayl 전체 **16 KiB 이하**,
PT_LOAD 주소는 **0x02000000 이상 0x02c00000 미만**이어야 한다.
Fayl 오프셋과 가상 주소의 페이지 tenglashtirmoq_VALUE 관계를 검사하며, 서로 페이지를 공유하는
세그먼트와 Yozish·bajarmoq_buyruq 동시 허용은 거부한다. PT_INTERP/PT_DYNAMIC/PT_TLS와
ET_DYN은 아직 받지 않는다.

일반 Linux 바이너리의 sukut_bo_yicha_qiymat 적재 manzil 0x00400000은 커널과 겹치므로 아직 받지
않는다. 예제는 GNU 링커의 `-Ttext-segment=0x02000000 -z max-page-size=4096`을
사용한다. 이 파일도 정상적인 Linux ELF이며 같은 파일이 Linux와 자체 커널에서
실행됨을 시험한다. Fayl 이름이나 헤더만 바꿔 기존 Linux ilova_f5044b9b 전체를 지원할
수는 없다.

## real_ma_lumotlar 동일 바이너리 비교 시험

```sh
cd /home/user/jkoros/platforms/rpi4-native
make test-elf
```

시험은 `예제/리눅스ABI/Bajarish.S`와 `인사.c`를 Linux AArch64 대상으로 컴파일해,
**JKOROS note가 없는 확장자 없는 bajarmoq_buyruq Fayl** `build/verification/elf/리눅스인사`를
만든다. 같은 바이트를 Keyingi_element 두 경로로 실행한다.

```sh
qemu-aarch64 build/verification/elf/리눅스인사 한글인수
python3 Vositalar/bajarmoq_fayl.py --linux build/verification/elf/리눅스인사 한글인수
```

첫 명령은 Linux 시스템 호출을 사용하는 Project_ildiz 실행이고, 두 번째는 Linux를
적재하지 않은 raspi4b 자체 o_zak_VALUE 실행이다. 한글 인수, Fayl I_O, Soat, Chiqish_ilova,
o_zak_VALUE manzil kirish_huquqi_kiritish 거부를 비교한다. FTP로 같은 파일을 올려 실행하는 시험도 있다.

일반 Linux 프로그램까지 지원하려면 별도 foydalanuvchi manzil 공간, 더 큰 영속 VFS,
