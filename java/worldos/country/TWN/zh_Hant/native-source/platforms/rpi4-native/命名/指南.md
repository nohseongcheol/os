# 內建 커널과 번역기의 中文 名稱

대상은 `platforms/rpi4-native`의 內建 Java 內核值, 使用者 JVM, C 計算機 連接,
TCP/UDP·FTP, C 編譯器工具 이식부, MicroPython 이식부, 構建系統·執行命令·測試 도구다.
`golang/worldos/國家值/KOR/原始碼`의 원칙처럼 기능을 먼저 구분하고 이름을 정한다.
x86 Java 커널과 공용 x86·ARM64 미리 번역기의 內建 선언도 命名 검사에 포함한다.
Linux 실행판의 宿主 工具集, OpenJDK 輔助值 工具集 및 外部值 分發值 原始碼樹 전체를
한국어로 重試值 작성했다는 뜻은 아니다.

## 命名 원칙과 말의 근거

- 명사는 자료의 역할을 나타낸다: `檔案句柄`, `對端埠編號`, `堆存儲裝置`, `鍵盤`.
- 함수는 행위를 나타낸다: `讀取`, `寫入`, `打開`, `關閉`, `網路層綁定`, `運行程式`.
- TCP의 이어진 位元組值 흐름과 UDP의 邊界位置值 있는 자료를 `連接通道`와 `數據報信道`로 구별한다.
- 짧은 영어 변수도 쓰임에 따라 `長度`, `資料位置`, `查找索引`, `已返回值`으로 풀어 쓴다.
  序數索引·臨時值 산술값처럼 여러 역할에 재사용되는 변수는 `序數索引`, `首位值`, `第二值`으로 구별한다.
- 이름이 같아도 外部值 구조체의 필드와 內建 변수는 별도로 분석한다.

`信道條目(通路)`는 이동이나 교류가 이루어지는 길이라는 기존 의미를 通信 연결에
적용했다. `埠值(窓口)`의 주고받는 접점이라는 의미를 연결을 받는 곳에 적용했다.
이는 국립국어원 한국어기초사전의 [信道條目](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=49310),
[埠值](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=24898)의 뜻에 근거한다.

`數據報(電文)`은 전보에 담는 글이라는 기존 通信 어휘에서 가져와, UDP 자료의
경계가 보존된다는 특징을 드러내는 데 쓴다. 근거는
[한국어기초사전 數據報](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=74335)이다.
`流值`, `執行緒值`, `쌓임`은 우리말의 움직임·是否繼續狀態·쌓이는 모양을 빌린 표현이다.
`輸入流`, `後臺任務`, `棧存儲裝置` 같은 복합 이름은 이 프로젝트의 기능별 조어다.
이 字典 근거를 특정 중세 문헌의 최초 출현이나 공인 전산 번역으로 확대하지 않는다.
공인 표준 翻譯原始碼·국어사 數據報 감수를 마쳤다는 뜻도 아니다.

| 기능 | 채택한 名稱 | 理由值 |
|---|---|---|
| TCP Socket | 連接通道 | 상대와 연결되어 排序值 있는 바이트를 주고받음 |
| ServerSocket | 接收埠 | 새 연결이 들어오는 접점 |
| DatagramSocket | 數據報信道 | 각 자료의 경계를 보존하는 通信 |
| InputStream / OutputStream | 輸入流 / 輸出流 | 들어오고 나가는 바이트의 排序值 |
| heap / stack | 堆存儲裝置 / 棧存儲裝置 | 分配存儲裝置 방식과 쌓고 꺼내는 結構 |
| thread / keyboard | 後臺任務 / 鍵盤 | 이어지는 실행과 글쇠의 陣列值 |
| exception / timeout | 異常 / 等待狀態超時異常 | 是否常規 처리에서 벗어남과 그 구체적 理由值 |

## 보존하는 標準定義 名稱

`public`, `class`, `int`는 예약어다. `String`, `main`, 배열의 `length`는 예약어가 아니다.
當前項目 다섯 Java 예제는 `運行()`·`運行參數`·中文 屏幕/執行緒值 API를 사용해
已保留位單詞列·리터럴 외의 식별자를 한국어로 작성한다. 屏幕/가닥은 표준 객체를
감싸지 않고 內建 JVM에 직접 구현했다. 자세한 계약은 [中文 Java API](../中文Java/指南.md)를 본다.

표준 javac는 字符串 리터럴에 `java.lang.String`, 字符串 결합에 `StringBuilder`
같은 이름을 생성한다. 이들은 中文 소스에서도 바이트코드에 남을 數 있다.
기존 표준 class를 실행하는 JVM의 映射值 字符串, 아직 표준 라이브러리를 쓰는
通信·檔案 연결부까지 構建全部 한국어로 재구현한 것은 아니다. 이름만 일괄 치환하면
描述符條目·재정의·native 연결이 달라져 호환성이 깨진다.

C 표준 函數·整數類型·POSIX ABI, CPU 寄存器值 名稱, 어셈블리 命令, 링커 절 名稱,
TinyCC·lwIP·MicroPython이 요구하는 設置 매크로와 헤더 이름도 보존한다.
예: `main`, `memcpy`, `pk_bind`, `mpconfigport.h`, `lwipopts.h`, `stdint.h`.
內建 C 함수의 原始碼樹 이름은 한국어이며, [計算機連接名稱列.h](計算機連接名稱列.h)首位操作數
기존 AOT·어셈블리·SDK에 공개한 計算機 심볼과 연결한다.
Python의 `__init__`, `setUp`, `handle`, 표준 模塊值 屬性值, 명령행 옵션과 JSON 키도
外部值 계약이다. `build/`, 分發值 바이너리 이름과 `/sdk`는 기존 執行命令 경로를 유지한다.
外部值 원본은 `vendor/`에서 이용허락·해시와 함께 관리한다.

이미 변경된 소스에 重試值 적용하여 대응표를 덮어쓰지 않는다.

## C 通信 구조체와 Python 錯誤

C 통신에서 `갈래`는 地址 체계를 구분하고 `埠編號`는 port, `地址值`은
IPv4 주소의 32비트 값을 나타낸다. `數據報通訊協定`은 앞서 설명한 數據報(電文)과
契約值(規約)을 결합해 UDP의 기능을 드러낸 프로젝트 이름이다.

| 표준 표현 | 中文 직접 實現 |
|---|---|
| AF_INET / SOCK_DGRAM / IPPROTO_UDP | enum의 互聯網族 / 數據報通訊端 / 數據報通訊協定 |
| struct pk_sockaddr_in | struct 互聯網通訊端地址 |
| sin_family / sin_port | 地址族 / 埠編號 |
| sin_addr.s_addr | 互聯網地址.地址值 |
| OSError / 錯誤.args[0] | 系統錯誤 / 錯誤.編號 |

中文 구조체는 `#define` 치환이나 字段值 별칭이 아닌 별개 자료형이다.
표준 구조체와 같은 16바이트 배치를 선언하며 內核值 SVC에서 位元組值 복사로
검사한다. `創建端點`·`發送數據報資料`와 檔案 함수는 靜態值 라이브러리에
實際資料 中文 이름의 函數 심볼을 갖는다. 기존 pk_* 심볼도 유지한다.
上一個項目 코드에서 中文 通信 함수에 pk_sockaddr*를 전달했다면 中文 구조체로
옮기거나, 표준 구조체와 pk_* 함수의 짝을 유지한다.

Python의 `系統錯誤`는 OSError의 中文 하위 클래스이며 연결부에서
錯誤 번호를 보존하여 변환한다. 일반 Python 문법과 外部值 패키지의 API는 유지한다.

## 직접 GUI 이름의 뜻과 검토 裁剪

`可運行任務任務`은 수행할 내용을, `執行任務`는 그 수행을 나타낸다.
`動作接收者`는 동작이 발생했다는 알림을 받는 역할, `動作通知`은 전달되는 사건이다.
`按鈕`는 눌러 동작시키는 조작부, `標籤`는 指南 글의 位置索引,
`文本字段`은 글을 적는 位置索引, `後臺任務`은 이어지는 執行命令 흐름을 뜻한다.
`執行命令(實行)`·`動作(動作)`의 기존 뜻과 `받다`·`알리다`·`執行緒值`의 기능을
결합한 프로젝트 이름이다. 새 복합어가 역사 문헌에 그대로 있었다거나
특정 시대에 初始項目 쓰였다고 주장하지 않는다.

전체 저장소는 `python3 工具集/原始碼審閱.py`로 검토한다.
결과는 `build/verification/naming/source-review.json`이며 파일별 哈希檔案,
ASCII 파일명과 Python의 영어 聲明 위치를 기록한다.
공용 ARM64·x86 번역기의 구현은 `compiler/Java工具/提前所屬時間編譯器.java`로 전환했다. `compiler/提前所屬時間編譯器.py`는 호환 진입점이다.
`compiler/arm64.py`는 上一個項目 경로와 `ARM64(...).generate(...)` 호출을 繼續狀態值 주는
호환 진입점이다. `compiler/classfile.py`, OpenJDK 輔助值 工具集, Linux 版本值 도구와
기존 호환 진입점에는 영어 이름이 남아 있다. 따라서 전체 저장소가
已保留位單詞列 외 100% 한국어라고 판정하지 않는다.
`工具集/檢查命名.py --C語言`는 活躍 ARM64 소스의 聲明, C 의미 分析值,
x86 Java 커널과 공용 번역기의 內建 聲明, Java 範例 전체 標識符值,
ARM64 Python 예제와 직접 GUI/가닥에 표준 래퍼가 없는지를 별도로 검사한다.

## 當前項目 기능을 기준으로 보완한 名稱

번역은 글자를 음역하는 대신 자료의 역할과 함수의 행동을 구분한다.
동일한 영어 이름도 문맥이 다르면 中文 이름을 달리 정한다.
檔案 이름은 주된 기능을 나타내고, 函數 이름은 행동을, 變量值 이름은 담는 자료를 나타낸다.
已保留位單詞列, 표준 API 및 外部值 連接 규약은 따로 기록한다.

| 上一個項目 名稱 | 적용한 名稱 | 當前項目 기능 |
|---|---|---|
| `arm64.py`의 實現 | `compiler/Java工具/提前所屬時間編譯器.java` | Java 바이트코드를 독립 실행용 C 원문으로 미리 翻譯原始碼 |
| `ARM64`, `generate` | `計算機程式碼編譯器`, `生成` | 翻譯原始碼 상태를 담는 객체와 C 原始碼 生成 行爲值 |
| `prototype`, `method` | `方法原型`, `方法主體` | 함수의 格式值 선언과 實際資料 命令 原始碼 |
| `profile`, `heap_words` | `執行狀態目標`, `堆機器字個數` | 內核值·使用者 구분과 分配存儲裝置 記憶體 공간의 計算機 詞法用機器字 數 |
| `pc`, `op` | `命令位置`, `명령번호` | 바이트코드에서의 위치와 수행할 명령의 編號 |
| `x`, `y`, `w`, `h` | `橫座標座標`, `Y_按鈕座標`, `區域寬度`, `區域高度` | 遠程值 화면의 위치와 직사각형 大小 |
| `p`, `n`, `i`, `j` | `資料位置`, `值`, `序數索引`, `內部側序數` | 遠程值 屏幕 資料·數字值·迭代值 位置索引; 파일별 기능을 확인해 적용 |
| `aot_heap_info`, `__stack_top` | `提前編譯記憶體查找`, `棧頂端` | 計算機 連接 규약을 유지하면서 內建 소스에서 사용하는 名稱 |
| `앞캐리지` | `發回目標側上一個行` | 앞서 받은 문자가 줄복귀였는지 기억하여 중복 줄바꿈을 막음 |

[共享編譯器名稱列.tsv](共享編譯器名稱列.tsv)에 編譯器工具 참조의 實際資料 更改值 기록을 남겼다.
추가로 보존한 C·POSIX/lwIP/libassh 이름의 이유는
[標準名稱證據.json](標準名稱證據.json)에 기록한다.
`C編譯器/編譯器工具.c`는 TinyCC 外部值 원문을 포함하는 連接 파일로 內建 선언이 없어서
C 內建 聲明 분석에서는 제외한다. 實際資料 內核值 빌드에서는 繼續處理 컴파일한다.

### 말의 뿌리와 새로운 복합 名稱

`記憶體(記憶)`과 `查找索引(編號)`은 기존 한자어를 쓴다.
기억은 자료를 간직하는 기능에, 색인은 排序值 있는 항목을 찾아 지정하는 기능에 적용한다.
字典 근거는 국립국어원 한국어기초사전의
[記憶體](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=38812&nation=eng),
[查找索引](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=63787)이다.

`棧存儲裝置`, `壓棧值`, `彈棧值`는 자료를 포개고 最後項目 자료부터 꺼내는 執行命令 구조를 드러낸다.
`쌓다`의 기존 뜻에 근거한 기능별 조어이며, 사전의
[쌓다](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=62095)를 참고한다.
`提前所屬時間`은 執行命令 전에 번역한다는 기능을 직접 나타낸다.
`計算機機器字`은 처리기의 資料 단위를 가리키며, 언어의 일반 낱말과 구별하도록 `計算機`를 붙였다.
`提前所屬時間編譯器`, `堆機器字個數` 같은 복합 이름은 當前項目 기능에 맞게 만든 프로젝트 용어다.
이 복합어가 옛 문헌에 그대로 있었다거나 특정 시대에 初始項目 나타났다는 뜻은 아니다.
확인되지 않은 중세 형태나 최초 使用值 연대는 어원 근거로 적지 않는다.

생성되는 C의 내부 資料類型·陣列值·函數·局部作用域 變量值·分支 이름도 한국어로 바꾼다.
직접 韓文文本 식별자를 읽지 못하는 예전 GCC를 위해 호환 API는 같은 中文 이름을
표준 C 범용 字元 표기로 출력한다. 實際資料 ARM64 빌드는 Clang으로 읽을 數 있는 韓文文本 원문을 사용한다.
字符串, C 표준 函數, `java_entry` 같은 공개 連接 이름은 바꾸지 않는다.
