# 內建 ARM64 使用者 執行命令 ABI v1

이 ABI는 `platforms/rpi4-native`의 제한된 freestanding 執行命令 환경이다. Linux AArch64 ABI나 POSIX 전체 구현이 아니다. **OpenJDK/JRE, CPython, libc, libstdc++는 아직 이식되지 않았다.**

ELF 로더는 檔案 확장자 대신 實際資料 ELF 헤더를 검사한다. 底端值 內建 ABI와 별도로 `run --linux FILE`에 제한된 Linux ARM64 靜態值 執行命令 檔案 경로를 추가했다. 두 시스템 調用 번호표를 혼합하지 않는다. [ELF·Linux ABI 매뉴얼](可執行文件ABI.md).

## ELF와 執行命令 수명

- ELF64 little endian, ET_EXEC, EM_AARCH64, 버전 1, e_flags=0.
- 程式 헤더 最大值 16개. PT_LOAD는 讀取 가능, 4 KiB 對齊值, 페이지 간 嵌套值 缺失方法, filesz≤memsz, 構建映像 地址 裁剪 안이어야 한다. W+X는 거부한다.
- 진입점은 檔案 내용이 있는 執行命令 세그먼트 안의 4바이트 對齊值 주소다.
- PT_NOTE에 名稱 `JKOROS\0`(namesz=7), type=1, descsz=4, 버전 1의 little endian uint32가 필요하다. SDK의 `start.o`首位操作數 넣는다.
- PT_DYNAMIC/PT_INTERP/PT_TLS 등은 거부한다. 동적 재배치·공유 庫·TLS 로더가 없다.
- 커널에 포함한 ELF 묶음을 검증하고 별도 使用者 메모리에 복사한 後端值 EL0로 진입한다. 커널에 함수로 靜態值 링크해 호출하는 上一個項目 `cpp_test`와 다르다.
- 내장 프로그램은 `demo.elf`, `fault.elf`의 8개 保護值 測試 模式值, `network.elf`, 內建 Java 工具集, MicroPython이다. 셸의 `load`/`run FILE`로 RAM의 16KiB 이하 ELF도 같은 有效性校驗 경로로 실행한다.
- `_start`首位操作數 `user_start`를 호출하고 `.init_array` → `開始用戶程式(int)` → `.fini_array` 순서로 실행한 後端值 exit 호출을 수행한다. 인수는 調用 15로 읽으며 표준 argc/argv/envp 操作數棧 배치는 없다.
- 한 번에 한 使用者 프로그램이 CPU에서 실행된다. 네 터미널에 각 하나씩 交互式 프로그램을 일시 정지해 보관할 數 있다. 是否常規 退出程式·異常·時間值 초과 시 커널에 복귀하고 열린 檔案/소켓을 닫으며 使用者 페이지 권한을 제거한다.
- 靜態值 생성자와 자동 객체의 RAII 소멸자를 시험했다. `__cxa_atexit`, 표준 C++ 異常/RTTI/STL, 일반적인 전역 物件值 退出程式 등록은 제공하지 않는다.

## 주소와 保護值

| 가상 地址 裁剪 | 용도 |
|---|---|
| 0x02000000–0x02bfffff | ELF 構建映像, 最大值 12 MiB |
| 0x02c00000–0x02ecffff | brk 堆值, 最大值 2880 KiB |
| 0x02ed0000–0x02efffff | 미매핑 文本範圍/操作數棧 底端值 保護值 文本範圍 |
| 0x02f00000–0x02ffffff | 1 MiB 使用者 操作數棧 |

內建 JVM의 類別值·物件值 자료를 수용하도록 使用者 창을 16 MiB로 확장했다. 程式 헤더의 允許值 裁剪, 페이지 權限值 檢查項, SDK 링커 腳本值 및 保護值 시험이 같은 배치를 사용한다. 기존에 brk 運行 주소를 상수로 가정한 프로그램은 새 SDK로 重試值 빌드한다. 일반 프로그램은 調用 8로 當前項目 brk를 조회한다.

執行命令 코드는 EL0 讀取/실행만, 資料·堆值·스택은 EL0 讀取/쓰기만 허용한다. 餘數值 內核值 RAM·設備 MMIO에는 EL0 권한을 주지 않는다. 이번 W^X 보장은 **使用者 페이지에 대한 것**이다. kernel identity map의 전체 權限值 분할이나 다중 프로세스 地址 地址區域 전환을 구현했다고 의미하지 않는다.

커널은 `-mgeneral-regs-only`로 빌드한다. 使用者 C/C++는 FP/SIMD를 허용하고, 使用者 條目分值 시 向量值 레지스터와 FPCR/FPSR를 초기화한다. 內核值 복귀용 callee-saved FP 상태를 보관한다. syscall/IRQ의 C 처리부는 FP 레지스터를 사용하지 않는다. 향후 여러 使用者 스레드를 전환할 때에는 각 스레드의 전체 FP 上下文值 보존을 별도로 구현해야 한다.

GIC-400의 물리 타이머 IRQ로 약 2초의 執行命令 기한을 적용한다. SVC 없는 무한 반복도 종료한다. 시스템 調用 運行 시 기한을 검사하지만 EL1 程序值條目 중에는 IRQ를 마스킹하므로 긴 輸出/畫圖屏幕 호출의 종료는 지연될 數 있다. 이것은 程式 執行命令 기한이며 일반 선점 스케줄러가 아니다.

## 시스템 調用

`svc #0`, 編號 x8, 實參 x0…x5, 結果 x0. 실패는 負數值 錯誤 번호다. `libposix-kor-user.a`는 이를 -1과 `錯誤編號`로 바꾼다. 使用者 프로그램의 errno는 當前項目 단일 執行命令 흐름용이며 pthread TLS가 아니다.

是否不支持 호출은 -ENOSYS이다. 모든 使用者 포인터와 해당 페이지의 讀取/寫入 권한을 확인한다. 파일은 3…18의 프로세스별 서술자를 內核值 서술자로 변환한다. 0은 當前項目 셸의 표준 輸入值(UART 또는 리다이렉션/파이프), 1은 표준 輸出(UART/GUI 또는 리다이렉션/파이프), 2는 UART/GUI 診斷值 출력이다. UART에 읽을 자료가 없으면 -EAGAIN, 檔案/파이프 輸入值 끝이면 read가 0을 반환한다. 출력은 檔案/파이프에서 LF를 그대로 유지하고 UART에서만 CRLF로 표시한다. 파이프는 16 KiB 순차 버퍼이며 프로세스 간 동시 파이프/PTY는 아니다. read/write 요청은 65536바이트 이하이며, RAM 파일은 最大值 64개, 각각 16384바이트다. 檔案 경로는 當前項目 命令殼 경로에 대한 對端值 路徑 또는 `/`로 시작하는 절대 경로이며 UTF-8 63바이트까지다. 디렉터리 生成·빈 目錄值 移除條目·種類值 조회는 調用 18로도 제공한다. 當前項目 路徑 변경은 命令殼 내장 cd가 담당한다. 그래픽 요청은 調用 22로 조회한 實際資料 屏幕 大小 안의 직사각형만 허용한다. 프레임버퍼 地址 자체는 사용자에게 노출하지 않는다.

힙의 페이지 單位值 축소·재확장에서 重試值 노출하는 페이지는 0으로 만든다. 같은 페이지 안에서 brk만 줄였다 늘리는 경우에는 해당 페이지 내용이 남을 數 있다. malloc/free나 mmap/mprotect의 구현은 아니다.

인수는 最大值 8개·각 255바이트다. 잘못된 번호는 -EINVAL, 작은 버퍼는 -ENAMETOOLONG, 寫入 불가능한 포인터는 -EFAULT다. `run FILE [ARGS]`는 파일명을 實參 0으로 포함한다. `javac`/`java`/`python`은 指令值 자체를 제외한 토큰을 전달한다. 인수는 內核值 保留值 자료를 使用者 버퍼로 복사하며 內核值 포인터를 반환하지 않는다.

## UDP 루프백의 계약

바깥 IPv4는 lwIP/SLIP로 확장했다. 기존 fd/구조체/指針 檢查項 규약을 유지하며 0.0.0.0 또는 10.0.2.15에 bind한 끝점을 바깥 통신에 연결한다. 127.0.0.1에 명시적으로 bind한 UDP는 루프백에 한정한다. 外部值 TCP connect는 비차단 -EINPROGRESS(-115)를 반환할 數 있으므로 같은 주소로 재시도하여 완료를 확인한다. [執行命令/限制值](檔案傳送與編譯過程.md).

`互聯網族`, `數據報通訊端`, 傳送通訊協定 0/`數據報通訊協定`을 허용한다. `struct 互聯網通訊端地址`는 16바이트이며 주소갈래는 設備 序列值, 접속번호와 互聯網地址.주소값은 網路值 차례다. 호환용 pk_sockaddr_in도 같은 배치지만 독립 자료형이다. 中文 함수는 직접 SVC를 호출하는 實際資料 함수이며 표준 이름으로 치환하는 매크로가 아니다. 宿主 Linux 헤더를 섞지 않는다.

- 목적지는 127.0.0.1만 允許值. bind는 0.0.0.0 또는 127.0.0.1, port=0이면 49152…65535에서 빈 창구를 고른다.
- 미바인드 소켓의 首位項目 전송은 臨時值 창구를 바인드한다. 같은 창구의 중복 bind는 EADDRINUSE.
- 最大值 8개 通訊端值, 각 큐 4개, 전문은 0…512바이트. 빈 전문도 소비된다.
- 接收值 버퍼가 작으면 복사할 부분만 반환하고 전문의 나머지는 버린다. peer 地址/창구를 반환한다.
- flags는 當前項目 0만 支持值. 비차단 수신의 빈 큐 및 發送值 目標值 큐 포화는 EAGAIN이다.
- 目標值 埠值 없음은 ECONNREFUSED, 512바이트 초과는 EMSGSIZE, 루프백에 명시적으로 바인드한 UDP의 外部值 IP는 ENETUNREACH, UDP 소켓에 잘못된 규약을 지정하면 EPROTONOSUPPORT. SOCK_STREAM은 별도 연결형 루프백에서 제공한다.
- 外部值 IPv4 TCP/UDP 헤더·체크섬·재전송은 lwIP가 처리한다. 實際資料 GENET/Wi-Fi NIC, poll/select, setsockopt는 아직 없다. 연결형 루프백의 connect/listen/accept는 底端值 擴展名值 ABI로 제공한다.

Java의 `板.運行用戶程式(index)`는 是否常規 exit 狀態值 0…255 또는 下一項目 값을 받는다. GUI는 실패를 표시하고 셸을 유지한다.

| 值 | 의미 |
|---:|---|
| -8 | ELF/ABI/地址/權限值 有效性校驗 失敗值 |
| -16 | 使用者 程式 嵌套值 執行命令 拒絕值 |
| -22 | 등록되지 않은 程式 編號 |
| -1001 | 使用者 資料 存取條目 異常 |
| -1002 | 使用者 指令值 存取條目 異常 |
| -1003 | 특권/是否不支持 命令 등 使用者 異常 |
| -1004 | 使用者 執行命令 기한 초과 |
| -1005 | 交互式 使用者 程式 일시 停機執行狀態; 內核值 命令殼 전용 結果 |

이는 완성된 POSIX signal/wait 상태가 아닌 當前項目 內建 실행기의 診斷值 규약이다.


## 여러 터미널의 使用者 上下文值

交互式 tty/GUI 대기를 명시적으로 시작한 프로그램은 輸入值 대기에서 약 2초 기한을 갱신한다. 等待狀態值 없이 무한 반복하면 타이머로 종료한다. 파이프/리다이렉션/복합 命令/스크립트에서 交互式 시작은 -ENOTSUP로 거부한다. vi와 Swing의 이벤트 루프가 이 API를 사용한다.

다른 창으로 전환하면 下一項目 等待狀態值 SVC에서 EL0 문맥을 저장하고 해당 SVC를 재실행할 위치에서 재개한다. x0…x30, SP/PC/PSTATE, v0…v31, FPCR/FPSR, 已映射值·堆值·執行命令 實參·檔案/通訊端值 소유권을 보관한다. 스냅샷은 內核值 전용 물리 地址 0x04000000…0x07ffffff(네 槽值 ×16 MiB)에 저장한다. 當前項目 活躍 EL0 地址 창은 종전 0x02000000…0x02ffffff를 사용한다. 스냅샷 저장소는 EL0에서 접근할 數 없다. fork/exec/wait, SMP 또는 일반 선점형 프로세스 스케줄러의 구현은 아니다.

SVC 40은 소유한 연결형 소켓의 對端值 硬件埠 번호를 반환한다(內建 JVM용 整數 查詢值).

연결형 루프백 fd는 40…55, UDP fd는 32…39다. 退出程式/終端 X 닫기에서 해당 프로그램의 檔案·소켓을 회수한다. 연결형 읽기의 資料 없음은 -EAGAIN, 상대가 닫고 버퍼도 비면 0, 상대가 닫힌 後端值 쓰기는 -EPIPE다. 쓰기는 짧게 완료될 數 있다. 큐 용량은 끝점마다 1024바이트이고 한 시스템 호출은 最大值 512바이트를 옮긴다. 父值 리스너를 닫으면 아직 accept하지 않은 연결도 회수한다. 外部值 연결은 lwIP TCP를 사용하며 外部值 接收值 버퍼는 4096바이트다. 實際資料 GENET NIC 드라이버는 없다.

협력 等待狀態值(17)는 일반 선점형 sleep/scheduler 구현이 아니다. 호출마다 最大值 100 ms 동안 통신을 처리하고 使用者 執行命令 기한을 갱신한다. 軟件包 설치기의 비차단 TCP 대기에 사용한다.
