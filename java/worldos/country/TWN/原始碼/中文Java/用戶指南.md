# jkoros 中文 庫 用戶指南

확인일: 2026-09-27. 대상은 `platforms/rpi4`의 **ARM64 Linux + OpenJDK 실행판**이며, QEMU에서도 같은 Java 라이브러리를 사용한다. `os/`의 內建 x86 內核值 및 `基礎原始碼/`의 관리 內核值 모형과 구분한다.

## 1. 當前項目 제공하는 庫

패키지는 `中文.Java`, 操作系統 안의 JAR 경로는 `/opt/jkoros/lib/中文Java.jar`第三操作數. **輔助器值 類別值 5개, 공개 靜態值 方法值 22개, 별도 GUI 프로그램인 工作區 1개**首位操作數 있다. JAR는 Java 11 이상을 대상으로 빌드하며 當前項目 ARM64 배포판에는 OpenJDK 25가 포함돼 있다.

| 類別值 | 方法值 數 | 기능 | 原始碼 |
|---|---:|---|---|
| `檔案` | 9 | UTF-8 텍스트·位元組值 檔案, 目錄值, 條目列表 | [檔案.java](原始碼/中文/Java/檔案.java) |
| `字元` | 5 | UTF-8 轉換值, NFC 正規化值, 程式碼值 포인트, 字符串 邊界位置值 | [字元.java](原始碼/中文/Java/字元.java) |
| `通信` | 2 | HTTP(S) GET, TCP 連接 | [通信.java](原始碼/中文/Java/通信.java) |
| `任務` | 4 | 스레드 執行命令·等待狀態值, 고정 大小 任務 運行器 | [任務.java](原始碼/中文/Java/任務.java) |
| `屏幕` | 2 | Swing 이벤트 程序值條目 가닥에 任務 예약, 窗口 生成 | [屏幕.java](原始碼/中文/Java/屏幕.java) |
| `工作區` | 條目分 `main` | Java 原始碼 編輯值·存儲值·編譯原始碼·執行命令 | [工作區.java](原始碼/中文/Java/工作區.java) |

표준 JDK 전체를 한국어로 번역한 라이브러리는 아니다. Java 키워드와 `String`, `Path`, `Socket`, `JFrame`, `IOException` 같은 표준 資料類型·예외를 함께 사용한다. 이 도우미에 없는 기능은 OpenJDK의 표준 API 또는 별도 라이브러리로 구현한다. 예를 들어 HTTP POST, UDP, Swing 按鈕·메뉴에는 각각 표준 Java API를 사용한다.

## 2. Java에서 開始任務

게스트 운영체제의 任務 폴더에서 `사용예.java`를 작성한다.

```java
import 中文.Java.*;
import java.nio.file.Path;

public class 사용예 {
    public static void main(String[] 實參) throws Exception {
        Path 目錄值 = 檔案.創建目錄(檔案.路徑("사용예자료"));
        Path 文檔集 = 目錄值.resolve("問候例.txt");
        檔案.寫入(文檔集, "韓文文本 😀");
        String 內容值 = 檔案.讀取(文檔集);
        System.out.println(內容值);
        System.out.println(字元.程式碼分個數(內容值)); // 한, 文本, 공백, 😀 → 4
        Thread 工作值 = 任務.運行("問候例 任務", () -> System.out.println("任務 執行命令"));
        任務.等待(工作值);
    }
}
```

```sh
javac -encoding UTF-8 -cp /opt/jkoros/lib/中文Java.jar 사용예.java
java -cp .:/opt/jkoros/lib/中文Java.jar 사용예
```

로그인 환경에 默認值 `CLASSPATH`도 설정돼 있지만, 명시적인 `-cp`는 다른 執行命令 환경에서도 경로를 분명하게 한다. 사용자가 `-cp`를 지정하면 필요한 JAR와 類別值 폴더를 構建全部 그 값에 포함해야 한다.

宿主 저장소에서는 다음처럼 構建系統·실행한다. 宿主 경로와 게스트의 `/opt/...` 경로는 서로 다르다.

```sh
cd /home/user/jkoros/中文Java
make
javac -encoding UTF-8 -cp build/中文Java.jar 範例/問候例.java
java -cp build/中文Java.jar:範例 問候例
```

## 3. 전체 輔助器值 API

底端值 메서드는 構建全部 `public static`이며, 객체를 만들지 않고 `檔案.讀取(...)`처럼 호출한다. 표의 이름은 實際資料 原始碼樹 및 JAR의 `javap -public` 결과와 대조했다. 선언된 檢查項 異常 외에도 잘못된 實參 등에 대한 표준 Java 執行命令 시 예외가 발생할 數 있다.

### 檔案: `中文.Java.檔案`

`Path`는 `java.nio.file.Path`, `List`는 `java.util.List`第三操作數.

| 方法值 | 發回類型 | 動作·條件 |
|---|---|---|
| `路徑(String 名稱)` | `Path` | 이름을 路徑 객체로 轉換值. 實際資料 파일을 만들지는 않음 |
| `讀取(Path 路徑)` | `String` | 檔案 전체를 UTF-8 텍스트로 讀取結果 |
| `寫入(Path 路徑, String 內容值)` | `Path` | UTF-8 存儲值. 파일이 없으면 생성하고, 있으면 기존 내용을 비움 |
| `讀取位元組值(Path 路徑)` | `byte[]` | 檔案 전체를 位元組值 배열로 讀取結果 |
| `寫入位元組值(Path 路徑, byte[] 內容值)` | `Path` | 位元組值 存儲值. 없으면 생성하고, 있으면 기존 내용을 비움 |
| `創建目錄(Path 路徑)` | `Path` | 필요한 상위 폴더까지 生成 |
| `是否執行存在(Path 路徑)` | `boolean` | 존재 여부 驗證. 확인할 數 없는 경우도 `false`工作值 數 있음 |
| `擦除條目(Path 路徑)` | `boolean` | 삭제했으면 `true`, 없으면 `false`. 폴더의 재귀 삭제는 아님 |
| `條目列表(Path 路徑)` | `List<Path>` | 바로 底端值 항목을 路徑 對齊值 순서로 發回結果. 재귀 탐색은 아님 |

`路徑`, `是否執行存在`를 제외한 頂端值 메서드는 `IOException`을 선언한다. `寫入`와 `寫入位元組值`는 상위 폴더를 자동으로 만들거나 내용을 繼續狀態值 쓰지 않는다. 필요한 폴더는 먼저 생성한다. 큰 파일은 전체 내용을 메모리에 담는 대신 표준 Java 스트림·信道值 API를 사용하는 방식으로 작성할 數 있다.

### 字元: `中文.Java.字元`

| 方法值 | 發回類型 | 動作·條件 |
|---|---|---|
| `編碼(String 內容值)` | `byte[]` | 문자열을 UTF-8 바이트로 轉換值 |
| `解密資料(byte[] 內容值)` | `String` | UTF-8 바이트를 문자열로 轉換值. 잘못된 입력은 대체 문자로 程序值條目 |
| `正規化值(String 內容值)` | `String` | Unicode值 NFC 正規化值. 예: 組合 字母構件值 `ᄀ` + `ᅡ` → `首位操作數` |
| `程式碼分個數(String 內容值)` | `int` | UTF-16 程式碼值 단위가 아닌 Unicode值 程式碼值 포인트 數 |
| `詞法用機器字(String 內容值, Locale 語言)` | `List<String>` | 賦值值 언어의 `BreakIterator` 詞法用機器字 경계로 나눈 文本範圍 |

`詞法用機器字`은 공백·문장부호 구간도 반환한다. 자연어 형태소 분석기나 공백을 제거한 機器字值 條目列表 API는 아니다. `正規化值`는 입력기나 翻譯原始碼 기능이 아니다. 程式碼值 포인트 數 역시 사람이 보는 字元值 수와 항상 같지는 않다. 여러 程式碼值 포인트로 이루어진 合併值列 字元·가족 이모지 등을 구분해야 한다.

### 通信: `中文.Java.通信`

| 方法值 | 發回類型 | 動作·條件 |
|---|---|---|
| `取用值(URI 地址, Duration 時間限制)` | `HttpResponse<String>` | HTTP(S) GET. 連接 및 申請 時間限制 設置. 回覆 본문을 UTF-8로 解析值 |
| `連接端點(String 地址, int 硬件埠, int 限制毫秒)` | `Socket` | TCP 連接 之後狀態 같은 값으로 讀取 제한시간도 設置 |

`取用值`는 `IOException`, `InterruptedException`을 선언한다. 제한시간은 양수다. 404·500 같은 HTTP 錯誤 상태도 응답으로 반환하므로 `statusCode()`로 판단하고 `body()`로 본문을 읽는다. 當前項目 구현은 호출마다 HTTP 클라이언트를 만들며 자동 리다이렉트 설정을 추가하지 않는다.

`連接端點`는 `IOException`을 선언한다. 연결된 소켓은 호출자가 `close()` 또는 try-with-resources로 닫아야 한다. 제한밀리초의 0은 限制值 없음이며, 寫入 전체의 截止時間值 시간을 보장하는 옵션은 아니다.

```java
var 回覆 = 通信.取用值(
    java.net.URI.create("http://127.0.0.1:8000/"),
    java.time.Duration.ofSeconds(5));
System.out.println(回覆.statusCode());
System.out.println(回覆.body());
```

頂端值 조각은 方法值 안에서 실행하며 별도로 해당 주소의 서버를 실행해야 한다. Java 異常 처리가 필요하다.

### 任務: `中文.Java.任務`

| 方法值 | 發回類型 | 動作·條件 |
|---|---|---|
| `運行(String 名稱, Runnable 動作)` | `Thread` | 이름을 지정한 스레드를 만들고 즉시 運行 |
| `等待(Thread 執行緒值)` | `void` | 해당 스레드가 종료할 때까지 `join()` |
| `剩餘部分短暫地(long 毫秒)` | `void` | 호출한 스레드를 賦值值 時間值 동안 `sleep()` |
| `工作臺值(int 執行緒個數)` | `ExecutorService` | 고정 大小 任務 運行器 生成. 가닥수는 양수 |

`等待`, `剩餘部分短暫地`는 `InterruptedException`을 선언한다. 任務 실행기는 使用值 之後狀態 `shutdown()`으로 종료하고 필요하면 `awaitTermination(...)`으로 완료를 기다린다. Swing 이벤트 程序值條目 가닥에서 긴 작업이나 `等待`를 실행하면 화면이 멈출 數 있다.

### 屏幕: `中文.Java.屏幕`

| 方法值 | 發回類型 | 動作·條件 |
|---|---|---|
| `稍後值(Runnable 動作)` | `void` | Swing 이벤트 程序值條目 가닥에 실행을 예약하고 發回結果 |
| `窗口(String 窗口標題, JComponent 內容值, int 寬度值, int 高度值)` | `JFrame` | 內容值·크기를 지정한 창을 생성해 顯示值 |

`窗口`을 Swing 이벤트 程序值條目 執行緒值 밖에서 부르면 `IllegalStateException`이 발생한다. 그래픽 세션도 필요하다. QEMU에서는 VNC 데스크톱의 터미널에서 실행한다.

```java
屏幕.稍後值(() -> 屏幕.窗口(
    "中文 屏幕", new javax.swing.JLabel("안녕하세요"), 500, 180));
```

반환된 `JFrame`에 표준 Swing API를 추가로 사용할 數 있다. 창의 關閉 동작은 `DISPOSE_ON_CLOSE`第三操作數. `屏幕.稍後值`首位操作數 반환됐다고 窗口 생성이 이미 끝난 것은 아니다.

### 工作區: 編輯值·編譯原始碼 GUI

`~/workspace`의 원문을 打開·저장하고, `javac`로 컴파일해 `java`로 실행한다. 執行命令 檔案 만들기는 `jclassc --target openjdk` 경로를 사용한다. 작업마당은 개발용 프로그램이며 별도의 檔案·字元 API 클래스가 아니다. 생성하는 執行命令 檔案 방식은 [編譯器 說明](../compiler/OpenJDK-可執行文件檔案.md)을 따른다.

## 4. Python과 C++에서 사용할 數 是否執行存在?

| 方法模式 | 當前項目 頭文件 狀態值 | 調用 가능 裁剪 |
|---|---|---|
| Java → 中文 JAR | 默認值 頭文件 | 頂端值 22개 메서드와 工作區 |
| Python → `java` 子值 프로세스 | Python·Java 默認值 頭文件 | 작은 Java 진입점을 통해 호출하고 표준 輸出·檔案 등으로 結果 前向值 |
| Python → JPype → JVM | JPype는 默認值 배포에 缺失方法 | 별도 安裝值 之後狀態 Java 類別值·方法值 調用 가능. 이 배포판의 ARM64/musl/Python 3.14 조합은 追加條目 有效性校驗 所需條件值 |
| C++ → JNI → JVM | `g++`, JNI 헤더, `libjvm.so` 頭文件 | JVM을 생성하고 中文 類別值·메서드를 직접 호출할 數 있음 |
| Python용 독립 中文 庫 | 當前項目 默認值 제공 缺失方法 | 필요하면 Python 표준 라이브러리를 감싸는 中文 모듈을 별도로 작성 |
| C/C++용 독립 中文 庫 | 內建 x86 `posix-kor`와 內建 ARM64 커널용 初始狀態 RAM 檔案 연결이 별도로 존재 | 二值 第三操作數 이 Linux/OpenJDK 실행판의 libc 라이브러리는 아님 |

Python의 일반 `import`第二操作數 `ctypes.CDLL`로 JAR를 바로 읽을 수는 없다. C++의 `#include`第二操作數 일반 네이티브 링커만으로 Java 메서드를 연결할 수도 없다. JVM 프로세스 또는 JVM 連接 계층을 거쳐야 한다.

### Python: 追加條目 패키지 없이 調用

執行命令 가능한 範例 원문은 [字符命令.java](範例/其他語言/字符命令.java), [Python調用.py](範例/其他語言/Python調用.py)第三操作數. Python이 Java 진입점을 실행하고 `字元.程式碼分個數`의 整數 결과를 받는다. 實參 목록을 사용하며 命令殼 命令 문자열을 조립하지 않는다. `subprocess.run`의 프로세스 執行命令·退出程式 程式碼值·輸出 程序值條目 방식은 [Python 공식 文檔集](https://docs.python.org/3/library/subprocess.html)를 따른다.

두 範例 파일을 게스트의 같은 폴더에 복사한 後端值 그 폴더에서 실행한다. 範例 檔案 자체는 默認值 시스템 이미지에 자동 설치돼 있지 않다.

```sh
mkdir -p classes
javac -encoding UTF-8 -cp /opt/jkoros/lib/中文Java.jar -d classes 字符命令.java
python3 Python調用.py --text '韓文文本 😀'
```

輸出: `Python → 中文.Java.字元.程式碼分個數: 4`

이 예제의 Python 函數 `程式碼分個數`는 이번 문서의 連接 예제이며 기존에 설치된 Python 라이브러리는 아니다. 當前項目 예제는 호출할 때마다 JVM 프로세스를 시작한다. Java 物件值 자체를 Python으로 가져오는 방식은 아니며, 다른 메서드를 사용하려면 진입점의 實參·結果 형식을 확장한다.

### Python: JPype로 같은 프로세스에서 調用

JPype를 별도 설치한 환경에서는 下一項目 형태로 연결할 數 있다. **아래는 選中狀態值 가능한 連接 방법이며, 當前項目 배포판에 JPype가 설치돼 있거나 執行命令 검증됐다는 뜻은 아니다.** JVM 시작과 `JClass`를 통한 類別值 접근은 [JPype 공식 說明](https://jpype.readthedocs.io/en/latest/userguide.html)을 참고한다.

```python
import jpype

jpype.startJVM(
    "/usr/lib/jvm/java-25-openjdk/lib/server/libjvm.so",
    classpath=["/opt/jkoros/lib/中文Java.jar"])
try:
    字元 = jpype.JClass("中文.Java.字元")
    print(字元.程式碼分個數(jpype.JString("韓文文本 😀")))
finally:
    jpype.shutdownJVM()
```

Python·JVM·連接 모듈의 CPU 아키텍처가 맞아야 한다. 이 실행판은 ARM64 + musl이므로 일반 x86_64/glibc용 바이너리를 그대로 설치하는 방식은 맞지 않는다. JPype 安裝值·패키지 빌드는 이번 文檔集 작업에서 수행하지 않았다.

### C++: JNI로 직접 調用

[Java調用.cpp](範例/其他語言/Java調用.cpp)는 實際資料 執行命令 가능한 예제다. JVM을 任務 스레드에서 생성하고 下一項目 메서드를 찾는다.

```cpp
jclass type = env->FindClass("中文/Java/字元");
jmethodID method = env->GetStaticMethodID(
    type, "程式碼分個數", "(Ljava/lang/String;)I");
```

JVM 生成·종료와 스레드 연결은 [JNI Invocation API](https://docs.oracle.com/en/java/javase/25/docs/specs/jni/invocation.html)의 방식이다. `JNIEnv*`는 生成·연결된 스레드에서 사용해야 한다. 예제는 Java 예외를 확인하고 JVM 종료까지 처리한다.

게스트에 `Java調用.cpp`를 복사한 後端值 컴파일한다. 로그인 환경의 `JAVA_HOME`은 `/usr/lib/jvm/java-25-openjdk`第三操作數.

```sh
g++ -std=c++11 -Wall -Wextra -pthread \
  -I"$JAVA_HOME/include" -I"$JAVA_HOME/include/linux" \
  Java調用.cpp -L"$JAVA_HOME/lib/server" \
  -Wl,-rpath,"$JAVA_HOME/lib/server" -ljvm -o Java調用
./Java調用 /opt/jkoros/lib/中文Java.jar
```

輸出: `C++ → 中文.Java.字元.程式碼分個數: 4`

예제는 `韓文文本 😀`을 UTF-16으로 만들어 `NewString`에 전달한다. `NewStringUTF`首位操作數 받는 modified UTF-8은 일반 UTF-8과 차이가 있으므로, 일반 UTF-8 이모지 바이트를 그대로 넘기는 예제로 작성하지 않았다. [JNI 字符串 格式值](https://docs.oracle.com/en/java/javase/25/docs/specs/jni/types.html#modified-utf-8-strings)

다른 中文 메서드도 JNI 서명과 實參 자료형을 맞춰 호출할 數 있다. 예를 들어 `Path`를 받는 檔案 API는 먼저 `檔案.路徑`로 Java 路徑 객체를 얻어 전달한다. Swing 호출에는 그래픽 세션과 이벤트 程序值條目 執行緒值 규칙도 그대로 적용된다. JNI는 Java 실행을 기계어로 대체하는 기능이 아니며 JVM이 繼續處理 필요하다.

### 기존 posix-kor와의 관계

추가된 [內建 ARM64 連接](../posix-kor/arm64-native/指南.md)은 C++에서 AOT Java 커널의 RAM 檔案 API를 직접 호출하며, 별도 EL0 使用者 라이브러리로 檔案/UDP 루프백 SVC 호출도 제공한다. JNI를 사용하지 않는다. 이 문서의 ARM64 **Linux** 및 中文 Java JAR와는 다른 執行命令 기반이며 內建 커널은 별도 제한형 Java 編譯器/JVM과 MicroPython 1.24.1을 실행한다. MicroPython의 `import jkoros`로 Java 內核值 檔案·UDP 루프백·矩形 호출이 가능하지만 이 문서의 JAR를 가져오는 기능은 아니다. 內建 커널의 전체 OpenJDK/JRE/CPython 이식은 아직 미완성이다.

[posix-kor](../posix-kor/指南.md)에는 `打開檔案`, `讀取檔案資料`, `寫入檔案資料`, `關閉檔案`, `創建端點`, `發送數據報資料` 등의 中文 C 별칭이 있다. 그러나 구현은 **內建 jkoros i386 커널의 `int 0x80` 調用 규약용**이다.

이 `libposix-kor.a`와 內建 `sys/stat.h` 등의 헤더는 當前項目 ARM64 Linux 실행판의 libc/C++용 라이브러리가 아니다. 해당 헤더·바이너리를 ARM64 Linux 프로그램에 그대로 연결해서는 ABI가 맞지 않는다. C++용 中文 類別值 라이브러리나 Python용 바인딩을 默認值 제공하는 상태도 아니다. 當前項目 Linux 실행판에서 그와 같은 독립 API를 제공하려면 Linux 표준 라이브러리를 대상으로 별도로 實現·빌드해야 한다.

## 5. 驗證 범위와 재현

패키지 頭文件 여부는 [分發值 패키지 條目列表](../platforms/rpi4/dist/packages.lock.json) 및 構建系統 루트의 實際資料 파일로 확인했다. JNI 헤더는 JDK의 `include/jni.h`, `include/linux/jni_md.h`, JVM 라이브러리는 `lib/server/libjvm.so`에 있다. 사용자가 之後值 별도로 설치한 패키지는 이 默認值 分發值 목록과 다를 數 있다.

이번에 **宿主 x86_64/OpenJDK 11에서** Python 子值 프로세스 호출과 C++ JNI 직접 호출을 編譯原始碼·실행해 각각 結果 4를 확인했다. JAR 공개 메서드도 소스와 대조했다. Python 連接 예제는 追加條目 패키지를 설치하지 않는다.

문서의 Java 使用值 예제도 編譯原始碼·실행했고, 22개 메서드의 文檔集 頭文件 여부와 로컬 文檔集 링크를 확인했다. [範例 有效性校驗 日誌記錄](build/其他語言/有效性驗證報告.json)

기존 ARM64 QEMU에서는 Java의 檔案·Unicode值·스레드·HTTP 및 Swing 測試 결과가 있다. 이번 Python/C++ 連接 예제의 **ARM64 게스트 실행과 JPype 설치는 별도 검증하지 않았다.** 이미지와 執行命令 중인 使用者 환경은 이 文檔集 작업에서 변경하지 않았다. [기존 操作系統 有效性校驗 日誌記錄](../platforms/rpi4/VERIFICATION.md)

호스트에서 Python 예제를 재현하려면:

```sh
cd /home/user/jkoros/中文Java
make
mkdir -p build/其他語言
javac -encoding UTF-8 --release 11 -cp build/中文Java.jar \
  -d build/其他語言 範例/其他語言/字符命令.java
python3 範例/其他語言/Python調用.py \
  --jar build/中文Java.jar --classes build/其他語言
```

宿主 C++ 예제는 頂端值 JNI 編譯原始碼 명령의 JDK 경로를 **宿主 JDK 路徑**로 바꾸고, 原始碼 `範例/其他語言/Java調用.cpp`와 JAR `build/中文Java.jar`를 지정한다. ARM64 게스트 JDK의 헤더·庫 경로를 宿主 x86_64 링크 명령에 섞지 않는다.
