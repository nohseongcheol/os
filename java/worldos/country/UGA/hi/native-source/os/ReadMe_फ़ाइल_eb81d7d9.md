# Java 네이티브 ऑपरेटिंग_सिस्टम

이 문서는 기존 **x86 कर्नेल_मान**을 설명한다. Raspberry Pi 4의 निज ARM64 प्रारंभिक_स्थिति 이식은 [별도 ReadMe_फ़ाइल_eb81d7d9](../platforms/rpi4-native/README.md)를 참고한다. 아래 x86 उपयोगकर्ता ELF·네트워크·IDE स्टोर_मान 기능이 ARM64에 모두 이식된 상태는 아니다.

Java 원문을 निज AOT 후단으로 x86 기계어로 컴파일해 부팅하는 작은 운영체제다. 커널과 별도로 निज 제한형 Java कंपाइलर·JVM ELF를 उपयोगकर्ता 모드에 적재할 수 있다. Linux, engos, koros4와 बाहरी_मान OpenJDK는 게스트에 적재하지 않는다. 부팅 진입과 포트/물리 मेमोरी_क्षेत्र 접근은 어셈블리이며, 문자 단말·입력 प्रक्रिया_मान_एन्ट्री·आदेश पार्स_करें_मान·작업 खंड_मान 관리는 `स्रोत/*.java`에 있다.

## 게스트 Java 개발

`javac Hello.java`, `java Hello`로 부팅된 ऑपरेटिंग_सिस्टम 안에서 कंपाइल_स्रोत·실행한다. `edit FILE.java`와 `.save`로 소스를 작성하며 `ls`, `cat`, `rm`을 제공한다. RAM 파일은 최대 8개, 각각 16KiB이다. 전용 IDE 매체를 연결하면 `sync`로 보존할 수 있다. 이 기능은 निज 제한형 구현이며 전체 OpenJDK/JDK 호환은 아니다. 사용법·समर्थन_मान 문법·संचिका 적재·교차 시험은 [Java 개발 환경](../문서/자바개발환경.md)에 있다. `make test-java`로 검증한다.

## 빌드와 निष्पादित_करें_आदेश

`compiler/`가 요구하는 도구에 더해 ISO 생성에는 `grub-file`, `grub-mkrescue`, GRUB BIOS मॉड्यूल_मान, `xorriso`가 필요하다. 실행에는 QEMU 또는 VirtualBox가 필요하다. अद्यतित_आइटम 설치된 도구만 사용한다. `make run-store`는 새 전용 가상 स्टोर_मान 매체를 만들어 연결한다. VirtualBox 실행기는 이 프로젝트가 만든 전용 VM만 설정하고 다른 VM은 변경하지 않는다. 가상 메모리는 डिफ़ॉल्ट_मान 64MiB이며 최소 16MiB가 필요하다.

```sh
cd /home/user/jkoros/os
make                 # build/kernel.elf
make iso             # build/kernel.iso (उपयोगकर्ता ELF समूह_मान 포함)
make run             # ELF 직접 부팅, 직렬 단말
make run-gui         # GRUB ISO 부팅, VGA 창과 PS/2 자판
make vbox            # 상위 폴더의 실행기로 전용 VirtualBox VM निष्पादित_करें_आदेश
make vbox-status     # 전용 VirtualBox VM अवस्था_मान सत्यापित_करें
make test            # ELF와 ISO 두 경로의 वास्तविक_डेटा 부팅/입력 시험
make apps            # उपयोगकर्ता 프로그램만 बिल्ड_सिस्टम
make test-network    # उपयोगकर्ता निष्पादित_करें_आदेश/UDP/रक्षित_करें_मान 시험
```

`make run`은 QEMU의 직렬 표준 입출력을 쓴다. `Ctrl+A`를 누른 वापस_मान `X`로 QEMU를 종료할 수 있다. `halt`는 게스트 CPU만 정지시키므로 QEMU खिड़की/프로세스는 별도로 닫는다. 폴링 방식이라 प्रतीक्षा_करें_मान 중에도 आयोजक CPU를 사용할 수 있다.

VirtualBox는 `make vbox`로 실행한다. 새 전용 VM을 मेमोरी_डेटा 64MiB, BIOS, 광학 드라이브 부팅으로 자동 설정하며 디스크는 필요 없다. वास्तविक_डेटा VirtualBox 5.2.42에서 부팅, Java निज 시험, शेल 입력, `run hello vbox`의 ring 3 실행과 정상 종료를 확인했다. अद्यतित_आइटम 통신 드라이버는 QEMU의 RTL8139 전용이며 VirtualBox의 PCnet/E1000에서는 네트워크를 사용할 수 없어 네트워크 장치를 비활성화한다. स्टोर_मान अवस्था_मान 재개와 새 बिल्ड_सिस्टम 반영 방법은 [VirtualBox निष्पादित_करें_आदेश ReadMe_फ़ाइल_eb81d7d9](../문서/가상상자실행.md)에 있다.

## 셸에서 उपयोगकर्ता ऐप_f5044b9b निष्पादित_करें_आदेश 및 네트워크 호출

독립 ELF32 निष्पादित_करें_आदेश 파일을 적재해 **ring 3**에서 실행한다. `int 0x80` 시스템 호출을 통해 단말 निर्गम, तर्क क्वेरी_मान, UDP खोलें·भेजें·받기·닫기를 제공한다. उपयोगकर्ता 코드를 कर्नेल_मान 함수로 직접 호출하는 구조가 아니다.

```text
jkoros> apps
jkoros> run hello first second
jkoros> net
jkoros> run netcheck
jkoros> run udp 10.0.2.2 9000 hello
```

마지막 명령의 응답을 받으려면 호스트의 별도 터미널에서 `python3 /home/user/jkoros/os/उपकरण/प्रतिध्वनि_डेटा.py --port 9000`을 먼저 실행한다. 상세 API, ऐप_f5044b9b जोड़ें_एन्ट्री, पता 공간과 제한은 [उपयोगकर्ता निष्पादित_करें_आदेश·네트워크 ReadMe_फ़ाइल_eb81d7d9](उपयोगकर्ता/ReadMe_फ़ाइल_eb81d7d9.md)에 있다.

부팅 सत्यापित_करें 문구:

```text
JKOROS NATIVE JAVA
자바 기계어 कर्नेल_मान चलाएँ
JAVA SELFTEST PASS
USER ELF: ring 3 / paging / int 0x80
help | info | mem | alloc | free N | echo TEXT | clear | test | halt
apps | run NAME [ARGS] | net
READY
jkoros>
```

## 구현한 기능

- GRUB Multiboot 1 ELF 부팅, x86 रक्षित_करें_मान मोड_मान GDT, BSS आरंभ, 64KiB ऑपरेंड_स्टैक.
- Java फ़ंक्_शन_मान वास्तविक_डेटा 실행과 부팅 सिस्टम_जानकारी मार्कर_मान सत्यापित_करें.
- COM1 직렬 इनपुट_आउटपुट, VGA 문자 화면·कर्सर_मान·스크롤·मिटाएँ_एन्ट्री.
- PS/2 डिफ़ॉल्ट_मान 자판, 좌우 Shift, Enter, Backspace. एक्सटेंशन_मान कुंजी_मान/마우스 자료는 आदेश 입력으로 쓰지 않는다.
- 길이 128의 आदेश 입력 버퍼, ओवरफ्लो_मान 방지, CR/LF प्रक्रिया_मान_एन्ट्री.
- `help`, `info`, `mem`, `alloc`, `free N`, `echo TEXT`, `clear`, `test`, `halt`.
- 4KiB 작업 खंड_मान 8개의 आवंटित_करें_संग्रहण·वापस_करें_परिणाम·재사용과 중복 वापस_करें_परिणाम 방지.
- Java सरणी_मान 256KiB 영역의 आकार·सबस्क्रिप्ट_मान 검사와 런타임 त्रुटि 중단.
- पढ़ें 전용 JKAP निष्पादित_करें_आदेश समूह_मान, ELF32 खंड_मान/प्रवेश_बिदुं मान्य_करें, उपयोगकर्ता मोड_मान·तर्क·निर्गमन_ऐप कोड_मान.
- कर्नेल_मान/उपयोगकर्ता 페이지 अनुमति_मान 분리, TSS, IDT, PIT 100Hz, उपयोगकर्ता CPU अपवाद प्रक्रिया_मान_एन्ट्री 및 निष्पादित_करें_आदेश समय_उपयोगिता 상한.
- PCI RTL8139 폴링 드라이버, ARP, 정적 IPv4, UDP योगफल_की_जाँच·송수신·प्रतीक्षा_करें_मान 제한.

`mem`의 Upper memory는 Multiboot의 1MiB 위쪽 연속 मेमोरी_डेटा आकार(KiB)이며, 전체 मेमोरी_डेटा 지도 분석이나 자유 물리 मेमोरी_डेटा 수치가 아니다. `alloc`은 이미 확보한 पूर्णांक सरणी_मान 안의 작업 खंड_मान 번호를 반환한다. 일반 물리 पेज_मान आवंटित_करें_संग्रहण, पता पता_क्षेत्र 또는 उपयोगकर्ता प्रक्रिया_मान मेमोरी_डेटा 관리가 아니다.

## 명시적인 한계

이 커널은 **उपयोगकर्ता 프로그램을 한 번에 하나 실행하는 प्रारंभिक_स्थिति कर्नेल_मान**이다. PIT IRQ0만 사용하며 키보드와 NIC는 폴링한다. उपयोगकर्ता CPU 예외는 해당 프로그램을 끝내고 셸로 복귀시키지만 कर्नेल_मान 예외는 중단한다. निष्पादित_करें_आदेश 시간은 약 3초로 제한한다. 완전한 선점 다중 प्रक्रिया_मान 스케줄러, FAT/ext 등 일반 디스크 फ़ाइल_सिस्टम, TCP·DNS·DHCP·IPv6·HTTP, 전체 POSIX, 일반 ऑब्जेक्ट_मान 모델/GC는 아직 없다. 전용 IDE संचिका 보존과 POSIX संचिका/UDP 일부 기능은 구현했다. JVM은 RAM 파일의 단일 클래스를 निष्पादित_करें_आदेश 시 적재하며 일반 ClassLoader나 JAR 로딩은 지원하지 않는다. 네이티브 निष्पादित_करें_आदेश 파일은 बिल्ड_सिस्टम 시 पढ़ें 전용 묶음에 넣으며, 일반 Linux ELF를 실행하는 환경이 아니다. 기존 `../लिगेसी_स्रोत/`의 JVM 관리 कर्नेल_मान 전체를 이식한 것도 아니다.

Java 식별자는 한국어다. 직렬 출력은 이 프로젝트의 한글(BMP 문자)을 UTF-8로 표시한다. VGA는 डिफ़ॉल्ट_मान ASCII 글꼴만 사용하므로 한글 자리에 `?`가 나온다. आदेश 입력도 अद्यतित_आइटम ASCII만 지원하며 한글 फ़ॉन्ट_मान·입력기 및 보조 평면 문자 출력은 후속 작업이다. `test`는 작은 배열을 새로 할당하고 GC가 없으므로 무한 반복하지 않는다.

## 자동 시험

`시험/부팅시험.py`는 디스크 없는 독립 QEMU를 생성해 다음을 검증하고 종료한다.

- ELF 직접 부팅 및 GRUB ISO 부팅.
- Java निज 시험과 UTF-8 직렬 문구.
- आदेश सहायता_दिखाना·सिस्टम_जानकारी·मेमोरी_डेटा·निर्गम·त्रुटि 입력·화면 मिटाएँ_एन्ट्री.
- 작업 खंड_मान 8개 आवंटित_करें_संग्रहण, 부족 प्रक्रिया_मान_एन्ट्री, वापस_करें_परिणाम/중복 वापस_करें_परिणाम/재할당.
- 직렬 줄바꿈·백스페이스·긴 입력 प्रक्रिया_मान_एन्ट्री.
- QEMU PS/2 कुंजी_मान 입력으로 `info` निष्पादित_करें_आदेश, `halt` 정지.

성공 로그는 `build/부팅시험.json`에 남는다. 로컬 Unix 소켓을 금지하는 샌드박스에서는 시험 도구에 해당 권한이 필요하다. 시험 도중 새로 만든 QEMU만 종료하며 기존 VM과 वास्तविक_डेटा 디스크는 건드리지 않는다.

`시험/사용자통신시험.py`는 ELF/ISO 각각에서 उपयोगकर्ता ELF, वास्तविक_डेटा ring 3, तर्क, आयोजक 루프백 UDP 왕복, 1,023/1,024바이트 24회 연속 왕복, समय_उपयोगिता 초과, NIC 없음, मेमोरी_डेटा/포트 पहुँच_एन्ट्री 차단, CPU अपवाद, 무한 पुनरावृति_मान, 잘못된 ELF를 시험한다. `build/사용자통신시험.json`에 게스트 기록과 호스트가 받은 데이터의 길이·해시를 저장한다. `시험/패킷시험.py`는 वास्तविक_डेटा Java मामला_मान 처리기에 손상된 패킷을 넣어 2,201개 경계/योगफल_की_जाँच 조건을 검사한다. आयोजक 루프백 외 बाहरी_मान 서버에는 시험 트래픽을 보내지 않는다.

부트 경계는 GNU의 [Multiboot 명세](https://www.gnu.org/software/grub/manual/multiboot/multiboot.html)를 따른다.

새 파일서술자·C ABI·IDE स्टोर_मान·Java संचिका 흐름의 범위와 हिंदी 명명 대응은 [posix-kor ReadMe_फ़ाइल_eb81d7d9](../posix-kor/ReadMe_फ़ाइल_eb81d7d9.md)에 있다. `make test-posix`로 ELF/ISO 실행과 재부팅 보존을 검증한다.
