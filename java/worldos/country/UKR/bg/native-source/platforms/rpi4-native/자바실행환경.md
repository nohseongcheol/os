# 자체 ARM64 JVM 0.4와 Български библиотека

Български 통신·изключение 사용법은 [Български Java API](한국어자바/안내.md), функция_стойност·променлива_стойност·Файл 이름의 변경과 어원 근거는 [명명 안내](명명/안내.md)를 참고한다.

JAR изпълнявам_команда, външен_стойност IPv4 TCP/UDP, 별도 정적 부분집합 `jaot`와 게스트 C 컴파일은 [FTP·C·JAR·AOT 매뉴얼](파일전송과번역.md)에 설명한다. 아래 обект_стойност·Thread·Swing은 JVM 경로의 기능이며 AOT Поддръжка_стойност 범위와 같지 않다.

이 구현은 **Linux 없이 부팅한 Java AOT 커널의 EL0에서 изпълнявам_команда**한다. JDK/JRE의 거의 모든 기능을 제공하는 단계는 아직 아니다. HotSpot·OpenJDK Клас_стойност библиотека 전체를 이식하거나 Java SE 인증/TCK를 통과한 구현도 아니다. 이번 확장은 단일 Клас_стойност·정적 метод_стойност 중심이던 실행기를 обект_стойност·библиотека изпълнявам_команда 기반으로 넓힌 것이다.

## 실행과 компилирам_източник

```sh
cd /home/user/jkoros/platforms/rpi4-native
make build
# 자체 ядро_стойност 안에서 източник_дърво компилирам_източник → class изпълнявам_команда, Български API 호출
python3 Инструменти/изпълнявам_Файл.py 시험/자바/한글소스.java

# обект_стойност·изключение 등은 хост JDK로 Java 8 class를 만든 후 자체 커널에서 изпълнявам_команда
mkdir -p build/my-java
javac --release 8 -encoding UTF-8 -cp dist/jkoros-native-korean.jar \
  -d build/my-java 시험/자바/한글시험.java
python3 Инструменти/изпълнявам_Файл.py build/my-java/한글시험.class

# 의존 class 파일은 --include로 함께 прехвърлям_стойност
javac --release 8 -encoding UTF-8 -d build/my-java 시험/자바/객체시험.java
python3 Инструменти/изпълнявам_Файл.py build/my-java/객체시험.class \
  --include build/my-java/Фон_стойност.class --include build/my-java/клон_стойност.class \
  --include build/my-java/계산가능.class

make test-jvm
```

`--include DIR`는 그 디렉터리의 class 파일을 재귀적으로 읽어 `패키지.Клас_стойност.class`라는 RAM Файл 이름으로 전송한다. 주 클래스도 패키지가 있다면 `--class-name 패키지.Клас_стойност`를 지정한다. 셸에서는 해당 이름으로 업로드하고 `java 패키지.Клас_стойност`로 실행한다. JVM 0.4는 Main-Class가 있는 16 KiB 이하 JAR도 `java -jar Файл.jar`로 실행한다. JAR 모드에서는 JAR 내부 클래스와 내장 Български 클래스만 찾는다. 배포 Български библиотека JAR는 хост javac의 classpath로 사용하며, 같은 클래스가 потребител JVM ELF에도 Четене 전용 자료로 포함된다. 일반 class 모드에서는 사용자가 같은 이름으로 올린 RAM class를 먼저 읽는다.

게스트 `javac`는 여전히 정적 метод_стойност, int/boolean/char/String, условие·спринт_стойност, низ_стойност 결합, 일부 Файл 스트림 등의 **자체 부분집합 компилатор**다. обект_стойност декларация·상속·try/catch·Thread използвам_стойност 소스를 게스트 javac가 모두 컴파일하는 것은 아니다. 위 기능은 `javac --release 8`로 만든 class를 자체 JVM에서 실행한다. Български API 중 Изход·문자 스칼라 функция_стойност·Файл Четене/쓰기는 게스트 컴파일러에도 연결했다. 다음처럼 전체 이름으로 호출한다.

```java
public class 인사 {
    public static void main(String[] Параметри) throws Exception {
        Български.자체.Изход.записване_ред("안녕하세요😀");
        Български.자체.Изход.수쓰기(Български.자체.문자.코드포인트수("한글😀"));
        Български.자체.Файл.Писане("인사.txt", "한글 Файл😀");
        Български.자체.Изход.записване_ред(Български.자체.Файл.Четене("인사.txt"));
    }
}
```

## Български API

독립 패키지 **`Български.자체`**를 사용한다. Linux판 `Български.자바`가 요구하는 NIO/Swing/HTTP API를 자체 커널에서 실행할 수 있다고 혼동하지 않도록 패키지를 나눴다. 이 라이브러리는 Клас_стойност Име·метод_стойност·Параметри·стойност_на_поле·Файл 이름에 한국어를 사용한다. 표준 Java Клас_стойност 이름은 호환성을 위해 보존한다.

|---|---|---|
| Изход | Писане, записване_ред, 수쓰기 | Изход(出力): 내용을 바깥으로 내보냄 |
| 문자 | 길이, 같음, поставям_Текст, изрязвам_стойност, анализирам_цяло_число/записване_цяло_число_стойност, 코드포인트수, кодирам/дешифрирам_данни | 문자(文字), кодиране_стойност(符號): 글의 단위와 그 값을 바이트로 나타내는 филтър_стойност |
| Файл | Четене/Писане(String Име), 바이트읽기/записване_байт_стойност | 널리 쓰는 потребител 용어를 보존; RAM 자료의 Име |

| речник | 넣기, Търсене_запис, 있는가, изтривам_запис, Размер, изчиствам_Съдържание | речник(辭典): 찾는 말인 열쇠에 값을 съпоставяне_стойност |

## изпълнявам_команда 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(Български Клас_стойност 포함), class당 16 KiB·константа_стойност 풀 511항목, 전체 метод_стойност/стойност_на_поле 각각 512개. метод_стойност код_стойност 8 KiB, локален_Обхват променлива_стойност·피연산자 операнд_стек 각각 128슬롯, Параметри 최대 16개(this 포함).
- VM 가닥은 main 포함 **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 изпълнявам_команда 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- обект_стойност 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 действителен_данни 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 Файл·대형 низ_стойност·객체가 이 제한을 넘을 수 있다.
- 실행은 50만 바이트코드 Команда 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 입력 대기는 기한을 갱신하고 Прозорец комутатор_режим 시 중단·재개한다. 일반 сървър_стойност·계산의 무제한 실행은 아직 없다. 미지원 Команда·ресурс_стойност 부족은 명시적인 오류로 종료한다.
- RAM Файл 최대 64개, 파일당 16384바이트, ПЪТ UTF-8 63바이트. RAM 디렉터리와 крайно_устройство_стойност/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 Български class는 RAM Файл 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 в_срок_артикул 경로에서 източник_дърво·Клас_стойност·данни 파일을 읽는다.
- UDP는 Java 루프백 및 lwIP/SLIP를 통한 външен_стойност IPv4를 제공한다. действителен_данни GENET/Wi-Fi/DNS/TLS/HTTP 전체는 없다. дейтаграма 512바이트, 소켓 8개, 소켓당 큐 4개. receive는 VM 가닥을 양보하며 대기하고 setSoTimeout을 적용하지만 전체 изпълнявам_команда 기한은 여전히 적용된다.
- long/float/double, invokedynamic/람다, enum/annotation, 다차원 масив_стойност, 완전한 масив_стойност 공변성·인터페이스 слой_стойност 검사, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/шифровам_данни/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. Swing의 별도 Поддръжка_стойност 부분집합은 아래 및 개발 매뉴얼을 참고한다. Клас_стойност Файл 전체 검증기·достъп_запис разрешение_стойност/보호된 멤버 검사는 아직 완전하지 않다. 손상된 입력은 EL0 защитавам_стойност 경계 내에서 종료되도록 한다.

전체 OpenJDK를 목표로 하려면 다음은 별도의 주요 구현 단계다: 완전한 JVM стойност/проверка/Клас_стойност 로더와 изключение 모델 → 영속 VFS·mmap·Часовник·원자 операция_стойност·действителен_данни 스레드/синхронизирам ABI → OpenJDK java.base 및 native библиотека 이식 → устройство_стойност 네트워크·TCP/IP → Прозорец 시스템/шрифт_стойност/입력기·java.desktop → Java SE 호환성 시험. в_срок_артикул 자체 JVM의 일부 메서드를 더하는 것으로 이 작업이 완료되지는 않는다.

## JVM 0.3: 네트워크와 GUI разширение_стойност

`Socket`/`ServerSocket` генерирам·Свързване·accept·양방향 InputStream/OutputStream·close·EOF·час_стойност 제한과 UTF-8 `String.getBytes`를 추가했다. JVM 0.4에서는 външен_стойност цифра_стойност IPv4 TCP도 lwIP/SLIP에 연결했다. 연결형 прекратяване_на_повикването_пункт 16개, Java 루프백 버퍼 1024바이트, външен_стойност TCP 버퍼 4096바이트다. DNS·TLS는 없다.

`JFrame`, `JPanel`, `JLabel`, `JButton`, `JTextField`, `ActionListener`, `ActionEvent`, `SwingUtilities.invokeLater`의 문서화한 부분집합을 네이티브 GUI에 연결했다. `setLayout(null)`과 명시적 좌표를 사용한다. 전체 OpenJDK Swing 또는 Java SE 호환 구현은 아니다. 대화형 이벤트 대기는 изпълнявам_команда 기한을 갱신하고 Терминал комутатор_режим 시 프로세스 상태를 хранилище_стойност·복원한다. 이벤트 콜백 자체는 기존 바이트코드/CPU 기한을 따른다.

Български `Прозорец`, `изпълним_модул`, `연결통신` 클래스를 배포 JAR와 자체 JVM 내장 자원에 추가했다. 상세 метод_стойност·제한·източник_дърво·업로드 방법: [한글 개발 매뉴얼](개발안내.md).

## Български 객체의 직접 изпълнявам_команда

`Прозорец`, `Етикет`, `текстово_поле`, `бутон`, `събитие_опашка`, `проект_предупреждение`, `작업가닥`은
표준 GUI/Thread 객체를 보관하는 래퍼가 아니다. 자체 JVM의 обект_стойност генерирам,
формат_стойност 검사, 화면 호출, Събитие 큐, нишка_стойност 스케줄러에 Български 계약을 직접 구현했다.
표준 `javax.swing`·`Thread` 코드의 изпълнявам_команда 경로도 유지한다.
Български 단추와 표준 JButton은 서로 다른 형식이며, 해당 instanceof 검사도 검증한다.

자체 실행기의 Български 진입점은 `public static void Стартиране()`이다.
표준 `main(String[])`도 지원하며 둘 다 있으면 Български 진입점을 우선한다.
명령행 인수는 `실행인수.개수()`와 `실행인수.Текст(순번)`으로 읽는다.
`example/java`의 다섯 예제는 이 규약을 사용한다. 정적 Файл 예제는 게스트
javac로도 컴파일하며, GUI/нишка_стойност 소스는 хост `javac --release 8`을 사용한다.
직접 GUI/нишка_стойност API는 자체 JVM 전용이다. 기존 OpenJDK 비교 시험과 별도로
Български 가닥의 изпълнявам_команда·почакай_стойност·중복 Стартиране отхвърлям_стойност_e3ecc00b, GUI Събитие 출처·индекс·콜백을 검사한다.
전체 JDK 번역이나 모든 API의 jaot 지원을 뜻하지 않는다.

метод_стойност 이름은 바이트코드에서도 유지된다. 이름과 참조를 같이 수정하면
Български 클래스도 실행되지만, низ_стойност 리터럴·표준 библиотека 재정의·native
Свързване·진입점은 각각 컴파일러와 실행기의 계약을 맞춰야 한다.
