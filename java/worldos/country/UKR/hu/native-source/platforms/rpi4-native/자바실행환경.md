magyar kommunikáció·kivétel 사용법은 [magyar Java API](한국어자바/fontos_fájl_eb81d7d9.md), FÜGGVÉNY_ÉRTÉK·változó_ÉRTÉK·Fájl 이름의 변경과 어원 근거는 [명명 fontos_fájl_eb81d7d9](명명/fontos_fájl_eb81d7d9.md)를 참고한다.

## végrehajt_parancs 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(magyar tanóra_ÉRTÉK 포함), class당 16 KiB·állandó_ÉRTÉK 풀 511항목, 전체 metódus_ÉRTÉK/mezőérték 각각 512개. metódus_ÉRTÉK KÓD_ÉRTÉK 8 KiB, helyi_hatókör változó_ÉRTÉK·피연산자 operandus_Sor 각각 128슬롯, Argumentumok 최대 16개(this 포함).
- VM 가닥은 main 포함 **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 végrehajt_parancs 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- objektum_ÉRTÉK 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 tényleges_adat 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 Fájl·대형 sztring_ÉRTÉK·객체가 이 제한을 넘을 szám 있다.
- 실행은 50만 바이트코드 Parancs 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 bevitel_ÉRTÉK 대기는 기한을 갱신하고 Ablak vált_mód 시 중단·재개한다. 일반 kiszolgáló_ÉRTÉK·계산의 무제한 실행은 아직 없다. 미지원 Parancs·erőforrás_ÉRTÉK 부족은 명시적인 오류로 종료한다.
- RAM Fájl 최대 64개, 파일당 16384바이트, ÚTVONAL UTF-8 63바이트. RAM 디렉터리와 társ_ÉRTÉK/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 magyar class는 RAM Fájl 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 aktuális_cikk 경로에서 forrás_fa·tanóra_ÉRTÉK·adat 파일을 읽는다.
- UDP는 Java 루프백 및 lwIP/SLIP를 통한 külső_ÉRTÉK IPv4를 제공한다. tényleges_adat GENET/Wi-Fi/DNS/TLS/HTTP 전체는 없다. datagram 512바이트, szoftvercsatorna_ÉRTÉK 8개, 소켓당 큐 4개. receive는 VM 가닥을 양보하며 대기하고 setSoTimeout을 적용하지만 전체 végrehajt_parancs 기한은 여전히 적용된다.
- long/float/double, invokedynamic/람다, enum/annotation, 다차원 TÖMB_ÉRTÉK, 완전한 TÖMB_ÉRTÉK 공변성·인터페이스 réteg_ÉRTÉK 검사, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/titkosít_adat/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. Swing의 별도 támogat_ÉRTÉK 부분집합은 아래 및 개발 매뉴얼을 참고한다. tanóra_ÉRTÉK Fájl 전체 검증기·hozzáfér_bejegyzés engedély_ÉRTÉK/보호된 멤버 검사는 아직 완전하지 않다. 손상된 입력은 EL0 véd_ÉRTÉK határ_ÉRTÉK 내에서 종료되도록 한다.
