# Java 네이티브 компілятор

OpenJDK своє 소스를 빌드하는 **`--target openjdk-build`**와 своє ядро_значення ABI 검사 도구를 추가했다.
이는 공식 javac/C/C++ 도구를 연결하는 별도 경로다. [збирання 방법·фактично_дані затвердити·ядро_значення 이식 кліп](OpenJDK-джерело_збірка_і-자체커널-이식.md)를 참고한다.

x86 직접 변환과 ARM64 C генерувати 후단은 모두 [기계어미리번역.java](자바도구/기계어미리번역.java)로 구현한다. `sh 미리번역.sh`로 직접 실행하며, [기계어미리번역.py](기계어미리번역.py)와 `компілятор.py`는 이전 команда·API 및 OpenJDK 도구를 위한 호환 진입점이다. своє Pi4 후단은 freestanding C를 거쳐 AArch64로 만든다. [arm64.py](arm64.py)는 이전 경로와 Python 호출을 위한 호환 진입점이다. функція_значення·змінна_значення·генерувати C 이름의 뜻과 예외는 [українська 명명 файл_Readme_eb81d7d9](../platforms/rpi4-native/명명/файл_Readme_eb81d7d9.md)를 참고한다. [ARM64 збирання·опора_значення кліп](../platforms/rpi4-native/файл_Readme_eb81d7d9.md)에 Виконати_команда 조건이 있다. 전체 OpenJDK나 일반 Клас_значення 실행기는 아니다.

Виконати_команда 시 JVM이 필요 없는 x86 32비트 ELF를 만든다. JDK 11 이상으로 실행하는 Java своє AOT 후단이며, Java 전체를 새로 구현한 컴파일러는 아니다. Java 문법·доступ_запис керування_значення·Тип_значення 검사는 JDK의 `javac`에 맡기고, Java 8 Клас_значення 파일을 읽어 각 바이트코드를 x86 명령으로 직접 변환한다. C 코드로 우회하거나 바이트코드 해석기를 커널에 넣지 않는다.

```text
Java вихіднийКод → javac의 문법·Тип_значення 검사 → 임시 .class
          → своє x86 변환기 → GNU as/ld → 네이티브 ELF32
```

## 준비와 Виконати_команда

збирання хост: Linux, Python 3.6 이상, JDK 11 이상(`javac --release 8`), GNU binutils(`as`, `ld`), Make. чинний_елемент 환경의 OpenJDK 11, Python 3.6, binutils 2.30으로 검증했다. зовнішній_значення Python 패키지와 네트워크 다운로드는 사용하지 않는다.

```sh
cd /home/user/jkoros/compiler
make
./build/계산
echo $?                  # 0이면 예제 випробування 성공

python3 компілятор.py --target linux --entry 계산.запустити \
    -o build/계산 예제/계산.java

make test
```

`linux` 대상은 Linux의 32비트 Виконати_команда 호환 기능이 필요하다. `int 0x80`을 차단하는 샌드박스에서는 `Bad system call`이 발생할 수 있다. 정상 Linux хост 또는 해당 실행을 허용한 випробування 환경에서 실행한다. 시험의 비정상 종료를 통과로 처리하지 않는다.

진입점은 `static int запустити()` 또는 `static void запустити()`처럼 인수가 없어야 한다. `--entry 패키지.Клас_значення.функція_значення`로 선택한다. `int` 반환값은 Linux 프로세스 Вийти_програма 코드가 되며 셸에는 하위 8비트가 보인다. 일반 `main(String[] args)` Виконати_команда 환경이나 표준 ввід_вивід 라이브러리는 제공하지 않는다.

`--target kernel`은 запуск_машини 코드와 연결할 재배치 ELF 오브젝트를 생성한다.

```sh
cd /home/user/jkoros
python3 compiler/компілятор.py --target kernel --entry Ядро.запустити \
    --export kernel_dispatch=системний_виклик.процес_значення_запис \
    -o os/build/java.o os/вихіднийКод/*.java
```

`--target user`는 jkoros 셸에서 실행할 독립 ELF를 생성한다. `простір_користувача` 클래스의 제한된 native API는 `int 0x80` 시스템 호출로 연결하며 `пристрій_значення` 클래스의 обладнання_значення 직접 접근은 거부한다. простір_користувача ELF는 Linux Виконати_команда файл ABI와 다르므로 호스트에서 실행하지 않는다. генерувати·реєстр_запис 방법은 [простір_користувача Виконати_команда файл_Readme_eb81d7d9](../os/простір_користувача/файл_Readme_eb81d7d9.md)에 있다. `--export 외부기호=Клас_значення.функція_значення`는 오버로드되지 않은 정적 함수를 своє операнд_Стіс ABI로 노출한다. 커널의 시스템 호출 진입점에 사용한다.

Java 파일은 필요한 클래스들을 한꺼번에 전달한다. Вивід 옆의 `.s`는 생성된 어셈블리, `.json`은 вихіднийКод SHA-256 및 네이티브 символ↔Java функція_значення 대응표다. українська 함수명은 원문과 대응표에 보존하고 ELF 내부에는 충돌 방지용 комп_ютер 기호를 쓴다. компілювати_джерело·조립·З_єднання 중 실패하면 기존 результат 파일을 덮어쓰지 않는다.

## опора_значення кліп

- `int`, `boolean`, `byte`, `short`, `char`의 32비트 계산 및 Тип_значення перетворити_значення.
- 정적 필드와 정적 функція_значення, 매개변수·반환값, 재귀, 클래스별 지연 초기화와 ініціалізувати цикл_значення.
- 조건문, 반복문, 단락 평가, 삼항식, ціле_число `switch`, 넓은 місцевий_масштаб змінна_значення 인덱스.
- 덧셈·뺄셈·곱셈·나눗셈·나머지·біт_значення 연산과 переміщати_значення. Java의 오버플로 및 `MIN_VALUE / -1` 동작을 유지한다.
- `int[]` генерувати·초기값 0·길이·Читання·Запис·довідка 비교. 256KiB 고정 масив_значення область_значення_0e9a97ab, 널/підрядковий_символ_значення/Розмір/адреса_область 검사.
- рядок_значення 리터럴과 `String` довідка, `length()` 및 `charAt()`. 문자열은 UTF-16 код_значення 단위로 저장하고 같은 리터럴은 공유한다. NUL 및 대리쌍도 시험한다.
- українська Клас_значення·функція_значення·змінна_значення·файл Назва.

`new Object`, 인스턴스 значення_поля/функція_значення, 상속/인터페이스, `long/float/double` Виконати_команда операція_значення, `int[]` 이외 масив_значення, рядок_значення 동적 결합, Java 표준 бібліотека, виняток процес_значення_запис, 스레드·синхронізувати·GC는 미지원이다. 실행에 필요한 미지원 바이트코드나 зовнішній_значення 호출을 발견하면 실패한다. 사용되지 않는 стандартне_значення 생성자는 Виконати_команда 코드로 만들지 않는다. Java 8 문법이어도 모든 프로그램을 컴파일할 수 있다는 뜻은 아니다.

виняток об_єкт_значення 대신 런타임 ПОМИЛКА 번호로 중단한다. Linux와 jkoros простір_користувача 대상에서는 `100 + індекс`로 종료하고 ядро_значення 대상에서는 `JKOROS PANIC індекс`를 출력하고 정지한다. простір_користувача 프로그램만 종료한 경우 셸은 계속 실행된다.

| індекс | 원인 |
| --- | --- |
| 1 | 0으로 ділення_КР |
| 2 | 널 довідка |
| 3 | масив_значення/рядок_значення підрядковий_символ_значення кліп 초과 |
| 4 | 음수 масив_значення Розмір |
| 5 | масив_значення область_значення_0e9a97ab 부족 |

масив_значення 영역은 증가식 할당이며 회수하지 않는다. 재귀 스택의 경계 검사도 아직 없으므로 무제한 재귀를 안전하게 처리하는 런타임은 아니다. 특권 ядро_значення 및 신뢰할 수 있는 작은 프로그램용 початковий_стан 구현이다.

## native 경계와 ABI

ядро_значення 대상에서는 `os/вихіднийКод/пристрій_значення.java`, простір_користувача 대상에서는 `os/простір_користувача/оголошення_4f4f026b/простір_користувача.java`의 정확한 метод_ім_я_Текст·서술만 허용한다. 임의의 `native` 함수와 Linux/простір_користувача 대상의 обладнання_значення 접근은 거부한다. Java 인수를 왼쪽부터 32비트 한 칸씩 스택에 놓으며, 반환값은 EAX, EBP/ESP 이외 레지스터는 호출자가 보존한다고 가정하지 않는다. C의 cdecl/JNI ABI가 아니므로 C 함수와 바로 연결하면 안 된다.

Java вихіднийКод 또는 `.class` 입력을 받는다. 전체 JVM 바이트코드 검증기는 제공하지 않는다. 어노테이션 처리는 비활성화하고 비어 있는 Клас_значення шлях/вихіднийКод 경로에서 명시한 소스만 컴파일한다.

## 검증과 реалізація 근거

`випробування/test_compiler.py`의 14개 시험에는 네이티브 ELF와 OpenJDK의 операція_значення результат 대조, Клас_значення ініціалізувати, ціле_число 극값, рядок_значення/масив_значення, 재귀·switch·wide, 런타임 오류와 미지원 기능 відхилити_значення, неполадка_значення 시 Вивід 보존, простір_користувача ELF/дозвіл_значення 경계 및 내보내기 검증이 포함된다. 이것은 Java 전체 적합성 시험은 아니다.

команда 의미와 Клас_значення файл 형식은 Oracle의 [JVM команда 명세](https://docs.oracle.com/javase/specs/jvms/se11/html/jvms-6.html), [Клас_значення файл 명세](https://docs.oracle.com/javase/specs/jvms/se11/html/jvms-4.html)를 참고했다.
