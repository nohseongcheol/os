# JUkrOS 구조

아래는 об_єкт_значення 기반 관리 ядро_значення 전체의 мета_об_єкт 구조다. чинний_елемент фактично_дані запуск_машини 가능한 제한형 구현은 `compiler/`와 `os/`에 있으며 [네이티브 операційна_система_ОС файл_Readme_eb81d7d9](../os/файл_Readme_eb81d7d9.md)에 реалізація 범위를 명시한다. 아래의 GC·문맥 перехід_режим·файлова_система 등이 새 ISO에 모두 포함돼 있지는 않다.

```text
GRUB 또는 UEFI
  ↓
x86 최소 부트·트랩 шар_значення
  ↓
Java AOT 실행기와 об_єкт_значення·масив_значення·GC 런타임
  ↓
обладнання_значення 경계
  ↓
Java 관리 ядро_значення
  ├─ Пам_ять_область/쪽관리/COW
  ├─ процес_значення/배정/wait
  ├─ файлова_система/ELF/POSIX
  └─ 입력/пристрій_збереження_даних/мережа_Стіс
```

OpenJDK 자체는 이미 운영체제가 제공하는 файл, 스레드, 가상 기억공간을 전제로 한다. 따라서 ядро_значення 부팅에는 OpenJDK를 그대로 넣지 않고 제한된 Java 바이트코드 AOT와 작은 런타임을 사용한다.

네이티브 계층에는 `in/out`, `hlt`, CR0/CR2/CR3/CR4, `iret`, 문맥 저장처럼 Java로 표현할 수 없는 CPU 동작만 남긴다. 정책과 자료구조는 Java에 둔다.
