# 셸에서 실행하는 простір_користувача 프로그램과 UDP

게스트에서 일반적인 `main(String[] args)` 형식의 소스를 직접 작성하고 컴파일하려면 [제한형 Java 개발 середовище файл_Readme_eb81d7d9](../../문서/자바개발환경.md)를 참고한다. 아래의 네이티브 ELF 개발과 별도로 `javac FILE.java`, `java CLASS`를 제공한다.

## 바로 Виконати_команда

хост термінал 1:

```sh
cd /home/user/jkoros
python3 os/інструменти/відлуння_дані.py --port 9000
```

이 서버는 `127.0.0.1`에만 바인딩한다. зовнішній_значення 연결을 받도록 방화벽이나 обладнання_порт 전달을 변경하지 않는다. Ctrl+C로 종료한다.

хост термінал 2:

```sh
cd /home/user/jkoros
make run
```

게스트의 `jkoros>` 프롬프트에 입력:

```text
apps
run hello first second
net
run netcheck
run udp 10.0.2.2 9000 hello
run stress 9000
```

- `hello`: 독립 Java ELF 실행과 фактично_дані CPU дозвіл_значення `ring 3`, аргументи Вивід.
- `netcheck`: порт_значення 중복, 잘못된 маркер_значення/курсор/길이, 비차단 받기와 час_значення 초과 перевіряти.
- `udp`: IPv4 Адреса·місце_значення порт_значення·한 Ігри_в_слова_значення 메시지를 받아 UDP로 보내고 같은 응답을 перевіряти. `UDP ECHO PASS`, `Exit: 0`이면 성공.
- `stress`: хост `10.0.2.2`의 Призначити_значення 창구와 1,023/1,024바이트 데이터그램을 24회 왕복. отримувати_значення_cef4d8ab цикл_значення_201e2521 경계를 여러 번 지난다.

`make run`/`run-gui`는 `-netdev user,id=net0 -device rtl8139,netdev=net0`을 사용한다. чинний_елемент 주소는 게스트 `10.0.2.15/24`, шлюз_значення `10.0.2.2`로 고정돼 있다. QEMU простір_користувача 네트워크의 хост доступ_запис 주소를 사용한 예제다. 다른 네트워크 설정에는 맞춰 수정해야 하며 자동 DHCP는 없다. NIC 없이 실행하려면 `make -C os run NET_ARGS='-net none'`을 사용한다. 이때 програма_f5044b9b 실행은 되지만 UDP 열기는 `-19`로 실패한다.

## 새 Java програма_f5044b9b додавати_запис

`예제/내프로그램.java`를 Далі_елемент 형식으로 만든다. 진입점은 аргументи 없는 `static int` 또는 `static void` 함수다. 인수는 простір_користувача API로 조회한다.

```java
public final class 내프로그램 {
    public static int запустити() {
        простір_користувача.Запис("My program is running in user mode.\n");
        return 0;
    }
}
```

`os/простір_користувача/програма_f5044b9b.mk`에 추가한다.

```make
APP_NAMES += mine
APP_SOURCE_mine := простір_користувача/예제/내프로그램.java
APP_ENTRY_mine := 내프로그램.запустити
```

여러 Java 파일을 쓰면 `APP_SOURCE_mine`에 공백으로 모두 나열한다. `простір_користувача/оголошення_4f4f026b/простір_користувача.java`는 자동으로 함께 컴파일한다.

```sh
cd /home/user/jkoros
make iso
make run
```

새로 부팅한 셸에서 `run mine`을 실행한다. 이미 Виконати_команда 중인 VM에는 збирання 결과가 자동 반영되지 않는다. програма_f5044b9b 이름은 чинний_елемент 셸의 ASCII 입력 제한에 맞춘 1~15자의 소문자 이름이며 Java Клас_значення·функція_значення·변수에는 한국어를 쓴다. 최대 32개 програма_f5044b9b, 한 Виконати_команда 파일은 최대 2MiB다.

독립 ELF만 컴파일할 수도 있다.

```sh
cd /home/user/jkoros
python3 compiler/компілятор.py --target user --entry 인사.запустити \
    -o os/build/apps/hello.elf os/простір_користувача/оголошення_4f4f026b/простір_користувача.java os/простір_користувача/예제/인사.java
```

`--target user`는 **jkoros 전용 ABI**다. Linux 대상과 시스템 호출 번호가 다르므로 хост 터미널에서 직접 실행하면 안 된다. `.class`는 별도 `java CLASS` 명령의 опора_значення кліп 안에서 실행한다. `.jar`와 일반 Linux Виконати_команда 파일은 지원하지 않는다.

## простір_користувача 네트워크 API

선언은 `оголошення_4f4f026b/простір_користувача.java`에 있다. `надсилати_дані`/`отримувати_дані`의 `int[]` елемент_елемент 한 개는 байт_значення 하나(0~255)를 나타낸다. 한 데이터그램의 최대 дані 길이는 1,024바이트다.

```java
int маркер_значення = простір_користувача.відкрито_мережа(0); // 0: 임시 місцевий_масштаб UDP порт_значення 자동 вибране_значення
int[] дані = new int[32];
дані[0] = 'H'; дані[1] = 'i';
int 보낸길이 = простір_користувача.надсилати_дані(маркер_значення, 0x0a000202, 9000, дані, 2);
int 받은길이 = простір_користувача.отримувати_дані(маркер_значення, дані, 1500);
простір_користувача.Закрити_мережа(маркер_значення);
```

фактично_дані 프로그램에서는 Відкрити·надсилати·받기의 음수 반환값을 각각 검사한다. 완성된 예제는 `예제/자료통신.java`에 있다. `отримувати_дані`의 хвилиноньку_панове_значення 시간은 0~2,000밀리초이며 0은 즉시 반환이다. 받은 데이터그램이 배열보다 크면 해당 데이터그램을 버리고 `-90`을 반환한다. 창구당 отримувати_значення_cef4d8ab 대기열은 한 개뿐이므로 додавати_запис 도착분은 버린다. `보낸주소`와 `보낸창구`로 마지막으로 받은 상대를 조회한다.

| 반환값 | 의미 |
| --- | --- |
| 0 이상 | маркер_значення·процес_значення_запис 길이·성공 등 해당 함수의 результат |
| -5 | пристрій_значення надсилати_значення неполадка_значення |
| -9 | 잘못되었거나 닫힌 통신 маркер_значення |
| -11 | 비차단 받기에서 도착한 дані 없음 |
| -14 | простір_користувача курсор/масив_значення кліп ПОМИЛКА |
| -19 | опора_значення NIC 없음 |
| -22 | порт_значення/хвилиноньку_панове_значення час_значення/аргументи значення ПОМИЛКА |
| -24 | 열린 мережа_порт 4개 한도 |
| -38 | 알 수 없는 시스템 호출 |
| -90 | дані 또는 отримувати_значення_cef4d8ab масив_значення Розмір 문제 |
| -98 | місцевий_масштаб порт_значення індекс 중복 |
| -101 | 지원하지 않는 місце_значення Адреса |
| -110 | ARP·пристрій_значення·отримувати_значення_cef4d8ab час_значення 초과 |

IP 주소는 상위 바이트부터 표기한 32비트 값이다. `10.0.2.2`는 `0x0a000202`이다. 주소를 반환하는 함수는 кодування_значення 있는 Java `int`의 біт_значення 패턴을 사용하므로 상위 비트가 1인 정상 IP 주소가 음수로 보일 수 있다. 단순히 모든 API 반환값의 부호를 오류로 판단하면 안 된다.

## Виконати_команда 경계와 시스템 호출

```text
оболонка run → JKAP에서 ELF затвердити·적재 → ring 3 простір_користувача програма_f5044b9b
                                 ↓ int 0x80
                      курсор 검사 → Java ядро_значення API → RTL8139/UDP
                                 ↓ Вийти_програма·виняток·час_значення 초과
                                оболонка 복귀
```

시스템 호출 레지스터는 `EAX=індекс`, `EBX,ECX,EDX,ESI,EDI=аргументи`, `EAX=результат`다. Java 호출 операнд_Стіс ABI는 컴파일러가 простір_користувача 스텁에서 이 형식으로 바꾼다. C의 POSIX/JNI ABI가 아니다.

| індекс | 호출 |
| --- | --- |
| 0 | Вийти_програма(Стан_значення код_значення) — запустити/ПОМИЛКА 런타임에서 використання_значення |
| 1 | рядок_значення Запис |
| 2 / 3 | аргументи 개수 / аргументи рядок_значення Адреса |
| 10 | UDP Відкрити |
| 11 | UDP надсилати(маркер_значення, IP, місце_значення порт_значення, масив_значення Адреса, 길이) |
| 12 | UDP отримувати(маркер_значення, масив_значення Адреса, 제한 밀리초) |
| 13 | UDP Закрити |
| 14 | місцевий_масштаб IP Адреса |
| 15 / 16 | 마지막 точка_значення IP / UDP порт_значення |
| 20 | RAM файл Читання(Назва int[] Адреса, Вивід int[] Адреса) |
| 21 | RAM файл Запис(Назва int[] Адреса, 입력 int[] Адреса, байт_значення 길이) |
| 22 | UTF-16 код_значення урок_значення 문자 Вивід(0~65535) |

файл API는 `простір_користувача.파일읽기(int[] Назва, int[] дані)`와 `простір_користувача.записування_Файл(int[] Назва, int[] дані, int 길이)`다. 이름은 ASCII код_значення масив_значення(최대 64칸, 0 Вийти_програма 또는 масив_значення 끝), дані елемент_елемент 하나는 한 바이트다. 반환값은 읽거나 쓴 길이이며 файл 없음 `-2`, курсор ПОМИЛКА `-14`, Назва/길이 ПОМИЛКА `-22`, файл 슬롯 부족 `-28`, Розмір 초과 `-90`을 반환한다. 쓰기는 затвердити 후 файл 전체를 대체한다. `простір_користувача.записування_символ_значення(int)`는 문자를 단말에 출력한다. Java 프로그램의 일반 `java.io` 구현은 아니다.

`실행권한()`은 시스템 호출이 아니라 простір_користувача 모드에서 CS의 하위 비트를 직접 읽으므로 фактично_дані Виконати_команда 권한을 확인한다. ядро_значення обладнання_порт 접근용 `пристрій_значення` native 함수는 простір_користувача мета 컴파일에서 거부한다. ELF에 직접 특권 명령을 넣더라도 CPU가 차단한다.

## 범위와 제한

- 한 번에 한 프로그램만 실행하며 완료 후 셸로 돌아온다. 백그라운드 Виконати_команда, 파이프, 프로세스 간 통신은 없다. Виконати_команда 파일은 커널의 Читання 전용 JKAP 묶음에서 적재한다. дані 파일에는 주기억 파일체계와 전용 IDE 보존 형식이 있다.
- простір_користувача 가상 Адреса `0x04000000..0x043fffff`를 물리 8~12MiB에 연결한다. Виконати_команда 영상은 фронтальна_камера_значення 2MiB, 인수는 `0x04300000`부터, 스택은 область_значення_0e9a97ab 끝에서 시작한다. ядро_значення identity 페이지는 supervisor 전용이다.
- 실행마다 4MiB простір_користувача 영역을 비우고 файл 구역을 복사해 BSS·масив_значення 영역을 초기화한다. простір_користувача GC는 없지만 Вийти_програма 후 Далі_елемент Виконати_команда 때 영역을 재사용한다. 인수는 공백으로 분리한 최대 16개이며 Цитування/이스케이프 파싱은 없다.
- простір_користувача 페이지의 код_значення/дані 분리 Читання 전용 Налаштування, NX, операнд_Стіс guard, ASLR은 아직 없다. 커널과 простір_користувача Пам_ять_дані·обладнання_порт дозвіл_значення 경계를 구현한 초기판이지 보안 인증된 샌드박스는 아니다.
- PIT 100Hz로 약 3초 Виконати_команда 상한을 두며 час_значення 초과는 `Exit: 124`다. простір_користувача CPU 예외는 `128 + виняток індекс`(페이지 ПОМИЛКА 142, 특권 위반 141), Java масив_значення/계산 오류는 101~105다. ядро_значення 오류까지 복구하는 구조는 아니다.
- 네트워크는 PCI bus 0/function 0의 RTL8139, 정적 IPv4, ARP, UDP만 지원한다. NIC는 폴링하고 송신은 동기식이다. IPv4 단편 재조립·TCP·DNS·DHCP·IPv6·HTTP·TLS·일반 `java.net`은 미지원이다. IPv4 UDP контрольна_сума 0은 규약에 따라 허용하고, 그 외 UDP/IP 검사합과 길이는 검증한다.
- простір_користувача Виконати_команда·네트워크·захищати_значення 경계 전체 시험은 QEMU에서 수행했다. VirtualBox에서도 `make vbox`로 부팅과 `run hello vbox`의 ring 3 Виконати_команда·정상 종료를 확인했다. VirtualBox PCnet/E1000용 드라이버는 없어 그 환경의 네트워크는 지원하지 않는다.

## затвердити 근거

`make test`는 компілятор 14개 випробування, Java 패킷 умова 2,201개 검사, 기존 оболонка ELF/ISO запуск_машини випробування, простір_користувача ELF/фактично_дані UDP/захищати_значення 경계 시험을 실행한다. 네트워크 시험은 루프백 서버가 받은 자료의 길이·해시까지 `os/build/사용자통신시험.json`에 기록한다. 시험용 손상된 ELF·특권 команда·무한 спринт_значення 프로그램은 임시 묶음에만 넣으며 배포용 `apps` 목록에는 넣지 않는다.
