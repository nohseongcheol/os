# своє ARM64 커널의 Codex інсталювати_значення 가능성 검토

검토일: 2026-10-05. 소스와 공식 문서를 대조한 설계 검토이며, 게스트에 Codex를 설치하거나
로그인·모델 호출을 실행한 결과는 아니다. своє ARM64 커널과 `../rpi4` Linux 실행판은 구분한다.

чинний_елемент своє 커널에는 공식 Codex CLI를 그대로 інсталювати_значення·실행할 수 없다.
기술적으로 필요한 Виконати_команда 환경을 추가하거나 Codex를 이식하는 경로는 있으나,
다운로드 команда 하나를 추가하는 작업으로 해결되지 않는다. JDK/JRE 기능 확장만으로도 해결되지 않는다.

## 확인한 근거

| запис_значення_962f286b | чинний_елемент 소스에서 확인한 Стан_значення | 직접 실행을 위한 작업 |

| Виконати_команда дозвіл_значення | EL0 보호는 있으나 Codex의 Linux 샌드박스와 같은 정책 집행 середовище 없음 | файл·네트워크·команда дозвіл_значення 정책과 승인 기능; своє 커널에 맞는 격리 реалізація |

여기서 ELF의 PT_TLS는 스레드별 сховище_значення 공간이다. HTTPS의 TLS пароль_значення 통신과 서로 다른 기능이다.
ELF файл 형식을 읽을 수 있다는 사실만으로 Linux Виконати_команда 환경을 제공하는 것은 아니다.
SSH/VNC를 위한 пароль_значення 라이브러리를 넣은 상태도 HTTPS реалізація 완료를 의미하지 않는다.

호스트의 `/home/user/.local/bin/codex`도 확인했다. 이것은 x86-64 ELF ET_DYN이며 약 209 MiB다.
해당 파일을 ARM64 게스트로 복사하여 실행할 수 없다. 이 크기를 ARM64 배포 파일의 크기로
해석하지 않는다. 공식 ARM64 빌드의 фактично_дані Розмір·의존성은 설치할 버전으로 додавати_запис 검사해야 한다.

## 가능한 реалізація шлях

1. **своє 커널에 공식 CLI 직접 이식**
   영속 сховище_значення/VFS와 простір_користувача Пам_ять_дані, 프로세스·스레드·I/O, libc/런타임, DNS/HTTPS,
   термінал·дозвіл_значення 체계를 갖춘다. 이후 мета 버전의 의존성을 조사하여 크로스 збирання·이식한다.
   Linux 커널을 반드시 탑재할 필요는 없지만, 공식 Linux 바이너리를 그대로 쓸 경우
   그 바이너리가 사용하는 Linux ABI까지 호환해야 한다. 큰 операційна_система_ОС 개발 과제다.

2. **зовнішній_значення хост Codex와 своє ядро_значення З_єднання — 첫 구현으로 권장**
   Linux PC에서 공식 CLI 또는 app-server를 실행하고 jkoros에는 전용 простір_користувача команда/화면을 만든다.
   호스트의 인증된 연결과 게스트 файл Читання·수정·업로드·команда Виконати_команда 어댑터가 필요하다.
   기존 SSH/TCP 경로를 활용할 수 있으나, файл 동기화나 Codex 전용 어댑터는 чинний_елемент 구현되어 있지 않다.
   호스트에서 수행한 빌드와 게스트에서 수행한 Виконати_команда 결과를 명확히 구분한다.
   이 구성은 своє 커널을 유지하지만, 공식 CLI 자체는 зовнішній_значення 호스트에서 실행된다.

3. **своє API 클라이언트 제작**
   своє ABI의 C 또는 지원되는 Java 부분집합으로 대화 UI와 файл/команда інструменти 호출 루프를 만든다.
   зовнішній_значення 중계기를 쓰지 않는다면 DNS/затвердити 가능한 TLS/HTTPS와 인증 дані 저장을 먼저 구현해야 한다.
   이는 OpenAI API를 이용하는 별도 에이전트이며 공식 Codex CLI 전체의 이식으로 표시하지 않는다.

4. **별도 ARM64 Linux 실행판에서 інсталювати_значення**
   `../rpi4`는 Linux와 musl 기반이므로 일반 Linux інсталювати_значення 경로를 검토할 수 있다.
   사용할 Codex 버전의 ARM64·musl 호환성, 의존성, 커널의 샌드박스 지원을 фактично_дані 검증해야 한다.
   이번 검토에서 інсталювати_значення 성공을 확인하지 않았다. 이 결과를 своє Java 커널의 지원으로 표시하지 않는다.

## 단계별 완료 Дії_корінь

- 직접 이식: `--version` запустити → 인증/HTTPS → файл Читання·수정 → дитина_значення команда Виконати_команда →
  대화형 입력/스트리밍 → дозвіл_значення 제한·Скасувати_операція → 재부팅 후 Налаштування/세션 보존을 각각 фактично_дані 게스트에서 확인한다.
- хост З_єднання: 게스트에서 запит 입력 → хост Codex процес_значення_запис → 게스트 файл змінювати_значення перевіряти →
  게스트 javac/cc Виконати_команда → результат 표시를 처음부터 끝까지 검증한다.
- COSL 상업 조건을 유지하려면 새로 도입하는 런타임/통신 라이브러리의 라이선스와
  Codex 배포 버전의 제3자 고지를 검토한다. зовнішній_значення 구성요소를 일괄 COSL로 재라이선스하지 않는다.
