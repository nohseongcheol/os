# jkoros 안에서 Java компілювати_джерело·Виконати_команда

이 문서의 запуск_машини·оболонка·сховище_значення 명령은 **x86 версія_значення** 기준이다. 공유 Java компілятор/JVM은 [своє ARM64 Pi4 версія_значення](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 ім_я_файлу_Текст, `edit`의 단독 `.` сховище_значення, 16개 RAM файл, 약 2초 Виконати_команда 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 фактично_дані JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. хост компілювати_джерело 서버나 Linux 게스트는 사용하지 않는다.

**чинний_елемент 구현은 своє 제한형 компілятор·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java програма_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 Виконати_команда

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. Виконати_команда 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 запуск_машини 절차는 [VirtualBox Виконати_команда файл_Readme_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 файл 전체를 새 내용으로 작성한다. 기존 내용의 рядок_введення правка_значення 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 байт_значення 수 показувати_значення.
- `cat FILE`: файл Вміст_значення показувати_значення. 텍스트 소스에 사용한다.
- `rm FILE`: Пам_ять_дані файл 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·Тип_значення 검사 неполадка_значення 시 기존 `.class`는 유지된다. 소스를 고친 НАЗАД_значення 컴파일이 실패했다면 이전 Виконати_команда 파일이 남아 있으므로 компілювати_джерело 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 сховище_значення 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 джерело_дерево·Клас_значення·дані 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, файл 이름은 ASCII 1~63자다. джерело_дерево 이름은 `.class` 확장자 адреса_область 때문에 최대 62자다. правка_значення 입력은 ASCII이고 한 рядок_введення 최대 128자다. рядок_введення 또는 файл 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. ядро_значення/компілятор/JVM 구현의 Java 식별자는 한국어이며, чинний_елемент 게스트 입력 제한 때문에 простір_користувача 예제 이름은 ASCII로 작성한다.

## зовнішній_значення файл 적재

호스트에서 만든 소스나 опора_значення кліп 안의 `.class`를 запуск_машини 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 фактично_дані 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# хост JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 запуск_машини 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 Далі_елемент 빌드에서는 додавати_запис 파일을 포함하지 않는다. файл Вміст_значення 변경과 запис_список 제거도 Далі_елемент 빌드에 반영된다. 원본 хост 파일에는 쓰지 않는다. стандартне_значення `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 стандартне_значення 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 Клас_значення файл 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 опора_значення кліп 안에 있어야 한다.

## опора_значення кліп

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| Клас_значення | 패키지 없는 단일 Клас_значення, 정적 функція_значення, 재귀, аргументи/повернути_КР | 실행마다 단일 Клас_значення 적재, public static main(String[]) |
| стандартне_значення значення | int, boolean, char, String, main의 String[] аргументи | ціле_число·довідка операнд_Стіс, String, int[], String[], 내부 StringBuilder |
| оператор_значення | 초기값 있는 місцевий_масштаб оголошення_4f4f026b, завдання_значення, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 ціле_число·довідка 바이트코드와 умова гілка |
| вираз_значення | 십진 ціле_число, UTF-8 소스의 рядок_значення/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, рядок_значення 결합 | ціле_число операція_значення·біт_значення операція_значення·Тип_значення перетворити_значення, 단락 평가, масив_значення доступ_запис |
| файл | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | фактично_дані ядро_значення 파일서술자와 З_єднання, генерувати·очищати_Зміст·이어쓰기·EOF |
| Вивід | System.out.print/println: int/boolean/char/String, println() | 동일 |
| рядок_значення/аргументи | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), рядок_значення 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 місцевий_масштаб оголошення_4f4f026b, 오버로드, 임의 Тип_значення перетворити_значення, масив_значення генерувати вихіднийКод, 8/16진 리터럴, Unicode джерело_дерево 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 константа_значення 축소 변환을 구현하지 않는다. зовнішній_значення `.class`의 `int[]` генерувати/Читання/쓰기는 지원하므로 хост `javac --release 8`로 만든 масив_значення 예제는 실행할 수 있다.

об_єкт_значення значення_поля·일반 об_єкт_значення генерувати·상속·인터페이스·여러 Клас_значення З_єднання, long/float/double, виняток процес_значення_запис, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java виняток 객체를 던지지 않고 진단 후 чинний_елемент 프로그램을 종료한다. 객체와 рядок_значення сховище_значення 공간은 Виконати_команда Вийти_програма 시 простір_користувача область_значення_0e9a97ab 전체와 함께 회수한다. 지속 Виконати_команда 중 GC는 없다.

## Виконати_команда 한도와 ПОМИЛКА

| ресурс_значення | 한도 |
| --- | --- |
| джерело_дерево/Клас_значення файл | 각각 16KiB |
| компілятор | токен_значення 2,047개, генерувати код_значення 4KiB, константа_значення 풀 4KiB |
| функція_значення/аргументи | 클래스당 32함수, 함수당 16인수 |
| JVM константа_значення | 511개 |
| JVM функція_значення код_значення | 함수당 8KiB |
| JVM 호출/операнд_Стіс/місцевий_масштаб змінна_значення | 32프레임, 프레임당 операнд_Стіс 128칸·місцевий_масштаб 128칸 |
| JVM об_єкт_значення сховище_значення адреса_область | 8,192개 32비트 칸, 헤더 оголошення 약 32KiB |
| Виконати_команда | 최대 500,000 команда, 기존 커널의 약 3초 CPU Виконати_команда 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 опора_значення 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM словник 검증기를 구현한 것은 아니다. файл/атрибут_значення 길이, константа_значення довідка, команда·гілка 경계를 검사하고, Виконати_команда 중 операнд_Стіс формат_значення·місцевий_масштаб ініціалізувати·масив_значення підрядковий_символ_значення·об_єкт_значення 참조를 검사한다. простір_користувача 코드의 페이지·обладнання_порт 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, компілювати_джерело·JVM 오류는 `Exit: 1`, команда аргументи 오류는 `Exit: 2`다. CPU час_значення 상한은 기존 `Exit: 124`이며, простір_користувача ELF 자체의 CPU/런타임 오류는 기존 Вийти_програма 코드를 따른다. неполадка_значення 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## реалізація 위치와 випробування

- `os/простір_користувача/자바/자바컴파일러.java`: 게스트 어휘·구문·Тип_значення 검사, константа_значення 풀 및 바이트코드 генерувати.
- `os/простір_користувача/자바/자바가상기계.java`: Клас_значення 적재, операнд_Стіс·프레임·об_єкт_значення сховище_значення, команда 해석과 제한된 표준 호출.
- `os/вихіднийКод/Пам_ять_файлова_система.java`: Пам_ять_дані файлова_система, правка_значення, запуск_машини файл 적재.
- `os/вихіднийКод/системний_виклик.java`, `compiler/ПУСК_користувач_програма.s`: файл/문자 Вивід API와 простір_користувача курсор 검사.
- `os/інструменти/자바파일묶기.py`: хост 입력 файл затвердити·запуск_машини Група_значення генерувати.

```sh
make test-java
make test
```

`os/випробування/자바시험.py`는 ELF/ISO запуск_машини, 게스트 компілювати_джерело·Виконати_команда, простір_користувача 입력, 재귀·반복문·ціле_число 극값·рядок_значення 결합·단락 평가, 재실행, джерело_дерево ПОМИЛКА 후 기존 Клас_значення 보존, масив_значення/수 해독 ПОМИЛКА, 무한 спринт_значення 제한, правка_значення 넘침과 файл 부족을 검사한다. 게스트 генерувати 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 хост OpenJDK의 Клас_значення, ціле_число 배열과 한글 상수를 게스트에 적재하며, 손상된 файл маркер_значення_7e8f90bd·버전·константа_значення 수·гілка·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 випробування VM만 생성하고 종료한다.

реалізація 형식의 참고 дані: Oracle [JVM Клас_значення файл 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM команда 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java файл ввід_вивід

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 Клас_значення 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 запуск_машини 이미지에 넣은 НАЗАД_значення `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. стандартне_значення Вивід 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. виняток об_єкт_значення·try/catch·try-with-resources는 지원하지 않으며 файл 오류를 진단하고 프로그램을 종료한다. масив_значення ввід_вивід, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 файл 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 оболонка `sync`가 필요하다. 예제의 файл 이름은 чинний_елемент 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/випробування/자바파일시험.py`는 фактично_дані 게스트 компілювати_джерело 결과를 OpenJDK `-Xverify:all`로 пробувати_знову_значення 실행해 файл 바이트와 출력을 대조한다. 범위와 сховище_значення носії_значення 사용법은 [posix-kor файл_Readme_eb81d7d9](../posix-kor/файл_Readme_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
