# 자체 ARM64 kernel_ᏧᎬᏩᎶᏗᏯ: FTP, C, JAR와 AOT ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ

대상은 **Linux를 적재하지 않는 Raspberry Pi 4용 Java AOT kernel_ᏧᎬᏩᎶᏗᏯ**이다. CPU·ᎠᏂᎩᏍᎩ_ᏧᎬᏩᎶᏗᏯ 경계는 C/어셈블리, ᎠᏍᏆᏂᎪᏙᏗ 체계와 셸은 Java이며, 이번 TCP/IP 스택은 C로 작성된 lwIP 2.2.0을 이식했다. 게스트 TinyCC와 `jaot`도 EL0에서 실행한다. 호스트에 컴파일을 요청하거나 ᎠᏁᏢᏍᎩ JVM으로 대신 실행하지 않는다.

## 먼저 알아둘 ᎦᎫᏍᏛᏗ_ᏧᎬᏩᎶᏗᏯ 경계

| 요청 | 이번 구현 | 남은 ᎠᎬᎭᎸᏓ_ᏗᏓᏴᎳᏛᏙᏗ |
|---|---|---|
| JAR를 ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ 파일처럼 ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ | `java -jar ᎠᏍᏆᏂᎪᏙᏗ.jar`, `./ᎠᏍᏆᏂᎪᏙᏗ.jar 인수`; Main-Class와 Store_ᏧᎬᏩᎶᏗᏯ/DEFLATE ZIP, CRC 검사 | 전체 Java SE, 임의의 모든 JAR 호환성 |
| 게스트 AOT | `jaot ᎠᏍᏆᏂᎪᏙᏗ.class -o ᎠᏍᏆᏂᎪᏙᏗ.elf`, `jaot ᎠᏍᏆᏂᎪᏙᏗ.jar -o ᎠᏍᏆᏂᎪᏙᏗ.elf`; ᎤᏙᎯᏳ_ᎾᏍᎩ_ᎨᏒ_ᎦᏟᏌᏅᎯ ARM64 기계어 생성 | ᎪᎱᏍᏗ_ᏧᎬᏩᎶᏗᏯ·예외·Thread·Swing·Socket의 AOT 변환, 여러 애플리케이션 ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ ᎫᏓᎳ |
| C ᎪᏢᏍᎩ_ᎦᏟᏌᏅᎯ | 게스트 `cc`/`tcc`, TinyCC C 전처리기·ARM64 생성기·링커; 한국어 식별자와 posix-kor | 전체 libc, 일반 Linux ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ ᎠᏍᏆᏂᎪᏙᏗ, 게스트 C++ 컴파일러 |
| 업로드한 ELF ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ | ELF64/AArch64 헤더 검사, 확장자 없는 `./ᎠᏍᏆᏂᎪᏙᏗ`; 자체 ABI 및 명시적인 제한형 Linux ABI | 일반 Linux 바이너리 호환, 동적 링커, 공유 ᏧᏂᎪᎵᏰᏗᎢ |
| 외부 TCP/UDP | 게스트 lwIP IPv4 스택, POSIX 소켓과 JVM의 숫자 IPv4 ᎪᏪᎵ_ᏫᏗᎦᏅᏗ | GENET/Wi-Fi 드라이버, DHCP·DNS·TLS, 실물 보드 네트워크 시험 |
| FTP | 게스트 서비스, 패시브 ᎠᎲᏍᏗ_ᏧᎬᏩᎶᏗᏯ, UTF-8 ᏚᏙᎥᎢ, STOR/RETR/SIZE/LIST/NLST/MLSD/DELE | TLS·사용자별 권한·하위 디렉터리·영속 Store_ᏧᎬᏩᎶᏗᏯ |
| 한글 Java | 기존 `한국어.자체` 클래스와 외부 ᎪᏪᎵ_ᏫᏗᎦᏅᏗ UDP 오버로드 | 전체 JDK의 일대일 한국어 대응 API |

JVM은 ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ 버전 45…52의 문서화한 부분집합이다. `java`는 바이트코드 실행기이고, `jaot`가 별도의 네이티브 ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ 파일을 만든다. **JAR ᎠᏍᏆᏂᎪᏛᎢ_ᏧᎬᏩᎶᏗᏯ 해제나 JVM을 함께 묶는 것을 AOT라고 표시하지 않는다.** 지원하지 않는 바이트코드/API는 `jaot`가 진단하고 출력을 만들지 않는다. 기존 출력 ELF도 ᎪᏢᏍᎩ_ᎦᏟᏌᏅᎯ ᎤᏄᎸᎲᎦ_ᏧᎬᏩᎶᏗᏯ 때 보존한다.

Android의 Dalvik/ART는 일반 JVM ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ/JAR가 아닌 **DEX**를 실행한다. ART의 AOT에는 GC, ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ 로딩, JNI 등 ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ 기반도 필요하다. 따라서 ART처럼 기계어로 바꾸는 기능만으로 임의의 OpenJDK JAR 및 Swing이 자동 호환되지는 않는다. [Android 공식 런타임 설명](https://source.android.com/docs/core/runtime)

```text

```

FTP는 루트 RAM 파일만 공개한다. 익명 로그인이며 비밀번호로 권한을 구분하지 않는다. ᎠᏓᏁᏟᏴᏍᏗᏍᎩ_ᏧᎬᏩᎶᏗᏯ ᎠᏁᏢᏍᎩ 바인딩은 `127.0.0.1`이고, ᎠᎯᎸᏍᏗ_ᏧᎬᏩᎶᏗᏯ 포트는 2121, 데이터 포트는 50000…50007이다. `--ftp-port 2122`로 ᎠᎯᎸᏍᏗ_ᏧᎬᏩᎶᏗᏯ 포트를 바꿀 수 있다. 동시에 한 FTP 세션을 제공하며 명령이 없는 세션은 60초 후 닫는다. TYPE A도 바이트를 변경하지 않으므로 프로그램은 바이너리 전송한다.

파일은 **64개, 각각 16 KiB**, 경로는 UTF-8 63바이트이다. 부팅 시 준비되는 `/example`도 이 한도를 공유한다. 초과/끊어진 STOR는 기존 파일에 반영하지 않는다. FTP 업로드는 RAM에만 저장되며 재부팅하면 사라진다. 이 제한 때문에 일반적인 대형 JAR 배포판을 그대로 올릴 수 없다.

QEMU의 raspi4b에는 GENET Ethernet 장치가 없다. 따라서 `network_bridge.py`가 QEMU NAT의 Ethernet과 보조 UART의 SLIP를 변환한다. **TCP ᎫᏓᎳ ᎢᏯᏛᏁᎵᏓᏍᏗ_ᏧᎬᏩᎶᏗᏯ_Ꭵ_ᎧᏁᏉᎢᏍᏙᏗ·체크섬·재전송·FTP 명령과 ᎠᏍᏆᏂᎪᏙᏗ 저장은 게스트 안에서 수행한다.** ᎠᏁᏢᏍᎩ 브리지는 FTP 서버가 아니다. [QEMU 공식 ᎠᏂᎩᏍᎩ_ᏧᎬᏩᎶᏗᏯ ᎦᎫᏍᏛᏗ_ᏧᎬᏩᎶᏗᏯ Ꭵ_ᎧᏁᏉᎢᏍᏙᏗ_ᏕᎦᏅᏅᏛ](https://www.qemu.org/docs/master/system/arm/raspi.html)

이 경로는 QEMU에서 검증했다. 보조 UART의 ᎤᏙᎯᏳ_ᎾᏍᎩ_ᎨᏒ_ᎦᏟᏌᏅᎯ Pi 4 핀/클럭 설정과 내장 RJ45 GENET 드라이버는 구현·검증하지 않았으므로, SD 이미지에 커널이 포함되어 있다는 사실을 ᎤᏙᎯᏳ_ᎾᏍᎩ_ᎨᏒ_ᎦᏟᏌᏅᎯ 보드의 LAN/FTP ᎠᏛᏁᎵᏓ 보장으로 해석하면 안 된다.

## 한국어 Java를 게스트에서 컴파일하고 AOT ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ

게스트 `vi 빛.java`로 다음 소스를 작성한다.

```java
public class 빛 {
    public static void main(String[] 인수) throws Exception {
        int 합 = 0;
        int 수 = 1;
        while (수 <= 10) {
            합 = 합 + 수;
            수 = 수 + 1;
        }
        한국어.자체.출력.수쓰기(합);
        한국어.자체.ᎠᏍᏆᏂᎪᏙᏗ.ᎪᏪᎶᏗ("aot.txt", "한글 AOT ᎠᏍᏆᏂᎪᏙᏗ 😀");
        한국어.자체.출력.ᎪᏪᎶᏗ_ᏚᏓᏅᏅᎢ(한국어.자체.ᎠᏍᏆᏂᎪᏙᏗ.읽기("aot.txt"));
    }
}
```

```text
javac 빛.java
java 빛
jaot 빛.class -o 빛.elf
run 빛.elf
```

`jaot`은 클래스의 바이트코드를 C로 변환하고, **게스트 TinyCC**가 ARM64 명령어를 생성·연결한다. ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ 때 JVM 인터프리터를 호출하지 않는다. JAR의 Main-Class가 같은 ᎦᎫᏍᏛᏗ_ᏧᎬᏩᎶᏗᏯ 범위이면 다음도 가능하다.

```text
jaot 빛.jar -o 빛.elf
run 빛.elf
```

AOT 지원은 한 애플리케이션 클래스의 ᎾᏓᏅᏍᎬᎾ_ᏧᎬᏩᎶᏗᏯ method_ᏧᎬᏩᎶᏗᏯ/ᏠᎨᏏ_ᏧᎬᏩᎶᏗᏯ, int 계열, integer 배열과 참조, 인수 array_ᏧᎬᏩᎶᏗᏯ, ᎤᏍᏗᏓᏅ·분기·반복, ᎠᏍᏘ_ᏧᎬᏩᎶᏗᏯ 리터럴, `System.out.print/println`의 int/String, 한국어 출력·ᎠᏍᏆᏂᎪᏙᏗ 읽기/쓰기로 제한된다. ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ/method_ᏧᎬᏩᎶᏗᏯ 수와 스택 등에도 고정 상한이 있다. Java 예외 ᎢᏯᏛᏁᎵᏓᏍᏗ_ᏧᎬᏩᎶᏗᏯ_Ꭵ_ᎧᏁᏉᎢᏍᏙᏗ, ᎪᎱᏍᏗ_ᏧᎬᏩᎶᏗᏯ 생성, 가상 method_ᏧᎬᏩᎶᏗᏯ 일반, switch/wide, long/float/double, invokedynamic, ᎠᏍᏘ_ᏧᎬᏩᎶᏗᏯ 결합용 StringBuilder, 일반 JDK·Socket·Thread·Swing은 이 AOT 백엔드에서 미지원이다. 내장 NUL/고립된 서로게이트 문자열도 거부한다. 잘못된 array_ᏧᎬᏩᎶᏗᏯ ᎬᏴᏍᏗ_Ꭵ_ᎧᏁᏉᎢᏍᏙᏗ/0으로 나누기 등은 네이티브 런타임 오류로 종료하며 Java 예외 객체로 전달하지 않는다.

입력 클래스뿐 아니라 **생성된 ELF도 16 KiB 이하**여야 한다. 기계어 확장과 ELF 페이지 ᏗᏅᏅᏓᎦᏥᏃᏍᏓ_ᏗᎦᏅᏅᏙᏗ_ᏧᎬᏩᎶᏗᏯ 때문에 짧은 클래스도 이 한도를 넘을 수 있으며, 이 경우 오류를 내고 기존 출력을 보존한다.

게스트 `javac`도 부분집합이다. 일반적인 ᎪᎱᏍᏗ_ᏧᎬᏩᎶᏗᏯ·Thread·Swing 소스는 호스트에서 `javac --release 8`로 컴파일하고, **기존 JVM의 ᎦᎫᏍᏛᏗ_ᏧᎬᏩᎶᏗᏯ ᎠᎬᎭᎸᏓ_ᏗᏓᏴᎳᏛᏙᏗ 안에서** `java`/`java -jar`로 실행한다. 정확한 API는 [JVM 매뉴얼](자바실행환경.md)과 [한글 개발 매뉴얼](개발안내.md)을 참고한다.

JAR는 하나의 애플리케이션 ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ 경로다. 내부 ᏚᏙᎥᎢ `ᎦᏇᏅᎯ/ᎬᏙᏗ_f5044b9b.class`와 점으로 구분한 Main-Class를 지원한다. 내부 클래스는 파일로 풀어 VFS 슬롯을 소비하지 않는다. 내장 한국어 클래스를 추가로 찾지만 현재 작업 폴더의 다른 클래스는 자동 혼합하지 않는다. ZIP64·ᎠᏕᎵᏍᏔᏅᎯ_ᎦᏟᏌᏅᎯ ZIP·manifest Class-Path·서명 검증은 지원하지 않는다. JAR 하나가 16 KiB 이하이어도 클래스당/적재 수/VM 힙 제한은 그대로 적용된다.

## C에서 한국어 POSIX 호출

게스트에서 `vi 인사.c`로 작성하거나 FTP로 소스를 업로드한다.

```c
#include <파일규약.h>

int main(void) {
    const char 인사말[] = "자체 ARM64 C에서 한글 POSIX 호출\n";
    int 문서 = ᎯᏍᏚᎢ_ᎠᏍᏆᏂᎪᏙᏗ("인사.txt", ᎠᎪᎵᏰᏗᏊ_ᎪᏪᎶᏗ | 없으면만들기 | 내용비우기, 0600);
    if (문서 < 0) return 1;
    입출력결과형 기록한수 = ᎪᏪᎶᏗ_ᎠᏍᏆᏂᎪᏙᏗ_ᎦᏟᏌᏅᎯ(문서, 인사말, sizeof(인사말) - 1);
    ᎯᏍᏚᎲᎦ_ᎠᏍᏆᏂᎪᏙᏗ(문서);
    ᎪᏪᎶᏗ_ᎠᏍᏆᏂᎪᏙᏗ_ᎦᏟᏌᏅᎯ(1, 인사말, sizeof(인사말) - 1);
    return 기록한수 == sizeof(인사말) - 1 ? 0 : 2;
}
```

```text
cc 인사.c -o 인사.elf
run 인사.elf
cat 인사.txt
```

TinyCC의 표준 C Ꭵ_ᎧᏁᏉᎢᏍᏙᏗ_ᎤᏓᏓᏟ `main`을 사용한다. 기존 ᎠᏁᏢᏍᎩ C/C++ SDK의 `ᎭᏂᎩᏍᏓ_ᎬᏗᏍᎩ_ᎬᏙᏗ(int)` 진입점과 구분한다. 포함 ᎠᏍᏆᏂᎪᏙᏗ·ᎠᎢᏎᏍᏗ ᎪᎱᏍᏗ_ᏧᎬᏩᎶᏗᏯ·`libposix-kor-user.a`는 컴파일러 내부의 읽기 전용 SDK에 들어 있다. C 전처리기/구조체/ᏧᎸᏫᏍᏓᏁᏗᏱ_ᏧᎬᏩᎶᏗᏯ/재귀/ᎠᏎᎯᎯ/부동소수점 생성 등을 사용하되 **일반 libc/libstdc++를 제공한다는 뜻은 아니다**. 제공하지 않는 함수는 ᎫᏓᎳ 오류가 난다. 컴파일러 자체의 문자/숫자 변환 지원도 완전한 libc 대체품이 아니다.

`ᎯᏍᏚᎢ_ᎠᏍᏆᏂᎪᏙᏗ` 등은 별도의 모의 호출이 아닌 기존 `pk_open` 등의 한국어 매크로이며, ELF의 SVC를 통해 ᎤᏙᎯᏳ_ᎾᏍᎩ_ᎨᏒ_ᎦᏟᏌᏅᎯ Java ᎠᏍᏆᏂᎪᏙᏗ 체계에 도달한다. ᎠᏍᏆᏂᎪᏙᏗ/소켓 호출 목록은 [ᎬᏗᏍᎩ ABI](사용자호출규약.md)에 있다. C/C++ ᎠᏁᏢᏍᎩ SDK ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ 파일도 FTP로 업로드 후 `run` 또는 `./ᎠᏍᏆᏂᎪᏙᏗ`로 실행하며 확장자는 필요 없다. Linux ARM64 ᎾᏓᏅᏍᎬᎾ_ᏧᎬᏩᎶᏗᏯ ELF에는 별도의 제한된 호환 ᎠᏍᏓᏩᏛᏍᏗ `run --linux ᎠᏍᏆᏂᎪᏙᏗ`을 추가했다. [ELF·Linux ABI 매뉴얼](실행파일규약.md)에 정확한 ᏱᎬᏁᎸᎯ_ᏧᎬᏩᎶᏗᏯ·시스템 호출·ᎪᏪᎵ_ᏫᏗᎦᏅᏗ 제한을 정리했다.

## 한국어 네트워크·작업·화면 API

| ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ | 호출 예 | ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ ᎠᏍᏓᏩᏛᏍᏗ |
|---|---|---|
| `출력` | `ᎪᏪᎶᏗ_ᏚᏓᏅᏅᎢ("안녕")`, `수쓰기(42)` | JVM 및 제한형 AOT |
| `ᎠᏍᏆᏂᎪᏙᏗ` | `ᎪᏪᎶᏗ("문서.txt", "ᎦᎸᏛᎢ_ᏧᎬᏩᎶᏗᏯ")`, `읽기("문서.txt")` | JVM 및 제한형 AOT |
| `통신` | `ᎯᏍᏚᎢ(0)`, `ᏫᎦᏅᏗ(종단, "10.0.2.2", 9000, "한글")`, `받기(종단)` | JVM의 UDP |
| `연결통신` | `ᎫᏓᎳ("10.0.2.2", 9000)`, `듣기(9000)`, `받기(ᏗᏯᏙᎯᎯ_ᏧᎬᏩᎶᏗᏯ)` | JVM의 Socket/ServerSocket |
| `작업` | `ᎠᎢᏎᏍᏗ(Runnable)`, `기다리기(Thread)`, `ᏗᏲᎯᏍᏗᎢ_ᏯᏛᏁᏗ()` | JVM의 협력식 ᎪᏪᎵ_ᏕᎦᏅᏃᏛᎢ_ᏧᎬᏩᎶᏗᏯ |
| `ᏦᎳᏂ`, `화면요소` | ᏦᎳᏂ·버튼·ᎪᏪᎸ_ᏧᎬᏩᎶᏗᏯ·ᎠᎪᎵᏰᏗ_ᏠᎨᏏ·ᎢᏳᎵᏍᏔᏂᏓᏍᏗᎢ ᎫᏓᎳ | JVM의 Swing 부분집합 |

명명에서는 표준 영어 API를 보존하고 한국어 호출 계층을 추가한다. `통신(通信)`, `ᎫᏓᎳ(連結)`, `출력(出力)`은 기존 단어의 뜻을 사용한다. `작업 ᎪᏪᎵ_ᏕᎦᏅᏃᏛᎢ_ᏧᎬᏩᎶᏗᏯ`은 한 ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ 흐름을 가닥에 빗댄 기술 표현, `ᎫᏓᎸᏗ_ᏧᎬᏩᎶᏗᏯ`는 포트의 접점을 설명하는 표현이다. 새 기술 결합어를 고대에 이미 존재한 용어처럼 설명하지 않는다. 전체 JDK의 번역을 완료했다고 표시하지 않는다.

외부 주소는 숫자 IPv4이며 QEMU 호스트는 `10.0.2.2`, 게스트는 `10.0.2.15`다. UDP 전문은 512바이트까지다. 소켓은 비차단 자체 ABI이며 JVM이 제한된 대기/재시도를 제공한다. TCP connect 대기는 최대 1초, ᎬᏗᏍᎩ ᎬᏙᏗ_f5044b9b 전체에는 기존 약 2초 CPU 기한이 적용된다. 일반적인 장기 ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ ᎬᏗᏍᎩ 서버와 pthread는 아직 없다. FTP는 ᎬᏗᏍᎩ ᎬᏙᏗ_f5044b9b 기한과 별개인 kernel_ᏧᎬᏩᎶᏗᏯ 서비스다.

게스트의 ᎬᏗᏍᎩ TCP/UDP 서버로 들어오는 연결은 NAT 포트를 추가한다. 예를 들어 `python3 도구/ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ.py --network --forward tcp:9300:9300 --forward udp:9301:9301`로 실행하면 호스트의 localhost 9300/TCP·9301/UDP를 게스트의 같은 포트로 전달한다. FTP의 ᎠᏓᏁᏟᏴᏍᏗᏍᎩ_ᏧᎬᏩᎶᏗᏯ ᎠᎯᎸᏍᏗ_ᏧᎬᏩᎶᏗᏯ/데이터 포트와 겹치면 ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ 전에 거부한다.

## 시험과 ᎪᏢᏍᎩ_ᏄᏍᏗᏓᏅᎢ 재현

```sh
cd /home/user/jkoros/platforms/rpi4-native
make test-ftp
make test
make image
```

`build/verification/ftp/report.json`은 ᎤᏙᎯᏳ_ᎾᏍᎩ_ᎨᏒ_ᎦᏟᏌᏅᎯ FTP ᎠᎲᏍᏗ_ᏧᎬᏩᎶᏗᏯ, 한글 ᎠᏍᏆᏂᎪᏙᏗ, ᎢᎩᏓ 초과 보존, ᎠᏍᏆᏂᎪᏛᎢ_ᏧᎬᏩᎶᏗᏯ JAR ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ, 게스트 C ᎪᏢᏍᎩ_ᎦᏟᏌᏅᎯ/ELF 재업로드, 외부 Java TCP/UDP, 게스트 javac/AOT 실행을 기록한다. `serial.log`에서 게스트 명령과 결과를 확인할 수 있다. 보고서의 kernel_ᏧᎬᏩᎶᏗᏯ SHA-256과 배포 이미지의 커널을 비교한다.

빌드는 기존 JDK/Clang/AArch64 binutils와 함께 `../rpi4/build/rootfs`의 ARM64 SDK 선언 헤더와 libgcc 산술 보조 함수를 사용한다(`make rpi-prepare`). **musl libc, Linux kernel_ᏧᎬᏩᎶᏗᏯ, 동적 로더를 게스트에 링크하지 않는다.** TinyCC/lwIP/uzlib 원본과 라이선스·버전 정보는 `vendor/`, 이식 코드는 `ccompiler/`, `network/`, `ᎬᏗᏍᎩ/ᎦᏇᏅᎯ.c`에 있다.

전체 JDK/AOT JVM으로 확장하려면 타입 ᎪᎯᏳᏙᏗ·ᎪᎱᏍᏗ_ᏧᎬᏩᎶᏗᏯ/예외/GC·동적 로딩·JNI, 영속 ᎠᏍᏆᏂᎪᏙᏗ ᎢᏯᏛᏁᏗ_ᏄᏍᏗᏓᏅᎢ_ᏧᎬᏩᎶᏗᏯ·mmap/TLS/시그널·스레드 ABI, OpenJDK native ᏧᏂᎪᎵᏰᏗᎢ, GUI peer/폰트/입력기, GENET 및 실물 ᎠᏂᎩᏍᎩ_ᏧᎬᏩᎶᏗᏯ 검증이 더 필요하다. 이 문서의 ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ 시험은 그 전체 이식을 대신하지 않는다.
