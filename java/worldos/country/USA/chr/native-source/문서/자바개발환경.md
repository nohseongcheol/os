# jkoros 안에서 Java ᎪᏢᏍᎩ_ᎦᏟᏌᏅᎯ·ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ

이 문서의 부팅·ᎤᏯᏍᎦ·Store_ᏧᎬᏩᎶᏗᏯ 명령은 **x86 ᏄᏓᎴᏒᎢ_ᏧᎬᏩᎶᏗᏯ** 기준이다. 공유 Java 컴파일러/JVM은 [자체 ARM64 Pi4 ᏄᏓᎴᏒᎢ_ᏧᎬᏩᎶᏗᏯ](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 ᎠᏍᏆᏂᎪᏙᏗ_ᏚᏙᎥᎢ_ᎠᎪᎵᏰᏗ, `edit`의 단독 `.` Store_ᏧᎬᏩᎶᏗᏯ, 16개 RAM ᎠᏍᏆᏂᎪᏙᏗ, 약 2초 ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 ᎤᏙᎯᏳ_ᎾᏍᎩ_ᎨᏒ_ᎦᏟᏌᏅᎯ JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. ᎠᏁᏢᏍᎩ ᎪᏢᏍᎩ_ᎦᏟᏌᏅᎯ 서버나 Linux 게스트는 사용하지 않는다.

**현재 구현은 자체 제한형 컴파일러·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java ᎬᏙᏗ_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ ᏍᎩᎪᎵᏯ_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 ᎠᏍᏆᏂᎪᏙᏗ 전체를 새 내용으로 작성한다. 기존 내용의 ᏚᏓᏅᏅᎢ ᎦᏁᏟᏴᏓ_ᎪᏪᎸ_ᏧᎬᏩᎶᏗᏯ 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 byte_ᏧᎬᏩᎶᏗᏯ 수 ᏍᎩᎪᏩᏛᏓ_ᏧᎬᏩᎶᏗᏯ.
- `cat FILE`: ᎠᏍᏆᏂᎪᏙᏗ ᎦᎸᏛᎢ_ᏧᎬᏩᎶᏗᏯ ᏍᎩᎪᏩᏛᏓ_ᏧᎬᏩᎶᏗᏯ. 텍스트 소스에 사용한다.
- `rm FILE`: ᎠᏅᏓᏗᏍᏙ_ᎦᏟᏌᏅᎯ ᎠᏍᏆᏂᎪᏙᏗ 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·형 검사 ᎤᏄᎸᎲᎦ_ᏧᎬᏩᎶᏗᏯ 시 기존 `.class`는 유지된다. 소스를 고친 ᎠᎰᏂ_ᏧᎬᏩᎶᏗᏯ 컴파일이 실패했다면 이전 ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ 파일이 남아 있으므로 ᎪᏢᏍᎩ_ᎦᏟᏌᏅᎯ 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 Store_ᏧᎬᏩᎶᏗᏯ 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 ᎦᏟᏌᏅᎯ_ᏡᎬ·ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ·ᎦᏟᏌᏅᎯ 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, ᎠᏍᏆᏂᎪᏙᏗ 이름은 ASCII 1~63자다. ᎦᏟᏌᏅᎯ_ᏡᎬ 이름은 `.class` 확장자 공간 때문에 최대 62자다. ᎦᏁᏟᏴᏓ_ᎪᏪᎸ_ᏧᎬᏩᎶᏗᏯ 입력은 ASCII이고 한 ᏚᏓᏅᏅᎢ 최대 128자다. ᏚᏓᏅᏅᎢ 또는 ᎠᏍᏆᏂᎪᏙᏗ 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. kernel_ᏧᎬᏩᎶᏗᏯ/컴파일러/JVM 구현의 Java 식별자는 한국어이며, 현재 게스트 입력 제한 때문에 ᎬᏗᏍᎩ 예제 이름은 ASCII로 작성한다.

## 외부 ᎠᏍᏆᏂᎪᏙᏗ 적재

호스트에서 만든 소스나 ᎦᎫᏍᏛᏗ_ᏧᎬᏩᎶᏗᏯ ᎠᎬᎭᎸᏓ_ᏗᏓᏴᎳᏛᏙᏗ 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 ᎤᏙᎯᏳ_ᎾᏍᎩ_ᎨᏒ_ᎦᏟᏌᏅᎯ 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# ᎠᏁᏢᏍᎩ JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 다음 빌드에서는 추가 파일을 포함하지 않는다. ᎠᏍᏆᏂᎪᏙᏗ ᎦᎸᏛᎢ_ᏧᎬᏩᎶᏗᏯ 변경과 Ꭵ_ᎧᏁᏉᎢᏍᏙᏗ_ᏕᎦᏅᏅᏛ 제거도 다음 빌드에 반영된다. 원본 ᎠᏁᏢᏍᎩ 파일에는 쓰지 않는다. ᎠᏓᏁᏟᏴᏍᏗᏍᎩ_ᏧᎬᏩᎶᏗᏯ `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 ᎠᏓᏁᏟᏴᏍᏗᏍᎩ_ᏧᎬᏩᎶᏗᏯ 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ ᎠᏍᏆᏂᎪᏙᏗ 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 ᎦᎫᏍᏛᏗ_ᏧᎬᏩᎶᏗᏯ ᎠᎬᎭᎸᏓ_ᏗᏓᏴᎳᏛᏙᏗ 안에 있어야 한다.

## ᎦᎫᏍᏛᏗ_ᏧᎬᏩᎶᏗᏯ ᎠᎬᎭᎸᏓ_ᏗᏓᏴᎳᏛᏙᏗ

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ | 패키지 없는 단일 ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ, ᎾᏓᏅᏍᎬᎾ_ᏧᎬᏩᎶᏗᏯ ᏧᎸᏫᏍᏓᏁᏗᏱ_ᏧᎬᏩᎶᏗᏯ, 재귀, 인수/반환 | 실행마다 단일 ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ 적재, public static main(String[]) |
| ᎠᏓᏁᏟᏴᏍᏗᏍᎩ_ᏧᎬᏩᎶᏗᏯ ᏧᎬᏩᎶᏗᏯ | int, boolean, char, String, main의 String[] 인수 | integer·참조 스택, String, int[], String[], 내부 StringBuilder |
| ᎧᏁᏨᎯ_ᏧᎬᏩᎶᏗᏯ | 초기값 있는 ᎡᏍᎦᏂ_ᎢᎦᎢ 선언, 대입, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 integer·참조 바이트코드와 ᎤᏍᏗᏓᏅ 분기 |
| ᎧᏁᎢᏍᏗ_ᏧᎬᏩᎶᏗᏯ_eb3593ac | 십진 integer, UTF-8 소스의 ᎠᏍᏘ_ᏧᎬᏩᎶᏗᏯ/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, ᎠᏍᏘ_ᏧᎬᏩᎶᏗᏯ 결합 | integer ᎠᎢᏒᎢ_ᏧᎬᏩᎶᏗᏯ·bit_ᏧᎬᏩᎶᏗᏯ ᎠᎢᏒᎢ_ᏧᎬᏩᎶᏗᏯ·형 변환, 단락 평가, array_ᏧᎬᏩᎶᏗᏯ ᎬᏴᏍᏗ_Ꭵ_ᎧᏁᏉᎢᏍᏙᏗ |
| ᎠᏍᏆᏂᎪᏙᏗ | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | ᎤᏙᎯᏳ_ᎾᏍᎩ_ᎨᏒ_ᎦᏟᏌᏅᎯ kernel_ᏧᎬᏩᎶᏗᏯ 파일서술자와 ᎫᏓᎳ, 생성·ᎯᎵᎦᎵᏯ_ᏕᎦᎸᏛᎢ·이어쓰기·EOF |
| 출력 | System.out.print/println: int/boolean/char/String, println() | 동일 |
| ᎠᏍᏘ_ᏧᎬᏩᎶᏗᏯ/인수 | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), ᎠᏍᏘ_ᏧᎬᏩᎶᏗᏯ 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 ᎡᏍᎦᏂ_ᎢᎦᎢ 선언, 오버로드, 임의 형 변환, array_ᏧᎬᏩᎶᏗᏯ 생성 ᎦᏟᏌᏅᎯ_0201f362, 8/16진 리터럴, Unicode ᎦᏟᏌᏅᎯ_ᏡᎬ 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 상수 축소 변환을 구현하지 않는다. 외부 `.class`의 `int[]` 생성/읽기/쓰기는 지원하므로 ᎠᏁᏢᏍᎩ `javac --release 8`로 만든 array_ᏧᎬᏩᎶᏗᏯ 예제는 실행할 수 있다.

ᎪᎱᏍᏗ_ᏧᎬᏩᎶᏗᏯ ᏠᎨᏏ_ᏧᎬᏩᎶᏗᏯ·일반 ᎪᎱᏍᏗ_ᏧᎬᏩᎶᏗᏯ 생성·상속·인터페이스·여러 ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ ᎫᏓᎳ, long/float/double, 예외 ᎢᏯᏛᏁᎵᏓᏍᏗ_ᏧᎬᏩᎶᏗᏯ_Ꭵ_ᎧᏁᏉᎢᏍᏙᏗ, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java 예외 객체를 던지지 않고 진단 후 현재 프로그램을 종료한다. 객체와 ᎠᏍᏘ_ᏧᎬᏩᎶᏗᏯ Store_ᏧᎬᏩᎶᏗᏯ 공간은 ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ ᎦᏅᎪᎢᏍᏗ_ᎬᏙᏗ 시 ᎬᏗᏍᎩ 영역 전체와 함께 회수한다. 지속 ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ 중 GC는 없다.

## ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ 한도와 ᎦᎵᏓᏍᏔᏅ

| ᎠᏓᏁᏢᎢ_ᏧᎬᏩᎶᏗᏯ | 한도 |
| --- | --- |
| ᎦᏟᏌᏅᎯ_ᏡᎬ/ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ ᎠᏍᏆᏂᎪᏙᏗ | 각각 16KiB |
| 컴파일러 | 토큰 2,047개, 생성 코드 4KiB, 상수 풀 4KiB |
| ᏧᎸᏫᏍᏓᏁᏗᏱ_ᏧᎬᏩᎶᏗᏯ/인수 | 클래스당 32함수, 함수당 16인수 |
| JVM 상수 | 511개 |
| JVM ᏧᎸᏫᏍᏓᏁᏗᏱ_ᏧᎬᏩᎶᏗᏯ 코드 | 함수당 8KiB |
| JVM 호출/스택/ᎡᏍᎦᏂ_ᎢᎦᎢ 변수 | 32프레임, 프레임당 스택 128칸·ᎡᏍᎦᏂ_ᎢᎦᎢ 128칸 |
| JVM ᎪᎱᏍᏗ_ᏧᎬᏩᎶᏗᏯ Store_ᏧᎬᏩᎶᏗᏯ 공간 | 8,192개 32비트 칸, 헤더 포함 약 32KiB |
| ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ | 최대 500,000 ᎤᏁᏤᎸᎩ, 기존 커널의 약 3초 CPU ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 ᎦᎫᏍᏛᏗ_ᏧᎬᏩᎶᏗᏯ 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM 사전 검증기를 구현한 것은 아니다. ᎠᏍᏆᏂᎪᏙᏗ/ᏄᏍᏛ_ᎠᎦᏅᏛᎢ_ᏧᎬᏩᎶᏗᏯ ᏱᎦᏅᎯᏓ_ᏧᎬᏩᎶᏗᏯ, 상수 참조, ᎤᏁᏤᎸᎩ·분기 경계를 검사하고, ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ 중 스택 ᏱᎬᏁᎸᎯ_ᏧᎬᏩᎶᏗᏯ·ᎡᏍᎦᏂ_ᎢᎦᎢ ᎠᏛᏅᎢᏍᏙᏗ·array_ᏧᎬᏩᎶᏗᏯ ᎭᏫᏂᏗᏜ_ᏗᎪᏪᎵ_ᏧᎬᏩᎶᏗᏯ·ᎪᎱᏍᏗ_ᏧᎬᏩᎶᏗᏯ 참조를 검사한다. ᎬᏗᏍᎩ 코드의 페이지·포트 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, ᎪᏢᏍᎩ_ᎦᏟᏌᏅᎯ·JVM 오류는 `Exit: 1`, ᎤᏁᏤᎸᎩ 인수 오류는 `Exit: 2`다. CPU 시간 상한은 기존 `Exit: 124`이며, ᎬᏗᏍᎩ ELF 자체의 CPU/런타임 오류는 기존 ᎦᏅᎪᎢᏍᏗ_ᎬᏙᏗ 코드를 따른다. ᎤᏄᎸᎲᎦ_ᏧᎬᏩᎶᏗᏯ 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## 구현 위치와 시험

- `os/ᎬᏗᏍᎩ/자바/자바컴파일러.java`: 게스트 어휘·구문·형 검사, 상수 풀 및 바이트코드 생성.
- `os/ᎬᏗᏍᎩ/자바/자바가상기계.java`: ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ 적재, 스택·프레임·ᎪᎱᏍᏗ_ᏧᎬᏩᎶᏗᏯ Store_ᏧᎬᏩᎶᏗᏯ, ᎤᏁᏤᎸᎩ 해석과 제한된 표준 호출.
- `os/ᎦᏟᏌᏅᎯ_0201f362/ᎠᏅᏓᏗᏍᏙ_ᎠᏍᏆᏂᎪᏙᏗ_ᏄᏍᏗᏓᏅᎢ.java`: ᎠᏅᏓᏗᏍᏙ_ᎦᏟᏌᏅᎯ ᎠᏍᏆᏂᎪᏙᏗ_ᏄᏍᏗᏓᏅᎢ, ᎦᏁᏟᏴᏓ_ᎪᏪᎸ_ᏧᎬᏩᎶᏗᏯ, 부팅 ᎠᏍᏆᏂᎪᏙᏗ 적재.
- `os/ᎦᏟᏌᏅᎯ_0201f362/체계호출.java`, `compiler/ᎭᏂᎩᏍᏓ_ᎬᏗᏍᎩ_ᎬᏙᏗ.s`: ᎠᏍᏆᏂᎪᏙᏗ/문자 출력 API와 ᎬᏗᏍᎩ ᎠᏎᎯᎯ 검사.
- `os/도구/자바파일묶기.py`: ᎠᏁᏢᏍᎩ 입력 ᎠᏍᏆᏂᎪᏙᏗ ᎪᎯᏳᏙᏗ·부팅 ᎤᎾᏓᏡᎬᎢ_ᏧᎬᏩᎶᏗᏯ 생성.

```sh
make test-java
make test
```

`os/시험/자바시험.py`는 ELF/ISO 부팅, 게스트 ᎪᏢᏍᎩ_ᎦᏟᏌᏅᎯ·ᎠᎴᏅᏗᏱ_ᎤᏁᏤᎸᎩ, ᎬᏗᏍᎩ 입력, 재귀·반복문·integer 극값·ᎠᏍᏘ_ᏧᎬᏩᎶᏗᏯ 결합·단락 평가, 재실행, ᎦᏟᏌᏅᎯ_ᏡᎬ ᎦᎵᏓᏍᏔᏅ 후 기존 ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ 보존, array_ᏧᎬᏩᎶᏗᏯ/수 해독 ᎦᎵᏓᏍᏔᏅ, 무한 반복 제한, ᎦᏁᏟᏴᏓ_ᎪᏪᎸ_ᏧᎬᏩᎶᏗᏯ 넘침과 ᎠᏍᏆᏂᎪᏙᏗ 부족을 검사한다. 게스트 생성 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 ᎠᏁᏢᏍᎩ OpenJDK의 ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ, integer 배열과 한글 상수를 게스트에 적재하며, 손상된 ᎠᏍᏆᏂᎪᏙᏗ 표식·버전·상수 수·분기·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 시험 VM만 생성하고 종료한다.

구현 형식의 참고 ᎦᏟᏌᏅᎯ: Oracle [JVM ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ ᎠᏍᏆᏂᎪᏙᏗ 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM ᎤᏁᏤᎸᎩ 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java ᎠᏍᏆᏂᎪᏙᏗ I_O

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 ᏄᏍᏛᎢ_ᏧᎬᏩᎶᏗᏯ 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 ᎠᎰᏂ_ᏧᎬᏩᎶᏗᏯ `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. ᎠᏓᏁᏟᏴᏍᏗᏍᎩ_ᏧᎬᏩᎶᏗᏯ 출력 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. 예외 ᎪᎱᏍᏗ_ᏧᎬᏩᎶᏗᏯ·try/catch·try-with-resources는 지원하지 않으며 ᎠᏍᏆᏂᎪᏙᏗ 오류를 진단하고 프로그램을 종료한다. array_ᏧᎬᏩᎶᏗᏯ I_O, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 ᎠᏍᏆᏂᎪᏙᏗ 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 ᎤᏯᏍᎦ `sync`가 필요하다. 예제의 ᎠᏍᏆᏂᎪᏙᏗ 이름은 현재 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 ᎤᏙᎯᏳ_ᎾᏍᎩ_ᎨᏒ_ᎦᏟᏌᏅᎯ 게스트 ᎪᏢᏍᎩ_ᎦᏟᏌᏅᎯ 결과를 OpenJDK `-Xverify:all`로 다시 실행해 ᎠᏍᏆᏂᎪᏙᏗ 바이트와 출력을 대조한다. 범위와 Store_ᏧᎬᏩᎶᏗᏯ ᎦᎶᏙᏗ_ᏧᎬᏩᎶᏗᏯ 사용법은 [posix-kor ᏍᎩᎪᎵᏯ_eb81d7d9](../posix-kor/ᏍᎩᎪᎵᏯ_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
