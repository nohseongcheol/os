# jkoros 안에서 Java कंपाइल_स्रोत·निष्पादित_करें_आदेश

이 문서의 부팅·शेल·स्टोर_मान 명령은 **x86 संस्करण_मान** 기준이다. 공유 Java कंपाइलर/JVM은 [निज ARM64 Pi4 संस्करण_मान](../platforms/rpi4-native/README.md)에도 연결되어 있다. ARM64에서는 UTF-8 UART 입력·한글 फ़ाइल_नाम_पाठ, `edit`의 단독 `.` स्टोर_मान, 16개 RAM संचिका, 약 2초 निष्पादित_करें_आदेश 제한을 사용한다.

`javac FILE.java`와 `java CLASS [ARGS]`를 네이티브 jkoros 셸에서 실행한다. 컴파일러와 JVM은 각각 독립 ELF로 적재되어 ring 3에서 동작한다. 소스를 게스트에서 읽어 वास्तविक_डेटा JVM `.class` 파일을 만들고, 그 파일의 바이트코드를 게스트 JVM이 해석한다. आयोजक कंपाइल_स्रोत 서버나 Linux 게스트는 사용하지 않는다.

**अद्यतित_आइटम 구현은 निज 제한형 कंपाइलर·JVM이다. OpenJDK/JDK 전체를 이식하거나 설치한 것이 아니며 Java SE 호환 환경도 아니다.** 표준 라이브러리는 아래의 일부 호출을 구현한 것이다. `java -version`과 `javac -version`에도 이 범위를 표시한다. 일반 JAR, Maven/Gradle, 임의의 Java ऐप_f5044b9b 실행은 아직 지원하지 않는다.

## 바로 निष्पादित_करें_आदेश

호스트에서:

```sh
cd /home/user/jkoros
make iso
make run
```

게스트에서:

```text
jkoros> javac -version
jkoros> java -version
jkoros> ls
jkoros> cat Hello.java
jkoros> javac Hello.java
Compiled: Hello.class (JVM class version 49)
Exit: 0
jkoros> java Hello
Hello from jkoros JVM!
55
Exit: 0
```

ISO는 `os/build/kernel.iso`다. 기존 VirtualBox 실행기도 같은 ISO를 사용한다. निष्पादित_करें_आदेश 중이거나 저장된 VM에는 새 ISO가 자동 반영되지 않는다. 새 부팅 절차는 [VirtualBox निष्पादित_करें_आदेश ReadMe_फ़ाइल_eb81d7d9](가상상자실행.md)를 따른다. 이 변경의 Java 자동 시험은 QEMU에서 수행했다.

## 직접 작성

`edit`는 संचिका 전체를 새 내용으로 작성한다. 기존 내용의 पंक्ति संपादन_मान 기능은 아니다. `.save`로 저장하고 `.cancel`로 취소한다.

```text
jkoros> edit Demo.java
...> public class Demo {
...>  public static int square(int n) { return n * n; }
...>  public static void main(String[] args) {
...>   int n = Integer.parseInt(args[0]);
...>   System.out.println("square=" + square(n));
...>  }
...> }
...> .save
jkoros> javac Demo.java
jkoros> java Demo 12
square=144
Exit: 0
```

- `ls`: 파일과 बाइट_मान 수 शो_मान.
- `cat FILE`: संचिका सामग्री_मान शो_मान. 텍스트 소스에 사용한다.
- `rm FILE`: मेमोरी_डेटा संचिका 삭제.
- `edit FILE`: 전체 내용을 새로 입력. 빈 파일도 저장할 수 있다.
- 구문·लिखें_मान 검사 विफलता_मान 시 기존 `.class`는 유지된다. 소스를 고친 वापस_मान 컴파일이 실패했다면 이전 निष्पादित_करें_आदेश 파일이 남아 있으므로 कंपाइल_स्रोत 성공 여부를 확인한다.

파일은 RAM에서 동작한다. 전용 स्टोर_मान 매체가 없거나 `sync`하지 않은 내용은 재부팅하면 사라진다. `make -C os run-store`로 연결한 매체에는 `sync`로 स्रोत_ट्री·कक्षा_मान·आँकड़े 파일을 보존할 수 있다. 최대 8개, 파일마다 16KiB, संचिका 이름은 ASCII 1~63자다. स्रोत_ट्री 이름은 `.class` 확장자 पता_क्षेत्र 때문에 최대 62자다. संपादन_मान 입력은 ASCII이고 한 पंक्ति 최대 128자다. पंक्ति 또는 संचिका 한도를 넘긴 편집은 `.save`에서 거부하여 기존 파일을 보존한다. कर्नेल_मान/कंपाइलर/JVM 구현의 Java 식별자는 한국어이며, अद्यतित_आइटम 게스트 입력 제한 때문에 उपयोगकर्ता 예제 이름은 ASCII로 작성한다.

## बाहरी_मान संचिका 적재

호스트에서 만든 소스나 समर्थन_मान क्लिप 안의 `.class`를 부팅 이미지에 포함할 수 있다. `JAVA_FILES`는 `게스트이름=호스트경로` 목록이다. 아래의 경로는 예시이며 वास्तविक_डेटा 파일의 절대 경로로 바꾼다. 공백 없는 경로를 사용한다.

```sh
# आयोजक JDK로 컴파일한 클래스도 사용할 수 있다.
javac --release 8 /tmp/Demo.java
make -C /home/user/jkoros iso \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
make -C /home/user/jkoros run \
  JAVA_FILES='Demo.java=/tmp/Demo.java Demo.class=/tmp/Demo.class'
```

새 부팅 후 `java Demo 12`를 실행한다. 소스만 넣었으면 게스트에서 `javac Demo.java`부터 실행한다. `JAVA_FILES`를 생략한 अगला_आइटम 빌드에서는 जोड़ें_एन्ट्री 파일을 포함하지 않는다. संचिका सामग्री_मान 변경과 एन्ट्री_सूची 제거도 अगला_आइटम 빌드에 반영된다. 원본 आयोजक 파일에는 쓰지 않는다. डिफ़ॉल्ट_मान `Hello.java`까지 합해 8개이며, 같은 이름을 명시하면 डिफ़ॉल्ट_मान 예제를 대체한다. 새 `.class`를 저장할 빈 슬롯도 남겨 둔다.

`--release 8`은 कक्षा_मान संचिका 버전을 맞추는 옵션이다. 사용하는 문법·바이트코드·라이브러리도 아래 समर्थन_मान क्लिप 안에 있어야 한다.

## समर्थन_मान क्लिप

| 기능 | 게스트 javac | 게스트 JVM |
| --- | --- | --- |
| कक्षा_मान | 패키지 없는 단일 कक्षा_मान, 정적 फ़ंक्_शन_मान, 재귀, तर्क/वापस_करें_परिणाम | 실행마다 단일 कक्षा_मान 적재, public static main(String[]) |
| डिफ़ॉल्ट_मान मान | int, boolean, char, String, main의 String[] तर्क | पूर्णांक·संदर्भ ऑपरेंड_स्टैक, String, int[], String[], 내부 StringBuilder |
| स्टेटमेंट_मान | 초기값 있는 स्थानीय_दायरा घोषणा, असाइनमेंट_मान, `+=`, `-=`, `*=`, `/=`, `%=`, 후위 ++/--, 블록, if/else, while, for, return | 해당 पूर्णांक·संदर्भ 바이트코드와 शर्त शाखा |
| व्यंजक_मान | 십진 पूर्णांक, UTF-8 소스의 स्ट्रिंग_मान/문자, + - * / %, 비교, ==/!=, !/&&/\|\|, स्ट्रिंग_मान 결합 | पूर्णांक ऑपरेशन_मान·बिट_मान ऑपरेशन_मान·लिखें_मान रूपांतरित_करें_मान, 단락 평가, सरणी_मान पहुँच_एन्ट्री |
| संचिका | FileInputStream(String), FileOutputStream(String[, boolean]), read()/write(int)/close() | वास्तविक_डेटा कर्नेल_मान 파일서술자와 जोड़ना, जनरेट_करें·साफ_करें_सामग्री·이어쓰기·EOF |
| निर्गम | System.out.print/println: int/boolean/char/String, println() | 동일 |
| स्ट्रिंग_मान/तर्क | String.length(), args.length, args[index], Integer.parseInt | 추가로 String.charAt(), स्ट्रिंग_मान 상수의 modified UTF-8 해독 |

선언은 지원하는 문법만 허용한다. 여러 변수를 한 선언에 나열하기, 초기값 없는 स्थानीय_दायरा घोषणा, 오버로드, 임의 लिखें_मान रूपांतरित_करें_मान, सरणी_मान जनरेट_करें स्रोत, 8/16진 리터럴, Unicode स्रोत_ट्री 이스케이프 등은 미지원이다. `char`는 문자 리터럴로 초기화하며 일반 JDK의 모든 अचर_मान 축소 변환을 구현하지 않는다. बाहरी_मान `.class`의 `int[]` जनरेट_करें/पढ़ें/쓰기는 지원하므로 आयोजक `javac --release 8`로 만든 सरणी_मान 예제는 실행할 수 있다.

ऑब्जेक्ट_मान फ़ील्ड_मान·일반 ऑब्जेक्ट_मान जनरेट_करें·상속·인터페이스·여러 कक्षा_मान जोड़ना, long/float/double, अपवाद प्रक्रिया_मान_एन्ट्री, 스레드·모니터, 리플렉션, JNI, JIT, GC, 위 표에 없는 `java.io`와 `java.nio`/`java.net` 일반 API, 컬렉션, JAR와 클래스패스는 미지원이다. 런타임 오류는 Java अपवाद 객체를 던지지 않고 진단 후 अद्यतित_आइटम 프로그램을 종료한다. 객체와 स्ट्रिंग_मान स्टोर_मान 공간은 निष्पादित_करें_आदेश निर्गमन_ऐप 시 उपयोगकर्ता क्षेत्र_मान 전체와 함께 회수한다. 지속 निष्पादित_करें_आदेश 중 GC는 없다.

## निष्पादित_करें_आदेश 한도와 त्रुटि

| संसाधन_मान | 한도 |
| --- | --- |
| स्रोत_ट्री/कक्षा_मान संचिका | 각각 16KiB |
| कंपाइलर | टोकन_मान 2,047개, जनरेट_करें कोड_मान 4KiB, अचर_मान 풀 4KiB |
| फ़ंक्_शन_मान/तर्क | 클래스당 32함수, 함수당 16인수 |
| JVM अचर_मान | 511개 |
| JVM फ़ंक्_शन_मान कोड_मान | 함수당 8KiB |
| JVM 호출/ऑपरेंड_स्टैक/स्थानीय_दायरा चर_मान | 32프레임, 프레임당 ऑपरेंड_स्टैक 128칸·स्थानीय_दायरा 128칸 |
| JVM ऑब्जेक्ट_मान स्टोर_मान पता_क्षेत्र | 8,192개 32비트 칸, 헤더 포함 약 32KiB |
| निष्पादित_करें_आदेश | 최대 500,000 आदेश, 기존 커널의 약 3초 CPU निष्पादित_करें_आदेश 상한도 적용 |

게스트 컴파일러는 버전 49.0 `.class`를 생성하며 JVM은 45.0~52.0 중 समर्थन_मान 명령으로 구성된 파일을 읽는다. 스택맵을 이용한 완전한 JVM कोश 검증기를 구현한 것은 아니다. संचिका/विशेषता_मान 길이, अचर_मान संदर्भ, आदेश·शाखा 경계를 검사하고, निष्पादित_करें_आदेश 중 ऑपरेंड_स्टैक फॉर्मैट_मान·स्थानीय_दायरा आरंभ·सरणी_मान सबस्क्रिप्ट_मान·ऑब्जेक्ट_मान 참조를 검사한다. उपयोगकर्ता 코드의 페이지·포트 접근은 기존 ring 3 경계로 보호한다.

일반 성공은 `Exit: 0`, कंपाइल_स्रोत·JVM 오류는 `Exit: 1`, आदेश तर्क 오류는 `Exit: 2`다. CPU समय_उपयोगिता 상한은 기존 `Exit: 124`이며, उपयोगकर्ता ELF 자체의 CPU/런타임 오류는 기존 निर्गमन_ऐप 코드를 따른다. विफलता_मान 후 셸에서 다른 프로그램을 계속 실행할 수 있다.

## 구현 위치와 시험

- `os/उपयोगकर्ता/자바/자바컴파일러.java`: 게스트 어휘·구문·लिखें_मान 검사, अचर_मान 풀 및 바이트코드 जनरेट_करें.
- `os/उपयोगकर्ता/자바/자바가상기계.java`: कक्षा_मान 적재, ऑपरेंड_स्टैक·프레임·ऑब्जेक्ट_मान स्टोर_मान, आदेश 해석과 제한된 표준 호출.
- `os/स्रोत/मेमोरी_फ़ाइल_सिस्टम.java`: मेमोरी_डेटा फ़ाइल_सिस्टम, संपादन_मान, 부팅 संचिका 적재.
- `os/स्रोत/체계호출.java`, `compiler/प्रारंभ_उपयोगकर्ता_ऐप.s`: संचिका/문자 निर्गम API와 उपयोगकर्ता सूचक 검사.
- `os/उपकरण/자바파일묶기.py`: आयोजक 입력 संचिका मान्य_करें·부팅 समूह_मान जनरेट_करें.

```sh
make test-java
make test
```

`os/시험/자바시험.py`는 ELF/ISO 부팅, 게스트 कंपाइल_स्रोत·निष्पादित_करें_आदेश, उपयोगकर्ता 입력, 재귀·반복문·पूर्णांक 극값·स्ट्रिंग_मान 결합·단락 평가, 재실행, स्रोत_ट्री त्रुटि 후 기존 कक्षा_मान 보존, सरणी_मान/수 해독 त्रुटि, 무한 पुनरावृति_मान 제한, संपादन_मान 넘침과 संचिका 부족을 검사한다. 게스트 जनरेट_करें 클래스의 바이트를 QEMU 메모리에서 꺼내 OpenJDK `java -Xverify:all`로 실행하고 결과를 대조한다. 반대 방향으로 आयोजक OpenJDK의 कक्षा_मान, पूर्णांक 배열과 한글 상수를 게스트에 적재하며, 손상된 संचिका मार्कर_मान·버전·अचर_मान 수·शाखा·스택을 거부하는지도 검사한다. 기록은 `os/build/자바시험.json`에 남는다. 디스크 없는 별도 시험 VM만 생성하고 종료한다.

구현 형식의 참고 आँकड़े: Oracle [JVM कक्षा_मान संचिका 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-4.html), [JVM आदेश 명세](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html).

## Java संचिका इनपुट_आउटपुट

[FileDemo.java](../posix-kor/자바예제/FileDemo.java)는 일반 Java 표준 कक्षा_मान 이름을 사용한다. 소스를 `edit FileDemo.java`로 입력하거나 `JAVA_FILES`로 부팅 이미지에 넣은 वापस_मान `javac FileDemo.java`, `java FileDemo`를 실행한다. 결과는 `65`, `255`, `66`, `-1`, `JAVA FILE IO PASS`다. `write(int)`는 하위 8비트를 쓰고 `read()`는 0~255 또는 EOF -1을 반환한다. डिफ़ॉल्ट_मान निर्गम 생성자는 내용을 비우고, boolean 인수가 true이면 이어쓴다.

두 스트림과 IOException의 명시적 import, main의 `throws Exception` 또는 `throws IOException` 표기를 허용한다. अपवाद ऑब्जेक्ट_मान·try/catch·try-with-resources는 지원하지 않으며 संचिका 오류를 진단하고 프로그램을 종료한다. सरणी_मान इनपुट_आउटपुट, InputStream/OutputStream으로의 다형성, Reader/Writer, getFD, 일반 संचिका 메타데이터 API는 아직 없다. close는 열린 서술자를 닫고, 재부팅 보존에는 शेल `sync`가 필요하다. 예제의 संचिका 이름은 अद्यतित_आइटम 셸과 파일체계에 맞춰 ASCII로 쓴다.

`os/시험/자바파일시험.py`는 वास्तविक_डेटा 게스트 कंपाइल_स्रोत 결과를 OpenJDK `-Xverify:all`로 다시 실행해 संचिका 바이트와 출력을 대조한다. 범위와 स्टोर_मान मीडिया_मान 사용법은 [posix-kor ReadMe_फ़ाइल_eb81d7d9](../posix-kor/ReadMe_फ़ाइल_eb81d7d9.md)를 참고한다. 참고한 표준 API는 Oracle [FileOutputStream](https://docs.oracle.com/javase/8/docs/api/java/io/FileOutputStream.html)이다.
