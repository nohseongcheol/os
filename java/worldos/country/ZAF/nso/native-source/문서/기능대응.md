## 기존 selo_boleng 기반 관리 khenele_boleng 전체를 부팅하기 위해 남은 Ikgokaganye

다음 항목은 Java 문법만으로 실행할 수 없는 CPU/sedirišwa_boleng 동작이므로 관리 계층과 별도로 AOT 런타임에 연결해야 한다.

- Multiboot go_tsenya_tshedimošo_ntlha_boleng, CR0/CR2/CR3/CR4, IDT 적재, `iret`, x86 Kamano_boleng lota_boleng
- kgonthe_data PIC/PIT/PS2/ATA/PCI 포트 및 AMD PCnet DMA ditaelopoeletšwa_boleng
- Java selo_boleng·arei_boleng linke_Sebopego, 예외, ya_go_se_fetoge_boleng_f430d3f5 thomiša, 가비지 수집기
- 컴파일된 Java 메서드를 freestanding i386 기계어로 바꾸는 AOT karolo_boleng_29ee1bb7
- FAT 디스크 구역을 kgonthe_data ATA 장치와 연결하는 I_O 접착 llaga_boleng

위 관리 계층은 engos 기능의 Java 관리 구현과 go_nea_ditirelo 검증판이다. 별도 `os/`에서는 제한형 AOT, Multiboot go_tsenya_tshedimošo_ntlha_boleng, ya_go_se_fetoge_boleng_f430d3f5 thomiša·palotlalo arei_boleng, VGA/직렬/PS2, 명령해석기, mošomiši ELF/ring 3/시스템 호출, RTL8139/ARP/IPv4/UDP를 연결해 QEMU 부팅과 go_nea_ditirelo 루프백 패킷 왕복을 검증했다. 위 표의 selo_boleng 기반 관리 기능 전체나 VirtualBox 네트워크 실행까지 검증했다는 뜻은 아니다.
