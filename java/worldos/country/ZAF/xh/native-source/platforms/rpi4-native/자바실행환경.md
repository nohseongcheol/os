## ukwenza_umyalelo 제한과 남은 작업

- 동시에 적재하는 class 최대 16개(isiXhosa iklasi_ixabiso 포함), class당 16 KiB·engajikiyo_ixabiso 풀 511항목, 전체 imethodi_ixabiso/ifildi_ixabiso 각각 512개. imethodi_ixabiso 코드 8 KiB, eyale_ndawo_umda 변수·피연산자 스택 각각 128슬롯, 인수 최대 16개(this 포함).
- VM 가닥은 main 포함 **실행당 최대 4개**, 가닥당 호출 깊이 32. 100개 명령마다 ukwenza_umyalelo 대상을 바꾼다. 네이티브 호출 도중에는 전환하지 않는다. pthread/SMP/OS 스레드가 아니며 Thread.sleep/interrupt/daemon/우선순위, Object.wait/notify, java.util.concurrent는 없다.
- into_ixabiso 힙은 32768개의 32비트 슬롯이다. 런타임의 AOT 배열은 eyona_yenzekileyo_iingcombolo 메모리에서 64비트 슬롯을 사용한다. GC가 있어도 대형 iFayili·대형 uluhlu_lweekharektha_ixabiso·객체가 이 제한을 넘을 수 있다.
- 실행은 50만 바이트코드 Umyalelo 및 커널의 약 2초 EL0 기한으로 제한된다. Swing의 입력 대기는 기한을 갱신하고 i_window tshintshela_imo 시 중단·재개한다. 일반 iseva_ixabiso·계산의 무제한 실행은 아직 없다. 미지원 Umyalelo·isixhobo_sekhompyutha_ixabiso 부족은 명시적인 오류로 종료한다.
- RAM iFayili 최대 64개, 파일당 16384바이트, INDLELA UTF-8 63바이트. RAM 디렉터리와 untanga_ixabiso/절대 경로를 제공하며 영속 저장은 아직 없다. 내장 isiXhosa class는 RAM iFayili 슬롯을 소비하지 않는다. 셸의 `cd`로 정한 현재 경로에서 umthombo_umthi·iklasi_ixabiso·iingcombolo 파일을 읽는다.

- long/float/double, invokedynamic/람다, enum/annotation, 다차원 ULUHLU_ixabiso, 완전한 ULUHLU_ixabiso 공변성·인터페이스 ileya_ixabiso 검사, Reflection/JNI/JIT, NIO/ZIP API/Charset 전체, 보안/ujiko_nkcukacha_zibe_kwifonti_yeekhowudi_iingcombolo/국제화 전체, 전체 AWT/Swing/JavaFX는 미지원이다. ## JVM 0.3: 네트워크와 GUI isongezelelo_ixabiso
