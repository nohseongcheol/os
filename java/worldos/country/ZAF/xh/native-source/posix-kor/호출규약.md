# umsebenzisi 호출 경계

대상은 jkoros i386 ELF32다. Linux i386의 호출 번호와 바이너리 호환이 아니다. C의 cdecl 인수를 `umatshini/운영체제호출.s`에서 EAX(indeksa), EBX·ECX·EDX·ESI·EDI(첫째~다섯째 인수)로 변환한다. EBX·ESI·EDI·EBP를 보존하며 결과는 EAX다. ikheneli_ixabiso 실패는 음수 Impazamo indeksa, C ilayibhrari 실패는 -1과 양수 errno다.

커널은 0x04000000 이상, 0x04400000 미만의 umsebenzisi 영역 안에 자료의 전체 길이가 들어가는지 확인한다. 단순 널 검사가 아니다. C iingcombolo 주소는 ibhayithi_ixabiso 주소이며, 기존 Java AOT `int[]` 포인터와 혼용하지 않는다. Java iFayili 흐름의 어셈블리 경계가 별도 ibhayithi_ixabiso 버퍼를 마련하여 같은 호출을 사용한다.

43번 요청은 32비트 주소와 32비트 길이의 두 칸이다. 44번 요청은 32비트 주소와 길이를 담은 32비트 값의 idilesi 두 칸이다. 수신 주소가 NULL이면 untanga_ixabiso idilesi 기록을 생략한다. sockaddr_in은 16바이트이며 idilesi 체계는 isixhobo_ixabiso ibhayithi_ixabiso ULANDELELWANO_ixabiso, 접속번호와 IP 주소는 네트워크 ibhayithi_ixabiso 차례다. 축소된 idilesi 버퍼에도 들어가는 앞부분을 쓰고 전체 idilesi Ubukhulu 16을 반환한다.

0~22번의 기존 Java AOT 호출은 유지한다. 0은 phuma_inkqubo, 2·3은 기존 인수 조회다. 현재 커널의 인수 목록이 ukwenza_umyalelo 이름을 제외하므로 C 진입기는 argv[0]에 고정 uluhlu_lweekharektha_ixabiso `jkoros-app`을 넣고 이후 인수를 전달한다. argv 끝에는 NULL이 있다. 이 제한도 일반 UNIX Inkqubo_ixabiso ABI와 다른 점이다.

표준 헤더의 inani_elipheleleyo Ubukhulu, 플래그 ixabiso, stat ifildi_ixabiso 순서는 `UMTHOMBO/포함/`에 정의한다. 동적 Nxulumanisa·다중 Inkqubo_ixabiso·스레드가 추가되면 Impazamo indeksa 저장과 isixhobo_sekhompyutha_ixabiso 수명, 호출 경계도 함께 검토해야 한다.
