# JZafOS 구조

아래는 into_ixabiso 기반 관리 ikheneli_ixabiso 전체의 ithagethi_into 구조다. 현재 eyona_yenzekileyo_iingcombolo 부팅 가능한 제한형 구현은 `compiler/`와 `os/`에 있으며 [네이티브 Indlela_yokusebenza i_README_eb81d7d9](../os/i_README_eb81d7d9.md)에 구현 범위를 명시한다. 아래의 GC·umxholo_ixabiso tshintshela_imo·uhlobo_loseto_lwefayile 등이 새 ISO에 모두 포함돼 있지는 않다.

```text
GRUB 또는 UEFI
  ↓
x86 최소 부트·트랩 ileya_ixabiso
  ↓
Java AOT 실행기와 into_ixabiso·ULUHLU_ixabiso·GC 런타임
  ↓
하드웨어 경계
  ↓
Java 관리 ikheneli_ixabiso
  ├─ 기억공간/쪽관리/COW
  ├─ Inkqubo_ixabiso/배정/wait
  ├─ uhlobo_loseto_lwefayile/ELF/POSIX
  └─ 입력/Ugcino_isixhobo/Inethiwekhi_fumba
```

OpenJDK 자체는 이미 운영체제가 제공하는 iFayili, 스레드, 가상 기억공간을 전제로 한다. 따라서 ikheneli_ixabiso 부팅에는 OpenJDK를 그대로 넣지 않고 제한된 Java 바이트코드 AOT와 작은 런타임을 사용한다.

네이티브 계층에는 `in/out`, `hlt`, CR0/CR2/CR3/CR4, `iret`, umxholo_ixabiso 저장처럼 Java로 표현할 수 없는 CPU 동작만 남긴다. 정책과 자료구조는 Java에 둔다.
