# 국가·언어와 독립 구현

`country/<ISO 3166-1 alpha-3>/<CLDR 언어 코드>/`마다 Java 원본 두 개, 해당 언어의 명명 사전, 화면 문구, C/POSIX 별칭 헤더, 예제, 빌드 도구를 실제 파일로 보관한다. 다른 나라의 소스를 심볼릭 링크하거나 실행할 때 다른 나라의 클래스를 불러오지 않는다. Java 패키지에 국가·언어 코드를 넣어 동명이 충돌하지 않는다.

각 판의 `make build`는 그 판 안의 소스만 컴파일한다. `make run`은 그 판의 `build/data.ext4`를 만들며 사용자 파일과 변경된 설정은 이 디스크에 저장한다. 운영체제의 읽기 전용 Linux/OpenJDK 실행 이미지는 중복을 줄이기 위한 공통 외부 구성요소 캐시다. `make export`는 실행 이미지도 복사하므로 한 판을 다른 국가 디렉터리 없이 옮겨 실행할 수 있다. Linux·OpenJDK 자체의 독립 재작성이나 각 나라별 커널 포크를 뜻하지 않는다.

# 새 용어와 역사

`naming/concepts.json`은 현재 코드에서 각 이름이 의미하는 동작, 검증 가능한 역사적 컴퓨터 개념의 문헌, 해당 언어의 어원 검토 상태를 분리한다. Unix 문헌의 파일·목록·실행과정, RFC의 통신 끝점·독립전문 개념을 기능 설명에 반영한다. 해당 언어의 오래된 어원이나 모든 국민이 공유하는 철학을 만들어 붙이지 않는다.

한국어 제안의 예는 `작업마당`, `실행가닥`, `실행과정`, `독립전문`, `자료목록`, `위치옮기기`, `기록맞추기`다. 일본어·중국어·아랍어·힌디어 등도 Java의 유니코드 식별자를 실제 클래스·메서드·필드·지역변수·원본 파일명에 사용한다. API 이름과 번역어의 대응은 각 판의 명명 JSON에서 확인할 수 있다.

영어를 포함한 기존 명칭과 새 제안을 구별하기 위해 각 항목에 `source`, `status`, `native_review`를 둔다. `untranslated`는 영어 대체어이며 완성된 번역으로 세지 않는다. GNU gettext에서 가져온 단어도 사용 문맥의 적합성을 검토해야 한다. `native_review=pending`인 제안을 원어민 검수 완료나 역사적 어원 확정으로 설명하면 안 된다.

# 유지하는 표준 명칭

`public`, `class`, `main`, `java.nio.file.Files`와 같은 Java 문법·표준 라이브러리 이름, Linux/POSIX ABI, ISO 코드, `.java`, `Makefile`, 도구가 읽는 메타데이터 키는 유지한다. 사용자는 표준 Java/POSIX를 그대로 쓰거나 새 언어별 진입점을 사용할 수 있다. Java 래퍼의 메서드와 POSIX 함수의 계약은 서로 다르므로 동일한 규격이라고 주장하지 않는다.

현재 언어별 진입점은 Java 메서드 12개와 C 함수 별칭 8개다. 한국어 C 별칭은 `posix-KOR/체계호출.h`에 있으며 `open`, `read`, `write`, `close`, `lseek`, `fsync`, `unlink`, `connect`를 연결한다. 그 밖의 기능은 전체 OpenJDK와 Linux/musl의 표준 API로 사용한다. 전체 POSIX 함수명이나 외부 프로젝트의 내부 변수명까지 번역한 상태는 아니다.

2026-10-18 검토에서는 영어 낱말이 같은 다른 분야의 뜻이 섞인 사례를 수정했다.
네덜란드어 `Belasting`은 소스 불러오기 함수 `broncodeLaden`으로,
포르투갈어 `Carga`는 `carregarFonte`로, 인도네시아어 `Beban`은
`muatSumber`로 바꾼다. 현재 동작은 `Files.readString`으로 원문을 편집기에
읽어 오는 것이다. 포트 매개변수도 번호임을 드러내며, 실행 종료 결과를
목적지나 레이블로 번역했던 사례도 수정한다.

네덜란드어 `laden`은 역사 사전, 포르투갈어 `carregar`는 Priberam,
이탈리아어 `caricare`는 Treccani에서 확인한 어근 이력을 기록했다.
`broncodeLaden`, `carregarFonte`, `caricaSorgente`라는 프로젝트 함수명이
옛 문헌에 등장한다는 뜻은 아니다. 정확한 URL과 확인 범위는
`naming/functional-review.json`에 있다. 원어민 자연스러움 검수는 여전히 대기 상태다.

# 수록 범위

ISO 3166-1의 국가·지역 249개와 CLDR 48 territoryInfo가 기록한 국가별 사용 언어 조합 전체를 수록한다. 공용어와 단순 인구 기록은 `official_status`로 구분한다. 이 목록에는 비주권 지역도 포함된다. CLDR의 수록 범위 밖인 언어는 자동으로 존재한다고 가장하지 않는다. 수록 언어 수, 독립판 수, 미번역 현황은 `naming/coverage.json`과 `editions.json`을 기준으로 확인한다.
