# 실행

프로젝트 최상위(`/home/user/java/worldos`)에서:

```sh
make build EDITION=KOR/ko
make run EDITION=KOR/ko
make run EDITION=JPN/ja
make run EDITION=SAU/ar
make list
```

창에는 Java 원문 편집기, 파일 열기·저장, 컴파일, 실행, 중지, 명령창이 있다. 한국어 판은 처음에 `원문.java`와 주 클래스 `원문`을 열며, 다른 판은 해당 언어의 이름을 사용한다. 이 예제를 실행하면 파일을 기록하고 Swing 창을 연다. 다른 클래스를 작성할 때 파일명과 주 클래스 이름을 함께 변경한다. 패키지가 있으면 주 클래스에 전체 패키지 이름을 입력한다. 실행 인수에는 따옴표를 사용할 수 있다. 명령창에서 `javac`, `java`, `jar`, `jshell`, `gcc`, `make`도 직접 사용할 수 있다.

사용자 작업은 게스트 `/home/user/workspace`에 저장된다. 해당 판의 `build/data.ext4`를 보존하면 재부팅 후 유지된다. 종료할 때는 직렬 콘솔의 `poweroff`를 사용한다. 창을 닫아 QEMU를 강제 종료하면 저장 중인 데이터가 유실될 수 있다. 다른 판은 다른 데이터 디스크를 사용한다.

호스트 요구 도구: Python 3.6 이상, JDK 11 이상, QEMU x86_64, e2fsprogs. 실행 이미지 재구성에는 squashfs-tools, kmod, 정적 `/bin/busybox`도 필요하다. 처음 구성할 때:

```sh
make fetch
make prepare-runtime
make runtime
make generate
make build-all
```

서명 검증하는 Alpine apk로 프로젝트 내부에 패키지를 풀며 호스트 시스템에 패키지를 설치하거나 chroot하지 않는다. 네트워크가 필요한 단계는 fetch/prepare-runtime이다. 정확한 취득 URL·SHA-256과 설치 패키지 버전은 vendor의 기록, 실행 이미지 해시는 build/runtime/manifest.json에 남는다. Alpine 저장소가 갱신되어 고정 버전이 사라지면 캐시나 해당 버전 보관 저장소가 필요하다. 모든 의존성의 완전한 재현 빌드를 보장하는 소스 빌드 시스템은 아니다.

# 독립 배포 디렉터리

```sh
make export EDITION=KOR/ko OUTPUT=/tmp/worldos-kor
cd /tmp/worldos-kor
make build
make run
```

내보내기에는 다른 국가의 소스나 개인 데이터 디스크가 들어가지 않는다. 실행 이미지가 포함되어 약 900MB 이상을 사용한다. 결과는 QEMU용 실행 디렉터리이며 설치 ISO는 아니다.

# 검증

```sh
make build-all
make test EDITION=KOR/ko
make test-gui EDITION=KOR/ko
make test-desktop EDITION=SAU/ar
make verify-editions
python3 tools/test_normal.py --root /tmp/worldos-kor
```

통합 시험은 별도 ext4 디스크를 만들고 게스트에서 javac/java/jar/gcc를 직접 실행한다. HTTP·HTTPS 시험 서버는 호스트 루프백에 임시로 생성한다. 게스트는 10.0.2.2를 통해 접근하며 HTTPS는 시험 인증서를 명시적으로 신뢰하고 호스트 이름 검증을 유지한다. DNS 시험에는 외부 DNS 접근이 필요하다. 결과는 build/verification 아래의 보고서·직렬 로그·화면 파일로 남는다.

`test_normal.py`는 먼저 내보낸 독립 판을 일반 모드로 부팅하고 직렬 콘솔에서 유니코드 Java 파일을 컴파일·실행한다. 그래픽 화면을 기록하고 콘솔의 `poweroff`로 종료한 뒤 ext4와 저장된 파일을 확인한다. 이 화면 시험에는 호스트의 Python Pillow와 QEMU 로컬 제어 소켓 사용 권한이 필요하다.

QEMU는 현재 사용자 모드 NAT를 사용한다. 게스트에서 외부로 연결할 수 있으며, 외부 장치에서 게스트 서버로 접속하려면 별도로 포트 전달 또는 브리지 설정이 필요하다. 호스트 디렉터리를 게스트에 자동 공유하지 않는다.

# 문자 입력

Fcitx5 프로필에는 영문 키보드와 해당 언어의 입력기를 설정한다. Ctrl+Space로 전환한다. Ctrl+Shift+U를 누르고 유니코드 코드 포인트를 16진수로 입력한 뒤 Space로 확정한다. 예를 들어 `ac00`은 `가`다. 입력기 자동 선택이 없는 언어는 영문 키보드를 기본으로 하며, 다른 설치된 배치·m17n 입력기 또는 유니코드 입력을 선택해야 한다. 언어별 선택과 검토 상태는 각 판의 edition.json에 기록한다. [Fcitx5의 유니코드 입력 구현](https://github.com/fcitx/fcitx5/blob/5.1.19/src/modules/unicode/unicode.cpp)

일부 데바나가리 누크타 표기는 Unicode NFC 상태여도 GCC가 정규화 경고를 내므로 시험 명령은 이 경고만 제외한다. 원본 문자의 철자는 바꾸지 않는다. Java 식별자는 UTF-8 그대로 컴파일한다.
